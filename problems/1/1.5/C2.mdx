# C2 서버가 정한 쓰기 위치가 증거 폴더와 겹침

원고 [1.5 증거 무결성 관리](/problems/1/1.5) · 소제목 「보호할 증거의 범위」

## 현상과 피해

이미지 경로 뒤에 붙인 이름으로 설정 파일을 써 이미지 폴더에 서버 파일이 생겼다(VolPilot, MCP). 압축 해제 기본 폴더가 증거 경로 아래다(SAVVYDFIR-MCP). 호스트 구분 없는 고정 이름으로 써 앞 단말에서 수집한 증거 사본이 바뀐다(winforensics-mcp, 1.1 주 배치).

## 문제가 관찰된 서버 (3)

### [SAVVYDFIR-MCP](/problems/servers/SAVVYDFIR-MCP)

- `load_memory`가 ZIP 메모리 덤프를 풀 폴더의 기본값을 `/evidence/memory`로 두고, 서버 자신의 쓰기 경로 검사(`OUTPUT_PATHS`, `/evidence/`가 든 `WRITE_PROTECTED_PATHS`)를 이 인자에 적용하지 않은 채 `7z x … -y`로 푼다 코드: [sift_mcp/server.py:184](https://github.com/kismatkunwar89/SAVVYDFIR-MCP/blob/9ac8e47540d4826227ac8957a5c5f4caf4f6c80b/sift_mcp/server.py#L184)–186, 203–229, 10763–10767, 10813–10824; [runners/base.py:245](https://github.com/kismatkunwar89/SAVVYDFIR-MCP/blob/9ac8e47540d4826227ac8957a5c5f4caf4f6c80b/runners/base.py#L245)–249

### [VolPilot](/problems/servers/VolPilot)

- 플러그인 설정 파일 위치를 이미지 경로 뒤에 `.vol3cfg.json`을 붙여 정해 이미지 폴더에 서버 파일을 쓴다. README에는 이 파일 언급이 없고 도구 설명은 "The memory image is read-only evidence"라고 적는다 코드: [session.py:32](https://github.com/cpuu/VolPilot/blob/5c848519cfa2e86a86abbe613c7249fddeffc6df/session.py#L32), 107–112; [plugins/_common.py:166](https://github.com/cpuu/VolPilot/blob/5c848519cfa2e86a86abbe613c7249fddeffc6df/plugins/_common.py#L166)–171

### [winforensics-mcp](/problems/servers/winforensics-mcp)

- `remote_collect_artifacts`가 호스트 구분 없는 고정 이름(`output_dir/evtx/<이름>.evtx`)으로 써, 앞 단말에서 수집한 증거 사본이 알림 없이 바뀐다 코드: [winforensics_mcp/collectors/artifact_collector.py:386-420](https://github.com/x746b/winforensics-mcp/blob/cce7f360873fc9ae564296017cbffe2a603d83dd/winforensics_mcp/collectors/artifact_collector.py#L386-L420)(collect_triage_package가 output_dir/evtx/&lt;이름&gt;.evtx, output_dir/registry/&lt;이름&gt;의 고정 이름으로 씀, 호스트 구분 없음); [winforensics_mcp/server.py:2431-2444](https://github.com/x746b/winforensics-mcp/blob/cce7f360873fc9ae564296017cbffe2a603d83dd/winforensics_mcp/server.py#L2431-L2444)(output_dir 필수 인자)
