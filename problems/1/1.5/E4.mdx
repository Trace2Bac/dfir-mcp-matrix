# E4 대조 범위가 기준값의 범위와 맞지 않음

원고 [1.5 증거 무결성 관리](/problems/1/1.5) · 소제목 「기준값 대조와 검증 결과」

## 현상과 피해

다른 이름의 EWF를 컨테이너 파일 해시로 계산해 획득 해시와 비교하므로 내용이 같아도 불일치가 난다(Camel). 분할 이미지의 등록 파일 하나만 해시한다(Camel). E01 조각 파일의 바이트를 해시해 매체 해시와 비교한다(trudi, 맞는 도구 `ewf_verify`가 따로 있음).

## 문제가 관찰된 서버 (2)

### [Camel](/problems/servers/Camel)

- 해시를 받지 않은 E01과 분할 raw 이미지는 등록 경로의 파일 하나만 해시하고 `.E02`·`.002` 같은 다른 조각은 해시하지 않는다 코드: [src/Camel.Environments/AuditEnvironment.cs:313-331](https://github.com/allisterb/Camel/blob/63f4cb2e26a2469a35f847bee607516cf6184e91/src/Camel.Environments/AuditEnvironment.cs#L313-L331)(해시를 준 항목은 IsEwfImage가 아니면 등록 경로 파일 하나를 그 알고리즘으로 해시해 비교), :352-355(.e01·.ex01만 EWF로 봄)
- `VerifyEvidence`는 확장자가 `.e01`·`.ex01`인 경우만 EWF로 보아 매체 내용 해시(`ewfverify`)로 대조하고, 다른 이름의 EWF는 컨테이너 파일 해시로 계산해 획득 해시와 비교하므로 내용이 같아도 MISMATCH가 난다(거짓 통과는 없음) 코드: [src/Camel.Environments/AuditEnvironment.cs:322](https://github.com/allisterb/Camel/blob/63f4cb2e26a2469a35f847bee607516cf6184e91/src/Camel.Environments/AuditEnvironment.cs#L322)(hasHash && IsEwfImage일 때만 ewfverify), :352-355(.e01·.ex01만 EWF, 대소문자 무시); [src/Camel.Server/MCPServer.cs:135-142](https://github.com/allisterb/Camel/blob/63f4cb2e26a2469a35f847bee607516cf6184e91/src/Camel.Server/MCPServer.cs#L135-L142)(설명은 .E01 EWF를 내용으로 검증한다고 적음)

### [trudi](/problems/servers/trudi)

- E01을 주면 그 조각 파일 하나의 바이트를 해시하므로 수집 도구가 남긴 매체 데이터 해시와 맞지 않는다 코드: [tools/hashing.py:345-389](https://github.com/nebulae/trudi/blob/88fbca78186b6a0ca40423cf5e37a9dc46ae051e/tools/hashing.py#L345-L389)(verify_evidence_hash가 받은 경로 파일의 바이트를 해시해 expected_md5·expected_sha1과 비교, 설명 'Use to verify chain of custody integrity before analysis'); [tools/ewf.py:18-77](https://github.com/nebulae/trudi/blob/88fbca78186b6a0ca40423cf5e37a9dc46ae051e/tools/ewf.py#L18-L77)(같은 서버에 ewf_verify 도구가 따로 있음)
