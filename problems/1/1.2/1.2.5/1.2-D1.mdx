# 1.2-D1 다시 쓰거나 모아 불러온 룰의 실제 내용을 결과에 연결하지 않음

원고 [1.2 분석 도구 관리](/problems/1/1.2) · 소제목 [1.2.5 참조 자료 선택과 사용](/problems/1/1.2/1.2.5)

## 현상과 피해

컴파일한 룰을 프로세스에 보관해 다시 쓰고 응답에는 일치한 룰 이름만 있어, 디스크의 룰과 실제 검사 룰이 달라도 알 수 없다(Wireshark-MCP). 여러 경로의 룰을 모을 때 없는 경로와 다른 확장자가 알림 없이 빠지고 같은 이름 규칙은 하나만 남으며, 경로 목록 키로 1시간 재사용한다(winforensics-mcp). 검증에서 뺀 룰 파일 수는 서버 로그에만 남는다(mulder). 포함 파일로 불러온 룰이 응답의 규칙 해시 목록에서 빠진다(MyIRTeam).

## 해당 기능이 있는 서버 (정하지 않음)

이 문제가 생길 수 있는 서버(분모)는 아직 정하지 않았다.

## 문제가 관찰된 서버 (4)

### [mulder](/problems/servers/mulder)

- YARA 룰 검증 결과를 경로 목록 키로 캐시한다. 코드: [src/mulder/server/tools/yara.py:142-208](https://github.com/calebevans/mulder/blob/3164843baf74c7fe69e7121dbd6150f8f77ce660/src/mulder/server/tools/yara.py#L142-L208)(_validate_rule_files, 155-158행 경로 목록 해시 키 캐시, 176·201행 뺀 수는 logger.info), 211-251(_resolve_cross_file_conflicts, 247행 로그), 585-603(응답에 결과 수·hit_metadata만), 627-631(호출 기록 인자는 rules 유무·ruleset만)

### [MyIRTeam](/problems/servers/MyIRTeam)

- 규칙의 include로 불러온 파일이 응답의 규칙 해시 목록에서 빠진다. 코드: [artifact-forensic-mcp/server.py:1008-1035](https://github.com/9-Security/MyIRTeam/blob/5fcaf7b80e2ade67b9eabacd93d64c0cdeba829c/artifact-forensic-mcp/server.py#L1008-L1035)(validate_rule_files: .yar·.yara 파일 목록만 만들고 include 줄을 보지 않음), 2202-2209(digest_rule_set: 목록 파일의 경로·SHA-256만), [artifact-forensic-mcp/server.py:2665](https://github.com/9-Security/MyIRTeam/blob/5fcaf7b80e2ade67b9eabacd93d64c0cdeba829c/artifact-forensic-mcp/server.py#L2665), 2759-2764(응답 rules.file_count·sha256), 2780(provenance rule_set_digest)

### [winforensics-mcp](/problems/servers/winforensics-mcp)

- rule_paths의 없는 경로와 다른 확장자 항목은 알리지 않고 빠지고, 다른 폴더의 같은 이름 규칙은 같은 namespace 키로 하나만 남으며, 컴파일 결과를 경로 목록 키로 1시간 재사용하는데 검사 응답에는 사용한 규칙 목록과 식별값이 없다. 코드: [winforensics_mcp/parsers/yara_scanner.py:25-27](https://github.com/x746b/winforensics-mcp/blob/cce7f360873fc9ae564296017cbffe2a603d83dd/winforensics_mcp/parsers/yara_scanner.py#L25-L27), [winforensics_mcp/parsers/yara_scanner.py:90-120](https://github.com/x746b/winforensics-mcp/blob/cce7f360873fc9ae564296017cbffe2a603d83dd/winforensics_mcp/parsers/yara_scanner.py#L90-L120), [winforensics_mcp/parsers/yara_scanner.py:122-134](https://github.com/x746b/winforensics-mcp/blob/cce7f360873fc9ae564296017cbffe2a603d83dd/winforensics_mcp/parsers/yara_scanner.py#L122-L134), [winforensics_mcp/parsers/yara_scanner.py:272-278](https://github.com/x746b/winforensics-mcp/blob/cce7f360873fc9ae564296017cbffe2a603d83dd/winforensics_mcp/parsers/yara_scanner.py#L272-L278)

### [Wireshark-MCP](/problems/servers/Wireshark-MCP)
