# C1 후속 작업이 저장된 생성 자료를 사건·증거와 대조하지 않고 고름

원고 [1.1 증거 및 사건 관리](/problems/1/1.1) · 소제목 「생성 자료와 증거의 연결」

## 현상과 피해

후속 작업이 다른 사건이나 앞선 작업에서 만든 자료를 이번 증거의 결과로 쓴다. 다른 사건의 덤프를 YARA로 검사(mulder), 다른 사건의 Security.evtx를 이번 이미지 출처로 적재(mulder), 앞 호스트의 덤프를 고를 수 있음(SAVVYDFIR-MCP), 다른 서버의 저장 파일을 받아들일 수 있음(agentic-dfir), 앞 캡처의 내보낸 파일 탐지가 이번 결과에 섞임(Wireshark-MCP), 다른 메모리 이미지의 출력과 짝지음(trudi).

## 문제가 관찰된 서버 (5)

### [agentic-dfir](/problems/servers/agentic-dfir)

- 파생 폴더 기본값이 /tmp/agentic-dfir-derived라 증거 폴더가 다른 서버들이 같은 곳에 저장 파일을 두고, sift_plaso_psort는 이 폴더 아래 저장 파일을 받아들여 다른 증거의 타임라인을 이번 결과로 읽을 수 있다. 코드: [dfir_mcp/src/dfir_mcp/sift_adapters/plaso.py:54-58](https://github.com/Juwon1405/agentic-dfir/blob/a17e90b8a3c5ab5431f0da9f354f315082257f99/dfir_mcp/src/dfir_mcp/sift_adapters/plaso.py#L54-L58), [dfir_mcp/src/dfir_mcp/sift_adapters/plaso.py:95-99](https://github.com/Juwon1405/agentic-dfir/blob/a17e90b8a3c5ab5431f0da9f354f315082257f99/dfir_mcp/src/dfir_mcp/sift_adapters/plaso.py#L95-L99)

### [mulder](/problems/servers/mulder)

- YARA 메모리 검사가 현재 사건에서 메모리 파일을 찾지 못하면 공유 폴더 cfg.db_dir/"extracted"를 rglob해 처음 찾은 후보(다른 사건의 덤프)를 검사한다. 코드: [src/mulder/server/tools/yara.py:383-393](https://github.com/calebevans/mulder/blob/3a1a317, b57f9e8/src/mulder/server/tools/yara.py#L383-L393) (3a1a317)
- run_evtx_parser의 _find_carved_evtx가 설명에 적힌 사건 DB의 bulk_extractor 출력 외에 cfg.db_dir 전체에서 .evtx를 찾아 복사해, Linux 이미지 사건에 다른 사건의 Security.evtx가 이번 이미지 출처로 적재된다. 코드: [src/mulder/server/tools/extract/evtx.py:118-123](https://github.com/calebevans/mulder/blob/3164843baf74c7fe69e7121dbd6150f8f77ce660/src/mulder/server/tools/extract/evtx.py#L118-L123) (설명 100-102)

### [SAVVYDFIR-MCP](/problems/servers/SAVVYDFIR-MCP)

- load_memory의 기본 출력 폴더 /evidence/memory를 사건·호스트마다 함께 쓰고 그 폴더 전체를 rglob해, 여러 호스트를 차례로 불러오면 앞 호스트에서 푼 덤프를 고를 수 있다. 코드: [sift_mcp/server.py:10763-10767](https://github.com/kismatkunwar89/SAVVYDFIR-MCP/blob/9ac8e47540d4826227ac8957a5c5f4caf4f6c80b/sift_mcp/server.py#L10763-L10767)(load_memory 기본 output_dir=/evidence/memory), 10829-10841(압축을 푼 뒤 output_dir 전체를 rglob해 처음 찾은 덤프); [README.md:365-378](https://github.com/kismatkunwar89/SAVVYDFIR-MCP/blob/9ac8e47540d4826227ac8957a5c5f4caf4f6c80b/README.md#L365-L378)(호스트마다 SAVVYDFIR_ANALYSIS_DIR로 상태를 나누라는 절차)

### [trudi](/problems/servers/trudi)

- correlate 도구가 기록의 tool_call 항목을 명령 문자열 부분 일치로 모아 PID로 프로세스 이름을 붙이며, 어느 메모리 이미지의 출력인지 보지 않는다. 코드: [tools/correlate.py:25-47](https://github.com/nebulae/trudi/blob/88fbca78186b6a0ca40423cf5e37a9dc46ae051e/tools/correlate.py#L25-L47), [tools/correlate.py:175-190](https://github.com/nebulae/trudi/blob/88fbca78186b6a0ca40423cf5e37a9dc46ae051e/tools/correlate.py#L175-L190)
