# 2.1-A3 반환값을 설명과 다른 뜻으로 채움

원고 [2.1 도구 설명](/problems/2/2.1) · 소제목 [2.1.2 입력 스키마와 반환 형식 정의](/problems/2/2.1/2.1.2)

## 현상과 피해

반환 필드, 경계 포함 여부, 정렬, 기록 범위가 설명과 다른 뜻으로 채워진다. 메타데이터 변경 시각을 생성 시각으로, 마지막 초를 뺀 요약을 사건 전체로, 앞 세션 호출을 이번 세션 기록으로, 가장 잘 맞는 기억을 가장 덜 맞는 것으로, 앞을 뺀 나머지를 끝 줄로 읽게 한다.

## 문제가 관찰된 서버 (6)

### [autopsy](/problems/servers/autopsy)

- summarize_timeline은 endTime을 끝을 포함하는 경계로 알리지만, 처리 함수는 같은 서버의 query_timeline과 달리 끝 경계를 1초 늘리지 않아 마지막 시각의 이벤트가 요약에서 빠진다. 코드: [Core/src/org/sleuthkit/autopsy/mcp/TskQueryService.java:1022-1030](https://github.com/sleuthkit/autopsy/blob/cb3dacdcad67abe7cf863c74f10dcdb8e25a5c21/Core/src/org/sleuthkit/autopsy/mcp/TskQueryService.java#L1022-L1030)

### [findevil](/problems/servers/findevil)

- get_audit_trail은 'every tool call made during this session'이라 알리지만, 서버를 다시 띄워도 이어 쓰는 audit.json 전체를 읽어 앞 세션의 호출이 이번 세션 기록으로 나온다. 코드: [src/findevil/tools/self_correction.py:618-636](https://github.com/marlyocat/findevil/blob/d1a8d25d9c8c05bd66881506cb1f12314ee7c5e1/src/findevil/tools/self_correction.py#L618-L636)

### [mcp-forensic-toolkit](/problems/servers/mcp-forensic-toolkit)

- file_metadata는 created_at과 프롬프트의 creation time으로 생성 시각을 알리지만, 처리 함수는 os.stat의 st_ctime(Linux에서는 메타데이터 변경 시각)을 시간대 없는 지역 시각으로 넣는다. 코드: [mcp_forensic_toolkit/server.py:79-88](https://github.com/axdithyaxo/mcp-forensic-toolkit/blob/b81db06088b2b5a3003549c98592fde40f8f3c58/mcp_forensic_toolkit/server.py#L79-L88)

### [mcp_dfir](/problems/servers/mcp_dfir)

- get_command_result의 tail을 끝에서부터의 줄 수로 알리지만, 처리 함수는 [tail:]로 잘라 앞의 tail줄을 뺀 나머지를 돌려준다. 코드: [mcp_dfir/tools/history.py:44-51](https://github.com/Androsh7/mcp_dfir/blob/305fcadb784f4f3e80cc8f8287b0ea57a007f8a5/mcp_dfir/tools/history.py#L44-L51)

### [protocol-siftpp](/problems/servers/protocol-siftpp)

- evidence_metadata의 설명·주석은 sha256을 'acquisition sha256'이라 적지만 실제 값은 서버가 첫 호출 때 처음 연 증거에서 계산한 값이다. 코드: [src/protocol_siftpp/mcp_server/server.py:57-68](https://github.com/tupils1/protocol-siftpp/blob/ae5e7d599df9aa3cbb726a9fd7dfed9fb4d98615/src/protocol_siftpp/mcp_server/server.py#L57-L68)(evidence_metadata 설명 'acquisition sha256 (chain of custody)', 값은 r.guard.sha256), :30-50(EvidenceGuard.open이 첫 도구 호출 때 증거에서 계산)

### [verdict-dfir](/problems/servers/verdict-dfir)

- memory_recall은 BM25 relevance 순으로 돌려준다고 알리지만, 관련도를 1/(1+|bm25|)로 계산해 가장 잘 맞는 행의 confidence가 가장 낮아지고 맨 뒤로 간다. 코드: [services/agent/findevil_agent/memory/store.py:118-133](https://github.com/TimothyVang/verdict-dfir/blob/acada5c6b91545639d5a470ba0d92c0e29e73063/services/agent/findevil_agent/memory/store.py#L118-L133)
