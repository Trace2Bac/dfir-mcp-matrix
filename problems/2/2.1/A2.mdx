# A2 설명과 다른 프로그램 기능이나 옵션으로 실행함

원고 [2.1 도구 설명](/problems/2/2.1) · 소제목 「설명 내용」

## 현상과 피해

포렌식 프로그램의 기능을 제공하는 도구가 설명한 기능을 실행하는 데 그 프로그램의 다른 옵션을 쓰거나 필요한 옵션을 빠뜨려, 설명한 처리가 되지 않은 결과가 정상 응답으로 나온다. 파일 식별이 폴더 한 줄로, `"false"`가 삭제 항목만으로, SHA1 지표 대조가 0건으로, 파일 수집이 0개로, TCP/UDP 통계가 TCP만으로 돌아온다.

## 문제가 관찰된 서버 (6)

### [mcp-velociraptor](/problems/servers/mcp-velociraptor)

- collect_file은 경로나 glob으로 Generic.Collectors.File 수집을 시작한다고 알리지만, 경로를 JSON 배열로 만들어 CSV를 받는 collectionSpec에 넘기고 Root를 넘기지 않아 파일 0개인 FINISHED flow로 끝난다. 코드: [mcp_velociraptor_bridge.py:1949-1960](https://github.com/mgreen27/mcp-velociraptor/blob/1f97a4f4e64d27faf07fe684d8cbfe270b57757d/mcp_velociraptor_bridge.py#L1949-L1960)

### [mulder](/problems/servers/mulder)

- run_hashdeep은 MD5·SHA1·SHA256을 만든다고 알리지만 hashdeep을 -c 없이 실행해 기본값인 MD5와 SHA256만 나오고 SHA1 IOC 대조는 0건 success가 된다. 코드: [src/mulder/server/tools/extract/misc.py:687-705](https://github.com/calebevans/mulder/blob/3164843baf74c7fe69e7121dbd6150f8f77ce660/src/mulder/server/tools/extract/misc.py#L687-L705)

### [MyIRTeam](/problems/servers/MyIRTeam)

- list_open_handles의 target에 lsass.exe를 주면 -p 없이 handle.exe의 이름 인자 자리로 넘어가, 그 프로세스의 핸들이 아니라 이름에 그 글자가 든 객체의 핸들을 찾는다(2.2 조사 MyIRTeam 9). 코드: [mcp-server/autoruns_mcp.py:1258-1273](https://github.com/9-Security/MyIRTeam/blob/5fcaf7b80e2ade67b9eabacd93d64c0cdeba829c/mcp-server/autoruns_mcp.py#L1258-L1273)(설명 'one explicit PID, process name, or path substring', 숫자만 -p로 넘기고 나머지는 handle.exe 이름 인자로); matrix reports/MyIRTeam/T/T10.mdx 각주 [16](Microsoft Learn Sysinternals handle.md: 이름 인자는 열린 객체 이름에서 찾을 조각, -p는 대상 프로세스)

### [sift-kernel](/problems/servers/sift-kernel)

- list_directory의 show_deleted를 true/false 문자열로 알리지만 값이 비어 있지 않으면 'false'여도 fls에 삭제 항목만 보이는 -d를 붙인다. 코드: [src/server.ts:161](https://github.com/Sathvik-1007/sift-kernel/blob/ea51bec90d4cb543e4aa6063af6e85ae3e4d9396/src/server.ts#L161)

### [trudi](/problems/servers/trudi)

- strings_file_identify_directory는 폴더 안 모든 파일의 형식을 식별한다고 알리지만, 처리 함수는 file -r &lt;폴더&gt;를 실행하고 GNU file의 -r은 재귀가 아니라 --raw다. 코드: [tools/strings_tools.py:262-266](https://github.com/nebulae/trudi/blob/88fbca78186b6a0ca40423cf5e37a9dc46ae051e/tools/strings_tools.py#L262-L266)
- ez.rla가 --out을 넘기지 않아 로그를 적용한 하이브를 만들지 못한다. 코드: [tools/eztools.py:626-640](https://github.com/nebulae/trudi/blob/88fbca78186b6a0ca40423cf5e37a9dc46ae051e/tools/eztools.py#L626-L640)
