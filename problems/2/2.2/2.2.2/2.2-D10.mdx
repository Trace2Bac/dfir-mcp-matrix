# 2.2-D10 없거나 종류가 다른 경로를 받아도 오류 없이 찾은 것 없음으로 응답함

원고 [2.2 도구 입력 검사](/problems/2/2.2) · 소제목 [2.2.2 경로 인자 해석과 검사](/problems/2/2.2/2.2.2)

같은 묶음의 다른 사례는 [1.4.3 분석 입력 형식 확인](/problems/1/1.4/1.4.3/2.2-D10), [2.2.1 인자 구조와 값 검사](/problems/2/2.2/2.2.1/2.2-D10), [4.1.2 결과 상태와 실패 이유 전달](/problems/4/4.1/4.1.2/2.2-D10), [4.2.3 분석 범위와 해석 한계 표시](/problems/4/4.2/4.2.3/2.2-D10)에 있다.

## 현상과 피해

없는 폴더나 대소문자가 틀린 `userProfileRoot`를 주면 `FindFilesAsync`가 빈 배열을 내고 "No browser databases ... found" 성공 응답이 돌아온다(Camel). `memory_recall`은 없는 `store_path`에 빈 SQLite를 만들고 `{"hits":[]}`를 돌려주며, 도구 설명은 빈 결과를 이전 사건 없음으로 읽으라고 한다(verdict-dfir). `hunt_ioc_pack`은 `artifacts_dir`가 있는지만 `exists()`로 보고 폴더인지는 보지 않아, 파일 경로를 주면 검사한 파일이 없어도 `found` false와 일치 없음 요약을 만든다(winforensics-mcp).

## 해당 기능이 있는 서버 (정하지 않음)

이 문제가 생길 수 있는 서버(분모)는 아직 정하지 않았다.

## 문제가 관찰된 서버 (3)

### [Camel](/problems/servers/Camel)

- WindowsAnalysisWorkflow.AnalyzeBrowserActivityAsync / userProfileRoot: 없는 폴더나 대소문자가 틀린 userProfileRoot를 주면 FindFilesAsync가 []를 내고 "No browser databases ... found" 성공이 돌아온다 코드: WindowsAnalysisWorkflow.AnalyzeBrowserActivityAsync → FindFilesAsync(없는 폴더와 일치 없음을 같은 빈 배열로)

### [verdict-dfir](/problems/servers/verdict-dfir)

- findevil-agent-mcp memory_recall / store_path: store_path에 없는 경로를 주면 그 자리에 빈 SQLite를 만들고 \{"hits":[]\}를 돌려준다(설명은 빈 결과를 이전 사건 없음으로 읽으라고 함) 코드: [services/agent_mcp/findevil_agent_mcp/tools/memory_recall.py:17](https://github.com/TimothyVang/verdict-dfir/blob/acada5c6b91545639d5a470ba0d92c0e29e73063/services/agent_mcp/findevil_agent_mcp/tools/memory_recall.py#L17) 부근(없는 store_path에 SQLite 연결을 만들어 빈 DB 생성)

### [winforensics-mcp](/problems/servers/winforensics-mcp)

- hunt_ioc_pack은 artifacts_dir가 있는지만 exists()로 확인하고 폴더인지는 보지 않은 채 root.rglob("*")로 검사할 파일을 찾으므로, 파일 경로를 주면 검사한 파일이 0개여도 found false와 No matches from &lt;팩&gt; 요약을 만든다. 코드: [winforensics_mcp/ioc_packs/behavior_hunter.py:216-230](https://github.com/x746b/winforensics-mcp/blob/cce7f360873fc9ae564296017cbffe2a603d83dd/winforensics_mcp/ioc_packs/behavior_hunter.py#L216-L230)
