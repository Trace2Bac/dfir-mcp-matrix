# 2.2-D10 대상이나 형식에 맞지 않는 인자 값을 거부하지 않고 그대로 처리함

원고 [2.2 도구 입력 검사](/problems/2/2.2) · 소제목 [2.2.1 인자 구조와 값 검사](/problems/2/2.2/2.2.1)

같은 묶음의 다른 사례는 [1.4.3 분석 입력 형식 확인](/problems/1/1.4/1.4.3/2.2-D10), [2.2.2 경로 인자 해석과 검사](/problems/2/2.2/2.2.2/2.2-D10), [4.1.2 결과 상태와 실패 이유 전달](/problems/4/4.1/4.1.2/2.2-D10), [4.2.3 분석 범위와 해석 한계 표시](/problems/4/4.2/4.2.3/2.2-D10)에 있다.

## 현상과 피해

없는 PID나 다른 운영체제 단말의 `client_id`처럼 대상과 맞지 않는 값을 주면 오류 없이 빈 결과가 돌아오거나 다른 대상의 결과가 돌아온다(VolPilot, mcp-velociraptor). `windows_pedump`의 `base`, `pid`, `kernel_module` 조합이나 `dataSourceId`, `artifactType`이 사건과 도구에 맞는지 검사하지 않고 실행하거나 조회한다(VolPilot, autopsy).

## 해당 기능이 있는 서버 (정하지 않음)

이 문제가 생길 수 있는 서버(분모)는 아직 정하지 않았다.

## 문제가 관찰된 서버 (3)

### [autopsy](/problems/servers/autopsy)

- queryArtifactsInternal은 dataSourceId를 사건의 데이터 소스와 대조하지 않고 0 이상이면 data_source_obj_id 조건으로, 음수이면 조건 없이 쓰며, artifactType이 데이터 아티팩트 유형인지 분석 결과 유형인지도 보지 않고 도구에 맞는 표만 조회한다. 코드: [Core/src/org/sleuthkit/autopsy/mcp/TskQueryService.java:609-625](https://github.com/sleuthkit/autopsy/blob/cb3dacdcad67abe7cf863c74f10dcdb8e25a5c21/Core/src/org/sleuthkit/autopsy/mcp/TskQueryService.java#L609-L625)

### [mcp-velociraptor](/problems/servers/mcp-velociraptor)

- OS별 수집 도구(windows_pslist, macos_pslist) / client_id: Linux 단말의 client_id로 windows_pslist를 부르면 precondition으로 건너뛰어 ok:true 빈 목록이 돌아오고, macos_pslist를 부르면 그 Linux 단말의 프로세스 81행이 돌아온다 코드: [mcp_velociraptor_bridge.py:704](https://github.com/mgreen27/mcp-velociraptor/blob/1f97a4f4e64d27faf07fe684d8cbfe270b57757d/mcp_velociraptor_bridge.py#L704) 부근(OS별 수집 도구가 client의 OS를 대조하지 않음)

### [VolPilot](/problems/servers/VolPilot)

- windows_pedump은 설명에 pid를 선택 인자로, kernel_module=True일 때 무시된다고 적고, run_pedump은 base, pid, kernel_module 조합을 검사하지 않고 Volatility PEDump에 넘긴 뒤 결과 표만 results로 돌려준다. 코드: [plugins/module.py:86-97](https://github.com/cpuu/VolPilot/blob/5c848519cfa2e86a86abbe613c7249fddeffc6df/plugins/module.py#L86-L97)
- pid 필터 도구 7개(windows_malware_hollowprocesses 등) / pid: pslist에 없는 PID(오타, 다른 이미지, detect_hidden_processes의 숨은 PID)를 주면 오류 없이 빈 results가 돌아오고 같은 값을 triage_process는 not found로 거부한다 코드: [mcp_server.py:225](https://github.com/cpuu/VolPilot/blob/5c848519cfa2e86a86abbe613c7249fddeffc6df/mcp_server.py#L225) 이하(triage_process는 pslist에 없는 PID를 거부); pid 필터 플러그인 도구 7개(plugins/)는 대조 없이 --pid로 실행
