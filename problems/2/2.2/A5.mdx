# A5 일부 진입점에서 같은 검사를 거치지 않음

원고 [2.2 도구 입력 검사](/problems/2/2.2) · 소제목 「인자 구조와 값 검사」

## 현상과 피해

직접 호출에서는 걸리는 값이 다른 진입점으로 들어오면 검사를 거치지 않는다. 다른 분석 실행(mulder 묶음), 0건 성공(agentic-dfir), 사건 밖 출력 파일(sift-mcp), 뒤의 조회까지 실패(mulder 수정 도구), 예외 문구가 `isError` 거짓으로(winforensics-mcp).

## 문제가 관찰된 서버 (5)

### [agentic-dfir](/problems/servers/agentic-dfir)

- python3 -m dfir_mcp.server로 띄운 서버의 tools/call이 거치는 _validate_arguments는 배열 인자의 최상위 자료형만 보고 items 자료형은 보지 않으며, sift_evtxecmd_filter_eids는 받은 event_ids로 집합을 만들어 문자열로 바꾼 EventId와 비교한다. 코드: [dfir_mcp/src/dfir_mcp/__init__.py:175-188](https://github.com/Juwon1405/agentic-dfir/blob/a17e90b8a3c5ab5431f0da9f354f315082257f99/dfir_mcp/src/dfir_mcp/__init__.py#L175-L188)

### [Cyber-Incident-Investigation-and-Triage-MCP-Server](/problems/servers/Cyber-Incident-Investigation-and-Triage-MCP-Server)

- call_tool은 tools/list에 없는 list_files와 browse_prepared_image_files도 browse_files_and_folders와 같은 처리기로 보내는데, MCP Python SDK 저수준 서버는 목록에 있는 이름에만 inputSchema 검사를 적용하므로, 목록에 없는 이름을 직접 보내는 클라이언트에서는 이 두 이름이 자료형과 필수 인자 검사 없이 처리기에 닿는다. 코드: [server.py:546-554](https://github.com/abhiii011/Cyber-Incident-Investigation-and-Triage-MCP-Server/blob/39e85090231cf0c9b7edcb1700d169372e50d8b1/server.py#L546-L554)

### [mulder](/problems/servers/mulder)

- run_parallel과 start_extraction_batch는 도구 함수를 직접 꺼내 validate_tool_args로 매개변수 이름만 확인한 뒤 부르므로 mode의 Literal 허용 값 검사를 거치지 않고, run_chainsaw는 hunt, search, srum이 아닌 mode를 모두 마지막 else 분기의 timeline으로 처리한다. 코드: [src/mulder/server/app.py:699-709](https://github.com/calebevans/mulder/blob/3164843baf74c7fe69e7121dbd6150f8f77ce660/src/mulder/server/app.py#L699-L709)
- update_finding은 evidence_refs의 ID가 감사 기록에 있는지만 확인하고 severity, confidence, 빈 evidence_refs를 Finding 모델로 검사하지 않은 채 ctx.db.update_finding으로 저장하며, 저장한 행을 get_finding으로 다시 읽을 때 비로소 모델 검사가 실패한다. 코드: [src/mulder/server/tools/findings.py:450-467](https://github.com/calebevans/mulder/blob/3164843baf74c7fe69e7121dbd6150f8f77ce660/src/mulder/server/tools/findings.py#L450-L467)

### [sift-mcp](/problems/servers/sift-mcp)

- run_command의 설명은 도구 자체의 출력 옵션은 검사하지 않는다고 적지만 command[0]의 실행 파일 이름으로 출력 플래그(get_output_flags)와 플래그 정책(sanitize_extra_args)을 찾아 검사하고, 카탈로그는 psort를 psort.py와 같은 도구로 등록하고도 출력 플래그 -w는 psort.py에만 두며, nice로 감싼 명령에는 감싼 도구의 정책이 적용되지 않는다. 코드: [packages/sift-mcp/src/sift_mcp/tools/generic.py:98-113](https://github.com/AppliedIR/sift-mcp/blob/5ef6081a35252380ffe5456dca1a5f3355fbe01a/packages/sift-mcp/src/sift_mcp/tools/generic.py#L98-L113)
