# 3.2-C2 검증 결과가 불완전과 변경, 기준값 없음을 가르지 않거나 기록 시점의 판정을 지금 상태처럼 옮김

원고 [3.2 파생물 관리](/problems/3/3.2) · 소제목 [3.2.3 파생물 기준값 보관과 대조](/problems/3/3.2/3.2.3)

같은 묶음의 다른 사례는 [3.1.3 호출 기록 보관과 변경 확인](/problems/3/3.1/3.1.3/3.2-C2)에 있다.

## 현상과 피해

기준값이 없는 source(`no_hash_recorded`)가 있어도 `modified`가 없으면 `verify_evidence_integrity`의 전체 상태가 `all_verified`이고 일부만 적재된 source도 `verified`가 되며, 저장된 `source_hash`와 `line_count`는 검증에 쓰지 않는다(mulder). 같은 `-o` 경로로 바뀐 앞 출력을 인용한 발견사항은 `CITED-UNVERIFIED`가 되지만 이유는 인용 줄이 출력에 없다는 것뿐이라 기록 뒤 변경과 처음부터 없음을 가르지 않고, 바뀌기 전에 기록한 발견사항은 다시 대조하지 않으며 보고서는 저장된 출처 판정을 옮겨 적는다(sift-mcp).

## 문제가 관찰된 서버 (2)

### [mulder](/problems/servers/mulder)

- 기준값이 없는 source(no_hash_recorded)가 있어도 modified가 없으면 verify_evidence_integrity의 전체 상태가 all_verified이고(같은 응답의 no_hash_count와 모순), 일부만 적재된 source도 verified다. 전체 출력 해시 source_hash와 line_count는 저장되지만 검증에 쓰이지 않는다 코드: [src/mulder/db.py:1254-1310](https://github.com/calebevans/mulder/blob/3164843baf74c7fe69e7121dbd6150f8f77ce660/src/mulder/db.py#L1254-L1310); [src/mulder/server/tools/case.py:446-459](https://github.com/calebevans/mulder/blob/3164843baf74c7fe69e7121dbd6150f8f77ce660/src/mulder/server/tools/case.py#L446-L459)

### [sift-mcp](/problems/servers/sift-mcp)

- 같은 -o 경로로 바뀐 앞 호출 출력을 인용한 발견사항은 CITED-UNVERIFIED가 되지만 이유 문장이 인용 줄이 출력에 없다는 것뿐이라 기록 뒤 변경과 처음부터 없음을 가르지 않고, 바뀌기 전에 기록한 발견사항은 다시 대조하지 않으며 보고서는 저장된 출처 판정을 옮겨 적는다 코드: [packages/report-mcp/src/report_mcp/server.py:738-742](https://github.com/AppliedIR/sift-mcp/blob/5ef6081a35252380ffe5456dca1a5f3355fbe01a/packages/report-mcp/src/report_mcp/server.py#L738-L742); Valhuntir d9ab927 [src/vhir_cli/provenance_view.py:1-7](https://github.com/AppliedIR/sift-mcp/blob/5ef6081a35252380ffe5456dca1a5f3355fbe01a/src/vhir_cli/provenance_view.py#L1-L7); src/vhir_cli/approval_checks.py
