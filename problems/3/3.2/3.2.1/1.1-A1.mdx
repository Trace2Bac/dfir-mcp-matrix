# 1.1-A1 출력 위치 이름이 입력 경로나 사건, 호스트를 구별하지 않아 다른 입력이 같은 위치를 받음

원고 [3.2 파생물 관리](/problems/3/3.2) · 소제목 [3.2.1 파생물 저장 위치와 이름 결정](/problems/3/3.2/3.2.1)

같은 묶음의 다른 사례는 [1.1.2 사건 식별과 증거 연결](/problems/1/1.1/1.1.2/1.1-A1), [1.1.4 실행 환경 연결과 재사용](/problems/1/1.1/1.1.4/1.1-A1)에 있다.

## 현상과 피해

출력 폴더나 파일 이름을 입력 파일의 stem이나 파일 이름만으로 정해, 다른 폴더의 같은 이름 메모리 덤프, 하이브(`NTUSER.DAT`), 이미지가 같은 출력 위치를 받고 앞 결과가 덮어쓰이거나 실행 전에 지워진다(Cyber-Incident-Investigation-and-Triage-MCP-Server, verdict-dfir). SRUM 내보내기 폴더를 `case_id` 앞 20자로 정해 앞 20자가 같은 사건 ID나 같은 사건의 다른 호스트가 같은 폴더를 받는다(SAVVYDFIR-MCP). `remote_collect_artifacts`는 `output_dir/evtx/<이름>.evtx`처럼 호스트 구분 없는 고정 이름으로 써서, 같은 수집 폴더로 모은 앞 단말의 증거 사본이 알림 없이 바뀐다(winforensics-mcp).

## 해당 기능이 있는 서버 (정하지 않음)

이 문제가 생길 수 있는 서버(분모)는 아직 정하지 않았다.

## 문제가 관찰된 서버 (4)

### [Cyber-Incident-Investigation-and-Triage-MCP-Server](/problems/servers/Cyber-Incident-Investigation-and-Triage-MCP-Server)

- 메모리 분석 출력 폴더를 CASES_DIR/memory_file.stem/memory/&lt;plugin&gt;으로 정하고 결과 파일을 플러그인 이름으로 'w' 모드에 써서, 다른 폴더의 같은 이름 덤프 결과가 같은 파일에 덮어쓰인다. 코드: [handlers/memory_forensics_handler.py:112-116](https://github.com/abhiii011/Cyber-Incident-Investigation-and-Triage-MCP-Server/blob/39e85090231cf0c9b7edcb1700d169372e50d8b1/handlers/memory_forensics_handler.py#L112-L116), [handlers/memory_forensics_handler.py:121-131](https://github.com/abhiii011/Cyber-Incident-Investigation-and-Triage-MCP-Server/blob/39e85090231cf0c9b7edcb1700d169372e50d8b1/handlers/memory_forensics_handler.py#L121-L131)
- analyze_registry 출력 폴더 이름에 입력 파일의 stem을 쓰고 준비한 이미지가 아닌 입력은 모두 local_analysis에 두어, 다른 사용자의 같은 이름 하이브(NTUSER.DAT)가 같은 출력 폴더를 받는다. 코드: [handlers/registry_forensics_handler.py:320-332](https://github.com/abhiii011/Cyber-Incident-Investigation-and-Triage-MCP-Server/blob/39e85090231cf0c9b7edcb1700d169372e50d8b1/handlers/registry_forensics_handler.py#L320-L332)

### [SAVVYDFIR-MCP](/problems/servers/SAVVYDFIR-MCP)

- SRUM 내보내기 폴더를 /cases/srum/&lt;case_id 앞 20자&gt;로 정해, 앞 20자가 같은 사건 ID나 같은 사건의 다른 호스트가 같은 폴더를 받는다. 코드: [sift_mcp/server.py:6908-6914](https://github.com/kismatkunwar89/SAVVYDFIR-MCP/blob/9ac8e47540d4826227ac8957a5c5f4caf4f6c80b/sift_mcp/server.py#L6908-L6914) (shimcache 6645-6653도 앞 20자)

- bulk_extract 출력 폴더 이름에 이미지 경로가 아니라 파일 이름만 들어가, 다른 폴더의 같은 이름 이미지가 같은 출력 폴더를 쓰고 실행 전에 앞 출력이 지워진다. 코드: [services/mcp/src/tools/bulk_extract.rs:309-320](https://github.com/TimothyVang/verdict-dfir/blob/acada5c6b91545639d5a470ba0d92c0e29e73063/services/mcp/src/tools/bulk_extract.rs#L309-L320)(sanitize_stem 폴더를 실행 전에 remove_dir_all), 543-555(sanitize_stem이 file_name만 씀)
