# 3.1-E2 기록 밖 끝 값이 없거나 고정한 키에 묶이지 않아 끝 잘림, 전체 삭제, 재작성이 검증을 통과함

원고 [3.1 도구 호출 기록](/problems/3/3.1) · 소제목 [3.1.3 호출 기록 보관과 변경 확인](/problems/3/3.1/3.1.3)

## 현상과 피해

체인을 다시 쓴 기록을 다른 키나 같은 서버의 `manifest_finalize`로 다시 봉인하면 검증이 통과한다(verdict-dfir). 없는 경로의 `audit_verify`가 `ok: true, record_count: 0`이다(verdict-dfir). 끝 항목을 지운 목록을 번호로 가를 수 없고 중간 삭제 뒤 번호가 겹친다(mcp_dfir). 인자 없는 초기화가 원장을 비우고 GENESIS부터 다시 유효하다(sift-kernel, 원고 서술).

## 문제가 관찰된 서버 (3)

### [mcp_dfir](/problems/servers/mcp_dfir)

- 명령 기록 번호를 목록 길이로 매겨 끝 항목을 지운 목록은 번호로 가를 수 없고, 중간 항목을 지운 뒤 명령을 더 실행하자 같은 번호가 둘이 되어 결과 본문 파일이 새 출력으로 바뀌었다 코드: [mcp_dfir/data_manager.py:44-49](https://github.com/Androsh7/mcp_dfir/blob/305fcadb784f4f3e80cc8f8287b0ea57a007f8a5/mcp_dfir/data_manager.py#L44-L49)

### [sift-kernel](/problems/servers/sift-kernel)

- 인자 없는 reset_investigation이 ledger 표를 비우고 다음 항목은 GENESIS 해시로 시작해, 빈 기록도 새로 쌓은 기록도 유효로 검증된다 코드: reports/sift-kernel/L/L04.mdx L04.01 근거 [3][4][9]; [src/server.ts:362](https://github.com/Sathvik-1007/sift-kernel/blob/ea51bec90d4cb543e4aa6063af6e85ae3e4d9396/src/server.ts#L362) (destructiveHint true)

### [verdict-dfir](/problems/servers/verdict-dfir)

- manifest_verify가 ed25519 서명을 manifest 안의 공개 키로만 검증하고 서명 종류를 서명 대상 밖 signature.kind에서 읽어, 체인을 다시 쓴 기록을 다른 키나 같은 서버의 manifest_finalize로 다시 봉인하면 overall과 signature_verified가 참이었다 코드: [services/agent/findevil_agent/crypto/manifest.py:440-444](https://github.com/TimothyVang/verdict-dfir/blob/acada5c6b91545639d5a470ba0d92c0e29e73063/services/agent/findevil_agent/crypto/manifest.py#L440-L444), [services/agent/findevil_agent/crypto/manifest.py:476-484](https://github.com/TimothyVang/verdict-dfir/blob/acada5c6b91545639d5a470ba0d92c0e29e73063/services/agent/findevil_agent/crypto/manifest.py#L476-L484), [services/agent/findevil_agent/crypto/manifest.py:529-556](https://github.com/TimothyVang/verdict-dfir/blob/acada5c6b91545639d5a470ba0d92c0e29e73063/services/agent/findevil_agent/crypto/manifest.py#L529-L556)
- 없는 경로로 부른 audit_verify가 ok true, record_count 0을 돌려주어 파일 없음과 빈 기록, 검증 통과를 구분하지 않는다. 중간 줄이 빠진 파일은 ok false가 아니라 handler 오류로 끝난다 코드: 매트릭스 L04 근거 [4][5][10]
