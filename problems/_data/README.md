# problems/_data — 문제 매트릭스 데이터

`problems/`의 페이지는 이 폴더의 CSV에서 `tools/problems_build.py`가 만든다. 페이지 파일은 손으로 고치지 않는다. 데이터를 고친 뒤 다시 만든다.
같은 스크립트가 화면 데이터 `problems.json`도 만든다. 사이트의 `problems-data` 플러그인이 이 파일을 `web/static/data/`로 옮기고, 첫 화면 지도와 항목 화면이 이 파일을 읽는다.

```
python tools/problems_build.py
```

| 파일 | 내용 |
|---|---|
| `chapters.csv` | 장 1~4 |
| `cells.csv` | 항목 1.1~4.4와 이름 |
| `headings.csv` | 소제목과 소제목ID(`1.3.2` = 항목 1.3의 두 번째 소제목) |
| `problems.csv` | 문제: 문제ID(`P0001`), 소제목ID, 문제, 현상과 피해, 근거 대장의 묶음(대장ID) |
| `servers.csv` | 서버와 저장소 |
| `snapshots.csv` | 분석 회차: 서버, 커밋, 커밋일, 분석일, 범위, 메모 |
| `findings.csv` | 근거: 서버, 커밋, 문제ID, 판정(관찰됨·문제 없음), 추정, 출처, 코드 위치, 요지, 링크 |
| `verifications.csv` | 실행 검증: 문제ID, 서버, 방법(PoC·시험·모델 실험), 수준, 커밋, 결과, 근거, 메모 |

## 판정

판정은 서버의 한 커밋에서 문제 하나를 본 결과다. 직접 적는 판정은 둘뿐이다.

- `관찰됨`: 문제가 있다. 근거에 문제가 있는 코드 위치를 적는다.
- `문제 없음`: 기능이 있고 제대로 구현했다. 근거에 그렇게 구현한 코드 위치나 고친 PR을 적는다.

나머지는 계산한다.

| 화면의 판정·변화 | 계산 |
|---|---|
| 기능 없음 | 그 회차의 범위 안인데 근거 줄이 없다 |
| 확인 안 함 | 어느 회차의 범위에도 들지 않았다(새 서버, 새 문제, 분모를 정하지 않은 문제) |
| 고쳐짐 | 앞 회차에서 관찰됨, 마지막 회차에서 문제 없음 |
| 다시 생김 | 앞 회차에서 문제 없음, 마지막 회차에서 관찰됨 |
| 확인 커밋 | 그 문제의 판정이 있는 가장 늦은 회차의 커밋 |

`추정`이 `예`인 줄은 근거 대장의 묶음 분모에서 옮긴 `문제 없음`이다. 코드로 다시 확인하면 그 줄을 지우고 근거를 적은 줄을 더한다.
`출처`가 `대장`인 줄은 `problems_export_from_ledger.py`가 다시 쓴다. 사람이 더한 줄은 출처를 비우고, 내보내기가 덮어쓰지 않는다.

## 분석 회차

회차 하나는 서버의 한 커밋에서 어디까지 봤는지다. 서버마다 커밋일 차례로 놓는다.

- 범위는 `전체`, 항목(`1.3`), 문제(`P0025`)를 공백으로 나열하고, 앞에 `-`를 붙이면 뺀다. 예: `전체 -P0003`, `1.3 P0102`.
- 서버마다 첫 `전체` 회차의 커밋이 기준 커밋이다.
- 근거 줄은 그 회차의 범위 안 문제에만 적을 수 있다. 범위 밖이면 `problems_build.py`가 멈춘다.
- 서버의 새 버전에서 일부 문제만 다시 보면 그 문제만 범위로 하는 회차를 더하고, 본 결과를 근거로 적는다. 나머지 문제는 앞 회차의 판정이 그대로 남는다.
- 새 서버는 회차를 더하고 본 문제만 범위로 적는다. 아직 보지 않은 문제는 확인 안 함으로 보인다.
- 새 문제를 더하면, 그 문제를 범위에 넣은 회차가 없는 서버는 모두 확인 안 함이 된다.

## 검증 방법

모든 근거는 코드 확인(정적 분석)에서 시작한다. 실행으로 더 확인하면 `verifications.csv`에 한 줄을 더한다.

| 방법 | 하는 일 | 결과 |
|---|---|---|
| PoC | 그 서버에 맞춘 재현 스크립트를 돌려 문제를 보인다 | 재현됨 · 재현 안 됨 |
| 시험 | 정한 판정 기준으로 통과·실패를 가린다. 같은 시험을 여러 서버와 커밋에 돌릴 수 있다 | 통과 · 실패 |
| 모델 실험 | 결함이 있을 때와 고쳤을 때 AI의 답을 여러 번 비교한다 | 영향 있음 · 영향 없음 |

수준은 `함수`, `MCP`, `에이전트`로 적고, 모르면 비운다. PoC와 시험의 코드와 기록은 dfir-mcp-bench에 둔다.

## 식별자

- 소제목ID는 `<항목>.<순서>`다(`1.3.2`). 항목 안에서 소제목의 차례가 바뀌면 함께 바뀐다.
- 문제ID는 `P`와 네 자리 번호다(`P0001`). 소제목과 따로 매기므로 문제를 다른 소제목으로 옮겨도 바뀌지 않는다. 지운 번호는 다시 쓰지 않고, 새 문제는 마지막 번호 다음 번호를 받는다.

구조 파일과 출처가 `대장`인 근거는 저장소 밖의 근거 대장에서 `tools/problems_export_from_ledger.py`로 내보낸다. 근거 대장은 사례마다 근거의 강도(원자료로 재현, 코드 확인 등)와 시험 기록을 관리하며, 이 매트릭스는 그 가운데 문제와 서버만 싣는다. 추정 판정은 근거 대장의 묶음 분모에서 왔고, 21개 서버를 코드로 다시 판정한 묶음(지금은 1.3 B2)만 그 결과로 바꿨다.
