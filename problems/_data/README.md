# problems/_data — 문제 매트릭스 데이터

`problems/`의 페이지는 이 폴더의 CSV에서 `tools/problems_build.py`가 만든다. 페이지 파일은 손으로 고치지 않는다. 데이터를 고친 뒤 다시 만든다.
같은 스크립트가 화면 데이터 `problems.json`도 만든다. 사이트의 `problems-data` 플러그인이 이 파일을 `web/static/data/`로 옮기고, 첫 화면의 격자와 원고 화면의 패널이 이 파일을 읽는다.

```
python tools/problems_build.py
```

| 파일 | 내용 |
|---|---|
| `chapters.csv` | 축: 가이드라인의 장 1~4와 범위(장 이름은 가안) |
| `cells.csv` | 셀: 원고 1.1~4.4와 이름 |
| `headings.csv` | 상세: 원고의 소제목(서버가 수행하는 처리) 번호, 이름, 처리 설명과 그 아래 문제 번호(L2 목차와 소제목 개편안 2026-11-24 기준) |
| `problems.csv` | 문제: 소제목, 문제 번호(처음 정리한 원고와 묶음, 예: 1.1-A1), 문제, 현상과 피해, 해당 기능이 있는 서버, 문제가 관찰된 서버, 같은 묶음이 놓인 소제목들(갈린 경우) |
| `observations.csv` | 문제가 관찰된 서버의 사례: 소제목, 문제 번호, 요지, 코드 위치, 저장소, 기준 커밋 |
| `experiments.csv` | 수정 전후 검증 실험(Trace2Bac/dfir-mcp-bench)과 문제 번호의 대응 |
| `servers.csv` | 서버 21개의 저장소와 기준 커밋 |

이 CSV는 저장소 밖의 근거 대장에서 `tools/problems_export_from_ledger.py`로 내보낸다. 근거 대장은 사례마다 근거의 강도(원자료로 재현, 코드 확인 등)와 시험 기록을 관리하며, 이 매트릭스는 그 가운데 문제와 서버만 싣는다. "해당 기능이 있는 서버"는 매트릭스 셀 상세에서 정한 묶음 분모이고, 21개 서버를 코드로 다시 판정한 묶음(지금은 1.3 B2)만 그 결과로 바꿨다.

문제 하나는 "소제목에 놓인 원래 묶음"이다. 개편안은 사례마다 소제목을 정했으므로, 한 묶음의 사례가 여러 소제목에 갈리면 소제목마다 그 소제목의 사례만 싣는다. 갈린 문제는 분모를 정하지 않고, 묶음 전체를 서술한 "현상과 피해"도 싣지 않는다(소제목별 서술을 정리한 뒤 싣는다). 매트릭스에는 기준 커밋의 코드 위치가 있는 사례만 싣고, 개편안에서 배치를 보류한 사례(새 항목 후보 범위)는 싣지 않는다.
