# C1 주의나 상태 값을 붙이는 조건이 그 뜻과 맞지 않음

원고 [4.2 결과 해석 정보 표시](/problems/4/4.2) · 소제목 「분석 범위와 해석 한계」

## 현상과 피해

로그 삭제 흔적만 있어도 보안 삭제 도구 문장이 붙거나(mulder), 양방향 캡처에서도 단방향 캡처 표시가 참이 된다(Wireshark-MCP). 같은 응답의 다른 필드와 대조하면 알 수 있어 피해는 중간이다.

## 문제가 관찰된 서버 (2)

### [mulder](/problems/servers/mulder)

- `assess_recovery`의 `_build_recovery_assessment`는 `anti_forensics` 목록이 비어 있지 않기만 하면 `evidence_gaps`에 "Secure delete tools detected -- some deleted files may be unrecoverable"을 넣는다. 이 목록에는 `log_clearing`도 들어가 이벤트 로그 삭제 흔적만 있어도 보안 삭제 도구 문장이 붙는다. 코드: [src/mulder/server/tools/composite/misc.py:527-546](https://github.com/calebevans/mulder/blob/3164843baf74c7fe69e7121dbd6150f8f77ce660/src/mulder/server/tools/composite/misc.py#L527-L546), [src/mulder/server/tools/composite/misc.py:585-604](https://github.com/calebevans/mulder/blob/3164843baf74c7fe69e7121dbd6150f8f77ce660/src/mulder/server/tools/composite/misc.py#L585-L604)

### [Wireshark-MCP](/problems/servers/Wireshark-MCP)

- `wireshark_detect_dos_attack`은 단방향 캡처 의심 경고를 SYN 50개 초과·SYN-ACK 0일 때만 더하지만, 발견사항의 `constraints.single_sided`는 `bool(warnings)`라 UDP 5,000개·DNS 증폭 1,000개·SYN 상한 경고나 조회 실패 경고만 있어도 참이 된다. 코드: [src/wireshark_mcp/tools/threat.py:451-608](https://github.com/bx33661/Wireshark-MCP/blob/0e1b6595a2dcfe097133deb1c0c3128fb7a110d4/src/wireshark_mcp/tools/threat.py#L451-L608), [src/wireshark_mcp/tools/threat.py:714](https://github.com/bx33661/Wireshark-MCP/blob/0e1b6595a2dcfe097133deb1c0c3128fb7a110d4/src/wireshark_mcp/tools/threat.py#L714), [src/wireshark_mcp/tools/threat.py:734](https://github.com/bx33661/Wireshark-MCP/blob/0e1b6595a2dcfe097133deb1c0c3128fb7a110d4/src/wireshark_mcp/tools/threat.py#L734), [src/wireshark_mcp/tools/threat.py:757](https://github.com/bx33661/Wireshark-MCP/blob/0e1b6595a2dcfe097133deb1c0c3128fb7a110d4/src/wireshark_mcp/tools/threat.py#L757), [src/wireshark_mcp/tools/threat.py:779](https://github.com/bx33661/Wireshark-MCP/blob/0e1b6595a2dcfe097133deb1c0c3128fb7a110d4/src/wireshark_mcp/tools/threat.py#L779)
