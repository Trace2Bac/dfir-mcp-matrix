# C4 부재를 단정할 수 없는 조건을 알리지 않고 부재·정상·배제로 냄

원고 [4.2 결과 해석 정보 표시](/problems/4/4.2) · 소제목 「분석 범위와 해석 한계」

## 현상과 피해

회전 로그에만 있는 설치 기록이 반증으로 판정되고, 끊긴 캡처의 부재가 `confirmed`로 나가며, "수집하지 않음"과 "보지 못함"이 구별되지 않는다.

## 문제가 관찰된 서버 (7)

### [Camel](/problems/servers/Camel)

- `FindFilesAsync`는 종료 코드를 보지 않고 표준 출력만 읽어, 없는 폴더·`find` 실패·일치 없음이 같은 빈 배열이 되고 읽지 못한 하위 항목이 있어도 표시 없이 일부 결과만 나간다(설명과 주석에 밝혀 둔 설계). 코드: [src/Camel.Toolkits/DiskAnalysis/DiskAnalysisToolkit.cs:224-235](https://github.com/allisterb/Camel/blob/63f4cb2e26a2469a35f847bee607516cf6184e91/src/Camel.Toolkits/DiskAnalysis/DiskAnalysisToolkit.cs#L224-L235), 238-256

### [findevil](/problems/servers/findevil)

- `verify_finding`의 `_verify_package_installed`는 `var/log/apt/history.log`와 `var/log/dpkg.log` 두 파일만 읽고, 둘 다 없거나 설치 기록이 없으면 `CONTRADICTED`와 "no apt/dpkg install event … found"를 돌려준다. 읽은 로그 파일과 회전 로그(`.1`, `.gz`)를 보지 않았다는 사실은 근거 문장에 없다. 코드: [src/findevil/tools/self_correction.py:185-211](https://github.com/marlyocat/findevil/blob/d1a8d25d9c8c05bd66881506cb1f12314ee7c5e1/src/findevil/tools/self_correction.py#L185-L211), 336-359
- `verify_package_integrity`는 MD5를 계산하지 못한 파일도 `files_checked`에 세고, 불일치가 없으면 "This rules out the timestomped-sshd class of attack"을 고른다. 코드: [src/findevil/tools/linux_packages.py:566-569](https://github.com/marlyocat/findevil/blob/d1a8d25d9c8c05bd66881506cb1f12314ee7c5e1/src/findevil/tools/linux_packages.py#L566-L569), 617-623

### [mulder](/problems/servers/mulder)

- `windowed_response`를 쓰는 조회 도구는 source 적재 여부와 관계없이 `status: success`, `result_count`, `total_windows`만 실어, 자료를 만들지 않은 상태의 0건이 자료 없음과 같다. 코드: [src/mulder/server/helpers.py:274-312](https://github.com/calebevans/mulder/blob/3164843baf74c7fe69e7121dbd6150f8f77ce660/src/mulder/server/helpers.py#L274-L312)

### [MyIRTeam](/problems/servers/MyIRTeam)

- `ingest_analysis_report`의 `shape_summary`는 Guided Hunt의 `rule_matches`·`hypothesis_templates`만 옮기고 `enabled`·`notes`를 버려 꺼진 경우와 일치가 없는 경우의 응답이 같고, IR_Collect `summary_v3`의 `collection_coverage`(complete·partial·failed·skipped·missing)가 있는데도 `artifact_coverage`를 늘 `NOT_PROVIDED_BY_SUMMARY_SCHEMA`로 적는다. 코드: [ir-collect-mcp/server.py:553-623](https://github.com/9-Security/MyIRTeam/blob/5fcaf7b80e2ade67b9eabacd93d64c0cdeba829c/ir-collect-mcp/server.py#L553-L623); IR_Collect b32c3d7 [src/Analysis/GuidedHunt.cs:95-139](https://github.com/9-Security/MyIRTeam/blob/5fcaf7b80e2ade67b9eabacd93d64c0cdeba829c/src/Analysis/GuidedHunt.cs#L95-L139), [src/Analysis/SummaryExport.cs:44](https://github.com/9-Security/MyIRTeam/blob/5fcaf7b80e2ade67b9eabacd93d64c0cdeba829c/src/Analysis/SummaryExport.cs#L44)

### [protocol-siftpp](/problems/servers/protocol-siftpp)

- Volatility 3 pslist는 목록 머리가 유효하지 않으면 예외 없이 끝나고 서버 응답은 `exit_code` 0, 빈 `result`, `row_count` 0이다. 실행 중인 Windows에서 프로세스 0개라는 결과가 해석 주의 없이 정상 결과로 온다(저장소 `docs/ACCURACY_REPORT.md`는 같은 현상을 심볼·KDBG 해석 실패로 설명). 코드: [src/protocol_siftpp/mcp_server/volatility.py:196-225](https://github.com/tupils1/protocol-siftpp/blob/ae5e7d599df9aa3cbb726a9fd7dfed9fb4d98615/src/protocol_siftpp/mcp_server/volatility.py#L196-L225); [docs/ACCURACY_REPORT.md:70](https://github.com/tupils1/protocol-siftpp/blob/ae5e7d599df9aa3cbb726a9fd7dfed9fb4d98615/docs/ACCURACY_REPORT.md#L70), 120, 142

### [VolPilot](/problems/servers/VolPilot)

- `windows_virtmap`은 커널 심볼에 필요한 항목이 없을 때 `SymbolError`를 받아 `{"plugin": "virtmap", "results": []}`를 돌려줘, 적용할 수 없는 경우가 매핑 영역이 없는 결과와 같은 모양이다. 코드: [plugins/memory.py:46-59](https://github.com/cpuu/VolPilot/blob/5c848519cfa2e86a86abbe613c7249fddeffc6df/plugins/memory.py#L46-L59)

### [Wireshark-MCP](/problems/servers/Wireshark-MCP)

- tshark가 패킷 중간에서 끊긴 캡처를 알리면 실행기는 성공 응답에 그 알림을 `stderr`로 싣는데, `wireshark_detect_dns_tunnel`·`wireshark_detect_port_scan`은 이를 보지 않아 경고 없이 `complete`와 `confirmed` 부재 발견사항을 싣는다. 질의 5,000개 상한에 닿은 경우는 `partial`을 싣지만 부재 발견사항은 `confirmed`다. 코드: [src/wireshark_mcp/tools/threat.py:255-275](https://github.com/bx33661/Wireshark-MCP/blob/0e1b6595a2dcfe097133deb1c0c3128fb7a110d4/src/wireshark_mcp/tools/threat.py#L255-L275), 404-420; [src/wireshark_mcp/tshark/client.py:598-609](https://github.com/bx33661/Wireshark-MCP/blob/0e1b6595a2dcfe097133deb1c0c3128fb7a110d4/src/wireshark_mcp/tshark/client.py#L598-L609), 631-632
