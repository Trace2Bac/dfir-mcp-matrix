# 4.1-E2 서버가 처리한 실패를 isError 없이 본문의 필드나 문장으로만 알림

원고 [4.1 실행 결과 상태 구분](/problems/4/4.1) · 소제목 [4.1.2 결과 상태와 실패 이유 전달](/problems/4/4.1/4.1.2)

## 현상과 피해

서버 처리기가 알아챈 실패(없는 파일, 없는 대상, 외부 명령 실패, 없는 도구 이름)가 본문 필드나 오류 문장으로만 오고 MCP 결과로는 성공이다. 같은 서버에서 처리하지 않은 예외나 SDK 인자 검사 실패는 isError 참이라, 같은 종류의 실패가 경로에 따라 갈린다. 모델은 본문을 읽어 대부분 실패를 안다. 피해는 isError로 분기하는 프로그램(오케스트레이터, 호출 결과 집계, 평가 도구)에서 생긴다.
