# P0095 실패나 처리할 수 없는 입력을 빈 결과·없음·정상 값으로 바꿔 성공으로 냄

항목 [4.1 실행 결과 상태 구분](/problems/4/4.1) · 소제목 4.1.2 「결과 상태와 실패 이유 전달」

외부 도구나 플러그인이 없거나 실패하면 결과를 빈 목록이나 0건으로 바꿔, 의심 신호 없음이나 일치 없음을 뜻하는 성공 응답을 낸다(findevil, Wireshark-MCP, VolPilot). 목록 내려받기, 키 조회, 파일 읽기에서 난 예외나 오류를 버리고 빈 값으로 처리하거나 오류 문장을 결과 항목으로 실어, 위협 없음, 키 없음, 일치 없음, 상관 없음과 같은 응답이 된다(WireMCP, regipy, trudi, mcp-forensic-toolkit). 입력 파일이 없으면 단계를 건너뛰거나 파일을 먼저 꺼내라는 안내를 지워, `isError` 거짓과 빈 결과 또는 0건을 돌려준다(sift-kernel). 없는 폴더나 `find` 실패를 일치 없음과 같은 빈 배열로 돌려준다(Camel). 조회하지 못한 해시가 VirusTotal에 있고 탐지 0인 파일로 나오고(trudi), 경로 검사 실패가 자격 증명 덤프 발견 1건으로 세어진다(agentic-dfir). 사건이 있는 메모리와 이벤트 로그가 사건 0건으로(VolPilot, winforensics-mcp), 로그 삭제 탐지가 clean으로(sift-kernel), 활동 기록이 있는 증거가 활동 없음으로(winforensics-mcp), 실행 중인 프로세스가 0개로(MyIRTeam), 원시 Android 덤프의 문자와 통화 기록이 없음으로(mulder) 나온다. `analyze_memory_summary`는 플러그인 종료 코드가 0이 아니면 프로세스, 모듈, malfind 결과를 빈 값으로 두고 판정해, 신호가 없으면 "The dump is internally consistent ..." 문장을 고른다(findevil). `ClamScanAsync`는 `clamscan …; true`로 늘 종료 코드 0을 만들어 실패해도 빈 일치 목록을 돌려주고, `ScanForMalwareAsync`는 일치가 0이면 "ClamAV reported no detections ..." 주의와 "No ClamAV/YARA detections"를 붙인다(Camel). 처리할 수 없는 입력에서도 같다. 없는 파일, 허용 폴더 밖 파일, 캡처가 아닌 파일, 쓰기 권한이 없는 출력 폴더, 문서가 지원한다고 적은 다른 출력 형식, `~`를 펼치지 않은 사건 폴더처럼 하위 실행이 처리하지 못하는 입력을 주면 그 실패가 일치 없음이나 0건의 성공 응답이 된다(Wireshark-MCP, SAVVYDFIR-MCP, agentic-dfir, trudi). 컴파일되지 않는 정규식, VQL 식, YARA 규칙을 주면 오류를 로그에만 남기거나 건너뛰어 빈 결과나 일치 0건을 돌려주고, 종료 코드를 보지 않거나 늘 0으로 만들어 문법 오류가 빈 배열이 된다(mcp-velociraptor, agentic-dfir, MyIRTeam, Camel). glob 꼴 패턴으로 정규식 생성이 실패하면 예외를 무시하고 거르지 않은 이미지 전체 목록을 검색 결과처럼 성공으로 돌려준다(sift-kernel). 이미지 안 경로의 일부를 찾지 못하면 이미지 루트나 상위 폴더 목록을 요청한 폴더 결과처럼 돌려준다(sift-kernel). 없는 폴더나 대소문자가 틀린 `userProfileRoot`를 주면 `FindFilesAsync`가 빈 배열을 내고 "No browser databases ... found" 성공 응답이 돌아온다(Camel). `memory_recall`은 없는 `store_path`에 빈 SQLite를 만들고 `{"hits":[]}`를 돌려주며, 도구 설명은 빈 결과를 이전 사건 없음으로 읽으라고 한다(verdict-dfir). `hunt_ioc_pack`은 `artifacts_dir`가 있는지만 `exists()`로 보고 폴더인지는 보지 않아, 파일 경로를 주면 검사한 파일이 없어도 `found` false와 일치 없음 요약을 만든다(winforensics-mcp).
