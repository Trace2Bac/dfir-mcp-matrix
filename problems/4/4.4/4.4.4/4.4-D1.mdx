# 4.4-D1 외부 조회로 보내는 지표에서 내부 주소와 호스트 이름을 거르지 않음

원고 [4.4 민감 정보 관리](/problems/4/4.4) · 소제목 [4.4.4 외부 전송 자료 선택과 가림](/problems/4/4.4/4.4.4)

## 현상과 피해

공개 평판 조회 서비스로 IP와 도메인 지표를 보내기 전에 사설 주소와 내부 호스트 이름을 거르지 않고 형식도 검사하지 않아, 피해 조직의 내부 정보가 제3자 서비스에 남는다.

## 해당 기능이 있는 서버 (7)

[Camel](/problems/servers/Camel), [mcp-velociraptor](/problems/servers/mcp-velociraptor), [mcp_dfir](/problems/servers/mcp_dfir), [mulder](/problems/servers/mulder), [sift-mcp](/problems/servers/sift-mcp), [trudi](/problems/servers/trudi), [winforensics-mcp](/problems/servers/winforensics-mcp)

## 문제가 관찰된 서버 (3)

### [mulder](/problems/servers/mulder)

- enrich_iocs가 IPv4를 키 없이 ip-api 평문 HTTP로, 키가 있으면 AbuseIPDB·OTX·VirusTotal로도 보내고 classify_ioc는 사설 주소와 내부 이름을 거르지 않는다 코드: [src/mulder/server/tools/enrichment.py:46-70](https://github.com/calebevans/mulder/blob/3164843baf74c7fe69e7121dbd6150f8f77ce660/src/mulder/server/tools/enrichment.py#L46-L70),130-182,444-494,513-560; [src/mulder/orchestrator/prompts/extract_analyst.md:187-188](https://github.com/calebevans/mulder/blob/3164843baf74c7fe69e7121dbd6150f8f77ce660/src/mulder/orchestrator/prompts/extract_analyst.md#L187-L188)

### [trudi](/problems/servers/trudi)

- enrich.machinae_lookup이 키나 설정 확인 없이 machinae를 실행해 기본 사이트 전부에 지표를 보내고 조회 도구 다섯이 값의 형식을 검사하지 않는다 코드: [tools/enrichment.py:19-171](https://github.com/nebulae/trudi/blob/88fbca78186b6a0ca40423cf5e37a9dc46ae051e/tools/enrichment.py#L19-L171)

### [winforensics-mcp](/problems/servers/winforensics-mcp)

- vt_lookup_ip·vt_lookup_domain이 모델이 준 값을 내부 주소 확인 없이 VirusTotal로 보낸다 코드: [winforensics_mcp/parsers/virustotal_client.py:348-387](https://github.com/x746b/winforensics-mcp/blob/cce7f360873fc9ae564296017cbffe2a603d83dd/winforensics_mcp/parsers/virustotal_client.py#L348-L387),443-481
