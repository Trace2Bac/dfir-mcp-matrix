# D1 이어 읽기 위치가 처리 순서나 실제 전달 위치와 맞지 않아 항목이 빠지거나 겹침

원고 [4.3 전달 크기 관리](/problems/4/4.3) · 소제목 「전체 출력 접근과 나머지 조회」

## 현상과 피해

하위 폴더 파일이 해시 목록에서 빠졌는데 `truncated` 거짓으로 끝나 무결성 기록이 불완전하다(trudi). 커서를 따라가면 창 몇 개의 글을 표시 없이 건너뛴다(mulder). 마지막 항목을 받지 못한다(agentic-dfir, `total`은 맞음).

### [agentic-dfir](/problems/servers/agentic-dfir)

- get_amcache·parse_shimcache의 limit에 minimum이 없어 limit -1이면 items[0:-1]로 마지막 항목이 빠지고 cursor_next -1이 온다. get_amcache는 그 값을 cursor로 주면 minimum 0 검사로 거부하고, parse_shimcache는 빈 목록과 cursor_next -2를 돌려준다(코드 추적). limit 0이면 빈 목록과 cursor_next 0이 되풀이된다. 코드: [dfir_mcp/src/dfir_mcp/__init__.py:180-187](https://github.com/Juwon1405/agentic-dfir/blob/a17e90b8a3c5ab5431f0da9f354f315082257f99/dfir_mcp/src/dfir_mcp/__init__.py#L180-L187), [dfir_mcp/src/dfir_mcp/__init__.py:232-267](https://github.com/Juwon1405/agentic-dfir/blob/a17e90b8a3c5ab5431f0da9f354f315082257f99/dfir_mcp/src/dfir_mcp/__init__.py#L232-L267), [dfir_mcp/src/dfir_mcp/__init__.py:294-333](https://github.com/Juwon1405/agentic-dfir/blob/a17e90b8a3c5ab5431f0da9f354f315082257f99/dfir_mcp/src/dfir_mcp/__init__.py#L294-L333)

### [trudi](/problems/servers/trudi)

- hash_directory의 _iter_files는 os.walk로 폴더마다 이름순으로 내려가는데 이어 읽기는 전체 경로 문자열이 start_after 이하인 파일을 건너뛰어, 루트 파일 이름보다 사전순으로 앞서는 하위 폴더의 파일이 빠지고 마지막 응답은 truncated false로 끝난다. 반대로 커서가 하위 폴더 파일이면 상위 폴더 파일을 다시 해싱해 output_manifest에 두 번 넣는다. 코드: [tools/hashing.py:140-162](https://github.com/nebulae/trudi/blob/88fbca78186b6a0ca40423cf5e37a9dc46ae051e/tools/hashing.py#L140-L162)(159행), [tools/hashing.py:165-189](https://github.com/nebulae/trudi/blob/88fbca78186b6a0ca40423cf5e37a9dc46ae051e/tools/hashing.py#L165-L189), [tools/hashing.py:234-237](https://github.com/nebulae/trudi/blob/88fbca78186b6a0ca40423cf5e37a9dc46ae051e/tools/hashing.py#L234-L237), [tools/hashing.py:289-296](https://github.com/nebulae/trudi/blob/88fbca78186b6a0ca40423cf5e37a9dc46ae051e/tools/hashing.py#L289-L296)
