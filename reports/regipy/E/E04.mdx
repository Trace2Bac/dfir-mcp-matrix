# E04 분석 입력 준비

### E04.02 선택 추출

**구현.** 이 방식은 하이브 폴더에서 분석할 하이브를 고르는 `_load_hives_from_directory`에 적용된다 [1].
이 함수는 `set_hive_directory`와 서버를 시작할 때 `--hives-dir`나 `REGIPY_HIVE_DIRECTORY`로 받은 폴더에 쓰인다 [1][2].
서버는 받은 폴더 바로 아래의 파일 가운데 확장자가 `.log`, `.log1`, `.log2`, `.sav`, `.regtrans-ms`, `.blf`, `.tmp`인 파일을 빼고 나머지를 하이브로 연다 [1].
하위 폴더는 보지 않는다 [1].
헤더를 해석하지 못한 파일도 뺀다 [1].
고른 하이브는 제자리에서 열고 파일 사본을 만들지 않는다 [1][3].
모델은 폴더만 고르고 파일을 고르는 규칙은 서버 코드가 정한다 [1].

서버 코드는 하이브의 트랜잭션 로그를 하이브로 열지 않으려고 건너뛸 뿐 찾아서 적용하거나 응답에 표시하지 않는다 [1].
regipy 6.5.2는 로그를 하이브에 적용해 복원한 하이브를 만드는 `apply_transaction_logs`를 두지만 서버는 이 함수가 있는 `regipy.recovery`를 불러오지 않는다 [4][5].
헤더의 두 순번이 1622와 1621로 다른 시험 하이브 `SYSTEM_B`를 로그 두 개와 함께 둔 폴더를 주자 서버는 `SYSTEM_B`만 불러 응답에 실었다 [6].
서버가 불러 둔 `SYSTEM_B`의 키는 33123개였고 regipy `apply_transaction_logs`로 같은 로그를 적용해 따로 만든 하이브의 키는 35595개였다 [6].
응답에는 로그가 있다는 사실이나 적용하지 않았다는 사실이 실리지 않았다 [6].

### E04.04 추출·생략 범위 기록

**구현.** 이 방식은 `set_hive_directory`의 응답과 `list_available_hives`에 적용된다 [7][8].
`set_hive_directory`는 불러온 하이브 수와 받은 폴더 경로를 첫 줄에 싣고 유형별로 파일 이름을 늘어놓는다 [7].
`list_available_hives`는 지금 불러 둔 하이브 수와 유형별 파일 이름을 돌려준다 [8].

**한계.** 확장자로 뺀 파일과 하이브로 열지 못한 파일은 응답에 실리지 않는다 [1][7].
확장자로 뺀 파일은 서버 로그에도 남지 않는다 [1].
하이브로 열지 못한 파일은 서버 로그에만 경고로 남는다 [1].
텍스트 파일 하나와 트랜잭션 로그 두 개를 둔 폴더에서 `set_hive_directory`의 응답에는 이 세 파일이 없었고 텍스트 파일의 `Failed to load` 경고만 서버의 표준 오류에 출력되었다 [6].
서버를 시작할 때 `--hives-dir`나 `REGIPY_HIVE_DIRECTORY`로 불러온 결과는 서버 로그에만 남는다 [2].
이 경우 모델은 `list_available_hives`를 불러야 불러온 목록을 받는다 [8].
불러올 하이브가 없으면 `set_hive_directory`는 폴더가 없는 경우와 폴더에 하이브가 없는 경우에 같은 문구를 돌려준다 [7][9].
빈 폴더와 없는 폴더로 부르자 둘 다 `No valid registry hives found in <폴더>` 문구가 돌아왔다 [6].

    for file_path in directory_path.iterdir():
