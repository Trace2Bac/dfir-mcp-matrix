# E03 원본 변경 방지

### E03.03 외부 도구·플랫폼에 위임

**구현.** 이 방식은 하이브 파일을 여는 유일한 경로인 regipy `RegistryHive`에 적용된다 [1][2].
서버 코드는 하이브 파일을 직접 열지 않고 `_load_hives_from_directory`에서 파일 경로를 `RegistryHive`에 넘긴다 [1].
이 경로에서 원본을 지키는 것은 regipy가 파일을 읽기만 한다는 동작이다.
regipy 6.5.2의 `RegistryHive`는 하이브를 `rb` 모드로 열어 내용 전체를 `BytesIO`에 복사하고 파일을 닫는다 [2].
헤더 해석, 키 조회, 플러그인 실행은 모두 이 메모리 사본으로 한다 [2][3].
`run_plugin`, `run_all_plugins_for_hive`, `get_registry_key`는 불러 둔 `RegistryHive` 객체만 쓰고 하이브 파일을 다시 열지 않는다 [4].

서버 코드에는 파일을 쓰거나 지우거나 이름을 바꾸는 호출이 없다 [5].
서버가 불러오는 `regipy.plugins.utils`에는 하이브를 JSON 줄 파일로 쓰는 `dump_hive_to_json`이 있지만 서버는 이 함수를 부르지 않는다 [6][7].
트랜잭션 로그를 적용해 복원한 하이브를 파일로 쓰는 `regipy.recovery`는 서버가 불러오지 않는다 [7][8].
서버는 하이브 폴더의 트랜잭션 로그를 확장자로 건너뛰고 열지 않는다 [1].
하이브 10개와 트랜잭션 로그를 둔 폴더로 도구 7개를 부른 뒤 하이브와 로그의 SHA-256과 수정 시각이 바뀌지 않았다 [9].

저장소에는 증거를 읽기 전용으로 연결하거나 서버를 읽기 전용 환경에서 실행하는 실행 구성이 없다 [10].
README는 클라이언트 설정에서 Python으로 `server.py`를 직접 실행하게 한다 [11].

        """
        This offset is from start of data (meaning that it starts from 4096)

        """
        self._stream.seek(REGF_HEADER_SIZE + offset)
