# L02 기록 구성

### L02.02 서버가 변환한 연산·인자 기록

**구현.** 이 방식은 `_load_hives_from_directory`, `run_plugin`, `run_all_plugins_for_hive`가 쓰는 항목에 적용된다 [1][2][3].
`set_hive_directory`의 항목은 서버가 받은 폴더에서 골라 열어 본 파일마다의 경로와 regipy가 그 파일에 정한 유형을 담는다 [1].
확장자로 건너뛴 파일과 파일이 아닌 항목은 항목을 남기지 않는다 [1].
폴더가 없을 때만 받은 폴더 경로를 그대로 담은 항목을 쓴다 [1].
`run_plugin`의 실패 항목은 받은 `plugin_name`과 서버가 그 플러그인의 호환 유형으로 고른 하이브 파일의 경로를 담는다 [2].
`run_all_plugins_for_hive`의 실패 항목은 서버가 `hive_type`으로 고른 하이브 파일의 경로를 담고 받은 `hive_type`은 담지 않는다 [3].
항목은 `basicConfig`의 기본 형식 `%(levelname)s:%(name)s:%(message)s`로 쓰여 수준, 로거 이름, 메시지만 있다 [4][5].
항목에는 도구 이름과 호출을 잇는 ID가 없다 [1][2][3][5].

**한계.** 성공한 플러그인 실행은 항목을 남기지 않는다 [2][3].
그래서 서버가 어느 하이브 파일로 어떤 플러그인을 실행했는지는 실패한 경우에만 남는다 [2][3].
`get_registry_key`는 항목을 쓰지 않아 받은 `key_path`와 서버가 고른 하이브가 남지 않는다 [6].
`set_hive_directory`에 파일 경로를 주면 항목 없이 오류로 끝난다 [1][7].

### L02.05 결과 상태·실행 시점 기록

**구현.** 이 방식은 `_load_hives_from_directory`, `run_plugin`, `run_all_plugins_for_hive`가 쓰는 항목에 적용된다 [1][2][3].
하이브 적재 항목은 `Successfully loaded`와 `Failed to load`로 파일마다 성공과 실패를 나눈다 [1].
플러그인 실행의 실패 항목은 수준 `ERROR`와 예외 문구로 실패를 알린다 [2][3].
항목은 `basicConfig`의 기본 형식으로 쓰여 수준, 로거 이름, 메시지만 있다 [4][5].

**한계.** 항목에 실행 시점이 없다 [5][7].
성공한 플러그인 실행은 항목을 남기지 않는다 [2][3].
`get_registry_key`는 결과와 관계없이 항목을 쓰지 않는다 [6].

    skip_extensions = {".log", ".log1", ".log2", ".sav", ".regtrans-ms", ".blf", ".tmp"}

    for file_path in directory_path.iterdir():
        if not file_path.is_file():
