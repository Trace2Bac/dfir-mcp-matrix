# T05 분석 도구 검증

### T05.01 저장소·의존성 고정

**구현.** 이 방식은 저장소 최상위의 `requirements.txt`가 고정하는 해석 라이브러리 3개와 같은 저장소에 들어 있는 regipy 소스의 키 경로와 값 매핑, 검증 목록에 적용된다 [1][2].
이 파일은 `construct==2.10.70`, `libfwsi-python==20240423`, `libfwps-python==20260522`를 적는다 [1].
regipy 6.5.2는 하이브 기본 블록 같은 구조를 `construct`의 `Struct`로 정의해 해석한다 [3].
셸백 플러그인은 `libfwsi-python`과 `libfwps-python`이 설치하는 모듈 `pyfwsi`, `pyfwps`로 셸 항목을 해석한다 [4].
분석 라이브러리 regipy의 소스는 같은 저장소의 기준 커밋에 들어 있고 `pyproject.toml`은 그 버전을 6.5.2로 적는다 [2].
플러그인이 쓰는 키 경로와 값 매핑, 검증 목록 `validated_plugins.json`도 이 소스에 들어 있다 [2].
regipy 저장소 README는 저장소를 받아 `pip install --editable .[full]`로 설치하는 방법을 적는다 [5].
이렇게 설치하면 받은 커밋의 소스가 실행된다 [5].

서버 실행용 라이브러리 `mcp`는 README가 `mcp >= 1.0.0`만 적고 이 방식으로 보지 않는다 [6].

**한계.** 서버 README가 적는 설치 조건은 `regipy >= 6.0.0`과 `mcp >= 1.0.0`이고 `requirements.txt`를 쓰라는 안내는 없다 [6].
기준 커밋의 파일 가운데 `requirements.txt`를 가리키는 파일은 없다 [7].
`requirements.txt`에는 regipy 자신이 없다 [1].
README의 `regipy >= 6.0.0`은 이 커밋의 6.5.2가 아닌 버전도 받는다 [6][2].
다른 버전이 설치되면 플러그인의 키 경로와 값 매핑, 검증 목록도 그 버전의 것이 쓰인다 [6][2].
저장소의 CI도 `requirements.txt`가 아니라 `pyproject.toml`의 범위로 설치한다 [8][7].
regipy 패키지의 필수 의존성은 `construct>=2.10`이고 선택 의존성 `full`은 `libfwsi-python>=20240315`, `libfwps-python>=20240310`처럼 하한만 적는다 [9].
이 저장소 사본을 `full`과 함께 설치한 실행 환경의 `libfwsi-python`은 `requirements.txt`의 20240423이 아니라 20260522였다 [10].
서버는 실행 중에 regipy나 해석 라이브러리의 버전을 읽거나 대조하지 않는다 [11][12].
