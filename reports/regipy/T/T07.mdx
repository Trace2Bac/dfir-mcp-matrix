# T07 도구 부재 처리

### T07.08 일부 제외 후 계속 실행

**구현.** 이 방식은 `run_all_plugins_for_hive`가 부르는 regipy 6.5.2의 `run_relevant_plugins`에 적용된다 [1][2].
`run_relevant_plugins`는 플러그인을 차례로 실행하다 `ModuleNotFoundError`가 나면 그 플러그인의 의존성이 없다는 오류 로그를 남기고 결과에 넣지 않은 채 다음 플러그인을 실행한다 [2].
서버는 `continue_on_error`를 주지 않으므로 기본값 거짓에서 이 플러그인은 결과에 오류 항목도 남기지 않는다 [1][2].
regipy 6.5.2에서 선택 의존성이 필요한 플러그인은 NTUSER와 UsrClass의 셸백 플러그인 2개이고 둘 다 `run()` 첫머리에서 `pyfwsi`를 불러온다 [3][4].
셸백 플러그인은 불러오지 못하면 `pip install regipy[full]`로 설치하라는 로그를 남기고 예외를 다시 낸다 [3][4].
`pyfwsi`와 `pyfwps`를 불러오지 못하게 한 프로세스에서 `run_all_plugins_for_hive`에 `ntuser`를 주자 셸백 플러그인 키만 빠진 12개 플러그인의 결과가 돌아왔다 [5].
`usrclass`를 주자 `UsrClass.dat`의 결과는 빈 `dict`였고 `files_analyzed`는 1이었다 [5].
응답에는 빠진 플러그인이나 없는 모듈을 알리는 필드가 없다 [1][5].
설치 안내는 서버가 표준 오류로 내보내는 로그에만 남는다 [3][6].

`run_plugin`은 이 방식을 쓰지 않는다 [7].
`run_plugin`은 플러그인 실행 중 난 예외를 종류와 관계없이 처리해 그 하이브 파일의 결과를 `{"error": <예외 문구>}`로 둔다 [7].
같은 프로세스에서 `run_plugin`에 `ntuser_shellbag_plugin`을 주자 `NTUSER.DAT`의 결과는 모듈을 불러오지 못했다는 예외 문구를 담은 `error`였다 [5].
서버는 이 오류를 다른 실행 오류와 구별하지 않는다 [7].
도구를 실행하기 전에 모듈이 있는지 확인하는 서버 코드는 없다 [1][7].

[1] `run_all_plugins_for_hive`는 `run_relevant_plugins`에 `continue_on_error`를 주지 않고 받은 결과를 그대로 싣는다.

    # Run all plugins on all compatible hives
    all_results = {}

        try:
            results = run_relevant_plugins(hive, as_json=True)
            serialized_results = _serialize_plugin_results(results)
            all_results[Path(path).name] = serialized_results

    return {"hive_type": hive_type, "files_analyzed": len(all_results), "results": all_results}
