# R03 분석 상태 알림

### R03.01 구조화 status·error

**구현.** 이 방식은 `dict`를 돌려주는 도구 4개와 서버가 처리하지 않은 예외에 적용된다 [1][2].
`run_plugin`, `run_all_plugins_for_hive`, `list_relevant_plugins`, `get_registry_key`는 적재한 하이브가 없거나 플러그인이나 유형에 맞는 하이브가 없으면 실행하지 않고 `error` 필드에 문구를 담아 돌려준다 [1].
`run_plugin`과 `run_all_plugins_for_hive`는 하이브 파일마다의 실패도 그 파일 아래 `error`로 싣는다 [3].
이 응답들의 `isError`는 거짓이다 [4].
서버가 처리하지 않은 예외, 인자 검사 실패, 목록에 없는 도구 이름은 MCP Python SDK 1.30.0이 `isError`가 참인 결과로 돌려준다 [2][4].
성공한 응답에는 성공 여부를 따로 적는 필드가 없다 [3].

**한계.** 문자열을 돌려주는 도구는 상태를 글로만 알린다 [5].
`set_hive_directory`는 폴더가 없거나 하이브를 하나도 적재하지 못하면 `No valid registry hives found in <폴더>` 글을 `isError`가 거짓인 결과로 돌려준다 [5][4].
`list_available_hives`는 하이브가 없으면 `No hives loaded` 글을 돌려준다 [5].
`get_registry_key`는 하이브 파일마다 난 예외를 `error`에 담지만 찾은 하이브가 없으면 그 `error`를 버리고 `found`만 거짓으로 돌려준다 [6].
유형을 판별하지 못한 하이브와 유형을 판별한 하이브를 함께 적재한 서버에서 맞는 하이브가 없는 유형으로 `run_all_plugins_for_hive`를 부르면 `available_types`를 정렬하다 `TypeError`가 난다 [7][8].
이 경우 `error` 응답 대신 `isError`가 참인 결과가 돌아가고 적재한 유형 목록은 실리지 않는다 [2][8].

### R03.02 찾지 못함과 실패 구분

**구현.** 이 방식은 `run_plugin`과 `run_all_plugins_for_hive`에 적용된다 [3].
두 도구는 플러그인이 찾은 것이 없으면 그 파일 아래 빈 목록이나 플러그인이 정한 빈 구조를 싣고 실패한 파일은 `error`를 담은 `dict`로 싣는다 [3].
regipy 6.5.2의 `installed_programs_ntuser`처럼 찾는 키가 하이브에 없으면 오류 로그를 남기고 결과를 비우는 플러그인이 있다 [9].
NTUSER 시험 하이브에 `run_all_plugins_for_hive`를 부르자 `installed_programs_ntuser`가 빈 목록이었고 서버 표준 오류에 `Did not find Uninstall at Software\Microsoft\Windows`가 남았다 [4].

`get_registry_key`는 찾아본 하이브 어디에서도 키를 찾지 못하면 `found`를 거짓으로 두고 찾아본 파일 이름 `searched_hives`를 담아 정상 결과로 돌려준다 [6].
하이브 파일마다 난 예외도 `found`가 거짓인 결과로 두므로 찾은 하이브가 없으면 실패와 찾지 못함이 같은 응답이 된다 [6].
적재한 하이브가 없거나 `hive_type`에 맞는 하이브가 없을 때만 `found` 없이 `error`를 돌려준다 [6][1].
없는 키 `\NoSuchKey`로 부르자 `found`가 거짓인 응답이 돌아왔고 `hive_type`을 `SYSTEM`으로 주자 `error`만 담긴 응답이 돌아왔다 [4].
regipy 6.5.2의 `get_key`가 돌려주는 객체에는 서버가 읽는 `path` 속성이 없어 키가 있어도 예외가 난다 [6][10].
SYSTEM 하이브에 있는 키와 루트 `\`로 부르자 없는 키와 같은 `found`가 거짓인 응답이 돌아왔다 [11].

**한계.** `run_all_plugins_for_hive`에서 의존 모듈을 불러오지 못한 플러그인은 결과에서 빠진다 [12].
그래서 그 플러그인 하나만 맞는 하이브는 실패 표시 없이 빈 `dict`로 실렸다 [13].

### R03.03 입력별 성공·실패·생략 목록

**구현.** 이 방식은 `run_plugin`과 `run_all_plugins_for_hive`에 적용된다 [3].
두 도구는 고른 유형의 하이브 파일마다 결과를 파일 이름 아래에 싣고 실패한 파일은 그 자리에 `error`를 싣는다 [3].
SYSTEM 하이브 두 개를 적재한 서버에서 `run_plugin`에 `computer_name`을 주자 `SYSTEM`과 `SYSTEM_2` 두 키 아래 결과가 돌아왔다 [11].
`run_all_plugins_for_hive`는 파일마다 플러그인 이름을 키로 한 결과를 싣는다 [3][12].

**한계.** 생략한 항목과 플러그인 단위의 실패는 싣지 않는다.
`run_all_plugins_for_hive`가 부르는 `run_relevant_plugins`는 검증 목록 밖 플러그인과 의존 모듈이 없는 플러그인을 결과에 넣지 않는다 [12].
`run_relevant_plugins`는 플러그인 하나가 예외를 내면 그 예외를 다시 내보내므로 그 파일 아래에는 다른 플러그인의 결과 없이 `error` 하나만 실린다 [12][3].
이 `error`에는 실패한 플러그인의 이름이 없다 [12][3].
손상 하이브에 같은 호출을 서버 프로세스 다섯 개에서 보내자 `error`에 실린 오류 문구가 실행마다 두 가지로 갈렸다 [14].
`files_analyzed`는 오류로 끝난 파일도 센다 [3].

class NKRecord:
    """
    The NKRecord represents a Name Key entry
    """

    def __init__(self, cell, stream):
        stream.seek(cell.offset)
        self.header = CM_KEY_NODE.parse_stream(stream)  # type: ignore[union-attr]
        self._stream = stream

        # Sometimes the key names are ASCII and sometimes UTF-16 little endian
        if self.header.flags.KEY_COMP_NAME:
            # Compressed (ASCII) key name
            self.name = self.header.key_name_string.decode("ascii", errors="replace")
        else:
            # Unicode (UTF-16) key name
            self.name = self.header.key_name_string.decode("utf-16-le", errors="replace")
            logger.debug(f'Unicode key name identified: "{self.name}"')

        self.subkey_count = self.header.subkey_count
        self.values_count = self.header.values_count
        self.volatile_subkeys_count = self.header.volatile_subkey_count
