# R07 증거 내용과 지시 구분

### R07.01 JSON 필드 분리

**구현.** 이 방식은 `dict`를 돌려주는 `run_plugin`과 `run_all_plugins_for_hive`에 적용된다 [1][2].
두 도구는 하이브에서 읽은 값을 플러그인 결과의 필드 값으로 담고 서버가 정한 `plugin`, `description`, `hive_type`, `error` 같은 필드와 따로 둔다 [1][2].
MCP Python SDK 1.30.0의 FastMCP는 이 `dict`를 JSON 글로 바꿔 싣는다 [3].
그래서 증거에서 온 문자열은 JSON 문자열 값으로 따옴표 안에 들어간다 [3][4].
도구 설명, 응답, 서버 지침 어디에도 증거에서 온 글을 데이터로 다루라는 안내는 없다 [5][4].
`get_registry_key`의 처리 코드는 키의 값을 필드로 담는 자리를 두지만 키가 있어도 `found`가 거짓인 응답만 돌아와 하이브에서 읽은 값이 실리지 않았다 [6][7].

`set_hive_directory`와 `list_available_hives`는 서버 문구와 하이브 파일 이름, 유형 이름을 한 글에 섞어 돌려준다 [8][9].
이 글에 들어가는 증거 쪽 값은 폴더 안 파일의 이름과 regipy가 정한 유형 이름이다 [8][9].

**한계.** `error`에는 regipy가 낸 예외 문구가 그대로 들어간다 [1][2].
regipy의 예외 문구에는 하이브에서 읽은 키 이름이 들어갈 수 있다 [10].
손상 하이브에 `run_all_plugins_for_hive`를 부른 응답의 `error`는 실행에 따라 `Did not find Lsa at ControlSet001`이거나 `No subkey AppCompatCache for b'Session Manager'`였다 [11].

### R07.02 출처 필드 부여

**구현.** 이 방식은 `run_plugin`과 `run_all_plugins_for_hive`에 적용된다 [1][2].
`run_plugin`의 응답은 결과를 만든 regipy 플러그인의 이름 `plugin`, 그 설명 `description`, 호환 하이브 유형 `hive_type`을 결과와 함께 싣는다 [1].
`run_all_plugins_for_hive`의 응답은 하이브 파일마다 플러그인 이름을 키로 결과를 싣는다 [2].
두 응답에는 신뢰 수준이나 플러그인의 검증 여부를 적는 필드가 없다 [1][2].

    def get_subkey(self, key_name, raise_on_missing=True):
        if not self.subkey_count and raise_on_missing:
            raise NoRegistrySubkeysException(f"No subkeys for {self.header.key_name_string}")

        for subkey in self.iter_subkeys():
            # This should not happen
            if not isinstance(subkey, NKRecord):
                raise RegipyGeneralException(f"Unknown record type: {subkey}")

            if subkey.name.upper() == key_name.upper():
                return subkey

        if raise_on_missing:
            raise NoRegistrySubkeysException(f"No subkey {key_name} for {self.header.key_name_string}")
