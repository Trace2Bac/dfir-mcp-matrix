# F02 발견사항·결론 도출

### 미구현

**판단.** 서버는 regipy 플러그인의 결과를 옮기고 형식을 바꿔 돌려줄 뿐 규칙으로 판정하거나 결과끼리 잇거나 점수를 매기지 않는다.
`run_plugin`은 하이브마다 플러그인 객체의 `entries`를 하이브 파일 이름 아래에 담아 돌려준다 [1].
`run_all_plugins_for_hive`는 하이브마다 regipy `run_relevant_plugins`가 돌려준 플러그인별 결과를 같은 방식으로 담는다 [2].
서버 코드가 결과에 하는 처리는 `_serialize_plugin_results`로 `datetime` 값을 ISO 8601 문자열로 바꾸는 것뿐이다 [3].
`get_registry_key`의 처리 코드는 키 하나의 시각과 값 목록을 담는 필드를 두지만 regipy 6.5.2에서는 키가 있어도 `found`가 거짓인 응답을 돌려준다 [4][5].
`list_relevant_plugins`는 받은 `question`을 응답에 그대로 싣고 플러그인을 고르는 데 쓰지 않는다 [6].

지속성 키처럼 정해 둔 키 목록을 읽어 결과를 만드는 일은 regipy 플러그인이 한다 [7].
regipy 플러그인 기반 클래스에는 이상 징후를 찾는 메서드 `detect_anomalies`가 있지만 본문이 비어 있고 서버 코드는 이 메서드를 부르지 않는다 [8][9].
README의 예시는 클라이언트 모델이 지속성 항목 가운데 의심스러운 항목을 짚었다고 적고 그때 부른 도구를 `answer_forensic_question`으로 적는다 [10].
기준 커밋의 서버에는 이 이름의 도구가 없다 [11].

[3] `_serialize_plugin_results`는 `dict`와 `list`를 따라가며 `datetime`만 문자열로 바꾼다.

```python
def _serialize_plugin_results(results):
    """Recursively serialize plugin results, converting datetimes to strings."""
    if isinstance(results, dict):
        return {k: _serialize_plugin_results(v) for k, v in results.items()}
    elif isinstance(results, list):
        return [_serialize_plugin_results(item) for item in results]
    elif isinstance(results, datetime):
        return results.isoformat()
    else:
        return results
```
