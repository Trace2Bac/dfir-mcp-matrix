# P01 분석 방법 적합성 확인

### P01.01 이름·확장자 판별

**구현.** 이 방식은 하이브 폴더에서 하이브를 불러오는 `_load_hives_from_directory`에 적용된다 [1].
이 함수는 `set_hive_directory`와 서버를 시작할 때 `--hives-dir`나 `REGIPY_HIVE_DIRECTORY`로 받은 폴더에 쓰인다 [1][2].
함수는 폴더 바로 아래의 파일만 보고 하위 폴더는 보지 않는다 [1].
확장자를 소문자로 바꿔 `.log`, `.log1`, `.log2`, `.sav`, `.regtrans-ms`, `.blf`, `.tmp` 가운데 하나이면 그 파일을 하이브로 열지 않고 건너뛴다 [1].
코드 설명은 이 처리를 트랜잭션 로그와 백업 파일을 빼는 것이라고 적는다 [1].
나머지 파일은 이름과 관계없이 모두 하이브로 열어 본다 [1].
하이브 파일 하나를 `SYSTEM_copy.log`로 이름을 바꿔 둔 폴더를 주자 이 파일은 불러온 목록에 없었다 [3].
같은 폴더의 `SYSTEM_B.LOG1`과 `SYSTEM_B.LOG2`도 열지 않았다 [3].

### P01.03 내용·헤더 검사

**구현.** 이 방식은 `_load_hives_from_directory`가 파일마다 만드는 regipy `RegistryHive` 객체에 적용된다 [1][4].
`RegistryHive`는 파일 앞부분을 `REGF_HEADER` 구조로 해석하고 이 구조의 첫 4바이트는 `regf`여야 한다 [4][5].
이어서 루트 hbin과 루트 키 레코드를 해석한다 [4].
해석이 예외로 끝나면 서버는 그 파일을 불러오지 않고 서버 로그에 경고를 남긴다 [1].
하이브 폴더에 둔 텍스트 파일 `notes.txt`는 불러온 목록에 없었고 서버 로그에 `Failed to load` 경고가 남았다 [3].

하이브 유형은 regipy `identify_hive_type`이 헤더의 `file_name` 필드 문자열로 정한다 [4][6].
`file_name`을 소문자로 바꿔 `ntuser.dat`로 끝나면 `ntuser`, `system`과 같으면 `system`, `amcache`가 들어 있으면 `amcache`처럼 정해 둔 규칙 8개와 대조한다 [6].
파일 이름이 아니라 하이브 헤더에 적힌 이름을 보므로 파일 이름은 유형에 영향을 주지 않는다 [6].
시험 하이브 `SYSTEM_2`와 `corrupted_system_hive`는 헤더의 `file_name`이 `SYSTEM`이어서 `system`으로 정해졌다 [3].

**한계.** `RegistryHive`는 불러올 때 헤더, 루트 hbin, 루트 키 레코드만 해석하므로 그 뒤 구조가 손상된 하이브도 불러온다 [4].
손상된 시험 하이브 `corrupted_system_hive`도 `system`으로 불러졌다 [3].
`file_name`이 규칙 8개 어디에도 맞지 않으면 유형은 `None`이 되고 서버는 그 하이브를 `unknown`으로 묶어 불러 둔다 [4][7].
헤더의 `file_name`이 빈 시험 하이브 `ntuser_software_partial`은 `unknown`으로 불러졌다 [3].
regipy `RegistryHive`는 유형을 인자 `hive_type`으로 받을 수 있지만 서버는 이 인자를 넘기지 않는다 [4][1].
그래서 유형을 판별하지 못한 하이브에 사용자나 모델이 유형을 정할 수 없다 [1][4].

### P01.04 방법과 형식·OS 대조

**구현.** 이 방식은 플러그인을 실행하는 `run_plugin`·`run_all_plugins_for_hive`와 플러그인 목록을 돌려주는 `list_relevant_plugins`·`list_available_plugins`에 적용된다 [8][9][10][11].
regipy 플러그인은 클래스마다 맞는 하이브 유형 `COMPATIBLE_HIVE`를 두고 `can_run`은 하이브의 유형이 이 값과 같은지 본다 [12].
`run_plugin`은 모델이 고른 플러그인의 `COMPATIBLE_HIVE`와 유형이 같은 하이브를 모두 고르고 하이브마다 `can_run`이 참일 때만 실행한다 [8][13].
그 유형의 하이브가 없으면 실행하지 않고 `required_hive_type`과 함께 오류를 돌려준다 [8].
NTUSER 하이브를 불러 두지 않은 서버에서 `run_plugin`에 `typed_urls`를 주자 `No ntuser hive loaded` 오류가 돌아왔다 [3].
`run_all_plugins_for_hive`는 모델이 준 유형의 하이브를 고르고 regipy `run_relevant_plugins`는 그 하이브에서 `can_run`이 참인 플러그인만 실행한다 [9][14].
`list_relevant_plugins`는 불러 둔 하이브의 유형에 맞지 않는 플러그인을 목록에서 뺀다 [10].
`list_available_plugins`는 맞는 하이브가 없는 플러그인에 `✗`를 붙인다 [11].
대조에 쓰는 값은 하이브 유형 하나다 [12].

`get_registry_key`는 플러그인을 쓰지 않고 모델이 준 키 경로를 하이브에서 찾는다 [15].
`hive_type`을 주지 않으면 유형과 관계없이 불러 둔 하이브 모두에서 찾는다 [15].

**한계.** 도구 설명은 `hive_type`의 예로 `'SYSTEM'`, `'SOFTWARE'`, `'NTUSER'`, `'SAM'` 같은 대문자 값을 적는다 [9][11].
regipy의 유형 값은 `system`처럼 소문자이고 서버는 대소문자를 구별해 대조한다 [16][13][17].
`SYSTEM` 하이브 하나를 불러 둔 서버에서 `run_all_plugins_for_hive`에 `SYSTEM`을 주자 `No SYSTEM hive loaded` 오류와 함께 `available_types`로 `system`이 돌아왔다 [3].
같은 서버에서 `list_available_plugins`에 `SYSTEM`을 주자 플러그인 0개가 돌아왔다 [3].
유형을 판별하지 못한 하이브와 유형을 판별한 하이브를 함께 불러 둔 서버에서 맞는 하이브가 없는 유형으로 `run_all_plugins_for_hive`를 부르면 오류 응답을 만들다가 `TypeError`로 끝난다 [9].
이 경우 MCP 응답은 `isError`가 참인 `'<' not supported between instances of 'str' and 'NoneType'` 문구였다 [3].

```python
def identify_hive_type(name: str) -> str:
    hive_name = name.lower()
    if hive_name.endswith("ntuser.dat"):
        return NTUSER_HIVE_TYPE
    elif hive_name == SYSTEM_HIVE_TYPE:
        return SYSTEM_HIVE_TYPE
    elif hive_name.endswith("system32\\config\\software"):
        return SOFTWARE_HIVE_TYPE
    elif hive_name == r"\systemroot\system32\config\sam":
        return SAM_HIVE_TYPE
    elif hive_name.endswith(r"\system32\config\security"):
        return SECURITY_HIVE_TYPE
    elif hive_name.endswith(r"\boot\bcd"):
        return BCD_HIVE_TYPE
    elif hive_name == r"\microsoft\windows\usrclass.dat":
        return USRCLASS_HIVE_TYPE
    elif "amcache" in hive_name.lower():
        return AMCACHE_HIVE_TYPE
    else:
        raise UnidentifiedHiveException(f"Could not identify hive: {name}")
```

```python
class Plugin:
    NAME: Optional[str] = None
    DESCRIPTION: Optional[str] = None
    COMPATIBLE_HIVE: Optional[str] = None

    def __init_subclass__(cls) -> None:
        PLUGINS.add(cls)

    def __init__(self, registry_hive: RegistryHive, as_json=False, trim_values=False):
        self.registry_hive = registry_hive
        self.as_json = as_json
        self.trim_values = trim_values

        self.partial_hive_path = registry_hive.partial_hive_path

        # This variable should always hold the final result - in order to use it in anomaly detection and timeline gen.
        # Can be either a list of dicts (most plugins) or a dict (some plugins that organize by key path)
        self.entries: Union[list[dict[str, Any]], dict[str, Any]] = []

    def can_run(self):
        """
        Whether the plugin can run or not, according to specific checks
        :return:
        """
```
