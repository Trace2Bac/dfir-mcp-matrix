# P05 사건 자료 정리

### P05.01 모델 도구로 삭제·초기화

**구현.** 이 방식은 `set_hive_directory`에 적용된다 [1].
`set_hive_directory`는 받은 폴더에서 하이브를 새로 읽어 하이브 목록 `_loaded_hives`를 통째로 바꾼다 [1].
앞서 불러 둔 하이브의 `RegistryHive` 객체와 그 안에 복사해 둔 하이브 내용은 이때 목록에서 빠진다 [1][2].
받은 폴더가 없거나 그 안에 불러올 하이브가 없으면 `_loaded_hives`는 빈 `dict`가 되고 응답은 `No valid registry hives found in <폴더>`다 [1][3].
하이브 10개를 불러 둔 서버에서 빈 폴더로 `set_hive_directory`를 부르자 이어서 부른 `list_available_hives`가 `No hives loaded`로 시작하는 문구를 돌려주었다 [4].
없는 폴더로 불렀을 때도 목록이 비었고 하이브 폴더 값 `_hive_directory`는 그 없는 폴더 경로로 바뀌었다 [4].

서버가 버리는 것은 프로세스 메모리의 상태뿐이다 [1].
서버 코드에는 파일을 지우는 호출이 없고 하이브 파일과 트랜잭션 로그는 그대로 남는다 [5][4].
도구 설명은 폴더를 정하고 하이브를 불러온다고만 적고 앞서 불러 둔 하이브를 버린다는 사실은 적지 않는다 [1].
응답도 버린 하이브를 적지 않는다 [1].

**한계.** 폴더가 아닌 파일 경로를 주면 `set_hive_directory`는 `_hive_directory`만 그 경로로 바꾸고 `NotADirectoryError`로 끝난다 [1][6].
그래서 앞서 불러 둔 하이브 목록은 그대로 남는다 [1][7].
하이브 8개를 불러 둔 서버에 파일 경로로 `set_hive_directory`를 보내자 `isError`가 참인 결과가 돌아왔고 이어 부른 `list_available_hives`는 하이브 8개를 보였다 [7].

@mcp.tool()
def set_hive_directory(directory: str) -> str:
    """
    Set the directory containing registry hives and load them.

    Args:
        directory: Path to directory containing registry hive files

    Returns:
        Summary of loaded hives
    """
    global _loaded_hives, _hive_directory

    _hive_directory = directory
    _loaded_hives = _load_hives_from_directory(directory)

    # Group by hive type

        hive_type = hive.hive_type or "unknown"
        if hive_type not in by_type:
            by_type[hive_type] = []
        by_type[hive_type].append(Path(path).name)

    result = [f"Loaded {len(_loaded_hives)} hive(s) from {directory}:\n"]
    for hive_type, files in sorted(by_type.items()):
        result.append(f"\n{hive_type}:")
        for file in files:
            result.append(f"  - {file}")

    return "\n".join(result)
