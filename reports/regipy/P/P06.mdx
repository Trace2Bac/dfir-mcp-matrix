# P06 조사 상태 유지

### P06.02 프로세스 메모리에만 보관

**구현.** 서버가 프로세스 메모리에 두는 조사 상태는 불러 둔 하이브 목록 `_loaded_hives`다 [1].
하이브 폴더 `_hive_directory`도 전역 값으로 두지만 어느 도구도 이 값을 읽지 않는다 [1][2].
`_loaded_hives`는 하이브 파일 경로를 키로, regipy `RegistryHive` 객체를 값으로 두는 `dict`다 [1].
`RegistryHive`는 하이브를 열 때 내용 전체를 `BytesIO`에 복사하고 그 뒤의 해석은 모두 이 메모리 사본으로 한다 [3].
`_loaded_hives`는 모듈 전역 변수라 모든 도구 호출이 함께 쓴다 [1].
서버는 이 상태를 파일이나 DB에 쓰지 않으므로 프로세스가 끝나면 상태도 사라진다 [4].

상태는 하이브 폴더를 받을 때 한꺼번에 채워진다.
서버를 시작할 때 `--hives-dir`나 `REGIPY_HIVE_DIRECTORY`가 있으면 그 폴더의 하이브를 불러 두고 둘 다 없으면 빈 목록으로 시작한다 [5].
실행 중에는 `set_hive_directory`가 목록을 새 폴더의 하이브로 바꾼다 [6].
다시 시작한 서버는 시작 인자나 환경변수의 폴더를 다시 읽고 실행 중에 `set_hive_directory`로 고른 폴더는 이어받지 않는다 [5].

불러 둔 하이브는 다시 읽지 않는다 [3][7].
하이브 하나를 불러 둔 서버에서 `computer_name`을 실행한 뒤 같은 경로의 파일을 다른 하이브로 덮어쓰고 다시 실행하자 처음과 같은 컴퓨터 이름이 돌아왔다 [8].
상태에는 유효 시간이나 개수 한도가 없다 [1][6].
플러그인 결과는 호출마다 새로 계산하고 담아 두지 않는다 [7].

```python
def _initialize_hives(hive_dir: Optional[str] = None):
    """
    Initialize hives from the specified directory or environment variable.

    Priority:
    1. Command-line argument (hive_dir parameter)
    2. REGIPY_HIVE_DIRECTORY environment variable
    3. If neither is set, hives must be loaded manually via set_hive_directory tool
    """
    global _loaded_hives, _hive_directory

    # Try parameter first, then environment variable
    _hive_directory = hive_dir or os.getenv("REGIPY_HIVE_DIRECTORY")

    if not _hive_directory:
        logger.warning("No hive directory specified. Use set_hive_directory tool or pass --hives-dir argument.")
        return

    logger.info(f"Loading hives from: {_hive_directory}")
    _loaded_hives = _load_hives_from_directory(_hive_directory)
    logger.info(f"Loaded {len(_loaded_hives)} hive(s)")
```
