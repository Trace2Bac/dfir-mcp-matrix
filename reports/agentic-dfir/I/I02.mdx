# I02 분석 도구 통신 차단

### 미구현

**판단.** 서버는 분석 도구를 실행하거나 라이브러리를 부를 때 그 통신을 끊거나 끄는 장치를 두지 않는다.
실행기 `run_tool`은 `subprocess.run`에 환경변수를 따로 주지 않는다 [1].
그래서 분석 도구는 서버 프로세스와 같은 환경변수와 네트워크로 실행된다 [1].
저장소에는 분석 도구를 네트워크 없는 컨테이너나 network namespace에서 실행하는 구성이 없다 [2].

Volatility 3 도구 12개는 `vol`에 `-q`, `-r csv`, `-f <이미지>`, 플러그인 이름을 넘기고 오프라인 옵션 `--offline`을 붙이지 않는다 [3].
`sift_vol3_windows_pslist`와 `sift_vol3_linux_bash`를 실행기 대신 인자를 받아 두는 함수로 바꿔 부르자 넘긴 인자 배열에 `--offline`이 없었다 [4].
Volatility 3 2.28.0의 `--offline`은 전역 값 `OFFLINE`을 켜고 이 값이 켜지면 URL을 여는 처리기가 http·https 요청을 막는다 [5][6].
`--offline`이 없으면 Volatility 3 2.28.0은 Windows 커널의 PDB 심볼 표가 로컬 심볼 폴더와 캐시에 없을 때 Microsoft 심볼 서버(`http://msdl.microsoft.com/download/symbols`)에서 PDB를 받아 변환한다 [7].
그래서 Windows 플러그인을 실행하는 도구 9개는 이미지에 맞는 심볼이 로컬에 없으면 Microsoft 심볼 서버에 접속한다 [3][7].
원격 ISF 목록 주소 `REMOTE_ISF_URL`은 기본값이 `None`이라 `-u`를 주지 않으면 그 목록은 조회하지 않는다 [8].
Volatility 3 2.28.0은 사용자 설정 폴더의 `vol.json`을 읽어 그 값을 인자 기본값으로 쓰므로 이 파일의 `remote_isf_url`로도 원격 목록 조회가 켜진다 [9].

`sift_plaso_psort`는 `output_format` 값을 검사하지 않고 `psort`의 `-o`에 넘긴다 [10].
Plaso 20260720의 `psort`는 `opensearch-py`를 불러올 수 있으면 출력 모듈 `opensearch`를 등록하고 `opensearch-py`는 Plaso의 기본 의존성이다 [11].
이 출력 모듈은 머리를 쓸 때 OpenSearch 서버에 접속하고 서버 주소의 기본값은 `127.0.0.1`, 포트의 기본값은 9200이다 [11][12].
`output_format`을 `opensearch`로 준 호출은 인자 배열에 `-o opensearch`로 넘어갔다 [4].
`filter_expression`은 저장 파일 경로 뒤에 인자 하나로 붙는다 [10].
`filter_expression`이 `--`로 시작하면 psort의 `argparse`가 그 값을 옵션으로 읽으므로 `-o opensearch`와 함께 주면 OpenSearch 서버 주소도 호출 인자로 정해진다 [13].
Plaso의 log2timeline과 YARA가 스스로 여는 통신은 확인하지 못했다.

Zimmerman 도구 가운데 EvtxECmd와 RECmd는 `--sync`를 줄 때만 GitHub에서 맵이나 배치 파일을 내려받는다 [14][15].
래퍼는 두 도구에 `--sync`를 넘기지 않는다 [16].
MFTECmd, PECmd, AmcacheParser의 기준 날짜 소스(`.cs`)에서는 내려받기 코드를 찾지 못했고 이 도구들이 쓰는 라이브러리는 확인하지 않았다 [17].

`correlate_timeline`과 `dfir_corr.correlate_timeline`은 `duckdb.connect(":memory:")`로 연결을 열고 확장 자동 설치·자동 불러오기와 외부 접근 설정 `enable_external_access`를 바꾸지 않는다 [18][19].
duckdb-python 1.5.5는 확장 자동 설치와 자동 불러오기를 켠 채 빌드된다 [20].
`correlate_timeline`은 모델이 준 `rules` 문자열을 허용 문자와 금지 낱말로 검사한 뒤 `JOIN … ON` 조건에 넣어 실행한다 [18].
금지 낱말에는 `read_csv`, `read_json`, `install`, `load`가 있고 `select`와 `read_text`는 없다 [18].
콜론 문자를 문자열 함수로 만들어 주소를 조립한 `read_text` 부분 질의를 규칙으로 넘기자 DuckDB가 `httpfs` 확장을 core 저장소에서 내려받아 설치하고 시험용 로컬 HTTP 서버에 `HEAD` 요청을 보냈다 [21].

`dfir_mcp/README.md`는 서버에 밖으로 나가는 네트워크가 없다고 적는다 [22].

                CREATE TABLE ev (ts TIMESTAMP, source VARCHAR, actor VARCHAR,
                                  target VARCHAR, type VARCHAR, raw VARCHAR)""")
            con.executemany("INSERT INTO ev VALUES (?, ?, ?, ?, ?, ?)", normalized)
            for rule in rules:
                if not isinstance(rule, str):
                    continue
                if not _RULE_ALLOWED_RE.match(rule):
                    user_matches.append({"rule": rule,
                                         "error": "rule rejected: disallowed character"})
                    continue
                if _RULE_FORBIDDEN_TOKENS.search(rule):
                    user_matches.append({"rule": rule,
                                         "error": "rule rejected: forbidden SQL keyword"})
                    continue
                try:
                    rows = con.execute(
                        f"SELECT e1.source, e1.ts, e1.target, e2.source, e2.ts, e2.target "
                        f"FROM ev e1 JOIN ev e2 ON {rule} LIMIT 50"
                    ).fetchall()
                    user_matches.append({"rule": rule, "hits": len(rows), "sample": rows[:5]})
                except Exception as ex:
                    user_matches.append({"rule": rule, "error": str(ex)[:200]})
