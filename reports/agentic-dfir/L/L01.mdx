# L01 기록 방식

### L01.01 공통 요청 처리 단계에서 기록

**구현.** 이 방식은 MCP SDK 없이 표준 입력의 JSON-RPC 줄을 직접 처리하는 진입점 `dfir_mcp.server`의 요청 처리 함수 `_handle`에 적용된다 [1].
`_handle`은 `tools/call` 요청마다 등록부의 `call_tool`을 부르고 예외가 올라오면 로거 `dfir_mcp.server`에 항목 하나를 쓴다 [1].
등록부에 없는 도구 이름이면 `call_tool`이 올린 `KeyError`를 받아 `INFO` 수준으로 `tool not found:`와 예외 메시지를 쓴다 [1].
이 예외 메시지에는 요청한 도구 이름이 들어 있다 [2].
그 밖의 예외는 `ERROR` 수준으로 `tool execution failed:`와 예외 종류, 예외 메시지를 쓰고 예외 추적 정보를 붙인다 [1].
이 항목은 실패한 호출에만 남고 성공한 호출에는 남지 않는다 [1].
서버는 모듈을 불러올 때 `logging.basicConfig`로 루트 로거를 `INFO` 수준과 표준 오류 출력으로 설정한다 [3].
그래서 항목은 파일이 아니라 서버 프로세스의 표준 오류로 나가고 그 출력을 어디에 남길지는 서버를 실행한 쪽이 정한다 [3].
JSON-RPC 요청 6개를 넣어 이 진입점을 실행하자 등록부에 없는 이름을 부른 호출, 없는 인자를 넣은 호출, 증거 폴더 밖 경로를 준 호출의 항목 3개가 표준 오류에 남았다 [4].
세 항목에서 도구 이름은 예외 메시지(`'no_such_tool'`, `get_amcache: unexpected argument 'bogus'`)나 예외 추적 정보의 함수 이름(`in get_amcache`)으로 보였다 [4].

MCP SDK의 저수준 `Server`를 쓰는 진입점 `dfir_mcp.server_stdio`에는 이 방식이 없다 [5].
이 진입점의 `handle_call_tool`은 모든 예외를 오류 JSON 글로 바꿔 돌려주고 로그를 쓰지 않는다 [5].
이 진입점은 로깅 처리기를 설정하지 않는다 [5].
MCP Python SDK 1.29.1은 요청마다 요청 종류를 `INFO`로 쓰고 목록에 없는 도구 이름은 `WARNING`으로 쓴다 [6].
처리기가 없는 로거의 항목은 CPython의 `lastResort` 처리기가 받아 `WARNING` 이상만 표준 오류에 쓴다 [7].
SDK 클라이언트로 이 진입점에 같은 종류의 호출 5개를 보내자 표준 오류에는 `Tool 'no_such_tool' not listed, no validation will be performed` 한 줄만 남았다 [8].
클라이언트 `dfir_agent`의 live 모드와 문서가 안내하는 `claude mcp add` 등록은 이 진입점을 실행한다 [9].

외부 도구를 실행하는 공통 함수 `run_tool`은 항목을 쓰지 않고 실행 결과와 출력 파일 해시만 돌려준다 [10].
이 함수의 설명 문구는 시간 제한과 함께 호출 기록(`audit logging`)을 한다고 적는다 [10].

**한계.** `call_tool`이 예외 없이 오류 결과를 돌려주는 호출은 `dfir_mcp.server`에서도 항목을 남기지 않는다 [1].
없는 파일 경로로 부른 `get_amcache`는 `file_not_found` 오류 결과를 돌려줬고 표준 오류에 항목이 남지 않았다 [4].

### L01.04 클라이언트의 MCP 호출 기록

**구현.** 이 방식은 같은 저장소의 클라이언트 `dfir_agent`로 조사할 때만 적용된다 [11].
다른 MCP 클라이언트로 서버에 붙으면 이 기록은 남지 않는다.
`dfir_agent`는 결정적 모드와 live 모드에서 서로 다른 파일에 기록한다 [11].

결정적 모드(`--mode deterministic`, 기본값)는 MCP 전송 없이 등록부의 `call_tool`을 같은 프로세스에서 부른다 [12].
부르는 도구는 코드에 정해 둔 `get_amcache` 1번과 `analyze_usb_history` 1~2번이다 [13].
`DeterministicAnalyst._call`은 `call_tool`의 결과를 받은 뒤 `AuditLogger.log`로 `--out` 폴더의 `audit.jsonl`에 항목 하나를 덧붙인다 [12][11].
항목에는 시각 `ts`, 반복 번호 `iteration`, 도구 이름 `tool_name`, 인자 `inputs`, 출력 해시 `output_digest`, 토큰 수, 발견사항 ID `finding_ids`, 항목 ID `audit_id`, 앞 항목 해시 `prev_hash`, 이 항목의 해시 `entry_hash`가 들어간다 [14].
`inputs`는 `call_tool`에 넘긴 인자 `dict`를 그대로 담는다 [12].
`output_digest`는 도구가 돌려준 `dict`를 키 정렬 JSON으로 바꾼 바이트의 SHA-256이고 출력 자체는 남지 않는다 [15].
그래서 이 해시는 분석 도구의 원래 출력이 아니라 서버 도구가 파싱해 돌려준 결과의 해시다 [15].
토큰 수는 인자 JSON 길이를 4로 나눈 값과 고정값 500이다 [12].
`finding_ids`는 스크립트가 호출 전에 정해 둔 발견사항 ID다 [13].
`AuditLogger`는 `--case` 값을 `run_id`로 받지만 항목에 쓰지 않는다 [11][16][14].
같은 폴더로 다시 실행하면 파일 마지막 항목의 `entry_hash`를 이어 받아 같은 파일에 덧붙인다 [16].
실행을 마치면 `AuditLogger.verify`로 연쇄를 검증하고 실패하면 종료 코드 1을 돌려준다 [11].
결정적 모드를 실행하자 `audit.jsonl`에 항목 3개가 남았고 같은 폴더로 다시 실행하자 6개가 한 연쇄로 검증되었으며 `--case` 값은 어느 항목에도 없었다 [17].
사용자 CLI `python -m dfir_audit`는 이 파일을 `verify`로 검증하고 `lookup`으로 `audit_id` 하나의 항목을, `trace`로 발견사항 ID를 담은 항목을, `summary`로 도구별·반복별 건수를 출력한다 [18].

live 모드(`--mode live`)는 `dfir_mcp.server_stdio`를 하위 프로세스로 실행하고 MCP 세션으로 도구를 부른다 [9].
모델이 낸 도구 호출마다 반복 번호, 도구 이름, 인자를 메모리 목록 `tool_call_log`에 넣은 뒤 `session.call_tool`을 부른다 [19].
대화가 끝나면 `live_run`이 이 목록을 `--out` 폴더의 `live_tool_calls.jsonl`에 쓴다 [20].
이 파일에는 결과, 오류 여부, 시각, 해시가 없다 [19][20].
`--dry-run`이 모델 대신 부르는 정해 둔 호출 4개는 결과 글 앞 200자 `output_preview`도 남긴다 [21].
live 모드는 `AuditLogger`를 쓰지 않는다 [20].
`--dry-run`으로 실행하자 `live_tool_calls.jsonl`에 4줄이 남았고 `audit.jsonl`은 생기지 않았다 [22].
사용자 CLI `analyze.py`는 `dfir_agent`를 live 모드로만 실행한다 [23].

**한계.** 결정적 모드에서 `call_tool`이 예외를 올리면 `_call`은 `AuditLogger.log`를 부르지 않고 그 예외로 실행이 끝난다 [12].
live 모드의 기록은 대화가 끝난 뒤 한 번에 쓰이므로 도중에 예외로 끝난 실행은 `live_tool_calls.jsonl`을 남기지 않는다 [20].
이 파일은 `write_text`로 쓰여 같은 폴더에 있던 앞선 기록을 덮어쓴다 [20].
`analyze.py`는 실행할 때마다 사례별 실행 폴더를 최근 10개만 두고 나머지를 지운다 [24].

저장소 문서의 설명은 코드와 다음 점에서 다르다.

- README는 모든 호출을 `dfir_audit`가 SHA-256 연쇄 JSONL 파일에 기록한다고 적지만 live 모드와 `analyze.py`의 실행은 `dfir_audit`를 쓰지 않는다 [25][20].
- `analyze.py`의 설명은 실행 폴더에 `audit.jsonl`과 `progress.jsonl`이 생긴다고 적지만 live 모드는 두 파일을 쓰지 않는다 [23].
- `docs/live-mode.md`는 모델의 모든 호출이 결과를 쓰기 전에 `live_tool_calls.jsonl`에 기록된다고 적지만 파일은 대화가 끝난 뒤 한 번 쓰인다 [26][20].
- `dfir_audit/README.md`는 SIFT 어댑터 항목에 어댑터가 실행한 명령이 남는다고 적지만 항목에는 도구 이름과 인자만 있다 [27][14].

@app.call_tool()
async def handle_call_tool(name: str, arguments: dict) -> list[TextContent]:
    """Execute a registered function. Any attempt to call something not in
    _REGISTRY raises the same KeyError the in-process path would raise."""
    try:
        result = call_tool(name, arguments or {})
        return [TextContent(
            type="text",
            text=json.dumps(result, default=str, indent=2),
        )]
    except KeyError as e:
        # Surface the ToolNotFound error as a structured result so the
        # agent can reason about it rather than crashing.
        return [TextContent(
            type="text",
            text=json.dumps({"error": "ToolNotFound", "detail": str(e)}),
        )]
    except Exception as e:
        return [TextContent(
            type="text",
            text=json.dumps({"error": type(e).__name__, "detail": str(e)[:500]}),
        )]

```python
def _rotate_out_dirs(case_out_root: Path, keep: int = 10) -> None:
    """Keep only the most recent `keep` timestamped run dirs for one case.

    Every analyze run writes out/<tier>/<case-id>/<timestamp>/ with a transcript,
    tool-call log, findings, etc. Left unchecked this grows without bound — basic
    housekeeping says rotate it. We keep the newest `keep` runs per case (by the
    timestamp dir name, which sorts chronologically) and delete the rest. Only
    timestamp-shaped dirs are touched; anything else is left alone. Best-effort:
    a cleanup failure never blocks the run.
    """
    try:
        if not case_out_root.is_dir():
            return
        runs = sorted(
            (p for p in case_out_root.iterdir()
             if p.is_dir() and p.name.isdigit() is False
             and len(p.name) == 15 and "T" in p.name),
            key=lambda p: p.name,
        )
        for old in runs[:-keep] if len(runs) > keep else []:
            shutil.rmtree(old, ignore_errors=True)
    except Exception:  # noqa: BLE001 — housekeeping must not break the run
        pass
```
