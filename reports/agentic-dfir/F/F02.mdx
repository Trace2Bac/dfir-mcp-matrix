# F02 발견사항·결론 도출

### F02.01 규칙·키 기반 판정·상관

**구현.** 이 방식은 증거 파일 하나를 읽어 정해 둔 규칙으로 항목을 고르는 도구, 모델이 넘긴 결과 목록에 규칙을 대조하는 도구, 공유 키로 결과 항목을 잇는 상관 도구, Sigma 규칙 묶음을 대조하는 `match_sigma_rules`에 적용된다 [1][2][3][4].
규칙은 대부분 이벤트의 필드 값이 아니라 명령줄, 메시지, 경로, URL 같은 글에 정규식이나 부분 문자열을 대조한다.
이벤트 ID, 로그온 유형, 암호화 유형 같은 이벤트 필드 값을 대조하는 규칙은 Windows 이벤트 도구와 `match_sigma_rules`에 있다 [5][6][7].
외부 도구 래퍼 25개 가운데 판정 규칙을 두는 것은 `sift_mftecmd_timestomp` 하나다 [8].

증거 파일을 읽어 판정하는 도구는 다음 규칙을 쓴다.

- `get_process_tree`는 이미지 이름에 `powershell`이 들어 있는 프로세스의 자식 이미지에 `cmd.exe`·`wscript`·`cscript`·`rundll32`가 들어 있으면 `powershell_spawns_shell`을 `flags`에 싣는다 [9].
- 같은 도구는 이미지 이름이 `cmd.exe`로 끝나는 프로세스의 자식이 3개 이상이면 `cmd_spawns_many_children`을 싣는다 [9].
- `analyze_usb_history`는 setupapi 로그에서 뽑은 VID·PID를 정해 둔 IP-KVM 장치 4쌍과 대조해 `is_ip_kvm`을 정하고 해당 사건을 `ip_kvm_indicators`에 모은다 [10].
- `parse_shellbags`는 경로가 `\\`로 시작하거나 `UNC\`를 포함하면 네트워크 공유로, `D:`부터 `Z:`까지의 드라이브 문자로 시작하면 이동식 드라이브로 표시한다 [11].
- `detect_persistence`는 Run 키 명령에 `powershell`·`downloadstring`·`iex `·`mshta`나 `\users\`·`\temp\`·`\appdata\`가 있으면 `severity_hint`를 `high`로, 없으면 `info`로 둔다 [12].
- 같은 도구는 시작 유형에 `auto`가 있거나 값이 `2`이거나 비어 있는 서비스만 보고 실행 경로에 사용자·임시 폴더나 `powershell`이 있으면 `high`로 둔다 [12].
- 예약 작업은 내용을 보지 않고 모두 `info`로 싣는다 [13].
- `analyze_event_logs`는 이벤트 ID가 같고 규칙의 채널 이름이 이벤트의 `Channel` 값에 부분 문자열로 들어 있는 규칙 5개를 고른다 [5].
- 그 가운데 LSASS 접근 규칙은 `TargetImage`에 `lsass.exe`가 있고 `GrantedAccess` 문자열이 `0x1000`·`0x1400`·빈 값이 아니면 맞는다 [1].
- PowerShell 규칙은 `ScriptBlockText`나 `Message`에 다운로드 실행 정규식이 맞으면 맞고 예약 작업 생성·서비스 설치·WMI 구독 규칙은 이벤트 ID와 채널만 맞으면 맞는다 [1].
- `parse_unified_log`는 `subsystem` 값에 규칙의 subsystem 이름이 부분 문자열로 들어 있는 규칙 5개를 고르고 `eventMessage` 글에 정해 둔 낱말이 있으면 경보를 낸다 [14].
- XProtect 규칙은 subsystem만 맞으면 그 이벤트를 모두 `high` 경보로 낸다 [14].
- `parse_fsevents`는 경로에 `/private/tmp/`·`/var/folders/`·`/users/shared/`가 있고 생성이나 삭제 표시가 있는 항목을 `suspicious_samples`로 고른다 [15].
- `parse_browser_history`와 `analyze_downloads`는 URL에 정규식 5개(최상위 도메인, 단축 URL, 붙여넣기 사이트, 숫자 IP, 파일 공유 사이트의 압축·실행 파일)를 대조해 의심 URL을 표시한다 [16].
- `analyze_downloads`는 저장 경로가 실행 파일 확장자 11개 가운데 하나로 끝나는 내려받기를 `executable_downloads`로 고른다 [17].
- `analyze_windows_logons`는 4624·4625·4648 이벤트의 시각이 업무 시간 인자 밖이면 `is_after_hours`를 참으로 두고 그 가운데 로그온 유형 2·10인 성공만 `after_hours_interactive_logons`에 싣는다 [18].
- `analyze_kerberos_events`는 4769 이벤트의 암호화 유형이 `0x17`·`23`·`rc4`이면 Kerberoasting 후보로, 4768 이벤트의 사전 인증 유형이 `0`·`0x0`이면 AS-REP Roasting 후보로 고른다 [6].
- `analyze_unix_auth`는 auth.log 줄에 정규식 6개를 차례로 대조해 SSH 성공·실패, 잘못된 사용자, sudo 성공·실패, su로 나누고 sudo 명령에 `rm -rf`·`curl`·`/etc/shadow` 같은 글자 7개 가운데 하나가 있으면 `severity_hint`를 `high`로 둔다 [19].
- `parse_linux_text_log`는 줄 모양으로 HTTP 접근 로그·syslog·auditd를 가린 뒤 그 줄 전체에 의심 정규식 10개를 모두 대조해 맞은 규칙마다 ATT&CK 기법 ID와 등급을 싣는다 [20][21].
- 같은 도구는 HTTP 접근 로그 줄의 User-Agent에 스캐너 이름이 있으면 줄 번호 0의 `scanner_user_agent` 항목을 하나 더한다 [22].
- `parse_linux_shell_history`와 `parse_bash_history`는 같은 셸 기록 파일에 서로 다른 규칙 표를 대조한다 [23][24].
- `parse_linux_shell_history`는 명령마다 규칙 11개를 모두 대조하고 `parse_bash_history`는 규칙 12개 가운데 처음 맞은 하나만 싣는다 [23][24].
- `analyze_web_access_log`는 메서드·경로·User-Agent를 이은 글에 웹 공격 정규식 16개를 차례로 대조해 처음 맞은 규칙 하나를 싣는다 [25][26].
- 같은 도구는 User-Agent에 스캐너 이름이 있는 요청과 경로가 2,048자를 넘는 요청을 따로 싣는다 [26].
- `detect_webshell`은 업로드·임시 폴더 아래의 웹 스크립트 확장자, 정해 둔 셸 파일 이름, 파일 내용의 셸 코드 정규식 10개, `eval`과 `base64_decode`가 함께 있는지, `\x`가 20번 넘게 나오는 PHP 파일을 신호로 둔다 [27][28][29].
- 내용 정규식, `eval`과 `base64_decode`, 파일 이름 가운데 하나라도 신호가 있으면 `high`이고 그 밖은 `medium`이다 [28].
- `parse_launchd_plist`는 plist의 절대 경로에 들어 있는 글자로 위치 종류와 쓰기 권한을 정한다 [30].
- 같은 도구는 사용자가 쓸 수 있는 위치의 `RunAtLoad`, 임시 폴더의 실행 파일, `KeepAlive`, 3자 미만의 `Label`을 지표로 싣는다 [31].
- `scan_pth_files_for_supply_chain_iocs`는 `.pth` 파일 이름이 `litellm_init.pth`이면 `critical`로, 내용에 `import`·`exec(`·URL·`base64` 같은 정규식 11개 가운데 맞는 것마다 `high`로 표시한다 [32].
- `detect_nodejs_install_hooks`는 `package.json`의 `scripts`에 설치 훅 이름 6개 가운데 하나가 있으면 싣고 `preinstall`이나 `postinstall`이면 `high`로 둔다 [33].
- `detect_python_backdoor_persistence`는 홈 폴더 아래 정해 둔 위치 11곳에 무엇이든 있으면 내용과 관계없이 싣고 `.config/sysmon`이면 `critical`, 나머지는 `high`로 둔다 [34].
- `grep_shell_history_for_c2`는 기록 줄마다 C2 정규식 9개와 모델이 준 `extra_patterns`를 차례로 대조해 처음 맞은 정규식을 싣는다 [35].
- `parse_macos_quarantine`는 내려받은 앱의 bundle ID가 정해 둔 브라우저·앱 13개에 없으면 `non_browser_downloader`를, 두 URL 필드에 정규식 8개가 맞으면 그 이름을 `flags`에 싣는다 [36].
- `parse_linux_cron_jobs`는 cron 일정과 명령을 이은 글에 정규식 11개를 대조하고 `cron.hourly` 같은 폴더의 스크립트는 파일 전체 내용에 대조한다 [37][38].
- `detect_dns_tunneling`은 질의 이름의 하위 레이블에 `dnscat`이 있거나 첫 하위 레이블이 `io`로 시작하고 40자를 넘으면 도구 서명으로 표시하고 TXT·NULL·CNAME 질의를 드문 유형으로 표시한다 [39].
- `sift_mftecmd_timestomp`는 MFTECmd 행마다 `$SI` 생성 시각이나 `$SI` 수정 시각이 `$FN` 생성 시각보다 `tolerance_seconds`를 넘게 이르면 싣는다 [8].
- 첫째 조건은 차이가 1시간을 넘거나 경로가 실행 파일 확장자로 끝나면 등급을 올리고 둘째 조건은 늘 `critical`로 둔다 [8].
- `detect_credential_file_access`는 정해 둔 자격증명 파일 14개가 있는지와 그 시각만 싣고 판정하지 않는다 [40].

모델이 넘긴 결과 목록에는 다음 도구가 규칙을 대조한다.

- `detect_lateral_movement`는 프로세스의 이미지와 명령줄을 이은 글에 원격 관리 도구 정규식 10개를 차례로 대조해 처음 맞은 도구 이름을 싣는다 [2].
- `detect_credential_access`는 이미지 파일 이름이 덤프 도구 이름 11개 가운데 하나와 같으면 싣고 같지 않으면 명령줄에 정규식 13개를 대조한다 [41][42].
- 같은 도구는 Sysmon 이벤트 10에서 `TargetImage`에 `lsass.exe`가 있고 `GrantedAccess`를 16진수로 읽은 값에 `0x10` 비트가 서 있거나 `0x1F0FFF`를 모두 포함하면 싣는다 [43].
- 파일 접근 목록은 경로에 민감 파일 정규식 11개를 대조한다 [44].
- `detect_ransomware_behavior`는 명령줄에 복구 방해 정규식 8개를 대조하고 생성 표시가 있는 파일 이름을 랜섬 노트 이름 17개와 대조한다 [45][46][47].
- `detect_defense_evasion`은 이벤트 ID가 1102·104이면 채널과 관계없이 로그 삭제로 보고 명령줄에 로그 삭제 정규식 4개와 timestomp 정규식 4개를 대조한다 [48][49][50].
- 같은 도구는 MFT CSV의 `$SI` 생성 시각이 `$FN` 생성 시각보다 `timestomp_si_fn_tolerance_seconds`를 넘게 이른 행을 모은다 [51].
- `detect_discovery`는 명령줄에 정찰 명령 정규식 23개를 차례로 대조해 처음 맞은 것의 기법 ID와 묶음 이름을 싣고 AD 묶음이면 `high`, 그 밖은 `medium`으로 둔다 [52][53].
- `detect_exfiltration`은 생성 표시가 있거나 `created` 값이 있는 압축 파일 항목을 신호로 만든다 [54][55].
- 같은 도구는 정해 둔 업로드 도메인 11개에 보낸 전송, 보낸 바이트 수가 `min_archive_bytes`의 10배 이상인 전송, 브라우저 기록의 같은 도메인 방문을 신호로 만든다 [54][56].

상관 도구는 공유 키로 결과 항목을 잇는다.

- `correlate_download_to_execution`은 내려받은 파일 이름과 실행 이미지의 파일 이름이 같거나 실행 경로에 그 파일 이름이 들어 있으면 둘을 잇는다 [57].
- `correlate_timeline`은 같은 저장소의 `dfir_corr`가 DuckDB에 올린 사건 가운데 출처가 다르고 행위자나 대상이 같은 쌍을 잇는다 [3].
- `dfir_corr`는 이은 쌍 가운데 행위자가 같고 사건 종류가 다른 것을 `actor_concurrent_disagreement` 모순으로 만든다 [58].
- `dfir_corr`는 `correlation-rules.yaml`의 규칙 9개마다 정해 둔 두 `source` 값이 같은 행위자로 시간 안에 나오면 그 규칙 이름의 모순도 만든다 [58][59].
- 이 두 모순 목록은 MCP 도구 `correlate_timeline`의 응답에 실리지 않는다 [60].
- MCP 응답은 이은 쌍 가운데 앞 사건 종류가 `usb_insert`이고 뒤가 `logon`인 것을 `kvm_precedes_logon`으로 고른다 [60].
- `correlate_events`는 USB 사건의 `is_ip_kvm`이 참이고 로그온이 시간 창 안에 있으면 `ip_kvm_precedes_logon` 모순으로 싣는다 [61].
- `correlate_timeline`의 `rules` 인자는 모델이 쓴 조인 조건이고 서버는 허용 문자와 금지 낱말만 검사한 뒤 실행해 50행까지 센 일치 수와 앞 5행을 싣는다 [62].

`match_sigma_rules`는 `dfir_sigma/rules/`의 규칙 11개를 이벤트마다 대조한다 [63][4].

- 조건 하나는 이벤트의 최상위 필드 값을 문자열로 바꿔 대소문자 없이 같은지 대조하고 수정자가 `contains`·`endswith`·`startswith`이면 부분 문자열로 대조한다 [7].
- 한 선택 블록의 필드는 모두 맞아야 하고 목록으로 준 블록은 하나만 맞으면 된다 [64].
- `condition`은 블록 이름, `and`, `or`, 괄호만 해석한다 [65].
- 일치 항목에는 규칙 ID·제목·파일 이름·`level`과 `attack.t`로 시작하는 태그만 싣고 tactic 태그와 `falsepositives`는 싣지 않는다 [4].

여러 도구가 규칙마다 ATT&CK 기법 ID를 정해 두고 맞은 항목에 싣는다 [20][23][24][42][46][50][53][8].
기법 ID를 tactic이나 공격 단계로 묶거나 흐름 문장을 만드는 코드는 없다.

판정 규칙에는 다음 제외 조건이 있다.

- `analyze_event_logs`의 LSASS 규칙은 `GrantedAccess`가 `0x1000`·`0x1400`이거나 비어 있으면 뺀다 [1].
- `detect_persistence`는 시작 유형이 자동이 아닌 서비스를 뺀다 [12].
- `parse_macos_quarantine`는 정해 둔 브라우저·앱 13개의 내려받기에 `non_browser_downloader`를 붙이지 않는다 [36].
- `detect_pypi_typosquatting`은 인기 패키지 이름과 같은 이름과 `_`·`.`로 시작하는 폴더를 대조에서 뺀다 [66].
- `analyze_web_access_log`는 요청이 20건 미만인 IP를 스캐닝 판정에서 뺀다 [67].
- 요청 19건이 모두 404인 IP는 스캐닝 판정에서 빠졌고 응답에는 판정에서 뺀 IP가 있다는 표시가 없었다 [68].
- `detect_webshell`은 웹 스크립트 확장자가 아니고 `max_file_size`보다 큰 파일을 신호 검사에서 뺀다 [28].
- 같은 도구는 내용 신호를 웹 스크립트 확장자이면서 `max_file_size` 이하인 파일에만 계산하고 그보다 큰 웹 스크립트 파일은 이름과 위치로만 판정한다 [69].
- `detect_dns_tunneling`은 8자 미만의 레이블에 엔트로피를 계산하지 않는다 [39].

**한계.** 다음 규칙은 도구 설명이나 결과 이름과 다르게 판정하거나 같은 입력을 도구마다 다르게 판정한다.

- `detect_ransomware_behavior`의 대량 이름 바꾸기 규칙은 `Renamed` 표시가 있는 항목을 확장자와 관계없이 센다 [70].
- 랜섬웨어 확장자는 생성 표시가 있는 항목에만 대조한다 [70].
- 이름만 바꾼 `.txt` 파일 20개를 넣자 T1486 `critical` 발견사항이 "renamed/created with ransomware extensions"라는 설명과 함께 나왔다 [71].
- `parse_launchd_plist`는 경로에 `/Library/LaunchAgents`가 있으면 사용자 홈 아래인지 보기 전에 `third_party_agent`·`root_only`로 정한다 [30].
- 그래서 `/Users/<사용자>/Library/LaunchAgents`의 plist는 `user_writable`로 분류되지 않고 `RunAtLoad`가 참이어도 사용자 쓰기 위치 지표가 붙지 않는다 [30][72].
- `analyze_event_logs`는 LSASS 접근 마스크를 문자열로, `detect_credential_access`는 16진수 값의 비트로 대조한다 [1][43].
- 같은 Sysmon 이벤트 2건 가운데 `0x00001000`은 `analyze_event_logs`에서만 경보가 되고 `0x1010`은 두 도구 모두에서 경보가 되었다 [73].
- 셸 기록 두 도구는 같은 명령에 다른 기법 ID를 붙인다 [74].
- `nc -e`는 `parse_linux_shell_history`에서 T1071.001, `parse_bash_history`에서 T1059.004가 되고 `chmod +s`는 T1222.002와 T1548.001이 되었다 [74].
- `analyze_web_access_log`의 `sqli_comment` 규칙은 `--`·`#`·`/*`가 경로 어디에 있어도 맞는다 [25].
- `/docs/page#section` 요청 하나가 `sqli_comment` `medium`으로 실렸다 [75].
- 같은 도구는 `log_format`을 받지만 쓰지 않고 줄 모양으로 형식을 고른다 [76].
- `analyze_kerberos_events`의 설명은 Golden Ticket 후보와 낯선 호스트의 TGT 요청을 찾는다고 적지만 코드에는 Golden Ticket 규칙이 없고 낯선 호스트 판정은 미뤄 둔 채 싣지 않는다 [77][78].
- `analyze_windows_logons`와 `analyze_unix_auth`의 설명은 낯선 출처를 찾는다고 적지만 두 도구는 원격 출처를 모으기만 하고 낯선지 판정하지 않는다 [79][80].
- `detect_exfiltration`의 설명은 클립보드 준비를 찾는다고 적지만 그 규칙은 없다 [81].
- `correlate_download_to_execution`의 설명은 자식 프로세스까지 잇는다고 적지만 결과에는 내려받기와 실행 한 쌍만 실린다 [82][83].
- `extract_mft_timeline` 항목에는 늘 `created` 값이 있어 이 목록을 `detect_exfiltration`에 넘기면 그 가운데 압축 파일은 모두 생성 신호에 포함된다 [55][84].
- `detect_brute_force_rdp`와 `analyze_unix_auth`는 무차별 대입 IP에서 온 로그온 성공을 시각 차례를 보지 않고 `critical` 생존자로 싣는다 [85][86].
- 그래서 실패보다 먼저 일어난 성공도 생존자로 실린다 [85][86].
- `sift_mftecmd_timestomp`는 `$SI` 수정 시각과 `$FN` 수정 시각의 차이를 읽기만 하고 판정에 쓰지 않는다 [87].
- 같은 도구는 MFTECmd 행을 1,000,000개까지만 읽어 판정한다 [88].

다음 경로는 판정을 알리지 않고 건너뛰거나 결과에 다른 것을 섞는다.

- `match_sigma_rules`는 파일의 처음 `limit`개(기본 200개) 이벤트만 판정하고 응답에는 읽은 수 `event_count`만 실린다 [89].
- 이벤트 3건 파일을 `limit` 2로 부르자 `event_count`는 2였고 셋째 이벤트는 대조되지 않았다 [90].
- 같은 도구는 중첩 필드나 `Message` 글 안의 값을 대조하지 않는다 [7][90].
- `not`, `1 of` 같은 낱말은 선택 블록 이름으로 읽혀 거짓으로 계산되고 해석하지 못한 낱말이 있다는 알림은 없다 [65].
- 규칙 묶음의 `pack.yml`은 가장 높은 버전의 묶음을 읽는다고 적지만 코드는 정해 둔 폴더의 `pack.yml` 하나만 읽는다 [91][63].
- `detect_credential_access`는 `sysmon_events_json`을 읽다가 예외가 나면 오류 문구를 기법 ID와 함께 `findings`에 넣고 `finding_count`와 `by_technique`에 센다 [92].
- 증거 폴더 밖 경로를 주자 `finding_count` 1, `by_technique` `{"T1003": 1}`이 실렸다 [93].
- 같은 도구와 `detect_defense_evasion`은 주어진 이벤트 파일이 없으면 그 단계를 알리지 않고 건너뛴다 [92][49].
- `detect_defense_evasion`은 MFT CSV를 읽다 예외가 나면 그때까지 모은 행만으로 판정한다 [51].
- `analyze_event_logs`와 `parse_unified_log`는 규칙 대조에서 예외가 나면 그 규칙을 알리지 않고 건너뛴다 [5][14].
- `sift_mftecmd_timestomp`는 `sift_mftecmd_parse`가 CSV를 얻지 못해 `metadata.error`를 싣고 빈 행을 돌려주면 그 오류를 옮기지 않고 빈 `findings`와 `rows_scanned` 0을 돌려준다 [94].
- CSV를 쓰지 않고 0으로 끝나는 시험용 실행 파일로 부르자 응답에는 오류 표시가 없었다 [95].
- `parse_linux_text_log`는 형식 3개에 맞지 않는 줄에 의심 정규식을 대조하지 않고 그 줄 수를 형식별 줄 수 `formats`의 `unparsed`로만 싣는다 [21][96].
- 형식에 맞지 않는 줄과 syslog 줄에 같은 `/etc/shadow` 글을 넣자 syslog 줄만 의심 항목이 되었고 `unparsed`는 1이었다 [97].

### F02.02 시각·위치 근접 연결

**구현.** 이 방식은 상관 도구 3개와 시간 창으로 두 사건을 잇는 `detect_*`·`analyze_*` 도구 6개에 적용된다 [61][3][57][98][99][100][101][102][103].

- `correlate_events`는 USB 사건 뒤 `proximity_seconds`(기본 600초) 안의 로그온을 잇는다 [61].
- `correlate_timeline`은 앞 사건 뒤 `window_seconds`(기본 300초) 안의 사건을 잇고 `correlation-rules.yaml`의 규칙은 규칙마다 정해 둔 시간 창을 쓴다 [3][58].
- `correlate_download_to_execution`은 내려받기 뒤 `window_seconds`(기본 86,400초) 안의 실행을 잇는다 [57].
- `detect_exfiltration`은 압축 파일 생성 뒤 3,600초 안에 업로드가 있으면 `archive_then_upload_chain`으로 잇는다 [98].
- `analyze_windows_logons`는 로그온 성공 앞 600초 안에 같은 사용자 이름의 실패가 3건 이상이면 `brute_force_survivors`에 싣는다 [99].
- `detect_lateral_movement`는 네트워크·RDP 로그온이나 4648 이벤트 뒤 `proximity_seconds`(기본 60초) 안의 원격 관리 도구 실행을 잇는다 [100].
- `detect_privilege_escalation`은 같은 사용자 이름의 로그온 뒤 `proximity_seconds`(기본 300초) 안의 권한 사건을 잇는다 [101].
- `detect_ransomware_behavior`는 서비스 중지 명령이 `mass_kill_window_seconds`(기본 120초) 안에 10건 이상이면 `mass_service_stop`으로 싣는다 [102].
- `detect_discovery`는 정찰 명령이 한 명령의 시각부터 `burst_seconds`(기본 60초) 안에 `burst_threshold`(기본 5)건 이상이면 `recon_bursts`에 싣는다 [103].

**한계.** `correlate_download_to_execution`은 두 시각 가운데 하나라도 읽지 못하면 시간 창을 대조하지 않고 이름만으로 잇는다 [57].
이때 `delay_seconds`가 `null`로 실린다 [57].
`detect_privilege_escalation`의 설명은 Windows에서 일반 사용자의 로그온 뒤 SYSTEM 권한의 프로세스 생성을 잇는다고 적는다 [104].
코드는 권한 사건의 사용자 이름이 로그온 사용자 이름과 같을 때만 잇는다 [101].
사용자가 `SYSTEM`인 프로세스와 `alice`의 로그온을 1분 차이로 넣자 `transitions`가 비었다 [105].
`detect_lateral_movement`는 `logons`에서 `event_id`가 4648인 항목을 명시 자격증명 로그온으로 고른다 [100].
같은 도구의 입력 설명은 `logons`로 `analyze_windows_logons`의 성공 목록을 넘기라고 적고 그 목록에는 4624 이벤트만 있다 [100][99].
`detect_discovery`의 묶음은 사용자를 가리지 않고 세며 묶음의 `user`에는 첫 명령의 사용자만 실린다 [103].

### F02.03 통계·점수 산정

**구현.** 이 방식은 유사도·엔트로피·비율·건수로 판정하는 도구와 등급을 모으는 도구에 적용된다 [66][39][67][106][86][85][78][70][107].

- `detect_pypi_typosquatting`은 site-packages 폴더 이름과 인기 패키지 이름 35개의 Levenshtein 거리가 1 이상 `max_distance`(기본 2) 이하이면 싣는다 [66].
- 거리가 1이면 `high`, 2 이상이면 `medium`이다 [66].
- `detect_dns_tunneling`은 8자 이상인 하위 레이블의 Shannon 엔트로피가 `entropy_threshold`(기본 3.8)를 넘거나 길이가 `long_label_threshold`(기본 50)를 넘으면 그 질의를 표시한다 [39].
- 같은 도구는 상위 도메인마다 질의 수를 세어 `volume_threshold`(기본 50) 이상이면 `high_volume_domains`에 싣는다 [108].
- 상위 도메인은 공개 접미사 목록 없이 정해 둔 2단계 접미사 22개로 정한다 [109].
- `analyze_web_access_log`는 요청이 20건 이상인 IP 가운데 4xx·5xx 비율이 `error_ratio_threshold`(기본 0.5) 이상이거나 서로 다른 경로가 50개 이상이면 스캐닝으로 보고 비율이 0.8 이상이면 `high`로 둔다 [67].
- `detect_webshell`은 신호가 있는 파일 가운데 파일이 5개 이상인 폴더에서 수정 시각이 폴더 중앙값보다 30일 넘게 늦은 것을 `age_anomalies`에 싣는다 [106].
- `analyze_unix_auth`는 IP마다 SSH 실패와 잘못된 사용자 수를 더해 `brute_force_threshold`(기본 5) 이상이면 무차별 대입 출처로 싣는다 [86].
- `detect_brute_force_rdp`는 IP마다 RDP 실패 수가 `threshold_failures`(기본 5) 이상이면 싣고 그 3배 이상이면 `high`로 둔다 [85].
- 같은 도구는 한 IP가 시도한 사용자가 `spray_distinct_users_threshold`(기본 5)명 이상이면 `credential_stuffing`으로, 한 사용자가 3개 이상의 IP에서 실패하면 `password_spray_users`로 싣는다 [85].
- `analyze_kerberos_events`는 한 사용자의 TGT 요청 출처 IP가 3개를 넘으면 `users_with_scattered_tgts`에 싣는다 [78].
- `detect_ransomware_behavior`는 이름 바꾸기 항목과 랜섬웨어 확장자로 생성된 항목이 합쳐 20개 이상이면 `mass_file_rename_to_ransom_ext`로 싣는다 [70].
- 판정 도구 여러 개는 결과 항목의 등급 가운데 가장 높은 것을 `max_severity`로 싣는다 [107].

**한계.** `detect_pypi_typosquatting`은 인기 패키지 이름을 `set`의 차례로 대조하고 거리 조건에 맞는 첫 이름에서 멈춘다 [66].
`set`의 차례는 프로세스마다 정해지는 문자열 해시에 따라 달라진다 [110].
`clask` 폴더 하나를 두고 `PYTHONHASHSEED`만 바꿔 실행하자 결과가 `flask`(거리 1, `high`)와 `click`(거리 2, `medium`)으로 갈렸다 [110].
`detect_dns_tunneling`의 설명은 짧은 시간 창 안의 질의 수를 본다고 적고 `volume_window_seconds` 인자도 받는다 [111].
코드는 이 인자를 쓰지 않고 로그 전체에서 상위 도메인별 질의 수를 센다 [108].
시각 없는 질의 60건을 `volume_window_seconds` 1로 넣자 `example.com`이 `high_volume_domains`에 실렸다 [112].
`detect_webshell`의 `age_anomalies`는 이미 신호가 있는 파일에만 계산하므로 신호가 없는 파일은 수정 시각이 늦어도 실리지 않는다 [106].

### F02.05 사용 근거·변환 기록

**구현.** 이 방식은 판정 도구의 응답에 적용된다 [5][96][4].
증거 파일을 읽는 판정 도구는 대부분 `source`에 그 파일의 경로와 SHA-256을 싣는다 [5][96][10].
`analyze_event_logs`와 `parse_unified_log`는 경보마다 규칙 ID를 싣고 불러온 규칙 수 `rules_loaded`를 싣는다 [5][14].
`parse_linux_text_log`는 의심 항목마다 줄 번호, 규칙 이름, 기법 ID, 줄 앞 240자를 싣는다 [21].
`grep_shell_history_for_c2`는 맞은 정규식과 줄 번호를 싣는다 [35].
`detect_credential_access`와 `detect_ransomware_behavior`는 명령줄 규칙에 맞은 항목에 그 정규식을 `pattern`으로 싣는다 [42][46].
`parse_linux_cron_jobs`는 작업마다 파일 경로, SHA-256, 줄 번호, 맞은 규칙 이름을 싣는다 [37].
`match_sigma_rules`는 일치마다 규칙 ID·제목·파일 이름과 맞은 이벤트 전체를 싣고 규칙 묶음의 `pack_version`과 `rule_count`를 싣는다 [4].
상관 도구는 이은 두 항목과 시각 차이를 함께 싣는다 [61][83][60].
`correlate_timeline`은 모델이 준 조인 조건을 일치 결과와 함께 `user_rule_matches`에 싣는다 [62].

**한계.** 모델이 넘긴 목록에 규칙을 대조하는 도구는 그 목록이 어느 호출의 응답인지 기록하지 않고 응답에서 온 값인지도 검사하지 않는다 [113].
`match_sigma_rules`의 응답에는 판정한 이벤트 파일의 경로와 해시가 없다 [4][90].
`analyze_downloads`와 `detect_webshell`의 `source`에는 경로만 있고 해시가 없다 [17][106].
처음 맞은 규칙에서 멈추는 도구는 같은 항목에 맞은 다른 규칙을 싣지 않는다 [2][53][26].
`detect_ransomware_behavior`의 `stats.ransom_notes_created`는 랜섬 노트 수가 아니라 랜섬 노트 발견사항 수(0이나 1)를 센다 [114].
`correlate_timeline`의 `cross_source_total`은 `dfir_corr`가 100개로 자른 뒤의 수를 센다 [3][60].
같은 사용자의 사건 30개를 세 출처로 넣자 `cross_source_total`은 100이었고 `dfir_corr`의 `correlations_truncated_at`은 100이었다 [115].

### F02.08 확신 수준·추정 범위 표시

**구현.** 이 방식은 `correlate_events`의 모순 상태 값에 적용된다 [61].
`correlate_events`는 모순마다 판단 보류에 해당하는 `status` `UNRESOLVED`를 싣는다 [61].
USB 사건과 133초 뒤 로그온을 넣자 `ip_kvm_precedes_logon` 모순이 `UNRESOLVED`로 실렸다 [116].
다른 판정 도구는 확신 수준을 따로 값으로 싣지 않는다.
`detect_exfiltration`의 해석 글, `analyze_event_logs`·`parse_unified_log`·`parse_bash_history`·`parse_launchd_plist`의 설명 글에는 "possible", "high-confidence", "(rootkit?)" 같은 낱말이 들어 있다 [55][98][1][14][24][31].
`detect_dns_tunneling`의 `iodine_signature_candidate`와 `analyze_kerberos_events`의 `kerberoasting_candidates`·`asrep_roasting_candidates`는 결과 이름에 후보를 붙인 것이다 [39][117].
`severity`, `severity_hint`, `level`은 위험 등급이고 확신 수준을 나타내지 않는다 [12][4].

**한계.** `dfir_corr`의 `correlate_timeline`도 모순마다 `UNRESOLVED`를 싣지만 MCP 도구 `correlate_timeline`은 이 모순 목록을 응답에 옮기지 않는다 [58][60].
`correlation-rules.yaml`의 규칙으로 만든 모순도 같이 빠진다 [60][59].
행위자가 같고 종류가 다른 사건 두 쌍을 넣자 `dfir_corr`는 모순 3건을 돌려줬고 MCP 응답에는 `contradictions` 키가 없었다 [115].
`dfir_corr`의 `correlate_download_to_execution`은 실행마다 `CORROBORATED`·`UNCORROBORATED`를 싣고 맞는 내려받기가 없는 실행이 하나라도 있으면 결과의 `revision_required`를 참으로 두지만 MCP 도구로 등록되지 않는다 [118].
같은 이름의 MCP 도구는 `dfir_mcp` 안의 다른 구현이고 이 상태 값이 없다 [83].

```python
def _field_matches(event: dict, field: str, expected) -> bool:
    """Evaluate one field condition against an event.

    Supports the ``field|contains`` modifier; otherwise equality (string-cast,
    case-insensitive) — enough for our event shapes.
    """
    if "|" in field:
        name, _, op = field.partition("|")
        val = event.get(name)
        if val is None:
            return False
        if op == "contains":
            return str(expected).lower() in str(val).lower()
        if op == "endswith":
            return str(val).lower().endswith(str(expected).lower())
        if op == "startswith":
            return str(val).lower().startswith(str(expected).lower())
        return str(val).lower() == str(expected).lower()
    val = event.get(field)
    if val is None:
        return False
    return str(val).lower() == str(expected).lower()
```

```python
def _parent_domain(fqdn: str) -> str:
    """Return the registered parent domain of an FQDN (heuristic, no PSL)."""
    parts = fqdn.lower().rstrip(".").split(".")
    if len(parts) <= 2:
        return ".".join(parts)
    # check two-level suffix
    if ".".join(parts[-2:]) in _TWO_LEVEL_SUFFIXES and len(parts) >= 3:
        return ".".join(parts[-3:])
    return ".".join(parts[-2:])
```
