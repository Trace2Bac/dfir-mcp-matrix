# F04 발견사항·결론 기록 관리

### 비적용

**판단.** 서버에는 발견사항, 결론, 가설, 단서 메모, 배제 처분을 받아 남기는 도구가 없다.
도구 73개는 증거 파일을 읽어 결과를 돌려주거나 모델이 넘긴 결과 목록에 규칙을 대조하는 도구이고 발견사항이나 메모를 인자로 받아 저장하는 도구가 없다 [1].
`call_tool`은 등록부의 처리 함수를 불러 결과를 돌려줄 뿐 호출 사이에 상태를 남기지 않는다 [2].
`correlate_events`는 모델이 준 `hypothesis_id`를 응답에 그대로 싣고 가설을 저장하지 않는다 [3].
판정 도구가 만드는 발견사항은 응답으로만 돌아간다.

같은 저장소의 클라이언트 `dfir_agent`는 발견사항과 가설을 클라이언트 쪽에 남긴다 [4].
결정적 모드는 정해 둔 문장의 발견사항 `Finding`과 가설 `Hypothesis`를 메모리에 두고 단계마다 가설과 미해결 목록을 `progress.jsonl`에 덧붙인다 [4][5].
live 모드는 모델의 마지막 글에서 `REPORT:` 뒤의 JSON을 읽어 발견사항 목록을 얻는다 [6].
이 기록은 클라이언트가 남기고 서버를 거치지 않는다.

### 근거

발견사항, 가설, 메모를 기록한다고 적은 도구는 없었다.

```python
def call_tool(name, arguments):
    if name not in _REGISTRY:
        raise KeyError(f"ToolNotFound: '{name}' is not exposed by dfir-mcp")
    spec = _REGISTRY[name]
    return spec.handler(**_validate_arguments(name, spec.schema, arguments))
```

[5] `ProgressTracker`는 단계마다 한 줄을 덧붙인다.

```python
class ProgressTracker:
    def __init__(self, path: Path) -> None:
        self.path = path
        self.path.parent.mkdir(parents=True, exist_ok=True)

    def write(self, snap: ProgressSnapshot) -> None:
        with self.path.open("a", encoding="utf-8") as f:
            f.write(json.dumps(asdict(snap), default=str, sort_keys=True) + "\n")
```
