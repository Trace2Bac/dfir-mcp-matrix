# D06 산출물 식별·재생성 처리

### D06.02 입력·작업별 고유 이름

**구현.** 이 방식은 `sift_plaso_log2timeline`과 `sift_plaso_psort`가 실행하는 Plaso의 로그 파일 이름에 적용된다 [1][2].
서버는 두 도구에 `--logfile`을 주지 않는다 [1][2].
Plaso 20260720은 이때 로그 파일 이름을 `<도구 이름>-YYYYMMDDThhmmss.log.gz`로 지어 실행 시각을 초 단위로 넣는다 [3].
`log2timeline.py`의 작업 프로세스 로그 파일도 같은 이름 앞에 프로세스 이름을 붙인다 [3].
그래서 다시 실행하면 앞 실행의 로그 파일은 남고 새 로그 파일은 이름의 시각으로 구분된다 [3].
이 이름 규칙은 서버 코드가 아니라 Plaso가 정한다.

Plaso 저장 파일의 이름과 위치는 호출 인자 `output_storage_path`가 정하고 서버는 그 이름에 실행이나 입력마다 다른 값을 넣지 않는다 [4].
Zimmerman 도구 래퍼와 `sift_plaso_psort`가 CSV를 쓰는 임시 폴더는 `mkdtemp`가 붙인 난수로 이름이 호출마다 다르지만 호출이 끝나면 지운다 [5].

**한계.** 같은 도구를 같은 초에 다시 실행하면 로그 파일 이름이 같다 [3].
Plaso 20260720은 주 프로세스와 작업 프로세스의 로그 파일을 처음에 쓰기 모드(`w`)로 열므로 이때 앞 로그 파일을 알리지 않고 덮어쓴다 [6].

### D06.04 덮어쓰기 선택·충돌 감지

**구현.** 이 방식은 `sift_plaso_log2timeline`의 저장 파일에 적용된다 [4].
`sift_plaso_log2timeline`은 `output_storage_path`의 경로에 파일이나 폴더가 이미 있으면 `log2timeline.py`를 실행하지 않고 `FileExistsError`로 끝낸다 [4].
오류 문장은 저장 파일이 이미 있으니 새 `output_storage_path`를 고르라고 알린다 [4].
그래서 같은 경로로 다시 부르면 앞 저장 파일은 그대로 남고 새 저장 파일은 만들어지지 않는다 [4][7].
앞 실행이 실패하며 남긴 쓰다 만 저장 파일이 있는 경로도 같은 방식으로 거부된다 [7].
덮어쓰거나 앞 결과를 돌려주도록 고르는 인자는 없다 [8].

같은 저장소의 클라이언트와 사용자 CLI가 쓰는 파일은 서버 구현으로 보지 않고 사실로 적는다.
`dfir_agent`의 결정적 모드는 같은 `--out`으로 다시 실행하면 `audit.jsonl`·`progress.jsonl` 뒤에 이어 쓰고 `report.json`은 알리지 않고 덮어쓴다 [9][10].
live 모드는 같은 폴더의 `live_transcript.txt`·`live_tool_calls.jsonl`·`live_summary.json`을 알리지 않고 덮어쓴다 [11].
`analyze.py`는 실행마다 초 단위 시각을 이름으로 한 폴더를 새로 만들어 `--out`으로 넘긴다 [12].
결과 발견사항이 0건이면 한 번 더 실행하고 두 실행이 같은 초에 시작하면 같은 폴더를 쓴다 [12].

```python
@contextmanager
def _tempdir(prefix: str = "dfir-sift-") -> Iterator[Path]:
    """Create + clean up a per-call temporary working directory."""
    d = tempfile.mkdtemp(prefix=prefix)
    try:
        yield Path(d)
    finally:
        shutil.rmtree(d, ignore_errors=True)
```
