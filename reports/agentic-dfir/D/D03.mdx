# D03 파생물 무결성 검증

### D03.01 기준값 자동 계산

**구현.** 이 방식은 `sift_plaso_log2timeline`이 만든 Plaso 저장 파일에 적용된다 [1].
`sift_plaso_log2timeline`은 저장 파일 경로를 공통 실행 함수 `run_tool`의 `capture_files`로 넘긴다 [1].
`run_tool`은 도구가 끝난 뒤 그 경로가 파일이면 내용 전체의 SHA-256을 계산한다 [2].
기준값은 저장 파일 내용 전체의 SHA-256 하나다 [1][2].
서버는 이 값을 응답의 `storage_sha256`에만 싣고 파일이나 다른 저장소에 남기지 않는다 [1].
`sift_plaso_psort`도 저장 파일을 읽기 전에 그 SHA-256을 계산해 응답의 `storage_sha256`에 싣는다 [3].
`sift_plaso_psort`는 이 값을 만들 때의 값이나 다른 기준값과 대조하지 않는다 [3].
저장 파일을 기준값과 대조하는 도구는 없다.
서버는 Plaso 로그 파일의 해시를 계산하지 않는다.

Zimmerman 도구 래퍼도 임시 폴더에 생긴 CSV의 SHA-256을 계산한다 [4].
그 값은 `sift_mftecmd_parse`·`sift_evtxecmd_parse`·`sift_pecmd_parse`·`sift_amcacheparser_parse`의 응답에만 `csv_sha256`이나 `csv_outputs_sha256`으로 실린다 [4].
그 CSV는 호출이 끝나면 임시 폴더와 함께 지워지므로 이 값과 대조할 파생물이 남지 않는다 [5].

같은 저장소의 클라이언트 `dfir_agent`는 `report.json`을 쓴 뒤 클라이언트 기록 `audit.jsonl`의 연쇄 해시만 검증하고 `report.json`의 해시는 남기지 않는다 [6].

**한계.** `log2timeline.py`가 0으로 끝났는데 저장 파일이 없으면 `storage_sha256`은 `null`이고 서버는 오류를 내지 않는다 [2][1].
가짜 실행 파일로 이 경우를 실행하면 응답은 `storage_sha256`이 `null`인 성공 응답이었다 [7].

def _tempdir(prefix: str = "dfir-sift-") -> Iterator[Path]:
    """Create + clean up a per-call temporary working directory."""
    d = tempfile.mkdtemp(prefix=prefix)
    try:
        yield Path(d)
    finally:
