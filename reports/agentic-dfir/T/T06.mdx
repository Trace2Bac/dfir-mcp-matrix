# T06 실행 환경정보 표시

### T06.01 응답 메타데이터에 버전 표시

**구현.** 이 방식은 `match_sigma_rules`에 적용된다 [1].
`match_sigma_rules`는 규칙 묶음의 규칙으로 사건을 대조한 뒤 묶음의 목록 파일 `pack.yml`을 읽어 그 `version` 값을 응답의 `pack_version`에 싣는다 [1].
응답은 일치한 규칙마다 규칙의 `id`, 제목, 파일 이름 `rule_file`도 싣는다 [1].
기준 커밋의 `dfir_sigma/pack.yml`이 적은 `version`은 `v2`다 [2].
환경변수 `DFIR_SIGMA_DIR`가 있으면 서버는 그 폴더를 규칙 묶음으로 읽고 `pack_version`도 그 폴더의 `pack.yml`에서 읽는다 [3].
실행 확인에서 저장소의 묶음으로 부르면 `pack_version`에 `v2`가, `rule_count`에 11이 실렸다 [4].

서버의 다른 결과에는 도구나 참조 자료의 버전이 실리지 않는다.
외부 도구 래퍼 25개는 응답의 `metadata.tool`에 `volatility3`, `mftecmd`, `yara` 같은 도구 이름만 싣고 실행한 실행 파일의 버전을 싣지 않는다 [5].
외부 도구가 0이 아닌 종료 코드로 끝나면 서버는 표준 오류의 앞 200자를 오류 문구에 넣는다 [6].
실행 확인에서 Volatility 3 2.28.0이 실패한 호출의 오류 문구에는 Volatility가 출력한 `Volatility 3 Framework 2.28.0` 줄이 들어 있었다 [4].
서버는 이 줄을 읽지 않고 문구째 넘긴다 [6].
YARA 래퍼는 사용자가 준 규칙 파일의 경로만 싣고 규칙 파일의 해시나 버전을 싣지 않는다 [7].
`correlate_timeline`은 `engine` 값 `duckdb`를 싣고 `parse_knowledgec`와 `parse_browser_history`는 SQLite 파일을 직접 읽었을 때 `engine` 값 `sqlite3_readonly`를 싣지만 라이브러리의 버전은 싣지 않는다 [8].
`analyze_event_logs`와 `parse_unified_log`는 코드에 둔 규칙의 수만 `rules_loaded`로 싣는다 [9].
`parse_registry_hive`는 python-registry로 하이브를 읽지만 응답에 그 버전을 싣지 않는다 [10].
`dfir_corr` 패키지는 `__version__` 값 `2.0.0`을 두지만 상관 도구의 응답에는 이 값이 없다 [11][8].
`sift_plaso_log2timeline`이 남기는 저장 파일은 log2timeline이 만들고 서버는 그 파일의 SHA-256과 경로만 응답에 싣는다 [12].

서버 자신의 버전은 MCP 초기화 응답의 `serverInfo`에만 있다 [13][14].
`server.py`는 `serverInfo.version`에 코드에 적은 `2.0.0`을 싣는다 [13].
`server_stdio.py`는 MCP Python SDK의 저수준 `Server`를 이름만 주어 만든다 [14].
MCP Python SDK 1.29.1은 서버 버전이 없으면 `mcp` 패키지의 버전을 `serverInfo.version`에 넣는다 [15].
실행 확인에서 `server_stdio`의 `serverInfo.version`은 `1.29.1`이었고 `server.py`의 값은 `2.0.0`이었다 [4].
서버 진입점은 호출 기록을 쓰지 않는다.
같은 저장소의 `dfir_agent`가 쓰는 호출 기록은 참조 실행 출력에서 도구 이름, 인자, 출력 해시, 시각을 싣고 버전 필드가 없다 [16].
서버는 처리 중에 모델을 부르지 않는다.

**한계.** 서버는 규칙을 읽는 과정과 따로 `pack.yml`을 다시 읽어 `pack_version`을 정한다 [1][3].
`pack.yml`이 없거나 YAML로 읽히지 않으면 서버는 기본 폴더 `rules`의 규칙으로 대조하고 `pack_version`을 `null`로 싣는다 [3][1].
실행 확인에서 규칙 파일 하나를 YAML로 읽히지 않게 바꾸고 `pack.yml`을 지운 묶음으로 부르면 규칙 10개로 대조한 결과와 함께 `pack_version`이 `null`이었다 [4].
`pack_version`은 `pack.yml`에 적힌 문자열이고 응답에 규칙 파일의 해시는 없다 [1].
그래서 `pack_version`이 같은 채로 규칙 파일의 내용이 바뀌면 응답으로는 구별되지 않는다 [1].

```python
def _load_rules() -> list[dict]:
    """Load every rule .yml under the highest-version pack's rules_dir."""
    root = _pack_root()
    manifest = _load_yaml(root / "pack.yml") or {}
    rules_dir = root / (manifest.get("rules_dir", "rules"))
    if not rules_dir.is_dir():
        return []
    rules = []
    for f in sorted(rules_dir.glob("*.yml")):
        r = _load_yaml(f)
        if isinstance(r, dict) and r.get("detection"):
            r["_file"] = f.name
            rules.append(r)
    return rules
```
