# T02 실행 허용 범위 제한

### T02.04 고정 명령·템플릿

**구현.** 이 방식은 외부 도구를 실행하는 래퍼 25개와 `correlate_timeline`의 기본 상관 질의에 적용된다 [1][2][3][4][5][6].
래퍼는 실행 파일, 옵션, 플러그인 이름을 서버 코드에서 정한 명령 배열로 만들고 모델 값은 정해 둔 자리에만 넣는다 [1][2][3][4][5].
Volatility 3 래퍼 12개는 `-q -r csv -f <이미지> <플러그인>` 배열을 만들고 플러그인 이름은 도구마다 코드에 적혀 있다 [1].
`sift_vol3_windows_dlllist`는 정수 `pid`를 `--pid` 뒤에, `sift_vol3_windows_runkey`는 문자열 `key`를 `--key` 뒤에 넣는다 [7].
MFTECmd·EvtxECmd·PECmd·AmcacheParser 래퍼 7개의 명령 배열에는 입력 경로와 서버가 만든 임시 출력 폴더만 들어가고 모델이 고르는 옵션은 없다 [2].
`sift_recmd_run_batch`는 배치 파일 이름을 서버 코드의 목록에서 고르고 `sift_recmd_query_key`는 `key_path`를 `--kn` 뒤에 넣는다 [3].
YARA 래퍼는 규칙 파일과 대상 경로, `fast_mode`에 따른 `-f`, `max_file_size`에 따른 `--max-file-size` 값을 넣는다 [4].
`sift_plaso_log2timeline`은 `parsers`를 `--parsers` 뒤에 넣고 `sift_plaso_psort`는 `output_format`을 `-o` 뒤에, `filter_expression`을 저장 파일 경로 뒤 위치 인자로 넣는다 [5].
경로 인자 자리에는 증거 폴더 안으로 변환한 절대 경로가 들어가고 Plaso 저장 파일 자리에는 `DFIR_DERIVED_ROOT` 아래 경로가 들어간다 [8].
인자를 기록하는 시험용 실행 파일을 `DFIR_*_BIN`으로 지정하고 래퍼 13개를 부르자 실행 파일이 받은 인자가 위의 배열과 같았다 [9].
`correlate_timeline`의 기본 상관 질의는 코드에 적힌 DuckDB 질의 틀에 정수로 바꾼 `window_seconds`만 넣고 사건 값은 매개변수로 넣는다 [6].
SQLite 파일을 읽는 `parse_knowledgec`와 `analyze_downloads`도 코드에 적힌 질의 틀에 모델 값을 매개변수나 정수로만 넣는다 [10].

모델이 부를 수 있는 도구는 등록부 `_REGISTRY`의 73개이고 서버는 등록부에 없는 이름을 `ToolNotFound`로 거부한다 [11].
두 진입점은 등록부 전체를 도구 목록으로 내보내고 사용자가 실행 인자, 환경변수, 설정 파일로 도구를 끄는 장치는 없다 [11][12].
같은 저장소의 클라이언트 `dfir_agent`의 live 모드는 `tools/list`로 받은 도구를 모두 모델에 넘기고 모델이 고른 이름을 그대로 `call_tool`로 보낸다 [13].
이 클라이언트에는 도구 허용·거부 목록이 없다 [13].
이 클라이언트는 Anthropic Messages API에 MCP 도구 정의만 넘기고 셸이나 파일 읽기 같은 클라이언트 자체 도구를 두지 않는다 [13].

**한계.** 모델 값을 넣기 전에 옵션 끝 표시를 두거나 `-`로 시작하는 값을 거르는 검사는 없다 [7][3][5].
`key`, `key_path`, `parsers`, `output_format`, `filter_expression`이 이런 자리에 들어간다 [7][3][5].
시험용 실행 파일로 확인하자 `-`로 시작하는 `key`·`key_path`·`parsers`·`filter_expression` 값이 받은 인자에 그대로 들어 있었다 [9].
psort는 argparse로 인자를 읽고 필터를 선택 위치 인자로 둔다 [14].
Plaso가 없는 환경이라 psort가 `-`로 시작하는 필터 값을 어떻게 읽는지는 실행해 보지 못했다 [14].
`output_format`은 서버 코드의 목록과 대조하지 않고 그대로 `-o`의 값이 되며 출력 파일 이름 `timeline.<output_format>`에도 들어간다 [5].
`sift_yara_scan_dir`은 `max_file_size`가 0보다 크면 `--max-file-size`를 넣는데 YARA 4.5.8에는 이 이름의 옵션이 없고 같은 일을 하는 옵션은 `-z`·`--skip-larger`다 [4][15].
YARA 4.5.8은 모르는 옵션을 받으면 종료 코드 1로 끝나고 래퍼는 이때의 예외를 `matches`가 빈 응답으로 바꾼다 [15][4].
YARA가 없는 환경이라 이 경로는 실행해 보지 못했다.

### T02.05 연산·플러그인 허용 목록

**구현.** 이 방식은 `sift_recmd_run_batch`의 `batch_name`, `analyze_downloads`의 `mode`, `parse_bash_history`의 `log_format`에 적용된다 [3][16][17].
`sift_recmd_run_batch`는 `batch_name`을 서버 코드의 `_KNOWN_BATCHES` 4개(`ASEPs`·`kroll`·`USB`·`All`)와 대조한다 [3].
목록에 없는 값은 거부하지 않고 `ASEPs`의 `RECmd_Batch_MC.reb`로 바꾼다 [3].
`batch_name`에 목록 밖 값을 주자 실행 파일이 `--bn RECmd_Batch_MC.reb`를 받았고 응답의 `batch_name`에는 준 값이 그대로 남았다 [9].
`analyze_downloads`의 `mode`는 `browser_db`·`zone_identifier`·`auto`, `parse_bash_history`의 `log_format`은 `auto`·`bash`·`zsh`로 입력 schema의 `enum`에 적혀 있고 처리 함수가 이 값으로 처리 방식을 고른다 [16][17].
`_validate_arguments`는 `enum` 밖의 값을 `ValueError`로 거부하고 `server_stdio.py`에서는 SDK가 같은 schema로 먼저 거부한다 [18][19].
`server_stdio.py`에 `enum` 밖의 값을 보내자 `Input validation error` 결과가 돌아왔다 [20].
`parse_browser_history`의 `browser`와 `analyze_web_access_log`의 `log_format`도 `enum`으로 값을 좁히지만 처리 함수는 이 값으로 처리 방식을 고르지 않는다 [21].
Volatility 플러그인과 Plaso 파서는 서버 코드의 목록과 대조하지 않는다 [1][5].
Volatility 플러그인은 도구마다 코드에 고정되어 모델이 고르지 않고 Plaso의 `parsers`는 모델이 준 문자열이 그대로 전달된다 [1][5].

### T02.06 질의 구조·연산 검사

**구현.** 이 방식은 `correlate_timeline`의 `rules`에 적용된다 [22].
`rules`의 각 문자열은 서버가 정한 DuckDB 질의 `SELECT … FROM ev e1 JOIN ev e2 ON <규칙> LIMIT 50`의 `ON` 자리에 들어간다 [22].
서버는 문자열을 넣기 전에 두 가지를 검사한다 [22].
먼저 문자열이 유니코드 글자·숫자·밑줄, 줄바꿈을 포함한 공백 문자와 `.()=<>!+-*/,'"` 문자로만 이루어졌는지 정규식으로 보고 다른 문자가 있으면 `rule rejected: disallowed character`로 거부한다 [22].
다음으로 `union`·`drop`·`attach`·`copy`·`pragma`·`read_csv` 같은 낱말 23개를 대소문자 구분 없이 찾고 있으면 `rule rejected: forbidden SQL keyword`로 거부한다 [22].
문자열이 아닌 항목은 결과 없이 건너뛰고 거부 사유와 실행 오류는 응답의 `user_rule_matches`에 `error`로 남는다 [22].
질의는 `ev` 표 하나만 만든 메모리 DuckDB 연결에서 실행된다 [22].
세미콜론을 쓴 규칙과 `union`을 쓴 규칙이 각각 두 사유로 거부되는 것을 실행으로 확인했다 [23].

**한계.** 검사는 문자 종류와 낱말 목록만 보고 질의의 구문 구조는 보지 않는다 [22].
`select`와 괄호는 거부 대상이 아니어서 규칙 안에 하위 질의를 둘 수 있다 [22].
낱말 목록에 없는 DuckDB 함수는 검사를 통과한다 [22].
서버는 연결을 열 때 DuckDB의 외부 접근 설정 `enable_external_access`를 끄지 않고 DuckDB 1.5.5에서 이 설정의 기본값은 `true`다 [22][24].
하위 질의에서 `read_text`로 증거 폴더 밖 파일을 읽는 규칙과 `glob`으로 폴더 목록을 읽는 규칙은 두 검사를 통과해 실행되었다 [23].
`read_text` 규칙은 읽은 파일 내용을 정수로 바꾸는 단계에서 실패했고 그 파일 내용이 `error` 문자열에 들어 있었다 [23].
같은 꼴로 `read_csv`를 쓴 규칙은 낱말 검사에서 거부되었다 [23].
