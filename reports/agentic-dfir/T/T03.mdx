# T03 실행 조건 확인

### 미구현

**판단.** 서버에는 앞선 작업 상태, 조사 단계, 승인, 호출자 신원, 실행 자원으로 호출을 막거나 미루는 코드가 없다.
두 진입점은 등록부에 있는 도구 이름과 인자 검사만 확인하고 바로 처리 함수를 부른다 [1][2].
`sift_plaso_psort`는 증거 폴더나 `DFIR_DERIVED_ROOT` 아래에 `storage_path` 파일이 있어야 실행한다 [3].
이 검사는 인자로 받은 경로가 있는지 보는 것이고 그 파일이 앞선 `sift_plaso_log2timeline` 호출이 만든 저장 파일인지는 대조하지 않는다 [3].
`sift_plaso_log2timeline`은 출력 경로에 파일이 이미 있으면 `FileExistsError`로 실행하지 않는다 [4].
이 조건은 이미 있는 결과를 덮어쓰지 않는 동작이고 호출마다 받는 승인이 아니다 [4].
도구 설명에도 선행 호출이나 승인을 요구하는 문구는 없다.

같은 저장소의 클라이언트 `dfir_agent`의 결정적 모드는 모델 없이 같은 프로세스에서 코드에 정한 단계 순서대로 `call_tool`을 부르고 `max_iterations`에 이르면 남은 단계를 건너뛴다 [5].
이 순서와 상한은 클라이언트의 진행 방식이고 서버가 호출을 거부하는 조건이 아니다 [5].
서버에는 사용자가 낸 승인 토큰이나 승인 기록을 요청과 대조하는 코드가 없다.
`server_stdio.py`는 SDK의 stdio 전송으로만 실행되고 `server.py`는 표준 입력의 JSON-RPC 줄을 읽으므로 원격 MCP 연결을 받지 않는다 [6][2].
메모리, CPU, 디스크 여유 공간을 확인하는 코드는 없다.

동시 실행 수를 정하는 장치도 없다.
MCP Python SDK 1.29.1의 저수준 `Server`는 받은 메시지마다 같은 이벤트 루프의 작업으로 처리기를 시작한다 [7].
`server_stdio.py`의 `handle_call_tool`은 `async` 함수이지만 안에서 동기 함수 `call_tool`을 바로 부른다 [1].
그래서 외부 도구의 `subprocess.run`을 포함한 한 호출이 끝날 때까지 다른 요청은 처리되지 않는다 [1][8].
2초 동안 기다리는 시험용 실행 파일을 Volatility 3 실행 파일로 지정하고 `sift_vol3_windows_pslist` 호출 2개를 동시에 보내자 둘째 실행이 첫째가 끝난 2.02초 뒤에 시작해 두 응답이 4.04초 뒤에 왔다 [9].
`server.py`는 표준 입력을 한 줄씩 읽어 처리를 마친 뒤 다음 줄을 읽는다 [2].
이는 서버가 정한 제한이 아니라 처리기가 동기 함수를 이벤트 루프에서 바로 부르는 방식에서 생기는 동작이다.

```python
async def handle_call_tool(name: str, arguments: dict) -> list[TextContent]:
    """Execute a registered function. Any attempt to call something not in
    _REGISTRY raises the same KeyError the in-process path would raise."""
    try:
        result = call_tool(name, arguments or {})
        return [TextContent(
            type="text",
            text=json.dumps(result, default=str, indent=2),

        )]

            type="text",
            text=json.dumps({"error": type(e).__name__, "detail": str(e)[:500]}),
        )]
```

```python
    def run(self) -> dict:
        # Hard cap: the controller refuses to exceed max_iter even if the
        # playbook schedules additional phases. Exit path writes a closeout
        # report so an early exit is still analyst-readable.
        phases = [
            self._phase_timeline,
            self._phase_hypothesis,
            self._phase_validate_usb,  # triggers self-correction
            self._phase_finalize,
        ]
        for phase in phases:
            if self.iteration >= self.max_iter:
                self._forced_exit_closeout()
                return self._report()
            phase()
        return self._report()
```
