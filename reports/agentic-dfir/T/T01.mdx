# T01 입력 검증

### T01.01 인자 구조·값 검사

**구현.** 이 방식은 등록부 `_REGISTRY`에 있는 도구 73개의 모든 호출에 적용된다 [1].
같은 프로세스 호출, `server.py`, `server_stdio.py`는 모두 `call_tool`로 도구를 부른다 [1][2].
`call_tool`은 처리 함수를 부르기 전에 `_validate_arguments`로 인자를 검사한다 [1].
`_validate_arguments`는 입력 schema의 `properties`·`required`·`additionalProperties`·`type`·`enum`·`minimum`·`maximum`·`default`만 읽는다 [3].
schema에 없는 인자와 빠진 필수 인자는 `TypeError`로 거부한다 [3].
schema에 `additionalProperties`가 없으면 없는 인자를 받지 않는 것으로 처리하고 이 키를 둔 도구는 없다 [3].
자료형은 `_schema_type_matches`로 대조하고 `integer`·`number` 자리에 `bool`이 오면 거부한다 [4].
`enum` 밖의 값과 `minimum`·`maximum`을 벗어난 수는 `ValueError`로 거부한다 [3].
빠진 선택 인자에는 schema의 `default`를 넣고 그 값도 같은 검사를 거친다 [3].
`get_amcache`에 없는 인자 `foo`, 문자열 `"10"`이나 `true`인 `limit`, 501인 `limit`, -1인 `cursor`를 주자 처리 함수가 실행되기 전에 모두 거부되었다 [5].
`parse_browser_history`의 `browser`에 `opera`를 주자 `not in enum` 오류로 거부되었다 [5].

`server_stdio.py`에서는 MCP Python SDK 1.29.1의 저수준 `Server`가 `_validate_arguments`보다 먼저 `tools/list`로 알린 입력 schema 전체로 인자를 검사한다 [6].
이 검사는 list 항목의 자료형도 보고 어긋나면 처리 함수를 부르지 않고 `Input validation error`로 시작하는 오류 결과를 돌려준다 [6].
`sift_evtxecmd_filter_eids`의 `event_ids`에 정수 list를 주자 `server_stdio.py`는 이 오류로 거부했다 [7].
같은 인자를 `server.py`와 같은 프로세스 호출에 주자 검사를 통과해 실행 파일을 찾는 단계에서 `SiftToolNotFoundError`로 끝났다 [7][5].
SDK 검사는 schema에 없는 인자를 막지 않으므로 그런 인자는 세 경로 모두 `_validate_arguments`가 거부한다 [7].

`extract_mft_timeline`은 `start`·`end`를 시각으로 읽지 못하면 부속 CSV를 읽지 않고 `bad_time_format`을 돌려준다 [8][5].
`parse_prefetch`는 부속 JSON이 없을 때 파일 이름이 `<이름>-<16진수 8자리>.pf` 꼴인지 보고 아니면 `bad_prefetch_name`을 돌려준다 [9].
`sift_recmd_run_batch`는 `batch_name`이 `_KNOWN_BATCHES`에 없으면 거부하지 않고 기본값 `ASEPs`의 배치 파일로 바꾼다 [10].
`batch_name`에 `no_such_batch`를 주자 `--bn RECmd_Batch_MC.reb`로 실행 파일이 불렸고 응답의 `batch_file`도 그 이름이었다 [11].
검사 기준은 모두 서버 코드의 schema와 상수이고 설치된 도구나 설정에서 읽는 기준은 없다 [3][10].

**한계.** 시각 인자는 대부분 `_parse_ts`로 읽고 읽지 못하면 `None`이 되어 그 시간 조건 없이 실행된다 [12].
`analyze_windows_logons`의 `time_window_end`에 `2000-01-01T00:00:00`을 주자 성공 로그온이 0건이었고 `garbage`를 주자 조건 없이 부른 것과 같은 275건이 나왔다 [13].
`grep_shell_history_for_c2`는 `extra_patterns`의 정규식을 컴파일하지 못하면 알리지 않고 그 패턴을 건너뛴다 [14].
`extra_patterns`에 `(`와 `sshd`를 주자 `patterns_checked`가 `sshd` 하나만 주었을 때와 같은 10이었다 [13].
`minimum`이 없는 정수 인자는 음수를 받는다 [3].
`parse_shimcache`의 `limit`에 -1을 주자 거부되지 않고 `cursor_next`가 -1인 응답이 왔다 [13].
`server.py`와 같은 프로세스 호출에서는 list 항목의 자료형을 검사하지 않는다 [3][7].

### T01.02 입력 존재·읽기 가능 검사

**구현.** 이 방식은 경로 인자를 받는 도구 63개 가운데 60개에 적용된다 [15][16].
네이티브 도구는 `_safe_resolve`로 대조한 경로가 없으면 파일을 읽지 않고 `file_not_found`나 `directory_not_found` 같은 오류를 돌려준다 [15].
`detect_webshell`, `scan_pth_files_for_supply_chain_iocs`, `detect_pypi_typosquatting`, `detect_nodejs_install_hooks`는 폴더인지도 보고 아니면 `not_a_directory`를 돌려준다 [15].
외부 도구 래퍼 25개는 `safe_evidence_input`이 경로가 없으면 `PathTraversalAttempt`를 내서 실행 파일을 부르지 않는다 [16].
없는 파일을 `parse_linux_text_log`에 주자 `file_not_found`가 왔고 `sift_vol3_windows_pslist`에 주자 `evidence path does not exist` 예외로 끝났다 [17].
`get_amcache`, `parse_shimcache`, `parse_shellbags`, `extract_mft_timeline`은 부속 CSV가 없으면 `amcache_csv_missing`·`shimcache_csv_missing` 같은 오류를 돌려주고 원래 파일을 파싱하지 않는다 [18].
서버는 읽기 권한을 미리 확인하지 않는다 [15][16].
권한이 없는 파일을 주자 `parse_linux_text_log`는 읽는 단계에서 `read_failed`를 돌려주었고 `get_process_tree`는 `PermissionError`로 끝났다 [17].

나머지 3개는 입력이 없어도 거부하지 않는다.
`detect_credential_access`의 `sysmon_events_json`과 `detect_defense_evasion`의 `events_json`·`mft_csv`는 선택 인자이고 경로가 없으면 그 단계를 알리지 않고 건너뛴다 [19].
이 두 도구에 없는 경로를 주자 오류 없이 `finding_count`가 0인 응답이 왔다 [17].
`parse_linux_cron_jobs`는 `evidence_root`가 있는지 확인하지 않고 그 아래 cron 위치가 없으면 빈 목록으로 처리한다 [20].

**한계.** `safe_evidence_input`의 설명은 읽기 권한을 확인한다고 적지만 코드는 경로가 있는지만 본다 [16].

### T01.03 실제 경로로 변환해 허용 폴더 대조

**구현.** 이 방식은 경로 인자를 받는 도구 63개의 읽기 경로 인자에 적용된다 [21][16].
네이티브 도구는 `_safe_resolve`를 직접 부르고 외부 도구 래퍼는 이 함수를 부르는 `safe_evidence_input`을 거친다 [21][16].
`_safe_resolve`는 인자를 `EVIDENCE_ROOT`에 이어 붙인 뒤 `Path.resolve()`로 실제 경로로 변환해 `..`와 심볼릭 링크를 해석한다 [21].
그 뒤 `relative_to`로 `EVIDENCE_ROOT`의 실제 경로 아래인지 대조하고 밖이면 `PathTraversalAttempt`로 거부한다 [21].
경로 구성 요소로 비교하므로 이름이 증거 폴더 이름으로 시작하는 이웃 폴더는 통과하지 못한다 [21][22].
절대 경로를 주면 이어 붙일 때 앞의 증거 폴더가 버려지고 그 절대 경로가 그대로 대조된다 [21][22].
도구는 이 함수가 돌려준 변환한 경로로 파일을 열거나 외부 도구에 넘긴다 [16].
`EVIDENCE_ROOT`는 서버 모듈을 불러올 때 환경변수 `DFIR_EVIDENCE_ROOT`에서 읽고 값이 없으면 `/mnt/evidence`다 [21].
`../outside/secret.txt`, `/etc/hostname`, 증거 폴더 밖을 가리키는 심볼릭 링크를 주자 모두 `path escapes evidence root`로 거부되었다 [22].
증거 폴더 안의 절대 경로는 통과했다 [22].

`sift_plaso_psort`의 `storage_path`는 증거 폴더 대조에 실패하면 `_safe_derived_path`로 `DFIR_DERIVED_ROOT` 아래인지 다시 대조한다 [23].
이 함수도 경로를 실제 경로로 변환해 `relative_to`로 대조하고 밖이면 거부한다 [23].
`DFIR_DERIVED_ROOT`가 없으면 시스템 임시 폴더 아래 `agentic-dfir-derived`가 두 번째 허용 폴더가 된다 [24].
`/etc/hostname`을 `storage_path`로 주자 `derived path escapes DFIR_DERIVED_ROOT`로 거부되었다 [22].
`sift_yara_scan_file`·`sift_yara_scan_dir`는 규칙 파일 경로 `rules_path`에도 같은 대조를 적용해 규칙 파일도 증거 폴더 안에 있어야 한다 [25].
`parse_linux_cron_jobs`의 `evidence_root` 기본값 `/`는 증거 폴더 밖이라 인자 없이 부르면 거부된다 [20][22].
인자가 없는 `list_scheduled_tasks`와 `detect_persistence`는 이 대조 없이 증거 폴더 아래 고정 위치를 연다 [26].
`Tasks` 폴더에 증거 폴더 밖 파일을 가리키는 심볼릭 링크를 두자 `list_scheduled_tasks`가 그 파일의 크기와 SHA-256을 돌려주었다 [27].

**한계.** 서버가 대조한 경로에서 다시 만든 경로는 대조하지 않는다.
`get_amcache`, `parse_prefetch`, `parse_shimcache`, `parse_shellbags`, `extract_mft_timeline`, `parse_knowledgec`, `parse_browser_history`, `analyze_downloads`는 대조한 경로의 확장자를 바꾸거나 붙여 부속 파일 경로를 만들고 그대로 연다 [28].
`Amcache.csv`가 증거 폴더 밖 CSV를 가리키는 심볼릭 링크일 때 `get_amcache`에 `Amcache.hve`를 주자 밖의 CSV 행이 `items`로 돌아왔다 [27].
폴더 아래를 훑는 도구는 `rglob`·`glob`·`iterdir`로 찾거나 정해 둔 상대 경로로 만든 하위 경로를 다시 대조하지 않고 연다 [29].
이 도구는 `analyze_downloads`의 `zone_identifier` 모드, `detect_webshell`, `_v05_supply_chain`의 폴더 도구 5개, `parse_linux_cron_jobs`다 [29].
`sift_yara_scan_dir`은 YARA에 `-r`로 폴더를 넘기고 `--no-follow-symlinks`를 주지 않는다 [30].
YARA 4.5.8은 이 옵션이 없으면 심볼릭 링크를 따라 검사하므로 폴더 안 링크가 가리키는 증거 폴더 밖 파일도 검사 대상이 된다 [30].
기본값처럼 `max_file_size`가 0보다 크면 YARA가 모르는 옵션으로 끝나므로 이 경로는 `max_file_size`를 0 이하로 준 호출에만 해당한다 [30].
YARA가 없는 환경이라 이 경로는 실행해 보지 못했다.
EvtxECmd, PECmd, log2timeline이 폴더를 받았을 때 심볼릭 링크를 따라가는지는 확인하지 못했다.

### T01.04 문자열 경로 검사

**구현.** 이 방식은 `_safe_resolve`의 앞부분과 `sift_plaso_psort`의 `storage_path`를 대조하는 `_safe_derived_path`에 적용된다 [21][23].
`_safe_resolve`는 파일시스템을 보기 전에 문자열이 아니거나 비어 있는 값, 널 문자가 들어 있는 값, 1024자를 넘는 값을 `PathTraversalAttempt`로 거부한다 [21].
`_safe_derived_path`는 널 문자를 거부하고 상대 경로이면 `\`를 `/`로 바꿔 나눈 조각에 `.`이나 `..`이 있으면 거부한다 [23].
두 검사를 통과한 값은 이어서 실제 경로로 변환되어 허용 폴더와 대조된다 [21][23].
널 문자가 들어 있는 경로와 1025자 경로는 `null byte in path`와 `path too long`으로 거부되었다 [22].
`storage_path`에 `../outside/secret.txt`를 주자 증거 폴더 대조에서 거부된 뒤 `invalid derived path`로 거부되었다 [22].

### T01.06 고정 입력 경로 사용

**구현.** 이 방식은 인자가 없는 `list_scheduled_tasks`와 `detect_persistence`에 적용된다 [26].
`list_scheduled_tasks`는 증거 폴더 아래 `disk/Windows/System32/Tasks`나 `Windows/System32/Tasks`만 훑는다 [26].
`detect_persistence`는 증거 폴더 아래 정해 둔 위치의 `NTUSER.DAT.runkeys.csv`·`SOFTWARE.runkeys.csv`·`SYSTEM.services.csv`(또는 `services.csv`)를 읽고 `list_scheduled_tasks`를 불러 예약 작업을 더한다 [26].
두 도구가 읽는 위치는 사용자가 `DFIR_EVIDENCE_ROOT`로 정한 증거 폴더와 코드에 적은 상대 경로로 정해진다 [26][21].
`parse_linux_cron_jobs`, `detect_python_backdoor_persistence`, `detect_credential_file_access`도 정해 둔 상대 경로를 읽지만 그 뿌리 폴더는 모델이 인자로 정한다 [20][31].

### T01.07 입력 부재 시 다른 입력으로 대체

**구현.** 이 방식은 `list_scheduled_tasks`, `detect_persistence`, `parse_shimcache`, `parse_shellbags`에 적용된다 [26][32].
`list_scheduled_tasks`는 `disk/Windows/System32/Tasks`가 없으면 증거 폴더 바로 아래 `Windows/System32/Tasks`를 훑는다 [26].
`detect_persistence`는 Run 키 CSV마다 `disk/Windows/System32/config/` 아래 파일이 없으면 증거 폴더 바로 아래 같은 이름의 파일을 읽는다 [26].
서비스 CSV는 `disk/Windows/System32/config/SYSTEM.services.csv`가 없으면 증거 폴더 바로 아래 `services.csv`를 읽는다 [26].
`parse_shimcache`와 `parse_shellbags`는 부속 CSV 이름 후보 4개를 차례로 찾아 처음 있는 파일을 읽는다 [32].
`Tasks`가 두 번째 위치에만 있는 증거 폴더에서 `list_scheduled_tasks`를 부르자 그 위치의 파일이 돌아왔다 [33].
응답에는 실제로 읽은 위치가 `items`의 `path`, `sources_examined`, `sidecar`로 남는다 [26][32].

`parse_prefetch`, `parse_knowledgec`, `parse_browser_history`, `analyze_downloads`는 받은 파일 옆에 부속 파일이 있으면 받은 파일 대신 부속 파일을 읽는다 [28].
이 네 도구는 부속 파일이 없을 때만 받은 파일을 직접 읽으므로 입력이 없어서 다른 입력으로 바꾸는 동작이 아니다 [28].
`get_amcache`는 받은 파일이 있어도 늘 부속 CSV를 읽고 `extract_mft_timeline`은 받은 파일이 CSV가 아니면 부속 CSV를 읽는다 [18][8].

```python
def _safe_resolve(path_str: str) -> Path:
    if not isinstance(path_str, str) or not path_str:
        raise PathTraversalAttempt(f"invalid path: {path_str!r}")
    if "\x00" in path_str:
        raise PathTraversalAttempt("null byte in path")
    if len(path_str) > 1024:
        raise PathTraversalAttempt(f"path too long: {len(path_str)} chars (max 1024)")
    root = EVIDENCE_ROOT.resolve()
    try:
        requested = (EVIDENCE_ROOT / path_str).resolve()
    except OSError as e:
        # File-name-too-long, no-such-process, etc. — treat as path attack
        raise PathTraversalAttempt(f"path resolution failed: {e}") from e
    try:
        requested.relative_to(root)
    except ValueError as e:
        raise PathTraversalAttempt(
            f"path escapes evidence root: {path_str!r} -> {requested}"
        ) from e
    return requested
```
