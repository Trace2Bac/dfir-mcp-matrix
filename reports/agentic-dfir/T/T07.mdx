# T07 도구 부재 처리

### T07.01 실행 전 도구·참조 자료 가용성 검사

**구현.** 이 검사는 외부 도구 래퍼 25개, `parse_registry_hive`, `match_sigma_rules`에 적용된다 [1][2][3].
래퍼는 명령을 만들 때 도구마다 정한 이름으로 `_which`를 불러 실행 파일을 찾고 찾지 못하면 `SiftToolNotFoundError`를 내어 실행하지 않는다 [1][4].
`_which`는 파일이 있는지와 실행 권한이 있는지만 확인하고 시험 실행은 하지 않는다 [1].
Volatility, Zimmerman 도구, `sift_plaso_psort` 래퍼는 입력 경로를 검사하고 입력 파일의 SHA-256을 계산한 뒤 실행 파일을 찾는다 [4].
`sift_plaso_log2timeline`은 실행 파일을 찾기 전에 `DFIR_DERIVED_ROOT` 아래에 저장 파일의 상위 폴더를 만든다 [5].
실행 확인에서 `log2timeline.py`가 없는 환경으로 이 도구를 부르면 `SiftToolNotFoundError`가 났고 저장 파일의 상위 폴더 `case1`은 이미 만들어져 있었다 [6].
실행 파일을 찾은 뒤 실행할 때 운영체제가 그 파일을 찾지 못하면 실행기 `run_tool`이 `FileNotFoundError`를 `SiftToolNotFoundError`로 바꾼다 [7].

`parse_registry_hive`는 python-registry를 도구 안에서 불러오고 불러오지 못하면 하이브를 읽지 않고 `registry_parser_missing`을 돌려준다 [2].
`match_sigma_rules`는 대조하기 전에 규칙 묶음을 읽고 읽은 규칙이 하나도 없으면 대조하지 않고 `no_rules_loaded`를 돌려준다 [3].
실행 확인에서 python-registry를 불러오지 못하게 한 프로세스와 빈 규칙 폴더로 두 도구를 부르면 각각 이 값이 돌아왔다 [6].

상관 도구와 RECmd 배치 도구는 쓰는 모듈이나 참조 자료가 있는지 실행 전에 확인하지 않는다.
`correlate_events`와 `correlate_timeline`은 `dfir_corr`를 도구 안에서 불러오고 `correlate_timeline`은 DuckDB도 불러온다 [8].
불러오지 못한 예외는 도구 안에서 처리하지 않는다 [8].
`sift_recmd_run_batch`는 RECmd에 배치 파일 이름만 넘기고 그 파일이 있는지 보지 않는다 [9].
서버는 작업 폴더를 정하지 않고 RECmd를 실행하므로 RECmd는 이 이름을 서버 프로세스의 작업 폴더를 기준으로 찾는다 [9].
RECmd 기준 날짜 커밋 `bcd0ac3`은 `--bn`에 준 파일이 없으면 오류를 기록하고 처리를 끝낸다 [10].
이 경우 CSV가 만들어지지 않고 서버는 빈 `registry_findings`를 오류 없이 돌려준다 [9].
`batch_name` 값 `USB`가 가리키는 `USB.reb`는 RECmd 같은 커밋의 `BatchExamples` 폴더에 없다 [9][11].
Volatility 3 래퍼는 심볼 표가 있는지 실행 전에 확인하지 않고 심볼 표를 얻지 못한 실행은 다른 실행 실패와 같은 `SiftToolFailedError`로 끝난다 [12].

**한계.** Plaso 래퍼는 `log2timeline.py`와 `psort.py`라는 이름의 실행 파일을 찾는다 [13].
기준으로 삼은 Plaso 20260720 패키지는 실행 파일을 `log2timeline`과 `psort`라는 이름으로 설치한다 [14].
`scripts/install.sh`는 `log2timeline.py`와 `psort.py`가 없으면 `pip`로 Plaso를 설치한다 [15].
그래서 이 방법으로 Plaso를 설치한 환경에서는 Plaso가 있어도 서버가 실행 파일이 없다고 정한다 [13][14][15].

### T07.02 대체 없는 실패 처리·도구 부재 알림

**구현.** 이 알림은 외부 도구 래퍼 25개, `parse_registry_hive`, `match_sigma_rules`에 적용된다 [1][2][3].
`_which`가 내는 `SiftToolNotFoundError`의 문구는 찾지 못한 실행 파일 이름, 경로를 지정할 환경변수 이름, `scripts/install.sh`를 실행하라는 안내를 담는다 [1].
이 예외는 실행 실패와 시간 초과에 쓰는 `SiftToolFailedError`와 다른 종류다 [16].
래퍼는 실행 파일을 찾는 단계의 예외를 처리하지 않으므로 두 진입점이 예외 종류 이름과 문구를 응답에 싣는다 [17][18].
`server.py`는 JSON-RPC 오류 코드 -32000과 `SiftToolNotFoundError: <문구>`를 돌려준다 [17].
`server_stdio.py`는 `{"error": "SiftToolNotFoundError", "detail": <문구 앞 500자>}` 글을 돌려준다 [18].
실행 확인에서 `vol`과 `yara`가 없는 환경으로 두 진입점에서 래퍼를 부르면 이 응답이 왔다 [6].
`parse_registry_hive`는 `registry_parser_missing`과 함께 `pip install python-registry` 안내를 `hint`에 싣는다 [2].
`match_sigma_rules`는 `no_rules_loaded`와 함께 읽으려던 묶음 폴더를 `pack_root`에 싣는다 [3].

서버는 도구가 없을 때 다른 도구로 바꿔 실행하지 않는다.
`_common.py`의 설명은 모델이 서버의 파이썬 구현 도구로 바꿀 수 있다고 적는다 [19].
같은 저장소의 `dfir_agent` live 모드 지시문도 `SiftToolNotFoundError`가 나면 같은 아티팩트를 다루는 다른 도구를 쓰라고 모델에게 적는다 [20].

**한계.** 실행할 때 `run_tool`이 바꾼 `SiftToolNotFoundError`의 문구는 `binary not found: <경로>`이고 설치 안내가 없다 [7].
YARA 래퍼는 `run_tool`의 예외를 모두 처리해 문구만 `metadata.error`에 싣고 예외 종류 이름을 싣지 않는다 [21].
`match_sigma_rules`는 PyYAML을 불러오지 못하면 모든 규칙 파일을 읽지 못한 것으로 다룬다 [22].
그래서 PyYAML이 없을 때도 규칙 묶음이 없을 때와 같은 `no_rules_loaded`를 돌려준다 [22][3].

### T07.03 알림 없는 대체 실행

**구현.** 이 대체는 외부 도구 래퍼 25개의 실행 파일 선택에 적용된다 [1].
도구마다 정한 환경변수(`DFIR_VOLATILITY3_BIN` 등)가 실행할 수 없는 경로를 가리키면 `_which`는 그 값을 쓰지 않고 `PATH`와 저장소 폴더에서 같은 이름을 찾는다 [1].
이 사실은 서버의 표준 오류에 경고 한 줄로만 남고 응답에는 실리지 않는다 [1][23].
실행 확인에서 `DFIR_VOLATILITY3_BIN`에 없는 경로를 주고 `PATH`에 `vol`을 두면 표준 오류에 경고가 남고 `PATH`의 `vol`이 실행되었다 [6].
그 호출의 오류 문구에는 실행된 `vol`의 경로만 있고 사용자가 지정한 경로를 쓰지 못했다는 사실은 없었다 [6].

### T07.04 실행 환경별 경로 분기

**구현.** 이 분기는 외부 도구 래퍼 25개에 적용된다 [1].
`_which`는 환경변수가 가리키는 실행 파일, `shutil.which`로 찾은 `PATH`의 실행 파일, 설치 스크립트가 실행 파일을 두는 저장소 폴더 순서로 찾는다 [1].
저장소 폴더는 `bin/`, `bin/zimmerman/`, 저장소 옆 `agentic-dfir-collector-adapter/bin`이고 있는 폴더만 본다 [24].
이 폴더들에서는 이름 그대로, `.exe`를 붙인 이름, `.dll`을 붙인 이름을 폴더 바로 아래와 한두 단계 아래에서 찾는다 [24].
`scripts/install.sh`는 Zimmerman 도구를 `bin/zimmerman/<도구>/`에 풀고 시스템에서 찾은 YARA 실행 파일을 `bin/yara`로 연결한다 [25].
고른 실행 파일의 경로는 성공한 호출의 응답 `metadata`에 실리지 않는다 [23].

### T07.08 일부 제외 후 계속 실행

**구현.** 이 방식은 `match_sigma_rules`의 규칙 파일에 적용된다 [22].
`_load_rules`는 규칙 폴더의 `*.yml`을 하나씩 읽고 YAML로 읽히지 않거나 `detection`이 없는 파일을 빼고 나머지 규칙으로 대조한다 [22].
응답은 읽은 규칙의 수 `rule_count`만 싣고 뺀 파일의 수나 이름을 싣지 않는다 [26].
실행 확인에서 규칙 파일 11개 가운데 하나를 YAML로 읽히지 않게 바꾼 묶음으로 부르면 `rule_count`가 10이었고 그 규칙에 맞는 사건은 일치 목록에서 빠졌다 [6].

`correlate_timeline`이 부르는 `dfir_corr.correlate_timeline`도 규칙 파일 `correlation-rules.yaml`이 없거나 PyYAML이 없거나 파일을 읽지 못하면 빈 규칙으로 기본 결합만 실행한다 [27].
이때 `load_rules`가 남긴 `_error`는 결과에 실리지 않는다 [27].
`correlate_timeline`의 응답은 `dfir_corr`의 결과에서 `correlations`만 옮기고 규칙 파일로 찾은 것을 포함한 `contradictions`는 옮기지 않는다 [28].
그래서 이 규칙 파일이 있는지는 MCP 응답을 바꾸지 않는다 [28].
실행 확인에서 같은 사건으로 `dfir_corr.correlate_timeline`을 직접 부르면 `contradictions`가 1건이었고 `correlate_timeline`의 응답에는 `contradictions` 키가 없었다 [6].

def _search_repo_bins(binary: str) -> str | None:
    """Look for `binary` (or binary.dll / a single-file build) under the
    installer-staged bin dirs. EZ Tools land at bin/zimmerman/<Tool>/<Tool>
    (net9 self-contained single file) so we glob a couple levels deep."""
    names = [binary, f"{binary}.exe", f"{binary}.dll"]
    for d in _repo_bin_dirs():
        # direct child
        for n in names:
            cand = d / n
            if cand.is_file() and os.access(cand, os.X_OK):
                return str(cand)
        # one/two levels deep (bin/zimmerman/MFTECmd/MFTECmd)
        for n in names:
            for cand in d.glob(f"*/{n}"):
                if cand.is_file() and os.access(cand, os.X_OK):
                    return str(cand)
            for cand in d.glob(f"*/*/{n}"):
                if cand.is_file() and os.access(cand, os.X_OK):
                    return str(cand)
    return None

    """Load the correlation rule pack. Caller may override with a custom
    path for testing.
