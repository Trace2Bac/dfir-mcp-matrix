# R05 결과 출처 표시

### R05.01 증거·파일 ID

**구현.** 이 방식은 증거 파일 경로를 인자로 받는 네이티브 도구 대부분과 외부 도구 래퍼에 적용된다 [1][2].
네이티브 도구는 응답의 `source`에 읽은 파일의 경로 `path`와 SHA-256 `sha256`을 싣는다 [1].
`path`는 증거 루트를 붙여 실제 경로로 바꾼 서버 호스트의 절대 경로다 [1][3].
`_v05` 도구는 `search_root`·`home_root`·`history_file`에 절대 경로를 싣고 `parse_linux_cron_jobs`는 `source`에 증거 루트와 살펴본 경로 목록을 싣는다 [4][5].
외부 도구 래퍼는 `metadata`에 모델이 준 입력 경로 문자열을 싣고 대부분 그 파일의 SHA-256도 싣는다 [2].
`sift_evtxecmd_parse`·`sift_pecmd_parse`처럼 폴더를 받는 래퍼는 폴더를 주면 해시 자리에 `null`을 싣는다 [2].

**한계.** 증거 파일을 읽으면서 그 출처를 싣지 않는 도구가 있다.
`sift_mftecmd_timestomp`와 `sift_pecmd_run_history`는 입력 경로만 싣고 해시를 싣지 않는다 [6].
`analyze_usb_history`의 `source`에는 두 파일의 해시만 있고 경로가 없다 [7].
`analyze_downloads`와 `detect_webshell`의 `source`에는 경로만 있다 [8][9].
`match_sigma_rules`의 응답에는 읽은 사건 파일의 경로도 해시도 없다 [10].
`detect_credential_access`와 `detect_defense_evasion`은 인자로 받은 사건 파일과 MFT CSV의 경로나 해시를 싣지 않는다 [11].
인자로 사건 목록을 받는 상관·탐지 도구는 그 사건이 어느 파일에서 왔는지 알지 못하고 출처 필드를 싣지 않는다 [12].

### R05.02 증거 내부 경로

**구현.** 이 방식은 파일 시스템을 훑는 도구와 경로 열을 읽는 도구에 적용된다 [13][14][15].
`list_scheduled_tasks`와 `detect_webshell`은 찾은 파일의 증거 루트 기준 상대 경로를 항목의 `path`에 싣는다 [13][9].
`analyze_downloads`의 Zone.Identifier 경로는 대상 파일의 증거 루트 기준 상대 경로를 `target_path`에 싣는다 [8].
`_v05` 도구와 `parse_linux_cron_jobs`는 찾은 파일의 서버 호스트 절대 경로를 싣는다 [4][5].
`parse_shimcache`·`parse_shellbags`·`extract_mft_timeline`은 부속 CSV의 경로 열에서 대상 시스템 안의 경로를 `path`에 싣는다 [14][15].
`extract_mft_timeline`은 `ParentPath`와 `FileName`을 이어 경로를 만든다 [15].
`parse_fsevents`와 `parse_auditd_log`도 입력의 `path`·`exe` 값을 싣는다 [16].

**한계.** 응답마다 경로의 기준이 다르다 [13][4][14].
증거 루트 기준 상대 경로, 증거 루트를 붙인 서버 호스트 절대 경로, 대상 시스템 안의 경로가 같은 이름 `path`로 실린다 [13][4][14].

### R05.03 레코드 키·번호

**구현.** 이 방식은 레코드 번호나 키를 싣는 도구 일부에 적용된다 [15][14][17][18].
`extract_mft_timeline`은 MFTECmd CSV의 `Entry`나 `EntryNumber` 열을 `entry`에 싣는다 [15].
`parse_shimcache`는 캐시 항목 위치를 `entry_position`에 싣는다 [14].
`parse_fsevents`는 FSEvents 사건 ID를, `parse_macos_quarantine`은 `LSQuarantineEventIdentifier`를 `event_id`에 싣는다 [17][18].
`parse_registry_hive`는 읽은 키 경로 `key`와 값 이름 `name`을 싣는다 [19].
Windows 사건을 읽는 네이티브 도구는 사건의 레코드 번호를 싣지 않는다 [20].
`parse_auditd_log`는 audit 기록의 일련번호를 시각과 함께 읽지만 응답에는 싣지 않는다 [21].
EvtxECmd 래퍼는 EvtxECmd CSV의 `RecordNumber`·`EventRecordId` 열을 그대로 싣는다 [22].
다른 Zimmerman 도구 CSV에 레코드 번호 열이 있는지는 도구 소스로 확인하지 못했다.

### R05.04 바이트·섹터·행 오프셋

**구현.** 이 방식은 텍스트 증거를 줄 단위로 읽는 도구 다섯 개에 적용된다 [23][24][25][26][5].
`parse_linux_text_log`는 기록과 의심 일치마다 파일의 줄 번호 `line`을 싣는다 [23].
`parse_linux_shell_history`는 명령마다 파일의 줄 번호 `line`과 서버가 매긴 차례 `index`를 싣는다 [24].
`grep_shell_history_for_c2`는 `line_number`를, `detect_dns_tunneling`과 `parse_linux_cron_jobs`는 `lineno`를 싣는다 [25][26][5].
같은 `bash_history`를 읽자 `parse_linux_shell_history`의 `line`은 epoch 줄을 센 파일의 줄 번호였다 [27].
다른 텍스트 로그 도구(`analyze_unix_auth`, `analyze_web_access_log`, `parse_bash_history`, `parse_auditd_log`)는 줄 번호를 싣지 않는다 [28].

**한계.** `parse_linux_text_log`는 접근 기록에서 만든 스캐너 UA 항목을 `line` 0으로 싣는다 [23][27].
`parse_linux_cron_jobs`는 `cron.hourly` 같은 폴더의 스크립트를 첫 명령 줄 번호 하나로 싣는다 [5].

```python
def get_amcache(hive_path, cursor=0, limit=100):
    p = _safe_resolve(hive_path)
    if not p.exists():
        return {"error": "file_not_found", "path": str(p)}
    csv_sidecar = p.with_suffix(".csv")
    if not csv_sidecar.exists():
        # Refuse to synthesize. A forensic tool MUST NOT return invented
        # records — an analyst seeing 'sample-0.exe ... sample-41.exe'
        # could plausibly mistake them for real evidence. Match the
        # pattern used elsewhere (e.g. _v05_supply_chain) and surface
        # the missing sidecar as an explicit error.
        return {
            "error": "amcache_csv_missing",
            "path": str(p),
            "hint": (
                "AmcacheParser sidecar not found alongside the hive. "
                "Run AmcacheParser.exe --csv <out_dir> -f <hive> and "
                "place the resulting CSV next to the hive with the "
                "same stem (e.g. Amcache.csv next to Amcache.hve)."
            ),
        }
    items = _read_csv(csv_sidecar)
    total = len(items)
    s, e = cursor, min(cursor + limit, total)
    return {"source": {"path": str(p), "sha256": _sha256(p)},
            "total": total, "cursor_next": e if e < total else None,
            "items": items[s:e]}
```
