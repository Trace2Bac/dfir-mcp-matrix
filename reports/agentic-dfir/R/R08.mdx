# R08 시간값 처리

### R08.01 시간 변환 전 값 유지

**구현.** 이 방식은 부속 CSV나 JSON 사건의 시각 문자열을 읽는 네이티브 도구 다수와 외부 도구 래퍼에 적용된다 [1][2][3][4].
`get_amcache`, `parse_shimcache`의 `last_modified`, `parse_shellbags`의 `first_interacted`·`last_interacted`는 CSV의 시각 문자열을 바꾸지 않고 싣는다 [1].
`extract_mft_timeline`은 시간 범위를 거를 때만 시각을 읽어 바꾸고 응답의 `created`·`modified`·`accessed`에는 CSV 문자열을 싣는다 [2].
`analyze_event_logs`·`parse_unified_log`의 `timestamp`, `analyze_windows_logons`·`analyze_kerberos_events`·`detect_brute_force_rdp`의 `ts`, `detect_persistence`의 `last_write`도 원래 문자열이다 [3].
`analyze_usb_history`는 setupapi 기록의 시각 문자열을, `parse_linux_text_log`는 정규식이 잡은 시각 문자열을 `ts`에 싣는다 [3][5].
`parse_linux_text_log`의 접근 기록 시각은 `10/Oct/2026:13:55:36 +0900`처럼 오프셋까지 원래 꼴로 실렸다 [5].
외부 도구 래퍼는 도구 CSV의 시각 열을 바꾸지 않고 싣는다 [4].
`detect_python_backdoor_persistence`와 `detect_credential_file_access`는 파일 시스템의 시각을 `os.stat`이 준 epoch 초 실수로 싣는다 [6].

다른 도구는 시각을 바꾼 값만 싣고 원래 값을 함께 싣지 않는다 [7][8][9][10][11].
`parse_auditd_log`·`parse_systemd_journal`·`parse_bash_history`·`parse_linux_shell_history`는 epoch 값을, `analyze_unix_auth`는 syslog 시각을, `analyze_web_access_log`는 접근 기록 시각을 ISO 꼴로 바꾼다 [7][8].
`parse_macos_quarantine`은 CFAbsoluteTime을, SQLite를 직접 읽는 `parse_browser_history`·`parse_knowledgec`·`analyze_downloads`는 브라우저와 KnowledgeC의 시각 정수를 바꾼다 [9][10].
`parse_registry_hive`의 `key_last_write`, `detect_webshell`의 `mtime`, `sift_mftecmd_timestomp`의 `si_created`·`fn_created`·`si_modified`도 바꾼 값이다 [11].
`correlate_timeline`은 받은 시각을 DuckDB `TIMESTAMP`로 넣고 질의 결과를 문자열로 바꿔 싣는다 [12].

### R08.03 시간대·단위·정밀도 표시

**구현.** 이 방식은 `parse_linux_shell_history`, `parse_macos_quarantine`, Volatility 래퍼에 적용된다 [8][9][13].
`parse_linux_shell_history`는 epoch 값을 UTC로 바꾸어 끝에 `Z`를 붙인다 [8].
`parse_macos_quarantine`은 CFAbsoluteTime을 UTC인 2001-01-01에 더해 `+00:00`이 붙은 ISO 꼴로 싣는다 [9].
이 도구는 CFAbsoluteTime이 0이거나 비어 있으면 2001-01-01로 바꾸지 않고 `timestamp`를 `null`로 싣는다 [9].
Volatility 래퍼는 플러그인을 CSV 렌더러로 실행한다 [13].
Volatility 3 2.28.0은 FILETIME과 Unix 시각을 UTC 시간대가 붙은 `datetime`으로 바꾸고 CSV 렌더러는 `datetime`을 `%Y-%m-%d %H:%M:%S.%f %Z` 꼴로 쓰므로 시각 끝에 `UTC`가 붙는다 [14][15].
같은 epoch 줄을 읽은 `parse_linux_shell_history`의 값은 시스템 시간대와 관계없이 `2026-03-15T13:20:00Z`였고 `parse_macos_quarantine`의 값은 `2026-03-15T00:00:00+00:00`이었다 [16].

**한계.** 서버가 바꾼 다른 시각에는 시간대 표시가 없다.
`parse_systemd_journal`·`parse_bash_history`·`detect_webshell`은 `datetime.fromtimestamp`를 시간대 없이 불러 서버 프로세스의 지역 시각으로 바꾼다 [7][17].
같은 epoch 값이 시스템 시간대 Asia/Seoul에서는 `2026-03-15T22:20:00`, `TZ=UTC`에서는 `2026-03-15T13:20:00`으로 실렸다 [16].
같은 파일을 읽은 `parse_linux_shell_history`의 값은 두 경우 모두 `2026-03-15T13:20:00Z`였다 [16].
`parse_auditd_log`는 UTC로 바꾼 뒤 시간대를 떼어 `2025-11-24T16:00:00.123000` 꼴로 싣는다 [7][16].
SQLite를 직접 읽는 세 도구의 `datetime(…, 'unixepoch')`는 UTC 시각을 `2026-03-15 00:04:00` 꼴로 시간대 없이 돌려준다 [10][16].
`parse_registry_hive`의 `key_last_write`는 python-registry 1.3.1이 시간대 없이 돌려준 UTC 값을 `isoformat()`으로 싣는다 [11][18].

원래 값의 시간대를 버리거나 가정하는 곳이 있다.
`analyze_web_access_log`는 `10/Oct/2026:13:55:36 +0900`에서 오프셋을 떼고 `2026-10-10T13:55:36`으로 싣는다 [19][16].
`analyze_unix_auth`는 연도가 없는 syslog 시각에 인자 `assumed_year`, 시간 범위 시작의 연도, 파일 mtime의 UTC 연도, 현재 연도 가운데 앞에서부터 있는 값을 넣는다 [20].
응답에는 어느 연도를 넣었는지와 시간대를 가정했다는 표시가 없다 [20].
`sift_mftecmd_timestomp`는 MFTECmd 시각의 소수 초와 `+` 뒤 오프셋을 버리고 `isoformat()`으로 싣는다 [21].
Volatility 3 2.28.0은 FILETIME을 초 단위로 버림한 뒤 바꾸므로 Volatility 래퍼의 시각은 소수 초 자리 6개가 늘 0이다 [14].
SQLite를 직접 읽는 세 도구는 시각을 초 단위 문자열로 바꾸므로 원래 값의 1초 미만 자리가 응답에 남지 않는다 [22].

시간 범위와 파생 값에 쓰는 `_parse_ts`는 끝의 `Z`를 떼고 정해 둔 꼴만 읽으며 오프셋이 붙은 시각은 읽지 못해 `None`으로 돌려준다 [23].
시간 범위를 거르는 도구는 `None`이 된 항목을 거르지 않고 싣는다 [24].
`analyze_windows_logons`에 `time_window_end` `2026-03-15T12:00:00`을 주자 시간대 없는 23:30 로그온은 빠지고 `+09:00`이 붙은 23:30 로그온은 실렸다 [16].
이 도구는 시간대 없는 시각의 시(hour)로 `is_after_hours`를 정하고 읽지 못한 시각은 거짓으로 둔다 [24].

`correlate_timeline`은 오프셋이 붙은 시각을 서버 프로세스의 지역 시각으로 바꾼 값으로 다루고 응답 시각에 시간대를 붙이지 않는다 [12][16].
`2026-03-15T10:00:00+09:00`과 `2026-03-15T01:00:30Z`를 넣자 Asia/Seoul에서는 상관이 없었고 `TZ=UTC`에서는 `ts1`이 `2026-03-15 01:00:00`인 상관 1건이 나왔다 [16].
DuckDB 1.5.5 소스에서 이 변환 위치는 확인하지 못했다.

시각 필드 이름에 시간대나 단위를 밝히지 않는 곳도 있다.
`parse_shimcache`는 CSV의 `LastModifiedTimeUTC` 열을 `last_modified`로, `detect_persistence`는 `LastWriteTimeUTC` 열을 `last_write`로 이름을 바꿔 싣는다 [1][3].
`detect_python_backdoor_persistence`·`detect_credential_file_access`의 `atime`·`mtime`·`ctime`은 epoch 초라는 단위를 밝히지 않는다 [6].

def _parse_ts_safe(s: str) -> datetime | None:
    """Best-effort timestamp parse from MFTECmd CSV format."""
    if not s or not s.strip():
        return None
    s = s.split(".")[0].split("+")[0].strip()
    for fmt in ("%Y-%m-%d %H:%M:%S", "%Y-%m-%dT%H:%M:%S"):
        try:
            return datetime.strptime(s, fmt)
        except ValueError:
            continue
    return None

_TS_FORMATS = (
    "%Y-%m-%dT%H:%M:%S.%f", "%Y-%m-%dT%H:%M:%S",
    "%Y-%m-%d %H:%M:%S.%f", "%Y-%m-%d %H:%M:%S",
    "%Y/%m/%d %H:%M:%S.%f", "%Y/%m/%d %H:%M:%S",
    "%m/%d/%Y %I:%M:%S %p",
)


def _parse_ts(s):
    if not s:
        return None
    s = s.strip().rstrip("Z")
    for fmt in _TS_FORMATS:
        try:
            return datetime.strptime(s, fmt)
        except ValueError:
            continue
    return None
