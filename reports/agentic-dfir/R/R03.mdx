# R03 분석 상태 알림

### R03.01 구조화 status·error

**구현.** 이 방식은 서버의 도구 73개 모두에 적용되지만 실패를 싣는 모양은 경로마다 다르다 [1][2][3].
네이티브 도구 대부분은 입력 파일이 없거나 읽지 못하면 예외를 내지 않고 `error` 필드에 오류 종류 코드를 담은 `dict`를 돌려준다 [1].
코드는 `file_not_found`, `amcache_csv_missing`·`shimcache_csv_missing`·`mft_csv_missing` 같은 부속 자료 없음, `sqlite_read_failed`, `read_failed`, `not_a_directory`, `hive_open_failed` 같은 값이다 [1].
많은 경우 `path`, `hint`, 앞부분만 남긴 예외 문구 `detail`을 함께 싣는다 [1].
`parse_macos_quarantine`·`detect_dns_tunneling`은 정상 응답과 같은 필드에 빈 목록과 0을 넣고 `error`에 문장을 싣는다 [4].

경로 검사와 외부 도구 래퍼는 예외를 낸다 [5][6][7].
`_safe_resolve`는 증거 루트를 벗어나는 경로에, 래퍼의 `safe_evidence_input`은 없는 경로에 `PathTraversalAttempt`를 낸다 [5][6].
래퍼는 실행 파일을 찾지 못하면 `SiftToolNotFoundError`를, 종료 코드가 0이 아니거나 시간 제한을 넘으면 `SiftToolFailedError`를 낸다 [6][7].
시간 제한을 넘은 실행과 0이 아닌 종료 코드는 같은 예외 종류이고 문구로만 구별된다 [7].
등록부는 없는 도구에 `KeyError`를, schema에 없는 인자나 맞지 않는 자료형에 `TypeError`를, 허용 값과 상한을 벗어난 값에 `ValueError`를 낸다 [8].

두 진입점은 이 예외를 다르게 싣는다 [2][3].
`server_stdio`는 도구 예외를 `{"error": <예외 종류 이름>, "detail": <문구 앞 500자>}` JSON 글로 만들어 정상 결과로 돌려준다 [2].
없는 도구는 `{"error": "ToolNotFound", …}`로 싣는다 [2].
MCP Python SDK 1.29.1은 입력 schema 검사에 실패한 호출만 `isError`가 참인 결과로 바꾼다 [9].
`server`는 없는 도구를 JSON-RPC 오류 -32601로, 다른 예외를 오류 -32000과 `<예외 종류>: <문구>`로 보낸다 [3].
같은 호출 12개를 두 진입점으로 부르자 `server_stdio`에서는 schema 상한을 넘긴 호출 하나만 `isError`가 참이었고 `server`에서는 9개 호출이 JSON-RPC 오류였다 [10].

외부 도구 래퍼의 정상 응답에는 상태 필드가 없다 [11].
YARA 래퍼는 YARA 실행 중의 예외를 처리해 `matches`를 빈 목록으로 두고 `metadata.error`에 예외 문구를 싣는다 [12].
서버는 실행 중인 호출의 진행을 알리지 않는다 [2][3].

**한계.** `server_stdio`에서는 도구가 예외로 끝나도 `isError`가 거짓이다 [2][10].
`detect_credential_access`는 Sysmon 사건 파일의 경로 검사나 읽기에서 예외가 나면 입력 경로 없이 `technique`과 `error`만 있는 항목을 `findings`에 넣고 이 항목을 `finding_count`와 `by_technique`에 센다 [13][14].
`error` 필드의 값은 네이티브 도구에서는 오류 코드, `_v06` 도구에서는 문장, 예외를 바꾼 응답에서는 예외 종류 이름이다 [1][4][2].

실패를 알리지 않는 경로가 있다.
`detect_credential_access`는 `sysmon_events_json`의 파일이 없으면 그 입력을 알리지 않고 건너뛴다 [13].
`detect_defense_evasion`은 `events_json`·`mft_csv`의 파일이 없으면 건너뛰고 MFT CSV를 읽다 예외가 나면 그때까지의 결과만 쓴다 [15].
JSON 사건을 읽는 도구는 JSON으로 읽지 못한 줄을 알리지 않고 건너뛴다 [16].
EvtxECmd·PECmd 래퍼, `sift_recmd_run_batch`, `sift_amcacheparser_parse`는 도구가 CSV를 만들지 않으면 빈 목록을 오류 표시 없이 싣는다 [17][18][19].
`sift_mftecmd_timestomp`는 `sift_mftecmd_parse`가 CSV 없음을 알리는 `metadata.error`를 옮기지 않고 빈 `findings`를 싣는다 [20].
`_run_evtxecmd`와 `_run_pecmd`가 남긴 표준 오류 끝부분은 래퍼의 응답에 옮겨지지 않는다 [17].
`sift_plaso_psort`는 `output_format`이 `l2tcsv`가 아니면 psort 출력을 읽지 않고 빈 `events`를 싣는다 [21].

`server`는 결과에 JSON으로 바꾸지 못하는 값이 있으면 도구가 끝난 호출도 오류로 보낸다 [3].
`correlate_timeline`에 사용자 규칙을 주자 `server`는 `TypeError: Object of type datetime is not JSON serializable` 오류를 보냈다 [10].

인자의 기본값이나 형식 때문에 늘 예외로 끝나는 호출이 있다.
`parse_linux_cron_jobs`의 `evidence_root` 기본값 `/`는 경로 검사에서 증거 루트 밖으로 해석되어 인자 없이 부르면 `PathTraversalAttempt`로 끝난다 [22][10].
`parse_macos_quarantine`은 UTC가 붙은 시각과 시간대 없는 시간 범위를 비교하므로 시간 범위를 주면 시각이 있는 행에서 `TypeError`로 끝난다 [23][24].
`correlate_events`에 시간대가 붙은 시각과 없는 시각을 섞어 주면 `TypeError`로 끝난다 [25][24].

### R03.02 찾지 못함과 실패 구분

**구현.** 이 방식은 네이티브 도구의 빈 결과, `parse_registry_hive`의 키·값 조회, YARA 래퍼에 적용된다 [1][26][12].
네이티브 도구는 입력을 읽고 일치가 없으면 `error` 없이 빈 목록과 0인 건수를 싣고 입력이 없으면 `error`를 싣는다 [1].
`parse_registry_hive`는 하이브를 연 뒤 키가 없으면 `key_not_found`, 값이 없으면 `value_not_found`를 싣는다 [26].
이 코드는 파일이 없는 `file_not_found`, 하이브를 열지 못한 `hive_open_failed`, 키를 열다 다른 예외가 난 `key_open_failed`와 다르다 [26].
`key_not_found` 응답에는 하이브의 루트 키 이름 `root_key_in_hive`와 키 경로를 쓰는 법을 적은 `hint`가 실린다 [26][24].
YARA 래퍼는 일치가 없으면 `metadata.error` 없이 빈 `matches`를, YARA가 실패하면 빈 `matches`와 `metadata.error`를 싣는다 [12].
`/bin/false`를 YARA 실행 파일로 지정하자 `matches`가 빈 목록이고 `metadata.error`가 `/bin/false exited with code 1: (no stderr)`인 응답이 왔다 [10].

**한계.** 입력이 없는 것을 빈 결과와 같은 모양으로 싣는 도구가 있다.
`list_scheduled_tasks`는 Tasks 폴더가 없으면 `items`를 빈 목록으로 두고 `note`에 문장을 싣는다 [27][24].
`parse_macos_quarantine`·`detect_dns_tunneling`은 입력 파일이 없으면 `total` 0과 빈 목록을 싣고 `error` 문장으로만 구별한다 [4][24].
YARA 래퍼의 두 경우도 `metadata.error`가 있는지로만 구별된다 [12].
앞의 한계에 적은 대로 CSV를 만들지 못한 EvtxECmd·PECmd·RECmd·AmcacheParser 래퍼와 `sift_mftecmd_timestomp`, `l2tcsv`가 아닌 psort, 입력 파일이 없는 `detect_credential_access`·`detect_defense_evasion`은 일치 0건과 같은 응답을 싣는다 [17][18][21][13][15].

### R03.03 입력별 성공·실패·생략 목록

**구현.** 이 방식은 `correlate_timeline`의 사용자 규칙과 `parse_linux_cron_jobs`의 파일 읽기 실패에 적용된다 [28][29].
`correlate_timeline`은 `rules`의 문자열마다 `user_rule_matches`에 항목 하나를 싣는다 [28].
허용 문자 검사에 실패하면 `rule rejected: disallowed character`, 금지 낱말이 있으면 `rule rejected: forbidden SQL keyword`, DuckDB 질의가 실패하면 예외 문구 앞 200자를 그 규칙 문자열과 함께 `error`에 싣는다 [28].
성공한 규칙은 `hits`와 `sample`을 싣는다 [28].
`parse_linux_cron_jobs`는 읽지 못한 cron 파일마다 `path`·`kind`·`error`를 담은 항목을 `jobs`에 넣는다 [29].

`grep_shell_history_for_c2`는 정규식으로 컴파일하지 못한 `extra_patterns`를 건너뛰고 `patterns_checked`에 쓴 정규식 수만 싣는다 [30].

**한계.** `correlate_timeline`은 문자열이 아닌 `rules` 항목을 항목 없이 건너뛴다 [28].
사건의 시각을 하나도 읽지 못하면 규칙을 실행하지 않아 `user_rule_matches`가 빈 목록이 된다 [28].
`parse_linux_cron_jobs`의 실패 항목은 작업 항목과 같은 `jobs` 목록에 섞이고 `total`에도 세어진다 [29][31].
`flagged_only`를 주면 실패 항목에는 `flags`가 없어 응답에서 빠진다 [31].
없는 cron 위치는 항목 없이 `scanned_paths`에만 실린다 [31].

```python
def _safe_resolve(path_str: str) -> Path:
    if not isinstance(path_str, str) or not path_str:
        raise PathTraversalAttempt(f"invalid path: {path_str!r}")
    if "\x00" in path_str:
        raise PathTraversalAttempt("null byte in path")
    if len(path_str) > 1024:
        raise PathTraversalAttempt(f"path too long: {len(path_str)} chars (max 1024)")
    root = EVIDENCE_ROOT.resolve()
    try:
        requested = (EVIDENCE_ROOT / path_str).resolve()
    except OSError as e:
        # File-name-too-long, no-such-process, etc. — treat as path attack
        raise PathTraversalAttempt(f"path resolution failed: {e}") from e
    try:
        requested.relative_to(root)
    except ValueError as e:
        raise PathTraversalAttempt(
            f"path escapes evidence root: {path_str!r} -> {requested}"
        ) from e
    return requested
```

```python
def safe_evidence_input(path_str: str) -> Path:
    """
    Resolve an evidence path under EVIDENCE_ROOT, with read-access verification.

    All SIFT adapters MUST pass user-supplied paths through this function
    before invoking subprocess. This is the boundary that makes path
    traversal structurally impossible.
    """
    p = _safe_resolve(path_str)
    if not p.exists():
        raise PathTraversalAttempt(f"evidence path does not exist: {path_str!r}")
    return p
```
