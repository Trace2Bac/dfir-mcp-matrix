# R01 결과 가공

### R01.01 가공 없이 전달

**구현.** 이 방식은 `sift_recmd_query_key`, PECmd JSON 부속 자료가 있을 때의 `parse_prefetch`, `match_sigma_rules`의 일치 항목 `event`에 적용된다 [1][2][3].
`sift_recmd_query_key`는 RECmd를 `--kn`으로 실행하고 그 표준 출력 전체를 문자열 하나로 `raw_output`에 싣는다 [1].
외부 도구 래퍼 25개 가운데 도구의 표준 출력을 파싱하지 않고 싣는 래퍼는 이 도구 하나다 [1].
`parse_prefetch`는 `.pf` 파일과 이름이 같은 `.json` 부속 자료가 있으면 그 JSON을 읽어 `source` 키만 더하고 돌려준다 [2].
`match_sigma_rules`는 규칙에 맞은 사건을 입력 파일에서 읽은 `dict` 그대로 `event`에 싣는다 [3].
시험 사건 파일로 부르자 `event`에는 입력 줄의 키와 값이 그대로 실렸다 [4].

**한계.** `parse_prefetch`는 부속 JSON에 `source` 키가 있으면 그 값을 서버가 만든 경로와 해시로 바꾼다 [2].

### R01.02 구조화 파싱·필드 선택

**구현.** 이 방식은 증거 파일, 부속 자료, 외부 도구 출력을 읽어 결과를 만드는 도구 전체에 적용된다 [5][6].
CSV를 읽는 도구는 `csv.DictReader`로 행마다 열 이름을 키로 한 `dict`를 만든다 [5][6].
`get_amcache`는 Amcache CSV 부속 자료의 행을 열을 고르지 않고 싣는다 [7][4].
Volatility 3, MFTECmd, EvtxECmd, AmcacheParser 래퍼와 `sift_pecmd_parse`·`sift_recmd_run_batch`·`sift_plaso_psort`도 도구가 쓴 CSV의 열을 모두 싣는다 [6][8].
Volatility 래퍼는 플러그인을 `-r csv`로 실행하고 출력을 CSV로 읽지 못하면 줄마다 `{"line": …}`로 싣는다 [6].

정해 둔 필드만 고르는 도구가 있다.
`parse_shimcache`는 열 이름 후보 여러 개에서 값을 찾아 `entry_position`·`path`·`last_modified`·`executed` 네 필드를 만든다 [9].
`extract_mft_timeline`은 `entry`·`path`·`created`·`modified`·`accessed`를 고르고 `path`는 `ParentPath`와 `FileName`을 이어 만든다 [10].
`get_process_tree`는 `pid`·`ppid`·`image`·`cmdline`·`start_ts`·`user`를 고르고 부모와 자식 관계로 트리를 만든다 [11].
`sift_pecmd_run_history`는 PECmd 행에서 실행 파일 이름, 실행 횟수, 실행 시각 8개, 크기, 해시만 고른다 [12].
`analyze_unix_auth`·`analyze_web_access_log`·`parse_linux_text_log`·`parse_auditd_log`는 줄마다 정해 둔 정규식으로 필드를 나눈다 [13].
`parse_browser_history`·`parse_knowledgec`·`parse_macos_quarantine`은 SQLite 질의로 고른 열만 읽는다 [14].

`correlate_timeline`은 `dfir_corr.correlate_timeline`의 결과를 이전 버전의 응답 모양으로 바꾼다 [15].
상관 항목의 키를 `s1`·`ts1`·`a1`·`t1`·`ty1`·`s2`·…·`delta_s`로 바꾸고 USB 삽입 뒤 로그온인 항목을 `kvm_precedes_logon`에 따로 모은다 [15].

**한계.** `correlate_timeline`은 `dfir_corr`가 만든 `contradictions`와 `correlations_truncated_at`을 응답에 싣지 않는다 [15][16].
`dfir_corr`의 모듈 설명은 모순을 `status`가 `UNRESOLVED`인 항목으로 돌려준다고 적는다 [16].
같은 사건 300개로 `dfir_corr`를 직접 부르자 `contradictions`가 300개 나왔고 MCP 응답에는 그 키가 없었다 [4].

`get_process_tree`는 PID나 부모 PID를 정수로 읽지 못한 행을 알리지 않고 건너뛴다 [11].
PID 열이 없거나 비어 있는 행은 PID 0으로 읽는다 [11].
같은 PID가 다시 나오면 뒤 행이 앞 행을 대신하므로 PID가 재사용된 프로세스는 하나만 남는다 [11].

`parse_linux_text_log`의 접근 기록 정규식은 요청 줄을 공백으로 나누므로 URL에 공백이 있으면 그 뒤가 `proto`에 들어간다 [13].
`GET /index.php?id=1 union select 1 HTTP/1.1` 줄은 `uri`가 `/index.php?id=1`, `proto`가 `union select 1 HTTP/1.1`로 실렸다 [4].
`analyze_web_access_log`는 `log_format` 인자를 받지만 쓰지 않고 줄 모양으로 형식을 고른다 [17].
combined 형식에 맞지 않는 줄은 IIS 기본 열 차례를 가정하고 정해 둔 위치의 칸을 IP, 메서드, 경로, 상태로 읽는다 [17].

### R01.03 형식 변환·건수 집계

**구현.** 이 방식은 건수를 세는 도구와 값을 다른 형식으로 바꾸는 도구에 적용된다.
`analyze_event_logs`·`parse_unified_log`는 경고를 등급별로 센 `alerts_by_severity`를 싣는다 [18].
`parse_auditd_log`는 시스템 호출별, 기록 종류별 건수의 상위 10개를 `by_syscall`·`by_type`에 싣는다 [19].
`parse_fsevents`는 플래그별 건수 `flag_statistics`를, `parse_knowledgec`는 앱별 건수의 상위 10개 `top_apps_by_event_count`를 싣는다 [20][21].
`parse_linux_text_log`는 형식별, 등급별, 기법별 건수를 싣는다 [22].
`analyze_windows_logons`는 로그온 유형별 건수와 원격 출발지 IP별 사용자 목록을 싣는다 [23].
탐지 도구 다수는 신호나 발견사항의 수를 `stats`·`by_technique`에 싣는다 [24].

값의 형식을 바꾸는 곳도 있다.
`parse_registry_hive`는 이진 값을 base64 문자열 `data_base64`와 길이 `data_size`로, 목록 값은 문자열 목록으로, 그 밖의 값은 문자열로 바꾼다 [25].
`parse_auditd_log`는 시스템 호출 번호를 표 `_SYSCALL_NAMES`에서 찾아 이름으로 바꾸고 표에 없는 번호는 숫자 그대로 둔다 [19].
`analyze_windows_logons`는 로그온 유형 숫자를 표 `LOGON_TYPE_MEANING`에서 찾아 `logon_type_name`과 `logon_type_meaning`을 더한다 [23].
`analyze_downloads`는 `Zone.Identifier`의 `ZoneId`를 영역 이름 `zone_meaning`으로 바꾸어 더한다 [26].

두 진입점은 결과 `dict`를 JSON 글로 바꾸는 방식이 다르다 [27][28].
`server_stdio`는 `json.dumps`에 `default=str`과 `indent=2`를 주어 JSON으로 바꾸지 못하는 값을 문자열로 싣는다 [27].
`server`는 `json.dumps`를 인자 없이 불러 들여쓰기 없는 JSON을 만든다 [28].

**한계.** 몇몇 건수는 전체가 아니라 상한으로 자른 뒤의 항목만 센다.
`parse_fsevents`는 `limit`에 닿으면 읽기를 멈추므로 `flag_statistics`는 실린 사건의 플래그만 센다 [20].
`parse_knowledgec`의 두 경로와 `parse_auditd_log`도 `limit`까지 모은 항목으로 앱별, 시스템 호출별 건수를 센다 [21][19].
`analyze_event_logs`는 경고가 `limit_alerts`에 닿으면 사건 읽기를 멈추고 그때까지의 경고로 `alerts_by_severity`를 센다 [18].
7045 사건 10개에 `limit_alerts` 3을 주자 `alerts_by_severity`의 `medium`은 3이었다 [4].
`parse_unified_log`도 경고가 `limit`에 닿으면 멈추고 그때까지의 경고로 `alerts_by_severity`를 센다 [29].
`parse_shellbags`의 `network_share_access_count`는 `limit`까지 실은 항목만 센다 [30].

`parse_auditd_log`의 `_SYSCALL_NAMES`는 기록의 `arch` 값을 보지 않고 같은 번호 대응을 쓴다 [19].
`detect_ransomware_behavior`의 `stats.ransom_notes_created`는 랜섬 노트 파일 수가 아니라 `ransom_note_written` 발견사항의 수라서 0이나 1이다 [31].
`detect_defense_evasion`의 `stats.mft_mismatches`도 불일치 항목 수가 아니라 `mft_si_fn_mismatch` 발견사항의 수다 [32].

`server`는 JSON으로 바꾸지 못하는 값이 결과에 있으면 결과 전체를 오류로 돌려준다 [28].
`correlate_timeline`의 사용자 규칙 결과 `sample`에는 DuckDB가 돌려준 `datetime`이 들어간다 [33].
같은 규칙으로 부르자 `server_stdio`는 시각을 문자열로 실은 결과를, `server`는 `TypeError: Object of type datetime is not JSON serializable` 오류를 돌려줬다 [4].

### R01.04 가공 사실·대상 표시

**구현.** 이 방식은 외부 도구 래퍼의 `metadata`와 부속 자료나 SQLite를 읽는 네이티브 도구 일부에 적용된다 [6][8][9].
외부 도구 래퍼는 `metadata.tool`에 실행한 도구 이름을 싣는다 [6][8].
Volatility 래퍼는 실행한 플러그인 이름을 `metadata.plugin`에 싣는다 [6].
`sift_mftecmd_parse`·`sift_evtxecmd_parse`·`sift_pecmd_parse`는 도구가 쓴 CSV의 SHA-256을 `csv_sha256`에, AmcacheParser 래퍼는 CSV 파일 이름마다의 SHA-256을 `csv_outputs_sha256`에 싣는다 [8].
`sift_evtxecmd_filter_eids`·`sift_pecmd_run_history`·`sift_mftecmd_timestomp`는 도구가 쓴 CSV의 해시를 싣지 않는다 [34].
`sift_recmd_run_batch`는 인자로 받은 `batch_name`과 실제로 쓴 batch 파일 `batch_file`을 함께 싣는다 [35].
`sift_evtxecmd_filter_eids`는 거른 사건 ID 목록 `filter_eids`를, `sift_plaso_psort`는 `output_format`과 `filter_expression`을 싣는다 [8].

네이티브 도구 가운데 `parse_shimcache`·`parse_shellbags`와 부속 CSV를 읽은 `parse_knowledgec`·`parse_browser_history`는 읽은 부속 자료의 증거 루트 기준 경로를 `sidecar`에 싣는다 [9][36][21][14].
SQLite 파일을 직접 읽은 `parse_knowledgec`·`parse_browser_history`는 `engine`에 `sqlite3_readonly`를 적는다 [21][14].
`analyze_downloads`는 항목마다 읽은 원천을 `source`(`browser_db_sidecar`·`browser_db_native`·`zone_identifier_ads`)에 적는다 [26].
`parse_bash_history`는 고른 형식을 `format_detected`에, `match_sigma_rules`는 규칙 묶음 버전 `pack_version`과 규칙 수를 싣는다 [37][3].

**한계.** `get_amcache`, 부속 JSON을 읽은 `parse_prefetch`, `extract_mft_timeline`은 받은 파일 옆의 부속 자료를 읽어 결과를 만들지만 그 부속 자료의 경로를 싣지 않는다 [7][2][10].
세 도구의 `source`는 받은 파일의 경로와 SHA-256이다 [7][2][10].
`get_amcache`의 `source`는 `Amcache.hve`의 경로와 해시였고 항목은 `Amcache.csv`의 행이었다 [4].

### R01.06 응답 항목 선별

**구현.** 이 방식은 `sift_evtxecmd_filter_eids`에 적용된다 [38].
`event_ids`를 주지 않거나 빈 목록으로 주면 서버가 정해 둔 사건 ID 20개 `_DEFAULT_HEAVY_HITTERS`에 맞는 행만 싣는다 [38].
목록은 Security 로그온·프로세스·서비스·예약 작업·계정·Kerberos·공유 사건 ID 15개와 Sysmon 1·3·11·13, PowerShell 4104다 [38].
맞지 않는 행은 CSV를 읽는 동안 버린다 [38][39].
도구 설명은 기본 목록을 침입의 약 80%를 잡는 사건 ID라고 적는다 [38].

**한계.** 서버는 행의 `EventId` 값만 대조하고 채널이나 제공자는 보지 않는다 [38].
그래서 설명이 Sysmon 사건으로 적은 1·3·11·13은 다른 채널의 같은 번호 사건도 남긴다 [38].

def parse_prefetch(prefetch_path):
    p = _safe_resolve(prefetch_path)
    if not p.exists():
        return {"error": "file_not_found", "path": str(p)}
    sidecar = p.with_suffix(".json")
    if sidecar.exists():
        data = json.loads(sidecar.read_text(encoding="utf-8"))
        data["source"] = {"path": str(p), "sha256": _sha256(p)}
        return data
    m = re.match(r"^(.+)-([0-9A-F]{8})\.pf$", p.name, re.IGNORECASE)
    if not m:
        return {"error": "bad_prefetch_name", "name": p.name}
    return {"source": {"path": str(p), "sha256": _sha256(p)},
            "executable": m.group(1), "path_hash": m.group(2),
            "size_bytes": p.stat().st_size,
            "note": "native reader — run PECmd for run counts and loaded modules"}

def get_amcache(hive_path, cursor=0, limit=100):
    p = _safe_resolve(hive_path)

    csv_sidecar = p.with_suffix(".csv")

        # records — an analyst seeing 'sample-0.exe ... sample-41.exe'
        # could plausibly mistake them for real evidence. Match the
        # pattern used elsewhere (e.g. _v05_supply_chain) and surface

                "Run AmcacheParser.exe --csv <out_dir> -f <hive> and "
                "place the resulting CSV next to the hive with the "
                "same stem (e.g. Amcache.csv next to Amcache.hve)."
            ),
        }
    items = _read_csv(csv_sidecar)
    total = len(items)
    s, e = cursor, min(cursor + limit, total)

def extract_mft_timeline(mft_path, start, end, cursor=0, limit=500):
    p = _safe_resolve(mft_path)
    if not p.exists():
        return {"error": "file_not_found", "path": str(p)}
    csv_path = p if p.suffix.lower() == ".csv" else p.with_suffix(".csv")
    if not csv_path.exists():

                "hint": f"run MFTECmd.exe -f {p} --csv <dir>",

    sdt, edt = _parse_ts(start), _parse_ts(end)
    if sdt is None or edt is None:
        return {"error": "bad_time_format"}
    matched = []

        if created is None or created < sdt or created > edt:

            "path": (row.get("ParentPath", "") + "\\" + row.get("FileName", "")).strip("\\"),
            "created": row.get("Created0x10") or row.get("Created"),
            "modified": row.get("LastModified0x10"),
            "accessed": row.get("LastAccess0x10"),
        })
    total = len(matched)
    s, e = cursor, min(cursor + limit, total)
    return {"source": {"path": str(p), "sha256": _sha256(p)},

    def _serialize_value(v):
        """Convert python-registry value to a JSON-friendly dict.
        Binary data is base64-encoded with explicit type marker; numeric
        types pass through; strings are kept as-is.
        """
        try:
            vtype = v.value_type_str()
        except Exception:
            vtype = "REG_UNKNOWN"
        try:
            raw = v.value()
        except Exception as e:
            return {"name": v.name(), "type": vtype, "error": str(e)[:100]}

            import base64
            return {"name": v.name(), "type": vtype,

                    "data_size": len(raw)}

            return {"name": v.name(), "type": vtype, "data": raw}
        if isinstance(raw, list):

def sift_evtxecmd_filter_eids(
    evtx_path: str,
    event_ids: list[str] | None = None,
    limit: int = 10000,
) -> dict[str, Any]:
    keep_eids = set(event_ids) if event_ids else set(_DEFAULT_HEAVY_HITTERS)

    # OOM-safe: push the EID predicate down into the streaming reader so
    # non-matching rows are discarded the instant they're read, never
    # accumulated. Only up to `limit` matching rows are materialized.
    def _keep(row: dict) -> bool:
        # EvtxECmd CSV column is "EventId" (no underscore, capital I)
        eid = str(row.get("EventId") or row.get("EventID") or "").strip()
        return eid in keep_eids

    parsed = _run_evtxecmd(evtx_path, max_rows=limit, row_filter=_keep)
