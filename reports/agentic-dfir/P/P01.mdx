# P01 분석 방법 적합성 확인

### P01.01 이름·확장자 판별

**구현.** 이 방식은 증거 옆의 부속 CSV·JSON을 이름으로 찾는 도구 8개, 증거 폴더의 정해 둔 경로에서 자료를 고르는 도구 3개, `parse_prefetch`와 `extract_mft_timeline`의 입력 확인에 적용된다 [1][2][3][4][5][6][7][8].
`get_amcache`는 받은 하이브와 이름이 같고 확장자만 `.csv`인 파일을 AmcacheParser가 낸 CSV로 보고 읽는다 [1].
`parse_shimcache`는 `<하이브 이름>.shimcache.csv`·`<하이브 이름>.appcompatcache.csv`와 확장자를 바꾼 같은 꼴의 이름 두 개를 차례로 찾는다 [2].
`parse_shellbags`는 같은 꼴로 `.shellbags.csv`·`.sbe.csv`가 붙은 이름 네 개를 찾는다 [2].
`parse_prefetch`는 확장자를 `.json`으로 바꾼 파일을 PECmd가 낸 JSON으로 보고 읽는다 [3].
`parse_knowledgec`는 확장자를 `.csv`로 바꾼 파일을, `parse_browser_history`는 DB 이름 뒤에 `.csv`를, `analyze_downloads`는 `.downloads.csv`를 붙인 파일을 찾는다 [4].
`extract_mft_timeline`은 받은 파일의 확장자가 `.csv`이면 그 파일을, 아니면 확장자를 `.csv`로 바꾼 파일을 MFTECmd CSV로 읽는다 [5].

`parse_prefetch`는 부속 JSON이 없으면 파일 이름이 `<실행 파일 이름>-<16진수 8자리>.pf` 꼴인지 보고 아니면 `bad_prefetch_name` 오류를 돌려준다 [3].
이름이 맞으면 이름에서 실행 파일 이름과 경로 해시를 꺼내 응답에 싣는다 [3].

`detect_persistence`는 증거 폴더의 `disk/Windows/System32/config/` 아래나 증거 폴더 바로 아래에서 `NTUSER.DAT.runkeys.csv`·`SOFTWARE.runkeys.csv`를 Run 키 자료로, `SYSTEM.services.csv`(바로 아래는 `services.csv`)를 서비스 자료로 고른다 [6].
`list_scheduled_tasks`는 `disk/Windows/System32/Tasks`와 `Windows/System32/Tasks` 가운데 먼저 있는 폴더의 파일을 예약 작업으로 본다 [7].
`parse_linux_cron_jobs`는 받은 루트 아래 `etc/crontab`, `etc/cron.d/`, `var/spool/cron/`처럼 정해 둔 경로 9곳마다 종류를 정한다 [8].
종류는 파싱 규칙을 정한다 [9].
`etc/cron.hourly/` 같은 주기 폴더의 파일은 스크립트 하나로, `etc/crontab`과 `etc/cron.d/`의 줄은 사용자 칸이 있는 crontab 줄로, `var/spool/cron/` 아래 파일의 줄은 파일 이름을 사용자로 보는 crontab 줄로 읽는다 [9].

**한계.** 서버는 부속 파일과 `.csv` 입력의 열 이름을 확인하지 않고 이름만 보고 그 도구의 출력으로 읽는다 [1][2][5].
`extract_mft_timeline`은 `Created0x10`이나 `Created` 열이 없는 줄을 시간 범위 밖의 줄과 같이 건너뛰므로 다른 형식의 CSV를 받으면 오류 없이 0건을 돌려준다 [5].
`parse_prefetch`는 내용을 보지 않으므로 Prefetch가 아닌 파일도 이름이 맞으면 실행 파일 이름과 경로 해시를 돌려준다 [3].
글자만 담은 파일을 `EVIL.EXE-12345678.pf`로 두고 부르자 `executable`이 `EVIL.EXE`인 응답이 돌아왔다 [10].
열 이름이 `a`·`b`인 CSV를 `extract_mft_timeline`에 주자 `total`이 0이고 `error`가 없는 응답이 돌아왔다 [10].
`detect_persistence`와 `list_scheduled_tasks`는 정해 둔 두 위치 밖에 놓인 같은 이름의 자료를 읽지 않는다 [6][7].
`parse_linux_cron_jobs`는 `etc/anacrontab`에 종류 `anacron_system`을 정하지만 그 종류에 맞는 파싱 규칙이 없어 `var/spool/cron/` 아래 파일과 같은 규칙으로 읽는다 [11].
anacrontab 형식의 줄 하나를 두고 부르자 `user`가 `anacrontab`이고 `schedule`에 작업 이름과 명령 앞부분이 섞인 작업이 돌아왔다 [12].

### P01.02 메타데이터 조회

**구현.** 이 방식은 부속 파일이 있는지로 읽을 입력을 고르는 도구 4개와 경로가 파일인지 폴더인지로 처리를 고르는 `analyze_downloads`, EvtxECmd·PECmd 래퍼 4개에 적용된다 [3][4][13][14].
`parse_knowledgec`, `parse_browser_history`, `analyze_downloads`는 부속 CSV가 있으면 SQLite DB를 열지 않고 CSV를 읽는다 [4].
부속 CSV가 없을 때만 DB를 읽기 전용으로 연다 [4].
`parse_prefetch`는 부속 JSON이 있으면 그 내용을 그대로 돌려주고 없으면 파일 이름만 읽는다 [3].
`analyze_downloads`는 `mode`가 `auto`이면 받은 경로가 파일일 때 브라우저 DB로, 폴더일 때 `Zone.Identifier` 파일을 모은 폴더로 읽는다 [13].
EvtxECmd·PECmd 래퍼는 받은 경로가 폴더이면 `-d`, 파일이면 `-f`로 도구에 넘긴다 [14].

서버가 증거의 OS나 파티션을 판별하는 코드는 없다.
Volatility 3 래퍼는 도구 이름마다 `windows.`·`linux.`·`mac.` 플러그인이 정해져 있고 `_run_vol_plugin`은 받은 이미지 경로와 그 플러그인을 그대로 넘긴다 [15].
같은 저장소의 사용자 CLI `analyze.py`는 모델에게 주는 첫 지시에 증거 폴더의 파일 목록을 200개까지 넣는다 [16].
그 주석은 이 목록으로 모델이 Windows·macOS·Linux 가운데 무엇인지 알게 한다고 적는다 [16].
클라이언트 `dfir_agent`의 live 모드 시스템 지침은 `sift_` 도구의 실행 파일이 없으면 같은 자료를 읽는 기본 도구로 바꾸라고 적는다 [17].
이 둘은 클라이언트가 모델에게 주는 글이라 다른 MCP 클라이언트로 붙으면 적용되지 않는다.

**한계.** `analyze_downloads`에 `mode`를 정해 주면 경로의 종류가 그 방식과 맞지 않아도 오류 없이 0건을 돌려준다 [13].
`browser_db`를 폴더에, `zone_identifier`를 DB 파일에 주자 `total_downloads`가 0이고 `error`가 없는 응답이 돌아왔다 [18].

### P01.03 내용·헤더 검사

**구현.** 이 방식은 브라우저 기록, 내려받기 기록, USB 기록, 셸 기록, Linux 텍스트 로그, 웹 접근 로그, 레지스트리 하이브를 읽는 도구와 JSON 사건 파일을 읽는 도구에 적용된다 [19][20][21][22][23][24][25][26][27].
`parse_browser_history`는 부속 CSV가 없으면 SQLite DB의 표 이름을 읽는다 [19].
`urls`와 `visits`가 있으면 Chromium 계열, `moz_places`가 있으면 Firefox, `history_visits`가 있으면 Safari로 보고 그에 맞는 질의를 고른다 [19].
어느 것도 없으면 찾은 표 이름과 함께 `unknown_browser_schema` 오류를 돌려준다 [19].
응답의 `browser`에는 판별한 값이 실리고 호출 인자 `browser`는 쓰이지 않는다 [19].
`analyze_downloads`는 부속 CSV가 없으면 DB의 표 이름을 읽어 `downloads` 표가 있을 때만 Chromium 질의를 실행한다 [20].
Chromium 형식 DB에 `browser`를 `firefox`로 주고 부르자 응답의 `browser`는 `chromium`이었다 [28].
`analyze_usb_history`는 `setupapi.dev.log`를 UTF-16LE, UTF-8, Latin-1 차례로 디코딩해 `Device Install`이 나오는 첫 인코딩을 쓴다 [21].
`parse_bash_history`는 `log_format`이 `auto`이면 앞 50줄에 `: `로 시작하고 `;`가 있는 줄이 있을 때 zsh 형식, 아니면 bash 형식으로 읽는다 [22].
`parse_linux_text_log`는 줄마다 Apache·nginx 접근 로그, syslog, auditd 정규식을 차례로 맞춰 형식을 정하고 맞는 정규식이 없는 줄은 `formats`의 `unparsed`로 처리한다 [23].
`analyze_web_access_log`는 줄이 combined 형식 정규식에 맞지 않으면 공백으로 나눈 칸이 10개 이상인 줄을 IIS W3C 기본 열 차례로 읽는다 [24].
Windows 사건·UnifiedLog·journal 내보내기를 읽는 도구와 `detect_credential_access`·`detect_defense_evasion`의 사건 파일 단계는 파일 전체를 JSON으로 읽어 보고 실패하면 줄마다 JSON으로 읽는다 [26].
`match_sigma_rules`는 내용이 `[`로 시작하면 JSON 배열로, 아니면 JSONL로 읽는다 [27].
`parse_launchd_plist`는 파일을 `plistlib.load`에 넘겨 XML plist와 이진 plist를 라이브러리가 가려 읽게 한다 [29].
`parse_registry_hive`는 하이브를 python-registry의 `Registry.Registry`로 열고 이 라이브러리가 `regf` 서명이 없는 파일을 거부하면 `hive_open_failed`를 돌려준다 [25].
하이브의 종류(SYSTEM·SOFTWARE 등)는 확인하지 않는다 [25].

고른 방법을 판별한 형식이나 OS와 대조하는 코드는 없다.
`match_sigma_rules`는 규칙 파일의 `logsource`를 사건과 맞춰 보지 않고 모든 규칙의 `detection`을 모든 사건에 적용한다 [30].
`Channel`이나 OS를 알리는 필드 없이 `EventID`와 `TicketEncryptionType`만 담은 사건 한 줄도 `logsource`가 Windows `security`인 `credential_access_kerberoasting.yml` 규칙에 일치했다 [31].

**한계.** `parse_browser_history`는 부속 CSV를 읽을 때 판별하지 않고 호출 인자 `browser`를 그대로 응답의 `browser`에 싣는다 [32].
`analyze_downloads`는 `downloads` 표가 없는 DB를 받으면 오류 없이 0건을 돌려준다 [20].
도구 설명은 Firefox `moz_annos`와 Safari `Downloads.plist`도 읽는다고 적지만 그 형식을 읽는 코드는 없다 [20].
`moz_annos` 표만 둔 DB로 부르자 `total_downloads`가 0이고 `error`가 없는 응답이 돌아왔다 [33].
`parse_bash_history`에 `log_format`을 정해 주면 내용을 보지 않고 그 형식으로 읽는다 [22].
zsh 형식 기록을 `bash`로 정해 부르자 `: <시각>:0;` 머리가 그대로 붙은 줄이 `ts`가 `null`인 명령으로 돌아왔다 [34].
`parse_linux_shell_history`의 설명은 bash와 zsh 기록을 읽는다고 적지만 처리기는 형식을 판별하지 않고 `#<숫자>` 줄만 시각으로 읽는다 [35].
`analyze_web_access_log`의 입력 schema는 `log_format`에 `combined`·`common`·`iis_w3c`·`auto`를 알리지만 처리기는 이 값을 쓰지 않는다 [36].
`analyze_usb_history`는 세 인코딩 모두에서 `Device Install`을 찾지 못하면 UTF-8로 디코딩하고 이를 응답에 알리지 않는다 [21].
JSON 사건 파일을 읽는 도구는 JSON으로 읽히지 않는 줄을 건너뛰고 건너뛴 줄 수를 응답에 싣지 않는다 [26].

def get_amcache(hive_path, cursor=0, limit=100):
    p = _safe_resolve(hive_path)
    if not p.exists():
        return {"error": "file_not_found", "path": str(p)}
    csv_sidecar = p.with_suffix(".csv")
    if not csv_sidecar.exists():
        # Refuse to synthesize. A forensic tool MUST NOT return invented
        # records — an analyst seeing 'sample-0.exe ... sample-41.exe'
        # could plausibly mistake them for real evidence. Match the
        # pattern used elsewhere (e.g. _v05_supply_chain) and surface
        # the missing sidecar as an explicit error.
        return {
            "error": "amcache_csv_missing",
            "path": str(p),
            "hint": (
                "AmcacheParser sidecar not found alongside the hive. "
                "Run AmcacheParser.exe --csv <out_dir> -f <hive> and "
                "place the resulting CSV next to the hive with the "
                "same stem (e.g. Amcache.csv next to Amcache.hve)."
            ),
        }
    items = _read_csv(csv_sidecar)
    total = len(items)
    s, e = cursor, min(cursor + limit, total)
    return {"source": {"path": str(p), "sha256": _sha256(p)},
            "total": total, "cursor_next": e if e < total else None,
            "items": items[s:e]}
```

def parse_prefetch(prefetch_path):
    p = _safe_resolve(prefetch_path)
    if not p.exists():
        return {"error": "file_not_found", "path": str(p)}
    sidecar = p.with_suffix(".json")
    if sidecar.exists():
        data = json.loads(sidecar.read_text(encoding="utf-8"))
        data["source"] = {"path": str(p), "sha256": _sha256(p)}
        return data
    m = re.match(r"^(.+)-([0-9A-F]{8})\.pf$", p.name, re.IGNORECASE)
    if not m:
        return {"error": "bad_prefetch_name", "name": p.name}
    return {"source": {"path": str(p), "sha256": _sha256(p)},
            "executable": m.group(1), "path_hash": m.group(2),
            "size_bytes": p.stat().st_size,
            "note": "native reader — run PECmd for run counts and loaded modules"}
```

def extract_mft_timeline(mft_path, start, end, cursor=0, limit=500):
    p = _safe_resolve(mft_path)
    if not p.exists():
        return {"error": "file_not_found", "path": str(p)}
    csv_path = p if p.suffix.lower() == ".csv" else p.with_suffix(".csv")
    if not csv_path.exists():
        return {"error": "mft_csv_missing",
                "hint": f"run MFTECmd.exe -f {p} --csv <dir>",
                "source": {"path": str(p), "sha256": _sha256(p)}}
    sdt, edt = _parse_ts(start), _parse_ts(end)
    if sdt is None or edt is None:
        return {"error": "bad_time_format"}
    matched = []
    for row in _read_csv(csv_path):
        created = _parse_ts(row.get("Created0x10") or row.get("Created") or "")
        if created is None or created < sdt or created > edt:
            continue
        matched.append({
            "entry": row.get("Entry") or row.get("EntryNumber"),
            "path": (row.get("ParentPath", "") + "\\" + row.get("FileName", "")).strip("\\"),
            "created": row.get("Created0x10") or row.get("Created"),
            "modified": row.get("LastModified0x10"),
            "accessed": row.get("LastAccess0x10"),
        })

```python
def _evidence_tree(root: Path, limit: int = 200) -> str:
    """List the evidence files available under root, relative to it.

    A real analyst is always handed an inventory of what was collected — they
    don't guess blindly whether the image is Windows, macOS or Linux. Giving
    the model the file list is that inventory, NOT a hint about the incident:
    it says what evidence exists, not what happened or which artifact is
    malicious. Without it the agent wastes iterations probing for Windows
    artifacts on a macOS image (and vice-versa) and can miss the evidence
    entirely. The scenario itself still has to be discovered from the data.
    """
    if not root.is_dir():
        return "(no evidence files found)"
    files = sorted(p.relative_to(root).as_posix()
                   for p in root.rglob("*") if p.is_file())
    if not files:
        return "(no evidence files found)"
    shown = files[:limit]
    out = "\n".join(f"  - {f}" for f in shown)
    if len(files) > limit:
        out += f"\n  ... and {len(files) - limit} more"
    return out
```
