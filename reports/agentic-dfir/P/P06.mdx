# P06 조사 상태 유지

### 미구현

**판단.** 서버는 열린 사건, 작업 목록, 불러온 자료, 캐시 같은 조사 상태를 두지 않는다.
도구는 호출마다 받은 경로의 증거를 다시 읽어 응답을 만들고 결과를 보관하지 않는다 [1].
`correlate_timeline`과 `dfir_corr`는 호출마다 DuckDB를 `:memory:`로 열어 표를 만들고 호출이 끝나기 전에 닫는다 [2].
`match_sigma_rules`는 호출마다 규칙 묶음 파일을 다시 읽고 `dfir_corr`도 상관 규칙 파일을 호출마다 다시 읽는다 [3].
외부 도구 래퍼가 만든 임시 폴더는 그 호출 안에서 지운다 [4].

요청 사이에 프로세스 메모리에 남는 값은 설정과 도구 등록부다.
증거 폴더 `EVIDENCE_ROOT`는 모듈을 불러올 때 환경변수에서 한 번 읽는다 [5].
도구 등록부 `_REGISTRY`는 도구 이름과 설명, 입력 schema, 처리 함수를 담는다 [6].
두 값은 조사에서 부른 도구나 받은 결과를 담지 않고 파일이나 DB에 쓰지 않는다 [5][6].
`DFIR_DERIVED_ROOT`와 외부 도구 경로 환경변수는 호출마다 다시 읽는다 [7].

`sift_plaso_log2timeline`이 쓴 Plaso 저장 파일은 프로세스가 끝나도 `DFIR_DERIVED_ROOT` 아래에 남는다 [8].
이 파일은 도구의 출력이고 서버는 그 경로를 기억하지 않는다 [8].
`sift_plaso_psort`는 모델이 경로를 다시 줄 때만 그 파일을 읽는다 [9].

같은 저장소의 클라이언트 `dfir_agent`는 조사 진행을 클라이언트 쪽에 둔다 [10][11].
결정적 모드는 가설과 미해결 항목을 클라이언트 프로세스 메모리에 두고 단계마다 `progress.jsonl`에 덧붙인다 [10].
live 모드는 모델과 주고받은 메시지와 도구 호출 목록을 클라이언트 프로세스 메모리의 `LiveRunState`에 두고 실행이 끝날 때 파일로 쓴다 [11].
클라이언트는 이 파일들을 다음 실행에서 다시 읽지 않는다 [10][11].

@contextmanager
def _tempdir(prefix: str = "dfir-sift-") -> Iterator[Path]:
    """Create + clean up a per-call temporary working directory."""
    d = tempfile.mkdtemp(prefix=prefix)
    try:
        yield Path(d)
    finally:
        shutil.rmtree(d, ignore_errors=True)
