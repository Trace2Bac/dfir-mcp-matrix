# agentic-dfir 원고

이 파일은 서버 개요다. 셀마다 이 폴더 아래 축 폴더의 `<축>/<셀ID>.mdx`에 쓴다.
셀과 상세 항목의 정의는 `matrix/cells/<축>/<셀ID>.mdx`를 따른다.
상세 항목마다 **구현**을 쓰고 그 방식이 적용되지 않는 경로나 조건이 있으면 **한계**를 따로 쓴다.
본문의 [번호]는 그 파일 끝 **근거**의 같은 번호를 가리킨다.

**기준 커밋.** [`a17e90b`](https://github.com/Juwon1405/agentic-dfir/tree/a17e90b8a3c5ab5431f0da9f354f315082257f99)(2026-09-06).
줄 번호는 모두 이 커밋 기준이다.

**범위.** `dfir_mcp` 패키지를 서버로 본다.
서버는 stdio MCP 서버이고 진입점이 둘이다.
`dfir_mcp/server_stdio.py`는 MCP Python SDK의 저수준 `Server`로 도구 목록과 호출을 처리한다.
`dfir_mcp/server.py`는 SDK 없이 표준 입력의 JSON-RPC 줄을 직접 읽고 응답을 쓴다.
두 진입점 모두 같은 도구 등록부의 `list_tools`와 `call_tool`을 부른다.
도구는 `dfir_mcp/__init__.py`와 `_v04_expansion`·`_v05_supply_chain`·`_v06_macos_linux`·`_v07_sigma` 모듈의 함수 48개, `sift_adapters/`의 외부 도구 래퍼 25개로 모두 73개다.
서버는 MCP 리소스와 프롬프트를 두지 않는다.
`dfir_corr` 패키지는 상관 도구가 불러 쓰는 같은 저장소의 모듈이라 서버 구현으로 본다.
`dfir_sigma/`의 규칙 묶음은 `match_sigma_rules`가 읽는 자료다.
Volatility 3, Zimmerman 도구, YARA, Plaso는 서버 프로세스가 하위 프로세스로 실행하는 분석 도구로 본다.

같은 저장소의 `dfir_agent`, `dfir_audit`, `analyze.py`, `dfir_playbook/`은 서버를 부르는 클라이언트와 사용자 CLI로 본다.
`dfir_agent`는 도구 등록부를 같은 프로세스에서 부르는 결정적 모드와, `server_stdio`를 하위 프로세스로 실행해 Anthropic API의 모델과 잇는 live 모드를 둔다.
`dfir_audit`는 `dfir_agent`가 도구 호출마다 쓰는 SHA-256 연쇄 JSONL 기록의 라이브러리이고 그 기록을 검증하고 조회하는 CLI다.
서버 진입점 가운데 `server.py`는 실패한 호출만 표준 오류에 로그로 남기고 `server_stdio.py`는 호출을 기록하지 않는다.
상세가 클라이언트 쪽 방식을 묻는 경우, 클라이언트가 MCP 도구 호출을 기록하는 경우, 클라이언트가 서버 응답으로 보고 산출물을 만드는 경우에만 이 코드를 구현으로 보고 그 밖에는 원고에 사실로만 적는다.
`scripts/install.sh`는 저장소가 지원하는 실행 환경을 만드는 설치 스크립트로 본다.
`scripts/`의 나머지와 `tests/`는 서버 구현으로 보지 않는다.
`examples/out/ref-01/`은 저장소에 커밋된 참조 실행의 출력이고 코드가 만든 기록의 실제 모양으로 인용한다.
저장소의 `CLAUDE.md`와 `AGENTS.md`는 저장소를 고치는 코딩 도우미에게 주는 안내이고 조사하는 모델에게 주는 지침이 아니다.

**확인 방법.** 코드는 기준 커밋을 `git show`로 읽었다.
라이브러리와 분석 도구의 동작은 아래 버전 기준의 소스로 확인했다.
근거의 "실행 확인"은 WSL Ubuntu 26.04에서 기준 커밋의 소스를 CPython 3.12.15로 실행해 본 결과다.
그 환경에는 아래 버전 기준의 `mcp`, `duckdb`, `python-registry`, `PyYAML`, Volatility 3를 설치했고 YARA, Plaso, Zimmerman 도구는 없었다.
서버를 루트 권한 없이 실행했다.
도구는 같은 프로세스의 `call_tool`, MCP SDK 클라이언트로 실행한 `server_stdio.py`, 표준 입력에 JSON-RPC 줄을 넣은 `server.py`의 세 경로로 불렀다.
`analyze_usb_history`는 직접 만든 `setupapi.dev.log`로 불렀고 이 도구는 `SYSTEM` 하이브의 해시만 계산하므로 하이브 자리에는 레지스트리 형식이 아닌 파일을 두었다.
없는 분석 도구의 래퍼는 받은 인자와 실행 조건을 기록하는 시험용 실행 파일을 `DFIR_*_BIN`으로 지정해 서버 쪽 처리만 확인했다.
Volatility 3는 메모리 이미지가 아닌 파일로 실패 경로만 실행했다.
시각 값은 서버의 `TZ`를 `Asia/Seoul`과 `UTC`로 바꿔 비교했다.

**외부 도구 버전 기준.** 저장소는 외부 도구 버전을 고정하지 않는다.
`scripts/install.sh`는 YARA를 배포판 패키지로, Volatility 3와 Plaso를 버전 없는 `pip install`로, Zimmerman 도구를 `net9` 배포 주소의 파일로 받는다.
파이썬 의존성은 `pyproject.toml`과 `requirements.txt`가 하한과 상한만 정하고 잠금 파일이 없다.
문서는 SIFT Workstation v22.04를 주 검증 환경으로 들지만 그 환경의 도구 버전을 적지 않는다.
그래서 기준 커밋 날짜(2026-09-06)에 나와 있던 최신 정식 릴리스를 기준으로 한다.

- Volatility 3: 2.28.0(`volatilityfoundation/volatility3` 태그 `v2.28.0`, `d61335e`)이다.
- Plaso: 20260720(`log2timeline/plaso` 태그 `20260720`, `4ea03ef`)이다.
- YARA: 4.5.8(`VirusTotal/yara` 태그 `v4.5.8`, `84b0e3c`)이다.
- Zimmerman 도구: GitHub 태그가 배포 빌드를 따르지 않아 기준 날짜의 기본 브랜치 커밋으로 확인한다.
- MCP Python SDK: `mcp<2`를 만족하는 1.29.1(`modelcontextprotocol/python-sdk` 태그 `v1.29.1`, `b222713`)이다.
- DuckDB: `duckdb<2`를 만족하는 1.5.5(`duckdb/duckdb-python` 태그 `v1.5.5`, `b236c81`)이다.
- python-registry: 1.3.1(PyPI 소스 배포본)이다. 이 버전에는 GitHub 태그가 없다.
- PyYAML: 6.0.3이다.
- 클라이언트의 `anthropic`은 1.4.0, `requests`는 2.34.2(`psf/requests` 태그 `v2.34.2`, `6e83187`)다.
- Python: `pyproject.toml`은 3.10 이상만 정한다. 실행 확인에는 CPython 3.12.15를 썼다.

**바뀔 수 있는 것.** 범위와 외부 도구 버전 기준은 조사하며 맞지 않는 곳이 나오면 검토를 거쳐 바꾼다.
