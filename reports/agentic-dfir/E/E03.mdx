# E03 원본 변경 방지

### E03.02 서버 코드의 원본 쓰기 제한

**구현.** 이 방식은 서버 코드가 증거 파일을 직접 여는 기본 도구 경로와 외부 도구의 출력 위치에 적용된다 [1][2][3][4].
기본 도구는 증거를 `read_text`·`read_bytes`나 읽기 모드의 `open`으로 읽는다 [1].
SQLite DB는 `parse_knowledgec`·`parse_browser_history`·`analyze_downloads`가 `mode=ro&immutable=1` URI로, `parse_macos_quarantine`이 `mode=ro` URI로 연다 [2].
서버 코드가 쓰기 위해 만드는 것은 외부 도구 래퍼의 호출마다의 임시 폴더와 Plaso 저장 파일의 폴더뿐이다 [3][4].
MCP 도구 가운데 쓸 파일을 인자로 받는 도구는 `sift_plaso_log2timeline` 하나다 [3].

외부 도구의 출력 위치는 증거 폴더와 다른 곳으로 정해 둔다.
Zimmerman 도구와 `psort`의 CSV는 호출마다 만든 임시 폴더에 쓰게 한다 [4].
`sift_plaso_log2timeline`의 저장 파일 경로는 `_safe_derived_path`가 `DFIR_DERIVED_ROOT` 아래로만 정한다 [5].
상대 경로는 `.`·`..` 조각을 거부하고 절대 경로와 상대 경로 모두 실제 경로로 변환해 그 폴더 밖이면 거부한다 [5].
같은 이름의 저장 파일이 이미 있으면 실행하지 않는다 [3].
`_safe_derived_path`의 설명 문자열은 파생물을 증거 폴더에 다시 쓰지 않으려고 따로 둔 폴더라고 적는다 [5].

**한계.** `parse_macos_quarantine`은 `immutable` 없이 `mode=ro`로만 연다 [2].
WAL 모드 DB를 이렇게 열자 원본 폴더의 `-shm` 파일 내용이 바뀌었다 [6].
`-shm`이 없던 경우에는 원본 폴더에 새 `-shm` 파일이 생겼다 [6].
DB 파일과 `-wal` 파일은 바뀌지 않았다 [6].
네 도구는 DB 경로를 퍼센트 인코딩하지 않고 `file:<경로>?mode=…` 문자열에 넣어 `sqlite3.connect`에 URI로 넘긴다 [2].
실행 확인 환경의 CPython 3.12.15가 쓰는 SQLite 3.53.1은 URI에서 `#`을 만나면 그 뒤를 읽지 않고 파일 이름에서 처음 나온 `?`의 뒤를 옵션으로 읽는다 [7].
CPython 3.12.15의 `sqlite3`는 SQLite에 읽기·쓰기와 만들기 플래그를 주고 연다 [8].
그래서 경로에 `#`이 있으면 `#` 앞까지가 파일 이름이 되고 `mode=ro`가 적용되지 않아 그 이름의 파일이 원본 폴더에 새로 생긴다 [2][7][8].
이름이 `know#ledge.db`인 DB로 `parse_knowledgec`를 부르자 같은 폴더에 0바이트 파일 `know`가 생겼고 도구는 `no such table` 오류를 돌려주었다 [6].
`parse_macos_quarantine`도 `Quar#V2`를 받아 같은 폴더에 `Quar`를 만들었다 [6].
경로에 `?`가 들어간 경우는 실행으로 확인하지 못했다 [7].
`_safe_derived_path`는 `DFIR_DERIVED_ROOT`가 증거 폴더와 겹치는지 확인하지 않는다 [5].
`DFIR_DERIVED_ROOT`를 증거 폴더 안으로 두자 `sift_plaso_log2timeline`은 실행 파일을 찾기 전에 증거 폴더 안에 저장 파일의 폴더를 만들었다 [9].

### E03.03 외부 도구·플랫폼에 위임

**구현.** 이 방식은 증거 경로를 외부 실행 파일에 넘기는 외부 도구 래퍼 25개와 하이브 경로를 파서 라이브러리에 넘기는 `parse_registry_hive`에 적용된다 [10][11].
래퍼는 받은 경로를 `safe_evidence_input`으로 확인한 뒤 Volatility 3·Zimmerman 도구·YARA·Plaso의 입력 인자로 넘기고 셸 없이 실행한다 [10][12].
Volatility 3·YARA 래퍼와 `sift_recmd_query_key`는 출력 파일 인자를 넘기지 않고 표준 출력을 받는다 [10].
이 경로에서 원본을 지키는 것은 외부 도구와 라이브러리가 증거를 읽기만 한다는 동작이다.

Volatility 3 2.28.0의 `FileLayer`는 파일을 `rb` 모드로 연다 [13].
Volatility 3는 심볼 캐시를 증거 옆이 아니라 자기 캐시 폴더에 쓴다 [14].
Zimmerman 도구는 기준 날짜의 기본 브랜치 커밋에서 입력 파일을 `FileAccess.Read`로 연다 [15].
MFTECmd는 `MFT` 라이브러리, PECmd는 `Prefetch` 라이브러리, AmcacheParser는 `Registry` 라이브러리를 거쳐 열고 EvtxECmd·RECmd는 도구 코드에서 연다 [15].
RECmd와 AmcacheParser는 하이브가 더티이면 같은 폴더의 `<하이브 이름>.LOG?` 파일을 읽어 메모리에 올린 하이브에 적용한다 [16].
YARA 4.5.8은 대상 파일을 `O_RDONLY`로 열고 `PROT_READ`·`MAP_PRIVATE`로 매핑한다 [17].
Plaso 20260720의 `psort`는 분석 플러그인이 없으면 저장 파일을 읽기 전용으로 확인하고 래퍼는 분석 플러그인 인자를 넘기지 않는다 [18].
`parse_registry_hive`는 하이브 경로를 `python-registry` 1.3.1의 `Registry.Registry`에 넘기고 이 라이브러리는 파일을 `rb`로 열어 내용 전체를 메모리로 읽는다 [11][19].

증거 폴더를 읽기 전용으로 마운트하는 실행 경로는 저장소에 없다.
README와 설계 문서는 에이전트를 시작하기 전에 증거를 OS 수준에서 읽기 전용으로 마운트한다고 적는다 [20].
사용자 안내서는 사용자가 `mount -o ro,loop`나 `mount --bind -o ro`를 직접 실행하라고 적는다 [21].
`scripts/install.sh`에서 `mount`가 나오는 줄은 `ewfmount` 패키지를 설명하는 주석 한 줄뿐이다 [22].
사용자 CLI `analyze.py`는 저장소 안의 사례 폴더 `evidence_root`를 마운트 없이 `DFIR_EVIDENCE_ROOT`로 둔다 [23].

**한계.** Plaso 20260720의 `log2timeline`이 받은 원본 이미지나 폴더를 읽기 모드로 여는지는 소스로 확인하지 못했다 [24].
그래서 `sift_plaso_log2timeline` 경로의 실제 보호는 확인하지 못했다(실제 보호 미확인) [24].

[5] `_safe_derived_path`는 저장 파일 경로를 `DFIR_DERIVED_ROOT` 아래로 제한하고 증거 폴더와 비교하지 않는다.

```python
def _safe_derived_path(path_str: str, *, must_exist: bool = False) -> Path:
    """Resolve a Plaso storage path under DFIR_DERIVED_ROOT.

    Plaso is the one adapter family that needs a persistent derived artifact
    for later psort slicing. Derived artifacts must never be written back into
    EVIDENCE_ROOT, so this helper constrains them to a separate root.
    """
    if not isinstance(path_str, str) or not path_str:
        raise PathTraversalAttempt(f"invalid derived path: {path_str!r}")
    if "\x00" in path_str:
        raise PathTraversalAttempt("null byte in derived path")

    root = _derived_root()
    raw = Path(path_str).expanduser()
    if raw.is_absolute():
        candidate = raw.resolve()
    else:
        norm = path_str.replace("\\", "/")
        parts = [p for p in norm.split("/") if p]
        if not parts or any(p in (".", "..") for p in parts):
            raise PathTraversalAttempt(f"invalid derived path: {path_str!r}")
        candidate = (root / Path(*parts)).resolve()

    try:
        candidate.relative_to(root)
    except ValueError as e:
        raise PathTraversalAttempt(
            f"derived path escapes {DERIVED_ROOT_ENV}: {path_str!r}"
        ) from e
```
