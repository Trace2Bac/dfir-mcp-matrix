# E04 분석 입력 준비

### E04.02 선택 추출

**구현.** 이 방식은 받은 폴더나 증거 폴더 아래에서 정해 둔 경로, 이름, 확장자로 파일을 고르는 도구와 증거 옆의 부속 CSV·JSON을 이름으로 고르는 도구에 적용된다 [1][2][3][4][5][6].
이 도구들은 고른 파일을 제자리에서 읽고 사본을 만들지 않는다.
`detect_persistence`는 Run 키·서비스 CSV를 정해 둔 두 위치에서 고르고 `list_scheduled_tasks`가 고른 Tasks 폴더의 파일을 더한다 [1].
`parse_linux_cron_jobs`는 받은 루트 아래 정해 둔 9곳을 고르고 그 경로가 폴더이면 바로 아래의 파일만 읽는다 [2].
`detect_python_backdoor_persistence`는 받은 홈 폴더 아래 정해 둔 상대 경로 11곳을 보고 폴더이면 이름 차례로 앞 50개 항목의 상태 값만 응답에 싣는다 [7].
`scan_pth_files_for_supply_chain_iocs`는 `*.pth`를, `detect_nodejs_install_hooks`는 `package.json`을 받은 폴더 아래 깊이 `max_depth` 안에서 고른다 [3].
`analyze_downloads`는 폴더를 받으면 하위 폴더까지 `*.Zone.Identifier` 파일을 찾아 경로 차례로 `limit`개까지 고른다 [4].
`detect_webshell`은 웹 루트 아래 파일을 모두 훑고 확장자가 `WEBSHELL_SUSPICIOUS_EXT`에 있고 `max_file_size` 이하인 파일만 내용을 읽는다 [5].
부속 CSV·JSON을 읽는 도구 8개는 받은 증거 대신 그 옆에서 이름으로 고른 파일을 분석 입력으로 쓴다 [6].
`detect_credential_file_access`는 정해 둔 자격증명 파일 14개와 `.env`를 고르지만 내용을 읽지 않고 상태 값만 응답에 싣는다 [8].

그 밖의 도구는 받은 경로를 그대로 쓴다.
외부 도구 래퍼는 받은 메모리 이미지, 디스크 이미지, 폴더 경로를 그대로 외부 도구에 넘긴다 [9].
`sift_plaso_log2timeline`은 받은 이미지나 폴더를 그대로 넘겨 Plaso가 스스로 이미지를 열게 한다 [9].
서버에는 이미지를 마운트하거나 보관 파일을 풀거나 작업 사본을 만드는 코드가 없다.

서버 코드는 하이브의 트랜잭션 로그나 SQLite의 `-wal` 같은 부속 자료를 찾지 않는다 [9][10].
RECmd와 AmcacheParser는 하이브가 더티이면 같은 폴더의 `<하이브 이름>.LOG?`를 스스로 찾아 메모리의 하이브에 적용한다 [11].
RECmd 래퍼는 `--nl`을 넘기고 주석에 로고를 끄는 인자라고 적는다 [12].
RECmd는 `--nl`을 더티 하이브에 로그 파일이 없어도 처리를 이어 가게 하는 인자로 정의한다 [11].
그래서 로그가 없는 더티 하이브는 RECmd가 경고만 남기고 처리하며 `sift_recmd_run_batch`의 응답에는 CSV 행만 실린다 [11][12].
AmcacheParser는 `--nl`이 없으면 로그가 없는 더티 하이브에서 처리를 멈추고 래퍼는 이 인자를 넘기지 않는다 [11][13].
그때 AmcacheParser는 CSV를 쓰지 않고 종료 코드 0으로 끝나며 `sift_amcacheparser_parse`는 `total_rows`가 0인 응답을 오류 없이 돌려준다 [14][13].
`parse_knowledgec`·`parse_browser_history`·`analyze_downloads`는 SQLite DB를 `immutable=1`로 열고 `parse_macos_quarantine`은 `mode=ro`로만 연다 [10].
`-wal`에만 있는 행을 가진 Chromium 형식 DB에서 `parse_browser_history`는 그 행을 돌려주지 않았고 응답에 이를 알리는 필드는 없었다 [15].
`-wal`에만 행이 있는 `QuarantineEventsV2`에서 `parse_macos_quarantine`은 그 행을 돌려주었다 [15].

**한계.** `detect_webshell`은 `max_files_scanned`에 닿으면 멈추고 응답에 그 사실을 적지 않는다 [5].
파일 5개를 둔 웹 루트에 `max_files_scanned` 2를 주자 `files_scanned`가 2인 응답이 돌아왔고 남은 파일이 있다는 표시는 없었다 [16].
`scan_pth_files_for_supply_chain_iocs`와 `detect_nodejs_install_hooks`는 `limit`개를 읽으면 멈추고 응답에 그 사실을 적지 않는다 [3].
두 도구는 `rglob`가 깊이와 관계없이 모든 하위 폴더를 훑게 두고 찾은 파일마다 깊이를 비교한다 [3].
`analyze_downloads`는 찾은 `Zone.Identifier` 파일을 `limit`개로 자르고 응답에 그 사실을 적지 않는다 [4].
정해 둔 경로 밖에 놓인 같은 종류의 자료는 이 도구들의 입력에 포함되지 않는다 [1][2].

### E04.04 추출·생략 범위 기록

**구현.** 이 방식은 고른 입력의 경로나 개수를 응답에 싣는 도구에 적용된다 [1][2][3][5][6][17].
`detect_persistence`는 읽은 CSV의 경로를 `sources_examined`에 싣는다 [1].
`parse_linux_cron_jobs`는 훑은 경로 9곳을 `scanned_paths`에, 작업마다 읽은 파일의 경로를 `path`에 싣는다 [2].
`list_scheduled_tasks`는 고른 파일마다 증거 폴더 기준 경로, 크기, SHA-256을 싣는다 [17].
`scan_pth_files_for_supply_chain_iocs`는 `files_scanned`를, `detect_nodejs_install_hooks`는 `package_jsons_scanned`를, `detect_webshell`은 `files_scanned`를 싣는다 [3][5].
`parse_shimcache`·`parse_shellbags`·`parse_knowledgec`·`parse_browser_history`는 읽은 부속 CSV의 경로를 `sidecar`에 싣는다 [6].

**한계.** `get_amcache`, `extract_mft_timeline`, `parse_prefetch`는 부속 파일을 읽어도 그 경로를 싣지 않고 받은 증거의 경로만 `source`에 싣는다 [6].
`analyze_downloads`는 부속 CSV에서 읽은 항목에 `browser_db_sidecar`라는 출처 이름만 붙이고 그 파일의 경로를 싣지 않는다 [6].
`parse_linux_cron_jobs`의 `scanned_paths`는 없는 경로도 담아 실제로 읽은 경로와 구별되지 않는다 [2].
`etc/crontab` 하나만 둔 증거 폴더에서도 `scanned_paths`에 9곳이 모두 실렸다 [18].
`detect_persistence`는 찾지 못한 CSV를 응답에 적지 않는다 [1].
`detect_webshell`의 `files_scanned`는 상한에 닿은 경우와 웹 루트의 파일을 다 훑은 경우를 구별하지 않는다 [5][16].
