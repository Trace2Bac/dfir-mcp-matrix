# L03 기록 실패 처리

### L03.03 알림 없이 계속

**구현.** 이 방식은 STDIO 래퍼가 `mcp-stdio.log`에 쓰는 모든 항목에 적용된다 [1].
`log`는 크기 확인, 파일 이름 바꾸기, 덧붙이기를 `try`로 감싸고 예외가 나면 아무것도 하지 않는다 [1].
`log`는 값을 돌려주지 않는다 [1].
`log`를 부른 처리기는 기록 결과와 관계없이 응답을 만든다 [1][2].
기록 파일 자리에 같은 이름의 폴더를 두어 덧붙이기가 실패하게 하자 `tools/list`와 `tools/call`은 평소와 같은 응답을 돌려줬고 표준 오류에도 아무것도 출력되지 않았다 [3].
Autopsy 프로세스 안의 HTTP 서버는 도구 호출 항목을 쓰지 않는다 [4].

### 근거

[1] 함수 `log`는 모든 쓰기 예외를 처리하고 아무것도 하지 않는다.

```javascript
function log(level, message) {
    // Only ERROR level is persisted to disk. INFO/DEBUG calls are no-ops
    // by design — they would be too noisy in production and are visible
    // during development via a debugger or by temporarily removing this guard.
    if (level !== "ERROR") return;
    try {
        // Rotate if the log has grown too large
        try {
            if (fs.statSync(LOG_PATH).size > MAX_LOG_BYTES) {
                fs.renameSync(LOG_PATH, LOG_PATH + ".1");
            }
        } catch { /* file doesn't exist yet — that's fine */ }

        const line = `${new Date().toISOString()} [${level}] ${message}\n`;
        fs.appendFileSync(LOG_PATH, line, "utf8");
    } catch { /* never let logging crash the process */ }
}
```
