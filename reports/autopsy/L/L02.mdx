# L02 기록 구성

### L02.05 결과 상태·실행 시점 기록

**구현.** 이 방식은 STDIO 래퍼가 `mcp-stdio.log`에 남기는 실패 항목에 적용된다 [1].
항목 한 줄은 `toISOString()`으로 만든 UTC 시각, 수준 `[ERROR]`, 메시지로 이루어진다 [1].
`tools/call` 처리기가 쓰는 메시지는 `tools/call <도구 이름> failed: <오류 메시지>` 형태다 [2].
오류 메시지에는 실패의 종류가 담긴다 [3][4].
토큰 파일이 없으면 케이스가 열려 있지 않거나 토큰 파일이 없다는 문장이 담긴다 [4].
HTTP 응답이 성공이 아니면 `Autopsy HTTP error <상태 코드>`가 담긴다 [3].
Java 쪽이 JSON-RPC 오류를 돌려주면 `Autopsy MCP error:` 뒤에 Java 쪽 메시지가 담긴다 [3].
시간 제한이 지나면 `Autopsy MCP timed out after 30s (tools/call)`이 담긴다 [3].
`callJava`는 HTTP 오류, JSON-RPC 오류, 시간 초과에서 같은 실패를 도구 이름 없이 메서드 이름만 붙인 줄로 한 번 더 남긴다 [3].
토큰 파일이 없는 실패와 시간 초과가 아닌 연결 실패는 처리기의 줄 하나만 남는다 [3][4].
`tools/list`가 실패하면 래퍼는 대체 도구를 돌려주기 전에 `tools/list failed — Autopsy not reachable:`로 시작하는 줄을 남긴다 [5].
JSON-RPC 오류를 받은 호출 하나에서 `<- tools/call MCP error: accountId is required`와 `tools/call bad failed: Autopsy MCP error: accountId is required` 두 줄이 남았다 [6].

도구 이름은 실패 항목의 메시지 글 안에만 있고 따로 나뉜 칸에 기록되지 않는다 [2].
항목에는 도구 인자를 담는 칸이 없고 응답 내용, 응답의 크기나 해시도 들어 있지 않다 [2][3].
다만 오류 메시지에는 Java 쪽 오류 문구가 그대로 실리고 Java 쪽은 `McpException`과 예상하지 못한 예외의 문구를 오류 문구로 돌려준다 [3][7].
그래서 `No object found with id <objectId>`, `Unknown tool: <이름>`, Sleuth Kit `findAllFilesWhere`가 예외 문구에 넣는 WHERE 조건처럼 모델이 준 인자 값이나 서버가 만든 질의 조건이 항목에 섞일 수 있다 [8][9].
한 호출에서 나온 두 줄을 잇는 호출 ID는 없다 [3].
`callJava`가 HTTP 요청에 싣는 JSON-RPC `id`는 늘 `"1"`이다 [3][6].
래퍼는 `callJava`가 실패로 끝난 뒤에 항목을 쓰므로 항목은 래퍼가 그 호출의 실패를 확인한 뒤의 상태다 [2].
시간 초과 항목은 래퍼가 기다리기를 끊은 시점의 상태다 [3].
Java 쪽 HTTP 처리기에는 시간 제한이나 취소 코드가 없어 Autopsy 안의 질의는 그 뒤에도 끝날 때까지 계속 실행된다 [10].
Autopsy 프로세스 안의 HTTP 서버는 도구 호출 항목을 남기지 않는다 [11].
이 서버는 요청 처리에서 예상하지 못한 예외와 잘못된 JSON만 도구 이름 없이 기록한다 [11].

**한계.** 성공한 호출은 항목을 남기지 않는다 [1][2].
그래서 기록에 항목이 없다는 사실로는 호출이 성공했는지 호출이 없었는지 구별하지 못한다.
설치본 실행 파일은 응답이 75초 늦는 호출도 시간 제한 없이 결과를 돌려주고 시간 초과 항목을 남기지 않았다 [12].
같은 소스를 Node.js 24로 실행하면 30초에서 호출을 끊고 시간 초과 항목 두 줄을 남겼다 [12].
토큰 파일이 없을 때 남는 메시지는 케이스가 열려 있지 않다고 적는다 [4].
그러나 Java 쪽은 MCP 서버를 시작할 때 토큰 파일을 쓰고 서버를 멈출 때 지우며 케이스를 열거나 닫을 때는 토큰 파일을 건드리지 않는다 [13].
그래서 이 항목은 Autopsy가 실행 중이 아니거나 MCP 서버가 꺼진 상태를 케이스가 열려 있지 않은 상태로 기록한다 [4][13].

const LOG_PATH = path.join(MCP_DIR, "mcp-stdio.log");
const MAX_LOG_BYTES = 1 * 1024 * 1024; // 1 MB — rotate when exceeded

function log(level, message) {
    // Only ERROR level is persisted to disk. INFO/DEBUG calls are no-ops
    // by design — they would be too noisy in production and are visible
    // during development via a debugger or by temporarily removing this guard.
    if (level !== "ERROR") return;
    try {
        // Rotate if the log has grown too large
        try {
            if (fs.statSync(LOG_PATH).size > MAX_LOG_BYTES) {
                fs.renameSync(LOG_PATH, LOG_PATH + ".1");
            }
        } catch { /* file doesn't exist yet — that's fine */ }

        const line = `${new Date().toISOString()} [${level}] ${message}\n`;
        fs.appendFileSync(LOG_PATH, line, "utf8");
    } catch { /* never let logging crash the process */ }
}
