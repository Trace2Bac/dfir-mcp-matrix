# L01 기록 방식

### L01.01 공통 요청 처리 단계에서 기록

**구현.** 이 방식은 STDIO 래퍼를 거치는 `tools/call`과 `tools/list` 요청에 적용된다 [1].
래퍼의 `tools/call` 처리기는 모든 도구 호출이 지나는 공통 단계다 [1].
이 처리기는 `callJava`가 실패하면 도구 이름과 오류 메시지를 한 줄로 기록한다 [1].
토큰 파일을 읽지 못해 HTTP 요청을 보내기 전에 난 실패도 이 줄로 남는다 [1][2].
HTTP 요청을 보내는 공통 함수 `callJava`도 HTTP 오류, JSON-RPC 오류, 시간 초과를 만나면 메서드 이름과 함께 한 줄을 기록한다 [3].
토큰 파일이 없는 실패와 시간 초과가 아닌 연결 실패에서는 `callJava`가 줄을 남기지 않는다 [3].
두 곳 모두 함수 `log`로 쓴다 [4].
`log`는 수준이 `ERROR`인 줄만 `%LOCALAPPDATA%\autopsy\mcp\mcp-stdio.log`에 덧붙인다 [4].
환경변수 `LOCALAPPDATA`가 없으면 기록 폴더는 사용자 홈 아래 `AppData\Local\autopsy\mcp`이다 [4].
토큰 파일이 없는 상태, HTTP 401·500, JSON-RPC 오류를 받은 호출에서 `[ERROR] tools/call <도구 이름> failed: <메시지>` 형태의 줄이 남았다 [2].

Autopsy 프로세스 안의 HTTP 서버는 도구 호출을 기록하지 않는다 [5].
`McpProtocolHandler.handle`은 해석하지 못한 JSON을 `WARNING`으로, 예상하지 못한 예외를 `SEVERE`로 기록한다 [5].
이 두 줄의 고정 메시지에는 도구 이름과 인자가 없다 [5].
함께 기록되는 예외에는 인자 값이 실릴 수 있고 Sleuth Kit `findAllFilesWhere`의 예외 문구는 모델 인자로 만든 WHERE 조건 전체를 담는다 [5][6].
알 수 없는 도구, 인자 오류, 사건 없음처럼 `McpException`으로 끝나는 호출은 기록하지 않는다 [5].
`McpServer.handleMcpRequest`는 처리기가 예외를 던질 때만 `SEVERE`로 기록한다 [7].
Java MCP 클래스 가운데 `AutopsyMcpModule`·`McpServer`·`McpProtocolHandler`는 `java.util.logging.Logger`를 직접 쓴다 [8].
Autopsy의 `coreutils.Logger`는 자기가 만든 로거에만 `autopsy.log` 파일 처리기를 붙이고 부모 처리기를 쓰지 않게 한다 [9].
그래서 이 처리기는 위 세 클래스의 로거에 붙지 않는다 [9].
위 세 클래스의 로거는 루트 로거의 처리기를 쓴다 [10].
NetBeans 플랫폼 15는 루트 로거에 사용자 폴더의 `var/log/messages.log`에 쓰는 처리기를 붙인다 [10].
이 기록이 실제로 `messages.log`에 남는지는 실행으로 확인하지 않았다 [10].
옵션 창의 `McpOptionsPanelController`만 Autopsy의 `coreutils.Logger`를 쓴다 [11].
이 컨트롤러는 설정 변경 알림 중 난 예외만 기록한다 [11].
사용자 문서는 `autopsy-mcp-stdio --test`가 연결하지 못하면 `\AppData\Local\Autopsy\MCP` 폴더의 기록을 보라고 안내한다 [12].
그 폴더에는 래퍼의 실패 줄만 남고 `--test`의 결과와 Java 서버가 시작에 실패할 때 `AutopsyMcpModule`이 남기는 `SEVERE` 기록은 남지 않는다 [13][14].

같은 저장소에 MCP 도구 호출을 기록하는 클라이언트 코드는 없다.
사용자 CLI인 `--test` 모드의 `runTest`는 확인 결과를 표준 출력에 출력하고 `log`를 부르지 않는다 [13].

**한계.** 성공한 호출은 기록에 남지 않는다 [1][4].
`tools/call` 처리기가 실행 전에 부르는 `log("INFO", …)`와 `callJava`의 `INFO` 줄은 `log`가 쓰지 않고 바로 돌아간다 [1][3][4].
Autopsy HTTP 서버는 토큰만 맞으면 `127.0.0.1`의 `POST /mcp` 요청을 받는다 [15].
그래서 STDIO 래퍼를 거치지 않고 HTTP 서버에 직접 보낸 도구 호출은 실패해도 래퍼 기록에 남지 않는다 [15].

const LOG_PATH = path.join(MCP_DIR, "mcp-stdio.log");
const MAX_LOG_BYTES = 1 * 1024 * 1024; // 1 MB — rotate when exceeded

function log(level, message) {
    // Only ERROR level is persisted to disk. INFO/DEBUG calls are no-ops
    // by design — they would be too noisy in production and are visible
    // during development via a debugger or by temporarily removing this guard.
    if (level !== "ERROR") return;
    try {
        // Rotate if the log has grown too large
        try {
            if (fs.statSync(LOG_PATH).size > MAX_LOG_BYTES) {
                fs.renameSync(LOG_PATH, LOG_PATH + ".1");
            }
        } catch { /* file doesn't exist yet — that's fine */ }

        const line = `${new Date().toISOString()} [${level}] ${message}\n`;
        fs.appendFileSync(LOG_PATH, line, "utf8");
    } catch { /* never let logging crash the process */ }
}
