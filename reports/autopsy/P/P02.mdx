# P02 다음 작업 결정

### P02.02 규칙·조사 상태로 추천

**구현.** 이 방식은 사건이 열려 있지 않을 때의 Java 쪽 오류 응답과 STDIO 래퍼가 Autopsy에 닿지 못할 때의 응답에 적용된다.
사건이 열려 있지 않으면 Java 쪽은 `get_server_status`·`get_case_summary` 밖의 도구 호출에 Autopsy에서 사건을 먼저 열라는 오류 문구를 돌려준다 [1].
래퍼는 토큰 파일이 없으면 Autopsy에서 사건을 먼저 열라는 오류 문구를 돌려준다 [2].
래퍼는 HTTP 상태가 성공이 아니면 Autopsy가 사건을 연 채 실행 중인지 묻는 문구를 오류에 붙인다 [3].
래퍼가 Autopsy에 닿지 못하면 `tools/list`는 대체 도구 `get_server_status` 하나만 돌려주고 그 설명은 Autopsy를 실행해 사건을 열고 MCP 서버를 켠 뒤 다시 시도하라고 적는다 [2].
이 안내는 응답 문자열이고 서버가 다음 호출을 대신 고르거나 안내를 따르지 않은 호출을 막지는 않는다.

이 밖의 경우에 서버는 다음 작업을 정하거나 권하지 않는다.
STDIO 래퍼는 `Server`를 만들 때 `tools` 능력만 알리고 서버 지침을 넘기지 않는다 [4].
Java 쪽 `initialize` 처리도 `protocolVersion`·`serverInfo`·`capabilities`만 돌려주고 래퍼는 이 처리를 부르지 않는다 [5].
조사 순서 안내는 도구 하나하나의 설명에만 있다.
`get_server_status`와 `get_case_summary`의 설명은 이 도구를 먼저 부르라고 적는다 [6].
`summarize_timeline`과 `query_timeline`의 설명은 `summarize_timeline`으로 활동 분류를 먼저 본 뒤 `query_timeline`으로 이벤트를 가져오라고 적는다 [7].
`get_hosts`는 데이터 소스를 보기 전에, `list_reports`는 `get_report_content` 전에 부르라고 설명에 적는다 [8].
사건이 열려 있을 때 `get_server_status` 밖의 도구 응답은 질의 결과와 `caseId`만 싣고 다음에 부를 도구를 싣지 않는다 [1].
`get_server_status`는 `caseId`로 감싸지 않은 상태 값을 돌려준다 [1].
`summarize_timeline`은 분류별 이벤트 수를 세는 집계 하나이고 여러 분석 단계를 묶은 절차가 아니다 [9].

**한계.** 래퍼의 토큰 파일 안내는 실제 상태와 다르다.
Java 쪽은 MCP 서버를 시작할 때 토큰 파일을 쓰고 서버를 멈출 때 지우며 사건을 열거나 닫을 때는 토큰 파일을 건드리지 않는다 [10].
그래서 토큰 파일이 없는 것은 Autopsy가 실행 중이 아니거나 MCP 서버가 꺼진 상태인데 래퍼는 사건을 먼저 열라고 안내한다 [2][10].
HTTP 401은 토큰이 맞지 않을 때 나는데 래퍼는 이때도 사건을 연 채 실행 중인지 묻는 같은 문구를 붙인다 [3][11].

    Map<String, Object> summarizeTimeline(JsonNode args) throws TskCoreException {
        TimelineManager tm = skCase.getTimelineManager();
        long startEpoch = parseTimeArg(args, "startTime", tm.getMinEventTime());
        long endEpoch   = parseTimeArg(args, "endTime",   tm.getMaxEventTime());

        TimelineFilter.RootFilter filter = buildTimelineFilter(args);

        Map<TimelineEventType, Long> counts = tm.countEventsByType(
                startEpoch, endEpoch, filter, TimelineEventType.HierarchyLevel.CATEGORY);

        long total = 0;
        Map<String, Long> byCategory = new LinkedHashMap<>();
        for (Map.Entry<TimelineEventType, Long> entry : counts.entrySet()) {
            byCategory.put(entry.getKey().getDisplayName(), entry.getValue());
            total += entry.getValue();
        }

        Map<String, Object> result = new LinkedHashMap<>();
        result.put("startTime",   epochToIso(startEpoch));
        result.put("endTime",     epochToIso(endEpoch));
        result.put("totalEvents", total);
        result.put("byCategory",  byCategory);
        return result;
    }
