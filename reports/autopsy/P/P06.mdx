# P06 조사 상태 유지

### P06.02 프로세스 메모리에만 보관

**구현.** 서버의 조사 상태는 열린 케이스를 가리키는 질의 서비스 하나이고 Autopsy 프로세스 메모리에만 있다 [1].
`McpProtocolHandler`는 질의 서비스를 `volatile` 필드에 두고 케이스가 열리면 새 객체로 바꾸고 닫히면 `null`로 바꾼다 [1][2].
질의 서비스는 케이스 DB 객체와 표시 이름만 가지며 질의 결과를 쌓아 두지 않고 호출마다 케이스 DB를 다시 질의한다 [3].
Autopsy가 끝나거나 사용자가 옵션 창에서 서버를 끄면 서버 객체와 함께 이 상태도 사라진다 [4].
케이스 자료 자체는 Autopsy 본체가 케이스 DB에 저장하고 서버는 그 DB를 읽는다.
서버는 어느 케이스를 쓰고 있었는지를 저장하지 않는다.
서버가 켜질 때 Autopsy에 열린 케이스가 있으면 그 케이스로 질의 서비스를 만들고 어느 케이스를 열지는 Autopsy 본체가 정한다 [5].

STDIO 래퍼가 메모리에 두는 것은 시작할 때 읽은 포트뿐이고 토큰 파일은 호출마다 다시 읽는다 [6][7].
그래서 Autopsy가 다시 시작해 토큰이 바뀌어도 래퍼를 다시 시작하지 않고 이어서 호출할 수 있다 [7].
사용자가 `mcp-config.properties`의 포트를 바꾸면 래퍼는 다시 시작해야 새 포트로 연결한다 [6].

### P06.03 조사 상태를 파일·DB에 저장

**구현.** 프로세스가 끝나도 남는 상태는 STDIO 래퍼의 호출 기록 파일 `mcp-stdio.log` 하나다 [8].
래퍼는 실패한 도구 호출의 도구 이름과 오류 문구를 이 파일에 덧붙이고 파일이 1MB를 넘으면 `mcp-stdio.log.1`로 이름을 바꾼다 [8].
성공한 호출은 이 파일에 남지 않는다 [8].
래퍼와 Java 쪽 어느 코드도 이 파일을 다시 읽지 않으므로 이 기록은 다음 실행의 조사 상태로 쓰이지 않는다 [8].
Java 쪽이 남기는 파일은 포트 설정 파일과 토큰 파일이고 어느 케이스를 쓰고 있었는지 같은 조사 상태는 담지 않는다 [9].

```javascript
const LOG_PATH = path.join(MCP_DIR, "mcp-stdio.log");
const MAX_LOG_BYTES = 1 * 1024 * 1024; // 1 MB — rotate when exceeded

function log(level, message) {
    // Only ERROR level is persisted to disk. INFO/DEBUG calls are no-ops
    // by design — they would be too noisy in production and are visible
    // during development via a debugger or by temporarily removing this guard.
    if (level !== "ERROR") return;
    try {
        // Rotate if the log has grown too large
        try {
            if (fs.statSync(LOG_PATH).size > MAX_LOG_BYTES) {
                fs.renameSync(LOG_PATH, LOG_PATH + ".1");
            }
        } catch { /* file doesn't exist yet — that's fine */ }

        const line = `${new Date().toISOString()} [${level}] ${message}\n`;
        fs.appendFileSync(LOG_PATH, line, "utf8");
    } catch { /* never let logging crash the process */ }
}
```
