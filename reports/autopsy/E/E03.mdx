# E03 원본 변경 방지

### E03.03 외부 도구·플랫폼에 위임

**구현.** 이 방식은 원본 증거의 내용을 읽는 `get_file_content`에 적용된다 [1].
`get_file_content`는 `objectId`로 Sleuth Kit의 `AbstractFile`을 찾아 `read`로 요청한 범위를 읽는다 [1].
MCP 코드는 증거 이미지나 파일을 직접 열지 않고 사건 DB에 쓰는 호출도 두지 않는다 [2].
이 경로에서 원본을 지키는 것은 Sleuth Kit 4.15.0 라이브러리가 원본을 읽기 모드로 연다는 동작뿐이다.

`AbstractFile.read`는 파일의 종류에 따라 세 경로로 나뉜다 [3].
수집 저장소에 있는 파일은 등록된 내용 제공자로 읽는다 [3].
로컬 경로가 정해진 파일은 `readLocal`로 읽는다 [3].
그 밖의 파일은 하위 클래스의 `readInt`로 읽는다 [3].
로컬 파일 데이터 소스의 파일은 `readLocal`이 `RandomAccessFile`을 `"r"` 모드로 열어 읽는다 [4].
파일시스템 안의 파일은 `FsContent.readInt`가 파일시스템 핸들에서 연 파일 핸들로 JNI `readFile`을 부른다 [5].

이미지 파일을 데이터 소스로 더하는 일은 Autopsy 본체가 한다.
이미지 핸들은 `Image.getImageHandle`이 처음 필요할 때 `SleuthkitJNI.openImage`로 연다 [6].
그래서 본체가 아직 열지 않은 이미지는 MCP 호출 중에 이 라이브러리가 열 수 있다 [6].
JNI는 `tsk_img_open_utf8`에 형식 자동 판별을 맡겨 이미지를 연다 [7].
raw 이미지는 Windows에서 `CreateFile`을 `FILE_READ_DATA` 권한으로, 다른 운영체제에서 `open`을 `O_RDONLY`로 연다 [8].
E01은 `LIBEWF_OPEN_READ`, VMDK는 `LIBVMDK_OPEN_READ`, VHD는 `LIBVHDI_OPEN_READ`, AFF는 `O_RDONLY`로 연다 [9].
논리 이미지 폴더 안의 파일은 `CreateFileW`를 `FILE_READ_DATA` 권한으로 열어 읽는다 [10].

나머지 MCP 도구는 원본 증거에 닿지 않는다.
이 도구들은 사건 DB를 조회한다 [2].
`get_report_content`는 원본 증거가 아닌 사건 보고서 파일을 `FileChannel`의 `READ` 모드로 읽는다 [11].
증거를 읽기 전용으로 마운트하거나 서버를 읽기 전용 환경에서 실행하는 경로는 저장소에 없다.
Java HTTP 서버는 Autopsy 프로세스 안에서 Autopsy와 같은 권한으로 실행된다 [12].

**한계.** 수집 저장소에 있는 파일(`YES_REPO`)은 사건에 내용 제공자가 등록되어 있으면 그 제공자가 읽는다 [3].
기준 커밋에는 내용 제공자 `AutopsyContentProvider`의 구현이 없고 Autopsy는 설치된 플러그인에서 제공자를 찾는다 [13].
그래서 이 경로가 원본을 읽기 모드로 여는지는 확인하지 못했다.
E01·VMDK·VHD 이미지는 libewf·libvmdk·libvhdi에 읽기 플래그를 넘기는 것까지 확인했다 [9].
이 라이브러리의 버전과 그 안의 동작은 소스로 확인하지 못했다.
