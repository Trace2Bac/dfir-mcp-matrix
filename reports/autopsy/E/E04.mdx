# E04 분석 입력 준비

### 비적용

**판단.** MCP 도구는 이미지, 보관 파일, 수집물 같은 증거 입력을 받지 않고 Autopsy 본체가 케이스 DB에 등록한 객체를 ID로 조회하거나 읽는다 [1].
이미지 안의 볼륨과 파일시스템을 해석해 파일 목록을 케이스 DB에 쓰는 일과 ingest 모듈이 파일을 꺼내 분석하는 일은 데이터 소스를 더할 때 Autopsy 본체가 한다.
MCP 코드에는 작업 사본을 만들거나 보관 파일을 풀거나 이미지를 마운트하거나 부속 자료를 찾는 처리가 없다 [1].
`get_file_content`는 모델이 `objectId`로 고른 파일의 범위를 Sleuth Kit의 `AbstractFile.read`로 읽는다 [2].
읽은 바이트는 UTF-8 글자로 바꿔 응답의 `content`에 싣고 서버의 다른 분석 단계나 외부 도구의 입력으로 넘기지 않는다 [3].
`get_data_source_tree`는 본체가 만든 이미지·볼륨 시스템·볼륨·파일시스템 구조를 조회해 돌려줄 뿐 파티션을 고르거나 파일시스템을 여는 단계가 아니다 [4].
분할 이미지의 조각 경로는 본체가 등록한 `paths` 목록을 `query_data_sources`·`get_hosts`·`get_data_source_tree`가 그대로 싣는다 [5].

        // REPLACE mode should never throw, but decode() declares CharacterCodingException.
        CharsetDecoder decoder = StandardCharsets.UTF_8.newDecoder()
                .onMalformedInput(CodingErrorAction.REPLACE)
                .onUnmappableCharacter(CodingErrorAction.REPLACE);
        CharBuffer chars;
        try {
            chars = decoder.decode(ByteBuffer.wrap(buf));
        } catch (java.nio.charset.CharacterCodingException ex) {
            // Cannot happen with REPLACE policy; fall back to lossy Latin-1 conversion
            chars = CharBuffer.wrap(new String(buf, StandardCharsets.ISO_8859_1));
        }
