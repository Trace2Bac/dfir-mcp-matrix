# E01 증거 등록 관리

### 비적용

**판단.** MCP 서버는 증거를 받거나 등록하지 않고 Autopsy 본체가 등록한 증거의 등록 정보를 조회하거나 내용을 읽기만 한다 [1].
증거를 케이스에 더하는 일은 Autopsy 본체가 데이터 소스 추가로 한다.
본체는 그때 데이터 소스의 정보를 케이스 DB에 쓴다 [2].
MCP 도구는 열린 케이스의 케이스 DB를 조회할 뿐 증거 목록이나 등록 정보를 따로 남기지 않는다 [1].

MCP 도구 가운데 등록 정보를 조회해 돌려주는 도구는 `query_data_sources`, `get_hosts`, `get_data_source_tree`다 [2][3][4].
`query_data_sources`는 케이스 DB의 데이터 소스마다 `objectId`, 이름, 형식, 크기, 시간대, `deviceId`, 추가 시각 `addedDate`를 싣는다 [2].
디스크 이미지이면 이미지 형식, 섹터 크기, 이미지 파일 경로 `paths`, 수집 해시, 수집 도구 정보를 함께 싣는다 [5].
`get_hosts`는 호스트마다 그 호스트에 속한 데이터 소스를 같은 항목으로 싣고 `get_data_source_tree`도 트리의 맨 위 마디에 같은 항목을 싣는다 [3][4].
이 값은 본체가 데이터 소스를 추가할 때 쓴 값이고 MCP 코드는 읽기만 한다 [2].
Sleuth Kit 4.15.0에서 추가 시각 열을 채우는 곳은 `SleuthkitCase.addImage`뿐이다 [6].
`TskCaseDbBridge.addImageToDb`와 `SleuthkitCase.addLocalFilesDataSource`는 이 열을 비워 둔다 [6].
이 열이 비어 있으면 `getDateAdded`가 0을 돌려주고 MCP 코드는 `addedDate`를 `null`로 싣는다 [2][7].
등록한 주체를 담는 항목은 응답에 없다 [2][5].

    List<Map<String, Object>> getHosts() throws TskCoreException {
        List<Map<String, Object>> result = new ArrayList<>();
        for (Host host : skCase.getHostManager().getAllHosts()) {
            Map<String, Object> item = new LinkedHashMap<>();
            item.put("id", host.getHostId());
            item.put("name", host.getName());

            List<Map<String, Object>> dataSources = new ArrayList<>();
            for (DataSource ds : skCase.getHostManager().getDataSourcesForHost(host)) {
                dataSources.add(buildDataSourceItem((Content) ds));
            }
            item.put("dataSources", dataSources);
            result.add(item);
        }
        return result;
    }
