# T03 실행 조건 확인

### T03.01 선행 결과 대조

**구현.** 이 방식은 Java HTTP 서버의 `tools/call` 가운데 `get_server_status`·`get_case_summary`를 뺀 도구 16개에 적용된다 [1].
조건은 Autopsy에 케이스가 열려 있는지다.
케이스는 사용자가 Autopsy 화면에서 열고 닫으며 MCP 도구로는 열 수 없다.
`AutopsyMcpModule`은 케이스 이벤트 `CURRENT_CASE`를 구독해 케이스가 열리면 그 케이스로 `TskQueryService`를 만들고 닫히면 지운다 [2][3].
서버를 켤 때 이미 열린 케이스가 있으면 그 케이스로 질의 서비스를 만든다 [2].
`dispatchToolCall`은 질의 서비스가 없으면 도구를 실행하지 않고 `No case is currently open in Autopsy`로 오류 `-32603`을 돌려준다 [1].
`get_server_status`는 케이스와 상관없이 서버 상태와 케이스 열림 여부를 돌려준다 [1][4].
`get_case_summary`는 케이스가 없으면 오류가 아니라 `message` 필드를 담은 정상 응답을 돌려준다 [1].
`tools/list`는 케이스가 없어도 도구 정의 18개를 모두 돌려준다 [5].
케이스를 닫을 때 Autopsy는 `CURRENT_CASE` 이벤트를 구독자에게 차례로 직접 전달한 뒤 케이스 자원을 닫는다 [6][7].
그래서 질의 서비스는 케이스 DB를 닫기 전에 지워진다.

**한계.** 이 확인은 호출이 시작될 때 한 번만 이루어진다 [1].
질의 서비스를 지역 변수로 받은 뒤 케이스가 닫히면 진행 중인 호출은 닫히는 케이스의 `SleuthkitCase`로 계속 조회한다 [1][6].
이때 호출이 어떤 결과나 오류를 돌려주는지는 확인하지 못했다.

### T03.08 원격 호출자 인증

**구현.** 이 방식은 Java HTTP 서버의 모든 요청에 적용된다 [8].
MCP 서버는 기본으로 꺼져 있고 사용자가 Autopsy 옵션 창에서 켜야 HTTP 서버와 이 검사가 시작된다 [9].
옵션 창은 사용 설정 상자를 Windows에서만 보여 주지만 Autopsy 시작 경로는 운영체제를 확인하지 않고 저장된 설정만 본다 [9][10].
STDIO 래퍼와 MCP 클라이언트 사이의 stdio 연결에는 이 검사가 없다.
HTTP 서버는 Javalin으로 `127.0.0.1`의 포트(기본 8743)에만 열린다 [8].
포트는 `mcp-config.properties`의 `port` 값이고 파일이 없으면 기본 포트로 그 파일을 만들며 값을 읽지 못하면 기본 포트를 쓴다 [11].
경로를 정하지 않은 `before` 필터는 모든 요청 경로에 적용되고 `Authorization` 헤더가 `Bearer <토큰>`과 다르면 401과 `Unauthorized`를 돌려준 뒤 `skipRemainingHandlers()`를 부른다 [8][12].
Javalin 7.1.0의 `skipRemainingHandlers()`는 요청의 남은 작업 목록을 비우고 `before` 작업 뒤에 오는 `POST /mcp` 처리기도 그 목록에 들어 있으므로 실행되지 않는다 [13].
헤더 비교는 `String.equals`로 한다 [8].
토큰은 `SecureRandom`의 32바이트를 패딩 없는 URL용 Base64로 바꾼 값이고 `McpServer`를 만들 때 하나 생긴다 [14].
`McpServer`는 Autopsy가 시작될 때 MCP 설정이 켜져 있거나 사용자가 옵션 창에서 MCP를 켤 때 만들어진다 [10].
서버는 포트를 연 뒤 토큰을 `%LOCALAPPDATA%\autopsy\mcp\mcp-token`에 쓰고 쓰지 못하면 HTTP 서버를 멈추고 시작을 실패로 끝낸다 [8][14].
토큰은 케이스를 열고 닫아도 바뀌지 않는다 [15].
사용자가 옵션 창에서 MCP를 끄면 `stop()`이 HTTP 서버를 멈추고 토큰 파일을 지우며 JVM이 끝날 때도 `deleteOnExit`로 파일을 지운다 [14][16].
코드는 토큰 파일의 접근 권한을 따로 정하지 않는다 [14].
래퍼의 `--test`는 토큰 파일을 읽으면 토큰의 앞 8자를 표준 출력에 출력한다 [17][18].
STDIO 래퍼는 호출할 때마다 이 파일을 다시 읽어 `Authorization` 헤더에 싣는다 [19].
래퍼는 이 헤더를 `127.0.0.1`의 설정한 포트에서 응답하는 프로세스에 보낸다 [19][20].
래퍼의 `callJava`에는 그 프로세스가 토큰 파일을 쓴 Autopsy인지 확인하는 코드가 없다 [19][20].

**한계.** 래퍼의 README는 케이스를 닫으면 토큰 파일이 지워진다고 적고 401이 나면 케이스를 다시 열어 새 토큰을 만들라고 안내한다 [21].
코드는 케이스를 닫을 때 토큰 파일을 지우지 않고 케이스를 다시 열어도 토큰을 새로 만들지 않는다 [15][3].
JVM이 정상 종료 없이 끝나면 `deleteOnExit`가 실행되지 않아 이전 토큰이 들어 있는 파일이 남는다 [14].
래퍼의 `--test`도 토큰 파일이 없으면 케이스를 먼저 열라고 안내한다 [17].
`--test`는 401 응답을 받으면 케이스를 다시 열라고 안내한다 [17].
래퍼 README는 HTTP 서버 포트를 8765로 적지만 코드의 기본 포트는 8743이다 [21][11].
사용자 문서는 MCP 서버를 켜려면 Autopsy를 다시 시작해야 한다고 적는다 [22].
코드는 옵션 창에서 설정을 바꾸면 `store()`가 곧바로 `enableServer()`나 `disableServer()`를 부른다 [23][10].
포트 설정 파일의 주석은 포트를 고친 뒤 Autopsy를 다시 시작하라고 적지만 옵션 창에서 MCP를 껐다 켜면 새 `McpServer`가 설정 파일의 포트를 다시 읽는다 [11][10].
