# T04 실행 방식

### T04.01 서버 프로세스 안 분석

**구현.** 이 방식은 `get_server_status`를 뺀 도구 17개에 적용된다 [1].
도구의 처리는 Autopsy 프로세스 안의 Java HTTP 서버에서 Sleuth Kit Java 바인딩을 불러 수행한다 [1][2].
`AutopsyMcpModule`은 NetBeans 모듈의 `@OnStart`로 Autopsy가 시작될 때 실행되고 Javalin HTTP 서버도 Autopsy JVM 안에서 열린다 [3][4].
`TskQueryService`는 열린 케이스의 `SleuthkitCase`로 케이스 DB를 조회한다 [1][2].
`get_file_content`가 부르는 Sleuth Kit 4.15.0의 `read`는 수집 저장소 파일이고 케이스에 내용 제공자가 등록되어 있으면 그 제공자의 스트림을 읽는다 [5].
그 밖에 `read`는 로컬 경로가 있는 파일이면 `RandomAccessFile`을 읽기 모드 `"r"`로 열어 읽고 파일시스템 안의 파일이면 JNI 함수 `SleuthkitJNI.readFile`로 이미지에서 읽는다 [5][6].
`get_report_content`가 부르는 `Report.read`는 보고서 파일을 `FileChannel`의 읽기 모드로 연다 [7].
MCP 패키지와 STDIO 래퍼에는 외부 프로그램을 실행하는 코드가 없다 [8].
그래서 도구 처리는 Autopsy 프로세스의 계정, 메모리, 파일 권한을 함께 쓴다.

STDIO 래퍼는 MCP 클라이언트가 실행하는 별도 Node.js 프로세스이고 분석을 하지 않는다 [9].
래퍼는 `tools/list`·`tools/call` 요청을 `http://127.0.0.1:<포트>/mcp`에 넘긴다 [9].
`tools/list`는 받은 도구 목록을 그대로 돌려주고 `tools/call`은 받은 결과를 JSON 글로 바꿔 돌려준다 [10].

server.setRequestHandler(CallToolRequestSchema, async (request) => {
    const toolName = request.params.name;
    log("INFO", `tools/call ${toolName}`);
    try {
        const result = await callJava("tools/call", {
            name: toolName,
            arguments: request.params.arguments ?? {}
        });
        return {
            content: [{ type: "text", text: JSON.stringify(result, null, 2) }]
        };
    } catch (err) {
        log("ERROR", `tools/call ${toolName} failed: ${err.message}`);
        return {
            content: [{ type: "text", text: `Autopsy is not reachable: ${err.message}` }],
            isError: true
        };
    }
});
