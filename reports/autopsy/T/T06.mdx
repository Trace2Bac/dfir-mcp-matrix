# T06 실행 환경정보 표시

### 미구현

**판단.** 서버는 Sleuth Kit Java 바인딩으로 케이스 DB를 조회하고 파일·보고서 내용을 읽어 결과를 만들지만 응답에 그 라이브러리나 결과를 만든 모듈의 버전을 싣지 않는다 [1].
분석 결과 항목은 객체 ID, 원본 파일 ID, 아티팩트 유형, 데이터 소스 ID, 점수, 속성만 담는다 [2].
결과를 케이스 DB에 쓴 ingest 모듈의 이름이나 버전은 이 항목에 없다 [2].
`list_reports`는 보고서마다 보고서 모듈 이름 `sourceModule`을 싣지만 그 모듈의 버전은 싣지 않는다 [3].
`query_data_sources`가 돌려주는 `acquisitionToolName`·`acquisitionToolVersion`은 디스크 이미지를 획득한 도구의 이름과 버전이고 케이스 DB에 저장된 값을 그대로 옮긴 것이다 [4].
이 값은 서버가 결과를 내는 데 쓴 도구의 버전이 아니다.

서버의 상태를 묻는 `get_server_status`도 서버 이름, 실행 상태, 케이스 열림 여부, 케이스 이름만 돌려주고 버전을 싣지 않는다 [5].
STDIO 래퍼는 초기화 응답의 `serverInfo`에 이름 `autopsy`와 버전 `1.0.0`을 싣는다 [6].
Java 쪽 `initialize` 처리도 `serverInfo`에 `1.0.0`을 적지만 MCP 클라이언트는 래퍼만 실행하므로 이 응답을 받지 않는다 [7].
서버는 MCP 도구 호출을 기록하지 않고 래퍼의 `mcp-stdio.log`에는 오류 줄만 남는다 [8].
서버는 파생물을 만들지 않고 모델을 부르지 않는다.

function log(level, message) {
    // Only ERROR level is persisted to disk. INFO/DEBUG calls are no-ops
    // by design — they would be too noisy in production and are visible
    // during development via a debugger or by temporarily removing this guard.
    if (level !== "ERROR") return;
    try {
        // Rotate if the log has grown too large
        try {
            if (fs.statSync(LOG_PATH).size > MAX_LOG_BYTES) {
                fs.renameSync(LOG_PATH, LOG_PATH + ".1");
            }
        } catch { /* file doesn't exist yet — that's fine */ }

        const line = `${new Date().toISOString()} [${level}] ${message}\n`;
        fs.appendFileSync(LOG_PATH, line, "utf8");
    } catch { /* never let logging crash the process */ }
}
