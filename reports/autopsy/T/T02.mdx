# T02 실행 허용 범위 제한

### T02.04 고정 명령·템플릿

**구현.** 이 방식은 Java HTTP 서버의 도구 호출 처리에 적용된다 [1].
`dispatchToolCall`은 `get_server_status`를 먼저 처리하고 나머지 17개 이름을 `switch`로 처리한다 [1][2].
사건이 열려 있으면 목록에 없는 이름은 `Unknown tool` 오류 `-32601`로 거부된다 [1].
사건이 열려 있지 않으면 이름을 보기 전에 사건이 없다는 오류 `-32603`을 돌려주므로 목록에 없는 이름도 같은 오류를 받는다 [3].
`get_server_status`는 Sleuth Kit을 부르지 않고 서버 상태 값을 만든다 [2].
나머지 17개 도구는 이름마다 부르는 Sleuth Kit API가 코드에 정해져 있다 [1].
STDIO 래퍼는 도구 이름을 가리지 않고 넘기므로 이 거부는 Java 쪽에서 일어난다 [4].
모델은 SQL이나 질의문을 보내지 못하고 정해 둔 인자의 값만 채운다.
`query_files`는 인자마다 정해 둔 조건 틀(`LOWER(name) LIKE '%…%'`, `size >= …` 등)을 `AND`로 이어 WHERE 절을 만들고 `findAllFilesWhere`에 넘긴다 [5].
Sleuth Kit 4.15.0의 `findAllFilesWhere`는 그 절을 `SELECT * FROM tsk_files WHERE ` 뒤에 붙여 실행한다 [6].
문자열 값은 `escapeSql`로 작은따옴표를 두 번 써서 따옴표 안에 넣고 숫자 값은 Jackson이 `long`으로 바꾼 값을 넣는다 [5][7].
정렬은 `orderBy`의 8개 값마다 정해 둔 `ORDER BY` 구문만 붙인다 [8].
`query_data_artifacts`·`query_analysis_results`는 유형 ID와 데이터 소스 ID 조건만 만들어 `getDataArtifactsWhere`·`getAnalysisResultsWhere`에 넘기고 속성 조건은 받은 결과를 Java에서 걸러 적용한다 [9].
타임라인 도구는 `TimelineFilter`의 데이터 소스·문자열 필터 객체를 만들어 `TimelineManager`에 넘긴다 [10].
나머지 도구는 정해진 조회 메서드를 부르고 받은 값을 객체 ID·데이터 소스 ID로 조회하는 데 쓰거나 `tagName`·`accountType`·`accountId`처럼 조회 결과를 거르는 데 쓴다 [11].

**한계.** `nameContains`·`pathContains`의 값과 `mimeType`의 앞부분은 `LIKE` 패턴에 그대로 들어가므로 값 안의 `%`·`_`가 와일드카드로 해석된다 [5].
그래서 `nameContains`에 `%`를 주면 이름 조건이 모든 파일과 일치한다 [5].
도구 설명은 이 인자를 부분 문자열 필터로 적는다 [12].
`query_timeline`의 `textFilter`도 같다 [13][14].
Sleuth Kit 4.15.0의 `TextFilter`는 값의 작은따옴표만 두 번 써서 `like '%…%'` 조건에 넣으므로 `%`·`_`가 와일드카드로 해석된다 [13].
도구 설명은 `textFilter`를 이벤트 설명에 그 문자열이 들어 있는지 거르는 필터로 적는다 [14].
`query_files`의 이름·경로 조건은 `LOWER`로 대소문자를 맞추지만 `TextFilter`의 `like` 조건은 대소문자를 맞추지 않는다 [5][13].
SQLite의 `LIKE`는 ASCII 글자의 대소문자를 구별하지 않고 PostgreSQL의 `LIKE`는 구별하므로 같은 `textFilter` 값이 사건 DB 종류에 따라 다른 이벤트를 고른다 [15].
