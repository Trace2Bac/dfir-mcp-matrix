# T01 입력 검증

### T01.01 인자 구조·값 검사

**구현.** 이 방식은 Java HTTP 서버의 `TskQueryService`가 도구 인자를 읽는 단계에 적용된다 [1].
STDIO 래퍼가 쓰는 MCP TypeScript SDK 1.27.1은 도구 호출 처리기를 부르기 전에 요청 구조를 검사한다 [2].
`name`이 문자열이 아니거나 `arguments`가 객체가 아니면 SDK가 처리기를 부르지 않고 JSON-RPC 오류 `-32603`을 돌려준다 [2][3].
이 검사를 통과한 `arguments`는 래퍼가 값을 검사하지 않고 그대로 HTTP 요청에 싣는다 [4].
결과 수 인자 `limit`은 0 이하이거나 도구별 최댓값을 넘으면 최댓값이 아니라 기본값으로 바뀐다 [1].
`query_files`·`query_data_artifacts`·`query_analysis_results`는 최댓값 500·기본값 50, `query_timeline`은 1,000·100, `get_communications_accounts`는 500·100이다 [1].
`get_file_content`·`get_report_content`의 `maxBytes`는 0 이하이거나 1,048,576을 넘으면 65,536으로 바뀌고 음수 `offset`은 0으로 바뀐다 [5].
`orderBy`는 정해 둔 8개 값만 정렬 구문으로 바꾸고 다른 값이면 정렬하지 않는다 [6].
`knownState`는 `UNKNOWN`·`KNOWN`·`NOTABLE`·`BAD`만 조건으로 바꾼다 [7].
`get_communications_accounts`의 `accountType`은 코드에 적은 20개 계정 유형만 조건으로 바꾼다 [8].
`get_account_relationships`의 `accountType`은 목록과 대조하지 않고 계정 유형 이름과 대소문자 구별 없이 비교한다 [9].
`artifactType`은 케이스 DB의 `blackboard_artifact_types`에서 같은 이름의 유형을 찾아 그 ID로 조건을 만든다 [10][11].
문자열 인자는 `textOrNull`이 앞뒤 공백을 지우고 빈 문자열을 인자가 없는 것으로 본다 [12].
기간 인자는 `parseTimeArg`가 `Instant.parse`로 바꾸고 길이가 10인 문자열에는 시작 경계면 `T00:00:00Z`, 끝 경계면 `T23:59:59Z`를 붙인다 [13].
`Instant.parse`가 해석하지 못한 문자열은 예외를 내고 그 호출은 조건 질의 전에 JSON-RPC 오류 `-32603`으로 끝난다 [13][14].
필수 인자는 도구마다 따로 확인한다.
`get_account_relationships`는 `accountId`나 `accountType`이 없으면, `get_object_children`·`get_report_content`는 `objectId`가 없으면 `McpException`으로 오류 `-32602`를 돌려준다 [15][16].
`get_file_content`는 `objectId`가 없거나 음수이면 `TskCoreException`을 내고 이 호출은 오류 `-32603`으로 끝난다 [17][14].
이 오류 코드는 Java HTTP 응답의 값이다.
STDIO 래퍼는 Java 오류의 `code`를 버리고 `message`만 담은 `isError` 글로 바꾸므로 MCP 클라이언트는 Java 쪽이 정한 오류 코드를 받지 않는다 [18].
문자열 필터 값은 형식을 검사하지 않고 작은따옴표만 두 번 써서 SQL 조건에 넣는다 [19].

**한계.** 입력 schema에 없는 인자 이름은 거부하지 않고 읽지 않은 채 둔다 [20].
`arguments`가 없는 호출도 거부하지 않고 모든 인자를 기본값으로 처리해 실행한다 [20].
숫자·논리값 인자는 Jackson의 변환 함수로 읽으므로 자료형이 다른 값도 거부하지 않는다 [21].
숫자로 읽히지 않는 문자열은 `asLong()`에서 0이 되고 `asInt(기본값)`·`asLong(기본값)`에서 기본값이 된다 [21].
예를 들어 `minSize`에 숫자가 아닌 문자열을 주면 `size >= 0` 조건이 만들어진다 [21][22].
`"true"`가 아닌 문자열을 받은 `isDirectory`·`allocated`는 `false`가 되어 반대 조건이 적용된다 [21][22].
`knownState`·`accountType`·`orderBy`가 정해 둔 값이 아니면 서버는 거부하지 않고 그 조건을 빼고 질의하며 응답에 조건을 뺐다는 표시를 하지 않는다 [6][7][8].
`get_communications_accounts`가 응답에 싣는 계정 유형은 표시 이름이다 [23].
그래서 그 값 가운데 `Credit Card`·`MessagingApp`을 이 도구의 `accountType`에 다시 넘기면 대조 목록의 이름과 맞지 않아 필터가 알림 없이 빠진다 [8][23][24].
문자열 인자에 객체나 배열을 주면 `textOrNull`이 부르는 `asText()`가 빈 문자열을 돌려주므로 대부분의 필터는 알림 없이 빠진다 [12][25].
`query_files`의 기간 인자 `modifiedAfter`·`modifiedBefore`·`createdAfter`·`createdBefore`는 다르게 처리된다 [26].
이 인자들은 인자가 있는지만 보고 `parseTimeArg`에 대체값 0을 넘기므로 빈 문자열, `null`, 객체, 배열을 받으면 필터가 빠지지 않고 0을 기준으로 한 조건이 된다 [26][13].
그래서 `*Before`는 시각이 0 이하인 파일만 고르고 `*After`는 시각이 0 이상인 모든 파일을 고른다 [26].
기간의 시작이 끝보다 늦어도 서버는 거부하지 않고 도구마다 다른 결과를 낸다 [27].
`query_timeline`은 Joda-Time 2.13.0의 `Interval`을 만들다 예외가 나 오류 `-32603`으로 끝나고 `summarize_timeline`은 0건을, `query_files`는 빈 목록을 돌려준다 [27][28].
`artifactType`이 케이스 DB에 없는 이름이면 Sleuth Kit 4.15.0의 `getArtifactType`이 `null`을 돌려준다 [11].
코드는 이 경우에 빈 목록을 돌려주려고 `TskCoreException`만 처리하므로 실제로는 `null`의 메서드를 부르다 실패해 오류 `-32603`이 된다 [10][14].
`get_object_children`·`get_report_content`는 `objectId`가 빠졌는지만 보므로 `null`이나 숫자가 아닌 문자열을 받으면 0번 객체를 찾는다 [16][21].

### T01.02 입력 존재·읽기 가능 검사

**구현.** 이 방식은 객체 ID를 받는 `get_object_children`에 적용된다 [16].
`objectId`는 케이스 DB의 객체 ID이고 그 객체는 Autopsy 본체가 추가한 데이터 소스와 보고서, ingest 모듈이 남긴 파생물과 아티팩트 등이다 [29].
MCP에는 객체를 등록하는 도구가 없고 서버가 따로 두는 ID 목록도 없다.
`get_object_children`은 `getContentById`가 `null`을 돌려주면 자식 객체를 조회하기 전에 `No object found with id`로 거부한다 [16].

객체 ID를 받는 다른 두 도구에는 이 검사가 없다.
`get_report_content`의 코드에는 `report == null` 확인이 있다 [16].
그러나 Sleuth Kit 4.15.0의 `getReportById`는 `reports` 표에 그 ID가 없으면 `null`을 돌려주지 않고 `No report found for id`로 `TskCoreException`을 낸다 [30].
그래서 그 확인은 실행되지 않고 이 호출은 오류 `-32603`으로 끝난다 [16][14].
`get_file_content`는 `getAbstractFileById`가 돌려준 값을 확인하지 않는다 [17].
Sleuth Kit은 `tsk_files`에 그 ID가 없으면 `null`을 돌려주고 서버는 그 값의 크기를 읽다 실패해 오류 `-32603`을 돌려준다 [17][31][14].
이때 오류 문구는 없는 ID라는 안내가 아니라 `NullPointerException`의 글이고 JRE 15부터 기본으로 켜진 자세한 NPE 글에는 `null`이었던 식이 적힌다 [32].
`get_account_relationships`는 받은 `accountType`·`accountId`와 같은 계정을 관계가 있는 계정 목록에서 찾고 없으면 관계를 조회하지 않고 `error` 필드를 담은 정상 응답을 돌려준다 [9].
데이터 소스를 고르는 `dataSourceId`는 있는지 확인하지 않는다 [33].
없는 ID를 받으면 `query_data_artifacts`·`query_analysis_results`·`query_timeline`·`summarize_timeline`은 빈 결과나 0건을 돌려주고 `get_data_source_tree`는 빈 목록을 돌려준다 [33].
음수 `dataSourceId`는 필터가 없는 것으로 처리되어 `query_data_artifacts`·`query_analysis_results`·`get_data_source_tree`가 모든 데이터 소스의 결과를 돌려준다 [33][34].

### T01.06 고정 입력 경로 사용

**구현.** 이 방식은 모든 도구에 적용된다.
모델은 파일 경로를 넘기지 않고 도구는 지금 열린 케이스의 `SleuthkitCase` 하나로만 조회한다 [35].
`get_file_content`는 `objectId`로 찾은 `AbstractFile`의 `read`로 내용을 읽는다 [17].
Sleuth Kit 4.15.0의 `AbstractFile.read`는 읽는 곳을 셋 가운데 하나로 고른다 [36].
수집 저장소에 있는 파일이고 케이스에 내용 제공자가 등록되어 있으면 그 제공자의 스트림을 읽는다 [36].
로컬 경로가 등록된 파일이면 그 경로를 읽고 그 밖에는 데이터 소스 이미지에서 읽는다 [36].
`get_report_content`는 `reports` 표의 `path`를 케이스 DB 폴더와 이은 경로의 파일을 읽는다 [30].
이 경로들은 Autopsy 본체가 데이터 소스와 보고서를 케이스에 추가하거나 ingest 모듈이 파생물을 만들 때 정하고 MCP 도구는 바꾸지 않는다.

        if (s == null) {
