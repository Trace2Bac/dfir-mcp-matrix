# T05 분석 도구 검증

### T05.01 저장소·의존성 고정

**구현.** 이 방식은 도구가 케이스 DB를 조회하고 파일 내용을 읽을 때 쓰는 Sleuth Kit Java 바인딩에 적용된다 [1].
저장소의 `TSKVersion.xml`은 `TSK_VERSION`을 4.15.0으로 정한다 [1].
`Core/nbproject/project.properties`는 Core 모듈이 `sleuthkit-4.15.0.jar`를 참조하도록 적는다 [2].
Core의 빌드는 환경변수 `TSK_HOME`이 가리키는 Sleuth Kit 폴더의 `bindings/java/dist/sleuthkit-${TSK_VERSION}.jar`를 모듈의 `ext` 폴더로 복사한다 [3].
설치본 Autopsy 4.23.1의 `autopsy/modules/ext`에는 `sleuthkit-4.15.0.jar`가 있다 [4].
Javalin, Jackson, MCP TypeScript SDK는 증거를 해석하지 않는 서버 실행용 라이브러리라 이 방식으로 세지 않는다.
서버는 실행 중에 Sleuth Kit의 버전이나 케이스 DB의 스키마 버전을 읽지 않는다.
도구가 조회하는 파일 정보, 아티팩트, 분석 결과는 Autopsy 본체의 ingest 모듈이 케이스 DB에 미리 쓴 값이고 서버는 그 값을 만든 모듈의 버전을 확인하지 않는다.

**한계.** 저장소는 Sleuth Kit의 버전 번호만 정하고 JAR을 만든 소스 커밋이나 JAR의 해시는 정하지 않는다 [1][3].
빌드는 사용자가 `TSK_HOME`에 준비한 Sleuth Kit 빌드 결과를 복사한다 [3].
저장소의 Windows 빌드 작업은 Sleuth Kit을 태그가 아니라 브랜치 `develop-4.1x`에서 받아 빌드한다 [5].
설치본의 `sleuthkit-4.15.0.jar`가 어느 Sleuth Kit 커밋에서 만들어졌는지는 확인하지 못했다 [4].

### 근거

[1] 저장소가 정한 Sleuth Kit 버전이다.

```text
<project name="TSK_VERSION">
    <property name="TSK_VERSION" value="4.15.0"/>
</project>
```

[`TSKVersion.xml:1-3`](https://github.com/sleuthkit/autopsy/blob/cb3dacdcad67abe7cf863c74f10dcdb8e25a5c21/TSKVersion.xml#L1-L3)

[2] Core 모듈이 참조하는 Sleuth Kit JAR이다.

```text
file.reference.sleuthkit-4.15.0.jar=release/modules/ext/sleuthkit-4.15.0.jar
file.reference.sleuthkit-caseuco-4.15.0.jar=release/modules/ext/sleuthkit-caseuco-4.15.0.jar
```

[`Core/nbproject/project.properties:96-97`](https://github.com/sleuthkit/autopsy/blob/cb3dacdcad67abe7cf863c74f10dcdb8e25a5c21/Core/nbproject/project.properties#L96-L97)

[3] 빌드는 `TSK_HOME`의 JAR을 복사한다.

```text
    <!-- Verify that the TSK_HOME env variable is set -->
    <target name="findTSK">
        <property environment="env"/>
        <condition property="tskFound">
            <isset property="env.TSK_HOME"/>
        </condition>
        <fail unless="tskFound" message="TSK_HOME must be set as an environment variable."/>
        <echo> TSK_HOME: ${env.TSK_HOME}</echo>
    </target>  
    
    <target name="getTSKJars" depends="findTSK">
        <property environment="env"/>
        <copy file="${env.TSK_HOME}/bindings/java/dist/sleuthkit-${TSK_VERSION}.jar" 
              tofile="${ext.dir}/sleuthkit-${TSK_VERSION}.jar"/>
        <copy file="${env.TSK_HOME}/bindings/java/lib/sqlite-jdbc-3.49.1.0.jar"
              tofile="${ext.dir}/sqlite-jdbc-3.49.1.0.jar"/>
		<copy file="${env.TSK_HOME}/bindings/java/lib/postgresql-42.7.5.jar" 
              tofile="${ext.dir}/postgresql-42.7.5.jar"/>
        <copy file="${env.TSK_HOME}/bindings/java/lib/c3p0-0.12.0.jar"
              tofile="${ext.dir}/c3p0-0.12.0.jar"/>
        <copy file="${env.TSK_HOME}/bindings/java/lib/mchange-commons-java-0.4.0.jar"
              tofile="${ext.dir}/mchange-commons-java-0.4.0.jar"/>
        <copy file="${env.TSK_HOME}/bindings/java/lib/SparseBitSet-1.3.jar"
              tofile="${ext.dir}/SparseBitSet-1.3.jar"/>	
        <copy file="${env.TSK_HOME}/case-uco/java/dist/sleuthkit-caseuco-${TSK_VERSION}.jar" 
              tofile="${ext.dir}/sleuthkit-caseuco-${TSK_VERSION}.jar"/>  
    </target>
```

[`Core/build.xml:121-147`](https://github.com/sleuthkit/autopsy/blob/cb3dacdcad67abe7cf863c74f10dcdb8e25a5c21/Core/build.xml#L121-L147)

[4] (실행 확인) 설치본 Autopsy 4.23.1의 `autopsy/modules/ext` 폴더 목록에 `sleuthkit-4.15.0.jar`가 있다.

[5] Windows 빌드 작업은 Sleuth Kit 브랜치를 받는다.

```yaml
      - name: Clone SleuthKit
        run: |
          git clone --branch develop-4.1x https://github.com/sleuthkit/sleuthkit "${{ github.workspace }}\sleuthkit"
```
