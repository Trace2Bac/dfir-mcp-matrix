# F01 판단 지침

### 미구현

**판단.** 서버는 도구 설명, 서버 지침, 리소스, 응답 어디에도 조사 전체의 해석 원칙이나 발견사항·결론을 서술하고 확인하는 방식을 적지 않는다.
STDIO 래퍼는 MCP SDK `Server`를 이름·버전과 `tools` 기능만으로 만들고 서버 지침(`instructions`)을 넘기지 않는다 [1].
래퍼가 등록한 요청 처리기는 `tools/list`와 `tools/call`뿐이어서 리소스와 프롬프트가 없다 [2].
Java 쪽 `initialize` 응답도 `protocolVersion`, `serverInfo`, `capabilities`만 담는다 [3].

도구 설명에 실린 안내는 다음 세 종류이고 어느 것도 발견사항이나 결론의 서술·확인을 다루지 않는다.

- `get_server_status`는 이 도구를 먼저 부르라고 적고 `query_timeline`·`summarize_timeline`은 기간별 분류 수를 먼저 보라고 적는다 [4][5].
- `query_analysis_results`는 분석 결과가 ingest 모듈이 내린 결론이고 `score`가 얼마나 눈여겨볼 항목인지를 나타낸다고 적는다 [6].
- `get_server_status`를 뺀 17개 도구의 설명 끝에는 응답의 `caseId`가 열린 사건을 가리키며 호출 사이에 바뀌면 사용자에게 알리라는 `CASE_ID_NOTE`가 붙는다 [7].

첫째는 다음에 부를 도구를 권하는 문구이고 둘째는 그 도구 결과의 뜻을 설명하는 문구이며 셋째는 응답이 어느 사건의 것인지 알리는 문구다 [4][6][7].

`get_server_status`를 뺀 도구 응답은 `caseId`와 `result`만 담고 `get_server_status`는 서버 상태 값만 담는다 [8][9].
어느 응답에도 도구와 관계없이 공통으로 붙는 안내 문구는 없다 [8][9].
