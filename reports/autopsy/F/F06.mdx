# F06 보고 산출물 구성

### 미구현

**판단.** 서버는 열린 케이스를 단위로 자료를 다루지만 보고 산출물을 만들거나 내보내는 도구가 없다.
`get_server_status`를 뺀 도구 응답은 열린 케이스의 표시 이름을 `caseId`로 붙여 돌려준다 [1][2].
케이스가 열려 있지 않을 때 `get_case_summary`의 `caseId`는 `null`이다 [2].
도구 18개 가운데 보고서를 다루는 것은 `list_reports`와 `get_report_content`이고 둘 다 이미 만들어진 보고서를 읽는다 [3].
`list_reports`는 Sleuth Kit `getAllReports`로 케이스 DB에 등록된 보고서의 이름, 만든 모듈, 경로, 크기를 돌려준다 [4].
`get_report_content`는 `getReportById`로 찾은 보고서 파일을 `Report.read`로 읽어 글로 돌려준다 [5].
Sleuth Kit의 `getReportById`는 보고서 경로를 케이스 DB 폴더 기준으로 만들고 `Report.read`는 그 파일을 읽기 모드로 연다 [6][7].
이 보고서는 Autopsy 본체가 `Case.addReport`로 케이스 DB에 등록한 것이다 [8].
서버의 도구 처리에는 보고서를 만들거나 등록하는 호출이 없다 [3][5].
도구 응답을 정한 코드로 가공해 파일로 남기는 사용자 CLI나 클라이언트 코드도 저장소에 없다 [9].

    public Report addReport(String localPath, String srcModuleName, String reportName, Content parent) throws TskCoreException {
        String normalizedLocalPath;
        try {
            if (localPath.toLowerCase().contains("http:")) {
                normalizedLocalPath = localPath;
            } else {
                normalizedLocalPath = Paths.get(localPath).normalize().toString();
            }
        } catch (InvalidPathException ex) {
            String errorMsg = "Invalid local path provided: " + localPath; // NON-NLS
            throw new TskCoreException(errorMsg, ex);
        }
        hasData = true;

        Report report = this.caseDb.addReport(normalizedLocalPath, srcModuleName, reportName, parent);
        eventPublisher.publish(new ReportAddedEvent(report));
        return report;
    }
