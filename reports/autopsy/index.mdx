# autopsy 원고

이 파일은 서버 개요다. 셀마다 이 폴더 아래 축 폴더의 `<축>/<셀ID>.mdx`에 쓴다.
셀과 상세 항목의 정의는 `matrix/cells/<축>/<셀ID>.mdx`를 따른다.
상세 항목마다 **구현**을 쓰고 그 방식이 적용되지 않는 경로나 조건이 있으면 **한계**를 따로 쓴다.
본문의 [번호]는 그 파일 끝 **근거**의 같은 번호를 가리킨다.

**기준 커밋.** [`cb3dacd`](https://github.com/sleuthkit/autopsy/tree/cb3dacdcad67abe7cf863c74f10dcdb8e25a5c21)(2026-05-04).
줄 번호는 모두 이 커밋 기준이다.
릴리스 태그 `autopsy-4.23.1`(`bbf4002`)은 이 커밋 뒤 2커밋이고, 그 사이에 바뀐 파일은 `NEWS.txt`, Doxygen 설정 2개, `nbproject/project.properties`의 버전 값뿐이다.

**범위.** Autopsy 데스크톱 프로그램에 붙은 MCP 연동 기능을 본다.
서버는 두 프로그램으로 이루어진다.

- Autopsy 프로세스 안의 HTTP 서버: `Core/src/org/sleuthkit/autopsy/mcp/`의 Java 코드다. `127.0.0.1`의 `POST /mcp`에서 JSON-RPC 요청을 받고, 도구 정의와 18개 도구의 처리를 모두 이곳에 둔다.
- STDIO 래퍼: `Tools/autopsy-mcp-stdio/autopsy-mcp-stdio.js`다. MCP TypeScript SDK의 `Server`로 stdio MCP 서버를 열고 `tools/list`·`tools/call`을 Autopsy HTTP 서버에 그대로 넘긴다. 도구 정의는 두지 않는다.

MCP 클라이언트가 실행하는 것은 STDIO 래퍼이고, 래퍼는 `initialize`를 스스로 처리하며 Java 쪽 `initialize` 처리는 부르지 않는다.
두 프로그램과 Autopsy 옵션 창의 MCP 설정 화면(`McpOptionsPanel`)을 서버 구현으로 센다.
MCP 서버는 기본으로 꺼져 있고 사용자가 옵션 창에서 켠다.
옵션 창의 사용 설정 상자는 Windows에서만 보이고 다른 운영체제에서는 Windows에서만 지원한다는 글이 대신 보인다.
옵션 창이 보여 주는 Claude 설정 조각과 사용자가 고치는 `claude_desktop_config.json`은 클라이언트 구성이다.

케이스 열기·닫기, 데이터 소스 추가, ingest 모듈 실행, 보고서 생성은 Autopsy 본체가 하는 일이고 MCP 도구가 실행하지 않는다.
MCP 도구는 본체가 케이스 DB에 이미 쓴 파일 정보, 아티팩트, 분석 결과, 태그, 타임라인 사건, 보고서 목록을 조회하고 파일·보고서 내용을 읽는다.
그래서 해시 값, 분석 결과의 점수, 보고서는 본체가 만든 값을 그대로 전달한 것으로 적고 MCP의 계산·판정·생성으로 세지 않는다.
본체 코드는 MCP가 부르는 부분(`Case`의 케이스 이벤트, `coreutils/Logger`)만 확인했다.

**확인 방법.** 코드는 기준 커밋을 `git show`로 읽었다.
Sleuth Kit Java 바인딩은 아래 버전 기준의 태그를 `git show`로 읽었다.
근거의 "실행 확인"은 Windows 11에서 설치본 Autopsy 4.23.1의 `bin/autopsy-mcp-stdio.exe`와, 기준 커밋의 `autopsy-mcp-stdio.js`를 Node.js 24.21.0과 잠금 파일의 의존성으로 실행해 본 결과다.
Autopsy의 Java HTTP 서버는 실행하지 않았고, 그 자리에 Java 코드의 응답 형태(`{"caseId": …, "result": …}`, JSON-RPC 오류, HTTP 401·500)를 흉내 낸 Python HTTP 서버를 두었다.
`LOCALAPPDATA`를 임시 폴더로 바꿔 래퍼가 그 폴더의 `autopsy/mcp/mcp-token`과 `mcp-config.properties`를 읽게 했다.
확인한 것은 다음과 같다.

- 토큰 파일이 없을 때 `tools/list`와 `tools/call`의 응답, `--test`의 출력과 종료 코드
- 토큰이 맞지 않을 때(HTTP 401), HTTP 500, JSON-RPC 오류 응답을 받은 `tools/call`의 응답
- 도구 호출 인자가 바뀌지 않고 HTTP 요청에 실리는지와, 요청 `id`가 늘 `"1"`인지
- `mcp-stdio.log`에 남는 줄
- `mcp-stdio.log`가 1MB를 넘은 상태에서 이미 `mcp-stdio.log.1`이 있을 때 이름 바꾸기로 앞선 `.1`이 대체되는지
- `mcp-stdio.log` 자리에 폴더를 두어 기록 쓰기가 실패할 때 도구 호출 응답과 표준 오류 출력
- 응답이 33초·75초 늦는 호출에서 30초 시간 제한이 적용되는지(실행 파일과 Node.js 24로 각각)
- 도구 18개 이상을 돌려주는 HTTP 서버를 상대로 한 `--test`의 케이스 확인 줄
- 설치본 `autopsy/modules/ext` 폴더에 있는 `javalin-7.1.0.jar`, `jackson-databind-2.18.2.jar`, `sleuthkit-4.15.0.jar`
- 실행 파일에 기준 커밋 래퍼 소스의 문자열(오류 문구, `CALL_TIMEOUT_MS = 3e4`, `tools.length < 15`)이 들어 있는지
- 래퍼 소스(Node.js 24)에 `name`이 없거나 `arguments`가 배열이거나 `task`가 붙은 `tools/call`을 보냈을 때 MCP SDK가 HTTP 요청 없이 -32603으로 거부하는지
- 래퍼 소스(Node.js 24)에서 `notifications/cancelled`로 취소한 `tools/call`에 응답이 오지 않는지와 그 요청이 이미 HTTP 서버에 도착해 있었는지
- 래퍼 소스(Node.js 24)의 `initialize`가 지원하지 않는 버전(`1999-01-01`)에는 `2025-11-25`로, `2024-11-05`에는 같은 버전으로 답하는지

케이스 없음·열기·닫기·전환, 실제 인증 실패, 대표 질의, 내용 범위 읽기, 결과 상한, Java 쪽 오류와 기록은 실행으로 확인하지 않았다.
원고에서 이 부분은 정적 분석 결과다.

**외부 도구 버전 기준.** 버전은 저장소의 의존성 정의를 따른다.

- Javalin: `CoreLibs/ivy.xml`이 정한 7.1.0이다. 소스는 `javalin/javalin`의 릴리스 태그 `javalin-parent-7.1.0`(`9766d2f`)으로 확인했다.
- Jackson: `CoreLibs/nbproject/project.properties`가 참조하는 2.18.2다.
- Sleuth Kit Java 바인딩: `Core/nbproject/project.properties`가 참조하는 `sleuthkit-4.15.0.jar`다. 소스는 `sleuthkit/sleuthkit`의 태그 `sleuthkit-4.15.0`(`01de034`, 2026-04-15)으로 확인했다.
- MCP TypeScript SDK: `package.json`은 `^1.10.2`를 적고, `package-lock.json`이 고정한 1.27.1을 기준으로 한다. 배포 실행 파일에 묶인 SDK 버전은 아래 빌드 조건 때문에 저장소가 정하지 못한다. 설치본 실행 파일 안의 `LATEST_PROTOCOL_VERSION = "2025-11-25"` 문자열로 1.2x대 SDK인 것까지만 확인했고 1.27.1인지는 확인하지 못했다.
- NetBeans 플랫폼: `nbproject/platform.properties`가 정한 `netbeans-plat-version=15`다. 소스는 `apache/netbeans`의 태그 `15`로 확인했다.
- Java 런타임: 저장소는 `Core/nbproject/project.properties`에 소스 수준 `javac.source=17`만 정한다. 런타임 동작은 설치본 Autopsy 4.23.1이 함께 설치하는 JRE 21.0.10(설치 폴더 `jre/release`의 `JAVA_VERSION`)을 기준으로 Java SE 21 API 문서로 확인한다.
- 래퍼 실행 파일의 Node.js: 저장소에 실행 파일이 없다. `package.json`의 `package` 스크립트가 pkg 대상을 `node18-win-x64`로 정하므로 Node.js 18을 기준으로 한다. 설치본 실행 파일은 실행할 때 fetch가 실험 기능인 Node.js 버전(21 이전)이 내는 "The Fetch API is an experimental feature" 경고를 출력했다.
- 래퍼 실행 파일의 빌드 조건: 실행 파일이 놓이는 `Tools/autopsy-mcp-stdio/dist/`는 `.gitignore` 대상이라 저장소에 실행 파일이 없다. 래퍼 README는 미리 만든 실행 파일을 저장소에 넣어 두었다고 적지만 `build.xml`의 주석과 `.gitignore`는 git에서 뺀다고 적는다. `build.xml`의 `compile-mcp-stdio`는 Windows에서만 돌고 `autopsy-mcp-stdio.js`가 실행 파일보다 새로울 때만 `npm run package`로 다시 만든다. `package.json`과 잠금 파일의 변경은 다시 만드는 조건에 들어 있지 않고 `npm install`은 `node_modules`가 없을 때만 실행한다. `build-zip`은 Windows에서 이 실행 파일을 배포 폴더의 `bin/`에 복사한다.

**바뀔 수 있는 것.** 범위와 외부 도구 버전 기준은 조사하며 맞지 않는 곳이 나오면 검토를 거쳐 바꾼다.
