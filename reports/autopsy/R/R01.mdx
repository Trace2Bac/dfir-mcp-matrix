# R01 결과 가공

### R01.02 구조화 파싱·필드 선택

**구현.** 이 방식은 Java HTTP 서버의 도구 가운데 `get_server_status`를 뺀 17개에 적용된다 [1].
`get_server_status`는 Sleuth Kit 객체를 쓰지 않고 서버 이름, 실행 상태, 케이스 열림 여부를 담은 `Map`을 직접 만든다 [2].
도구는 Sleuth Kit Java 바인딩이 돌려주는 객체(`AbstractFile`, `BlackboardArtifact`, `TimelineEvent`, `OsAccount` 등)에서 필드를 골라 `Map`과 `List`를 만들고 Jackson이 이를 JSON으로 바꾼다 [1].
`query_files`는 파일 객체마다 식별 정보, 크기, 시각 4개, 유형·플래그, 알려진 파일 상태, MIME 유형, 해시 3개, 소유자, 메타데이터 주소, 파일 속성을 고른다 [3].
`query_data_artifacts`·`query_analysis_results`는 아티팩트 ID, 출처 객체 ID, 유형, 데이터 소스 ID, 속성 목록을 고르고 분석 결과에는 점수의 `significance`·`priority`를 덧붙인다 [4].
`get_object_children`은 객체의 종류에 따라 다른 필드 묶음을 고른다 [5].
`get_data_source_tree`는 `dataSourceId`가 데이터 소스 하나와 일치하면 그 항목 하나를 객체로 돌려주고 그 밖에는 목록을 돌려준다 [6].
STDIO 래퍼는 Java 응답의 `result`를 바꾸지 않고 `JSON.stringify(result, null, 2)`로 글 하나를 만들어 돌려준다 [7].

**한계.** 파일의 `path`는 `getUniquePath()`가 실패하면 `parentPath`와 이름을 이은 값으로 바뀌고 응답에는 바뀐 값이라는 표시가 없다 [3].
`buildFileItem`은 파일 속성 조회가 실패하면 `attributes`를 빈 목록으로 싣는다 [3].
이 값은 속성이 없는 파일의 값과 같다 [3].
`buildDataSourceItem`은 이미지의 해시와 획득 정보 조회가 실패하면 그 필드를 `null`로 싣는다 [8].
이 값은 값이 저장되지 않은 경우의 값과 같다 [8].

### R01.03 형식 변환·건수 집계

**구현.** 서버는 값의 형식을 바꾸고 일부 도구에서 건수를 계산한다.
`get_file_content`·`get_report_content`는 읽은 바이트를 UTF-8로 해석해 글로 바꾸고 해석할 수 없는 바이트는 대체 문자로 바꾼다 [9].
아티팩트 속성 값은 값 유형에 따라 문자열, 정수, 실수로 바꾸고 `DATETIME` 값은 ISO 8601 문자열로 바꾼다 [10].
`JSON` 값 유형의 속성은 해석하지 않고 저장된 JSON 글을 문자열 값으로 싣는다 [10].
`get_case_summary`는 데이터 소스 수, `tsk_files` 표의 모든 행 수, `blackboard_artifacts` 표의 모든 행 수를 센다 [11][12].
`tsk_files`의 행에는 파일 시스템의 파일과 폴더 밖에 카빙한 파일, 파생물, 미할당 블록, 가상 폴더, 슬랙 같은 종류가 함께 들어 있다 [13].
`summarize_timeline`은 Sleuth Kit `TimelineManager.countEventsByType`이 범주별로 센 값을 싣고 그 합 `totalEvents`를 더한다 [14].
`get_communications_accounts`는 계정마다 그 계정의 전체 관계 출처 수를 필터 없이 세어 `relationshipCount`로 싣는다 [15].
`get_account_relationships`는 대상 계정과 관련 계정이 함께 나온 출처 수를 관련 계정마다 `relationshipCount`로 싣고 그 합을 `totalRelationships`로 싣는다 [15].
`get_object_children`은 자식 수 `childCount`를 싣는다 [5].
`list_reports`·`get_report_content`의 `contentType`은 보고서 경로의 확장자로 정한 값이고 `.html`·`.htm`·`.xhtml`이면 `text/html`, 나머지는 `text/plain`이다 [16].

**한계.** `get_case_summary`는 아티팩트 수를 세는 질의에서 `SQLException`이 나면 `totalArtifacts`를 0으로 두고 오류를 알리지 않는다 [11].
`contentType`은 파일 내용을 보지 않으므로 HTML이 아닌 이진 보고서도 `text/plain`으로 표시된다 [16].
`attrValueAsObject`와 `fileAttrValueAsObject`는 `BYTE`처럼 처리하지 않는 값 유형의 속성 값을 `null`로 싣는다 [17].
이 값은 값이 저장되지 않은 속성의 값과 구별되지 않는다 [17].
`totalArtifacts`는 검사자가 거부(`REJECTED`)한 아티팩트까지 센다 [11].
`query_data_artifacts`·`query_analysis_results`는 거부한 아티팩트를 돌려주지 않으므로 두 도구로 모은 수와 `totalArtifacts`가 어긋날 수 있다 [18].
`get_file_content`의 설명은 해석할 수 없는 바이트를 `?`로 바꾼다고 적는다 [19].
코드는 `CodingErrorAction.REPLACE`를 쓰고 대체 문자열을 따로 정하지 않으므로 그 바이트는 기본 대체 문자열 U+FFFD로 바뀐다 [9][20].

`summarize_timeline`의 건수는 응답에 실린 `endTime`과 같은 초의 사건을 빼고 센다 [21][22].
도구 설명은 `endTime`을 포함하는 범위라고 적지만 Sleuth Kit `countEventsByType`은 `time < endTime` 조건으로 센다 [23][22].
`endTime`을 생략하면 끝이 케이스의 가장 늦은 사건 시각이 되어 그 시각의 사건이 빠진다 [21][22].
날짜만 준 `endTime`은 그 날 23:59:59 UTC로 바뀌므로 23:59:59의 사건이 빠진다 [23][24].
`query_timeline`은 끝 시각에 1초를 더해 조회하므로 같은 `endTime`으로 두 도구가 다루는 범위가 다르다 [25].

### R01.06 응답 항목 선별

**구현.** `get_data_source_tree`는 정해 둔 규칙으로 이미지 수준의 파일 시스템 목록을 고른다 [26].
이미지에 볼륨 시스템이 있으면 이미지 수준의 `fileSystems`를 빈 목록으로 두고 각 볼륨 아래에 그 볼륨의 파일 시스템을 싣는다 [26].
Sleuth Kit `Image.getFileSystems()`가 데이터 소스의 파일 시스템을 모두 돌려주므로 이 규칙은 같은 파일 시스템이 두 번 실리는 것을 막는다 [27].

서버가 부르는 Sleuth Kit 질의가 정한 규칙으로 빠지는 항목도 있다.
`query_data_artifacts`·`query_analysis_results`가 부르는 `getDataArtifactsWhere`·`getAnalysisResultsWhere`는 검토 상태가 `REJECTED`인 아티팩트를 빼는 조건을 늘 붙인다 [28].
`get_object_children`이 파일 객체의 자식을 얻는 `getChildren`도 아티팩트를 같은 질의로 읽으므로 거부한 아티팩트는 자식 목록과 `childCount`에서 빠진다 [29].
`get_hosts`와 `get_os_accounts`가 부르는 `getAllHosts`·`getOsAccounts`는 상태가 `ACTIVE`인 호스트와 계정만 돌려준다 [30].
`get_communications_accounts`가 부르는 `getAccountDeviceInstancesWithRelationships`는 관계가 하나 이상 있는 계정만 돌려준다 [31].
`get_account_relationships`는 같은 계정이 여러 장치에 있어도 처음 일치한 계정·장치 하나만 대상으로 삼는다 [32].

**한계.** 볼륨 아래 파일 시스템은 Sleuth Kit `Volume.getFileSystems()`가 돌려주는 볼륨의 바로 아래 자식만 싣는다 [33].
Sleuth Kit은 풀(`Pool`)을 부모 객체 아래 별도 객체로 둔다 [34].
그래서 볼륨 시스템이 있는 이미지에서 볼륨 아래 풀을 거쳐 놓인 파일 시스템은 트리에 실리지 않고 응답에도 뺐다는 표시가 없다 [26][33].
풀이 있는 이미지로 실행해 확인하지는 않았다.
Sleuth Kit 질의가 빼거나 서버가 처음 하나만 고른 항목에도 응답에는 뺐다는 표시가 없다 [28][29][30][31][32].

    private static long parseTimeArg(JsonNode args, String field, Long fallback) {
        String s = textOrNull(args, field);
        if (s == null) {
            return fallback != null ? fallback : 0L;
        }
        // Accept date-only strings (e.g. "2012-03-02").
        // End-boundary fields (endTime, *Before) expand to 23:59:59 so the full
        // day is included; start-boundary fields expand to 00:00:00 (midnight UTC).
        if (s.length() == 10) {
            boolean isEndBoundary = "endTime".equals(field) || field.endsWith("Before");
            s = s + (isEndBoundary ? "T23:59:59Z" : "T00:00:00Z");
        }
        return Instant.parse(s).getEpochSecond();
    }
