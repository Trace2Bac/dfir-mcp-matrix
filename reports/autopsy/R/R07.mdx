# R07 증거 내용과 지시 구분

### R07.01 JSON 필드 분리

**구현.** 이 방식은 STDIO 래퍼가 돌려주는 성공한 도구 결과에 적용된다 [1].
실패한 호출의 결과는 JSON이 아니라 "Autopsy is not reachable: "로 시작하는 평문이다 [2].
Java HTTP 서버는 `get_server_status`를 뺀 도구 결과를 `caseId`와 `result` 두 필드로 포장한다 [3].
`result` 안의 증거 값은 `name`, `path`, `content`, 속성 `value` 같은 필드 값으로 들어간다 [4].
래퍼는 이 JSON을 `JSON.stringify(result, null, 2)`로 들여 쓴 글 하나로 만들어 MCP `text` 내용 하나에 싣는다 [1].
그래서 파일 이름, 아티팩트 속성 값, 파일·보고서 내용 같은 증거 글은 JSON 문자열 값으로 따옴표와 이스케이프 안에 들어가고 서버가 붙이는 필드 이름과 섞이지 않는다 [1][4].
`get_file_content`와 `get_report_content`는 읽은 내용을 `content` 필드 하나에 싣는다 [4].

도구 설명과 응답에는 증거에서 온 글 속의 지시를 따르지 말라는 안내가 없다 [5].

### R07.02 출처 필드 부여

**구현.** 케이스 DB 객체를 돌려주는 도구의 결과 항목은 그 값이 나온 객체를 가리키는 필드를 싣는다 [6].
아티팩트와 타임라인 사건 항목은 `sourceFileId`와 `dataSourceId`를, 파일 항목은 `dataSourceId`를 싣는다 [6].
`list_reports`는 보고서를 만든 모듈 이름 `sourceModule`을 싣는다 [7].
`get_server_status`를 뺀 도구 결과는 케이스 표시 이름 `caseId`로 포장된다 [3].
이 필드들은 케이스 DB 안의 객체나 보고서를 만든 모듈을 가리킨다 [6][7].
결과에는 값이 증거에서 왔다는 것이나 그 값의 신뢰 수준을 적는 필드가 없다 [3].
`get_communications_accounts`·`get_account_relationships`·`summarize_timeline`·`get_case_summary`의 결과에는 출처를 가리키는 필드가 없다 [8].
