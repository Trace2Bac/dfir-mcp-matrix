# R03 분석 상태 알림

### R03.01 구조화 status·error

**구현.** 성공과 실패는 Java HTTP 서버의 JSON-RPC 오류 응답과 STDIO 래퍼의 MCP 오류 결과(`isError: true`)로 구분된다 [1][2].
Java 서버는 처리 중 예외가 나면 `result` 대신 `error` 객체(`code`, `message`)를 싣는다 [1].
알 수 없는 메서드는 `-32601`, 인자 오류로 던진 `McpException`은 `-32602`, 그 밖의 예외는 `-32603`이다 [1][3].
알 수 없는 도구 이름은 케이스가 열려 있을 때만 `-32601`을 받는다 [4].
케이스가 열려 있지 않으면 `get_server_status`·`get_case_summary` 밖의 도구 호출은 알 수 없는 이름이어도 케이스가 열려 있지 않다는 `-32603` 오류를 받는다 [4].
JSON 형식이 잘못된 요청에는 `-32700`을 돌려준다 [1].
요청 본문을 읽다가 예외가 나거나 오류 응답을 만드는 데 실패하면 `McpServer.handleMcpRequest`가 HTTP 500과 함께 `-32603`, 고정 문구 `Internal error`, 예외 문구를 담은 `data`를 보낸다 [5].
래퍼는 Java 응답에 `error`가 있거나 HTTP 상태가 성공이 아니면 예외를 던진다 [2].
도구 호출 처리기는 그 예외를 `isError: true`와 오류 문구를 담은 결과로 바꾼다 [6].
`get_server_status`는 케이스 열림 여부를 `caseOpen` 필드로 돌려준다 [7].

**한계.** 래퍼는 처리기까지 온 도구 호출의 오류를 모두 "Autopsy is not reachable: "로 시작하는 문구로 돌려준다 [6].
그래서 인자 오류(`-32602`)나 HTTP 500처럼 Autopsy에 연결된 상태에서 난 오류도 연결할 수 없다는 문구로 표시된다 [6][8].
래퍼는 Java 오류의 `code`를 결과에 싣지 않으므로 오류 종류는 `message` 문구로만 남는다 [2][8].
처리기에 닿기 전의 오류는 다르게 돌아온다.
MCP TypeScript SDK 1.27.1은 `name`이 문자열이 아니거나 `arguments`가 객체가 아닌 `tools/call`을 래퍼의 처리기에 넘기지 않고 zod 검사 문구를 담은 `-32603` 오류로 돌려준다 [9][10].

래퍼가 Autopsy에 연결하지 못하면 `tools/list`는 오류 대신 `get_server_status` 하나만 담은 도구 목록을 돌려준다 [11][12].
Autopsy에 계속 닿지 못하는 동안 이 대체 도구를 부르면 Java 서버의 상태 응답이 아니라 연결 실패를 알리는 `isError: true` 결과가 돌아온다 [12].
래퍼는 도구 목록이 바뀌었다는 알림(`listChanged`)을 선언하지 않는다 [13].
그래서 클라이언트가 대체 목록을 계속 쓰는 사이 Autopsy가 켜지면 같은 이름의 호출은 Java 쪽 `get_server_status`의 결과를 받는다 [13].

래퍼는 토큰 파일이 없으면 Autopsy에 케이스가 열려 있지 않다는 문구를 돌려준다 [14].
Java 쪽은 MCP 서버를 시작할 때 토큰 파일을 쓰고 서버를 멈출 때 지우며 케이스를 열거나 닫을 때는 토큰 파일을 건드리지 않는다 [15].
그래서 토큰 파일이 없는 것은 Autopsy가 실행 중이 아니거나 MCP 서버가 꺼진 상태인데 응답은 케이스 상태를 원인으로 적는다 [14][15].

`get_case_summary`는 아티팩트 수를 세는 질의에서 `SQLException`이 나면 `totalArtifacts`를 0으로 싣고 실패를 알리지 않는다 [16].
래퍼 코드는 HTTP 응답이 30초 안에 오지 않으면 시간 초과 오류를 돌려주게 되어 있지만 설치본 실행 파일에서는 이 제한이 적용되지 않았다 [17][18].

### R03.02 찾지 못함과 실패 구분

**구현.** 목록을 돌려주는 도구는 조건에 맞는 항목이 없으면 성공 응답에 빈 목록을 싣고 처리 중 예외가 나면 JSON-RPC 오류를 돌려준다 [1][19].
래퍼는 성공 응답을 글로 바꾸고 오류 응답은 `isError: true` 결과로 바꾸므로 일치 0건과 실패는 `isError`로 갈린다 [6].
`get_account_relationships`는 계정을 찾지 못하면 오류가 아닌 결과 안에 `error` 필드와 "Account not found" 문구를 싣는다 [20].
이 도구는 `accountId`나 `accountType`이 없으면 `-32602` 오류를 돌려주므로 대상 없음과 입력 부재도 갈린다 [21].
케이스가 열려 있지 않을 때 `get_case_summary`는 오류가 아닌 결과에 `message` 필드를 싣고 다른 도구는 `-32603` 오류를 돌려준다 [4].
응답에 찾지 못함만을 뜻하는 상태 값은 없고 `get_account_relationships`의 필드 이름은 `error`다 [20].

**한계.** 다음 도구는 대상이 없는 상태를 실패와 같은 오류로 돌려준다.
`query_data_artifacts`·`query_analysis_results`는 아티팩트 유형 조회의 `TskCoreException`만 처리해 빈 목록을 돌려주게 되어 있다 [22].
Sleuth Kit `getArtifactType`은 없는 유형 이름에 예외 대신 `null`을 돌려주므로 없는 유형을 주면 `NullPointerException`으로 생긴 `-32603` 오류가 된다 [22].
`get_object_children`은 없는 객체 ID에 인자 오류와 같은 `-32602` 오류를, `get_file_content`는 없는 파일 ID에 `NullPointerException`으로 생긴 `-32603` 오류를 돌려준다 [23][24].
`get_report_content`의 "No report found" 처리는 실행되지 않는다 [25].
Sleuth Kit `getReportById`는 없는 ID에 `null`을 돌려주지 않고 `TskCoreException`을 던지므로 이 경우 `-32603` 오류가 된다 [25][26].
래퍼는 이 오류들도 "Autopsy is not reachable: "로 시작하는 문구로 돌려준다 [6].
`get_file_content`는 `objectId`가 없으면 `McpException`이 아니라 `TskCoreException`을 던지므로 입력 부재도 `-32603`이 되어 없는 파일 ID와 같은 코드를 받는다 [27].

계정 유형 값은 도구 사이에서 이어지지 않는다.
`get_communications_accounts`와 `get_account_relationships`의 결과는 계정 유형을 Sleuth Kit의 표시 이름(`Credit Card`, `MessagingApp` 등)으로 싣는다 [28].
`get_account_relationships`는 받은 `accountType`을 유형 이름(`CREDIT_CARD`, `MESSAGING_APP` 등)과 대소문자 없이 대조한다 [29][30].
그래서 결과에서 받은 표시 이름을 그대로 넘기면 표시 이름과 유형 이름이 대소문자 밖에서도 다른 유형은 계정이 있어도 "Account not found"를 담은 정상 응답이 돌아온다 [29][30].
