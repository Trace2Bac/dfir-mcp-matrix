# R06 증거에서 추출한 민감정보 노출 제어

### 미구현

**판단.** 서버는 증거에서 나온 값을 응답에 싣고 그 가운데 비밀 값을 가리거나 빼는 처리를 두지 않는다.
MCP 패키지와 STDIO 래퍼에는 값을 가리는 함수가 없다 [1].

`query_data_artifacts`·`query_analysis_results`는 아티팩트의 속성을 유형과 값 그대로 모두 싣는다 [2].
`query_data_artifacts`의 설명은 `TSK_SERVICE_ACCOUNT`의 속성으로 `TSK_PASSWORD`를, `TSK_ACCOUNT`의 속성으로 `TSK_CARD_NUMBER`를 적는다 [3].
서버는 이 속성의 값도 가리지 않고 싣는다 [2].
`get_object_children`도 자식 아티팩트의 속성 값을 그대로 싣는다 [4].
`get_file_content`는 모델이 고른 파일 ID의 내용을 바이트 범위 그대로 읽어 글로 싣는다 [5].
`query_files`는 파일마다 Sleuth Kit 파일 속성의 값을 모두 싣는다 [6].

서버 기록에 증거 값을 싣는 코드는 없다.
래퍼의 `mcp-stdio.log`에는 오류 문구만 남고 Java 서버는 예외만 기록한다 [7][8].

function log(level, message) {
    // Only ERROR level is persisted to disk. INFO/DEBUG calls are no-ops
    // by design — they would be too noisy in production and are visible
    // during development via a debugger or by temporarily removing this guard.
    if (level !== "ERROR") return;
    try {
        // Rotate if the log has grown too large
        try {
            if (fs.statSync(LOG_PATH).size > MAX_LOG_BYTES) {
                fs.renameSync(LOG_PATH, LOG_PATH + ".1");
            }
        } catch { /* file doesn't exist yet — that's fine */ }

        const line = `${new Date().toISOString()} [${level}] ${message}\n`;
        fs.appendFileSync(LOG_PATH, line, "utf8");
    } catch { /* never let logging crash the process */ }
}
