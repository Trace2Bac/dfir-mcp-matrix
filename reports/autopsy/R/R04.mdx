# R04 도구 결과 해석 주의

### R04.01 도구별 정적 주의

**구현.** 도구 설명의 두 가지 문구가 결과와 관계없이 해석 제약을 적는다.
`get_server_status`를 뺀 도구 17개의 설명 끝에는 응답의 `caseId`가 지금 열린 케이스를 가리키고 호출 사이에 값이 바뀌면 사용자에게 알리라는 문구 `CASE_ID_NOTE`가 붙는다 [1].
이 문구는 호출마다 결과가 다른 케이스에서 나올 수 있다는 점을 알린다 [1].
`get_file_content`의 설명은 내용을 UTF-8 글로 돌려주고 해석할 수 없는 바이트를 바꿔 싣는다고 적는다 [2].
`get_report_content`도 `get_file_content`와 같은 방식으로 읽을 수 없는 바이트를 바꾸지만 설명에는 이 사실이 없다 [3][4].

도구 응답에는 결과 내용에 따라 붙는 해석 주의가 없다 [5].
서버는 MCP 리소스·프롬프트와 서버 지침을 두지 않는다 [6].

**한계.** `get_file_content`의 설명은 해석할 수 없는 바이트를 `?`로 바꾼다고 적지만 코드는 Java `CharsetDecoder`의 대체 모드를 쓰므로 그 바이트는 대체 문자 U+FFFD로 바뀐다 [2][7][3].

`caseId`에 싣는 값은 케이스 표시 이름이다 [8].
그래서 표시 이름이 같은 두 케이스 사이에서 케이스가 바뀌면 `caseId`가 바뀌지 않아 설명의 안내가 적용되지 않는다 [1][8].

        // Decode as UTF-8, replacing undecodable bytes with '?'
        // REPLACE mode should never throw, but decode() declares CharacterCodingException.
        CharsetDecoder decoder = StandardCharsets.UTF_8.newDecoder()
                .onMalformedInput(CodingErrorAction.REPLACE)
                .onUnmappableCharacter(CodingErrorAction.REPLACE);
        CharBuffer chars;
        try {
            chars = decoder.decode(ByteBuffer.wrap(buf));
        } catch (java.nio.charset.CharacterCodingException ex) {
            // Cannot happen with REPLACE policy; fall back to lossy Latin-1 conversion
            chars = CharBuffer.wrap(new String(buf, StandardCharsets.ISO_8859_1));
        }
