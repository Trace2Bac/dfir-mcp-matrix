# L02 기록 구성

### L02.01 MCP 요청 기록

**구현.** 이 방식은 `audit.json`에 항목을 쓰는 44개 도구에 적용된다 [1].
항목은 `timestamp`, `tool`, `params`, `result_summary` 네 필드로 이루어진다 [1].
`tool`에는 도구 본문이 MCP 도구 이름과 같은 문자열을 적는다 [2].
`params`에는 도구 본문이 고른 인자를 `dict`로 적는다 [2].
경로 인자는 서버가 실제 경로로 변환하기 전에 모델이 보낸 문자열 그대로다 [2].
`verify_finding`은 `params` 문자열을 JSON으로 해석한 객체를 적는다 [3].
이 해석은 값의 뜻을 바꾸지 않고 형식만 바꾼다.
서버가 `_run_tool`에 넘긴 명령 목록과 Volatility 명령은 항목에 없다 [4][5].
`get_audit_trail`은 `audit.json` 대신 `get_audit_trail_invocations.jsonl`에 `timestamp`와 세 인자 `filter_tool`·`filter_since`·`limit`만 적는다 [6].
이 기록에는 도구 이름 필드와 결과 요약이 없다 [6].
그래서 L02.03에는 연결하지 않는다.
서버는 처리 중에 모델 API를 부르지 않아 L02.04에도 연결하지 않는다.

**한계.** 도구 본문이 인자를 골라 적으므로 일부 인자는 항목에 남지 않는다 [7].
`strings_extract`는 `encoding`을, `log_search`는 `context_lines`를, `find_timestamp_anomalies`·`find_recent_changes`는 `limit`을 적지 않는다 [7].
`build_timeline`은 `fs_subpath`·`fallback_year`·`max_events`를 적지 않는다 [7].
인자 값 대신 요약만 적는 도구도 있다 [8].
`extract_iocs`·`bulk_ioc_lookup`은 `text` 대신 그 길이 `text_len`을 적는다 [8].
`find_contradictions`·`finalize_report`는 `claims_json` 대신 주장 수 `claim_count`를 적는다 [8].
`assess_coverage`는 `findings_json` 대신 값이 있었는지를 나타내는 `findings_supplied`만 적는다 [8].
Volatility 도구는 `memory_dump_path`를 `path`나 `dump`라는 이름으로, `find_recent_changes`·`build_timeline`은 `since_iso`·`until_iso`를 `since`·`until`로 바꿔 적는다 [9].
`verify_finding`의 항목에는 모델이 보낸 JSON 문자열 원문이 남지 않는다 [3].
그래서 항목만으로는 모델이 보낸 요청을 모두 되살릴 수 없다.

### L02.02 서버가 변환한 연산·인자 기록

**구현.** 이 방식은 `hexdump`, `baseline_create`, `baseline_diff`에 적용된다 [10][11][12].
`hexdump`는 `length`를 4096 이하로 줄인 뒤의 값을 적는다 [10].
이 상한 조정은 서버가 실행할 인자 값을 바꾸는 값 범위 조정이다 [10].
`baseline_create`는 `output_file`이 비었으면 기본값 `baseline.json` 경로를 채우고 실제 경로로 변환한 출력 경로를 적는다 [13][11].
`baseline_diff`는 `baseline_file`을 현재 폴더 기준 절대 경로로 바꾼 값을 적는다 [12].
이 세 도구의 항목에는 모델이 보낸 원래 값이 따로 남지 않는다 [10][11][12].

### L02.05 결과 상태·실행 시점 기록

**구현.** 이 방식은 Volatility 도구 7개와 `finalize_report`에 적용된다 [14][15].
모든 항목의 `timestamp`는 `_audit`을 부른 UTC 시각이다 [1].
도구 본문은 결과를 다 만든 뒤 `_audit`을 부르므로 이 시각은 처리를 마친 시점이다 [2].
항목에는 결과 상태를 담는 필드가 따로 없고 상태는 `result_summary` 문자열 안에만 있다 [1].
`analyze_memory_summary`를 뺀 Volatility 도구는 `vol` 실행이 실패하면 `result_summary`에 반환 코드를 `rc=<값>`으로 적는다 [14].
Volatility 도구 7개 모두 커널 심볼 표가 없으면 `no symbols`를 적는다 [14][16].
반환 코드 124는 서버가 정한 600초 시간 제한을 넘긴 경우이고 127은 `vol`이 설치되지 않은 경우다 [17].
`finalize_report`는 `result_summary`를 `REJECTED:`나 `ACCEPTED:`로 시작하고 거부한 주장 수와 모순 수를 함께 적는다 [15].

다른 도구의 항목에는 결과 상태가 없다.
`_run_tool`은 명령이 0이 아닌 코드로 끝나면 표준 오류를 출력 끝에 붙여 돌려줄 뿐 상태를 따로 돌려주지 않는다 [4].
`file_info`·`hash_file`은 그 출력 앞부분을 요약으로 적으므로 실패 문구가 요약에 섞일 수 있다 [18].

**한계.** 같은 도구라도 덤프 경로를 확인하지 못한 Volatility 도구 호출과 입력 형식 오류나 빈 주장 목록으로 거부한 `finalize_report` 호출은 항목을 쓰지 않는다 [19].
그래서 이 거부 상태는 호출 기록에 남지 않는다.

`analyze_memory_summary`는 심볼 표 문제가 아닌 플러그인 실패를 요약에 적지 않는다 [16].
`vol`이 없어 모든 플러그인이 실패해도 요약에는 숨은 모듈·malfind 영역·프로세스 이상이 모두 0이라고 적힌다 [16].

### L02.06 결과 참조·요약값 기록

**구현.** 이 방식은 `file_info`·`hash_file`·`log_search`·`hexdump`를 뺀 40개 도구에 적용된다 [20].
도구 본문은 `result_summary`에 결과를 센 값을 문장으로 적는다 [20].
`auth_failed_logins`는 실패 시도 수와 IP 수를, `find_persistence`는 발견사항 수와 그 가운데 `high` 수를, `build_timeline`은 사건 수와 출처 수를 적는 식이다 [20].
`verify_finding`은 판정 값 하나를 요약으로 적는다 [3].
`baseline_create`는 쓴 기준 파일의 이름을 요약에, 전체 경로를 `params`에 적는다 [11].
서버는 응답이나 출력의 해시를 계산해 항목에 넣지 않는다 [1].
`_audit`은 모든 요약을 500자에서 자른다 [1].

`file_info`·`hash_file`은 응답 앞 500자를, `log_search`는 응답 앞 200자를 그대로 요약으로 적는다 [18][21].
이 셋의 항목은 출력의 미리보기다.
`hash_file`의 미리보기에는 계산한 MD5·SHA256 값과 증거 경로가 들어 있다 [18].
`hexdump`는 4,096 이하로 줄인 `length` 값을 바이트 수로 적고 실제로 출력한 크기는 적지 않는다 [10].
`length`가 음수이면 `xxd`가 파일 끝까지 출력해도 요약에는 그 음수가 바이트 수로 적힌다 [10][22].
항목에는 호출 ID가 없어 한 호출의 항목을 다른 기록과 ID로 잇지 않으므로 L02.07에는 연결하지 않는다 [1].

```python
def _run_tool(cmd: list[str], timeout: int = 120) -> str:
    """Run a SIFT tool as a subprocess, capture output, never modify evidence."""
    # Fault injection: only active when FINDEVIL_FAULT_RATE > 0. Lets
    # tests/harness/fault_injection_test.py exercise graceful degradation.
    if _fault_rng is not None and _fault_rng.random() < _FAULT_RATE:
        return (
            f"[STDERR]: simulated fault — {cmd[0]} exited 124 (timeout). "
            "FINDEVIL_FAULT_RATE is set; this is a test harness injection, "
            "not a real tool failure."
        )
    result = subprocess.run(
        cmd,
        capture_output=True,
        text=True,
        timeout=timeout,
    )
    output = result.stdout
    if result.returncode != 0:
        output += f"\n[STDERR]: {result.stderr}"
    return output
```
