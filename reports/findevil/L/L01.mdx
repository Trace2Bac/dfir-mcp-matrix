# L01 기록 방식

### L01.02 도구별 기록 호출

**구현.** 이 방식은 서버의 MCP 도구 45개 모두에 적용된다.
44개 도구는 본문에서 결과를 다 만든 뒤 `server.py`의 기록 함수 `_audit`을 불러 항목 하나를 쓴다 [1][2].
`_audit`은 `findevil.audit` 로거로 JSON 한 줄을 `FINDEVIL_LOGS_DIR`의 `audit.json`에 덧붙인다 [1].
서버는 모듈을 불러올 때 이 폴더를 만들고 `server.py`가 두 번 불려도 로거에 파일 핸들러를 한 번만 붙인다 [1][3].
도구를 등록하는 FastMCP `@mcp.tool()`은 기록하지 않으므로 기록을 남길지와 언제 남길지는 도구 본문이 정한다 [2].
외부 명령을 실행하는 공통 함수 `_run_tool`과 Volatility를 실행하는 `_run_vol_plugin`도 기록하지 않는다 [4][5].
그래서 `file_info`처럼 한 호출이 외부 명령을 여러 번 실행해도 항목은 하나다 [2].

`get_audit_trail`은 `_audit`을 부르지 않는다 [6].
대신 본문이 같은 폴더의 `get_audit_trail_invocations.jsonl`에 시각과 세 인자를 한 줄 덧붙인다 [6].
그래서 `get_audit_trail` 호출은 `audit.json`에 남지 않는다 [6].

**한계.** 도구 본문은 결과를 다 만든 뒤 마지막에 `_audit`을 부르므로 그 앞에서 돌아가는 반환 지점은 기록을 남기지 않는다 [2][7].
증거 폴더 밖 경로의 거부와 없는 파일의 오류는 거의 모든 도구에서 이 반환 지점에 해당한다 [2].
`strings_extract`의 인코딩 거부, `find_recent_changes`의 시각 형식 오류, `verify_finding`의 유형·JSON 오류도 같다 [7].
`finalize_report`가 입력 형식 오류나 빈 주장 목록으로 거부하는 호출과 `baseline_create`가 출력 경로를 거부하거나 파일을 쓰지 못한 호출도 같다 [7].
Volatility 도구 7개는 덤프 경로를 확인하지 못하면 기록 없이 돌아간다 [7].
`baseline_diff`가 기준 파일을 찾거나 읽지 못한 호출, `find_contradictions`가 입력 형식으로 거부한 호출, `correlate_memory_and_disk`가 `fs_root`를 거부한 호출도 기록을 남기지 않는다 [8].

도구 본문에서 예외가 나면 대신 기록하는 공통 처리가 없다 [2].
`_run_tool`은 `subprocess.run`의 시간 제한 초과나 실행 파일이 없을 때의 예외를 처리하지 않는다 [4].
그래서 이런 호출은 FastMCP가 오류 결과를 돌려주고 항목은 남지 않는다 [4].
`_run_tool`은 명령 출력을 `text=True`로 받으므로 출력에 UTF-8로 읽히지 않는 바이트가 있을 때의 `UnicodeDecodeError`도 같은 경우다 [4][9].
`verify_finding`의 `params`에 JSON 배열을 주면 `AttributeError`로 호출이 오류로 끝나고 `audit.json`에 항목이 남지 않는다 [10].
`logs/README.md`는 `audit.json`이 모든 도구 호출을 자동으로 기록한다고 적지만 위 호출들은 기록되지 않는다 [11].

`_audit`은 도구 함수 안에서 부르는 보통 함수여서 MCP 호출이 아닌 실행도 같은 파일에 항목을 남긴다 [12][13].
사용자 CLI `scripts/investigate.py`는 반복마다 `assess_coverage` 함수를 프로세스 안에서 직접 불러 `audit.json`에 `assess_coverage` 항목을 더한다 [12].
사용자 CLI `scripts/capture_example_run.py`도 LLM 없이 도구 함수를 직접 불러 같은 기록 함수로 항목을 쓴다 [13].
이 항목들은 MCP 호출에서 나온 항목과 구별하는 필드 없이 같은 파일에 섞인다 [1].

### L01.04 클라이언트의 MCP 호출 기록

**구현.** 이 방식은 사용자가 조사를 마친 뒤 사용자 CLI `scripts/extract_token_usage.py`를 실행할 때만 적용된다 [14].
이 스크립트는 Claude Code가 남긴 세션 대화 기록 JSONL에서 이름이 `mcp__findevil__`로 시작하는 `tool_use` 블록마다 도구 이름, 인자, `tool_use_id`를 꺼낸다 [14].
도구를 부른 응답 차례마다 시각, 세션, 요청 ID, 모델, 호출 목록, 토큰 사용량을 `FINDEVIL_LOGS_DIR`의 `token_usage.jsonl`에 한 줄씩 쓴다 [15][16].
이 파일은 서버의 `audit.json`과 별도이고 두 기록에 공통 ID는 없다 [11][1].
`logs/README.md`는 두 기록을 시각으로 맞춰 보라고 적는다 [11].
도구 결과와 오류 여부는 이 기록에 없다 [14].

`scripts/investigate.py`가 반복마다 쓰는 `iteration-NN.json`은 그 반복 동안 늘어난 `audit.json` 항목 수만 담아 개별 MCP 도구 호출을 식별하지 않는다 [12].
이 수에는 CLI가 반복을 마친 뒤 직접 부른 `assess_coverage`의 항목 1건도 들어간다 [12].
저장소의 `.mcp.json`은 서버 실행 방법만 정하고 훅을 두지 않는다 [17].

**한계.** 세션이나 대화 기록 파일을 지정하지 않으면 스크립트는 findevil 도구 호출이 가장 많은 대화 기록 하나만 읽는다 [18].
대화 기록 폴더는 현재 폴더 경로의 `/`를 `-`로 바꿔 찾는다 [18].
스크립트는 실행할 때마다 `token_usage.jsonl`을 새로 써서 앞선 실행의 내용을 남기지 않는다 [16].

def _run_tool(cmd: list[str], timeout: int = 120) -> str:
    """Run a SIFT tool as a subprocess, capture output, never modify evidence."""
    # Fault injection: only active when FINDEVIL_FAULT_RATE > 0. Lets
    # tests/harness/fault_injection_test.py exercise graceful degradation.
    if _fault_rng is not None and _fault_rng.random() < _FAULT_RATE:
        return (
            f"[STDERR]: simulated fault — {cmd[0]} exited 124 (timeout). "
            "FINDEVIL_FAULT_RATE is set; this is a test harness injection, "
            "not a real tool failure."
        )
    result = subprocess.run(
        cmd,
        capture_output=True,
        text=True,
        timeout=timeout,
    )
    output = result.stdout
    if result.returncode != 0:
        output += f"\n[STDERR]: {result.stderr}"
    return output
```

def _findevil_calls(line_obj: dict) -> list[dict]:
    """Return the findevil tool_use blocks in an assistant message, if any."""
    msg = line_obj.get("message")
    if not isinstance(msg, dict):
        return []
    calls = []
    for block in msg.get("content") or []:
        if (
            isinstance(block, dict)
            and block.get("type") == "tool_use"
            and str(block.get("name", "")).startswith(TOOL_PREFIX)
        ):
            calls.append(
                {
                    "name": block["name"][len(TOOL_PREFIX) :],
                    "params": block.get("input", {}),
                    "tool_use_id": block.get("id"),
                }
            )
    return calls
```
