# T08 실행 종료 판별

### T08.01 종료 코드 확인

**구현.** 이 방식은 서버가 실행하는 두 경로에 적용된다.
첫째 경로는 `file_info`·`hash_file`·`strings_extract`·`list_evidence`·`log_search`·`hexdump`가 운영체제 명령을 실행하는 `_run_tool`이다 [1].
`_run_tool`은 종료 코드가 0이 아니면 표준 출력 뒤에 `[STDERR]:` 줄과 표준 오류를 붙여 돌려준다 [1].
종료 코드 값은 응답에 싣지 않고 응답은 MCP 오류 결과가 아닌 정상 결과다 [1].

둘째 경로는 메모리 도구 7개가 Volatility 3을 실행하는 `_run_vol_plugin`이다 [2].
`_run_vol_plugin`은 종료 코드를 결과의 `rc`에 담는다 [2].
도구는 `rc`가 0이 아니면 플러그인 결과를 해석하지 않고 `vol failed (rc=<값>)` 줄과 표준 오류의 앞부분을 응답에 싣는다 [3].
싣는 표준 오류의 길이는 `analyze_memory_processes`·`analyze_memory_network`가 500자, `analyze_memory_modules`·`analyze_memory_bash_history`·`analyze_memory_malfind`가 400자, `correlate_memory_and_disk`가 플러그인마다 200자다 [4].
호출 기록의 결과 요약에도 `rc=<값>`을 남긴다 [3].

**한계.** `log_search`가 실행하는 `grep`은 일치하는 줄이 없을 때도 종료 코드 1로 끝난다 [5][6].
`_run_tool`은 이 종료 코드도 실패와 같은 `[STDERR]:` 줄로 표시한다 [1].
실행 확인에서 일치하는 줄이 없는 패턴으로 `log_search`를 부르면 응답과 호출 기록의 결과 요약이 모두 `[STDERR]: ` 한 줄이었다 [6].

`analyze_memory_summary`는 플러그인 6개를 실행하지만 각 플러그인의 `rc`가 0이 아니면 그 결과를 빈 목록으로 두고 판정을 만든다 [7].
심볼 부재로 분류되지 않은 실패와 시간 초과는 응답에 표시되지 않는다 [7].

환경변수 `FINDEVIL_FAULT_RATE`가 0보다 크면 `_run_tool`은 그 비율만큼 명령을 실행하지 않는다 [1][8].
대신 명령이 종료 코드 124로 끝났다는 문구와 시험용 주입이라는 문구를 출력으로 돌려준다 [1].

### T08.02 시간 제한·종료 신호 처리

**구현.** 이 방식은 Volatility 실행과 운영체제 명령 실행에 적용된다.
`_run_vol_plugin`은 `subprocess.run`에 시간 제한 600초를 준다 [2][9].
제한을 넘으면 서버는 예외를 처리해 `rc`를 124로 정하고 표준 오류 자리에 `vol <플러그인> timed out after 600s`를 넣는다 [2].
끊기 전에 받은 출력은 버리고 같은 플러그인을 다시 실행하지 않는다 [2].

`_run_tool`은 도구마다 시간 제한을 준다 [1].
기본값은 120초이고 `strings_extract`와 `log_search`는 60초, `hexdump`는 30초다 [1][10].
제한을 넘으면 `subprocess.run`이 낸 시간 초과 예외를 서버가 처리하지 않는다 [1].
MCP Python SDK 1.27.2의 FastMCP가 이 예외를 `Error executing tool <도구>: ` 뒤에 붙여 `isError` 응답으로 돌려준다 [11].
실행 확인에서 40초 동안 멈추는 `xxd`로 `hexdump`를 부르면 `timed out after 30 seconds` 문구의 오류 응답이 왔고 호출 기록에는 항목이 남지 않았다 [12].

서버 소스에서 시간 제한을 주는 곳은 위 두 경로와 `vol`이 있는지 확인하는 `vol --help` 실행까지 `subprocess.run` 호출 세 곳이다 [13].
`find_persistence`, auth·journal·웹 로그 도구, `verify_finding`, `finalize_report`처럼 서버 프로세스 안에서 증거 파일을 읽어 분석하는 도구에는 시간 제한이 없다 [13].

**한계.** `analyze_memory_summary`는 시간 제한을 넘긴 플러그인의 결과도 빈 목록으로 다룬다 [7].

### T08.03 오류·출력 내용 판독

**구현.** 이 방식은 Volatility 실행과 `log_search`에 적용된다 [2].
`_run_vol_plugin`은 종료 코드가 0이 아니면 표준 오류에 심볼을 찾지 못했다는 문구 4가지 가운데 하나가 있는지 본다 [2][14].
있으면 결과에 심볼 부재를 따로 표시한다 [2][14].
도구는 이 표시가 있으면 일반 실패 대신 심볼 설치 안내를 싣는다 [15].
`analyze_memory_network`·`analyze_memory_malfind`·`analyze_memory_summary`는 표준 오류에 `invalid choice`가 있는지 보고 플러그인이 없는 실패를 구별한다 [16][17].
종료 코드가 0이면 표준 출력을 JSON으로 읽고 앞에 경고 줄이 붙어 읽히지 않으면 `[`로 시작하는 배열 부분을 찾아 다시 읽는다 [18].
`log_search`는 출력이 비었는지 보고 비었으면 일치하는 줄이 없다는 문구를 돌려준다 [5].

**한계.** 종료 코드가 0인데 표준 출력을 JSON으로 읽지 못하면 결과 행은 빈 목록이 된다 [18].
도구는 이 경우를 결과가 없는 실행과 같게 다루어 프로세스 0개나 `No bash history recovered` 같은 문구를 싣는다 [19].
`log_search`의 출력은 일치하는 줄이 없을 때 `[STDERR]:` 줄을 담으므로 비어 있지 않고 일치하는 줄이 없다는 문구는 나오지 않는다 [1][6].
반대로 `grep`이 이진으로 판정한 파일에서는 일치하는 줄이 있어도 표준 출력이 비고 종료 코드가 0이다 [20].
이때 `_run_tool`은 표준 오류를 붙이지 않으므로 `log_search`는 일치하는 줄이 없다는 `No matches found for pattern` 문구를 돌려준다 [1][5][20].
`log_search`는 `grep`에 `-a`를 넘기지 않으므로 NUL 바이트가 들어간 기록 파일에서는 있는 줄을 없다고 알린다 [5][20].

### T08.06 프로세스 안 분석 예외를 실패로 구별

**구현.** 이 방식은 `verify_finding`과 `finalize_report`가 쓰는 검증 함수 가운데 인증 기록과 웹 접근 기록을 다시 읽는 다섯 함수에 적용된다 [21][22].
이 함수들은 `_read_safe_log`로 기록 파일을 읽고 파일이 없거나 `OSError`가 나면 내용 대신 `None`을 받는다 [21].
그 경우 판정을 `INSUFFICIENT_EVIDENCE`로 정하고 이유에 기록이 없거나 읽을 수 없다는 문구를 싣는다 [21][22].
`finalize_report`는 이 판정을 받은 확정 주장을 `SUPPORTED`가 아닌 주장으로 보고 거부 사유에 적는다 [23].
같은 검증 함수 가운데 `file_modified_in_window`는 주장의 시각 값을 해석하지 못하면, `sudo_command_executed`는 주장의 정규식을 컴파일하지 못하면 판정을 `INSUFFICIENT_EVIDENCE`로 정한다 [24].
`assess_coverage`는 받은 발견사항 JSON을 해석하지 못하면 IOC 추적과 검증 누락을 보지 못했다는 항목을 누락 목록에 넣으므로 `COVERAGE CLEAN` 판정을 내지 않는다 [25].

서버 안의 다른 분석 코드는 파일을 읽다 난 예외를 처리하지 않거나 그 파일을 실패로 표시하지 않는다.
`analyze_journal`·`analyze_nginx_access`와 auth 도구는 증거 파일을 `read_text`로 읽고 권한 오류 같은 `OSError`를 처리하지 않는다 [26].
`package_installed` 검증도 apt·dpkg 기록을 `read_text`로 읽고 그 예외를 처리하지 않는다 [27].
이 예외는 MCP Python SDK 1.27.2의 FastMCP가 `isError` 응답으로 돌려준다 [11].
지속성 검사의 `_read_safe`는 예외가 나면 `[unreadable: …]` 문장을 파일 내용처럼 돌려주고 검사기는 그 문장에 규칙을 댄다 [28].
`find_ai_signatures`의 `_read_safe`는 빈 문자열을 돌려주고 컨테이너 검사는 읽지 못한 설정 파일의 발견사항 없이 돌아간다 [29].
`verify_package_integrity`는 MD5를 계산하지 못한 파일을 비교한 수에 넣고 결과에서 뺀다 [30].
FIM은 해시를 계산하지 못한 파일을 기준선 항목에서 빼므로 `baseline_diff`는 그 파일을 없어진 파일로 싣는다 [31][32].
그 파일의 심각도가 critical이면 `baseline_diff`의 판정은 `LIKELY COMPROMISE`가 된다 [32].
`persistence_mechanism_exists` 검증은 지속성 검사의 `_read_safe`를 거치므로 설정 파일을 읽지 못해도 판정이 `INSUFFICIENT_EVIDENCE`가 아니라 `CONTRADICTED`가 된다 [33][28].
`analyze_bash_history`는 기록 파일을 읽지 못하면 그 오류 문장을 변조 징후 목록에 넣고 기록 파일이 비었다는 문장을 붙인다 [34].
`find_webshells`는 읽지 못한 파일을 훑은 파일 수에 세고 발견사항이 없는 파일과 같게 다룬다 [35].
`bulk_ioc_lookup`은 저장소의 IOC 파일을 읽거나 해석하지 못하면 빈 IOC 목록으로 조회하고 그 오류를 응답에 싣지 않으므로 모든 IOC가 목록에 없다고 나간다 [36].
`build_timeline`은 `since_iso`·`until_iso`를 해석하지 못하면 파일 시각 사건을 알리지 않고 뺀다 [37].
`analyze_journal`과 `build_timeline`의 journal 파서는 JSON으로 읽지 못한 줄을 건너뛰고 건너뛴 줄 수를 응답에 싣지 않는다 [38].

**한계.** 다섯 검증 함수는 기록 파일을 읽은 뒤 서버 파서가 한 줄도 해석하지 못해도 실패로 정하지 않는다 [39].
그 경우 해석한 사건이 0건이므로 판정은 `INSUFFICIENT_EVIDENCE`가 아니라 `CONTRADICTED`가 된다 [39].

```python
def _run_tool(cmd: list[str], timeout: int = 120) -> str:
    """Run a SIFT tool as a subprocess, capture output, never modify evidence."""
    # Fault injection: only active when FINDEVIL_FAULT_RATE > 0. Lets
    # tests/harness/fault_injection_test.py exercise graceful degradation.
    if _fault_rng is not None and _fault_rng.random() < _FAULT_RATE:
        return (
            f"[STDERR]: simulated fault — {cmd[0]} exited 124 (timeout). "
            "FINDEVIL_FAULT_RATE is set; this is a test harness injection, "
            "not a real tool failure."
        )
    result = subprocess.run(
        cmd,
        capture_output=True,
        text=True,
        timeout=timeout,
    )
    output = result.stdout
    if result.returncode != 0:
        output += f"\n[STDERR]: {result.stderr}"
    return output
```

```python
    """Compute SHA256 streaming. Returns empty string on permission error."""
```
