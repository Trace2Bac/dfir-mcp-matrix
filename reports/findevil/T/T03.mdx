# T03 실행 조건 확인

### 미구현

**판단.** 서버에는 도구 인자 밖의 조건으로 호출을 막거나 미루는 코드가 없다.
도구 함수는 경로 대조와 인자 검사를 마치면 바로 외부 명령을 실행하거나 파일을 분석한다 [1].
서버 지침은 `list_evidence`로 시작해 `assess_coverage`가 `COVERAGE CLEAN`을 돌려줄 때까지 조사하고 `finalize_report`로 마치라고 안내하지만 이 순서를 확인하는 코드는 없다 [2].
`finalize_report`는 앞선 `assess_coverage`의 결과나 호출 기록을 보지 않고 받은 claim을 그 자리에서 다시 확인한다 [3].
`assess_coverage`는 남은 작업을 응답에 적기만 하고 다른 도구의 호출을 막지 않는다 [4].
`baseline_diff`는 `baseline_create`를 앞서 불렀는지 보지 않고 모델이 넘긴 기준선 파일이 있는지만 확인한다 [5].
`verify_finding`의 설명은 다른 도구가 발견사항을 낸 뒤에 부르라고 적지만 서버는 앞선 호출이 있었는지 보지 않고 바로 증거를 다시 읽는다 [6].
`scripts/investigate.py`는 claude CLI의 승인 확인을 기본으로 켜 두지만 이 승인은 클라이언트가 하고 서버는 승인 기록을 받거나 대조하지 않는다 [7].
서버는 `mcp.run()`을 기본 전송 방식인 stdio로 실행하므로 원격 MCP 연결을 받지 않는다 [8].
메모리 도구가 실행 전에 `vol --help`를 실행해 보는 것은 도구가 있는지 보는 확인이고 실행 자원의 상태를 보지 않는다 [9].

동시 실행 수를 정하는 장치도 없다.
도구 함수가 모두 동기 함수라서 MCP Python SDK 1.27.2의 FastMCP는 이벤트 루프에서 함수를 await 없이 바로 부른다 [10].
한 호출이 끝날 때까지 같은 이벤트 루프의 다른 요청은 처리되지 않으므로 도구 호출은 하나씩 차례로 실행된다 [10].
이는 서버가 정한 제한이 아니라 SDK가 동기 함수를 부르는 방식에서 생기는 동작이라 T03.12에 연결하지 않는다.
