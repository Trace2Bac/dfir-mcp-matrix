# T07 도구 부재 처리

### T07.01 실행 전 도구·참조 자료 가용성 검사

**구현.** 이 검사는 Volatility 3을 실행하는 메모리 도구 7개에 적용된다 [1].
서버는 플러그인을 실행할 때마다 `_vol_available`로 `vol --help`를 시간 제한 10초로 시험 실행한다 [1][2].
시험 실행이 실행 파일을 찾지 못하거나 시간 제한을 넘기거나 0이 아닌 종료 코드로 끝나면 플러그인을 실행하지 않는다 [1][2].

참조 자료인 커널 심볼은 서버가 실행 전에 확인하지 않는다 [1].
심볼을 찾는 일은 Volatility가 하고 서버는 실행이 실패한 뒤 표준 오류의 문구로 심볼 부재를 알아본다 [3].

참조 자료인 IOC 파일 `data/threat_intel.json`도 서버가 조회 전에 확인하지 않는다 [4].
`_load_cache`는 이 파일을 읽지 못하면 빈 조회 표에 오류를 담은 `_error` 키를 더한 `dict`를 돌려준다 [4].
그러면 `bulk_ioc_lookup`은 모든 IOC를 `not in cache`로 싣고 `_error`의 내용은 응답에도 호출 기록에도 싣지 않는다 [5].

`file_info`·`hash_file`·`strings_extract`·`list_evidence`·`log_search`·`hexdump`가 쓰는 운영체제 명령은 `_run_tool`이 확인 없이 실행한다 [6].
명령이 없으면 `subprocess.run`이 낸 예외를 서버가 처리하지 않고 MCP Python SDK 1.27.2의 FastMCP가 이 예외를 `Error executing tool <도구>: ` 뒤에 붙여 `isError` 응답으로 돌려준다 [6][7].
실행 확인에서 `file`이 없는 `PATH`로 `file_info`를 부르면 `[Errno 2] No such file or directory: 'file'` 문구의 오류 응답이 왔다 [8].

**한계.** `vol --help`가 10초 안에 끝나지 않거나 0이 아닌 종료 코드로 끝나도 서버는 실행 파일이 없을 때와 같은 결과를 만든다 [2].
그래서 이 경우에도 응답은 Volatility가 설치되지 않았다고 적는다 [1].

### T07.02 대체 없는 실패 처리·도구 부재 알림

**구현.** 이 처리는 메모리 도구 7개에 적용된다 [1].
`vol`이 없으면 서버는 다른 도구로 바꾸지 않고 종료 코드 127과 ``volatility3 (`vol`) not installed on PATH`` 문구를 실패 결과로 만든다 [1].
`analyze_memory_processes` 같은 도구는 이 문구를 `vol failed (rc=127)` 줄과 함께 응답에 싣는다 [9][8].

커널 심볼이 없어 실행이 실패하면 서버는 `## ⚠ Kernel symbols required` 머리와 함께 심볼 파일을 둘 폴더와 `dwarf2json`으로 만드는 방법을 응답에 싣는다 [3][10].
이때 서버는 `banners.Banners`를 한 번 더 실행해 커널 배너를 얻으면 배너도 함께 싣는다 [10][11].
실행 확인에서 Volatility 3 2.28.0과 심볼 없는 덤프로 `analyze_memory_processes`와 `analyze_memory_network`를 부르면 이 안내가 실렸다 [12].

**한계.** `analyze_memory_summary`는 `vol`이 없을 때 이 사실을 응답에 싣지 않는다 [13].
플러그인 실패가 심볼 부재로 분류되지 않으면 이 도구는 실패한 플러그인의 결과를 빈 목록으로 다룬다 [13].
실행 확인에서 `vol`이 없는 환경으로 이 도구를 부르면 프로세스 0개, 숨은 모듈 0개와 함께 `No strong memory-resident compromise indicators` 판정이 실렸다 [8].

### T07.04 알림 없는 대체 실행

**구현.** 이 대체는 `analyze_memory_network`·`analyze_memory_malfind`·`analyze_memory_summary`의 플러그인 실행과 메모리 도구 7개의 실행 파일 선택에 적용된다 [14][15][16].
서버는 소켓 목록을 `linux.sockstat.Sockstat`으로 먼저 실행하고 실패 출력에 `invalid choice`가 있으면 `linux.netstat`으로 다시 실행한다 [14].
코드 주입 영역은 `linux.malware.malfind.Malfind`를 먼저 실행하고 같은 조건에서 `linux.malfind`로 다시 실행한다 [15].
응답과 호출 기록은 어느 플러그인으로 결과를 얻었는지 싣지 않는다 [14][17].
`analyze_memory_network`의 도구 설명은 `linux.netstat`을 감싼다고 적는다 [18].

환경변수 `FINDEVIL_VOL`이 가리키는 경로가 파일이 아니면 서버는 알리지 않고 `PATH`나 가상 환경 폴더의 `vol`을 쓴다 [16].
사용자가 정한 실행 파일을 쓰지 못했다는 사실은 응답에도 호출 기록에도 남지 않는다 [16][17].

기준으로 삼은 Volatility 3 2.28.0은 `linux.sockstat.Sockstat`과 `linux.malware.malfind.Malfind`를 모두 두므로 이 버전에서는 대체 플러그인이 실행되지 않는다 [12].

### T07.05 실행 환경별 경로 분기

**구현.** 서버는 모듈을 불러올 때 `_resolve_vol_bin`으로 `vol` 실행 파일을 한 번 정하고 이후 모든 메모리 도구가 그 값을 쓴다 [16].
환경변수 `FINDEVIL_VOL`이 가리키는 파일이 있으면 그것을 쓴다 [16].
없으면 `PATH`에서 `vol`, `vol.py` 차례로 찾고 그다음 서버를 실행한 Python과 같은 폴더에서 같은 이름을 찾는다 [16].
모두 없으면 `vol`이라는 이름을 그대로 쓴다 [16].
실행 확인에서 `PATH`에 `vol`이 없는 환경으로 서버를 실행하면 가상 환경 폴더의 `vol`이 쓰였다 [12].
고른 실행 파일의 경로는 응답에도 호출 기록에도 남지 않는다 [17][19].

```python
        return False
    try:
        proc = subprocess.run(
            [_VOL_BIN, "--help"],
            capture_output=True, text=True, timeout=10,
```

```python
def _run_tool(cmd: list[str], timeout: int = 120) -> str:
    """Run a SIFT tool as a subprocess, capture output, never modify evidence."""
    # Fault injection: only active when FINDEVIL_FAULT_RATE > 0. Lets
    # tests/harness/fault_injection_test.py exercise graceful degradation.
    if _fault_rng is not None and _fault_rng.random() < _FAULT_RATE:
        return (
            f"[STDERR]: simulated fault — {cmd[0]} exited 124 (timeout). "
            "FINDEVIL_FAULT_RATE is set; this is a test harness injection, "
            "not a real tool failure."
        )
    result = subprocess.run(
        cmd,
        capture_output=True,
        text=True,
        timeout=timeout,
    )
    output = result.stdout
    if result.returncode != 0:
        output += f"\n[STDERR]: {result.stderr}"
    return output
```

```python
def _identify_kernel(dump: Path) -> tuple[str, list[str]]:
    """Run banners.Banners and return (best_banner, all_banners).

    The kernel banner determines which symbol table Volatility needs.
    Returning the banner gives the agent something to act on if symbols
    are missing.
    """
    res = _run_vol_plugin(dump, "banners.Banners", json_output=True)
    banners: list[str] = []
    for row in res.rows:
        b = row.get("Banner") or row.get("banner")
        if isinstance(b, str) and b.strip():
            banners.append(b.strip())
    # Prefer the longest Linux banner (kernel header banner is usually verbose)
    linux_banners = [b for b in banners if "Linux version" in b]
    best = max(linux_banners, key=len) if linux_banners else (banners[0] if banners else "")
    return best, banners
```

```python
def _resolve_vol_bin() -> str:
    """Find the Volatility 3 entrypoint.

    Order of preference:
      1. FINDEVIL_VOL env var (explicit override)
      2. `vol` / `vol.py` on $PATH
      3. The findevil venv's own bin/ (so installs into the project venv work
         even when the venv is not activated by the calling shell)
      4. Fall back to "vol" so the no-such-binary error message is clean
    """
    override = os.environ.get("FINDEVIL_VOL")
    if override and Path(override).is_file():
        return override
    for name in ("vol", "vol.py"):
        found = shutil.which(name)
        if found:
            return found
    # Note: do NOT call .resolve() here — venv pythons are typically
    # symlinks to the system interpreter, and resolving that symlink
    # leaks back to the system bin dir where `vol` likely isn't.
    venv_bin = Path(sys.executable).parent
    for name in ("vol", "vol.py"):
        cand = venv_bin / name
        if cand.is_file():
            return str(cand)
    return "vol"


_VOL_BIN = _resolve_vol_bin()
```

```python
@mcp.tool()
def analyze_memory_network(memory_dump_path: str) -> str:
    """List network connections recovered from a Linux memory dump.

    Wraps `linux.netstat`. Surfaces every TCP/UDP/UNIX socket the kernel
    knew about at capture time. Flags listeners on common reverse-shell
    handler ports (4444, 4445, 1337, 31337, 8888, 9001, 6666, 13337)
    and outbound connections to non-RFC1918 destinations, since live
    network state is often the only place to see a rootkit's C2.
```
