# T09 대상 시스템 대응 조치 처리

### 비적용

**판단.** 서버는 대상 시스템에 접속하거나 그 상태를 바꾸는 도구를 두지 않는다.
도구 45개는 증거 폴더 아래 파일을 읽거나, 모델이 넘긴 글과 서버 기록을 읽어 결과를 만든다 [1].
증거 경로 인자는 `_validate_evidence_path`로 경로가 환경변수 `FINDEVIL_EVIDENCE_DIR`의 폴더 안인지 확인한다 [2].
`baseline_create`의 `output_file`, `baseline_diff`의 `baseline_file`, `build_timeline`의 `fs_subpath`는 이 확인을 거치지 않는다 [3][4][5].
서버가 실행하는 외부 프로그램은 파일을 읽는 운영체제 명령과 메모리 덤프를 읽는 Volatility 3이고 원격 호스트에 접속하는 명령은 없다 [6][7].

서버가 쓰는 파일은 서버 기록 파일 둘과 `baseline_create`의 기준 파일이다 [8][9].
`audit.json`에 호출 기록을 남긴다 [8].
`get_audit_trail_invocations.jsonl`에는 `get_audit_trail`을 부를 때마다 시각과 인자를 한 줄씩 남긴다 [9].
`baseline_create`는 기준 파일 경로 `output_file`이 증거 폴더 안이면 거부하고 경로를 받지 않으면 기록 폴더의 `baseline.json`에 쓴다 [3].
`output_file`에 증거 폴더 밖 경로를 주면 서버 계정이 쓸 수 있는 어느 경로든 상위 폴더를 만들고 그 파일을 기준 JSON으로 덮어쓴다 [3][10].
`baseline_create`의 도구 설명은 가동 중인 호스트를 감시하려면 증거 폴더를 `/`의 읽기 전용 마운트로 정하라고 안내한다 [11].
이 구성에서도 도구는 증거 폴더 아래를 읽기만 한다 [1].
다만 `output_file`은 마운트 밖의 경로도 받으므로 서버가 감시하는 호스트에서 실행되면 그 호스트의 파일을 기준 JSON으로 덮어쓸 수 있다 [3][11].
이 쓰기는 기준 JSON을 남기는 기능이고 격리·차단·프로세스 종료·설정 변경 같은 조치를 하는 도구는 없다 [1].
그래서 조치 전후 상태, 변경 내역, 되돌림을 남길 대상 시스템 조치가 없다.

```python
def _validate_evidence_path(path_str: str) -> Path:
    """Ensure the requested path is inside the evidence directory.

    Uses Path.relative_to() rather than a string-prefix check. A naive
    startswith() would accept ``/tmp/X/evidence-malicious/...`` as being
    "inside" ``/tmp/X/evidence`` because the string literally begins
    with the prefix. Tests in tests/security/test_path_validation.py
    hold this invariant in place.
    """
    requested = Path(path_str).resolve()
    evidence_resolved = EVIDENCE_DIR.resolve()
    try:
        requested.relative_to(evidence_resolved)
    except ValueError as exc:
        raise ValueError(
            f"Access denied: {path_str} is outside the evidence directory ({EVIDENCE_DIR})"
        ) from exc
    return requested
```
