# T02 실행 허용 범위 제한

### T02.04 고정 명령·템플릿

**구현.** 이 방식은 외부 명령을 실행하는 `file_info`, `hash_file`, `strings_extract`, `list_evidence`, `log_search`, `hexdump`와 메모리 도구 7개에 적용된다 [1].
이 도구들은 서버 코드가 정한 실행 파일과 인자 배열로 명령을 실행하고 모델은 배열 안의 값만 채운다 [1].
`file_info`는 `file -b <경로>`와 `stat <경로>`를, `hash_file`은 `md5sum <경로>`와 `sha256sum <경로>`를, `list_evidence`는 `ls -lahR <경로>`를 실행한다 [1].
`strings_extract`는 `strings -n<min_length> -e<encoding> <경로>`를, `log_search`는 `grep -n -i -C<context_lines> -E <pattern> <경로>`를, `hexdump`는 `xxd -s <offset> -l <length> <경로>`를 실행한다 [1].
메모리 도구는 `vol -q -f <덤프 경로> -r json <플러그인>` 배열로 Volatility 3을 실행한다 [2].
플러그인 이름은 도구마다 코드에 정해 두고 모델은 덤프 경로만 넘긴다 [3].
경로 값은 경로 대조 함수가 돌려준 절대 경로라 `-`로 시작하지 않으므로 옵션으로 읽히지 않는다 [4].
서버는 셸이나 임의 명령을 실행하는 도구를 두지 않는다.
나머지 도구는 외부 명령을 실행하지 않고 서버 코드의 파서로 분석한다.

**한계.** `log_search`는 `pattern`을 옵션 끝 표시 `--`나 `-e` 없이 명령 인자에 넣는다 [1].
그래서 `pattern`이 `-`로 시작하면 `grep`이 그 값을 옵션으로 읽는다 [5].
`pattern`을 `-f`와 경로를 붙인 값으로 주면 `grep`은 증거 폴더 밖 파일을 검색 패턴 목록으로 읽어 증거 파일을 검색한다 [5].

### T02.05 연산·플러그인 허용 목록

**구현.** 이 방식은 `verify_finding`의 `claim_type`에 적용된다 [6].
`verify_finding`은 `claim_type`을 서버 코드의 목록 `_VALID_CLAIM_TYPES`의 8개 값과 대조하고 목록에 없으면 지원 목록을 적은 오류 문구를 돌려준다 [6][5].
목록의 값마다 `_VERIFIER_MAP`에 검증 함수 하나가 정해져 있다 [7].
`finalize_report`는 `type`이 이 목록에 있는 `confirmed` 항목만 그 검증 함수로 다시 확인한다 [8].
목록에 없는 `type`은 거부하지 않고 `evidence` 인용이 있는지만 본다 [8].
목록을 바꾸는 설정이나 인자는 없다.

저장소의 `.mcp.json`은 서버를 실행하는 명령만 적는다 [9].
`scripts/investigate.py`는 `claude -p`에 권한 모드, 출력 형식, 턴 수, 모델만 넘기고 허용·거부 도구 목록을 넘기지 않는다 [10].
저장소에는 모델이 쓸 도구를 정하거나 클라이언트 자체 도구를 막는 클라이언트 설정이나 훅이 없다.
