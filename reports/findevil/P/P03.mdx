# P03 조사 진척 판단

### P03.01 기준 작업 목록 대조

**구현.** `assess_coverage`는 자료 종류 11개마다 그 종류를 다룰 도구 묶음을 `_ARTIFACT_CHECKS`에 정해 둔다 [1].
예를 들어 인증 로그에는 `auth_summary` 등 인증 도구 5개를, 메모리 이미지에는 `analyze_memory_summary` 등 메모리 도구 6개를 둔다 [1].
서버는 호출 기록 `audit.json`의 모든 줄을 읽어 기록된 도구 이름 집합을 만든다 [2].
증거 폴더에 있는 자료 종류마다 그 묶음의 도구가 하나라도 이 집합에 있으면 `examined`, 없으면 `NOT examined`로 표에 싣는다 [3].
`NOT examined`인 종류는 실행할 작업 문구와 함께 남은 작업으로 응답에 싣는다 [3].

**한계.** 도구 묶음의 도구 하나만 호출 기록에 있으면 그 종류 전체를 `examined`로 본다 [1][3].
그래서 셸 기록 파일 목록만 내는 `find_shell_histories`를 한 번 부르면 셸 기록을 하나도 분석하지 않아도 셸 기록이 `examined`가 된다 [1][4].
웹 서버 접근 로그는 접근 로그를 읽지 않는 `find_webshells`로, 패키지 로그는 로그를 읽지 않는 `verify_package_integrity`로도 `examined`가 된다 [1].
대조는 도구 이름으로만 하고 호출 인자의 경로는 보지 않는다 [2][3].
같은 종류의 파일이 여러 폴더에 있어도 한 파일에 도구를 실행하면 나머지 파일도 `examined`로 처리한다 [3][5].
호출 기록 파일은 서버를 다시 시작하거나 다른 증거를 조사해도 이어 쓰므로 앞선 조사의 호출도 이번 조사의 수행으로 처리한다 [2][6].
메모리 도구는 Volatility 3 실행이 실패하거나 심볼이 없어 분석하지 못해도 호출 기록을 남기므로 메모리 이미지가 `examined`가 된다 [7].
`analyze_journal`처럼 읽은 사건이 없다는 응답으로 끝난 호출도 기록되므로 그 자료 종류는 `examined`가 된다 [8].
서버가 호출 기록 파일에 쓰지 못해도 도구는 정상 응답을 돌려주고 이 사실을 알리지 않는다 [9][10].
그래서 실제로 실행한 도구가 호출 기록에 없어 그 자료 종류가 `NOT examined`로 남을 수 있다 [9][3].
목록 함수는 경로를 200,000개까지만 모아 그 뒤 경로의 자료 종류는 대조하지 않는다 [5].

### P03.02 단계 상태·완료 조건 대조

**구현.** `assess_coverage`는 남은 작업이 없으면 `COVERAGE CLEAN`을, 있으면 남은 작업 수와 함께 `GAP(S) REMAIN`을 판정으로 싣는다 [11].
첫째 완료 조건은 증거 폴더에 있는 자료 종류가 모두 `examined`인 것이다 [3].
둘째 조건은 `findings_json`에 공개 IPv4나 MD5·SHA-1·SHA-256 해시가 있으면 `bulk_ioc_lookup` 호출이 기록에 있는 것이다 [12].
셋째 조건은 `findings_json`에서 `confidence`가 `confirmed`인 항목 수가 기록된 `verify_finding` 호출 수보다 많지 않은 것이다 [12].
`findings_json`이 JSON으로 읽히지 않으면 IOC와 검증 조건을 보지 못했다는 남은 작업을 더한다 [13].
서버 지침은 `COVERAGE CLEAN`이 나올 때까지 조사를 되풀이하라고 적는다 [14].
서버는 이 판정으로 다른 도구 호출을 막지 않는다.

사용자 CLI `scripts/investigate.py`는 `claude -p` 실행이 끝날 때마다 `findings_json` 없이 `assess_coverage`를 직접 부르고 그 실행 동안 `finalize_report`의 `ACCEPTED`가 기록됐는지 본다 [15].
둘 다 채우면 반복을 멈추고 아니면 `--max-iterations`(기본 5)까지 되풀이한다 [15].

**한계.** 검증 조건은 CONFIRMED 항목 수와 호출 기록 전체의 `verify_finding` 호출 수만 비교하고 어느 호출이 어느 항목을 검증했는지 보지 않는다 [12].
`verify_finding`이 `CONTRADICTED`나 `INSUFFICIENT_EVIDENCE`를 돌려준 호출과 앞선 조사의 호출도 이 수에 포함된다 [12][16].
`finalize_report`가 안에서 실행한 재확인은 `verify_finding` 호출로 기록되지 않아 이 수에 포함되지 않는다 [17].
IOC 조건은 `bulk_ioc_lookup`이 한 번이라도 기록에 있으면 채워지고 그 IOC를 조회했는지는 보지 않는다 [12].
도메인과 URL은 IOC 조건에서 보지 않는다 [12].
`findings_json`을 주지 않으면 자료 종류 조건만 보고 `COVERAGE CLEAN`을 싣는다 [11].

### P03.03 미조사 범위·생략 사유 보고

**구현.** `assess_coverage`는 증거 폴더에 있지만 어느 도구도 다루지 않은 자료 종류를 남은 작업으로 응답에 싣는다 [3].
항목마다 자료 종류 이름, 증거 폴더 기준 경로 3개까지, 실행할 작업 문구를 적는다 [3].
`findings_json`을 읽지 못하면 JSON 오류 문구와 함께 IOC와 검증 조건을 확인하지 않았다는 사실을 남은 작업으로 싣는다 [13].
자료 종류 11개 가운데 어느 것에도 속하지 않는 파일은 대조하지 않고 응답에도 오르지 않는다 [1][18].
모델이 진행 기록을 적는 도구는 없고 `assess_coverage`의 호출 기록에도 `findings_json`을 받았는지만 남는다 [19].

**한계.** 도구 이름만 대조하므로 같은 종류의 다른 파일에 도구를 실행했으면 다루지 않은 파일이 있어도 응답에 오르지 않는다 [3][5].
`find_shell_histories`처럼 기록 내용을 읽지 않는 도구 하나로도 그 종류가 남은 작업에서 빠진다 [1][4].
목록 함수는 경로를 200,000개까지만 모으므로 그 뒤 경로에 있는 자료 종류는 다루지 않은 범위로도 응답에 오르지 않는다 [5].

    """Return every audit.json entry as a dict (best-effort, never raises)."""
    audit_path = LOGS_DIR / "audit.json"
    if not audit_path.is_file():
        return []
    try:
        raw = audit_path.read_text(errors="replace").splitlines()
    except OSError:
        return []
    out: list[dict] = []
    for line in raw:
        line = line.strip()
        if not line:
            continue
        try:
            out.append(json.loads(line))
        except json.JSONDecodeError:

    return out

def _audit(tool: str, params: dict, result_summary: str) -> None:
    """Write a structured audit log entry for every tool invocation."""
    entry = {
        "timestamp": datetime.now(timezone.utc).isoformat(),
        "tool": tool,
        "params": params,
        "result_summary": result_summary[:500],
    }
    audit_logger.info(json.dumps(entry))

def _match_artifact(path: Path, kind: str) -> bool:
    name = path.name.lower()
    parent = path.parent.name.lower()
    full = str(path).lower()
    if kind == "auth":
        return name in {"auth.log", "secure"} or name.startswith("auth.log")
    if kind == "journal":
        return name.endswith(".journal") or "journal" in name
    if kind == "weblog":
        return name.startswith("access.log") or parent in {"nginx", "apache2", "httpd"}
    if kind == "authkeys":
        return name == "authorized_keys"
    if kind == "sshdconfig":
        return name == "sshd_config"
    if kind == "sudoers":
        return name == "sudoers" or parent == "sudoers.d"
    if kind == "history":
        return name in {".bash_history", "bash_history", ".zsh_history", "zsh_history"}
    if kind == "pkglog":
        return name == "dpkg.log" or full.endswith("apt/history.log")
    if kind == "container":
        return name in {"daemon.json", "config.v2.json", "hostconfig.json"} or (
            "docker" in full or "containerd" in full
        )
    if kind == "memory":
        return name.endswith((".lime", ".mem", ".raw", ".vmem", ".dump", ".lime.raw"))
    return False
