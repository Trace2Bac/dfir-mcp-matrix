# P02 다음 작업 결정

### P02.01 고정 문서·프로필 반환

**구현.** 서버는 FastMCP `instructions`(서버 지침)로 조사 절차를 내놓는다 [1].
지침은 먼저 `list_evidence`로 증거를 훑고 가설을 세워 도구를 실행하라고 적는다 [1].
도구가 IOC를 내면 다음 작업으로 가기 전에 `extract_iocs`·`bulk_ioc_lookup`을 실행하고 다른 증거에서도 찾으라고 적는다 [1].
이어서 `assess_coverage`가 `COVERAGE CLEAN`을 돌려줄 때까지 조사를 되풀이하고 마지막에 `finalize_report`를 부르라고 적는다 [1].
`finalize_report`가 거부하면 다시 조사하거나 확신 수준을 `inference`·`uncertain`으로 낮춰 다시 부르라고 적는다 [1].
지침은 서버 객체를 만들 때 정한 문자열이라 조사 상태와 관계없이 같다 [1].
서버는 MCP 리소스와 프롬프트를 두지 않는다.
저장소의 `CLAUDE.md`도 같은 4단계 절차를 적지만 Claude Code가 읽는 클라이언트 설정이라 이 상세의 구현으로 세지 않는다 [2].
지침과 도구 설명에는 클라이언트 문맥이 압축되거나 끊긴 뒤 저장한 상태를 다시 읽으라는 안내가 없어 P02.05에는 연결하지 않는다 [1].

### P02.02 규칙·조사 상태로 추천

**구현.** `assess_coverage`는 호출 기록 `audit.json`에 남은 도구 이름과 증거 폴더의 자료 종류를 맞춰 남은 작업을 응답에 싣는다 [3].
증거 폴더에 있는 자료 종류의 도구가 호출 기록에 하나도 없으면 `_ARTIFACT_CHECKS`에 적어 둔 작업 문구를 붙인다 [3][4].
예를 들어 셸 기록이면 `find_shell_histories`를 실행한 뒤 기록마다 `analyze_bash_history`를 실행하라고 적는다 [4].
모델이 `findings_json`으로 준 발견사항에 공개 IPv4나 해시가 있는데 `bulk_ioc_lookup` 호출이 기록에 없으면 `bulk_ioc_lookup`을 실행하라고 적는다 [5].
`confidence`가 `confirmed`인 항목 수가 기록된 `verify_finding` 호출 수보다 많으면 CONFIRMED 항목마다 `verify_finding`을 실행하라고 적는다 [5].
남은 작업이 없으면 `finalize_report`로 가라고 적는다 [6].

결과로 다음 작업을 권하는 도구도 있다.
`auth_summary`는 실패가 5회 이상인 IP에서 성공한 로그인이 있으면 `auth_successful_logins`·`auth_sudo_commands`·`auth_user_events`를 부르라고 적는다 [7].
`finalize_report`는 거부할 때 거부 사유가 된 claim마다 다시 조사하거나 확신 수준을 낮춘 뒤 다시 부르라고 적는다 [8].
`analyze_memory_summary`는 숨은 커널 모듈이나 `malfind` 결과가 있으면 `analyze_memory_modules`·`analyze_memory_malfind`·`find_persistence`를 실행하라고 적는다 [9].
이 권고는 응답 문자열이고 서버가 권고를 따르지 않은 호출을 막지는 않는다.

**한계.** `assess_coverage`는 자료 종류의 도구가 다른 파일이나 앞선 조사에서 한 번이라도 기록됐으면 그 종류의 작업을 권하지 않는다 [3].
메모리 도구는 Volatility 3 실행이 실패해도 호출 기록을 남기고 `analyze_journal`은 읽은 사건이 없어도 호출 기록을 남긴다 [10].
그래서 분석하지 못하고 끝난 호출로도 그 자료 종류의 작업을 다시 권하지 않는다 [3][10].
`verify_package_integrity`는 불일치가 없을 때 패키지 밖 실행 파일은 `find_persistence`와 `scan_devshm_executables`로 보라고 적는다 [11].
`scan_devshm_executables`는 `find_persistence`가 안에서 부르는 함수이고 MCP 도구가 아니다 [12].

### P02.04 서버 코드에 고정한 분석 절차

**구현.** `analyze_memory_summary`는 커널 배너 확인, `linux.pslist`, `linux.sockstat.Sockstat`, `linux.lsmod`, `linux.check_modules`, `linux.malware.malfind.Malfind`를 이 차례로 실행한다 [13].
실행 결과의 이상 항목을 모아 판정 문구 하나를 정한다 [9].
`correlate_memory_and_disk`는 `linux.lsmod`·`linux.check_modules` 비교와 디스크의 커널 모듈 지속성 검사를 함께 실행하고 두 결과를 네 경우로 나눠 판정한다 [14].
`find_persistence`는 계정, cron, systemd, SSH 키, 셸 초기화 파일, 라이브러리 preload 등 검사 16개를 정한 차례로 실행해 결과를 한 목록으로 합친다 [12].
`build_timeline`은 인증 로그, journal 내보내기, 패키지 로그, 접근 로그, 셸 기록을 찾아 읽고 사건을 시각순으로 합친다 [15].
`find_ai_signatures`는 LLM API 참조, 에이전트 경로, 도구 호출 JSONL, 스크립트 작성 습관, 셸 기록 속도 검사 5개를 정한 차례로 실행해 결과를 합친다 [16].
`analyze_container_artifacts`는 Docker 컨테이너 설정, docker-compose, Docker daemon 설정, Kubernetes 매니페스트 검사를 차례로 실행해 결과를 합친다 [17].
`analyze_memory_modules`는 `linux.lsmod`와 `linux.check_modules`를 실행해 두 목록의 차이로 숨은 모듈을 정한다 [18].
모델은 이 도구와 인자만 고르고 그 안의 단계는 서버 코드가 정한다.
서버 안에서 모델을 불러 계획을 세우는 경로는 없어 P02.03에는 연결하지 않는다.

**한계.** `analyze_memory_summary`는 심볼이 없는 경우에만 묶음을 멈추고 다른 실패는 그 단계의 결과를 빈 값으로 두고 이어 간다 [19].
`vol`이 설치되어 있지 않으면 모든 단계가 종료 코드 127로 끝나지만 서버는 이를 빈 결과로 합친다 [19][20].
그 결과 응답은 이상 항목이 없다는 판정 "No strong memory-resident compromise indicators"를 싣고 호출 기록에도 숨은 모듈과 `malfind` 결과가 0으로 남는다 [21].
