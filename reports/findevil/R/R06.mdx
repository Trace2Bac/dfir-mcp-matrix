# R06 증거에서 추출한 민감정보 노출 제어

### 미구현

**판단.** 서버는 증거에서 나온 값을 응답과 호출 기록에 싣고 그 가운데 비밀 값을 가리거나 빼는 처리를 두지 않는다.
서버 코드에는 값을 가리는 함수가 없다 [1].

응답에서는 기본 도구가 증거 파일의 내용을 명령 출력 그대로 싣는다 [2].
`strings_extract`·`hexdump`·`log_search`는 모델이 고른 파일의 문자열, 바이트, 일치 줄을 그대로 돌려준다 [2].
`find_ai_signatures`는 `ANTHROPIC_API_KEY`·`OPENAI_API_KEY` 같은 API 키 할당을 찾으면 그 파일의 앞 400자를 표본으로 싣는다 [3].
그래서 찾아낸 키 값이 표본에 들어 있으면 그대로 모델에게 간다 [3].
`find_persistence`는 의심 파일의 앞 400~500자를 표본으로 싣고 `/etc/passwd` 계정 항목은 그 줄을 그대로 싣는다 [4].
`analyze_systemd_unit`은 unit 파일 내용을 1,500자까지 싣고 `auth_sudo_commands`·`analyze_bash_history`·`analyze_memory_bash_history`는 명령 줄을 그대로 싣는다 [5].
`find_persistence`의 계정 검사 `scan_users`는 `/etc/shadow`의 비밀번호 칸을 읽지만 비어 있는지만 판정하고 해시 값은 응답에 싣지 않는다 [6].

호출 기록에서는 `_audit`이 도구 인자와 결과 요약 앞 500자를 `audit.json`에 남긴다 [7].
`log_search`는 결과 글 앞 200자를, `verify_finding`은 모델이 넘긴 인자 객체 전체를 기록한다 [8].
`get_audit_trail`은 이 기록의 인자와 요약을 200자까지 다시 응답에 싣는다 [9].
