# R02 대량 결과 전달

### R02.01 문자·항목 상한

**구현.** 서버는 도구마다 응답에 싣는 줄 수나 항목 수에 상한을 둔다.
기본 도구는 `strings_extract`가 500줄, `list_evidence`·`log_search`가 300줄에서 출력을 자르고 `hexdump`는 요청 길이를 4,096바이트로 줄인다 [1][2][3].
공통 함수 `emit_table`은 `top_n`을 넘는 행을 표에 싣지 않는다 [4].
이 함수를 쓰는 `auth_successful_logins`·`auth_sudo_commands`의 기본 상한은 200행이다 [5].
메모리 도구는 프로세스 60개, 소켓 50개, 복구한 명령 200개, malfind 영역 30개까지 싣는다 [6].
`analyze_nginx_access`는 공격 표지가 붙은 요청 30건과 업로드 사슬 20건까지, `extract_iocs`는 IOC 종류마다 50개까지 싣는다 [7][8].
`build_timeline`·`find_recent_changes`·`analyze_package_logs`·`verify_package_integrity`는 인자 `max_events`·`limit`·`max_mismatches`로 항목 수를 제한한다 [9].
`auth_failed_logins`는 IP를 `top_n`개(기본 20개), `analyze_journal`·`analyze_nginx_access`는 IP를 `top_n_ips`개(기본 10개)까지 싣는다 [10].
`analyze_journal`은 커널 모듈 메시지와 우선순위 높은 항목을 20개씩, `analyze_memory_summary`는 프로세스 이상과 네트워크 표시를 10개씩 싣는다 [11].
`assess_coverage`는 자료 종류마다 경로를 10개까지 모아 그 가운데 3개를 표에 싣고 증거 폴더 탐색을 경로 200,000개에서 멈춘다 [12].
`build_timeline`은 파일 수정 시각 사건을 500개까지만 모으고 이 수는 `max_events`와 따로 적용된다 [13].

상한 가운데 `top_n`·`top_n_ips`·`limit`·`max_events`·`max_mismatches`는 모델이 인자로 바꿀 수 있고 서버는 그 값의 최댓값을 두지 않는다 [4][9][10].
`hexdump`의 4,096바이트와 메모리 도구의 행 수 같은 나머지 상한은 코드에 정해져 있다 [3][6].

다음 도구의 응답에는 항목 수 상한이 없다.
`find_persistence`는 심각도 `info`가 아닌 항목을, `find_webshells`·`analyze_container_artifacts`·`find_ai_signatures`는 찾은 항목을 모두 내용 표본과 함께 싣는다 [14][15].
`analyze_journal`은 로그인 성공과 sudo 명령 표에는 상한을 두지 않고 `auth_user_events`·`analyze_bash_history`·`analyze_sudoers`·`baseline_diff`도 찾은 항목을 모두 싣는다 [16].
`bulk_ioc_lookup`은 공인 IP·도메인·해시를 모두 조회해 싣는다 [17].

**한계.** `hexdump`는 `length`가 음수이면 `min(length, 4096)`이 그 음수를 그대로 남겨 `xxd -l`에 넘긴다 [3].
`xxd`는 `-l`에 음수를 받으면 파일 끝까지 출력하므로 이 경우 4,096바이트 상한이 적용되지 않고 응답에 줄 상한도 없다 [18].
`emit_table`은 `top_n`이 음수이면 뒤쪽 행을 빼고 실제로 뺀 수보다 큰 숨긴 행 수를 적는다 [4].
`get_audit_trail`은 `limit`이 0이면 마지막 0개가 아니라 조건에 맞는 항목 전체를 싣는다 [19].

### R02.02 전체·반환 건수 표시

**구현.** 상한으로 자른 응답 여러 곳이 전체 수와 반환한 범위를 함께 적는다.
`emit_table`은 숨긴 행의 수와 그 행까지 보려면 넘길 `top_n` 값을 표 끝에 적고 호출하는 도구는 제목에 전체 수를 적는다 [4][5].
`analyze_memory_processes`는 전체 프로세스 수와 표가 앞 60개라는 것, 잘린 수를 함께 적는다 [6].
`analyze_memory_network`는 전체 소켓 수와 표가 앞 50개라는 것을 적는다 [20].
`analyze_memory_bash_history`·`analyze_memory_malfind`·`verify_package_integrity`는 머리에 전체 수를 적고 잘린 수를 목록 끝에 적는다 [21].
`extract_iocs`는 IOC 종류마다 전체 수를 소제목에 적고 50개를 넘으면 잘린 수를 적는다 [8].
`analyze_nginx_access`는 공격 표지가 붙은 요청 목록 제목에 `first 30 of N`을 적는다 [7].
`build_timeline`과 `find_recent_changes`는 전체 수를 머리에 적고 표 끝에 잘린 수를 적는다 [22].
`strings_extract`·`list_evidence`·`log_search`는 자른 출력 끝에 `[TRUNCATED: N total ...]`로 전체 줄 수를 적는다 [1][2].
`get_audit_trail`은 조건에 맞는 전체 항목 수와 보여 주는 마지막 항목 수를 제목에 적는다 [23].

**한계.** `log_search`는 `grep -C`의 출력 줄 수를 `total matches`로 적는다 [2].
이 줄 수에는 앞뒤 문맥 줄과 구분 줄이 들어가므로 실제 일치 수와 다르다 [2].

반환 범위를 적지 않는 상한도 있다.
`bulk_ioc_lookup`은 사설 IP·URL·Bitcoin 주소·CVE·이메일 목록을 20개에서 자르고 제목의 전체 수만 적는다 [17].
`find_timestamp_anomalies`는 분류마다 `limit`개까지 싣고 요약 줄에 분류별 전체 수만 적으며 같은 시각 묶음은 10묶음, 묶음마다 10개 경로까지 잘린 표시 없이 싣는다 [24].
`hexdump`는 요청한 길이를 4,096바이트로 줄였다는 것을 응답에 알리지 않는다 [3].
`find_persistence`는 `high`·`medium` 항목이 없을 때 `info` 항목 앞 10개의 경로만 싣고 요약 줄에 `info` 항목의 전체 수를 적지만 목록이 잘렸다는 표시는 없다 [15].
`auth_failed_logins`는 머리에 전체 IP 수를 적지만 표가 앞 `top_n`개라는 것을 적지 않는다 [10].
`analyze_journal`·`analyze_nginx_access`의 IP 목록과 `analyze_journal`의 20개 목록, `analyze_memory_summary`의 10개 목록도 전체 수만 적거나 아무 수도 적지 않는다 [10][11].
`analyze_package_logs`는 `Flagged events`에 전체 수를 적고 표는 `max_events`개에서 잘린 표시 없이 자른다 [25].
`analyze_memory_modules`는 lsmod에만 있는 모듈의 전체 수를 소제목에 적고 앞 20개만 싣는다 [26].
`assess_coverage`는 자료 종류마다 경로 3개만 싣고 탐색을 200,000개에서 멈춘 사실을 알리지 않는다 [12].
`build_timeline`의 파일 수정 시각 사건 500개 상한도 응답에 드러나지 않는다 [13].

### R02.06 값 단위 잘림

**구현.** 결과 항목 안의 값 하나를 정해진 길이에서 자르는 곳이 여러 도구에 있다.
`find_persistence`·`analyze_container_artifacts`는 의심 파일의 내용 표본을 400~500자, `find_webshells`는 300자, `find_ai_signatures`는 300·400·500자에서 자른다 [27][28].
`find_persistence`의 `authorized_keys` 표본은 키 줄을 120자, 키 옵션을 80자에서 자르고 키를 10개까지 싣는다 [29].
`find_persistence`의 이유 문장은 udev 명령과 D-Bus 명령을 100자, modprobe 지시문을 120자에서 자른다 [30].
`analyze_nginx_access`는 요청 경로를 140자, 질의 문자열을 80자에서 자르고 `build_timeline`은 nginx 요청 경로를 180자에서 자른다 [31].
`build_timeline`은 사건 내용을 200자, 행위자를 40자에서 자르고 `analyze_journal`은 메시지를 160자에서 자른다 [22][32].
`get_audit_trail`은 기록 항목의 인자와 결과 요약을 각각 200자에서 자르고 호출 기록의 결과 요약 자체도 `_audit`이 500자에서 자른 값이다 [23][33].
메모리 도구는 Volatility 표준 오류를 400~500자, 복구한 명령을 200자, 커널 배너를 200자에서 자르고 `correlate_memory_and_disk`는 두 플러그인의 표준 오류를 200자씩 자른다 [34][35].
이 잘림에는 잘렸다는 표시가 없다 [27][32][34].
`analyze_authorized_keys`는 키 데이터의 앞 32자와 끝 12자만 `...`로 이어 싣고 원래 길이를 `len=`으로 함께 적는다 [36].
같은 도구는 해석하지 못한 키 줄을 80자에서 자르고 잘렸다는 표시를 붙이지 않는다 [36].

### R02.07 건수 없는 잘림 표시

**구현.** `analyze_systemd_unit`은 unit 파일 내용을 1,500자에서 자르고 그 뒤에 `... [truncated] ...`를 붙인다 [37].
이 표시는 파일 전체 길이나 잘린 길이를 적지 않는다 [37].

def _events_from_filesystem(
    fs_root: Path, since_ts: float, until_ts: float, max_files: int = 500
) -> list[TimelineEvent]:
    out: list[TimelineEvent] = []
    count = 0
    for p in fs_root.rglob("*"):

            if not p.is_file():
                continue
            mt = p.stat().st_mtime
            if since_ts <= mt <= until_ts:
                iso = datetime.fromtimestamp(mt, tz=timezone.utc).isoformat()
                out.append(TimelineEvent(
                    iso, "filesystem",
                    actor="?",
