# R07 증거 내용과 지시 구분

### R07.03 경계 태그 표시

**구현.** 이 방식은 `find_persistence`, `find_webshells`, `analyze_container_artifacts`, `find_ai_signatures`, `analyze_systemd_unit` 다섯 도구의 응답에 적용된다 [1][2][3].
네 검사 도구는 발견사항마다 경로·요약·이유 목록을 서버 문구로 쓴 뒤 증거 파일의 내용 표본을 Markdown 코드 블록 표시(백틱 세 개) 두 줄 사이에 싣는다 [1][2].
여는 표시와 닫는 표시는 같은 코드에서 함께 붙고 표본이 빈 값이면 블록을 싣지 않는다 [1][2].
`analyze_systemd_unit`은 `## Raw content` 아래에 unit 파일의 앞 1,500자를 ```` ```ini ````와 닫는 표시 사이에 싣는다 [3].
`find_webshells`의 표본은 의심 파일의 앞 300자다 [4].
`find_ai_signatures`의 표본은 검사한 파일의 앞 400~500자다 [5].
`find_persistence`의 설정 파일 검사와 `analyze_container_artifacts`의 docker-compose·Kubernetes 검사는 파일 앞 400~500자를 표본으로 쓴다 [6].
계정 검사는 `passwd`의 원래 줄을 표본으로 쓴다 [6].
이 표본들은 증거 파일에서 읽은 글만 담는다 [4][5][6].

여러 도구는 증거에서 온 명령이나 값 하나를 백틱 한 쌍으로 감싸 표 칸이나 목록 항목에 싣는다 [7].
`analyze_bash_history`·`analyze_memory_bash_history`의 명령, `analyze_journal`의 sudo 명령, `analyze_sudoers`의 규칙, `analyze_systemd_unit`의 `ExecStart` 값이 이렇게 실린다 [7].
`assess_coverage`는 자료 종류마다 증거 폴더 기준 경로를 3개까지 백틱 한 쌍으로 감싸 자료 범위 표와 남은 작업 문구에 싣는다 [8].

다른 도구는 증거에서 온 글을 이런 표시로 감싸지 않는다.
기본 도구 `file_info`·`strings_extract`·`list_evidence`·`log_search`·`hexdump`는 명령 출력을 감싸지 않고 싣고 잘림 문장을 그 바로 뒤에 붙인다 [9].
모든 응답은 Markdown 글 하나이고 `structuredContent`도 그 글을 `result` 필드 하나에 담는다 [10].
서버 지침과 도구 설명에는 증거에서 온 글 속의 지시를 따르지 말라는 안내가 없다 [11].

**한계.** 서버는 표본 안의 백틱 세 개를 바꾸거나 막지 않는다 [1][3].
그래서 증거 파일에 백틱 세 개로 시작하는 줄이 있으면 블록이 그 줄에서 끝나고 그 뒤의 증거 글은 서버 문구와 같은 Markdown 글로 읽힌다 [1].

일부 표본은 서버 문구를 블록 안에 함께 담는다.
`find_persistence`의 `authorized_keys` 표본은 판정한 키 줄 앞에 `⚠ `를, 뒤에 `  — `와 판정 이유를 붙인다 [12].
`/dev/shm` 아래 실행 파일, PAM `.so`, `extra` 아래 `.ko`의 표본은 파일 내용이 아니라 서버가 만든 `"{경로} ({크기} bytes)"` 문장이다 [13].
Docker 컨테이너 표본은 서버가 설정 JSON에서 고른 여섯 필드로 새로 만든 JSON이고 Docker daemon 표본은 설정 JSON을 다시 직렬화한 값이다 [14].
`analyze_systemd_unit`은 파일이 1,500자를 넘으면 서버 문구 `... [truncated] ...`를 블록 안 증거 뒤에 넣는다 [3].
같은 도구는 파일을 읽지 못하면 `_read_safe`가 돌려준 `[unreadable: …]` 문장을 파일 내용 자리에 넣어 블록 안에 싣는다 [15].

같은 응답의 블록 밖에도 증거에서 온 글이 있다.
머리 줄은 증거 파일의 경로를, 요약은 파일·모듈·계정 이름을 서버 문구와 한 줄에 싣는다 [1][16].
이유 목록은 `pam_exec invokes world-writable path:` 같은 서버 문장 뒤에 증거 파일의 명령을 붙인다 [17].

백틱 한 쌍으로 감싼 값은 값 안의 `|`만 바꾸고 백틱은 바꾸지 않는다 [7].
그래서 증거 값에 백틱이 있으면 감싼 구간이 그 자리에서 끝난다 [7].
공통 표 함수 `emit_table`은 칸 값의 백틱을 바꿔 쓰지만 칸 값을 백틱으로 감싸지 않는다 [18].
`assess_coverage`는 `emit_table`을 쓰지 않고 경로를 감쌀 때 백틱, `|`, 줄바꿈 가운데 어느 것도 바꾸지 않는다 [8].
그래서 경로에 이 문자가 있으면 백틱으로 감싼 구간이나 표 칸이 그 자리에서 끝난다 [8].

```python
def _read_safe(path: Path, max_bytes: int = 65536) -> str:
    """Read a file with size cap and error tolerance."""
    try:
        with path.open("rb") as f:
            data = f.read(max_bytes)
        return data.decode(errors="replace")
    except (OSError, PermissionError) as e:
        return f"[unreadable: {e}]"
```

```python
def _escape_cell(value: str) -> str:
    """Make a cell value safe to embed in a Markdown table row.

    Embedded newlines are replaced with ``<br>`` so a multi-line value
    (e.g. a sudo COMMAND with a literal ``\n``) does not break the row.
    """
    return (
        str(value)
        .replace("|", "\\|")
        .replace("`", "\\`")
        .replace("\r\n", "<br>")
        .replace("\n", "<br>")
        .replace("\r", "<br>")
    )
```
