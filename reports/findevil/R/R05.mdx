# R05 결과 출처 표시

### R05.01 증거·파일 ID

**구현.** 증거 파일 하나를 읽는 도구 가운데 메모리 도구 7개, `analyze_journal`, `analyze_nginx_access`, `analyze_bash_history`, `stat_file`, `analyze_authorized_keys`, `analyze_systemd_unit`, `analyze_sshd_config`, `analyze_sudoers`는 응답 제목에 모델이 준 증거 경로를 적는다 [1].
`auth_summary`는 응답 제목에 파일 이름만 적는다 [2].
다른 auth 도구 4개와 `file_info`·`hash_file`·`strings_extract`·`log_search`·`hexdump`는 응답에 증거 경로를 적지 않는다 [2].
폴더를 훑는 도구는 결과 항목마다 그 항목이 나온 파일의 경로를 모델이 준 폴더 기준의 상대 경로로 싣는다 [3].
`find_persistence`·`find_webshells`·`analyze_container_artifacts`·`find_ai_signatures`·`find_shell_histories`가 이 방식으로 경로를 싣는다 [3].
`build_timeline`은 사건마다 그 사건을 읽은 기록 파일과 줄 번호를 `provenance` 칸에 싣는다 [4].
`verify_finding`의 `brute_force_from_ip`·`user_created`·`persistence_mechanism_exists` 검증은 판정 근거 문장에 모델이 준 경로를 적고 다른 검증은 경로를 적지 않는다 [5][6].

서버는 디스크 이미지나 압축 파일을 직접 열지 않고 `FINDEVIL_EVIDENCE_DIR` 아래 폴더의 파일을 읽으므로 증거 안 경로를 따로 싣지 않는다 [7].

`bulk_ioc_lookup`이 돌려주는 참조 지식은 서버에 함께 실린 IOC 캐시 `threat_intel.json`의 항목이다 [8].
공인 IP 결과 줄은 캐시 항목의 `source`를 싣지만 이 값은 `findevil:scenario-01`·`public:torproject` 같은 이름표이고 원문 주소나 원문 ID가 아니다 [8][9].
도메인과 해시 결과 줄에는 `source`도 없다 [9].
캐시의 IP·도메인·해시 16개 가운데 9개는 `source`가 `findevil:scenario-01`~`04`나 `findevil:synthetic`인 저장소 예시 시나리오의 값이다 [8].
이 항목들은 대부분 `tags`에 `simulated`를 담고 `bulk_ioc_lookup`은 세 종류 모두 결과 줄에 `tags`를 싣는다 [8][9].
캐시 전체의 출처 설명 `_metadata.sources`는 응답에 실리지 않는다 [8][9].
캐시 판정은 추출한 IOC 값과 같은 줄에 붙고 코드와 설명은 그 판정이 증거가 아니라고 밝히지 않는다 [9].
지속성 검사 결과의 이유 문장에 들어 있는 Diamorphine·BPFDoor 같은 악성코드 이름도 출처 없이 서버 코드에 적은 문구다 [10].

**한계.** `build_timeline`의 `provenance`는 기록 파일의 경로가 아니라 파일 이름만 싣는다 [4].
여러 사용자의 `.bash_history`에서 온 사건은 모두 `.bash_history:<줄>`로 적히고 어느 파일인지는 `actor` 칸의 사용자 이름으로만 가른다 [11].
`actor`는 기록 파일의 절대 경로에서 처음 나오는 `home` 조각 다음 조각으로 정한다 [11].
증거 폴더 자체가 `/home/<사용자>/` 아래에 있으면 모든 `.bash_history` 사건의 `actor`가 그 사용자 이름이 된다 [11][12].
`FINDEVIL_EVIDENCE_DIR`의 기본값은 서버를 시작한 폴더의 `./evidence`이고 README는 저장소를 클론한 폴더에서 클라이언트를 시작하라고 안내한다 [12].

### R05.03 레코드 키·번호

**구현.** 메모리 도구는 Volatility 행의 PID를 결과 항목마다 싣는다 [13].
`analyze_memory_processes`는 프로세스마다 PID와 PPID를, `analyze_memory_bash_history`·`analyze_memory_malfind`는 행마다 PID를 싣는다 [13].
`analyze_memory_network`의 소켓 표는 프로세스 이름만 싣고 PID는 싣지 않는다 [13].
`verify_package_integrity`는 바뀐 파일마다 dpkg 패키지 이름과 그 파일 경로를 싣는다 [14].
`file_info`는 `stat`의 출력을 바꾸지 않고 실으므로 `stat`이 출력하는 inode 번호가 그대로 전달된다 [15].

### R05.04 바이트·섹터·행 오프셋

**구현.** 텍스트 기록을 읽는 도구는 결과 항목마다 기록 파일의 줄 번호를 싣는다.
`auth_successful_logins`·`auth_sudo_commands`·`auth_user_events`는 사건마다 줄 번호를, `auth_failed_logins`는 IP마다 처음과 마지막 줄 번호를 싣는다 [16].
`analyze_journal`·`analyze_nginx_access`·`analyze_bash_history`는 항목마다 export 파일이나 기록 파일의 줄 번호를 싣는다 [17].
`build_timeline`의 `provenance`와 `verify_finding`의 판정 근거도 줄 번호를 싣는다 [4][5].
`find_persistence`는 `/etc/passwd`에서 찾은 계정 항목의 경로에 줄 번호를 붙인다 [18].
`log_search`는 `grep -n`을, `hexdump`는 `xxd`를 실행하므로 외부 도구가 출력한 줄 번호와 바이트 오프셋이 그대로 전달된다 [19].

`analyze_package_logs`의 표지 표에는 줄 번호 칸이 없다 [20].
지속성·웹셸·컨테이너·AI 흔적 검사 결과는 파일 경로와 내용 표본만 싣고 파일 안 위치는 싣지 않는다 [3].

**한계.** apt 기록 파서는 패키지마다 줄 번호를 그 패키지가 들어 있는 기록 묶음의 `Start-Date` 줄로 정한다 [21].
그래서 `build_timeline`의 apt 사건 `provenance`는 패키지가 적힌 `Install:` 같은 줄이 아니라 묶음의 첫 줄을 가리킨다 [21][22].

서버 파서는 기록 파일의 글을 `str.splitlines()`로 나눈 차례를 줄 번호로 쓴다 [23].
CPython 3.12.3의 `str.splitlines()`는 `\n` 말고도 `\r`, `\x0b`, `\x0c`, `\x1c`~`\x1e`, `\x85`, U+2028, U+2029에서 줄을 나눈다 [24].
그래서 기록 한 줄 안에 이 문자가 있으면 그 뒤 항목의 줄 번호는 `\n`으로만 센 줄 번호보다 커진다 [23][24].

def _validate_evidence_path(path_str: str) -> Path:
    """Ensure the requested path is inside the evidence directory.

    Uses Path.relative_to() rather than a string-prefix check. A naive
    startswith() would accept ``/tmp/X/evidence-malicious/...`` as being
    "inside" ``/tmp/X/evidence`` because the string literally begins
    with the prefix. Tests in tests/security/test_path_validation.py
    hold this invariant in place.
    """
    requested = Path(path_str).resolve()
    evidence_resolved = EVIDENCE_DIR.resolve()
    try:
        requested.relative_to(evidence_resolved)
    except ValueError as exc:
        raise ValueError(
            f"Access denied: {path_str} is outside the evidence directory ({EVIDENCE_DIR})"
        ) from exc
    return requested
```

def _events_from_bash_history(path: Path) -> list[TimelineEvent]:
    from findevil.tools.linux_shell_history import parse_history
    out: list[TimelineEvent] = []
    content = path.read_text(errors="replace")
    user = "?"
    if "home" in path.parts:
        try:
            user = path.parts[path.parts.index("home") + 1]
        except (ValueError, IndexError):
            pass
    elif "root" in path.parts:
        user = "root"
    for entry in parse_history(content):
        if not entry.timestamp:
            continue  # skip entries without HISTTIMEFORMAT timestamps
        out.append(TimelineEvent(
            entry.timestamp, "bash_history",
            actor=user,
            action="shell_command",
            detail=entry.command[:200],
            provenance=f"{path.name}:{entry.line_number}",
        ))
    return out
```

def _events_from_apt(apt_log: Path) -> list[TimelineEvent]:
    from findevil.tools.linux_packages import parse_apt_history
    out: list[TimelineEvent] = []
    content = apt_log.read_text(errors="replace")
    for e in parse_apt_history(content):
        flag_note = f" ⚠ {'; '.join(e.flags)}" if e.flags else ""
        out.append(TimelineEvent(
            e.timestamp, "apt",
            actor="apt",
            action=f"package_{e.action}",
            detail=f"{e.name}={e.version}{flag_note}",
            provenance=f"{apt_log.name}:{e.source_line}",
        ))
    return out
