# R01 결과 가공

### R01.01 가공 없이 전달

**구현.** 이 방식은 `server.py`의 기본 도구 6개 `file_info`·`hash_file`·`strings_extract`·`list_evidence`·`log_search`·`hexdump`에 적용된다 [1].
이 도구들은 공통 실행기 `_run_tool`로 운영체제 명령을 실행하고 표준 출력 문자열을 응답에 싣는다 [2].
명령이 0이 아닌 종료 코드로 끝나면 `_run_tool`은 표준 출력 뒤에 `[STDERR]:`와 표준 오류를 이어 붙인다 [2].
`file_info`는 `file -b`와 `stat`의 출력을, `hash_file`은 `md5sum`과 `sha256sum`의 출력을 제목 줄 아래에 바꾸지 않고 싣는다 [3].
`strings_extract`·`list_evidence`·`log_search`는 명령 출력을 그대로 싣고 줄 상한을 넘을 때만 앞부분을 남긴다 [1].
`hexdump`는 `xxd` 출력을 그대로 싣고 줄 상한 없이 읽을 바이트 수만 줄인다 [4].
메모리 도구는 Volatility가 실패하면 표준 오류의 앞 400~500자를 코드 블록에 담아 그대로 싣는다 [5].

모든 도구 함수는 반환형을 `str`로 선언하고 Markdown 글 하나를 돌려준다 [1].
MCP Python SDK 1.27.2의 FastMCP는 반환형이 `str`인 함수에 `result` 필드 하나짜리 출력 schema를 만든다 [6].
그래서 응답은 그 글을 담은 글 블록 하나와, 같은 글을 `result`에 담은 `structuredContent`로 나간다 [6].

### R01.02 구조화 파싱·필드 선택

**구현.** 이 방식은 Volatility 3를 실행하는 메모리 도구 7개와, 증거 파일을 서버 안 파서로 읽는 도구에 적용된다.
`_run_vol_plugin`은 Volatility를 JSON 렌더러 `-r json`으로 실행하고 표준 출력을 JSON 목록으로 읽어 `dict` 행만 남긴다 [7].
JSON 앞에 다른 글이 붙어 읽기에 실패하면 정규식으로 목록 부분을 다시 찾는다 [7].
`analyze_memory_processes`는 행에서 PID·PPID·프로세스 이름만 골라 표에 싣는다 [8].
`analyze_memory_network`는 주소·포트·프로토콜·상태·프로세스 이름을 골라 표에 싣고 inet 소켓이 아닌 행은 판정에서 뺀다 [9].
열 이름이 Volatility 버전마다 달라 두 도구는 여러 열 이름을 차례로 찾는다 [8][9].
`analyze_memory_malfind`는 PID·프로세스·시작 주소·끝 주소·보호 속성을 골라 싣는다 [10].
Volatility 3 2.28.0의 `linux.malware.malfind.Malfind`가 내는 `Path`·`Hexdump`·`Disasm` 열은 응답에 싣지 않는다 [10][11].

증거 파일을 읽는 도구는 정규식이나 JSON으로 줄을 필드로 나눈다.
`parse_auth_line`은 syslog 줄을 시각·호스트·서비스·PID·메시지로 나누고 sshd·sudo·useradd 같은 사건마다 사용자·IP·명령 같은 필드를 뽑는다 [12].
`parse_journal`은 `journalctl -o json` 줄에서 시각·unit·식별자·우선순위·메시지·UID·PID를 고른다 [13].
`parse_access_log`는 Combined Log Format 줄을 IP·시각·메서드·경로·상태·크기·referer·User-Agent로 나눈다 [14].
apt·dpkg·yum·pip 기록은 시각·동작·패키지 이름·버전으로 나눈다 [15].

### R01.03 형식 변환·건수 집계

**구현.** 이 방식은 서버가 파싱한 결과를 Markdown 표와 건수로 바꾸는 도구에 적용된다.
공통 함수 `emit_table`은 행 목록을 Markdown 표로 바꾸면서 칸 값의 `|`·백틱·줄바꿈을 바꿔 쓴다 [16].
`auth_summary`는 사건 종류마다 건수를 세고 실패한 로그인이 많은 IP 5개를 싣는다 [17].
`auth_failed_logins`는 실패 사건을 IP로 묶어 시도 수, 대상 사용자 수, 인증 방법별 건수, 처음과 마지막 줄 번호를 싣는다 [18].
`analyze_journal`·`analyze_nginx_access`·`analyze_package_logs`도 사건 종류, IP, 공격 표지, 패키지 동작마다 건수를 센다 [19].
`build_timeline`은 여러 기록의 사건을 시각·출처·행위자·동작·내용·위치 칸으로 맞춰 한 표로 합치고 시각 차례로 정렬한다 [20].
메모리 도구는 Volatility의 JSON 행을 Markdown 표와 건수로 바꾼다 [8][9].

일부 도구의 응답 제목은 도구가 읽은 입력 경로를 적고 메모리 도구의 일부 줄은 값을 만든 플러그인 이름을 적는다 [8][21].
그러나 응답이 서버가 가공한 결과라는 표시는 없다 [17][21].

**한계.** 파서가 형식에 맞지 않는 줄을 버리면 건수에 넣지 않고 버린 줄 수도 알리지 않는다.
`parse_auth_log`는 syslog 형식이 아닌 줄을 건너뛰고 `auth_summary`의 `Total events`는 읽힌 줄만 센다 [12][17].
`parse_access_log`는 형식이 맞지 않는 줄을, `parse_journal`은 JSON으로 읽히지 않는 줄을 같은 방식으로 건너뛴다 [13][14].

`auth_failed_logins`와 `auth_summary`는 sshd의 `Invalid user` 줄과 `Failed password` 줄을 모두 실패 사건으로 센다 [12][17][18].
sshd는 없는 계정으로 비밀번호 로그인을 시도하면 한 시도에 이 두 줄을 남긴다 [22].
그래서 없는 계정에 대한 시도는 응답의 시도 수 `Attempts`와 `Failed logins`에서 두 번씩 세어진다 [17][18][22].
`analyze_journal`의 `Failed auth attempts`와 `build_timeline`의 `login_failed` 사건도 두 줄을 따로 세어 같은 시도가 두 번 들어간다 [23].

`analyze_container_artifacts`는 `etc/kubernetes`를 하위 폴더까지 훑은 뒤 `etc/kubernetes/manifests`를 다시 훑는다 [24].
그래서 `manifests` 아래 파일은 두 번 검사되어 같은 발견사항이 두 번 실리고 `Findings` 수가 늘어난다 [24].

### R01.06 응답 항목 선별

**구현.** 이 방식은 `find_persistence`의 응답과 `build_timeline`의 사건 목록에 적용된다 [25][26].
`find_persistence`의 검사기는 의심 근거가 없는 지속성 파일도 심각도 `info`인 항목으로 만든다 [27].
응답을 만드는 `_format_findings`는 상세 목록에서 `info` 항목을 빼고 `high`·`medium` 항목이 하나도 없을 때만 `info` 항목 앞 10개의 경로를 싣는다 [25].
`build_timeline`은 journal 사건 가운데 식별자가 `sshd`·`sudo`·`useradd`·`kernel`·`systemd`인 것만 넣는다 [26].
auth.log 사건은 로그인 성공·실패, sudo, 계정 추가만 넣고 계정 삭제와 그룹 추가는 넣지 않는다 [28].
access log 사건은 시각을 ISO 8601로 바꾸지 못하면 빼고 bash 기록 항목은 `HISTTIMEFORMAT` 시각이 없으면 뺀다 [29].
`parse_dpkg_log`는 `status`·`trigproc`·`configure` 줄을 빼고 `install`·`remove`·`upgrade` 줄만 사건으로 만들어 `analyze_package_logs`와 `build_timeline`에 넘긴다 [30].
뺀 항목의 뜻은 바뀌지 않는다.

`find_persistence` 응답의 요약 줄은 `info`를 포함한 심각도별 건수를 싣는다 [25].
`build_timeline` 응답에는 뺀 사건의 수와 고른 규칙이 없다 [20][26].
`analyze_package_logs` 응답의 `Total events parsed`도 뺀 `dpkg` 줄을 세지 않는다 [30].

```python
    """Run a SIFT tool as a subprocess, capture output, never modify evidence."""

    # tests/harness/fault_injection_test.py exercise graceful degradation.

    if result.returncode != 0:
        output += f"\n[STDERR]: {result.stderr}"
    return output
```

```python
def _classify_processes(rows: list[dict]) -> tuple[list[dict], list[str]]:
    """Return (processes, anomalies)."""
    procs = []
    anomalies = []
    seen_pids: set[int] = set()
    for row in rows:
        pid = row.get("PID") or row.get("Pid")
        ppid = row.get("PPID") or row.get("Ppid")
        comm = row.get("COMM") or row.get("Comm") or row.get("Process") or "?"
        try:
            pid_i = int(pid) if pid is not None else None
            ppid_i = int(ppid) if ppid is not None else None
        except (TypeError, ValueError):
            pid_i = ppid_i = None
        proc_obj = {"pid": pid_i, "ppid": ppid_i, "comm": str(comm)}
        procs.append(proc_obj)
        if pid_i is not None:
            seen_pids.add(pid_i)
        if isinstance(comm, str) and comm.lower() in _SUSPICIOUS_PROCESS_NAMES:
            anomalies.append(f"PID {pid_i}: known-bad process name `{comm}`")

    # Process whose parent is missing from the snapshot (orphaned by a parent kill)
    for p in procs:
        if p["ppid"] is not None and p["ppid"] != 0 and p["ppid"] not in seen_pids:
            anomalies.append(
                f"PID {p['pid']} (`{p['comm']}`) has PPID={p['ppid']} not present in snapshot"
            )

    return procs, anomalies
```
