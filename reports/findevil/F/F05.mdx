# F05 발견사항·결론 근거 검증

### F05.02 근거 내용 대조

**구현.** 이 방식은 `finalize_report`가 `confidence`가 `confirmed`인 주장을 받는 경로와 `verify_finding` 도구에 적용된다 [1][2].
두 경로는 같은 검증 함수를 쓰고 주장이 가리키는 로그나 파일시스템 루트를 다시 읽어 주장의 값과 비교한다 [3][4].
주장의 `type`이 검증 함수가 있는 8가지 유형이면 `finalize_report`는 주장 객체의 최상위 필드를 그 유형의 검증 함수에 넘긴다 [1][3].
예를 들어 `brute_force_from_ip`는 인증 로그를 다시 파싱해 그 IP의 실패 줄 수가 `min_attempts` 이상이어야 `SUPPORTED`다 [4].
서버는 도구 출력을 저장하지 않으므로 검증 함수는 앞선 호출의 출력이 아니라 증거 파일을 다시 읽는다 [4].
인증 로그를 읽는 검증 함수는 auth 도구와 같은 파서 `parse_auth_log`가 만든 사건 목록을 주장의 값과 비교하고 로그 원문 줄과는 대조하지 않는다 [4][5][6].
`finalize_report`는 판정이 `SUPPORTED`가 아닌 확정 주장이 하나라도 있으면 마무리 전체를 `REJECTED`로 돌려준다 [1][7].
`SUPPORTED`이면 그 주장을 `[CONFIRMED ✓ verified]`와 첫 판정 이유를 붙여 받아들인 목록에 싣는다 [1].
도구 설명과 서버 지침은 `finalize_report`를 결론을 내는 유일한 경로로 두고 확정 주장은 이 검사를 통과해야 한다고 밝힌다 [8].
`inference`·`uncertain` 주장은 검증 없이 그 확신도로 목록에 싣는다 [1].
`verify_finding` 도구는 같은 판정과 이유를 응답과 호출 기록에 싣고 그 판정을 주장의 확정 여부에 쓰지 않는다 [2].

검증 함수가 없는 유형의 확정 주장은 `evidence` 인용이 비어 있지 않으면 `[CONFIRMED · cited]`로 받아들인다 [1].
이 경로는 인용한 근거가 서버 기록이나 증거에 있는지 대조하지 않는다 [1].

**한계.** 서버 지침은 `finalize_report`를 통과한 주장만 보고서에 확정으로 적으라고 안내하지만 IR 보고서는 클라이언트 모델이 쓰고 서버는 그 보고서를 받지 않는다 [8].
그래서 거부된 주장을 확정으로 적은 보고서나 `finalize_report`를 부르지 않고 쓴 보고서를 서버가 막지 않는다 [8].
주장의 `type`은 자유 문자열이다 [9].
같은 주장을 검증 함수가 없는 유형 이름으로 내면 인용 문자열만으로 확정된다 [1][9].
모순 규칙이 쓰는 부재 주장 유형 `no_failed_logins`·`persistence_empty`·`file_not_found`·`user_not_in_log`·`no_successful_login_from_ip`도 검증 함수가 없다 [3][10].
그래서 이 유형의 확정 주장은 인용 문자열만 있으면 `[CONFIRMED · cited]`로 받아들여진다 [1].
검증 함수는 주장의 `statement`를 읽지 않는다 [1].
그래서 주장 문장이 검증 인자보다 넓은 내용을 말해도 인자가 맞으면 받아들인다.
검증 기준값도 주장이 정한다.
`brute_force_from_ip`는 주장에 적은 `min_attempts`를 쓰고 값이 없으면 10을 쓴다 [4].
`persistence_mechanism_exists`는 주장한 분류에 `high` 발견사항이 하나라도 있으면 경로와 관계없이 `SUPPORTED`다 [11].
`successful_login_after_brute_force`는 그 IP의 실패와 성공이 로그에 모두 있는지만 보고 실패가 성공보다 앞서는지는 보지 않는다 [5].
`sudo_command_executed`는 `command_regex`가 빈 문자열이면 모든 sudo 명령에 맞는다 [12].
`webshell_upload_chain`은 `ip`·`path`를 주지 않으면 로그에 사슬이 하나라도 있을 때 `SUPPORTED`다 [13].
`package_installed`·`file_modified_in_window`·`persistence_mechanism_exists`는 증거 파일이나 폴더가 없어도 판단을 보류하지 않고 `CONTRADICTED`를 낸다 [14].
그래서 확인할 증거가 없는 주장도 반박된 주장으로 거부된다 [14][7].

### F05.05 제출 주장 간 모순 대조

**구현.** 이 방식은 `finalize_report`가 받은 주장 전체에 있다 [1][10].
서버는 확신도와 관계없이 받은 주장 전체에 `find_contradictions`와 같은 6가지 모순 규칙을 댄다 [1][10].
모순이 하나라도 있으면 마무리를 `REJECTED`로 돌려주고 모순 목록을 싣는다 [7].
규칙은 같은 로그 경로의 `brute_force_from_ip`와 `no_failed_logins`, 같은 IP의 확정 `compromise_verdict`와 `no_successful_login_from_ip`를 모순으로 본다 [10].
같은 분류의 `persistence_mechanism_exists`와 `persistence_empty`, 같은 이름의 `user_created`와 `user_not_in_log`, 같은 경로의 `file_modified_in_window`와 `file_not_found`도 모순으로 본다 [10].
서로 다른 `initial_access_vector` 주장이 둘 이상이면 근거와 관계없이 모순으로 본다 [10].
`find_contradictions` 도구를 따로 부르면 같은 규칙의 결과를 응답에만 싣고 확정 여부에 쓰지 않는다 [15].

**한계.** 규칙은 경로, IP, 이름 같은 필드 값을 문자열로 그대로 비교한다 [10].
그래서 같은 로그를 상대 경로와 절대 경로로 적은 두 주장은 모순으로 판정되지 않는다.

```python
def _read_auth_log(path: str) -> tuple[Path, list[AuthEvent]]:
    """Validate path, read file, parse events. Raises if path is unsafe."""
    validated = _validate_evidence_path(path)
    if not validated.exists():
        raise FileNotFoundError(f"File not found: {path}")
    if not validated.is_file():
        raise ValueError(f"Not a file: {path}")

    content = validated.read_text(errors="replace")
    return validated, parse_auth_log(content)
```

```python
def _parse_claims(json_str: str) -> tuple[list[Claim] | None, str | None]:
    try:
        raw = json.loads(json_str)
    except json.JSONDecodeError as e:
        return None, f"invalid JSON: {e}"
    if not isinstance(raw, list):
        return None, "expected JSON array of claim objects"
    claims: list[Claim] = []
    for i, item in enumerate(raw):
        if not isinstance(item, dict):
            return None, f"claim {i}: not an object"
        if "type" not in item:
            return None, f"claim {i}: missing 'type'"
        claims.append(
            Claim(id=str(item.get("id", f"c{i}")), type=item["type"], data=item)
        )
    return claims, None
```
