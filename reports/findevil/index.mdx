# findevil 원고

이 파일은 서버 개요다. 셀마다 이 폴더 아래 축 폴더의 `<축>/<셀ID>.mdx`에 쓴다.
셀과 상세 항목의 정의는 `matrix/cells/<축>/<셀ID>.mdx`를 따른다.
상세 항목마다 **구현**을 쓰고 그 방식이 적용되지 않는 경로나 조건이 있으면 **한계**를 따로 쓴다.
본문의 [번호]는 그 파일 끝 **근거**의 같은 번호를 가리킨다.

**기준 커밋.** [`d1a8d25`](https://github.com/marlyocat/findevil/tree/d1a8d25d9c8c05bd66881506cb1f12314ee7c5e1)(2026-06-07).
줄 번호는 모두 이 커밋 기준이다.

**범위.** `python -m findevil`이 실행하는 stdio MCP 서버(`src/findevil/`)를 본다.
`src/findevil/server.py`가 FastMCP 서버를 만들고 `src/findevil/tools/`의 모듈 14개를 불러와 도구를 붙이며, 모델에게 보이는 MCP 도구는 45개다.
서버는 MCP 리소스와 프롬프트를 두지 않고, 조사 절차는 FastMCP `instructions`(서버 지침)로 내놓는다.
서버가 읽는 증거는 환경변수 `FINDEVIL_EVIDENCE_DIR`(기본값 `./evidence`) 아래 폴더이고, 서버가 쓰는 기록은 `FINDEVIL_LOGS_DIR`(기본값 `./logs`) 아래 파일이다.
저장소의 `.mcp.json`(Claude Code 연결 설정)과 `CLAUDE.md`(Claude Code가 읽는 조사 지침)는 이 서버를 쓰는 클라이언트 구성이다.
`scripts/investigate.py`는 `claude -p`를 반복 실행하는 사용자 CLI이고, `scripts/capture_example_run.py`는 LLM 없이 도구 함수를 직접 불러 호출 기록 예시를 만드는 사용자 CLI다.
`scripts/extract_token_usage.py`와 `scripts/grade_example_reports.py`, `tests/`는 클라이언트 기록과 예시 보고서를 다루는 보조 도구와 시험 코드다.
상세가 클라이언트 쪽 방식을 묻는 경우(예: T02.01), 같은 저장소의 클라이언트나 사용자 CLI가 MCP 도구 호출을 기록하는 경우(L01.04), 같은 저장소의 CLI·클라이언트가 서버 기록으로 보고 산출물을 만드는 경우(F06)에만 이 구성을 구현으로 세고, 그 밖에는 원고에 사실로만 적는다.

**확인 방법.** 코드는 기준 커밋을 `git show`로 읽었다.
`samples/`와 `docs/example-reports/`의 예시 기록은 도구 동작을 확인하는 근거로 쓰지 않았다.
근거의 "실행 확인"은 WSL Ubuntu에서 Python 3.14.4와 MCP Python SDK 1.27.2(`mcp[cli]==1.27.2`)로 기준 커밋의 `src/`를 실행해 본 결과다.
도구 함수는 FastMCP의 `call_tool`로 직접 부르거나 stdio MCP 클라이언트로 서버를 시작해 불렀고, 메모리 도구는 Volatility 3 2.28.0을 설치하기 전과 뒤에 각각 불렀다.
증거 폴더에는 `samples/attack-scenario-01`과 임의의 4KiB 파일, 시험용으로 만든 심볼릭 링크를 두었다.
확인한 것은 다음과 같다.

- 도구 목록·서버 지침·`serverInfo`·도구 schema와 annotation 유무
- 증거 폴더 밖 경로 거부, `../`와 절대 경로를 받은 `build_timeline`의 `fs_subpath`, 증거 폴더 밖을 가리키는 심볼릭 링크를 따라 읽는 `find_persistence`
- `-f`로 시작하는 `log_search`의 `pattern`, 일치하는 줄이 없는 `log_search`의 응답과 호출 기록
- `hexdump`의 `length` 상한, `strings_extract`의 `encoding` 거부, `verify_finding`의 `claim_type` 거부와 JSON 배열 `params`
- `PATH`를 비운 `file_info`, 40초 동안 멈추는 시험용 `xxd`를 쓴 `hexdump`의 시간 제한
- `vol`이 없을 때와 있을 때의 메모리 도구 응답
- `/dev/full`을 가리키게 한 `audit.json`에 기록할 때의 응답, `baseline_create`의 `output_file`로 `audit.json`을 덮어쓴 뒤의 `get_audit_trail`·`assess_coverage`
- 증거 폴더 밖 기준 파일을 받은 `baseline_diff`
- 음수 `length`를 받은 `xxd -l`과 NUL 바이트가 든 파일에 대한 `grep -n -i -C3 -E`의 출력과 종료 코드
- 명령 출력에 UTF-8이 아닌 바이트가 있을 때 `subprocess.run(text=True)`가 내는 `UnicodeDecodeError`와 그 호출의 응답·호출 기록

**외부 도구 버전 기준.** 서버는 외부 도구 버전을 고정하지 않는다.
`pyproject.toml`은 의존성으로 `mcp[cli]>=1.0.0`만 적고, README는 SANS SIFT Workstation이나 Ubuntu 22.04 이상과 Python 3.11 이상을 전제한다.
메모리 분석 도구는 `docs/accuracy-report.md`가 findevil venv에 `pip install volatility3`로 설치해 확인했다고 적은 Volatility 3 2.28.0(PyPI 공개 2026-04-30)을 기준으로 삼는다.
Python 표준 라이브러리 동작은 README가 설치 단계에서 `python3.12-venv`를 쓰므로 CPython 3.12.3(Ubuntu 24.04 패키지 버전)의 소스로 확인한다.
MCP Python SDK는 `>=1.0.0` 범위에서 기준 커밋 시각(2026-06-07 06:38Z) 전 마지막 정식 릴리스인 1.27.2(PyPI 공개 2026-05-29)를 기준으로 삼는다.
`file`·`stat`·`ls`·`grep`·`strings`·`xxd`·`md5sum`·`sha256sum`은 서버가 인자 목록으로 실행하는 운영체제 명령이다.
`grep`이 고른 줄이 없을 때 종료 상태 1로 끝나는 동작은 GNU grep 설명서와 실행 확인으로 확인했다.
`grep`이 이진으로 판정한 파일의 일치 줄을 표준 출력에 싣지 않는 동작과 `xxd -l`에 음수를 주면 파일 전체를 출력하는 동작은 WSL의 GNU grep 3.12와 xxd 2025-11-26으로 확인했다.
그 밖에는 이 명령의 버전에 기대는 판단을 하지 않는다.
서버가 해석하는 sshd_config의 규칙(첫 값 우선, 지시어 대소문자 무시)은 Ubuntu 24.04의 OpenSSH 9.6p1 설명서(`sshd_config.5`)로 확인한다.

**바뀔 수 있는 것.** 범위와 외부 도구 버전 기준은 조사하며 맞지 않는 곳이 나오면 검토를 거쳐 바꾼다.
