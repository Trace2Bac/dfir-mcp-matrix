# E04 분석 입력 준비

### E04.02 선택 추출

**구현.** 이 방식은 파일시스템 루트를 받아 그 아래에서 정해 둔 경로나 이름으로 파일을 고르는 도구에 적용된다.
파일시스템 루트는 마운트한 디스크 이미지나 수집물의 루트 폴더이고 증거 폴더 안에 있어야 한다 [1].
이 도구들은 받은 루트 아래에서 정해 둔 상대 경로나 이름 패턴으로 파일을 골라 제자리에서 읽고 사본을 만들지 않는다 [2][3][4].
`find_persistence`는 `etc/crontab`·`etc/cron.d/*`·`var/spool/cron` 아래, systemd unit 폴더, `root/.ssh/authorized_keys`·`home/*/.ssh/authorized_keys` 같은 경로를 고른다 [2].
`analyze_package_logs`는 `var/log/apt/history.log`와 그 `.1`, `var/log/dpkg.log`와 그 `.1`, `var/log/yum.log`·`var/log/dnf.log`, `root`와 `home/*`의 pip 로그를 고른다 [3].
`find_webshells`는 `var/www`·`srv/http`·`home/*/public_html` 같은 웹 루트 7곳 아래에서 확장자가 `.php`·`.jsp`·`.cgi` 같은 실행 확장자인 파일만 고른다 [4].
`build_timeline`은 받은 사건 폴더 바로 아래의 `auth.log`·`journal.jsonl`·`access.log`와 `fs_subpath` 아래의 패키지 로그·pip 로그·`.bash_history`를 고른다 [5][6].
`find_shell_histories`, `verify_package_integrity`, `analyze_container_artifacts`, `find_ai_signatures`, `baseline_create`도 같은 방식으로 루트 아래 정해 둔 경로를 고른다 [7].
`correlate_memory_and_disk`는 받은 `fs_root` 아래에서 `etc/modules`, `etc/modprobe.d`의 `.conf`, `lib/modules/*/extra`의 `.ko`만 고른다 [8].
`find_recent_changes`와 `find_timestamp_anomalies`는 파일시스템 루트를 받지만 그 아래 파일을 고르지 않고 모두 훑는다 [9].

파일 하나를 받는 도구와 메모리 도구는 받은 경로를 그대로 쓰고 입력을 따로 준비하지 않는다.
메모리 도구는 받은 덤프 경로를 그대로 Volatility 3의 `-f` 인자로 넘긴다 [10].
서버에는 디스크 이미지를 마운트하거나 보관 파일을 풀거나 작업 사본을 만드는 코드가 없다.
README는 사용자가 예시 사건을 `cp -r`로 증거 폴더에 복사하게 한다 [11].

**한계.** `analyze_package_logs`의 설명은 apt `term.log`도 읽는다고 적지만 코드는 `term.log`를 고르지 않는다 [3].
이 도구는 회전된 로그를 `.1` 하나만 읽고 `.2.gz` 같은 압축 회전 로그는 읽지 않으며 응답에 그 사실을 적지 않는다 [3].
`build_timeline`의 설명은 `auth.log`·`access.log`·`.bash_history`를 증거 루트 아래 어디에 있든 찾는다고 적는다 [5].
코드는 `auth.log`·`access.log`를 받은 사건 폴더 바로 아래에서만 찾고 `.bash_history`는 `fs_subpath`의 `root`와 `home/*` 바로 아래에서만 찾는다 [6].
그래서 `fs/var/log/auth.log`처럼 파일시스템 안에 있는 auth 로그와 웹 로그는 이 도구의 입력에 포함되지 않는다 [6].
지속성 스캐너는 파일마다 앞 64 KiB만 읽는다 [12].
`find_ai_signatures`는 API 참조 검사에서 파일 앞 128 KiB, 스크립트 검사에서 32 KiB, 셸 기록 속도 검사에서 64 KiB를 읽고 JSONL 검사에서는 앞 8 KiB의 처음 10줄만 본다 [12][13].
`find_ai_signatures`는 1 MiB보다 큰 설정 파일과 5 MB보다 큰 JSONL은 건너뛴다 [12].
이렇게 줄이거나 건너뛴 사실은 응답에 적지 않는다 [12].

### E04.05 추출·생략 범위 기록

**구현.** 이 방식은 고른 입력의 범위를 응답에 싣는 `find_webshells`·`verify_package_integrity`·`find_shell_histories`·`build_timeline`·`analyze_package_logs`에 적용된다 [14][15][16][17][18].
`find_webshells`는 훑은 웹 루트 수와 훑은 실행 확장자 파일 수를 싣는다 [14].
`verify_package_integrity`는 읽은 패키지 수, 대조한 파일 수, dpkg가 기록했지만 디스크에 없는 파일 수를 싣는다 [15].
`find_shell_histories`는 찾은 history 파일마다 경로·소유자·크기를 표로 싣는다 [16].
`build_timeline`은 사건을 뽑은 출처 종류를 `Sources`로 싣고 사건마다 파일 이름과 줄 번호를 붙인다 [17].
`analyze_package_logs`는 사건을 뽑은 로그 종류를 `Sources`로 싣는다 [18].

`find_persistence`는 고른 파일의 목록을 싣지 않는다 [19].
수상한 점이 없는 `info` 등급 파일은 `high`·`medium` 발견사항이 하나도 없을 때만 10개까지 적는다 [19].

**한계.** `find_webshells`는 파일마다 앞 64 KiB만 대조하고 읽지 못한 파일도 훑은 파일 수에 센다 [4][14].
`verify_package_integrity`는 MD5를 계산하지 못한 파일도 대조한 파일 수에 세고 읽지 못한 `.md5sums` 파일은 세지 않고 건너뛴다 [20].
`build_timeline`은 파일시스템 수정 시각 사건을 500개에서 멈추고 이 사실을 응답에 적지 않는다 [21].

```python
def _scan_file_for_webshell(p: Path) -> list[str]:
    try:
        data = p.read_bytes()[:65536]
    except (OSError, PermissionError):
        return []
    text = data.decode(errors="replace")
    reasons = []
    for pat, label in _WEBSHELL_PATTERNS:
        if pat.search(text):
            reasons.append(label)
    return list(dict.fromkeys(reasons))
```

```python
def _events_from_filesystem(
    fs_root: Path, since_ts: float, until_ts: float, max_files: int = 500
) -> list[TimelineEvent]:
    out: list[TimelineEvent] = []
    count = 0
    for p in fs_root.rglob("*"):
        try:
            if not p.is_file():
                continue
            mt = p.stat().st_mtime
            if since_ts <= mt <= until_ts:
                iso = datetime.fromtimestamp(mt, tz=timezone.utc).isoformat()
                out.append(TimelineEvent(
                    iso, "filesystem",
                    actor="?",
                    action="fs_modify",
                    detail=f"mtime modified: {p.relative_to(fs_root)}",
                    provenance=f"fs:{p.relative_to(fs_root)}",
                ))
                count += 1
                if count >= max_files:
                    break
        except (OSError, PermissionError):
            continue
    return out
```
