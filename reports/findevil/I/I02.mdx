# I02 분석 도구 통신 차단

### 미구현

**판단.** 서버는 메모리 분석 도구 7개에서 Volatility 3을 실행한다.
서버는 Volatility 3의 통신을 끄는 옵션이나 장치를 두지 않는다.
서버가 만드는 명령은 실행 파일, `-q`, `-f <덤프>`, `-r json`, 플러그인 이름뿐이고 `--offline`을 넣지 않는다 [1].
실행 파일은 환경변수 `FINDEVIL_VOL`이 가리키는 파일이나 `PATH`·venv에서 찾은 `vol`이다 [2].

Volatility 3 2.28.0에서 온라인 여부를 정하는 전역 값 `OFFLINE`의 기본값은 거짓이다 [3].
원격 심볼 목록 주소 `REMOTE_ISF_URL`의 기본값은 `None`이다 [3].
원격 심볼 목록 조회는 `OFFLINE`이 꺼져 있고 원격 목록 주소가 정해졌을 때 일어난다 [4].
서버는 원격 목록 주소를 정하는 `-u`를 넘기지 않는다 [1].
Volatility 3 2.28.0은 사용자 설정 폴더(`~/.config/volatility3`)의 `vol.json`을 읽어 그 값을 인자 기본값으로 쓴다 [5].
그래서 이 파일에 `remote_isf_url`이 있으면 서버가 실행한 Volatility도 원격 심볼 목록을 조회한다 [5][4].
`--offline`을 주면 이 값보다 먼저 적용되어 원격 목록 주소를 정하지 않는다 [6].
Volatility 3 2.28.0의 오프라인 처리기는 `OFFLINE`이 켜졌을 때만 http·https 요청을 막는다 [7].

서버가 실행하는 나머지 분석 도구는 `file`·`stat`·`strings`·`xxd`·`md5sum`·`sha256sum`·`ls`·`grep`이다 [8].
서버는 이 명령에도 통신을 끄는 옵션을 붙이지 않는다 [8].
자식 프로세스의 네트워크를 끊는 다른 장치도 저장소에 없다 [8].

```python
def _resolve_vol_bin() -> str:
    """Find the Volatility 3 entrypoint.

    Order of preference:
      1. FINDEVIL_VOL env var (explicit override)
      2. `vol` / `vol.py` on $PATH
      3. The findevil venv's own bin/ (so installs into the project venv work
         even when the venv is not activated by the calling shell)
      4. Fall back to "vol" so the no-such-binary error message is clean
    """
    override = os.environ.get("FINDEVIL_VOL")
    if override and Path(override).is_file():
        return override
    for name in ("vol", "vol.py"):
        found = shutil.which(name)
        if found:
            return found
    # Note: do NOT call .resolve() here — venv pythons are typically
    # symlinks to the system interpreter, and resolving that symlink
    # leaks back to the system bin dir where `vol` likely isn't.
    venv_bin = Path(sys.executable).parent
    for name in ("vol", "vol.py"):
        cand = venv_bin / name
        if cand.is_file():
            return str(cand)
    return "vol"
```
