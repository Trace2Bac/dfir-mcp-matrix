# P01 분석 방법 적합성 확인

### 미구현

**판단.** 서버는 증거 형식이나 OS를 판별하지 않고 고른 플러그인이 증거에 맞는지 대조하지 않는다.
증거 파일을 열 때 서버가 확인하는 것은 파일이 있는지, 크기, 수정 시각, SHA-256뿐이다 [1].
실행할 수 있는 플러그인은 모두 Windows 메모리용 `windows.*` 플러그인 9개이고 증거가 Windows 메모리 이미지인지 보지 않고 실행한다 [2][3].
도구 설명과 `evidence_metadata`의 도구 요약은 각 플러그인이 무엇을 보여 주는지 안내할 뿐이다 [2][4].

메모리 이미지의 계층 구성과 심볼은 Volatility 3이 스스로 찾는다.
맞지 않는 입력이면 Volatility가 요구 조건을 채우지 못했다는 글과 함께 종료 코드 1로 끝나고 서버는 그 출력과 종료 코드를 그대로 돌려준다 [3][5].
메모리 이미지가 아닌 합성 파일로 `vol_pslist`를 부르면 `exit_code` 1과 `Unsatisfied requirement` 글이 담긴 정상 응답이 돌아온다 [5].

증거 후보를 확장자로 고르는 코드는 사용자 CLI `siftpp-download-case`에만 있다 [6].
이 CLI는 내려받은 압축을 푼 뒤 메모리 이미지 확장자를 가진 파일을 크기순으로 후보로 출력하고 서버는 이 결과를 읽지 않는다 [6].

def memory_candidates(paths: list[Path]) -> list[Path]:
    candidates = [p for p in paths if p.suffix.lower() in MEMORY_SUFFIXES]
    if candidates:
        return sorted(candidates, key=lambda p: p.stat().st_size, reverse=True)
    return sorted(paths, key=lambda p: p.stat().st_size, reverse=True)
