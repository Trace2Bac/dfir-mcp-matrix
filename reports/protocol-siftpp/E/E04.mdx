# E04 분석 입력 준비

### 미구현

**판단.** 서버는 증거 파일을 받지만 분석 입력을 따로 준비하지 않는다.
Volatility 도구 9개는 환경변수로 받은 증거 파일 경로를 그대로 `-f` 뒤에 넣어 Volatility 3에 넘긴다 [1].
서버는 증거를 복사하거나 형식을 바꾸지 않고 부속 자료를 찾지도 않는다 [1][2].
메모리 이미지 형식을 알아보고 계층을 쌓는 일은 Volatility 3이 스스로 한다.

압축을 푸는 코드는 사용자 CLI `siftpp-download-case`에 있다 [3].
이 CLI는 SANS 사례 압축 파일을 내려받아 `py7zr`로 풀고 풀린 파일 목록을 `case_manifest.json`에 적는다 [3].
서버는 이 CLI의 결과를 읽지 않고 사용자가 풀린 파일 하나를 `--evidence`나 `SIFTPP_EVIDENCE`로 넘긴다 [2][4].

def _build_runner() -> VolatilityRunner:
    evidence = os.environ.get("SIFTPP_EVIDENCE")
    if not evidence:
        raise RuntimeError("Set SIFTPP_EVIDENCE to the path of the memory image")
    audit = AuditLogger(os.environ.get("SIFTPP_AUDIT_LOG", "analysis/audit.jsonl"))
    runner = VolatilityRunner(
        guard=EvidenceGuard.open(evidence),
        audit=audit,
        agent=os.environ.get("SIFTPP_AGENT", "investigator"),
        offline=os.environ.get("SIFTPP_VOL_OFFLINE") == "1",
    )
    runner.session_start()
    return runner
```

def _server_params(evidence: Path, server_audit: Path, offline: bool) -> StdioServerParameters:
    env = {
        **os.environ,
        "SIFTPP_EVIDENCE": str(evidence),
        "SIFTPP_AUDIT_LOG": str(server_audit),
    }
    if offline:
        env["SIFTPP_VOL_OFFLINE"] = "1"
    return StdioServerParameters(
        command=sys.executable,
        args=["-m", "protocol_siftpp.mcp_server.server"],
        env=env,
    )
```
