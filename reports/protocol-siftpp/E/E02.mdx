# E02 증거 무결성 검증

### E02.01 등록 시 기준값 자동 계산

**구현.** 서버는 처음 도구를 부를 때 증거 파일을 열고 모델의 요청 없이 파일 전체의 SHA-256을 계산한다 [1][2].
해시 범위는 증거 파일 하나의 처음부터 끝까지이고 1MiB씩 읽는다 [2].
계산한 값은 `EvidenceGuard.sha256`에 기준값으로 보관하고 같은 때 크기와 수정 시각(`st_mtime_ns`)도 함께 보관한다 [2].
기준값은 호출 기록의 `evidence_opened`에 남고 `evidence_metadata`의 `sha256`과 Volatility 도구 응답의 `evidence_sha256`으로 모델에게 간다 [3][4][5].

서버는 사용자나 수집 도구가 남긴 해시를 받지 않는다 [1].
그래서 서버를 시작하기 전에 바뀐 증거는 바뀐 상태가 기준값이 된다.
같은 저장소의 사용자 CLI `siftpp-download-case`는 표본 사건 압축 파일의 SHA-256을 `case_manifest.json`에 적고 압축에서 푼 파일은 경로와 크기만 적는다 [6].
보조 스크립트 `tools/linux_volcheck.sh`는 증거 파일을 다른 폴더로 복사한 뒤 복사본의 SHA-256과 스크립트에 적은 기대값을 나란히 출력하고 두 값을 비교하지 않는다 [7].
서버는 이 두 값을 읽지 않는다 [1].

**한계.** `evidence_metadata`는 보관한 기준값을 다시 계산하지 않고 `sha256`으로 돌려주며 응답에 그 사실을 표시하지 않는다 [4].
증거 파일이 바뀐 뒤에 불러도 처음 계산한 해시를 그대로 돌려준다 [8].
Volatility 도구 응답의 `evidence_sha256`도 실행 때 계산한 값이 아니라 보관한 기준값이다 [5].
`evidence_metadata`의 설명은 `sha256`을 수집 시점("acquisition")의 해시라고 적지만 실제로는 서버가 처음 증거를 열 때 계산한 해시다 [4][2].

### E02.03 도구 호출 중 자동 검증

**구현.** 이 방식은 Volatility 도구 9개에 적용된다 [5].
서버는 Volatility를 실행하기 직전과 끝난 직후에 증거 파일의 크기와 수정 시각을 다시 읽어 처음 연 때의 값과 비교한다 [5][9].
해시는 다시 계산하지 않는다 [9].
그래서 크기와 수정 시각을 그대로 둔 채 내용만 바꾸면 이 비교를 통과한다 [9].
기준값은 처음 연 때 보관한 크기와 `st_mtime_ns`다 [2].
둘 중 하나라도 다르면 `IntegrityError`를 내고 호출을 끝낸다 [9].
`evidence_metadata`와 `verify_evidence_integrity`는 이 비교를 하지 않는다 [4][10].

**한계.** Volatility 도구 응답은 다시 계산하지 않은 `evidence_sha256`을 늘 `true`인 `integrity_ok`와 함께 싣는다 [5].
`integrity_ok`는 서버 코드에 적은 상수라 크기·수정 시각 비교만 통과했다는 뜻인데 응답에는 무엇을 비교했는지 표시하지 않는다 [5].
합성 증거의 첫 바이트를 바꾸고 수정 시각을 되돌린 뒤 `vol_info`를 부르면 처음 계산한 해시와 `integrity_ok: true`를 담은 응답이 돌아온다 [8].
모듈 주석은 Volatility를 실행할 때마다 증거 파일이 실행 전후에 바이트 단위로 같은지("byte-identical") 확인한다고 적는다 [11].
그러나 실제로는 크기와 수정 시각만 비교한다 [9].

### E02.04 도구를 요청해 검증

**구현.** 모델이 `verify_evidence_integrity`를 부르면 서버는 증거 파일 전체의 SHA-256을 다시 계산해 기준값과 비교한다 [10].
기준값은 서버가 처음 증거를 연 때 계산한 해시다 [2][10].
응답은 경로, `sha256_before`(기준값), `sha256_after`(다시 계산한 값), 두 값이 같은지 `unchanged`를 싣는다 [10].
비교 결과는 호출 기록의 `evidence_integrity` 항목에도 같은 값으로 남는다 [12].
크기와 수정 시각을 그대로 둔 내용 변경은 이 도구로 드러난다 [8].
기준값을 다시 시작할 때마다 새로 계산하므로 서버 실행 사이에 바뀐 증거는 이 도구로 드러나지 않는다.

서버 프로세스에서 처음 부른 도구가 `verify_evidence_integrity`이면 기준값 계산과 재계산이 같은 호출 안에서 잇달아 실행되므로 `unchanged`는 `true`가 된다 [1][2][10][13].
등록하지 않은 도구 이름으로 부르면 FastMCP가 도구 함수를 부르기 전에 `Unknown tool` 오류로 거부하므로 서버는 증거를 열지 않는다 [14].
사용자 CLI `siftpp-spoliation-test`는 등록하지 않은 도구 이름 14개만 부른 뒤 이 도구를 부르므로 이 경우에 해당한다 [15].
`siftpp-verify`와 `siftpp-gui`도 새 서버 프로세스를 실행해 같은 검사 함수 `assess_spoliation`을 부른다 [16].

`siftpp-investigate`는 조사를 끝낼 때 이 도구를 부르고 결과를 보고서 요약과 기록 `run_end`에 싣는다 [17].

**한계.** 해시 비교가 어긋나도 서버는 `unchanged: false`를 담은 정상 응답을 돌려주고 기록에 같은 값을 남길 뿐 이후 호출을 막지 않는다 [10][12].
크기와 수정 시각이 그대로인 내용 변경이면 `unchanged: false`가 나온 뒤에도 Volatility 도구가 그대로 실행되고 `integrity_ok: true`를 돌려준다 [8].

### E02.05 불일치 시 중단·경고

**구현.** 이 방식은 도구 호출 중의 크기·수정 시각 비교에 적용된다.
비교가 어긋나면 서버는 `IntegrityError`를 내고 FastMCP가 이를 `isError` 응답으로 돌려준다 [9][18].
오류 문구는 `Evidence changed during analysis: <경로>`다 [9][8].
기준값은 바뀌지 않으므로 그 뒤의 모든 Volatility 도구 호출도 같은 오류로 실행 전에 끝난다 [2][9].
실행이 끝난 뒤의 비교에서 어긋나면 이미 받은 Volatility 출력을 버리고 호출 기록 항목도 남기지 않는다 [9].
이 오류는 응답으로만 알리고 호출 기록에는 남지 않는다 [9].
`verify_evidence_integrity`의 해시 비교가 어긋난 경우는 값만 돌려준다 [10].

```python
    @classmethod
    def open(cls, path: str | Path) -> "EvidenceGuard":
        p = Path(path)
        if not p.is_file():
            raise FileNotFoundError(f"Evidence file not found: {p}")
        g = cls(path=p)
        st = p.stat()
        g.size = st.st_size
        g._mtime_ns = st.st_mtime_ns
        g.sha256 = g.full_sha256()  # acquisition hash (chain of custody)
        return g

    def full_sha256(self) -> str:
        h = hashlib.sha256()
        with self.path.open("rb") as fh:
            for chunk in iter(lambda: fh.read(1 << 20), b""):
                h.update(chunk)
        return h.hexdigest()
```

```python
async def assess_spoliation(mcp: Any, *, attempts=DESTRUCTIVE_ATTEMPTS) -> dict[str, Any]:
    """Probe an (already-connected) MCP bridge; return a structured pass/fail report."""
    surface = [{"tool": t["name"], "destructive": _looks_destructive(t["name"])}
               for t in mcp.anthropic_tools]

    results = []
    for name, args in attempts:
        try:
            res = await mcp.call(name, args)
            refused = _refused(res)
            detail = (res.get("result_text") or json.dumps(res.get("result")) or "")[:160]
        except Exception as exc:  # unknown tool -> server raises -> refused
            refused = True
            detail = f"{type(exc).__name__}: {str(exc)[:140]}"
        results.append({"attempt": name, "args": args, "refused": refused, "detail": detail})

    try:
        integrity = await mcp.call("verify_evidence_integrity", {})
    except Exception as exc:
        integrity = {"unchanged": None, "error": str(exc)}
```
