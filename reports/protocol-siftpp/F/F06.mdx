# F06 보고 산출물 구성

### F06.01 증거·환경 manifest 포함

**구현.** 이 방식은 사용자가 `siftpp-investigate`를 실행해야 만들어지는 `report.json`·`report.md`와 사용자가 `siftpp-report`를 실행해야 만들어지는 `report.html`에 있다 [1][2].
MCP 도구에는 보고 산출물을 만드는 도구가 없다 [3].
보고서는 서버 기록 파일을 읽지 않고 조사 중 받은 서버 응답에서 서버 기록과 같은 값을 옮긴다 [4][5].
`report.html`은 사용자 CLI `siftpp-report`가 `report.json`과 클라이언트 기록 `audit.jsonl`을 읽어 만든다 [2].
다른 MCP 클라이언트로 서버를 쓰면 이 보고서는 만들어지지 않는다 [3][6].
클라이언트는 조사를 시작할 때 서버의 `evidence_metadata`를 불러 증거 경로와 SHA-256을 받고 이를 보고서의 `evidence_path`·`evidence_sha256`에 싣는다 [7].
`report.md`와 `report.html`도 이 두 값을 싣는다 [1][2].
증거 크기, 서버·Volatility·모델의 이름과 버전은 보고서에 없다 [7][8].

**한계.** 클라이언트는 `evidence_metadata` 호출이 실패해도 조사를 계속한다 [7][9].
MCP 클라이언트 다리는 JSON으로 읽히지 않는 오류 응답을 `result_text`·`exit_code`만 담은 값으로 돌려준다 [9].
이때 보고서의 `evidence_path`는 `unknown`, `evidence_sha256`은 빈 문자열이 된다 [7].

### F06.03 발견사항과 근거 링크 포함

**구현.** 이 방식은 사용자가 `siftpp-investigate`를 실행해야 만들어지는 `report.json`·`report.md`와 `siftpp-report`를 실행해야 만들어지는 `report.html`에 있다 [1][2].
`report.json`은 발견사항마다 근거 `evidence` 목록을 싣고 근거마다 도구 이름, 실행한 인자 배열, 출력 앞 400자, 출력 SHA-256, 바이트 수, 시각을 담는다 [8][10].
`report.md`와 `report.html`은 근거마다 도구 이름과 출력 SHA-256 앞 16자만 싣는다 [1][2].
출력 SHA-256은 클라이언트 기록과 서버 기록의 같은 호출 항목에도 남으므로 이 값으로 기록 항목을 찾는다 [4][5].
보고서에 기록 항목의 `seq`나 기록 파일로 가는 연결은 없다 [1][2].

**한계.** 근거는 발견사항을 낼 때 모델이 적은 도구 이름마다 그 도구에서 출력 해시가 있는 가장 마지막 호출 하나로 채운다 [10][4].
같은 도구를 다른 `pid`로 여러 번 불렀으면 모델이 근거로 삼은 호출이 아니라 마지막 호출이 근거로 실린다 [10].
출력 해시가 있는 호출이 없는 도구 이름(아직 부르지 않았거나 `isError`로 끝난 호출만 있는 이름)은 알리지 않고 빠진다 [10][4][9].
서버는 종료 코드가 0이 아닌 실행에도 표준 출력의 해시를 돌려주므로 실패한 실행이 근거로 실릴 수 있다 [11][4].
Skeptic이 검토하며 다시 부른 도구 호출은 검토하는 발견사항의 근거에 더해지지 않는다 [12].
그러나 그 호출도 도구별 호출 목록에 쌓이므로 재조사 차례에 낸 발견사항에는 Skeptic의 호출이 근거로 붙을 수 있다 [4][12].

### F06.04 검증·한계 포함

**구현.** 이 방식은 사용자가 `siftpp-investigate`를 실행해야 만들어지는 `report.json`·`report.md`와 `siftpp-report`를 실행해야 만들어지는 `report.html`에 있다 [1][2].
보고서 요약은 확정한 발견사항 수, 전체 발견사항 수, 재조사 차례 수, 증거 해시 재대조 결과를 담는다 [7].
재대조 결과는 조사 끝에 부른 `verify_evidence_integrity`의 `unchanged`가 참이면 `verified`, 아니면 `FAILED`다 [7].
발견사항마다 Skeptic 판정의 이유가 실리고 `report.json`에는 반증하려고 확인한 내용 `refutation_attempt`도 실린다 [1][8].
`report.html`은 클라이언트 기록 `audit.jsonl`의 해시 체인 검증 결과와 항목 수, 사건 종류별 개수를 싣는다 [2].
서버 기록 `mcp-server.jsonl`의 체인 검증 결과는 어느 보고서에도 없다 [2][1].
재대조의 기준값은 서버가 그 실행에서 처음 증거를 연 때의 해시다.
Investigator와 Skeptic의 차례는 모델 응답의 `stop_reason`이 `tool_use`가 아니거나 모델과 도구 사이의 왕복 24회를 다 쓰면 끝난다 [13].
보고서는 차례가 둘 가운데 어느 쪽으로 끝났는지와 `stop_reason` 값을 싣지 않는다 [7][8].
`stop_reason`은 클라이언트 기록 `model_call`에만 남는다 [13].

**한계.** 조사 끝의 `verify_evidence_integrity` 호출이 오류로 끝나면 MCP 클라이언트 다리는 `unchanged`가 없는 값을 돌려준다 [9].
이때 요약은 대조하지 못한 것과 해시가 달라진 것을 가리지 않고 `evidence integrity FAILED`로 적는다 [7].

`siftpp-investigate`는 같은 `--out`으로 다시 실행하면 앞 실행의 클라이언트 기록 `audit.jsonl`에 이어 쓴다 [14].
`siftpp-report`는 그 파일의 모든 항목을 세므로 `report.html`의 항목 수와 `model_call`·`tool_call` 개수에는 앞 실행의 항목이 함께 들어간다 [2].

### F06.05 내보내기

**구현.** 사용자가 `siftpp-investigate`를 실행하면 조사가 끝난 뒤 출력 폴더에 `report.json`과 `report.md`가 쓰인다 [6].
출력 폴더는 `--out`으로 정하고 없으면 `analysis/<사건 ID>`다 [6].
클라이언트는 `Orchestrator.run`이 값을 돌려준 뒤에만 두 파일을 쓴다 [15].
클라이언트 오케스트레이터 `orchestrator.py`에서 예외를 처리하는 곳은 `mcp.call`, `Severity` 변환, `FindingStatus` 변환 세 곳이고 명령 본문 `_run`에는 없다 [16].
그래서 모델 API 호출이나 `submit_finding`·`submit_review`의 인자를 `Finding`·`SkepticReview`로 바꾸는 단계에서 예외가 나면 명령은 두 파일을 쓰지 않고 끝난다 [15][16].
그때까지 받은 발견사항은 클라이언트 기록 `finding_submitted`에만 남는다 [16].
`siftpp-report --run <실행 폴더>`는 그 폴더의 `report.json`과 `audit.jsonl`로 외부 자원 없는 HTML 파일 하나를 쓴다 [2].
`siftpp-gui`는 `docs/examples/`와 `analysis/` 아래 실행 폴더의 같은 HTML을 웹으로 보여 준다 [17].

### F06.07 판단의 확정 상태 표시

**구현.** 이 방식은 사용자가 `siftpp-investigate`를 실행해야 만들어지는 `report.json`·`report.md`와 `siftpp-report`를 실행해야 만들어지는 `report.html`에 있다 [1][2].
발견사항은 Skeptic 판정에 따라 `confirmed`·`inferred`·`refuted`·`draft`로 나뉘어 실린다 [1][2].
`report.md`는 이 차례로 상태마다 `## <상태> (<개수>)` 소제목을 두고 그 아래에 발견사항을 싣는다 [1].
`report.html`도 같은 차례로 상태마다 절을 나누고 발견사항 카드마다 상태 표시를 붙인다 [2].
`report.html`의 통계 칸은 `confirmed`·`inferred`·`refuted` 발견사항 수를 싣는다 [2].
`report.json`은 발견사항마다 상태 `status`와 Skeptic 판정 `review`를 싣는다 [8].
상태는 Skeptic 모델이 `submit_review`로 낸 판정 값이다 [12].
Skeptic이 판정을 내지 않으면 클라이언트가 상태를 `inferred`로 정하고 판정을 받지 못했다는 문구를 판정 이유로 싣는다 [18].
클라이언트는 차례가 끝난 뒤 `submit_review` 호출이 있었는지만 보므로 왕복 24회를 다 써서 끝난 Skeptic의 차례도 같은 상태와 같은 문구로 실린다 [18][13].
조사 끝에 아직 검토하지 않은 발견사항을 모두 검토하므로 끝까지 실행한 조사의 보고서에는 `draft` 상태가 남지 않는다 [19].
재조사에서 다시 낸 주장은 새 발견사항으로 실리고 앞 발견사항은 앞 상태 그대로 함께 실린다 [19].
상태 값마다의 뜻은 어느 보고서에도 적지 않는다 [1][2].
`report.html`의 바닥글은 발견사항의 상태를 Skeptic이 정한다고만 적는다 [20].

**한계.** `report.md`는 `claim`과 Skeptic 판정 이유 `rationale`의 줄바꿈과 Markdown 문법을 바꾸지 않고 넣는다 [1].
그래서 값에 줄바꿈과 Markdown 제목 표시가 들어 있으면 상태별 소제목과 같은 형태의 줄이 발견사항 항목 안에 들어간다 [1].
`report.html`은 같은 값을 `html.escape`로 바꿔 넣는다 [21].

```python
def render_markdown(report: CaseReport) -> str:
    order = [FindingStatus.confirmed, FindingStatus.inferred, FindingStatus.refuted, FindingStatus.draft]
    lines = [
        f"# Incident Report — {report.case_id}",
        "",
        f"- Evidence: `{report.evidence_path}`",
        f"- Evidence sha256: `{report.evidence_sha256}`",
        f"- Self-correction iterations: {report.iterations_run}",
        f"- Summary: {report.summary}",
        "",
    ]
    for status in order:
        group = report.by_status(status)
        if not group:
            continue
        lines.append(f"## {status.value.capitalize()} ({len(group)})")
        for f in group:
            lines.append(f"### [{f.severity.value}] {f.claim}")
            lines.append(f"- confidence: {f.confidence:.2f}")
            if f.mitre_attack:
                lines.append(f"- ATT&CK: {', '.join(f.mitre_attack)}")
            if f.review:
                lines.append(f"- Skeptic: {f.review.rationale}")
            for e in f.evidence:
                lines.append(f"- evidence: `{e.tool}` (sha256 `{e.output_sha256[:16]}…`)")
            lines.append("")
    return "\n".join(lines)
```

```python
    def _resume(self) -> None:
        """Continue an existing log's chain instead of restarting it."""
        last = None
        with self.path.open("r", encoding="utf-8") as fh:
            for line in fh:
                line = line.strip()
                if line:
                    last = line
        if last:
            rec = json.loads(last)
            self._seq = int(rec.get("seq", 0))
            self._prev_hash = rec.get("hash", _GENESIS)

    def log(self, event: str, **fields: Any) -> dict[str, Any]:
        with self._lock:
            self._seq += 1
            record: dict[str, Any] = {
                "seq": self._seq,
                "ts": datetime.now(timezone.utc).isoformat(),
                "event": event,
                **fields,
                "prev_hash": self._prev_hash,
            }
            record["hash"] = sha256_hex(self._prev_hash + _canonical(record))
            self._prev_hash = record["hash"]
            with self.path.open("a", encoding="utf-8") as fh:
```
