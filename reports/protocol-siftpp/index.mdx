# protocol-siftpp 원고

셀 원고의 머리다. 셀마다 이 폴더 아래 축 폴더의 `<축>/<셀ID>.mdx`에 쓴다.
셀과 상세 항목의 정의는 `matrix/cells/<축>/<셀ID>.mdx`를 따른다.
상세 항목마다 **구현**을 쓰고 그 방식이 적용되지 않는 경로나 조건이 있으면 **한계**를 따로 쓴다.
본문의 [번호]는 그 파일 끝 **근거**의 같은 번호를 가리킨다.

**기준 커밋.** [`ae5e7d5`](https://github.com/tupils1/protocol-siftpp/tree/ae5e7d599df9aa3cbb726a9fd7dfed9fb4d98615)(2026-06-10).
줄 번호는 모두 이 커밋 기준이다.

**범위.** `src/protocol_siftpp/mcp_server/`의 stdio MCP 서버(`siftpp-mcp`)를 본다.
서버는 FastMCP로 도구 11개를 등록한다.
Volatility 3 플러그인 하나씩을 실행하는 `vol_info`·`vol_pslist`·`vol_pstree`·`vol_psscan`·`vol_cmdline`·`vol_dlllist`·`vol_malfind`·`vol_netscan`·`vol_svcscan` 9개와 `evidence_metadata`·`verify_evidence_integrity`다.
서버가 쓰는 호출 기록 모듈 `audit.py`와 해시 함수 `schema.sha256_hex`도 서버 동작으로 본다.
증거 파일 경로, 호출 기록 경로, 기록에 적을 에이전트 이름, Volatility 오프라인 실행 여부는 환경변수 `SIFTPP_EVIDENCE`·`SIFTPP_AUDIT_LOG`·`SIFTPP_AGENT`·`SIFTPP_VOL_OFFLINE`으로 정한다.
`SIFTPP_ECHO`가 비어 있지 않고 `0`도 아니면 기록 항목을 표준 오류에도 한 줄씩 출력한다.

같은 저장소의 `siftpp-investigate`(`cli.py`·`orchestrator.py`·`mcp_client.py`·`client_tools.py`·`prompts.py`·`agent_config.py`)는 이 서버를 stdio로 실행해 쓰는 클라이언트다.
이 클라이언트는 Anthropic SDK로 Investigator와 Skeptic 두 역할의 모델을 차례로 부른다.
모델에게는 서버 도구와, 클라이언트가 직접 처리하는 도구 `submit_finding`·`submit_review`를 준다.
클라이언트는 자기 호출 기록 `audit.jsonl`과 보고서 `report.json`·`report.md`를 출력 폴더에 쓴다.
같은 저장소에는 사용자 CLI도 있다.
`siftpp-download-case`는 SANS 표본 사건의 메모리 이미지 압축 파일을 내려받아 푼다.
`siftpp-demo`는 서버를 실행하지 않고 정해 둔 도구 응답과 정해 둔 모델 응답으로 클라이언트의 조사 절차를 시연한다.
`siftpp-spoliation-test`·`siftpp-tamper-test`·`siftpp-verify`·`siftpp-trace`·`siftpp-report`·`siftpp-gui`는 서버를 시험하거나 기록을 검증·표시한다.

다음 경우에만 이 클라이언트와 사용자 CLI를 구현으로 세고 그 밖에는 원고에 사실로만 적는다.

- 상세가 클라이언트 쪽 방식을 묻는 경우(예: T02.03, L01.10)
- 상세가 사용자 명령을 묻는 경우(예: L04.06, P05.02)
- 같은 저장소의 CLI·클라이언트가 서버 기록이나 서버 응답으로 산출물을 만드는 경우(F06)

**확인 방법.** 코드는 기준 커밋을 `git show`로 읽었다.
근거의 "실행 확인"은 기준 커밋을 `git archive`로 풀고 `uv sync --frozen`으로 잠금 파일의 버전을 설치한 Windows 11 환경(Python 3.12.13)에서 확인한 결과다.
MCP Python SDK 1.27.2의 클라이언트로 서버를 stdio로 실행해 초기화 응답과 도구 목록을 읽고 도구를 불렀다.
증거로는 메모리 이미지가 아닌 1,216바이트짜리 합성 파일을 썼으므로 Volatility 플러그인은 모두 요구 조건을 채우지 못해 종료 코드 1로 끝났다.
그 상태에서 다음 경우의 응답과 호출 기록을 확인했다.

- 범위 밖 `pid`와 등록하지 않은 도구 이름으로 부른 경우
- 크기와 수정 시각을 그대로 두고 증거 내용을 바꾼 경우와 수정 시각을 바꾼 경우
- 호출 기록 파일을 읽기 전용으로 바꿔 쓰기가 실패한 경우
- 같은 호출 기록 파일로 서버를 다시 시작한 경우
- 도구 호출 두 개를 동시에 보낸 경우

실제 메모리 이미지는 분석하지 않았고 모델 API 키가 필요한 `siftpp-investigate`는 실행하지 않았다.
저장소 `docs/examples/`의 조사 기록은 근거로 쓰지 않았다.

**외부 도구 버전 기준.** 잠금 파일 `uv.lock`이 정한 버전을 기준으로 삼는다.
분석 도구 Volatility 3은 `volatility3` 2.28.0([`d61335e`](https://github.com/volatilityfoundation/volatility3/tree/d61335e2a54961bfd619fe6cd7f7b27f01481604)), MCP SDK는 `mcp` 1.27.2([`6213787`](https://github.com/modelcontextprotocol/python-sdk/tree/62137874ff26dd74d2fea80ff528a7fd9ca7a5e7))다.
`.python-version`과 Dockerfile이 정한 Python 3.12의 표준 라이브러리 동작은 CPython 3.12.13([`3bb231a`](https://github.com/python/cpython/tree/3bb231a6a5dc02b95658877318bf61501a7209e9))으로 확인했다.
`pyproject.toml`은 두 패키지를 `>=` 범위로만 적고 서버는 가상 환경 밖의 `vol`도 찾으므로 이 기준과 다른 버전이 실행될 수 있다(T05).
