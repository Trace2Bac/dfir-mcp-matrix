# T05 분석 도구 검증

### T05.01 저장소·의존성 고정

**구현.** 분석 도구 Volatility 3은 잠금 파일 `uv.lock`이 `volatility3` 2.28.0으로 고정하고 배포 파일의 sha256도 적는다 [1].
`uv sync`나 `uv run`으로 설치하면 이 버전이 가상 환경에 설치되고 Dockerfile도 `uv sync --frozen --no-dev`로 잠금 파일 그대로 설치한다 [2].
`pyproject.toml`은 `volatility3>=2.28.0`처럼 하한만 적는다 [3].
MCP SDK `mcp` 1.27.2도 잠금 파일에 고정되어 있지만 증거를 해석하지 않는 서버 실행용 라이브러리라 이 상세의 근거로 보지 않는다 [3][4].

Volatility가 쓰는 Windows 심볼은 고정하지 않는다.
Volatility는 자기 심볼 폴더와 캐시 폴더에서 맞는 심볼을 찾는다 [5].
찾지 못하면 Microsoft 심볼 서버에서 PDB를 받아 변환하고 그 결과를 심볼 폴더에 저장한다 [6].
서버는 실행 중에 Volatility나 심볼의 버전을 묻거나 읽지 않는다 [7].

**한계.** 서버는 실행할 `vol`을 서버를 실행한 Python의 폴더에서 먼저 찾고 없으면 `PATH`에서 찾는다 [8].
그래서 잠금 파일로 설치하지 않은 Python으로 서버를 실행하면 `PATH`에 있는 다른 버전의 Volatility가 실행될 수 있다 [8].
잠금 파일 없이 `pyproject.toml`로 설치해도 다른 버전이 설치될 수 있다 [3].
서버가 부르는 `windows.malfind`는 Volatility 2.28.0에서 `windows.malware.malfind`로 이름이 바뀐 옛 이름이고 2026-06-07 뒤 첫 릴리스에서 지울 예정이라고 적혀 있다 [9][10].
하한만 적은 범위 안에서 이 이름이 없는 버전이 설치될 수 있지만 서버는 버전을 확인하지 않는다 [3][7].

[8] `vol` 실행 파일을 찾는 순서다.

```python
def vol_executable() -> str:
    """Locate the Volatility 3 ``vol`` console script in this venv, else PATH."""
    here = Path(sys.executable).parent
    for name in ("vol.exe", "vol"):
        cand = here / name
        if cand.exists():
            return str(cand)
    found = shutil.which("vol")
    if found:
        return found
    raise RuntimeError("Volatility 3 'vol' executable not found in the venv or on PATH")
```
