# T08 실행 종료 판별

### T08.01 종료 코드 확인

**구현.** 이 방식은 Volatility 도구 9개의 실행에 적용된다 [1].
서버는 `vol`의 종료 코드를 받아 응답의 `exit_code`와 호출 기록의 `exit_code`에 싣는다 [1][2].
종료 코드가 0이 아니면 표준 오류 끝 2,000자를 응답의 `stderr`에 싣고 0이면 표준 오류를 버린다 [2].
종료 코드가 0이 아니어도 서버는 MCP 오류 결과를 쓰지 않고 출력과 함께 정상 응답을 돌려준다 [2][3].
Volatility 3 2.28.0은 플러그인 요구 조건을 채우지 못하면 채우지 못한 요구 조건을 표준 출력에, 요약 한 줄을 표준 오류에 쓰고 종료 코드 1로 끝난다 [4].
실행 중 예외가 나면 오류 설명을 표준 오류에 쓰고 종료 코드 1로 끝난다 [4].

서버는 출력이 JSON으로 읽히는지 보지만 그 결과로 실패를 정하지 않는다 [2].
JSON으로 읽히지 않는 출력은 `result_text`에 글로 싣는다 [2].
합성 증거로 부른 Volatility 도구는 종료 코드 1로 끝났고 Volatility가 표준 출력에 쓴 오류 글이 `result_text`에 실렸다 [3].

### T08.02 시간 제한·종료 신호 처리

**구현.** 이 방식은 Volatility 도구 9개의 실행에 적용된다 [1].
서버는 `subprocess.run`에 시간 제한 900초(`DEFAULT_TIMEOUT_S`)를 준다 [1][5].
제한을 넘으면 Python 3.12의 `subprocess.run`이 자식 프로세스를 강제 종료하고 그때까지 받은 출력을 예외에 담아 넘긴다 [6].
서버는 이 예외를 받아 `timed_out`을 참으로, 종료 코드를 -1로 정하고 표준 오류 끝에 `[timed out]`을 붙인다 [1].
끊기 전에 받은 표준 출력은 해시하고 JSON으로 읽히면 `result`에, 아니면 `result_text`에 싣는다 [2].
같은 작업을 다시 실행하지 않는다.

Windows 가상 환경에서 `vol`은 `vol.exe` 실행 파일이다 [7].
시간 제한으로 `vol.exe`를 끊은 뒤 실행 전에 없던 Python 프로세스가 남지 않았다 [7].
