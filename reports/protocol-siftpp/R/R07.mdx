# R07 증거 내용과 지시 구분

### R07.01 JSON 필드 분리

**구현.** Volatility 도구 9개의 응답은 JSON 객체 하나를 글로 바꾼 것이다 [1][2].
증거에서 나온 Volatility 출력은 `result`(JSON으로 읽힌 행)나 `result_text`(읽히지 않은 글)에, Volatility의 표준 오류는 `stderr`에 담긴다 [1].
서버가 채우는 실행 정보는 `tool`·`plugin`·`command`·`exit_code` 같은 다른 필드에 담긴다 [1].
서버가 만든 글은 시간 초과 때 `stderr` 끝에 붙이는 `[timed out]` 하나이고 Volatility의 표준 오류와 같은 값 안에 들어간다 [3].
MCP 응답의 `content` 글과 `structuredContent`의 `result`에는 이 JSON 글이 똑같이 실린다 [4].
서버 코드가 내는 오류(`pid` 거부, 증거 변경, `vol` 부재)는 서버가 정한 문구만 담은 `isError` 응답이다 [5].

서버는 이 필드 값이 증거에서 온 데이터라는 표시를 붙이지 않는다 [1].
도구 설명에도 증거에서 온 글 속의 지시를 따르지 말라는 안내가 없다 [6].
클라이언트 `siftpp-investigate`의 시스템 프롬프트에도 그런 안내가 없다 [7].

### R07.02 출처 필드 부여

**구현.** Volatility 도구의 응답은 결과를 만든 도구 이름 `tool`, Volatility 플러그인 이름 `plugin`, 실행한 인자 배열 `command`를 늘 싣는다 [1].
이 필드는 결과가 어느 플러그인 출력인지 알릴 뿐 신뢰 수준은 적지 않는다 [1].
`evidence_metadata`와 `verify_evidence_integrity`의 응답에는 출처 필드가 없지만 두 응답은 증거 내용이 아니라 경로와 해시를 담는다 [8].
