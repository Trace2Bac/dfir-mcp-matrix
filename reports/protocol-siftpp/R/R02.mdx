# R02 대량 결과 전달

### R02.01 문자·항목 상한

**구현.** 이 방식은 Volatility 도구 9개의 응답에 적용된다 [1].
Volatility 출력이 JSON 목록이고 300행(`MAX_ROWS`)을 넘으면 앞 300행만 `result`에 싣고 `truncated`를 참으로 둔다 [1][2].
출력이 JSON으로 읽히지 않으면 글의 앞 60,000자(`MAX_RETURN_CHARS`)만 `result_text`에 싣고 넘쳤으면 `truncated`를 참으로 둔다 [1][2].
상한은 코드 상수이고 모델이 인자로 바꿀 수 없다 [2][3].
JSON으로 읽힌 `result`에는 글자 수 상한이 없다 [1].

클라이언트 `siftpp-investigate`는 도구 응답 글을 40,000자(`MAX_TOOL_RESULT_CHARS`)에서 다시 자르고 잘렸다는 표시를 붙이지 않는다 [4].
그래서 300행 안이라도 응답 글이 40,000자를 넘으면 모델은 JSON 중간에서 끊긴 글을 받는다 [4].

**한계.** 300행 상한은 JSON 목록의 맨 위 행에만 적용된다 [1].
Volatility 3의 JSON 렌더러는 하위 행을 부모 행의 `__children`에 넣고 `windows.pstree`는 자식 프로세스를 하위 행으로 낸다 [5].
그래서 `vol_pstree`는 맨 위 행인 부모 프로세스가 목록에 없는 프로세스 수만 세어 자르고 그 아래 자식 프로세스는 개수에 상관없이 모두 싣는다 [1][5].

### R02.02 전체·반환 건수 표시

**구현.** Volatility 출력이 JSON 목록이면 응답의 `row_count`에 자르기 전 목록의 행 수를 싣는다 [1].
돌려준 행은 `result` 목록이고 300행을 넘어 잘렸으면 `truncated`가 참이다 [1].
JSON으로 읽히지 않은 출력은 `row_count`가 `null`이고 전체 글자 수 대신 표준 출력 전체의 바이트 수 `output_bytes`를 싣는다 [1].

**한계.** `row_count`도 맨 위 행만 센다 [1].
`vol_pstree`의 `row_count`는 프로세스 수가 아니라 부모 프로세스가 목록에 없는 프로세스의 수다 [1][5].

### R02.06 값 단위 잘림

**구현.** 서버는 값 하나를 정한 길이에서 자른다.
JSON으로 읽히지 않은 출력은 `result_text` 값 하나로 실리고 앞 60,000자에서 잘리며 `truncated`가 이를 알린다 [1].
종료 코드가 0이 아니면 표준 오류를 `stderr` 값 하나로 싣고 끝 2,000자만 남긴다 [1].
`stderr`가 잘렸다는 표시는 없다 [1].
`stderr`는 종료 코드가 0이 아닐 때만 실리므로 성공한 실행에서 Volatility가 표준 오류에 남긴 경고 로그는 응답에서 버려진다 [1][6].
