# R05 결과 출처 표시

### R05.01 증거·파일 ID

**구현.** Volatility 도구 9개의 응답은 결과가 나온 증거 파일을 두 필드로 가리킨다 [1].
`command`는 실행한 인자 배열이고 `-f` 다음 값이 증거 파일 경로다 [1][2].
`evidence_sha256`은 그 증거 파일의 기준 해시다 [1].
인자 배열은 목록이라 경로가 다른 인자와 섞이지 않는다 [2].
경로는 사용자가 준 값 그대로라 상대 경로이면 서버 작업 폴더 기준이다(E01.02).
`verify_evidence_integrity`의 응답도 `path`에 증거 파일 경로를 싣는다 [3].

### R05.03 레코드 키·번호

**구현.** 서버는 Volatility 출력의 열을 그대로 전달하므로 플러그인이 내는 프로세스 ID가 결과 행에 실린다(R01.01).
`pslist`·`psscan`·`pstree`·`cmdline`·`dlllist`·`malfind`·`netscan` 행에는 `PID`가 있다 [4].
`psscan`은 끝난 프로세스도 찾으므로 같은 `PID`가 여러 행에 나올 수 있다 [5].
`svcscan` 행에는 서비스의 `PID`와 서비스 이름이 있다 [4].

### R05.04 바이트·섹터·행 오프셋

**구현.** 이 방식은 `vol_netscan`의 `Offset` 열과 `vol_psscan`의 `Offset(V)` 열에 적용된다 [6][5].
Volatility 3 2.28.0의 `netscan`과 `psscan`은 같은 풀 스캔을 쓰고 이 풀 스캔은 Windows 10 이전 이미지에서는 커널 가상 주소 계층이 아니라 그 아래의 메모리 계층을 훑는다 [7][5].
그래서 이 이미지의 두 열은 메모리 계층 안의 물리 주소다 [7][5].
원시 메모리 이미지에서는 이 값이 파일 안 위치와 같지만 크래시 덤프처럼 머리말이나 구간 표가 있는 형식에서는 파일 안 위치와 다를 수 있다.

`pslist`·`pstree`의 `Offset(V)`, `malfind`의 `Start VPN`, `dlllist`의 `Base`, `svcscan`의 `Offset`은 가상 주소라 이미지 안 위치가 아니다 [4].
서버는 `psscan`에 메모리 계층의 주소로 바꿔 출력하는 `--physical`을 넘기지 않는다 [2][5].

**예외.** Windows 10 이후 이미지에서는 풀 스캔이 커널 가상 주소 계층을 훑으므로 두 열이 가상 주소가 된다 [7][5].
`netscan`의 `Offset` 열 이름과 응답 어디에도 이 값이 물리 주소인지 가상 주소인지 표시하지 않는다 [6][1].
`psscan`의 열 이름 `Offset(V)`는 Windows 10 이전 이미지에서 물리 주소를 담는데도 가상 주소라고 표시한다 [5].

        """Re-hash the FULL evidence file and prove it equals acquisition.
