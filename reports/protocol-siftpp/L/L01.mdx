# L01 기록 방식

### L01.08 도구별 기록 호출

**구현.** 이 방식은 `verify_evidence_integrity`에 적용된다 [1].
이 도구는 실행기의 `verify_integrity`를 부르고 이 함수가 증거 해시를 다시 계산한 뒤 `evidence_integrity` 항목을 쓴다 [1][2].

**예외.** 첫 호출에서 실행기를 만들지 못하거나 해시를 다시 계산하다 증거 파일을 읽지 못하면 항목 없이 호출이 끝난다 [3][2].

### L01.09 실행기 안 기록

**구현.** Volatility 도구 9개는 실행기 `VolatilityRunner.run`이 `vol`을 실행한 뒤 호출마다 `tool_call` 항목을 쓴다 [4].
실행기를 처음 만들 때는 증거를 연 사실을 `evidence_opened` 항목으로 쓴다 [3].
항목은 기록 객체 `AuditLogger`가 환경변수 `SIFTPP_AUDIT_LOG`의 JSONL 파일에 덧붙인다 [5].
시간 초과로 끊긴 실행과 종료 코드가 0이 아닌 실행도 항목이 남는다 [4].

**예외.** `evidence_metadata`는 실행기를 거치지 않고 보관한 값을 돌려주므로 호출 항목이 남지 않는다 [6].
첫 호출이면 실행기를 만들면서 `evidence_opened`만 남는다 [3][6].
실행기가 항목을 쓰기 전에 예외를 내면 그 호출은 기록되지 않는다 [4].
그런 경우는 `pid` 거부, `vol` 부재, Volatility 실행 전후의 증거 크기·수정 시각 변경, `subprocess.run` 자체의 `OSError`다 [4].
첫 호출에서 증거가 설정되지 않았거나 증거 파일이 없어 실행기를 만들지 못한 호출도 기록되지 않는다 [3].
실행 뒤의 비교에서 증거 변경이 드러나면 Volatility는 이미 실행되었지만 항목이 남지 않는다 [4].
등록하지 않은 도구 이름은 FastMCP가 처리기를 부르기 전에 거부하므로 기록되지 않는다 [7].

### L01.10 클라이언트의 보조 기록

**구현.** 이 방식은 저장소의 클라이언트 `siftpp-investigate`로 서버를 쓸 때만 적용된다 [8].
클라이언트는 출력 폴더에 자기 호출 기록 `audit.jsonl`을 두고 서버 기록 `mcp-server.jsonl`을 같은 폴더에 쓰게 한다 [8].
클라이언트 기록은 서버 기록과 같은 `AuditLogger`로 쓰고 서버를 거치지 않는 사건을 남긴다 [8][9].
그런 사건은 모델 호출마다의 `model_call`, 클라이언트 도구 `submit_finding`·`submit_review`의 결과인 `finding_submitted`·`review_submitted`, 역할 사이의 `agent_message`, 재조사 차례 `iteration`, 조사 시작·끝 `run_start`·`run_end`다 [9][10].
클라이언트를 거친 서버 도구 호출도 `tool_call`로 한 번 더 남기고 호출한 역할을 `agent`에 적는다 [11].
서버 기록 `mcp-server.jsonl`과 클라이언트 기록 `audit.jsonl`은 해시 체인을 따로 잇고 서로의 `seq`나 해시를 가리키지 않는다 [8][5].
서버가 거부해 서버 기록에 남지 않은 호출(범위 밖 `pid` 등)도 클라이언트 기록에는 `exit_code` 1의 `tool_call`로 남는다 [12][11].
다른 MCP 클라이언트로 붙으면 이 기록은 생기지 않는다.

**예외.** 클라이언트가 조사 시작에 부르는 `evidence_metadata`와 조사 끝에 부르는 `verify_evidence_integrity`는 `tool_call`로 남기지 않는다 [10].
두 결과는 `run_start`의 증거 경로·해시와 `run_end`의 `evidence_unchanged`로만 남는다 [10].
`submit_review`의 `status`가 허용 값이 아니어서 거부한 호출은 기록되지 않는다 [13].
Skeptic이 한 차례 안에서 `submit_review`를 여러 번 부르면 마지막 판정만 `review_submitted`로 남는다 [13].
`submit_finding`에 `claim`이 없으면 `KeyError`가 나서 조사가 중단되고 그 호출은 기록되지 않는다 [14].
`submit_finding`이나 `submit_review`의 `confidence`가 0~1 밖이면 `Finding`·`SkepticReview`의 값 검사에서 예외가 나서 조사가 중단되고 그 호출은 기록되지 않는다 [15][14][13].
클라이언트를 거친 서버 도구 호출에서 `mcp.call`이 예외를 내면 `tool_call` 없이 오류 문구만 모델에게 돌려준다 [11].

    async def call(self, name: str, arguments: dict[str, Any] | None = None) -> dict[str, Any]:
        assert self.session is not None, "session not started"
        result = await self.session.call_tool(name, arguments or {})
        text = "".join(getattr(c, "text", "") for c in result.content)
        try:
            return json.loads(text)
        except (json.JSONDecodeError, ValueError):
            return {"result_text": text, "exit_code": 1 if result.isError else 0}
