# L02 기록 구성

### L02.03 외부 실행 명령 기록

**구현.** Volatility 도구의 `tool_call` 항목은 실제로 실행한 인자 배열을 `command`에 목록으로 남긴다 [1].
목록에는 `vol` 실행 파일 경로, 증거 경로, `--offline` 여부, 플러그인 이름, `--pid`와 그 값이 들어 있다 [1][2].
인자를 목록으로 남기므로 인자 사이의 경계가 그대로 남는다 [1].
모델이 보낸 인자는 따로 남지 않고 `pid`는 `command` 안의 `--pid` 값으로만 남는다 [1][2].
항목에는 MCP 도구 이름 `tool`과 증거 기준 해시 `evidence_sha256`도 남는다 [1].
Volatility 출력 자체와 표준 오류는 기록에 남지 않는다 [1].

`agent`에는 환경변수 `SIFTPP_AGENT` 값이 서버 프로세스마다 하나로 정해져 남는다 [3].
클라이언트 `siftpp-investigate`는 자기 환경변수를 그대로 서버에 넘기고 이 값을 역할마다 바꾸지 않는다 [3].
그래서 Investigator와 Skeptic의 호출이 서버 기록에는 같은 `agent` 값으로 남고 사용자 환경에 이 값이 없으면 `investigator`다 [3][4].
호출한 역할은 클라이언트 기록의 `tool_call`에 따로 남는다 [5].

### L02.05 결과 상태·실행 시점 기록

**구현.** `tool_call` 항목은 실행이 끝난 뒤 한 번 쓰이고 기록 시각 `ts`, 걸린 시간 `duration_ms`, 종료 코드 `exit_code`를 담는다 [1][6].
시작 시각은 따로 남지 않고 완료 시각과 소요 시간을 기록한다 [6].
기록은 실행 뒤 쓰므로 `ts`에서 소요 시간을 뺀 값은 정확한 프로세스 시작 시각과 구별한다 [6].
`verify_evidence_integrity`의 `evidence_integrity` 항목은 기준 해시, 다시 계산한 해시, 같은지 여부 `unchanged`를 담는다 [7].

**한계.** 시간 제한에 걸려 끊긴 실행은 `exit_code` -1로만 남고 응답에 있는 `timed_out` 필드는 기록에 없다 [1][8].
표준 오류 끝에 붙이는 `[timed out]`도 기록에는 남지 않는다 [1][8].
POSIX에서는 신호 1로 끝난 프로세스의 종료 코드도 -1이라 기록만으로는 시간 초과와 구별되지 않는다 [9].

### L02.06 결과 참조·요약값 기록

**구현.** 서버의 Volatility 실행 항목은 캡처한 표준 출력의 SHA-256 `output_sha256`과 바이트 수 `output_bytes`를 담는다 [1].
해시는 표준 출력 바이트를 대상으로 계산하며 증거 기준 해시 `evidence_sha256`와 구별한다 [10].
표준 오류와 출력 내용 전체는 이 항목에 넣지 않는다 [1].
클라이언트의 기록 품질은 L02의 대상이 아니다.

    def log(self, event: str, **fields: Any) -> dict[str, Any]:
        with self._lock:
            self._seq += 1
            record: dict[str, Any] = {
                "seq": self._seq,
                "ts": datetime.now(timezone.utc).isoformat(),
                "event": event,

            record["hash"] = sha256_hex(self._prev_hash + _canonical(record))
