# R07 증거 내용과 지시 구분

### R07.01 JSON 필드 분리

**구현.** 공통 응답 함수와 적재 자료를 읽는 조회 도구가 증거에서 온 글을 서버 문구와 다른 필드에 담는다.
`windowed_response`와 `search`는 증거 본문을 결과 항목의 `raw_text`에 싣고 서버 안내는 `hint`에 따로 싣는다 [1][2].
`get_raw_output`은 이은 본문을 `raw_text` 하나에 싣는다 [3].
복합 도구는 결과 항목의 증거 글을 `evidence_text`에 싣는다 [4].
적재 도구의 응답 공통 함수 `tool_response`는 결과 요약을 `preview`에, 다음 조회 안내를 `hint`에 싣는다 [5].
서버는 서버 지침(`instructions`) 없이 만들어진다 [6].
증거 내용을 지시로 따르지 말라는 문구는 같은 저장소의 오케스트레이터 프롬프트 4곳에만 있다 [7].

**한계.** 외부 도구가 실패하면 여러 도구가 그 도구의 표준 오류나 표준 출력을 서버 문장 뒤에 이어 `error_message` 문자열 하나로 돌려준다 [8].
`decrypt_app_data`와 `extract_steganography`는 서버가 쓴 머리 줄과 증거에서 꺼낸 내용을 한 본문으로 이어 적재하므로 나중에 돌려주는 `raw_text` 안에서 둘이 섞인다 [9].
`tool_response`의 `preview`는 결과 `dict` 전체를 JSON 문자열로 바꿔 500자에서 자른 값이라 결과 안의 서버 문구와 증거에서 온 값이 한 문자열에 함께 들어간다 [5].
디스크 이미지를 받은 `run_evtx_parser`의 `preview`에는 이미지 안 경로로 만든 EVTX 파일 이름 목록과 서버 안내 `hint`가 함께 들어간다 [10].
`index_evtx_file`은 꺼낸 EVTX 파일의 이름으로 적재 자료 이름을 만들어 `tool_response`에 넘긴다 [11].
`tool_response`는 그 이름을 작은따옴표로 둘러 `hint` 문장 안에 넣으므로 이미지 안 경로로 만든 이름이 서버 안내 필드에 들어간다 [5][11].
`extract_archive`가 이미 푼 압축에 돌려주는 `message`는 푼 파일 하나의 상대 경로를 서버 문장 안에 넣는다 [12].

### R07.02 출처 필드 부여

**구현.** 사건 DB에 적재한 자료를 돌려주는 응답이 출처 필드를 붙인다.
`windowed_response`와 `tool_response`는 `source`를, `search` 결과 항목과 `get_raw_output`은 `source_name`을 싣는다 [1][2][3][5].
복합 도구의 결과 항목에도 `source`가 있다 [4].
이 필드는 적재 자료 이름이고 신뢰 수준은 적지 않는다.
적재 자료 이름은 `volatility.pslist`, `tsk.filelist`처럼 그 자료를 만든 도구와 모듈을 잇는 값이다 [13].
일부 도구는 이 값 뒤에 증거에서 읽은 이름을 잇는다 [14].
`analyze_disk_pcaps`는 이미지 안 PCAP 파일 이름을, `index_app_files`는 이미지 안 파일 이름을, `index_evtx_file`은 꺼낸 EVTX 파일 이름을, `run_registry_parser`는 사용자 폴더 이름을, `parse_autoruns`는 Autoruns CSV의 `Profile` 열 값을 잇는다 [14].
이 이름에는 도구에 따라 소문자 변환과 공백·`%`·역슬래시 바꾸기만 적용하고 `analyze_disk_pcaps`는 확장자만 뗀다 [14].
증거 파일을 바로 읽는 `read_evidence_file`의 응답에는 출처 필드가 없다 [15].

**한계.** 이 필드의 자료 이름은 어느 도구 출력인지를 알릴 뿐 모델에게 "이 글은 믿지 말 데이터"라는 신호를 주지 않을 수 있다.
공통 오류 응답 함수 `error_response`가 만드는 응답에는 출처 필드가 없다 [16].
이 응답에도 외부 도구의 표준 오류나 표준 출력이 `error_message`로 실린다 [8].
`find_defense_evasion`의 timestomping 지표는 출처 필드 `source`에 `window` 본문의 앞 20자를 담아 증거에서 온 글이 출처 필드에 들어간다 [17].
