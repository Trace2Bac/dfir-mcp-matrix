# R01 결과 가공

### R01.01 가공 없이 전달

**구현.** 외부 도구를 실행하는 추출 도구는 표준 출력을 사건 DB에 적재한다 [1].
적재 함수는 출력을 줄 단위로 4096자 안팎의 `window`로 나눠 원래 글자 그대로 저장한다 [2].
`get_raw_output`은 source 이름으로 그 `window`들을 꺼내 `raw_text` 하나로 이어 돌려준다 [3].
모델은 이 도구로 외부 도구가 낸 출력을 받는다 [3].
도구를 부른 직후의 응답에는 출력이 아니라 적재 요약이 실리며 이것은 R01.02에서 본다 [1].

**한계.** `get_raw_output`은 `window` 사이에 줄바꿈을 하나 더 넣어 잇는다 [3].
`window`마다 끝에 줄바꿈이 남아 있으므로 `window` 경계마다 원래 출력에 없던 빈 줄이 생긴다 [2][3].
4096자보다 긴 줄은 여러 `window`로 나뉘어 저장되므로 이어 붙인 결과에서는 그 줄 가운데에 줄바꿈이 들어간다 [2][3].
도구 설명은 이 결과를 "full raw text"라고 적는다 [3].

### R01.02 구조화 파싱·필드 선택

**구현.** 추출 도구의 응답은 외부 도구 출력이 아니라 적재 결과에서 고른 필드다 [1].
적재 함수는 `source_name`·`windows_indexed`·`line_count`·`status`를 돌려주고 도구마다 필드를 더한다 [1].
`tool_response`는 그 결과 `dict`를 JSON으로 바꿔 앞 500자를 `preview`로 싣는다 [4].
조회 도구는 적재한 `window`를 `window_id`·`source_id`·`line_start`·`line_end`·`event_time`·`raw_text` 필드로 돌려준다 [5].
`query_registry_value`는 레지스트리 값을 `name`·`type`·`data`로 나누고 이진 값은 hex 문자열로 바꾼다 [6].

### R01.03 형식 변환·건수 집계

**구현.** 출력의 형식을 바꿔 적재하는 도구가 있다.
`run_volatility_batch`는 Volatility 라이브러리가 돌려준 표를 탭으로 구분한 글로 바꿔 적재한다 [7].
`parse_browser_history`는 브라우저 DB를 SQL로 조회해 행마다 값을 탭으로 이은 글을 만든다 [8].
여러 출력이나 레코드를 묶어 건수를 세는 도구도 있다.
`correlate_across_sources`는 시간 범위 안의 `window`를 source별로 묶고 source마다 `window` 수를 센다 [9].
YARA 결과에는 규칙 이름 앞부분으로 센 규칙 계열 수를 `hit_metadata`로 붙인다 [10].
`get_ioc_summary`는 제출된 발견사항의 제목·설명에서 IP·전자우편 주소·Windows와 Unix 경로·계정, URL의 호스트를 정규식으로 뽑는다 [11].
`bulk.email`·`bulk.url`·`bulk.domain` `source`가 적재돼 있으면 그 `window`에서 전자우편 주소와 도메인을 더 뽑는다 [12].
뽑은 값은 종류마다 중복을 지운 뒤 그 수를 모두 더해 `total_unique_iocs`로 싣는다 [13].
`get_deleted_files`와 `list_files`는 `tsk.filelist`에서 고른 `window`의 줄 수를 더해 항목 수로 싣는다 [14][15].
`assess_recovery`는 `tsk.filelist`의 `window` 가운데 삭제 표지 `"* "`가 들어 있는 것의 수를 `total_deleted_files`로 싣는다 [16].

`decode_payload`는 모델이 준 문자열이나 적재한 source에서 찾은 base64 문자로만 된 20자 이상 문자열을 hex·UTF-16LE·base64로 풀어 `decoded`와 단계별 `layers`를 돌려준다 [17].
base64를 푼 바이트가 gzip 머리로 시작하면 압축까지 푼다 [18].
pickle로 판단한 입력은 `pickletools.dis`로 역어셈블한 글만 돌려주고 역직렬화하지 않는다 [18].
입력이 100,000자를 넘으면 풀지 않고 오류를 돌려준다 [19].

**한계.** `get_eventlog_anomalies`의 설명은 k-NN 밀도로 이벤트마다 점수를 매겨 이상치를 돌려준다고 적는다 [20].
코드는 그 채널과 시간 범위의 `window`를 그대로 `windowed_response`에 넘기고 `top_percent` 인자를 쓰지 않는다 [20].
`read_evidence_file`의 설명은 이진 파일이면 hex 미리보기를 돌려준다고 적는다 [21].
코드는 이진 파일을 UTF-8 대체 문자로 푼 글의 앞 2000자를 돌려준다 [21].
`get_ioc_summary`의 설명은 제출된 발견사항 전체에서 도메인을 찾고 bulk_extractor 결과를 확인한다고 적는다 [11].
코드는 발견사항 본문에서 `http://`·`https://` URL의 호스트만 도메인으로 뽑으므로 URL이 아닌 도메인 표기는 결과에 포함되지 않는다 [11].
bulk `source`마다 앞 `window` 200개만 읽고 응답에는 일부만 읽었다는 표시가 없다 [12][13].
`decode_payload`는 base64를 푼 글이 다시 hex·UTF-16LE·pickle 꼴이면 같은 이름의 함수 `decode_payload`를 불러 한 겹 더 풀려고 한다 [22].
모듈의 이 이름은 서버가 도구를 등록하면서 비동기 wrapper로 바꾼 함수를 가리킨다 [23].
그래서 안쪽 호출은 결과 `dict` 대신 coroutine을 받고 바로 다음의 `.get`에서 예외가 나 도구 호출이 실패한다 [22][23].
`decode_payload`의 설명은 source의 첫 일치에서 가장 긴 base64 꼴 문자열을 뽑는다고 적지만 코드는 일치한 `window` 5개까지 가운데 가장 긴 문자열을 고른다 [24].
`get_deleted_files`는 삭제 표지 `"* "`가 하나라도 들어 있는 `window`를 고른 뒤 그 `window`의 줄 수 전체를 `approx_deleted_count`와 `hint`의 삭제 항목 수로 적는다 [14].
그래서 같은 `window`에 들어 있는 삭제되지 않은 항목도 삭제 항목으로 센다 [14].
`list_files`의 설명은 `include_deleted=True`이면 삭제된 파일만 보인다고 적지만 코드는 같은 방식으로 `window`를 골라 삭제되지 않은 줄도 `approx_file_count`에 센다 [15].
`assess_recovery`의 `total_deleted_files`는 이름과 달리 삭제 파일 수가 아니라 삭제 항목이 하나라도 들어 있는 `window`의 수다 [16].
`window` 하나에는 파일 목록 여러 줄이 들어가므로 이 값은 삭제 파일 수보다 작을 수 있다 [16][2].

### R01.05 가공 사실·대상 표시

**구현.** 복합 도구 11개는 공통 마무리 함수 `finalize_composite_result`로 응답을 만든다 [25].
이 함수는 도구가 조회하려는 source 접두어를 적재된 source 이름과 견줘 맞은 이름을 `sources_queried_names`에, 그 수와 전체 source 수를 `sources_queried`·`total_sources_available`에 싣는다 [25].
적재되지 않은 source가 있으면 `coverage_note`에 그 이름을 적는다 [25].
`correlate_across_sources`는 조회한 source 목록과 그 시간 범위에 자료가 없던 source 목록을 싣는다 [26].
추출 도구 응답의 `hint`는 전체 출력을 적재한 source 이름을 알린다 [4].

**한계.** 복합 도구가 쓰는 키워드 하위 조회는 요청한 source가 적재되지 않았으면 모든 source를 검색한다 [27].
이때도 `sources_queried_names`에는 접두어가 맞는 source만 들어가고 `coverage_note`는 요청한 source가 적재되지 않았다고만 적는다 [25][27].

```python
def _render_treegrid_to_text(treegrid: Any) -> str:
    """Convert a Volatility TreeGrid to tab-separated text."""
    columns = [c.name for c in treegrid.columns]
    lines = ["\t".join(columns)]

    def _visitor(node: Any, accumulator: Any) -> Any:
        """Append one row of tab-separated values to *accumulator*."""
        values = treegrid.values(node)
        row = []
        for i, _col in enumerate(treegrid.columns):
            val = values[i]
            if val is None:
                row.append("")
            else:
                row.append(str(val))
        accumulator.append("\t".join(row))
        return accumulator

    treegrid.populate(_visitor, lines)
    return "\n".join(lines)
```

```python
    windows = [w for w, _sname in results]

    actual_label = effective_source or "all"
```
