# R01 도구 출력 가공

### R01.01 가공 없이 전달

**구현.** 외부 도구를 실행하는 추출 도구는 표준 출력을 사건 DB에 적재한다 [1].
적재 함수는 출력을 줄 단위로 4096자 안팎의 `window`로 나눠 원래 글자 그대로 저장한다 [2].
`get_raw_output`은 source 이름으로 그 `window`들을 꺼내 `raw_text` 하나로 이어 돌려준다 [3].
모델은 이 도구로 외부 도구가 낸 출력을 받는다 [3].
도구를 부른 직후의 응답에는 출력이 아니라 적재 요약이 실리며 이것은 R01.02에서 본다 [1].

**예외.** `get_raw_output`은 `window` 사이에 줄바꿈을 하나 더 넣어 잇는다 [3].
`window`마다 끝에 줄바꿈이 남아 있으므로 `window` 경계마다 원래 출력에 없던 빈 줄이 생긴다 [2][3].
4096자보다 긴 줄은 여러 `window`로 나뉘어 저장되므로 이어 붙인 결과에서는 그 줄 가운데에 줄바꿈이 들어간다 [2][3].
도구 설명은 이 결과를 "full raw text"라고 적는다 [3].

### R01.02 구조화 파싱·필드 선택

**구현.** 추출 도구의 응답은 외부 도구 출력이 아니라 적재 결과에서 고른 필드다 [1].
적재 함수는 `source_name`·`windows_indexed`·`line_count`·`status`를 돌려주고 도구마다 필드를 더한다 [1].
`tool_response`는 그 결과 `dict`를 JSON으로 바꿔 앞 500자를 `preview`로 싣는다 [4].
조회 도구는 적재한 `window`를 `window_id`·`source_id`·`line_start`·`line_end`·`event_time`·`raw_text` 필드로 돌려준다 [5].
`query_registry_value`는 레지스트리 값을 `name`·`type`·`data`로 나누고 이진 값은 hex 문자열로 바꾼다 [6].

### R01.03 형식 변환·집계

**구현.** 출력의 형식을 바꿔 적재하는 도구가 있다.
`run_volatility_batch`는 Volatility 라이브러리가 돌려준 표를 탭으로 구분한 글로 바꿔 적재한다 [7].
`parse_browser_history`는 브라우저 DB를 SQL로 조회해 행마다 값을 탭으로 이은 글을 만든다 [8].
여러 출력을 묶어 값을 계산하는 도구도 있다.
`scan_hidden_processes`는 psscan 출력의 PID에서 pslist 출력의 PID를 뺀 차집합을 돌려준다 [9].
`correlate_across_sources`는 시간 범위 안의 `window`를 source별로 묶고 source마다 `window` 수를 센다 [10].
복합 도구 `find_suspicious_processes`는 프로세스마다 의심 이유 `reasons`의 가중치를 더해 `anomaly_score`를 매기고 점수순으로 정렬한다 [11].
YARA 결과에는 규칙 이름 앞부분으로 센 규칙 계열 수를 `hit_metadata`로 붙인다 [12].
`get_ioc_summary`는 제출된 발견사항의 제목·설명에서 IP·전자우편 주소·Windows와 Unix 경로·계정, URL의 호스트를 정규식으로 뽑는다 [13].
`bulk.email`·`bulk.url`·`bulk.domain` `source`가 적재돼 있으면 그 `window`에서 전자우편 주소와 도메인을 더 뽑는다 [14].
뽑은 값은 종류마다 중복을 지우고 IP는 공인과 사설로 나누며 정한 잡음 도메인 3개를 뺀 뒤 전체 수를 `total_unique_iocs`로 싣는다 [15].

**예외.** `get_eventlog_anomalies`의 설명은 k-NN 밀도로 이벤트마다 점수를 매겨 이상치를 돌려준다고 적는다 [16].
코드는 그 채널과 시간 범위의 `window`를 그대로 `windowed_response`에 넘기고 `top_percent` 인자를 쓰지 않는다 [16].
`read_evidence_file`의 설명은 이진 파일이면 hex 미리보기를 돌려준다고 적는다 [17].
코드는 이진 파일을 UTF-8 대체 문자로 푼 글의 앞 2000자를 돌려준다 [17].
`get_ioc_summary`의 설명은 제출된 발견사항 전체에서 도메인을 찾고 bulk_extractor 결과를 확인한다고 적는다 [13].
코드는 발견사항 본문에서 `http://`·`https://` URL의 호스트만 도메인으로 뽑으므로 URL이 아닌 도메인 표기는 결과에 들지 않는다 [13].
bulk `source`마다 앞 `window` 200개만 읽고 응답에는 일부만 읽었다는 표시가 없다 [14][15].

### R01.05 가공 사실·대상 표시

**구현.** 복합 도구 11개는 공통 마무리 함수 `finalize_composite_result`로 응답을 만든다 [18].
이 함수는 도구가 조회하려는 source 접두어를 적재된 source 이름과 견줘 맞은 이름을 `sources_queried_names`에, 그 수와 전체 source 수를 `sources_queried`·`total_sources_available`에 싣는다 [18].
적재되지 않은 source가 있으면 `coverage_note`에 그 이름을 적는다 [18].
`correlate_across_sources`는 조회한 source 목록과 그 시간 범위에 자료가 없던 source 목록을 싣는다 [19].
추출 도구 응답의 `hint`는 전체 출력을 적재한 source 이름을 알리며 이것은 R02.04에서 본다 [4].

**예외.** 복합 도구가 쓰는 키워드 하위 조회는 요청한 source가 적재되지 않았으면 모든 source를 검색한다 [20].
이때도 `sources_queried_names`에는 접두어가 맞는 source만 들어가고 `coverage_note`는 요청한 source가 적재되지 않았다고만 적는다 [18][20].
`find_lateral_movement_indicators`는 보안 이벤트 로그가 없으면 이렇게 다른 source에서 찾은 `window`도 4624나 "logon"이 들어 있으면 로그온 지표로 분류한다 [21].
그 지표 항목의 `source`는 실제 source와 관계없이 보안 이벤트 로그 이름으로 적히며 항목의 출처 표시는 R05에서 본다 [21].

### R01.06 시간 변환 전 값 유지

**구현.** 외부 도구 출력을 적재하는 경로는 시각 문자열을 바꾸지 않고 `raw_text`에 그대로 둔다 [2].
`get_raw_output`은 이 `raw_text`를 돌려주므로 외부 도구가 낸 시각 표기가 그대로 모델에게 간다 [3].

서버가 출력을 다시 만드는 도구는 다르다.
`parse_browser_history`는 Chrome·Firefox·Safari의 시각 정수를 SQLite `datetime`으로 바꾼 값만 적재하고 원래 정수는 버린다 [8].
`parse_ios_artifacts`도 iOS 앱 DB의 시각을 같은 방식으로 바꾼 값만 적재한다 [22].

### R01.07 정규화 시간과 변환 전 값 병기

**구현.** 적재 함수는 `window`마다 본문에서 찾은 시각 하나를 ISO 형식으로 바꿔 `event_time`에 넣고 본문 `raw_text`는 그대로 둔다 [2][23].
`search`·`get_timeline`과 `windowed_response`를 쓰는 조회 도구는 `window`의 `event_time`과 `raw_text`를 한 항목에 함께 싣는다 [5].
`query_registry_value`는 8바이트 이진 값이 1980년부터 2100년 사이의 FILETIME으로 풀리면 원래 hex 값 `data` 옆에 풀어 쓴 시각 `decoded`를 둔다 [6][24].

정규화 값은 원래 값보다 정보가 적다.
ISO 형식 정규식은 초 단위까지만 읽어 소수 초와 시간대 표기를 버린다 [23].
연도가 없는 syslog 시각에는 정규화하는 시점의 현재 연도를 채운다 [23].
`window` 하나는 레코드 여러 개를 담지만 `event_time`은 하나뿐이다 [2][23].
응답은 `event_time`이 서버가 정규화하거나 연도를 가정한 값이라는 것을 알리지 않아 R01.09에는 연결하지 않는다 [5].

**예외.** 조회 응답은 `raw_text`를 잘라 싣는다 [5].
`search`와 `windowed_response`는 300자, `get_timeline`은 500자, `correlate_across_sources`는 200자에서 자른다 [5].
`event_time`은 4096자 `window` 전체에서 찾은 값이라 그 시각이 든 줄이 잘린 뒤쪽에 있으면 응답에는 정규화 값만 남는다 [5][23].
잘림 자체는 R02.06에서 본다.

### R01.08 시간대·단위·정밀도 표시

**구현.** `query_registry_value`가 FILETIME을 풀어 쓴 `decoded`는 UTC 시간대가 붙은 시각이라 값 끝에 `+00:00`이 붙는다 [24].
`window`의 `event_time`과 `parse_browser_history`가 바꾼 시각에는 시간대 표기가 없다 [8][23].

**예외.** 같은 응답의 키 수정 시각 `last_written`은 python-registry가 돌려준 값을 `isoformat()`으로 바꾼 것이다 [25].
이 값에 시간대가 붙는지는 그 라이브러리의 동작에 달려 있어 확인하지 못했다 [25].

```python
def _render_treegrid_to_text(treegrid: Any) -> str:
    """Convert a Volatility TreeGrid to tab-separated text."""
    columns = [c.name for c in treegrid.columns]
    lines = ["\t".join(columns)]

    def _visitor(node: Any, accumulator: Any) -> Any:
        """Append one row of tab-separated values to *accumulator*."""
        values = treegrid.values(node)
        row = []
        for i, _col in enumerate(treegrid.columns):
            val = values[i]
            if val is None:
                row.append("")
            else:
                row.append(str(val))
        accumulator.append("\t".join(row))
        return accumulator

    treegrid.populate(_visitor, lines)
    return "\n".join(lines)
```

```python
    for item in results:
```
