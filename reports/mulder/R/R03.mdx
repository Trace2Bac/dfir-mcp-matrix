# R03 분석 상태 알림

### R03.01 구조화 status·error

**구현.** 응답을 만드는 공통 함수 두 개가 상태 필드를 붙인다.
성공 응답 함수 `tool_response`는 `status: success`를, 오류 응답 함수 `error_response`는 `status: error`와 오류 종류 `error_type`, 오류 문구 `error_message`를 싣는다 [1].
서버 코드는 `tool_response`를 87곳, `error_response`를 247곳에서 부른다 [1].
`error_response`를 부르는 247곳 가운데 63곳은 `error_type`을 주지 않아 값이 `unknown`이 된다 [1].
`error_response`를 거치지 않고 오류 `dict`를 직접 만드는 도구도 있고 그 응답에는 `error_type`이 없다 [2].
`windowed_response`와 응답을 직접 만드는 `search`·복합 도구도 `status: success`를 넣는다 [3].

**예외.** `run_volatility`는 플러그인 오류·시간 초과·머리글만 나온 결과를 결과 `dict`의 `status`로 적고 그 `dict`에 `source_name`도 넣는다 [4].
`tool_response`는 `source`가 있으면 결과와 관계없이 최상위 `status`를 `success`로 두고 결과 `dict`는 500자 `preview` 문자열 안에만 싣는다 [5].
그래서 실패한 플러그인 실행이 최상위 `status: success`로 나간다 [4][5].
`run_pcap_analysis`도 모드별 실패를 목록 항목의 `status: error`로 만든 뒤 같은 함수로 감싸 최상위 `success`로 돌려준다 [6].
`finalize_report`와 `check_extraction_status`의 정상 응답에는 `status` 필드가 없다 [7].

### R03.02 찾지 못함과 실패 구분

**구현.** `search`는 일치가 없으면 `status: success`와 `total_matches: 0`을 돌려주고 정규식이 틀리거나 너무 길면 `status: error`를 돌려준다 [8].
`detect_timestomping`은 MFT가 적재되지 않았으면 `status: error`를, 분석했는데 지표가 없으면 결과 안의 `status`를 `no_results`로 돌려준다 [9].
`detect_steganography`는 경로가 없으면 `status: error`를, 이미지 파일을 찾지 못했거나 탐지 문구가 없으면 결과 안의 `status`를 `no_results`로 돌려준다 [10][11].
복합 도구는 필요한 source가 적재되지 않았으면 그 이름과 먼저 돌릴 도구를 `missing_sources`에 싣는다 [12].

다른 조회 도구는 source가 아직 적재되지 않은 것과 결과가 없는 것을 값으로 가르지 않는다.
`list_processes_from_memory` 같은 `windowed_response` 도구는 source가 없어도 `total_windows: 0`인 성공 응답을 돌려준다 [13].
`scan_hidden_processes`는 둘을 `hint` 문장으로만 가른다 [14].
`decode_payload`는 source에서 패턴을 찾지 못한 것을 `status: error`로 돌려준다 [15].

**예외.** `search`를 `regex=True`로 부르면서 `source`를 주지 않으면 서버는 빈 문자열을 source 이름 조건으로 넘긴다 [16].
DB 조건은 이름이 빈 문자열이거나 `.`으로 시작하는 source만 고르므로 일치하는 `window`가 있어도 `total_matches: 0`인 성공 응답이 나온다 [17].
`search`의 설명은 결과 0건을 색인된 증거에 근거가 없다는 뜻이라고 적는다 [18].
`detect_steganography`는 상한 밖에서 검사하지 않은 파일과 실행 오류·시간 초과·읽기 오류로 건너뛴 파일을 응답에 따로 싣지 않는다 [19].
탐지 문구가 없으면 `no_results`와 "No steganographic content detected in N files"를 돌려주고 N은 모은 JPEG·PNG 파일 전체 수다 [11].
그래서 검사하지 못한 파일도 탐지가 없는 파일로 세어진다 [11][19].
stegdetect와 zsteg가 모두 없을 때의 경고 한 줄과 HEIC 변환 안내 한 줄은 탐지 문구와 같은 목록에 들어간다 [20].
이때 탐지가 없어도 결과 안의 `status`는 `no_results`가 아니라 적재 요약의 `indexed`가 되고 `result_count`는 1 이상이 된다 [20][11].
`heif-convert`가 없으면 HEIC 파일을 빼므로 HEIC 파일만 있는 폴더는 이미지 파일을 찾지 못했다는 `no_results` 응답을 받는다 [21][10].

### R03.03 입력별 성공·실패·생략 목록

**구현.** 입력이나 하위 작업 여러 개를 처리하는 도구가 항목마다 상태를 싣는다.
`run_volatility_batch`는 플러그인마다 `status`를 담은 `per_plugin`과 성공·머리글만·실패 개수를 결과 전체로 돌려준다 [22].
`start_extraction_batch`는 인자가 맞지 않아 넣지 않은 작업을 도구·인자·이유와 함께 `tasks_rejected`에 싣고 이미 적재돼 건너뛴 작업을 `tasks_skipped`에 싣는다 [23].
`analyze_disk_pcaps`는 처리하지 못한 PCAP을 파일 이름과 이유로 `pcaps_failed`에 싣고 크기 상한을 넘은 PCAP을 `pcaps_skipped_oversize`에 싣는다 [24].
`detect_masquerading`은 열지 못한 파티션을 `partitions_skipped`에 싣고 미리보기에서 빠지지 않도록 탐지 결과보다 앞에 둔다 [25].
`scan_evidence`는 해시하지 못한 증거 파일의 경로를 `failed_files`에 싣는다 [26].
복합 도구는 적재되지 않은 source를 `missing_sources`와 `coverage_note`에 싣는다 [12].

**예외.** `run_pcap_analysis`에 `mode='all'`을 주면 모드 8개의 상태 목록이 500자 `preview`로만 나가 뒤쪽 모드의 상태가 응답에서 잘린다 [5][6].
`run_registry_parser`의 하이브별 상태 `per_hive`도 같은 미리보기로만 나간다 [27].
`scan_evidence`의 분류기는 알아보지 못한 파일, 점으로 시작하는 경로 조각이 있는 파일, 자동 제외 폴더 아래 파일, 열지 못한 파일을 증거 목록에서 빼고 응답에 알리지 않는다 [28].
일괄 작업의 상태를 묻는 `check_extraction_status`의 `failed_jobs`는 도구 이름과 오류 문구만 싣고 어느 입력에 돌린 작업인지는 싣지 않는다 [29].

### R03.04 시간 초과·부분 완료 표시

**구현.** `run_volatility`는 시간 초과 전에 나온 출력이 있으면 그것을 적재하고 결과 `dict`의 `status`를 `partial`, `error_type`을 `timeout`으로 둔다 [30].
출력이 없으면 `status: error`와 `error_type: timeout`을 둔다 [30].
`run_volatility_batch`의 라이브러리 경로는 플러그인마다 시간 제한을 걸고 넘기면 그 플러그인의 `error_type`을 `timeout`으로 둔다 [31].
`run_zeek_analysis`와 `run_suricata`는 시간 초과 전에 나온 결과를 `zeek.partial`·`suricata.partial`이라는 source로 적재하고 결과 `dict`에 `timed_out: true`를 넣는다 [32].
`run_bulk_extractor`는 시간 초과 때 결과 `dict`에 `partial: true`와 경고 문장을 넣는다 [33].
`run_cli_tool`을 쓰는 도구는 시간 초과를 `error_type: timeout`으로 알린다 [34].
`run_plaso`·`run_foremost` 같은 여러 도구는 시간 초과를 `error_type` 없이 문장으로만 알려 종류가 `unknown`이 된다 [35].

**예외.** `run_zeek_analysis`·`run_suricata`의 `timed_out`과 `run_bulk_extractor`의 `partial`은 결과 목록 뒤에 붙어 500자 `preview`에서 잘릴 수 있다 [5][32][33].
이때 `run_zeek_analysis`·`run_suricata`의 부분 완료는 `zeek.partial`·`suricata.partial`이라는 source 이름으로만 드러난다 [32].
`run_volatility`의 `partial`도 최상위 `status: success` 아래 `preview` 문자열 안에만 있다 [5][30].
`run_cli_tool`은 실행 파일을 열지 못한 운영체제 오류까지 `error_type: timeout`으로 적는다 [34].

```python
def error_response(
    tc_id: str,
    tool_name: str,
    params: Mapping[str, object],
    error: str,
    elapsed_ms: float = 0,
    error_type: str = "unknown",
    suggestion: str | None = None,
) -> dict[str, object]:
    """Build an audited error response and log the tool call."""
    if has_ctx():
        ctx = get_ctx()
        ctx.audit.log_tool_call(
            tool_call_id=tc_id,
            tool_name=tool_name,
            params=params,
            output_hash=hash_output({"error": error}),
            duration_ms=elapsed_ms,
            batch_id=current_batch_id.get(),
        )
    result: dict[str, object] = {
        "tool_call_id": tc_id,
        "status": "error",
        "error_type": error_type,
        "error_message": error,
    }
    if suggestion:
        result["suggestion"] = suggestion
    return result
```

```python
def _check_missing_sources(
    required: list[tuple[str, str]],
) -> list[dict[str, str]]:
    """Return a list of missing sources with suggested extraction commands.

    *required* is a list of ``(source_name, suggested_command)`` pairs.
    Only returns entries for sources not yet indexed.  Uses prefix
    matching so ``volatility.netscan.host1`` satisfies ``volatility.netscan``.

    Network sources (netscan/connscan/sockscan) are treated as
    interchangeable; having any one satisfies the requirement.
    """
    missing = []
    for src, cmd in required:
        if src in _NETWORK_SOURCE_ALTERNATIVES:
            if not any(_source_exists(alt) for alt in _NETWORK_SOURCE_ALTERNATIVES):
                missing.append({"source": src, "suggestion": cmd})
        elif not _source_exists(src):
            missing.append({"source": src, "suggestion": cmd})
    return missing
```
