# I02 분석 도구 통신 차단

### 미구현

**판단.** mulder는 분석 도구를 부를 때 그 도구의 통신을 끊거나 끄는 장치가 없다.
외부 도구를 실행하는 공통 함수 `run_subprocess`는 명령만 넘기고 실행 환경(`env`)이나 네트워크 설정을 바꾸지 않는다 [1].
도구별로 `subprocess.run`을 직접 부르는 곳에도 `env` 인자가 없다 [1].
Volatility 3를 명령 행으로 부를 때는 메모리 파일(`-f`)과 플러그인 이름만 넘기고 오프라인 옵션을 붙이지 않는다 [2].
Volatility 3를 라이브러리로 부를 때도 기본 설정의 `Context`를 만들고 오프라인 설정을 켜지 않는다 [3].
`uv.lock`은 Volatility 3를 2.28.0으로 고정한다 [4].
Volatility 3 2.28.0에서 전역 값 `constants.OFFLINE`의 기본값은 거짓이고 이 값을 켜는 곳은 명령 행의 `--offline` 처리와 URL을 열다 `ValueError`가 난 경우뿐이다 [5].
그래서 명령 행 경로와 라이브러리 경로 모두 기본으로 오프라인 설정이 꺼진 채 실행된다 [2][3][5].
이 값이 꺼져 있으면 Volatility 3는 Windows 커널의 PDB 심볼 표가 로컬 심볼 폴더와 캐시에 없을 때 Microsoft 심볼 서버(`http://msdl.microsoft.com/download/symbols`)에서 PDB를 받아 변환한다 [6].
원격 ISF 목록 주소 `REMOTE_ISF_URL`은 기본값이 `None`이라 이 값을 정하지 않으면 원격 목록은 조회하지 않는다 [7].
명령 행 경로는 사용자 설정 폴더의 `vol.json`을 인자 기본값으로 읽으므로 그 파일이 `offline`이나 `remote_isf_url`을 정하면 동작이 달라진다 [8].
`Dockerfile`은 빌드할 때 Volatility 재단의 Windows·Linux 심볼 묶음을 받아 `mulder` 계정의 Volatility 캐시 폴더 아래 `symbols`에 넣는다 [9].
MVT 도구 `run_mvt_android`·`run_mvt_ios`도 `mvt-android`·`mvt-ios`에 출력 폴더, 증거 경로, 선택 인자 `--iocs`만 넘긴다 [10].
저장소 `Dockerfile`은 MVT를 버전을 정하지 않고 설치한다 [11].
MVT가 실행 중에 새 버전 확인이나 지표 내려받기를 하는지는 MVT 소스를 보지 못해 확인하지 못했다.
README가 안내하는 컨테이너 실행 명령에도 네트워크를 끊는 옵션이 없다 [12].

```python
def run_subprocess(
    cmd: list[str],
    *,
    timeout: int = TOOL_TIMEOUT,
    text: bool = True,
) -> subprocess.CompletedProcess[str] | str:
    """Run a subprocess with standardized timeout handling.

    Returns the CompletedProcess on success, or an error message string
    on timeout/OS failure. Callers check ``isinstance(result, str)`` to
    detect failures.
    """
    try:
        return subprocess.run(cmd, capture_output=True, text=text, timeout=timeout, check=False)
    except subprocess.TimeoutExpired:
        return f"{cmd[0]} timed out after {timeout}s"
    except OSError as exc:
        return f"Failed to run {cmd[0]}: {exc}"
```
