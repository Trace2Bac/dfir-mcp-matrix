# T02 실행 허용 범위 제한

### T02.01 클라이언트 도구 선택

**구현.** 같은 저장소의 `mulder investigate` 오케스트레이터가 이 서버를 쓰는 MCP 클라이언트로서 단계마다 모델에게 보일 도구를 고른다 [1].
도구마다 붙은 `tool_access` 선언은 역할별 도구 이름 목록을 만든다 [2].
오케스트레이터는 그 목록에서 역할 밖 도구를 골라 `disallowed_tools`로 넘겨 모델에게서 숨긴다 [1].
실행 역할 세션을 열 때 `run_executor`는 계획에서 역할 목록 밖 도구의 작업을 뺀다 [3].
그 세션의 허용 목록은 `_build_dynamic_allowlist`가 계획에 나온 도구와 역할 목록의 교집합에 `_EXECUTOR_CONTROL_TOOLS`의 도구 8개를 더해 만든다 [4].
계획에 도구 이름이 하나도 없으면 역할 목록 전체를 허용 목록으로 쓴다 [4].
서버는 도구 모듈을 조건 없이 모두 불러와 등록하고 호출할 때 역할을 검사하지 않는다 [5].
서버에는 이 검사가 없어 다른 MCP 클라이언트로 붙으면 이 제한이 적용되지 않는다 [1][5].

**한계.** 오케스트레이터 안에서도 `run_parallel`과 `start_extraction_batch`는 등록된 도구 이름이면 무엇이든 받아 실행하므로 역할에서 숨긴 도구가 이 두 도구를 거쳐 불린다 [6].
`_build_dynamic_allowlist`는 `_EXECUTOR_CONTROL_TOOLS`의 도구를 역할 목록과 대조하지 않고 더한다 [4].
그 가운데 `list_cases`는 `tool_access` 선언에 실행 역할이 없고 `start_extraction_batch`·`check_extraction_status`·`get_completed_results`·`wait`·`wait_all`은 실행 역할 가운데 `Role.EXTRACT_EXECUTOR`로만 선언된다 [7].
그래서 계획에 도구 이름이 있으면 `list_cases`는 모든 실행 세션에서, 나머지 5개는 `cross_system`·`alternative_narrative` 단계의 실행 세션에서 `disallowed_tools`에 포함되지 않는다 [1][4][7].

### T02.02 클라이언트 자체 도구 우회 차단

**구현.** 이 방식은 같은 저장소의 `mulder investigate` 오케스트레이터가 여는 Claude Agent SDK 세션에 있다 [8].
오케스트레이터는 모든 세션의 옵션에 `tools: []`를 넣어 Claude Code 내장 도구(`Read`·`Grep`·`Glob`·`Write`·`Edit`·`WebFetch`·`Task` 등)를 빼고 MCP 도구만 남긴다 [8].
`uv.lock`이 고정한 claude-agent-sdk 0.2.152는 빈 `tools` 목록을 CLI 인자 `--tools ""`로 넘기고 이 값을 내장 도구를 모두 끄는 값으로 설명한다 [9].
단계 설정은 모든 역할에 적용되는 차단 목록 `disallowed_tools`의 기본값을 `Bash`·`Shell`로 두고 추출 단계의 `_EXTRACTION_BLOCKED_TOOLS`도 이 둘을 담는다 [10].
세션 옵션은 이 차단 목록에 역할 밖 mulder 도구를 더해 `disallowed_tools`로 넘기고 SDK는 이를 `--disallowedTools`로 CLI에 넘긴다 [1][9].
그래서 세션의 모델은 셸이나 파일 도구로 증거를 직접 읽거나 작업 폴더에 쓰지 못하고 MCP 도구만 부른다 [8].
작업 폴더의 `.mcp.json`에 사용자가 넣은 다른 MCP 서버는 세션에 그대로 남고 역할 밖 도구를 고르는 목록은 mulder 도구만 대상으로 한다 [11][1].
이 설정은 오케스트레이터가 여는 세션에만 적용되고 서버에는 이 검사가 없어 다른 MCP 클라이언트로 붙으면 적용되지 않는다 [5].

**한계.** 오케스트레이터는 세션 시작 메시지에 내장 도구가 남아 있으면 경고 로그만 남기고 세션을 이어 간다 [12].
SDK에 묶여 오는 Claude Code CLI가 `--tools ""`를 받으면 실제로 내장 도구를 모두 빼는지는 CLI 소스를 볼 수 없어 확인하지 못했다 [9].

### T02.04 고정 명령·템플릿

**구현.** 외부 도구를 실행하는 도구는 서버 코드가 실행 파일과 옵션을 인자 목록으로 정하고 모델 값을 그 목록의 정해진 칸에 넣는다 [13].
`run_volatility`는 `-f` 뒤에 `memory_path`를, 그 뒤에 플러그인 이름을 둔다 [13].
`run_chainsaw`의 search 모드는 `search` 뒤에 검색어와 증거 경로를 두고 출력 옵션을 붙인다 [13].
실행할 연산을 고르는 값(플러그인 이름, 프로필, 파서 목록)도 이 칸으로 들어간다.

**한계.** 경로 인자가 `-`로 시작하는지 보는 도구는 없고 경로 앞에 `--`를 두어 옵션 해석을 끊는 곳은 `run_dislocker` 하나다 [14].
`run_strings`·`run_hashdeep`·`run_exiftool`·`run_ssdeep`·`run_clamav`는 받은 경로를 옵션 뒤 마지막 칸에 그대로 붙인다 [15].
`run_chainsaw` search 모드의 검색어도 구분자 없이 위치 인자로 들어간다 [13].
이 값들이 `-`로 시작할 때 각 외부 도구가 옵션으로 읽는지는 실행해 보지 않아 확인하지 못했다 [15].
`run_volatility`는 `.`이 들어간 플러그인 이름을 손대지 않고 넘기므로 `-`로 시작하는 이름이 Volatility 옵션으로 읽히는지도 확인하지 못했다 [16].

### T02.05 연산·플러그인 허용 목록

**구현.** `run_pcap_analysis`는 분석 모드를 코드에 둔 10개 목록과 대조하고 목록 밖이면 거부한다 [17].
목록 안의 `custom` 모드는 모델이 쓴 tshark 표시 필터를 `-Y` 값으로 넘기고 서버는 그 필터를 검사하지 않는다 [18].
`parse_android_artifacts`와 `parse_ios_artifacts`는 `artifact_types`를 코드에 둔 아티팩트 표와 대조하고 표에 없는 이름이 있으면 거부한다 [19].

다른 도구에서 실행할 연산을 고르는 값은 목록과 대조하지 않는다.
`run_volatility`의 플러그인 이름은 짧은 이름 표에 없으면 `windows.` 접두어를 붙여 넘긴다 [16].
`run_regripper`의 `profile`과 `run_plaso`의 `parsers`도 목록 없이 `-p`·`--parsers` 값으로 넘긴다 [20].

도구 단위의 허용 목록은 서버에 없다 [5].

### T02.06 질의 구조·연산 검사

**구현.** `query_sqlite_from_image`는 질의가 `SELECT`로 시작하는지와 `;`가 없는지 본 뒤 디스크 이미지에서 꺼낸 DB 사본을 읽기 전용으로 연다 [21].
그 연결에 authorizer `_readonly_authorizer`를 걸어 SQLite가 조회·읽기·함수 호출 연산만 허용하게 한다 [22].
YARA 스캔 도구 3개는 `rules`로 받은 룰 문자열에 `include` 지시문이 있으면 룰을 만들지 않고 오류를 돌려준다 [23].
`run_radare2`는 모델이 넘긴 radare2 명령 묶음 앞에 `e cfg.sandbox=true;`를 붙여 셸 실행, 다른 파일 열기, 대상을 쓰기 모드로 다시 열기를 radare2가 거부하게 한다 [24].
코드 주석은 sandbox를 켠 뒤 같은 묶음 안에서 끄려 하면 radare2가 거부한다고 적고 저장소 시험이 그 동작을 실제 radare2로 확인하는 검사를 둔다 [25].

질의를 받는 다른 인자는 구조를 검사하지 않는다.
`filter_timeline`의 `t_start`·`t_end`·`parser`와 `run_plaso`의 `time_range`는 작은따옴표 안에 그대로 이어 붙여 psort 필터식이 되므로 값에 `'`가 들어가면 필터식의 구조가 바뀐다 [26].
`run_pcap_analysis`의 `custom` 모드 표시 필터도 검사 없이 넘긴다 [18].

**한계.** YARA 스캔 도구의 `rules`가 이미 있는 `.yar` 파일이나 폴더를 가리키면 그 파일을 그대로 쓰고 `include` 검사를 하지 않는다 [23].

```python
    """Return every registered mulder MCP tool that is not in *allowed_tools*.

    ``ClaudeAgentOptions.allowed_tools`` only auto-approves permissions, and
    ``bypassPermissions`` already approves everything, so on its own the

    allowlist is what makes the allowlist real.

    Args:
        allowed_tools: Fully qualified tool names the session may use.

    Returns:

    """
```

```python
    @staticmethod
    def _executable_tasks(
        plan: Plan,
        executor_allowed: list[str],
    ) -> tuple[list[dict[str, Any]], list[str]]:
        """Split plan tasks into those the executor role may run and the rest.

        A task whose tool is off the role allowlist would only ever fail
        with "Tool not available", so it is removed from the plan handed
        to the executor and its tool name reported for logging.

        Args:
            plan: Structured plan from the planner.
            executor_allowed: Full phase-level executor allowlist.

        Returns:
            ``(tasks, dropped)``: executable tasks in plan order, and the
            sorted unique tool names that were dropped.
        """
        allowed_set = frozenset(executor_allowed)
        tasks: list[dict[str, Any]] = []
        dropped: set[str] = set()
        for task in plan.tasks:
            tool = task.get("tool")
            if tool and f"mcp__mulder__{tool}" not in allowed_set:
                dropped.add(str(tool))
            else:
                tasks.append(task)
        return tasks, sorted(dropped)
```

```python
    @staticmethod
    def _build_dynamic_allowlist(
        plan: Plan,
        fallback_allowed: list[str],
    ) -> list[str]:
        """Restrict executor tools to those referenced in the plan.

        Extracts tool names from the planner's task list and intersects
        them with the role-based allowlist. Falls back to the full phase
        allowlist when the plan contains no recognizable tool references.

        Args:
            plan: Structured plan from the planner.
            fallback_allowed: Full phase-level tool allowlist (role-based).

        Returns:
            Sorted list of MCP tool names for the executor session.
        """
        plan_tools = {f"mcp__mulder__{t['tool']}" for t in plan.tasks if t.get("tool")}
        if not plan_tools:
            return fallback_allowed

        allowed_set = frozenset(fallback_allowed)
        safe_plan_tools = plan_tools & allowed_set
        dynamic = safe_plan_tools | _EXECUTOR_CONTROL_TOOLS
        return sorted(dynamic)
```

```python
R2_SANDBOX_PREFIX = "e cfg.sandbox=true;"
"""Enables radare2's sandbox as the first command of every batch.

``commands`` is an r2 script, not a list of arguments, and r2's own command
language can leave r2:

``!cmd``
    runs ``cmd`` in a shell. ``#!pipe sh -c cmd`` does the same by another
    route.
``oo+`` then ``w``
    reopens the target read-write and patches it, even though mulder never
    passes ``-w`` -- so a command string can modify the evidence it was asked
    to examine.
``o /some/path``
    opens any other file the server can read.

The sandbox closes all of these. It has to be the first *command* rather than
an ``-e`` flag: ``r2 -e cfg.sandbox=true`` is applied before the target is
opened and then refuses to open it at all ("Cannot open ..."), so the tool
would return nothing. Set this way it takes effect once the file is open, and
r2 refuses to turn it back off ("Cannot disable sandbox") -- so prefixing it to
an attacker-chosen command string is not something the rest of that string can
undo.
"""
```
