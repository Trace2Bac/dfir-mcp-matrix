# T04 실행 방식

### T04.01 서버 프로세스 안 라이브러리 호출

**구현.** 동기 도구 함수는 서버 프로세스의 스레드에서 실행된다 [1].
`run_volatility_batch`는 Volatility 3 라이브러리로 분석 문맥을 서버 프로세스 안에 만들고 플러그인을 실행한다 [2].
`query_registry_value`는 python-registry 라이브러리로 하이브를 연다 [3].
`index_evtx_file`은 EvtxECmd를 쓸 수 없거나 결과가 없으면 python-evtx 라이브러리로 EVTX를 읽는다 [4].
모바일 아티팩트 도구는 `sqlite3`로 증거 DB를 읽고 `extract_archive`는 `zipfile`·`tarfile`로 압축을 푼다 [5].

`enrich_iocs`는 외부 위협 정보 서비스 API에 IOC를 묻는 조회이고 분석 작업을 원격에 맡기지 않는다 [6].

### T04.02 같은 권한의 별도 프로세스

**구현.** 외부 도구를 쓰는 도구는 `subprocess.run`에 인자 목록을 넘겨 자식 프로세스로 실행한다 [7].
셸 명령 문자열로 실행하는 곳은 찾지 못했다.
자식 프로세스의 계정을 바꾸거나 권한을 낮추는 인자를 주는 곳은 없어 외부 도구는 서버와 같은 계정·파일·네트워크 권한으로 실행된다.
Volatility 실행 파일이 없으면 서버의 파이썬으로 `volatility3.cli`를 별도 프로세스로 실행한다 [8].

컨테이너 이미지는 진입점에서 `gosu`로 비루트 계정 `mulder`로 바꾼 뒤 컨테이너 명령을 실행하므로 서버와 외부 도구도 같은 컨테이너 안에서 그 계정으로 실행된다 [9].
README의 컨테이너 실행 예는 `--privileged`를 주고 증거 폴더를 읽기 전용으로 붙인다 [10].
이미지 주석은 디스크 이미지를 FUSE로 마운트하려면 `--privileged`나 `SYS_ADMIN` 권한으로 컨테이너를 실행하라고 적는다 [11].
서버와 도구를 함께 한 계정으로 낮춘 구성이다.

### T04.05 실행별 작업 폴더

**구현.** `run_zeek_analysis`는 호출마다 임시 폴더를 만들어 Zeek의 작업 위치(`cwd`)로 두고 호출이 끝나면 지운다 [12].
서버 코드에서 외부 도구에 `cwd`를 주는 곳은 이 하나다 [12].
다른 외부 도구는 서버 프로세스의 작업 폴더에서 실행된다.
EZ Tools와 카빙 도구처럼 출력만 호출별 임시 폴더에 쓰게 하는 도구는 이 항목에 넣지 않는다 [13].
