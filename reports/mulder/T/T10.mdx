# T10 도구 명세 구성

### T10.01 처리 함수에서 명세 생성

**구현.** 이 방식은 `mulder serve`가 실행하는 서버의 MCP 도구 모두에 적용된다 [1].
서버는 MCP Python SDK 2.2.0의 `MCPServer`이고 도구는 `@mcp.tool()`로 등록한다 [1].
`app.py`는 `mcp.tool`을 `_concurrent_tool`로 바꿔 동기 함수를 작업 스레드에서 실행하는 비동기 함수로 감싸고 SDK에 넘긴다 [2].
감싼 함수는 `functools.wraps`로 원래 함수의 이름과 docstring을 넘겨받는다 [2].
SDK는 함수 docstring을 도구 설명으로 쓰고 함수 서명으로 입력 schema를 만든다 [3].
서명은 `inspect.signature`로 읽으므로 `functools.wraps`가 남긴 원래 함수의 서명이 schema가 된다 [3].
역할 등록 데코레이터 `tool_access`는 함수를 등록부에 적고 그대로 돌려준다 [4].
예를 들어 `parse_mft`의 설명은 docstring이고 입력 schema의 인자는 `t_start`와 `t_end`다 [5].

서버는 지침(`instructions`) 없이 만들어진다 [1].
서버 코드는 도구 annotation, 목록 변경 알림, MCP 리소스와 프롬프트를 등록하지 않는다 [1].
역할별 도구 목록 `get_tools_for_role`은 오케스트레이터가 쓰는 클라이언트 쪽 허용 목록이다 [4].

**한계.** `run_hashdeep`의 도구 설명인 docstring은 MD5·SHA1·SHA256 해시를 만든다고 적는다 [6].
명령에는 알고리즘을 고르는 `-c`가 없어 hashdeep 4.4의 기본값인 MD5와 SHA-256만 계산한다 [6][7].
`run_aleapp`·`run_ileapp`의 설명은 `artifact_filter`를 처리할 모듈 이름 목록이라고 적는다 [8].
코드는 이 값을 ALEAPP·iLEAPP 명령에 넘기지 않고 모든 모듈을 실행한 뒤 출력 TSV 파일 이름이 목록에 있는 결과만 고른다 [9].
그래서 목록의 이름이 어느 TSV 파일 이름과도 맞지 않으면 모듈이 결과를 냈어도 `no_artifacts`와 "produced no parseable output" 문구를 돌려준다 [10].
`extract_mft_timeline`은 이름과 달리 MFT 자료가 아니라 Plaso 시간선 `plaso.timeline`을 읽는다 [11].
설명은 관련성이 높은 묶음만 돌려준다고 적지만 코드는 시각 범위 안의 `window`를 줄 차례대로 `windowed_response`에 넘겨 앞 20개를 돌려준다 [11][12].
`yara_scan_files`·`yara_scan_memory`의 입력 schema는 `ruleset`을 알리지만 세 값 모두 같은 signature-base 룰을 고르므로 이 인자는 처리에 영향을 주지 않는다 [13].

### T10.02 처리기와 따로 둔 명세

**구현.** 이 방식은 EZ Tools 결과를 읽는 도구 7개(`parse_prefetch_detailed`·`parse_amcache`·`parse_shimcache`·`parse_jump_lists`·`parse_lnk_files`·`parse_shellbags`·`parse_srum`)에 적용된다 [14].
표 `_EZ_TOOLS`의 행마다 도구 이름, 읽을 source 이름, 도구 설명이 있다 [14].
모듈을 읽을 때 루프가 행마다 `_make_ez_tool`로 처리 함수를 만들고 그 함수의 이름과 docstring을 표의 값으로 바꾼 뒤 `mcp.tool()`로 등록한다 [15].
그래서 도구 설명은 처리 코드가 아니라 표에서 오고 입력 schema는 처리 함수의 서명에서 온다 [15][16].
처리 함수는 인자가 없고 표가 준 source 이름의 색인 결과를 요약해 돌려준다 [16].
표의 설명과 처리 코드를 대조하는 장치는 없다 [14][15].
표의 설명은 도구가 건수와 표본을 돌려주고 전체 자료는 `search()`나 `get_raw_output()`로 보라고 적고 처리 함수의 응답도 같은 안내를 싣는다 [14][16].

### T10.03 묶음 도구의 연산별 인자를 schema가 구분하지 않음

**구현.** 이 방식은 다른 도구를 이름으로 부르는 `run_parallel`과 `start_extraction_batch`에 적용된다 [17][18].
두 도구의 입력 schema는 `tasks: list[dict[str, Any]]` 하나이고 각 항목에 넣을 `tool`과 `args`의 모양은 docstring에만 적혀 있다 [17][18].
대상 도구별 인자는 schema에 없고 모델은 그 대상 도구의 MCP 명세를 따로 보고 채운다.
서버는 실행 전에 대상 도구 이름이 등록부에 있는지와 인자 이름이 대상 함수 서명과 맞는지를 확인한다 [17][18][19].

```python
    """Drop-in replacement for ``mcp.tool()`` that auto-threads sync handlers."""
    original_decorator = _original_mcp_tool(**kwargs)

    def decorator(fn: Callable[..., Any]) -> Callable[..., Any]:
        """Register *fn* with the MCP server, wrapping sync handlers for threading."""
        tool_name = kwargs.get("name") or fn.__name__
        _tool_dispatch_sync[tool_name] = fn
        if not inspect.iscoroutinefunction(fn):
            fn = _wrap_sync_tool(fn)
        _tool_dispatch[tool_name] = fn
        return original_decorator(fn)

    return decorator
```

```python
def tool_access(*roles: Role, unthrottled: bool = False) -> Callable[[F], F]:
    """Declare which pipeline roles may call this tool.

    Place this decorator BELOW ``@mcp.tool()`` so it runs first
    and registers the function before MCPServer wraps it.

    ``unthrottled=True`` exempts the tool from the resource gate and
    the tool thread limiter (see ``UNTHROTTLED``).

    Example::

        @mcp.tool()
        @tool_access(EXECUTORS)
        def run_volatility(...):
            ...
    """
    combined = Role(0)
    for r in roles:
        combined |= r

    def decorator(fn: F) -> F:
        _registry[fn.__name__] = combined
        if unthrottled:
            UNTHROTTLED.add(fn.__name__)
        return fn

    return decorator


def get_tools_for_role(role: Role) -> list[str]:
    """Return sorted MCP tool names accessible by a given role."""
    return sorted(f"mcp__mulder__{name}" for name, allowed in _registry.items() if role & allowed)
```

```python
# EZ Tools are registered dynamically to avoid duplicating 7 identical
# no-arg tool functions. Each tool queries a different source name but
# shares the same implementation (_make_ez_tool). The trade-off is that
# these tools are invisible to @mcp.tool() grep searches and IDE
# go-to-definition. If you add a new EZ tool, append to _EZ_TOOLS above.
_EZ_TOOL_ROLES = Role.EXTRACT_ANALYST | Role.CROSS_EXECUTOR

for _name, _source, _doc in _EZ_TOOLS:
    _fn = _make_ez_tool(_source, _name)
    _fn.__name__ = _name
    _fn.__qualname__ = _name
    _fn.__doc__ = _doc
    _fn = tool_access(_EZ_TOOL_ROLES)(_fn)
    mcp.tool()(_fn)
```

```python
async def run_parallel(tasks: list[dict[str, Any]]) -> dict[str, Any]:
    """Run multiple tool calls in parallel and return all results.

    Use this when you need to run the same tool on multiple evidence items
    (e.g., extracting 4 archives, running fls on 4 disk images) or any mix

    Each task specifies a tool name and its arguments.  All tasks execute

    spawn heavy child processes (e.g. ``run_bulk_extractor``) are
    automatically run sequentially to avoid resource exhaustion.

    Args:
        tasks: List of objects, each with ``tool`` (tool name string) and
            ``args`` (dict of keyword arguments for that tool).
```

```python
def validate_tool_args(fn: Callable[..., Any], args: dict[str, Any]) -> str | None:
    """Return why *args* cannot be passed as ``fn(**args)``, or None if they can.

    Planner-generated task args reach tool functions by name, so a wrong
    keyword would otherwise surface as a bare ``TypeError`` in the worker.
    The message names the accepted parameters so the caller can correct
    the call instead of retrying it verbatim.
    """
    params = inspect.signature(fn).parameters
    if any(p.kind is inspect.Parameter.VAR_KEYWORD for p in params.values()):
        return None
    keyword_kinds = (inspect.Parameter.POSITIONAL_OR_KEYWORD, inspect.Parameter.KEYWORD_ONLY)
    accepted = [n for n, p in params.items() if p.kind in keyword_kinds]
    unexpected = sorted(set(args) - set(accepted))
    missing = [
        n for n in accepted if params[n].default is inspect.Parameter.empty and n not in args
    ]
    if not unexpected and not missing:
        return None
    problems = []
    if unexpected:
        problems.append("unexpected parameter(s) " + ", ".join(repr(n) for n in unexpected))
    if missing:
        problems.append("missing required parameter(s) " + ", ".join(repr(n) for n in missing))
    return "; ".join(problems) + "; accepted: " + ", ".join(accepted)
```
