# T07 도구 부재 처리

### T07.01 실행 전 도구·참조 자료 가용성 검사

**구현.** 외부 도구를 실행하는 도구는 실행 전에 실행 파일을 찾고 없으면 실행하지 않는다.
공통 실행 함수 `run_cli_tool`은 `require_binary`로 PATH에서 실행 파일을 찾는다 [1].
capa·Chainsaw·MVT처럼 도구마다 `subprocess.run`을 직접 부르는 곳도 같은 검사를 앞에 둔다 [2].
Volatility는 PATH의 `vol`·`vol3`, 서버 파이썬 옆의 `vol`, `volatility3` 모듈을 차례로 찾고 모두 없으면 실행하지 않는다 [3].
Plaso 도구는 PATH에서 이름을 찾고 없으면 파이썬 인터프리터마다 `-m plaso.cli.<도구> --version`을 시험 실행해 성공하는 것을 쓴다 [4].
EZ Tools 도구는 `dotnet`과 DLL을 둘 다 찾는다 [5].
`detect_steganography`는 `shutil.which`로 stegdetect·zsteg를 먼저 찾고 없는 도구는 실행하지 않는다 [6].
HEIC 변환 함수도 `heif-convert`를 먼저 찾고 없으면 변환하지 않는다 [7].

참조 자료도 실행 전에 본다.
`run_chainsaw`는 hunt 모드에서 Sigma 매핑 파일이 없으면 실행하지 않는다 [8].
YARA 스캔 도구는 룰 파일을 모은 뒤 `yara`로 하나씩 컴파일해 보고 컴파일되는 파일만 쓴다 [9].
쓸 룰이 하나도 없으면 `mulder setup`을 실행하라는 오류로 끝낸다 [10].

**예외.** EVTX를 디스크 이미지에서 꺼내는 함수는 `icat`이 있는지 보지 않고 실행하며 실행 오류가 난 파일은 결과에서 뺀다 [11].
`detect_masquerading`은 시작할 때 `fls`·`icat`을 찾지만 파일 앞부분을 읽는 `_read_head`는 `icat`을 실행하지 못하면 빈 값을 돌려준다 [11].
EVTX를 하나도 꺼내지 못하면 파서는 다른 폴더의 EVTX 파일을 대신 쓰며 이 경로는 T01.08에서 본다.
YARA 룰 파일 가운데 컴파일되지 않거나 다른 파일과 함께 컴파일되지 않는 파일은 빼고 나머지로 스캔한다 [9].
뺀 파일 수는 서버 로그에만 남고 응답에는 없다 [9][12].
`run_plaso`는 `log2timeline`만 실행 전에 찾고 `psort`는 찾지 못해도 `psort.py`라는 이름으로 실행한다 [13].
이 실행은 시간 초과가 나면 오류 응답을 돌려주고 다른 예외는 처리하지 않으므로 `psort.py`도 없으면 예외가 도구 밖으로 나간다 [13].
그 전에 `log2timeline`의 저장 파일은 이미 사건 폴더에 복사돼 있다 [13].

### T07.02 대체 없는 실패 처리·도구 부재 알림

**구현.** 공통 실행 함수와 여러 도구는 실행 파일을 찾지 못하면 `error_type`을 `binary_missing`으로 둔 오류를 돌려준다 [1][14].
Chainsaw·EZ Tools·Volatility는 `mulder setup`이나 설치 방법을 오류 문구나 `suggestion`으로 함께 알린다 [14].
레지스트리 하이브 파서는 RECmd와 RegRipper가 모두 없으면 하이브마다 `no_parser_installed`를 상태로 남기고 RECmd만 실패하고 RegRipper가 없으면 `no_regripper_fallback`을 남긴다 [15].
`run_clamav`처럼 `error_type` 없이 `clamscan not found on PATH` 문구로만 알리는 도구도 있다 [16].

### T07.04 알림 없는 대체 실행

**구현.** 다음 경로는 도구가 없거나 실행·추출이 실패하면 다른 프로그램·경로로 처리하고 응답에 대체 사실을 적지 않는다.

`run_evtx_parser`는 EVTX 파일이나 폴더를 받으면 EZ Tools의 `EvtxECmd`로 먼저 파싱한다 [17].
`EvtxECmd`나 `dotnet`이 없거나 CSV가 나오지 않으면 `python-evtx`로 파싱한다 [17].
두 경로의 응답은 출처 이름(`ez.evtx`와 `evtx.<채널>`)과 사건 DB에 남는 추출기 이름(`eztools`와 `python-evtx`)만 다르다 [17].

EVTX를 하나도 꺼내지 못했을 때 다른 폴더의 EVTX 파일을 대신 쓰는 경로는 T01.08에서 본다.

하이브 파서는 RECmd가 없거나 시간 초과로 끝나거나 빈 출력을 내면 RegRipper로 파싱한다 [18].
RegRipper가 성공하면 하이브 결과에 RECmd 실패를 적지 않고 추출기 이름만 `regripper`로 남는다 [18].
Prefetch·Amcache·Shimcache·MFT 파서와 하이브 파서는 TSK로 파일을 꺼내지 못하면 이미지를 마운트해 다시 찾고 응답은 두 경로를 가리지 않는다 [19].
`extract_archive`는 파이썬 `zipfile`이 압축 방식을 다루지 못하거나 zip 형식이 잘못됐다고 보면 `7z`가 PATH에 있을 때 같은 폴더에 `7z`로 압축 전체를 다시 푼다 [20].
`zipfile`이 먼저 푼 파일은 지우지 않고 `7z`는 `-y`로 같은 이름의 파일을 덮어쓰며 응답은 어느 방식으로 풀었는지 적지 않는다 [20].

### T07.05 실행 환경별 경로 분기

**구현.** 자산은 `MULDER_ASSET_ROOT`가 있으면 그 폴더에서만, 없으면 `/opt`와 사용자 폴더 `~/.local/share/mulder/assets`에서 차례로 찾는다 [21].
Chainsaw는 PATH를 먼저 보고 자산 폴더를 다음에 보며 Hayabusa는 자산 폴더를 먼저 보고 PATH를 다음에 본다 [22].
Volatility는 PATH 실행 파일, 서버 파이썬 옆 실행 파일, 서버 프로세스 안 모듈 호출 순서로 고른다 [3].
Plaso·Hindsight·ALEAPP·iLEAPP를 부르는 도구는 서버 자신의 인터프리터, PATH의 `python3`, `python` 순서로 시험한다 [4][23].
EZ Tools DLL은 자산 폴더 순서대로 찾고 한 폴더 안에서는 설치된 .NET 런타임이 실행할 수 있는 가장 높은 `netN` 폴더의 DLL을 고른다 [24].
고른 실행 파일·인터프리터·DLL의 경로는 응답과 호출 기록에 싣지 않는다 [25].

### T07.06 대체 사실을 응답·기록에 표시

**구현.** Volatility 도구는 netscan 플러그인이 지원되지 않는다는 오류로 실패하면 connscan·sockscan을 차례로 시도한다 [26][27].
대체 플러그인이 결과를 내면 그 결과의 `status`를 `fallback_used`로 두고 원래 플러그인 이름(`original_plugin`)을 함께 싣는다 [26][27].
`run_volatility_batch`는 Volatility 3 라이브러리를 불러오지 못하거나 분석 문맥을 만들지 못하면 플러그인마다 별도 프로세스로 실행한다 [28].
이때 응답에 `execution_mode: subprocess_fallback`을 싣는다 [28].
대체한 까닭(라이브러리 오류 문구)은 서버 로그에만 남는다 [28].
호출 기록에는 결과의 해시만 남아 대체 사실은 응답에만 있다 [29].
`detect_steganography`는 stegdetect·zsteg를 쓸 수 있었는지를 응답 필드 `tools_available`에 싣는다 [30].
두 도구가 모두 없으면 서버의 EOI·`IEND` 기본 검사만 한 결과가 되고 그 사실을 적은 경고 한 줄을 결과 문구와 함께 `steg.detection` `source`로 적재한다 [31].
이 경고는 응답 본문에는 실리지 않고 응답에는 적재 요약만 실린다 [31].

**예외.** 비동기 일괄 실행(`start_extraction_batch`)으로 Volatility 도구를 부르면 `get_completed_results`가 작업 결과에서 몇 필드만 옮긴다 [32].
`run_volatility`의 `preview`와 `run_volatility_batch`의 `results`는 옮기지 않으므로 이 경로로는 대체 표시가 모델에게 가지 않는다 [32].
같은 경로로 `detect_steganography`를 부르면 `tools_available`도 옮기지 않아 stegdetect·zsteg를 쓸 수 없었다는 표시가 모델에게 가지 않는다 [32][30].
HEIC 변환에 쓰는 `heif-convert`가 없다는 사실은 `tools_available`에도 경고에도 없다 [7][30].

def _read_head(image_path: str, offset: int, inode: str, n: int) -> bytes:
    """Return the first *n* bytes of *inode* via icat, killing icat afterwards."""
    cmd = [*_tsk_cmd("icat", image_path, offset), inode]
    try:
        with subprocess.Popen(cmd, stdout=subprocess.PIPE, stderr=subprocess.DEVNULL) as proc:
            assert proc.stdout is not None
            try:
                head: bytes = proc.stdout.read(n)
                return head
            finally:
                proc.kill()
    except OSError:
        return b""

def interpreter_candidates() -> list[str]:
    """Python interpreters to probe, most-likely-correct first.

    ``sys.executable`` is mulder's own interpreter: under ``pipx install`` /
    ``uv tool install`` it is the only one that can see dependencies injected
    into mulder's venv.  The PATH interpreters follow because several helper
    tools (plaso, pyhindsight, ALEAPP, iLEAPP) are *not* mulder dependencies
    and on SIFT live in the system interpreter or a separate venv.  Order
    matters; duplicates are dropped so a probe never runs twice against the
    same binary.
    """
    seen: set[str] = set()
    out: list[str] = []
    for cand in (sys.executable, shutil.which("python3"), shutil.which("python")):
        if cand and cand not in seen:
            seen.add(cand)
            out.append(cand)
    return out

```python
def _framework_rank(path: Path, ceiling: int | None) -> tuple[int, int, str]:
    """Sort key for a DLL candidate: runnable first, then highest netN, then path.

    ``ceiling`` is the installed dotnet major.  .NET rolls *forward* -- a net6
    DLL runs on a net9 runtime -- but never backward, so a DLL whose netN
    exceeds the ceiling cannot run at all and must lose to any DLL that can.
    A DLL with no ``netN`` path component (the container's flat layout) ranks
    ``best = -1``: always runnable, always last among runnable candidates.
    """
    best = -1
    for part in path.parts:
        m = _NET_DIR_RE.match(part)
        if m:
            best = max(best, int(m.group(1)))
    runnable = 1 if (ceiling is None or best <= ceiling) else 0
    return (runnable, best, str(path))
```

@functools.lru_cache(maxsize=32)
def _find_ez_tool(dll_name: str) -> str | None:
    """Locate an EZ Tool DLL: platform root first, mulder's assets second.

    The platform root is searched first even when it is unwritable, because
    SIFT's DLLs are version-matched to SIFT's ``dotnet`` and shadowing them
    with mulder's downloads is a regression.  Within a root, ``sorted()``
    plus the ceilinged rank replaces ``rglob``'s filesystem ordering, which
    picked nondeterministically between ``net6/`` and ``net9/`` copies of the
    same tool.
    """
    ceiling = _dotnet_major()
    for root in asset_candidates(_EZ_TOOL_DIRNAME):
        if not root.is_dir():
            continue
        hits = sorted(root.rglob(dll_name))
        if hits:
            return str(max(hits, key=lambda p: _framework_rank(p, ceiling)))
    return None
