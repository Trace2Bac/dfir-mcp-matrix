# T01 입력 검증

### T01.01 인자 구조·값 검사

**구현.** 값의 가짓수가 정해진 인자는 도구 본문이 코드 상수 목록과 대조한다 [1].
`run_zircolite`의 `log_format`과 `parse_pst`의 파일 확장자는 목록 밖이면 거부한다 [1].
`run_hayabusa`의 최소 심각도, `run_hindsight`의 브라우저, `yara_scan_files`의 `ruleset`은 목록 밖이면 기본값으로 바꾼다 [1].
`submit_finding`은 받은 값으로 `Finding` 모델을 만들어 `severity`·`confidence`가 정한 값인지와 `evidence_refs`가 비어 있지 않은지 보고 어긋나면 거부한다 [2].
사건 시각 인자는 ISO-8601이 아니거나 `T00:00:00` 자정 값이면 비우고 경고를 붙인다 [3].
사건 ID 검사는 T01.05에서 본다.

서버가 실행할 때 읽은 기준과 인자를 대조하는 도구도 있다.
`run_bulk_extractor`는 `scanners`로 받은 이름을 설치된 `bulk_extractor -h` 출력에서 읽은 스캐너 목록과 대조하고 모르는 이름이 있으면 거부한다 [4].
도움말에서 목록을 읽지 못하면 코드에 둔 기본 목록과 대조한다 [4].
`run_bulk_extractor`는 대조하기 전에 `url`·`ip`·`ssn` 같은 이름을 코드에 둔 별칭 표로 `email`·`net`·`accts` 같은 스캐너 이름으로 바꾼다 [5].
바꾼 이름으로 명령을 만들고 응답과 호출 기록에는 받은 `scanners` 값만 남긴다 [6].
`run_volatility_batch`는 Volatility 3 라이브러리가 읽어 들인 플러그인 목록에서 이름을 찾고 없으면 그 플러그인을 실행하지 않고 오류로 남긴다 [7].
플러그인 하나를 별도 프로세스로 실행하는 `run_volatility`는 이름을 대조하지 않는다 [7].
`open_case`는 사용자가 환경변수 `MULDER_CASE_ID`를 두었을 때 다른 사건 ID를 거부한다 [8].
같은 설정에서 `scan_evidence`는 요청한 사건 ID를 그 값으로 바꾼다 [8].

여러 도구를 한 호출로 실행하는 `run_parallel`과 `start_extraction_batch`는 하위 도구 함수를 서버 안에서 바로 부른다 [9].
그 전에 `validate_tool_args`가 인자 이름이 함수 서명과 맞는지만 본다 [9].
하위 도구 본문의 값 검사는 이 경로에서도 그대로 실행된다 [9].

**한계.** `update_finding`은 `severity`·`confidence`·`evidence_refs`를 `Finding` 모델을 거치지 않고 사건 DB에 바로 쓴다 [10].
그래서 `submit_finding`이 거부하는 심각도 값이나 빈 `evidence_refs`도 `update_finding`으로는 들어간다 [10].
`run_volatility_batch`는 라이브러리를 불러오지 못하거나 분석 문맥을 만들지 못하면 플러그인마다 실행 파일을 따로 실행하고 이 경로에서는 플러그인 이름을 대조하지 않는다 [11].
`MULDER_CASE_ID`가 없으면(기본값) 사건 ID를 대조하지 않는다 [8].

### T01.02 입력 존재·읽기 가능 검사

**구현.** 외부 도구에 입력 경로를 넘기는 도구 다수는 실행 전에 경로가 있는지 보고 없으면 `file_not_found` 오류를 돌려준다 [12].
공통 함수는 없고 도구 본문마다 따로 검사한다 [12].
`run_volatility`는 `memory_path`가 없으면 실행 파일을 찾기 전에 거부한다 [13].
외부 도구 실행을 감싸는 `run_cli_tool`은 `check_exists`를 받을 때만 이 검사를 하고 그 값을 넘기는 도구는 `run_pasco` 하나다 [14].
`run_strings`·`run_hashdeep`·`run_exiftool`·`run_ssdeep`·`run_clamav`·`run_regripper`는 경로가 있는지 보지 않고 외부 도구를 실행한다 [15].
읽기 권한을 따로 보는 도구는 없다.

### T01.04 실제 경로로 변환해 허용 폴더 대조

**구현.** `read_evidence_file`과 `list_directory`는 경로 인자를 `resolve_allowed_path`로 실제 경로로 변환해 허용 폴더 안인지 대조하고 밖이면 거부한다 [16].
이 함수는 `..`을 접고 있는 심볼릭 링크를 따라간 경로로 비교하고 그 경로를 돌려준다 [17].
두 도구는 돌려받은 경로로 파일을 열거나 목록을 만든다 [16].
허용 폴더는 사건 DB를 두는 cases 폴더(`db_dir`)와 지금 사건의 증거 루트(`evidence_root`) 둘이다 [18].
cases 폴더 전체가 허용 폴더라서 다른 사건의 DB와 호출 기록 파일도 두 도구로 읽힌다 [18].
`resolve_allowed_path`를 부르는 곳은 두 도구 말고는 `extract_archive`의 압축 해제 목적지뿐이고 그 검사는 쓰기 경로라 D04에서 본다 [19].
외부 파서에 증거 경로를 넘기는 도구와 룰·매핑 파일 경로를 받는 도구는 경로를 허용 폴더와 비교하지 않는다 [20].
`run_chkrootkit`은 `target_path`를 주지 않으면 `-r` 없이 `chkrootkit`을 실행해 서버가 실행되는 시스템 자체를 검사한다 [21].
그 결과는 `source_path`가 `/`인 `chkrootkit.scan`으로 사건 DB에 적재된다 [22].

**한계.** 증거 루트는 모델이 `scan_evidence`의 `evidence_path`로 넘긴 경로를 실제 경로로 변환한 값이다 [23].
`MULDER_CASE_ID`를 두지 않은 서버에서는 모델이 `/` 같은 넓은 경로와 새 사건 ID로 `scan_evidence`를 불러 허용 폴더를 넓힌다 [23].

### T01.05 문자열 경로 검사

**구현.** 사건 ID는 cases 폴더 아래 DB와 호출 기록 파일의 이름이 되므로 `validate_case_id`가 문자열로 검사한다 [24].
빈 값, 플랫폼의 경로 구분자와 `/`, 제어 문자가 든 ID를 거부한다 [24].
구분자가 없는 ID는 뒤에 `.db` 같은 확장자가 붙어 `.`이나 `..`이 아닌 이름 하나가 되므로 cases 폴더 밖을 가리키지 못한다 [24].
이 검사는 사건을 여는 `load_case`와 사건을 만드는 `create_case`, 도구 `open_case`·`scan_evidence`, 시작 인자 `--case-id`를 받는 `init_server`에서 실행된다 [25].

### T01.06 등록된 ID와 대조

**구현.** `extract_file_by_inode`와 `get_file_metadata`는 `image_path`를 받으면 사건 DB에 적재된 `tsk.partitions` 자료 가운데 `source_path`가 같은 것을 찾고 없으면 예외를 내 호출이 오류로 끝난다 [26].
그래서 두 도구가 `icat`·`istat`에 넘기는 이미지는 앞서 파티션 목록을 적재한 이미지로 한정된다 [26].
`image_path`를 주지 않으면 처음 적재한 이미지를 쓴다 [26].

`submit_finding`은 `evidence_refs`의 값마다 호출 기록에 같은 `tool_call_id`가 있는지 보고 하나라도 없으면 거부한다 [27].
이 대조는 사건을 열 때 호출 기록 파일을 읽어 만든 메모리 색인으로 한다 [28].
`update_finding`도 `evidence_refs`를 받으면 같은 대조를 한다 [29].
거부 응답은 호출 기록의 `tool_call_id` 10개를 `valid_refs`로 돌려준다 [27].
대조한 ID의 호출을 근거로 인정할 수 있는지는 D07.01에서 본다.

### T01.07 고정 입력 경로 사용

**구현.** `parse_browser_history`·`parse_plist`·`query_sqlite_from_image`는 이미지 경로를 인자로 받지 않는다 [30].
세 도구는 사건 DB에 적재된 `tsk.partitions`나 `tsk.filelist` 자료의 `source_path`를 이미지 경로로 쓴다 [30].
`filter_timeline`도 사건 DB의 `plaso.stats` 자료가 가리키는 `.plaso` 파일이나 사건 DB 옆의 `.plaso` 파일만 읽는다 [31].

### T01.08 입력 부재 시 다른 입력으로 대체

**구현.** 이 방식은 `run_evtx_parser`와 Hayabusa 도구가 디스크 이미지에서 EVTX를 얻는 경로에 적용된다 [32][33].
두 도구는 TSK의 `icat`으로 EVTX를 하나도 꺼내지 못하면 bulk_extractor 출력 폴더와 사건 DB 폴더(`db_dir`) 아래의 `.evtx` 파일을 모아 대신 쓴다 [32][33].
`extract_archive`는 사건과 관계없이 보관 파일을 `db_dir/extracted` 아래에 풀고 사건 DB도 `db_dir`에 사건마다 하나씩 둔다 [34].
그래서 대신 쓰는 파일에는 카빙한 파일뿐 아니라 다른 사건의 보관 파일에서 푼 `.evtx`도 섞인다 [32][34].
같은 이름의 파일은 처음 찾은 하나만 쓴다 [32].
응답의 파일 목록(`manifest`)은 파일 이름·크기·우선순위만 담아 어느 경로로 얻은 파일인지 가릴 수 없다 [35].

def _sanitize_event_time(ts: str | None) -> tuple[str | None, str | None]:
    """Validate an event timestamp and nullify day-precision placeholders.

    Returns ``(cleaned_value, warning_message)``.  If the timestamp ends
    in ``T00:00:00Z`` it is almost certainly a fabricated day-level
    placeholder and is replaced with ``None``.
    """
    if not ts:
        return None, None
    if _MIDNIGHT_RE.search(ts):
        return None, (
            f"Timestamp '{ts}' looks like a day-precision placeholder "
            f"(T00:00:00). Nullified; omit timestamps you don't have "
            f"precise values for."
        )
    try:
        datetime.fromisoformat(ts.replace("Z", "+00:00"))
    except ValueError:
        return None, f"Timestamp '{ts}' is not valid ISO-8601. Nullified."
    return ts, None
```

def _known_scanners() -> frozenset[str]:
    """Scanner names the installed bulk_extractor accepts.

    Parsed from ``bulk_extractor -h`` on first use so the set tracks the
    installed version; falls back to ``_FALLBACK_SCANNERS`` when the binary
    cannot be run or prints help in an unexpected format.
    """
    try:
        # -h exits non-zero and prints to stdout.
        proc = subprocess.run(
            ["bulk_extractor", "-h"], capture_output=True, text=True, timeout=30, check=False
        )
        parsed = _parse_scanner_help(proc.stdout + proc.stderr)
    except (OSError, subprocess.TimeoutExpired):
        parsed = frozenset()
    if not parsed:
        logger.warning("Could not parse scanner list from bulk_extractor -h; using built-in list")
        return _FALLBACK_SCANNERS
    return parsed
```

def _resolve_plugin_name(plugin: str) -> str:
    """Resolve a short plugin name to the full Volatility 3 class path."""
    if "." in plugin:
        return plugin
    lower = plugin.lower()
    if lower in _VOL_PLUGIN_MAP:
        return _VOL_PLUGIN_MAP[lower]

```python
def validate_tool_args(fn: Callable[..., Any], args: dict[str, Any]) -> str | None:
    """Return why *args* cannot be passed as ``fn(**args)``, or None if they can.

    Planner-generated task args reach tool functions by name, so a wrong
    keyword would otherwise surface as a bare ``TypeError`` in the worker.
    The message names the accepted parameters so the caller can correct
    the call instead of retrying it verbatim.
    """
    params = inspect.signature(fn).parameters
    if any(p.kind is inspect.Parameter.VAR_KEYWORD for p in params.values()):
        return None
    keyword_kinds = (inspect.Parameter.POSITIONAL_OR_KEYWORD, inspect.Parameter.KEYWORD_ONLY)
    accepted = [n for n, p in params.items() if p.kind in keyword_kinds]
    unexpected = sorted(set(args) - set(accepted))
    missing = [
        n for n in accepted if params[n].default is inspect.Parameter.empty and n not in args
    ]
    if not unexpected and not missing:
        return None
    problems = []
    if unexpected:
        problems.append("unexpected parameter(s) " + ", ".join(repr(n) for n in unexpected))
    if missing:
        problems.append("missing required parameter(s) " + ", ".join(repr(n) for n in missing))
    return "; ".join(problems) + "; accepted: " + ", ".join(accepted)
```

```python
def resolve_allowed_path(target: Path, allowed_roots: Iterable[Path]) -> Path:
    """Return *target* resolved inside one of *allowed_roots*.

    Resolution makes containment path-component aware, collapses ``..``,
    follows existing symlinks, and retains the previous behavior for
    non-existent paths.  Symlink loops and other resolution failures are
    denied.

    Raises:
        PathPolicyError: If resolution fails or the target is outside every
            allowed root.
    """
    try:
        resolved_target = _resolve(target)
    except (OSError, RuntimeError) as exc:
        raise PathPolicyError(f"Cannot resolve path: {target}") from exc

    resolved_roots: list[Path] = []
    for root in allowed_roots:
        try:
            resolved_roots.append(_resolve(root))
        except (OSError, RuntimeError) as exc:
            raise PathPolicyError(f"Cannot resolve allowed root: {root}") from exc

    if any(resolved_target.is_relative_to(root) for root in resolved_roots):
        return resolved_target

    raise PathPolicyError("Access denied: path is outside allowed directories")
```
