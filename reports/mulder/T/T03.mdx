# T03 실행 조건 확인

### T03.01 선행 결과 존재 대조

**구현.** 사건을 다루는 도구는 `get_ctx`로 지금 사건을 얻고 앞서 `scan_evidence`나 `open_case`로 연 사건이 없으면 예외를 내 호출이 오류로 끝난다 [1].
`submit_finding`은 `evidence_refs`의 값마다 호출 기록에 같은 `tool_call_id`가 있는지 보고 하나라도 없으면 거부한다 [2].
이 대조는 사건을 열 때 호출 기록 파일을 읽어 만든 메모리 색인으로 한다 [3].
대조는 그 호출이 있었는지만 보므로 오류로 끝난 호출이나 조회 호출의 ID도 통과한다 [3].
거부 응답은 호출 기록의 `tool_call_id` 10개를 `valid_refs`로 돌려준다 [2].

`finalize_report`는 백그라운드 일괄 작업이 모두 끝났는지 먼저 보고 끝나지 않은 묶음이 있으면 `blocked` 상태를 돌려준다 [4].
그 뒤 게이트 5개를 차례로 보고 하나라도 통과하지 못하면 보고서를 쓰지 않는다 [5].
게이트는 부정 발견사항을 뺀 발견사항 수, 시각 면제 등급이 아닌 발견사항의 시작 시각, `narrative` 제출, 점검 도구 `audit_evidence_coverage`·`audit_tool_coverage` 호출, 발견사항이 인용한 증거 `source` 수를 본다 [6].
점검 도구 게이트는 호출 기록의 도구 이름별 호출 횟수에 두 이름이 있는지만 본다 [7].
`load_case`는 끝나지 않은 일괄 작업이 있으면 다른 사건으로 바꾸는 호출을 거부한다 [8].

서버는 `--transport streamable-http`로 HTTP 서버로도 실행되지만 호출자를 확인하는 코드가 없어 T03.09·T03.10에는 연결하지 않는다 [9].

**예외.** `update_finding`은 `evidence_refs`로 빈 목록을 받으면 대조할 값이 없어 통과시키고 그 목록을 그대로 저장하므로 인용이 없는 발견사항이 남는다 [10].
점검 도구 게이트는 오류로 끝난 호출도 센다 [7].
`audit_tool_coverage`는 증거 루트에 접근하지 못하면 `status: "error"`를 돌려주면서 같은 도구 이름으로 호출 기록을 남기므로 점검 없이 게이트를 채운다 [11].
`finalize_report` 설명은 적용할 도구를 모두 실행했는지와 Q1~Q8 질문에 답했는지를 부르기 전 조건으로 적지만 코드는 두 조건을 보지 않는다 [12].
인용 `source` 게이트는 발견사항의 `sources` 문자열과 증거 `source` 이름을 양방향 부분 문자열로 대조한다 [13].
그래서 `sources`에 빈 문자열이 하나 있으면 모든 증거 `source`가 인용된 것으로 세어진다 [13].

### T03.11 실행 자원 사용률 확인

**구현.** 동기 MCP 도구는 등록할 때 `_wrap_sync_tool`로 감싸지고 이 래퍼가 도구를 실행하기 전에 `async_wait_for_resources`를 부른다 [14].
이 함수는 메모리와 CPU 사용률이 기준 이상이면 5초마다 다시 확인하며 기다리고 300초가 지나면 자원 부족이 이어져도 그대로 실행한다 [15].
기준은 메모리·CPU 모두 기본 90%이고 `mulder serve`의 `--mem-limit`·`--cpu-limit`로 바꾼다 [16].
`UNTHROTTLED`로 선언한 작업 조회·대기 도구는 이 확인을 건너뛴다 [14].
비동기 함수로 등록한 도구(`run_parallel`·`enrich_iocs`)는 래퍼로 감싸지지 않아 그 호출 자체는 이 확인을 거치지 않는다 [17].
`run_parallel`은 하위 도구를 등록 표 `_tool_dispatch`에 있는 래퍼로 부르므로 하위 작업은 각자 이 확인을 거친다 [17][18].
배경 작업 스레드는 같은 기준의 동기 함수 `wait_for_resources`로 기다린다 [15].

**예외.** 사용률을 읽지 못하면 값을 -1로 두고 그 값은 기준을 넘지 않은 것으로 보아 확인 없이 실행한다 [15].
`--mem-limit`·`--cpu-limit`를 0으로 주면 확인이 꺼진다 [15][16].

### T03.12 동시 실행 수 제한

**구현.** 이 방식은 `_wrap_sync_tool`로 감싼 동기 MCP 도구에 적용된다 [14].
래퍼는 자원 확인 뒤 공유 `CapacityLimiter`로 도구를 실행한다 [14].
이 제한은 서버 프로세스 하나에 하나 만들어지고 동시에 진행 중인 동기 도구 실행을 `--workers` 개수(기본 8개)로 제한한다 [19][16].
한도는 사용자가 `mulder serve`의 `--workers`로 정하고 모델은 바꾸지 못한다 [16].
`run_parallel`의 하위 작업도 등록 표의 래퍼를 거치므로 같은 제한을 나눠 쓴다 [18].
`UNTHROTTLED`로 선언한 도구는 공유 제한을 건너뛰고 anyio의 기본 스레드 제한 아래에서 실행된다 [14][20].
코드 주석은 이 선언을 외부 프로그램을 실행하지 않는 작업 조회·대기 도구에만 쓴다고 적는다 [20].

**예외.** 배경 작업을 맡기는 `start_extraction_batch`는 `UNTHROTTLED`로 선언되어 공유 제한을 거치지 않는다 [21].
이 도구가 넘긴 추출 작업은 `JobStore`의 별도 `ThreadPoolExecutor`에서 실행된다 [22][23].
이 풀의 크기도 `--workers` 값이고 공유 `CapacityLimiter`와 따로 센다 [19].
작업 스레드는 감싸기 전의 동기 함수 표 `_tool_dispatch_sync`에서 도구를 꺼내 바로 부르므로 공유 제한을 거치지 않는다 [17][24].
그래서 같은 추출 도구가 공유 제한 안에서 `--workers`개, 배경 작업 풀에서 `--workers`개까지 동시에 실행될 수 있다 [19].
미룬 작업을 다시 실행하는 스레드는 배경 작업 풀 밖에서 따로 만들어진다 [25].
이 동작은 코드로만 확인했고 실행하지 않았다.

### T03.13 특정 도구 차례 실행

**구현.** 이 방식은 `run_parallel` 호출 하나 안의 작업 묶음에 적용된다 [26].
`run_parallel`은 `_SEQUENTIAL_ONLY`에 있는 `run_bulk_extractor`를 병렬 묶음에서 빼 두고 병렬 묶음이 모두 끝난 뒤 하나씩 실행한다 [26].
대상 도구 목록은 서버 코드에 고정되어 있고 모델이나 사용자가 바꾸지 못한다 [26].

**예외.** `start_extraction_batch`로 넘긴 `run_bulk_extractor`는 다른 작업과 함께 배경 작업 풀에 들어가 이 순서 제약 없이 실행된다 [22].
모델이 `run_bulk_extractor`를 직접 부르거나 `run_parallel`을 여러 번 겹쳐 부르면 그 실행은 다른 호출의 작업과 차례를 맞추지 않는다 [26].
이 동작은 코드로만 확인했고 실행하지 않았다.

```python
def source_is_cited(source_name: str, finding_sources: set[str]) -> bool:
    """Check if a source is cited by any finding using substring matching.

    Findings cite shorthand like ``"bulk.email (carry-tablet)"`` while
    DB sources are stored as ``"bulk.email"``, so we match if the
    source_name appears as a substring of any finding source string,
    or vice versa.

    Args:
        source_name: Canonical source name from the database.
        finding_sources: Set of source strings cited across findings.

    Returns:
        True if *source_name* is matched by any entry in *finding_sources*.
    """
```

```python
    """Async throttle for MCP tool calls; yields to the event loop while waiting.

    heartbeats and new requests while this tool waits for resources

            tool_name or "tool",

        )
```
