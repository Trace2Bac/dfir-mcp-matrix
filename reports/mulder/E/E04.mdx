# E04 분석 입력 준비

### E04.01 작업 사본 생성

**구현.** `extract_archive`는 zip·tar·gz·bz2·7z·rar 압축 파일을 사건 DB 폴더 아래 `extracted/<압축 이름>-<경로 해시>`에 통째로 푼다 [1][2].
`extract_to`를 주면 그 경로가 `extracted` 안인지 실제 경로로 확인한 뒤 거기에 푼다 [1].
풀기를 마치면 압축 파일 경로와 파일 수를 적은 완료 표시 파일을 쓰고 같은 압축 파일을 다시 부르면 푼 폴더를 그대로 돌려준다 [3].

증거를 사본 없이 제자리에서 여는 도구도 있다.
`parse_android_artifacts`의 폴더 입력과 `decrypt_app_data`는 증거 폴더의 SQLite를 바로 연다 [4].
Volatility·plaso 같은 외부 도구에는 증거 경로를 그대로 넘긴다(E03.03).

**한계.** 완료 표시 파일은 압축 파일의 경로만 대조하므로 같은 경로의 압축 파일 내용이 바뀌어도 앞서 푼 파일을 돌려준다 [3].
`extract_to`로 이미 다른 파일이 있는 폴더를 주면 그 파일까지 이번 압축 파일의 결과 목록과 분류에 들어간다 [2][5].

### E04.02 선택 추출

**구현.** 디스크 이미지를 다루는 파서는 사건 DB에 적재한 `fls` 파일 목록(없으면 그 자리에서 실행한 `fls` 출력)에서 경로가 맞는 항목을 골라 `icat`으로 임시 폴더에 꺼낸다 [6].
Prefetch·레지스트리 하이브처럼 여러 파일을 고르는 경로는 경로 조각을 대소문자 없이 부분 문자열로 대조한다 [6].
`run_evtx_parser`는 이미지에서 이름이 `.evtx`로 끝나는 파일을 모두 꺼내기만 하고 파싱은 `index_evtx_file`로 넘긴다 [7][8].
`extract_file_by_inode`와 `query_sqlite_from_image`는 모델이 고른 inode 하나를 꺼낸다 [9].
`extract_optical_file`은 광학 디스크 이미지에서 경로가 같은 파일 하나를 사건 DB 폴더의 `extracted` 아래로 꺼낸다 [10].
`parse_android_artifacts`는 원시 휴대폰 덤프를 받으면 SQLite 머리 서명으로 DB를 최대 50개까지 잘라 임시 폴더에 쓴다 [11].
잘라 낸 DB는 덤프 안 오프셋으로 이름을 지은 바이트 범위라 원래 파일 경로와 파일시스템 시각이 없다 [11].
`parse_ios_artifacts`는 iOS 백업의 `Manifest.db`에서 앱 DB의 `file_id`로 찾은 파일만 임시 폴더에 복사한 뒤 그 사본을 연다 [12].

**한계.** 레지스트리 하이브는 `config/SYSTEM` 같은 조각을 부분 문자열로 대조해 꺼내므로 `SYSTEM.LOG1`·`SYSTEM.LOG2` 같은 트랜잭션 로그와 `config/systemprofile` 아래 파일도 함께 꺼낸다 [6][13].
꺼낸 파일의 이름이 하이브 이름 목록과 같지 않으면 이름 안에 들어 있는 하이브 이름을 찾아 붙이고 그 파일을 하이브로 파싱한다 [13].
꺼낸 파일 이름은 `Windows_System32_config_SOFTWARE`처럼 전체 경로를 이은 것이다 [6].
그래서 `Windows/System32/config` 아래 파일 이름에는 `system`이 늘 들어 있고 SOFTWARE 하이브에 어느 이름을 붙일지는 `set`을 순회하는 차례에 달려 있다 [13].
`run_evtx_parser`가 이미지에서 EVTX를 하나도 꺼내지 못했을 때 다른 폴더의 `.evtx`를 대신 쓰는 경로는 T01.08에서 본다 [7].
`parse_ios_artifacts`는 `Manifest.db`에서 앱 DB를 찾지 못하면 백업 폴더에서 이름으로 찾은 원본을 복사 없이 연다 [12].

`parse_android_artifacts`는 잘라 낸 DB를 `carved_<오프셋>.sqlite`로 쓰지만 아티팩트마다 `mmssms.db` 같은 정한 파일 이름이나 `mailstore.*.db` 꼴로만 DB를 찾는다 [11][14].
그래서 원시 덤프를 받으면 DB를 잘라 놓고도 어느 아티팩트도 파싱하지 못하고 `No Android artifacts found`를 돌려준 뒤 임시 폴더를 지운다 [15].
`carve_sqlite_from_raw`의 설명은 사건 DB 폴더의 `carved_sqlite`에 잘라 낸 DB를 `query_sqlite_from_image`나 `parse_android_artifacts`로 분석하라고 적는다 [16].
이 도구도 DB를 같은 이름으로 쓰므로 그 폴더를 `parse_android_artifacts`에 주어도 어느 DB도 찾지 못한다 [16][14].
`query_sqlite_from_image`는 파일 경로가 아니라 적재한 디스크 이미지 안의 inode를 받으므로 잘라 낸 DB 파일을 열지 못한다 [17].

### E04.03 전체·부분 마운트

**구현.** 디스크 이미지 파서 5개는 TSK로 파일을 꺼내지 못하면 이미지를 마운트한다(E03.01).
마운트 함수는 `mmls` 결과에서 NTFS·Linux 파티션을 먼저 고르고 없으면 가장 큰 파티션을 골라 그 파티션 하나만 `xmount`로 평면 파일로 보이게 한다 [18].
그 위에 `ntfs-3g`나 `fuse2fs`로 파일시스템을 올리고 파서는 그 아래 정해진 폴더를 읽는다 [18][19].
같은 이미지를 동시에 마운트하면 마운트 하나를 함께 쓰고 마지막 호출이 끝날 때 내린다 [19].
광학 디스크 도구는 E01 이미지만 `xmount`로 평면 파일로 보이게 하고 파일시스템은 서버 코드가 직접 읽는다 [10][20].
`run_dislocker`의 복호화 모드는 BitLocker 볼륨을 `dislocker-fuse`로 임시 폴더에 마운트하고 복호화한 이미지 경로를 돌려준다 [21].

### E04.05 추출·생략 범위 기록

**구현.** `run_evtx_parser`는 꺼낸 EVTX의 이름·크기·우선순위 목록을 응답에 싣고 사건 DB에 `evtx.manifest`로 적재한다 [22].
`extract_archive`는 푼 파일 수와 분류 결과를 응답에 싣고 완료 표시 파일에 파일 수를 남긴다 [3][5].
`extract_optical_file`은 꺼낸 바이트 수가 디스크 목록의 크기와 다르면 경고를 붙인다 [10].
`run_registry_parser`는 하이브마다 파싱 결과나 실패 상태를 응답에 싣는다 [23].

**한계.** `icat`이 실패하거나 시간 제한에 걸린 파일은 기록 없이 건너뛴다 [6][24].
zip 안의 절대 경로나 `..`가 든 항목은 풀지 않고 서버 로그에만 경고를 남긴다 [25].
사용자 하이브를 꺼내지 못한 경우도 서버 로그에만 남는다 [24].

### E04.06 부속 자료 탐색

**구현.** `xmount`로 EWF 이미지를 여는 두 경로(디스크 마운트, 광학 디스크)는 `.E01` 다음 이름(`.E02`, `.E03` …)의 조각을 차례로 찾아 모두 `xmount`에 넘긴다 [18][20][26].
TSK 도구에는 받은 첫 조각의 경로만 넘긴다 [27].
서버 코드가 부속 자료를 찾는 곳은 이 EWF 조각 탐색뿐이다.
SQLite 증거는 본 파일만 복사하거나 inode 하나만 꺼내 `-wal`·`-shm`을 함께 옮기지 않는다 [12][9].
레지스트리 트랜잭션 로그는 E04.02의 한계처럼 부분 문자열 대조에 걸려 함께 꺼내질 뿐 하이브에 적용할 로그로 다루지 않는다 [13].
RECmd가 같은 폴더에 꺼내진 로그를 스스로 적용하는지는 확인하지 못했다.

**한계.** 중간 조각이 없으면 그 앞 조각까지만 `xmount`에 넘기고 뒤에 조각이 더 있다는 사실은 서버 로그에만 남긴다 [26].
응답에는 넘긴 조각 수가 없다.

def _extraction_is_complete(dest: Path, archive: Path) -> bool:
    """Return True only if *dest* holds a finished extraction of *archive*."""
    marker = dest / _COMPLETION_MARKER
    if not marker.is_file():
        return False
    try:
        recorded = json.loads(marker.read_text())
    except (OSError, json.JSONDecodeError):
        return False
    return bool(recorded.get("archive") == str(archive))


def _mark_extraction_complete(dest: Path, archive: Path, file_count: int) -> None:
    """Record that *archive* was fully extracted into *dest*."""
    try:
        (dest / _COMPLETION_MARKER).write_text(
            json.dumps(
                {
                    "archive": str(archive),
                    "file_count": file_count,
                    "completed_utc": datetime.now(timezone.utc).isoformat(),
                },
                indent=2,
            )
        )
    except OSError as exc:
        logger.warning("Could not write extraction marker in %s: %s", dest, exc)

def raw_image(image_path: str) -> Iterator[Path]:
    """Yield a flat, seekable path for *image_path*, xmounting EWF images."""
    path = Path(image_path)
    if not _EWF_FIRST_SEGMENT.search(path.name):
        yield path
        return
    if not shutil.which("xmount"):
        raise OpticalError("xmount not found; cannot read an E01 disc image")
    raw_dir = Path(tempfile.mkdtemp(prefix="mulder_optical_"))
    cmd = ["xmount", "--in", "ewf", *map(str, _ewf_segments(path)), "--out", "raw", str(raw_dir)]
    if not _run(cmd, timeout=120):
        shutil.rmtree(raw_dir, ignore_errors=True)
        raise OpticalError(f"xmount could not expose {path.name}")
    try:
        raw = next(raw_dir.glob("*.dd"), None)
        if raw is None:
            raise OpticalError(f"xmount exposed no .dd file for {path.name}")
        yield raw
    finally:
        _unmount_path(raw_dir, lazy=True)
        shutil.rmtree(raw_dir, ignore_errors=True)

```python
def _ewf_segments(first: Path) -> list[Path]:
    """Every segment file of the EWF image starting at *first*, in order.

    xmount does not find ``.E02``... itself: its ``--in`` help says "If your
    image is split into multiple files, you have to specify them all!", and
    they must be in order.  Walks the names until one is missing; a gap in
    the middle is logged, since xmount will then fail to read the end of the
    data.
    """
    segments = [first]
    while (nxt := segments[-1].with_suffix(_next_ewf_suffix(segments[-1].suffix))).exists():
        segments.append(nxt)
    sibling = re.compile(re.escape(first.stem + first.suffix[:2]) + r"\w\w$")
    strays = sum(1 for p in first.parent.iterdir() if sibling.match(p.name)) - len(segments)
    if strays > 0:
        logger.warning(
            "%s is missing but %d later segment(s) exist; mounting %d segment(s) up to %s",
            nxt.name,
            strays,
            len(segments),
            segments[-1].name,
        )
    return segments
```

def _build_tsk_cmd(
    tool: str,
    image_path: str,
    offset: int,
    fs_type: str | None,
) -> list[str]:
    """Build the base TSK command with optional offset and filesystem type."""
    cmd = [tool]
    if fs_type:
        cmd.extend(["-f", fs_type])
    if offset > 0:
        cmd.extend(["-o", str(offset)])
    cmd.append(image_path)
    return cmd
