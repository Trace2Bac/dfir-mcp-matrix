# T06 실행 환경정보 표시

### T06.01 응답 메타데이터에 버전 표시

**구현.** 결과에 도구 버전을 싣는 도구는 `run_capa` 하나다 [1].
`run_capa`는 capa JSON 출력의 `meta.version`을 결과 필드 `capa_version`으로 옮긴다 [1].
이 값은 그 호출에서 실제로 실행한 capa가 적은 확인 버전이다 [1].
`run_capa`는 capa 원래 출력을 사건 DB의 `capa.analysis`에 넣은 뒤 그 적재 요약에 분석 결과를 더해 `tool_response`로 응답을 만든다 [2].
사건 DB에 넣은 원래 출력에는 capa가 적은 `meta.version`이 그대로 남는다 [2].

다른 외부 도구의 버전은 응답에 싣지 않는다.
호출 기록에는 결과 전체의 해시(`output_hash`)만 남고 버전 값은 남지 않는다 [3].
사건 DB의 `case_metadata`에는 버전을 담을 열 `extractor_versions`가 있지만 서버는 사건을 만들 때 빈 `dict`를 넣고 다시 채우지 않는다 [4].
이 열을 채우는 `update_extractor_versions`를 부르는 곳은 테스트뿐이다 [5].
서버 자신의 판(`__version__`)은 명령 행의 `--version`, `mulder investigate` 시작 문구, `mulder setup`의 상태 파일에만 쓰인다 [6].
MCP 서버의 응답·호출 기록·보고서에는 실리지 않는다 [6].
서버는 모델을 부르지 않으므로 모델 버전을 실을 일이 없다.

**예외.** `tool_response`는 사건 DB에 적재한 도구의 결과를 JSON으로 바꿔 앞 500자만 `preview`로 보낸다 [3].
`capa_version`은 결과 JSON에서 탐지 목록(`capabilities`)과 ATT&CK 요약(`mitre_summary`) 뒤에 놓인다 [1].
탐지 목록이 길면 `capa_version`은 `preview`에서 잘려 응답에 보이지 않는다 [3].
비동기 일괄 실행(`start_extraction_batch`)으로 `run_capa`를 부르면 `get_completed_results`는 작업 결과에서 몇 필드만 옮기고 `preview`는 옮기지 않는다 [7].
이 경로로는 `capa_version`이 모델에게 가지 않는다 [7].

    def update_extractor_versions(self, versions: dict[str, str]) -> None:
        """Update the stored extractor version map."""

        def _do_update() -> None:
            """Overwrite the extractor_versions JSON column."""
            case_id = self._get_case_id()
            with self._engine.begin() as conn:
                conn.execute(
                    update(case_metadata_t)
                    .where(case_metadata_t.c.case_id == case_id)
                    .values(extractor_versions=json.dumps(versions))
                )

        self._wq.submit(_do_update)
