# I02 분석 도구 통신 차단

### 미구현

**판단.** mulder는 분석 도구를 부를 때 그 도구의 통신을 끊거나 끄는 장치가 없다.
외부 도구를 실행하는 공통 함수 `run_subprocess`는 명령만 넘기고 실행 환경(`env`)이나 네트워크 설정을 바꾸지 않는다 [1].
도구별로 `subprocess.run`을 직접 부르는 곳에도 `env` 인자가 없다 [1].
Volatility 3를 명령 행으로 부를 때는 메모리 파일(`-f`)과 플러그인 이름만 넘기고 오프라인 옵션을 붙이지 않는다 [2].
Volatility 3를 라이브러리로 부를 때도 기본 설정의 `Context`를 만들고 오프라인 설정을 켜지 않는다 [3].
Volatility 3가 로컬에 없는 심볼을 스스로 내려받으려 하는지는 실행해 보지 않아 확인하지 못했다.
README가 안내하는 컨테이너 실행 명령에도 네트워크를 끊는 옵션이 없다 [4].
서버 코드가 일부러 여는 YARA 룰 갱신과 IOC 평판 조회는 I01에서 본다.

```python
def run_subprocess(
    cmd: list[str],
    *,
    timeout: int = TOOL_TIMEOUT,
    text: bool = True,
) -> subprocess.CompletedProcess[str] | str:
    """Run a subprocess with standardized timeout handling.

    Returns the CompletedProcess on success, or an error message string
    on timeout/OS failure. Callers check ``isinstance(result, str)`` to
    detect failures.
    """
    try:
        return subprocess.run(cmd, capture_output=True, text=text, timeout=timeout, check=False)
    except subprocess.TimeoutExpired:
        return f"{cmd[0]} timed out after {timeout}s"
    except OSError as exc:
        return f"Failed to run {cmd[0]}: {exc}"
```
