# F02 발견사항·결론 도출

### F02.01 규칙·키 기반 판정·상관

**구현.** 이 방식은 `composite` 모듈의 복합 도구 11개, 숨은 항목 탐지 도구 `scan_hidden_processes`·`scan_kernel_modules`, 탐지 도구 `detect_timestomping`·`detect_masquerading`·`detect_steganography`, 문서 분석 도구 `analyze_office_document`·`analyze_pdf`, 발견사항에서 IOC를 뽑는 `get_ioc_summary`, `finalize_report`가 부르는 보고서 렌더러에 적용된다 [1][2][3][4][5][6][7][8][9].
복합 도구는 사건 DB에 적재된 `source`를 하위 조회로 다시 읽어 정한 규칙과 공유 키로 결과 항목을 만든다 [1].
`find_suspicious_processes`는 Volatility 플러그인 결과마다 PID 색인을 만들고 같은 PID의 흔적을 한 항목에 모은다 [10].
`reconstruct_execution_chains`는 `pstree`의 부모 PID로 자식 목록을 만들고 시스템 프로세스를 부모로 둔 비시스템 프로세스에서 사슬을 시작한다 [11].
사슬은 자식이 있거나 `malfind`·네트워크 연결·DLL 이상이 붙은 것만 남는다 [11].
`find_execution_evidence`는 prefetch·amcache·shimcache·jump list·LNK·`pstree`의 `window`를 실행 파일 이름으로 묶고 그 이름이 나온 자료 종류를 `sources`에 싣는다 [12].
`correlate_pcap_with_host`는 패킷 결과에서 뽑은 IP 집합과 `netscan` 줄의 IP가 겹치면 그 줄의 PID·프로세스 이름을 붙인 항목을 만든다 [13].
`find_lateral_movement_indicators`는 키워드 검색으로 가져온 `window`를 본문의 이벤트 ID·낱말로 로그온·실패 로그온·명시적 자격 증명·WinRM 지표로 나눈다 [14].
같은 도구는 `netscan`과 패킷 대화 목록을 측면 이동 포트 목록(445·3389·5985·5986·135)으로 거른다 [14].
보고서 렌더러는 같은 `evidence_refs`를 인용한 발견사항끼리 관련 발견사항으로 잇는다 [15].
`scan_hidden_processes`는 `volatility.psscan`의 PID 가운데 `volatility.pslist`에 없는 것을 숨은 프로세스로 돌려준다 [2].
`scan_kernel_modules`는 `volatility.modscan`의 모듈 이름 가운데 `volatility.modules`에 없는 것을 숨은 모듈로 돌려준다 [3].
두 도구는 이름이 정확히 같은 `source`의 `window`를 모두 읽으므로 같은 플러그인을 여러 메모리 이미지에 실행한 사건에서는 이미지가 다른 PID와 모듈도 한 집합으로 대조한다 [16].
`analyze_execution_timeline`은 prefetch·amcache·shimcache의 `window`를 실행 파일 이름으로 묶고 amcache에 있고 prefetch에 없는 실행 파일에 `amcache_only_no_prefetch` 표지를 붙인다 [17].
도구 설명은 이 표지를 정리 흔적일 수 있다고 적는다 [18].
prefetch `source`가 적재되지 않은 사건에서도 같은 비교를 하므로 amcache에 나온 실행 파일마다 이 표지가 붙는다 [17][18].
`find_defense_evasion`과 `assess_recovery`는 키워드 검색으로 가져온 이벤트 로그 `window`에 `104`나 `1102`가 문자열로 들어 있거나 `cleared`가 있으면 로그 삭제 지표로 분류한다 [19].
`assess_recovery`는 prefetch·amcache·shimcache의 `window`에 정한 보안 삭제 도구 이름이 들어 있으면 `secure_delete_tool` 지표로 분류한다 [20].
`find_data_exfiltration_indicators`는 정한 서비스 문자열 18개(`mega.nz`·`pastebin.com` 등) 가운데 하나가 `bulk.url`의 `window` 본문에 들어 있으면 `exfil_upload_service` 지표로 싣는다 [21][22].
`bulk.domain`·`pcap.dns`·`pcap.http`의 `window`에서는 같은 문자열의 첫 `/` 앞부분이 본문에 들어 있는지를 본다 [23].
`bulk.email`의 `window`는 `@`가 있으면 `exfil_email` 지표로 싣는다 [22].
`netscan`의 `window`에서 뽑은 포트가 1024보다 크고 정한 표준 포트 목록에 없으면 `high_port_connection` 지표로 싣는다 [24].
Plaso 타임라인을 키워드로 검색해 가져온 `window` 20개 가운데 압축 확장자(`.zip`·`.rar`·`.7z`·`.tar`)나 `staging`·`archive` 낱말이 있는 것은 `large_file_access` 지표로 싣고 파일 크기는 보지 않는다 [25].
이 도구의 설명은 유출 가능성이 있는 지표를 찾는다고 적고 코드는 문자열 조건에 맞은 `window`를 지표로 모을 뿐 전송이 일어났는지는 판정하지 않는다 [26].
`find_file_staging`은 `tsk.filelist`·`ez.mft`의 `window`에 압축 확장자가 들어 있으면 `archive_file`, 압축 확장자와 임시·내려받기·휴지통 폴더 경로 조각이 함께 들어 있으면 `archive_in_suspicious_location` 지표로 싣는다 [27].
`ez.mft`의 `window`에서 읽은 `FileSize` 값이 50MB 이상이면 `large_file_staging` 지표로 싣는다 [28].
압축 확장자와 삭제 표시(`inuse:false`·`deleted`)가 함께 들어 있으면 `archive_created_then_deleted` 지표로 싣는다 [29].
`find_persistence_mechanisms`는 `registry.system`·`registry.software`의 `window`에 정한 자동 실행 키 조각 11개(`\Run\`·`\Winlogon\`·`\Services\` 등) 가운데 하나가 들어 있으면 `registry_autorun` 항목으로 싣는다 [30].
shimcache·amcache·prefetch의 `window`에 `schtasks.exe`·`reg.exe`·`sc.exe` 같은 정한 실행 파일 이름 9개 가운데 하나가 들어 있으면 그 `window`를 지속성 관련 실행 흔적으로 싣는다 [31].
`volatility.svcscan`의 `window`는 조건 없이 모두 `installed_service` 항목으로 싣는다 [32].
`detect_timestomping`은 적재된 MFTECmd 결과 `ez.mft`의 행마다 $SI 생성 시각, $FN 생성 시각, $SI 수정 시각을 비교한다 [4].
$SI 생성 시각이 $FN 생성 시각보다 10초 넘게 이르거나 $SI 수정 시각보다 늦으면 그 파일을 timestomping 지표로 분류하고 맞은 규칙을 `reasons`에 적는다 [4].
Windows Update·servicing·installer 폴더처럼 정한 경로 아래의 파일은 비교에서 뺀다 [4].
지표 파일마다 경로·두 생성 시각·이유를 한 줄로 만들어 `forensic.timestomping` `source`로 사건 DB에 적재하고 응답에는 적재 요약과 지표 수 `result_count`를 싣는다 [33].
`detect_masquerading`은 `fls`로 나열한 일반 파일 가운데 확장자 표에 있는 파일의 앞부분을 `icat`으로 읽어 매직 바이트로 내용 종류를 정한다 [5].
그 종류가 확장자 표가 허용한 종류에 없으면 불일치로 분류하고 표에 없는 확장자나 알아보지 못한 내용은 불일치로 보지 않는다 [5].
표본은 `max_files`(기본 5000)개나 300초에 닿으면 멈추고 응답에 `truncated`를 붙인다 [5].
불일치 파일마다 경로·확장자·탐지한 종류·크기·삭제 여부·시각을 `tsk.masquerade` `source`로 적재하고 결과에 표본 수 `files_sampled`를 싣는다 [34].
`detect_steganography`는 JPEG에는 stegdetect를, PNG에는 zsteg를 실행하고 stegdetect 출력은 `negative`가 없을 때만, zsteg 출력은 비어 있지 않을 때 탐지 문구로 남긴다 [35].
서버 코드의 기본 검사는 JPEG·PNG 파일 끝 8192바이트에서 마지막 JPEG EOI 표지나 PNG `IEND` 청크를 찾고 그 뒤 데이터가 10바이트를 넘으면 덧붙은 데이터로 분류한다 [36].
덧붙은 데이터가 8192바이트보다 길면 원래 표지가 읽은 범위 밖이 되어 이 검사로 찾지 못할 수 있다 [36].
stegdetect는 JPEG 앞 200개, zsteg는 PNG 앞 100개, 기본 검사는 JPEG·PNG를 합친 앞 200개 파일만 보고 실행 오류·시간 초과·읽기 오류가 난 파일은 건너뛴다 [35][36].
HEIC·HEIF 파일은 `heif-convert`로 앞 100개를 JPEG로 바꿔 JPEG 목록에 더한다 [37].
탐지 문구가 하나라도 있으면 그 문구를 `steg.detection` `source`로 사건 DB에 적재한다 [38].

`analyze_office_document`는 olevba가 매크로마다 낸 자동 실행 여부와 의심 낱말의 존재 조합으로 `risk_level`을 정한다 [7].
VBA가 없으면 `clean`, 자동 실행과 함께 실행 낱말이나 내려받기 낱말이 있으면 `malicious`, 자동 실행만 있으면 `high`, 의심 낱말이 있으면 `medium`, VBA만 있으면 `low`다 [7].
이 판정은 가중치나 건수를 쓰지 않고 난독화 낱말(`Chr(`·`ChrW(`·`CallByName`)은 `reasons`와 `obfuscation_detected`에만 실린다 [7].
`analyze_pdf`는 pdfid가 센 구조 낱말과 pdf-parser로 꺼낸 JavaScript로 `risk_level`을 정한다 [8].
`/Launch`가 있거나 JavaScript 낱말·자동 실행 낱말·난독화된 JavaScript 객체가 함께 있으면 `malicious`, JavaScript나 자동 실행 낱말이 있으면 `medium`, 내장 파일 낱말만 있으면 `low`다 [8].

`get_ioc_summary`는 발견사항의 제목·설명에서 정규식으로 뽑은 IP·전자우편 주소·경로·계정·URL 호스트와 적재된 bulk_extractor 결과의 전자우편 주소·도메인을 IOC 목록으로 돌려준다 [9][39].
발견사항은 사건 전체를 읽고 제목이 `[NEGATIVE]`로 시작하는 것도 빼지 않는다 [39].
도메인 목록에서는 정한 잡음 도메인 3개(`microsoft.com`·`windows.com`·`windowsupdate.com`)를 빼고 IP는 공인과 사설로 나눈다 [40].
보고서 렌더러는 "Indicators of Compromise" 부록의 IOC를 뽑을 때 `[NEGATIVE]` 발견사항을 쓰지 않고 나머지 가운데 등급이 `low`·`info`인 것과 제목이나 설명에 "false positive"가 있는 것도 뺀다 [41].

**한계.** `find_lateral_movement_indicators` 설명은 4624 Type 3·10 네트워크 로그온과 WinRM 이벤트 91·168·169를 찾는다고 적는다 [42].
코드는 `4624`나 `logon`이 들어 있는 `window`를 모두 `network_logon`으로 싣고 `type 3`·`type 10`이 없으면 `logon_type`만 `other`로 둔다 [14].
보안 이벤트 로그 `source`가 적재되지 않았으면 하위 검색이 모든 `source`에서 가져온 `window`에도 이 규칙을 적용한다 [14][43].
WinRM 지표는 `window` 본문 어디에든 `91`·`168`·`169`가 있으면 붙으므로 `192.168.`처럼 IP 주소에 `168`이 들어 있는 `window`도 WinRM 연결 지표가 된다 [14].
`detect_timestomping` 설명은 `ez.mft`의 파일 항목마다 $SI와 $FN 시각을 비교한다고 적는다 [44].
코드는 `window`마다 첫 줄을 CSV 머리글로 읽고 그 줄에 $SI·$FN 생성 시각 열 이름이 없으면 그 `window`를 건너뛴다 [45].
`run_mft_parser`는 MFTECmd CSV 전체를 `extract_and_index`로 줄을 자르지 않는 최대 4096자 `window`로 나눠 적재하므로 머리글 줄은 첫 `window`에만 있다 [46][47].
그래서 이 도구는 첫 `window`에 들어 있는 행만 비교하고 나머지 `window`의 행은 비교하지 않는다 [45][46].
지표가 없을 때의 문구와 `total_mft_windows_analyzed`는 가져온 `window` 전체의 수를 분석한 수로 적는다 [33].
`detect_masquerading`이 파일 앞부분을 읽는 함수는 `icat`을 실행하지 못하면 빈 값을 돌려주고 `icat`의 종료 코드는 보지 않는다 [48].
읽지 못한 파일은 알아보지 못한 내용으로 처리되어 불일치에 포함되지 않지만 `files_sampled`에는 표본으로 처리된다 [5].
`detect_steganography`는 `files_scanned`와 결과 없음 문구 "No steganographic content detected in N files"의 N에 모은 JPEG·PNG 파일 전체 수를 쓴다 [38].
그래서 이 수에는 상한 밖에서 검사하지 않은 파일과 오류가 나 건너뛴 파일이 들어간다 [35][36][38].
도구 설명은 HEIC·HEIF 파일을 JPEG로 바꿔 검사한다고 적지만 `heif-convert`가 없으면 그 파일을 알림 없이 뺀다 [6][37].
폴더를 받으면 POSIX 경로에서 대소문자를 가리는 `*.jpg`·`*.jpeg`·`*.png`·`*.heic`·`*.HEIC`·`*.heif` 패턴으로 파일을 모은다 [6].
그래서 `.JPG`·`.PNG`처럼 확장자가 대문자인 JPEG·PNG 파일은 검사하지 않는다 [6].
`analyze_office_document`는 실행 낱말이 있는지를 `write_to_filesystem` 필드에 싣는다 [7].
이 필드 이름은 파일 쓰기를 뜻하지만 값은 `Shell`·`Execute`·`PowerShell` 같은 명령 실행 낱말에서 나온다 [7].
`analyze_pdf`를 `extract_javascript=False`로 부르면 JavaScript를 꺼내지 않고 빈 목록으로 등급을 계산한다 [49].
그래서 JavaScript·자동 실행·난독화 조합의 `malicious` 규칙이 적용되지 않는다 [8][49].
`scan_hidden_processes`의 설명은 psscan이나 pslist가 적재되지 않았으면 빈 결과를 돌려준다고 적는다 [2].
코드는 둘 다 없을 때만 빈 결과를 돌려주고 pslist만 없으면 psscan의 모든 PID를 숨은 프로세스로 돌려준다 [2].
이때 응답에는 pslist가 없다는 안내가 붙지 않고 안내는 psscan이 없을 때만 붙는다 [50].
`scan_kernel_modules`도 modules가 없으면 modscan의 모든 모듈을 숨은 모듈로 돌려주고 안내는 modscan이 없을 때만 붙인다 [3].
같은 대조를 하는 `find_defense_evasion`은 두 자료가 모두 적재돼 있을 때만 대조한다 [51].
로그 삭제 규칙은 문자열 비교라서 IP 주소·시각·레코드 번호에 들어 있는 `104`에도 맞는다 [19].
`find_defense_evasion`은 요청한 이벤트 로그 `source`가 없으면 모든 `source`를 검색한 결과에 이 규칙을 적용한다 [19][43].
`find_data_exfiltration_indicators`는 서비스 문자열을 호스트 이름 단위로 나누지 않고 `window` 본문에 부분 문자열로 있는지만 본다 [22][23].
그래서 서비스 이름을 일부로 가진 다른 호스트 이름이 들어 있는 `window`도 지표가 된다 [22][23].
도구 설명은 외부 전자우편 주소를 표시한다고 적지만 코드는 `bulk.email`의 `window`에 `@`가 있으면 모두 `exfil_email`로 싣고 주소가 조직 안의 것인지 밖의 것인지 가리지 않는다 [22][26].
`find_file_staging`의 설명은 만든 뒤 지운 압축 파일을 찾는다고 적지만 코드는 생성 시각과 삭제 시각을 비교하지 않고 압축 확장자와 삭제 표시가 한 `window`에 함께 있는지만 본다 [29].

### F02.02 시각·위치 근접 연결

**구현.** 이 방식은 `find_lateral_movement_indicators`, `correlate_across_sources`, `deduplicate_findings`에 있다 [52].
`find_lateral_movement_indicators`는 로그온 지표와 측면 이동 포트 연결 지표의 `event_time` 차이가 30초 이하이면 `temporal_correlation` 항목을 만든다 [52].
이 항목에는 두 시각과 로그온 종류·포트·시각 차이만 실리고 호스트·주소·계정은 대조하지 않는다 [52].
`correlate_across_sources`는 모델이 준 시작·끝 시각 사이에 `event_time`이 들어 있는 `window`를 `source` 이름별로 묶는다 [53].
`deduplicate_findings`는 두 발견사항의 사건 시각 범위가 겹치는지를 유사도 점수의 한 항목으로 쓴다 [54].

**한계.** `find_lateral_movement_indicators` 설명은 이벤트를 30초 창으로 잇는다고 적지만 비교하는 시각은 `window`마다 하나다 [42].
`window`는 줄을 모은 최대 4096자 묶음이고 `event_time`은 그 안에서 처음 찾은 시각이다 [47].
이 시각은 초 단위까지만 읽고 시간대 표기를 버린다 [47].
그래서 한 `window`의 뒤쪽 이벤트 시각은 비교하지 않고 출력마다 시간대가 달라도 적힌 숫자를 그대로 비교한다 [47].
`correlate_pcap_with_host` 설명은 패킷 시각을 이벤트 로그·prefetch와 대조한다고 적지만 코드는 시각을 비교하지 않는다 [55].
`t_start`는 이벤트 로그 키워드 검색어에 문자열로 들어가고 `t_end`는 함께 주어졌는지만 본다 [55].
이 도구는 prefetch를 조회하지 않는다 [55].

### F02.03 통계·점수 산정

**구현.** 이 방식은 `find_suspicious_processes`, `triage_binary`, `analyze_pdf`, `enrich_iocs`, `deduplicate_findings`, `find_execution_evidence`, `analyze_execution_timeline`, `run_pcap_analysis`의 `beaconing`·`tunneling` 모드에 적용된다 [56][8][17][57].
`find_suspicious_processes`는 의심 이유마다 정한 가중치를 더해 `anomaly_score`를 싣고 점수순으로 정렬하도록 짜여 있다 [56].
가중치 표는 코드 주입 10, 숨은 프로세스 9, 의심 네트워크 8 같은 값을 두고 표에 없는 이유는 3으로 처리한다 [56].
`triage_binary`는 패킹 지표 하나에 2, 고위험 범주 API 하나에 3, 그 밖의 의심 API 하나에 1, 불가능한 컴파일 시각에 5, 의심스러운 시각에 2, RWX 섹션에 4를 더한다 [58].
합이 10 이상이면 `malicious_indicators`, 4 이상이면 `suspicious_indicators`로 분류하고 분석 단계가 실패했으면 `benign_indicators`를 `inconclusive`로 바꾼다 [58].
`analyze_pdf`는 `malicious` 규칙에 해당하지 않은 문서에서 위험도가 `high`인 pdfid 낱말(`/JS`·`/JavaScript`·`/OpenAction`·`/AA`·`/Launch`)이 두 종류 이상 나오거나 JBIG2 낱말이 있으면 `high`로 둔다 [8][59].
JavaScript 객체의 난독화 여부는 escape 수, `eval`과 `unescape`·`fromCharCode`의 조합, `+` 수, 짧은 변수 선언 수로 만든 지표 5개 가운데 2개 이상이 맞는지로 정한다 [60].
`enrich_iocs`는 외부 조회 서비스가 준 `reputation_score`의 평균을 0~100으로 잘라 `aggregate_score`로 싣고 서비스별 결과는 같은 항목의 `sources`에 남긴다 [61].
`deduplicate_findings`는 제목 낱말·ATT&CK ID·설명 속 IOC·`evidence_refs`·`sources`의 Jaccard 계수와 시각 겹침에 0.20·0.15·0.15·0.25·0.15·0.10을 곱해 더한다 [62].
유사도가 기준값(기본 0.4) 이상인 발견사항은 한 무리가 되고 설명이 가장 긴 것 하나에 나머지가 합쳐진다 [63].
합친 발견사항은 무리 안에서 가장 높은 `severity`를 받고 하나라도 `confirmed`이면 `confirmed`가 된다 [63].
실제로 합치는 호출은 기준값이 0.4 미만이거나 사건 발견사항의 25%를 넘게 흡수하면 거부된다 [64].
`find_execution_evidence`는 실행 파일마다 그 이름이 나온 자료 종류의 수로 결과를 정렬한다 [65].
`analyze_execution_timeline`은 실행 파일마다 붙은 표지 수로 결과를 정렬하고 표지 수가 같으면 그 이름이 나온 자료 종류의 수로 정렬한다 [17].

`run_pcap_analysis`의 `beaconing` 모드는 목적지 IP·포트마다 연결 시각 간격의 평균과 표준편차로 변동계수를 계산한다 [66].
연결이 10번 이상이고 변동계수가 0.3 미만이면 `POTENTIAL BEACON`, 20번 이상이고 0.5 미만이면 `POSSIBLE BEACON`으로 분류한다 [66].
`tunneling` 모드는 DNS 질의 이름의 마지막 두 label을 도메인으로 묶고 도메인마다 질의 수, 하위 도메인의 평균 길이, 하위 도메인 글자의 엔트로피를 계산한다 [67].
질의가 10번 이상인 도메인 가운데 하위 도메인 평균 길이가 20자를 넘거나 엔트로피가 3.5비트를 넘으면 `POTENTIAL DNS TUNNEL`로 분류한다 [67].
질의가 100번을 넘고 고유 하위 도메인이 50개를 넘는 도메인도 같은 판정을 받고 맞은 이유는 판정 문구에 함께 적힌다 [67].
두 모드의 판정 문구와 분석한 목적지·도메인 수는 `pcap.beaconing`·`pcap.tunneling` `source`로 사건 DB에 적재된다 [57].

**한계.** `find_suspicious_processes`의 점수 함수는 항목의 `reasons`를 읽지만 이 도구가 만드는 항목은 이유를 `suspicion_reasons`에 담는다 [68].
그래서 모든 항목의 `anomaly_score`가 0이 되고 정렬은 PID 차례를 바꾸지 않는다 [68].
가중치 표의 이유 이름 4개(`suspicious_network`·`suspicious_cmdline`·`unusual_parent`·`suspicious_dll_path`)도 이 도구가 붙이는 이름(`external_network_connection`·`encoded_powershell`·`suspicious_parent`·`unusual_dll_path`)과 다르다 [68].
`tunneling` 모드는 tshark가 오류를 내면 DNS 질의 목록을 비운 채 계산하고 오류 문구 없이 분석한 도메인 0개와 의심 도메인 0개를 적는다 [69].

### F02.05 사용 근거·변환 기록

**구현.** 이 방식은 복합 도구 11개가 함께 쓰는 마무리 함수 `finalize_composite_result`와 `correlate_across_sources`, `deduplicate_findings`, 점수 도구의 응답에 있다 [70].

`analyze_pdf`는 JavaScript·자동 실행·`/Launch`·내장 파일 낱말과 난독화된 객체 수를 `reasons`에, JBIG2 낱말을 `exploit_indicators`에 싣는다 [8].
high 낱말이 두 종류 이상이라 `high`가 된 경우 그 건수 규칙은 `reasons`에 남지 않는다 [8].

def _extract_chains(nodes: dict[int, dict[str, Any]]) -> list[list[dict[str, Any]]]:
    """Identify chain roots and walk their trees."""
    chains: list[list[dict[str, Any]]] = []
    for pid, node in nodes.items():

                or node["dll_anomalies"]
            ):
                chains.append(chain)

        reverse=True,

    """Compute 0-100 aggregate threat score from multi-source results.
