# L04 기록 위변조 방지

### 미구현

**판단.** 호출 기록 항목에는 앞 항목과 잇는 해시도, 서명도, 일련번호도 없다 [1].
`finding` 항목도 같다 [2].
`_append`는 파일을 덧붙이기 모드로 열 뿐 파일 권한이나 추가 전용 속성을 정하지 않는다 [3].
서버가 사건을 열 때 `_load_existing`이 파일을 읽어 메모리 색인을 다시 만들고 해석하지 못한 줄은 건너뛴 뒤 개수만 경고로 남긴다 [4].
`submit_finding`은 이 색인으로 인용한 호출 ID를 대조하므로 파일에 덧붙여진 항목은 출처를 묻지 않고 인용 근거가 된다 [5].
`verify_evidence_integrity`는 사건 DB에 적재한 자료의 해시만 다시 계산하고 호출 기록 파일은 보지 않는다 [6].
그래서 기록의 수정·삭제·순서 변경을 막거나 알아보는 장치가 없다.

모델이 부를 수 있는 도구로 호출 기록 파일을 지우는 경로도 있다.
`scan_evidence`를 `replace=True`로 부르고 기존 사건 DB가 비었거나 열리지 않으면 DB와 함께 `.audit.jsonl`을 지운다 [7].
`extract_optical_file`은 광학 디스크 이미지 안의 항목 경로를 검사 없이 추출 폴더 아래에 붙이고 그 경로를 `wb`로 연다 [8].
UDF 목록을 만드는 쪽은 부모 항목 표시만 거르고 이름의 `..`는 거르지 않는다 [9].
그래서 조작한 이미지의 항목 경로가 사건 폴더의 `<case_id>.audit.jsonl`을 가리키면 그 파일을 덮어쓸 수 있다 [8][9].

```python
    def _load_existing(self) -> None:
        """Populate in-memory indexes from an existing JSONL file."""
        if not self._log_path.exists():
            return
        parse_errors = 0
        with open(self._log_path) as fh:
            for line in fh:
                line = line.strip()
                if not line:
                    continue
                try:
                    entry = json.loads(line)
                except json.JSONDecodeError:
                    parse_errors += 1
                    continue
                if isinstance(entry, dict):
                    self._index_entry(cast(dict[str, object], entry))
        if parse_errors > 0:
            logger.warning(
                "Audit log %s: %d lines failed to parse (possible corruption)",
                self._log_path,
                parse_errors,
            )
```
