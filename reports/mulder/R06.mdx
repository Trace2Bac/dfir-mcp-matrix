# R06 증거에서 추출한 민감정보 노출 제어

### R06.01 값 가림·필드 제외

**구현.** 조사 중 찾은 비밀번호를 인자로 받는 도구 3개가 호출 기록에서 그 값을 가린다.
`run_dislocker`는 BitLocker 복구 키와 비밀번호를 호출 기록 인자에 `***`로 적는다 [1].
`decrypt_app_data`는 도구 설명에서 키로거 출력·브라우저 저장 비밀번호처럼 조사 중 찾은 비밀번호를 넘기라고 안내하고 호출 기록에는 비밀번호 개수만큼 `***`를 적는다 [2].
이 도구는 복호화에 성공한 DB를 적재할 때 본문 첫 줄에도 비밀번호를 `***`로 적는다 [3].
`extract_steganography`는 호출 기록에 비밀번호 목록 대신 목록을 받았는지만 적는다 [4].
호출 기록 줄은 인자와 결과의 해시만 담고 결과 본문은 담지 않는다 [5].

이 가림은 세 도구의 비밀번호 인자에만 적용된다.
다른 도구의 인자는 그대로 적고 `search`의 질의어도 가리지 않는다 [6].
이 밖에 증거에서 나온 값을 응답·보고서에 싣기 전에 가리는 코드는 없다.
`decrypt_app_data`는 SharedPreferences XML의 키 이름과 값을 그대로 적재한다 [7].
적재 본문은 `get_raw_output`의 `raw_text`로 가리지 않고 돌아간다 [8].
`run_volatility`는 점이 든 플러그인 이름을 바꾸지 않고 넘기고 [9] 그 출력을 가리지 않고 적재한다 [10].
`finalize_report`가 쓰는 HTML 보고서에는 적재 자료마다 `window` 50개까지의 `raw_text`가 그대로 들어간다 [11].
detect-secrets로 비밀 값을 `[REDACTED]`로 바꾸는 `Redactor` 클래스가 있지만 서버와 보고서 코드에서 부르는 곳이 없다 [12].

**예외.** `extract_steganography`는 호출 기록에서 뺀 비밀번호 가운데 추출에 성공한 값을 응답의 `password_used`에 그대로 싣는다 [13].
같은 값을 적재 본문의 문장에도 넣으므로 `search`와 `get_raw_output`으로 다시 나온다 [14].
