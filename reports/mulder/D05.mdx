# D05 발견사항 기록 관리

### D05.01 자유 노트

**구현.** `bookmark_window`는 `window_id` 하나에 자유 글 `note`와 선택 인자 `source_name`을 붙여 북마크로 남긴다 [1].
도구 설명은 발견사항으로 올리기 전의 단서를 표시하는 용도라고 적는다 [1].
북마크 행에는 서버가 작성 시각 `created_at`을 넣고 `window_id`는 외래 키로 `windows` 행을 가리킨다 [2].
`get_bookmarks`는 메모와 함께 그 `window` 본문 앞부분과 사건 시각을 돌려준다 [3].
`submit_narrative`가 받는 보고서 본문은 D08에서 본다 [4].

### D05.02 발견사항 필드 구분 저장

**구현.** `submit_finding`은 제목·설명·심각도·확신도·근거 호출·근거 `source`·ATT&CK ID·사건 시각을 따로 받는다 [5].
배제한 가설은 따로 두지 않고 제목 앞에 `[NEGATIVE]`를 붙인 발견사항으로 남긴다 [6].
이 접두어가 붙은 발견사항은 보고서 마감 게이트의 개수와 사건 시각 요구에서 빠진다 [6].
가설의 상태나 지지·반박 근거를 따로 두는 필드는 없어 D05.07·D05.08에는 연결하지 않는다 [7].

### D05.03 근거 증거·호출 참조

**구현.** 발견사항은 근거 호출 ID 목록 `evidence_refs`와 근거 `source` 이름 목록 `sources`를 필드로 가진다 [7].
자료 모델은 `evidence_refs`가 비어 있으면 거부한다 [7].
`submit_finding`과 `update_finding`은 `evidence_refs`의 값이 모두 호출 기록에 있는지 대조하고 그 심사는 D07에서 본다 [8].
`sources`는 `source` 행의 ID가 아니라 이름 목록이다 [7].

**예외.** `submit_finding`은 `sources`의 이름이 사건 DB의 `source`에 있는지 보지 않고 빈 목록도 받는다 [5].
`update_finding`에 빈 `evidence_refs` 목록을 넘기면 대조할 값이 없어 통과하고 DB에 빈 목록이 저장된 뒤 다시 읽는 단계에서 예외로 끝난다 [9][8].

### D05.04 사건 시각과 작성 시각 분리

**구현.** 발견사항은 사건 시각 `event_time_start`·`event_time_end`와 작성 시각 `submitted_at`을 다른 필드로 가진다 [7].
`submitted_at`은 `submit_finding`이 UTC 현재 시각으로 넣고 `update_finding`은 이 필드를 받지 않는다 [10].
사건 시각은 모델이 넣는 선택 값이고 서버는 ISO-8601이 아니거나 자정 정각으로 끝나는 값을 비우고 경고를 돌려준다 [11].
`deduplicate_findings`로 합친 발견사항의 사건 시각은 합친 발견사항들의 가장 이른 시작과 가장 늦은 끝으로 바뀐다 [12].

### D05.05 수정·철회 이력

**구현.** `update_finding`은 DB의 발견사항 행을 그 자리에서 고치고 호출 기록에 바꾼 필드의 새 값과 시각을 남긴다 [9][13].
`delete_finding`은 행을 지우고 호출 기록에 `finding_id`만 남긴다 [14].
`deduplicate_findings`는 흡수한 발견사항의 제목·ID·심각도·확신도·설명을 남기는 발견사항의 설명 끝에 붙이고 흡수한 행을 지운다 [12].
호출 기록에는 남긴 발견사항과 흡수한 ID의 대응을 인자로 남긴다 [12].
DB 행에는 수정 시각이나 이전 값 열이 없다 [15].

**예외.** `submit_finding`의 호출 기록에는 `description`과 사건 시각이 빠지므로 제출한 뒤 이 둘을 고치면 처음 값은 어디에도 남지 않는다 [16].
`delete_finding`으로 지운 발견사항의 내용은 호출 기록에도 남지 않는다 [14].
`update_finding`이 다시 읽는 단계에서 예외로 끝나면 DB만 바뀌고 호출 기록에는 그 수정이 남지 않는다 [9][13].

### D05.06 파일·DB에 저장

**구현.** 발견사항은 사건마다 하나인 SQLite 파일 `<case_id>.db`의 `findings` 테이블에 쓴다 [15][17].
쓰기는 DB 쓰기 대기열을 거쳐 트랜잭션으로 끝난다 [17].
북마크도 같은 파일의 `bookmarks` 테이블에 남는다 [2].
호출 기록 파일에는 제출마다 `finding_id`와 근거 호출을 담은 `finding` 항목이 따로 남는다 [18].

### D05.10 판정 값 형식 검사

**구현.** `submit_finding`은 `Finding` 자료 모델을 만들며 `severity`가 다섯 값 가운데 하나인지, `confidence`가 `confirmed`·`inference` 가운데 하나인지 검사하고 어긋나면 `validation` 오류로 거부한다 [5][7].

**예외.** `update_finding`은 받은 값을 자료 모델 검사 없이 DB에 쓴 뒤 그 행을 다시 읽는다 [9].
`severity`에 정해진 값 밖의 문자열을 넘기면 DB에는 그 값이 저장되고 다시 읽는 단계의 자료 모델 검사에서 예외로 끝난다 [9][19].
그 뒤에는 같은 행을 읽는 `get_findings`와 `finalize_report`도 같은 검사에서 예외로 끝난다 [19].

def bookmark_window(
    window_id: int,
    note: str,
    source_name: str = "",
) -> dict[str, object]:
    """Bookmark a specific window for later review.

    Use this to flag interesting evidence that doesn't yet warrant a
    full finding. Bookmarks persist in the database and survive context
    compaction. Review bookmarks later with get_bookmarks(). Read-only
    on evidence (writes only to case DB metadata).

    Args:
        window_id: The window_id to bookmark.
        note: Why this window is interesting.
        source_name: Source name for context (optional).
    """
    ctx = get_ctx()
    bookmark_id = ctx.db.add_bookmark(window_id, source_name, note)

    return {
        "status": "success",
        "bookmark_id": bookmark_id,
        "window_id": window_id,
        "note": note,
    }
```

def _sanitize_event_time(ts: str | None) -> tuple[str | None, str | None]:
    """Validate an event timestamp and nullify day-precision placeholders.

    Returns ``(cleaned_value, warning_message)``.  If the timestamp ends
    in ``T00:00:00Z`` it is almost certainly a fabricated day-level
    placeholder and is replaced with ``None``.
    """
    if not ts:
        return None, None
    if _MIDNIGHT_RE.search(ts):
        return None, (
            f"Timestamp '{ts}' looks like a day-precision placeholder "
            f"(T00:00:00). Nullified; omit timestamps you don't have "
            f"precise values for."
        )
    try:
        datetime.fromisoformat(ts.replace("Z", "+00:00"))
    except ValueError:
        return None, f"Timestamp '{ts}' is not valid ISO-8601. Nullified."
    return ts, None
```

    def get_finding(self, finding_id: str) -> Finding | None:
        """Return a single finding by ID, or None if not found."""
        stmt = select(findings_t).where(findings_t.c.finding_id == finding_id)
        with self._engine.connect() as conn:
            row = conn.execute(stmt).fetchone()
        if row is None:
            return None
        return Finding(
            finding_id=row.finding_id,
            case_id=row.case_id,
            title=row.title,
            description=row.description,
            severity=row.severity,
            confidence=row.confidence,
            evidence_refs=json.loads(row.evidence_refs),
            sources=json.loads(row.sources),
            mitre_attack_ids=json.loads(row.mitre_attack_ids) if row.mitre_attack_ids else [],
            event_time_start=row.event_time_start,
            event_time_end=row.event_time_end,
            submitted_at=row.submitted_at,
