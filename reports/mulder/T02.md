# T02 실행 허용 범위 제한

### T02.03 클라이언트 도구 선택

**구현.** 같은 저장소의 `mulder investigate` 오케스트레이터가 이 서버를 쓰는 MCP 클라이언트로서 단계마다 모델에게 보일 도구를 고른다 [1].
도구마다 붙은 `tool_access` 선언은 역할별 도구 이름 목록을 만든다 [2].
오케스트레이터는 그 목록에서 역할 밖 도구를 골라 `disallowed_tools`로 넘겨 모델에게서 숨긴다 [1].
서버는 도구 모듈을 조건 없이 모두 불러와 등록하고 호출할 때 역할을 검사하지 않는다 [3].

**예외.** 다른 MCP 클라이언트로 서버에 붙으면 이 제한이 걸리지 않는다 [1][3].
오케스트레이터 안에서도 `run_parallel`과 `start_extraction_batch`는 등록된 도구 이름이면 무엇이든 받아 실행하므로 역할에서 숨긴 도구가 이 두 도구를 거쳐 불린다 [4].

### T02.06 고정 명령·템플릿

**구현.** 외부 도구를 돌리는 도구는 서버 코드가 실행 파일과 옵션을 인자 목록으로 정하고 모델 값을 그 목록의 정해진 칸에 넣는다 [5].
`run_volatility`는 `-f` 뒤에 `memory_path`를, 그 뒤에 플러그인 이름을 둔다 [5].
`run_chainsaw`의 search 모드는 `search` 뒤에 검색어와 증거 경로를 두고 출력 옵션을 붙인다 [5].
실행할 연산을 고르는 값(플러그인 이름, 프로필, 파서 목록)도 이 칸으로 들어가고 그 값을 좁히는지는 T02.07에서 본다.
셸을 거치지 않는 실행 방식은 T04에서 본다.

**예외.** 경로 인자가 `-`로 시작하는지 보는 도구는 없고 경로 앞에 `--`를 두어 옵션 해석을 끊는 곳은 `run_dislocker` 하나다 [6].
`run_strings`·`run_hashdeep`·`run_exiftool`·`run_ssdeep`·`run_clamav`는 받은 경로를 옵션 뒤 마지막 칸에 그대로 붙인다 [7].
`run_chainsaw` search 모드의 검색어도 구분자 없이 위치 인자로 들어간다 [5].
이 값들이 `-`로 시작할 때 각 외부 도구가 옵션으로 읽는지는 실행해 보지 않아 확인하지 못했다 [7].
`run_volatility`는 `.`이 든 플러그인 이름을 손대지 않고 넘기므로 `-`로 시작하는 이름이 Volatility 옵션으로 읽히는지도 확인하지 못했다 [8].

### T02.07 연산·플러그인 허용 목록

**구현.** `run_pcap_analysis`는 분석 모드를 코드에 둔 10개 목록과 대조하고 목록 밖이면 거부한다 [9].
목록 안의 `custom` 모드는 모델이 쓴 tshark 표시 필터를 `-Y` 값으로 넘기고 서버는 그 필터를 검사하지 않는다 [10].
`parse_android_artifacts`와 `parse_ios_artifacts`는 `artifact_types`를 코드에 둔 아티팩트 표와 대조하고 표에 없는 이름이 있으면 거부한다 [11].

다른 도구에서 실행할 연산을 고르는 값은 목록과 대조하지 않는다.
`run_volatility`의 플러그인 이름은 짧은 이름 표에 없으면 `windows.` 접두어를 붙여 넘긴다 [8].
`run_regripper`의 `profile`과 `run_plaso`의 `parsers`도 목록 없이 `-p`·`--parsers` 값으로 넘긴다 [12].

도구 단위의 허용 목록은 서버에 없고 클라이언트 쪽 도구 선택은 T02.03에서 본다 [3].

### T02.08 질의 구조·연산 검사

**구현.** `query_sqlite_from_image`는 질의가 `SELECT`로 시작하는지와 `;`가 없는지 본 뒤 디스크 이미지에서 꺼낸 DB 사본을 읽기 전용으로 연다 [13].
그 연결에 authorizer `_readonly_authorizer`를 걸어 SQLite가 조회·읽기·함수 호출 연산만 허용하게 한다 [14].
YARA 스캔 도구 3개는 `rules`로 받은 룰 문자열에 `include` 지시문이 있으면 룰을 만들지 않고 오류를 돌려준다 [15].
`run_radare2`는 모델이 넘긴 radare2 명령 묶음 앞에 `e cfg.sandbox=true;`를 붙여 셸 실행, 다른 파일 열기, 대상을 쓰기 모드로 다시 열기를 radare2가 거부하게 한다 [16].
코드 주석은 sandbox를 켠 뒤 같은 묶음 안에서 끄려 하면 radare2가 거부한다고 적고 저장소 시험이 그 동작을 실제 radare2로 확인하는 검사를 둔다 [17].

질의를 받는 다른 인자는 구조를 검사하지 않는다.
`filter_timeline`의 `t_start`·`t_end`·`parser`와 `run_plaso`의 `time_range`는 작은따옴표 안에 그대로 이어 붙여 psort 필터식이 되므로 값에 `'`가 들어가면 필터식의 구조가 바뀐다 [18].
`run_pcap_analysis`의 `custom` 모드 표시 필터도 검사 없이 넘긴다 [10].

**예외.** YARA 스캔 도구의 `rules`가 이미 있는 `.yar` 파일이나 폴더를 가리키면 그 파일을 그대로 쓰고 `include` 검사를 하지 않는다 [15].

```python
def off_role_tools(allowed_tools: list[str]) -> list[str]:
    """Return every registered mulder MCP tool that is not in *allowed_tools*.

    ``ClaudeAgentOptions.allowed_tools`` only auto-approves permissions, and
    ``bypassPermissions`` already approves everything, so on its own the
    role allowlist restricts nothing. ``disallowed_tools`` is the option that
    removes tools from the model's context, so the complement of the
    allowlist is what makes the allowlist real.

    Args:
        allowed_tools: Fully qualified tool names the session may use.

    Returns:
        Sorted MCP tool names the session must not see.
    """
    allowed = frozenset(allowed_tools)
    return [t for t in get_tools_for_role(ALL_ROLES) if t not in allowed]
```

```python
def _readonly_authorizer(
    action: int, arg1: object, arg2: object, db_name: object, trigger: object
) -> int:
    """SQLite authorizer that only permits read operations."""
    if action in _ALLOWED_SQLITE_OPS:

    return sqlite3.SQLITE_DENY
```

```python
        if os.path.isdir(stripped):
            dir_rules = sorted(str(p) for p in Path(stripped).rglob("*.yar"))
            if not dir_rules:
                return [], False
            idx, cleanup = _build_index_file(dir_rules)
            return ([idx], cleanup) if idx else ([], False)
        if re.search(r"^\s*include\s+", stripped, re.MULTILINE | re.IGNORECASE):
            return [], False
        fd, tmp_path = tempfile.mkstemp(suffix=".yar", prefix="mulder_yara_")
        with os.fdopen(fd, "w") as fh:
            fh.write(stripped)
        return [tmp_path], True
```

[17] sandbox 설정의 동작을 적은 주석과 끄기 시도를 확인하는 시험이다.

```python
R2_SANDBOX_PREFIX = "e cfg.sandbox=true;"
"""Enables radare2's sandbox as the first command of every batch.

``commands`` is an r2 script, not a list of arguments, and r2's own command
language can leave r2:

``!cmd``
    runs ``cmd`` in a shell. ``#!pipe sh -c cmd`` does the same by another
    route.
``oo+`` then ``w``
    reopens the target read-write and patches it, even though mulder never
    passes ``-w`` -- so a command string can modify the evidence it was asked
    to examine.
``o /some/path``
    opens any other file the server can read.

The sandbox closes all of these. It has to be the first *command* rather than
an ``-e`` flag: ``r2 -e cfg.sandbox=true`` is applied before the target is
opened and then refuses to open it at all ("Cannot open ..."), so the tool
would return nothing. Set this way it takes effect once the file is open, and
r2 refuses to turn it back off ("Cannot disable sandbox") -- so prefixing it to
an attacker-chosen command string is not something the rest of that string can
undo.
"""
```
