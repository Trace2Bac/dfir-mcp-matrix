# P01 분석 방법 적합성 확인

### P01.01 이름·확장자 판별

**구현.** 사건을 만드는 `scan_evidence`, 압축을 푸는 `extract_archive`, 점검 도구 `audit_tool_coverage`는 같은 분류기 `EvidenceClassifier`로 증거 폴더를 훑는다 [1].
분류기는 확장자와 파일 이름으로 `memory_dump`·`disk_image`·`network_capture`·`evtx` 같은 유형을 정한다 [2].
`.mem`·`.vmem`·`.dmp`·`.001`·`.raw`는 메모리 덤프로, `.e01`·`.dd`·`.img`·`.vmdk`·`.vhd`·`.vhdx`는 디스크 이미지로 본다 [2][3].
두 확장자 목록에 `.iso`가 없어 `.iso` 파일은 사건 목록에 오르지 않는다 [2][3].
분류기 docstring은 실제로 처리할 수 있는지를 추출 때 `Extractor.can_handle`이 정한다고 적지만 기준 커밋에서 그 함수를 정의한 곳을 찾지 못했다 [4].
`scan_evidence`는 정한 유형을 응답의 `evidence_tree`와 `type_summary`에 싣고 어떤 도구를 실행할지는 모델에게 맡긴다 [5].

EVTX 추출 도구 `run_evtx_parser`와 `run_chainsaw`·`run_hayabusa`는 받은 경로가 디스크 이미지인지 확장자로 따로 정하고 이미지이면 이벤트 로그를 꺼내거나 앞서 꺼낸 폴더를 찾아 쓴다 [6].

**한계.** 같은 `.raw`·`.001` 파일을 분류기는 메모리 덤프로 정하고 EVTX·Chainsaw·Hayabusa 도구는 디스크 이미지로 정한다 [2][3][6].
그래서 확장자가 `.raw`인 디스크 이미지는 사건 목록과 점검 도구에서 메모리 덤프로 분류되고 P01.03의 광학 매체 검사도 받지 않는다 [2][7].

### P01.02 메타데이터 조회

**구현.** 디스크 이미지를 읽는 Sleuth Kit 도구는 `mmls`가 읽은 파티션 표 설명으로 분석할 파티션을 고른다 [8].
NTFS·Windows 파티션 가운데 가장 큰 것을 먼저 고르고 없으면 Linux 파티션을, 그것도 없으면 가장 큰 파티션을 고른다 [8].
디스크 이미지 파서가 TSK로 파일을 꺼내지 못해 이미지를 마운트할 때는 `mmls` 결과에서 NTFS·Linux 파티션을 먼저 고르고 없으면 가장 큰 파티션을 고른다 [9].
inode로 파일을 꺼내는 `extract_file_by_inode`와 파일 메타데이터를 읽는 `get_file_metadata`는 `fsstat` 출력에서 파일 시스템 종류를 읽어 `icat`·`istat`에 `-f` 값으로 넘긴다 [10].
`fsstat`가 실패하면 `-f` 없이 Sleuth Kit의 자동 판별에 맡긴다 [10].
분류기는 `.bin` 파일이 50,000,000바이트 이상일 때만 휴대전화 덤프로 보고 `Manifest.db`와 `Info.plist` 또는 `Status.plist`가 함께 있는 폴더를 iOS 백업으로 본다 [11].
이 조회들은 파티션과 파일 시스템 종류를 정할 뿐 증거의 OS를 따로 판별하지 않는다.

**한계.** 모델이 `extract_file_by_inode`·`get_file_metadata`에 `filesystem_type`을 주면 서버는 `fsstat`로 읽은 종류와 대조하지 않고 준 값을 쓴다 [12].

### P01.03 내용·헤더 검사

**구현.** 광학 매체 검사 `probe_optical`은 이미지의 16~31번 섹터를 읽어 UDF·ISO 9660 서명을 찾는다 [13].
EWF 이미지는 Sleuth Kit의 `img_cat`으로 그 섹터만 풀어 읽는다 [13].
`scan_evidence`는 디스크 이미지로 분류한 파일마다 이 검사를 실행하고 광학 매체이면 목록 항목에 `media`와 `run_optical_listing`을 쓰라는 `note`를 붙인다 [7].
`extract_archive`는 이름이 `.gz`·`.bz2`인 압축 파일을 tar로 열어 항목 수를 세고 항목이 있으면 tar로, 없으면 파일 하나로 푼다 [14].

**한계.** EWF 이미지인데 `img_cat`이 없거나 읽다가 오류·시간 초과가 나면 `probe_optical`은 광학 매체가 아니라는 값(`None`)을 돌려주고 판별하지 못했다는 표시를 남기지 않는다 [13].

### P01.04 방법과 형식·OS 대조

**구현.** Sleuth Kit으로 이미지를 처음 읽는 `run_mmls`·`run_fls`·`run_fsstat`은 Sleuth Kit이 실패하거나 `fls`가 빈 출력을 내면 `_optical_redirect`로 이미지를 다시 판별한다 [15].
광학 매체이면 결과를 적재하지 않고 `error_type`이 `optical_media`인 오류와 `run_optical_listing`을 부르라는 `suggestion`을 돌려준다 [16].
docstring은 Sleuth Kit이 UDF·ISO 9660을 읽지 못해 모델들이 디스크의 파일을 다른 장치에서 찾았던 일을 이 대조의 이유로 적는다 [16].

메모리 덤프에는 이런 대조가 없다.
서버는 메모리 덤프의 OS를 판별하지 않고 짧은 플러그인 이름을 모두 `windows.` 플러그인으로 바꾼다 [17].
플러그인이 열 이름만 내면 ISF 심볼이 없거나 메모리 형식을 다 지원하지 못한 경우가 많다는 문구를 붙여 돌려준다 [18].

**한계.** 같은 `fls`로 이미지를 읽는 `run_mactime`은 이 대조를 하지 않아 광학 매체에서는 `fls produced no bodyfile output` 오류만 돌려준다 [19].

    entry: dict[str, object] = {
        "path": str(item.path),

def probe_optical(image_path: str) -> str | None:
    """Return ``udf``/``iso9660`` when *image_path* carries an optical signature.

    Cheap enough for catalog time: raw images are read directly; EWF images
    go through TSK ``img_cat`` (which decompresses just the needed chunk), so
    no mount is involved.
    """
    path = Path(image_path)
    try:
        if _EWF_FIRST_SEGMENT.search(path.name):
            if not shutil.which("img_cat"):
                return None
            proc = subprocess.run(
                ["img_cat", "-b", str(SECTOR), "-s", str(_VRS_START), "-e", str(_VRS_END - 1)]
                + [str(path)],
                capture_output=True,
                timeout=60,
                check=False,
            )
            vrs = proc.stdout if proc.returncode == 0 else b""
        else:
            with open(path, "rb") as fh:
                fh.seek(_VRS_START * SECTOR)
                vrs = fh.read((_VRS_END - _VRS_START) * SECTOR)
    except (OSError, subprocess.TimeoutExpired):
        return None
    return signature_from_vrs(vrs)
```

def _tar_member_count(archive: Path) -> int:
    """Return how many members *archive* yields when read as a tar, else 0.

    ``tarfile.is_tarfile`` cannot answer this for a compressed file: it sees
    the gzip wrapper and returns True for a plain ``.dd.gz`` as readily as for
    a real ``.tar.gz``.  Counting members is the only honest test.
    """
    try:
        with tarfile.open(archive, "r:*") as tf:
            return sum(1 for _ in tf)
    except (tarfile.TarError, OSError, EOFError):
        return 0
```

    tc_id: str, tool_name: str, params: Mapping[str, object], image_path: str
) -> dict[str, object] | None:
    """An error response pointing at run_optical_listing when *image_path* is a disc.

    Sleuth Kit has no UDF/ISO 9660 support: on a burned CD-R ``fls`` and
    ``fsstat`` exit 1 with "Possible encryption detected (High entropy)" and
    ``mmls`` finds no partition table, which sent every model in the NDLC
    benchmark looking for the disc's files on other devices.
    """
    media = probe_optical(image_path)
    if media is None:
        return None
    return error_response(
        tc_id,
        tool_name,
        params,
        f"optical media ({media.upper()}) - Sleuth Kit cannot read CD/DVD filesystems; "
        "use run_optical_listing",
        error_type="optical_media",
        suggestion=(
            f"Call run_optical_listing(image_path={image_path!r}) to list the disc "
            "(deleted files included), then extract_optical_file for individual files."
        ),
    )

def _resolve_plugin_name(plugin: str) -> str:
    """Resolve a short plugin name to the full Volatility 3 class path."""
    if "." in plugin:
        return plugin
    lower = plugin.lower()
    if lower in _VOL_PLUGIN_MAP:
        return _VOL_PLUGIN_MAP[lower]
    return f"windows.{lower}.{plugin}"
