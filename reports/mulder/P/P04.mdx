# P04 조사 문맥 관리

### P04.01 사건 시작 시 ID 확정

**구현.** 사건은 `scan_evidence`가 만든다 [1].
호출자가 `case_id`를 주지 않으면 증거 폴더 이름을 소문자와 하이픈으로 바꿔 ID로 쓰고 받은 ID는 경로 구분자와 제어 문자가 없는지 검사한다 [1][2].
환경변수 `MULDER_CASE_ID`가 있으면 받은 ID 대신 그 값을 쓰고 `open_case`가 다른 사건을 여는 요청을 거부한다 [1][3].
저장소에서 이 환경변수를 넣는 곳은 `mulder investigate` 오케스트레이터뿐이다 [3].
`MULDER_CASE_ID`가 없으면 `open_case`나 다른 ID의 `scan_evidence`로 언제든 열린 사건을 바꾼다 [3][1].
서버를 `--case-id`로 실행하고 그 사건의 DB가 있으면 시작 때 그 사건을 연다 [4].

열린 사건은 프로세스에 하나이고 도구 대부분은 사건 ID를 받지 않고 그 사건에 쓴다 [5].
`enrich_iocs`·`index_app_files`·`query_registry_value` 등 12개 도구는 `case_id` 인자를 받지만 열린 사건과 대조하지 않아 P04.02에는 연결하지 않는다 [6].

**한계.** `--case-id`로 실행했는데 그 사건의 DB가 아직 없으면 서버는 그 ID를 기억하지 않는다 [4].
그때 `MULDER_CASE_ID`도 없으면 첫 `scan_evidence`는 모델이 준 ID나 증거 폴더 이름으로 다른 사건을 만든다 [1][4].

### P04.03 폴더·DB·manifest에 사건 ID 연결

**구현.** 사건 DB 파일 이름이 `<case_id>.db`이고 DB의 `case_metadata` 행에 사건 ID·증거 루트·생성 시각이 들어간다 [7].
발견사항 행에도 사건 ID가 들어간다 [8].
호출 기록 `<case_id>.audit.jsonl`, 보고서 `<case_id>.report.md`·`.report.html`, 서버 로그 사본 `<case_id>.mulder.log`, Plaso 저장 파일 `<case_id>.plaso`도 사건 ID를 이름으로 쓴다 [9].
호출 기록 항목에는 사건 ID 필드가 없고 파일 이름으로만 사건에 묶인다 [10].

**한계.** 압축을 푸는 `extract_archive`와 광학 매체의 파일을 꺼내는 `extract_optical_file`은 cases 폴더의 공용 `extracted/` 아래에 쓰고 폴더 이름에 사건 ID가 없다 [11].
두 도구는 열린 사건이 없어도 실행되고 그때는 호출 기록을 남기지 않는다 [12].

### P04.04 사건별 폴더·DB 분리

**구현.** 사건마다 DB 파일을 따로 만들고 열어서 `source`·`window`·발견사항·증거 해시 목록·진행 기록이 사건별로 나뉜다 [7][13].
프로세스 메모리의 캐시 가운데 `source` 목록 캐시와 디스크 이미지 정보 캐시는 사건 ID를 키에 넣어 사건을 바꾸면 다시 읽는다 [14].

**한계.** `extract_archive`는 압축 파일 경로로만 폴더 이름을 정해 다른 사건이 같은 압축을 풀면 앞 사건이 푼 결과를 그대로 돌려준다 [15].
`carve_sqlite_from_raw`는 복구한 DB를 cases 폴더의 `carved_sqlite/carved_<오프셋>.sqlite`에 써서 다른 사건에서 같은 오프셋으로 만든 파일을 덮어쓴다 [16].
`run_evtx_parser`는 이미지에서 EVTX를 찾지 못하면 cases 폴더 전체에서 찾은 `.evtx`를 이 사건의 추출 폴더로 복사한다 [17].
EVTX 추출 폴더 목록은 프로세스 전역이고 `index_evtx_file`·`run_chainsaw`·`run_hayabusa`는 요청한 이미지의 폴더가 없으면 가장 최근 폴더를 써서 앞 사건의 이벤트 로그를 이 사건에 적재할 수 있다 [18].
IOC 조회 캐시는 IOC 값만 키로 삼는 프로세스 전역 캐시라 앞 사건의 조회 결과를 `cached: True`로 뒤 사건에 돌려주고 그 사건 DB에 적재한다 [19].
서버 로그 `mulder.log`는 cases 폴더에 하나이고 `finalize_report`가 그 파일 전체를 `<case_id>.mulder.log`로 복사해 사건별 사본에 다른 사건의 줄이 섞인다 [20].

### P04.06 동시 작업의 사건 문맥 검사

**구현.** 사건을 여는 `load_case`와 새 사건을 만들기 전에 지금 사건을 닫는 `_close_current_ctx`는 job store에 끝나지 않은 batch가 있으면 사건 전환을 거부한다 [21].

**한계.** 이 검사는 job store의 batch만 본다 [21].
`run_parallel`이 실행하는 작업과 모델이 따로 부른 도구는 job store에 포함되지 않아 그 작업이 진행 중일 때도 사건을 바꿀 수 있다 [22].
적재 함수 `extract_and_index`는 적재하는 시점에 `get_ctx`로 열린 사건을 다시 읽으므로 전환 전에 시작한 추출의 결과가 새 사건에 들어갈 수 있다 [23].
이 경로는 코드로만 확인했고 실행해 보지 않았다.

### P04.08 프로세스 메모리에만 보관

**구현.** 열린 사건 문맥 `_ctx`(사건 ID, DB 연결, 호출 기록 객체)는 모듈 전역 변수 하나다 [5].
세션마다 문맥을 따로 두는 코드가 없어 `--transport streamable-http`로 실행하면 연결한 클라이언트가 모두 같은 열린 사건을 쓴다 [5][24].
그래서 P04.05에는 연결하지 않는다.
job store의 작업·batch·전달한 결과 목록, EVTX·TSK 추출 폴더 목록, `source` 목록 캐시, 디스크 이미지 정보 캐시, IOC 조회 캐시도 프로세스 메모리에만 있다 [25].
이 상태에는 유효 시간이나 개수 한도가 없고 프로세스가 끝나면 사라진다 [25].

### P04.09 조사 상태를 파일·DB에 저장

**구현.** 사건 DB에는 적재한 `source`와 `window`, 발견사항, `narrative`, 증거 해시 목록, 북마크, 진행 기록(`progress`), 키-값 표(`kv_store`)가 있다 [26].
`kv_store`에는 `run_fls`가 찾은 파티션 오프셋과 EVTX 추출 폴더 경로 같은 중간값이 들어간다 [27].
호출 기록은 `AuditLog`가 호출마다 JSONL 한 줄을 덧붙이고 `fsync`로 디스크에 쓴다 [28].
북마크와 진행 기록의 docstring은 DB에 남아 문맥 압축 뒤에도 남는다고 적는다 [29].
발견사항을 남기는 방식은 D05에서 본다.

### P04.10 재시작 뒤 자동 복구

**구현.** `--case-id`를 주고 서버를 실행하면 `init_server`가 그 사건의 DB를 바로 연다 [4].
`--case-id`가 없으면 모델이 `open_case`를 불러야 같은 사건을 다시 읽는다 [4].
사건을 열 때 `AuditLog`는 기존 JSONL을 처음부터 읽어 호출 ID 목록과 도구별 호출 횟수를 다시 만든다 [30].
그래서 다시 시작한 서버에서도 발견사항의 인용 확인과 마감 조건이 앞 프로세스의 호출 기록을 본다 [30].
파티션 오프셋은 `kv_store`에서 다시 읽는다 [27].

**한계.** EVTX 추출 폴더는 서버가 정상 종료할 때 지우지만 `kv_store`의 폴더 경로는 남는다 [31].
다시 시작한 서버에서 `index_evtx_file`은 그 경로를 읽고 폴더가 없어 `run_evtx_parser`를 먼저 부르라는 오류를 낸다 [32].
`run_evtx_parser`를 `force` 없이 다시 부르면 그 이미지에서 만든 `evtx.manifest` `source`가 있어 건너뛴다 [33].
job store의 batch는 다시 만들어지지 않고 그 결과는 P03.03에서 본다.

def slugify(name: str) -> str:
    """Convert a directory name into a valid case ID."""
    slug = name.lower()
    slug = re.sub(r"[^a-z0-9]+", "-", slug)
    return slug.strip("-") or "case"

```python
def _archive_slot(archive: Path) -> str:
    """Return a per-archive directory name that cannot collide.

    ``archive.stem`` alone is ambiguous: two unrelated archives called
    ``evidence.zip`` collect in the same slot, and the second call then takes
    the "already extracted" path and reports the *first* archive's files as
    its own.  Appending a digest of the resolved source path keeps the name
    readable while making it unique to one archive on disk.
    """
    digest = hashlib.blake2b(str(archive).encode(), digest_size=6).hexdigest()
    return f"{archive.stem}-{digest}"
```

        """Populate in-memory indexes from an existing JSONL file."""
        if not self._log_path.exists():
            return
        parse_errors = 0
        with open(self._log_path) as fh:

                    entry = json.loads(line)
                except json.JSONDecodeError:
