# P05 사건 자료 정리

### P05.01 모델 도구로 삭제·초기화

**구현.** 모델 도구 `scan_evidence`에 `replace=True`를 주면 이미 있는 사건을 지우고 다시 만든다 [1].
서버는 지금 열린 사건을 닫고 같은 ID의 DB 파일과 호출 기록 `.audit.jsonl`, 보고서 `.report.md`, Plaso 저장 파일 `.plaso`를 지운 뒤 빈 DB를 만든다 [2].
`.report.html`과 `<case_id>.mulder.log`, `extracted/`·`carved_sqlite/` 아래 파일은 지우지 않는다 [2].
프로세스 메모리의 EVTX 추출 폴더 목록과 IOC 조회 캐시도 비우지 않는다 [2].
끝나지 않은 batch가 있으면 사건을 닫지 못해 지우지 않는다 [3].
새 호출 기록에는 `replace`가 참인 `scan_evidence` 호출이 남을 뿐 무엇을 지웠는지는 남지 않는다 [4].
DB가 손상돼 지울 때만 서버 로그에 경고가 남는다 [4].
진행 중인 조사에서 발견사항이나 북마크 한 건을 지우는 도구는 D05에서 본다.

**한계.** 도구 설명은 사건이 이미 있으면 지우고 다시 만든다고 적지만 적재한 `source`가 하나라도 있으면 지우지 않고 기존 사건을 연다 [1][5].
그때 응답은 `case_exists`와 분석을 이어 하라는 문구뿐이고 `replace`를 받아들이지 않았다는 사실은 서버 로그에만 남는다 [5].

### P05.03 자동 정리

**구현.** 서버는 디스크 이미지에서 꺼낸 EVTX 파일과 Sleuth Kit으로 꺼낸 파일을 임시 폴더에 두고 프로세스가 끝날 때 `atexit`으로 그 폴더를 모두 지운다 [6].
Prefetch·Amcache·ShimCache·레지스트리 하이브처럼 꺼낸 파일을 바로 파싱하는 도구는 파싱이 끝나면 그 임시 폴더를 곧바로 지운다 [7].
두 경로 모두 지운 사실을 기록하지 않는다 [6][7].
파일에서 읽어 적재한 본문은 사건 DB에 남는다.
지운 폴더의 경로가 사건 DB에 남아 다시 시작한 뒤 생기는 일은 P06에서 본다.

### P05.05 원본 증거를 삭제 대상에서 제외

**구현.** `replace`가 지우는 파일은 cases 폴더 안의 `<case_id>.db`와 같은 이름의 파일 3개로 정해져 있고 증거 루트의 파일은 대상에 없다 [2].
사건 ID는 경로 구분자를 담을 수 없어 이 파일들이 cases 폴더 밖을 가리키지 못한다 [8].
자동 정리가 지우는 폴더도 서버가 `tempfile.mkdtemp`로 만든 임시 폴더다 [6][9].

### P05.08 자료가 남은 사건의 초기화 거부

**구현.** `replace=True`로 이미 있는 사건을 다시 만들려 해도 그 DB에 적재한 `source`가 있으면 지우지 않고 기존 DB를 연다 [5].
`create_case` docstring은 단계 사이에 새로 뜬 서버가 추출 자료를 지우지 않게 하려는 장치라고 적는다 [10].

**한계.** 이 판단은 `source` 수만 센다 [5].
`source`를 적재하지 않은 사건은 발견사항, `narrative`, 증거 해시 목록, 호출 기록이 있어도 모두 지운다 [2][5].
DB를 열거나 메타데이터를 읽다가 오류가 나면 `replace=True`일 때 그 DB와 호출 기록을 함께 지운다 [11].

### P05.09 진행 중인 세션이 있는 사건의 초기화 거부

**구현.** `scan_evidence`는 사건을 만들기 전에 지금 열린 사건을 닫는다 [2].
job store에 끝나지 않은 batch가 있으면 닫기가 오류로 멈추므로 `replace=True`로도 사건을 지우지 않는다 [3].
이때 `scan_evidence`는 `scan_evidence failed:` 뒤에 그 batch가 아직 실행 중이라는 문구를 붙여 오류로 답한다 [12].
진행 여부는 job store의 batch 상태로만 판단한다 [3].

**한계.** `run_parallel`이 실행하는 작업과 모델이 따로 부른 도구는 job store에 포함되지 않아 진행 중이어도 초기화를 막지 않는다 [13].

def _cleanup_tsk_extract_dir(dir_path: str) -> None:
    """Remove a TSK extraction temp directory and deregister it.

    Callers should invoke this after consuming extracted files so that
    disk space is reclaimed promptly rather than at process exit.

    Args:
        dir_path: Absolute path to the temp directory to remove.
    """
    shutil.rmtree(dir_path, ignore_errors=True)
    with _tsk_lock, contextlib.suppress(ValueError):
        _tsk_extract_dirs.remove(dir_path)

    No extractors are run; the agent populates the case incrementally
    by calling Tier 2 extraction tools.

    If a database for this case already exists and contains indexed

    takes effect when the existing database is empty.
