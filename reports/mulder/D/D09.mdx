# D09 파생물 저장 실패 처리

### D09.01 오류·부분 완료 표시

**구현.** 이 방식은 공통 적재 함수 `extract_and_index`를 거치는 추출 도구, 비동기 작업, `finalize_report`에 있다 [1].
`extract_and_index`는 `sources` 행을 먼저 등록하고 `window`를 5000개 묶음으로 넣는다 [1].
적재 중 난 예외는 처리하지 않고 호출한 쪽으로 그대로 올린다 [1].
DB 쓰기는 쓰기 전용 스레드가 맡고 그 예외를 요청한 스레드에 다시 던진다 [2].
도구 호출을 작업 스레드로 넘기는 래퍼도 예외를 처리하지 않고 그대로 올리므로 적재가 실패하면 그 호출은 예외로 끝난다 [3].
성공 응답과 호출 기록 항목은 적재가 끝난 뒤 `tool_response`가 만들므로 이때는 호출 기록 항목도 남지 않는다 [4].
`start_extraction_batch`의 비동기 작업과 `run_parallel`의 하위 작업은 예외가 나면 작업 상태를 `failed`로 두거나 결과 자리에 오류 문구를 넣는다 [5].
`finalize_report`는 HTML 보고서를 만들지 못하면 마크다운만 쓰고 응답에 `html_warning`을 싣고 `html_report_path`를 비운다 [6].
마크다운이나 HTML 파일 쓰기가 실패하면 `finalize_report`는 예외로 끝난다 [6].

**예외.** 적재 도중 `window` 묶음 쓰기가 실패해도 먼저 커밋한 `sources` 행과 앞 묶음의 `window`는 사건 DB에 남는다 [1][2].
남은 `sources` 행의 `line_count`는 전체 출력의 줄 수이고 표에는 적재가 끝났는지 가리는 열이 없다 [1][7].
재실행 건너뛰기 검사 `sources_already_indexed`는 `sources` 행이 있는지만 보므로 이 검사를 쓰는 추출 도구는 `force` 없이 다시 부르면 남은 일부 자료를 이미 적재된 것으로 보고 건너뛴다 [8].
이 경로는 코드로 따라갔고 실행해 보지 않았다.

### D09.03 저장 확인·검증

**구현.** 이 방식은 압축 해제 도구 `extract_archive`에만 있다 [9].
`extract_archive`는 압축을 다 풀고 분류까지 마친 뒤 마지막으로 대상 폴더에 완료 표시 파일을 쓴다 [9].
표시에는 원래 압축 파일 경로·파일 수·완료 시각이 들어간다 [9].
다음 호출은 표시가 있고 그 안의 압축 파일 경로가 같을 때만 기존 결과를 다시 쓴다 [10].
표시가 없는 폴더는 중간에 멈춘 자료로 보고 다시 푼다 [10].
표시를 쓰지 못하면 경고 로그만 남기고 성공으로 응답하며 다음 호출은 그 폴더를 다시 푼다 [9][10].
사건 DB에 적재하는 도구 출력에는 이런 완료 표시가 없다 [7].

### D09.04 알림 없이 계속

**구현.** 이 방식은 복합 도구 11개의 결과 적재, `correlate_across_sources`, `enrich_iocs`, `run_plaso`, `finalize_report`의 로그 사본에 있다 [11].
복합 도구는 결과를 `composite.*` `source`로 적재하다 예외가 나면 경고 로그만 남기고 `status: success`와 그 `source` 이름을 돌려준다 [11].
그래서 응답이 가리키는 `source`가 사건 DB에 없을 수 있다 [11].
`correlate_across_sources`는 적재 실패를 debug 로그로만 남기고 응답에 `composite.correlation`을 싣는다 [12].
`enrich_iocs`는 조회 결과를 `enrichment.iocs`로 적재하다 실패하면 경고 로그만 남기고 결과를 돌려준다 [13].
보고서는 IOC 평판을 `enrichment.iocs`에서 읽으므로 이때 보고서의 IOC 표에서 평판 값이 빠진다 [13].
`run_plaso`는 Plaso 저장 파일을 사건 폴더의 `<case_id>.plaso`로 복사하다 실패하면 그 오류를 버린다 [14].
그 뒤 `plaso.stats`의 `source_path`는 `<case_id>.plaso`가 있으면 그 경로를, 없으면 증거 경로를 쓴다 [14].
앞 실행이 남긴 `<case_id>.plaso`가 있으면 이번 실행의 통계가 앞 실행의 저장 파일을 가리킨다 [14].
`finalize_report`는 `mulder.log`를 `<case_id>.mulder.log`로 복사하다 실패하면 debug 로그만 남긴다 [15].
응답의 `log_path`는 사본 파일이 있는지만 보고 고르므로 앞선 호출이 만든 사본이 있으면 그 사본을 가리킨다 [15].

```python
    def submit(self, fn: Callable[..., _T], *args: object, **kwargs: object) -> _T:
        """Submit *fn* to the writer thread and block until it completes.

        Returns the result of ``fn(*args, **kwargs)`` or re-raises its
        exception in the calling thread with the original traceback.
        """
        result_holder = _QueueResult()
        done_event = threading.Event()
        self._queue.put((fn, args, kwargs, result_holder, done_event))
        done_event.wait()
        if result_holder.error is not None:
            raise result_holder.error.with_traceback(result_holder.error.__traceback__)
        return cast(_T, result_holder.value)
```

```python
def _extraction_is_complete(dest: Path, archive: Path) -> bool:
    """Return True only if *dest* holds a finished extraction of *archive*."""
    marker = dest / _COMPLETION_MARKER
    if not marker.is_file():
        return False
    try:
        recorded = json.loads(marker.read_text())
    except (OSError, json.JSONDecodeError):
        return False
    return bool(recorded.get("archive") == str(archive))
```
