# T05 분석 도구 검증

### T05.01 선언: 저장소·의존성 고정

**구현.** `mulder setup`이 설치하는 도구·참조 자료의 버전은 자산 목록 `manifest.py`에 적혀 있다 [1].
Chainsaw 2.16.0, Hayabusa 3.8.1, capa 9.4.0, FLOSS 3.1.0, Zircolite 2.20.0, Sigma 룰 `r2024-09-02`가 상수로 고정돼 있다 [1].
모듈 설명은 이 값이 Dockerfile의 값과 같고 둘이 어긋나면 테스트가 빌드를 실패시킨다고 적는다 [1].
capa·Chainsaw·DIE·FLOSS·Hayabusa 릴리스 파일은 잠금 파일 `assets.lock`에 아키텍처별 URL과 SHA-256이 있다 [2].
`mulder setup`은 잠금 파일에 해시가 없는 고정 대상을 내려받지 않고 받은 파일의 SHA-256이 다르면 설치를 멈춘다 [3].

이 해시 대조는 설치할 때만 한다.
서버는 도구를 실행하기 전에 실행 파일을 이름과 위치로 찾기만 하고 해시를 대조하지 않는다 [4].
ATT&CK 데이터(`master`), signature-base·Didier Stevens 도구·ALEAPP·iLEAPP(`HEAD`), EZ Tools(`net9`), Volatility 심볼(`latest`)은 버전을 고정하지 않는다 [5].

**예외.** Chainsaw와 capa는 PATH에 있는 실행 파일을 먼저 쓰고 Volatility도 PATH의 `vol`·`vol3`를 먼저 쓴다 [6].
PATH에 다른 버전이 설치돼 있으면 고정한 버전이 아닌 파일이 실행된다 [6].
Hayabusa는 `mulder setup`이 amd64에서만 내려받고 arm64에서는 소스에서 직접 빌드하라고 안내한다 [7].
signature-base 클론은 서버 프로세스마다 YARA 룰을 처음 준비할 때 `git pull --ff-only`로 갱신된다 [8].
클론 폴더에 서버 계정이 쓸 수 없는 설치에서만 갱신을 건너뛰고 설치한 버전을 그대로 쓴다 [8].

### T05.02 선언: 설정·호출 인자 지정

**구현.** 환경변수 `MULDER_ASSET_ROOT`를 주면 서버는 그 폴더 하나에서만 자산을 찾는다 [9].
주지 않으면 `/opt`를 먼저 보고 사용자 폴더 `~/.local/share/mulder/assets`를 다음에 본다 [9].
룰과 IOC 목록은 호출 인자로 바꿀 수 있다 [10].
`run_chainsaw`는 `sigma_rules_path`·`mapping_path`, `run_capa`는 `rules_path`, YARA 스캔 도구는 `rules`, MVT 도구는 `iocs`로 쓸 파일을 받는다 [10].
인자를 주지 않으면 설치한 기본 룰로 실행한다 [10].
서버는 인자로 받은 파일의 경로만 넘기고 그 파일의 버전을 읽지 않는다 [10].

**예외.** YARA 스캔 도구의 `ruleset` 인자는 `builtin`·`standard`·`full` 가운데 하나를 받지만 세 값 모두 같은 signature-base 룰 묶음을 고른다 [11].
코드 주석은 이 인자를 API 호환 때문에 남겼다고 적는다 [11].
호출 기록에는 모델이 고른 `ruleset` 값이 그대로 남는다 [11].
MVT 도구는 `iocs`로 받은 경로가 파일이 아니면 `--iocs` 없이 실행한다 [12].
이때도 결과의 `iocs_file`에는 받은 경로를 그대로 싣는다 [12].

### T05.03 확인: 실행 시 버전 조회

**구현.** `run_capa`는 capa JSON 출력의 `meta.version`을 결과 필드 `capa_version`으로 옮기고 값이 없으면 `unknown`을 넣는다 [13].
EZ Tools를 쓰는 도구는 `dotnet --list-runtimes`로 설치된 .NET 런타임의 주 버전을 읽는다 [14].
이 값은 실행할 DLL(`net6`·`net9` 폴더)을 고르는 데만 쓴다 [14].
Plaso 도구는 `--version`을 부르지만 실행되는지 시험하는 데만 쓰고 값은 버린다 [15].
이 시험은 T07에서 본다.
capa 말고 다른 외부 도구의 버전은 실행 중에 묻지 않는다.
signature-base를 `git pull`로 갱신한 뒤에도 클론의 커밋을 읽지 않는다 [8].
룰·심볼·매핑 같은 참조 자료의 버전을 읽는 코드는 없다.

**예외.** `dotnet --list-runtimes`가 실패하거나 10초 안에 끝나지 않으면 주 버전을 `None`으로 두고 가장 높은 `netN` 폴더의 DLL을 고른다 [14].
이 경우 그 DLL을 설치된 런타임이 실행할 수 있는지는 보지 않는다 [14].

```python
def _check_digest(asset: Asset, arch: str, result: FetchResult, *, primary: bool) -> None:
    """Compare a download against ``assets.lock``.

    Only the primary URL of a pinnable row is locked; the siblings (ICS ATT&CK)
```

```python
def _chainsaw_binary() -> str | None:
    """Resolve the chainsaw executable: PATH first, asset root second.

    PATH wins so a SIFT/apt/cargo install keeps being used.  The resolved value
    is also what gets exec'd -- gating on ``which`` and then exec'ing a
    hardcoded ``/usr/local/bin/chainsaw`` is what made a ``~/.local/bin``
    install report ``os_error`` instead of ``binary_missing`` and silently
    never run.
    """
    found = require_binary("chainsaw")
    if found:
        return found
    candidate = asset_path("chainsaw", "chainsaw")
    if candidate is not None and os.access(candidate, os.X_OK):
        return str(candidate)
    return None
```

```python
def _update_community_rules() -> None:
    """Pull latest YARA rules from signature-base (best-effort, once per session)."""
    global _rules_updated  # noqa: PLW0603
    with _rules_lock:
        if _rules_updated:
            return
        _rules_updated = True
    # Resolve once: four separate lookups could disagree if a concurrent
    # ``mulder setup`` publishes the clone mid-function.
    base = _signature_base_dir()
    if base is None or not (base / ".git").is_dir():
        return
    if not (os.access(base, os.W_OK) and os.access(base / ".git", os.W_OK)):
        # A pull has to write objects, refs and the worktree, and git also
        # refuses to touch a clone owned by another user. The container image
        # ships a root-owned, SHA-pinned clone under /opt and runs the server
        # as `mulder`, so there the pinned rules are the rules by design.
        logger.info(
            "YARA rules: %s is not writable by this user; using the installed checkout as-is",
            base,
        )
        return
    try:
        proc = subprocess.run(
            ["git", "-C", str(base), "pull", "--ff-only", "-q"],
            capture_output=True,
            text=True,
            timeout=30,
            check=False,
        )
```

```python
@functools.lru_cache(maxsize=8)
def _roots(env: str | None, home: str) -> tuple[Path, ...]:
    if env:
        return (Path(env).expanduser(),)
    roots: list[Path] = []
    if SYSTEM_ROOT.is_dir():
        roots.append(SYSTEM_ROOT)
    roots.append(Path(home) / ".local" / "share" / "mulder" / "assets")
    return tuple(roots)


def asset_roots() -> tuple[Path, ...]:
    """Ordered read roots.

    Keyed on the environment variable and ``$HOME`` so a change in either takes
    effect without an explicit cache flush; only the ``/opt`` stat is memoized.

    ``MULDER_ASSET_ROOT`` is *exclusive* rather than prepended, so that the test
    suite can be hermetic and the container can pin an exact root that a
    bind-mounted ``$HOME`` cannot shadow.
    """
    return _roots(os.environ.get(ENV_ASSET_ROOT) or None, str(Path.home()))
```

```python
@functools.lru_cache(maxsize=1)
def _dotnet_major() -> int | None:
    """Highest ``Microsoft.NETCore.App`` major the host can run, or None.

    One subprocess, memoized for the process lifetime.  None means "dotnet
    absent or unparseable", in which case ranking degrades to highest-netN,
    which is the best guess available.
    """
    exe = require_binary(_DOTNET)
    if exe is None:
        return None
    try:
        proc = subprocess.run(
            [exe, "--list-runtimes"], capture_output=True, text=True, timeout=10, check=False
        )
    except (OSError, subprocess.TimeoutExpired):
        return None
    majors = [
        int(m.group(1)) for line in proc.stdout.splitlines() if (m := _RUNTIME_RE.match(line))
    ]
    return max(majors) if majors else None
```

```python
def _framework_rank(path: Path, ceiling: int | None) -> tuple[int, int, str]:
    """Sort key for a DLL candidate: runnable first, then highest netN, then path.

    ``ceiling`` is the installed dotnet major.  .NET rolls *forward* -- a net6
    DLL runs on a net9 runtime -- but never backward, so a DLL whose netN
    exceeds the ceiling cannot run at all and must lose to any DLL that can.
    A DLL with no ``netN`` path component (the container's flat layout) ranks
    ``best = -1``: always runnable, always last among runnable candidates.
    """
    best = -1
    for part in path.parts:
        m = _NET_DIR_RE.match(part)
        if m:
            best = max(best, int(m.group(1)))
    runnable = 1 if (ceiling is None or best <= ceiling) else 0
    return (runnable, best, str(path))
```
