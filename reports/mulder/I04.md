# I04 서버 자격증명 처리

### I04.01 환경변수·설정 파일에 분리 보관

**구현.** 서버가 외부 연동에 쓰는 자격증명은 IOC 평판 조회 도구 `enrich_iocs`의 API 키 3개다 [1].
서버는 호출마다 `_load_api_keys`로 환경변수 `VIRUSTOTAL_API_KEY`·`ABUSEIPDB_API_KEY`·`OTX_API_KEY`를 읽는다 [1].
키를 담는 설정 파일은 없고 코드에도 키 값이 없다 [1].
키가 없을 때 남기는 debug 로그에는 서비스 이름과 환경변수 이름만 적는다 [1].
YARA 룰 갱신의 `git pull`에는 서버 코드가 자격증명을 넘기지 않는다 [2].

### I04.04 도구 인자 수신 금지

**구현.** 이 방식은 `enrich_iocs`에 있다 [3].
`enrich_iocs`의 인자는 `case_id`·`iocs`·`skip_sources`뿐이고 API 키를 받지 않는다 [3].
키는 서비스별 요청 헤더(`Key`·`X-OTX-API-KEY`·`x-apikey`)에만 싣는다 [4].
응답의 서비스별 결과는 `_result_to_dict`가 고른 필드만 담고 키는 담지 않는다 [5].
호출 기록에는 인자로 `case_id`와 IOC 개수만 남긴다 [6].
질의 중 예외가 나면 예외 문구(`str(exc)`)를 그대로 응답의 `error`에 싣고 문구에서 비밀값을 지우는 처리는 없다 [7].

```python
def _load_api_keys() -> dict[str, str]:
    """Load available API keys from environment variables.

    Returns:
        Map of source name to API key for sources with configured keys.
    """
    keys: dict[str, str] = {}
    for source_name, env_var in _ENRICHMENT_SOURCES.items():
        val = os.environ.get(env_var, "").strip()
        if val:
            keys[source_name] = val
        else:
            logger.debug("No API key for %s (env var %s not set)", source_name, env_var)
    return keys
```
