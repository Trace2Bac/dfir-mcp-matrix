# L02 기록 구성

### L02.01 요청 원문 기록

**구현.** 호출 기록의 `tool_call` 항목은 모든 도구에서 도구 이름 `tool_name`과 인자 `params`를 담는다 [1].
항목에는 이와 함께 호출 ID `tool_call_id`, 결과 해시 `output_hash`, 소요 시간 `duration_ms`, 기록 시각 `timestamp`가 들어간다 [1].
`params`에 넣을 값은 기록을 부르는 도구가 정해 넘긴다 [1].
`audited_tool`을 붙인 도구 5개는 받은 키워드 인자를 그대로 넣는다 [2].
응답 함수를 쓰는 도구는 대개 받은 인자로 `params`를 만든다 [3].
`scan_evidence`는 `MULDER_CASE_ID`로 `case_id`를 바꾸기 전에 받은 값으로 `params`를 만든다 [3].

서버가 고친 값이나 실제 실행 명령은 항목에 없다.
외부 명령을 돌리는 `run_cli_tool`도 실행한 명령 줄 `cmd` 대신 도구가 넘긴 `params`를 기록한다 [4].
그래서 L02.02·L02.03·L02.04에는 연결하지 않는다.

항목에는 결과 상태 필드와 시작 시각이 없다 [1].
`error_response`는 오류 문구로 만든 해시만 `output_hash`에 넣으므로 오류 항목이 성공 항목과 같은 모양이다 [5].
그래서 L02.06에는 연결하지 않는다.
외부 요청을 보내는 `enrich_iocs`는 사건 ID와 IOC 개수만 남기고 어느 서비스에 무엇을 물었는지와 응답은 남기지 않는다 [6].
YARA 스캔 도구가 룰 저장소에서 `git pull`을 돌린 일과 그 결과는 서버 로그에만 남는다 [7].
그래서 L02.09에도 연결하지 않는다.
서버 안에서 모델을 부르는 도구는 없어 L02.05는 볼 대상이 없다.

**예외.** 여러 도구가 받은 인자 일부를 빼거나 요약값으로 바꿔 기록한다.
`run_volatility_batch`는 `force`를 뺀다 [8].
`extract_file_by_inode`는 `filesystem_type`·`image_path`를 빼고 `inode`만 넣는다 [9].
`submit_finding`은 `description`·`event_time_start`·`event_time_end`를 뺀다 [10].
`enrich_iocs`는 IOC 목록 대신 개수를 넣는다 [6].
`decode_payload`는 입력 `data` 대신 길이를 넣는다 [11].
YARA 스캔 도구는 `rules` 대신 룰을 넘겼는지만 참·거짓으로 넣는다 [12].
`run_parallel`과 `start_extraction_batch`는 하위 작업의 인자를 빼고 도구 이름 목록만 넣는다 [13].
위는 확인한 도구이고 153개 도구의 기록 인자를 모두 받은 인자와 대조하지는 않았다.

### L02.08 호출 ID·시각으로 항목 연결

**구현.** 한 호출이 여러 항목을 낳는 경로는 `run_parallel`과 백그라운드 배치다 [14][15].
`run_parallel`은 자기 항목의 `tool_call_id`로 배치 ID를 쓰고 하위 호출의 ID를 `sub_calls`에 담는다 [14].
하위 호출을 부르는 동안에는 문맥 변수 `current_batch_id`에 같은 배치 ID를 넣는다 [16].
응답 함수는 이 값을 하위 항목의 `batch_id`에 넣는다 [17].
백그라운드 작업도 실행 전에 `current_batch_id`에 그 작업의 배치 ID를 넣는다 [15].

**예외.** `audited_tool`과 본문에서 `log_tool_call`을 직접 부르는 도구는 `batch_id`를 넘기지 않아 배치 안에서 불려도 항목에 배치 ID가 없다 [18].
`start_extraction_batch`의 항목에는 배치 ID가 없어 그 배치의 하위 항목과 이어지지 않는다 [19].
배치 ID는 그 항목의 `output_hash`를 만드는 입력에만 들어간다 [19].
`submit_finding`이 쓰는 `finding` 항목과 `tool_call` 항목은 서로의 ID를 담지 않는다 [20].
`run_parallel`이 자기 항목을 남기지 못하고 끝나면 하위 항목의 `batch_id`가 가리키는 항목이 없다 [14].
그 경로는 L01에서 본다.

        """Execute a single task and store its result at *idx*."""
        token = current_batch_id.set(batch_id)
        try:
            fn = _tool_dispatch.get(tool_name)
            if fn is None:
                results[idx] = {"error": f"Unknown tool: {tool_name}"}
                return
            arguments = fill_case_id(fn, arguments, open_case_id)
            problem = validate_tool_args(fn, arguments)
            if problem is not None:
                results[idx] = {"error": f"{tool_name}: {problem}"}
                return
            try:
                results[idx] = await fn(**arguments)
            except Exception as exc:
                logger.exception("run_parallel: %s failed", tool_name)
                results[idx] = {"error": f"{tool_name} failed: {exc}"}
        finally:
            current_batch_id.reset(token)
