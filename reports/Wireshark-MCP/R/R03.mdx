# R03 분석 상태 알림

### R03.01 구조화 status·error

**구현.** 이 방식은 모든 도구의 `envelope`와 `WiresharkMCP.call_tool`에 적용된다 [1][2].
성공한 결과는 `success` 참과 `data`를, 실패한 결과는 `success` 거짓과 `error`의 `type`·`message`·`details`를 싣는다 [1].
실패 종류는 `FileNotFound`·`PermissionDenied`·`InvalidParameter`·`ToolNotFound`·`ExecutionError`·`TimeoutError`·`LimitExceeded`·`SecurityError`·`DependencyMissing` 같은 값으로 나뉜다 [3][4][5].
`type`이 없는 오류는 `normalize_tool_result`가 `ToolError`로 채운다 [1].
`WiresharkMCP.call_tool`은 글 블록의 JSON 최상위 `success`가 거짓이면 MCP 결과의 `isError`를 참으로 둔다 [2].
이 판단은 응답 상한을 적용하기 전의 글로 한다 [2].
없는 캡처 파일을 주자 `isError`가 참이고 `type`이 `FileNotFound`인 결과가 돌아왔다 [6].
MCP Python SDK 2.1.1은 인자 검사 실패와 처리하지 못한 예외를 `isError`가 참인 글 결과로 돌려준다 [7].

**한계.** 실행 함수 `_run_command`는 줄 상한으로 출력을 자른 실행의 종료 코드를 확인하지 않는다 [8].
그래서 `tshark`가 0이 아닌 코드로 끝나도 출력이 `limit`보다 길면 성공 결과가 나간다 [8].
뒤쪽에 손상된 레코드가 있는 캡처 파일을 `wireshark_get_packet_list`에 `limit` 5로 주자 성공 결과가 돌아왔고 `limit` 1000으로 주자 종료 코드 2의 `ExecutionError`가 돌아왔다 [9].

여러 단계를 이어 실행하는 도구 가운데 일부는 하위 단계의 실패를 성공 결과로 돌려준다.
`wireshark_quick_analysis`는 단계마다 예외와 실패를 문장으로 바꾸고 늘 `success` 참을 돌려준다 [10].
`wireshark_analyze_tcp_health`는 하위 조회가 실패하면 그 항목을 `N/A (filter not applicable)`로 적는다 [11].
`wireshark_scan_file_signatures`는 하위 검색이 실패한 형식을 0건으로 처리한다 [12].
`wireshark_detect_exfiltration`은 두 하위 조회가 실패하면 그 결과를 건너뛰고 실패를 응답에 싣지 않는다 [13].
없는 캡처 파일을 이 4개 도구에 주자 모두 `isError`가 거짓인 결과를 돌려줬다 [6].
`wireshark_geoip_enrich`는 필드 추출이 실패하면 실패 `envelope`를 `success_response`로 다시 감싸 최상위 `success`를 참으로 둔다 [14].

일부 도구는 하위 단계의 오류 종류를 버린다.
`wireshark_detect_dos_attack`은 SYN 조회가 실패하면 `type`을 주지 않고 `error_response`를 불러 `ToolError`를 돌려준다 [15].
없는 캡처 파일을 주자 `FileNotFound` 대신 `ToolError`가 실렸다 [6].
`wireshark_yara_scan`도 객체 내보내기 실패를 `type` 없이 돌려준다 [16].
SDK가 만든 오류 결과는 `envelope`가 아닌 평문이다 [7][6].

### R03.02 찾지 못함과 실패 구분

**구현.** 이 방식은 `envelope`를 쓰는 도구 전체에 적용된다 [1].
일치가 없으면 `success` 참인 결과를, 입력 파일이 없거나 실행이 실패하면 `success` 거짓과 오류 종류를 돌려준다 [1][3].
`wireshark_aggregate`는 일치가 없으면 `matched_packets` 0과 빈 `groups`를 싣는다 [17].
탐지 도구와 BLE 분석은 대상 트래픽이 없으면 빈 `findings`나 빈 목록과 `summary` 문장을 싣는다 [18][19].
프로토콜 분석기는 추출 결과가 20자보다 짧으면 `No … found` 문장을 싣는다 [20].
`wireshark_follow_stream`은 `search_content`가 스트림에 없으면 그 사실을 적은 성공 결과를 돌려준다 [21].

**한계.** 필드가 여러 개인 프로토콜 분석기의 머리글 줄은 20자를 넘는다 [20].
그래서 일치하는 패킷이 없어도 `No … found` 문장 대신 머리글 줄만 실린 결과가 나간다 [20].
DNS 패킷만 있는 캡처 파일로 `dhcp`·`wireguard`·`mqtt` 분석을 부르자 머리글 줄만 실렸고 MQTT 분석은 `Total MQTT messages: 0`을 적었다 [22].
입력 파일이 없을 때 성공 결과를 돌려준 도구 4개는 입력 파일이 없을 때와 일치가 없을 때 같은 문장을 돌려준다 [6].
`wireshark_detect_exfiltration`과 `wireshark_scan_file_signatures`는 없는 캡처 파일에 대해 내보낸 데이터나 파일 서명이 없다는 `[OK]` 문장을 돌려줬다 [6].
Modbus 분석의 쓰기 연산 조회는 실패하면 그 절을 빼고 응답에 실패를 알리지 않는다 [23].
`tshark` 4.0.17은 이 조회의 필터 `modbus.func_code in {5 6 15 16}`을 받지 않아 Modbus 요청 20개가 있는 캡처 파일에서 이 조회가 매번 실패했다 [24].

### R03.03 입력별 성공·실패·생략 목록

**구현.** 이 방식은 `wireshark_detect_port_scan`과 `wireshark_detect_dos_attack`에 적용된다 [25][15].
두 도구는 하위 조회 가운데 실패한 것의 이름을 `coverage.failed_checks`에 싣고 `warnings`에 실패 문구를 더한다 [25][15].
실패한 조회가 있으면 `coverage.status`를 `partial`로 둔다 [25][15].

**한계.** 목록에는 실패한 조회만 실린다 [25][15].
`wireshark_detect_port_scan`의 SYN 조회와 `wireshark_detect_dos_attack`의 SYN 조회가 실패하면 도구 전체가 오류로 끝나 이 목록이 만들어지지 않는다 [25][15].

### R03.04 시간 초과·부분 완료 표시

**구현.** 이 방식은 실행 함수의 시간 초과·출력 상한 오류와 `coverage`를 싣는 도구에 적용된다 [3][17].
`_run_command`는 시간 제한(기본 30초)을 넘으면 프로세스를 끝내고 `type`이 `TimeoutError`인 오류를 돌려준다 [3].
출력 상한을 넘어 프로세스를 끝낸 경우는 `LimitExceeded`다 [3].
`wireshark_aggregate`는 스트리밍 읽기가 시간 제한, 행 상한, 오류로 끝나면 오류와 함께 `coverage`의 `status`를 `partial`로, `scanned`를 그때까지 읽은 행 수로 싣는다 [17][26].
묶음 상한이나 고유 값 상한에 닿아 일부를 세지 않았으면 성공 결과에도 `coverage.status`를 `partial`로 둔다 [17].
탐지 도구, 자격 증명 도구, BLE 분석은 줄 상한에 닿으면 `coverage.status`를 `partial`로 둔다 [25][18][19].

**한계.** 패킷 중간에서 끝난 캡처 파일은 성공 결과로 돌아가고 부분 결과라는 상태 값이 없다 [8].
`_run_command`는 `tshark`가 종료 코드 14나 `cut short` 문구와 함께 종료 코드 2를 내고 출력이 있으면 성공 `envelope`를 만든다 [8].
남는 표시는 `tshark`의 표준 오류 글을 담은 `stderr`뿐이다 [8].
같은 캡처 파일에 `wireshark_aggregate`는 `coverage.status`를 `complete`로 실었다 [27].
`_maybe_summarize`를 거치는 통계 도구 5개는 `stderr`도 버리므로 이 캡처 파일로 부른 `wireshark_stats_endpoints`의 응답에는 잘린 캡처 파일이라는 표시가 없었다 [28][27].
줄 상한으로 출력이 잘린 경우 `_run_command`는 `stderr`를 싣지 않고 종료 코드도 보지 않는다 [8].
`wireshark_aggregate`의 스트리밍 읽기는 시간 초과로 끝나면 읽은 행 수를 넘기지 않으므로 `coverage.scanned`가 0이 된다 [26][17].

`coverage.status`의 `partial`은 상한이나 실패가 없어도 다른 경고가 있으면 붙는다 [17][29][30].
`wireshark_aggregate`는 숫자가 아닌 수치 칸 경고나 쉼표가 들어 있는 고유 값 경고만 있어도 `partial`을 싣는다 [17][29].
`wireshark_detect_dos_attack`은 단방향 캡처 경고만 있어도 `partial`을 싣는다 [30].
DNS 질의 300개를 모두 읽은 `wireshark_aggregate` 호출과 SYN 100개뿐인 캡처 파일의 `wireshark_detect_dos_attack` 호출이 모두 `partial`을 실었다 [31].

def _error_object(error: Any) -> dict[str, Any]:
    if isinstance(error, dict):
        error_type = error.get("type")
        message = error.get("message")
        details = error.get("details")
        normalized: dict[str, Any] = {
            "type": error_type if isinstance(error_type, str) and error_type else "ToolError",
            "message": message if isinstance(message, str) and message else "Tool failed",
        }
        if details is not None:
            normalized["details"] = details
        for key, value in error.items():
            if key not in normalized and key not in {"type", "message", "details"}:
                normalized[key] = value
        return normalized

    if isinstance(error, str) and error.strip():
        return {"type": "ToolError", "message": error.strip()}

    return {"type": "ToolError", "message": "Tool failed"}


def success_response(data: Any, compact: bool = False) -> str:
    if compact and isinstance(data, str):
        return data
    return json.dumps({"success": True, "data": data})
