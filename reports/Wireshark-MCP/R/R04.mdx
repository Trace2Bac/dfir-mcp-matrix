# R04 도구 결과 해석 주의

### R04.01 도구별 정적 주의

**구현.** 이 방식은 `wireshark_extract_fingerprints`와 `wireshark_scan_file_signatures`의 도구 설명에 적용된다 [1].
`wireshark_extract_fingerprints`의 설명은 사용자 목록과 맞은 JA3 결과를 단서로 다루라고 적는다 [1].
`wireshark_scan_file_signatures`의 설명은 일치가 객체 추출과 검증을 거쳐야 하는 결과라고 적는다 [1].
두 도구의 응답에는 같은 문구가 없다 [1].

다른 도구의 설명에는 결과가 증명하지 못하는 것이나 해석 한계를 적은 문구가 없다 [2].
탐지 도구의 설명은 탐지하는 패턴만 적는다 [2].
JA3 값이 프로그램이 아니라 TLS 설정을 가리킨다는 설명은 소스 주석에만 있고 도구 설명과 응답에는 없다 [3].

### R04.02 결과 조건별 주의

**구현.** 이 방식은 `wireshark_detect_dos_attack`, `wireshark_detect_dns_tunnel`, `wireshark_aggregate`, BLE 분석의 `warnings`와 `summary`에 적용된다 [4][5][6][7].
`wireshark_detect_dos_attack`은 SYN이 50개를 넘는데 SYN-ACK가 0개이면 단방향 캡처일 수 있어 SYN 비율이 서비스 거부 공격이 아니라 수집 위치를 반영할 수 있다는 문구를 `warnings`에 더한다 [4].
`wireshark_detect_dns_tunnel`은 지표가 2개 이상이면 `summary` 첫 줄에 도메인 확인이 필요하다고 적는다 [5].
`wireshark_aggregate`는 고유 값 칸에 쉼표가 있으면 여러 값이 한데 세어졌을 수 있다는 문구를 `warnings`에 적는다 [6].
수치 칸에 숫자가 아닌 값이 있으면 그 칸을 건너뛰었다는 문구도 적는다 [6].
BLE 장치·스캐너 분석은 줄 상한에 닿으면 프레임 수와 요청 수가 하한값이라고 적는다 [7].
BLE 페어링 분석은 요청과 응답이 모두 있지 않으면 페어링 방식을 `unknown`으로 두고 그 이유를 `note`에 적는다 [8].

**한계.** `wireshark_detect_dos_attack`은 근거 제약 `constraints.single_sided`를 `warnings`가 하나라도 있으면 참으로 둔다 [9].
줄 상한 경고나 하위 조회 실패 경고만 있어도 단방향 캡처라는 값이 된다 [9][4].

### R04.03 추가 확인 도구·증거 추천

**구현.** 이 방식은 사용 안내 리소스, 탐지 도구와 자격 증명 도구의 `next_steps`, `wireshark_scan_file_signatures`의 설명에 적용된다 [10][11][12][1].
리소스 `wireshark://guide/usage`는 추출한 한 쪽으로 캡처 전체를 짐작하지 말고 `wireshark_aggregate`를 쓰라고 적는다 [10].
`wireshark_detect_dns_tunnel`은 후보 도메인을 CDN·클라우드 기반 시설과 대조한 뒤 악성을 판단하라고 `next_steps`에 적는다 [11].
`wireshark_detect_port_scan`은 스캔한 포트가 RST/ACK나 SYN-ACK로 응답했는지 확인하라고 적는다 [11].
`wireshark_extract_credentials`는 근거의 TCP 스트림을 `wireshark_follow_stream`으로 보라고 적는다 [12].
`wireshark_detect_dos_attack`은 지표 수에 따라 다른 확인 작업을 적는다 [4].

**한계.** BLE 장치 분석은 광고 프레임이 없을 때 HCI 캡처는 `wireshark_extract_gatt_timeline`으로 보라고 적는다 [7].
서버에는 이 이름의 도구가 없고 GATT 시간순 목록은 `wireshark_analyze_protocol`의 `ble_gatt_timeline` 값으로 본다 [13].

```python
def _load_fingerprint_db() -> list[dict[str, str]]:
    """Load user-supplied JA3 fingerprints from ~/.wireshark-mcp/fingerprints/*.json.

    No list ships with the package. A JA3 hash is a digest of Client Hello parameters
    (cipher suites, extensions, curves), so every client built on the same TLS stack
    with the same configuration produces the same hash — the value identifies a
    configuration, not a program. Labelling one `CobaltStrike` therefore reports a
    confident attribution for traffic that may be any application sharing that stack,
    and a five-entry snapshot pinned in a released package cannot be kept current.

    Matching against a list the operator maintains is a different proposition: they
    own both the intel and its freshness, and they know what the labels mean.
    Expected shape: {"fingerprints": [{"ja3": "<md5>", "label": "...", "category": "..."}]}
    """
```
