# R01 결과 가공

### R01.01 가공 없이 전달

**구현.** 이 방식은 `tshark`·`capinfos` 출력을 클라이언트 함수 결과 그대로 돌려주는 도구에 적용된다 [1][2].
실행 함수 `_run_command`는 하위 프로세스의 표준 출력을 바꾸지 않고 `_ok`로 감싸 `success`와 `data`를 가진 JSON 글을 만든다 [1].
코드는 이 공통 형식을 `envelope`라고 부른다 [1].
`wireshark_get_packet_list`·`wireshark_get_packet_details`·`wireshark_get_packet_bytes`·`wireshark_extract_fields`·`wireshark_get_file_info`·`wireshark_stats_protocol_hierarchy`·`wireshark_flow_graph`와 복호화·해석 설정 도구는 이 `envelope`를 `normalize_tool_result`에 넘겨 그대로 돌려준다 [2][3].
`normalize_tool_result`는 `success`·`data`·`truncated`·`stderr` 같은 키를 옮겨 다시 쓰고 `data` 안의 글은 바꾸지 않는다 [3].
`wireshark_get_file_info`는 `capinfos`가 낸 글을 `data`에 그대로 싣는다 [4].

**한계.** `wireshark_get_packet_list`와 `wireshark_extract_fields`는 `tshark -E header=y`의 머리글 줄도 출력 줄로 센다 [5][6].
그래서 `offset`을 0보다 크게 준 다음 쪽에는 머리글 줄이 없고 열 이름 없이 값 줄만 실린다 [6][7].
`wireshark_get_packet_context`는 기준 패킷 앞뒤 `count`개를 머리글 줄을 포함한 `count * 2 + 1`줄로 요청하므로 기준 패킷 뒤쪽 패킷이 하나 덜 실린다 [8][6].
DNS 질의 300개가 있는 캡처 파일에서 10번 패킷과 `count` 5를 주자 5~14번 패킷 10개만 실렸다 [9].

### R01.02 구조화 파싱·필드 선택

**구현.** 이 방식은 `wireshark_aggregate`, 탐지 도구, `wireshark_extract_credentials`, `wireshark_analyze_protocol`의 BLE 분석과 서버가 필드를 정해 둔 추출 도구에 적용된다 [10][11][12][13].
추출 도구는 서버가 정한 `tshark` 필드 목록으로 `-T fields`를 실행한다 [14].
`wireshark_extract_http_requests`는 메서드·URI·호스트·User-Agent 4개 필드를, `wireshark_extract_dns_queries`는 질의 이름·종류·응답 여부 3개 필드를 고른다 [14].
`wireshark_analyze_protocol`은 프로토콜 값마다 정해 둔 필드 목록과 표시 필터로 출력을 뽑는다 [15].
`wireshark_aggregate`·탐지 도구·BLE 분석은 탭으로 나뉜 줄을 칸으로 나누고 필요한 칸을 `dict`의 키로 옮긴다 [10][11][13].
`wireshark_extract_credentials`는 줄마다 패킷 번호, TCP 스트림 번호, 출발 주소, 자격 증명 칸을 읽어 근거 항목 `FindingEvidence`의 `frame`·`stream`·`value`·`description`에 넣는다 [12][16].

**한계.** Modbus 분석은 칸이 8개 이상인 줄만 센다 [17].
`tshark`는 줄 끝의 빈 칸 뒤에도 탭을 쓰지만 서버는 출력 전체에 `strip()`을 적용한 뒤 줄을 나누므로 마지막 줄의 끝 탭이 사라진다 [17].
예외 코드 칸이 빈 Modbus 요청 20개를 넣자 기능 코드 분포가 `FC 3: 19`로 실려 마지막 패킷이 빠졌다 [18].

`wireshark_extract_credentials`는 줄 상한으로 잘린 추출 결과 끝의 안내 줄도 자격 증명 줄로 읽어 근거 항목을 만든다 [19][6].
HTTP Basic 인증 요청 60개가 있는 캡처 파일에서 근거 항목 50개 가운데 마지막 항목은 패킷 번호가 없고 `value`에 안내 줄을 가린 글이 실렸다 [20].

### R01.03 형식 변환·건수 집계

**구현.** 이 방식은 `wireshark_aggregate`, `wireshark_quick_analysis`, 프로토콜 분석기, 탐지 도구, `wireshark_detect_arp_spoofing`, `wireshark_scan_file_signatures`에 적용된다 [10][21][22][11][23][24].
`wireshark_aggregate`는 표시 필터에 맞는 패킷을 끝까지 읽으며 묶음마다 패킷 수, 고유 값 수, 합계·최솟값·최댓값·평균을 계산한다 [10][25].
시간 묶음을 주면 `frame.time_relative`를 정한 폭의 구간으로 내려 묶는다 [25].
`wireshark_quick_analysis`는 HTTP 호스트와 DNS 질의 이름의 출현 수를 센다 [21].
MQTT·Modbus·S7comm·DNP3·CoAP·Zigbee·WebSocket 분석은 메시지 종류와 기능 코드의 분포, 고유 값 수, 전체 패킷 수를 글로 적는다 [22][17].
BLE 분석은 ATT·SMP 연산 코드, PDU 종류, HCI 끊김 사유 코드를 서버 코드의 표로 이름을 붙이고 연결 간격 값을 밀리초로 바꿔 `interval_ms`에 싣는다 [13].
탐지 도구는 출발지별 포트 수, SYN·SYN-ACK 비율, 초당 패킷 수 같은 값을 계산해 싣는다 [11].
`wireshark_detect_arp_spoofing`은 ARP 패킷 수, ARP 응답 수, 보낸 주소와 대상 주소가 같은 ARP 수를 세어 글로 적는다 [23].
`wireshark_scan_file_signatures`는 파일 형식 8종마다 그 서명 바이트가 들어 있는 패킷 수를 센다 [24].

**한계.** 프로토콜 분석기의 `Total … packets` 값은 `limit` 줄 안에서 센 값이다 [17][22].
줄 상한으로 잘린 출력에는 빈 줄과 잘림 안내 줄이 붙는데 서버는 이 두 줄도 패킷 줄로 센다 [17][6].
Modbus 요청 20개가 있는 캡처 파일에 `limit` 5를 주자 값 줄 4개가 실리고 `Total Modbus packets: 6`이 실렸다 [18].
`wireshark_quick_analysis`의 호스트 출현 수는 앞 500줄 안에서 센 값이고 응답에 그 범위가 없다 [21].
`wireshark_analyze_tcp_health`는 항목마다 패킷 목록을 10,000줄까지만 읽어 줄 수로 패킷 수를 센다 [26].
그래서 10,000줄을 넘는 항목의 수는 실제 수가 아니고 잘림 안내 줄이 한 줄로 더해진다 [26][6].
`wireshark_scan_file_signatures`는 형식마다 패킷 목록을 머리글 줄을 포함해 50줄까지 받아 줄 수로 센다 [24].
그래서 한 형식의 일치가 49개를 넘으면 늘 50이 실리고 이 값에는 잘림 안내 줄이 한 줄 포함된다 [24][6].
PNG 서명이 들어 있는 패킷 80개가 있는 캡처 파일에서 `PNG: 50 packet(s)`가 실렸다 [27].
`wireshark_detect_dos_attack`의 패킷 수와 `wireshark_detect_arp_spoofing`의 `Total ARP packets`도 줄 상한에 닿으면 빈 줄과 안내 줄을 함께 센다 [23][6].

### R01.04 가공 사실·대상 표시

**구현.** 이 방식은 `wireshark_aggregate`, 탐지 도구, `wireshark_extract_credentials`, BLE 분석의 응답에 적용된다 [10][11][12][13].
`wireshark_aggregate`는 결과에 적용한 `display_filter`, `group_by`, `distinct`, 수치 연산, 시간 묶음 폭, 정렬 기준을 함께 싣는다 [10].
탐지 도구, `wireshark_extract_credentials`, BLE 분석은 `scope`에 캡처 파일 경로를 싣는다 [11][12][13].
DNS 터널 탐지와 BLE 분석은 실행한 표시 필터도 `scope`에 싣는다 [11][13].
근거 항목 `FindingEvidence`마다 그 근거를 다시 골라낼 표시 필터를 `filter`에 싣는다 [12][11].

**한계.** 글로 결과를 돌려주는 프로토콜 분석기, `wireshark_quick_analysis`, 이상 탐지 도구 3개, `wireshark_analyze_tcp_health`는 결과가 서버가 가공한 것이라는 표시도 입력 파일과 필터도 싣지 않는다 [22][21][28][26].
`wireshark_detect_port_scan`의 `scope`에는 파일 경로와 문턱값만 있고 실행한 필터 3개는 근거 항목에만 있다 [11].
`wireshark_aggregate`의 결과에는 캡처 파일 경로가 없다 [10].

### R01.06 응답 항목 선별

**구현.** 이 방식은 `wireshark_quick_analysis`, `wireshark_geoip_enrich`, BLE 스캐너 분석에 적용된다 [21][29][13].
`wireshark_quick_analysis`는 HTTP 호스트와 DNS 질의 이름을 출현 수 차례로 정렬해 각각 8개만 싣는다 [21].
`wireshark_geoip_enrich`는 Python `ipaddress`의 `is_private`가 참인 주소를 빼고 나머지 값만 조회해 싣는다 [29][30].
BLE 스캐너 분석은 스캐너마다 요청을 받은 대상 주소를 많은 차례로 10개까지 `top_targets`에 싣고 근거 항목은 앞 스캐너 5개에만 만든다 [13].

**한계.** `wireshark_quick_analysis`는 골라 낸 8개 밖의 호스트 수를 싣지 않는다 [21].

`wireshark_geoip_enrich`에서 멀티캐스트 주소는 `is_private`가 거짓이라 빠지지 않는다 [30][31].
주소로 읽히지 않는 값도 빠지지 않고 조회 대상에 들어간다 [30].
목적지가 멀티캐스트·공인·사설 주소인 패킷 10,010개가 있는 캡처 파일에서 `224.0.0.251`과 필드 추출의 잘림 안내 줄이 공인 주소로 세어졌다 [31].

```python
    @staticmethod
    def _ok(data: str, stderr: str = "", truncated: bool = False) -> str:
        """Wrap successful command output in the canonical success envelope.

        Every client method returns this shape (or an error envelope), so the
        raw text lives in ``data`` and is never re-parsed by consumers — output
        that happens to look like JSON can no longer be mistaken for an error.
        Diagnostic stderr is kept in a separate field so it never corrupts
        structured (``-T json`` / ``-T fields``) output in ``data``.
        """
        envelope: dict[str, Any] = {"success": True, "data": data}
        if stderr:
            envelope["stderr"] = stderr
        if truncated:
            envelope["truncated"] = True
        return json.dumps(envelope)
```

    if "success" in payload and isinstance(payload["success"], bool):

            envelope: dict[str, Any] = {"success": True, "data": payload.get("data")}

```python
    @staticmethod
    def _paginate(output: str, limit_lines: int, offset_lines: int) -> tuple[str, bool]:
        """Slice full command output to an offset/limit window.

        Returns the windowed text and whether it was truncated. A truncation
        footer is appended so callers can page forward. Applied *after* caching
        so the cache always holds the complete output.
        """
        lines = output.splitlines()
        total_lines = len(lines)

        if offset_lines > 0:
            lines = lines[offset_lines:]

        truncated = False
        if limit_lines > 0 and len(lines) > limit_lines:
            lines = lines[:limit_lines]
            truncated = True

        final_output = "\n".join(lines)
        if truncated:
            final_output += (
                f"\n\n[Showing {limit_lines}/{total_lines} lines. Next: offset={offset_lines + limit_lines}]"
            )
        return final_output, truncated
```
