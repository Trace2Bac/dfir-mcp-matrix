# R02 대량 결과 전달

### R02.01 문자·항목 상한

**구현.** 이 방식은 모든 도구 결과에 적용되는 응답 상한과 도구별 줄·항목 상한에 적용된다 [1][2].
`WiresharkMCP.call_tool`은 도구가 돌려준 글 블록마다 `cap_result_text`를 적용한다 [1].
상한은 환경변수 `WIRESHARK_MCP_MAX_RESULT_CHARS`로 정하고 없으면 8,000자, 512보다 작으면 512자다 [3].
`cap_result_text`는 응답 글이 JSON이면 `envelope`의 형태를 남기고 자른다 [2].
`data`가 목록이면 앞에서부터 상한 안에 들어가는 항목 수를 이분 탐색으로 찾는다 [2].
`data`가 `dict`이면 `groups`·`records`·`packets`·`findings`·`items`·`results` 차례로, 없으면 처음 나온 비지 않은 목록 키를 같은 방법으로 줄인다 [2].
`data`가 글이면 앞부분과 뒷부분을 남기고 가운데를 뺀다 [2][4].

도구별 상한도 있다.
`wireshark_get_packet_list`·`wireshark_extract_fields`·`wireshark_follow_stream`·`wireshark_read_packets`는 모델이 준 `limit`이나 `limit_lines`로 줄 수를 줄인다 [5][6].
복호화·해석 설정 도구와 Kerberos 분석은 `tshark -c`로 읽을 패킷 수를 정한다 [7].
엔드포인트·대화·I/O·전문가 정보·서비스 응답 시간 통계는 표를 50줄(전문가 정보는 80줄)까지 싣는다 [8][9].
`wireshark_quick_analysis`는 절마다 10~15줄, 전체를 4,000자까지 싣는다 [10].
`wireshark_aggregate`는 `top_k`(1~200)개 묶음만 싣고 묶음 10,000개, 묶음마다 고유 값 5,000개, 고유 값 전체 50,000개를 넘는 값은 세지 않는다 [11][12].
탐지 도구와 자격 증명 도구는 필드 추출 줄 수를 10~10,000줄로 코드에 정해 둔다 [13][14].

**한계.** 응답 상한은 SDK가 글 블록으로 돌려준 결과에만 적용된다 [1].
인자 검사 오류처럼 MCP Python SDK 2.1.1이 예외로 만든 오류 결과는 `WiresharkMCP.call_tool`을 거치지 않으므로 상한이 적용되지 않는다 [15].

`cap_result_text`가 고른 목록 밖의 내용은 응답에서 빠진다 [2].
상한 512자에서 `wireshark_extract_credentials`를 부르자 `findings`가 빈 목록이 되고 `summary` 문자열만 남았다 [16].
같은 상한에서 `wireshark_detect_dns_tunnel`은 `{"success":true,"data":{},"truncated":true}`를 돌려줬다 [16].
`findings`가 빈 목록인 모양은 탐지 결과가 없을 때의 응답과 같고 둘을 가르는 값은 `truncated`와 `pagination`이다 [16][13].

### R02.02 전체·반환 건수 표시

**구현.** 이 방식은 줄 상한을 적용한 클라이언트 결과, `wireshark_aggregate`, 응답 상한이 목록을 줄인 응답, `wireshark_geoip_enrich`, `wireshark_follow_stream`, `wireshark_extract_credentials`의 `summary`에 적용된다 [6][11][2][17][18][19].
`_paginate`는 잘린 출력 끝에 `[Showing <상한>/<전체 줄 수> lines. Next: offset=<다음 위치>]`를 붙이고 `envelope`에 `truncated`를 참으로 둔다 [6][20].
`wireshark_aggregate`는 매칭 패킷 수 `matched_packets`, 전체 묶음 수 `groups_total`, 돌려준 묶음 수 `groups_returned`를 싣는다 [11].
`cap_result_text`는 목록을 줄이면 `pagination`에 `total`·`returned`·`next_offset`·`has_more`를 넣고 `dict` 안에 `<목록>_returned`·`groups_returned`·`returned` 키가 있으면 줄인 수로 고친다 [2].
`wireshark_geoip_enrich`는 머리 줄에 조회한 수와 공인 주소 전체 수를 적고 `limit`을 넘으면 앞 몇 개만 보였다고 적는다 [17].
`wireshark_follow_stream`은 보인 줄 수와 남은 줄 수를 적는다 [18].
`wireshark_extract_credentials`의 `summary`는 첫 줄에 근거 전체 수를 적고 앞 10개만 줄로 적은 뒤 나머지 수를 적는다 [19].
근거 항목 전체는 `findings`에 남는다 [19].

**한계.** `pagination.total`은 응답 상한이 줄이기 전 목록의 항목 수다 [2].
`wireshark_aggregate`에 `top_k` 200을 주자 `groups_total`은 300인데 `pagination.total`은 200, `returned`는 177로 실렸다 [21].
`wireshark_extract_credentials`의 `coverage.scanned`는 읽은 패킷 수가 아니라 만든 근거 항목 수이고 근거가 없으면 0이다 [14].
`wireshark_geoip_enrich`의 공인 주소 전체 수는 앞 10,000줄 안에서 센 값이다 [17].
줄 상한에 닿으면 이 수에는 잘림 안내 줄 하나가 공인 주소로 더해진다 [17][22].

### R02.03 페이지·커서 조회

**구현.** 이 방식은 `offset` 인자를 받는 `wireshark_get_packet_list`·`wireshark_extract_fields`·`wireshark_read_packets`와 `offset_lines`를 받는 `wireshark_follow_stream`에 적용된다 [5][23].
잘린 출력 끝의 안내 줄은 다음에 줄 `offset` 값을 적는다 [6][18].
`_run_command`는 끝까지 읽은 표준 출력을 파일 경로·수정 시각·크기·명령으로 만든 키로 5분 동안 메모리에 두고 다음 쪽 요청을 그 출력에서 자른다 [20][24].
3,000패킷 캡처 파일에서 `limit` 5로 부르자 `Next: offset=5`가 붙었고 그 값으로 부르자 이어지는 패킷 줄이 실렸다 [25].

**한계.** `offset`과 `limit`은 머리글 줄을 포함한 줄 수다 [6][5].
`wireshark_read_packets`는 `tshark -c`에 `limit`과 `offset`의 합을 주고 앞 `offset`개를 버리며 다음 위치를 알리지 않는다 [26].
다음 위치를 받는 인자가 없는 도구에도 이어 읽으라는 안내가 붙는다.
`wireshark_analyze_protocol`의 글 결과에는 필드 추출의 `Next: offset=…`이 남지만 이 도구는 `offset` 인자가 없다 [6][27].
`wireshark_get_packet_context`도 `offset` 인자가 없는데 잘린 출력에 `Next: offset=…`이 붙는다 [5][6][28].
통계 도구 5개의 50줄 잘림 안내는 `display_filter`나 `offset`을 쓰라고 적지만 이 도구들은 두 인자를 받지 않는다 [8][9].
응답 상한이 목록을 줄인 응답의 `pagination.next_offset`은 응답 안 목록의 위치이고 `wireshark_aggregate`·`wireshark_extract_credentials`처럼 이 값을 받는 인자가 없는 도구에도 붙는다 [2][21][16].
응답 상한이 글을 줄일 때 넣는 `use offset for pagination` 안내의 수는 글자 수이고 도구의 `offset`은 줄 수다 [4][25].

### R02.05 상한 초과 시 거부

**구현.** 이 방식은 하위 프로세스 출력 상한과 `wireshark_aggregate`의 전체 스캔 상한에 적용된다 [29][30].
`_run_command`는 표준 출력이 16 MiB를, 표준 오류가 1 MiB를 넘으면 프로세스를 끝내고 결과를 자르지 않고 `LimitExceeded` 오류를 돌려준다 [29].
`wireshark_aggregate`는 표시 필터에 맞는 행이 스캔 상한을 넘으면 행을 더 읽지 않고 `LimitExceeded` 오류를 돌려준다 [30][31].
`wireshark_aggregate`가 쓰는 스트리밍 읽기 `_stream_field_rows`는 표준 출력이 50 MiB를, 표준 오류가 1 MiB를 넘어도 프로세스를 끝내고 `LimitExceeded`를 돌려준다 [29][32].
스캔 상한은 `WIRESHARK_MCP_AGGREGATE_SCAN_LIMIT`로 1,000~10,000,000 사이에서 정하고 기본값은 1,000,000이다 [33].
서버 지침은 `wireshark_aggregate`가 필터 전체를 스캔하고 `top_k`는 돌려줄 묶음만 줄인다고 적는다 [34].
20,000패킷 캡처 파일을 `wireshark_read_packets`에 `limit` 0으로 주자 `LimitExceeded` 오류가 돌아왔다 [35].
스캔 상한을 1,000으로 두고 3,000패킷 캡처 파일을 `wireshark_aggregate`에 주자 `LimitExceeded`와 `coverage.scanned` 1000이 돌아왔다 [35].

### R02.06 값 단위 잘림

**구현.** 이 방식은 응답 상한의 `dict` 처리, 오류 응답 처리, DNS 터널 탐지의 표본 값에 적용된다 [2][13].
`cap_result_text`는 `data`의 목록을 모두 비워도 상한을 넘거나 줄일 목록이 없으면 `data` 안의 100자 넘는 문자열 값을 각각 100자로 줄인다 [2].
오류 응답은 `message`를 상한의 절반으로 줄이고 `details`가 상한의 절반을 넘으면 `... [truncated]`로 바꾼다 [2].
`wireshark_detect_dns_tunnel`은 근거 항목의 표본 질의 이름을 60자에서 자른다 [13].

**한계.** 긴 질의 이름 표본은 원래 길이를 적고 앞 60자 뒤에 늘 `...`를 붙인다 [13].
그래서 잘리지 않은 51~60자 이름에도 `...`가 붙는다 [13].
TXT 질의 표본은 표시 없이 60자에서 자른다 [13].
76자 질의 이름이 있는 캡처 파일에서 TXT 표본은 60자에서 끝나고 잘렸다는 표시가 없었다 [36].

### R02.07 건수 없는 잘림 표시

**구현.** 이 방식은 응답 상한, 통계 표 요약, `wireshark_quick_analysis`, 줄 상한에 닿은 탐지·자격 증명 도구에 적용된다 [2][8][10][13][14].
`cap_result_text`는 무엇을 자르든 응답에 `truncated`를 참으로 두고 글을 줄일 때 가운데에 뺀 글자 수를 적은 안내를 넣는다 [2][4].
통계 표 요약과 `wireshark_quick_analysis`는 남은 줄 수만 적는다 [9][10].
탐지·자격 증명 도구는 줄 상한에 닿으면 `warnings`에 상한 값을 적고 `coverage.status`를 `partial`로 둔다 [13][14].
이 경고에는 상한 밖에 있는 패킷 수가 없다 [13][14].

**한계.** 이상 탐지 도구 3개, `wireshark_geoip_enrich`, `wireshark_analyze_tcp_health`, `wireshark_detect_arp_spoofing`, `wireshark_scan_file_signatures`, BLE 분석을 뺀 `wireshark_analyze_protocol`은 필드 추출이나 패킷 목록 결과의 `truncated`를 읽지 않는다 [27][17][37].
그래서 줄 상한에 닿아도 이 도구들의 응답에는 `truncated`도 경고도 없다 [27][37].
PNG 서명이 들어 있는 패킷 80개가 있는 캡처 파일에서 `wireshark_scan_file_signatures`의 응답에는 `PNG: 50 packet(s)`만 실리고 잘림 표시가 없었다 [38].
`wireshark_analyze_protocol`의 글 결과에는 필드 추출 결과의 안내 줄만 남는다 [27][6].
`_maybe_summarize`는 50줄로 줄인 통계 표를 새 `envelope`에 담으므로 클라이언트 결과의 `truncated`와 `stderr`가 빠진다 [8].
`tshark -c`로 줄인 복호화·해석 설정 도구와 Kerberos 분석의 응답에는 잘림 표시가 없다 [7].
`tshark` 4.0.17의 `-c`는 표시 필터에 맞지 않는 패킷도 센다 [39].
그래서 이 도구들은 캡처 파일의 앞 `limit`개 패킷 안에서만 일치를 찾고 그 뒤의 일치는 표시 없이 응답에서 빠진다 [7][39].
DNS 질의 300개가 있는 캡처 파일에 `display_filter` `frame.number > 150`과 `limit` 100을 주자 `wireshark_set_protocol_prefs`와 `wireshark_decode_as`는 머리글 줄만 돌려줬다 [40].

### R02.09 항목 참조값으로 전체 내용 재조회

**구현.** 이 방식은 패킷 번호를 싣는 목록 도구와 `wireshark_get_packet_details`·`wireshark_get_packet_bytes`에 적용된다 [5][41].
`wireshark_get_packet_list`는 기본 열 7개 가운데 첫 열로 `frame.number`를 싣는다 [5].
근거 항목과 BLE 결과도 패킷 번호를 `frame`·`first_frame`·`last_frame`에 싣는다 [13][14][42].
`wireshark_get_packet_details`에 이 번호를 주면 서버는 캡처 파일을 다시 읽어 그 패킷 하나의 전체 해석을 JSON으로 돌려준다 [41].
`wireshark_get_packet_bytes`는 같은 번호로 그 패킷의 16진 덤프를 돌려준다 [41].
서버는 목록 결과를 따로 보관하지 않는다.

**한계.** `custom_columns`를 주면 고른 열만 실리므로 `frame.number`를 고르지 않은 목록에는 참조값이 없다 [5].
`wireshark_get_packet_details`의 결과도 응답 상한을 거치므로 해석 JSON이 상한을 넘으면 가운데가 빠진다 [1][2].

```python
# 2x the smart_truncate default, so output that already bounds itself is untouched.
DEFAULT_MAX_RESULT_CHARS = 8000
MIN_MAX_RESULT_CHARS = 512


def _resolve_max_result_chars() -> int:
    """Read the result ceiling from the environment, falling back to the default."""
    raw = os.environ.get(MAX_RESULT_CHARS_ENV, "").strip()
    if not raw:
        return DEFAULT_MAX_RESULT_CHARS
    try:
        value = int(raw)
    except ValueError:
        logger.warning("Ignoring non-integer %s=%r", MAX_RESULT_CHARS_ENV, raw)
        return DEFAULT_MAX_RESULT_CHARS
    if value < MIN_MAX_RESULT_CHARS:
        logger.warning("Clamping %s=%r to minimum %d", MAX_RESULT_CHARS_ENV, raw, MIN_MAX_RESULT_CHARS)
        return MIN_MAX_RESULT_CHARS
    return value
```

[4] `smart_truncate`는 뒤쪽 최대 500자와 앞쪽 나머지를 남기고 가운데에 뺀 글자 수를 적는다.

```python
def smart_truncate(text: str, max_chars: int = 4000) -> str:
    """Truncate long output preserving head and tail."""
    if len(text) <= max_chars:
        return text
    if max_chars <= 0:
        return ""

    # Compute the marker and content budgets together so very small limits never
    # produce a negative slice (which would retain almost the entire input).
    marker = f"\n\n[... {len(text)} chars omitted, use offset for pagination ...]\n\n"
    if len(marker) >= max_chars:
        return text[:max_chars]

    remaining = max_chars - len(marker)
    tail_budget = min(500, remaining // 4)
    head_budget = remaining - tail_budget
    omitted = len(text) - head_budget - tail_budget
    marker = f"\n\n[... {omitted} chars omitted, use offset for pagination ...]\n\n"

    # The number of digits in `omitted` can change the marker length.
    remaining = max_chars - len(marker)
    tail_budget = min(500, max(0, remaining // 4))
    head_budget = max(0, remaining - tail_budget)
    omitted = len(text) - head_budget - tail_budget
    marker = f"\n\n[... {omitted} chars omitted, use offset for pagination ...]\n\n"
    head_budget = max(0, max_chars - len(marker) - tail_budget)

    result = f"{text[:head_budget]}{marker}{text[-tail_budget:] if tail_budget else ''}"
    return result[:max_chars]
```

```python
    @staticmethod
    def _paginate(output: str, limit_lines: int, offset_lines: int) -> tuple[str, bool]:
        """Slice full command output to an offset/limit window.

        Returns the windowed text and whether it was truncated. A truncation
        footer is appended so callers can page forward. Applied *after* caching
        so the cache always holds the complete output.
        """
        lines = output.splitlines()
        total_lines = len(lines)

        if offset_lines > 0:
            lines = lines[offset_lines:]

        truncated = False
        if limit_lines > 0 and len(lines) > limit_lines:
            lines = lines[:limit_lines]
            truncated = True

        final_output = "\n".join(lines)
        if truncated:
            final_output += (
                f"\n\n[Showing {limit_lines}/{total_lines} lines. Next: offset={offset_lines + limit_lines}]"
            )
        return final_output, truncated
```

```python
def summarize_tabular(data: str, max_rows: int = 50) -> str:
    """Truncate tabular data beyond max_rows with a hint."""
    lines = data.splitlines()
    if len(lines) <= max_rows + 1:
        return data
    header = lines[0]
    rows = lines[1 : max_rows + 1]
    remaining = len(lines) - max_rows - 1
    return "\n".join([header] + rows + [f"[{remaining} more rows. Use display_filter or offset to narrow.]"])
```

```python
    def _make_key(self, pcap_file: str, cmd: list[str]) -> tuple[str, str] | None:
        """Build a cache key and resolved path from file identity and command args."""
        try:
            path = Path(pcap_file).resolve()
            if not path.exists():
                return None
            stat = path.stat()
            identity = f"{path}:{stat.st_mtime_ns}:{stat.st_size}"
        except OSError:
            return None

        cmd_str = "\x00".join(cmd)
        raw = f"{identity}\x01{cmd_str}"
        return hashlib.sha256(raw.encode()).hexdigest()[:32], str(path)
```
