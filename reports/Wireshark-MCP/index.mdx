# Wireshark-MCP 원고

이 파일은 서버 개요다. 셀마다 이 폴더 아래 축 폴더의 `<축>/<셀ID>.mdx`에 쓴다.
셀과 상세 항목의 정의는 `matrix/cells/<축>/<셀ID>.mdx`를 따른다.
상세 항목마다 **구현**을 쓰고 그 방식이 적용되지 않는 경로나 조건이 있으면 **한계**를 따로 쓴다.
본문의 [번호]는 그 파일 끝 **근거**의 같은 번호를 가리킨다.

**기준 커밋.** [`0e1b659`](https://github.com/bx33661/Wireshark-MCP/tree/0e1b6595a2dcfe097133deb1c0c3128fb7a110d4)(2026-10-18).
줄 번호는 모두 이 커밋 기준이다.

**범위.** 저장소의 Python 패키지 `wireshark_mcp`(`src/wireshark_mcp/`)가 MCP 서버 하나다.
`server.py`의 `_build_server`가 MCP Python SDK 2.x의 `MCPServer`를 이어받은 `WiresharkMCP`(`mcp_app.py`)를 만들고 도구 52개, 리소스 4개, 프롬프트 6개, 초기화 지침(`instructions`)을 등록한다.
도구 프로필은 셋이다.
기본 `full`은 도구 52개를 모두 등록하고 `analysis`는 실시간 캡처와 파일을 쓰는 도구를 빼 40개를, `core`는 그 가운데 복호화, 해석 설정 변경, 저수준 보기 도구까지 빼 32개를 등록한다.
진입점은 `wireshark-mcp serve`(`server.py`의 `main`)이고 전송은 stdio(기본), SSE, Streamable HTTP 가운데 하나를 고른다.
`wireshark-mcp`의 `install`, `update`, `uninstall`, `config`, `doctor`, `clients` 명령과 `installer/`는 여러 MCP 클라이언트의 설정 파일에 이 서버를 등록하고 실행 환경을 점검하는 사용자 CLI다.
`src/wireshark_mcp/`의 나머지(`mcp_app.py`, `profiles.py`, `prompts.py`, `resources.py`, `tool_annotations.py`, `toolchain.py`, `tools/`, `tshark/`, `data/`)는 서버 구현이다.
Wireshark의 `tshark`, `capinfos`, `editcap`, `mergecap`, `dumpcap`, `text2pcap`은 서버가 하위 프로세스로 실행하는 분석 도구로 본다.
선택 의존성 `yara-python`과 `geoip2`는 서버가 불러 쓰는 라이브러리이고 GeoIP 데이터베이스 파일은 저장소에 없다.

`skills/`(`.agents/skills/`는 같은 폴더를 가리킨다)는 클라이언트 모델에게 주는 skill 문서와 모델이 MCP를 거치지 않고 `tshark`를 직접 실행하는 스크립트다.
`.claude-plugin/`, `.codex-plugin/`, `.agents/plugins/`, `.well-known/mcp/server.json`, `homebrew/`는 서버와 skill을 배포하는 설정이다.
`Dockerfile`은 저장소가 GHCR에 게시하는 컨테이너 이미지를 만든다.
이 클라이언트 자료, 배포 설정, 사용자 CLI는 상세가 클라이언트 쪽 방식을 묻는 경우, 클라이언트가 MCP 도구 호출을 기록하는 경우, 클라이언트가 서버 응답으로 보고 산출물을 만드는 경우에만 구현으로 보고 그 밖에는 원고에 사실로만 적는다.
`scripts/`, `evals/`, `tests/`, `docs/`는 서버 구현으로 보지 않는다.
`docs/deployment-scenarios.md`의 컨테이너 실행 안내도 서버 구현은 아니지만 README가 가리키고 공식 이미지를 실행하는 명령이므로 저장소가 지원하는 배포 경로로 본다.
README와 `SECURITY.md`의 설명은 코드로 확인한 것만 사실로 쓴다.

**확인 방법.** 코드는 기준 커밋을 `git show`로 읽었다.
분석 도구와 라이브러리의 동작은 아래 버전 기준의 소스로 확인했다.
근거의 "실행 확인"은 기준 커밋을 `git archive`로 풀어 둔 사본을 아래 두 환경에서 실행해 본 결과다.

- 주 환경: 저장소 `Dockerfile`과 같은 `python:3.12-slim-bookworm` 이미지에 Debian 패키지 `tshark` 4.0.17-0+deb12u3을 설치하고 `uv.lock`에 고정된 의존성 버전(`mcp` 2.1.1 등)으로 사본을 설치한 컨테이너다(CPython 3.12.15). 근거에 환경을 따로 적지 않은 실행 확인은 이 환경의 결과다.
  저장소 `Dockerfile`은 PyPI의 `wireshark-mcp` 3.1.0을 설치하지만 확인에는 기준 커밋 사본을 설치했다.
- 보조 환경: Windows 11 Pro(10.0.26200)에 설치된 Wireshark 4.6.7과 같은 의존성 버전을 설치한 CPython 3.13.14다. 이 환경의 결과는 근거에 "Windows"라고 적는다.

도구는 `wireshark-mcp serve`로 띄운 서버에 MCP SDK 클라이언트로 부르거나 도구 모듈을 같은 프로세스에서 불러 확인했다.
입력은 저장소의 시험용 캡처(`tests/fixtures/pcaps/`)와 작업 폴더에 직접 만든 캡처만 썼다.
실시간 캡처와 인터페이스 목록 도구는 네트워크를 끈 컨테이너에서만 실행했고 이 호스트의 네트워크 인터페이스로는 실행하지 않았다.
SSE와 Streamable HTTP 전송은 컨테이너 안이나 `127.0.0.1`에만 열었다.

**외부 도구 버전 기준.** 저장소는 Wireshark 버전을 고정하지 않는다.
저장소가 전제하는 환경 가운데 버전이 정해지는 것은 `Dockerfile`뿐이라 그 이미지가 설치하는 Debian bookworm 패키지를 기준으로 한다.

- Wireshark(`tshark` 등): Debian bookworm 패키지 4.0.17-0+deb12u3이다. 소스는 upstream 태그 `wireshark-4.0.17`(`wireshark/wireshark`, `882448b`)로 확인하고 Debian 패치는 동작이 갈릴 때만 대조한다. 보조 환경의 4.6.7(태그 `v4.6.7`, `b439fb7`)과 동작이 다르면 원고에 두 버전을 함께 적는다.
- MCP Python SDK: `pyproject.toml`은 `mcp>=2.1.1,<3.0.0`을 적고 `uv.lock`은 2.1.1을 고정한다. 2.1.1(`modelcontextprotocol/python-sdk` 태그 `v2.1.1`, `0921d94`)을 기준으로 한다.
- `yara-python`: `uv.lock`의 4.5.4(`VirusTotal/yara-python` 태그 `v4.5.4`, `74920b6`)다.
- `geoip2`: `uv.lock`의 5.3.0(`maxmind/GeoIP2-python` 태그 `v5.3.0`, `9346701`)이다.
- Starlette와 uvicorn: `uv.lock`의 Starlette 1.6.0(`Kludex/starlette` 태그 `1.6.0`, `4f250d6`)과 uvicorn 0.52.4(`Kludex/uvicorn` 태그 `0.52.4`, `8988c23`)다.
- Python: `pyproject.toml`은 3.10 이상을 적고 `Dockerfile`은 3.12를 쓴다.

**바뀔 수 있는 것.** 범위와 외부 도구 버전 기준은 조사하며 맞지 않는 곳이 나오면 검토를 거쳐 바꾼다.
