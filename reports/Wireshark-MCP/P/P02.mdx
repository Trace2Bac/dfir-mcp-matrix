# P02 다음 작업 결정

### P02.01 고정 문서·프로필 반환

**구현.** 이 방식은 서버의 초기화 지침, 프롬프트 6개, 사용법 리소스 `wireshark://guide/usage`에 적용된다 [1][2][3].
서버는 초기화 지침 `SERVER_INSTRUCTIONS`를 `instructions`로 등록한다 [1].
지침은 `wireshark_open_file`로 시작하고 캡처 전체의 집계는 `wireshark_aggregate`로 낸 뒤 패킷 단위 도구로 가장 중요한 발견사항을 확인하라고 적는다 [1].
프롬프트 6개(`security_audit`, `performance_analysis`, `incident_response`, `traffic_overview`, `analyze_with_hypothesis`, `investigate_alert`)는 캡처 파일 경로를 받아 단계마다 부를 도구와 인자를 적은 절차와 보고서 항목을 돌려준다 [2].
`incident_response`는 분류, IOC 추출, 공격 분석, 영향 평가의 네 단계를 적고 앞의 세 단계에 소요 시간(5분, 10분, 15분)을 붙인다 [2].
`analyze_with_hypothesis`는 가설을 세우고 확인하거나 반박할 증거와 도구를 정한 뒤 결과로 가설을 고치는 단계를 되풀이하라고 적는다 [4].
`investigate_alert`는 받은 IOC 값을 IOC 유형별 검색 필터에 넣어 IOC 찾기, 통신 호스트 찾기, 시간순 정리, 관련 지표 넓히기, 증거 사슬 보고의 다섯 단계를 돌려준다 [5].
사용법 리소스는 일반 분석, 보안 분석, 프로토콜 분석의 흐름을 번호 매긴 단계로 적는다 [3].

프롬프트 하나는 도구 프로필에 맞춰 내용이 바뀐다.
서버는 프롬프트를 등록할 때 프로필이 `full`인지를 파일 쓰기 도구 사용 여부로 넘긴다 [6].
`incident_response`는 그 값이 거짓이면 객체 내보내기 단계를 읽기 전용 프로필이라 내보내기를 할 수 없다는 문구로 바꾼다 [6].
세 프로필로 서버를 실행하자 지침, 프롬프트, 리소스에 나오는 도구 이름이 모두 그 프로필의 도구 목록에 있었다 [7].
`analysis`·`core` 프로필의 `incident_response`는 내보내기 단계 대신 그 문구를 실었다 [7].

절차는 모델에게 주는 글이고 서버는 모델이 그 순서를 따르는지 확인하지 않는다.
사용법 리소스는 `wireshark_open_file`이 권장일 뿐 필수가 아니고 모든 도구를 언제든 쓸 수 있다고 적는다 [3].
같은 저장소의 `skills/wireshark-traffic-analysis`는 클라이언트 모델이 읽는 skill 문서다 [8].
이 문서는 정해 둔 도구 목록을 차례로 실행하지 말고 답을 바꿀 질의를 고르라고 적고 내장 프롬프트는 선택해 쓰는 시작 자료라고 적는다 [8].
서버는 이 문서를 도구나 리소스로 돌려주지 않는다.

### P02.02 규칙·조사 상태로 추천

**구현.** 이 방식은 `wireshark_open_file`의 추천과 발견사항을 내는 탐지 도구 응답의 `next_steps`에 적용된다 [9][10].
`wireshark_open_file`은 캡처 파일의 프로토콜 계층 통계에서 읽은 프로토콜 이름을 추천 표와 대조해 다음에 부를 도구를 응답에 싣는다 [9][11].
추천은 지금 서버 프로필에서 뺀 도구를 넣지 않는다 [11].
`core` 프로필로 HTTP 캡처 파일을 열자 `full` 프로필의 추천 8개에서 `wireshark_export_objects`와 `wireshark_yara_scan`이 빠진 6개가 실렸다 [12].
BLE 계열 프로토콜이 있으면 BLE 분석 값마다 무엇을 보는지와 `limit=20`으로 시작하라는 안내를 덧붙인다 [13].
응답 끝에는 늘 `wireshark_quick_analysis`나 `wireshark_get_packet_list`로 시작하고 전체 집계는 `wireshark_aggregate`로 내라는 문장이 붙는다 [13].

발견사항 형식 `Finding`에는 다음 작업 목록 `next_steps`가 있다 [14].
`wireshark_detect_port_scan`, `wireshark_detect_dos_attack`, `wireshark_detect_dns_tunnel`, `wireshark_extract_credentials`, BLE 페어링 분석은 판정 결과에 따라 고른 `next_steps`를 발견사항마다 싣는다 [10].
`wireshark_detect_port_scan`과 `wireshark_detect_dos_attack`은 성공한 검사에서 탐지한 것이 없고 하위 질의가 실패했으면 실패한 검사의 이름을 넣어 그 질의를 다시 실행하라는 다음 작업을 싣는다 [15].
하위 질의 하나를 실패하게 한 실행에서 두 도구의 응답은 `Re-run individual extraction queries for failed checks: ICMP flood analysis.`처럼 실패한 검사를 적은 다음 작업을 실었다 [16].
다른 검사에서 탐지한 것이 있으면 다음 작업은 판정에 맞춘 고정 문장이고 실패한 검사를 넣지 않는다 [10][15].
`wireshark_detect_port_scan`은 문턱값을 넘는 스캔이 없고 실패한 검사도 없으면 그 문턱값보다 낮춰 다시 보라는 다음 작업을 싣는다 [15].
`wireshark_extract_credentials`는 첫 증거에 TCP 스트림 번호가 있으면 그 스트림을 `wireshark_follow_stream`으로 보라는 다음 작업을 싣는다 [17].
스트림 번호가 없으면 `wireshark_get_packet_details`로 해당 프레임을 보라는 다음 작업을 싣는다 [17].
이 안내는 응답의 글이고 서버가 다음 호출을 대신 고르거나 따르지 않은 호출을 막지는 않는다.

**한계.** 추천은 프로토콜 이름만 보고 추천한 도구가 지금 실행 환경에서 동작하는지는 보지 않는다 [11].
`ip`가 있으면 늘 `wireshark_geoip_enrich`를 추천하지만 GeoIP 데이터베이스가 없는 실행 환경에서 이 도구는 `DatabaseMissing` 오류로 끝났다 [12][18].
`http`가 있으면 추천하는 `wireshark_yara_scan`도 `yara-python`이 설치되어 있지 않으면 `DependencyMissing` 오류를 돌려준다 [19].

### P02.04 서버 코드에 고정한 분석 절차

**구현.** 이 방식은 `wireshark_quick_analysis`, `wireshark_yara_scan`, 여러 질의를 묶은 탐지 도구에 적용된다 [20][21][22].
`wireshark_quick_analysis`는 파일 정보, 프로토콜 계층 통계, IP 종단점, TCP 대화, HTTP 요청의 호스트 이름 500개, DNS 질의 이름 500개, 전문가 정보의 7개 단계를 동시에 실행한다 [20].
결과는 6개 절로 합치고 절마다 정한 줄 수에서 자르며 호스트 이름과 질의 이름은 이름별로 세어 많은 차례로 8개씩 싣는다 [20].
전문가 정보 절은 정해 둔 낱말 6개가 출력에 있는지만 보고 낱말마다 표시를 붙이며 응답 전체는 4,000자에서 자른다 [20].
`wireshark_yara_scan`은 고른 프로토콜의 객체를 내보내고 내보낸 파일마다 YARA 규칙을 맞춘 뒤 등급별 건수와 일치 목록을 한 응답으로 만든다 [21].
`wireshark_detect_port_scan`은 SYN, SYN-FIN, NULL 질의 3개를, `wireshark_detect_dos_attack`은 SYN, SYN-ACK, ICMP, UDP, 큰 DNS 응답 질의 5개를 차례로 실행해 판정 하나로 합친다 [22].
`wireshark_detect_exfiltration`은 외부로 가는 TCP 질의와 긴 DNS 이름 질의 2개를, `wireshark_extract_credentials`는 HTTP Basic 인증, FTP `PASS`, Telnet 로그인 문자열 검색 3개를, `wireshark_scan_file_signatures`는 파일 서명 8개의 검색을 묶는다 [22].
모델은 이 도구와 인자만 고르고 그 안의 단계는 서버 코드가 정한다.
서버 안에서 모델을 불러 계획을 세우는 경로는 없다.

**한계.** `wireshark_quick_analysis`는 단계가 예외로 끝나면 빈 문자열로 바꾸고 결과가 실패이거나 10글자 이하이면 그 절에 `Could not read file info`나 `No protocol data available` 같은 고정 문장을 싣는다 [23].
그래서 응답의 그 절은 단계가 실패한 경우와 자료가 없는 경우를 구별하지 않는다 [23].
`capinfos`가 없는 실행에서 응답의 파일 정보 절은 `Could not read file info`였고 다른 절은 그대로 실렸다 [12].
`wireshark_detect_exfiltration`은 두 질의 가운데 실패한 질의를 결과가 없는 질의와 같게 다룬다 [24].
긴 DNS 이름 질의를 실패하게 한 실행에서 응답은 긴 DNS 질의가 없다고 적었다 [16].
`wireshark_scan_file_signatures`는 서명 검색이 실패하면 그 형식을 0건으로 처리한다 [25].
