# L03 기록 실패 처리

### L03.03 알림 없이 계속

**구현.** 이 방식은 서버 코드가 로거 `wireshark_mcp`에 쓰는 모든 항목에 적용된다 [1].
`serve`는 `basicConfig`로 표준 오류에 쓰는 `StreamHandler` 하나를 루트 로거에 붙이고 그 처리기의 오류 처리를 바꾸지 않는다 [1][2].
`WiresharkMCP`를 만들 때 MCP Python SDK 2.1.1의 `MCPServer`가 `configure_logging`으로 `basicConfig`를 한 번 더 부른다 [3].
CPython 3.12.15의 `basicConfig`는 루트 로거에 처리기가 이미 있으면 처리기를 바꾸지 않으므로 처리기는 `serve`가 붙인 하나로 남는다 [2].
CPython 3.12.15의 `StreamHandler.emit`은 쓰기나 비우기에서 난 예외를 `handleError`로 넘긴다 [4].
`handleError`는 `--- Logging error ---`와 예외를 `sys.stderr`에 쓰려 하고 그 쓰기에서 `OSError`가 나면 아무것도 하지 않는다 [5].
기록을 받는 곳과 실패를 알리는 곳이 같은 표준 오류여서 표준 오류에 쓰지 못하면 실패를 알리는 글도 남지 않는다 [1][5].
로거를 부르는 서버 코드는 그 결과를 확인하지 않고 응답을 만든다 [6].
서버 프로세스의 표준 오류를 `/dev/full`에 연결하고 `--log-level DEBUG`로 도구 호출 14번을 보내자 모든 호출이 표준 오류를 파일로 받은 실행과 같은 응답을 돌려줬다 [7].
응답에 기록 실패를 알리는 내용은 없었다 [7].

[6] `_cap_content`와 `_run_command`는 로거를 부른 뒤 그 결과와 관계없이 응답을 만든다.

```python
    def _cap_content(self, result: Any, tool_name: str) -> Any:
        """Apply the ceiling to text blocks, leaving other content shapes alone."""
        # Structured tools return (content, structured_data); cap only the text side.
        if isinstance(result, tuple) and len(result) == 2:
            return (self._cap_content(result[0], tool_name), result[1])

        if not isinstance(result, (list, tuple)):
            return result

        capped: list[Any] = []
        for block in result:
            if isinstance(block, TextContent):
                text = cap_result_text(block.text, self._max_result_chars)
                if text != block.text:
                    logger.debug("Capped %s result from %d to %d chars", tool_name, len(block.text), len(text))
                    block = block.model_copy(update={"text": text})
            capped.append(block)
        return capped
```
