# L01 기록 방식

### L01.01 공통 요청 처리 단계에서 기록

**구현.** 이 방식은 모든 도구 호출의 결과가 지나는 `WiresharkMCP.call_tool`에 적용된다 [1].
`call_tool`은 SDK의 `call_tool`로 도구를 실행한 뒤 결과 글을 `_cap_content`에 넘겨 글자 수 상한을 적용한다 [1].
`_cap_content`는 결과 글을 잘랐을 때만 로거 `wireshark_mcp`에 `DEBUG` 수준으로 `Capped <도구 이름> result from <원래 글자 수> to <자른 글자 수> chars` 항목 하나를 쓴다 [2].
이 항목에는 도구 이름이 있고 인자는 없다 [2].
`serve`는 시작할 때 `logging.basicConfig`로 루트 로거에 표준 오류 출력 처리기를 붙이고 수준을 `--log-level` 값으로 정한다 [3].
`--log-level`의 기본값은 `WARNING`이다 [3].
그래서 항목은 파일이 아니라 서버 프로세스의 표준 오류로 나가고 그 출력을 어디에 남길지는 서버를 실행한 쪽이 정한다 [3].
`--log-level DEBUG`로 실행한 서버에서 결과 상한을 600자로 낮추고 도구를 부르자 상한을 넘은 `wireshark_get_file_info`와 `wireshark_get_packet_list` 호출마다 이 항목이 남았다 [4].

MCP Python SDK 2.1.1의 도구 호출 처리기 `_handle_call_tool`도 같은 표준 오류에 줄을 쓴다 [5].
도구가 `ToolError`로 끝나면 도구 이름과 오류 문구를 `INFO`로 쓰고 인자 검사에서 거부되면 도구 이름과 거부된 인자 이름을 `INFO`로 쓴다 [5].
그 밖의 예외로 끝나면 도구 이름과 예외 추적 정보를 `ERROR`로 쓴다 [5].
이 서버의 도구 코드는 `ToolError` 예외를 내지 않고 도구 실행 실패를 `success`가 거짓인 결과로 돌려준다 [6].
그래서 SDK의 이 줄은 인자 검사 거부, 등록되지 않은 도구 이름, 처리하지 못한 예외에만 남는다 [5][4].
등록되지 않은 도구 이름을 부른 호출과 정수 인자에 문자열을 준 호출은 `--log-level`이 `INFO`나 `DEBUG`일 때 이 `INFO` 줄을 남겼고 기본 수준에서는 남기지 않았다 [4].
SDK의 SSE 처리기는 받은 JSON-RPC 요청 본문을 `DEBUG`로 그대로 쓴다 [7].
SSE 전송을 `--log-level DEBUG`로 실행해 도구 하나를 부르자 도구 이름과 인자를 담은 `tools/call` 요청 본문과 응답 본문이 표준 오류에 남았다 [8].
Streamable HTTP 전송을 같은 수준으로 실행했을 때는 `sse_starlette`가 쓴 응답 본문 줄만 남았고 요청 본문은 남지 않았다 [8].
stdio 전송에서는 같은 수준에서도 요청 본문을 쓴 줄이 없었다 [4].

같은 저장소에는 MCP 도구 호출을 기록하는 클라이언트 코드, 훅, 사용자 CLI가 없다.
`wireshark-traffic-analysis` skill 문서는 여러 호출에 걸친 조사에서 질문, 범위, 이미 얻은 결과를 간추린 조사 상태를 유지하라고 클라이언트 모델에게 안내한다 [9].
이 상태는 클라이언트 모델이 안내문에 따라 쓰는 글이고 코드가 남기는 기록이 아니다.

**한계.** 결과 글이 상한을 넘지 않은 호출은 이 항목을 남기지 않는다 [2].
기본 수준 `WARNING`에서는 이 항목이 출력되지 않는다 [3][4].
환경변수 `WIRESHARK_MCP_MAX_RESULT_CHARS`로 상한을 올리면 항목을 남기는 호출이 줄어든다 [10].

### L01.02 도구별 기록 호출

**구현.** 이 방식은 도구가 부르는 클라이언트 메서드가 거치는 경로 검사 함수 `_validate_file`·`_validate_output_path`에 적용된다 [11][12].
도구마다 하나씩 있는 클라이언트 메서드가 입력 파일 경로를 `_validate_file`로, 출력 경로를 `_validate_output_path`로 검사한다 [12].
도구 52개 가운데 `wireshark_get_capabilities`와 `wireshark_list_interfaces`를 뺀 50개가 입력 파일 경로 검사를 거친다 [12].
`_validate_file`은 경로가 `WIRESHARK_MCP_ALLOWED_DIRS`의 폴더 밖이면 `Path sandbox violation: <받은 경로>` 항목을 `WARNING`으로 쓰고 `PermissionDenied` 오류를 돌려준다 [11].
`_validate_output_path`는 출력 경로가 허용 폴더 밖이면 `Output path sandbox violation: <받은 경로>` 항목을 `WARNING`으로 쓴다 [11].
이 항목에는 거부된 경로 인자가 있고 도구 이름은 없다 [11].
항목은 `serve`가 붙인 표준 오류 처리기로 나가고 기본 수준 `WARNING`에서도 출력된다 [3].
허용 폴더를 정한 서버에서 허용 폴더 밖 경로로 도구를 부르자 기본 수준에서 이 항목이 남았다 [4].

**한계.** `WIRESHARK_MCP_ALLOWED_DIRS`를 정하지 않으면 `_validate_file`은 허용 폴더 대조를 하지 않아 이 항목을 쓰지 않는다 [11][13].
같은 상태에서 `_validate_output_path`는 쓰기를 거부하며 `Blocked file write because WIRESHARK_MCP_ALLOWED_DIRS is not configured`를 쓰고 이 줄에는 경로도 도구 이름도 없다 [14].
경로가 비었거나 Windows 장치 경로이거나 파일이 없는 경우처럼 다른 검사에서 거부된 호출은 항목을 쓰지 않는다 [11].

### L01.03 공통 실행 함수에서 기록

**구현.** 이 방식은 분석 도구를 하위 프로세스로 실행하는 공통 실행 함수 `WiresharkSuiteClient._run_command`에 적용된다 [15].
`tshark`, `capinfos`, `editcap`, `mergecap`, `dumpcap`, `text2pcap`을 실행하는 클라이언트 메서드는 `wireshark_aggregate`가 쓰는 `stream_fields`와 버전 확인을 빼면 모두 `_run_command`를 부른다 [16].
`_run_command`는 실행 직전에 `Executing: <명령 줄>` 항목을 `DEBUG`로 쓴다 [15].
실행이 시간 제한을 넘거나 출력 상한을 넘거나 0이 아닌 코드로 끝나면 명령 줄을 담은 `WARNING` 항목을 쓴다 [17].
`tshark`가 잘린 캡처 파일을 읽고 부분 결과를 돌려줄 때도 `WARNING` 항목을 쓴다 [17].
실행 중 예외가 나면 `logger.exception`으로 명령 줄과 예외 추적 정보를 쓴다 [17].
같은 명령의 결과가 캐시에 있으면 실행하지 않고 명령 배열의 앞 4개 값을 담은 `Cache hit for:` 항목을 `DEBUG`로 쓴다 [18].
허용 목록에 없는 실행 파일이면 실행하지 않고 그 이름을 `ERROR`로 쓴다 [18].
항목은 `serve`가 붙인 표준 오류 처리기로 나간다 [3].
기본 수준에서 도구 14번을 부르자 `tshark`가 실패한 실행 2번과 잘린 캡처를 읽은 실행 1번의 `WARNING` 항목이 남았다 [4].
`--log-level DEBUG`에서는 `_run_command`를 거친 실행마다 `Executing:` 항목이 남았고 같은 인자로 두 번째 부른 `wireshark_get_packet_list`에는 `Cache hit for:` 항목이 남았다 [4].

**한계.** `wireshark_aggregate`는 `_run_command` 대신 `_stream_field_rows`로 `tshark`를 실행하고 이 함수는 실행 전 항목을 쓰지 않는다 [19].
`_stream_field_rows`는 `tshark`가 0이 아닌 코드로 끝나거나 행 수·출력 상한을 넘거나 시간 제한을 넘어도 오류 결과만 돌려주고 항목을 쓰지 않는다 [19].
이 함수는 프로세스를 만들지 못하거나 행을 읽다 예외가 났을 때만 `logger.exception`으로 항목을 쓴다 [19].
`DEBUG` 수준에서 성공한 `wireshark_aggregate` 호출과 잘못된 표시 필터로 실패한 `wireshark_aggregate` 호출은 둘 다 항목을 남기지 않았다 [4].
`wireshark_get_capabilities`의 버전 확인은 `_run_command`를 거치지 않고 각 실행 파일을 `-v`로 직접 실행하며 항목을 쓰지 않는다 [20].
기본 수준 `WARNING`에서는 `Executing:` 항목이 출력되지 않아 성공한 실행은 기록에 남지 않는다 [3][4].
줄 상한으로 출력을 자른 실행은 0이 아닌 코드로 끝나도 실패 항목을 남기지 않는다 [21].
뒤쪽에 손상된 레코드가 있는 캡처 파일을 `limit` 5로 읽은 `wireshark_get_packet_list` 호출은 `DEBUG` 수준에서도 `Executing:` 항목만 남겼다 [22].

```python
    def _cap_content(self, result: Any, tool_name: str) -> Any:
        """Apply the ceiling to text blocks, leaving other content shapes alone."""
        # Structured tools return (content, structured_data); cap only the text side.
        if isinstance(result, tuple) and len(result) == 2:
            return (self._cap_content(result[0], tool_name), result[1])

        if not isinstance(result, (list, tuple)):
            return result

        capped: list[Any] = []
        for block in result:
            if isinstance(block, TextContent):
                text = cap_result_text(block.text, self._max_result_chars)
                if text != block.text:
                    logger.debug("Capped %s result from %d to %d chars", tool_name, len(block.text), len(text))
                    block = block.model_copy(update={"text": text})
            capped.append(block)
        return capped
```

[10] 결과 글자 수 상한은 `WIRESHARK_MCP_MAX_RESULT_CHARS`에서 읽고 기본값은 8000이다.

```python
MAX_RESULT_CHARS_ENV = "WIRESHARK_MCP_MAX_RESULT_CHARS"
# 2x the smart_truncate default, so output that already bounds itself is untouched.
DEFAULT_MAX_RESULT_CHARS = 8000
MIN_MAX_RESULT_CHARS = 512


def _resolve_max_result_chars() -> int:
    """Read the result ceiling from the environment, falling back to the default."""
    raw = os.environ.get(MAX_RESULT_CHARS_ENV, "").strip()
    if not raw:
        return DEFAULT_MAX_RESULT_CHARS
    try:
        value = int(raw)
    except ValueError:
        logger.warning("Ignoring non-integer %s=%r", MAX_RESULT_CHARS_ENV, raw)
        return DEFAULT_MAX_RESULT_CHARS
    if value < MIN_MAX_RESULT_CHARS:
        logger.warning("Clamping %s=%r to minimum %d", MAX_RESULT_CHARS_ENV, raw, MIN_MAX_RESULT_CHARS)
        return MIN_MAX_RESULT_CHARS
    return value
```
