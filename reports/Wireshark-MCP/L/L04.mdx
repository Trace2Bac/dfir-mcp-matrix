# L04 기록 위변조 방지

### 미구현

**판단.** 서버 기록은 서버 코드와 MCP SDK가 로거에 쓰는 항목이고 서버는 이 항목을 표준 오류로만 내보낸다 [1].
서버 코드에서 로깅 처리기를 붙이는 곳은 `serve`의 `basicConfig` 한 곳이고 기록 파일이나 DB를 여는 곳은 없다 [1][2].
항목 형식은 시각, 로거 이름, 수준, 메시지뿐이고 앞 항목의 해시나 일련번호가 없다 [1].
표준 오류를 어디에 어떻게 남길지는 서버를 실행한 쪽이 정한다 [1].
저장소의 `Dockerfile`이 만드는 이미지도 서버를 같은 방식으로 실행하고 기록을 담을 폴더를 따로 두지 않는다 [3].
저장소에는 기록을 다시 계산해 어긋난 항목을 알려 주는 도구나 명령이 없다 [2].
그래서 서버 기록의 수정, 삭제, 순서 변경을 막거나 알아차리는 장치가 없다.

### 근거

[1] `serve`는 시각, 로거 이름, 수준, 메시지 형식으로 표준 오류에 쓰는 `basicConfig`를 부른다.

```python
    # Configure logging
    logging.basicConfig(
        level=getattr(logging, args.log_level),
        format="%(asctime)s [%(name)s] %(levelname)s: %(message)s",
        stream=sys.stderr,
    )
```

[2] (실행 확인) 기준 커밋의 `src/wireshark_mcp/`를 `git grep`으로 찾았다.
`logging.basicConfig`를 부르는 곳은 `server.py` 한 곳이었고 `FileHandler`, `RotatingFileHandler`, `sqlite3`를 쓰는 곳은 없었다.
`hashlib`은 결과 캐시의 키를 만드는 `tshark/cache.py`에서만 썼다.

[3] 이미지는 `/captures`와 `/results`만 만들고 `wireshark-mcp`를 그대로 실행한다.

```dockerfile
RUN apt-get update \
    && DEBIAN_FRONTEND=noninteractive apt-get install --yes --no-install-recommends ca-certificates tshark \
    && apt-get clean \
    && rm -rf /var/lib/apt/lists/* \
    && python -m pip install --no-cache-dir --upgrade "setuptools>=83" \
    && python -m pip install --no-cache-dir "wireshark-mcp==${WIRESHARK_MCP_VERSION}" \
    && groupadd --gid 10001 wireshark-mcp \
    && useradd --uid 10001 --gid 10001 --create-home wireshark-mcp \
    && mkdir --parents /captures /results \
    && chown wireshark-mcp:wireshark-mcp /captures /results

USER wireshark-mcp
WORKDIR /captures

EXPOSE 8080

ENTRYPOINT ["wireshark-mcp"]
CMD ["serve", "--transport", "streamable-http", "--host", "0.0.0.0", "--port", "8080", "--allow-insecure-http", "--profile", "analysis"]
```
