# E04 분석 입력 준비

### E04.01 작업 사본 생성

**구현.** 이 방식은 `wireshark_export_objects`, `wireshark_yara_scan`, `wireshark_merge_pcaps`, `wireshark_editcap_split`, `wireshark_text2pcap_import`에 적용된다 [1][2][3].
`wireshark_export_objects`는 캡처 파일에서 고른 프로토콜(`http`·`smb`·`tftp`·`imf`·`dicom`)로 전달된 객체를 모두 `tshark --export-objects`로 `dest_dir`에 파일로 꺼낸다 [1].
서버는 `tshark`를 실행하기 전에 `dest_dir`를 만든다 [1].
`wireshark_yara_scan`은 같은 내보내기로 꺼낸 파일을 같은 호출에서 YARA 검사의 입력으로 쓴다 [2].
`dest_dir`를 주지 않으면 허용 폴더 안의 임시 폴더에 꺼내고 호출이 끝나면 그 폴더를 지운다 [2].
`wireshark_merge_pcaps`는 쉼표로 받은 캡처 파일들의 패킷을 `mergecap`으로 새 캡처 파일 하나에 모은다 [3][4].
서버는 `mergecap`에 출력 형식 인자를 넘기지 않는다 [4].
pcap 형식의 캡처 파일을 합친 결과는 pcapng 파일이었다 [5].
`wireshark_editcap_split`은 캡처 파일 전체를 패킷 수나 시간 간격마다 `editcap`으로 나눠 여러 파일에 쓴다 [3].
`wireshark_text2pcap_import`은 ASCII나 16진 덤프 글 파일을 `text2pcap`으로 캡처 파일로 바꾼다 [3].
HTTP 캡처 파일의 객체를 내보내자 `dest_dir`에 `sample.txt`가 생겼고 패킷 25개짜리 캡처 파일을 10개씩 나누자 `part_00000_<시각>.pcap`부터 3개 파일이 생겼다 [6].

출력 위치는 모델이 인자로 정하고 서버는 그 위치가 허용 폴더 안인지만 확인한다 [7].
이 도구들은 `full` 프로필에만 등록되고 `analysis`·`core` 프로필에는 없다 [8].
나머지 분석 도구는 사본을 만들지 않고 받은 캡처 파일 경로를 그대로 분석 도구 인자로 넘긴다.
서버에는 입력 옆의 부속 자료(링 버퍼나 분할로 나뉜 다른 캡처 파일)를 찾는 코드가 없고 `wireshark_merge_pcaps`는 모델이 나열한 파일만 합친다 [4].

### E04.02 선택 추출

**구현.** 이 방식은 `wireshark_extract_frames`, `wireshark_filter_save`, `wireshark_editcap_trim`에 적용된다 [9][10][11].
`wireshark_extract_frames`는 프레임 번호와 번호 범위를 받아 `editcap -r`로 그 프레임만 새 캡처 파일에 쓴다 [12].
서버는 범위가 1 이상의 정수와 `시작-끝` 꼴인지, 끝이 시작보다 작지 않은지, 번호가 10억 이하이고 토막이 1,000개 이하인지 확인한다 [9].
`wireshark_filter_save`는 표시 필터를 받아 `tshark -Y`에 맞는 패킷만 `-w`로 새 캡처 파일에 쓴다 [10].
`wireshark_editcap_trim`은 시작 시각과 끝 시각을 받아 `editcap -A`·`-B`로 그 구간의 패킷만 새 캡처 파일에 쓴다 [11].
고르는 기준은 경로, 이름, inode, 내용 서명이 아니라 프레임 번호, 표시 필터, 시간 구간이다.
세 도구는 만든 파일을 다른 분석에 넘기지 않고 그 파일을 분석 입력으로 쓸지는 모델이 정한다.

### E04.04 추출·생략 범위 기록

**구현.** 이 방식은 `wireshark_yara_scan`에 적용된다 [2].
`wireshark_yara_scan`은 응답에 내보낸 파일 수와 일치 건수를 적고 일치한 파일은 이름과 규칙을 적는다 [13].
검사하지 못한 파일이 있으면 그 수와 결과가 불완전하다는 문장을 붙이고 내보낸 파일이 없으면 그 사실을 적는다 [13][14].
HTTP 캡처 파일의 응답은 `1 YARA match(es) in 1 file(s)`였고 `tftp`로 부른 응답은 `No files exported from tftp traffic`이었다 [6].

다른 사본·추출 도구는 준비한 범위를 응답에 싣지 않는다.
`wireshark_export_objects`의 응답은 `tshark`가 표준 출력에 낸 패킷 목록이고 꺼낸 파일의 목록이 아니다 [1][6].
`wireshark_merge_pcaps`와 `wireshark_editcap_split`의 응답은 빈 글이었다 [6].
`wireshark_extract_frames`의 응답은 모델이 준 범위와 출력 경로를 그대로 적고 실제로 쓴 패킷 수는 적지 않는다 [12].
패킷 25개짜리 캡처 파일에 없는 프레임 번호를 섞은 범위를 주자 응답은 그 범위를 그대로 적었고 만든 파일의 패킷은 3개였다 [6].
`wireshark_filter_save`의 응답은 출력 경로만 적는다 [10].

### E04.08 내용을 바꾼 사본 생성

**구현.** 이 방식은 `wireshark_editcap_time_shift`와 `wireshark_editcap_deduplicate`에 적용된다 [15].
`wireshark_editcap_time_shift`는 받은 초만큼 모든 패킷의 시각을 옮긴 새 캡처 파일을 `editcap -t`로 쓴다 [16].
`wireshark_editcap_deduplicate`는 정한 패킷 수 범위 안에서 `editcap`이 중복으로 판단한 패킷을 뺀 새 캡처 파일을 `editcap -D`로 쓴다 [16].
두 도구는 모델이 준 출력 경로에 새 파일을 쓰고 그 파일을 분석 입력으로 쓸지는 모델이 정한다 [16].
두 도구는 `full` 프로필에만 등록된다 [8].
첫 패킷 시각이 `00:33:20`인 캡처 파일을 3600초 옮기자 새 파일의 첫 패킷 시각은 `01:33:20`이었다 [17].
같은 캡처 파일을 두 번 합친 패킷 50개짜리 파일에서 중복을 빼자 25개가 남았다 [17].

**한계.** 응답에는 바꾼 내용이 실리지 않는다 [16][17].
시각 이동의 응답 `data`는 빈 글이었고 중복 제거로 뺀 패킷 수는 `editcap`이 표준 오류에 적은 `stderr` 글에만 있었다 [17].
두 도구가 만든 파일의 형식은 입력의 pcap과 달리 pcapng였다 [17].

        """Export Objects (--export-objects protocol,dest_dir)."""

                crit_high = severity_counts.get("critical", 0) + severity_counts.get("high", 0)
                if crit_high > 0:
                    output.append(f"{CRIT} {total_matches} YARA match(es) in {len(files)} file(s)")
                else:
                    output.append(f"{WARN} {total_matches} YARA match(es) in {len(files)} file(s)")

                breakdown = ", ".join(f"{k}: {v}" for k, v in sorted(severity_counts.items()))
                output.append(f"Severity breakdown: {breakdown}")
                output.append("")
                output.append(f"{'File':<30} {'Rule':<25} {'Description':<35} {'Sev':<10} {'Cat'}")
                output.append("-" * 110)
                output.extend(results)
            else:
                output.append(f"{OK} No YARA matches in {len(files)} exported {protocol} file(s)")

            if scan_errors:
                output.append(f"{WARN} {scan_errors} exported file(s) could not be scanned; result is incomplete")

    async def editcap_time_shift(self, input_file: str, output_file: str, seconds: float) -> str:
        """Editcap: Shift packet timestamps by a relative amount."""
        required = self._require_tool("editcap")
        if not required["success"]:
            return json.dumps(required)

        validation = self._validate_file(input_file)
        if not validation["success"]:
            return json.dumps(validation)

        output_validation = self._validate_output_path(output_file)
        if not output_validation["success"]:
            return json.dumps(output_validation)

        editcap_path = self._get_checked_tool_path("editcap")
        cmd = [editcap_path, "-t", str(seconds), input_file, output_file]
        return await self._run_command(cmd)
