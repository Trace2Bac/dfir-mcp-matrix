# D06 산출물 식별·재생성 처리

### D06.02 입력·작업별 고유 이름

**구현.** 이 방식은 `wireshark_editcap_split`의 분할 파일과 `ring_buffer`를 준 `wireshark_capture`의 캡처 파일에 적용된다 [1][2].
두 이름 규칙은 서버 코드가 아니라 Wireshark 4.0.17의 `editcap`과 `dumpcap`이 정한다 [1][2].
`editcap`은 받은 경로의 마지막 조각에서 마지막 `.` 앞까지를 접두어로 삼아 `<접두어>_<5자리 번호>_<시각><확장자>` 이름으로 쓴다 [1].
번호는 분할할 때마다 0부터 매기고 시각은 그 분할 파일 첫 패킷의 기록 시각이다 [1].
이 시각은 입력마다 다른 값이라 첫 패킷 시각이 다른 캡처를 같은 접두어로 분할하면 이름이 다르다 [1].
같은 입력을 같은 접두어로 다시 분할하면 같은 이름이 되고 앞 파일을 덮어쓴다 [1][3].
같은 캡처를 같은 `output_prefix`로 1초 넘게 사이를 두고 다시 분할하자 세 파일이 같은 이름으로 모두 다시 쓰였다 [3].

`dumpcap`은 링 버퍼 파일마다 `<접두어>_<5자리 번호>_<YYYYMMDDHHMMSS><확장자>` 이름을 짓고 시각은 그 파일을 연 때의 현지 시각이다 [2].
그래서 1초 넘게 사이를 두고 같은 `output_file`로 다시 캡처하면 앞 파일과 이름이 다르다 [2].
같은 `output_file`로 두 번 캡처하자 시각만 다른 두 파일이 남았다 [4].

그 밖의 파일을 쓰는 도구는 호출 인자로 받은 이름에 그대로 쓴다 [5].
`ring_buffer`를 주지 않은 `wireshark_capture`도 `output_file` 이름 그대로 쓴다 [5].
`dest_dir` 없이 부른 `wireshark_yara_scan`의 임시 폴더 이름은 `mkdtemp`가 짓지만 호출이 끝나면 지운다 [6].

**한계.** 링 버퍼 이름의 시각은 초 단위라 같은 초에 같은 `output_file`로 시작한 캡처는 같은 이름을 쓰고 `dumpcap`은 그 파일을 `O_TRUNC`로 열어 덮어쓴다 [2].

### D06.03 버전·이력 보존

**구현.** 이 방식은 `wireshark_export_objects`와 `dest_dir`를 준 `wireshark_yara_scan`이 이미 파일이 있는 폴더로 다시 내보낼 때 적용된다 [7][6].
이 규칙은 서버 코드가 아니라 Wireshark 4.0.17의 `tshark`가 정한다 [7].
`tshark`는 같은 이름의 파일이 있으면 확장자 앞에 `(1)`, `(2)` 같은 번호를 붙인 새 이름으로 쓰고 앞 파일을 지우지 않는다 [7].
`report.txt`가 있는 폴더로 내보내자 앞 파일은 내용과 수정 시각이 그대로 남고 새 내용은 `report(1).txt`로 생겼다 [8].
번호가 붙은 파일과 앞 파일을 가르는 것은 이름의 번호뿐이고 서버는 어느 호출이 어느 파일을 썼는지 남기지 않는다 [7][9].

**한계.** 원래 이름과 `(1)`부터 `(999)`까지의 이름이 모두 있으면 `tshark`는 `(999)` 이름의 파일을 덮어쓴다 [7][10].
같은 서버 프로세스에서 같은 캡처 파일과 같은 인자로 다시 부른 호출이 결과 캐시로 처리되면 `tshark`를 실행하지 않아 번호를 붙인 새 파일도 생기지 않는다 [11][12].

### D06.04 덮어쓰기 선택·충돌 감지

**구현.** 이 방식은 파일을 쓰는 도구 가운데 `wireshark_export_objects`, `wireshark_filter_save`, `wireshark_extract_frames`와 `dest_dir`를 준 `wireshark_yara_scan`에 적용된다 [11][13][6].
`_run_command`는 명령에 `-r`이 있으면 바로 뒤의 인자를 입력 파일로 보고 결과 캐시 `ResultCache`에서 같은 명령의 결과를 찾는다 [11].
찾으면 분석 도구를 실행하지 않고 캐시에 둔 표준 출력을 성공 응답으로 돌려준다 [11].
`tshark`를 부르는 두 도구는 `-r`로 입력을 넘기고 `wireshark_extract_frames`는 `editcap`의 `-r` 선택지 바로 뒤에 입력 파일을 둔다 [13].
`editcap`에서 `-r`은 고른 프레임만 남기라는 선택지이지만 서버는 이 명령에도 같은 방식으로 캐시를 쓴다 [13][11].
캐시 키는 입력 파일의 실제 경로, `st_mtime_ns`, `st_size`와 명령 인자 전체로 만든다 [12].
종료 코드 0으로 끝난 실행의 출력만 캐시에 넣고 넣은 지 300초가 지난 항목은 쓰지 않는다 [11][14].
그래서 같은 프로세스에서 같은 입력과 같은 인자로 300초 안에 다시 부르면 출력 파일을 다시 만들지 않는다 [15].
`dest_dir` 없이 부른 `wireshark_yara_scan`은 호출마다 임시 폴더 이름이 달라 명령이 같지 않으므로 캐시 결과를 쓰지 않는다 [6].
덮어쓸지를 호출 인자로 고르게 하는 도구는 없다.

이 방식이 없는 도구는 목적지에 같은 이름이 있는지 보지 않는다.
`wireshark_merge_pcaps`, `wireshark_text2pcap_import`, `wireshark_editcap_trim`, `wireshark_editcap_time_shift`, `wireshark_editcap_deduplicate`, `wireshark_editcap_split`, `ring_buffer`를 주지 않은 `wireshark_capture`는 같은 이름의 앞 파일을 알리지 않고 덮어쓴다 [5][16].
`wireshark_merge_pcaps`의 `output_file`로 캡처가 아닌 기존 파일을 주자 그 파일이 pcapng 파일로 바뀌었고 응답은 빈 `data`의 성공 응답이었다 [16].

**한계.** 캐시는 출력 파일이 남아 있는지나 그 내용이 바뀌었는지 보지 않는다 [11][12].
출력 파일을 지운 뒤 같은 호출을 다시 하자 `wireshark_export_objects`, `wireshark_filter_save`, `wireshark_extract_frames` 모두 성공 응답을 돌려주었고 파일은 다시 생기지 않았다 [15].
`wireshark_export_objects`의 두 번째 응답은 첫 호출과 같은 패킷 목록이었다 [15].
같은 `dest_dir`로 다시 부른 `wireshark_yara_scan`은 내보내기를 하지 않아 빈 폴더를 보고 `nothing to scan` 성공 응답을 돌려주었다 [15].
다른 도구가 같은 출력 경로에 다른 캡처를 쓴 뒤 `wireshark_extract_frames`를 같은 인자로 다시 부르자 응답은 `Extracted frames 1-3`이었고 파일은 다른 도구가 쓴 내용 그대로였다 [15].
캐시는 프로세스 메모리에만 있어 넣은 지 300초가 지나거나 서버를 다시 시작하거나 항목이 128개·50MB 상한으로 밀려나면 다시 실행한다 [14].
이때 `wireshark_filter_save`와 `wireshark_extract_frames`는 같은 이름의 앞 파일을 알리지 않고 덮어쓰고 `wireshark_export_objects`와 `dest_dir`를 준 `wireshark_yara_scan`은 번호를 붙인 새 파일을 쓴다 [5][7].
출력이 12.5MB를 넘는 실행은 캐시에 넣지 않는다 [14].

```python
    def _make_key(self, pcap_file: str, cmd: list[str]) -> tuple[str, str] | None:
        """Build a cache key and resolved path from file identity and command args."""
        try:
            path = Path(pcap_file).resolve()
            if not path.exists():
                return None
            stat = path.stat()
            identity = f"{path}:{stat.st_mtime_ns}:{stat.st_size}"
        except OSError:
            return None

        cmd_str = "\x00".join(cmd)
        raw = f"{identity}\x01{cmd_str}"
        return hashlib.sha256(raw.encode()).hexdigest()[:32], str(path)
```
