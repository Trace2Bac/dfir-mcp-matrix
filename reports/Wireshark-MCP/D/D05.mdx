# D05 파생물 저장 실패 처리

### D05.01 오류·부분 완료 표시

**구현.** 이 방식은 파일을 쓰는 도구 11개가 분석 도구를 실행하는 경로와 `wireshark_export_objects`가 목적지 폴더를 만드는 경로에 적용된다 [1][2].
`_run_command`는 분석 도구가 0이 아닌 종료 코드로 끝나면 `ExecutionError`와 표준 오류를 담은 실패 응답을 돌려준다 [1].
쓰기 권한이 없는 폴더를 목적지로 준 `wireshark_merge_pcaps`, `wireshark_editcap_trim`, `wireshark_filter_save`, `wireshark_extract_frames`는 종료 코드 2와 쓰기 권한이 없다는 표준 오류를 담은 실패 응답으로 끝났다 [3].
없는 하위 폴더 아래를 목적지로 준 `wireshark_editcap_trim`도 종료 코드 2의 실패 응답으로 끝났다 [3].
시간 제한을 넘으면 분석 도구 프로세스를 끝내고 `TimeoutError` 실패 응답을 돌려주며 그 밖의 예외는 `ExecutionError` 실패 응답으로 돌려준다 [4].
`export_objects`는 `os.makedirs`에서 난 예외를 처리하지 않는다 [2].
MCP Python SDK 2.1.1은 도구 함수에서 처리하지 않은 예외를 `Error executing tool <도구 이름>` 글의 오류 결과로 돌려준다 [5].
쓰기 권한이 없는 폴더 아래의 새 폴더를 `dest_dir`로 주자 `PermissionError`가 났고 `is_error`가 참인 결과가 왔다 [3].

Wireshark 4.0.17의 `tshark --export-objects`는 꺼낸 파일을 열지 못하면 표준 오류에 그 파일 이름을 적고 다음 파일로 간다 [6].
이때 종료 코드는 0이고 `_run_command`는 표준 오류를 성공 응답의 `stderr`에 싣는다 [1][7].
쓰기 권한이 없는 폴더로 부른 `wireshark_export_objects`의 응답은 `success`가 참이고 `stderr`에 두 파일을 쓰지 못했다는 줄이 있었다 [3].

`wireshark_capture`, `wireshark_filter_save`, `wireshark_extract_frames`는 분석 도구가 성공한 뒤 출력 파일이 있는지 본다 [8][9].
있으면 저장 경로를 담은 새 글을 돌려준다 [8][9].
없으면 `wireshark_capture`는 `Capture completed but file not found`를 성공 응답에 싣고 나머지 둘은 받은 응답을 그대로 돌려준다 [8][9].
이 확인은 경로에 무엇이 있는지만 보고 이번 호출이 쓴 파일인지 가리지 않는다 [8][9].
`wireshark_capture`는 성공한 실행의 `data`만 새 응답에 넣어 `dumpcap`의 표준 오류를 응답에 싣지 않는다 [8].
저장한 파일을 다시 읽어 확인하거나 완료 표시를 남기는 코드는 없다.

**한계.** 분석 도구가 실패하거나 시간 제한으로 끝나도 서버는 쓰다 만 출력 파일을 지우지 않는다 [1][4].
잘린 캡처 파일을 입력으로 준 `wireshark_filter_save`와 `wireshark_merge_pcaps`는 실패 응답으로 끝났지만 목적지에는 각각 패킷 1개와 26개를 담은 파일이 남았다 [10].
`ring_buffer`를 준 `wireshark_capture`에서 `dumpcap`은 `output_file`에 번호와 시각을 붙인 이름으로 쓰므로 `output_file` 경로에는 파일이 없다 [11].
그래서 이 호출은 캡처 파일을 쓰고도 `Capture completed but file not found`를 담은 성공 응답을 돌려주었다 [12].
허용 폴더 자체를 `output_file`로 준 같은 호출은 그 폴더가 있으므로 `Capture saved to`와 폴더 경로를 실었고 캡처 파일은 그 상위 폴더에 생겼다 [12].

### D05.03 알림 없이 계속

**구현.** 이 방식은 `wireshark_yara_scan`, `wireshark_extract_frames`, `wireshark_filter_save`가 분석 도구의 표준 오류를 다루는 경로에 적용된다 [13][9].
`wireshark_yara_scan`은 내보내기 응답에서 `success`만 보고 `stderr`는 읽지 않는다 [13].
그다음 목적지 폴더에 파일이 없으면 `No files exported from <프로토콜> traffic`과 `nothing to scan`을 담은 성공 응답을 돌려준다 [13].
쓰기 권한이 없는 폴더를 `dest_dir`로 준 호출은 꺼낸 파일을 쓰지 못했다는 표준 오류 없이 이 성공 응답을 받았다 [3].

`wireshark_extract_frames`와 `wireshark_filter_save`는 출력 파일이 있으면 받은 응답에서 `_unwrap`으로 `data`만 꺼내 새 성공 응답을 만든다 [9][14].
그래서 분석 도구가 종료 코드 0으로 끝나며 표준 오류에 적은 내용은 응답에 남지 않는다 [9][14].
잘린 캡처 파일에서 프레임 1~5를 고른 `wireshark_extract_frames`의 응답은 `Extracted frames 1-5`였고 `stderr`가 없었으며 출력 파일에는 패킷 1개만 있었다 [10].
같은 입력으로 부른 `wireshark_editcap_trim`의 응답은 `editcap`이 표준 오류에 적은 잘린 파일이라는 줄을 `stderr`에 실었다 [10].

    if "success" in payload and isinstance(payload["success"], bool):
        if payload["success"]:
            envelope: dict[str, Any] = {"success": True, "data": payload.get("data")}
            for extra_key in ("scope", "coverage", "pagination", "warnings", "truncated", "stderr"):
                if extra_key in payload:
                    envelope[extra_key] = payload[extra_key]
            if "data" not in payload:

                envelope["data"] = extra if extra else None

```python
    @staticmethod
    def _unwrap(result: str) -> tuple[bool, str]:
        """Extract (success, text) from a client envelope for internal reuse.

        On a success envelope, returns the ``data`` text. On an error envelope,
        returns ``(False, <original envelope>)`` so callers can propagate it
        unchanged. Non-envelope strings are treated as raw success text.
        """
        try:
            parsed = json.loads(result)
        except (json.JSONDecodeError, ValueError):
            return True, result
        if isinstance(parsed, dict) and "success" in parsed:
            if parsed.get("success") is True:
                data = parsed.get("data", "")
                return True, data if isinstance(data, str) else json.dumps(data)
            return False, result
        return True, result
```
