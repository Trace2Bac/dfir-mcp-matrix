# D02 파생물 추적

### 미구현

**판단.** 서버가 남기는 파생물은 파일을 쓰는 도구가 만든 캡처 파일과 캡처에서 꺼낸 파일이고 서버는 이 파일을 그것을 만든 호출이나 사용한 입력과 잇는 값을 남기지 않는다 [1].
출력 경로는 호출 인자가 정하고 서버 코드는 출력 이름에 호출이나 입력을 가리키는 값을 넣지 않는다 [1].
출력 파일 곁에 manifest를 두지 않는다.
서버는 로그를 표준 오류로만 출력하고 호출 기록을 파일이나 DB에 쓰지 않는다 [2].
실행한 명령줄은 `DEBUG` 수준의 `Executing:` 로그에만 들어 있고 기본 로그 수준은 `WARNING`이다 [3].

`wireshark_filter_save`와 `wireshark_extract_frames`의 응답은 출력 파일 경로를 싣고 입력 파일 경로는 싣지 않는다 [4].
`wireshark_text2pcap_import`의 응답에는 `text2pcap`이 표준 오류에 적은 입력 파일과 출력 파일 경로가 `stderr`로 실렸다 [5].
이 응답은 모델에게 돌아갈 뿐 서버가 파일이나 DB에 남기지 않는다 [2].

`mergecap`은 pcapng 출력의 섹션 헤더에 운영체제와 `mergecap` 이름·버전을 적는다 [5].
Wireshark 4.0.17의 `mergecap`은 첫 입력 파일에 섹션 주석이 있을 때만 그 주석 뒤에 입력 파일 이름 목록을 붙여 출력의 섹션 주석으로 쓴다 [6].
섹션 주석이 없는 pcap 두 개를 합친 출력에는 입력 파일 이름이 없었고 섹션 주석이 있는 pcapng를 앞에 두고 합친 출력에는 두 입력 파일의 경로가 있었다 [5].
이 주석은 `mergecap`이 쓰는 것이고 서버 코드는 이 값을 만들거나 읽지 않으며 MCP 호출과 잇는 값도 없다 [1].

같은 저장소의 skill 스크립트가 남기는 기록은 서버 구현으로 보지 않고 사실로 적는다.
`skills/tshark-cli-analysis/scripts/run_tshark.py`는 모델이 MCP를 거치지 않고 `tshark`를 직접 실행할 때 쓰는 스크립트다 [7].
이 스크립트는 새로 만든 출력 폴더에 `tshark`의 표준 출력과 표준 오류를 파일로 쓴다 [7].
같은 폴더의 `execution.json`에는 입력 캡처 파일의 실제 경로·SHA-256·크기, 실행한 명령, 두 출력 파일의 SHA-256이 들어간다 [7].
이 기록에는 MCP 도구 호출과 잇는 값이 없다 [7].
