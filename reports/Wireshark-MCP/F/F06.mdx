# F06 보고 산출물 구성

### 비적용

**판단.** 서버에는 사건 단위가 없고 보고 산출물을 만들거나 내보내는 도구도 없다.
도구 52개의 인자에는 사건이나 조사 세션을 가리키는 식별자가 없고 서버도 그런 식별자를 만들지 않는다 [1].
서버는 호출 사이에 발견사항이나 호출 기록을 모아 두지 않는다 [2].

파일을 쓰는 도구는 캡처 파일을 자르거나 나누거나 합치거나 거르거나 가져오는 도구, 객체와 프레임을 내보내는 도구, 내보낸 객체를 검사하는 `wireshark_yara_scan`, 실시간 캡처 도구다 [3].
이 도구들은 증거에서 얻은 패킷이나 객체를 쓰고 조사의 범위, 방법, 결과, 한계, 판단의 확정 상태를 싣지 않는다 [3].
`wireshark_quick_analysis`는 파일 정보, 프로토콜, 상위 통신 상대, 대화, 호스트 이름, 이상 요약을 4000자 안의 글로 응답에만 돌려주고 파일을 쓰지 않는다 [4].

MCP 프롬프트 `security_audit`와 `incident_response`는 모델에게 Markdown 보안 보고서와 사고 보고서를 쓰라고 적는다 [5].
README의 빠른 시작 예시도 모델에게 발견사항을 `report.md`에 쓰라고 적는다 [6].
같은 저장소의 skill 문서 `report-template.md`는 보고와 인계에 쓸 항목을 적는다 [7].
이 보고서는 클라이언트 모델이 안내문에 따라 직접 쓰는 글이다.
같은 저장소에는 서버 응답을 정해진 코드로 가공해 보고 산출물을 만드는 사용자 CLI나 클라이언트 코드가 없다.
사용자 CLI의 `install`, `update`, `uninstall`, `config`, `doctor`, `clients`는 MCP 클라이언트 설정과 실행 환경 점검만 다룬다 [8].
