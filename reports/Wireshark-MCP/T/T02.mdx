# T02 실행 허용 범위 제한

### T02.04 고정 명령·템플릿

**구현.** 이 방식은 서버가 Wireshark 도구를 실행하는 모든 경로에 적용된다 [1].
실행기는 결과를 한 번에 읽는 `_run_command`와 필드 행을 흘려 읽는 `_stream_field_rows`이고 둘 다 `asyncio.create_subprocess_exec`에 인자 배열을 넘겨 셸을 거치지 않는다 [1].
두 실행기는 실행 전에 배열 첫 항목의 파일 이름을 `tshark`·`capinfos`·`mergecap`·`editcap`·`dumpcap`·`text2pcap`과 각각에 `.exe`를 붙인 이름의 목록과 대조하고 목록 밖이면 `SecurityError`로 거부한다 [2].
배열 첫 항목은 서버가 시작할 때 찾아 둔 도구 경로이고 모델 인자에서 오지 않는다 [3].

도구마다 클라이언트 메서드가 옵션 배열을 코드에 정해 두고 모델 값은 정한 자리에만 넣는다 [4].
`wireshark_stats_protocol_hierarchy`는 `-r <캡처 파일> -q -z io,phs`를 넘기고 모델은 캡처 파일만 정한다 [4].
`wireshark_get_packet_list`는 필드 7개와 출력 꼴 옵션을 정해 두고 모델 값은 캡처 파일, 표시 필터, 열 이름 자리에 들어간다 [4].
탐지·분석 도구는 표시 필터와 필드 목록을 코드에 정해 두고 모델은 캡처 파일과 문턱값, 건수만 정한다 [5].
`wireshark_detect_port_scan`이 SYN 패킷을 찾는 필터와 필드 4개가 그 예다 [5].

표시 필터 안에 모델 문자열을 넣는 처리는 도구와 모드마다 다르다.

- `wireshark_search_packets`의 `bytes` 범위는 `hex`가 아닌 검색어의 `\`와 `"`를 이스케이프해 따옴표 안에 넣고 `details` 범위는 `regex`가 아닌 검색어를 `re.escape`로 바꿔 넣는다 [6].
- `wireshark_search_packets`의 `bytes` 범위 `hex` 검색, `details` 범위 `regex` 검색, `filter` 범위는 받은 문자열을 그대로 필터에 넣는다 [6].
- `wireshark_stats_io_graph`의 `filters`는 항목마다 큰따옴표로 감싸 `io,stat` 통계 인자에 이어 붙이고 항목 안의 따옴표는 바꾸지 않는다 [7].

정한 자리에 들어가지만 tshark의 동작을 정하는 값은 내용을 보지 않고 넘긴다 [8].
`wireshark_set_protocol_prefs`의 `prefs` 항목은 `-o` 값으로, `wireshark_decode_as`의 `decode_rules` 항목은 `-d` 값으로 넘긴다 [8].
표시 필터와 필드 이름도 구조를 검사하지 않고 tshark의 `-Y`·`-e` 값으로 넘긴다 [9].

**한계.** 캡처 파일 경로를 위치 인자로 받는 `capinfos`·`editcap`·`mergecap`·`text2pcap` 실행 배열에는 옵션의 끝을 알리는 표시가 없다 [10].
경로 검사는 `-`로 시작하는 경로를 거부하지 않는다 [11].
서버 작업 위치에 `-`로 시작하는 이름의 캡처 파일을 두고 그 이름을 상대 경로로 `wireshark_get_file_info`에 주자 `capinfos`가 그 이름을 옵션으로 읽어 사용법 안내를 출력했고 서버는 성공 응답을 돌려줬다 [12].

도구 버전을 묻는 `check_capabilities`는 실행기를 거치지 않고 `asyncio.create_subprocess_exec`로 각 도구 경로를 `-v`와 함께 바로 실행한다 [13].
그래서 이 실행에는 실행 파일 이름 대조가 적용되지 않는다 [13].

### T02.05 연산·플러그인 허용 목록

**구현.** 이 방식은 모델이 분석 종류, 통계 종류, 프로토콜, 흐름 종류를 고르는 인자에 적용된다 [14][15].
`wireshark_analyze_protocol`의 `protocol`은 값 25개를 `Literal`로 적는다 [16].
처리 함수는 그 값으로 서버 코드의 처리기 `dict`를 찾고 없으면 `ValueError` 오류를 돌려준다 [14].
처리기마다 표시 필터와 필드 목록이 정해져 있다 [14].
`wireshark_search_packets`의 `search_type`·`scope`와 `wireshark_aggregate`의 `sort_by`도 `Literal` 목록이다 [16].
`Literal` 목록 때문에 MCP 호출에서는 목록 밖의 값이 처리 함수에 닿기 전에 SDK 검사에서 거부된다 [16][17].

`wireshark_stats_endpoints`·`wireshark_stats_conversations`의 `type`은 7개, `wireshark_follow_stream`의 `protocol`은 5개, `wireshark_export_objects`·`wireshark_yara_scan`의 `protocol`은 5개 값의 목록과 대조한다 [15].
대조는 받은 값을 소문자로 바꿔서 하고 목록 밖이면 허용 값을 함께 적은 `InvalidParameter` 오류를 돌려준다 [15].
`wireshark_flow_graph`의 `flow_type`은 받은 값을 그대로 4개 값과 대조하고 목록 밖이면 오류 종류 없이 문구를 돌려준다 [18].
목록 밖의 `type`, 스트림 `protocol`, 객체 `protocol`, `flow_type`을 주자 tshark를 실행하지 않고 거부되었다 [17].

`wireshark_stats_service_response_time`의 `protocol`은 목록 없이 `-z <protocol>,tree`로 넘긴다 [19].
그래서 tshark가 아는 통계 이름 가운데 `,tree`로 끝나는 것이면 무엇이든 실행된다 [19].
`wireshark_follow_stream`의 `output_mode`도 목록 없이 `-z follow` 인자에 넣는다 [20].
목록에 없는 통계 이름과 표시 방식을 주자 tshark가 오류로 끝나고 그 오류 문구가 돌아왔다 [17].

**한계.** 목록 대조는 소문자로 바꾼 값으로 하지만 tshark에는 받은 값을 그대로 넘긴다 [15][21].
대문자로 적은 `type`과 스트림 `protocol`은 대조를 통과한 뒤 tshark가 `-z` 인자 오류로 거부했다 [22].

### T02.08 설정으로 도구 끄기

**구현.** 이 방식은 시작 인자 `--profile`과 환경변수 `WIRESHARK_MCP_ALLOWED_DIRS`에 적용된다 [23][24].
`--profile`은 `full`·`analysis`·`core` 가운데 하나를 받고 기본값은 `full`이다 [23].
`analysis`는 실시간 캡처와 인터페이스 목록 도구 2개, 파일을 쓰는 도구 10개를 등록하지 않는다 [25].
`core`는 여기에 복호화, 해석 설정 변경, 저수준 보기 도구 8개를 더 등록하지 않는다 [25].
뺄 도구 이름은 `profiles.py`의 고정 집합이다 [25].
`WiresharkMCP.add_tool`은 이 집합에 있는 이름을 도구 관리자에 넘기지 않으므로 그 도구는 목록에 없고 부를 수도 없다 [26].
세 프로필의 도구 목록은 52개, 40개, 32개였고 `analysis` 서버에 뺀 도구를 부르자 `Unknown tool` 오류가 돌아왔다 [27].
저장소 `Dockerfile`의 기본 실행 인자는 `--profile analysis`다 [28].

파일 쓰기는 `WIRESHARK_MCP_ALLOWED_DIRS`가 없으면 꺼진다 [29].
출력 경로 검사 `_validate_output_path`와 임시 폴더를 만드는 `_create_temporary_output_dir`은 이 값이 없으면 `PermissionDenied`로 거부한다 [29].
그래서 `full` 프로필에서 이 값이 없으면 파일을 쓰는 도구 11개는 목록에 남지만 부르면 외부 도구를 실행하지 않고 오류를 돌려준다 [29][25].
이 값 없이 `wireshark_editcap_trim`과 `wireshark_yara_scan`을 부르자 쓰기가 꺼져 있다는 `PermissionDenied`가 돌아왔다 [27].

**한계.** `analysis` 프로필과 쓰기가 꺼진 상태에서도 `wireshark_set_protocol_prefs`는 남는다 [25].
이 도구는 `prefs` 항목을 내용을 보지 않고 tshark의 `-o` 값으로 넘긴다 [8].
Wireshark 4.0.17의 `tshark`에는 출력 파일 경로를 값으로 받는 해석 설정이 있다 [30].
`WIRESHARK_MCP_ALLOWED_DIRS` 없이 `analysis` 프로필로 실행한 서버에서 이 설정에 다른 폴더의 파일 경로를 넣어 부르자 tshark가 그 경로에 파일을 만들었다 [30].
README는 `analysis` 프로필이 파일을 쓰는 도구를 모두 뺀다고 적는다 [31].

    return _EXCLUSIONS.get(profile, frozenset())
