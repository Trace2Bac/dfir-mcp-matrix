# T09 대상 시스템 대응 조치 처리

### 비적용

**판단.** 서버는 조사하는 대상 시스템에 접속하거나 그 상태를 바꾸는 도구를 두지 않는다.
실행기는 실행 파일 이름이 Wireshark 도구 6개 가운데 하나일 때만 실행한다 [1].
분석 도구는 인자로 받은 캡처 파일을 `tshark`, `capinfos`, `editcap`, `mergecap`, `text2pcap`으로 읽거나 새 캡처 파일과 내보낸 객체를 허용된 폴더에 쓴다 [2][3].
`wireshark_capture`와 `wireshark_list_interfaces`는 서버가 실행되는 호스트의 인터페이스를 `dumpcap`이나 `tshark`로 나열하고 그 인터페이스의 패킷을 파일로 받는다 [4].
서버가 캡처에 주는 인자는 인터페이스, 출력 파일, 캡처 필터, 시간·개수·크기 상한, 링 버퍼뿐이고 통신 상대에게 패킷을 보내는 인자는 없다 [4].
캡처하는 동안 인터페이스를 promiscuous 모드로 여는 것은 Wireshark 4.0.17 캡처 설정의 기본값이고 서버는 이 값을 바꾸는 `-p` 인자를 주지 않는다 [4][5].
서버 코드가 여는 연결은 SSE나 Streamable HTTP 전송을 고를 때 MCP 클라이언트의 요청을 받는 HTTP 서버뿐이다 [6].
`wireshark_filter_save`와 편집 도구가 쓰는 파일은 서버 자신의 작업 파일이다 [2].
사용자 CLI의 `install`, `update`, `uninstall`은 이 호스트의 MCP 클라이언트 설정 파일을 고치지만 조사 대상 시스템을 바꾸지 않는다 [7].
그래서 조치 전후 상태, 변경 내역, 되돌림을 남길 대상 시스템 조치가 없다.

    async def export_objects(self, pcap_file: str, protocol: str, dest_dir: str) -> str:
        """Export Objects (--export-objects protocol,dest_dir)."""
        validation = self._validate_file(pcap_file)
        if not validation["success"]:
            return json.dumps(validation)

        proto_validation = self._validate_protocol(protocol, self.VALID_EXPORT_PROTOCOLS)
        if not proto_validation["success"]:
            return json.dumps(proto_validation)

        output_validation = self._validate_output_path(dest_dir)
        if not output_validation["success"]:
            return json.dumps(output_validation)

        os.makedirs(dest_dir, exist_ok=True)
        cmd = [
            self.tshark_path,
            "-r",
            pcap_file,
            "--export-objects",
            f"{protocol},{dest_dir}",
        ]
        return await self._run_command(cmd)
