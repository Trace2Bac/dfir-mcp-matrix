# T03 실행 조건 확인

### 미구현

**판단.** 서버에는 앞선 작업 상태, 모델 밖 승인, 원격 호출자 신원, 실행 자원으로 호출을 막거나 미루는 코드가 없다.
`WiresharkMCP.call_tool`은 SDK의 `call_tool`로 도구를 부른 뒤 응답 크기만 줄이고 그 앞에서 조건을 보지 않는다 [1].
도구 함수는 인자와 경로 검사를 마치면 바로 Wireshark 도구를 실행한다 [2].
서버 지침은 `wireshark_open_file`로 시작하라고 안내하고 사용 안내 리소스는 이 도구가 권장일 뿐 필수가 아니라고 적는다 [3].
다른 도구는 앞서 `wireshark_open_file`을 불렀는지 보지 않는다 [2].
도구 annotation은 파일을 쓰는 도구 11개에 `readOnlyHint` 거짓과 `destructiveHint` 참을 붙이지만 서버는 이 값으로 호출을 막지 않는다 [4].
파일 쓰기가 꺼지는 것은 서버가 시작할 때 읽는 환경변수 `WIRESHARK_MCP_ALLOWED_DIRS`에 따른 것이고 호출마다 받는 승인이 아니다 [5].

SSE와 Streamable HTTP 전송은 호출자를 확인하지 않는다 [6].
서버는 `WiresharkMCP`를 만들 때 MCP SDK의 인증 설정을 넘기지 않는다 [6].
컨테이너 안에서 `127.0.0.1`에 연 Streamable HTTP 서버에 자격증명 없이 접속하자 도구 52개 목록과 도구 호출 결과가 돌아왔다 [7].
`main`은 SSE나 Streamable HTTP를 루프백이 아닌 주소에 열려고 할 때 `--allow-insecure-http`가 없으면 시작하지 않고 오류로 끝난다 [8].
이 인자가 있으면 경고 기록을 남기고 그 주소에 연다 [8].
`0.0.0.0`과 루프백이 아닌 다른 주소로 시작하자 두 전송 모두 종료 코드 2로 끝났다 [7].
`--allow-insecure-http`로 루프백 밖에 연 실행은 확인하지 않았다 [7].
저장소 `Dockerfile`의 기본 실행 인자는 Streamable HTTP를 `0.0.0.0`에 `--allow-insecure-http`와 함께 연다 [9].
MCP Python SDK 2.1.1은 바인드 주소가 `127.0.0.1`·`localhost`·`::1`일 때만 Host·Origin 헤더 검사를 켠다 [10].
서버의 루프백 판정은 `127.0.0.0/8`의 다른 주소도 루프백으로 보므로 그런 주소에 열면 플래그 없이 시작되고 이 헤더 검사는 켜지지 않는다 [8][10].
stdio 전송은 원격 연결을 받지 않는다.

서버는 실행 전에 메모리, CPU, 디스크 여유 공간을 확인하지 않는다.
`wireshark_capture`의 시간·패킷 수·파일 크기 상한과 하위 프로세스 출력 바이트 상한은 실행의 크기를 정하는 값이고 실행 자원의 상태를 보지 않는다 [11].

동시 실행 수를 정하는 장치도 없다.
도구 함수는 `async` 함수이고 Wireshark 도구를 `asyncio` 하위 프로세스로 실행하므로 여러 호출이 함께 진행된다 [12].
`wireshark_quick_analysis`, `wireshark_analyze_tcp_health`, `wireshark_scan_file_signatures`, `wireshark_detect_exfiltration`은 한 호출 안에서 tshark 실행 여러 개를 `asyncio.gather`로 함께 시작한다 [13].
tshark 경로에 시작과 끝 시각을 남기는 실행 파일을 두고 `wireshark_analyze_tcp_health`를 부르자 tshark 실행 8개가 동시에 진행되었다 [7].

        self,

    ) -> CallToolResult | InputRequiredResult:
        result = await super().call_tool(name, arguments, context)
        if isinstance(result, CallToolResult):
            # Check is_error on original content BEFORE capping
            is_error = bool(getattr(result, "is_error", False))

        return result

def annotations_for(tool_name: str) -> ToolAnnotations:
    """Build the annotation set for a tool.

    ``destructiveHint`` is left unset for read-only tools rather than set to
    ``False``: it would be redundant next to ``readOnlyHint`` and unset fields are
    dropped from the wire payload, which keeps the prompt prefix smaller.
    """
    writes = tool_name in WRITE_TOOLS
    return ToolAnnotations(
        read_only_hint=not writes,
        destructive_hint=True if writes else None,
        open_world_hint=tool_name in OPEN_WORLD_TOOLS,
    )
