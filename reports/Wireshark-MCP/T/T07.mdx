# T07 도구 부재 처리

### T07.01 실행 전 도구·참조 자료 가용성 검사

**구현.** 이 방식은 `capinfos`·`mergecap`·`editcap`·`text2pcap`을 실행하는 클라이언트 함수 8개, 실시간 캡처 도구 2개, `wireshark_yara_scan`, `wireshark_geoip_enrich`에 적용된다 [1][2][3][4].
서버는 클라이언트를 만들 때 Wireshark 도구 6개의 경로를 한 번 정해 둔다 [5].
`_tool_is_available`은 그 경로가 파일로 있거나 `PATH`에서 찾히면 도구가 있다고 본다 [6].
클라이언트 함수 8개는 실행 전에 `_require_tool`로 도구를 확인하고 없으면 실행하지 않고 오류를 돌려준다 [1][2].
`wireshark_get_file_info`가 부르는 `get_file_info`는 입력 파일을 먼저 검사한 뒤 `capinfos`를 확인한다 [1].
`wireshark_list_interfaces`와 `wireshark_capture`는 실행 파일을 고른 뒤 `_get_checked_tool_path`로 그 파일이 있는지 다시 확인한다 [3].

`wireshark_yara_scan`은 모듈을 불러올 때 `yara`를 불러올 수 있었는지 `_YARA_AVAILABLE`에 두고 호출마다 이 값을 먼저 확인한다 [4].
그다음 패키지에 들어 있는 `basic_rules.yar`와 사용자 폴더 `~/.wireshark-mcp/yara/`의 룰 파일을 읽어 컴파일하고 컴파일한 룰이 없으면 실행하지 않는다 [7][4].
`wireshark_geoip_enrich`는 `geoip2`를 불러올 수 있었는지 확인한 뒤 GeoLite2 데이터베이스 파일을 정해 둔 위치에서 찾고 찾지 못하면 실행하지 않는다 [8][9].
`pyproject.toml`은 `yara-python`과 `geoip2`를 선택 의존성으로 두고 저장소의 `Dockerfile`은 선택 의존성 없이 패키지를 설치한다 [10][11].
실행 확인에서 `capinfos`와 `editcap`의 경로 환경변수를 없는 파일로 주자 `wireshark_get_file_info`와 `wireshark_editcap_trim`은 실행하지 않고 오류를 돌려주었다 [12].
`yara`와 `geoip2`를 불러오지 못하게 한 프로세스와 데이터베이스가 없는 컨테이너에서도 두 도구는 분석을 실행하지 않았다 [12].

`tshark`를 실행하는 도구에는 이 확인이 없다 [13].
`tshark`는 `requirement`가 `required`인 도구이지만 서버의 도구 대부분이 `_require_tool` 없이 `tshark`를 실행한다 [14][13].
실행 파일이 없으면 하위 프로세스를 시작하는 단계에서 실패한다 [15].

**한계.** `_tool_is_available`은 경로에 파일이 있는지만 보고 실행할 수 있는 파일인지는 보지 않는다 [6].

### T07.02 대체 없는 실패 처리·도구 부재 알림

**구현.** 이 방식은 앞의 확인이 적용되는 도구에 적용된다 [2][4][9].
`_require_tool`은 `ToolNotFound` 오류에 도구 이름 `tool`, 필요 수준 `requirement`, 경로를 정하는 환경변수 이름 `env_var`를 싣는다 [2].
`wireshark_yara_scan`은 `yara-python`이 없으면 `DependencyMissing` 오류에 설치 명령을, 룰이 없으면 `ConfigurationError` 오류에 룰을 둘 폴더를 싣는다 [4].
`wireshark_geoip_enrich`는 `geoip2`가 없으면 `DependencyMissing` 오류에 설치 명령을, 데이터베이스가 없으면 `DatabaseMissing` 오류에 둘 위치, 환경변수 `GEOIP_DB_PATH`, 내려받을 주소를 싣는다 [9].
실행 확인에서 네 오류 종류가 모두 응답에 실렸고 `ToolNotFound`의 `details`에는 `WIRESHARK_MCP_CAPINFOS_PATH`와 `WIRESHARK_MCP_EDITCAP_PATH`가 실렸다 [12].

`tshark`가 없을 때는 도구가 없다는 사실을 따로 구분하지 않는다 [15].
실행기는 하위 프로세스를 시작하다 난 예외를 `ExecutionError`와 `Command execution failed`로 돌려주고 OS 오류 문구를 `details`에 싣는다 [15][16].
실행 확인에서 `tshark` 경로를 없는 파일로 주자 `wireshark_get_packet_list`와 `wireshark_aggregate`는 이 오류를 돌려주었다 [12].
같은 실행에서 `wireshark_quick_analysis`는 성공 응답을 돌려주고 `tshark`로 채우는 다섯 절에 `No protocol data available` 같은 빈 결과 문구를 실었다 [12][17].

**한계.** `dumpcap`과 `tshark`가 모두 없으면 `_get_checked_tool_path`가 낸 `RuntimeError`를 캡처 도구가 처리하지 않는다 [3].
실행 확인에서 두 경로를 모두 없는 파일로 주자 MCP 세션의 `wireshark_list_interfaces` 응답은 `isError`가 참인 `Error executing tool wireshark_list_interfaces` 한 줄이었다 [12].
GeoLite2 데이터베이스 파일이 있지만 열지 못하면 `_get_reader`가 낸 예외를 `wireshark_geoip_enrich`가 처리하지 않는다 [18].
데이터베이스 파일이 없어 이 경로는 실행하지 않았다.

YARA 룰 컴파일이 실패해도 `No YARA rules available` 오류를 돌려준다 [7][4].
실행 확인에서 사용자 폴더에 문법 오류가 있는 룰 파일 하나를 두자 패키지에 들어 있는 룰도 쓰이지 않고 이 오류가 왔다 [12].

### T07.03 알림 없는 대체 실행

**구현.** 이 방식은 실시간 캡처 도구 2개의 실행 파일 선택, `wireshark_analyze_protocol`의 `dhcp`·`grpc`, `wireshark_geoip_enrich`의 데이터베이스 선택에 적용된다 [19][20][21][22].
`_select_capture_backend`는 `dumpcap`이 없으면 `tshark`를 고른다 [19].
`wireshark_list_interfaces`와 `wireshark_capture`의 응답은 어느 실행 파일을 썼는지 싣지 않는다 [3][23].
고른 실행 파일의 이름은 `wireshark_get_capabilities`와 리소스 `wireshark://capabilities`의 `_meta.capture_backend`에만 실린다 [24].
실행 확인에서 `dumpcap` 경로를 없는 파일로 주자 `wireshark_list_interfaces`는 `tshark -D`의 결과를 돌려주었고 목록은 extcap 인터페이스까지 14개로 `dumpcap`의 7개와 달랐다 [12].

`dhcp`는 `dhcp.*` 필드로 `tshark`를 실행하고 그 실행이 어떤 이유로든 실패하면 옛 이름 `bootp.*` 필드로 다시 실행한다 [20].
응답에는 다시 실행했다는 사실이 없고 TSV 머리 줄의 필드 이름으로만 짐작할 수 있다 [20].

`grpc`는 gRPC 필드 추출이 실패하면 HTTP/2 머리 필드로 다시 추출한다 [21].
응답에는 다시 추출했다는 사실이 없고 머리 문구가 `gRPC over HTTP/2:`로 달라지는 것으로만 짐작할 수 있다 [21].
다시 추출이 성공하는 입력은 만들지 못해 이 경로는 실행하지 않았다.

환경변수 `GEOIP_DB_PATH`의 파일이 없으면 `_find_geoip_db`는 알리지 않고 다음 후보 위치의 데이터베이스를 쓴다 [22].
응답은 어느 데이터베이스 파일을 읽었는지 싣지 않는다 [25].

**한계.** `dhcp`가 다시 실행해 실패하면 응답은 처음 실행의 오류가 아니라 다시 실행한 쪽의 오류를 싣는다 [20].
Wireshark 4.0.17의 `tshark`는 `-e`의 필드 이름을 등록된 이름으로만 찾으므로 `bootp.*` 필드를 받지 않는다 [26].
Wireshark 4.6.7의 `tshark`는 `-e`의 필드 이름을 표시 필터로 컴파일해 검사하므로 별칭 `bootp`의 필드를 받는다 [27].
실행 확인에서 캡처 파일이 아닌 입력으로 `dhcp`를 부르자 주 환경의 응답은 `Some fields aren't valid`와 `bootp.*` 필드 8개를 실었다 [12].
같은 입력으로 Windows에서 부르면 응답은 캡처 파일 형식이 아니라는 오류를 실었다 [28].

`grpc`는 다시 추출도 실패하면 처음 추출의 오류를 싣는다 [21].

### T07.04 실행 환경별 경로 분기

**구현.** 이 방식은 Wireshark 도구 6개의 경로, 실시간 캡처의 실행 파일, GeoLite2 데이터베이스 위치에 적용된다 [6][19][22].
`_resolve_tool_path`는 도구마다 `WIRESHARK_MCP_TSHARK_PATH` 같은 도구별 환경변수가 있으면 그 값을 그대로 쓰고 없으면 `PATH`에서 찾는다 [6][14].
`PATH`에서도 찾지 못하면 `tshark`는 이름 `tshark`를 그대로 두고 다른 도구는 경로를 비운다 [6][5].
환경변수가 가리키는 파일이 없어도 `PATH`로 바꾸지 않는다 [6].
실시간 캡처는 `WIRESHARK_CAPTURE_BACKEND_ORDER`의 차례대로 `dumpcap`, `tshark` 가운데 있는 첫 실행 파일을 쓴다 [14][19].
`_find_geoip_db`는 `GEOIP_DB_PATH`, `~/.wireshark-mcp/geoip/`의 `GeoLite2-City.mmdb`·`GeoLite2-Country.mmdb`·`GeoLite2-ASN.mmdb`, 시스템 폴더 3곳의 `GeoLite2-City.mmdb` 차례로 보고 처음 있는 파일을 쓴다 [22].

서버는 운영체제별 Wireshark 설치 폴더를 찾지 않는다 [6].
사용자 CLI의 `install`과 `doctor`는 환경변수, `PATH`, 운영체제별 설치 폴더 차례로 도구를 찾고 `install`은 찾은 경로를 클라이언트 설정의 서버 환경변수로 적는다 [29].
실행 확인에서 Wireshark가 `C:\Program Files\Wireshark`에 있고 `PATH`에 없는 Windows에서 환경변수 없이 서버를 실행하자 도구 6개가 모두 `available` 거짓이었다 [28].

**한계.** 데이터베이스 후보에는 Country와 ASN 데이터베이스가 있지만 `wireshark_geoip_enrich`는 늘 `city`로 조회한다 [22][9].
`geoip2` 5.3.0의 `Reader`는 데이터베이스 종류가 City가 아니면 `city` 조회에 `TypeError`를 낸다 [30].
도구는 IP마다 모든 예외를 처리해 칸을 `—`로 채우고 그 IP를 처리한 건수에 넣는다 [9].
그래서 Country나 ASN 데이터베이스가 먼저 골라지면 응답은 모든 IP를 처리했다고 적고 값은 비어 있다.
실행 확인 환경에는 데이터베이스 파일이 없어 이 경우는 실행하지 않았다.

### T07.08 일부 제외 후 계속 실행

**구현.** 이 방식은 `wireshark_open_file`, `wireshark_quick_analysis`, `wireshark_yara_scan`의 룰 읽기, `wireshark_extract_fingerprints`의 사용자 목록 읽기에 적용된다 [31][17][7][32].
`wireshark_open_file`은 `capinfos` 결과를 얻지 못하면 `Detailed file metadata unavailable (capinfos not installed or file summary failed).`를 싣고 프로토콜 계층과 추천 도구를 계속 만든다 [31].
`wireshark_quick_analysis`는 실행 7개를 따로 실행하고 실패한 실행의 절에는 `Could not read file info`나 `No … data available`을 싣고 나머지 절을 채운다 [17].
실행 확인에서 `capinfos` 경로를 없는 파일로 주자 두 도구는 파일 정보만 빼고 나머지를 돌려주었다 [12].

YARA 룰은 패키지 룰이나 사용자 룰 파일 하나를 읽지 못하면 그 파일만 빼고 나머지를 컴파일한다 [7].
`wireshark_extract_fingerprints`는 `~/.wireshark-mcp/fingerprints/`의 JSON 파일 하나를 읽지 못하면 그 파일만 빼고 나머지 항목과 대조한다 [32].
실행 확인에서 읽을 수 없는 사용자 룰 파일을 두자 `wireshark_yara_scan`은 성공 응답을 돌려주었다 [12].
JSON이 아닌 목록 파일과 항목 1개짜리 목록 파일을 함께 두자 `wireshark_extract_fingerprints`는 `No matches in your fingerprint list (1 entries)`를 돌려주었다 [12].

**한계.** 읽지 못해 뺀 YARA 룰 파일과 JA3 목록 파일은 응답에 남지 않는다.
읽지 못한 룰 파일과 목록 파일은 서버 로그에만 적힌다 [7][32].
`wireshark_quick_analysis`의 절 문구는 도구가 없는 경우, 실행이 실패한 경우, 결과가 빈 경우를 구별하지 않는다 [17].
`wireshark_open_file`의 문구도 `capinfos`가 없는 경우와 실행이 실패한 경우를 한 문장으로 적는다 [31].
