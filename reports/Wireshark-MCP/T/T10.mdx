# T10 도구 명세 구성

### T10.01 처리 함수에서 명세 생성

**구현.** 이 방식은 서버가 등록하는 도구 52개 모두에 적용된다 [1][2].
도구 함수에는 `@mcp.tool()`을 붙이거나 `ToolRegistry.register`가 `add_tool(fn, name=name)`으로 등록하고 설명과 입력 schema를 따로 주지 않는다 [1][2].
MCP Python SDK 2.1.1의 `Tool.from_function`은 이름을 받지 않으면 함수 이름을, 설명을 받지 않으면 docstring을 쓰고 함수 서명에서 입력 schema를 만든다 [3].
두 등록 경로는 모두 `MCPServer`를 이어받은 `WiresharkMCP.add_tool`을 거친다 [4].
`WiresharkMCP.add_tool`은 `structured_output`을 따로 받지 않으면 거짓으로 두어 출력 schema를 만들지 않는다 [4].
같은 함수는 SDK가 만든 입력 schema에서 `title` 키를 모두 지운다 [4][5].
`ToolRegistry.register`는 도구 함수를 이름 차례로 등록하고 등록 중 예외가 나면 서버 로그에 적고 그 도구를 건너뛴다 [2].

실행 확인에서 도구 목록의 도구 52개는 모두 docstring 한 줄을 설명으로 실었고 출력 schema와 `title`이 있는 도구는 없었다 [6].
입력 schema는 인자마다 자료형과 기본값만 싣고 인자의 뜻을 적은 글은 싣지 않는다 [6].
서버 코드가 `Literal`로 적은 인자는 `enum`으로 실렸다 [6].
`wireshark_analyze_protocol`의 `protocol`은 25개 값, `wireshark_aggregate`의 `sort_by`는 7개 값, `wireshark_search_packets`의 `search_type`과 `scope`는 3개 값이다 [6][7].
정해 둔 값만 받는 다른 인자는 schema에 문자열로 실리고 허용 값은 설명 글에만 있다 [6].
`wireshark_stats_endpoints`·`wireshark_stats_conversations`의 `type`, `wireshark_follow_stream`의 `protocol`·`output_mode`, `wireshark_export_objects`·`wireshark_yara_scan`의 `protocol`, `wireshark_flow_graph`의 `flow_type`이 그 인자다 [6].
초기화 응답의 `tools.listChanged`는 거짓이었다 [6].

서버는 `MCPServer`를 만들 때 서버 지침 `instructions`를 준다 [8].
지침은 `wireshark_open_file`로 시작하고 전체 건수와 분포에는 `wireshark_aggregate`를 쓰라고 적는다 [8].
서버는 리소스 4개와 프롬프트 6개도 등록한다 [9][10].
리소스는 표시 필터 문법, 프로토콜 필드 이름, 사용 안내, 도구 가용성 표를 돌려준다 [9].
프롬프트는 캡처 파일 경로를 받아 조사 단계마다 부를 도구 이름을 적은 글을 돌려준다 [10].

**한계.** 다음 도구는 설명이나 지침이 알리는 것과 처리 코드의 동작이 다르다.

`wireshark_stats_service_response_time`의 설명은 `protocol` 값의 예로 `'http'|'dns'|'smb'`를 적는다 [11].
처리 코드는 `-z <protocol>,tree`를 실행하고 Wireshark 4.0.17과 4.6.7의 `tshark`에는 `smb,tree` 통계가 없다 [11][12].
실행 확인에서 `smb`를 주자 `Invalid -z argument "smb,tree"` 오류가 왔다 [12].
`wireshark_yara_scan`의 설명은 `protocol: http|smb|tftp`를 적지만 처리 코드는 `imf`와 `dicom`도 받는다 [13].
`wireshark_flow_graph`의 설명은 `'any', 'tcp', 'icmp'`를 적지만 처리 코드는 `icmpv6`도 받는다 [14].
실행 확인에서 `icmpv6`를 주자 성공 응답이 왔다 [12].
서버 지침은 `wireshark_aggregate`가 필터 전체를 자동으로 훑는다고 적는다 [8].
`wireshark_aggregate`는 맞는 패킷이 기본 1,000,000행을 넘거나 기본 30초가 지나면 집계 대신 오류를 돌려주고 두 값은 환경변수로 바뀐다 [15].
실행 확인에서 150만 패킷 캡처를 집계하자 `LimitExceeded` 오류가 왔다 [12].

### T10.03 묶음 도구의 연산별 인자를 schema가 구분하지 않음

**구현.** 이 방식은 `wireshark_analyze_protocol`과 `wireshark_search_packets`에 적용된다 [7][16].
`wireshark_analyze_protocol`은 `protocol` 값으로 처리기 25개 가운데 하나를 골라 `pcap_file`과 `limit`을 넘긴다 [16].
입력 schema는 `protocol`을 25개 값의 `enum`으로, `limit`을 기본값 100인 정수 하나로 알린다 [6].
처리기마다 `limit`을 쓰는 방식이 다르다 [16].
`rtp`와 `smb`는 `limit`을 받기만 하고 쓰지 않는다 [16].
설명은 `Returns a summary and bounded rows`라고 적고 어느 값이 `limit`을 쓰지 않는지 적지 않는다 [16].
처리기 25개는 `tshark`에 줄 필드 목록과 필터를 처리기 안에 따로 두고 schema에는 이 내용이 없다 [17].

`wireshark_search_packets`는 `scope`로 `match_pattern`을 쓰는 방식을 고른다 [7].
`bytes`이면 `search_type`이 `hex`일 때만 바이트 열로, 나머지는 문자열로 찾는다 [7].
`details`이면 `search_type`이 `regex`일 때만 정규식으로, 나머지는 글자 그대로 찾는다 [7].
`filter`이면 `match_pattern`을 표시 필터로 그대로 쓰고 `search_type`을 쓰지 않는다 [7].
입력 schema는 두 인자를 각각 3개 값의 `enum`으로만 알리고 설명은 `[Search] Find packets by content.` 한 줄이다 [6].

### T10.04 실행 설정·클라이언트별 명세 변경

**구현.** 이 방식은 프롬프트 `incident_response`에 적용된다 [18].
사용자는 서버를 시작할 때 `--profile`로 `full`, `analysis`, `core` 가운데 하나를 고른다 [19].
`_build_server`는 프로필이 `full`일 때만 `register_prompts`에 `write_tools_enabled`를 참으로 넘긴다 [19][18].
`incident_response`는 이 값이 거짓이면 `wireshark_export_objects`로 파일을 꺼내라는 줄을 `Object export is disabled by the selected read-only profile; record candidate streams for later extraction.`로 바꾼다 [18].
실행 확인에서 세 프로필의 명세를 비교하자 다른 것은 `incident_response`의 이 한 줄뿐이었다 [20].
서버 지침, 리소스 4개, 나머지 프롬프트 5개, 두 프로필에 함께 있는 도구의 이름·설명·schema·annotation은 같았다 [20].
클라이언트 종류에 따라 명세를 바꾸는 코드는 없다.

### T10.06 도구 annotation 표시

**구현.** 이 방식은 서버가 등록하는 도구 52개 모두에 적용된다 [4][21].
`WiresharkMCP.add_tool`은 등록하는 쪽이 annotation을 주지 않으면 `annotations_for`가 도구 이름으로 만든 annotation을 붙인다 [4].
`annotations_for`는 `WRITE_TOOLS`에 있는 도구 11개에 `readOnlyHint` 거짓과 `destructiveHint` 참을, 나머지 도구에 `readOnlyHint` 참을 싣는다 [21].
`openWorldHint`는 `wireshark_capture`만 참이고 나머지는 거짓이다 [21].
`WRITE_TOOLS`는 캡처, 편집, 병합, 변환, 필터 저장, 객체 내보내기, 프레임 추출 도구와 객체를 내보낸 뒤 검사하는 `wireshark_yara_scan`이다 [21].
실행 확인에서 `full` 프로필의 도구 52개 가운데 41개가 `readOnlyHint` 참, 11개가 `readOnlyHint` 거짓과 `destructiveHint` 참이었다 [6].
MCP Python SDK 2.1.1의 `ToolAnnotations`는 모든 속성을 힌트로 적고 서버는 annotation으로 호출을 막지 않는다 [22].

**한계.** `readOnlyHint`가 참인 도구도 파일을 만들거나 있는 파일을 덮어쓸 수 있다 [23][24].
`wireshark_set_protocol_prefs`는 받은 해석 설정을 값 검사 없이 `tshark -o`로 넘긴다 [23].
실행 확인에서 파일 경로를 값으로 받는 해석 설정을 이 도구에 주자 컨테이너 안의 지정한 경로에 파일이 생겼다 [24].
같은 설정 값으로 허용 폴더 안의 다른 캡처 파일 경로를 주자 호출은 성공했고 그 캡처 파일은 다른 내용으로 덮어쓰였다 [24].

```python
def strip_schema_titles(node: Any) -> Any:
    """Recursively drop ``title`` keys from a JSON Schema.

    Pydantic generates a title for the argument model and for every property;
    neither carries information the field name does not already give.
    """
    if isinstance(node, dict):
        return {key: strip_schema_titles(value) for key, value in node.items() if key != "title"}
    if isinstance(node, list):
        return [strip_schema_titles(item) for item in node]
    return node
```
