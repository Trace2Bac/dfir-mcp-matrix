# T01 입력 검증

### T01.01 인자 구조·값 검사

**구현.** 이 방식은 MCP SDK가 모든 도구에 하는 자료형 검사와 클라이언트 메서드·도구 함수가 일부 인자에 하는 값 검사에 적용된다 [1][2].
MCP Python SDK 2.1.1의 `MCPServer`는 도구 함수의 매개변수 형으로 만든 pydantic 모델로 인자를 검사한다 [1].
형이 맞지 않으면 도구 함수를 부르지 않고 `is_error`가 참인 응답을 돌려준다 [1].
`Literal`로 적은 `wireshark_analyze_protocol`의 `protocol`, `wireshark_search_packets`의 `search_type`·`scope`, `wireshark_aggregate`의 `sort_by`는 이 단계에서 목록 밖의 값이 거부된다 [3].
목록 밖의 `protocol`과 `scope`를 주자 pydantic 검사 오류가 돌아왔다 [4].
이 모델은 정의하지 않은 인자를 거부하지 않고 버린다 [1].
`wireshark_get_file_info`에 정의하지 않은 인자를 더해 부르자 그 인자 없이 실행되었다 [4].

서버 코드의 값 검사는 외부 도구를 실행하기 전에 클라이언트 메서드와 도구 함수가 한다 [2].
어긋나면 결과를 담는 JSON 꼴 `envelope`의 `success`를 거짓으로 두고 `InvalidParameter` 오류를 담아 돌려준다 [2].
`wireshark_flow_graph`의 `flow_type` 검사만 오류 종류 없이 문구를 돌려주므로 응답의 오류 종류는 `ToolError`가 된다 [5].
목록 밖의 `flow_type`을 주자 오류 종류가 `ToolError`인 응답이 돌아왔다 [6].
검사 기준은 모두 서버 코드의 상수이고 실행할 때 읽는 기준은 없다 [2].

- `wireshark_capture`는 `duration_seconds`를 0~300초, `packet_count`를 0~1,000,000개로 제한한다 [7].
- `wireshark_capture`의 `ring_buffer`는 `filesize`와 `files`를 모두 적어야 하고 파일 하나 102,400KiB, 파일 10개, 합계 102,400KiB를 넘으면 거부한다 [8].
- `ring_buffer`가 없으면 서버가 `-a filesize:102400`을 붙여 캡처 파일 하나의 크기를 정한다 [8].
- `wireshark_extract_frames`의 `frame_ranges`는 1 이상의 프레임 번호나 범위를 공백으로 나눠 1,000개까지 받고 범위의 끝이 시작보다 작으면 거부한다 [9].
- `wireshark_editcap_split`은 `packets_per_file`과 `seconds_per_file`이 모두 0 이하이면 거부한다 [10].
- `wireshark_aggregate`는 필드를 12개까지 받고 `top_k`는 1~200, `time_bucket_seconds`는 0이거나 0.000001초 이상의 유한한 수여야 한다 [11].
- `wireshark_aggregate`의 `sort_by`가 `numeric_`로 시작하면 `sort_numeric`은 합계·최솟값·최댓값·평균을 요청한 필드여야 한다 [11].
- `wireshark_decode_as`와 `wireshark_set_protocol_prefs`는 규칙이나 설정이 하나도 없으면 거부한다 [12].
- 통계 종류, 스트림·객체 프로토콜, 흐름 종류를 고르는 인자는 서버 코드의 값 목록과 대조해 목록 밖이면 거부한다 [13].

시간 300초를 넘는 캡처, `files`가 없는 `ring_buffer`, 합계를 넘는 `ring_buffer`, 0번 프레임과 거꾸로 된 범위, 나눌 기준이 없는 분할, `top_k` 0, 음수 시간 구간, 필드 13개, 요청하지 않은 `sort_numeric`을 주자 모두 외부 도구를 실행하지 않고 거부되었다 [4].

다른 인자는 꼴을 보지 않고 외부 도구의 옵션 값으로 넘긴다 [14].
`display_filter`, `fields`·`custom_columns`, `layers`, `decode_rules`·`prefs`의 각 항목, `interface`·`capture_filter`, `start_time`·`stop_time`, `encapsulation`·`timestamp_format`, `wireshark_follow_stream`의 `output_mode`, `wireshark_stats_service_response_time`의 `protocol`, `wireshark_decrypt_wpa`의 `wpa_passphrase`·`ssid`가 여기에 해당한다 [14][15].
건수와 간격을 정하는 정수 인자도 위에 적은 것 말고는 범위를 보지 않는다 [14].
`decrypt_wpa_traffic`의 키 목록 검사는 도구 함수가 늘 항목 하나를 넘기므로 빈 암호를 거르지 않는다 [15].
이런 값이 맞지 않으면 tshark가 0이 아닌 종료 코드로 끝나고 서버는 그 표준 오류를 오류 응답의 `details`에 담는다 [16].
잘못된 `output_mode`와 끝나지 않은 표시 필터를 주자 tshark의 오류 문구가 돌아왔다 [4].

### T01.02 입력 존재·읽기 가능 검사

**구현.** 이 방식은 캡처 파일, 키 로그 파일, 병합할 입력 파일, `text2pcap` 입력 파일을 받는 모든 클라이언트 메서드에 적용된다 [17].
메서드는 외부 도구를 부르기 전에 `_validate_file`로 경로를 검사한다 [17].
`_validate_file`은 빈 문자열을 `InvalidParameter`로, 없는 경로를 `FileNotFound`로, 일반 파일이 아닌 경로를 `InvalidParameter`로 거부한다 [18].
파일을 읽을 수 있는지는 확인하지 않는다 [18].
`wireshark_merge_pcaps`는 `input_files`의 경로마다 검사하고 하나라도 실패하면 `mergecap`을 부르지 않는다 [19].
없는 파일, 폴더, 빈 문자열을 주자 각각의 오류가 돌아왔다 [4].
`wireshark_capture`의 `interface`는 경로로 다루지 않아 이 검사를 하지 않는다 [7].

**한계.** 여러 하위 실행의 결과를 모아 응답을 만드는 도구 가운데 일부는 이 검사의 오류를 응답에 오류로 싣지 않는다 [20][21][22].
`wireshark_quick_analysis`는 하위 실행이 오류를 돌려주면 그 단계를 파일 정보를 읽지 못했다는 문구나 자료가 없다는 문구로 적고 성공 응답을 돌려준다 [20].
`wireshark_scan_file_signatures`는 실패한 검색을 0건으로 센다 [21].
`wireshark_analyze_tcp_health`는 실패한 점검을 `N/A (filter not applicable)`로 적는다 [22].
없는 파일을 세 도구에 주자 모두 `success`가 참인 응답이 돌아왔다 [4].
그 가운데 `wireshark_scan_file_signatures`의 응답은 파일 서명이 검출되지 않았다는 문구였다 [4].

### T01.03 실제 경로로 변환해 허용 폴더 대조

**구현.** 이 방식은 `_validate_file`을 거치는 모든 읽기 경로에 적용된다 [18].
허용 폴더는 사용자가 환경변수 `WIRESHARK_MCP_ALLOWED_DIRS`에 쉼표로 나눠 적는다 [23].
서버는 시작할 때 폴더마다 `Path.resolve`로 실제 경로로 변환하고 없는 폴더가 있으면 `ValueError`를 내고 시작하지 않는다 [24].
`_validate_file`은 받은 경로를 `Path.resolve`로 변환한 뒤 허용 폴더 아래에 있는지 `relative_to`로 대조한다 [18][25].
변환은 `..`와 심볼릭 링크를 해석하고 상대 경로는 서버의 작업 위치를 기준으로 한다 [18].
허용 폴더 밖이면 `PermissionDenied`로 거부하고 경로를 경고 기록에 남긴다 [18].
`wireshark_decrypt_tls`·`wireshark_verify_ssl_decryption`의 `keylog_file`과 `wireshark_merge_pcaps`의 입력 파일도 같은 대조를 거친다 [19][26].
허용 폴더 밖의 파일, 상위 폴더 표기로 밖을 가리키는 경로, 허용 폴더 안의 심볼릭 링크로 밖을 가리키는 경로를 주자 모두 거부되었다 [4].
허용 폴더 밖의 키 로그 파일을 `wireshark_decrypt_tls`에 주자 거부되었다 [4].

**한계.** `WIRESHARK_MCP_ALLOWED_DIRS`에는 기본값이 없고 값이 없으면 `_validate_file`은 허용 폴더를 대조하지 않는다 [18][23].
저장소의 Claude 플러그인 설정과 `Dockerfile`은 이 값을 정하지 않는다 [27].
Codex 플러그인 설정은 이 이름을 클라이언트 환경에서 넘겨받을 변수로 적기만 한다 [27].
값 없이 실행한 서버에 다른 폴더의 캡처 파일을 주자 `capinfos` 결과가 돌아왔다 [4].

대조에는 변환한 경로를 쓰지만 외부 도구에는 받은 문자열을 그대로 넘긴다 [18][28].
외부 도구는 그 문자열을 다시 해석해 파일을 연다.

`wireshark_set_protocol_prefs`는 `prefs`의 각 항목을 내용을 보지 않고 tshark의 `-o` 값으로 넘긴다 [29].
그래서 키 로그 파일 위치를 정하는 해석 설정을 이 인자로 넘기면 경로 대조를 거치지 않는다 [29].
`wireshark_decrypt_tls`가 거부한 허용 폴더 밖의 키 로그 파일을 이 도구의 `prefs`로 넘기자 tshark가 실행되어 성공 응답이 돌아왔다 [4].
시험 캡처에 TLS 세션이 없어 tshark가 그 파일을 실제로 읽었는지는 확인하지 못했다 [4].

`wireshark_quick_analysis`는 허용 폴더 밖이라 거부된 하위 실행도 파일 정보를 읽지 못했다는 문구로 적고 성공 응답을 돌려준다 [20].
허용 폴더 밖의 캡처 파일을 이 도구에 주자 `success`가 참인 응답이 돌아왔다 [4].

### T01.04 문자열 경로 검사

**구현.** 이 방식은 서버가 Windows에서 실행될 때 `_validate_file`과 `_validate_output_path`를 거치는 모든 읽기·쓰기 경로에 적용된다 [30][31].
`_is_unsafe_windows_path`는 파일시스템을 보지 않고 경로 문자열만 검사한다 [30].
장치 이름 공간 접두어로 시작하는 경로를 거부한다 [30].
경로 조각에 `:`가 있으면 대체 데이터 스트림으로 보고 거부한다 [30].
경로 조각의 첫 `.` 앞 이름이 `CON`·`PRN`·`AUX`·`NUL`·`COM1`~`COM9`·`LPT1`~`LPT9` 가운데 하나이면 대소문자와 끝의 공백·점을 가리지 않고 거부한다 [30].
두 검사 함수는 이 검사를 실제 경로 변환과 허용 폴더 대조보다 먼저 한다 [18][31].
Windows에서 예약 장치 이름, 확장자를 붙인 예약 이름, 장치 이름 공간 경로, 대체 데이터 스트림 경로를 주자 읽기·쓰기 검사 모두 `InvalidParameter`로 거부했다 [32].
Windows가 아닌 실행 환경에서는 이 함수가 늘 거짓을 돌려주므로 이 검사를 하지 않는다 [30].

```python
    def _validate_file(self, filepath: str) -> dict[str, Any]:
        """Validate file exists, is readable, and within allowed directories."""
        if not filepath:
            return {"success": False, "error": {"type": "InvalidParameter", "message": "File path cannot be empty"}}

        if self._is_unsafe_windows_path(filepath):
            return {
                "success": False,
                "error": {
                    "type": "InvalidParameter",
                    "message": "Windows device paths, reserved names, and alternate data streams are not allowed",
                },
            }

        try:
            path = Path(filepath).resolve()
        except OSError:
            return {
                "success": False,
                "error": {"type": "InvalidParameter", "message": "File path could not be resolved"},
            }

        if self._allowed_dirs and not any(self._is_path_within(path, allowed) for allowed in self._allowed_dirs):
            logger.warning("Path sandbox violation: %s", filepath)
            return {
                "success": False,
                "error": {
                    "type": "PermissionDenied",
                    "message": "Access denied: path is outside allowed directories",
                },
            }

        if not path.exists():
            return {"success": False, "error": {"type": "FileNotFound", "message": f"File not found: {filepath}"}}

        if not path.is_file():
            return {
                "success": False,
                "error": {"type": "InvalidParameter", "message": f"Path is not a file: {filepath}"},
            }

        return {"success": True}
```

```python
    @staticmethod
    def _is_unsafe_windows_path(filepath: str) -> bool:
        """Reject Windows device namespaces, reserved names, and NTFS ADS paths."""
        if sys.platform != "win32":
            return False

        normalized = filepath.replace("/", "\\")
        if normalized.startswith(("\\\\.\\", "\\\\?\\")):
            return True

        path = PureWindowsPath(filepath)
        parts = path.parts[1:] if path.anchor else path.parts
        for part in parts:
            if ":" in part:
                return True
            base_name = part.rstrip(" .").split(".", 1)[0].rstrip(" ").upper()
            if base_name in _WINDOWS_RESERVED_NAMES:
                return True
        return False
```
