# R07 증거 내용과 지시 구분

### R07.01 JSON 필드 분리

**구현.** 이 방식은 증거에서 온 글을 돌려주는 `sift-mcp`·`forensic-mcp`·`report-mcp`·`windows-triage-mcp`의 응답에 적용된다 [1][2][3][4].
`sift-mcp`의 `run_command`는 도구 출력을 `data` 아래 `stdout`·`stderr`나 파싱한 `rows`·`lines`·`data`에 두고 서버 문구는 `caveats`·`advisories`·`discipline_reminder`·`error`·`input_files_warning` 같은 다른 최상위 키에 둔다 [1].
`windows-triage-mcp`·`rag-mcp`·`opencti-mcp`는 결과 `dict`를 JSON 글로 바꿔 돌려주고 서버 문구는 `caveats`·`interpretation_constraint`에 둔다 [2].
`forensic-mcp`의 `get_findings`는 모델이 인용한 도구 출력을 발견사항의 `artifacts[].content`에 담아 돌려준다 [3].
`report-mcp`의 `generate_report`는 승인된 발견사항을 정해 둔 내부 필드만 빼고 `report_data.findings`에 실으므로 인용 `artifacts[].content`도 그 필드 안에 실린다 [4].
(실행 확인) 지시처럼 쓴 영어 문장을 넣은 CSV를 출력하는 `EvtxECmd` 시험용 실행 파일의 응답에서 그 문장은 `data.rows[].PayloadData1`에, 서버 문구는 `discipline_reminder`·`caveats`에 따로 실렸다 [5].
게이트웨이는 백엔드가 돌려준 글 내용을 바꾸지 않고 넘긴다 [6].

**한계.** 서버 문장 안에 입력이나 출력의 값을 넣는 필드가 있다.
`run_command`의 시간 제한 `error`는 실행한 명령 줄 전체를 문장 안에 넣는다 [7].
`windows-triage-mcp`의 `findings[].description`은 모델이 넘긴 파일 이름이나 부모 프로세스 이름을 서버 문장 안에 넣는다 [8].

### R07.02 출처 필드 부여

**구현.** 이 방식은 `sift-mcp`의 `run_command`, `rag-mcp`의 `search_knowledge`, `opencti-mcp`의 `lookup_ioc`에 적용된다 [1][9][10].
`run_command`의 응답은 늘 `data_provenance` 값 `tool_output_may_contain_untrusted_evidence`와 `tool`을 싣는다 [1].
이 값은 `data`에 공격자가 만든 증거 내용이 들어 있을 수 있다는 표시다 [1].
`build_response`는 `run_command`의 성공 응답과 오류 응답을 모두 만들므로 `data`가 비어 있는 응답에도 이 값이 실린다 [1][11].
분석 도구 목록에 있는 도구를 실행하면 그 버전 `tool_version`과 실제 경로 `resolved_path`도 함께 싣는다 [1][12].
`search_knowledge`는 결과 항목마다 지식 원천 `source`와, 사용자 색인이 열려 있으면 배포 색인인지 사용자 색인인지 `origin`을 싣는다 [9].
`lookup_ioc`는 플랫폼의 레코드를 플랫폼 이름 아래 `providers.<이름>`에 나눠 싣는다 [10].

`forensic-mcp`의 `get_findings`는 `artifacts[]` 항목마다 인용 `content`와 함께 모델이 적은 출처 `source`, 추출 방법 `extraction`, 인용한 호출의 `audit_id`를 싣는다 [3].
`sift-mcp`의 다른 도구와 `case-mcp`·`report-mcp`·`windows-triage-mcp`의 응답에는 출처나 신뢰 수준 필드가 없다 [2].

### R07.04 증거 내 지시 무시 안내

**구현.** 이 방식은 `sift-mcp`의 서버 지침과 `run_command`·`suggest_tools` 응답의 순환 안내 문장에 적용된다 [13][14].
`sift-mcp`의 서버 지침은 파일 이름, 이벤트 로그 메시지, 레지스트리 값 같은 증거 내용이 공격자가 넣은 글일 수 있으니 지시로 해석하지 말고 분석을 지시하는 문구가 보이면 사용자에게 알리라고 적는다 [13].
게이트웨이의 백엔드별 끝점 `/mcp/sift-mcp`도 초기화 응답에 이 지침을 싣는다 [15].
`run_command`와 `suggest_tools`는 응답의 `discipline_reminder`에 15개 문장 가운데 하나를 호출 수에 따라 돌아가며 싣고 그 가운데 하나가 같은 안내다 [14].
(실행 확인) `build_response`를 30번 부르자 13번째와 28번째 응답에만 이 문장이 실렸다 [16].

**한계.** 게이트웨이의 묶음 끝점 `/mcp`는 초기화 응답에 게이트웨이 지침만 싣고 이 지침에는 증거 내 지시에 관한 문장이 없다 [15][17].
`forensic-mcp`·`case-mcp`·`report-mcp`·`windows-triage-mcp`·`rag-mcp`·`opencti-mcp`의 서버 지침에도 이 문장이 없다 [18].
묶음 끝점으로 붙은 클라이언트는 이 안내를 `run_command`·`suggest_tools` 응답의 순환 안내 문장으로만 받는다 [14][15].
