# R04 도구 결과 해석 주의

### R04.01 도구별 정적 주의

**구현.** 이 방식은 `windows-triage-mcp`·`rag-mcp`·`opencti-mcp`의 오류가 아닌 응답, `sift-mcp`의 `run_command`·`get_tool_help`·`suggest_tools` 응답, `forensic-mcp`의 도구 해석 안내, 서버 지침에 적용된다 [1][2][3][4][5][6][7][8].
`windows-triage-mcp`·`rag-mcp`·`opencti-mcp`는 응답마다 도구 이름으로 고른 `caveats` 목록과 `interpretation_constraint` 문장을 싣는다 [1].
예를 들어 `check_file`은 `UNKNOWN`이 기준 DB에 없다는 뜻이지 의심스럽다는 뜻이 아니라고 적고 `lookup_ioc`는 위협 정보에 없다고 정상이라는 뜻이 아니라고 적는다 [1].
`search_knowledge`는 결과가 사건 증거가 아닌 참조 지식이고 점수가 신뢰도가 아닌 의미 유사도라고 적는다 [1].
`run_command`는 실행한 도구의 FK 지식에서 도구의 `caveats`, 필드 뜻 `field_meanings`, 시각 필드의 뜻 `field_notes`를 응답에 싣는다 [2].
도구가 다루는 아티팩트마다 그 아티팩트가 증명하지 못하는 것(`does_not_prove`)과 흔한 오해를 `advisories`에 싣는다 [2][9].
명령 인자에 보안 이벤트 ID나 `security`·`sysmon` 같은 파일 이름 낱말이 있으면 그 아티팩트의 주의만 고른다 [10].
(실행 확인) Sleuth Kit `fls`로 시험용 ext2 이미지를 나열하자 응답에 `fls`의 `caveats` 6개와 MFT의 "This artifact does NOT prove" 문장이 들어간 `advisories`가 실렸다 [11].
`get_tool_help`는 FK의 도구 `caveats`·`advisories`·`field_meanings`를, `suggest_tools`는 아티팩트마다 증명하지 못하는 것 `what_it_does_not_reveal`을 싣는다 [3][4].
`forensic-mcp`는 도구 이름으로 해석 안내와 흔한 오탐을 돌려주는 리소스(`--deferred-tools`에서는 도구 `get_tool_guidance`·`get_false_positive_context`)를 둔다 [5].
`sift-mcp`의 서버 지침은 도구 출력이 발견사항이 아니라 데이터이고 필드 뜻을 확인한 뒤 해석하며 결과가 없다는 것이 사건이 없었다는 증명이 아니라고 적는다 [6].
`windows-triage-mcp`의 서버 지침은 `EXPECTED`가 기본 설치라는 뜻이지 정상이라는 뜻이 아니고 `UNKNOWN`은 기준 DB에 없다는 중립 결과라고 적는다 [7].
`opencti-mcp`의 서버 지침은 위협 정보와 일치하는 것이 증명이 아니라 보조 근거라고 적는다 [8].

**한계.** FK에 지식이 없는 명령(`echo`·`seq` 등)의 응답에는 `caveats`·`advisories`가 붙지 않는다 [2][12].
`fls`의 FK 지식은 다루는 아티팩트를 MFT 하나로 적으므로 ext2 이미지를 나열한 응답에도 NTFS MFT에 관한 문장이 실렸다 [11].
모델이 `run_command`에 `skip_enrichment`를 참으로 주면 `caveats`·`field_meanings`·`field_notes`·`advisories`를 싣지 않는다 [2][13].
게이트웨이의 서버 지침은 같은 도구를 두 번째로 부를 때부터 `skip_enrichment`를 참으로 주라고 적는다 [14].
`advisories`는 한 서버 프로세스에서 도구마다 처음 세 번과 그 뒤 열 번째 호출마다만 싣는다 [2].
(실행 확인) 같은 `EvtxECmd` 시험용 실행을 다섯 번 하자 넷째와 다섯째 응답에는 `caveats`만 있고 `advisories`가 없었다 [15].
(실행 확인) `skip_enrichment`를 참으로 준 응답에는 `caveats`·`advisories`·`field_meanings`가 없었다 [15].
FK 지식을 읽다가 예외가 나면 경고만 기록하고 주의 없이 응답한다 [2].
게이트웨이의 묶음 끝점 `/mcp`는 초기화 응답에 게이트웨이 지침만 싣고 백엔드의 서버 지침은 백엔드별 끝점 `/mcp/<백엔드>`에만 싣는다 [16].

### R04.02 결과 조건별 주의

**구현.** 이 방식은 `windows-triage-mcp`의 대조 도구, `sift-mcp`의 `run_command`, `opencti-mcp`의 `lookup_ioc`, `rag-mcp`의 `search_knowledge`에 적용된다 [17][18][19][20][21].
`windows-triage-mcp`는 판정의 `reasons`에 대조하지 않은 내용을 골라 붙인다 [17][18].
`check_file`은 해시를 받지 않고 `EXPECTED` 계열 판정을 내리면 경로만 대조하고 내용은 확인하지 않았다고 적는다 [17].
기준 DB에 그 경로의 해시가 없어 대조하지 못하면 그 사실을 적고 경로가 볼륨 섀도 복사본이나 관리 공유 경로면 실제 위치가 아니라고 적는다 [17].
8.3 짧은 이름이 들어간 경로는 여러 긴 경로를 가리킬 수 있다고 `reasons`에 적는다 [17].
`check_scheduled_task`·`check_autorun`·`check_pipe`는 `EXPECTED`를 내릴 때 작업의 명령, 자동 실행 값의 데이터, 파이프를 연 프로세스를 대조하지 않았다고 적는다 [18].
`check_process_tree`는 계정을 판단하지 못하면 그 이유를 `reasons`에 더한다 [18].
`run_command`는 캡처 상한에서 프로세스를 끝낸 응답의 `error`에 종료 코드가 도구의 것이 아니라 서버가 멈춘 결과라고 적는다 [19].
`lookup_ioc`는 OpenCTI 관계를 읽지 못하면 관계 목록이 불완전하다고 `relationships_unavailable`에 적는다 [20].
사설·루프백·링크 로컬 IP 주소는 조회하지 않고 위협 정보 범위가 아니라고 `note`에 적는다 [20].
`search_knowledge`는 사용자 문서 색인이 배포 색인과 맞지 않거나 열리지 않아 검색에서 빠지면 `warning`에, 아직 색인되지 않았으면 `notice`에 그 사실을 적는다 [21].

### R04.03 추가 확인 도구·증거 추천

**구현.** 이 방식은 `sift-mcp`의 `run_command`·`suggest_tools` 응답, `windows-triage-mcp`의 일부 판정, `forensic-mcp`의 대조 안내, 순환 안내 문장, `rag-mcp`의 서버 지침에 적용된다 [2][22][23][24][25][26].
`run_command`는 FK 아티팩트의 `corroborate_with`를 목적별 확인 아티팩트 목록 `corroboration`으로, `cross_mcp_checks`를 확인할 서버·도구·조건 목록으로 싣는다 [2][9].
도구가 실행 파일 분석·지속성·실행 흔적·메모리 묶음(`binary_analysis`·`persistence`·`execution`·`memory`)에 속하면 다른 서버의 확인 도구 목록 `related_tools`를 싣는다 [22].
`suggest_tools`는 아티팩트 유형에 맞는 도구와 함께 `corroboration`·`cross_mcp_checks`를 싣는다 [4].
`check_process_tree`는 의심 부모 프로세스마다 정해 둔 설명을 붙이고 Office 부모에는 VBA 매크로와 DDE 링크를 확인하라고 적는다 [23].
`check_file`은 섀도 복사본이나 관리 공유 경로를 받으면 드라이브 문자 경로로 다시 확인하라고 적는다 [17].
`forensic-mcp`는 발견사항 유형별 확인 대상을 돌려주는 리소스(`--deferred-tools`에서는 도구 `get_corroboration_suggestions`)를 둔다 [24].
`run_command`와 `suggest_tools`의 순환 안내 문장 가운데 하나는 Shimcache·Amcache가 실행이 아니라 존재만 증명하므로 Prefetch, UserAssist, BAM, 프로세스 생성 이벤트로 확인하라고 적는다 [25].
`rag-mcp`의 서버 지침은 검색 결과를 1차 문서와 대조해 확인해야 할 수 있다고 적는다 [26].

**한계.** `corroboration`·`cross_mcp_checks`·`related_tools`도 도구마다 처음 세 번과 그 뒤 열 번째 호출마다만 싣고 `skip_enrichment`를 주면 `corroboration`·`cross_mcp_checks`를 싣지 않는다 [2][22].
`related_tools`가 권하는 도구 가운데 `wintools-mcp`·`remnux-mcp`·`opensearch-mcp`의 도구는 게이트웨이 설정 예시에서 꺼져 있거나 이 저장소에 없는 서버의 것이다 [22][27].
순환 안내 문장은 응답마다 15개 가운데 하나만 실리므로 Shimcache·Amcache 문장은 열다섯 번 호출에 한 번 실린다 [25][4].

```python
def _detect_artifact_context(command: list[str]) -> str | None:
    """Detect artifact context from command for FK advisory filtering.

    Returns an artifact name (e.g., "event_logs_security") to filter
    FK advisories, or None for no filtering (include all).
    """
    for i, token in enumerate(command):
        # Match --inc 4624, --inc 4624,4625, or --inc=4624
        value = None
        if token.startswith("--inc="):
            value = token.split("=", 1)[1]
        elif token == "--inc" and i + 1 < len(command):
            value = command[i + 1]
        if value:
            ids = set(value.replace(",", " ").split())
            if ids & _SECURITY_EVENT_IDS:
                return "event_logs_security"

    for token in command:
        if token.startswith("-"):
            continue
        basename = token.rsplit("/", 1)[-1].rsplit("\\", 1)[-1].lower()
        for keyword, artifact in _FILENAME_ARTIFACT_MAP.items():
            if keyword in basename:
                return artifact
```
