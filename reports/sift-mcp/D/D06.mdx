# D06 산출물 식별·재생성 처리

### D06.01 실행 ID별 위치

**구현.** 이 방식은 `sift-mcp`의 `run_command`가 만드는 작업 폴더와 게이트웨이의 참조 응답 사본에 적용된다 [1][2].
두 경우 모두 폴더 이름은 그 호출의 호출 기록 항목 ID다 [1][2].
ID는 `<서버 접두어>-<검토자>-<UTC 날짜>-<ULID>` 형식이고 ULID는 밀리초 시각과 80비트 난수로 만든다 [3].
`run_command`는 분석 도구를 실행하기 전에 이 폴더를 만들고 그 호출의 보관 출력과 도구가 쓴 파일을 이 폴더에 둔다 [1].
참조 응답 사본은 `os.makedirs`와 배타 생성 모드 `xb`로 쓰므로 같은 이름의 폴더나 파일이 있으면 쓰지 않는다 [2].
같은 명령을 두 번 부르자 서로 다른 `extractions/<audit_id>/` 폴더에 각 실행의 표준 출력 파일과 도구가 쓴 파일이 따로 남았다 [4].

**한계.** `run_command`는 폴더가 이미 있으면 `FileExistsError`를 무시하고 그 폴더를 쓴다 [1].
출력 플래그로 작업 폴더 밖 경로를 주면 그 파일은 호출 ID 폴더로 나뉘지 않고 받은 경로에 그대로 쓰인다 [5].
활성 사건이 없으면 호출 ID도 작업 폴더도 만들지 않는다 [1].

### D06.02 입력·작업별 고유 이름

**구현.** 이 방식은 `run_command`가 보관하는 표준 출력·표준 오류 파일과 `forensic-mcp`의 기록 ID에 적용된다 [6][7].
보관 파일 이름은 UTC 초 단위 시각, 실행 파일 경로를 영숫자·`-`·`_`로 바꾼 앞 40자, `uuid4` 앞 8자로 짓는다 [6].
시각과 난수가 들어가므로 같은 입력으로 다시 실행해도 이름이 다르다 [6].
파일은 배타 생성 모드 `xb`로 열어 이미 있는 파일을 바꾸지 않는다 [6].
`forensic-mcp`는 발견사항에 `F-<검토자>-<번호>`, 타임라인 사건에 `T-<검토자>-<번호>`, IOC 기록에 `IOC-<검토자>-<번호>` ID를 매긴다 [7].
번호는 같은 접두어 ID 가운데 가장 큰 번호에 1을 더한 값이다 [8].
발견사항과 타임라인 사건은 사건 잠금을 획득한 채 번호를 정하고 저장한다 [9].

### D06.03 버전·이력 보존

**구현.** 이 방식은 `report-mcp`의 `save_report`와 `case-mcp`의 `backup_case`에 적용된다 [10][11].
`save_report`는 같은 이름의 보고서가 있으면 `<이름>_v2`부터 `_v999`까지 가운데 비어 있는 첫 이름에 새 보고서를 쓰고 앞 보고서는 그대로 둔다 [10].
999번까지 모두 있으면 `Too many report versions`로 거부한다 [10].
`backup_case`는 같은 이름의 백업 폴더가 있으면 `-1`, `-2`를 붙인 새 폴더를 만든다 [11].
`r1.md`를 두 번 저장하자 `r1.md`와 `r1_v2.md`가 남았고 백업을 두 번 만들자 `-1`이 붙은 폴더가 따로 생겼다 [12].

**한계.** `save_report`는 이름이 있는지 본 뒤 임시 파일을 `os.replace`로 그 이름에 옮긴다 [10][13].
그 사이에 같은 이름의 파일이 생기면 그 파일을 바꾼다 [13].

### D06.04 덮어쓰기 선택·충돌 감지

**구현.** 이 방식은 `record_finding`이 발견사항의 `iocs`로 만드는 IOC 기록에 적용된다 [14].
IOC 값을 정규화한 키로 `iocs.json`의 기존 기록을 찾고 있으면 새 기록을 만들지 않는다 [14].
그 대신 기존 기록의 `source_findings`, `sightings`, `mitre_techniques`에 새 발견사항의 값을 더한다 [14].
새 발견사항의 확신도 `confidence`가 더 높으면 기록의 확신도를 바꾼다 [14][15].
기존 기록에 값을 더할 때마다 `modified_at`과 `content_hash`를 다시 계산한다 [14].
두 발견사항에 같은 IP를 IOC로 주자 IOC 기록은 하나였고 `source_findings`에 두 발견사항 ID가 들어갔다 [16].

`record_finding`과 `record_timeline_event`는 같은 내용의 기록이 있는지 보지 않고 새 ID로 기록을 더한다 [7][17].
`record_timeline_event`의 도구 설명은 `artifact_ref`를 중복 제거 힌트라고 적지만 코드는 그 값을 저장만 하고 대조하지 않는다 [18][17].
같은 `timestamp`·`description`·`artifact_ref`로 두 번 부르자 `T-tester-001`과 `T-tester-002`가 따로 저장되었다 [16].
`run_command`는 출력 플래그 경로에 앞 결과가 있는지 보지 않고 분석 도구를 실행하며 덮어쓸지 고르는 인자도 없다 [19].
서버는 실행 전후 파일의 inode·크기·수정 시각을 비교해 바뀐 파일을 그 호출의 출력으로 새 해시와 함께 기록한다 [19].
같은 `-o` 경로를 두 번 주자 두 호출 모두 성공했고 파일은 둘째 호출이 쓴 내용으로 바뀌었다 [5].

def _next_seq(items: list[dict], id_field: str, prefix: str, examiner: str) -> int:
    """Find max sequence number for IDs matching {prefix}-{examiner}-NNN."""
    pattern = f"{prefix}-{examiner}-"
    max_num = 0
    for item in items:
        item_id = item.get(id_field, "")
        if item_id.startswith(pattern):
            try:
                num = int(item_id[len(pattern) :])
                max_num = max(max_num, num)
            except ValueError:
                pass
    return max_num + 1
```

def _atomic_write(path: Path, content: str) -> None:
    """Write file atomically via temp file + rename."""
    fd, tmp_path = tempfile.mkstemp(dir=str(path.parent), suffix=".tmp")
    try:
        with os.fdopen(fd, "w") as f:
            f.write(content)
            f.flush()
            os.fsync(f.fileno())
        os.replace(tmp_path, str(path))
    except BaseException:
        try:
            os.unlink(tmp_path)
        except OSError:
            pass
        raise
```
