# D04 출력 경로 제한

### D04.01 서버가 출력 위치 결정

**구현.** 이 방식은 `sift-mcp`의 `run_command`가 정하는 작업 폴더와 보관 출력, 게이트웨이의 참조 응답 사본, `forensic-mcp`의 기록 파일, `report-mcp`의 `save_report`에 적용된다 [1][2][3][4][5].
사건 폴더는 호출 인자가 아니라 환경변수 `VHIR_CASE_DIR`나 활성 사건 표시 파일 `~/.vhir/active_case`로 정한다 [6].
활성 사건이 있으면 `run_command`는 사건 폴더 아래 `extractions/<audit_id>/`를 만들어 분석 도구의 작업 폴더로 준다 [1].
명령에 쓴 상대 경로는 이 폴더를 기준으로 해석된다 [1][7].
보관하는 표준 출력·표준 오류 파일은 같은 폴더에 서버가 지은 이름으로 쓴다 [2].
게이트웨이의 참조 응답 사본은 게이트웨이가 매긴 호출 기록 ID 폴더 아래 `response.json`이다 [3].
`forensic-mcp`는 사건 폴더의 정해진 이름 `findings.json`·`timeline.json`·`iocs.json`에 쓴다 [4].
`save_report`는 사건 폴더의 `reports/`에 쓴다 [5].
호출 인자 `filename`은 영문자·숫자·`.`·`_`·`-` 밖의 문자를 `_`로 바꾼 이름 한 조각으로만 경로에 들어간다 [5].
`a b;c.md`를 `filename`으로 주자 `reports/a_b_c.md`가 생겼다 [8].

**한계.** 활성 사건이 없으면 `run_command`는 작업 폴더를 주지 않고 분석 도구는 서버 프로세스의 현재 폴더에서 실행된다 [1][9].
작업 폴더를 만들다 `OSError`가 나도 경고 로그만 남기고 같은 방식으로 실행한다 [1].
사건 없이 `run_command`를 부르자 시험용 실행 파일이 쓴 파일이 서버 프로세스의 현재 폴더에 생겼다 [9].

### D04.02 실제 경로와 허용 폴더 대조

**구현.** 이 방식은 `run_command`가 받은 명령의 출력 플래그 값에 적용된다 [10][11].
출력 플래그는 카탈로그 `security.yaml`에 적은 공통 플래그(`-o`, `--output`, `--csv`, `--json` 등)와 도구별 플래그(`tshark`의 `-w`, `vol`의 `--output-dir` 등)다 [11].
`--플래그=값`, 붙여 쓴 `-o<경로>`, 출력 플래그 다음 인자를 모두 출력 경로로 본다 [10].
`validate_output_path`는 상대 경로를 작업 폴더에 붙인 뒤 `Path.resolve()`로 링크와 `..`를 해석한 실제 경로로 바꾼다 [12].
활성 사건이 있으면 그 실제 경로가 사건 폴더의 실제 경로 아래일 때만 통과시키고 밖이면 `ValueError`로 호출을 거부한다 [12].
활성 사건이 없으면 `/tmp`와 서버 프로세스의 현재 폴더 아래만 통과시킨다 [12].
사건 폴더 밖의 `/tmp` 경로를 `-o`로 주자 실패 응답이 왔고 파일은 생기지 않았다 [13].
사건 없이 `/tmp`도 현재 폴더도 아닌 경로를 주자 같은 방식으로 거부되었다 [9].

**한계.** 서버는 대조에 쓴 실제 경로가 아니라 받은 문자열을 그대로 분석 도구에 넘긴다 [10].
허용 폴더가 사건 폴더 전체라서 다른 호출의 `extractions/` 폴더와 `reports/` 아래 경로도 통과한다 [12].
같은 `-o` 경로를 두 호출에 주자 둘 다 성공했고 첫 호출이 쓴 파일이 바뀌었다 [14].
출력 플래그 목록에 없는 방식으로 받는 목적지에는 이 대조가 적용되지 않는다 [10].
위치 인자로 받는 목적지는 실제 경로를 시스템 폴더와 사용자 설정 폴더의 차단 목록과만 대조하는 입력 경로 검사를 받는다 [10][15][16].
도구 설명은 `dd`, `bash -c`, `python -c`와 도구 고유의 출력 옵션을 검사하지 않는다고 적는다 [17].

### D04.03 파생물 ID로만 수정·삭제

**구현.** 이 방식은 검토 포털 `case-dashboard`의 검토 결정과 `case-mcp`의 `import_bundle`에 적용된다 [18][19].
포털은 발견사항·타임라인·IOC에 대한 편집과 결정을 항목 ID로 `pending-reviews.json`에 모은다 [20].
검토자가 서명한 결정을 커밋하면 사건 잠금 안에서 그 ID의 항목만 사건 파일에 반영하고 `pending-reviews.json`에서 뺀다 [18].
`import_bundle`은 가져온 발견사항과 타임라인을 ID로 맞춰 합치고 이 사건에서 기록한 항목은 바꾸지 않는다 [19].
발견사항·타임라인·IOC를 경로로 받아 고치거나 지우는 MCP 도구는 없다 [19][21].

**한계.** `run_command`의 출력 플래그 대조는 사건 폴더 안이면 통과시키므로 보관 출력이나 보고서 파일 경로를 목적지로 주면 ID를 거치지 않고 그 파일을 바꿀 수 있다 [12][14].

### D04.04 이름·확장자·충돌 검사

**구현.** 이 방식은 `save_report`의 `filename`과 `backup_case`의 `destination`에 적용된다 [5][22].
`save_report`는 `filename`에 `..`, `/`, `\`가 들어 있으면 거부하고 200자를 넘거나 NUL 문자가 있어도 거부한다 [5][23].
`backup_case`는 `destination`에 `..`가 들어 있거나 200자를 넘으면 거부한다 [22].
두 검사는 실제 경로로 바꾸지 않는 문자열 검사다 [5][22].
`..`나 `/`를 넣은 `filename`은 `Invalid filename`으로, `..`를 넣은 `destination`은 `invalid path traversal`로 거부되었다 [8][24].

### D04.05 서버가 파일 이름 결정

**구현.** 이 방식은 `case-mcp`의 `backup_case`에 적용된다 [22][25].
목적지 폴더는 호출 인자 `destination`으로 받고 그 안의 백업 폴더 이름은 서버가 `<case_id>-<UTC 날짜>`로 짓는다 [25].
복사하는 동안에는 `<이름>.incomplete` 폴더에 쓰고 마치면 정한 이름으로 바꾼다 [25].
그 이름의 폴더가 이미 있으면 `-1`, `-2`를 붙인 이름을 `mkdir`로 새로 만들어 앞 백업을 덮어쓰지 않는다 [26].
같은 목적지로 두 번 부르자 `<case_id>-<날짜>`와 `<case_id>-<날짜>-1` 폴더가 생겼다 [24].

**한계.** 목적지 폴더는 실제 경로로 바꿔 허용 폴더와 대조하지 않고 받은 문자열을 그대로 쓴다 [25].
목적지 폴더가 없으면 상위 폴더까지 만든다 [26].

### D04.07 실제 경로로 바꿔 보호 대상 대조

**구현.** 이 방식은 `run_command`가 실행하는 `rm`·`shred`·`unlink`·`truncate`·`tee`·`mv`·`cp`·`install`·`ln`의 목적지에 적용된다 [27].
`run_command`는 이 명령의 목적지를 실제 경로로 바꾼 뒤 사건 폴더 바로 아래 기록 파일 이름(`findings.json`, `timeline.json` 등)이거나 `audit/` 아래이거나 `evidence/` 아래의 이미 있는 파일이면 거부한다 [27].
`rm`은 목적지의 실제 경로가 사건 폴더 안이면 기록 파일이 아니어도 거부한다 [28].
다른 파일을 사건의 `DELETE/` 폴더로 옮기는 명령은 거부하지 않는다 [27].
이 검사는 정해 둔 명령에만 적용되고 다른 분석 도구가 출력 플래그로 같은 파일에 쓰는 경로에는 적용되지 않는다 [27][12].

**한계.** 함수 설명은 몇 가지 옵션 표기로 준 목적지를 검사하지 않는다고 적는다 [27].

def resolve_case_dir() -> str:
    """Resolve the active case directory.

    Resolution order: VHIR_CASE_DIR env var → ~/.vhir/active_case file → "".
    VHIR_CASE_DIR must be a directory containing CASE.yaml to be valid.
    If set but invalid, falls through to active_case.
    """
    case_dir = os.environ.get("VHIR_CASE_DIR", "").strip()
    if case_dir:
        p = Path(case_dir)
        if p.is_dir() and (p / "CASE.yaml").exists():
            return case_dir
        # Set but invalid — fall through to active_case
    active_file = Path.home() / ".vhir" / "active_case"
    if active_file.is_file():
        try:
            content = active_file.read_text().strip()
        except OSError:
            return ""
        if content:
            p = Path(content)
            if p.is_dir() and (p / "CASE.yaml").exists():
                return content
    return ""
```

def _validate_str_length(
    value: str | None, field: str, max_len: int, *, free_text: bool = False
) -> None:
    """Reject strings exceeding max_len, containing null bytes, or path traversal.

    free_text: the field is prose or a command line that is stored, never
    used as a path, so ".." in it ("then prefetch...", "cd ..") is kept.
    """
    if value is not None and isinstance(value, str):
        if len(value) > max_len:
            raise ValueError(f"{field} exceeds maximum length of {max_len} characters")
        if "\x00" in value:
            raise ValueError(f"{field} contains invalid null byte")
        if ".." in value and not free_text:
            raise ValueError(f"{field} contains invalid path traversal")
```
