# D01 파생물 보관

### D01.01 파생물 파일 보관

**구현.** 이 방식은 `sift-mcp`의 `run_command`, 게이트웨이의 참조 조회 기록, `forensic-mcp`의 발견사항·타임라인·IOC 기록, `report-mcp`의 `save_report`, `case-mcp`의 `backup_case`에 적용된다 [1][2][3][4][5].
활성 사건이 있으면 `run_command`는 호출마다 사건 폴더 아래 `extractions/<audit_id>/` 폴더를 먼저 만들고 그 폴더를 작업 폴더로 삼아 분석 도구를 실행한다 [1].
`audit_id`는 그 호출의 호출 기록 항목 ID다 [1].
표준 출력과 표준 오류는 `save_output` 값과 출력 크기에 관계없이 이 폴더에 `_stdout.txt`·`_stderr.txt`로 끝나는 파일로 남는다 [6].
두 파이프는 합쳐서 `max_output_bytes`(기본 50 MiB)까지만 읽으므로 보관한 파일은 읽은 부분만 담는다 [7].
분석 도구가 작업 폴더에 쓴 파일과 출력 인자(`-o`, `--csv` 등)로 받은 경로에 새로 생기거나 바뀐 파일도 지우지 않고 남는다 [8].
호출 기록 항목에는 표준 출력의 앞 500자 `stdout_head`만 들어간다 [9].
시험용 실행 파일로 `run_command`를 부르자 `extractions/<audit_id>/`에 표준 출력 파일과 도구가 작업 폴더에 쓴 파일이 남았다 [10].

게이트웨이는 `opencti-mcp`의 `lookup_ioc`와 `windows-triage-mcp`의 `check_*` 도구 응답을 사건 폴더의 `extractions/<audit_id>/response.json`에 백엔드가 돌려준 글 그대로 남긴다 [2].
이 `audit_id`는 게이트웨이가 그 조회에 따로 매긴 호출 기록 항목 ID다 [2].
시험용 응답으로 이 기록 함수를 부르자 `response.json`이 생겼고 조회 도구가 아닌 `search_threat_intel`에는 파일이 생기지 않았다 [11].

`forensic-mcp`는 발견사항, 타임라인 사건, IOC를 사건 폴더의 `findings.json`·`timeline.json`·`iocs.json`에 JSON 배열로 남긴다 [3].
세 파일은 임시 파일에 전체를 쓴 뒤 이름을 바꾸고 쓰기 권한을 뺀 `0444` 모드로 둔다 [12].
발견사항에 붙은 인용 `content`는 앞 5,000자까지만 저장하고 자른 사실을 그 뒤에 적는다 [13].

`save_report`는 모델이 보낸 보고서 글 뒤에 서버가 만든 검증 결과와 출처 목록을 붙여 사건 폴더의 `reports/`에 쓴다 [4].
`backup_case`는 사건 기록 파일, 호출 기록, 보고서를 받은 목적지 아래 새 폴더로 복사하고 파일마다 SHA-256을 적은 `backup-manifest.json`을 함께 둔다 [5].
MCP 도구 `backup_case`는 `evidence/`와 `extractions/`를 복사하지 않으므로 `run_command`의 보관 출력과 참조 응답 사본은 이 복사본에 들어가지 않는다 [5].

`windows-triage-mcp`, `rag-mcp`, `opencti-mcp`와 `sift-mcp`의 다른 4개 도구는 결과를 응답으로만 돌려주고 파일을 쓰지 않는다 [14].
보관 기간이나 보관 대상을 정하는 설정과 코드는 없다.
보관한 파생물을 지우는 MCP 도구는 없다 [15].

**한계.** 활성 사건이 없으면 `run_command`는 출력을 보관하지 않는다 [16].
작업 폴더를 정하지 않으므로 `save_output`을 참으로 주어도 저장할 폴더가 없어 아무 파일도 쓰지 않는다 [16].
도구 설명은 `save_output`이 표준 출력과 표준 오류를 SHA-256과 함께 파일로 저장한다고 적는다 [17].
사건 없이 `save_output=True`로 부르자 응답에 `full_output_path`가 없었고 분석 도구가 쓴 파일만 서버 프로세스의 현재 폴더에 남았다 [18].
게이트웨이를 거치지 않고 `opencti-mcp`나 `windows-triage-mcp`를 직접 붙이면 참조 응답 사본은 생기지 않는다 [19].
게이트웨이는 백엔드가 오류로 표시한 응답의 사본도 남기지 않는다 [19].

```python
def _atomic_write(path: Path, content: str) -> None:
    """Write file atomically via temp file + rename to prevent data loss on crash."""
    fd, tmp_path = tempfile.mkstemp(dir=path.parent, suffix=".tmp")
    try:
        with os.fdopen(fd, "w") as f:
            f.write(content)
            f.flush()
            os.fsync(f.fileno())
        os.replace(tmp_path, path)
    except BaseException:
        try:
            os.unlink(tmp_path)
        except OSError:
            pass
        raise
```

```python
def _protected_write(path: Path, content: str) -> None:
    """Write to a chmod-444-protected case data file.

    Uses atomic write (tempfile + rename), then locks (0o444).
    The temp file is created writable, so we only need to unlock the
    existing file for _atomic_write's rename to succeed on the same inode.
    """
    try:
        if path.exists():
            os.chmod(path, 0o644)
    except OSError:
        pass  # May already be writable or on non-POSIX fs
    try:
        _atomic_write(path, content)
    finally:
        # Always re-lock, even if the write failed partway
        try:
            if path.exists():
                os.chmod(path, 0o444)
        except OSError:
            pass  # Non-POSIX filesystem
```
