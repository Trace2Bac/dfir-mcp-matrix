# sift-mcp 원고

이 파일은 서버 개요다. 셀마다 이 폴더 아래 축 폴더의 `<축>/<셀ID>.mdx`에 쓴다.
셀과 상세 항목의 정의는 `matrix/cells/<축>/<셀ID>.mdx`를 따른다.
상세 항목마다 **구현**을 쓰고 그 방식이 적용되지 않는 경로나 조건이 있으면 **한계**를 따로 쓴다.
본문의 [번호]는 그 파일 끝 **근거**의 같은 번호를 가리킨다.

**기준 커밋.** [`5ef6081`](https://github.com/AppliedIR/sift-mcp/tree/5ef6081a35252380ffe5456dca1a5f3355fbe01a)(2026-10-24).
줄 번호는 모두 이 커밋 기준이다.

**범위.** 저장소 `AppliedIR/sift-mcp`는 Valhuntir 플랫폼의 SIFT 쪽 구성 요소를 담은 monorepo이다.
이 원고는 이 저장소의 게이트웨이와 게이트웨이가 기본으로 붙이는 MCP 서버 7개를 한 서버로 본다.
여러 서버가 같은 공통 모듈 `sift-common`과 같은 사건 폴더를 쓰는 한 제품이므로 원고는 문장마다 어느 백엔드의 동작인지 밝힌다.

- `sift-gateway`는 Starlette와 MCP Python SDK의 `StreamableHTTPSessionManager`로 HTTP MCP 끝점 하나를 열고 설정 파일의 백엔드를 stdio나 HTTP로 붙여 도구를 모아 내놓는다. 설정 예시는 `127.0.0.1:4508`에 열고 API 키마다 검토자와 역할을 둔다.
- `forensic-mcp`(FastMCP)는 발견사항, 타임라인, 할 일, 조사 절차와 분석 규율 자료를 다룬다. 기본은 도구 10개와 리소스 8개·리소스 템플릿 6개다. 게이트웨이 설정 예시가 주는 `--deferred-tools`로 띄우면 규율 자료를 도구로 내놓아 도구가 24개가 된다(실행 확인).
- `sift-mcp`(FastMCP)는 SIFT Workstation의 분석 도구 목록, 도움말, 설치 확인, 추천과 명령 실행 `run_command`를 둔 도구 5개를 둔다(실행 확인).
- `case-mcp`(FastMCP)는 사건 생성·전환, 증거 등록 같은 사건 관리 도구 16개를 둔다(실행 확인).
- `report-mcp`(FastMCP)는 보고서 생성 도구 6개를 둔다(실행 확인).
- `windows-triage-mcp`(저수준 `Server`)는 파일, 프로세스, 서비스, 레지스트리, 예약 작업 등을 정상 기준 DB와 대조하는 도구 13개를 둔다.
- `rag-mcp`(`packages/forensic-rag`, 저수준 `Server`)는 포렌식 지식 색인을 검색하는 도구 3개를 둔다.
- `opencti-mcp`(`packages/opencti`, 저수준 `Server`)는 OpenCTI·MISP 위협 정보를 조회하는 도구 8개를 둔다(실행 확인).

검토 포털 `case-dashboard`는 게이트웨이 프로세스가 `/portal` 아래에 띄우므로 서버 구현으로 본다.
`case-mcp`, `report-mcp`, 게이트웨이가 불러 쓰는 사용자 CLI 패키지 `vhir-cli`(저장소 `AppliedIR/Valhuntir`)의 모듈(사건 입출력, 원장 검증, 증거 목록, 출처 표시 등)은 서버 프로세스에서 실행되므로 서버 구현으로 본다.
`forensic-knowledge`(분석 규율·도구 지식 YAML)와 설정 예시 `config/gateway.yaml.example`은 서버가 읽는 자료다.
Sleuth Kit, libewf, Volatility 3, Zimmerman 도구, Plaso, RegRipper, YARA, Hayabusa 등 `sift-mcp`가 실행하는 SIFT 분석 도구는 서버가 하위 프로세스로 실행하는 분석 도구로 본다.

게이트웨이 설정 예시가 기본으로 끈 원격 HTTP 백엔드(Windows 도구 실행 `wintools-mcp`, REMnux, Microsoft Learn 등)와 별도 저장소의 `opensearch-mcp`는 이 저장소의 서버가 아니므로 원고에 사실로만 적는다.
`claude-code/`(CLAUDE.md, 규율 문서, 명령, 훅, `settings.json`), `codex/`, `agents/`, `skills/`, `AGENTS.md`는 클라이언트 자료와 설정이다.
게이트웨이 없이 쓰는 Lite 구성은 클라이언트가 `rag-mcp`와 `windows-triage-mcp`만 stdio로 직접 띄우고 사건 기록은 클라이언트 쪽 스크립트 `claude-code/lite/scripts/case-manager.sh`가 맡으므로 클라이언트 자료로 본다.
사용자가 실행하는 `vhir` 명령(승인·반려 서명, 원장 검증, 설치), `setup-sift.sh`, `quickstart*.sh`, `scripts/`, `deps/`는 사용자 CLI와 설치·개발 도구다.
이 클라이언트 자료, 설정, 사용자 CLI는 상세가 클라이언트 쪽 방식을 묻는 경우, 클라이언트가 MCP 도구 호출을 기록하는 경우, 클라이언트가 서버 기록이나 응답으로 보고 산출물을 만드는 경우에만 구현으로 보고 그 밖에는 원고에 사실로만 적는다.
`tests/`, `docs/`, 각 패키지의 `tests/`는 서버 구현으로 보지 않는다.
README와 문서의 설명(도구 수, 보장 문구, 서명·출처 강제 같은 통제 설명)은 코드로 확인한 것만 사실로 쓴다.

**확인 방법.** 코드는 기준 커밋을 `git show`로 읽었고 `vhir-cli`는 `AppliedIR/Valhuntir`의 `d9ab927`(2026-10-21)로 읽었다.
분석 도구와 라이브러리의 동작은 아래 버전 기준의 소스로 확인했다.
근거의 "실행 확인"은 두 커밋을 `git archive`로 풀어 둔 사본을 Docker 컨테이너에서 실행해 본 결과다.
컨테이너는 SIFT 기준 환경과 같은 `ubuntu:22.04`에 Ubuntu 패키지 Sleuth Kit 4.11.1, ewf-tools, YARA를 설치하고 패키지 9개와 `vhir-cli`를 저장소의 잠금 파일 `deps/vhir.lock`을 제약으로 설치한 것이다(CPython 3.10.12, MCP Python SDK 1.30.0).
`rag-mcp`가 쓰는 torch, chromadb, sentence-transformers는 설치하지 않아 `rag-mcp`는 실행하지 않았다.
`windows-triage-mcp`는 정상 기준 DB를 내려받지 않았고 저장소의 스키마로 만든 빈 DB로는 시작하지 않았다.
설치본에는 `sift-mcp`의 도구 목록 폴더가 들어 있지 않아 실행 확인 때는 소스 사본의 목록 폴더를 `SIFT_CATALOG_DIR`로 지정했다.
승인 원장 폴더 `/var/lib/vhir/ledger`는 이미지에 없어 시험 폴더를 만들어 썼고 검토자 서명 키는 컨테이너 안에서 시험용으로 만들었다.
설치되지 않은 분석 도구는 받은 인자를 기록하는 시험용 실행 파일로 바꿔 서버 쪽 처리만 확인했다.
입력은 컨테이너 안에서 직접 만든 시험용 파일만 썼고 컨테이너는 네트워크를 끈 상태(`--network none`)로 실행했다.

**외부 도구 버전 기준.** `setup-sift.sh`는 SANS SIFT Workstation에서 실행한다고 전제한다. 설치할 때 `AppliedIR/Valhuntir`의 기본 브랜치를 받아 Python 의존성을 `deps/vhir.lock`(2026-10-08 전에 공개된 버전으로 고정)을 제약으로 설치한다.
그래서 Python 의존성은 이 잠금 파일의 버전을 쓴다(MCP Python SDK 1.30.0, pydantic 2.14.0, Starlette 1.7.0, uvicorn 0.54.0, httpx 0.28.1, chromadb 1.5.9, sentence-transformers 6.1.0, torch 2.14.1).
`vhir-cli`는 기준 커밋 시각(2026-10-24 06:39Z) 전 `AppliedIR/Valhuntir` 기본 브랜치의 마지막 커밋 `d9ab927`이다.
SIFT 분석 도구는 기준 커밋 시각 전 마지막 정식 SIFT Workstation 설치 정의인 `teamdfir/sift-saltstack` v2026.10.19를 기준 환경으로 삼는다.
이 설치 정의는 Ubuntu 22.04와 24.04를 모두 지원하고 잠금 파일은 Python 3.10을 하한으로 만들어졌으므로 앞선 SIFT 계열 서버와 같은 Ubuntu 22.04를 쓴다.
SIFT 설치 정의가 고정한 버전을 먼저 쓰고 그다음 Ubuntu 22.04 저장소의 패키지 버전을 쓴다.
받는 때에 따라 버전이 달라지는 것은 공개 시각이 기준 커밋 시각보다 앞선 최신 릴리스를, 버전 없이 기본 브랜치를 받는 것은 기준 커밋 시각 전 마지막 소스 커밋을 쓴다.

- Sleuth Kit 4.11.1, ewf-tools 20140807, YARA 4.1.3, Python 3.10.12: Ubuntu 22.04 패키지다.
- Sleuth Kit 4.11.1의 소스는 태그 `sleuthkit-4.11.1`의 커밋 `16f14f3`, YARA 4.1.3의 소스는 태그 `v4.1.3`의 커밋 `b99a808`로 확인한다.
- MCP Python SDK 1.30.0은 태그 `v1.30.0`의 커밋 `8c2fa6e`, chromadb 1.5.9는 태그 `1.5.9`의 커밋 `11f3c74`, sentence-transformers 6.1.0은 태그 `v6.1.0`의 커밋 `b0bf399`로 확인한다.
- 원고에서 인용한 그 밖의 분석 도구 버전은 이 단락에 더한다.

**바뀔 수 있는 것.** 범위와 외부 도구 버전 기준은 조사하며 맞지 않는 곳이 나오면 검토를 거쳐 바꾼다.
