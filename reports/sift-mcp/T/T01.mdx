# T01 입력 검증

### T01.01 인자 구조·값 검사

**구현.** 이 검사는 게이트웨이와 백엔드 7개의 도구 인자에 적용된다 [1][2][3][4][5][6][7][8].
게이트웨이는 도구 이름이나 인자의 키·값 어디에든 UTF-16 서로게이트 쌍의 한쪽만 있어 UTF-8로 보낼 수 없는 문자가 있으면 백엔드에 보내지 않고 거부한다 [1].
게이트웨이의 MCP 끝점은 `Content-Length`가 없는 POST를 411로, 10MB를 넘는 요청을 413으로 거부하고 REST 도구 호출은 `arguments`가 객체가 아니면 400으로 거부한다 [2].
인자에 서로게이트 문자를 넣은 REST 호출은 백엔드에 가지 않고 `UnsendableArguments` 오류로 끝났다 [9].

백엔드는 각자 다음 값을 검사한다.
- `forensic-mcp`는 제목 500자, 본문 10,000자, 짧은 값 200자를 넘거나 NUL 문자가 있는 문자열을 거부하고 `offset`이 음수이거나 참·거짓 값이면 거부한다 [3].
- `forensic-mcp`의 `record_finding`은 필수 필드, `type`의 4개 값, `confidence_justification`, ISO 8601 꼴의 `event_timestamp`를 검사하고 `confidence`를 규율 자료의 신뢰도 정의와 대조해 어긋나면 `VALIDATION_FAILED`를 돌려준다 [4].
- 같은 도구는 `challenged`가 없으면 `REJECTED`를 돌려준다 [4].
- `case-mcp`는 길이와 NUL 문자를 검사하고 자유 글이 아닌 필드에 `..`가 있으면 거부하며 `case_init`의 `case_id`는 영문·숫자로 시작하는 2~64자의 영문·숫자·하이픈·밑줄이어야 한다 [5].
- `report-mcp`의 `set_case_metadata`는 보호 필드와 모르는 필드를 거부하고 열거 필드는 값 목록과, 날짜 필드는 ISO 8601 꼴과, 목록 필드는 `list`인지 대조한다 [6].
- `windows-triage-mcp`는 경로·이름·해시의 길이 상한과 NUL 문자를 검사해 `validation_error`를 돌려주고 해시 꼴이 아니면 `Invalid hash format`을, 예약 작업·자동 실행 조회에 `os_version`이 없으면 조회하지 않고 오류를 돌려준다 [7].
- `rag-mcp`는 질의 1,000자, 필터 100자, `source_ids` 20개를 넘으면 거부하고 `top_k`가 1보다 작으면 5로, 상한을 넘으면 상한으로 바꾼다 [8].
- `opencti-mcp`는 길이·NUL 문자, UUID 꼴, 라벨, 날짜, 관측값 형식을 검사하고 `limit`·`days`·`offset`은 범위 안으로 바꾼다 [10].
- `opencti-mcp`의 관측값 형식 목록에는 사용자가 `OPENCTI_EXTRA_OBSERVABLE_TYPES`로 더한 형식도 들어간다 [10].
- `sift-mcp`의 `run_command`는 `preview_lines`를 0~200으로 바꾼다 [11].
`case_init`에 `..`가 들어간 `case_id`를, `set_case_metadata`에 목록 밖의 `severity`, 보호 필드, 모르는 필드를 주자 모두 오류로 끝났다 [9].

규율 자료의 신뢰도 정의 파일이 없으면 정의가 빈 값이 되어 `record_finding`은 어떤 `confidence`도 받지 않는다 [4].

**한계.** `opencti-mcp`의 `lookup_ioc`는 길이, 빈 값, NUL 문자만 거부하고 형식을 알아보지 못한 값도 `unknown` 형식으로 조회한다 [10].
`windows-triage-mcp`의 길이 상한은 `WT_MAX_PATH_LENGTH` 같은 환경변수로 바꿀 수 있다 [7].

### T01.02 입력 존재·읽기 가능 검사

**구현.** 이 방식은 `case-mcp`의 `evidence_register`와 `import_bundle`에 적용된다 [12][13].
`evidence_register`는 상대 경로를 사건 폴더 기준으로 바꾼 뒤 그 경로가 없으면 등록하지 않고 `File not found` 오류를 돌려준다 [12].
`import_bundle`은 허용 폴더 대조를 통과한 묶음 파일이 없으면 읽지 않고 오류를 돌려준다 [13].
사건의 `evidence/`에 없는 파일을 `evidence_register`에 주자 `File not found` 오류로 끝났다 [9].

`sift-mcp`의 `run_command`는 명령이 가리키는 입력이 있는지 보고 거부하지 않는다 [14].
있는 파일과 폴더만 입력으로 기록하고 `input_files`로 적은 파일이 없으면 경고만 붙인 채 명령을 실행한다 [14][15].
없는 파일을 `input_files`에 적은 호출은 실행되었고 응답에 `input_files_warning`이 붙었다 [9].

### T01.03 실제 경로로 변환해 허용 폴더 대조

**구현.** 이 방식은 `case-mcp`의 `import_bundle`과 `evidence_register`에 적용된다 [13][16].
`import_bundle`은 `bundle_path`를 `Path.resolve()`로 실제 경로로 바꾸어 지금 사건 폴더나 `/tmp` 아래인지 대조하고 밖이면 거부한 뒤 바꾼 경로로 파일을 읽는다 [13].
`evidence_register`는 `vhir_cli`의 `register_evidence_data`를 불러 경로를 실제 경로로 바꾸고 사건 폴더 안인지 대조한다 [16].
사건 폴더 밖의 파일을 `evidence_register`에, 사건 폴더와 `/tmp` 밖의 파일을 `import_bundle`에 주자 모두 거부되었다 [9].

**한계.** `register_evidence_data`는 실제 경로가 사건 폴더 밖이어도 바꾸기 전 경로가 사건 폴더 안이면 받아들인다 [16].
그래서 사건 폴더 안에 둔 심볼릭 링크는 링크가 가리키는 폴더 밖 파일로 등록된다 [16].
거부 문구는 사건 폴더 밖 파일을 `evidence/`에 복사하거나 그 안에 심볼릭 링크를 만들라고 안내한다 [16].
사건의 `evidence/`에 둔 링크로 사건 폴더 밖 파일을 등록하자 거부되지 않았고 등록 경로는 링크가 가리키는 파일의 경로였다 [9].

### T01.04 문자열 경로 검사

**구현.** 이 방식은 사건 ID와 사건 폴더 이름을 받는 `case-mcp`·`report-mcp`의 인자에 적용된다 [5][17].
`case-mcp`의 `case_status`·`case_activate`와 `report-mcp`의 `generate_report`는 `case_id`에 `..`, `/`, `\`가 있으면 거부한다 [17].
`case-mcp`는 `cases_dir`, `name` 같은 자유 글이 아닌 필드에 `..`가 있으면 거부한다 [5].
`generate_report`와 `case_activate`에 `..`로 시작하는 사건 ID를 주자 `Invalid case ID` 오류로 끝났다 [9].

**한계.** `case-mcp`의 `cases_dir`는 `..`와 길이만 보고 절대 경로는 거부하지 않는다 [5].

### T01.05 등록된 ID와 대조

**구현.** 이 방식은 `forensic-mcp`의 `record_finding`이 받는 `artifacts`에 적용된다 [18].
`artifacts`의 항목마다 `audit_id`를 사건 폴더의 호출 기록에서 읽은 ID 목록과 대조한다 [18].
목록은 사건 폴더 `audit/` 아래 모든 `*.jsonl` 파일 항목의 `audit_id`다 [19].
`case-mcp`의 `log_external_action`이 모델이 알린 대로 남긴 항목의 ID도 이 목록에 들어간다 [19].
`audit_id`가 없으면 바로 `REJECTED`로 거부한다 [18].
`audit_id`가 목록에 없으면 0.1초 뒤 호출 기록을 한 번 더 읽고 그래도 없으면 발견사항을 `REJECTED`로 거부한다 [18].
호출 기록에 없는 `audit_id`를 단 `artifacts`를 준 `record_finding`은 `not found in audit trail` 사유로 거부되었다 [9].

**한계.** 발견사항 본문의 `audit_ids`는 하나씩 거부하지 않는다 [20].
서버는 이 ID를 호출 기록에서 찾아 출처 등급으로 나누고 모두 찾지 못했으면서 `supporting_commands`도 없을 때만 발견사항을 거부한다 [20].
`supporting_commands`를 주면 호출 기록에 없는 `audit_ids`도 거부되지 않고 저장된다 [20].
`challenged`의 검사별 `audit_ids`가 호출 기록에 없거나 발견사항 자신의 ID이면 그 검사를 `not run`으로 저장하고 발견사항은 거부하지 않는다 [21].

### T01.06 고정 입력 경로 사용

**구현.** 이 방식은 사건 기록을 읽는 조회·보고 도구와 기준 자료를 읽는 `windows-triage-mcp`·`rag-mcp`에 적용된다 [22][23].
`forensic-mcp`의 `get_findings`·`get_timeline`, `report-mcp`의 `generate_report`, `case-mcp`의 `evidence_verify`는 경로 인자 없이 지금 사건 폴더의 기록과 증거 등록부에 적힌 경로를 읽는다 [22].
`windows-triage-mcp`는 환경변수 `WT_KNOWN_GOOD_DB`·`WT_CONTEXT_DB`·`WT_REGISTRY_DB`나 `WT_DATA_DIR`이 정한 DB만 읽고 `rag-mcp`는 `RAG_INDEX_DIR`이 정한 색인만 읽는다 [23].

### T01.08 실제 경로로 변환해 금지 폴더 대조

**구현.** 이 방식은 `sift-mcp`의 `run_command`가 받은 명령의 인자에 적용된다 [24][25].
서버는 `/`나 `..`로 시작하거나 `/`가 들어 있는 인자, `--플래그=값`의 값, `-`로 시작하지 않는 맨 이름을 경로로 보고 사건이 있으면 실행별 작업 폴더, 없으면 서버 프로세스의 작업 폴더 기준으로 `Path.resolve()`를 거친 실제 경로로 바꾼다 [24][25][26].
바꾼 경로가 금지 폴더 13곳(`/etc`, `/proc`, `/sys`, `/dev`, `/boot`, `/var/lib/vhir`, `~/.vhir`, `~/.ssh`, `~/.claude` 등) 아래이면 명령을 실행하지 않고 오류를 돌려준다 [25].
금지 폴더 안의 `~/.vhir/cases`와 `~/.vhir/hayabusa-output`은 예외로 받는다 [25].
Sleuth Kit, `dd`, 마운트 도구처럼 장치를 읽는 도구 22개의 `/dev/` 인자와 출력 플래그 뒤의 값은 이 대조를 하지 않는다 [24][27].
`/etc` 아래 파일, `/etc` 아래를 가리키는 링크, 상대 경로로 `/etc`에 닿는 인자, `--file=` 꼴로 준 `/etc` 아래 파일은 모두 실행되지 않고 오류로 끝났다 [9].

**한계.** 서버는 대조에 쓴 실제 경로가 아니라 모델이 준 문자열을 그대로 도구에 넘긴다 [28].
`-`로 시작하고 `=`가 없는 인자는 출력 플래그에 붙여 쓴 꼴만 따로 보고 그 밖에는 경로로 보지 않는다 [24].
옵션과 경로를 한 인자에 붙여 쓴 일부 꼴은 인자 안의 경로를 금지 폴더와 대조하지 않는다 [24].
이런 꼴로 준 금지 폴더 아래 파일은 거부되지 않고 도구가 실행되었다 [9].
셸 해석기에 넘긴 문자열이나 도구가 설정·목록 파일에서 읽는 경로는 대조하지 않는다 [24][29].

```python
def lone_surrogate_in(arguments: dict) -> str | None:
    """The top-level argument with a lone surrogate (half of a UTF-16 pair) in
    a key or a value at any depth, or None. Such text can't be sent as UTF-8:
    the transport fails in its writer task, and the call waits out the call
    timeout. The name comes escaped, so it's safe to show."""
    for top, value in arguments.items():
        stack = [top, value]
        while stack:
            v = stack.pop()
            if isinstance(v, str):
                if _unsendable(v):
                    return ascii(top)
            elif isinstance(v, dict):
                stack.extend(v.keys())
                stack.extend(v.values())
            elif isinstance(v, (list, tuple)):
                stack.extend(v)
    return None
```

```python
def check_sendable(backend_name: str, name: str, arguments: dict | None) -> None:
    """Raise UnsendableArguments, naming what can't be sent, or return."""
    where = "its name" if _unsendable(name) else None
    if where is None and (arg := lone_surrogate_in(arguments or {})) is not None:
```

```python
def _validate_str_length(
    value: str | None, field: str, max_len: int, *, free_text: bool = False
) -> None:
    """Reject strings exceeding max_len, containing null bytes, or path traversal.
```
