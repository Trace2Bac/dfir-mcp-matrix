# T07 도구 부재 처리

### T07.01 실행 전 도구·참조 자료 가용성 검사

**구현.** 이 방식은 `sift-mcp`의 `run_command`, `windows-triage-mcp`의 정상 기준 DB, `rag-mcp`의 색인, `opencti-mcp`의 위협 정보 플랫폼 설정에 적용된다 [1][2][3][4].
`run_command`는 인자 검사를 마친 명령의 첫 인자를 `find_binary`로 찾고 찾지 못하면 실행하지 않는다 [1].
`find_binary`는 `PATH`를 먼저 보고 없으면 정해 둔 폴더 네 곳에서 실행 권한이 있는 파일을 찾는다 [5].
실행 확인에서 설치되지 않은 이름으로 `run_command`를 부르자 프로그램을 실행하지 않고 오류로 끝났다 [6].

`windows-triage-mcp`는 시작할 때 `known_good.db`와 `context.db`를 읽기 전용으로 열고 두 DB의 통계를 읽어 본다 [2].
열지 못하거나 통계를 읽지 못하면 `DatabaseError`로 끝나고 서버는 종료 코드 1로 멈춘다 [2][7].
실행 확인에서 DB가 없는 컨테이너의 `windows-triage-mcp`는 `Database error: SQLite error during validation: unable to open database file`을 남기고 시작하지 않았다 [8].
레지스트리 기준 DB `known_good_registry.db`는 없어도 시작하고 `check_registry`가 부를 때마다 DB를 쓸 수 있는지 확인한다 [9].

`rag-mcp`는 첫 호출에서 색인을 열기 전에 색인 폴더 아래 `chroma` 폴더가 있는지 확인하고 없으면 열지 않는다 [3].

`opencti-mcp`는 시작할 때 `THREATINTEL_PROVIDERS`에 적힌 플랫폼마다 설정을 읽는다 [10].
설정이 없거나 모듈을 불러오지 못한 플랫폼은 요청을 보내지 않는 `Unavailable` 객체로 둔다 [4].
OpenCTI 설정이 없으면 OpenCTI만 읽는 도구 7개는 요청 없이 끝난다 [11].
시작할 때 OpenCTI 연결 시험이 시간 안에 끝나지 않거나 연결되지 않으면 `_degraded`를 참으로 두고 그 뒤 OpenCTI 클라이언트 호출은 요청 없이 `DegradedError`로 끝낸다 [12].

**한계.** `windows-triage-mcp`는 환경변수 `WT_SKIP_DB_VALIDATION`이 참이면 시작할 때 DB 통계를 읽지 않고 DB를 쓰기 가능으로 연다 [13].
`opencti-mcp`의 시작 연결 시험은 환경변수 `FF_STARTUP_VALIDATION`으로 끌 수 있다 [14].
`lookup_ioc`는 이 연결 시험의 결과를 쓰지 않고 플랫폼마다 따로 요청한다 [15].
`run_command`는 실행 파일만 찾고 그 도구가 읽는 룰, 맵, 심볼 같은 참조 자료는 확인하지 않는다 [1].

### T07.02 대체 없는 실패 처리·도구 부재 알림

**구현.** 이 방식은 `sift-mcp`의 `run_command`와 `get_tool_help`, `windows-triage-mcp`의 `check_registry`, `rag-mcp`의 색인 부재, `opencti-mcp`의 플랫폼 설정 부재에 적용된다 [1][16][9][17][11].
`run_command`는 실행 파일을 찾지 못하면 `Binary '<이름>' not found on this system.`을 `error`에 싣고 `success`를 거짓으로 돌려준다 [1][18].
실행을 시작할 때 실행 파일이 사라졌으면 `Binary not found: <경로>`를 돌려준다 [19].
`get_tool_help`는 카탈로그 도구가 설치되지 않았으면 `available`을 거짓으로 두고 도움말을 싣지 않는다 [16].
실행 확인에서 설치되지 않은 이름의 `run_command` 응답은 `Binary 'nosuchtool_t2' not found on this system.`이었고 Hayabusa의 `get_tool_help` 응답은 `available`이 거짓이었다 [6].

`check_registry`는 레지스트리 기준 DB가 없으면 `Registry database not available`과 설치 안내를 돌려주고 `lookup_performed`를 거짓으로 둔다 [9].
`rag-mcp`는 색인 폴더가 없으면 `Index not found`와 색인을 만드는 명령 `python -m rag_mcp.build`를 담은 문구를 `internal_error`로 돌려준다 [3][17].
`opencti-mcp`는 OpenCTI 설정이 없으면 OpenCTI만 읽는 도구에서 `opencti_not_configured`와 그 사유를 돌려준다 [11].
`lookup_ioc`는 쓸 수 없는 플랫폼을 `providers.<이름>`의 `outcome` `UNAVAILABLE`과 사유 `reason`으로 알린다 [4][15].
`DegradedError` 문구는 플랫폼에 닿지 못한 사유와 백엔드를 다시 시작하는 `vhir service restart` 명령을 적는다 [12].
실행 확인에서 OpenCTI 설정 없이 부르자 `search_threat_intel`과 `get_entity`는 `opencti_not_configured`를, `lookup_ioc`는 `providers.opencti.reason`에 토큰이 없다는 문구를 돌려줬다 [20].

**한계.** `windows-triage-mcp`는 정상 기준 DB가 없으면 시작하지 않으므로 그 도구를 부른 호출에는 DB가 없다는 문구가 오지 않는다 [2][7].

### T07.03 알림 없는 대체 실행

**구현.** 이 방식은 `opencti-mcp`의 `search_threat_intel`이 지표를 찾는 단계에 적용된다 [21][22].
`search_threat_intel`이 부르는 `search_indicators`는 회로 차단기가 열렸거나 질의가 실패하면 같은 질의의 만료된 캐시 항목을 찾아 돌려준다 [21].
이 캐시는 환경변수 `FF_RESPONSE_CACHING`을 켰을 때만 채워진다 [23].
대체하면 클라이언트 객체의 `_last_response_degraded`를 참으로 두지만 서버는 이 값을 읽지 않고 응답에도 싣지 않는다 [21][24].
이 경로는 코드로만 확인했고 OpenCTI 서버에 연결하는 실행은 하지 않았다.

### T07.04 실행 환경별 경로 분기

**구현.** 이 방식은 `sift-mcp`가 실행 파일을 찾는 `find_binary`, Zimmerman 도구의 실행 방식, 버전·도움말을 묻는 실행 파일 선택에 적용된다 [5][25][26].
`find_binary`는 `shutil.which`로 `PATH`를 먼저 보고 없으면 `/usr/local/bin`, `/opt/zimmerman`, `/opt/volatility3`, `/opt/hayabusa` 차례로 실행 권한이 있는 파일을 찾는다 [5].
`run_command`는 Zimmerman 도구의 래퍼를 찾은 뒤 `dotnet`이 있고 `/opt/zimmermantools` 아래에 `<도구>.dll`이 있으면 래퍼 대신 `dotnet <도구>.dll`로 실행한다 [25][1].
`get_tool_help`와 `check_tools`는 카탈로그의 `binary`를 먼저 찾고 없으면 다른 버전이 설치하는 이름 `other_binaries`를 차례로 찾는다 [26][27].
고른 경로는 응답과 호출 기록의 `resolved_path`에 남는다 [28].

**한계.** 설정 객체는 환경변수 `SIFT_TOOL_PATHS`의 폴더를 `tool_paths`에 더하지만 `find_binary`는 이 값을 읽지 않는다 [29][5].
실행 확인에서 `SIFT_TOOL_PATHS`가 가리키는 폴더에만 둔 실행 파일을 `run_command`로 부르자 찾지 못했다는 오류가 왔다 [6].
`run_command`는 명령에 적힌 이름 하나만 찾으므로 `other_binaries`의 이름으로 바꿔 실행하지 않는다 [1][26].

### T07.08 일부 제외 후 계속 실행

**구현.** 이 방식은 `rag-mcp`의 사용자 문서 저장소와 `opencti-mcp`의 `lookup_ioc`에 적용된다 [30][4].
`rag-mcp`는 다음 경우에 사용자 문서 저장소를 빼고 기본 색인만 검색한다 [30].

- 사용자 문서 저장소가 아직 만들어지지 않았다 [30].
- 사용자 문서 저장소의 임베딩 모델이나 거리 방식이 기본 색인과 다르다 [30].
- 사용자 문서 저장소가 열리지 않는다 [30].

이때 검색 응답의 `notice`나 `warning`에 뺀 사실과 다시 만드는 명령을 싣는다 [30][31].
`lookup_ioc`는 설정한 플랫폼 가운데 쓸 수 없는 플랫폼을 `UNAVAILABLE`로 두고 나머지 플랫폼의 답을 함께 돌려준다 [4][15].
최상위 `outcome`은 한 플랫폼이라도 일치하면 `MATCH`이고 일치가 없고 쓸 수 없는 플랫폼이 있으면 `UNAVAILABLE`이다 [32].

### T07.09 별도 점검 도구로 가용성 알림

**구현.** 이 방식은 `sift-mcp`의 `check_tools`·`list_available_tools`, `windows-triage-mcp`의 `get_db_stats`·`get_health`, `opencti-mcp`의 `get_health`에 적용된다 [27][33][34][35][11].
`check_tools`는 카탈로그 도구마다 `probe`로 실행 파일을 찾아 버전을 묻고 `available`, `binary_path`, `installed_version`, `resolved_path`를 돌려준다 [27].
설치된 버전이 카탈로그의 시험된 버전 범위 밖이면 `outside_tested_ranges`와 `tested_ranges`를 더한다 [27].
`list_available_tools`는 카탈로그 도구마다 실행 파일을 찾아 `available`과 `binary_path`를 싣는다 [33].
`get_db_stats`는 레지스트리 기준 DB가 없으면 `registry_db.available`을 거짓으로 둔다 [34].
`get_health`는 정상 기준 DB 두 개에 통계 질의를 보내 DB마다 `healthy`나 오류 이름을 돌려준다 [35].
`opencti-mcp`의 `get_health`는 OpenCTI에 닿는지를 `opencti_available`로 돌려준다 [11].
실행 확인에서 `check_tools`는 Sleuth Kit의 `fls`와 `mmls`를 `available` 참과 버전 `4.11.1`로, `vol`과 `hayabusa`를 `available` 거짓으로 돌려줬다 [6].
분석 도구는 이 결과로 막지 않는다.

**한계.** `check_tools`는 카탈로그에 없는 이름이면 설치되었는지 보지 않고 `available`을 거짓으로 두고 실행은 할 수 있다는 `note`를 붙인다 [27].
`opencti-mcp`의 `get_health`는 OpenCTI 클라이언트만 보고 `lookup_ioc`가 묻는 MISP 같은 다른 플랫폼은 보지 않는다 [11][4].
`windows-triage-mcp`의 두 점검 도구는 서버가 시작된 뒤에만 부를 수 있고 정상 기준 DB가 없으면 서버가 시작하지 않는다 [2][7].
`rag-mcp`에는 점검 도구가 없고 `get_knowledge_stats`는 색인이 없으면 색인 부재 오류를 돌려준다 [36][17].

```python
def find_binary(name: str, extra_paths: list[str] | None = None) -> str | None:
    """Find a binary on PATH or in common forensic tool locations."""
    # shutil.which checks PATH
    found = shutil.which(name)
    if found:
        return found

    # Check extra paths
    search_paths = extra_paths or [
        "/usr/local/bin",
        "/opt/zimmerman",
        "/opt/volatility3",
        "/opt/hayabusa",
    ]
    for d in search_paths:
        candidate = Path(d) / name
        if candidate.is_file() and os.access(candidate, os.X_OK):
            return str(candidate)

    return None
```
