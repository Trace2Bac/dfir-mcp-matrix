# T05 분석 도구 검증

### T05.01 저장소·의존성 고정

**구현.** 이 방식은 저장소에 함께 넣은 참조 자료 `forensic-knowledge`와 `sift-mcp`의 도구 카탈로그에 적용된다 [1][2].
`forensic-knowledge`의 YAML은 도구별 주의 사항과 조언, 아티팩트가 보여 주는 것과 보여 주지 않는 것, 분석 규율과 신뢰도 정의를 담고 저장소 커밋으로 내용이 정해진다 [1].
`sift-mcp`와 `forensic-mcp`는 이 자료를 응답에 싣거나 발견사항 검사의 기준으로 쓴다 [1][3].
`sift-mcp`의 카탈로그 YAML은 도구 정의, 시험한 명령 예시 `recipes`와 그 예시를 시험한 버전 범위, 실행 검사 목록 `security.yaml`을 담는다 [2].

이 방식은 분석 도구와 다른 참조 자료에는 적용되지 않는다.
`setup-sift.sh`는 Python 의존성을 잠금 파일 `deps/vhir.lock`의 버전과 해시로 설치하지만 이 파일이 고정하는 서버 범위의 라이브러리는 MCP SDK, chromadb, sentence-transformers 같은 서버 실행·지식 검색용 라이브러리다 [4][5].
`run_command`가 실행하는 SIFT 분석 도구는 SIFT Workstation에 설치된 것을 쓰고 저장소는 그 버전을 정하지 않는다 [6].
`windows-triage-mcp`의 기준 DB와 `rag-mcp`의 색인을 받는 스크립트는 기본값으로 이름이 `triage-db-`·`rag-index-`로 시작하는 가장 최근 릴리스를 받는다 [7][8].
두 스크립트는 받은 파일을 같은 릴리스에 함께 올린 체크섬 파일과 대조하고 체크섬 파일이 없으면 대조를 건너뛴다 [7][8].
`rag-mcp`의 임베딩 모델은 이름 `BAAI/bge-base-en-v1.5`만 코드에 있고 모델 파일의 리비전이나 해시는 정하지 않는다 [9].

### T05.02 설정·호출 인자로 지정

**구현.** 이 방식은 백엔드마다 도구와 참조 자료의 위치를 정하는 환경변수와 게이트웨이의 `PATH`에 적용된다 [10][11][12][13][14][15].
- `sift-mcp`는 `SIFT_CATALOG_DIR`가 가리키는 폴더가 있으면 그 폴더의 카탈로그와 `security.yaml`을 읽는다 [10].
- `sift-mcp`는 실행 파일을 `PATH`에서 먼저 찾고 없으면 `/usr/local/bin`, `/opt/zimmerman`, `/opt/volatility3`, `/opt/hayabusa`에서 찾는다 [11].
- 게이트웨이는 백엔드를 실행하기 전에 `~/.local/bin`을 `PATH` 앞에 넣어 SIFT가 그 폴더에 설치하는 Hayabusa, capa, floss, chainsaw를 찾게 한다 [12].
- `forensic-knowledge`는 `FK_DATA_DIR`가 가리키는 폴더가 있으면 그 폴더의 자료를 읽는다 [13].
- `windows-triage-mcp`는 `WT_DATA_DIR`, `WT_KNOWN_GOOD_DB`, `WT_CONTEXT_DB`, `WT_REGISTRY_DB`로 기준 DB의 위치를 정한다 [14].
- `rag-mcp`는 `RAG_INDEX_DIR`로 색인 위치를, `RAG_MODEL_NAME`으로 임베딩 모델을 정한다 [15].
- `rag-mcp`의 `RAG_MODEL_NAME`은 허용 모델 5개 가운데 하나여야 하고 목록 밖이면 모델을 불러오지 않는다 [16][17].
- `opencti-mcp`는 `OPENCTI_URL`, `MISP_URL`, `THREATINTEL_PROVIDERS`로 조회할 위협 정보 플랫폼의 주소와 목록을 정한다 [18].
이 값들은 위치나 이름만 정하고 그 내용의 버전은 정하지 않는다.

**한계.** `SIFT_TOOL_PATHS`와 `SIFT_HAYABUSA_DIR`는 설정 객체의 값으로 읽히지만 실행 파일을 찾는 `find_binary`는 이 값을 쓰지 않는다 [19][11].

### T05.03 실행 시 버전 조회

**구현.** 이 방식은 `sift-mcp`의 카탈로그 도구 실행과 `opencti-mcp`의 `lookup_ioc`에 적용된다 [20][21][22].
`sift-mcp`는 `run_command`가 카탈로그 도구를 실행할 때마다 명령이 가리키는 실행 파일에 버전을 묻고 결과를 저장해 두지 않는다 [20][21].
버전은 카탈로그의 `version_argv`, `--version`, `-V` 차례로 실행해 출력에서 처음 나오는 버전 꼴 문자열로 읽는다 [21].
`get_tool_help`와 `check_tools`도 같은 방법으로 실행 파일에 버전을 묻는다 [23].
Sleuth Kit `fls`의 버전은 4.11.1로 읽혔다 [24].

`opencti-mcp`의 `lookup_ioc`는 조회 질의에 OpenCTI의 `about { version }`을 함께 넣어 조회할 때마다 OpenCTI 버전을 읽는다 [22].
MISP 버전은 `/servers/getVersion`으로 읽고 앞서 읽은 지 1분이 지나지 않았으면 앞서 읽은 값을 쓴다 [22][25].
남은 조회 시간이 모자라거나 다른 조회가 읽는 중일 때도 앞서 읽은 값을 쓴다 [25].
두 버전은 각 플랫폼의 응답에 실린다 [22][25].

**한계.** 카탈로그에 없는 실행 파일은 버전을 묻지 않는다 [20].
출력에서 버전 꼴 문자열을 찾지 못하면 `unknown`으로 둔다 [21].

### T05.05 사용 전 기대값 대조

**구현.** 이 방식은 `rag-mcp`가 사용자 문서 저장소를 열 때 적용된다 [26].
사용자가 더한 문서 색인은 `metadata.json`에 적힌 임베딩 모델과 거리 함수(`hnsw:space`)를 기본 색인의 값과 대조하고 다르면 검색에서 빼고 경고를 남긴다 [26].
RAG 검색 서버는 실행하지 않았고 코드로만 확인했다.

**한계.** 대조하는 값은 메타데이터에 적힌 이름이고 색인 파일의 해시는 대조하지 않는다 [26].
서버는 `RAG_MODEL_NAME`으로 정한 모델을 기본 색인의 `metadata.json`에 적힌 모델과 대조하지 않는다 [16][26].

### T05.06 시험 버전 범위 대조·표시

**구현.** 이 방식은 `sift-mcp`의 `get_tool_help`와 `check_tools`에 적용된다 [23].
두 도구는 실행 파일에서 읽은 버전을 카탈로그 `recipes`마다 적힌 시험 버전 범위와 대조한다 [23][2].
`get_tool_help`는 읽은 버전이 범위에 맞는 `recipes`만 보여 주고 나머지는 시험한 범위만 적어 따로 둔다 [23].
맞는 범위가 하나도 없으면 `recipe_note`에 그 버전의 예시가 없다는 사실과 시험한 범위를 적는다 [23].
`check_tools`는 `recipes`가 있는 도구의 버전이 어느 범위에도 맞지 않으면 `outside_tested_ranges`와 `tested_ranges`를 붙인다 [23].
범위 밖 버전이어도 실행을 막지 않는다 [23][24].
카탈로그의 시험 범위 밖 버전을 출력하는 시험용 `hayabusa`를 `PATH` 앞에 두자 `check_tools`가 `outside_tested_ranges`를 붙였고 `run_command`는 그 실행 파일을 실행했다 [24].
`run_command`는 실행할 때 버전을 읽기만 하고 이 범위와 대조하지 않는다 [20].

**한계.** 버전을 읽지 못해 `unknown`이 된 도구에는 어느 `recipes` 범위도 맞지 않는다 [21][23].
범위가 빈 `recipes`는 어느 버전과도 맞지 않는 것으로 본다 [23].

```python
def _find_catalog_dir() -> Path:
    """Locate the data/catalog directory."""
    global _CATALOG_DIR
    if _CATALOG_DIR is not None:
        return _CATALOG_DIR

    env = os.environ.get("SIFT_CATALOG_DIR")
    if env:
        p = Path(env)
        if p.is_dir():
            _CATALOG_DIR = p
            return p

    # Relative to this file: src/sift_mcp/catalog.py → ../../data/catalog/
    source = Path(__file__).resolve().parent.parent.parent / "data" / "catalog"
    if source.is_dir():
        _CATALOG_DIR = source
        return source
```

```python
def find_binary(name: str, extra_paths: list[str] | None = None) -> str | None:
    """Find a binary on PATH or in common forensic tool locations."""
    # shutil.which checks PATH
    found = shutil.which(name)
    if found:
        return found

    # Check extra paths
    search_paths = extra_paths or [
        "/usr/local/bin",
        "/opt/zimmerman",
        "/opt/volatility3",
        "/opt/hayabusa",
    ]
    for d in search_paths:
        candidate = Path(d) / name
        if candidate.is_file() and os.access(candidate, os.X_OK):
            return str(candidate)

    return None
```
