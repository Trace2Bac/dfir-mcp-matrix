# T04 실행 방식

### T04.01 서버 프로세스 안 분석

**구현.** 이 방식은 `windows-triage-mcp`, `rag-mcp`, `forensic-mcp`, `case-mcp`의 분석과 `sift-mcp`의 큰 출력 파싱에 적용된다 [1][2][3][4][5].
`windows-triage-mcp`는 기준 DB를 서버 프로세스 안의 `sqlite3` 연결로 읽기 전용으로 열어 경로·해시·서비스·예약 작업을 조회하고 파일 이름 분석도 서버 코드로 한다 [1].
`rag-mcp`는 sentence-transformers 모델을 서버 프로세스에 불러 질의를 임베딩하고 chromadb `PersistentClient`로 색인을 검색한다 [2].
`forensic-mcp`는 `record_finding`의 인용 대조와 출처 추적을 사건 폴더의 호출 기록과 파일을 읽는 서버 코드로 한다 [3].
`case-mcp`는 증거 해시를 서버 프로세스 안에서 계산하고 큰 파일은 같은 프로세스의 데몬 스레드에서 계산한다 [4].
`sift-mcp`는 도구의 표준 출력이 응답 상한을 넘으면 서버 안의 CSV·JSON·텍스트 파서로 미리보기를 만든다 [5].
`opencti-mcp`는 위협 정보 플랫폼에 HTTP로 조회하고 분석 작업을 원격에 맡기지 않는다 [6].

### T04.02 같은 권한의 별도 프로세스

**구현.** 이 방식은 `sift-mcp`의 `run_command`와 버전·도움말 실행에 적용된다 [7][8][9].
`run_command`는 검사를 마친 명령의 첫 인자를 `find_binary`가 `PATH`에서 찾은 실행 파일 경로로 바꾸고 인자 목록 그대로 `subprocess.Popen`에 넘긴다 [7][8].
`shell=True`는 쓰지 않고 자식 프로세스는 서버와 같은 계정과 환경에서 실행된다 [8].
EZ Tools는 `.dll`이 설치되어 있으면 `dotnet <도구>.dll`로 실행한다 [7].
`get_tool_help`, `check_tools`, `run_command`의 버전 조회는 카탈로그의 인자로 도구를 `Popen`에 표준 입력 없이 실행하고 10초 안에 끝나지 않으면 종료시킨다 [9].
컨테이너에서 `run_command`로 `pwd`와 `fls -V`를 실행하자 분석 도구가 서버와 같은 사용자로 실행되어 결과를 돌려주었다 [10].

모델이 `bash -c`를 명령으로 주면 서버는 셸 해석기를 같은 방식으로 실행하고 셸이 그 문자열을 해석한다 [11][10].
서버 코드는 `sudo`를 붙여 도구를 실행하지 않고 거부 목록에도 `sudo`가 없다 [7][12].
모델이 관리자 권한으로 실행하는 명령을 앞에 붙였을 때 권한이 바뀌는지는 서버 계정의 설정에 달려 있고 확인하지 못했다.

### T04.05 실행별 작업 폴더

**구현.** 이 방식은 사건이 있을 때 실행하는 `sift-mcp`의 `run_command`에 적용된다 [13][14].
서버는 호출마다 호출 기록 ID를 먼저 정하고 사건 폴더 아래 `extractions/<호출 기록 ID>/`를 빈 폴더로 만든다 [13].
명령의 상대 경로는 이 폴더 기준으로 해석하고 도구는 이 폴더를 작업 위치(`cwd`)로 실행된다 [13][14].
실행이 끝나면 이 폴더의 파일을 그 실행의 출력으로 기록한다 [15].
사건이 있을 때 `pwd`를 실행하자 `extractions/<호출 기록 ID>`가 출력되었다 [10].
폴더는 명령 검사보다 먼저 만들어지므로 거부된 호출의 폴더도 빈 채로 남았다 [10][13].

**한계.** 사건이 없으면 실행별 폴더를 만들지 않고 서버 프로세스의 작업 폴더에서 실행한다 [13].
사건 없이 `pwd`를 실행하자 서버 프로세스의 폴더가 출력되었다 [10].
폴더를 만들지 못하면 경고만 남기고 서버 프로세스의 작업 폴더에서 실행하며 같은 이름의 폴더가 이미 있으면 그 폴더를 그대로 쓴다 [13].
