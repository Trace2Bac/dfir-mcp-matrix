# T10 도구 명세 구성

### T10.01 처리 함수에서 명세 생성

**구현.** 이 방식은 `forensic-mcp`, `sift-mcp`, `case-mcp`, `report-mcp`의 도구와 `forensic-mcp`의 리소스에 적용된다 [1].
네 서버는 MCP Python SDK의 `FastMCP`에 도구 함수마다 `@server.tool()`을 붙이고 입력 schema를 따로 주지 않는다 [1].
MCP Python SDK 1.30.0의 `FastMCP`는 함수 이름을 도구 이름으로, docstring을 설명으로 쓰고 함수 서명에서 입력 schema를 만든다 [2].
`forensic-mcp`의 `get_procedure`만 설명을 `description` 인자로 따로 준다 [3].
실행 확인에서 도구 수는 `forensic-mcp` 10개, `sift-mcp` 5개, `case-mcp` 16개, `report-mcp` 6개였고 설명이 빈 도구는 없었다 [4].
`forensic-mcp`는 규율 자료를 `@server.resource`로 등록해 리소스 8개와 리소스 템플릿 6개를 낸다 [5][4].

`forensic-mcp`의 `record_finding`은 발견사항을 `finding: dict` 하나로 받고 `record_timeline_event`는 사건을 `event: dict` 하나로 받는다 [6].
입력 schema에는 두 인자가 필드 없는 객체(`additionalProperties` 참)로 실리고 넣어야 할 필드는 docstring에만 있다 [6][4].
네 서버의 도구에는 annotation과 출력 schema가 없고 초기화 응답의 `tools.listChanged`는 거짓이다 [4].

### T10.02 처리기와 따로 둔 명세

**구현.** 이 방식은 `windows-triage-mcp`의 도구 13개, `rag-mcp`의 도구 3개, `opencti-mcp`의 도구 8개와 `forensic-mcp`의 `get_procedure` 설명에 적용된다 [7][8][9][3].
세 서버는 MCP Python SDK의 저수준 `Server`에 `list_tools` 처리기를 달고 도구 이름, 설명, 입력 schema를 코드 안의 `Tool` 객체로 적는다 [7][8][9].
실제 처리는 `call_tool` 처리기가 도구 이름으로 갈라 부르는 함수가 한다 [10][11][12].
schema와 처리 함수를 대조하는 장치는 없다.
실행 확인에서 `opencti-mcp`의 도구 8개에는 annotation과 출력 schema가 없었다 [4].

`get_procedure`의 설명은 서버를 불러올 때 저장소 체크아웃의 `skills/MANIFEST`에서 읽은 절차 이름으로 만든다 [3][13].
이 파일이 없으면 설명은 절차가 설치되지 않았다고 적는다 [13].
실행 확인에서 패키지만 설치한 컨테이너의 `get_procedure` 설명은 `procedures aren't installed with this forensic-mcp`로 끝났다 [4].

**한계.** `windows-triage-mcp`의 `get_db_stats` 설명은 DB마다 기록 수, 쓸 수 있는 OS 버전, 마지막 갱신 시각을 돌려준다고 적는다 [14].
처리 함수는 표마다 항목 수만 세고 갱신 시각은 돌려주지 않는다 [15][16].
`get_health` 설명은 메모리 사용량을 돌려준다고 적지만 처리 함수의 결과에는 메모리 값이 없다 [14][17].

### T10.03 묶음 도구의 연산별 인자를 schema가 구분하지 않음

**구현.** 이 방식은 `sift-mcp`의 `run_command`와 `opencti-mcp`의 `search_entity`에 적용된다 [18][19].
`run_command`의 입력 schema는 명령을 문자열 목록 `command` 하나로 받고 카탈로그 도구 65개와 카탈로그 밖 프로그램을 모두 이 인자로 실행한다 [18][4][20].
도구마다 다른 인자는 schema에 없다 [4].
카탈로그의 시험된 명령 예시 `recipes`와 설치된 도구의 도움말은 `get_tool_help`가 돌려주고 그 설명은 명령을 만들기 전에 부르라고 적는다 [21].

`search_entity`는 `type`으로 OpenCTI 조회 함수 16개 가운데 하나를 골라 부른다 [22].
입력 schema는 `type`마다 쓰는 인자를 나누지 않는다 [19].
처리기는 `confidence_min`을 4개 `type`에서만, `offset`·`labels`·날짜 인자를 9개 `type`에서만 읽는다 [23][24].
`observable`에서 읽는 `observable_types`는 입력 schema에 없다 [19][24].

### T10.04 실행 설정·클라이언트별 명세 변경

**구현.** 이 방식은 `forensic-mcp`의 시작 인자 `--deferred-tools`와 게이트웨이의 끝점 선택에 적용된다 [25][26].
`forensic-mcp`는 기본으로 규율 자료를 리소스 8개와 리소스 템플릿 6개로 내고 `--deferred-tools`로 시작하면 같은 자료를 도구 14개로 낸다 [25][5][27].
게이트웨이 설정 예시는 `forensic-mcp`를 `--deferred-tools`로 시작한다 [28].
실행 확인에서 `--deferred-tools`로 시작한 `forensic-mcp`의 도구는 24개였고 리소스는 없었다 [4].

게이트웨이는 모든 백엔드의 도구를 모은 묶음 끝점 `/mcp`와 백엔드마다 끝점 `/mcp/<백엔드>`를 둔다 [26].
묶음 끝점은 초기화 응답에 게이트웨이 지침 `GATEWAY`를 싣고 백엔드별 끝점은 그 백엔드의 지침을 싣는다 [29].
백엔드별 끝점은 그 백엔드의 도구 목록을 그대로 내고 이름이 겹치는 도구의 접두어는 묶음 끝점에만 붙는다 [30][31].
실행 확인에서 같은 게이트웨이의 묶음 끝점은 도구 37개와 1273자 지침을, `sift-mcp`의 백엔드별 끝점은 도구 5개와 4277자 지침을 냈다 [32].
두 끝점에서 `sift-mcp` 도구의 이름, 설명, 입력 schema는 같았다 [32].
사용자 CLI의 `vhir setup client`는 게이트웨이에 닿으면 실행 중인 백엔드마다 백엔드별 끝점을 클라이언트 설정에 쓰고 닿지 못하면 묶음 끝점을 쓴다 [33].

### T10.05 등록 이름 변환

**구현.** 이 방식은 게이트웨이의 묶음 끝점에 적용된다 [31].
게이트웨이는 시작된 백엔드의 도구 이름을 모아 두 백엔드 이상이 같은 이름을 내면 모두 `<백엔드>__<도구>`로 바꾼다 [31].
`windows-triage-mcp`와 `opencti-mcp`는 모두 `get_health`라는 도구를 둔다 [7][9].
게이트웨이 설정 예시는 두 백엔드를 `windows-triage-mcp`와 `threatintel-mcp`라는 이름으로 켠다 [34].
호출을 넘길 때는 접두어를 떼고 백엔드의 원래 이름으로 부른다 [35].
실행 확인에서 `sift-mcp`를 두 이름으로 붙이자 묶음 끝점의 도구 5개가 모두 `sift-mcp__`와 `sift-copy__` 접두어를 달았고 접두어 없는 `run_command` 호출은 `unknown tool`로 끝났다 [36].

묶음 끝점의 명세는 백엔드 도구의 이름, 설명, 입력 schema만 옮겨 새 `Tool`로 만든다 [37].
게이트웨이는 백엔드가 늦게 시작되거나 유휴로 멈추면 도구 표를 다시 만든다 [38].
게이트웨이 초기화 응답의 `tools.listChanged`는 거짓이다 [36].

```python
    def get_stats(self) -> dict[str, Any]:
        """Get database statistics."""
        conn = self.connect()

        stats = {
            "os_versions": 0,
            "files": 0,
            "hashes": 0,
            "services": 0,
            "tasks": 0,
            "autoruns": 0,
        }

        for table, key in [
            ("baseline_os", "os_versions"),
            ("baseline_files", "files"),
            ("baseline_hashes", "hashes"),
            ("baseline_services", "services"),
            ("baseline_tasks", "tasks"),
            ("baseline_autoruns", "autoruns"),
        ]:
            try:
                cursor = conn.execute(f"SELECT COUNT(*) FROM {table}")
                stats[key] = cursor.fetchone()[0]
            except sqlite3.OperationalError:
                stats[key] = 0

        return stats
```
