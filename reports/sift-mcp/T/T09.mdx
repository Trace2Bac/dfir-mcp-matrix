# T09 대상 시스템 대응 조치 처리

### 비적용

**판단.** 서버는 조사하는 대상 시스템의 격리, 차단, 프로세스 종료, 계정 잠금, 파일 삭제, 설정 변경을 하는 도구를 두지 않는다.
`forensic-mcp`, `case-mcp`, `report-mcp`의 도구는 사건 폴더의 발견사항, 타임라인, 할 일, 증거 목록, 보고서를 읽고 쓴다 [1][2][3].
`windows-triage-mcp`와 `rag-mcp`는 서버 안의 정상 기준 DB와 지식 색인을 읽는다 [4][5].
`opencti-mcp`의 도구 8개는 위협 정보 플랫폼에 조회 요청만 보내고 서버 클래스의 설명도 읽기 전용이라고 적는다 [6].

`sift-mcp`의 `run_command`는 SIFT 워크스테이션에서 분석 도구를 실행하는 범용 실행 도구다 [7].
실행을 거부하는 이름은 파일 시스템 생성, 시스템 종료, 프로세스 종료, 환경변수 출력, 원시 소켓 도구다 [8].
도구 설명은 `curl`, `wget`, `dd`, `fdisk`, `python3`도 실행할 수 있다고 적는다 [7].
거부 목록에는 `ssh`, `curl`, `wget` 같은 원격 접속·전송 도구가 없다 [8].
이 도구가 실행한 명령은 다른 분석 실행과 같이 `run_command` 호출 기록 항목으로 남고 서버는 대상 시스템 조치로 따로 다루지 않는다 [9].
`run_command`가 실행하는 마운트·해제 도구는 SIFT 워크스테이션의 마운트를 바꾸고 증거 이미지를 대상으로 한다 [10].

`case-mcp`의 `log_external_action`은 서버 밖에서 실행한 명령을 모델이 알린 대로 기록하는 도구이고 서버가 조치를 실행하지 않는다 [11].
Windows 분석 워크스테이션에서 도구를 실행하는 `wintools-mcp`는 게이트웨이 설정 예시에서 기본으로 꺼진 별도 원격 백엔드이고 이 서버의 범위 밖이다 [12].
그래서 조치 전후 상태, 변경 내역, 되돌림을 남길 대상 시스템 조치가 없다.

        Most SIFT-installed tools can be executed including curl, wget, dd,
        fdisk, and python3. Only mkfs, shutdown, kill, and raw socket
        tools (nc/ncat) are blocked. Tools in the forensic catalog
        get enriched responses with caveats and corroboration suggestions.
        In a case the command runs in its own empty folder,
        extractions/<audit_id>/, so a relative path means a path there.
        Give parallel runs distinct output folders: files new in a folder two

        Deleting or overwriting case records, audit/ or evidence files is refused;
        bash -c, python -c, dd and a tool's own output options are not checked.

  - "mkfs"

  - "mkfs.xfs"
  - "mkfs.btrfs"
  - "mkfs.ntfs"
  # System state — no forensic use

  - "reboot"
  - "poweroff"
  - "halt"
  - "init"

  - "kill"
  - "killall"
  - "pkill"

  - "printenv"
  # Raw sockets — no forensic use via run_command

  - "ncat"
