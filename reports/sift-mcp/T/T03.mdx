# T03 실행 조건 확인

### T03.01 선행 결과 대조

**구현.** 이 방식은 사건 기록을 다루는 `forensic-mcp`, `case-mcp`, `report-mcp`의 도구에 적용된다 [1][2][3].
세 백엔드는 도구를 실행하기 전에 지금 사건을 찾고 찾지 못하면 기록을 읽거나 쓰지 않고 오류를 돌려준다 [1][2][3].
`forensic-mcp`의 `_require_active_case`는 `~/.vhir/active_case`가 가리키는 폴더에 `CASE.yaml`이 있는지 보고 없으면 `No active case` 오류를 낸다 [1].
같은 함수는 `CASE.yaml`의 `status`가 `closed`이면 닫힌 사건이라는 오류를 내고 발견사항, 타임라인 사건, 할 일을 기록하지 않는다 [1].
`case-mcp`와 `report-mcp`의 `_resolve_case_dir`는 `active_case`가 가리키는 폴더가 없으면 환경변수 `VHIR_CASE_DIR`의 폴더를 쓰고 둘 다 없으면 오류를 낸다 [2][3].
사건이 없는 상태에서 `evidence_register`, `get_findings`, `record_timeline_event`를 부르자 모두 사건이 없다는 오류로 끝났다 [4].
닫힌 사건에서 `record_timeline_event`를 부르자 거부되었다 [4].

`sift-mcp`의 `run_command`는 사건이 없어도 명령을 실행한다 [5].
사건이 없으면 실행별 폴더를 만들지 않고 호출 기록 ID도 정하지 않은 채 서버 프로세스의 작업 폴더에서 실행한다 [5][4].

**한계.** 닫힌 사건 검사는 `forensic-mcp`에만 있다 [1][2][3].
`case-mcp`와 `report-mcp`는 `CASE.yaml`의 `status`를 보지 않으므로 닫힌 사건에도 증거 등록과 보고서 저장을 받는다 [2][3].
`forensic-mcp`는 한 번 찾은 사건을 프로세스 안에 기억하고 `active_case` 파일이 없어지면 기억한 사건을 그대로 쓴다 [1].
같은 프로세스에서 `active_case` 파일을 치운 뒤 `get_findings`를 부르자 오류 없이 응답했다 [4].

### T03.08 원격 호출자 인증

**구현.** 이 방식은 게이트웨이 `sift-gateway`의 HTTP 끝점에 적용된다 [6][7].
모든 백엔드의 도구를 모은 `/mcp`와 백엔드마다 둔 `/mcp/<백엔드>`는 같은 API 키 목록으로 요청을 검사한다 [7][8].
REST 경로(`/api/v1/tools/<도구>` 등)는 Starlette 미들웨어 `AuthMiddleware`가 같은 목록으로 검사한다 [6].
API 키 목록은 설정 파일의 `api_keys`이고 키마다 검토자 이름 `examiner`와 역할 `role`을 둔다 [9].
요청의 `Authorization` 헤더가 `Bearer <키>` 꼴이 아니면 401을 돌려준다 [6][8].
키가 1024자를 넘거나 목록의 어느 키와도 맞지 않으면 403을 돌려준다 [6][8].
키 대조는 `hmac.compare_digest`로 목록의 모든 키와 한 번씩 한다 [8].
맞은 키의 `examiner`를 요청 상태에 두고 `analyst_override`를 받는 도구 8개를 부를 때 그 값을 `analyst_override`에 덮어써 넘긴다 [10][11].
헤더 없는 요청은 401, 틀린 키는 403으로 거부되었고 맞는 키로는 도구 목록과 MCP 초기화가 성공했다 [12].
`analyst_override`에 다른 이름을 준 `record_action`은 키의 `examiner`로 기록되었다 [12].

원격 기계를 붙일 때 쓰는 join 코드는 설정 파일의 첫 번째 키로만 만들 수 있다 [13].
join 코드는 임의의 8자 문자열이고 bcrypt 해시로만 저장되며 1~48시간 뒤 만료되고 한 번 쓰면 다시 쓰지 못한다 [13][14].
`/api/v1/setup/join`은 인증하지 않는 경로이고 IP마다 15분 안에 틀린 코드가 3번 쌓이면 다음 요청을 429로 거부한다 [15].
join이 성공하면 서버가 새 키를 만들어 역할 `examiner`로 설정 파일에 더한다 [16].
첫 번째가 아닌 키로 join 코드를 요청하자 403이 돌아왔다 [12].
틀린 코드를 네 번 보내자 세 번은 403, 네 번째는 429가 돌아왔다 [12].

게이트웨이를 거치지 않고 클라이언트가 백엔드를 stdio로 직접 실행하는 구성에는 이 검사가 없다.
이때 `forensic-mcp`와 `case-mcp`는 `analyst_override`에 모델이 준 이름을 그대로 검토자로 기록한다 [17].

**한계.** 설정 파일에 `api_keys`가 없거나 비어 있으면 인증을 하지 않고 모든 요청을 `anonymous` 검토자로 처리한다 [6][8].
`--host`로 `127.0.0.1` 밖의 주소에 열어도 이 동작은 같고 키가 없다는 이유로 시작을 거부하지 않는다 [18].
키 없는 설정으로 게이트웨이를 실행하자 헤더 없는 요청으로 도구 목록 조회와 `run_command` 실행이 성공했다 [12].
`role`은 요청 상태에 넣기만 하고 도구 호출을 허용하거나 거부하는 데 쓰지 않는다 [10].
역할이 `readonly`인 키로 `run_command`를 부르자 실행되었다 [12].
백엔드 시작·중지 같은 서비스 관리 REST 경로는 첫 번째 키인지 보지 않고 어느 키로도 부를 수 있다 [19].
첫 번째가 아닌 키로 `case-mcp` 중지를 요청하자 200이 돌아왔다 [12].
`/health`, 검토 포털 `/portal`의 HTML, `/api/v1/setup/join`은 인증하지 않는 경로다 [6].

### T03.12 외부 서비스 요청 빈도 제한

**구현.** 이 방식은 `opencti-mcp`가 OpenCTI에 보내는 조회와 `lookup_ioc`의 조회처 요청에 적용된다 [20][21].
OpenCTI 조회는 60초 창 안에 보낸 질의 수가 `rate_limit_queries`에 이르면 OpenCTI에 묻지 않고 `RateLimitError`를 낸다 [20][22].
`rate_limit_queries`의 기본값은 600이고 사용자가 환경변수 `OPENCTI_RATE_LIMIT_QUERIES`로 바꾼다 [23].
`lookup_ioc`는 OpenCTI를 설정했으면 이 질의 상한을 함께 쓰고 설정하지 않았으면 60초 창 600회의 상한을 따로 둔다 [21].
상한에 이르면 기다리지 않고 `rate_limit_exceeded` 오류와 다음 요청까지 남은 초 `wait_seconds`를 돌려준다 [24][22].
캐시에 있는 응답을 돌려주는 조회는 이 수에 넣지 않는다 [25].
이 상한은 실행으로 확인하지 않았고 코드로만 확인했다.

### T03.13 원격 호출자별 요청 수 제한

**구현.** 이 방식은 게이트웨이의 MCP 끝점 `/mcp`·`/mcp/<백엔드>`와 REST 도구 호출 경로 `/api/v1/tools/<도구>`에 적용된다 [26][27].
게이트웨이는 호출자 주소마다 60초 창 안의 요청 수를 세어 60회에 이르면 다음 요청을 429로 거부한다 [28][26][27].
이 검사는 인증과 요청 크기 검사보다 먼저 실행된다 [26].
모든 끝점은 프로세스에 하나인 상한 객체를 코드에 정한 기본값으로 함께 쓰고 설정으로 바꾸는 값은 없다 [29].
로컬 주소에서 온 요청에 `X-Forwarded-For` 헤더가 있으면 그 첫 주소를 호출자 주소로 본다 [26][27].
호출자 주소가 `127.0.0.1`·`::1`·`localhost`이면 요청을 세지 않는다 [29].
이 상한은 실행으로 확인하지 않았고 코드로만 확인했다.

**한계.** REST 경로 가운데 도구 목록 조회, 백엔드·서비스 관리, join 경로에는 이 상한이 적용되지 않는다 [27][30].

```python
    code: str, expires_hours: int = 2, bound_name: str | None = None

    """Hash and store a join code with expiry. A code bound to a name
    (`vhir setup join-code --name NAME`) joins as that name only."""

    # bcrypt hash of the code
    code_bytes = code.encode("utf-8")
```

```python
    def check_and_record(self) -> bool:
        """Atomically check and record if allowed (thread-safe).

        Returns True if call was allowed and recorded, False if rate limited.
        """
        with self._lock:
            now = monotonic()
            self._cleanup_unlocked(now)
            if len(self.calls) < self.max_calls:
                self.calls.append(now)
                return True
            return False

    def wait_time(self) -> float:
        """Return seconds to wait before next call allowed (thread-safe)."""
        with self._lock:
            if self.max_calls <= 0:
                return float(self.window)
            now = monotonic()
            self._cleanup_unlocked(now)
            if len(self.calls) < self.max_calls:
                return 0.0
            if not self.calls:
                return 0.0
            oldest = self.calls[0]
            return max(0.0, oldest + self.window - now)
```

```python
def check_rate_limit(ip: str) -> bool:
    """Convenience: check the singleton limiter. Returns True if allowed.

    Localhost connections are always allowed — rate limiting protects
    against remote abuse, not local Claude Code connections.
    """
    if ip in ("127.0.0.1", "::1", "localhost"):
        return True
    return get_rate_limiter().is_allowed(ip)
```
