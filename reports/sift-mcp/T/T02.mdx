# T02 실행 허용 범위 제한

### T02.01 클라이언트 도구 선택

**구현.** 이 방식은 저장소가 함께 제공하는 Claude Code 설정, finding-skeptic 에이전트 정의, Codex용 훅에 적용된다 [1][2][3][4].
Full 구성의 Claude Code 설정은 허용 목록 `allow`에 `mcp__forensic-mcp__*`, `mcp__sift-mcp__*`처럼 MCP 서버 13개의 도구 전체를 두어 확인 없이 쓰게 하고 막는 서버 도구는 없다 [1].
Lite 구성의 설정은 `rag-mcp`, `windows-triage-mcp`, 위협 정보 서버 등 서버 8개의 도구 전체를 허용 목록에 둔다 [2].
Claude Code용 finding-skeptic 에이전트 정의는 `tools`에 읽기·조회 도구와 `run_command`를 적어 그 에이전트가 쓸 수 있는 도구를 정한다 [3].
Codex용 `codex-skeptic-tools.sh`는 PreToolUse 훅에서 `agent_type`이 `finding-skeptic`인 호출을 같은 도구 목록 `ALLOWED`와 대조한다 [4].
목록 밖의 MCP 도구, 셸, `apply_patch`, 다른 에이전트를 시작하거나 메시지를 보내는 도구는 종료 코드 2로 거부한다 [4].
다른 에이전트의 호출과 입력을 읽지 못한 호출은 각각 통과와 거부로 처리한다 [4].
finding-skeptic의 두 목록에는 임의 명령을 실행하는 `run_command`가 들어 있다 [3][4].
게이트웨이는 키의 역할로 도구를 거르지 않으므로 이 목록들은 저장소의 설정을 설치한 Claude Code와 Codex에만 적용되고 다른 MCP 클라이언트로 붙으면 적용되지 않는다 [5].

### T02.02 클라이언트 자체 도구 우회 차단

**구현.** 이 방식은 Full 구성의 Claude Code 설정과 Codex용 관리 설정이 서버가 관리하는 사건 기록과 승인 자료를 지키는 데 적용된다 [6][7][8].
Claude Code 설정의 거부 목록 `deny`는 사건 기록(`findings.json`, `timeline.json`, `approvals.jsonl`, `evidence.json` 등)과 `audit/*.jsonl`을 `Edit`로 고치는 것을 막는다 [6].
같은 목록은 승인 자료 폴더 `/var/lib/vhir`와 API 키가 들어 있는 `~/.vhir/gateway.yaml`의 `Read`, 승인·반려 명령 `vhir approve`·`vhir reject`의 `Bash` 실행을 막는다 [6].
같은 설정은 Claude Code sandbox를 켜고 `~/.vhir`의 설정·훅·`active_case` 쓰기와 `/var/lib/vhir`·`gateway.yaml` 읽기를 막는다 [7].
`Bash` 실행 전에는 훅 `case-data-guard.sh`가 명령을 토큰으로 나누어 사건 기록, `audit/` 아래 파일, `evidence/`의 기존 파일을 지우거나 덮어쓰는 `rm`·`mv`·`cp`·출력 방향 바꾸기를 찾고 있으면 종료 코드 2로 거부한다 [8].
이 훅은 읽을 수 없는 입력, 자신의 오류, 5초를 넘긴 검사도 거부로 처리한다 [8].
Codex용 관리 설정은 셸이 `~/.vhir`를 읽기만 하게 하고 `/var/lib/vhir`와 `gateway.yaml` 읽기를 막으며 `Bash`와 `apply_patch` 앞에 같은 훅을 둔다 [9].

서버가 감싼 분석 도구를 `Bash`로 직접 실행하는 것은 막지 않는다 [6][10].
`mcp-route.py`는 셸 명령의 첫 실행 파일이 MCP 도구로도 실행할 수 있는 도구이면 그 사실을 호출 기록 훅에 알려 표시하고 안내하게 할 뿐 거부하지 않는다 [10].
Lite 구성의 설정은 `vhir approve`·`vhir reject` 실행만 막고 사건 기록 쓰기를 막는 항목이나 PreToolUse 훅이 없다 [2].
이 설정과 훅은 저장소의 Claude Code·Codex 설정을 설치한 세션에만 적용되고 다른 MCP 클라이언트에는 적용되지 않는다 [6][9].
훅은 실행해 보지 않았고 코드로만 확인했다.

**한계.** 훅 주석은 이 검사가 보안 경계가 아니라고 적고 셸 문자열 안의 명령, `xargs`, 스크립트, 제자리 편집 같은 형태는 보지 않는다고 적는다 [8].
거부 목록의 쓰기 항목은 `Edit(...)` 규칙으로만 적혀 있고 `Write`를 따로 적은 항목은 없다 [6].
Claude Code가 편집 도구의 거부 규칙을 파일 쓰기 도구에도 적용하는지는 확인하지 못했다.

### T02.04 고정 명령·템플릿

**구현.** 이 방식은 `opencti-mcp`의 위협 정보 조회, `windows-triage-mcp`의 기준 DB 조회, `sift-mcp`의 버전·도움말 실행에 적용된다 [11][12][13][14].
`opencti-mcp`의 GraphQL 클라이언트는 질의 문자열을 코드의 루트·선택 필드로 만들고 모델 값은 `search`, `filters`, `first` 같은 변수로만 넘긴다 [11].
정렬 값 `orderBy`·`orderMode`는 정해 둔 목록에 있을 때만 질의 문자열에 넣는다 [11].
`lookup_ioc`는 OpenCTI에는 고정 질의 `LOOKUP_QUERY`를, MISP에는 고정 경로 `/attributes/restSearch`를 쓰고 IOC 값만 변수나 본문 필드로 넣는다 [12].
`windows-triage-mcp`의 DB 조회 함수는 SQL 문을 코드에 두고 경로·이름·해시를 `?` 자리 인자로 넘긴다 [13].
`sift-mcp`의 `get_tool_help`와 버전 조회는 카탈로그의 `version_argv`·`help_argv`·`subcommand_help` 인자 목록으로 도구를 실행하고 모델 값은 `subcommand` 자리에만 들어간다 [14].
`subcommand`는 소문자로 시작하는 41자 이하의 영문 소문자·숫자·하이픈이어야 하고 카탈로그에 `subcommand_help`가 없는 도구는 받지 않는다 [14].

`sift-mcp`의 `run_command`는 모델이 명령 전체를 정하므로 이 방식에 해당하지 않는다 [15].

### T02.05 연산·플러그인 허용 목록

**구현.** 이 방식은 `report-mcp`의 `generate_report`, `opencti-mcp`의 `search_entity`·`get_relationships`, `sift-mcp`의 `get_tool_help`에 적용된다 [16][17][18][19].
`generate_report`는 `profile`을 `PROFILES`의 6개(`full`·`executive`·`timeline`·`ioc`·`findings`·`status`)와 대조하고 목록에 없으면 오류를 돌려준다 [16].
`search_entity`는 `type`을 `VALID_ENTITY_TYPES`의 16개와 대조하고 목록에 없으면 `ValidationError`로 거부한 뒤 맞는 값은 정해 둔 클라이언트 메서드로 바꾼다 [17].
`get_relationships`는 `relationship_types`의 각 값을 `VALID_RELATIONSHIP_TYPES`와 대조하고 목록에 없으면 거부한다 [18].
`get_tool_help`는 카탈로그에 없는 `tool_name`을 받으면 도구를 실행하지 않고 오류를 돌려준다 [19].
목록에 없는 `profile`을 준 `generate_report`는 유효한 값 목록을 담은 오류로 끝났다 [20].

### T02.06 질의 구조·연산 검사

**구현.** 이 방식은 모델이 명령 전체를 인자 목록으로 넘기는 `sift-mcp`의 `run_command`에 적용된다 [15][21].
서버는 실행 전에 다음을 차례로 검사하고 하나라도 어긋나면 실행하지 않고 오류를 돌려준다 [21][22].
- 첫 인자의 경로 앞부분을 뗀 실행 파일 이름이 거부 목록 `denied_binaries`의 17개(`mkfs` 계열, `shutdown`, `kill`, `env`, `printenv`, `nc` 등)에 있으면 거부한다 [21][23].
- `rm`이면 사건 폴더와 증거 저장 폴더를 지우는 인자를 거부하고 `rm`·`mv`·`cp`·`tee` 등이 사건 기록, `audit/`, `evidence/`의 파일을 지우거나 덮어쓰면 거부한다 [21][24].
- 인자마다 `=` 앞부분을 소문자로 바꾸어 도구별 거부 플래그(`find`의 `-exec`·`-delete`, `sed`의 `-i`, `tar`의 `-x`·`-c` 등)와 전역 위험 플래그(`-e`, `--exec`, `--command`, `-enc`, `--script` 등)에 있으면 거부한다 [22][25].
- 전역 위험 플래그는 `grep`·`sed`·`strings`·`tshark` 같은 도구에서는 도구별 허용 목록으로 통과시킨다 [22][25].
- 인자에 `;`, `&&`, `||`, 백틱, `$(`, `${`가 들어 있으면 거부한다 [22].
- `awk` 계열 도구의 프로그램 글에 `system(`, `getline`, 파이프·파일 출력 꼴이 있으면 거부한다 [22].
검사 목록은 카탈로그 폴더의 `security.yaml`에서 읽고 이 파일을 읽지 못하면 빈 목록으로 진행하지 않고 오류를 낸다 [26].
거부 목록의 `kill`·`env`, `perl -e`, `find -delete`, `&&`가 들어간 인자, `system(`을 쓴 `awk` 프로그램은 모두 실행되지 않고 오류로 끝났다 [20].

**한계.** 거부 목록은 첫 인자의 실행 파일 이름에만 적용된다 [21].
다른 실행 파일의 인자로 둔 거부 목록 실행 파일은 거부되지 않고 실행되었다 [20].
도구 설명은 `bash -c`, `python -c`, `dd`와 도구 자체의 출력 옵션을 검사하지 않는다고 적는다 [15].
같은 설명은 거부하는 실행 파일로 `mkfs`, `shutdown`, `kill`, `nc`·`ncat`만 적고 `env`·`printenv`, `reboot` 같은 나머지 이름은 적지 않는다 [15][23].
`-c`는 전역 위험 플래그가 아니어서 `bash -c`로 넘긴 셸 문자열은 위 문자 목록에 없는 한 실행되었다 [25][20].
환경변수 `SIFT_CATALOG_DIR`가 가리키는 다른 카탈로그 폴더가 있으면 그 폴더의 `security.yaml`을 검사 목록으로 쓴다 [26].

### T02.08 설정으로 도구 끄기

**구현.** 이 방식은 게이트웨이가 붙이는 백엔드에 적용된다 [27][28].
사용자는 게이트웨이 설정 파일의 백엔드 항목에 `enabled: false`를 두어 그 백엔드를 만들지 않게 하고 그 백엔드의 도구는 도구 목록과 호출 대상에서 빠진다 [27].
설정 예시는 원격 HTTP 백엔드 `wintools-mcp`, `remnux-mcp`, `microsoft-learn`, `zeltser-ir-writing`을 `enabled: false`로 둔다 [28].
백엔드 하나의 도구 가운데 일부만 끄는 설정은 없다 [27].

```bash
WRITES = {"apply_patch", "Bash", "exec_command", "write_stdin", "shell", "local_shell"}
# A namespaced tool's name comes prefixed, e.g. collaborationspawn_agent
HANDS_ON = ("spawn_agent", "send_input", "resume_agent", "followup_task", "send_message", "assign_agent_task")


def refuse(why):
    print(f"BLOCKED: {why}", file=sys.stderr)
    sys.exit(2)


try:
    payload = json.load(sys.stdin)
    agent, tool = payload.get("agent_type"), str(payload["tool_name"])
except Exception:
    refuse("the skeptic's tool check couldn't read this call, so it was blocked to be safe")
if agent != "finding-skeptic":
    sys.exit(0)
if tool.startswith("mcp__"):
    server, _, name = tool[5:].partition("__")
    if name:  # mcp__<server>__<tool>, the server as Codex names it (a "-" made "_"): that pair
        ok = any(server.replace("-", "_") == s.replace("-", "_") and name in n for s, n in ALLOWED.items())
    else:  # another shape: the tool's name alone
        ok = any(tool.rsplit("__", 1)[-1] in n for n in ALLOWED.values())
    if not ok:
        refuse(f"the finding-skeptic reads and queries only; {tool} isn't one of its tools")
elif tool in WRITES or tool.endswith(HANDS_ON):
    refuse(f"the finding-skeptic reads and queries only; it can't use {tool}")
sys.exit(0)
```

```python
def _find_catalog_dir() -> Path:
    """Locate the data/catalog directory."""
    global _CATALOG_DIR
    if _CATALOG_DIR is not None:
        return _CATALOG_DIR

    env = os.environ.get("SIFT_CATALOG_DIR")
    if env:
        p = Path(env)
        if p.is_dir():
            _CATALOG_DIR = p
            return p

    # Relative to this file: src/sift_mcp/catalog.py → ../../data/catalog/
    source = Path(__file__).resolve().parent.parent.parent / "data" / "catalog"
    if source.is_dir():
        _CATALOG_DIR = source
        return source

    raise FileNotFoundError("Cannot find sift-mcp catalog directory.")
```
