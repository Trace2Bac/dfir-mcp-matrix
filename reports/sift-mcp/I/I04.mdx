# I04 서버 자격증명 처리

### I04.01 환경변수·설정 파일에 분리 보관

**구현.** 이 방식은 `opencti-mcp`의 OpenCTI 토큰과 MISP 키, 게이트웨이와 `case-mcp`가 HTTP 백엔드에 보내는 Bearer 토큰에 적용된다 [1][2][3][4].
OpenCTI 토큰은 환경변수 `OPENCTI_TOKEN`, `~/.config/opencti-mcp/token`, 옛 위치 `~/.config/rag/opencti_token`, 작업 폴더의 `.env` 차례로 찾는다 [1].
`OPENCTI_TOKEN`이 공백만 담고 있으면 다음 위치를 찾지 않고 토큰이 없는 것으로 처리한다 [1].
MISP 키는 환경변수 `MISP_KEY`에서 읽는다 [2].
게이트웨이 설정 예시는 위협 정보 백엔드의 토큰과 HTTP 백엔드의 `bearer_token`을 `${VAR}`로 적고 게이트웨이가 시작할 때 환경변수 값으로 바꾼다 [5][6].
설치 스크립트 `setup-sift.sh`는 설치 때 받은 OpenCTI 주소와 토큰을 `gateway.yaml`의 백엔드 `env`에 값으로 적고 이 파일을 새로 만들 때 권한을 600으로 둔다 [7].
`wintools-mcp`의 토큰은 가입 API가 받은 값을 게이트웨이가 `gateway.yaml`에 그대로 써 둔다 [8].
`case-mcp`의 사건 알림은 `gateway.yaml`에서 그 토큰을 읽어 보낸다 [4].

### I04.02 도구 인자 수신 금지

**구현.** 이 방식은 `opencti-mcp`와 게이트웨이의 외부 연결 전체에 적용된다 [9][3].
어느 도구도 토큰이나 키를 인자로 받지 않고 서버가 환경변수와 설정 파일에서 읽는다 [9][1][2].
토큰과 키는 요청의 `Authorization` 헤더에만 넣는다 [10][11][3].
MISP 조회를 부른 호출의 응답과 `opencti-mcp.jsonl`에 키 값이 들어가지 않았다 [12].

### I04.03 설정 파일 권한 검사

**구현.** 이 방식은 `opencti-mcp`가 OpenCTI 토큰을 읽는 토큰 파일과 `.env`에 적용된다 [1][13][14].
토큰 파일은 그룹이나 다른 사용자가 읽거나 쓸 수 있으면 읽지 않고 설정 오류를 낸다 [13].
권한 644의 토큰 파일은 거부되었고 600으로 바꾸자 읽혔다 [12].
`.env`는 다른 사용자가 읽거나 쓸 수 있으면 운영 로그에 경고를 남긴다 [14].

**한계.** `.env`는 경고만 남기고 토큰을 읽는다 [14].
권한 644의 `.env`는 경고와 함께 읽혔다 [12].
두 검사는 권한 비트만 보고 파일 소유자는 검사하지 않는다 [13][14].
MISP 키는 환경변수 `MISP_KEY`에서만 읽고 이 검사를 거치지 않는다 [2].
게이트웨이는 위협 정보 백엔드의 토큰과 `bearer_token`을 담는 `gateway.yaml`을 읽을 때 권한을 검사하지 않는다 [15][7].

### I04.04 응답·기록·오류에서 비밀값 제거

**구현.** 이 방식은 `opencti-mcp`의 OpenCTI 토큰에 적용된다 [16].
OpenCTI 토큰은 `SecretStr`에 담아 문자열로 바꾸면 `***`가 되고 설정 객체의 `repr`도 토큰을 `***`로 적는다 [16].
`opencti-mcp`는 시작할 때 이 설정 객체를 운영 로그에 적는다 [17].

**한계.** MISP 키는 이런 처리 없이 일반 문자열로 보관한다 [2].
