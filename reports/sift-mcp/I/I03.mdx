# I03 외부 전송 범위 구성

### I03.01 해시 전송

**구현.** 이 방식은 `opencti-mcp`의 `lookup_ioc`에 적용된다 [1].
`lookup_ioc`는 받은 IOC의 종류를 `validate_ioc`로 나누고 MD5·SHA-1·SHA-256 등 해시 형식이면 그 해시 문자열을 조회처에 보낸다 [2][1].
OpenCTI에는 지표 이름이 그 값과 같은지 묻는 GraphQL 필터로 보내고 MISP에는 속성 검색 요청의 `value`로 보낸다 [3][4].
파일 내용은 올리지 않는다 [3][4].
MD5 해시로 `lookup_ioc`를 부르자 MISP 속성 검색과 경고 목록 확인 요청에 그 해시만 들어갔다 [5].

### I03.02 메타데이터·추출 값 전송

**구현.** 이 방식은 `opencti-mcp`의 `lookup_ioc`에 적용된다 [1].
IP 주소, CIDR, URL, 도메인, CVE, MITRE ID로 나뉜 값은 해시와 같은 요청으로 조회처에 보낸다 [2][3][4].
보낼 값은 모델이 `ioc` 인자로 고른다 [1].

`opencti-mcp`의 `search_threat_intel`·`search_entity`·`search_reports`는 모델이 쓴 검색어를 그대로 OpenCTI에 보낸다 [6].
`get_entity`·`get_relationships`는 UUID 형식으로 검사한 OpenCTI 개체 ID를 보낸다 [6].
`case-mcp`의 사건 알림과 게이트웨이의 사건 활성화 요청은 사건 ID만 `wintools-mcp`에 보낸다 [7][8].
게이트웨이는 사용자가 켠 HTTP 백엔드에 도구 호출의 인자를 `analyst_override` 말고는 모델이 준 그대로 보낸다 [9].

**한계.** `validate_ioc`는 어느 종류에도 맞지 않는 값을 `unknown`으로 두고 거부하지 않는다 [2].
그래서 IOC 형식이 아닌 글도 조회처로 나간다 [1].
`free text value`로 부르자 그 글이 MISP 속성 검색 요청에 그대로 들어갔다 [5].

### I03.05 민감 값 빼기·가림 후 전송

**구현.** 이 방식은 `opencti-mcp`의 `lookup_ioc`에 적용된다 [10].
`lookup_ioc`는 Python `ipaddress`가 사설·루프백·링크 로컬로 보는 IP 주소면 어느 조회처에도 묻지 않고 내부 주소라는 이유와 함께 `UNAVAILABLE`을 돌려준다 [10].
`192.168.1.5`와 `::1`로 부르자 조회처 요청이 하나도 나가지 않았다 [5].
`search_threat_intel`·`search_entity`·`search_reports`의 검색어에는 내부 주소를 빼는 처리가 없다 [6].

**한계.** 내부 주소를 빼는 처리는 IP 주소 하나로 해석되는 값에만 적용되고 내부 호스트 이름은 그대로 보낸다 [10].
`fileserver.corp.local`로 부르자 도메인으로 나뉘어 MISP로 나갔다 [5].
CIDR로 나뉜 값과 URL 안의 IP 주소는 이 처리를 거치지 않아 내부 대역도 조회처로 나간다 [10][2].

```python
def _internal_address(ioc: str) -> str:
    """The reason an IP address isn't looked up, or "" for anything else."""
    try:
        ip = ipaddress.ip_address(ioc)
    except ValueError:
        return ""
    if ip.is_private or ip.is_loopback or ip.is_link_local:
        return f"Internal address ({ioc}) — not in threat intelligence scope."
    return ""
```
