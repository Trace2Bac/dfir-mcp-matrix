# E04 분석 입력 준비

### 미구현

**판단.** 서버는 디스크 이미지, 메모리 이미지, KAPE 수집물 같은 증거를 받지만 분석 입력을 따로 준비하지 않는다.
분석 도구로 증거를 읽는 경로는 `sift-mcp`의 `run_command` 하나이고 이 도구는 모델이 만든 명령 목록의 실행 파일만 찾아 바꾼 뒤 증거 경로를 그대로 분석 도구에 넘긴다 [1].
상대 경로는 그 실행의 작업 폴더 `extractions/<호출 기록 ID>` 기준으로 읽힌다 [2].
서버 코드에는 증거를 작업 사본으로 복사하거나 보관 파일을 풀거나 이미지를 마운트하거나 부속 자료를 찾는 부분이 없다.

모델은 `run_command`로 `ewfmount`, `mount`, `icat`, `7z` 같은 도구를 실행해 입력을 직접 준비할 수 있다 [3].
서버는 마운트 도구가 성공하면 마운트한 이미지와 새로 생긴 마운트 지점을 호출 기록의 `mount`에 적고 작업 폴더에 생긴 파일을 해시와 함께 `outputs`에 적는다 [4][5].
이 기록은 모델이 실행한 명령의 결과를 남기는 것이고 서버가 고른 범위나 서버가 바꾼 인자를 남기는 것은 아니다.
`case-mcp`의 `evidence_register`는 KAPE 수집물 폴더를 등록할 때 안의 파일 목록을 manifest로 남기지만 분석 입력을 만들지는 않는다 [6].
`suggest_tools`는 `wintools-mcp`가 설정에 없을 때 레지스트리 항목에 트랜잭션 로그 복구가 제한된다는 정해 둔 안내를 싣지만 실제 입력의 부속 자료를 보지는 않는다 [7].
