# L04 기록 위변조 방지

### L04.05 기록 밖 항목 해시 대조

**구현.** 이 방식은 `forensic-mcp`가 근거 사슬을 저장한 발견사항과 검토 포털 `case-dashboard`의 승인 처리에 적용된다 [1][2].
`forensic-mcp`는 발견사항을 저장할 때 그 근거 사슬에 들어간 호출 기록 항목마다 그 줄의 SHA-256을 발견사항의 `entry_sha256`에 넣는다 [1].
검토 포털은 승인할 때 그 항목 줄을 다시 해시해 바뀌었으면 `ENTRY_CHANGED`, 없으면 `ENTRY_MISSING`, 같은 ID가 둘 이상이면 `ENTRY_DUPLICATE`로 알린다 [3][2].
사용자 CLI `vhir approve`도 승인 전에 같은 대조를 실행한다 [4].

게이트웨이와 백엔드 7개의 호출 기록은 사건 폴더 `audit/`의 JSONL 파일이고 공통 기록기 `AuditWriter`는 항목을 덧붙이기 모드로 쓴다 [5].
항목에는 앞 항목의 해시, 서명, 일련번호가 없다 [6].
항목 ID는 시각과 무작위 값으로 만든 ULID로 끝나며 순서를 나타내는 번호가 아니다 [7].
사건 기록을 남기지 않는 조회 도구는 사건 밖 파일 `~/.vhir/logs/lookups.jsonl`에 `log_lookup`으로 한 줄을 덧붙이고 이 줄에도 앞 줄의 해시나 번호가 없다 [8].
JSONL 파일 전체를 다시 읽어 해시 체인이나 일련번호를 검증하는 도구와 사용자 CLI 명령은 없다.
`case-mcp`의 `audit_summary`가 부르는 `vhir_cli`의 집계 함수는 항목 수를 셀 뿐 어긋난 항목을 찾지 않는다 [9].

**한계.** 이 대조는 `provenance_schema`가 2인 발견사항의 근거 사슬에 들어간 항목에만 적용되고 타임라인 항목에는 적용되지 않는다 [3][10].
대조에 실패해도 검토자가 이유를 적으면 승인을 계속할 수 있다 [3][4].

### L04.06 서버 코드의 기록 쓰기 차단

**구현.** 이 방식은 `sift-mcp`의 `run_command`가 실행하는 `rm`·`shred`·`unlink`·`truncate`·`tee`·`mv`·`cp`·`install`·`ln`에 적용된다 [11].
`run_command`는 이 명령의 인자를 실제 경로로 바꿔 사건 폴더의 `audit/`를 가리키면 실행하지 않고 오류를 돌려준다 [11].
이 검사는 인자 배열만 보고 실행 환경의 쓰기 권한을 바꾸지 않는다 [11][12].
`audit/`의 `rm`과 `cp` 덮어쓰기를 `run_command`로 시도하자 두 호출 모두 실행되지 않고 오류를 돌려줬다 [13].
정해 둔 명령 밖의 분석 도구가 출력 플래그로 받는 경로는 사건 폴더 안인지만 대조한다 [11][14].
`run_command`의 경로 인자 검사는 `~/.vhir` 아래에서 사건 폴더 등 예외로 둔 곳이 아니면 거부하고 `lookups.jsonl`이 있는 폴더는 예외가 아니다 [15].

`forensic-mcp`와 `report-mcp`는 사건 기록 파일을 쓴 뒤 권한을 444로 바꾸지만 `AuditWriter`는 호출 기록 파일의 권한을 바꾸지 않는다 [16][5].
같은 저장소의 Claude Code 설정은 `**/audit/*.jsonl`의 `Edit`를 거부 목록에 두고 `case-data-guard.sh` 훅으로 Bash 명령을 검사한다 [17].
이 설정과 훅은 클라이언트 자료이고 다른 클라이언트로 붙으면 적용되지 않는다.

**한계.** 도구 설명은 셸이나 인터프리터에 넘긴 명령 문자열, `dd`, 분석 도구 자신의 출력 인자를 이 검사가 보지 않는다고 적는다 [12].

```python
def new_ulid() -> str:
    """A 26-character lowercase ULID: 48-bit milliseconds, 80 random bits."""
    n = (time.time_ns() // 1_000_000) << 80 | int.from_bytes(os.urandom(10), "big")
    return "".join(_ULID_ALPHABET[(n >> s) & 31] for s in range(125, -1, -5))
```

[16] `forensic-mcp`와 `report-mcp`의 `_protected_write`는 사건 기록 파일을 쓴 뒤 권한을 `0o444`로 바꾼다.

```python
def _protected_write(path: Path, content: str) -> None:
    """Write to a chmod-444-protected case data file.

    Uses atomic write (tempfile + rename), then locks (0o444).
    The temp file is created writable, so we only need to unlock the
    existing file for _atomic_write's rename to succeed on the same inode.
    """
    try:
        if path.exists():
            os.chmod(path, 0o644)
    except OSError:
        pass  # May already be writable or on non-POSIX fs
    try:
        _atomic_write(path, content)
    finally:
        # Always re-lock, even if the write failed partway
        try:
            if path.exists():
                os.chmod(path, 0o444)
```
