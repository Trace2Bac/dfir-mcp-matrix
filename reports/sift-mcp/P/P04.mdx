# P04 조사 단위 관리

### P04.01 사건 시작 시 ID 확정

**구현.** 이 방식은 `case-mcp`의 `case_init`과 `case_activate`, 그리고 열린 사건을 읽는 모든 백엔드 도구에 적용된다 [1][2][3].
`case_init`은 사건 ID를 받지 않으면 `INC-<연도>-<월일시분초>`로 정하고 받으면 첫 글자가 영문자나 숫자이고 영문자·숫자·`-`·`_`로 된 2~64자인지 검사한다 [1].
같은 이름의 사건 폴더가 있거나 그 ID의 서명 원장이 이미 있으면 사건을 만들지 않는다 [1].
만든 사건의 폴더 경로를 열린 사건 표시 파일 `~/.vhir/active_case`에 쓰고 응답의 `activation`에 앞서 열려 있던 사건을 적는다 [1].
`case_activate`는 `/`, `\`, `..`가 없고 폴더가 있는 사건 ID만 받아 표시 파일을 그 사건으로 바꾼다 [2].
상위 폴더를 가리키는 ID와 공백이 들어간 ID는 거부되었고 없는 사건 ID로 `case_activate`를 부르자 `Case not found`가 돌아왔다 [4].

뒤의 호출은 이 표시 파일로 사건에 묶인다.
`case-mcp`와 `forensic-mcp`는 호출마다 표시 파일을 다시 읽어 사건 폴더를 정한다 [3][5].
`forensic-mcp`는 `CASE.yaml`의 상태가 `closed`인 사건이면 기록 도구를 거부한다 [5].
`sift-mcp`의 `run_command`는 호출을 시작할 때 사건을 한 번 정하고 그 사건으로 호출 기록 ID와 작업 폴더 `extractions/<호출 기록 ID>`를 만든다 [6].
명령이 끝날 때 열린 사건이 바뀌어 있어도 출력과 호출 기록 항목은 시작할 때의 사건에 남는다 [6].

**한계.** 표시 파일은 운영체제 사용자 홈에 하나뿐이어서 같은 사용자로 실행된 모든 세션과 게이트웨이의 모든 API 키가 한 사건을 같이 쓴다 [1][7].
한 세션이 사건을 바꾸면 다른 세션의 다음 호출도 바뀐 사건에 기록된다 [7].
백엔드마다 열린 사건을 정하는 차례가 다르다 [3][5][8].
`sift-mcp`와 `sift-common`의 공통 함수는 환경변수 `VHIR_CASE_DIR`를 먼저 보고 `case-mcp`는 표시 파일을 먼저 보며 `forensic-mcp`는 표시 파일만 본다 [3][5][8].
`forensic-mcp`는 표시 파일이 없거나 사건 폴더를 가리키지 않으면 그 프로세스가 마지막으로 읽은 사건에 계속 기록한다 [5].
표시 파일을 지운 뒤 `forensic-mcp`의 `add_todo`는 앞 사건에 할 일을 더했고 `case-mcp`의 `record_action`은 열린 사건이 없다는 오류를 돌려주었다 [9].
게이트웨이 설정 예시는 게이트웨이 프로세스에 `VHIR_CASE_DIR`가 있으면 그 값을 백엔드마다 넘기고 없으면 넘기지 않는다 [10][11].
사용자가 `VHIR_CASE_DIR`를 정해 두어 그 값이 사건 B를, 표시 파일이 사건 A를 가리킬 때 `run_command`의 출력과 호출 기록은 B에 쓰였고 `case-mcp`와 `forensic-mcp`는 A를 썼다 [4].
닫힌 사건을 거부하는 것은 `forensic-mcp`뿐이다 [5].
`case_activate`는 닫힌 사건도 열린 사건으로 바꾸었고 그 뒤 `case-mcp`의 `record_action`과 `sift-mcp`의 `run_command`는 기록을 남겼다 [4].
사건을 닫는 일은 MCP 도구가 아니라 사용자 CLI `vhir case close`가 `CASE.yaml`의 상태를 `closed`로 바꾸고 표시 파일이 그 사건을 가리키면 지우는 방식으로 한다 [12].
이 명령으로 표시 파일이 지워진 경우에는 `forensic-mcp`가 메모리에 둔 사건의 상태가 `closed`이므로 기록 도구가 거부된다 [5][12].

### P04.03 폴더·DB·manifest에 사건 ID 연결

**구현.** 이 방식은 사건 폴더 이름, `CASE.yaml`, 호출 기록 항목, 사건 밖 조회 기록에 적용된다 [1][13][14].
사건 폴더는 사건 ID를 이름으로 `VHIR_CASES_DIR` 아래에 만들고 `CASE.yaml`에 `case_id`, 상태, 만든 검토자, 만든 시각과 사건 고유값 `case_uuid`를 적는다 [1][4].
호출 기록 항목의 `case_id`는 도구가 넘긴 사건 폴더가 있으면 그 폴더의 `CASE.yaml` 값이고 없으면 환경변수 `VHIR_ACTIVE_CASE`나 표시 파일이 가리키는 폴더의 이름이다 [13].
`run_command`의 작업 폴더 이름인 호출 기록 ID에는 사건 ID가 들어가지 않고 그 폴더는 사건 폴더 안에 만들어진다 [6].
호출 기록을 남기지 않는 조회 도구(`list_available_tools`, `check_tools`, `get_procedure` 등)는 사건 폴더 밖 `~/.vhir/logs/lookups.jsonl`에 줄마다 사건 폴더 이름을 `case`로 적는다 [14].

**한계.** `case_id`를 정하는 기준과 항목을 쓸 폴더를 정하는 기준이 달라 두 값이 어긋날 수 있다 [13].
`VHIR_CASE_DIR`가 사건 B를, 표시 파일이 사건 A를 가리킬 때 `suggest_tools`의 호출 기록 항목은 B의 `audit/`에 쓰였고 `case_id`는 `CASE-A`였다 [15].

### P04.04 사건별 폴더·DB 분리

**구현.** 이 방식은 사건 자료 파일, `run_command`의 출력, `case_activate`의 사건 폴더 확인에 적용된다 [1][6][16][17].
`case_init`은 사건마다 `evidence/`, `extractions/`, `reports/`, `audit/` 폴더와 `findings.json`, `timeline.json`, `todos.json`, `evidence.json`을 사건 폴더 안에 만든다 [1].
백엔드마다 쓰는 호출 기록 파일 `audit/<백엔드>.jsonl`, 큰 파일의 해시 결과 `audit/file-identity.jsonl`, 증거 목록, 할 일, 발견사항이 모두 그 사건 폴더 안에 있다 [1][13].
`run_command`는 열린 사건이 있으면 출력 경로 인자가 그 사건 폴더 밖을 가리킬 때 실행하지 않는다 [16].
`evidence_register`도 사건 폴더 밖의 파일을 등록하지 않는다 [4].
`case_activate`는 `CASE.yaml`의 사건 고유값 `case_uuid`마다 그 사건을 둔 폴더를 `~/.vhir/case-paths.json`에 적는다 [17].
적어 둔 폴더가 아직 같은 고유값을 가지고 있으면 같은 고유값을 가진 다른 폴더는 열린 사건으로 바꾸지 않는다 [17].
사건 폴더 전체를 복사한 폴더를 `case_activate`로 열자 원래 사건의 사본이라는 오류가 돌아왔고 표시 파일은 원래 사건을 가리킨 채였다 [9].

**한계.** 사건 폴더 밖에 사건마다 나뉘지 않은 상태가 있다.
열린 사건 표시 파일과 조회 기록 `lookups.jsonl`은 모든 사건이 같이 쓴다 [7][14].
서명 원장과 사건 잠금 파일은 `/var/lib/vhir/ledger/` 아래에 사건 ID로 이름을 짓는다 [18].
그래서 이전에 같은 ID로 원장을 만든 사건이 있으면 그 ID로 새 사건을 만들 수 없다 [1].
`run_command` 응답의 참조 지식 횟수는 프로세스 하나에 하나뿐이어서 사건을 바꿔도 나뉘지 않는다 [19].
`run_command`의 출력 경로 검사는 출력 옵션의 값에만 적용되고 위치 인자로 준 경로에는 적용되지 않는다 [20].
`validate_case_data_targets`는 모든 사건의 기존 증거와 기록을 지우거나 덮어쓰는 명령만 거부하므로 위치 인자로 다른 사건 폴더에 새 파일을 쓰는 명령은 실행된다 [20].
열린 사건에서 다른 사건의 `evidence/`에 새 파일을 복사하는 명령은 실행되었고 같은 경로를 출력 옵션 값으로 준 명령은 거부되었다 [21].

```python
def resolve_case_dir() -> str:
    """Resolve the active case directory.

    Resolution order: VHIR_CASE_DIR env var → ~/.vhir/active_case file → "".
    VHIR_CASE_DIR must be a directory containing CASE.yaml to be valid.
    If set but invalid, falls through to active_case.
    """
    case_dir = os.environ.get("VHIR_CASE_DIR", "").strip()
    if case_dir:
        p = Path(case_dir)
        if p.is_dir() and (p / "CASE.yaml").exists():
            return case_dir
        # Set but invalid — fall through to active_case
    active_file = Path.home() / ".vhir" / "active_case"
    if active_file.is_file():
        try:
            content = active_file.read_text().strip()
        except OSError:
            return ""
        if content:
            p = Path(content)
            if p.is_dir() and (p / "CASE.yaml").exists():
                return content
    return ""
```

def _interpolate_env(value: str) -> str:
    """Replace ${VAR} patterns with environment variable values.

    If a referenced variable is not set, the placeholder is replaced with
    an empty string to prevent literal '${VAR}' from leaking into configs.
    """

    def _replace(match: re.Match) -> str:
        var_name = match.group(1)
        return os.environ.get(var_name, "")
