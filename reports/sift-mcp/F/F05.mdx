# F05 발견사항·결론 근거 검증

### F05.01 근거 참조 존재 확인

**구현.** 이 방식은 `forensic-mcp`의 `record_finding`에 적용된다 [1][2].
인용 원문 `artifacts` 항목의 근거 호출 `audit_id`가 사건의 호출 기록에 없으면 0.1초 뒤 기록을 한 번 더 읽고 그래도 없으면 `REJECTED`로 거부한다 [1].
그다음 발견사항의 근거 호출 ID 전체를 사건 폴더 `audit/`의 호출 기록 파일과 대조해 출처 분류를 정한다 [2][3].
`claude-code.jsonl`에 있는 ID는 `HOOK`, 그 밖의 호출 기록 파일에 있는 ID는 `MCP`, 기록에 없거나 정한 형식에 맞지 않는 ID는 `none`으로 나눈다 [3].
`fileidentity-`로 시작하는 ID는 인용 원문을 추적하려고 읽은 사건 기록에 있으면 `MCP`, 그 밖에는 `unchecked`로 나눈다 [1][3].
ID 형식은 접두어, 검토자, 날짜, 일련번호나 ULID를 하이픈으로 이은 모양이고 이 형식에 맞지 않는 ID는 기록에 있어도 `none`이다 [3][4].
모든 ID가 `none`이고 셸 명령 `supporting_commands`도 없으면 근거가 없다는 오류로 거부한다 [2].
기록에 없는 ID 하나만 준 발견사항과 기록에 없는 `audit_id`를 단 인용 원문은 모두 `REJECTED`로 거부되었다 [5].

**한계.** 근거로 보는 호출 기록은 백엔드나 도구를 가리지 않는다 [3].
`forensic-mcp`가 앞서 남긴 `record_finding` 호출 기록 항목 하나만 인용한 발견사항도 저장되었다 [5].
서버가 `supporting_commands`마다 `forensic-mcp`의 호출 기록에 남기는 `shell-` 항목도 `MCP`로 나눈다 [3][6].
`log_external_action`으로 모델이 알린 실행 항목도 `MCP`로 나눈다 [3][7].
ID 가운데 하나라도 기록에 있으면 기록에 없는 ID가 섞여 있어도 받고 그 ID들도 발견사항의 `audit_ids`에 남는다 [3][8].
`supporting_commands`에 명령과 목적만 적으면 그 명령이 실행되었는지와 관계없이 이 검사를 지난다 [2][6].
명령 칸에 `analytical reasoning`만 적고 근거 호출 ID를 비운 발견사항도 저장되었다 [5].
`case-mcp`의 `import_bundle`로 다른 사건에서 가져온 발견사항은 이 검사를 거치지 않고 DRAFT로 더해진다 [9][10].

### F05.02 근거 내용 대조

**구현.** 이 방식은 `forensic-mcp`의 `record_finding`이 받은 인용 원문 `artifacts`에 적용된다 [11].
서버는 항목마다 원문 `content`의 줄을 공백을 정리해 인용한 호출이 실제로 낸 출력과 대조한다 [12].
실행 호출이면 저장된 표준 출력 파일과 호출 기록에 적힌 출력 파일에서 줄을 찾고 그 파일이 기록된 SHA-256과 같을 때만 찾은 것으로 본다 [13][14].
위협 정보 조회와 정상 기준 대조 같은 참조 조회는 게이트웨이가 저장한 응답에서 찾고 찾아도 증거가 아니라는 사유로 `BROKEN`을 준다 [12][15].
한 줄이라도 찾지 못하면 그 항목의 출처 등급을 `CITED-UNVERIFIED`로 정하고 찾지 못한 줄을 사유에 적는다 [13].
발견사항의 출처 등급은 항목 등급 가운데 가장 낮은 것이고 참조 자료 항목은 증거 항목이 있으면 빼고 정한다 [16].
`CITED-UNVERIFIED` 발견사항도 거부하지 않고 DRAFT로 저장하며 응답 `message`에 등급과 사유를 싣는다 [17].
글자나 숫자가 없는 원문과 64K자를 넘는 원문은 거부한다 [18].
출력에 있는 줄을 인용한 발견사항은 `FULL`, 출력에 없는 문장을 인용한 발견사항은 `CITED-UNVERIFIED`로 저장되었다 [5].

**한계.** 대조는 `artifacts`의 원문에만 적용되고 관찰과 해석 글의 주장은 대조하지 않는다 [11][12].
`artifacts` 없이 근거 호출 ID만 준 발견사항은 대조 없이 `DECLARED` 등급으로 저장된다 [16].
`log_external_action`으로 남긴 호출이 출력 파일을 적지 않았으면 원문을 그 호출에 모델이 적은 `output_summary`와 대조한다 [19].
호출 기록에 적힌 출력 파일이 64MiB를 넘으면 그 파일은 읽지 않는다 [13][14].
`supporting_commands`의 출력 발췌 `output_excerpt`는 대조하지 않는다 [6].

### F05.04 교차 확인·반론 검토

**구현.** 이 방식은 `forensic-mcp`의 `record_finding`에 적용된다 [20].
`record_finding`은 반론 검토 결과 `challenged`가 없으면 거부한다 [20].
반론 검토는 클라이언트 쪽의 별도 에이전트가 하고 서버는 그 결과를 받아 검사한다 [20][21].
결과 `outcome`은 `stands`·`revised`·`contested`·`withdrawn`·`not_challenged` 가운데 하나여야 하고 아니면 `not_challenged`로 바꿔 저장한다 [22][23].
`contested`와 `withdrawn`은 반대 근거 `contradiction`이 없으면 `not_challenged`로 바꿔 저장한다 [23].
검사 항목 `checks`마다 결과와 반론 쪽 근거 호출 ID를 받고 그 ID가 증거 백엔드 호출 기록의 도구 출력이며 발견사항 자신의 근거 ID가 아닐 때만 결과를 인정한다 [24][25].
인정하지 못한 검사는 `not run`으로 저장하고 그 사유를 붙인다 [24].
인정한 ID마다 그 호출이 실행한 명령을 `ran`에 남긴다 [24].
제목과 관찰이 있는 `withdrawn`에 인정된 `contradicts` 검사와 반대 근거가 있으면 발견사항으로 저장하지 않고 `WITHDRAWN`을 돌려준다 [26][27].
조건을 채우지 못한 `withdrawn`은 철회를 거부하고 DRAFT로 저장하며 거부 사유를 `refused`에 남긴다 [28].
철회를 호출 기록에 남기지 못하면 검토자에게 넘기도록 DRAFT로 저장한다 [29].
다른 도구 출력을 근거로 낸 `withdrawn`은 저장되지 않았고 발견사항 자신의 근거 ID를 반론 근거로 낸 `withdrawn`은 철회가 거부되어 DRAFT로 저장되었다 [5].

**한계.** `not_challenged`와 사유를 주면 반론 검토 없이 DRAFT로 저장된다 [23].
인정된 검사가 하나도 없어도 `stands`·`revised`·`contested`는 받은 값 그대로 저장된다 [23][24].
서버는 반론 쪽 호출이 도구 출력인지와 발견사항 자신의 근거인지만 보고 그 호출이 주장을 다시 확인한 것인지는 보지 않는다 [24].
인정하는 호출 기록에는 `opencti-mcp`의 위협 정보 조회와 `windows-triage-mcp`의 정상 기준 조회 기록도 포함된다 [25].
반론 검토를 한 클라이언트와 모델 이름은 클라이언트가 적은 값을 `self_reported` 표시와 함께 저장한다 [30].

### F05.10 사람 검토

**구현.** 이 방식은 `forensic-mcp`의 `record_finding`·`record_timeline_event`, 검토 포털 `case-dashboard`의 승인 처리, `report-mcp`의 `generate_report`·`save_report`에 적용된다 [31][32][33][34].
`record_finding`은 정해 둔 필드만 입력에서 받고 발견사항을 상태 `DRAFT`로 저장한다 [31].
`record_timeline_event`는 상태와 승인 필드를 입력에서 버리고 타임라인 사건을 `DRAFT`로 저장한다 [32].
`forensic-mcp`의 발견사항·타임라인 도구는 기록하기와 읽기뿐이다 [35].
서버 쪽에서 발견사항과 타임라인 사건의 상태를 승인이나 반려로 바꾸는 곳은 검토 포털의 커밋이다 [36].
포털은 게이트웨이 API 키로 들어온 검토자만 서명하게 하고 키 없이 `anonymous`로 들어온 요청은 `NO_API_KEYS`로 거부한다 [33].
포털은 승인할 발견사항과 타임라인 사건마다 승인 확인 검사를 실행하고 실패한 항목은 검토자가 그 실패에 맞는 사유를 적어야 받는다 [37].
커밋은 항목마다 검토자의 서명을 받아 검증하고 서명이 없거나 검증되지 않으면 아무것도 쓰지 않고 거부한다 [36].
서명이 검증된 뒤에 서명 원장에 줄을 덧붙이고 항목의 상태를 바꿔 저장한다 [36].
사용자 CLI `vhir approve`로 서명한 결정도 같은 서명 원장에 들어간다 [38].

`generate_report`와 `save_report`는 보고 자료와 출처 블록을 만들 때마다 `approved_view`로 서명 원장을 다시 검증한다 [34][39].
`approved_view`는 서명 검증을 통과한 승인 항목만 보고에 실을 항목으로 고르고 나머지 승인 상태 항목은 `not_verified`에 상태와 함께 둔다 [39].
`forensic-mcp`의 `get_findings`·`get_timeline`은 승인 항목마다 같은 검증 결과를 `approval_verification`에 싣고 검증되지 않은 항목이 있으면 경고를 붙인다 [40].
서명 없이 `findings.json`의 상태만 `APPROVED`로 바꾼 발견사항은 보고 자료에서 빠졌다 [41].
승인한 뒤 관찰을 바꾼 발견사항도 보고 자료에서 빠지고 `ALTERED_AFTER_APPROVAL`로 실렸다 [42].

**한계.** 서명 원장을 쓰기 전의 0.6 형식 승인 기록 줄은 서명이 아니어도 항목 내용이 그 줄의 사본과 같으면 `APPROVED_UNDER_0_6`으로 보고 자료에 실린다 [43].
이 항목에는 `approved under 0.6 (before signing)` 표시가 붙는다 [43].
사건에 서명 원장이 하나도 없으면 0.6 형식 승인 기록 파일의 줄을 모두 승인 기록으로 센다 [44].
`approved_view`는 고정해 둔 키 없이 원장 검증을 부른다 [45].
그래서 서명은 그 줄에 담긴 공개키로만 검증되고 그 키가 검토자의 키인지는 대조하지 않는다 [45].
다른 사건에서 가져온 항목에는 승인 확인 검사를 적용하지 않고 결과를 `not-applicable`로 둔다 [46].

    """The quoted lines a run's saved output and recorded output files don't
    hold, each file only while it has its recorded hash; and the files too

    (up to the size cap) only while lines are still missing."""

    sources = [
        (relocated(case, e, rs.get("output_file")), rs.get("output_sha256"), None)
    ]

```python
def _found_in(path, sha256, lines: list[str], cap: int | None) -> tuple[set, str]:
    """Which quoted lines a saved file holds, read in bounded chunks with an
    overlap (whitespace normalized across them), the file counted only when it
    still has its recorded SHA-256. Returns (found, why skipped): a file over
    `cap` isn't read at all, and says so."""
    try:
        size = os.path.getsize(path)
    except (OSError, TypeError):
        return set(), ""
    if cap is not None and size > cap:
        return set(), f"output too large to check ({path})"
    if not sha256:
        return set(), ""
    digest = hashlib.sha256()
    decode = codecs.getincrementaldecoder("utf-8")(errors="replace").decode
    keep = max((len(q) for q in lines), default=0)
    found, carry = set(), ""
    try:
        with open_regular(path) as f:
            for chunk in iter(lambda: f.read(_CHUNK), b""):
                digest.update(chunk)
                text = re.sub(r"\s+", " ", decode(chunk))
                if carry.endswith(" ") and text.startswith(" "):
                    text = text[1:]
                window = carry + text
                found |= {q for q in lines if q in window}
                carry = window[-keep:] if keep else ""
    except (OSError, NotRegularFile):
        return set(), ""
    return (found if digest.hexdigest() == sha256 else set()), ""
```
