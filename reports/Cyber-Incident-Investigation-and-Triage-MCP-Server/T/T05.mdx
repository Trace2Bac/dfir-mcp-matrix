# T05 분석 도구 검증

### T05.01 저장소·의존성 고정

**구현.** 이 방식은 저장소에 들어 있는 도구 정의 파일 `config/forensic_tools.yaml`과 처리기 코드의 판단 목록에 적용된다 [1][2][3].
`forensic_tools.yaml`은 YAML 기반 도구 9개의 모듈 ID, 모듈마다 실행할 KAPE 모듈 이름 `kape_module_name`, 적용 파일, 포렌식 설명을 적는다 [1].
서버는 이 파일을 저장소 안의 정해진 경로에서 읽어 도구 명세와 실행할 KAPE 모듈을 정하므로 기준 커밋이 그 내용을 정한다 [1][4].
ShimCache 처리기의 의심 경로 목록과 이벤트 로그 처리기가 건수를 셀 이벤트 ID 같은 판단 목록은 서버 코드의 상수라 역시 기준 커밋이 내용을 정한다 [2][3].
FSEvents 파서는 mac_apt에서 옮겨 온 코드로 저장소에 들어 있다 [5].

분석 도구의 버전은 저장소가 고정하지 않는다.
`.gitignore`는 KAPE, Zimmerman 도구, SleuthKit, Arsenal Image Mounter, Volatility 3, UnifiedLogReader를 둘 `Tools/` 폴더를 저장소에서 뺀다 [6].
`install.ps1`은 그 도구들이 이미 `Tools\`에 있다고 적고 내려받거나 해시를 대조하지 않는다 [7].
chainbreaker는 `git+https://github.com/n0fate/chainbreaker.git`의 기본 브랜치를, apfs-fuse는 기본 브랜치를 `git clone`해 빌드하고 둘 다 커밋을 정하지 않는다 [7].
`requirements.txt`는 `python-registry`, `lz4`, `biplist`, `pefile`을 버전 없이 적는다 [8].
`mcp<2`는 증거를 해석하지 않는 서버 실행용 라이브러리라 이 방식으로 세지 않는다 [8].
KAPE 모듈 정의 파일과 EvtxECmd 맵 같은 도구 쪽 참조 자료도 `Tools/` 아래에 두므로 저장소가 내용을 정하지 않는다 [6].
Volatility 3가 쓰는 심볼 표도 저장소에 없고 서버는 Volatility 3에 심볼 폴더나 오프라인 옵션을 넘기지 않는다 [9].
Volatility 3 2.28.0은 로컬에 없는 Windows 심볼 표를 Microsoft 심볼 서버에서 PDB로 받아 변환한다 [10].

**한계.** `forensic_tools.yaml`은 KAPE 모듈의 이름만 정하고 그 이름의 모듈 정의 파일은 사용자가 둔 KAPE 폴더의 것을 쓴다 [1][6].

### T05.02 설정·호출 인자로 지정

**구현.** 이 방식은 `config/config.yaml`이 위치를 정하는 KAPE, Zimmerman 도구, SleuthKit, Arsenal, Volatility 3, hashcat과 `crack_hash`의 단어 목록·규칙 파일 인자에 적용된다 [11][12][13].
설정 파일은 KAPE 실행 파일과 모듈 폴더, SleuthKit 도구 8개, `aim_cli.exe`, `vol.py`와 해석기, hashcat 실행 파일·단어 목록·규칙 파일의 경로를 적는다 [11].
`load_config`는 설정의 `D:\forensics_mcp_server`로 시작하는 경로를 저장소 루트로 바꾸므로 기본 설정의 도구 위치는 저장소의 `Tools\` 아래가 된다 [12].
SleuthKit 경로의 폴더 이름 `sleuthkit-4.14.0-win32`만 버전을 드러내고 서버는 그 값을 버전으로 읽지 않는다 [11].
MFTECmd·AmcacheParser·AppCompatCacheParser는 KAPE 모듈 폴더의 `bin\`에서, EvtxECmd는 `bin\EvtxECmd\`에서 찾는다 [14].
`crack_hash`는 호출 인자 `wordlist`·`rules`로 단어 목록과 규칙 파일의 위치를 받고 `wordlist`가 없으면 설정의 기본 단어 목록을 쓴다 [13].
Volatility 3 설정의 `python_executable`이 `python`이면 서버 해석기 `sys.executable`을 쓴다 [15].
작업 사본에서 시험용 AmcacheParser·`vol.py`·hashcat이 이 규칙으로 정해진 위치에서 실행되었다 [16].

설정을 따르지 않는 도구도 있다.
`analyze_macos_unified_logs`는 설정의 `unified_log_reader` 경로를 읽지 않고 저장소 루트의 `Tools\macos_forensics\UnifiedLogReader`를 쓴다 [17].
chainbreaker는 서버 해석기에서 불러올 수 있는 `chainbreaker` 모듈을 쓰고 없으면 `PATH`와 해석기 폴더의 `Scripts`에서 찾는다 [18].
SleuthKit 이미지의 FSEvents 추출은 설정 대신 이름 `icat`만 넘긴다 [19].
`list_memory_plugins`는 `vol.py` 폴더를 작업 위치로 두고 `python.exe`라는 이름만 넘겨 서버 해석기 경로를 쓰지 않는다 [20].

**한계.** 설정한 hashcat 실행 파일이 없으면 `_resolve_hashcat`이 `PATH`의 `hashcat`이나 저장소 `Tools\hashcat*` 아래의 `hashcat.exe`로 바꾸고 단어 목록·규칙 파일 경로도 그 폴더 기준으로 바꾼다 [21].
기본 설정의 hashcat 경로가 없는 작업 사본에서 `crack_hash`는 `Tools\hashcat-fake\hashcat.exe`와 그 폴더의 `rockyou.txt`를 썼다 [16].
SleuthKit 설정을 읽지 못하거나 `sleuthkit.enabled`가 거짓이면 SleuthKit 도구는 설정 경로 대신 `mmls`·`fls`·`icat` 같은 이름으로 실행된다 [22].

```python
_LEGACY_BASES = ["D:\\forensics_mcp_server", "D:/forensics_mcp_server"]


def _remap_path_string(value: str) -> str:
    """Rewrite a single path string from the legacy install base to BASE_DIR."""
    repo_root = str(BASE_DIR)
    for legacy in _LEGACY_BASES:
        if value.lower().startswith(legacy.lower()):
            return repo_root + value[len(legacy):]
    return value


def _remap_config_paths(obj):
    """Recursively remap all path-like strings in the loaded config."""
    if isinstance(obj, dict):
        return {k: _remap_config_paths(v) for k, v in obj.items()}
    if isinstance(obj, list):
        return [_remap_config_paths(v) for v in obj]
    if isinstance(obj, str):
        return _remap_path_string(obj)
    return obj
```

```python
        if tools_dir.exists():
            matches = (list(tools_dir.glob("hashcat*/hashcat.exe"))
                       + list(tools_dir.glob("hashcat*/*/hashcat.exe")))
            found = str(matches[0]) if matches else None

    if not found:
        return config

    new_exe = str(Path(found).resolve())
    new_dir = str(Path(new_exe).parent)
    old_dir = hc.get("hashcat_directory", "")

    def _reroot(value):
        if isinstance(value, str) and old_dir and value.lower().startswith(old_dir.lower()):
            return new_dir + value[len(old_dir):]
        return value

    hc["executable_path"] = new_exe
    for key in ("default_wordlist", "potfile_path"):
        if key in hc:
            hc[key] = _reroot(hc[key])
    for section in ("wordlists", "rule_files"):
        if isinstance(hc.get(section), dict):
            hc[section] = {k: _reroot(v) for k, v in hc[section].items()}
    hc["hashcat_directory"] = new_dir
    return config
```

```python
    def _load_sleuthkit_config(self) -> Dict[str, str]:
        """Load SleuthKit tool paths from the central (portable) app config.

        Uses app_config.CONFIG so the paths go through the repo-root remap.
        Reading config.yaml directly here would use the non-portable hardcoded
        install paths (a "D:" drive that may not exist) and break SleuthKit
        discovery -- reporting "SleuthKit not installed" even when the binaries
        are present under the repo's Tools/ folder.
        """
        try:
            from app_config import CONFIG
            sleuthkit_config = CONFIG.get('sleuthkit', {})
            if not sleuthkit_config.get('enabled', False):
                raise Exception("SleuthKit is disabled in config")

            return sleuthkit_config.get('tools', {})
        except Exception as e:
            self.logger.error(f"Failed to load SleuthKit config: {e}")
            return {
                'mmls': 'mmls',
                'fsstat': 'fsstat',
                'fls': 'fls',
                'icat': 'icat'
            }
```
