# T09 대상 시스템 대응 조치 처리

### 비적용

**판단.** 서버는 조사하는 대상 시스템에 접속하거나 그 상태를 바꾸는 도구를 두지 않는다.
도구 31개는 디스크 이미지를 준비하고 그 안의 파일이나 사용자가 넘긴 증거 파일을 읽어 분석한다 [1].
서버 코드가 실행하는 외부 프로그램은 KAPE, EZ Tools, SleuthKit, Volatility 3, chainbreaker, hashcat, Arsenal Image Mounter, WSL의 마운트 도구이고 원격 호스트에 접속하는 프로그램은 없다 [1].
서버가 여는 연결은 `remote_server.py`가 MCP 클라이언트의 요청을 받는 SSE 서버뿐이다 [2].
격리, 차단, 프로세스 종료, 계정 잠금, 파일 삭제, 설정 변경을 하는 도구는 없다.
`analyze_registry` 같은 도구는 이미지에 속하지 않는 경로도 받아 서버가 실행되는 호스트의 파일을 읽지만 그 파일을 바꾸지 않는다 [3].

이미지를 붙이고 떼는 일은 서버가 실행되는 분석 호스트에서 일어난다.
`prepare_disk_image`는 Windows 이미지를 `aim_cli.exe --mount --readonly --background`로 붙이고 새로 생긴 드라이브 문자를 접근 위치로 쓴다 [4].
APFS 물리 저장소는 WSL 배포판 `Ubuntu`에서 apfs-fuse로 `/tmp` 아래에 붙인다 [5].
LVM2 이미지는 같은 배포판에서 root로 `losetup`을 실행하고 `vgchange -ay`로 볼륨 그룹을 켠 뒤 `mount -o ro`로 붙인다 [6].
`vgchange -ay`는 이미지의 볼륨 그룹만이 아니라 그 배포판이 찾은 모든 볼륨 그룹을 켠다 [6].
SleuthKit 방식은 이미지를 붙이지 않고 출력 폴더에 접근 위치 폴더와 메타데이터 파일만 만든다 [7].

`cleanup_prepared_image`가 바꾸는 것도 분석 호스트의 마운트 상태와 서버의 등록부다 [8].
Arsenal 항목은 같은 프로세스에 남은 마운트 객체가 있으면 `aim_cli.exe` 프로세스를 끝내고 없으면 장치를 지정하지 않은 `aim_cli.exe --dismount`를 실행한다 [8][9].
그 뒤 성공 여부와 상관없이 장치를 지정하지 않은 `--dismount`를 한 번 더 실행한다 [8].
응답은 이 실행을 `Final Arsenal CLI dismount (all devices)`로 적는다 [8].
SleuthKit 항목은 같은 프로세스에 접근 객체가 남아 있으면 접근 위치 폴더를 지운다 [10].
WSL로 붙인 `wsl_apfs_fuse`·`wsl_lvm` 항목은 등록부에서만 지우고 마운트, 루프 장치, 볼륨 그룹은 그대로 둔다 [8].
서버 코드에는 WSL 마운트를 떼는 함수를 부르는 곳이 없다 [11].
`force` 인자는 받기만 하고 쓰지 않는다 [8].
실행 확인에서 실제 마운트 없이 등록부에 Arsenal 항목을 넣고 시험용 `aim_cli.exe`로 `cleanup_prepared_image`를 부르면 `--dismount`만 받은 실행이 두 번 있었다 [12].
같은 실행 확인에서 `wsl_lvm` 항목은 `Unknown mount type 'wsl_lvm' - cleaning up metadata only`로 끝났다 [12].

분석 도구의 출력과 임시 파일은 서버 자신의 작업 파일이다.
KAPE, EZ Tools, Volatility 3의 출력은 설정의 출력 폴더 아래 사건 폴더에 쓰이고 이미지에서 꺼낸 파일은 출력 폴더와 임시 폴더에 쓰인다 [13].
`crack_hash`는 해시를 시스템 임시 폴더의 파일로 쓰고 실행이 끝나면 지운다 [14].
그래서 조치 전후 상태, 변경 내역, 되돌림을 남길 대상 시스템 조치가 없다.

```python
def sanitize_path_component(component: str) -> str:
    """
    Sanitize a string to be safe for use as a filesystem path component.
    
    Args:
        component: String to sanitize
        
    Returns:
        str: Sanitized string safe for filesystem paths
        
    Example:
        >>> safe_name = sanitize_path_component("Windows/System32\\config")
        >>> # Returns: "Windows_System32_config"
    """
    sanitized = component.replace('\\', '_').replace('/', '_')
    sanitized = sanitized.replace(':', '').replace('*', '').replace('?', '')
    sanitized = sanitized.replace('"', '').replace('<', '').replace('>', '').replace('|', '')
    sanitized = sanitized.replace(' ', '_')
    
    return sanitized
```
