# T02 실행 허용 범위 제한

### T02.04 고정 명령·템플릿

**구현.** 이 방식은 YAML 기반 도구 9개, `kape_parse_artifact`, SleuthKit 추출, `analyze_macos_keychain`, `crack_hash`, `analyze_memory`, `analyze_sqlite_database`의 정해 둔 연산이 외부 도구나 질의를 실행하는 경로에 적용된다 [1][2][3][4][5][6][7].
YAML 기반 도구 가운데 KAPE를 거치는 5개는 `kape.exe`에 `--msource <원본 폴더> --mdest <출력 폴더> --module <KAPE 모듈>` 인자 배열을 넘긴다 [1].
KAPE 모듈 이름은 모델이 고른 모듈 ID에 대응해 YAML에 적힌 `kape_module_name`이다 [1].
MFT·Amcache·ShimCache·이벤트 로그 도구는 MFTECmd·AmcacheParser·AppCompatCacheParser·EvtxECmd를 KAPE 없이 직접 실행하고 `-f <파일>`과 `--csv <출력 폴더>` 같은 정해 둔 배열을 넘긴다 [2].
모델 값은 입력 경로와 출력 형식 자리에만 들어간다 [1][2].
SleuthKit 추출은 `icat -o <오프셋> <이미지> <inode>`처럼 서버가 정한 배열로 실행한다 [3].
`analyze_macos_keychain`은 `dump_type`을 정해 둔 플래그 하나로 바꾸고 그 뒤에 파일 경로와 `--password <값>`을 붙인다 [4].
`crack_hash`는 `-m <모드> -a 0 <해시 파일> <단어 목록>` 뒤에 규칙 파일과 설정의 작업 부하 값을 붙인다 [5].
등록되지 않은 `Amcache.hve`로 부른 `analyze_amcache`와 해시 하나로 부른 `crack_hash`에서 시험용 실행 파일이 받은 인자 배열이 이 틀과 같았다 [8].
`analyze_sqlite_database`의 `list_tables`·`describe_table`·`export_table`은 서버가 쓴 SQL 틀에 `table_name`을 대괄호로 감싸 넣는다 [6].

모델이 명령의 일부를 직접 정하는 도구도 있다.
`analyze_memory`는 `-f <파일>`과 `-r <출력 형식>` 뒤에 모델이 준 `plugin`과 `plugin_args`를 그대로 붙인다 [7].
`get_memory_plugin_help`도 받은 `plugin`을 Volatility 3 인자로 넘긴다 [9].
`kape_parse_artifact`는 받은 `kape_module`을 `--module`의 값으로 넘기고 그 값을 어떤 목록과도 대조하지 않는다 [10].
`analyze_sqlite_database`의 `query` 연산은 모델이 쓴 SQL 문장을 실행한다 [11].

**한계.** 서버는 모델 값이 `-`로 시작하는지 보지 않고 옵션 끝을 알리는 표시도 넣지 않는다 [7][10].
Volatility 3에 `plugin`으로 `-`로 시작하는 값을 주면 그 값이 플러그인 이름 자리에 그대로 들어간다 [7].
`table_name`은 대괄호로 감싸기만 하고 값 안의 문자는 검사하지 않는다 [6].
두 경우 외부 도구나 SQLite가 그 값을 어떻게 읽는지는 실행해 확인하지 않았다.

### T02.05 연산·플러그인 허용 목록

**구현.** 이 방식은 YAML 기반 도구의 `modules`, `analyze_sqlite_database`의 `operation`, `analyze_macos_keychain`의 `dump_type`, `crack_hash`의 `hash_mode_name`에 적용된다 [12][13][4][14].
YAML 기반 도구는 `modules`를 `config/forensic_tools.yaml`의 모듈 ID 목록과 대조해 목록 밖이면 거부한다 [12].
없는 모듈 ID를 레지스트리 도구에 주자 KAPE를 실행하지 않고 허용 ID 목록을 적은 오류가 돌아왔다 [8].
`analyze_sqlite_database`는 `operation`이 연산 4개가 아니면 `Unknown operation`으로 거부한다 [13].
MCP SDK도 입력 schema의 `enum`으로 같은 값을 먼저 거부한다 [15].
`analyze_macos_keychain`은 `dump_type`이 `all`·`passwords`·`certificates`·`keys`가 아니면 거부하지 않고 `--dump-all`을 쓴다 [4].
`crack_hash`는 `hash_mode_name`을 설정의 `common_hash_modes`에서 찾아 모드 번호로 바꾸고 없으면 거부한다 [14].

**한계.** `crack_hash`의 `hash_mode`는 정수이기만 하면 목록과 대조하지 않고 `-m`의 값이 된다 [14][5].
`query` 연산은 자유 질의를 받으므로 연산 목록이 질의 내용을 좁히지 않는다 [11].

### T02.06 질의 구조·연산 검사

**구현.** 이 방식은 `analyze_sqlite_database`의 SQL 실행에 적용된다 [16].
서버는 이미지에서 꺼낸 DB 사본을 `file:<경로>?mode=ro` URI로 열어 SQLite가 그 DB 파일의 쓰기를 거부하게 한다 [16].
행을 넣는 문장을 주자 `attempt to write a readonly database`로 거부되었다 [17].
서버 코드는 SQL의 구조나 연산을 검사하지 않고 `cursor.execute`에 넘긴다 [11].

**한계.** 읽기 전용 모드는 열린 DB 파일의 쓰기만 막고 SQL이 지정한 다른 경로에 DB 사본을 새로 쓰는 문장은 막지 않는다 [16][11].
그런 문장을 주자 응답은 오류였지만 작업 폴더에 새 DB 파일이 생겼다 [17].
다른 DB 파일을 붙이는 문장은 실행되었지만 호출마다 문장 하나만 실행하고 연결을 닫으므로 붙인 파일을 같은 호출에서 읽지 못했다 [17][18].

### T02.08 설정으로 도구 끄기

**구현.** 이 방식은 `crack_hash`와 `prepare_disk_image`에 적용된다 [19][20].
`crack_hash`는 모듈을 불러올 때 읽은 `hashcat.enabled`가 거짓이면 hashcat을 실행하지 않고 오류 글을 돌려준다 [19].
`prepare_disk_image`는 `sleuthkit.enabled`가 거짓이면 `verify_tool_requirements`에서 `ToolNotAvailableError`가 나 마운트하지 않는다 [20].
두 도구는 이 값과 관계없이 `tools/list`에 남는다 [21].
두 값을 거짓으로 둔 작업 사본에서 도구는 31개였고 두 도구를 부르자 각각 `Hashcat is not enabled`와 `TOOL NOT AVAILABLE`이 돌아왔다 [22].
설정 파일의 `arsenal.enabled`와 `macos_forensics` 아래의 `enabled` 값은 서버 코드가 읽지 않는다 [23].

**한계.** `sleuthkit.enabled`가 거짓이어도 SleuthKit 접근 클래스는 설정을 읽지 못한 경우로 처리해 `mmls`·`fls`·`icat` 같은 이름만 담은 도구 표를 쓴다 [24].
그래서 등록부에 이미 있는 이미지를 읽는 도구는 이 값과 관계없이 SleuthKit 도구를 실행한다 [24].
이 경로는 코드로만 따라갔다.

```python
    def _load_sleuthkit_config(self) -> Dict[str, str]:
        """Load SleuthKit tool paths from the central (portable) app config.

        Uses app_config.CONFIG so the paths go through the repo-root remap.
        Reading config.yaml directly here would use the non-portable hardcoded
        install paths (a "D:" drive that may not exist) and break SleuthKit
        discovery -- reporting "SleuthKit not installed" even when the binaries
        are present under the repo's Tools/ folder.
        """
        try:
            from app_config import CONFIG
            sleuthkit_config = CONFIG.get('sleuthkit', {})
            if not sleuthkit_config.get('enabled', False):
                raise Exception("SleuthKit is disabled in config")

            return sleuthkit_config.get('tools', {})
        except Exception as e:
            self.logger.error(f"Failed to load SleuthKit config: {e}")
            return {
                'mmls': 'mmls',
                'fsstat': 'fsstat',
                'fls': 'fls',
                'icat': 'icat'
            }
```
