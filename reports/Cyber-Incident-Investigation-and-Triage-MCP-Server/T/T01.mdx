# T01 입력 검증

### T01.01 인자 구조·값 검사

**구현.** 이 방식은 MCP SDK가 `tools/list`에 실린 도구 31개에 하는 입력 schema 검사와 YAML 기반 도구 9개·`crack_hash`·`read_csv_data`·`analyze_sqlite_database`의 서버 코드 값 검사, 파일을 읽는 도구 4개의 입력 파일 크기 검사에 적용된다 [1][2][3][4].
서버는 MCP Python SDK의 저수준 `Server`에 `call_tool`을 등록하고 `validate_input` 기본값 `True`를 바꾸지 않는다 [5].
MCP Python SDK 1.29.1은 호출된 도구의 정의를 `tools/list` 결과에서 찾아 `jsonschema.validate`로 인자를 검사하고 어긋나면 처리기를 부르지 않고 `Input validation error` 응답을 돌려준다 [1].
입력 schema가 `enum`을 적은 인자는 `analyze_sqlite_database`의 `operation`, `analyze_macos_plist`의 `plist_type`, `analyze_macos_unified_logs`·`decompress_mozilla_lz4`의 `output_format`, YAML 기반 도구의 `output_format`이다 [6][7].
`operation`에 목록 밖의 값을, `analyze_lnk_files`의 `output_format`에 목록 밖의 값을, `analyze_memory`의 `memory_file`에 정수를 주자 모두 이 오류로 거부되었다 [8].

YAML 기반 도구는 `modules`를 `config/forensic_tools.yaml`의 그 도구 모듈 ID 목록과 대조한다 [2][9].
레지스트리·Prefetch 처리기는 `validate_module_ids`로 목록 밖의 ID를 골라 그 ID와 허용 ID를 적은 오류를 돌려주고 KAPE를 실행하지 않는다 [2].
Shellbags·LNK·점프 목록·MFT·Amcache·ShimCache 처리기도 각자 같은 목록과 대조해 거부한다 [9].
`modules`에 `all`이 있으면 목록의 모든 모듈을 실행한다 [2].
레지스트리 도구에 없는 모듈 ID를 주자 허용 ID 9개를 적은 `INVALID MODULE IDs` 오류가 돌아왔다 [10].
Shellbags·LNK·점프 목록 처리기는 `output_format`이 YAML의 `available_output_formats`에 없으면 거부하지 않고 `csv`로 바꾼다 [11].
이벤트 로그 처리기는 `output_format`이 `csv`·`json`·`xml`이 아니면 `--csv`를 쓴다 [12].

`crack_hash`는 `hash_mode_name`을 소문자로 바꿔 `config/config.yaml`의 `common_hash_modes`에서 찾고 없으면 허용 이름을 적은 오류를 돌려준다 [13].
없는 이름을 주자 `Unknown hash mode name` 오류와 함께 설정의 이름 목록이 돌아왔다 [10].
`hash_mode`와 `hash_mode_name`이 모두 없으면 `hash_value`의 꼴로 모드를 고르고 고르지 못하면 거부한다 [13].
`read_csv_data`는 `start_row`가 1보다 작으면 1로, `end_row`가 행 수보다 크면 행 수로 바꾸고 `start_row`가 `end_row`보다 크면 거부한다 [14].
`read_csv_data`는 확장자가 `.csv`가 아니면, `decompress_mozilla_lz4`는 확장자와 `mozLz40` 머리글이 맞지 않으면, `analyze_sqlite_database`는 파일 앞의 `SQLite format 3` 머리글이 없으면 거부한다 [15].

서버가 실행할 때 읽는 기준은 저장소의 `config/forensic_tools.yaml`과 `config/config.yaml`이다 [9][13].
`forensic_tools.yaml`을 읽지 못하면 도구 생성 함수는 빈 목록을 돌려주고 처리기는 설정 파일 예외나 `Tool configuration ... not found` 오류로 끝난다 [16].
`common_hash_modes`가 없으면 빈 목록과 대조하므로 모든 `hash_mode_name`이 거부된다 [13].

`read_text_file`·`parse_xml_evidence`는 50MB, `read_csv_data`는 100MB, `decompress_mozilla_lz4`는 10MB를 넘는 입력 파일을 분석하지 않고 거부한다 [4].
호출 인자의 크기와 건수 값에는 범위 검사가 없다.
`read_text_file`의 `max_lines`, `browse_files_and_folders`의 `depth`, `analyze_sqlite_database`의 `max_rows`, `crack_hash`의 `timeout`은 받은 값을 그대로 쓴다 [17].
`analyze_memory`의 `plugin`·`plugin_args`·`output_format`과 `kape_parse_artifact`의 `kape_module`은 값 검사 없이 외부 도구 인자가 된다 [18][19].
`analyze_macos_keychain`의 `dump_type`은 목록 밖이면 `--dump-all`로 바꾼다 [20].

**한계.** `call_tool`은 `tools/list`에 없는 이름 `list_files`·`browse_prepared_image_files`도 `browse_files_and_folders`의 처리기로 보낸다 [3].
SDK는 목록에 없는 도구 이름이면 경고만 남기고 입력 schema 검사를 하지 않는다 [1].
그래서 이 두 이름으로 부르면 `browse_files_and_folders`의 자료형 검사가 적용되지 않는다 [3][1].
이 경로는 코드로만 따라갔다.

YAML 기반 도구의 처리기는 `server.py`에서 `paths`·`modules`·`output_format` 세 인자만 받아 부르고 그 밖의 인자는 넘기지 않는다 [3].

### T01.02 입력 존재·읽기 가능 검사

**구현.** 이 방식은 파일 경로를 받는 도구 대부분에 적용된다 [21][22][23][24].
`analyze_memory`는 `memory_file`이 없으면 Volatility 3를 실행하지 않고 `Memory file not found`를 돌려준다 [21].
없는 메모리 파일을 주자 시험용 `vol.py`는 실행되지 않고 이 오류가 돌아왔다 [10].
`prepare_disk_image`는 이미지 파일이 없으면 해시 계산과 마운트를 하지 않고 거부한다 [22].
`analyze_macos_unified_logs`는 세 경로를 읽을 수 있는 경로로 바꾼 뒤 하나라도 없으면 거부한다 [23].
`crack_hash`는 단어 목록과 규칙 파일이 없으면 hashcat을 실행하지 않고 거부한다 [24].
`read_text_file`·`parse_xml_evidence`·`read_csv_data`·`decompress_mozilla_lz4`는 대상이 없거나 일반 파일이 아니면 거부한다 [25].
Shellbags를 뺀 YAML 기반 도구는 경로 확인을 통과하지 못한 경로 가운데 있는 경로만 받고 받은 경로가 하나도 없으면 거부한다 [26].
MFT·Amcache 처리기는 폴더를 받으면 그 아래 `$MFT`·`Amcache.hve`가 있는지 확인한다 [27].
서버는 읽기 권한을 미리 확인하지 않는다.

**한계.** `crack_hash`는 단어 목록과 규칙 파일이 있는지 서버의 작업 위치에서 확인하고 hashcat은 hashcat 폴더를 작업 위치로 실행하므로 상대 경로는 확인한 파일과 다른 파일을 가리킬 수 있다 [28].
이 경로는 실행해 확인하지 않았다.

### T01.03 실제 경로로 변환해 허용 폴더 대조

**구현.** 이 방식은 경로 인자를 `validate_file_access`로 검사하는 도구에 적용된다 [29][30].
허용 폴더는 준비된 이미지 등록부 `PREPARED_IMAGES`의 항목마다 있는 `access_point`(마운트 위치나 접근 폴더)와 `case_dir`(사건 출력 폴더)이다 [29].
`get_prepared_image_for_path`는 경로를 `Path.resolve()`로 실제 경로로 변환하고 각 허용 폴더도 변환한 뒤 `relative_to`로 그 아래인지 대조한다 [29].
어느 폴더 아래에도 없으면 `SecurityError`로 거부한다 [29].
이 검사를 통과해야 실행하는 도구는 `read_text_file`·`parse_xml_evidence`·`analyze_sqlite_database`·`kape_parse_artifact`·`analyze_macos_plist`·`analyze_macos_keychain`·`analyze_macos_fsevents`다 [30].
`read_csv_data`·`decompress_mozilla_lz4`는 경로가 출력 폴더 조건에 맞지 않으면 이 검사를 거쳐 허용 폴더 밖의 경로를 거부한다 [31][32].
준비된 이미지가 없을 때 `analyze_sqlite_database`에 작업 폴더의 파일을 주자 `ACCESS DENIED`로 거부되었다 [10].

같은 함수를 부르지만 거부하지 않는 도구가 있다.
Shellbags와 이벤트 로그를 뺀 YAML 기반 도구 7개와 `identify_file_type`은 `SecurityError`가 나면 받은 경로가 있는지만 보고 그 경로를 분석 입력으로 쓴다 [26][33].
Shellbags 처리기는 `except SecurityError`로 대조 실패를 받도록 적었지만 그 이름을 불러오지 않는다 [34].
그래서 대조에 실패하면 `NameError`가 나 처리기 전체가 `FATAL ERROR`로 끝나고 SBECmd를 실행하지 않는다 [34].
등록된 이미지가 없을 때 작업 폴더 경로를 `analyze_shellbags`에 주자 `name 'SecurityError' is not defined`를 담은 `FATAL ERROR`가 돌아왔고 시험용 KAPE는 실행되지 않았다 [35].
`analyze_memory`·`prepare_disk_image`·`crack_hash`는 이 함수를 부르지 않는다 [21][22][24].
`crack_hash`는 `hash_value`가 있는 파일 경로이면 그 파일을 해시 파일로 hashcat에 넘기고 이 경로도 허용 폴더와 대조하지 않는다 [24].
`analyze_macos_unified_logs`는 실행 전에는 이 함수를 부르지 않고 분석을 마친 뒤 결과를 둘 사건 폴더를 찾을 때 `uuidtext_path`로 부른다 [23][36].
그래서 등록된 이미지가 있을 때 등록된 이미지 밖의 경로를 주면 UnifiedLogReader는 실행되고 응답은 분석 결과 대신 오류 문구가 된다 [36].
등록된 이미지 밖의 `Amcache.hve`를 `analyze_amcache`에 주자 시험용 AmcacheParser가 그 파일 경로를 `-f` 인자로 받았다 [10].

**한계.** 대조를 통과한 경로 가운데 Arsenal 마운트 경로와 메타데이터 파일이 없는 사건 폴더 경로는 `get_readable_file_path`가 받은 문자열을 그대로 돌려주어 변환한 경로가 아니라 그 문자열로 파일을 연다 [37].

`get_prepared_image_for_path`는 실제 경로로 변환하기 전에 `/`나 `\`로 시작하는 경로를 문자열로 먼저 본다 [38].
SleuthKit으로 준비한 Linux 이미지가 등록되어 있으면 `/`로 시작하는 경로는 실제 경로 대조 없이 받는다 [38].
SleuthKit으로 준비한 macOS 이미지가 등록되어 있을 때도 `/`로 시작하는 경로를 받는다 [38].
이 경로를 받은 처리기가 이미지 안의 경로로 다루지 않으면 같은 문자열을 호스트 경로로 연다 [37].
`read_text_file`과 `read_csv_data`는 검사를 통과한 `/mnt/<드라이브>/` 아래 경로를 Windows 드라이브 경로로 바꿔 연다 [39].
SleuthKit Linux 항목을 등록한 상태에서 등록 폴더 밖의 시험 파일을 `/mnt/` 꼴 경로로 `read_text_file`에 주자 그 파일 내용이 돌아왔고 같은 파일을 Windows 경로로 주자 거부되었다 [40].

`analyze_sqlite_database`는 `db_path`만 이 대조로 검사하고 `query` 연산의 SQL은 검사하지 않는다 [41].
한 호출은 SQL 문장 하나만 실행하고 호출이 끝나면 연결을 닫는다 [41][42][43].
다른 DB 파일을 붙이는 문장을 주자 붙이기는 실행되었지만 응답은 오류였고 붙인 파일의 행을 같은 호출에서 읽지 못했다 [43].

### T01.04 문자열 경로 검사

**구현.** 이 방식은 출력 폴더나 등록 폴더를 문자열로 받는 경로와 이벤트 로그·Shellbags 밖 일부 처리기의 대체 경로에 적용된다 [44][31][45][46].
`browse_files_and_folders`는 이미지에 속하지 않는 경로라도 `Path.absolute()` 문자열이 출력 폴더 `OUTPUT_DIR`의 문자열로 시작하면 그 폴더를 나열한다 [44].
이 도구는 경로 문자열이 등록 항목의 `access_point` 문자열로 시작하는지로 이미지를 고르고 처리 중 예외가 나면 SleuthKit 접근 폴더와 `access_point`도 같은 문자열 접두어로 비교한다 [44][46].
`read_csv_data`·`decompress_mozilla_lz4`는 경로가 `BASE_OUTPUT_DIR` 문자열로 시작하거나 경로 어디에든 그 폴더 이름 `forensic_output`이 들어 있으면 이미지 검사 없이 연다 [31].
이벤트 로그 처리기는 이미지 검사를 통과하지 못한 경로가 설정의 출력 폴더나 임시 폴더 문자열로 시작하고 존재할 때만 받는다 [45].
이 비교는 파일시스템을 보지 않는다 [44][31][45].
`Path.absolute()`는 `..`을 해석하지 않으므로 비교한 문자열과 실제 위치가 다를 수 있다 [44].
`get_prepared_image_for_path`의 `/`로 시작하는 경로 처리도 문자열 비교다 [38].

**한계.** `read_csv_data`·`decompress_mozilla_lz4`의 폴더 이름 비교는 접두어가 아니라 포함 여부라서 출력 폴더 밖이라도 경로에 그 이름이 있으면 통과한다 [31].
LNK·점프 목록 처리기는 출력 폴더 문자열을 비교하지만 결과와 상관없이 있는 경로를 받는다 [47].

### T01.05 등록된 ID와 대조

**구현.** 이 방식은 `/<unique_image_id>/` 꼴의 이미지 경로와 `cleanup_prepared_image`의 `image_path`에 적용된다 [38][48].
`get_prepared_image_for_path`는 `/`로 시작하는 경로의 첫 단계를 등록된 이미지의 `unique_image_id`와 대조하고 같으면 그 이미지의 정보를 돌려준다 [38].
`get_readable_file_path`와 `browse_files_and_folders`도 같은 첫 단계로 이미지를 고르고 나머지 경로를 이미지 안의 경로로 쓴다 [37][49].
`cleanup_prepared_image`는 `image_path`가 등록부의 키에 없으면 정리하지 않고 거부한다 [48].
등록부는 `prepare_disk_image`가 성공하면 만들고 `forensic_output/prepared_images_registry.json`에 저장한다 [50].
stdio 진입점 `main.py`는 시작할 때 이 파일을 다시 읽고 `remote_server.py`는 읽지 않는다 [50][51].

**한계.** 같은 경로 인자는 첫 단계가 등록된 ID가 아니어도 다른 분기에서 받는다 [38].

### T01.07 입력 부재 시 다른 입력으로 대체

**구현.** 이 방식은 WSL apfs-fuse로 마운트한 APFS 이미지와 SleuthKit 이미지의 이미지 안 경로 해석, LVM2 이미지 준비에 적용된다 [52][53][54].
`WSLAPFSMounter.extract_file`은 요청한 경로를 `cp`로 복사하지 못하면 같은 폴더에서 이름을 대소문자 구분 없이 `find -iname`으로 찾아 처음 나온 파일을 대신 복사한다 [52].
`resolve_path_to_inode`는 경로 단계마다 `fls` 목록에서 이름을 대소문자 구분 없이 비교해 처음 맞는 항목을 따라간다 [53].
그래서 대소문자를 가리는 파일시스템에서는 요청한 이름이 없거나 대소문자만 다른 항목이 `fls` 목록에서 먼저 나오면 그 항목이 입력이 된다 [53].
두 경로 모두 응답에 바꾼 경로를 따로 표시하지 않는다 [52][53].
`prepare_disk_image`는 LVM2 이미지를 WSL로 마운트하지 못하면 거부하지 않고 파일시스템 종류가 `lvm2`·`unknown`·`fat`이 아닌 첫 파티션으로 바꿔 준비한다 [54].
응답은 파티션 수와 쓴 파티션 번호만 적고 LVM 볼륨 대신 다른 파티션을 읽는다는 사실은 적지 않는다 [54][55].
이 동작은 이미지를 마운트하지 않아 코드로만 확인했다.
