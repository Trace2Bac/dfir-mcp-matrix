# T10 도구 명세 구성

### T10.02 처리기와 따로 둔 명세

**구현.** 이 방식은 서버가 등록하는 도구 31개 모두에 적용된다 [1].
서버는 MCP Python SDK의 저수준 `Server`를 쓰고 `list_tools` 처리 함수가 `Tool` 객체 목록을 직접 만들어 돌려준다 [1].
도구 22개의 이름, 설명, 입력 schema는 `server.py`의 `list_tools` 안에 손으로 적었다 [2].
나머지 9개는 `list_tools`가 실행될 때마다 `generate_tools_from_yaml`이 `config/forensic_tools.yaml`의 도구 항목에서 만든다 [1][3].
처리기와 명세를 잇는 것은 `call_tool`의 이름 분기와 `get_tool_handler_mapping`의 이름·처리기 표이고 둘 다 명세와 따로 코드에 적혀 있다 [4][5].

YAML에서 만드는 도구는 항목 키 앞에 `analyze_`를 붙여 이름을 짓는다 [3].
설명은 `tool_name`, `short_description`, `forensic_value`, `category`와 모듈마다의 이름·짧은 설명으로 만든다 [6].
입력 schema는 9개 모두 `paths`, `modules`, `output_format` 세 인자로 같고 `output_format`의 `enum`과 기본값만 항목의 `available_output_formats`에서 가져온다 [7].
`call_tool`은 이 9개 도구에 `paths`, `modules`, `output_format` 세 값만 넘긴다 [4].

MCP Python SDK 1.29.1의 `Server`는 `list_tools`가 돌려준 도구를 저장해 두고 호출 인자를 그 입력 schema로 검사한다 [8].
목록에 없는 이름은 schema 검사 없이 처리 함수로 넘긴다 [8].
`call_tool`의 분기에는 목록에 없는 이름 `list_files`와 `browse_prepared_image_files`도 있고 `browse_files_and_folders`와 같은 처리기로 간다 [9].
도구 annotation, 출력 schema, 목록 변경 알림은 없고 리소스, 프롬프트, 서버 지침 `instructions`도 없다 [10].
실행 확인에서 도구는 31개였고 annotation과 출력 schema가 있는 도구는 0개였으며 초기화 응답의 `tools.listChanged`는 거짓이었다 [10].
같은 실행 확인에서 `analyze_registry`에 `output_format` `xml`을 주자 `isError`가 참인 `Input validation error: 'xml' is not one of ['csv', 'json']`가 왔다 [10].

**한계.** YAML을 읽지 못하면 그 9개 도구는 알림 없이 목록에서 빠진다.
`generate_tools_from_yaml`은 설정을 읽다 예외가 나면 서버 기록에만 남기고 빈 목록을 돌려준다 [3].
`get_tool_handler_mapping`은 YAML과 상관없이 9개 이름을 처리기로 보낸다 [5].
실행 확인에서 같은 프로세스에서 설정 읽기 함수만 예외를 내게 바꾸자 만든 도구 수가 9에서 0이 되었다 [11].
YAML 항목의 `detailed_description`은 읽기만 하고 설명에 넣지 않는다 [6].

다음 도구는 명세가 알리는 것과 처리기의 동작이 다르다.

- `analyze_prefetch`, `analyze_shellbags`, `analyze_lnk_files`, `analyze_jump_lists`는 `output_format`을 KAPE에 넘기지 않는다 [12].
- `analyze_registry`만 KAPE에 `--mef`로 형식을 넘긴다 [12].
- `analyze_event_logs`는 `modules` 값을 쓰지 않고 늘 `event_logs_all`로 실행한다 [13].
- 9개 도구의 `paths` 설명은 하위 폴더를 재귀로 찾는다고 적고 `C:/Windows/System32/config/`와 `C:/Users/`를 예로 든다 [7].
- `analyze_mft`와 `analyze_amcache`는 폴더를 받으면 그 폴더 바로 아래 `$MFT`와 `Amcache.hve`만 찾고 `analyze_shimcache`는 파일만 받는다 [14].
- `analyze_event_logs`는 준비한 이미지, 설정의 출력 폴더, 임시 폴더 밖의 경로를 받지 않는다 [15].
- `cleanup_prepared_image`의 `force`, `audit_kape_operations`의 `date`, `get_memory_plugin_help`의 `memory_file`은 처리기가 받기만 하고 쓰지 않는다 [16].
- `analyze_macos_fsevents`의 `start_time`과 `end_time`은 시간 필터라고 설명하지만 처리기는 응답 머리에 그 값을 적기만 하고 사건을 거르지 않는다 [17].
- `analyze_macos_fsevents`는 이미지에서 FSEvents 파일을 앞 10개만 꺼내 읽고 설명은 이 상한을 적지 않는다 [18].
- `analyze_macos_unified_logs`의 설명은 10~30분이 걸릴 수 있다고 적지만 처리기는 300초만 기다린다 [19].
- `analyze_sqlite_database`의 설명은 `export_table`이 표 전체를 내보낸다고 적지만 처리기는 `max_rows`(기본 1000)행까지만 쓴다 [20].
- `list_hash_modes`의 설명은 hashcat이 지원하는 모든 해시 모드를 보인다고 적지만 처리기는 hashcat을 실행하지 않고 설정의 `common_hash_modes` 14개만 돌려준다 [21].
- `analyze_memory`의 `output_format` 설명은 `pretty`를 고를 수 있다고 적지만 `pretty`이면 `-r`을 넘기지 않아 Volatility 3의 기본 출력 방식 `quick`으로 실행된다 [22][23].

실행 확인에서 `output_format` `json`으로 `analyze_prefetch`를 부르면 응답은 `Output format: JSON`을 적었고 시험용 KAPE가 받은 인자에는 `--mef`가 없었다 [11].
같은 실행 확인에서 `modules`에 없는 이름을 주어도 `analyze_event_logs`는 EvtxECmd를 실행했다 [11].
`list_hash_modes`는 hashcat이 없는 작업 사본에서도 모드 14개를 돌려주었다 [10].

### T10.03 묶음 도구의 연산별 인자를 schema가 구분하지 않음

**구현.** 이 방식은 `analyze_sqlite_database`와 `analyze_memory`에 적용된다 [24][25].
`analyze_sqlite_database`는 `operation` 값으로 `list_tables`, `describe_table`, `query`, `export_table` 가운데 하나를 실행한다 [24].
입력 schema는 `operation`을 네 값의 `enum`으로 알리고 `table_name`, `sql_query`, `max_rows`를 한 목록에 둔다 [24].
`describe_table`과 `export_table`은 `table_name`을, `query`는 `sql_query`를 쓰지만 schema의 `required`는 `db_path`와 `operation`뿐이다 [24].
연산별 인자는 `table_name`과 `sql_query`의 설명 글에만 적혀 있고 `table_name` 설명은 `describe_table`에도 필요하다는 것을 적지 않는다 [24].

`analyze_memory`는 `plugin`으로 Volatility 3 플러그인을 고르고 `plugin_args`의 문자열을 그 플러그인의 인자로 그대로 넘긴다 [25].
입력 schema는 `plugin_args`를 문자열 배열로만 알리고 플러그인별 옵션은 schema에 없다 [25].
플러그인 목록과 플러그인별 옵션은 `list_memory_plugins`와 `get_memory_plugin_help`가 Volatility 3의 도움말을 돌려주어 알린다 [26].

def get_tool_handler_mapping() -> Dict[str, str]:
    """
    Get mapping of tool names to handler function names.
    
    Returns:
        Dict mapping tool name to handler import path
        e.g., {'analyze_registry': 'handlers.registry_forensics_handler.analyze_registry_handler'}
    """
    
    mapping = {
        'analyze_registry': 'handlers.registry_forensics_handler.analyze_registry_handler',
        'analyze_prefetch': 'handlers.prefetch_forensics_handler.analyze_prefetch_handler',
        'analyze_shellbags': 'handlers.shellbags_forensics_handler.analyze_shellbags_handler',
        'analyze_lnk_files': 'handlers.lnk_forensics_handler.analyze_lnk_files_handler',
        'analyze_jump_lists': 'handlers.jump_lists_forensics_handler.analyze_jump_lists_handler',
        'analyze_mft': 'handlers.mft_forensics_handler.analyze_mft_handler',
        'analyze_amcache': 'handlers.amcache_forensics_handler.analyze_amcache_handler',
        'analyze_shimcache': 'handlers.shimcache_forensics_handler.analyze_shimcache_handler',
        'analyze_event_logs': 'handlers.event_logs_forensics_handler.analyze_event_logs_handler',
    }
    
    return mapping
