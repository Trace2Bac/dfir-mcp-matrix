# P02 다음 작업 결정

### P02.02 규칙·조사 상태로 추천

**구현.** 이 방식은 `identify_file_type`, `prepare_disk_image`, `list_prepared_images`의 응답과 준비한 이미지 밖의 경로를 거부하는 응답에 적용된다 [1][2][3][4].
`identify_file_type`은 머리 바이트와 이름으로 정한 형식마다 `Primary Tool`과 KAPE 모듈을 싣고 `RECOMMENDED NEXT STEPS`에 부를 도구와 인자를 적는다 [1].
레지스트리 하이브와 EVTX·Prefetch로 판별하면 `get_kape_modules_catalog`와 `kape_parse_artifact`를, SQLite로 판별하면 `analyze_sqlite_database`를 차례로 적는다 [1].
`analyze_sqlite_database`는 SQLite가 아닌 파일을 거부할 때 같은 판별 함수가 고른 도구를 `CORRECT APPROACH`로 적는다 [5].
`prepare_disk_image`는 판별한 OS와 준비 방식에 따라 레지스트리 하이브, Prefetch, 이벤트 로그, 셸 기록, 브라우저 기록 같은 자료의 경로를 `USAGE EXAMPLES`로 싣는다 [2].
APFS로 판별한 이미지에는 SleuthKit 4.14.0이 다루지 못하는 범위와 대처 방법을 덧붙인다 [2].
`list_prepared_images`는 준비한 이미지마다 둘러볼 경로와 레지스트리 하이브 폴더를 부르는 호출문을 싣고 끝에 정리 도구의 호출문을 적는다 [3].
파일을 읽는 도구가 준비한 이미지 밖의 경로를 거부하면 응답은 준비한 이미지의 접근 위치 목록과 함께 `prepare_disk_image`를 먼저 부르라고 적는다 [4].
`browse_files_and_folders`는 준비한 이미지가 없으면 `prepare_disk_image`를 먼저 부르라고 적고 있으면 쓸 수 있는 이미지 경로의 앞부분을 적는다 [4].
`analyze_registry`의 응답은 출력 폴더를 `browse_files_and_folders`로 둘러보고 `read_csv_data`로 CSV를 읽으라는 다음 단계를 적는다 [6].
`kape_parse_artifact`의 응답은 출력 폴더의 파일을 읽는 `read_text_file`·`read_csv_data` 호출문을 적는다 [6].
이 문장들은 응답 문자열이고 서버는 권한 도구를 대신 부르거나 권고를 따르지 않은 호출을 막지 않는다.

서버는 MCP 리소스, 프롬프트, 초기화 지침을 두지 않는다 [7].
`get_kape_modules_catalog`, `list_memory_plugins`, `list_hash_modes`는 KAPE, Volatility 3, hashcat이 낸 목록을 돌려주고 서버가 정한 절차를 싣지 않는다 [8].
도구 설명은 도구마다 쓰임과 모듈을 적을 뿐 도구 사이의 차례를 정하지 않는다 [9].

**한계.** 서버가 권하는 도구 이름 가운데 도구 목록에 없는 것이 있다 [1][10].
`identify_file_type`은 `.DS_Store`와 Mach-O 실행 파일에 `parse_dsstore`·`parse_macho`를, XML 문서에 `parse_xml`을 권하고 gzip으로 압축한 FSEvents에는 `parse_fsevents`를 쓰라고 적는다 [1].
기준 커밋을 실행해 받은 도구 31개의 목록에는 이 네 이름이 없었다 [10].
`list_prepared_images`와 KAPE 도구가 권하는 `browse_prepared_image_files`도 도구 목록에 없고 `call_tool`의 분기에만 있다 [3][11][10].
SQLite DB에 권하는 `analyze_sqlite_database` 호출문은 연산 이름으로 `schema`와 `export_all`을 적지만 도구 정의의 `operation`은 `list_tables`·`describe_table`·`query`·`export_table`만 받는다 [1][12].
SQLite가 아닌 파일 `fake.db`를 `analyze_sqlite_database`에 주자 거부 응답은 같은 `analyze_sqlite_database`를 대신 쓰라고 적었다 [13].
OS를 `windows`로 판별해 SleuthKit으로 준비한 이미지의 `USAGE EXAMPLES`는 서버가 만든 빈 접근 폴더 아래의 경로를 적는다 [2][14].
이 경로를 `read_text_file`에 주자 파일이 없다는 오류가 났다 [15].
같은 응답은 모든 경로에 `/<이미지 ID>/` 접두를 쓰라고 적지만 `kape_parse_artifact`는 이 꼴의 경로에서 파일을 꺼내지 못한다 [16][17].
SleuthKit으로 준비한 시험 이미지의 `SYSTEM`을 이 꼴로 주자 `kape_parse_artifact`는 `Failed to extract file from forensic image`를 돌려주었고 접근 폴더 아래 경로로 주자 KAPE를 실행했다 [18].
