# P06 조사 상태 유지

### P06.02 프로세스 메모리에만 보관

**구현.** 이 방식은 준비한 이미지의 준비 객체와 마운트 객체, 파일 추출에 쓰는 관리 객체에 적용된다 [1][2][3].
등록부 `PREPARED_IMAGES`는 모듈 전역 `dict`이고 항목마다 SleuthKit·WSL 준비 객체를 `mounter`에, Arsenal 마운트 객체를 `arsenal`에 둔다 [1][4].
Arsenal 마운트 객체는 실행한 `aim_cli` 프로세스 객체와 드라이브 문자를 `mounted_images`에 둔다 [2].
WSL APFS·LVM 마운트 객체도 이미지마다 마운트 위치를 `mounted_images`에 둔다 [2].
레지스트리 폴더 추출을 맡는 `ExtractionManager`는 프로세스에 하나를 만들어 다시 쓰고 경로 대응표 `PathMapper`는 이미지 경로의 MD5마다 하나를 모듈 전역 `_MAPPERS`에 두어 다시 쓴다 [3][5].
등록부 파일에 쓸 때 `mounter` 키는 빼므로 SleuthKit·WSL 준비 객체는 프로세스가 끝나면 사라진다 [6].

**한계.** 프로세스가 끝나도 Arsenal이 마운트한 드라이브와 WSL 마운트가 남는지는 확인하지 못했다 [2].

### P06.03 조사 상태를 파일·DB에 저장

**구현.** 이 방식은 등록부, 레지스트리 폴더 추출 기록, SleuthKit 파일 추출의 경로 대응표, 분석 도구의 출력 폴더에 적용된다 [6][7][8][9].
`prepare_disk_image`와 `cleanup_prepared_image`는 등록부를 바꿀 때마다 `forensic_output/prepared_images_registry.json`에 전체를 다시 쓴다 [6].
항목에는 이미지 경로, 이미지 ID, 해시, 사건 폴더, 접근 위치, 파일시스템, OS, 파티션 위치, 준비 시각이 들어간다 [10].
`ExtractionManager`는 이미지 ID와 내부 경로마다 추출 위치, 시각, 파일 수를 `extract/extraction_registry.json`에 쓰고 같은 경로를 다시 요청하면 앞서 꺼낸 폴더를 돌려준다 [7].
`PathMapper`는 이미지 안 경로마다 꺼낸 파일 경로, inode, 크기를 사건 폴더의 `path_mapping.json`에 쓰고 같은 경로를 다시 읽으면 꺼낸 파일을 돌려준다 [8].
레지스트리·KAPE 도구는 출력 폴더에 파일이 있으면 KAPE를 다시 실행하지 않고 `CACHED`로 그 폴더를 돌려준다 [9].
같은 레지스트리 요청을 두 번 부르자 두 번째 응답은 `CACHED (already analyzed)`였다 [11].

**한계.** `analyze_registry`는 KAPE를 실행하기 전에 출력 폴더 안에 `Registry` 폴더를 만든다 [9].
그래서 KAPE가 실패해도 출력 폴더가 비어 있지 않아 같은 요청을 다시 부르면 `CACHED`를 돌려준다 [9].
시험용 KAPE가 실패하게 한 뒤 같은 요청을 다시 부르자 응답은 `CACHED (already analyzed)`였고 출력 폴더에는 빈 `Registry` 폴더만 있었다 [12].
캐시 판정은 출력 폴더 이름만 보므로 같은 이름의 폴더를 쓰는 다른 입력의 결과도 돌려준다 [9][13].
`kape_parse_artifact`의 출력 폴더 이름은 이미지 안 경로를 `_`로 이은 것이고 레지스트리 도구는 파일 이름 줄기나 폴더 이름으로 짓는다 [9][13].

### P06.04 재시작 뒤 자동 복구

**구현.** 이 방식은 stdio 진입점 `main.py`의 시작 처리에 적용된다 [14].
`main.py`는 서버를 만들기 전에 `load_prepared_images`로 등록부 파일을 읽어 `PREPARED_IMAGES`를 채운다 [14][15].
`load_prepared_images`에는 읽은 Arsenal 항목의 드라이브를 확인해 없으면 지우는 단계가 있지만 서버가 Arsenal 항목을 넣어 쓴 등록부는 읽히지 않는다 [15][4][6].
SleuthKit 항목은 준비 객체 없이 복구되고 `browse_files_and_folders`는 준비 객체가 없으면 등록부의 이미지 경로와 파티션 번호로 다시 만든다 [16].
`analyze_registry`는 준비 객체가 없으면 부를 때마다 등록부의 이미지 경로로 준비 객체를 다시 만들고 파티션은 다시 판별해 고른 것을 쓴다 [17][18].
SleuthKit 파일 읽기 경로는 준비 객체를 쓰지 않고 등록부의 이미지 경로와 파티션 위치로 SleuthKit을 다시 실행한다 [19].
WSL 항목은 파일을 읽거나 둘러볼 때 등록부의 마운트 위치로 마운트 객체를 다시 만든다 [19][16].
LVM 마운트 객체는 파일을 읽거나 둘러볼 때 `mountpoint -q`로 마운트를 확인하고 없으면 같은 위치에 다시 마운트한다 [20].
시험 이미지를 준비한 프로세스를 끝내고 새 프로세스에서 시작 처리를 부르자 그 이미지의 항목이 준비 객체 없이 복구되었고 `browse_files_and_folders`가 준비 객체를 다시 만들었다 [21].

**한계.** SSE 진입점 `remote_server.py`는 `load_prepared_images`를 부르지 않는다 [22].
그래서 SSE로 시작한 서버는 앞서 준비한 이미지를 모른다 [22].
그 상태에서 이미지를 준비하면 등록부 파일을 그 프로세스의 항목만으로 다시 쓰므로 앞 항목이 파일에서 사라진다 [6][22].
`kape_parse_artifact`·`analyze_prefetch`·`analyze_lnk_files`·`analyze_shellbags`·`analyze_jump_lists`는 준비 객체를 다시 만들지 않는다 [23].
재시작 뒤 다른 도구가 준비 객체를 만들기 전에 `kape_parse_artifact`와 `analyze_prefetch`를 부르자 둘 다 `No mounter available` 오류를 돌려주었다 [21].
Arsenal로 준비하면 항목에 Arsenal 마운트 객체를 `arsenal` 키로 넣는데 등록부 저장은 `mounter` 키만 빼고 JSON으로 쓴다 [4][6].
Arsenal 꼴의 항목을 넣고 저장하자 등록부 파일은 그 객체에서 끊긴 121바이트로 남았고 다음 `load_prepared_images`는 빈 등록부를 돌려주었다 [24].
이때 같은 파일의 다른 항목도 함께 복구되지 않는다 [24].
APFS 항목은 마운트가 살아 있는지 확인하지 않고 복구한다 [15].
LVM 마운트가 실패해 다른 파티션을 등록한 이미지에서는 재시작 뒤 `analyze_registry`가 등록한 것과 다른 파티션을 읽을 수 있다 [17][18][25].
이 경로는 코드로만 확인했다.

def save_prepared_images(prepared_images, base_output_dir):
    """Save prepared images registry to disk (excluding non-serializable objects)"""
    registry_file = Path(base_output_dir) / "prepared_images_registry.json"
    
    try:
        serializable_images = {}
        for path, info in prepared_images.items():
            serializable_info = {k: v for k, v in info.items() if k != 'mounter'}
            serializable_images[path] = serializable_info
        
        with open(registry_file, 'w') as f:
            json.dump(serializable_images, f, indent=2)
        logger.info(f"Saved prepared images registry: {len(serializable_images)} images")

        """Load extraction registry from JSON file"""

def load_prepared_images(base_output_dir):
    """Load prepared images registry from disk and validate mounts"""
    global PREPARED_IMAGES
    
    registry_file = Path(base_output_dir) / "prepared_images_registry.json"
    
    if not registry_file.exists():
        logger.info("No existing prepared images registry found")
        return {}
    
    try:
        with open(registry_file, 'r') as f:
            data = json.load(f)
            PREPARED_IMAGES.clear()
            PREPARED_IMAGES.update(data)
        logger.info(f"Loaded prepared images registry: {len(PREPARED_IMAGES)} images")
        
        stale_count = validate_arsenal_mounts()
        
        if stale_count > 0:
            save_prepared_images(PREPARED_IMAGES, base_output_dir)
            logger.info(f"Updated registry after removing {stale_count} stale mount(s)")
        
        return PREPARED_IMAGES
    except Exception as e:
        logger.error(f"Failed to load prepared images registry: {e}")
        return {}

        """Check if mount is still active using mountpoint command"""
        image_path = str(Path(image_path).resolve())
        if image_path not in self.mounted_images: return False
        mount_point = self.mounted_images[image_path]['mount_point']
        
        # mountpoint -q returns 0 if it is a mount point, non-zero otherwise
