# P03 조사 진척 판단

### 미구현

**판단.** 서버는 대상별로 수행한 작업과 남은 작업을 표현하지 않고 완료 판단을 모델에 맡긴다.
서버에는 증거 유형마다 해야 할 작업 목록, 조사 단계, 완료 조건이 없고 모델이 진행을 적는 도구도 없다.

도구 응답이 다룬 범위를 적는 곳은 그 호출 한 번의 결과에 그친다.
`prepare_disk_image`는 SleuthKit으로 준비한 이미지에서 파티션이 둘 이상이면 찾은 파티션 수와 쓰는 파티션 번호를 싣고 다른 파티션을 고르지 않은 이유는 적지 않으며 파티션을 고르는 인자도 받지 않는다 [1][2].
두 파티션을 가진 시험 이미지에서 응답은 `Partitions: 2 detected, using partition 2`를 실었다 [3].
Arsenal로 마운트하면 읽지 못한 드라이브를 `Unreadable drives (FAT12/corrupt)`로 적는다 [1].
APFS로 판별한 이미지에는 스냅숏과 암호화한 볼륨을 다루지 못한다는 고정 문장을 붙인다 [4].
`analyze_macos_fsevents`는 찾은 FSEvents 파일 수와 꺼낸 파일 수를 따로 적고 앞의 10개만 꺼낸다는 사실은 적지 않는다 [5].
`analyze_prefetch`와 `analyze_jump_lists`는 폴더에서 꺼낸 파일 수를 적고 0개면 찾은 파일이 없다는 문장으로 끝낸다 [6].
`analyze_registry`는 실행한 모듈이 하나도 없으면 가능한 사유 세 가지를 고정 문장으로 돌려준다 [7][8].
이름이 맞지 않아 건너뛴 모듈은 서버 로그에만 남기고 응답의 `Modules Executed`에는 고른 모듈 수를 그대로 적는다 [7].
이 값들은 대상별로 모이지 않고 서버가 다음 호출에서 다시 쓰지 않는다.
