# P05 사건 자료 정리

### P05.01 모델 도구로 삭제·초기화

**구현.** 이 방식은 준비한 이미지를 정리하는 `cleanup_prepared_image`에 적용된다 [1].
`cleanup_prepared_image`는 받은 `image_path`를 등록부 `PREPARED_IMAGES`의 키와 그대로 대조하고 같은 항목이 있으면 준비 방식에 따라 정리한다 [1].
SleuthKit 항목은 메모리에 있는 준비 객체의 `cleanup`을 불러 그 객체가 만든 접근 폴더를 지운다 [1][2].
이 접근 폴더는 이미지 파일 이름 줄기로 지은 `forensic_access/<줄기>`이고 그 안에는 메타데이터 파일 `.forensic_metadata.json`이 있다 [3].
Arsenal 항목은 마운트 객체로 그 이미지의 `aim_cli` 프로세스를 끝낸다 [1].
이 단계가 실패하면 `aim_cli --dismount`를 실행한다 [1].
그 뒤 성공 여부와 관계없이 `aim_cli --dismount`를 한 번 더 실행한다 [1].
준비 방식이 무엇이든 마지막에 등록부에서 항목을 지우고 등록부 파일을 다시 쓴다 [1][4].
시험 이미지를 정리하자 등록부 파일은 `{}`이 되었고 `forensic_access/disk01` 폴더가 지워졌다 [5].

사건 폴더, 꺼낸 파일, 분석 출력을 지우는 MCP 도구는 없다.
`extract` 아래 추출 폴더를 지우는 `cleanup_image_extractions`, 사건 폴더의 `extracted_files`를 지우는 `cleanup_extracted_files`, 경로 대응표의 파일을 지우는 `cleanup_all_mappers`는 서버 안에서 부르는 곳이 없다 [6].
같은 저장소의 `mounters/cleanup_wsl_mounts.py`는 사용자가 실행하는 스크립트로 WSL의 `/mnt/forensic*` 폴더 가운데 마운트되지 않은 것과 원본 파일이 없는 loop 장치를 찾아 확인 질문 뒤에 정리하도록 쓰여 있다 [7].
마운트되지 않은 폴더가 하나라도 있으면 그 목록을 출력하는 반복문이 같은 목록에 항목을 덧붙여 끝나지 않으므로 확인 질문과 정리 단계를 실행하지 않는다 [8].
이 동작은 코드로만 확인했다.
서버의 WSL 마운트는 `/tmp/apfs_mount_<시각>`과 `/mnt/ubuntu_forensics`를 쓰므로 이 스크립트의 대상 이름과 맞지 않는다 [9].
`cleanup_prepared_image`는 서버 운영 로그에 도구 이름과 인자를 남기고 `operations_logs`의 기록에는 남기지 않는다 [10][11].
SleuthKit 접근 폴더를 지울 때는 그 폴더 경로가 서버 운영 로그에 한 줄 남는다 [2][5].

**한계.** 등록부 키와 글자가 다른 경로를 주면 정리하지 않는다 [1].
같은 이미지를 `/` 구분자로 적은 경로로 부르자 `Image not found in prepared list`를 돌려주었다 [5].
서버를 다시 시작하면 등록부에 준비 객체가 없다 [4].
그래서 `browse_files_and_folders` 같은 도구가 준비 객체를 다시 만들기 전에 정리하면 SleuthKit 항목은 접근 폴더를 지우지 않고 등록부 항목만 지운다 [1].
이 경우 응답에는 `No SleuthKit mounter instance found`가 실린다 [1].
WSL로 마운트한 APFS·LVM 항목은 마운트를 내리는 함수가 있는데도 부르지 않고 등록부 항목만 지운다 [1][12].
Arsenal 항목의 `aim_cli --dismount`에는 이미지를 가리키는 인자가 없어 다른 이미지의 Arsenal 드라이브도 함께 내려가지만 그 이미지들의 등록부 항목은 남는다 [1].
접근 폴더를 지우다 실패해도 준비 객체는 로그만 남기고 응답은 `Successfully cleaned up SleuthKit mount`를 적는다 [1][2].
`force` 인자는 받기만 하고 쓰지 않는다 [1].

### P05.03 자동 정리

**구현.** 이 방식은 Windows 아티팩트 도구와 macOS 도구가 호출 중에 만드는 임시 폴더, `crack_hash`의 임시 해시 파일, 서버 시작 때와 같은 이미지를 다시 준비할 때의 등록부 항목에 적용된다 [13][14][15][16][17].
`analyze_prefetch`·`analyze_lnk_files`·`analyze_shellbags`·`analyze_jump_lists`는 SleuthKit으로 꺼낸 파일을 둔 `<도구>_extract_<inode>` 폴더를 KAPE 실행 뒤에 지운다 [13].
`analyze_macos_unified_logs`는 `tempfile.mkdtemp`로 만든 출력 폴더를 응답을 만든 뒤에 지운다 [14].
`analyze_macos_fsevents`는 `tempfile.TemporaryDirectory`에 FSEvents 파일을 꺼내므로 파싱이 끝나면 폴더가 지워진다 [14].
`crack_hash`는 해시 값을 쓴 임시 파일을 실행 뒤에 지운다 [15].
서버가 시작할 때 `load_prepared_images`는 Arsenal 항목 가운데 드라이브가 없는 것을 등록부에서 지우고 파일을 다시 쓴다 [16].
드라이브 `Q:`가 없는 Arsenal 항목을 넣어 별도로 만든 등록부를 읽게 하자 그 항목이 빠진 등록부가 파일에 다시 쓰였다 [18].
`prepare_disk_image`는 같은 이미지가 이미 등록되어 있고 Arsenal 드라이브나 WSL LVM 마운트가 남아 있지 않으면 앞 항목을 지우고 다시 준비한다 [17].
SleuthKit 항목은 마운트가 남아 있는지 확인하는 분기가 없어 다시 부를 때마다 앞 항목을 지운다 [17].
레지스트리 폴더 추출 기록과 경로 대응표는 기록된 파일이 디스크에 없으면 그 기록을 지운다 [19].

**한계.** `kape_parse_artifact`는 `kape_extract_<inode>` 폴더를 지우지 않는다 [20].
`analyze_prefetch`는 폴더에서 꺼낸 `.pf` 파일이 0개이면 정리 표시를 하기 전에 돌아가 임시 폴더가 남는다 [13].
재시작을 흉내 낸 실행이 끝난 뒤 임시 폴더에는 `kape_extract_100`과 빈 `prefetch_extract_67`이 남아 있었다 [5].
`analyze_macos_unified_logs`는 파싱 단계가 오류를 돌려주면 정리하지 않고 돌아가므로 `unified_logs_` 임시 폴더가 남는다 [14].
설정 파일은 `temp_cleanup_hours: 24`에 24시간이 지난 임시 파일을 자동으로 지운다는 주석을 달지만 이 값을 읽는 코드는 없다 [21].
서버가 Arsenal 항목을 넣어 쓴 등록부 파일은 그 항목의 마운트 객체에서 끊겨 시작할 때 읽히지 않으므로 시작 때의 Arsenal 항목 정리는 서버가 쓴 등록부에는 적용되지 않는다 [16][4][22][23].
등록부 키는 받은 경로 문자열이고 다시 준비할 때는 실제 경로로 바꾼 값으로 찾으므로 앞 준비를 상대 경로처럼 실제 경로와 다른 표기로 했으면 앞 항목을 찾지 못해 지우지 않는다 [17][24].
같은 시험 이미지를 소문자 표기로 준비한 뒤 상대 경로로 다시 준비하자 등록부에 같은 `unique_image_id`의 항목이 두 개 남았다 [25].
지운 임시 폴더와 시작 때 지운 등록부 항목은 서버 운영 로그에만 남는다 [13][16].

### P05.05 원본 증거를 삭제 대상에서 제외

**구현.** 이 방식은 `cleanup_prepared_image`와 자동 정리 경로 모두에 적용된다 [1][13].
지우는 대상은 등록부 항목, 서버가 설정 폴더 아래에 지은 접근 폴더, 서버가 만든 임시 폴더와 임시 파일이다 [1][2][13][15].
받은 `image_path`는 등록부 키를 찾는 데만 쓰고 지우는 경로로 쓰지 않는다 [1].
시험 이미지를 정리한 뒤 이미지 파일, 사건 폴더, 꺼낸 파일은 그대로 남았다 [5].

```python
        """Unmount APFS image"""
```

```python
    def unmount_lvm_image(self, image_path: str) -> Dict:
        """Cleanup logic following the forensic workflow"""
        try:
            image_path = str(Path(image_path).resolve())
            if image_path not in self.mounted_images:
                return {'success': False, 'error': 'Not mounted'}
            
            mount_info = self.mounted_images[image_path]
            mount_point = mount_info['mount_point']
            loop_device = mount_info['loop_device']
            
            self._run_wsl(f'umount "{mount_point}"')
            
            self._run_wsl("vgchange -an")
            
            if loop_device:
                self._run_wsl(f"losetup -d {loop_device}")
            
            del self.mounted_images[image_path]
            return {'success': True}
        except Exception as e:
            return {'success': False, 'error': str(e)}
```

```python
def load_prepared_images(base_output_dir):
    """Load prepared images registry from disk and validate mounts"""
    global PREPARED_IMAGES
    
    registry_file = Path(base_output_dir) / "prepared_images_registry.json"
    
    if not registry_file.exists():
        logger.info("No existing prepared images registry found")
        return {}
    
    try:
        with open(registry_file, 'r') as f:
            data = json.load(f)
            PREPARED_IMAGES.clear()
            PREPARED_IMAGES.update(data)
        logger.info(f"Loaded prepared images registry: {len(PREPARED_IMAGES)} images")
        
        stale_count = validate_arsenal_mounts()
        
        if stale_count > 0:
            save_prepared_images(PREPARED_IMAGES, base_output_dir)
            logger.info(f"Updated registry after removing {stale_count} stale mount(s)")
        
        return PREPARED_IMAGES
    except Exception as e:
        logger.error(f"Failed to load prepared images registry: {e}")
        return {}
```
