# I03 외부 전송 범위 구성

### 비적용

**판단.** 서버 코드가 외부 서비스에 조사 자료를 보내는 요청은 없다 [1][2].
서버 코드가 스스로 여는 외부 연결은 `remote_server.py`의 ngrok 연결뿐이다 [1].
이 연결을 열 때 서버 코드가 `pyngrok`에 넘기는 값은 환경변수 `NGROK_AUTHTOKEN`과 로컬 포트뿐이다 [2].
ngrok 터널은 원격 MCP 클라이언트와 SSE 엔드포인트 사이의 요청과 응답을 나른다 [2][3].
이 터널로 나가는 도구 응답은 서버가 모델 클라이언트에 돌려주는 응답이다 [3].
stdio 진입점 `main.py`는 외부 연결을 열지 않는다 [4].
분석 도구가 스스로 여는 통신(Volatility 3의 심볼 내려받기, KAPE 갱신 모듈)은 서버 코드가 보내는 요청이 아니다.

### 근거

[1] 기준 커밋의 Python 코드에서 `requests`, `urllib`, `socket`, `http`, `httpx`, `aiohttp`, `pyngrok`을 불러오는 줄을 찾으면 [`remote_server.py:90`](https://github.com/abhiii011/Cyber-Incident-Investigation-and-Triage-MCP-Server/blob/39e85090231cf0c9b7edcb1700d169372e50d8b1/remote_server.py#L90)만 나온다.

[2] `start_ngrok`은 토큰과 로컬 포트만 `pyngrok`에 넘긴다.

```python
def start_ngrok(port: int) -> str | None:
    try:
        from pyngrok import ngrok

        token = os.environ.get("NGROK_AUTHTOKEN")
        if token:
            ngrok.set_auth_token(token)

        tunnel = ngrok.connect(port)
        public_url = tunnel.public_url
```

sse = SseServerTransport("/messages/")

    """
    GET /sse  – opens a long-lived SSE stream.
    The MCP SDK needs raw ASGI (scope, receive, send).
    Starlette stores them on the Request object.
