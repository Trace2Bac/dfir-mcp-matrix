# I02 분석 도구 통신 차단

### 미구현

**판단.** 서버는 분석 도구를 실행할 때 그 도구의 통신을 끊거나 끄는 옵션이나 장치를 두지 않는다.
처리기는 하위 프로세스를 실행할 때 `env`를 넘기지 않아 분석 도구는 서버 프로세스의 환경변수와 네트워크 설정을 그대로 물려받는다 [1].
저장소에는 분석 도구를 네트워크 없는 컨테이너, network namespace, 방화벽 규칙 아래에서 실행하는 구성이 없다.

Volatility 3는 통신을 끄지 않은 채 실행된다 [2][3].

- `analyze_memory`는 `vol.py`에 메모리 파일(`-f`), 출력 형식(`-r`), 플러그인, 모델이 준 플러그인 인자만 넘기고 오프라인 옵션 `--offline`을 붙이지 않는다 [2].
- 서버는 모델이 준 `plugin` 값을 목록과 대조하지 않고 출력 형식 옵션 바로 뒤에 둔다 [2].
- 그래서 모델은 `plugin` 값으로 `--offline`이나 원격 ISF 목록 주소 옵션 `-u` 같은 Volatility 3 전역 옵션을 플러그인 이름 앞에 넣을 수 있다 [2][4].
- Volatility 3 2.28.0에서 `constants.OFFLINE`의 기본값은 거짓이고 명령 행의 `--offline`이 이 값을 켠다 [3].
- 이 값이 꺼져 있으면 Volatility 3는 Windows 커널의 PDB 심볼 표가 로컬 심볼 폴더와 캐시에 없을 때 Microsoft 심볼 서버(`http://msdl.microsoft.com/download/symbols`)에서 PDB를 받아 변환한다 [3].
- 원격 ISF 목록 주소 `REMOTE_ISF_URL`은 기본값이 `None`이라 `-u`를 주지 않으면 그 목록은 조회하지 않는다 [3].
- `analyze_memory`는 `memory_file`이 있는지만 확인하고 네트워크 공유를 가리키는 UNC 경로를 거부하지 않는다 [5].
- 그 경로를 Volatility 3가 열 때 운영체제가 네트워크 연결을 여는지는 실행해 보지 않아 확인하지 못했다.

KAPE는 모델이 고른 모듈을 그대로 실행한다 [6][7][8].

- `kape_parse_artifact`는 `kape_module` 인자를 목록과 대조하지 않고 KAPE의 `--module` 값으로 넘긴다 [6].
- KAPE 문서는 `--sync`를 GitHub의 KapeFiles 저장소에서 Target과 Module 설정을 받아 바꾸는 옵션으로 적는다 [7].
- 같은 문서는 `!!ToolSync` 모듈이 RECmd·EvtxECmd 같은 도구를 그 도구의 갱신 인자로 실행한다고 적는다 [7].
- 기준 날짜의 KapeFiles에서 `Sync_KAPE` 모듈은 `kape.exe --sync`를, `Sync_EvtxECmd` 모듈은 `EvtxECmd.exe --sync --debug`를 실행한다 [8].
- 시험용 KAPE를 둔 서버에 `kape_module`로 `Sync_KAPE`를 주자 `--module Sync_KAPE`가 그대로 넘어갔다 [9].
- 사용자의 KAPE 설치에 이 모듈 파일이 있으면 모델이 이 모듈을 골라 갱신 통신을 실행할 수 있다 [6][8].
- KAPE가 갱신 모듈 없이 실행될 때 스스로 통신하는지는 KAPE 소스가 공개되어 있지 않아 확인하지 못했다.

서버가 직접 실행하는 EZ Tools는 갱신 옵션 없이 실행된다 [10][11][12].

- EvtxECmd와 RECmd는 `--sync`를 줄 때만 GitHub에서 맵이나 배치 파일을 받아 오고 `--sync`의 기본값은 거짓이다 [11].
- `analyze_event_logs`는 EvtxECmd에 `-f`·`-d`와 출력 형식 옵션만 넘기고 `--sync`를 넘기지 않는다 [10].
- LECmd, JLECmd, PECmd, AppCompatCacheParser, MFTECmd, AmcacheParser의 기준 커밋 소스에서는 내려받기 코드를 찾지 못했고 이 도구들이 쓰는 라이브러리는 확인하지 않았다 [12].

`remote_server.py`가 부르는 `pyngrok`과 ngrok 에이전트도 스스로 통신한다 [13][14].

- `pyngrok` 8.1.2는 ngrok 실행 파일이 없으면 코드에 적힌 `https://bin.ngrok.com/…` 주소에서 받아 설치한다 [13].
- ngrok 문서는 에이전트 설정 `update_check`의 기본값이 참이라 에이전트가 새 버전을 확인한다고 적는다 [14].
- `pyngrok` 8.1.2가 처음 만드는 기본 설정 파일에는 이 값이 없고 서버 코드도 이 값을 정하지 않는다 [13][15].

hashcat 7.1.2의 brain client는 원격 brain 서버에 연결하는 기능이고 기본값이 꺼져 있다 [16].
`crack_hash`는 이 기능을 켜는 `-z`를 hashcat에 넘기지 않는다 [17][16].
SleuthKit, chainbreaker, UnifiedLogReader, apfs-fuse가 스스로 통신하는지는 확인하지 않았다.
Arsenal Image Mounter는 소스가 공개되어 있지 않아 스스로 통신하는지 확인하지 못했다.
