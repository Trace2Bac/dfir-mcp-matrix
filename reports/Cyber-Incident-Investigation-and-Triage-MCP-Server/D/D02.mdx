# D02 파생물 추적

### D02.01 ID·경로 참조

**구현.** 이 방식은 `ExtractionManager`가 남기는 `extraction_registry.json`과 파일 도구가 남기는 `path_mapping.json`, 준비된 이미지의 파생물을 두는 `cases/<이미지 ID>/` 경로, `kape_parse_artifact`가 남기는 `kape_operations.log`에 적용된다 [1][2][3][4].

`ExtractionManager`는 이미지에서 푼 폴더마다 그것을 푼 이미지의 경로 `image_path`, 이미지 ID `image_id`, 이미지 안의 내부 경로 `internal_path`, 푼 위치 `extract_location`을 `extraction_registry.json`에 적는다 [1].
그래서 이 기록에서 꺼낸 파일이 어느 이미지의 어느 내부 경로에서 나왔는지 이어진다 [1].
파일 도구가 SleuthKit 이미지에서 꺼낸 파일은 `path_mapping.json`이 이미지 안 경로, inode, 크기, 꺼낸 시각에 잇는다 [2].

파생물이 담기는 경로 자체가 그것을 만든 이미지를 가리킨다.
`prepare_disk_image`는 이미지 이름과 그 이미지 앞부분의 SHA-256을 이어 붙인 `<이미지 이름>_<os>_<해시 앞 12자>`를 이미지 ID로 짓고 `prepared_images_registry.json`에 이미지 경로와 함께 적는다 [5][6].
준비된 이미지를 분석하는 처리기는 `get_case_output_directory`로 이 이미지 ID의 `cases/<이미지 ID>/` 아래에 파생물을 둔다 [3].
`analyze_sqlite_database`는 `cases/<이미지 이름>_<해시>/` 아래에 둔다 [7].
그래서 두 경로에서 파생물을 만든 이미지의 이름과 해시가 드러난다 [5][7].

`kape_parse_artifact`는 KAPE를 실행할 때마다 `kape_operations.log`에 항목을 남긴다 [4].
항목에는 시각과 명령으로 만든 16진수 ID `operation_hash`, 실행한 명령줄, KAPE의 표준 출력과 표준 오류가 담긴다 [4][8].
처리기는 KAPE 실행 전과 후에 항목을 하나씩 남긴다 [8][9].
명령줄에는 입력 폴더 `--msource`와 출력 폴더 `--mdest`가 들어 있어, 이 기록에서 출력 폴더가 어느 입력에서 나왔는지 이어진다 [8].
`audit_kape_operations`는 이 기록을 읽어 ID, 시각, 종류, 명령 요약으로 돌려준다 [10].

**한계.** YAML에서 만든 도구 9개는 `kape_operations.log`에 명령을 남기지 않는다 [11][12].
이 가운데 5개는 KAPE를 직접 실행하고 4개는 EZ Tools 실행 파일을 직접 실행한다 [11][12].
그래서 이 도구의 파생물은 출력 폴더 경로로만 입력과 이어진다 [11].
`analyze_memory`의 출력 폴더와 준비된 이미지가 아닌 입력의 출력 폴더는 메모리 파일 이름, 입력 파일·폴더 이름, 시각, `local_analysis` 같은 대체 이름으로 지어 이미지를 가리키지 않는다 [3][13].
`kape_parse_artifact` 응답의 `Operation Hash`는 모듈 이름, 파일 경로, 시각으로 따로 구한 값이라 `kape_operations.log`의 `OPERATION ID`와 같지 않다 [4][14].
그래서 응답에서 기록 항목으로는 ID가 아니라 명령줄의 출력 폴더로만 이어진다 [8][14].
실행 확인에서 응답의 `Operation Hash`와 기록의 `OPERATION ID`가 서로 달랐다 [15].
KAPE와 EZ Tools의 출력 파일 안이나 곁에 그것을 만든 호출이나 입력을 가리키는 값을 서버가 더 적지는 않는다.
앞 도구의 파생물을 뒤 도구가 입력으로 쓸 때 그 부모 관계를 기록하는 코드는 없다.
`extraction_registry.json`의 기록은 이미지에서 꺼낸 파일에만 있다 [1].
그 파일을 분석해 만든 CSV를 다시 그 꺼낸 파일과 잇지는 않는다 [1].

```python
    def add_mapping(self, linux_path: str, windows_path: str, inode: int, 
                   size: Optional[int] = None) -> bool:
        """
        Add or update path mapping
        
        Args:
            linux_path: Original Linux path in image
            windows_path: Extracted Windows file location
            inode: Inode number
            size: File size in bytes (optional)
            
        Returns:
            True if mapping added successfully
        """
        linux_path = self.normalize_linux_path(linux_path)
        windows_path = str(windows_path)
        
        self.path_mapping[linux_path] = {
            'windows_path': windows_path,
            'inode': inode,
            'timestamp': datetime.now().isoformat(),
            'size': size
        }
        
        self.reverse_mapping[windows_path] = linux_path
        
        self._save_mappings()
        
        return True
```

```python
def save_prepared_images(prepared_images, base_output_dir):
    """Save prepared images registry to disk (excluding non-serializable objects)"""
    registry_file = Path(base_output_dir) / "prepared_images_registry.json"
    
    try:
        serializable_images = {}
        for path, info in prepared_images.items():
            serializable_info = {k: v for k, v in info.items() if k != 'mounter'}
            serializable_images[path] = serializable_info
        
        with open(registry_file, 'w') as f:
            json.dump(serializable_images, f, indent=2)
        logger.info(f"Saved prepared images registry: {len(serializable_images)} images")
```
