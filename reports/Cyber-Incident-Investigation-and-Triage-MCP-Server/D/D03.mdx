# D03 파생물 무결성 검증

### 미구현

**판단.** 서버가 남기는 파생물은 KAPE와 EZ Tools, Volatility 3의 출력 파일, 이미지에서 꺼낸 파일, SQLite 조회 결과 파일이다 [1].
서버는 이 파생물의 기준값을 얻지도 대조하지도 않는다 [2].
`core/forensic_tools.py`에 파일의 SHA-256을 구하는 `calculate_file_hash`가 있다 [3].
`image_handlers.py`는 이 이름을 가져오기만 하고 부르지 않으며 어느 처리기도 이 함수로 파생물의 해시를 계산하지 않는다 [2].

서버가 계산하는 해시는 파생물이 아니라 다른 대상을 가리킨다.
`prepare_disk_image`는 `ExtractionManager`로 이미지 앞부분 10MB의 SHA-256을 구해 이미지 ID에 넣는데 이 값은 원본 이미지의 것이고 꺼낸 파일의 것이 아니다 [4][5].
`kape_parse_artifact`가 응답에 싣는 `Operation Hash`는 모듈 이름·파일 경로·시각의, 기록에 남기는 `operation_hash`는 시각·명령줄의 SHA-256 앞 16자라 둘 다 출력 파일의 것이 아니다 [6][7].
`analyze_amcache`의 CSV에 담기는 SHA-1은 `AmcacheParser`가 증거 레지스트리에서 읽은 실행 파일의 해시이고 CSV 자체의 해시가 아니다 [8].

파생물을 다시 읽어 기준값과 대조하는 도구나 경로도 없다.
파생물을 인용·검토·보고하는 다른 도구 호출에서 서버가 스스로 파생물을 대조하는 곳은 없다 [2].
모델이 검증 도구를 따로 부를 수 있는 경로도 없다 [2].

```python
def calculate_file_hash(file_path):
    """Calculate SHA256 hash of a file for chain of custody"""
    sha256_hash = hashlib.sha256()
    with open(file_path, "rb") as f:
        for byte_block in iter(lambda: f.read(4096), b""):
            sha256_hash.update(byte_block)
    return sha256_hash.hexdigest()
```
