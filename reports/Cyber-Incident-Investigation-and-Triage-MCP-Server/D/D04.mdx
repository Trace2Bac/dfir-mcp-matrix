# D04 출력 경로 제한

### D04.01 서버가 출력 위치 결정

**구현.** 이 방식은 파생물을 남기는 모든 도구에 적용된다 [1][2].
어느 도구도 생성·수정·삭제 대상 경로를 호출 인자로 받지 않는다 [1].
YAML에서 만든 아홉 개 도구는 입력 경로 `paths`, 모듈 `modules`, 출력 형식 `output_format`만 받고 목적지 경로를 받는 인자가 없다 [1].
`kape_parse_artifact`는 분석할 파일 경로와 KAPE 모듈 이름만 받는다 [3].

출력 폴더는 `get_case_output_directory`가 정한다 [2].
이 함수는 준비된 이미지 정보가 있으면 `cases/<이미지 ID>/<도구 종류>/<모듈>_<식별자>/`를, 없으면 `cases/<대체 이름 또는 local_analysis>/<도구 종류>/<모듈>_<식별자>/`를 만든다 [2].
`<도구 종류>`는 처리기 코드가 정하고 `<모듈>`은 YAML 도구에서는 설정과 처리기 코드가, `kape_parse_artifact`에서는 호출 인자 `kape_module`이 정한다 [2][4][5].
`<식별자>`는 `analyze_registry`·`analyze_lnk_files`에서는 입력 경로의 마지막 이름이고 `kape_parse_artifact`에서는 이미지 안 상대 경로의 구분자를 `_`로 바꾼 값이며 나머지 도구는 고정 문자열이다 [5][6].
KAPE와 EZ Tools 실행 파일에는 이 폴더를 출력 위치로 넘긴다 [7][8].
모델이 준 목적지는 넘기지 않는다 [7].

`analyze_memory`는 출력 폴더를 `cases/<메모리 파일 이름>/memory/<플러그인>/`으로 정하고 파일 이름을 플러그인 이름의 `.`과 `/`를 `_`로 바꾼 값으로 짓는다 [9].
`analyze_sqlite_database`는 `cases/<이미지 이름>_<해시>/sqlite_analysis/<DB 이름>/` 폴더에 쓴다 [10].
`query`는 조회문의 해시로 지은 `query_<숫자>.csv`를 쓴다 [11].
파생물을 고치거나 지우는 데 호출 인자의 ID나 경로를 쓰는 도구는 없다.
서버가 실제 경로로 바꿔 허용 위치와 대조하는 것은 읽을 입력 경로뿐이다 [12].

**한계.** 호출 인자가 목적지 이름 조각으로 들어가는 곳은 세 곳이고 서버는 그 값에 경로 구분자나 상위 폴더 표기가 있는지 검사하지 않는다 [5][13][14].
`kape_parse_artifact`는 `kape_module`을 출력 폴더와 콘솔 로그 파일의 이름에 넣고 그 폴더를 KAPE를 실행하기 전에 만든다 [5][15].
`analyze_memory`는 Volatility 3 실행이 성공한 뒤 `plugin`을 출력 폴더 이름에 그대로 넣고 파일 이름에서만 `.`과 `/`를 `_`로 바꾼다 [9][14].
`analyze_sqlite_database`의 `export_table`은 `table_name`으로 한 `SELECT` 질의가 성공한 뒤 그 값을 그대로 넣은 `<table_name>.csv`를 쓴다 [13][16].
이 값으로 서버가 정한 폴더 밖에 파일이 쓰이는지는 실행해 확인하지 못했다.
`analyze_sqlite_database`의 `query`는 호출 인자 `sql_query`를 그대로 실행하고 그 문장 안의 쓰기 경로를 검사하지 않는다 [17].
DB는 읽기 전용 URI `mode=ro`로 열지만 이 설정은 SQL 문장이 정한 경로에 DB 사본을 쓰는 것을 막지 않는다 [17][18].
실행 확인에서 DB 사본을 쓰는 문장을 `sql_query`로 주자 응답은 오류였고 서버 출력 폴더 밖의 작업 폴더에 새 DB 파일이 생겼다 [18].

def _get_memory_output_directory(memory_file_path: str, plugin_name: str) -> Path:
