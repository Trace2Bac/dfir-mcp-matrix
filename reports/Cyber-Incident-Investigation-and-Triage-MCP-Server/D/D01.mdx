# D01 파생물 보관

### D01.01 파생물 파일 보관

**구현.** 이 방식은 KAPE와 EZ Tools, Volatility 3, SleuthKit을 부르는 도구가 쓰는 출력 파일, 추출 파일, SQLite 조회 결과 파일에 적용된다 [1][2][3].
서버 코드에는 이 파일들을 호출 뒤에 지우는 곳이 없다.
파생물은 모두 설정 `output_directory`가 가리키는 `forensic_output` 아래에 남는다 [4].
이 값은 `config/config.yaml`에 `D:\forensics_mcp_server\forensic_output`으로 적혀 있고 `app_config.py`가 저장소 위치를 기준으로 다시 매핑한다 [4][5].

`analyze_registry`·`analyze_prefetch`·`analyze_shellbags`·`analyze_lnk_files`·`analyze_jump_lists`·`analyze_mft`·`analyze_amcache`·`analyze_shimcache`·`analyze_event_logs`와 `kape_parse_artifact`는 KAPE나 EZ Tools 실행 파일에 출력 폴더를 넘겨 그 폴더에 CSV·JSON·HTML을 쓰게 한다 [6][7][1].
출력 폴더는 `get_case_output_directory`가 만드는 `cases/<이미지 ID>/<도구 종류>/<모듈>_<식별자>/`다 [6].
KAPE 모듈은 그 아래에 범주 이름의 하위 폴더를 하나 더 만든다 [8].
`kape_parse_artifact`는 KAPE가 실행 파일 폴더에 남긴 `*_ConsoleLog.txt`를 출력 폴더로 옮겨 `<모듈>_ConsoleLog.txt`로 둔다 [7].
`analyze_mft`는 `MFTECmd.exe`에 `--csv`로 출력 폴더를 넘기고 `mft_resident_files` 모듈에서는 `--dr`로 그 폴더 아래 `Resident` 폴더에 복구한 상주 파일을 쓰게 한다 [9][10].
`analyze_memory`는 `save_output`이 참이면 Volatility 3의 표준 출력을 `cases/<메모리 파일 이름>/memory/<플러그인>/<플러그인>.<형식>`에 쓴다 [11].

이미지에서 꺼낸 파일도 호출 뒤에 남는다.
`analyze_registry`는 SleuthKit로 마운트한 이미지를 분석할 때 `ExtractionManager`로 요청한 폴더를 `forensic_output/extract/<이미지 ID>/<내부 경로>/`에 꺼낸다 [12].
꺼낸 위치는 `extraction_registry.json`에 적는다 [13].
`ExtractionManager`는 같은 이미지의 같은 내부 경로를 이미 꺼낸 적이 있고 그 폴더가 남아 있으면 다시 꺼내지 않고 그 폴더를 쓴다 [14].
`analyze_sqlite_database`는 준비된 이미지의 DB 파일을 `cases/<이미지 ID>/extracted_files/`에 복사해 두고 지우지 않는다 [15].
그 밖의 파일 도구는 SleuthKit 이미지의 파일을 같은 폴더 아래 `<내부 경로 해시>/inode_<번호>_<이름>`으로 꺼내 두고 지우지 않는다 [16].

`analyze_sqlite_database`는 `query`와 `export_table`에서 조회 결과를 `cases/<이미지 이름>_<해시>/sqlite_analysis/<DB 이름>/` 아래 CSV로 쓴다 [3].
`analyze_macos_unified_logs`는 임시 폴더에 쓴 결과 파일을 `case_dir/unified_logs/`로 복사한 뒤 임시 폴더를 지운다 [17].
설정에는 보관 기간을 정하는 `temp_cleanup_hours`가 있지만 도구 처리 코드는 이 값을 읽지 않는다 [4].
보관 용량이나 대상을 정하는 설정이나 코드는 없다.

호출 안에서만 쓰고 지우는 파일도 있다.
`kape_parse_artifact`·`analyze_prefetch`·`analyze_shellbags`·`analyze_lnk_files`·`analyze_jump_lists`는 SleuthKit 이미지에서 꺼낸 파일을 설정 `temp_directory` 아래 `<종류>_extract_<inode>` 폴더에 두고 `finally`에서 그 폴더를 지운다 [18][19].

**한계.** `analyze_memory`는 호출 인자 `save_output`이 거짓이거나 Volatility 3 출력이 비어 있으면 출력을 파일로 남기지 않는다 [20].
`analyze_macos_unified_logs`는 입력이 사건 폴더가 있는 준비된 이미지에 속하고 `start_line`이 결과의 줄 수보다 작을 때만 결과 파일을 `unified_logs`로 복사한다 [21].
그 밖의 호출에서는 결과 파일을 남기지 않고 임시 폴더를 지운다 [21].

### D01.03 도구 출력·가공본 별도 보관

**구현.** 이 방식은 `analyze_lnk_files`의 `lnk_removable` 모듈에 적용된다 [22].
이 모듈은 `LECmd`에 `--csv`로 출력 폴더를 넘겨 원래 CSV `<시각>_LECmd_Output.csv`를 쓰게 한 뒤, 서버가 그 CSV를 읽어 이동식 드라이브 항목만 남긴 `<시각>_LECmd_Output_Removable.csv`를 같은 폴더에 따로 쓴다 [22][23].
원래 CSV와 걸러 낸 CSV는 둘 다 남는다 [23].
이동식 드라이브 항목이 들어간 `.lnk`를 분석하자 두 파일이 모두 출력 폴더에 남았다 [24].

    def generate_windows_filename(self, linux_path: str, inode: int) -> Path:
        """
        Generate unique Windows filename for extracted file
        
        Args:
            linux_path: Original Linux path
            inode: Inode number of the file
            
        Returns:
            Full Windows path for extracted file
        """
        filename = Path(linux_path).name
        
        safe_filename = f"inode_{inode}_{filename}"
        
        path_hash = hashlib.md5(linux_path.encode()).hexdigest()[:8]
        subdir = self.extraction_base_dir / path_hash
        subdir.mkdir(exist_ok=True)
        
        return subdir / safe_filename
