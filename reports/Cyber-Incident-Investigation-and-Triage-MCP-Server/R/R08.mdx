# R08 시간값 처리

### R08.01 시간 변환 전 값 유지

**구현.** 이 방식은 `read_csv_data`, `analyze_sqlite_database`, `analyze_memory`, `analyze_macos_unified_logs`에 적용된다 [1][2][3][4].
`read_csv_data`는 CSV 줄의 시각 열을 값 그대로 싣는다 [1].
`analyze_sqlite_database`의 질의는 표의 정수 시각 값을 바꾸지 않고 싣는다 [2].
`analyze_memory`는 Volatility 출력을 바꾸지 않고 싣는다 [3].
`analyze_macos_unified_logs`는 UnifiedLogReader가 쓴 줄을 바꾸지 않고 싣는다 [4].
서버 코드에는 네 도구의 시각을 찾거나 바꾸는 코드가 없다 [1][2][3][4].
시험용 CSV의 `2024-01-01 00:00:00` 꼴 열과 SQLite 표의 `1700000000` 꼴 정수가 응답에 그대로 실렸다 [1][2].

### R08.03 시간대·단위·정밀도 표시

**구현.** 이 방식은 `analyze_memory`에 적용된다 [3].
Volatility 3 2.28.0의 JSON 렌더러는 `datetime` 값을 `isoformat()` 문자열로 출력한다 [5].
같은 버전의 `quick`·`pretty`·`csv` 렌더러는 `datetime`을 `%Y-%m-%d %H:%M:%S.%f %Z` 형식으로 적어 시간대 이름을 붙인다 [6].
`wintime_to_datetime`은 Windows FILETIME을 UTC 시간대가 붙은 `datetime`으로 바꾸므로 이 문자열 끝에는 `+00:00`이 붙는다 [7].
`analyze_memory`는 이 문자열을 바꾸지 않으므로 응답의 시각 값에 시간대가 값으로 실린다 [3].
FILETIME이 0이면 Volatility는 값 대신 해당 없음 표시를 내고 JSON 렌더러는 이를 `null`로 출력한다 [5][7].

**한계.** `read_csv_data`로 전달되는 EZ Tools CSV의 시각과 SQLite 정수 시각, plist의 시각에는 시간대나 단위 표기가 없고 서버는 이를 보태지 않는다 [1][2][8].
PECmd acdf082는 기본 시각 형식을 `yyyy-MM-dd HH:mm:ss`로 정해 시간대를 붙이지 않는다 [9].
`analyze_macos_plist`는 이진 형식 plist의 `datetime`을 `str`로 적어 `2024-01-02 03:04:05` 꼴로 싣고 시간대와 원래 바이트를 밝히지 않는다 [8].
UnifiedLogReader `39f774e`는 시각을 시간대 없는 `datetime` 문자열로 쓴다 [10].
