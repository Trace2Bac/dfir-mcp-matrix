# R01 결과 가공

### R01.01 가공 없이 전달

**구현.** 이 방식은 `analyze_memory`와 `read_csv_data`에 적용된다 [1][2].
`analyze_memory_handler`는 Volatility를 하위 프로세스로 실행하고 그 표준 출력 `stdout`을 바꾸지 않고 응답 본문에 싣는다 [1].
`read_csv_data_handler`는 모델이 준 행 범위의 CSV 줄을 값 그대로 응답에 싣는다 [2].
두 함수는 값을 다시 계산하거나 필드로 나누지 않는다 [1][2].
`analyze_lnk_files`는 `lnk_removable` 모듈에서 LECmd가 만든 CSV를 다시 읽어 `DriveType` 열에 removable이나 USB가 들어 있거나 값이 `2`인 줄만 `_Removable.csv`에 따로 쓴다 [3].
이 파일과 원래 CSV는 응답 본문에 실리지 않고 `browse_files_and_folders`·`read_csv_data`로 다시 읽어야 모델에게 전달된다 [4].

**한계.** `analyze_memory`는 `stdout`이 5,000자를 넘으면 앞 5,000자만 싣는다 [1].
`read_csv_data`는 CSV 줄을 ```` ```csv ```` 표시로 감싸 응답에 싣고 요청한 행 범위 밖은 싣지 않는다 [2].
`read_csv_data`는 줄마다 앞뒤 공백을 지우고 줄 사이를 줄바꿈 문자 대신 `\`와 `n` 두 글자로 이어 응답에 싣는다 [5][2].
앞뒤에 공백을 둔 시험용 CSV 줄은 공백 없이 실렸고 줄 사이는 `\n` 두 글자로 이어졌다 [6].

### R01.02 구조화 파싱·필드 선택

**구현.** 이 방식은 `analyze_sqlite_database`, `analyze_macos_plist`, `analyze_macos_fsevents`, `identify_file_type`에 적용된다 [7][8][9][10].
`analyze_sqlite_database_handler`는 SQLite 데이터베이스를 읽어 `list_tables`에서 객체 이름과 종류를, 질의 결과에서 열 이름과 행 값을 골라 응답에 싣는다 [7].
`analyze_macos_plist_handler`는 이진 형식 plist를 `plistlib`로 읽고 `plist_type`이 `login_items`·`recent_items`·`dock`·`launch_agent`이면 정해 둔 키만 골라 싣는다 [8].
`analyze_macos_fsevents_handler`는 FSEvents 파일을 `parse_fsevents_directory`로 읽어 레코드마다 `event_id`·`path`·`type`·`actions`를 뽑아 싣는다 [9][11].
`identify_file_type_handler`는 파일 앞부분의 매직 바이트를 읽어 `file_type`·`category`·`primary_tool` 같은 필드로 나눠 싣는다 [10].

### R01.03 형식 변환·건수 집계

**구현.** 이 방식은 `analyze_mft`, `analyze_amcache`, `analyze_shimcache`, `analyze_event_logs`, `analyze_sqlite_database`, `analyze_macos_fsevents`에 적용된다 [12][13][14][15][7][9].
`analyze_mft_handler`는 `mft_timeline` 모듈에서 결과 폴더의 `MFT_Timeline.csv`를 다시 읽어 머리 줄을 뺀 행 수를 `Records Processed`로 싣는다 [12].
같은 파일 전체를 대문자로 바꾼 뒤 `DELETED`가 나온 횟수와 `:`가 나온 횟수를 세어 `Deleted Files Found`와 `ADS Found`로 싣는다 [12].
`analyze_amcache_handler`는 결과 폴더에 있는 CSV 파일마다 머리 줄을 뺀 줄 수를 더해 `Programs Found`에 싣는다 [13].
`analyze_shimcache_handler`는 CSV를 `csv.DictReader`로 읽어 캐시 항목 수, `Executed`가 참인 수, 의심 경로 수를 집계한다 [14].
`analyze_event_logs`는 EvtxECmd가 만든 CSV의 행 수를 더해 `Total events processed`에 싣고 파일 이름에 `Security`가 들어간 CSV의 행 수를 `Security events`에 싣는다 [15][16].
`analyze_sqlite_database`의 `list_tables`는 표마다 행 수를 세어 싣는다 [7].
`analyze_macos_fsevents_handler`는 FSEvents의 이진 레코드를 `dict` 목록으로 바꾸고 동작별 개수를 집계해 싣는다 [9].

**한계.** `analyze_shimcache`가 세는 실행 수, USB 경로 수, 의심 경로 수는 응답 본문에 실리지 않고 캐시 항목 수만 실린다 [17].
MFTECmd `6aadd87`은 `--csvf`가 없으면 결과 파일 이름을 `<시각>_MFTECmd_$MFT_Output.csv`로 짓고 서버는 `--csvf`를 넘기지 않으므로 `analyze_mft`의 세 값은 `File not found`로 실린다 [12][18][19].
`MFT_Timeline.csv`가 있을 때도 `ADS Found`는 대체 데이터 스트림 수가 아니라 MFTECmd 기본 시각 형식 `yyyy-MM-dd HH:mm:ss.fffffff`의 `:`까지 센 수다 [12][18].
AmcacheParser `2904455`는 프로그램, 파일, 바로 가기, 드라이버, 장치 항목을 서로 다른 CSV에 쓰므로 `Programs Found`는 프로그램 수가 아니라 이 CSV들의 행 수 합이다 [13][20].
`analyze_amcache`의 결과 폴더는 같은 증거에서 늘 같은 경로이고 AmcacheParser는 파일 이름 앞에 실행 시각을 붙이므로 앞선 실행의 CSV가 남아 있으면 그 행도 더한다 [21][20].
`analyze_amcache` 응답의 `SHA1 Hashes`는 값을 채우는 코드가 없어 늘 `N/A`로 실린다 [22].
EvtxECmd `03a7a1f`는 `--csvf`가 없으면 모든 로그를 `<시각>_EvtxECmd_Output.csv` 파일 하나에 쓰고 서버는 `--csvf`를 넘기지 않으므로 `Security events`는 늘 0이다 [15][23].
`analyze_event_logs` 응답의 `System events`와 `Application events`는 값을 채우는 코드가 없어 늘 `N/A`로 실린다 [16].

### R01.04 가공 사실·대상 표시

**구현.** 이 방식은 `analyze_memory`, `analyze_sqlite_database`, `analyze_mft`, `analyze_amcache`의 응답에 적용된다 [1][7][22].
`analyze_memory_handler`는 응답 머리에 `Memory File`과 `Plugin`을 적어 결과가 어느 파일에 어느 Volatility 플러그인을 실행한 것인지 밝힌다 [1].
`analyze_sqlite_database`의 질의 응답은 `QUERY RESULTS`와 실행한 `Query`를 적는다 [7].
`Query`에는 실행한 질의의 앞 100자까지만 싣는다 [7].
`analyze_mft`·`analyze_amcache`의 응답은 실행한 명령 `Command`와 결과를 만든 모듈 이름을 적는다 [22].
