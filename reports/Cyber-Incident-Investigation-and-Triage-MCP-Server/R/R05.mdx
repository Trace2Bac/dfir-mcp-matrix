# R05 결과 출처 표시

### R05.01 증거·파일 ID

**구현.** 이 방식은 `read_text_file`, `analyze_memory`, `analyze_macos_plist`, `analyze_macos_keychain`, `analyze_mft`, `analyze_amcache`, `analyze_shellbags`, `analyze_lnk_files`에 적용된다 [1][2][3][4][5].
`read_text_file`은 응답 머리에 읽은 파일 이름과 준비한 이미지 경로 `Source Image`를 적는다 [1].
`analyze_memory`는 분석한 메모리 파일 이름 `Memory File`을 적는다 [2].
`analyze_macos_plist`와 `analyze_macos_keychain`은 읽은 파일의 경로 `File`·`Keychain File`과 준비한 이미지 이름을 적는다 [3][4].
`File`·`Keychain File`은 모델이 준 경로이고 `Source`·`Source Image`는 준비한 이미지 파일의 경로나 이름이다 [1][3][4].
`analyze_mft`, `analyze_amcache`, `analyze_shellbags`는 결과마다 분석한 입력 경로를 `Path`로, `analyze_lnk_files`는 `Source`로 싣는다 [5].

### R05.02 증거 내부 경로

**구현.** 이 방식은 `browse_files_and_folders`, `analyze_macos_fsevents`, `read_csv_data`에 적용된다 [6][7][8].
`browse_files_and_folders`는 이미지 안의 파일 목록을 돌려주고 항목마다 이미지 안 경로를 싣는다 [6].
`analyze_macos_fsevents`는 사건마다 파일 시스템 안 경로를 `path`로 싣는다 [7].
`parse_fsevents_directory`는 FSEvents 레코드의 경로 바이트를 해석해 이 값을 만든다 [9].
`read_csv_data`는 MFTECmd CSV의 `ParentPath` 열처럼 EZ Tools가 적은 증거 안 경로를 바꾸지 않고 싣는다 [8][10].

### R05.03 레코드 키·번호

**구현.** 이 방식은 `analyze_macos_fsevents`, `analyze_memory`, `read_csv_data`에 적용된다 [7][2][8].
`analyze_macos_fsevents`는 사건마다 FSEvents 레코드 번호 `event_id`를 싣는다 [7].
`analyze_memory`는 Volatility 출력을 바꾸지 않고 싣고 `pslist`·`psscan`·`netscan` 출력에 있는 프로세스 식별자 `PID` 열이 그대로 전달된다 [2][11].
`read_csv_data`는 EZ Tools CSV의 열을 바꾸지 않고 실으므로 EvtxECmd의 `RecordNumber`·`EventRecordId`, MFTECmd의 `EntryNumber`, RECmd의 `KeyPath`가 그대로 전달된다 [8][10].

### R05.04 바이트·섹터·행 오프셋

**구현.** 이 방식은 `analyze_memory`에 적용된다 [2].
`analyze_memory`는 Volatility 출력을 바꾸지 않고 싣는다 [2].
Volatility 3 2.28.0의 `netscan`은 구조체 위치를 `Offset` 열로, `psscan`은 `Offset(V)` 열로 내므로 이 값이 결과 행에 그대로 전달된다 [11].

**한계.** `netscan`·`psscan`의 오프셋이 이미지 안의 물리 위치인지 가상 주소인지는 이미지의 Windows 판에 따라 다르고 서버는 이를 표시하지 않는다 [11][2].
