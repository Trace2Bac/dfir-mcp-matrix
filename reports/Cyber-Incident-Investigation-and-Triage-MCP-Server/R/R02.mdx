# R02 대량 결과 전달

### R02.01 문자·항목 상한

**구현.** 이 방식은 `read_text_file`, `parse_xml_evidence`, `analyze_sqlite_database`, `analyze_macos_unified_logs`, `analyze_memory`, `decompress_mozilla_lz4`, `browse_files_and_folders`에 적용된다 [1][2][3][4][5][6][7].
`read_text_file`은 읽을 줄 수를 `max_lines`로 제한하고 기본값은 100이다 [1].
`parse_xml_evidence`는 돌려줄 요소 수를 `max_elements`로 제한하고 기본값은 50이다 [2].
`parse_xml_evidence`는 `max_elements`와 관계없이 요소 10개를 싣고 멈춘다 [8].
`analyze_sqlite_database`는 질의와 표 내보내기에서 CSV로 남길 행 수를 `max_rows`로 제한하고 기본값은 1,000이다 [3].
질의 응답 본문에는 그 가운데 앞 20행만 싣는다 [9].
`analyze_macos_unified_logs`는 `start_line`과 `end_line`으로 돌려줄 줄 범위를 정하고 기본값은 0과 100이다 [4].
`analyze_memory`는 Volatility 표준 출력을 5,000자, 표준 오류를 500자에서 자른다 [5].
`decompress_mozilla_lz4`는 JSON을 10,000자, JSON이 아닌 글을 5,000자, 열린 탭을 20개, 최상위 키를 10개까지 싣는다 [6].
`browse_files_and_folders`는 WSL로 마운트한 APFS·LVM 이미지의 경로 목록을 500개까지 싣는다 [7].
`read_text_file`과 `parse_xml_evidence`는 50 MB, `read_csv_data`는 100 MB, `decompress_mozilla_lz4`는 10 MB를 넘는 입력 파일을 읽지 않고 오류를 돌려준다 [10][11][12][13].

### R02.02 전체·반환 건수 표시

**구현.** 이 방식은 `read_csv_data`, `analyze_sqlite_database`, `parse_xml_evidence`, `analyze_macos_fsevents`에 적용된다 [14][9][2][15].
`read_csv_data`는 응답에 전체 행 수 `Total Data Rows`, 이번에 돌려준 행 수 `Retrieved`, 남은 행 수 `Remaining`을 구별해 싣는다 [14].
`analyze_sqlite_database`의 질의는 CSV로 내보낸 행 수를 `Rows`로 적고 응답 본문에 실은 20행 밖의 수를 `... and N more rows`로 적는다 [9].
질의 결과가 `max_rows`를 넘으면 `Results limited to {max_rows} rows`를 싣는다 [9].
`parse_xml_evidence`는 찾은 요소 수와 보여 주는 요소 수를 구별해 싣는다 [2].
`analyze_macos_fsevents`는 파싱한 사건 가운데 어느 범위를 보여 주는지 `Displayed … of N total`로 싣는다 [15].

**한계.** `analyze_sqlite_database`의 질의는 결과가 `max_rows`를 넘으면 전체 행 수를 세지 않는다 [9].
이때 `Full results in CSV`라고 적지만 내보낸 CSV에도 `max_rows`행만 들어 있다 [9].
30행 표를 `max_rows` 25로 질의하자 `Rows: 25`, 본문 20행, `... and 5 more rows`가 실렸다 [16].
`parse_xml_evidence`는 `Showing`과 `(showing N of M)`에 `max_elements`로 자른 수를 적지만 응답에는 요소 10개만 싣는다 [8].
XPath 없이 부르면 `M`도 `max_elements`로 자른 수다 [2].
자식 60개인 시험용 XML에서 `Showing: 50`과 `(showing 50 of 50)`이 적혔고 요소는 10개가 실렸다 [17].
`analyze_macos_fsevents`는 파싱한 사건이 1만 건에 이르면 남은 파일을 읽지 않고 사건 번호가 큰 1만 건만 남긴다 [18].
SleuthKit 경로는 FSEvents 파일을 앞 10개만 꺼낸다 [18].
그래서 `of N total`의 `N`은 증거 전체의 사건 수보다 작을 수 있다 [15][18].

### R02.03 페이지·커서 조회

**구현.** 이 방식은 `read_csv_data`, `analyze_macos_unified_logs`, `analyze_macos_fsevents`에 적용된다 [14][4][15].
`read_csv_data`는 `start_row`와 `end_row`로 행 범위를 받고 응답에 다음 범위를 `Next Chunk`로 안내한다 [14].
`analyze_macos_unified_logs`는 `start_line`과 `end_line`으로, `analyze_macos_fsevents`는 `start_index`와 `end_index`로 다음 범위를 이어 읽게 한다 [4][15].
두 도구 가운데 `analyze_macos_fsevents`만 응답에 다음 범위를 `To see next batch`로 안내한다 [15].

**한계.** macOS 두 도구는 부를 때마다 증거를 처음부터 다시 파싱하고 `analyze_macos_unified_logs`는 `end_line`까지 파싱한다 [19][18].
그래서 `analyze_macos_unified_logs` 응답의 `of N total`에서 `N`은 로그 전체 항목 수가 아니다 [4][19].

### R02.04 파일·리소스로 전체 결과 조회

**구현.** 이 방식은 `analyze_memory`, KAPE를 부르는 분석 도구, `analyze_event_logs`에 적용된다 [20][21][22].
`analyze_memory`는 `save_output`이 참이면 Volatility 출력 전체를 사건 폴더의 파일에 저장하고 응답에 그 경로를 `Saved`로 적는다 [20].
`output_format`이 `csv`이면 저장한 파일을 `read_csv_data`로 다시 읽을 수 있다 [20][23].
레지스트리, Prefetch 같은 KAPE 분석 도구와 `analyze_event_logs`는 CSV를 사건 폴더에 저장하고 응답에 그 폴더나 파일 경로를 적는다 [21][22].
모델은 `browse_files_and_folders`와 `read_csv_data`로 그 CSV를 다시 읽는다 [21].

**한계.** `analyze_memory`가 저장한 파일은 준비한 이미지의 파일이 아니므로 `read_text_file`은 이 파일을 거부하고 `read_csv_data`는 확장자가 `.csv`가 아닌 파일을 읽지 않는다 [24].
그래서 기본값 `json`이나 `pretty`로 저장한 전체 결과는 MCP 도구로 다시 읽을 수 없다 [24].
`read_csv_data`는 100 MB를 넘는 CSV를 거부하므로 그보다 큰 결과는 끝까지 다시 읽을 수 없다 [12].
`json`으로 저장한 시험용 출력에 `read_text_file`은 `ACCESS DENIED`를, `read_csv_data`는 확장자 경고를 돌려주었다 [23].

### R02.06 값 단위 잘림

**구현.** 이 방식은 `parse_xml_evidence`에 적용된다 [25].
`parse_xml_evidence`는 요소 하나의 글자 값을 200자에서 자르고 `...`를 붙인다 [25].

### R02.07 건수 없는 잘림 표시

**구현.** 이 방식은 `analyze_memory`와 `read_text_file`에 적용된다 [20][26].
`analyze_memory`는 Volatility 출력이 5,000자를 넘으면 `... (output truncated, full results saved to file)`를 붙이고 전체 건수와 반환 건수는 적지 않는다 [20].
`read_text_file`은 읽을 줄이 더 남으면 `WARNING: File continues...`를 붙이고 전체 줄 수와 반환 줄 수는 적지 않는다 [26].

**한계.** `analyze_memory`는 `save_output`이 거짓이면 파일을 쓰지 않는데도 같은 문구를 붙인다 [20].
`save_output`을 거짓으로 부르자 `Saved:` 줄 없이 이 문구가 실렸다 [23].
