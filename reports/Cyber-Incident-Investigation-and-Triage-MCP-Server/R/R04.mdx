# R04 도구 결과 해석 주의

### 미구현

**판단.** 도구 설명, 서버 지침, 응답 어디에도 도구 결과의 해석 한계나 추가 확인이 필요하다는 점을 적지 않는다.
서버의 `create_server`는 `list_tools`와 `call_tool`만 등록하고 MCP 리소스, 프롬프트, 초기화 지침 `instructions`를 두지 않는다 [1].
초기화 응답의 `instructions`는 비어 있었다 [2].
YAML에서 만드는 분석 도구의 설명은 `_generate_tool_from_config`가 짧은 설명, 포렌식 가치, 분류, 모듈 목록으로만 짓고 YAML에 있는 `limitations`·`warnings` 필드는 읽지 않는다 [3].
이 필드를 담아 글로 만드는 `get_tool_info_text`는 서버 어디에서도 부르지 않는다 [4].
그래서 Shimcache 설정의 "Last Modified time is NOT execution time" 같은 해석 한계 문구는 모델에게 전달되지 않는다 [5].
`analyze_shimcache`·`analyze_mft`·`analyze_amcache`·`analyze_jump_lists`의 처리기는 결과에 분석 도움말 `forensic_context`를 붙이고 `analyze_event_logs`의 처리기는 `forensic_guidance`를 붙인다 [6].
`analyze_shimcache`의 `forensic_context`에는 해석 한계 목록 `limitations`가 있고 같은 "Last Modified time is NOT execution time" 문구가 들어 있다 [6].
응답 글을 만드는 코드는 이 키를 읽지 않아 이 내용도 모델에게 전달되지 않는다 [7].
직접 적은 도구 설명은 실행하는 명령과 인자 사용법, 예시만 적는다 [8].
`analyze_macos_unified_logs`의 설명이 적는 "Can take 10-30 minutes"는 처리 시간을 알릴 뿐 결과의 해석 한계가 아니다 [8].
명령을 실행하는 도구와 파싱 도구의 응답에는 결과 내용에 따라 붙이는 해석 주의가 없다 [9].
