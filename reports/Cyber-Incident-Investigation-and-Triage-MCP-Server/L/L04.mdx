# L04 기록 위변조 방지

### 미구현

**판단.** 서버의 기록은 모두 덧붙여 쓰는 글 파일이고 수정, 삭제, 순서 변경을 막거나 알아차리는 장치가 없다 [1][2][3].

- 루트 로거의 `forensic_output/logs/mcp_server_<시작 시각>.log`와 `remote_server.log`, 운영 기록 `forensic_output/operations_logs/operations_<날짜>.log`는 표준 라이브러리 `FileHandler`가 쓴다 [1].
- KAPE 기록 `forensic_output/kape_logs/kape_operations.log`는 `log_kape_operation`이 덧붙이기 모드로 열어 쓴다 [2].
- `main.py`는 표준 오류를 저장소 폴더의 `stderr.log`에 덧붙여 쓴다 [3].

항목에는 앞 항목의 해시나 일련번호가 없다 [1][2].
KAPE 기록 항목의 `OPERATION ID`는 초 단위 시각과 명령 글의 SHA-256 앞 16자리로 항목마다 따로 계산한다 [2].
그래서 같은 초에 같은 명령으로 쓴 항목은 같은 값을 갖는다 [2].
`kape_parse_artifact`를 부르자 같은 실행의 실행 전 항목과 실행 뒤 항목이 같은 `OPERATION ID`로 남았다 [4].
`audit_kape_operations`는 KAPE 기록을 읽어 항목의 ID, 시각, 종류, 반환 코드, 명령을 보여 줄 뿐 해시를 다시 계산해 대조하지 않는다 [5].
이 도구는 기록을 줄로 나눌 때 줄바꿈 문자 대신 역슬래시와 `n` 두 글자를 기준으로 쓴다 [5].
그래서 파일 전체가 한 줄로 읽혀 항목이 몇 개든 `Total entries found: 1`로 보고하고 첫 `OPERATION ID:` 뒤의 내용 전체를 ID 자리에 싣는다 [5][4].
저장소에는 기록 폴더를 읽기 전용으로 두고 분석 도구를 실행하는 구성이 없다.
KAPE와 그 모듈, EZ Tools, Volatility 3는 서버와 같은 계정으로 같은 호스트에서 실행된다 [6].

```python
def log_kape_operation(operation_type, command, return_code, output, error, kape_logs_dir):
    """Log KAPE operations to audit log for forensic defensibility"""
    from datetime import datetime
    import hashlib
    
    log_file = Path(kape_logs_dir) / "kape_operations.log"
    log_file.parent.mkdir(parents=True, exist_ok=True)
    
    timestamp = datetime.now().strftime('%Y-%m-%d %H:%M:%S')
    operation_hash = hashlib.sha256(f"{timestamp}{command}".encode()).hexdigest()[:16]
    
    log_entry = f"""
{'='*80}
OPERATION ID: {operation_hash}
TIMESTAMP: {timestamp}
TYPE: {operation_type}
COMMAND: {command}
RETURN CODE: {return_code}
{'='*80}
OUTPUT:
{output}
{'='*80}
ERRORS:
{error}
{'='*80}
"""
    
    with open(log_file, 'a', encoding='utf-8') as f:
        f.write(log_entry)
```
