# L02 기록 구성

### L02.01 MCP 요청 기록

**구현.** 이 방식은 모든 도구 호출에 `call_tool`이 남기는 `Tool called` 줄에 적용된다 [1].
줄의 메시지는 `Tool called: <도구 이름> with arguments: <인자>` 꼴이고 인자는 처리기에 넘기기 전의 `dict`를 Python 표기로 적은 글이다 [1].
`call_tool`은 처리기를 고르고 YAML 도구의 기본값을 채우기 전에 이 줄을 쓰므로 인자는 서버가 바꾸기 전의 값이다 [1].
이 값은 MCP SDK가 해석해 넘긴 값이고 전송된 요청 원문 전체는 아니다.
도구 이름과 인자는 한 메시지 글 안에 있고 따로 나뉜 칸에 기록되지 않는다 [1].
운영 기록의 시작 항목 가운데 `prepare_disk_image`와 macOS 도구 4개의 항목도 받은 인자 일부를 바꾸지 않은 채 JSON으로 적는다 [2][3].
stdio 서버에 `kape_parse_artifact`를 부르자 `Tool called: kape_parse_artifact with arguments: {'file_path': …, 'kape_module': 'EvtxECmd'}`처럼 받은 인자가 그대로 남았다 [4].

**한계.** MCP Python SDK 1.29.1이 입력 schema 검사에서 거부한 호출은 처리기에 오지 않아 이 줄이 남지 않는다 [5][6].

### L02.02 서버가 변환한 연산·인자 기록

**구현.** 이 방식은 `crack_hash`의 시작 항목과 `analyze_registry`·`analyze_prefetch`의 모듈 선택 줄에 적용된다 [7][8].
`crack_hash`는 해시 값의 앞뒤 공백을 지우고 `b'…'`·`b"…"` 꼴로 감싼 글자를 벗긴 뒤 시작 항목을 쓴다 [7].
시작 항목의 `hash`에는 바꾼 값의 앞 50자와 `...`이 들어가고 `wordlist`에는 인자가 없을 때 실제 경로 대신 `default`가 들어간다 [7].
`mode`에는 모드 번호 인자가 없으면 모드 이름 인자가 그대로 들어가고 서버가 이름에서 찾은 모드 번호는 들어가지 않는다 [7].
`analyze_registry`·`analyze_prefetch`는 `modules` 인자를 설정의 모듈 목록과 대조한 뒤 고른 모듈 ID를 `Running selected … modules` 줄에 적는다 [8].
`modules`가 비었거나 `all`을 담으면 모듈 ID 대신 모듈 수만 적는다 [8].
64자 해시로 `crack_hash`를 부르자 시작 항목의 `hash`가 앞 50자와 `...`로 남고 `wordlist`가 `default`로 남았다 [4].

### L02.03 외부 실행 명령 기록

**구현.** 이 방식은 KAPE 기록 파일의 `COMMAND` 칸과 처리기들이 루트 로거에 쓰는 실행 줄에 적용된다 [9][10].
`log_kape_operation`은 실행 파일과 인자를 담은 `list`를 Python 표기 그대로 `COMMAND` 칸에 적으므로 인자의 경계가 남는다 [9].
항목의 `OPERATION ID`는 초 단위 시각과 이 명령 글을 이은 문자열의 SHA-256 앞 16자리이고 출력의 해시가 아니다 [9].

다음 도구는 실행 직전에 실행 파일과 인자를 공백으로 이은 줄을 루트 로거에 쓴다 [10].

- `kape_parse_artifact`와 `analyze_registry`·`analyze_lnk_files`·`analyze_shellbags`는 KAPE 실행 줄을 쓴다 [10].
- `analyze_amcache`·`analyze_mft`·`analyze_shimcache`·`analyze_event_logs`는 EZ Tools 실행 줄을 쓴다 [10].
- `analyze_memory`·`list_memory_plugins`는 Volatility 3 실행 줄을 쓴다 [10].
- `prepare_disk_image`는 Arsenal Image Mounter와 SleuthKit `mmls` 실행 줄을 쓰고 SleuthKit으로 파일 목록을 읽는 경로는 `fls` 실행 줄을 쓴다 [10].

`analyze_macos_keychain`은 chainbreaker 명령의 `list`를 Python 표기로 한 번 더 적는다 [10].
`analyze_prefetch`·`analyze_jump_lists`의 KAPE 실행과 `get_memory_plugin_help`의 Volatility 3 실행은 실행 줄을 쓰지 않는다 [11].
SleuthKit `icat` 실행 줄은 `DEBUG`로 쓰지만 그 로거의 수준을 `INFO`로 고정해 남지 않는다 [11].
`kape_parse_artifact`를 부르자 KAPE 기록의 `COMMAND` 칸에 `--msource`, `--mdest`, `--module`과 그 값이 `list` 표기로 남았다 [4].

**한계.** `kape_parse_artifact`는 KAPE를 실행하기 전에 `Executing KAPE command` 줄과 KAPE 기록의 실행 전 항목을 쓴다 [12].
그래서 그 뒤에 실행이 막히면 실행하지 않은 명령도 기록에 남는다 [12].
`kape_operations.log`에 쓸 수 없게 하고 `kape_parse_artifact`를 부르자 시험용 KAPE는 실행되지 않았는데 `Executing KAPE command` 줄은 남았다 [13].
`crack_hash`의 실행 줄은 명령 `list`의 앞 5개 요소 뒤에 `...`만 붙여 나머지 인자를 남기지 않는다 [10].

### L02.05 결과 상태·실행 시점 기록

**구현.** 이 방식은 운영 기록의 완료·오류 항목, KAPE 기록 항목, `call_tool`의 예외 줄, 일부 처리기가 루트 로거에 쓰는 결과 줄에 적용된다 [14][9][15][16][17][18].
`log_operation_success`·`log_operation_error`는 `SUCCESS`·`ERROR`와 걸린 시간을 적고 처리기 형식이 줄 앞에 시각을 붙인다 [14].
`log_kape_operation`은 `TIMESTAMP`와 `RETURN CODE` 칸을 둔다 [9].
`call_tool`까지 올라온 예외는 `ERROR` 수준 줄로 남고 루트 처리기 형식이 시각을 붙인다 [15].
운영 기록과 KAPE 기록을 쓰지 않는 도구 가운데 일부도 처리기가 루트 로거에 결과 상태 줄을 쓴다 [16][17][18].
`list_memory_plugins`·`analyze_lnk_files`·`analyze_shellbags`는 하위 프로세스의 종료 코드를 적는다 [16].
`analyze_amcache`·`analyze_mft`·`analyze_shellbags`·`analyze_jump_lists`는 모듈 실행의 성공 수를 전체 수나 실패 수와 함께 적는다 [17].
`analyze_mft`·`analyze_shimcache`는 외부 도구가 0이 아닌 종료 코드로 끝나면 `ERROR` 줄을 쓴다 [18].
`analyze_memory`·`analyze_event_logs`는 외부 도구 실행 중 예외가 나면 `ERROR` 줄을 쓴다 [18].
그 밖의 도구는 처리기가 오류를 응답 글로 돌려주면 `call_tool`이 예외 줄을 쓰지 않으므로 실패가 결과 상태로 남지 않는다 [15].
없는 메모리 파일로 `analyze_memory`를 부르자 `ERROR:` 응답이 돌아왔고 `Tool called` 줄 뒤에 결과 상태를 적은 줄은 없었다 [4].

**한계.** 다음 경로는 기록에 남는 결과 상태가 실제와 다르거나 비어 있다.

- `kape_parse_artifact`는 `log_kape_operation`에 인자를 위치로 넘기는데 차례가 함수 정의와 달라 실행 뒤 항목의 `RETURN CODE` 칸에 표준 출력이, `OUTPUT` 칸에 표준 오류가, `ERRORS` 칸에 종료 코드가 들어간다 [19].
- 같은 도구의 실행 전 항목은 `RETURN CODE` 칸이 비고 `ERRORS` 칸에 `0`이 들어간다 [19].
- `crack_hash`와 macOS 도구 4개는 `log_operation_start`가 돌려준 `dict`를 도구 이름 자리에 넘기므로 완료·오류 항목의 도구 이름 칸에 시작 항목 전체가 `dict` 표기로 들어간다 [20].
- `prepare_disk_image`는 반환 지점 5곳에서 오류를 돌려주면서 오류 항목을 쓰지 않는다 [21].
- `crack_hash`는 시작 항목을 쓴 뒤 hashcat 설정이 꺼졌거나 실행 파일이 없거나 모드 이름을 찾지 못하면 완료 항목 없이 돌아간다 [22].
- `kape_parse_artifact`는 KAPE가 관리자 권한이 없다고 출력하면 실행 뒤 항목을 쓰지 않고 돌아간다 [12].

stdio 서버에서 `kape_parse_artifact`의 실행 뒤 항목은 `RETURN CODE` 칸에 시험용 KAPE의 표준 출력이, `ERRORS` 칸에 `0`이 남았다 [4].
실행 파일이 없는 설정으로 `crack_hash`를 부르자 운영 기록에 `START` 항목만 남았다 [4].
`analyze_macos_plist`의 `SUCCESS` 항목에는 도구 이름 대신 `{'event': 'operation_start', 'tool': 'analyze_macos_plist', …}`가 남았다 [4].

### L02.06 결과 참조·요약값 기록

**구현.** 이 방식은 일부 처리기가 루트 로거와 운영 기록에 쓰는 완료 줄에 적용된다 [23].

- `analyze_memory`는 출력을 파일로 저장하면 그 경로를 `Saved output to:` 줄에 적는다 [23].
- `list_memory_plugins`는 출력의 글자 수를 적는다 [23].
- `analyze_shimcache`는 찾은 캐시 항목 수와 만든 출력 파일 수를 적는다 [23].
- `analyze_macos_unified_logs`의 완료 항목은 처리한 항목 수를 적는다 [23].
- `prepare_disk_image`의 완료 항목은 파일 시스템 종류와 이미지 ID `unique_image_id`를 적는다 [23].
- `analyze_lnk_files`·`analyze_shellbags`는 모듈마다 출력 파일 수와 합계 크기를 적는다 [24].
- `analyze_lnk_files`는 `lnk_removable` 모듈에서 전체 행 수와 고른 행 수를 적는다 [24].
- `analyze_amcache`·`analyze_mft`·`analyze_event_logs`·`analyze_lnk_files`·`analyze_shellbags`는 결과 폴더 경로를 적는다 [25].

KAPE 기록은 결과 폴더를 `COMMAND` 칸의 `--mdest` 값으로만 가리키고 출력 파일 목록이나 크기를 적지 않는다 [9].
어느 기록도 도구 출력의 해시를 남기지 않는다 [9][23].
요약값을 적는 줄은 처리기마다 따로 쓰고 적는 값도 처리기마다 다르다 [23][24].

```python
    async def call_tool(name: str, arguments: dict):
        """Route tool calls to appropriate handlers (with lazy loading for performance)"""
        try:
            logger.info(f"Tool called: {name} with arguments: {arguments}")
            
            from core.tool_generator import get_tool_handler_mapping
            yaml_mapping = get_tool_handler_mapping()
            
            if name in yaml_mapping:
                handler_path = yaml_mapping[name]
                module_path, function_name = handler_path.rsplit('.', 1)
                
                import importlib
                module = importlib.import_module(module_path)
                handler = getattr(module, function_name)
                
                return await handler(

                    modules=arguments.get("modules", ["all"]),
                    output_format=arguments.get("output_format", "csv")
                )
```

```python
def log_kape_operation(operation_type, command, return_code, output, error, kape_logs_dir):
    """Log KAPE operations to audit log for forensic defensibility"""
    from datetime import datetime
    import hashlib
    
    log_file = Path(kape_logs_dir) / "kape_operations.log"
    log_file.parent.mkdir(parents=True, exist_ok=True)
    
    timestamp = datetime.now().strftime('%Y-%m-%d %H:%M:%S')
    operation_hash = hashlib.sha256(f"{timestamp}{command}".encode()).hexdigest()[:16]
    
    log_entry = f"""
{'='*80}
OPERATION ID: {operation_hash}
TIMESTAMP: {timestamp}
TYPE: {operation_type}
COMMAND: {command}
RETURN CODE: {return_code}
{'='*80}
OUTPUT:
{output}
{'='*80}
ERRORS:
{error}
{'='*80}
"""
    
    with open(log_file, 'a', encoding='utf-8') as f:
        f.write(log_entry)
```

```python
def log_operation_success(tool_name: str, result_summary: str, execution_time: float = None):
    """Log successful completion of a forensic operation"""
    log_entry = {
        'event': 'operation_success',
        'tool': tool_name,
        'result': result_summary,
        'execution_time': execution_time,
        'timestamp': datetime.now().isoformat()
    }
    time_str = f" | {execution_time:.3f}s" if execution_time else ""
    operations_logger.info(f"SUCCESS | {tool_name} | {result_summary}{time_str}")
    return log_entry

def log_operation_error(tool_name: str, error_message: str, exception_details: str = None, execution_time: float = None):
    """Log failed forensic operation"""
    log_entry = {
        'event': 'operation_error',
        'tool': tool_name,
        'error': error_message,
        'exception': exception_details,
        'execution_time': execution_time,
        'timestamp': datetime.now().isoformat()
    }
    time_str = f" | {execution_time:.3f}s" if execution_time else ""
    operations_logger.error(f"ERROR | {tool_name} | {error_message}{time_str}")
    if exception_details:
        operations_logger.error(f"EXCEPTION | {tool_name} | {exception_details}")
    return log_entry
```
