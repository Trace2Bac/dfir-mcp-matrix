# E03 원본 변경 방지

### E03.01 실행 환경의 읽기 전용 강제

**구현.** 이 방식은 `prepare_disk_image`가 이미지를 마운트하는 세 경로(Arsenal Image Mounter, WSL LVM, WSL apfs-fuse)에 적용된다 [1][2][3].
OS를 `windows`로 판별한 이미지는 `aim_cli --mount --readonly --background --filename=<이미지>`로 Windows 드라이브에 마운트한다 [1].
분석 도구는 그 드라이브 아래 파일을 그대로 읽는다 [4].
LVM2 이미지는 WSL에서 loop 장치로 붙이고 논리 볼륨을 `mount -o ro`로 `/mnt/ubuntu_forensics`에 마운트한다 [2].
파일은 그 마운트에서 `cat`으로 읽는다 [5].
APFS 컨테이너 이미지는 WSL에서 `apfs-fuse <이미지> <마운트 위치>`로 마운트한다 [3].
서버 명령에는 읽기 전용 옵션이 없지만 apfs-fuse는 마운트 옵션에 늘 `ro`를 넣고 쓰기로 여는 요청을 거부하며 이미지를 `O_RDONLY`로 연다 [6].
이 마운트 경로들은 실행 확인에서 실행하지 않았고 코드와 apfs-fuse 소스로만 확인했다.

**한계.** Arsenal Image Mounter는 소스가 공개되어 있지 않아 `--readonly`가 이미지 파일에 쓰기를 막는지는 확인하지 못했다 [1].
WSL LVM 경로는 `losetup -fP --show`에 읽기 전용 옵션을 주지 않아 loop 장치는 쓰기가 되는 상태로 붙고 `vgchange -ay`로 볼륨 그룹을 활성화한다 [2].
이 상태에서 `mount -o ro`가 파일시스템 저널 처리 같은 일로 이미지에 쓰는지는 확인하지 못했다 [2].
Arsenal 마운트가 실패하면 SleuthKit으로 파일을 꺼내는 방식으로 바꾸고 이 장치 없이 진행한다 [7].

### E03.02 서버 코드의 원본 쓰기 제한

**구현.** 이 방식은 서버 코드가 이미지와 증거 파일을 직접 여는 해시 계산, 서명 확인, 파일 읽기 도구에 적용된다 [8][9][10].
`calculate_image_hash`와 파티션 표가 없는 이미지의 서명 확인, LVM 서명 확인은 이미지를 `rb`로 연다 [8][9].
`identify_file_type`·`decompress_mozilla_lz4`·`analyze_macos_plist`는 받은 파일을 `rb`로, `read_text_file`·`read_csv_data`는 `r`로 연다 [10].
`analyze_sqlite_database`는 이미지 안 DB를 사건 폴더의 `extracted_files`로 복사한 뒤 그 사본을 `mode=ro` URI로 연다 [11][12].
서버가 만드는 파일은 설정의 출력 폴더와 임시 폴더 아래에 둔다 [13].
설정 파일의 `read_only_mode: true`를 읽는 코드는 없다 [14].

### E03.03 외부 도구·플랫폼에 위임

**구현.** 이 방식은 SleuthKit, Volatility 3, KAPE와 EZ Tools, chainbreaker, UnifiedLogReader에 이미지와 증거 파일을 넘기는 경로에 적용된다 [15][16].
이 경로에는 서버 코드의 쓰기 차단 장치가 없고 원본 보호는 외부 도구의 동작에 달려 있다.
SleuthKit의 `mmls`·`fsstat`·`fls`·`icat`에는 이미지 경로를 그대로 넘긴다 [15].
SleuthKit 4.14.0은 raw 이미지를 Windows에서 `FILE_READ_DATA`로, 그 밖에서는 `O_RDONLY`로 열고 EWF 이미지는 libewf를 `LIBEWF_OPEN_READ`로 연다 [17].
`analyze_memory`는 메모리 파일 경로를 Volatility 3의 `-f`로 넘긴다 [16].
Volatility 3 2.28.0의 `FileLayer`는 파일을 `rb`로 연다 [18].
Arsenal 드라이브와 로컬 경로의 Windows 아티팩트는 KAPE의 `--msource`나 EvtxECmd·MFTECmd·AmcacheParser·AppCompatCacheParser의 입력으로 원래 위치를 넘긴다 [19][20].
EvtxECmd와 RECmd는 입력 파일을 `FileAccess.Read`의 `FileStream`으로 열어 파싱한다 [21].
chainbreaker는 키체인을 `rb`로 읽고 UnifiedLogReader의 파일 객체는 기본으로 `rb`로 연다 [22].

원본을 지키는 서버 쪽 장치가 없는 다른 경로도 있다.
`analyze_memory`는 경로 대조 없이 받은 경로를 넘긴다 [16].
`analyze_registry`·`analyze_prefetch`·`analyze_mft`·`analyze_shimcache`·`analyze_jump_lists`·`analyze_lnk_files`·`analyze_amcache`는 준비한 이미지 밖의 로컬 경로를 받으면 그 원래 위치를 외부 도구에 넘긴다 [20][23].

**한계.** KAPE는 소스가 공개되어 있지 않아 `--msource` 폴더에 쓰는지는 확인하지 못했다 [19].
SBECmd는 공개 소스를 찾지 못했다.
LECmd·JLECmd·PECmd·MFTECmd는 바로 가기 파일, 점프 목록, Prefetch, `$MFT`를, AmcacheParser·AppCompatCacheParser는 하이브를 별도 라이브러리로 연다 [24][25].
이 라이브러리들은 버전 기준에 포함되지 않아 여는 모드를 확인하지 못했다.
그래서 KAPE와 이 도구들은 실제 보호 미확인이다.
SleuthKit·Volatility 3·apfs-fuse·EvtxECmd·RECmd·chainbreaker·UnifiedLogReader는 버전 기준의 소스에서 읽기 모드로 여는 것을 확인했다 [17][18][6][21][22].
