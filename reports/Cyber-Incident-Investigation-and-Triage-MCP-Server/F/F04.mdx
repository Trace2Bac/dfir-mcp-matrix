# F04 발견사항·결론 기록 관리

### 비적용

**판단.** 서버에는 발견사항, 결론, 가설, 단서 메모를 받아 남기는 도구가 없다.
YAML에서 만드는 도구 9개의 입력은 분석할 경로 `paths`, 모듈 `modules`, 출력 형식 `output_format`뿐이다 [1].
직접 적은 도구 22개의 입력은 증거와 출력의 경로, 깊이, 행 범위, SQL 질의, 플러그인 이름, 해시 값 같은 분석 인자이고 발견사항이나 메모를 받는 인자가 없다 [2].
도구 이름별 처리에도 받은 글을 저장소에 남기는 분기가 없다 [3].

파일을 쓰는 경로는 분석 도구의 출력과 증거에서 고른 자료를 쓴다.

- KAPE·Zimmerman 도구, Volatility 3, UnifiedLogReader의 출력은 사건 폴더 아래 아티팩트별 폴더에 쓰인다 [4].
- `analyze_sqlite_database`의 `query`와 `export_table`은 질의 결과를 CSV로 쓴다 [5].
- `prepare_disk_image`는 준비한 이미지의 정보를 `prepared_images_registry.json`에 쓴다 [6].

서버가 스스로 붙이는 판정 표시는 응답 글이나 서버 로그에만 남는다.

- `analyze_macos_plist`의 지속성 수단 후보 표시는 응답 글에만 실린다 [7].
- `analyze_shimcache`가 센 의심 경로 수는 서버 로그의 진행 줄에만 적힌다 [8].

```python
def save_prepared_images(prepared_images, base_output_dir):
    """Save prepared images registry to disk (excluding non-serializable objects)"""
    registry_file = Path(base_output_dir) / "prepared_images_registry.json"
    
    try:
        serializable_images = {}
        for path, info in prepared_images.items():
            serializable_info = {k: v for k, v in info.items() if k != 'mounter'}
            serializable_images[path] = serializable_info
        
        with open(registry_file, 'w') as f:
            json.dump(serializable_images, f, indent=2)
        logger.info(f"Saved prepared images registry: {len(serializable_images)} images")
    except Exception as e:
        logger.error(f"Failed to save prepared images registry: {e}")
```
