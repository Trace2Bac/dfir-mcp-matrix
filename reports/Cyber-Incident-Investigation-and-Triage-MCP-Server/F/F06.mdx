# F06 보고 산출물 구성

### 미구현

**판단.** 서버는 준비한 이미지마다 사건 폴더를 두고 분석 출력과 실행 기록을 남기지만 보고 산출물을 만들거나 내보내는 도구가 없다.
`prepare_disk_image`는 이미지 이름, 운영체제 종류, 해시 앞부분으로 `unique_image_id`를 만들고 `cases` 아래에 그 이름의 사건 폴더를 만든다 [1].
준비 정보에는 이 폴더가 `case_dir`로 남는다 [1].
분석 도구는 `get_case_output_directory`로 그 사건 폴더 아래 아티팩트와 모듈 이름의 폴더에 출력을 쓴다 [2].
서버는 도구 호출을 서버 로그에, macOS 도구와 `crack_hash`, 이미지 준비의 시작과 끝을 `operations_logs`에, KAPE 명령을 `kape_operations.log`에 적는다 [3][4].

도구 31개 가운데 이 자료를 모아 증거 목록, 수행 범위, 발견사항, 한계를 담은 파일을 만드는 도구는 없다 [5].

- `audit_kape_operations`는 `kape_operations.log`의 항목을 읽어 항목마다 ID, 시각, 종류, 명령 앞부분을 응답 글로 돌려주고 파일을 쓰지 않는다 [6].
- `list_prepared_images`는 준비한 이미지의 해시 `hash`, 파일 시스템, 운영체제 종류, 사건 폴더를 응답 글로 돌려주고 파일을 쓰지 않는다 [7].
- 파일을 쓰는 도구는 `analyze_sqlite_database`의 질의 결과 CSV와 `analyze_memory`의 플러그인 출력처럼 증거에서 고른 자료나 분석 도구의 출력을 쓴다 [8].

README는 보고서 초안을 대화로 쓴다고 적는다 [9].
이 보고서는 클라이언트 모델이 직접 쓰는 글이다.
같은 저장소에는 서버 기록이나 서버 응답을 정해진 코드로 가공해 보고 산출물을 만드는 사용자 CLI나 클라이언트 코드가 없다.
저장소의 두 진입점 `main.py`와 `remote_server.py`는 모두 `create_server`로 서버를 열 뿐이다 [10].
