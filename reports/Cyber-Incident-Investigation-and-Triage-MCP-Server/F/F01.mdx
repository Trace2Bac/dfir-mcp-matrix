# F01 판단 지침

### 미구현

**판단.** 서버는 도구 설명, 서버 지침, 리소스, 응답 어디에도 조사 전체의 해석 원칙이나 발견사항·결론을 서술하고 확인하는 방식을 적지 않는다.
서버는 MCP SDK의 저수준 `Server`를 이름 `forensics`만으로 만들고 서버 지침(`instructions`)을 넘기지 않는다 [1].
등록한 요청 처리기는 `list_tools`와 `call_tool`뿐이어서 리소스와 프롬프트가 없다 [2].
MCP SDK 클라이언트로 stdio 서버를 열자 `initialize` 응답의 `instructions`는 비어 있었고 리소스와 프롬프트 목록 요청은 `Method not found`로 거부되었다 [3].

도구 설명 31개는 도구가 처리하는 아티팩트와 인자를 적는다.

- `server.py`에 직접 적은 22개의 설명은 처리하는 파일 형식, 인자의 뜻, 걸리는 시간을 적는다 [4].
- `config/forensic_tools.yaml`에서 만드는 9개의 설명은 `_generate_tool_from_config`가 `tool_name`, `short_description`, `forensic_value`, `category`, 모듈 목록으로 조립한다 [5].
- `forensic_value`는 아티팩트마다 `CRITICAL`이나 `HIGH`에 한 줄 설명을 붙인 값이다 [6].
- 이 값은 그 아티팩트의 결과가 갖는 증거 가치를 적을 뿐 조사 전체의 해석 원칙, 결론 서술 방식, 확인 절차를 다루지 않는다 [6].

YAML에는 아티팩트 하나의 해석 주의가 있지만 모델에게 가지 않는다.

- `legal_considerations`, `warnings`, `best_practices`, `detailed_description`에는 Prefetch가 실행을 보이지만 사용자 신원을 보이지 않는다는 글처럼 아티팩트별 해석 주의와 다른 아티팩트와 대조하라는 권고가 있다 [7].
- `_generate_tool_from_config`는 `detailed_description`을 변수로 읽지만 설명 글에 넣지 않고 나머지 세 필드는 읽지 않는다 [5].
- 이 필드를 글로 만드는 `get_tool_info_text`와 `get_module_info_text`는 저장소에서 부르는 곳이 없다 [8].
- stdio 서버가 돌려준 도구 설명 31개에 이 필드의 구절이 실리지 않았다 [3].

처리기 4개가 결과에 붙이는 해석 안내도 응답 글에 실리지 않는다.

- `analyze_shimcache`, `analyze_amcache`, `analyze_mft`, `analyze_event_logs`의 처리기는 `_get_forensic_context`가 만든 안내를 결과 `dict`의 `forensic_context`나 `forensic_guidance`에 넣는다 [9].
- 이 안내는 아티팩트마다 분석 순서, 한계, 법정 증거 가치를 적는다 [10].
- 응답 글은 처리 건수와 출력 파일 목록으로만 만들고 이 필드를 읽지 않는다 [11].
- AppCompatCacheParser와 EvtxECmd 자리에 시험용 대체를 두고 두 처리기를 같은 프로세스에서 부르자 응답에 이 안내가 실리지 않았다 [12].

도구와 관계없이 응답에 붙는 문구는 `call_tool`이 모르는 도구 이름이나 예외를 만났을 때 돌려주는 오류 문구뿐이다 [13].
응답에 실리는 다른 안내는 그 도구의 다음 작업이나 결과 하나의 뜻을 다룬다 [14].
