# mcp-velociraptor 원고

이 파일은 서버 개요다. 셀마다 이 폴더 아래 축 폴더의 `<축>/<셀ID>.mdx`에 쓴다.
셀과 상세 항목의 정의는 `matrix/cells/<축>/<셀ID>.mdx`를 따른다.
상세 항목마다 **구현**을 쓰고 그 방식이 적용되지 않는 경로나 조건이 있으면 **한계**를 따로 쓴다.
본문의 [번호]는 그 파일 끝 **근거**의 같은 번호를 가리킨다.

**기준 커밋.** [`1f97a4f`](https://github.com/mgreen27/mcp-velociraptor/tree/1f97a4f4e64d27faf07fe684d8cbfe270b57757d)(2026-06-29).
줄 번호는 모두 이 커밋 기준이다.

**범위.** 저장소 루트의 `mcp_velociraptor_bridge.py`, `velociraptor_api.py`, `velociraptor_env.py` 세 파일을 서버로 본다.
서버는 stdio MCP 서버 하나다.
`mcp_velociraptor_bridge.py`가 MCP Python SDK의 `FastMCP`로 도구 78개를 등록하고, `velociraptor_api.py`가 Velociraptor 서버의 gRPC API에 VQL 질의를 보낸다.
서버는 MCP 리소스와 프롬프트를 두지 않는다.
README는 이 저장소를 POC(개념 증명)라고 적는다.

이 서버는 Velociraptor 서버에 붙어 동작한다.
아티팩트를 단말에서 실행하고, 수집 결과와 파일을 보관하고, hunt를 여러 단말에 배포하는 일은 Velociraptor 서버와 단말의 Velociraptor 클라이언트가 한다.
MCP 서버가 하는 일은 도구 인자로 VQL 문장을 만들어 API로 보내고 돌아온 행을 JSON으로 돌려주는 것이다.
그래서 Velociraptor가 한 수집, 저장, 해시 계산, 권한 확인은 서버 구현으로 세지 않고 원고에 사실로만 적는다.
MCP 서버가 Velociraptor에 무엇을 요청하는지와 돌아온 결과를 어떻게 다루는지는 서버 구현으로 본다.

같은 저장소의 `agent_poc/`는 이 MCP 서버를 하위 프로세스로 실행해 도구를 부르고 모델(Ollama나 Azure OpenAI)로 요약을 만드는 에이전트 예제다.
`agent_poc/`는 MCP 클라이언트이므로 서버 구현으로 세지 않는다.
상세가 클라이언트 쪽 방식을 묻는 경우에만 구현으로 세고, 다른 클라이언트로 붙으면 적용되지 않는다는 점을 그 상세의 구현 단락에 적는다.
`test_api.py`는 API 연결을 손으로 확인하는 스크립트이고 서버 구현으로 세지 않는다.

**확인 방법.** 코드는 기준 커밋을 `git show`로 읽었다.
Velociraptor와 라이브러리의 동작은 아래 버전 기준의 소스로 확인했다.
근거의 "실행 확인"은 WSL Ubuntu에서 기준 커밋을 `git archive`로 푼 소스를 Python 3.12.15로 실행해 본 결과다.
Velociraptor v0.77.1 서버와 같은 기계의 Velociraptor 클라이언트 하나(Linux)를 실행하고, README의 안내대로 `administrator,api` 역할로 만든 API 설정 파일로 MCP 서버를 붙였다.
Windows·macOS 단말은 붙이지 않았다.
확인한 것은 다음과 같다.

- MCP Python SDK 클라이언트 세션(stdio)으로 서버를 실행해 초기화 응답, 도구 목록 78개의 annotation과 `outputSchema`, 리소스·프롬프트 목록, 자료형이 다른 인자와 빠진 필수 인자의 거부, 서버가 실패로 돌려준 응답의 `isError` 값을 확인했다.
- API 설정 파일이 없을 때, 경로가 틀릴 때, 작업 폴더와 홈 폴더에 함께 있을 때, 닫힌 포트를 가리킬 때의 서버 시작과 도구 호출 결과를 확인했다.
- API 설정 파일이 비었을 때, 키가 빠졌을 때, YAML이 아닐 때의 서버 시작을 확인했다.
- `.env`를 읽는 두 경로(`python-dotenv`와 대체 함수)의 차이와 `VELOCIRAPTOR_ENV_FILE`·환경변수 사이의 우선순위를 확인했다.
- `VELOCIRAPTOR_ENV_FILE`에 없는 경로와 상대 경로를 주었을 때의 서버 시작을 확인했다.
- `ENABLE_DANGEROUS_TOOLS`를 끈 채 `run_vql`·`quarantine_host`·`kill_process`를 불러 거부 문구를 확인했다.
- 같은 상태에서 `collect_artifact`로 `Linux.Sys.BashShell`을 요청해 직접 실행한 `sleep` 프로세스가 끝나는 것을 확인했다.
- 같은 상태에서 `collect_artifact`로 `Generic.Client.VQL`을 요청해 넘긴 VQL의 결과 행이 오고 단말이 HTTP 요청을 보내는 것을 확인했다.
- 설정을 켜고 직접 실행한 `sleep` 프로세스의 PID로 `kill_process`를 불러 수집 시작이 실패하고 프로세스가 남는 것을 확인했다.
- 수집 시작 함수를 호출만 적는 함수로 바꿔 `unquarantine_host`와 격리 아티팩트를 준 `collect_artifact`·`hunt_across_fleet`이 설정 확인 없이 시작 함수에 닿는 것을 확인했다.
- 잘못된 `Fields`, 아티팩트 이름, 인자 이름, 중첩 값을 주어 값 검사의 오류 응답을 확인하고 따옴표와 역슬래시가 든 값이 VQL에서 원래 값으로 읽히는지 확인했다.
- `hunt_across_fleet`를 매개변수 없이, 정의에 있는 매개변수로, 정의에 없는 매개변수로, 대소문자만 다른 매개변수로 불러 hunt의 상태를 확인했다.
- `hunt_across_fleet`에 논리값, `null`, list 값을 매개변수로 주어 대조 결과와 응답에 실리는 값을 확인했다.
- 설명이 같은 hunt가 없을 때와 있을 때 `hunt_across_fleet`에 Velociraptor가 받지 않는 `os_filter` 값을 주어 응답과 앞선 hunt의 상태를 확인했다.
- 확인하며 만든 hunt는 모두 멈췄다.
- 도구가 넘기는 아티팩트 이름, 매개변수 이름과 기본값, source 이름, 기본 열 이름을 시험 서버의 아티팩트 정의 437개와 대조했다.
- 같은 조건을 도구와 `collect_artifact`에 주어 도구의 인자 기본값이 결과를 바꾸는지 확인했다.
- Linux 단말에 Linux 도구를 불러 행 수와 열, `Fields`·`limit`·정규식 인자가 결과에 반영되는지 확인했다.
- 결과가 모인 hunt에 `get_hunt_results_tool`을 `limit` 0과 -1, `fields`, 없는 hunt ID로 불렀다.
- 같은 Linux 단말에 Windows·macOS 도구를 불렀을 때의 응답을 확인했다.
- 없는 `client_id`와 정의에 없는 아티팩트로 실시간 수집 도구를 불러 90초 동안 응답이 없고 그 사이 flow가 만들어지지 않는 것을 확인했다.
- 두 번째 단말을 등록했다가 끈 뒤 그 단말로 실시간 수집 도구를 불러 응답이 돌아오지 않는 것을 확인했다.
- stdio 세션에서 응답이 돌아오지 않는 호출 뒤에 다른 도구를 불러 그 호출도 응답이 없는 것을 확인했다.
- `collect_artifact`와 `collect_file`로 flow를 시작해 끝난 flow, 오류로 끝난 flow, 취소한 flow에서 `get_flow_status`와 `get_collection_results`의 응답을 확인했다.
- 한 서버 프로세스에서 시작한 flow의 결과를 새로 실행한 서버 프로세스에서 같은 `flow_id`로 받았다.
- `run_vql`에 없는 플러그인, 문법이 틀린 VQL, `http_client()` 호출을 주어 응답과 Velociraptor 서버가 보내는 요청을 확인했다.
- `VELOCIRAPTOR_DEBUG_VQL`을 켠 서버의 표준 오류와 Velociraptor의 API 로그를 확인했다.
- 시험 파일에 넣은 가짜 비밀 값이 셸 기록 도구의 응답에 실리는지 확인했다.
- 수집 뒤 Velociraptor 데이터 저장소와 `uploads()`에 남는 기록을 확인했다.
- `agent_poc`는 모델 서버 없이 CLI와 `VelociraptorAgent`를 실행해 도구 호출, 결과 파일의 내용과 경로, 자식 서버로 전달되는 환경변수를 확인했다.
- `ollama` 패키지가 없는 환경에서는 모델 호출이 예외를 내는 대체 모듈을 두고 `agent_poc`를 실행했다.
- `agent_poc`를 Linux 단말과 기본 분석 종류 `triage`로 실행해 70초 동안 끝나지 않고 결과 파일이 쓰이지 않는 것을 확인했다.

다음은 실행으로 확인하지 않았다.

- Windows·macOS 아티팩트를 부르는 도구의 단말 쪽 동작
- 격리와 격리 해제
- 시험 서버에 정의가 없는 아티팩트를 부르는 도구의 수집 결과
- 실제 모델을 쓴 `agent_poc`의 요약과 Azure OpenAI 전송
- org가 여러 개인 배치

원고에서 이 부분은 정적 분석 결과다.

**외부 도구 버전 기준.** 저장소는 버전을 정하지 않는다.
`requirements.txt`는 패키지 이름만 적고 잠금 파일이 없으며, Velociraptor 버전도 적지 않는다.
그래서 기준 커밋 날짜(2026-06-29)에 나와 있던 최신 정식 릴리스를 기준으로 한다.

- Velociraptor: v0.77.1(`Velocidex/velociraptor` 태그 `v0.77.1`, `3137c7f`, 2026-06-23)이다.
- MCP Python SDK: `mcp` 1.28.1(2026-06-26)이다. 같은 날 나온 2.0.0a3은 시험판이라 쓰지 않는다.
- Velociraptor API 클라이언트: `pyvelociraptor` 0.1.14(2026-05-05)다.
- Python: 저장소는 버전을 정하지 않는다. 실행 확인 환경인 CPython 3.12.15를 기준으로 한다.
- `grpcio`, `pyyaml`, `python-dotenv`는 실행 확인 환경에 설치된 버전(1.84.0, 6.0.3 등)을 썼고 기준 커밋 날짜의 버전으로 맞추지 않았다.

**바뀔 수 있는 것.** 범위와 외부 도구 버전 기준은 조사하며 맞지 않는 곳이 나오면 검토를 거쳐 바꾼다.
