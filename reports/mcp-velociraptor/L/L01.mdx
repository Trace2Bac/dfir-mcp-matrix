# L01 기록 방식

### L01.04 클라이언트의 MCP 호출 기록

**구현.** 이 방식은 같은 저장소의 MCP 클라이언트인 `agent_poc`로 분석할 때만 적용된다 [1].
다른 MCP 클라이언트로 서버에 붙으면 이 기록은 남지 않는다.
`agent_poc/mcp_agent.py`의 `analyze_endpoint`는 분석이 끝나면 `_save_results`로 결과를 `<hostname>_<analysis_type>_<시각>.json` 파일에 쓴다 [1].
파일을 두는 폴더는 `output_dir`이고 값을 주지 않으면 `agent_poc/output`이다 [2].
이 파일의 `analysts.<역할>.evidence.tool_results`는 분석 역할이 부른 MCP 도구 이름을 키로 쓴다 [3].
도구 이름마다 성공 여부 `ok`, 행 수 `row_count`, 조건에 맞는 행 `highlights`, 앞 3행 `sample_rows`가 남는다 [3][4].
실패한 호출은 `ok`가 `false`인 항목과 `tool_errors`의 도구 이름·오류 메시지로 남는다 [3].
역할마다 허용한 도구 목록 `allowed_tools`와 시작·끝 시각 `started_at`·`completed_at`도 같은 파일에 남는다 [5].
Linux 단말을 대상으로 `process` 분석을 실행하자 결과 파일의 `tool_results`에 `linux_pslist` 항목이 `ok`·`row_count`와 함께 남았다 [6].
`-v`를 주면 분석 역할이 도구를 부를 때마다 진행 문장을 표준 오류에 쓴다 [7].
진행 문장에는 MCP 도구 이름 대신 `TOOL_DISPLAY_NAMES`에 정해 둔 아티팩트 이름이 실린다 [3][8][6].
이 문장은 파일로 남지 않는다 [7].

서버는 도구 호출을 기록하지 않는다.
`mcp_velociraptor_bridge.py`는 `mcp` 로거의 수준을 `WARNING`으로 올려 SDK가 요청마다 쓰는 `INFO` 항목을 끈다 [9][10].
도구 실행 중에 난 예외는 `_run_json_tool`이 `{"ok": false}` 응답으로 바꾸고 로그에는 쓰지 않는다 [11].
서버 코드에서 로거에 항목을 쓰는 곳은 `run_vql_query`의 `logger.debug` 한 곳이다 [12].
이 호출은 `VELOCIRAPTOR_DEBUG_VQL`을 켰을 때만 실행되고 항목에는 Velociraptor에 보내는 VQL 요청이 담긴다 [12].
FastMCP는 만들어질 때 루트 로거를 `INFO` 수준으로 설정하고 서버는 이 수준을 바꾸지 않으므로 `DEBUG` 수준인 이 항목은 출력되지 않는다 [13][14].
README는 `VELOCIRAPTOR_DEBUG_VQL=1`이면 VQL 요청이 표준 오류에 기록된다고 적는다 [15].
`VELOCIRAPTOR_DEBUG_VQL=1`로 서버를 실행해 성공한 호출, 오류 응답이 나온 호출, 인자 형식이 틀린 호출을 보냈을 때 표준 오류에 남은 항목은 없었다 [14].
등록되지 않은 도구 이름을 부른 호출에만 SDK가 그 이름을 담은 경고 한 줄을 표준 오류에 썼다 [10][14].

Velociraptor 서버는 받은 API 질의를 자기 로그에 남긴다 [16].
이 로그는 Velociraptor의 기록이며 항목에 MCP 도구 이름은 없다 [16].

**한계.** 결과 파일에는 도구에 넘긴 인자와 호출마다의 시각이 없다 [3][5].
대상 단말을 찾으려고 부르는 `client_info` 호출은 결과 파일에 도구 이름으로 남지 않는다 [6][17].
`agent_poc`는 요약을 요청할 때 모델에 도구 정의를 주지 않는다 [18].
그래도 모델 응답에 도구 호출이 들어 있으면 `_chat_ollama`와 `_chat_azure_openai`는 그 도구를 `call_tool`로 부르고 결과를 대화 기록에만 넣는다 [18].
이렇게 부른 도구는 결과 파일에 남지 않는다 [18][3].
이 경로는 코드로만 확인했다.

결과 파일은 분석 종류에 속한 역할이 모두 끝난 뒤에 쓰이므로 응답이 돌아오지 않는 도구를 부른 역할이 있으면 그 분석에서 부른 도구는 하나도 기록되지 않는다 [1][19].
Linux 단말을 대상으로 기본 분석 종류 `triage`를 실행하자 `linux_pslist`와 `linux_netstat_enriched`가 행을 돌려준 뒤 `linux_arp_cache`의 응답이 70초 동안 오지 않았고 결과 파일은 쓰이지 않았다 [20].
`linux_arp_cache`가 요청하는 `Linux.Network.ArpCache`는 Velociraptor v0.77.1 시험 서버에 정의가 없다 [20].

`call_tool_payload`는 MCP 결과의 `isError`를 읽지 않고 `_decode_tool_payload`는 JSON으로 읽히지 않는 응답 글을 `ok`가 `true`인 값으로 바꾼다 [21].
`_collect_role_evidence`는 이 값을 받으면 그 호출을 `ok`가 `true`이고 `row_count`가 0인 항목으로 적는다 [3][4][22].
`client_id` 없이 부른 `linux_pslist`와 등록되지 않은 도구 이름을 `call_tool_payload`로 부르자 둘 다 `ok`가 `true`이고 `data`가 오류 문구인 값이 돌아왔다 [23].
역할 표에 정해 둔 인자로 부른 호출이 MCP 오류 결과로 끝나는 경우는 실행으로 확인하지 못했다.

`agent_poc/README.md`는 `VELOCIRAPTOR_AGENT_VERBOSE=1`이면 `-v` 없이도 진행 문장이 나온다고 적는다 [24].
`VelociraptorMCPClient`는 `verbose`를 받지 않았을 때만 이 환경변수의 값을 쓰고 CLI는 `-v`의 값을 늘 `verbose`로 넘긴다 [25].
`_emit_verbose_progress`도 `VelociraptorAgent`의 `verbose`만 확인하므로 CLI에서 이 환경변수는 진행 문장을 켜지 않는다 [7][25].
`VELOCIRAPTOR_AGENT_VERBOSE=1`을 주고 `VelociraptorAgent`를 만들자 `VelociraptorAgent`와 그 클라이언트의 `verbose`는 모두 `False`였다 [26].

```python
def run_vql_query(vql: str, org_id: str | None = None):
    if stub is None:
        raise RuntimeError("Stub not initialized. Call init_stub() first.")
    request = api_pb2.VQLCollectorArgs(Query=[api_pb2.VQLRequest(VQL=vql)])
    resolved_org_id = resolve_org_id(org_id)
    if resolved_org_id:
        request.org_id = resolved_org_id
    results = []
    if DEBUG_VQL:
        logger.debug("VQL request: %s", request)
    
    for resp in stub.Query(request):
        if hasattr(resp, "error") and resp.error:
            raise RuntimeError(f"Velociraptor API error: {resp.error}")
        if hasattr(resp, "Response") and resp.Response:
            results.extend(json.loads(resp.Response))
    return results
```

```python
    async def call_tool_payload(self, tool_name: str, arguments: dict) -> dict:
        """Execute a tool via MCP and return the structured bridge payload."""
        try:
            result = await self.session.call_tool(tool_name, arguments)
            if result.content:
                raw_text = "\n".join(
                    item.text if hasattr(item, "text") else str(item)
                    for item in result.content
                )
                return self._decode_tool_payload(raw_text)
            return {"ok": True, "data": str(result)}
        except Exception as e:
            return {"ok": False, "error": f"Error calling tool {tool_name}: {str(e)}"}
```
