# P05 사건 자료 정리

### 비적용

**판단.** 서버는 사건 자료를 파일, DB, 메모리 어디에도 남기지 않는다.
서버 코드에는 파일이나 DB에 쓰는 코드가 없다 [1].
서버 코드가 여는 파일은 `.env`와 API 설정 파일이고 둘 다 읽기만 한다 [2][3].
프로세스 메모리에 두는 값은 Velociraptor API 연결 객체 `stub`과 시작할 때 환경변수에서 읽은 `DEFAULT_ORG_ID`, `DEBUG_VQL`, `ENABLE_DANGEROUS_TOOLS`다 [4][5].
이 값은 연결과 설정이고 증거, 호출 기록, 파생물, 조사 상태를 담지 않는다 [4][5].
서버는 도구 호출의 인자와 결과를 쌓아 두지 않고 응답을 돌려준 뒤 버린다 [6].
`DEBUG_VQL`이 켜져 있으면 요청을 `logger.debug`로 넘기지만 서버 코드에는 이 기록을 파일에 쓰는 설정이 없다 [7].

flow, hunt, 수집 결과는 Velociraptor 서버가 자기 저장소에 보관한다 [8].
서버에는 flow, hunt, 수집 결과를 지우는 도구가 없다 [9].
서버가 hunt를 멈추는 요청은 `hunt_across_fleet`의 매개변수 대조가 실패했을 때 보내는 `hunt_update`의 `stop=TRUE` 하나이고 이 요청은 hunt를 지우지 않는다 [10].
`run_vql`은 `ENABLE_DANGEROUS_TOOLS`가 켜져 있으면 받은 VQL을 검사 없이 Velociraptor에 보낸다 [11].
이 경로로 Velociraptor의 기록을 지우는 VQL을 보내는 것은 실행으로 확인하지 않았다.

같은 저장소의 MCP 클라이언트 예제 `agent_poc/`는 분석 결과 JSON을 출력 폴더에 쓴다 [12].
이 파일은 클라이언트가 남기는 것이고 `agent_poc/`의 코드에도 그 파일을 지우는 코드는 없다 [12].
