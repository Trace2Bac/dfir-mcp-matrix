# P01 분석 방법 적합성 확인

### 미구현

**판단.** 서버는 단말의 OS나 증거 형식을 판별하지 않고 호출자가 고른 도구와 `client_id`를 대조 없이 Velociraptor에 넘긴다 [1][2].
도구는 이름이 `linux_`·`macos_`·`windows_`로 시작하는 묶음으로 나뉘고 도구마다 요청할 아티팩트 이름이 코드에 고정되어 있다 [3].
이 도구들은 `client_id`가 가리키는 단말의 OS를 조회하지 않고 `collect_client` 요청 VQL을 만든다 [1][2].
`yara_scan_files`, `yara_scan_process`, `quarantine_host`, `unquarantine_host`, `collect_forensic_triage`는 이름에 OS가 없지만 `Windows.`로 시작하는 아티팩트를 요청하고 Windows용이라는 사실은 도구 설명에만 적혀 있다 [4].
`client_info`와 `list_clients`가 돌려주는 `OSType`은 Velociraptor가 단말 기록에 둔 `os_info.system` 값이다 [5].
서버는 이 값을 응답에 실을 뿐 다른 도구의 실행 조건으로 쓰지 않는다 [1][5].
`list_clients`의 `os_filter`는 받은 문자열을 `os_info.system`에 대한 정규식 조건으로 넘기고 `hunt_across_fleet`의 `os_filter`는 Velociraptor `hunt()`의 `os` 인자로 넘긴다 [6].
두 인자는 호출자가 준 값이고 서버는 그 값을 요청할 아티팩트와 대조하지 않는다 [6].
`collect_artifact`와 `hunt_across_fleet`는 아티팩트 이름의 문자 종류만 검사하고 받은 이름대로 요청한다 [7].
`list_windows_artifacts`·`list_linux_artifacts`·`list_macos_artifacts`는 이름이 `windows.`·`linux.`·`macos.`에 맞는 아티팩트를 골라 이름, 줄인 설명, 매개변수 이름을 돌려준다 [8].
이 목록 도구는 단말을 인자로 받지 않고 아티팩트 정의의 precondition을 응답에 싣지 않는다 [8].
`macos_browser_history`는 `URLRegex`가 기본값이 아니면 요청할 아티팩트에 `URLRegex` 매개변수가 없다는 오류를 돌려준다 [9].
이 검사는 인자 값을 코드에 적어 둔 기본값과 비교할 뿐 Velociraptor의 아티팩트 정의나 단말의 OS를 조회하지 않는다 [9].

아티팩트가 단말의 OS에 맞는지는 Velociraptor가 아티팩트 정의의 precondition으로 판단한다 [10].
Velociraptor v0.77.1의 `Windows.System.Pslist`는 `OS = 'windows'`를 precondition으로 둔다 [10].
Linux 단말에 `windows_pslist`를 부르면 서버는 `ok`가 참이고 `data`가 빈 목록인 응답을 돌려준다 [11].
같은 단말에 `collect_artifact`로 `Windows.System.Pslist`를 요청하면 flow가 시작되고 flow 기록에는 precondition 때문에 질의를 건너뛰었다는 문구가 남는다 [12].
서버는 flow 기록의 이 문구를 읽지 않으므로 응답만으로는 OS가 맞지 않아 실행되지 않은 경우와 맞는 항목이 없는 경우를 구별할 수 없다 [2][11].
`macos_pslist`가 요청하는 `MacOS.Sys.Pslist`는 `Linux.Sys.Pslist`의 다른 이름이고 precondition이 `linux|darwin`이다 [3][13].
그래서 Linux 단말에 `macos_pslist`를 부르면 그 단말의 프로세스 목록이 돌아온다 [14].
Windows 단말과 macOS 단말에 요청했을 때의 동작은 실행으로 확인하지 않았다.

같은 저장소의 MCP 클라이언트 예제 `agent_poc/`는 `client_info` 응답의 `OSType`으로 단말의 OS를 정하고 그 OS의 역할 표에 적힌 도구만 부른다 [15][16].
`OSType`이 `win`·`lin`·`mac`으로 시작하거나 `darwin`·`osx`이면 각각 `windows`·`linux`·`macos`로 정한다 [15].
그 OS의 표에 없는 역할은 실행하지 않고 결과의 `skipped`에 `not_applicable`로 적는다 [16].
이 선택은 클라이언트 코드가 하므로 다른 MCP 클라이언트로 붙으면 적용되지 않고 서버는 어느 클라이언트에서 온 호출이든 OS를 대조하지 않는다 [1][16].

```python
def normalize_artifact_name(artifact: str) -> str:
    cleaned = artifact.strip()
    if not cleaned or not VALID_ARTIFACT_RE.fullmatch(cleaned):
        raise ValueError(f"Invalid artifact name: {artifact!r}")
    return cleaned
```

```python
def _summarize_artifacts(
    scope_regex: str,
    org_id: str = "",
    include_parameter_details: bool = False,
    name_regex: str = ".",
) -> list[dict]:
    parameter_projection = "*" if include_parameter_details else "name"
    vql = f"""
    LET params(data) = SELECT {parameter_projection} FROM data
    SELECT name, description, params(data=parameters) AS parameters
    FROM artifact_definitions()
    WHERE type =~ 'client'
      AND name =~ {vql_literal(scope_regex)}
      AND name =~ {vql_literal(name_regex or ".")}
    ORDER BY name
    """
```
