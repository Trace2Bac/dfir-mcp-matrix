# P02 다음 작업 결정

### P02.02 규칙·조사 상태로 추천

**구현.** 이 방식은 `run_vql`·`quarantine_host`·`kill_process`의 거부 응답과 `macos_browser_history`의 인자 오류 응답에 적용된다 [1][2][3].
`ENABLE_DANGEROUS_TOOLS`가 켜져 있지 않으면 세 도구는 Velociraptor에 요청하지 않고 `ENABLE_DANGEROUS_TOOLS=true`로 설정하라는 문구를 오류로 돌려준다 [1][2][4].
이 값은 서버가 시작할 때 환경변수에서 한 번 읽으므로 사용자가 환경변수를 바꾸고 서버를 다시 시작해야 도구가 실행된다 [1].
`macos_browser_history`는 `URLRegex`가 기본값이 아니면 실행하지 않고 걸러 내려면 `urlSQLQuery`를 쓰라는 문구를 돌려준다 [3].
두 문구는 응답의 `error` 문자열이고 서버는 다음 호출을 대신 고르지 않는다 [1][3].

그 밖의 응답은 다음에 부를 도구를 싣지 않는다.
`collect_artifact`처럼 flow를 시작만 하는 도구는 `flow_id`와 요청 내용을 돌려주고 `get_collection_results`를 부르라는 문구를 싣지 않는다 [5].
`get_collection_results`는 정한 횟수 안에 flow가 끝나지 않으면 결과가 없거나 flow가 끝나지 않았다는 문구만 돌려준다 [6].
`client_info`는 단말을 찾지 못하면 `Client not found`와 받은 호스트 이름만 돌려준다 [7].
API 설정 파일을 찾지 못하면 서버는 MCP 세션을 열기 전에 `FileNotFoundError`로 끝난다 [8][9].
그래서 `VELOCIRAPTOR_API_CONFIG`를 설정하라는 문구는 표준 오류에만 나오고 도구 응답으로 전달되지 않는다 [8][9].

서버는 절차서나 조사 프로필을 돌려주는 도구를 두지 않고 서버 지침, MCP 리소스, MCP 프롬프트도 두지 않는다 [10][11].
도구 설명 세 곳이 다른 호출을 가리킨다.
`client_info`의 설명은 응답의 `client_id`를 다른 아티팩트 수집에 쓸 수 있다고 적는다 [12].
`get_collection_results`의 설명은 `flow_id`가 앞선 수집이 돌려준 값이라고 적는다 [13].
`windows_ntfs_mft`의 설명은 실패하면 `collect_artifact`로 다시 시도하라고 적는다 [14].
세 문장은 그 도구의 설명에만 있고 서버는 이를 절차로 묶어 돌려주지 않는다 [12][13][14].
`list_windows_artifacts`의 도구 설명은 NTFS 질의에서 파일 이름 정규식 매개변수와 경로 glob을 쓰라고 적는다 [15].
도구 설명에는 클라이언트 문맥이 압축되거나 끊긴 뒤 상태를 다시 읽으라는 안내가 없다.

`list_windows_artifacts`·`list_linux_artifacts`·`list_macos_artifacts`는 Velociraptor에 등록된 아티팩트의 목록을 돌려준다 [16][17].
서버는 Velociraptor의 `artifact_definitions()`에서 `type`이 `client`에 맞고 이름이 도구마다 정한 OS 정규식에 맞는 아티팩트를 이름순으로 조회한다 [16][17].
응답 항목은 `name`, `short_description`, `parameters` 세 필드다 [18].
목록의 내용은 서버 코드에 적은 값이 아니라 연결한 Velociraptor 서버의 아티팩트 정의이므로 그 서버에 등록된 아티팩트에 따라 달라진다 [17].
Velociraptor v0.77.1의 기본 정의에서는 Windows 199개, Linux 52개, macOS 22개가 돌아온다 [19].
서버는 목록을 만들 때 단말이나 앞선 호출을 보지 않고 항목에 차례나 권고를 붙이지 않는다 [17][18].
이름이 `Generic.`이나 `Admin.`으로 시작하는 아티팩트처럼 OS 이름으로 시작하지 않는 아티팩트는 세 도구 어느 것에도 실리지 않는다 [16][20].
`collect_file`이 요청하는 `Generic.Collectors.File`이 그 예다 [20][21].

같은 저장소의 MCP 클라이언트 예제 `agent_poc/`는 조사 절차를 클라이언트 코드에 둔다 [22][23].
`agent_poc/`는 `triage`·`engagement`·`deep` 프로필마다 역할 목록을 두고 역할마다 부를 도구와 인자를 OS별 표에 적는다 [22].
클라이언트 코드는 표의 도구를 차례로 부른 뒤 모은 결과를 모델에 넘겨 요약하게 한다 [23].
이 절차는 클라이언트 코드가 정하므로 다른 MCP 클라이언트로 붙으면 적용되지 않고 서버 응답에도 실리지 않는다 [22][23].

**한계.** `kill_process`는 거부 문구대로 `ENABLE_DANGEROUS_TOOLS`를 켜도 Velociraptor v0.77.1 시험 서버에서는 `Failed to start collection: []`를 돌려준다 [24].
이 서버에는 `kill_process`가 요청하는 `Generic.Utils.KillProcess` 정의가 없고 이 오류 문구는 그 원인이나 다음에 할 일을 싣지 않는다 [24][5].

```python
def _summarize_artifacts(
    scope_regex: str,
    org_id: str = "",
    include_parameter_details: bool = False,
    name_regex: str = ".",
) -> list[dict]:
    parameter_projection = "*" if include_parameter_details else "name"
    vql = f"""
    LET params(data) = SELECT {parameter_projection} FROM data
    SELECT name, description, params(data=parameters) AS parameters
    FROM artifact_definitions()
    WHERE type =~ 'client'
      AND name =~ {vql_literal(scope_regex)}
      AND name =~ {vql_literal(name_regex or ".")}
    ORDER BY name
    """
```
