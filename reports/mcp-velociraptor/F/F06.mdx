# F06 보고 산출물 구성

### F06.02 수행·누락 범위 포함

**구현.** 이 방식은 사용자가 같은 저장소의 CLI `agent_poc/mcp_agent.py`를 실행할 때 쓰이는 결과 파일에 적용된다 [1].
MCP 도구에는 보고 산출물을 만드는 도구가 없고 다른 MCP 클라이언트로 서버에 붙으면 이 파일은 만들어지지 않는다.
CLI는 서버를 하위 프로세스로 실행하고 `client_info`로 호스트 이름에 맞는 `client_id`와 운영체제를 얻는다 [2][3].
그 뒤 분석 종류에 속한 역할마다 정해 둔 도구를 차례로 부른다 [4].
어느 도구를 어떤 인자로 부를지는 운영체제와 역할별 표 `WINDOWS_TOOL_REQUESTS`·`LINUX_TOOL_REQUESTS`·`MACOS_TOOL_REQUESTS`에 정해져 있고 모델이 고르지 않는다 [5][4].
결과 파일의 맨 위에는 분석 종류 `workflow`, 대상 `hostname`·`client_id`·`org_id`·`os_type`, 시작·종료 시각과 걸린 시간이 실린다 [6].
`analysts` 아래에는 역할마다 그 역할에 정해 둔 도구 이름 `allowed_tools`, 상태, 시작·종료 시각, 증거 묶음 `evidence`가 실린다 [6].
증거 묶음은 부른 도구마다 성공 여부 `ok`, 행 수 `row_count`, 조건으로 고른 행 `highlights`, 앞에서부터 3행 `sample_rows`를 담는다 [7].
실패한 도구는 오류 문구와 함께 `tool_results`와 `tool_errors`에 실린다 [4].
대상 운영체제에 정해 둔 도구가 없는 역할은 이유와 함께 `skipped`에 실리고 실패한 역할은 `errors`에 실린다 [8][9].
`highlights`는 `_highlight_row`가 역할마다 정한 조건에 맞는 행을 8개까지 고른 것이다 [7][10].
조건은 경로나 명령줄에 `SUSPICIOUS_KEYWORDS`의 낱말이 있는지, 경로가 `USER_WRITABLE_SEGMENTS`의 위치인지, 서명 상태가 `untrusted`·`unsigned`·`error`인지, 사설 대역 밖 주소와 `ESTABLISHED` 상태로 이어져 있는지 같은 것이다 [10][11].
역할별 `summary`는 CLI가 증거 묶음을 넘겨 부른 모델이 쓴 글이고 CLI는 이 글을 고치지 않고 싣는다 [12].
`manager_summary`는 여러 역할을 묶은 분석 종류에서는 CLI가 상태가 `completed`인 역할의 요약과 `skipped`·`errors`를 넘겨 부른 모델이 쓴 글이고 역할 하나만 실행하는 분석 종류에서는 그 역할의 요약을 옮긴 글이다 [12].
상태가 `completed`인 역할이 없으면 `manager_summary`에는 고정 문장 `No completed analyst findings were produced.`가 실린다 [12][13].
모델 호출이 실패한 역할의 `summary`에는 도구별 행 수와 고른 행 수를 적은 고정 형식의 글이 실린다 [14].
Ollama 서버가 없는 환경에서 Linux 단말을 대상으로 `process` 분석을 실행하자 역할 상태는 `error`였고 결과 파일에는 `linux_pslist`의 증거 묶음과 고정 형식의 글이 실렸다 [13].
`SUSPICIOUS_KEYWORDS`는 부분 문자열로 대조하므로 `tor`는 `velociraptor`에도 맞는다 [11].
이 실행에서 고른 8행 가운데 3행은 이름이 `velociraptor`인 프로세스였다 [13].

결과 파일에는 발견사항을 항목으로 나눈 칸이 없고 요약 글을 증거 묶음의 행과 잇는 식별자도 없다 [6].
모델 이름, 모델 제공자, 서버와 Velociraptor의 버전은 결과 파일에 실리지 않는다 [6].
CLI에는 수집한 행이나 모델이 쓴 요약을 검증하는 단계가 없어 결과 파일에 검증 결과가 실리지 않는다 [4][12].

**한계.** 결과 파일에는 도구가 돌려준 행 전체가 실리지 않는다.
도구마다 앞 3행과 고른 행 8개까지만 실리고 나머지는 `row_count`의 수로만 남는다 [7].
CLI는 행을 실을 때 빈 값을 지우고 `list`를 앞 5개까지만 남기며 줄였다는 표시를 하지 않는다 [15].
도구를 부를 때 넘긴 인자와 Velociraptor의 `flow_id`는 결과 파일에 실리지 않는다 [4][7].
서버의 실시간 수집 도구는 응답에 `flow_id`를 싣지 않으므로 결과 파일의 행을 Velociraptor의 수집 기록과 잇는 값이 없다 [16].
`skipped`에는 대상 운영체제에 정해 둔 도구가 없는 역할만 실린다 [8].
분석 종류에 속하지 않아 부르지 않은 역할과 표에 없어 부르지 않은 서버 도구는 결과 파일에 적히지 않는다 [8][5].
`call_tool_payload`는 MCP 결과의 `isError`를 읽지 않아 FastMCP가 만든 오류 결과를 받은 호출은 증거 묶음에 `ok`가 `true`이고 `row_count`가 0인 항목으로 실린다 [17][4].
이 경우는 코드로만 확인했다.

### F06.05 내보내기

**구현.** 이 방식은 사용자가 같은 저장소의 CLI `agent_poc/mcp_agent.py`를 실행할 때 `_save_results`가 쓰는 JSON 파일에 적용된다 [1].
MCP 도구에는 파일을 내보내는 도구가 없고 다른 MCP 클라이언트로 서버에 붙으면 이 파일은 쓰이지 않는다.
`analyze_endpoint`는 분석이 끝나면 결과를 `<output_dir>/<hostname>_<analysis_type>_<시각>.json`으로 쓰고 그 경로를 표준 출력에 적는다 [1][18].
`output_dir`의 기본값은 `agent_poc/output`이다 [19].
파일 이름의 시각은 CLI를 실행한 컴퓨터의 지역 시각을 초 단위로 적은 값이다 [1].
파일 안의 `started_at`과 `completed_at`은 UTC 시각이다 [20].
분석 종류를 `full`로 주면 파일 이름에는 `full`이 실리고 파일 안의 `workflow`에는 `engagement`가 실린다 [18].
CLI는 같은 결과를 표준 출력에도 JSON이나 `--output-type text`의 글로 내고 파일은 이 선택과 관계없이 JSON으로 쓴다 [21].
모델 호출이 실패해도 CLI는 그때까지 모은 증거 묶음을 담아 파일을 쓴다 [13].
호스트 이름에 맞는 단말을 찾지 못한 때에도 오류 항목만 담은 파일을 쓴다 [22][18].

**한계.** `_save_results`는 예외 처리 없이 파일을 쓴다 [1].
쓰기가 실패하면 `analyze_endpoint`가 예외로 끝나고 CLI는 모은 결과를 표준 출력에도 내지 않는다 [18][21].
파일 이름에는 `hostname` 인자가 검사 없이 들어간다 [1].
`../../zz`를 호스트 이름으로 주고 실행하자 결과 파일은 `output_dir` 밖인 저장소 루트에 `zz_triage_<시각>.json`으로 쓰였다 [23].
`VelociraptorMCPClient.connect`는 서버를 `env=None`으로 실행한다 [2].
MCP Python SDK 1.28.1은 이때 `HOME`·`PATH`처럼 정해 둔 환경변수만 하위 프로세스에 넘긴다 [24].
그래서 셸에서 내보낸 `VELOCIRAPTOR_API_CONFIG`는 서버에 전달되지 않는다 [2][24].
`agent_poc/README.md`의 사용법대로 이 변수를 내보내고 실행하자 서버가 API 설정 파일을 찾지 못해 CLI는 `Connection closed` 오류로 끝났고 결과 파일은 쓰이지 않았다 [25][26].
저장소 루트의 `.env`에 같은 값을 두자 CLI가 실행되었다 [26].

결과 파일은 분석 종류에 속한 역할이 모두 끝난 뒤에 한 번 쓰이고 CLI는 도구 호출에 시간 제한을 두지 않는다 [17][18][27].
역할 표의 도구 가운데 11개는 Velociraptor v0.77.1 시험 서버에 정의가 없는 아티팩트를 요청한다 [5][28].
서버의 실시간 수집 도구는 수집이 시작되지 않아도 완료 알림을 시간 제한 없이 기다리므로 이 도구를 부른 역할은 끝나지 않는다 [16][29].
그래서 그 역할이 속한 분석에서는 먼저 끝난 역할의 증거 묶음도 파일로 쓰이지 않는다 [27][29].
Linux 단말의 역할 표에서는 `network` 역할의 `linux_arp_cache`와 `persistence` 역할의 `linux_ssh_authorized_keys`가 이런 도구다 [5][28].
CLI의 기본 분석 종류 `triage`에는 `network` 역할이 속한다 [5][30].
Linux 단말을 대상으로 `triage`를 실행하자 `process` 역할이 77행을 모은 뒤에도 70초 동안 분석이 끝나지 않았고 결과 파일은 쓰이지 않았다 [29].
Windows와 macOS 단말의 역할은 실행으로 확인하지 않았다.

        """Resolve hostname to client metadata deterministically via the MCP tool."""
        payload = await self.client.call_tool_payload("client_info", {"hostname": hostname})
        if payload.get("ok") and payload.get("data"):

def _simplify_value(value: Any) -> Any:
    if value in (None, "", [], {}):
        return None
    if isinstance(value, dict):
        simplified = {
            key: _simplify_value(nested_value)
            for key, nested_value in value.items()
        }
        return {key: nested for key, nested in simplified.items() if nested is not None}
    if isinstance(value, list):
        simplified_list = [_simplify_value(item) for item in value[:5]]
        return [item for item in simplified_list if item is not None]
    return value


def _compact_row(row: Any) -> Any:
    if not isinstance(row, dict):
        return row
    simplified = {
        key: _simplify_value(value)
        for key, value in row.items()
    }
    return {key: value for key, value in simplified.items() if value is not None}
