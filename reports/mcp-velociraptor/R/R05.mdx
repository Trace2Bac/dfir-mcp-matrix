# R05 결과 출처 표시

### R05.01 증거·파일 ID

**구현.** 이 방식은 hunt 결과를 읽는 `get_hunt_results_tool`의 응답에 적용된다 [1][2].
`get_hunt_results`는 `hunt_results()`에서 `fields`의 열을 고르는 질의를 만들고 `fields`의 기본값은 `*`다 [1].
Velociraptor의 `hunt_results()`는 결과 행마다 그 행을 낸 단말의 `ClientId`·`Fqdn`, 수집의 `FlowId`, `_OrgId`를 더해 돌려준다 [3].
서버는 이 열을 만들거나 고르지 않고 `*`로 온 행을 그대로 싣는다 [1][4].
`Linux.Sys.Users`로 hunt를 만들고 결과를 읽자 행마다 `ClientId`·`FlowId`·`Fqdn`·`_OrgId`가 아티팩트의 열과 함께 실렸다 [2].
`list_clients`는 `search`를 `client_id`에도 대조하므로 모델은 이 `ClientId`로 단말의 호스트 이름과 주소를 조회할 수 있다 [5].

다음 응답에는 결과 행이 나온 단말이나 수집을 가리키는 값이 없다.
실시간 수집 도구 62개의 응답은 행 목록만 싣고 단말의 `client_id`, 아티팩트 이름, flow ID를 싣지 않는다 [6][4].
`realtime_collection`의 질의는 `collect_client`가 돌려준 `flow_id`를 결과를 읽는 데만 쓰고 결과 열로 고르지 않는다 [6].
`linux_pslist`를 부르자 응답의 행에는 `Pid`·`Name`·`CommandLine` 같은 아티팩트의 열만 있었다 [7].
`get_collection_results`의 응답도 행 목록만 싣는다 [8][9].
이 도구에서 단말, flow, 아티팩트는 모델이 호출 인자로 준 값이다 [8].
`hunt_across_fleet`의 응답은 만든 hunt의 `hunt_id`와 요청한 아티팩트 이름 목록 `artifacts`를 싣는다 [10].
`collect_artifact`·`collect_file`·`collect_forensic_triage`·`unquarantine_host`·`quarantine_host`·`kill_process`는 수집을 시작만 하고 응답에 `flow_id`와 `artifacts`를 싣는다 [11][12].
이 두 종류의 응답에는 단말에서 나온 결과 행이 없다 [10][11].

**한계.** 모델이 `fields`에 열 이름을 주면 그 열만 실리므로 `ClientId`·`FlowId`·`Fqdn`은 `fields`에 넣을 때만 남는다 [13][2].

### R05.02 증거 내부 경로

**구현.** 이 방식은 아티팩트가 단말의 파일 경로 열을 내는 수집 결과에 적용된다 [6][14].
서버는 `Fields`가 `*`이면 아티팩트가 낸 열을 모두 싣고 경로 열의 값을 바꾸지 않는다 [6][4].
`linux_bash_history`의 행은 기록 한 줄 `Line`과 그 줄을 읽은 파일의 단말 안 경로 `OSPath`를 싣는다 [14].
`linux_file_finder`의 행은 찾은 파일의 경로 `OSPath`를 싣는다 [15].
`windows_scheduled_tasks`는 기본 `Fields`에 작업 파일의 경로 `OSPath`를 넣는다 [16][17].
Windows와 macOS 도구의 결과는 단말이 없어 실행으로 확인하지 않았다.

**한계.** 서버가 기본 `Fields`를 열 이름 목록으로 정한 도구 가운데 경로 열을 넣지 않은 도구가 있다 [18].
`windows_event_logs`·`windows_event_log_cleared`·`windows_powershell_scriptblock`이 부르는 `Windows.EventLogs.EvtxHunter`는 사건마다 EVTX 파일의 경로 `OSPath`를 내지만 세 도구의 기본 `Fields`에는 이 열이 없다 [18][19].
`windows_browser_history`가 부르는 `Windows.Applications.Chrome.History`도 기록 DB의 경로 `OSPath`를 내지만 기본 `Fields`에는 이 열이 없다 [18][20].
`windows_usn_journal`의 기본 `Fields`는 경로 열로 `FullPath`를 적는다 [21].
Velociraptor v0.77.1의 `Windows.Forensics.Usn`은 경로를 `OSPath` 열로 내고 `FullPath` 열을 내지 않는다 [22].
`windows_shellbags`의 기본 `Fields`에 있는 `_OSPath`와 `windows_execution_amcache`의 기본 `Fields`에 있는 `FullPath`도 v0.77.1 정의가 내지 않는 이름이다 [23].
결과에 없는 열 이름을 `Fields`에 주면 그 열은 `null`로 실린다 [24].

### R05.03 레코드 키·번호

**구현.** 이 방식은 아티팩트가 레코드 키 열을 내는 Windows 수집 결과에 적용된다 [21][25][26].
`windows_usn_journal`은 기본 `Fields`에 USN 번호 `Usn`을 넣는다 [21][22].
`windows_mountpoints2`는 기본 `Fields`에 하이브 경로 `Hive`와 레지스트리 키 경로 `Key`를 넣는다 [25][27].
`windows_shellbags`는 기본 `Fields`에 `Hive`와 키 경로 `KeyPath`를 넣는다 [25][28].
`windows_ntfs_mft`와 `windows_ntfs_mft_search`는 `Fields`의 기본값이 `*`여서 `Windows.NTFS.MFT`가 내는 MFT 항목 번호 `EntryNumber`가 실린다 [26][29].
이 값은 Velociraptor 아티팩트가 낸 열이고 서버가 만든 값이 아니다 [6].
이 도구들은 Windows 단말이 없어 실행으로 확인하지 않았다.

**한계.** `Windows.EventLogs.EvtxHunter`는 사건마다 이벤트 레코드 번호 `EventRecordID`를 내지만 이 아티팩트를 부르는 세 도구의 기본 `Fields`에는 이 열이 없다 [18][19].
`linux_file_finder`의 행에는 `Inode` 열이 있지만 Linux 단말에서 그 값은 `null`이었다 [15].

### R05.04 바이트·섹터·행 오프셋

**구현.** 이 방식은 `yara_scan_files`와 `windows_powershell_history`의 결과에 적용된다 [30].
두 도구는 `Fields`의 기본값이 `*`여서 아티팩트가 낸 위치 열이 그대로 실린다 [30][6].
`yara_scan_files`가 부르는 `Windows.Detection.Yara.NTFS`는 일치한 문자열의 파일 안 오프셋을 `HitOffset` 열로 낸다 [31].
`windows_powershell_history`가 부르는 `Windows.System.Powershell.PSReadline`은 기록 파일에서 읽은 줄의 차례를 `LineNum` 열로 낸다 [32].
두 도구는 Windows 단말이 없어 실행으로 확인하지 않았다.

Linux 단말의 셸 기록과 파일 검색 결과에는 위치 열이 없다 [14][15].
`linux_bash_history`의 행은 `Line`과 `OSPath`뿐이고 줄 번호가 없다 [14].
`linux_file_finder`에 YARA 규칙을 주면 행에 일치한 문자열 `Keywords`가 실리고 오프셋은 실리지 않는다 [15].

```python
def realtime_collection(
    client_id: str,
    artifact: str,
    parameters: Mapping[str, ParameterValue] | None = None,
    fields: str = "*",
    result_scope: str = "",
    org_id: str | None = None,
) -> list[dict]:
    normalized_artifact = normalize_artifact_name(artifact)
    normalized_result_artifact = normalize_artifact_name(f"{artifact}{result_scope}")
    normalized_fields = normalize_fields(fields)
    normalized_parameters = normalize_env_dict(parameters)
    vql = (
        f"LET collection <= collect_client(urgent='TRUE',client_id={vql_literal(client_id)}, "
        f"artifacts={vql_literal(normalized_artifact)}, env=dict({normalized_parameters})) "
        f"LET get_monitoring = SELECT * FROM watch_monitoring(artifact='System.Flow.Completion') WHERE FlowId = collection.flow_id LIMIT 1 "
        f"LET get_results = SELECT * FROM source(client_id=collection.request.client_id, flow_id=collection.flow_id,artifact={vql_literal(normalized_result_artifact)}) "
        f"SELECT {normalized_fields} FROM foreach(row=get_monitoring, query=get_results) "
    )

    return run_vql_query(vql, org_id=org_id)
```

```python
def normalize_fields(fields: str) -> str:
    cleaned = fields.strip()
    if not cleaned:
        raise ValueError("Fields must not be empty.")
    if cleaned == "*":
        return cleaned

    result = []
    for field in cleaned.split(","):
        candidate = field.strip()
        if not candidate or not VALID_FIELD_RE.fullmatch(candidate):
            raise ValueError(
                "Invalid field selection. Use '*' or a comma-separated list of field "
                "names such as 'Pid, Name, CommandLine'."
            )
        result.append(candidate)

    return ", ".join(result)
```
