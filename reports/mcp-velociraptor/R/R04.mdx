# R04 도구 결과 해석 주의

### R04.01 도구별 정적 주의

**구현.** 이 방식은 `windows_execution_shimcache` 하나에 적용된다 [1].
이 도구의 설명은 ShimCache 항목이 있다는 것이 실제 실행을 뜻하지 않을 수 있고 파일이 시스템에 접근되거나 관찰됐다는 것만 뜻한다고 적는다 [1].
이 문구는 함수의 docstring에 있고 MCP 도구 목록의 설명으로 실린다 [1][2].
이 문구는 도구 설명에만 있고 `windows_execution_shimcache`의 응답에는 실리지 않는다 [1][3].
도구 목록의 설명 78개 가운데 결과의 해석 한계를 적은 것은 이 하나다 [2].
실행 흔적을 다루는 `windows_execution_amcache`·`windows_execution_userassist`·`windows_execution_prefetch`의 설명에는 해석 한계를 적은 문구가 없다 [4].
`windows_ntfs_mft`의 설명은 행이 많이 올 수 있다는 것과 실패하면 `collect_artifact`로 다시 하라는 것을 적는다 [5].
`list_windows_artifacts`의 설명은 파일 이름 정규식이 NTFS 질의에서 더 빠르다는 것을 적는다 [6].
이 두 설명은 도구 사용법과 성능을 안내하고 결과의 해석 한계는 적지 않는다 [5][6].
서버는 `FastMCP("velociraptor-mcp")`로 만들어지고 서버 지침을 넘기지 않는다 [7].
서버는 MCP 리소스와 프롬프트를 등록하지 않는다 [2].
응답은 `ok`와 `data`나 `error`만 담는다 [3].
README의 Caveats 절은 결과가 돌아온 자료의 양, 쓰는 모델, 컨텍스트 창에 달려 있다고 적는다 [8].
이 문구는 README에만 있고 도구 설명이나 응답으로 모델에게 전달되지 않는다 [2][8].
