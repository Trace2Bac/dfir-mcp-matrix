# R02 대량 결과 전달

### R02.01 문자·항목 상한

**구현.** 이 방식은 `list_clients`와 `get_hunt_results_tool`에 적용된다 [1][2].
`list_clients`는 `limit`(기본값 100)을 VQL `LIMIT`으로 넘긴다 [1][3].
`get_hunt_results_tool`은 `limit`(기본값 500)을 VQL `LIMIT`으로 넘긴다 [2][4].
두 도구는 `limit`을 `int()`로 바꾸기만 하고 최댓값을 두지 않는다 [3][4].
`list_clients`는 `LastSeen` 내림차순으로 정렬한 뒤 자르므로 상한에 닿으면 가장 최근에 본 단말부터 남는다 [3].
`get_hunt_results_tool`의 질의에는 정렬 조건이 없다 [4].
27행이 모인 hunt에 `limit` 2로 부르자 2행이 왔다 [5].

상한으로 자른 응답에는 전체 건수나 잘렸다는 표시가 없다 [3][4][5].
두 도구에는 건너뛸 행 수를 받는 인자가 없어 나머지 행은 `limit`을 키워 다시 불러야 읽을 수 있다 [1][2].

다음 도구의 응답에는 행 수 상한이 없다.
실시간 수집 도구 62개는 `source()`가 돌려준 행을 모두 싣는다 [6].
`get_collection_results`는 flow의 결과 행을 모두 싣고 `run_vql`은 질의의 결과 행을 모두 싣는다 [7][8].
`list_windows_artifacts`·`list_linux_artifacts`·`list_macos_artifacts`는 조건에 맞는 아티팩트 정의를 모두 싣는다 [9].
서버 코드에는 응답 글의 길이를 재거나 자르는 곳이 없다 [10].
`list_windows_artifacts`의 응답은 인자 없이 47,686자였고 `include_parameter_details`를 참으로 주자 238,153자였다 [11].
`get_flow_status`의 `LIMIT 100`은 flow 기록에서 완료 문구를 찾는 질의에 붙은 것이고 응답의 행 수를 제한하지 않는다 [12].

`get_collection_results`는 수집을 시작만 하는 도구가 돌려준 `flow_id`로 Velociraptor에 보관된 결과를 읽는다 [7].
이 도구는 결과 전체를 한 번에 싣고 일부 행만 읽는 인자가 없다 [7].
실시간 수집 도구의 응답에는 flow ID가 없다 [6].

**한계.** 서버는 `limit`이 0이거나 음수인지 확인하지 않는다 [3][4].
27행이 모인 hunt에 `get_hunt_results_tool`을 `limit` 0과 -1로 부르자 두 번 모두 빈 목록이 아니라 1행이 왔다 [13].
단말 하나가 등록된 서버에서 `list_clients`도 `limit` 0과 -1에 그 단말 한 행을 돌려줬다 [13].

### R02.06 값 단위 잘림

**구현.** 이 방식은 아티팩트 목록 도구 3개의 `short_description`에 적용된다 [9].
`shorten`은 아티팩트 설명에서 첫 마침표 앞까지를 떼어 120자까지 남기고 `...`을 붙인다 [9].
`list_windows_artifacts`가 돌려준 199개의 `short_description`은 가장 긴 것이 123자였다 [14].

**한계.** `...`은 설명이 비어 있지 않으면 늘 붙으므로 120자에서 잘렸는지를 알려 주지 않는다 [9][14].
`shorten`은 마침표가 문장 끝이 아닌 곳에 있어도 그 앞에서 자른다 [9].
`Windows.Analysis.EvidenceOfDownload`의 설명 726자는 `Zone.Identifier`라는 이름 안의 마침표 앞에서 잘렸다 [14].
`include_parameter_details`를 참으로 줘도 `short_description`은 같고 설명 전문을 돌려주는 인자는 없다 [9][14].

def list_all_clients(
    search: str = ".",
    os_filter: str = ".",
    limit: int = 100,
    org_id: str | None = None,
) -> list[dict]:
    search_pattern = search or "."
    os_pattern = os_filter or "."
    vql = (
        "SELECT client_id,"
        "timestamp(epoch=first_seen_at) as FirstSeen,"
        "timestamp(epoch=last_seen_at) as LastSeen,"
        "os_info.hostname as Hostname,"
        "os_info.fqdn as Fqdn,"
        "os_info.system as OSType,"
        "os_info.release as OS,"
        "os_info.machine as Machine,"
        "agent_information.version as AgentVersion,"
        "last_ip as LastIP "
        "FROM clients() "
        f"WHERE (os_info.hostname =~ {vql_literal(search_pattern)} "
        f"OR os_info.fqdn =~ {vql_literal(search_pattern)} "
        f"OR client_id =~ {vql_literal(search_pattern)}) "
        f"AND os_info.system =~ {vql_literal(os_pattern)} "
        f"ORDER BY LastSeen DESC LIMIT {int(limit)}"
    )
    return run_vql_query(vql, org_id=org_id)

def get_flow_status(client_id: str, flow_id: str, artifact: str, org_id: str | None = None) -> str:
    artifact_pattern = f"^Collection {re.escape(normalize_artifact_name(artifact))} is done after"
    vql = (
        f"SELECT * FROM flow_logs(client_id={vql_literal(client_id)}, flow_id={vql_literal(flow_id)}) "
        f"WHERE message =~ {vql_literal(artifact_pattern)} "
        "LIMIT 100"
    )

    results = run_vql_query(vql, org_id=org_id)

    if results and isinstance(results, list) and len(results) > 0:
        return "FINISHED"

    return "RUNNING"
