# R03 분석 상태 알림

### R03.01 구조화 status·error

**구현.** 이 방식은 서버의 도구 78개 모두에 적용된다 [1].
도구는 성공이면 `{"ok": true, "data": …}`를, 실패면 `{"ok": false, "error": "<문구>"}`를 JSON 글로 돌려준다 [1].
`_run_json_tool`은 부른 함수에서 난 예외를 모두 처리해 예외 문구를 `error`에 싣는다 [1].
gRPC 호출이 실패하거나 서버의 인자 검사가 예외를 내면 이 경로로 `ok`가 `false`인 응답이 된다 [1][2][3].
수집을 시작만 하는 도구는 Velociraptor의 결과에 `flow_id`가 없으면 `Failed to start collection`으로 시작하는 `error`를 돌려준다 [4].
`client_info`는 단말을 찾지 못하면 `Client not found`로 시작하는 `error`를 돌려준다 [5].
`ok`가 `false`인 응답은 MCP 결과의 `isError`가 `false`다 [2].
MCP 오류 결과(`isError: true`)는 도구 함수가 실행되기 전에 FastMCP가 만든다 [6].
FastMCP는 인자의 자료형이 맞지 않거나 필수 인자가 빠지면 `Error executing tool`로 시작하는 오류 결과를 돌려준다 [6][2].
등록되지 않은 도구 이름에는 `Unknown tool`로 시작하는 오류 결과를 돌려준다 [6][2].
`hunt_across_fleet`의 성공 응답에는 `state`·`parameter_validation`·`created_paused`·`start_result`가 실린다 [7].
`parameter_validation`은 모델이 아티팩트 매개변수를 주지 않았으면 `validated: false`와 `reason: no_parameters_requested`다 [8][9].
매개변수를 줬으면 서버는 Velociraptor가 hunt에 넣은 매개변수를 요청한 값과 대조해 일치하면 `validated: true`를 싣는다 [8].
일치하지 않으면 서버는 hunt를 멈추고 `ok`가 `false`인 응답을 돌려준다 [8][9].

서버는 `Context`를 가져오지 않고 도구 함수에는 진행 알림을 보내는 코드가 없다 [10].
`progressToken`을 붙여 `linux_pslist`와 30초 동안 재시도한 `get_collection_results`를 불렀을 때 진행 알림과 로그 알림은 하나도 오지 않았다 [11].

**한계.** Velociraptor가 질의를 실행하다 낸 오류는 `ok`가 `true`인 응답으로 돌아온다 [12].
`run_vql_query`는 응답 메시지에 `error` 속성 값이 있으면 `RuntimeError`를 내도록 적혀 있다 [13].
pyvelociraptor 0.1.14의 응답 메시지 `VQLResponse`에는 `error` 필드가 없어 이 분기는 실행되지 않는다 [12][14].
Velociraptor는 질의의 오류를 `log` 필드에 실어 보내고 서버는 `log`를 읽지 않는다 [13][12].
`run_vql`에 없는 플러그인을 부르는 VQL과 문법이 틀린 VQL을 주자 둘 다 `{"ok": true, "data": []}`가 왔다 [12].
없는 플러그인을 부르는 질의를 `Generic.Client.VQL`로 수집하자 flow는 Velociraptor에서 `ERROR`가 됐고 `get_collection_results`는 그 flow에 `{"ok": true, "data": []}`를 돌려줬다 [15].

응답에는 오류 종류를 나타내는 필드가 없고 `error`는 서버가 정한 문구이거나 예외 문구 그대로다 [1].
API 포트가 틀린 설정으로 `list_clients`를 부르자 `error`에 gRPC 예외 객체의 문자열 표현이 그대로 실렸다 [3].
수집 시작이 실패한 응답의 `error`는 `Failed to start collection: []`이고 Velociraptor가 flow를 만들지 않은 이유는 실리지 않는다 [4][16].
`hunt_across_fleet`의 `state`는 서버가 적은 고정 문자열 `STARTED`이고 Velociraptor에서 읽은 hunt 상태가 아니다 [7].
hunt를 만든 직후 Velociraptor `hunts()`가 돌려준 `state`는 `RUNNING`이었다 [17].
`hunt()`가 hunt를 만들지 못해도 설명이 같은 hunt가 이미 있으면 `start_hunt`는 그 hunt의 ID로 처리를 이어 가 `ok`가 `true`인 응답을 돌려준다 [18].
멈춰 둔 hunt와 설명이 같은 요청을 Velociraptor가 받지 않는 `os_filter` 값 `plan9`로 보내자 새 hunt는 생기지 않았고 응답은 멈춰 둔 hunt의 `hunt_id`를 담은 성공이었다 [19].

`get_collection_results`는 재시도 횟수를 다 쓰면 `ok`가 `false`인 응답과 고정 문구를 돌려준다 [20].
flow가 아직 끝나지 않은 경우, flow ID가 없는 경우, `artifact`가 flow의 아티팩트 이름과 다른 경우, `max_retries`가 0인 경우에 같은 문구가 돌아왔다 [21].
끝난 flow에 그 flow의 아티팩트 이름을 주어도 이 문구가 돌아오는 경우가 있다 [15].
30행을 모으고 끝난 `Linux.Sys.Crontab` flow에 `artifact`를 `Linux.Sys.Crontab`으로 주자 이 문구가 왔고 `Linux.Sys.Crontab/CronTabs`로 주자 6행이 왔다 [15].
`artifact`를 `Linux.Sys.Crontab/CronScripts`나 `Linux.Sys.Crontab/Uploaded`로 주어도 이 문구가 왔다 [15].
`collect_file`은 `ok`가 `true`인 응답으로 `flow_id`를 돌려줬고 그 flow는 0행으로 끝났다 [15].
이 flow에 `artifact`를 `Generic.Collectors.File`로 주자 같은 문구가 왔다 [15].
소스 이름에 공백이 있는 `Generic.Collectors.File/All Matches Metadata`를 주자 `Invalid artifact name`으로 시작하는 `error`가 왔다 [15].
이 응답에는 시간이 다 됐다는 것을 다른 실패와 구분하는 값이 없다 [20].

`realtime_collection`은 Velociraptor의 완료 알림을 기다리는 질의에 시간 제한을 두지 않는다 [22].
등록되지 않은 `client_id`로 `linux_pslist`를 부르자 60초 뒤 호출을 끊을 때까지 응답이 오지 않았다 [23].
서버가 수집 처리기에 넘기는 아티팩트 이름 63개 가운데 13개는 Velociraptor v0.77.1 시험 서버의 정의 437개에 없다 [24].
13개 가운데 11개는 실시간 수집 도구가 부르는 이름이고 2개는 수집을 시작만 하는 `kill_process`와 `collect_forensic_triage`가 부르는 이름이다 [24].
11개 가운데 `Linux.Network.ArpCache`를 부르는 `linux_arp_cache`는 75초 동안 응답이 오지 않았고 flow도 생기지 않았다 [23].

### R03.02 찾지 못함과 실패 구분

**구현.** 이 방식은 행 목록을 돌려주는 도구에 적용된다 [1][13].
조건에 맞는 행이 없으면 `run_vql_query`가 빈 목록을 돌려주고 도구는 `{"ok": true, "data": []}`를 돌려준다 [1][13].
gRPC 호출이 실패하거나 서버의 인자 검사가 예외를 내면 `ok`가 `false`인 응답이 돌아오므로 이 실패와 결과가 없는 것은 `ok` 값으로 나뉜다 [1].
`get_collection_results`는 flow가 끝났고 결과가 0행이면 `{"ok": true, "data": []}`를 돌려준다 [20].
응답에 찾지 못함만을 뜻하는 상태 값은 없다 [1].

**한계.** `client_info`는 단말을 찾지 못한 경우를 `ok`가 `false`인 응답으로 돌려준다 [5].
이 응답은 조회 실패와 `ok` 값이 같고 `error`의 문구로만 구분된다 [5][16].
`collect_artifact`에 없는 아티팩트 이름을 주면 `Failed to start collection: []`이 `error`로 돌아온다 [4][16].

빈 목록은 조건에 맞는 행이 없다는 뜻이 아닌 경우에도 돌아온다.
Velociraptor가 질의를 실행하다 오류를 낸 `run_vql` 호출과 `ERROR`로 끝난 flow의 응답은 `{"ok": true, "data": []}`였다 [12][15].
Linux 단말에 `windows_pslist`를 부르자 Velociraptor는 사전 조건이 맞지 않아 질의를 건너뛰었고 응답은 `{"ok": true, "data": []}`였다 [25].
`linux_crontab`은 flow가 30행을 모았는데도 `{"ok": true, "data": []}`를 돌려줬다 [26].
없는 hunt ID로 부른 `get_hunt_results_tool`의 응답도 `{"ok": true, "data": []}`였다 [27].
이 응답들은 조건에 맞는 행이 없을 때의 응답과 같다 [25][26][27].

def _json_success(data) -> str:
    return json.dumps({"ok": True, "data": data}, default=str)


def _json_error(message: str) -> str:
    return json.dumps({"ok": False, "error": message})


def _run_json_tool(func, *args, **kwargs) -> str:
    try:
        return _json_success(func(*args, **kwargs))
    except Exception as exc:
        return _json_error(str(exc))

```python
def run_vql_query(vql: str, org_id: str | None = None):
    if stub is None:
        raise RuntimeError("Stub not initialized. Call init_stub() first.")
    request = api_pb2.VQLCollectorArgs(Query=[api_pb2.VQLRequest(VQL=vql)])
    resolved_org_id = resolve_org_id(org_id)
    if resolved_org_id:
        request.org_id = resolved_org_id
    results = []
    if DEBUG_VQL:
        logger.debug("VQL request: %s", request)
    
    for resp in stub.Query(request):
        if hasattr(resp, "error") and resp.error:
            raise RuntimeError(f"Velociraptor API error: {resp.error}")
        if hasattr(resp, "Response") and resp.Response:
            results.extend(json.loads(resp.Response))
    return results
```
