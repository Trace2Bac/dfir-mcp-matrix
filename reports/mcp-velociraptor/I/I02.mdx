# I02 분석 도구 통신 차단

### 미구현

**판단.** 서버가 분석에 쓰는 외부 프로그램은 Velociraptor이고 서버는 VQL을 보내 아티팩트 수집을 요청한다 [1].
아티팩트를 실행하는 쪽은 Velociraptor 서버와 단말의 Velociraptor 클라이언트다.
서버가 만드는 수집 VQL에는 `client_id`, 아티팩트 이름, 아티팩트 매개변수만 있고 실행 중의 통신을 끊거나 끄는 인자는 없다 [1].
`collect_artifact`와 `hunt_across_fleet`는 요청할 아티팩트 이름을 인자로 받는다 [2].
`normalize_artifact_name`은 이 이름의 글자 형식만 검사하고 이름을 목록과 대조하지 않는다 [3].
두 도구는 `ENABLE_DANGEROUS_TOOLS`를 확인하지 않는다 [2].
`ENABLE_DANGEROUS_TOOLS`를 켜지 않은 채 `collect_artifact`로 `Generic.Client.VQL`에 `http_client()`를 쓰는 VQL을 넘기자 단말의 Velociraptor 클라이언트가 VQL에 적힌 주소로 HTTP 요청을 보냈다 [4].
`run_vql`은 `ENABLE_DANGEROUS_TOOLS`를 켜면 받은 VQL을 그대로 Velociraptor 서버에 보낸다 [5].
이 도구로 `http_client()`를 쓰는 VQL을 보내자 Velociraptor 서버가 VQL에 적힌 주소로 HTTP 요청을 보냈다 [6].
YARA 도구는 규칙 본문을 `YaraRule` 인자로 받아 아티팩트 매개변수로 넘기고 규칙을 내려받을 주소를 넘기는 인자는 두지 않는다 [7].
이것은 내려받기 인자를 붙이지 않은 것이고 통신을 끄는 장치가 아니다.

서버 프로세스가 직접 부르는 라이브러리는 pyvelociraptor, grpcio, PyYAML, python-dotenv, MCP Python SDK다 [8].
이 라이브러리들이 Velociraptor API 접속 밖에서 스스로 통신하는지는 소스로 확인하지 않았다.

```python
def normalize_artifact_name(artifact: str) -> str:
    cleaned = artifact.strip()
    if not cleaned or not VALID_ARTIFACT_RE.fullmatch(cleaned):
        raise ValueError(f"Invalid artifact name: {artifact!r}")
    return cleaned
```
