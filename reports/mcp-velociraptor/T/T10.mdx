# T10 도구 명세 구성

### T10.01 처리 함수에서 명세 생성

**구현.** 이 방식은 도구 78개 모두에 적용된다 [1].
서버는 MCP Python SDK의 `FastMCP` 객체를 하나 만들고 처리 함수마다 인자 없는 `@mcp.tool()`을 붙여 도구로 등록한다 [1].
SDK는 함수 이름을 도구 이름으로, docstring을 설명으로 쓰고 함수 서명에서 입력 schema를 만든다 [2].
그래서 schema의 인자 이름, 자료형, 기본값은 처리 함수의 매개변수와 같다 [2].
실행 확인에서 도구 목록은 78개였고 설명이 빈 도구는 없었다 [3].
`collect_artifact`와 `hunt_across_fleet`의 `parameters`를 뺀 인자 375개의 schema에는 `title`, `type`, `default`만 있고 인자 설명은 docstring의 `Args` 부분에 글로만 있다 [3].
docstring에 `Args` 부분이 없는 도구 48개에는 인자 설명이 없다 [3].
SDK는 반환 자료형 `str`에서 출력 schema도 만들어 모든 도구가 문자열 `result` 하나를 가진 출력 schema를 싣는다 [3].
그 문자열에 담기는 `ok`, `data`, `error`의 구조는 출력 schema에 없다 [3].
annotation과 `title`을 가진 도구는 없다 [3].
초기화 응답의 `tools.listChanged`는 거짓이고 서버 지침 `instructions`는 없으며 리소스와 프롬프트도 없다 [3].
`ENABLE_DANGEROUS_TOOLS`는 도구 목록과 설명을 바꾸지 않는다 [4].
`run_vql`·`quarantine_host`·`kill_process`는 설정이 꺼져 있어도 목록에 있고 설명에 `Disabled unless ENABLE_DANGEROUS_TOOLS=true`를 적는다 [4][3].
`unquarantine_host`의 설명에는 이 문구가 없고 처리 함수도 이 설정을 확인하지 않는다 [5].

**한계.** 다음 도구는 schema와 설명이 알리는 것과 처리 함수의 동작이 다르다.
`linux_pslist`와 `macos_pslist`는 `ProcessRegex`를 같은 이름의 아티팩트 매개변수로 넘긴다 [1][6].
Velociraptor v0.77.1의 `Linux.Sys.Pslist`와 `MacOS.Sys.Pslist` 정의에 있는 매개변수 이름은 `processRegex`여서 이 값은 프로세스를 거르지 않는다 [3].
`linux_pslist`의 설명은 `ProcessRegex`를 프로세스 이름을 거르는 정규식으로 적는다 [1].
실행 확인에서 `linux_pslist`에 `ProcessRegex="velociraptor"`를 주면 `systemd`를 포함한 56행이 왔고 `collect_artifact`로 `processRegex="velociraptor"`를 주면 3행이 왔다 [3].
`linux_journal_logs`는 `SearchRegex`를 같은 이름의 매개변수로 넘기지만 `Linux.Forensics.Journal` 정의에는 그 이름의 매개변수가 없다 [7][3].
실행 확인에서 로그에 없는 문자열을 `SearchRegex`로 주어도 50,509행이 왔다 [3].
아티팩트가 v0.77.1 정의에 있는 도구가 넘기는 매개변수 이름을 정의와 대조했을 때 정의에 없는 이름은 이 세 도구의 것뿐이었다 [3].
`linux_file_finder`·`macos_file_finder`·`windows_hash_search`는 `Hash`와 `HashRegex`를 받지만 값이 있으면 `Calculate_Hash`를 참으로 바꾸기만 하고 그 값을 아티팩트에 넘기지 않는다 [8].
그래서 준 해시와 맞는 파일만 고르는 처리는 없다.
`macos_browser_history`는 schema에 `URLRegex`를 싣지만 기본값 `.`이 아닌 값을 받으면 수집하지 않고 그 아티팩트에 `URLRegex`가 없다는 오류를 돌려준다 [9].
`macos_browser_history`와 `windows_browser_history`의 schema는 `historyGlobs`와 `urlSQLQuery`를 기본값이 빈 문자열인 인자로 싣고 처리 함수는 모델이 주지 않아도 그 빈 문자열을 아티팩트 매개변수로 넘긴다 [9][10].
v0.77.1 정의에서 두 아티팩트는 `historyGlobs`로 기록 파일을 찾아 `urlSQLQuery`로 읽고 두 매개변수의 기본값은 브라우저 기록 파일의 경로와 그 파일을 읽는 SQL 문장이다 [3].
수집 요청에 실린 값은 빈 문자열이어도 정의의 기본값을 대신한다 [3].
실행 확인에서 `linux_groups`는 인자 없이 부르면 57행을, 정의의 기본값이 `/etc/group`인 `GroupFile`을 빈 문자열로 주면 0행을 돌려주었다 [3].
VQL `glob(globs='')`은 행을 내지 않았다 [3].
그래서 두 인자를 주지 않은 호출에는 정의의 기본 경로와 기본 SQL 문장이 쓰이지 않는다 [10].
두 도구의 응답은 Windows와 macOS 단말이 없어 실행으로 확인하지 않았다.
`macos_pslist`의 설명은 macOS 호스트의 프로세스를 나열한다고 적지만 처리 함수는 단말의 OS를 확인하지 않는다 [6].
실행 확인에서 Linux 단말에 `macos_pslist`를 부르면 그 단말의 프로세스 81행이 왔다 [3].
`windows_mountpoints2`의 설명은 다운로드 흔적을 모은다는 문장 `Collect evidence of download from a Windows host.`이고 처리 함수는 `Windows.Registry.MountPoints2`를 요청한다 [11].

`collect_file`의 설명은 경로나 glob으로 `Generic.Collectors.File` 수집을 시작한다고 적는다 [12].
처리 함수는 받은 경로를 JSON 배열 `[{"glob": path}]`로 만들어 `collectionSpec`에 넘기고 다른 매개변수는 넘기지 않는다 [12].
v0.77.1 정의에서 `collectionSpec`은 `Glob` 열을 가진 CSV이고 glob을 적용할 위치 `Root`의 기본값은 `C:`다 [13].
실행 확인에서 Linux 단말에 `collect_file`로 `/etc/hostname`을 주면 수집은 0행에 올린 파일 0개로 끝났다 [3].
같은 아티팩트를 `collect_artifact`로 `collectionSpec`을 CSV로, `Root`를 `/`로 주어 수집하면 2행에 올린 파일 1개로 끝났다 [3].

고정된 아티팩트를 요청하는 도구 67개가 넘기는 아티팩트 이름 63개 가운데 13개는 Velociraptor v0.77.1에 들어 있는 아티팩트 정의 437개에 없다 [14][3].
이 13개 이름은 도구 13개가 하나씩 요청한다 [14].
Linux 도구는 `linux_ssh_authorized_keys`(`Linux.Sys.SSHAuthorizedKeys`)와 `linux_arp_cache`(`Linux.Network.ArpCache`)다 [14].
macOS 도구는 `macos_users`(`MacOS.Sys.Users`), `macos_launch_agents`(`MacOS.Sys.LaunchAgents`), `macos_login_items`(`MacOS.Sys.LoginItems`), `macos_bash_history`(`MacOS.Sys.BashHistory`), `macos_quarantine_events`(`MacOS.Forensics.Quarantine`)다 [14].
Windows 도구는 `windows_mounted_mass_storage_usb`(`Windows.Mounted.Mass.Storage`), `windows_timestomp`(`Windows.NTFS.Timestomp`), `windows_malfind`(`Windows.Detection.Malfind`), `windows_logon_events`(`Windows.EventLogs.LogonSessions`), `collect_forensic_triage`(`Windows.Triage.Targets`)다 [14].
나머지 하나는 `kill_process`(`Generic.Utils.KillProcess`)다 [14].
이 도구들의 설명은 그 아티팩트를 Velociraptor 서버에 따로 등록해야 한다는 점을 적지 않는다 [14].
실행 확인에서 `linux_arp_cache`는 90초 동안 응답이 없어 호출을 끊었고 그 사이 그 단말에 새 flow는 만들어지지 않았다 [3].
`kill_process`는 설정을 켠 상태에서 `Failed to start collection: []`를 돌려주었다 [3].

`linux_crontab`·`windows_mutants`·`windows_srum`이 요청하는 아티팩트는 v0.77.1 정의에서 모든 source에 이름이 있는데 세 도구는 source 이름 없이 결과를 읽는다 [15][3].
실행 확인에서 `linux_crontab`은 수집이 30행을 모았는데도 빈 `data`를 돌려주었다 [3].
`windows_netstat_enriched`와 `windows_scheduled_tasks`는 source 이름 `Netstat`과 `Analysis`를 붙여 읽고 두 이름은 정의에 있다 [16][3].
Windows 단말이 없어 `windows_mutants`와 `windows_srum`의 결과는 실행으로 확인하지 않았다 [15].

`get_hunt_results_tool`의 설명은 끝난 hunt의 행을 가져온다고 적지만 처리 함수는 hunt의 상태를 확인하지 않는다 [17].
실행 확인에서 `RUNNING` 상태의 hunt에서 27행이 왔다 [3].
`get_collection_results`의 설명은 flow가 끝나지 않았거나 결과가 아직 없으면 기다렸다 다시 조회한다고 적는다 [18].
처리 함수는 완료 문구가 없을 때만 다시 조회하고 완료 문구가 있으면 결과가 비어도 바로 돌려준다 [18].
같은 설명은 `artifact`에 수집한 아티팩트의 이름을 주라고 적고 예로 `Windows.NTFS.MFT`를 적는다 [18].
처리 함수는 이 이름이 flow 로그의 완료 문구에 적힌 이름과 같을 때만 수집이 끝난 것으로 판정한다 [19].
실행 확인에서 끝난 `Linux.Sys.Crontab` flow에 `artifact`를 `Linux.Sys.Crontab`으로 주면 대기 중단 문구가 왔고 `Linux.Sys.Crontab/CronTabs`로 주면 6행이 왔다 [3].

### T10.03 묶음 도구의 연산별 인자를 schema가 구분하지 않음

**구현.** 이 방식은 `collect_artifact`, `hunt_across_fleet`, `run_vql`에 적용된다 [20][21][22].
`collect_artifact`와 `hunt_across_fleet`은 아티팩트 이름 `artifact`와 그 아티팩트의 매개변수 `parameters`를 받아 Velociraptor 서버에 있는 어느 아티팩트든 수집을 요청한다 [20][21].
입력 schema는 `artifact`를 문자열로, `parameters`를 값이 스칼라이거나 스칼라 배열인 객체로만 알린다 [20][3].
아티팩트마다 다른 매개변수의 이름과 자료형은 schema에 없다 [3].
`legacy_parameters`는 문자열 하나이고 서버는 그 값이 `{`로 시작하면 JSON 객체로, 아니면 `이름=값`을 쉼표로 이은 글로 읽는다 [23].
`run_vql`은 VQL 문자열 `query`를 받아 Velociraptor 서버에 보내고 schema는 `query`를 문자열로만 알린다 [22][3].
아티팩트별 매개변수는 `list_windows_artifacts`·`list_linux_artifacts`·`list_macos_artifacts`의 응답으로 알 수 있다 [24].
세 도구는 아티팩트마다 매개변수 이름을 돌려주고 `include_parameter_details`가 참이면 정의에 적힌 매개변수 항목 전체를 돌려준다 [24].
세 도구는 이름이 `windows.`로 시작하거나 이름에 `linux.`나 `macos.`가 들어 있는 아티팩트만 고르므로 `Generic.Client.VQL`처럼 이름이 `Generic.`으로 시작하는 아티팩트의 매개변수는 돌려주지 않는다 [25].
`collect_artifact`는 받은 매개변수 이름의 글자 형식만 검사하고 그 아티팩트 정의에 있는 이름인지 대조하지 않는다 [26].
`hunt_across_fleet`은 hunt를 만든 뒤 요청한 매개변수가 hunt의 수집 요청에 실렸는지 대조하고 실리지 않았으면 hunt를 멈추고 오류를 돌려준다 [27].
실행 확인에서 `Linux.Sys.Pslist` 정의에 없는 이름 `ProcessRegex`를 `parameters`로 준 `hunt_across_fleet`은 `Refusing to start parameterized hunt`로 시작하는 오류를 돌려주었고 그 hunt는 `STOPPED`가 되었다 [3].

```python
@mcp.tool()
async def linux_pslist(
    client_id: str,
    org_id: str = "",
    ProcessRegex: str = ".",
    Fields: str = "*"
) -> str:
    """
    List running processes on a Linux host.

    Args:
        client_id: The Velociraptor client ID.
        org_id: Optional Velociraptor org ID for multi-tenant deployments.
        ProcessRegex: Case-insensitive regex to filter process names.
        Fields: Comma-separated string of fields to return.

    Returns:
        Process list as a string or error message.

    """
    artifact = "Linux.Sys.Pslist"
    result_scope = ""
    parameters = {"ProcessRegex": ProcessRegex}

    return _run_collection_tool(client_id, artifact, parameters, Fields, result_scope, org_id)
```

[3] (실행 확인) `mcp.list_tools()`는 도구 78개를 돌려주었고 설명이 빈 도구는 0개, `annotations`가 있는 도구는 0개, `title`이 있는 도구는 0개, `outputSchema`가 있는 도구는 78개였다.

도구 78개의 입력 schema에 있는 인자 377개 가운데 375개는 `title`, `type`, `default`만 실었고 나머지 2개는 `collect_artifact`와 `hunt_across_fleet`의 `parameters`였다.
`parameters`의 schema는 `additionalProperties`의 `type`이 `string`, `integer`, `number`, `boolean`, 그 값들의 `array`, `null` 가운데 하나인 `object`이거나 `null`이었다.
`run_vql`의 입력 schema는 문자열 `query`와 `org_id`였다.
처리 함수 78개의 docstring 가운데 `Args:`가 없는 것은 48개였다.
`macos_browser_history`의 설명은 `Collect macOS browser history from supported browsers.` 한 줄이었다.
stdio 클라이언트 세션의 초기화 응답은 `tools.listChanged`가 거짓, `instructions`가 없음이었고 프롬프트와 리소스는 0개였다.
`ENABLE_DANGEROUS_TOOLS`가 없는 상태에서도 `run_vql`, `quarantine_host`, `kill_process`가 목록에 있었다.
Velociraptor v0.77.1 시험 서버의 `artifact_definitions()` 437개와 도구 78개의 아티팩트 이름, 매개변수 이름, source 이름을 대조했다.
수집 함수를 호출 내용만 적는 함수로 바꾸고 고정된 아티팩트를 요청하는 도구 67개를 부르면 넘긴 아티팩트 이름은 63개였다.
정의에 없는 아티팩트 이름은 13개였고 도구 13개에서 나왔다.
정의에 없는 매개변수 이름은 `linux_pslist`와 `macos_pslist`의 `ProcessRegex`(정의는 `processRegex`), `linux_journal_logs`의 `SearchRegex`(정의는 `JournalGlob`, `IdentifierRegex`, `IocRegex`, `DateAfter`, `DateBefore`, `AlsoUpload`)였다.
모든 source에 이름이 있는 아티팩트를 source 이름 없이 읽는 도구는 `linux_crontab`(`CronTabs`, `CronScripts`, `Uploaded`), `windows_mutants`(`Handles`, `ObjectTree`), `windows_srum`(`Upload`, `Execution Stats`, `Application Resource Usage`, `Network Connections`, `Network Usage`)이었다.
`Windows.Network.NetstatEnriched`의 source는 `Netstat`, `Windows.System.TaskScheduler`의 source는 `Analysis`였다.
Linux 단말에 `linux_pslist`를 `ProcessRegex="velociraptor"`로 부르면 `systemd`를 포함한 56행이 왔고 인자 없이 불러도 56행이 왔다.
`collect_artifact`로 `Linux.Sys.Pslist`를 `processRegex="velociraptor"`로 수집하면 `velociraptor` 3행이 왔다.
`linux_journal_logs`를 `SearchRegex="zzzz_no_such_text_t2"`로 부르면 50,509행이 왔다.
같은 단말에 `macos_pslist`를 부르면 `systemd`를 포함한 81행이 왔다.
`linux_crontab`은 `{"ok": true, "data": []}`를 돌려주었고 같은 아티팩트의 flow는 30행을 모았으며 `Linux.Sys.Crontab/CronTabs`에 6행, `Linux.Sys.Crontab/CronScripts`에 10행이 있었다.
끝난 `Linux.Sys.Crontab` flow에 `get_collection_results`를 `artifact="Linux.Sys.Crontab"`으로 부르면 `No results found after multiple retries or the flow did not finish.`가 왔고 `artifact="Linux.Sys.Crontab/CronTabs"`로 부르면 6행이 왔다.
`collect_file`에 `/etc/hostname`을 주어 시작한 flow는 `FINISHED`, 0행, 올린 파일 0개였다.
`collect_artifact`로 `Generic.Collectors.File`을 `collectionSpec="Glob\netc/hostname\n"`, `Root="/"`, `Accessor="file"`로 수집한 flow는 `FINISHED`, 2행, 올린 파일 1개였다.
`linux_arp_cache`를 `asyncio.wait_for`로 90초 기다렸고 응답이 없어 호출을 끊었다.
호출 전후에 `flows()`로 읽은 그 단말의 flow는 148개로 같았다.
`linux_groups`를 인자 없이 부르면 0.6초 만에 57행이 왔고 `GroupFile`을 빈 문자열로 주면 0행이 왔다.
`artifact_definitions()`로 읽은 `Linux.Sys.Groups`의 `GroupFile` 기본값은 `/etc/group`이었다.

```python
def normalize_env_dict(parameters: Mapping[str, ParameterValue] | None = None) -> str:
    if parameters is None:
        return ""
    if not isinstance(parameters, Mapping):
        raise TypeError("parameters must be a mapping or None")

    items = []
    for key, value in parameters.items():
        if not VALID_PARAMETER_NAME_RE.fullmatch(key):
            raise ValueError(f"Invalid parameter name: {key!r}")
        normalized_value = normalize_parameter_value(value)
        items.append(f"{key}={vql_literal(normalized_value)}")

    return ",".join(items)
```
