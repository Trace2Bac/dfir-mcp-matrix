# T06 실행 환경정보 표시

### T06.04 환경 조회 도구에서만 반환

**구현.** 이 방식은 단말 정보를 조회하는 `client_info`와 `list_clients`에 적용된다 [1].
두 도구는 Velociraptor의 `clients()`에서 단말마다 `agent_information.version`을 읽어 `AgentVersion` 필드로 돌려준다 [1].
이 값은 그 단말에서 아티팩트를 실행하는 Velociraptor 클라이언트의 버전이다.
실행 확인에서 두 도구는 시험 단말의 `AgentVersion`을 `0.77.1`로 돌려주었다 [2].

수집 결과를 돌려주는 응답에는 버전이 없다.
결과를 기다렸다 돌려주는 도구 62개와 `get_collection_results`·`get_hunt_results_tool`은 Velociraptor가 돌려준 결과 행을 `{"ok": true, "data": …}`에 담고 다른 필드를 더하지 않는다 [3][4].
실행 확인에서 `linux_users`가 돌려준 행의 키는 `Description`, `Gid`, `Homedir`, `Shell`, `Uid`, `User`뿐이었다 [2].
수집을 시작하는 도구의 응답은 `flow_id`, `artifacts`, `timeout`, `specs`이고 `hunt_across_fleet`의 응답에도 버전 필드가 없다 [5].
그래서 어느 수집이 어느 버전의 클라이언트에서 실행됐는지는 `client_id`로 단말 조회 응답을 따로 찾아야 알 수 있다 [1].
hunt 결과는 여러 단말의 행이 섞여 오지만 행마다 클라이언트 버전이 실리지 않는다 [4].

서버 코드에는 Velociraptor 서버의 버전을 조회하는 질의가 없다.
아티팩트 정의는 Velociraptor 서버가 보관하고 수집마다 그 정의대로 실행된다.
`list_windows_artifacts`·`list_linux_artifacts`·`list_macos_artifacts`는 정의의 이름, 설명 첫 문장, 매개변수만 돌려주고 정의의 내용을 가리키는 값은 돌려주지 않는다 [6].
그래서 수집에 쓰인 아티팩트 정의가 Velociraptor에 들어 있던 것인지 사용자가 바꾼 것인지는 응답으로 알 수 없다.

서버 자신의 버전도 응답에 싣지 않는다.
서버는 `FastMCP` 객체에 이름 `velociraptor-mcp`만 주고 버전을 주지 않는다 [7].
MCP Python SDK 1.28.1은 버전을 받지 못하면 초기화 응답의 `serverInfo.version`에 SDK 패키지의 버전을 넣는다 [8].
실행 확인에서 그 값은 `1.28.1`이었다 [2].
서버는 호출 기록과 파생물을 만들지 않으므로 버전을 실을 기록도 없다.
서버는 모델을 부르지 않는다.
