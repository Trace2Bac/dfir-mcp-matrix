# T05 분석 도구 검증

### T05.02 설정·호출 인자로 지정

**구현.** 이 방식은 서버가 붙는 Velociraptor 서버의 위치와 YARA 검사에 쓰는 룰에 적용된다 [1][2].
서버는 환경변수 `VELOCIRAPTOR_API_CONFIG`가 가리키는 API 설정 파일을 읽고 값이 없으면 작업 폴더의 `api_client.yaml`, 그다음 `~/.config/api_client.yaml`을 읽는다 [1].
이 환경변수가 프로세스 환경에 없으면 서버는 `VELOCIRAPTOR_ENV_FILE`이 가리키는 파일과 저장소 폴더의 `.env`에 적힌 값을 쓴다 [3].
그 파일의 `api_connection_string`이 요청을 받을 Velociraptor 서버의 주소를 정한다 [4].
서버는 이 파일에서 인증서, 키, 주소만 읽고 붙은 Velociraptor 서버의 버전은 묻지 않는다 [4].
`yara_scan_files`·`yara_scan_process`·`linux_yara_scan`과 `linux_file_finder`·`macos_file_finder`·`windows_hash_search`는 호출 인자 `YaraRule`로 룰 본문을 받아 아티팩트 인자로 넘긴다 [2].
도구가 수집하는 아티팩트의 정의는 붙은 Velociraptor 서버에 있고 서버 코드에는 그 이름만 있다 [5].
도구 67개가 코드에 적은 아티팩트 이름 63개를 쓰고 `collect_artifact`와 `hunt_across_fleet`는 모델이 준 이름을 쓴다 [5][6].
저장소에는 아티팩트 정의 파일이 없다.
`requirements.txt`는 `pyvelociraptor`·`grpcio`·`mcp`를 비롯한 패키지 20개를 버전 없이 이름만 적는다 [7].
저장소에 의존성 잠금 파일은 없다.

**한계.** 서버는 코드에 적은 아티팩트 이름이 붙은 Velociraptor 서버에 있는지 호출 전에 확인하지 않는다 [5].
Velociraptor v0.77.1 시험 서버의 아티팩트 437개에는 코드에 적은 이름 63개 가운데 13개가 없었다 [8].
없는 이름은 `Generic.Utils.KillProcess`, `Windows.Triage.Targets`, `Windows.Detection.Malfind`, `Windows.NTFS.Timestomp`, `Windows.EventLogs.LogonSessions`, `Windows.Mounted.Mass.Storage`, `Linux.Sys.SSHAuthorizedKeys`, `Linux.Network.ArpCache`, `MacOS.Sys.Users`, `MacOS.Sys.LaunchAgents`, `MacOS.Sys.LoginItems`, `MacOS.Sys.BashHistory`, `MacOS.Forensics.Quarantine`이다 [8].
Velociraptor v0.77.1 소스의 `artifacts/definitions/Generic/Utils` 폴더에도 `KillProcess` 정의는 없다 [9].
`Linux.Network.ArpCache`를 쓰는 `linux_arp_cache`는 시험 서버에서 90초 동안 응답이 없어 호출을 끊었고 그 사이 그 단말에 새 flow는 만들어지지 않았다 [10].
`ENABLE_DANGEROUS_TOOLS`를 켠 `kill_process`는 시험 서버에서 `Failed to start collection: []` 오류를 돌려주었고 대상으로 준 시험용 프로세스는 끝나지 않았다 [11].
이 13개가 Velociraptor의 다른 버전이나 따로 올리는 아티팩트 묶음에 있는지는 확인하지 못했다.

README는 `api_client.yaml`을 저장소 루트에 복사하거나 `VELOCIRAPTOR_API_CONFIG`로 경로를 주라고 안내한다 [12].
`resolve_config_path`는 환경변수가 없을 때 이 파일을 저장소 루트가 아니라 서버 프로세스의 작업 폴더에서 찾는다 [1].
`.env`는 `velociraptor_env.py`가 있는 폴더에서 찾으므로 두 파일을 찾는 기준 폴더가 다르다 [3].
그래서 서버를 저장소 루트가 아닌 작업 폴더에서 실행하면 저장소 루트에 둔 `api_client.yaml`은 쓰이지 않는다 [1].
실행 확인에서 서버 파일과 같은 폴더에 `api_client.yaml`과 `.env`를 두고 작업 폴더를 `/`로 두면 `.env`의 값은 읽혔고 `resolve_config_path`는 `FileNotFoundError`를 냈다 [13].
`VELOCIRAPTOR_ENV_FILE`이 가리키는 경로에 파일이 없으면 서버는 오류나 알림 없이 그 파일을 건너뛰고 저장소의 `.env`에 적힌 값을 쓴다 [3].

### T05.03 실행 시 버전 조회

**구현.** 이 방식은 `client_info`와 `list_clients`가 읽는 단말의 Velociraptor 클라이언트 버전에 적용된다 [14].
두 도구의 질의는 `clients()`의 `agent_information.version`을 `AgentVersion` 열로 읽는다 [14].
시험 서버에서 `list_clients`의 응답은 단말 행에 `"AgentVersion": "0.77.1"`을 담았다 [15].
서버는 이 값을 응답에 싣기만 하고 기준값과 대조하지 않는다 [14].
이 값은 Velociraptor 서버가 단말마다 보관한 기록에서 오고 서버가 단말에 직접 묻는 값이 아니다 [14].
수집 도구와 `hunt_across_fleet`는 대상 단말의 클라이언트 버전을 읽지 않는다 [16].
Velociraptor 서버의 버전과 아티팩트 정의의 버전은 어느 도구도 읽지 않는다.
아티팩트 목록 도구 3개는 `artifact_definitions()`에서 이름, 설명, 인자만 읽는다 [17].

```python
def resolve_config_path(config_path: str | None = None) -> Path:
    explicit_path = config_path or os.environ.get("VELOCIRAPTOR_API_CONFIG")
    if explicit_path:
        resolved = Path(explicit_path).expanduser()
        if resolved.is_file():
            return resolved
        raise FileNotFoundError(
            f"Velociraptor API config not found: {resolved}. "
            "Set VELOCIRAPTOR_API_CONFIG to a valid file path."
        )

    candidates = [
        Path("api_client.yaml"),
        Path.home() / ".config" / "api_client.yaml",
    ]
    for candidate in candidates:
        resolved = candidate.expanduser()
        if resolved.is_file():
            return resolved

    raise FileNotFoundError(
        "Velociraptor API config not found. Checked ./api_client.yaml and "
        "~/.config/api_client.yaml. Set VELOCIRAPTOR_API_CONFIG to override."
    )
```
