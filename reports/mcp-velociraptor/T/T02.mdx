# T02 실행 허용 범위 제한

### T02.01 클라이언트 도구 선택

**구현.** 이 방식은 저장소가 함께 내놓는 MCP 클라이언트 예제 `agent_poc/`에 적용된다 [1].
이 예제는 운영체제마다 역할 표를 두고 역할마다 쓸 도구 이름 목록을 코드에 적는다 [2].
`get_tool_definitions`는 이 목록에 없는 도구를 모델에게 보여 줄 도구 정의에서 뺀다 [3].
저장소의 조사 흐름은 역할마다 이 목록을 그 역할의 클라이언트에 허용 도구로 준다 [4].
증거 수집은 모델이 아니라 코드가 역할 표의 도구를 차례로 불러 한다 [5].
역할 표의 도구는 58개이고 `run_vql`, `quarantine_host`, `unquarantine_host`, `kill_process`, `hunt_across_fleet`, `collect_artifact`는 어느 역할에도 없다 [2].
증거를 모은 뒤 모델에게 요약을 맡기는 호출은 허용 도구를 빈 목록으로 주어 모델에게 도구 정의를 하나도 주지 않는다 [4].
서버에는 이 목록이 없어 다른 MCP 클라이언트로 붙으면 이 방식이 적용되지 않는다 [6].

**한계.** 모델 응답의 도구 호출을 실행하는 반복문은 도구 이름을 허용 목록과 대조하지 않고 `call_tool`에 넘긴다 [7].
`call_tool`도 허용 목록을 확인하지 않고 받은 이름으로 MCP 도구를 부른다 [7].
그래서 모델이 받은 도구 정의에 없는 이름을 도구 호출로 돌려주면 그 도구가 실행된다 [7].
모델이 정의를 받지 않은 도구 이름을 실제로 돌려주는지는 확인하지 못했다.

### T02.03 외부 플랫폼 권한에 위임

**구현.** 이 방식은 모델이 아티팩트 이름이나 VQL 문장을 정하는 `collect_artifact`·`hunt_across_fleet`·`run_vql`에 적용된다 [8][9].
`collect_artifact`는 이름이 형식 검사를 지나면 어느 아티팩트든 대상 단말에서 수집하게 한다 [8].
`hunt_across_fleet`는 같은 방식으로 어느 아티팩트든 여러 단말에 배포한다 [10].
`run_vql`은 `ENABLE_DANGEROUS_TOOLS`가 켜져 있으면 모델이 쓴 VQL 문장을 검사하지 않고 그대로 보낸다 [9].
서버는 이 세 도구가 요청하는 아티팩트와 VQL을 좁히지 않고 API 설정 파일의 인증서로 붙은 계정의 역할 권한이 허용한 작업만 Velociraptor에서 실행되도록 맡긴다 [11].
Velociraptor v0.77.1은 API 질의에 `ANY_QUERY`, 단말 수집에 `COLLECT_CLIENT`, hunt에 `START_HUNT` 권한을 요구한다 [12].
README는 `administrator,api` 역할로 API 설정 파일을 만드는 명령을 안내한다 [13].

**한계.** README가 안내하는 `administrator` 역할은 `ANY_QUERY`·`COLLECT_CLIENT`·`START_HUNT`와 단말에서 명령을 실행하는 아티팩트가 요구하는 `EXECVE`를 가진다 [12].
시험 서버에서 이 역할의 API 설정으로 `collect_artifact`에 `EXECVE`를 요구하는 `Linux.Sys.BashShell`을 주자 단말에서 셸 명령이 실행되었다 [14][15].
API 설정에 준 역할이 이 요청들을 얼마나 막는지는 운영 배포의 설정에 달려 있고 저장소는 `administrator,api` 밖의 역할을 안내하지 않는다 [13].

### T02.04 고정 명령·템플릿

**구현.** 이 방식은 `run_vql`을 뺀 도구 77개가 Velociraptor에 보내는 VQL 문장에 적용된다 [16][17].
VQL 문장의 틀은 서버 코드에 문자열로 적혀 있고 모델이 준 값은 그 틀의 정한 자리에만 들어간다 [16][17].
수집 도구 62개는 `realtime_collection`의 틀을 쓰고 `collect_artifact`를 비롯한 도구 6개는 `start_collection`의 틀을 쓴다 [16][17].
두 틀은 `collect_client(urgent='TRUE', client_id=…, artifacts=…, env=dict(…))` 호출로 수집을 요청한다 [16][17].
`hunt_across_fleet`는 `hunt(description=…, artifacts=…, spec=…, os=…)` 틀을 쓴다 [18].
단말 목록, 조직 목록, 아티팩트 목록, 수집 결과와 hunt 결과를 읽는 도구 8개도 코드에 적은 `SELECT` 틀을 쓴다 [19].
문자열 값은 `vql_literal`이 역슬래시와 작은따옴표 앞에 역슬래시를 붙이고 작은따옴표로 감싸 틀에 넣는다 [20].
논리값, 숫자, `None`, list는 `TRUE`·`FALSE`, 숫자, `null`, 대괄호 목록으로 바꿔 넣는다 [20].
아티팩트 인자의 이름과 열 이름은 따옴표 없이 틀에 들어가고 서버는 그 전에 이름이 영문자, 숫자, `_`(열 이름은 `.`도)만 담는지 검사한다 [20][21].

도구가 아티팩트 인자의 값을 코드에 정해 두는 경우도 있다.
`windows_shadow_copies`는 `Windows.System.WMIQuery`의 `WMIQuery`를 `SELECT * FROM Win32_ShadowCopy`로 정해 두고 모델에게서 질의를 받지 않는다 [22].
`windows_event_log_cleared`와 `windows_powershell_scriptblock`은 `Windows.EventLogs.EvtxHunter`의 `ChannelRegex`와 `IdRegex`를 코드에 정한 값으로 넘긴다 [22].
`collect_file`은 모델이 준 경로를 `[{"glob": path}]` 모양의 JSON 문자열로 감싸 `collectionSpec` 값에 넣는다 [23].
`collect_forensic_triage`는 `Targets`를 `["_BasicCollection"]`으로, `timeout`을 2400으로 정해 둔다 [23].
`quarantine_host`는 `MessageBox`를, `unquarantine_host`는 `RemovePolicy`를 코드에 정한 값으로 넘기고 `kill_process`는 모델에게서 `pid`만 받는다 [23].
`windows_netstat_enriched`는 아티팩트 이름에 source 이름을 붙인 `Windows.Network.NetstatEnriched/Netstat`를 코드에 적어 쓴다 [24].
`linux_file_finder`와 `macos_file_finder`는 `SearchGlob` 값이 있으면 `SearchFilesGlob` 자리에 넣고 `windows_hash_search`는 `SearchGlob`이나 `SearchFilesGlob` 값을 `Glob` 자리에 넣는다 [25].
`windows_event_logs`는 `SearchRegex`를 `IocRegex` 자리에, `EventIDRegex`를 `IdRegex` 자리에 넣고 `SearchVSS`가 참이고 `VSSAnalysisAge`가 0이면 30으로 바꾼다 [26].
`windows_powershell_scriptblock`도 `SearchRegex`를 `IocRegex` 자리에 넣는다 [22].
`windows_mutants`는 `ProcessRegex`를 아티팩트 인자 `processRegex` 자리에 넣고 `MutantNameRegex`가 비면 `MutantRegex` 값을 `MutantNameRegex` 자리에 넣는다 [27].
`windows_powershell_history`는 `SearchRegex`가 기본값 `.`이 아니고 `SearchStrings`가 비었을 때 `SearchRegex` 값을 `SearchStrings` 자리에 넣는다 [27].
`windows_ntfs_mft`는 `Device` 값이 있으면 `MFTDrive` 자리에 넣고 `windows_usn_journal`은 `Device`가 비면 `DriveLetter` 값을 `Device` 자리에 넣는다 [27].

도구는 모델이 주지 않은 인자에도 함수의 기본값을 아티팩트 인자로 넘기고 그 기본값 가운데에는 아티팩트 정의의 기본값보다 범위가 넓은 값이 있다 [28][29].
`linux_file_finder`는 `SearchFilesGlob`을 `/**`로, `LocalFilesystemOnly`를 거짓으로, `ExcludePathRegex`를 빈 문자열로 넘긴다 [28].
Velociraptor v0.77.1의 `Linux.Search.FileFinder` 정의에서 이 세 인자의 기본값은 `/home/*`, `Y`, `^/(proc|sys|run|snap)`이다 [29].
수집 요청에 실린 값은 빈 문자열이어도 정의의 기본값을 대신한다 [30].
실행 확인에서 `SearchFilesGlob`만 `/proc/sys/kernel/**`로 주어 `linux_file_finder`를 부르면 하위 폴더의 파일 21행을 포함한 145행이 왔고 같은 값만 주어 `collect_artifact`로 수집하면 0행이었다 [30].
`macos_file_finder`도 `SearchFilesGlob`의 기본값이 `/**`이고 정의의 기본값이 `Y`인 `DoNotFollowSymlinks`를 거짓으로 넘긴다 [28][29].
`windows_hash_search`는 `Glob`의 기본값이 `C:/**`이고 정의의 기본값이 `N`인 `UPLOAD_IS_RESUMABLE`을 참으로 넘긴다 [28][29].
`yara_scan_files`는 `FileNameRegex`와 `PathRegex`의 기본값이 `.`이고 정의의 기본값은 `^kernel32\.dll$`과 `C:\\Windows\\System32\\`다 [28][29].
`windows_usn_journal`은 정의에 기본값이 없는 `FastPaths`를 참으로 넘기고 정의는 이 인자를 더 빠르지만 덜 정확한 경로 조립 방식으로 설명한다 [28][29].
`windows_ntfs_mft`는 정의의 기본값이 `ntfs`인 `Accessor`를 `auto`로 넘기고 같은 아티팩트를 요청하는 `windows_ntfs_mft_search`는 `Accessor`를 넘기지 않는다 [28][29].
macOS와 Windows 도구가 넘기는 이 기본값의 결과는 단말이 없어 실행으로 확인하지 않았다.

틀에 넣는 값 가운데에는 모델이 쓴 룰과 질의가 있다.
`yara_scan_files`·`yara_scan_process`·`linux_yara_scan`과 `linux_file_finder`·`macos_file_finder`·`windows_hash_search`는 `YaraRule`로 받은 YARA 룰 본문을 아티팩트 인자로 넘긴다 [31].
`windows_browser_history`와 `macos_browser_history`는 `urlSQLQuery`로 받은 SQL 문장을 아티팩트 인자로 넘긴다 [32].
서버는 이 룰 본문과 SQL 문장의 구조나 연산을 검사하지 않는다 [31][32].
`run_vql`은 틀 없이 모델이 쓴 VQL 문장 전체를 보낸다 [9].

### T02.07 사전 등록된 백엔드 작업만 호출

**구현.** 이 방식은 아티팩트 이름을 코드에 적어 둔 도구 67개에 적용된다 [33].
수집 도구 62개와 `collect_file`·`collect_forensic_triage`·`quarantine_host`·`unquarantine_host`·`kill_process`는 도구마다 수집할 아티팩트 이름 하나를 코드에 문자열로 적어 둔다 [33][23].
코드에 적힌 이름은 63개다 [34].
`Windows.EventLogs.EvtxHunter`는 도구 3개가, `Windows.NTFS.MFT`와 `Windows.Remediation.Quarantine`은 도구 2개씩이 함께 쓴다 [34].
이 도구들에는 아티팩트 이름을 받는 인자가 없어 모델은 도구를 골라 그 도구에 정해진 아티팩트를 고르기만 한다 [33].
아티팩트가 단말에서 실행할 VQL은 Velociraptor 서버에 등록된 아티팩트 정의에 있고 저장소에는 아티팩트 정의 파일이 없다.
서버 코드에는 아티팩트 정의를 Velociraptor에 올리거나 고치는 VQL이 없다.

**한계.** `collect_artifact`와 `hunt_across_fleet`는 모델이 준 아티팩트 이름을 형식만 검사해 수집하므로 모델은 이 두 도구로 코드에 적히지 않은 아티팩트도 수집할 수 있다 [8][10].
서버는 코드에 적은 이름이 붙은 Velociraptor 서버에 등록되어 있는지 확인하지 않는다 [16].
Velociraptor v0.77.1 시험 서버의 아티팩트 정의 437개에는 코드에 적은 63개 가운데 13개가 없었다 [34].
`YaraRule`과 `urlSQLQuery`를 받는 도구 8개에서는 모델이 준 값이 그 아티팩트가 실행할 룰과 SQL 문장이 된다 [31][32].

### T02.08 설정으로 도구 끄기

**구현.** 이 방식은 `run_vql`·`quarantine_host`·`kill_process`에 적용된다 [35].
서버는 환경변수 `ENABLE_DANGEROUS_TOOLS`를 모듈을 불러올 때 한 번 읽어 값이 `1`·`true`·`yes`·`on` 가운데 하나일 때만 참으로 둔다 [35].
이 값은 한 번만 읽으므로 서버를 실행하는 동안에는 바뀌지 않는다 [35].
서버는 이 값을 읽기 전에 `.env` 파일을 불러오므로 값은 프로세스 환경이나 `.env` 파일에서 온다 [36].
세 도구는 이 값이 참이 아니면 Velociraptor에 요청하지 않고 사용 설명을 담은 오류를 돌려준다 [37].
세 도구는 이 값과 관계없이 도구로 등록된다 [9].
`example.env`는 이 값의 기본을 `false`로 적고 disruptive 도구를 켠다고 설명한다 [38].
`unquarantine_host`는 `quarantine_host`와 같은 `Windows.Remediation.Quarantine`을 `RemovePolicy=Y`로 수집하지만 이 값을 확인하지 않는다 [23].

**한계.** `collect_artifact`와 `hunt_across_fleet`는 이 값을 확인하지 않고 어느 아티팩트든 수집하게 한다 [8][10].
그래서 `quarantine_host`와 `kill_process`가 쓰는 아티팩트 이름을 이 두 도구에 넘기면 값이 꺼져 있어도 요청이 Velociraptor에 전달된다 [8][10].
값이 꺼진 상태에서 `collect_artifact`에 `Linux.Sys.BashShell`을 주어 직접 실행한 `sleep` 프로세스를 끝냈다 [15].
같은 상태에서 `collect_artifact`에 `Generic.Client.VQL`을 주자 `Command` 인자로 준 VQL 문장이 단말에서 실행되어 결과 행이 왔다 [39].
`collect_artifact`에 `Generic.Utils.KillProcess`를 직접 넘겼을 때 그 아티팩트가 프로세스를 끝내는지는 시험 서버에 그 정의가 없어 확인하지 못했다 [15].

```python
def vql_literal(value: ParameterValue) -> str:
    if isinstance(value, list):
        return "[" + ", ".join(vql_literal(item) for item in value) + "]"
    if value is None:
        return "null"
    if isinstance(value, bool):
        return "TRUE" if value else "FALSE"
    if isinstance(value, (int, float)) and not isinstance(value, bool):
        return str(value)

    escaped = str(value).replace("\\", "\\\\").replace("'", "\\'")
    return f"'{escaped}'"
```

```python
def normalize_env_dict(parameters: Mapping[str, ParameterValue] | None = None) -> str:
    if parameters is None:
        return ""
    if not isinstance(parameters, Mapping):
        raise TypeError("parameters must be a mapping or None")

    items = []
    for key, value in parameters.items():
        if not VALID_PARAMETER_NAME_RE.fullmatch(key):
            raise ValueError(f"Invalid parameter name: {key!r}")
        normalized_value = normalize_parameter_value(value)
        items.append(f"{key}={vql_literal(normalized_value)}")

    return ",".join(items)
```

```python
def normalize_fields(fields: str) -> str:
    cleaned = fields.strip()
    if not cleaned:
        raise ValueError("Fields must not be empty.")
    if cleaned == "*":
        return cleaned

    result = []
    for field in cleaned.split(","):
        candidate = field.strip()
        if not candidate or not VALID_FIELD_RE.fullmatch(candidate):
            raise ValueError(
                "Invalid field selection. Use '*' or a comma-separated list of field "
                "names such as 'Pid, Name, CommandLine'."
            )
        result.append(candidate)

    return ", ".join(result)
```
