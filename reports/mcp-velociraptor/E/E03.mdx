# E03 원본 변경 방지

### E03.03 외부 도구·플랫폼에 위임

**구현.** 이 방식은 단말에서 Velociraptor 아티팩트를 수집하는 도구에 적용된다 [1].
이 서버에서 원본은 Velociraptor 클라이언트가 설치된 단말이다.
서버는 아티팩트 이름과 매개변수를 넣은 `collect_client` VQL을 Velociraptor API로 보내고 단말에서 무엇을 읽고 쓰는지는 아티팩트 정의의 VQL이 정한다 [1].
서버 코드는 아티팩트 이름에 쓰인 글자의 종류만 정규식으로 검사하고 그 아티팩트가 단말을 바꾸는지는 가리지 않는다 [2].

수집 요청을 받을지는 Velociraptor가 API 계정의 권한으로 정한다.
Velociraptor는 수집 요청을 받으면 계정에 `COLLECT_CLIENT` 권한이 있는지 확인하고 아티팩트 정의에 `required_permissions`가 있으면 계정이 그 권한을 모두 가졌는지 확인한다 [3].
계정에 `COLLECT_BASIC` 권한이 있고 아티팩트가 basic으로 표시되어 있으면 Velociraptor는 이 두 확인 없이 요청을 받는다 [3].
README와 `example.env`는 API 계정을 `administrator,api` 역할로 만드는 명령을 안내한다 [4].
Velociraptor의 `administrator` 역할에는 `Execve`·`FilesystemWrite`·`Network`·`MachineState` 권한이 있다 [5].
실행 확인에서 `EXECVE`를 요구하는 `Windows.System.WMIQuery`를 `collect_artifact`로 요청하자 `administrator,api` 계정에서는 flow가 만들어졌고 `investigator,api` 계정에서는 만들어지지 않았다 [6].

서버는 환경변수 `ENABLE_DANGEROUS_TOOLS`가 `1`·`true`·`yes`·`on` 가운데 하나가 아니면 `run_vql`·`quarantine_host`·`kill_process` 세 도구를 실행하지 않고 오류를 돌려준다 [7][8][9].
`quarantine_host`는 `Windows.Remediation.Quarantine`을, `kill_process`는 `Generic.Utils.KillProcess`를 수집하는 도구다 [8].
이 값을 켜면 `run_vql`은 모델이 준 VQL을 검사 없이 Velociraptor API로 보낸다 [9].
실행 확인에서 이 값을 켜지 않은 서버의 세 도구는 같은 오류 문장을 돌려주었다 [10].
이 설정은 도구 세 개를 켜고 끄는 값이고 단말을 바꾸는 요청이 다른 도구로 들어오는 것은 막지 않는다 [7][11].

`collect_artifact`와 `hunt_across_fleet`는 모델이 준 아티팩트 이름과 매개변수를 이 설정을 확인하지 않고 받는다 [11].
그래서 `Windows.Remediation.Quarantine`과 `Generic.Utils.KillProcess`도 두 도구로 요청할 수 있다 [2][11].
`hunt_across_fleet`는 받은 아티팩트로 hunt를 만들어 단말 한 대가 아니라 hunt 조건에 맞는 단말 모두에 수집을 요청한다 [11].
실행 확인에서 이 값을 켜지 않은 서버의 `collect_artifact`에 `Generic.Utils.KillProcess`를 주자 서버는 차단 오류를 내지 않고 Velociraptor에 요청을 보냈다 [12].
같은 서버의 `collect_artifact`에 `Linux.Sys.BashShell`과 `touch` 명령을 담은 `Command` 매개변수를 주자 Linux 단말에 그 파일이 만들어졌다 [13].
`unquarantine_host`는 `Windows.Remediation.Quarantine`을 `RemovePolicy` 매개변수로 수집하고 이 설정을 확인하지 않는다 [8].
`windows_shadow_copies`가 수집하는 `Windows.System.WMIQuery`와 `windows_netstat_enriched`가 수집하는 `Windows.Network.NetstatEnriched`는 정의가 `EXECVE` 권한을 요구하는 아티팩트이고 두 도구도 이 설정을 확인하지 않는다 [14][15].

**한계.** 아티팩트가 단말을 읽기만 하는지는 Velociraptor v0.77.1 시험 서버에 있는 아티팩트 정의에서 확인했다 [15].
서버 코드가 수집 요청에 넣는 아티팩트 이름은 63개이고 그 가운데 50개가 시험 서버에 정의되어 있었다 [15].
50개 가운데 44개는 정의의 VQL에 `execve`·`pskill`·`rm`·`copy`·`write_*`·`reg_set_*`·`reg_rm_*` 호출이 없고 `required_permissions`와 `implied_permissions`가 비어 있었다 [15].
이 확인은 함수 이름을 찾은 것이다.
44개 가운데 8개는 정의의 VQL이 다른 아티팩트를 부르고 불린 아티팩트의 정의는 확인하지 않았다 [15].
그 밖의 VQL 플러그인이 단말의 파일을 어떤 모드로 여는지는 Velociraptor 소스에서 확인하지 못해 실제 보호 미확인이다.

나머지 6개의 정의에는 단말에서 명령을 실행하거나 파일을 쓰는 권한이 적혀 있었다 [15].
`Windows.Remediation.Quarantine`은 `EXECVE`와 `NETWORK`를 요구하고 `execve`를 부른다 [15].
`Windows.Network.NetstatEnriched`는 `KillProcess` 매개변수가 켜지면 결과 행의 프로세스마다 `pskill`을 부른다 [15].
`windows_netstat_enriched`는 이 매개변수를 넘기지 않지만 `collect_artifact`로는 넘길 수 있다 [11][14].
`Windows.System.WMIQuery`는 매개변수로 받은 WMI 질의를 실행하고 `windows_shadow_copies`는 그 질의를 `SELECT * FROM Win32_ShadowCopy`로 정해 둔다 [14][15].
`Linux.Sys.Services`는 `execve`로 `systemctl list-units`를 실행한다 [15].
`Windows.EventLogs.EvtxHunter`와 `Windows.Forensics.SRUM`은 `implied_permissions`에 `FILESYSTEM_WRITE`가 있다 [15].

63개 가운데 13개는 시험 서버에 정의가 없어 실제 보호 미확인이다 [15].
`kill_process`가 수집하는 `Generic.Utils.KillProcess`와 `collect_forensic_triage`가 수집하는 `Windows.Triage.Targets`도 이 13개에 속한다 [15].
Windows와 macOS 단말에서는 수집을 실행하지 않아 그 아티팩트가 단말에 남기는 변화는 확인하지 않았다.
