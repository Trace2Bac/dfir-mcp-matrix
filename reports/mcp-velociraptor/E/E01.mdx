# E01 증거 등록 관리

### 미구현

**판단.** 서버는 Velociraptor에 단말의 아티팩트 수집을 요청하지만 수집 대상이나 수집물을 식별하는 목록이나 등록 정보를 따로 남기지 않는다 [1].
서버의 모듈 수준 값은 gRPC 연결 `stub`과 환경변수에서 읽은 설정, 인자 검사용 정규식뿐이고 도구 처리기는 Velociraptor 질의 결과를 JSON 문자열로 돌려준다 [1].

단말을 등록하고 `client_id`를 매기는 일은 Velociraptor가 한다 [2].
`client_info`와 `list_clients`는 Velociraptor의 `clients()`를 조회해 `client_id`·`FirstSeen`·`LastSeen`·`Hostname`·`Fqdn`·`OSType`·`OS`·`Machine`·`AgentVersion`을 응답으로 돌려준다 [2].
`list_clients`의 응답에는 `LastIP`도 있다 [2].
`client_info`의 응답에는 org가 정해졌으면 `OrgId`가, org가 정해지지 않았고 `search_all_orgs`가 참이면 `OrgId`와 `OrgName`이 더 있다 [3].
서버는 이 조회 결과를 저장하지 않는다 [1].

수집 도구는 `client_id`를 모델이 준 문자열 인자로 받는다 [4].
서버는 이 값을 VQL 문자열로 바꿔 `collect_client` 호출에 넣고 등록된 단말의 값인지 확인하지 않는다 [4].
실행 확인에서 등록되지 않은 `client_id`로 `collect_artifact`를 부르자 Velociraptor가 flow를 만들지 않았고 서버의 응답은 `Failed to start collection: []`였다 [5].

`collect_artifact`·`collect_file`·`collect_forensic_triage`는 수집을 시작하고 Velociraptor가 돌려준 `flow_id`·`artifacts`·`timeout`·`specs`를 응답으로 돌려준다 [6].
`hunt_across_fleet`는 hunt를 시작하고 `hunt_id`와 아티팩트 이름, 매개변수를 응답으로 돌려준다 [7].
아티팩트 하나를 수집해 결과를 바로 돌려주는 도구는 결과 행만 돌려주고 그때 만든 수집의 `flow_id`를 응답에 싣지 않는다 [8].
실행 확인에서 `linux_users` 응답의 행에는 아티팩트의 열만 있었다 [9].
서버는 시작한 수집의 `flow_id`와 대상 `client_id`를 어디에도 적어 두지 않는다 [1].
단말에 시작한 수집의 목록을 조회하는 MCP 도구는 없다.
수집의 기록은 Velociraptor 서버의 flow 기록에 남는다 [10].

```python
def _start_collection_tool(
    client_id: str,
    artifact: str,
    parameters: ArtifactParameters | None = None,
    timeout: int | None = None,
    org_id: str = "",
) -> str:
    try:
        response = start_collection(
            client_id,
            artifact,
            parameters,
            timeout=timeout,
            org_id=org_id,
        )
    except Exception as exc:
        return _json_error(str(exc))

    if not isinstance(response, list) or not response or "flow_id" not in response[0]:
        return _json_error(f"Failed to start collection: {response}")

    return _json_success(response[0])
```
