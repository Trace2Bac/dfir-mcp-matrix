# Camel 원고

이 파일은 서버 개요다. 셀마다 이 폴더 아래 축 폴더의 `<축>/<셀ID>.mdx`에 쓴다.
셀과 상세 항목의 정의는 `matrix/cells/<축>/<셀ID>.mdx`를 따른다.
상세 항목마다 **구현**을 쓰고 그 방식이 적용되지 않는 경로나 조건이 있으면 **한계**를 따로 쓴다.
본문의 [번호]는 그 파일 끝 **근거**의 같은 번호를 가리킨다.

**기준 커밋.** [`63f4cb2`](https://github.com/allisterb/Camel/tree/63f4cb2e26a2469a35f847bee607516cf6184e91)(2026-08-27).
줄 번호는 모두 이 커밋 기준이다.

**범위.** `src/Camel.Server`의 MCP 서버를 본다.
이 서버는 code-mode 서버다. MCP 도구는 `SetCaseId`·`SetEvidence`·`VerifyEvidence`·`Execute` 넷이고 포렌식 분석은 `Execute`가 받아 실행하는 JavaScript가 부르는 SDK(`src/Camel.Toolkits`·`src/Camel.Workflows`·`src/Camel.Environments`, 스크립트에 직접 넣는 `src/Camel.Inference`의 `AnomalyDetectionToolkit`)에서 일어난다.
그래서 SDK의 메서드와 그 아래 실행 환경(로컬·SSH)도 서버 구현으로 본다.
`src/Camel.Training`·`src/Camel.Search`는 서버 프로젝트가 참조하지 않아 범위 밖이다.
`camel create-case`가 사건 폴더에 써 넣는 Claude Code 설정(`src/Camel.CLI/CaseTemplate/`)은 저장소가 함께 내놓는 클라이언트 구성이다.
상세가 클라이언트 쪽 방식을 묻는 경우(예: T02.01·T02.02)에는 이 설정도 구현으로 세고, 다른 클라이언트로 붙으면 적용되지 않는다는 점은 그 상세의 구현 단락에 적는다.
하위 모듈(`ext/Expect.NET`·`ext/protocol-sift-camel`)은 로컬 클론에 받지 않아 그 코드에 기대는 동작은 확인하지 못한 것으로 적는다.

**확인 방법.** 코드는 기준 커밋을 `git show`로 읽었다.

**외부 도구 버전 기준.** 서버는 외부 도구 버전을 대부분 고정하지 않는다.
설정 파일 `src/Camel.CLI/appsettings.json`은 분석 도구의 실행 경로만 적고 버전은 적지 않는다.
README는 요구 사항으로 로컬에 설치했거나 SSH로 접속할 수 있는 SIFT Workstation을 적는다.
SDK의 toolkit은 만들어질 때 `InstallMissingTools`로 워크스테이션에 없는 일부 도구를 설치한다.
apt 패키지 `libbde-tools`·`tshark`·`suricata`·`pst-utils`·`libesedb-utils`·`yara`는 버전 없이 설치하고 hayabusa만 v3.9.0 릴리스 주소로 받는다.
RECmd, RECmd 배치 파일 `DFIRBatch.reb`, `lolbas.json`, Yara-Rules 규칙, Suricata 규칙은 버전 없이 최신 배포본이나 기본 브랜치를 받는다.
SSH 실행 환경을 만드는 `AuditEnvironment.CreateFromConfig`는 대상 OS 버전을 `24.04.4`로 넘긴다.
그래서 기준 커밋 날짜(2026-08-27) 전 마지막 정식 SIFT Workstation 설치 정의인 `teamdfir/sift-saltstack` v2026.04.21을 기준 환경으로 삼는다.
저장소 코드가 버전을 고정한 도구는 그 버전을 먼저 쓴다.
그다음은 SIFT 설치 정의가 고정한 버전, 코드가 전제한 Ubuntu 24.04 저장소의 패키지 버전 차례다.
버전 없이 받는 도구와 자료는 기준 커밋 시각(2026-08-27 08:23Z) 전 마지막 릴리스나 소스 커밋을 쓴다.
이 기준으로 외부 도구의 소스는 아직 확인하지 않았다.
원고에서 외부 도구의 동작을 "확인하지 못했다"고 적은 곳은 이 기준의 소스로 확인할 때까지 그대로 둔다.
