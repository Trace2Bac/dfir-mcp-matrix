# R05 결과 출처 표시

### R05.01 증거·파일 ID

**구현.** 이 절은 SDK 메서드가 Execute 스크립트에 돌려주는 객체를 결과로 본다.
그 객체가 응답 글에 실리는지는 호출자 코드가 정한다.
출처 표시는 SDK가 돌려주는 모델 객체의 필드에 있고 `Execute` 응답에는 스크립트가 그 필드를 출력에 쓸 때만 실린다 [1].
로그 파일 하나를 분석하는 workflow 보고서는 분석한 파일 경로를 필드에 싣는다.
`AnalyzeAuthLogAsync`는 `auth.log`와 `secure` 가운데 읽은 파일의 경로를 `LogPath`에 싣는다 [2].
`AnalyzeWebServerLogsAsync`는 접근 로그 경로를 `LogPath`에 싣는다 [3].
`AnalyzeUsnJournalAsync`는 분석한 `$J` 파일 경로를 `UsnFile`에 싣는다 [3].
workflow의 `Message`는 대개 입력 이미지·캡처 파일 경로를 문장에 넣는다 [4].
`Execute` 응답 끝의 `[audit]` 블록은 사건 ID와 실행 ID를 적는다 [5].
사건 호출 기록 파일의 명령 줄에는 그 실행 ID와 명령 인자의 증거 경로가 함께 남는다 [6].
이 기록은 MCP 도구나 리소스로 조회하지 않고 파일로 읽는다.

참조 지식을 돌려주는 SDK 메서드는 LOLBAS 자료를 읽는 `LoadLolbasAsync`와 내장 프로세스 기대 규칙을 돌려주는 `GetProcessExpectations`다 [7][8].
이 메서드가 돌려주는 `LolbasReference`는 항목 수 `Count`와 조회 메서드 `IsLolbin`·`CanonicalPaths`·`IsCanonicalPath`만 내놓는다 [9].
이 객체에는 LOLBAS 원문 위치도, 자료를 받은 주소나 날짜도, 증거가 아니라는 표시도 없어 R05.05와 R05.06에는 연결하지 않는다 [7][9].
`GetProcessExpectations`는 내장 `process_expectations.yaml`을 읽어 프로세스 이름마다 `ProcessExpectation`을 돌려준다 [8].
이 항목은 규칙마다 자료 이름 `Source`(`MemProcFS`·`SANS`·`Custom` 등)와 메모 `Notes`를 싣는다 [10].
`Source`는 자료 이름이고 원문 주소나 원문 ID가 아니다 [10].
증거가 아니라는 표시도 없어 이 메서드도 R05.05와 R05.06에 해당하지 않는다.
같은 규칙으로 판정한 `ProcessExpectationFinding`에는 `Source`가 없다 [10].

### R05.02 증거 내부 경로

**구현.** 디스크 이미지 안의 파일에서 나온 결과 항목은 그 파일의 경로를 싣는다.
Plaso 사건 `TimelineEvent`는 `Filename`과 `DisplayName`을 싣는다 [11].
EvtxECmd 레코드 `EventLogEntry`는 레코드가 나온 EVTX 파일을 `SourceFile`에 싣는다 [12].
`ListDeletedFilesAsync`의 삭제 파일 항목은 파일 시스템 안 경로 `Path`를 싣는다 [13].
shell 기록 항목은 `HistoryFile`에, 지속성 항목은 `Source`에 파일 경로를 싣는다 [14][15].
마운트한 볼륨에서 읽는 메서드의 경로는 이미지 안 경로 앞에 마운트 폴더가 붙은 값이다 [14].

이상 탐지 결과에는 경로가 없다.
정규화 사건 `CanonicalEvent`는 경로를 몇 가지 위치 범주와 확장자로 줄이고 경로 문자열은 버린다 [16].
`TriageTimelineAsync`의 pivot은 시각·사건 유형·점수·이유만 싣는다 [17].

**한계.** `TriageHostAsync`의 `TopFindings`는 하위 보고서 항목을 한 줄 문자열로 줄이며 인증 로그 항목과 shell 기록 항목에서 파일 경로를 뺀다 [18].
같은 보고서의 하위 보고서 필드에는 경로가 남아 있다 [18].

### R05.03 레코드 키·번호

**구현.** `TimelineEvent`는 Plaso가 낸 `Inode`를 싣는다 [11].
hayabusa 경보 `HayabusaAlert`는 `Computer`·`Channel`·`EventID`·`RecordID`를 싣는다 [19].
`EventLogEntry`는 `RecordNumber`와 `EventRecordId`를 싣는다 [12].
fls 항목과 삭제 파일 항목은 TSK inode 주소 `Inode`를 싣는다 [13][20].

이상 탐지 결과의 `EventIndex`는 서버가 시각순으로 정렬하고 걸러 낸 내부 배열의 위치라 증거 안 레코드가 아니다 [21].

**한계.** `PsortReducedAsync`는 `PsortAsync`와 같은 `TimelineEvent`를 돌려주지만 줄인 내보내기에 inode를 넣지 않는다 [22].
그래서 이 메서드가 돌려준 사건은 `Inode`가 비어 있다 [11][22].

### R05.04 바이트·섹터·행 오프셋

**구현.** foremost로 복구한 파일 항목 `CarvedFile`은 복구 입력 안의 바이트 오프셋 `Offset`을 싣는다 [23].
Linux 메모리의 `LinuxPsScan`은 Volatility가 낸 물리 오프셋을 `Offset`에 싣는다 [24].
이 값은 물리 메모리 안의 위치이고 서버는 메모리 이미지 형식을 가리지 않으므로 LiME나 크래시 덤프처럼 머리말이 있는 형식에서는 이미지 파일 안의 바이트 위치와 다를 수 있다.
shell 기록 항목은 `LineNumber`를 싣는다 [25].

**한계.** `CarveUnallocatedSpaceAsync`는 이미지가 아니라 blkls로 뽑은 비할당 영역 임시 파일을 복구 입력으로 쓴다 [26].
그래서 `Offset`은 그 임시 파일 안의 위치이고 workflow는 끝날 때 그 파일을 지운다 [26].
보고서는 이 오프셋이 이미지 안 위치가 아니라는 것을 알리지 않는다 [26].
photorec으로 복구한 항목은 `Offset`을 채우지 않아 0이 된다 [27].
`LineNumber`는 파일의 줄 번호가 아니라 빈 줄과 bash 시각 줄을 건너뛰고 센 명령 차례다 [25].

```csharp
public class LolbasReference
{
    // Lowercased binary name (e.g. "rundll32.exe") -> its canonical Full_Path entries (normalized).
    private readonly Dictionary<string, string[]> _byName;
    private LolbasReference(Dictionary<string, string[]> byName) => _byName = byName;

    public int Count => _byName.Count;

    /// <summary>True if <paramref name="fileName"/> (a bare binary name) is a known LOLBAS entry.</summary>
    public bool IsLolbin(string fileName) => _byName.ContainsKey(Norm(fileName));

    /// <summary>The canonical install paths LOLBAS records for <paramref name="fileName"/> (empty if unknown).</summary>
    public string[] CanonicalPaths(string fileName) => _byName.TryGetValue(Norm(fileName), out var p) ? p : [];
```

```csharp
    private static IEnumerable<ShellHistoryEntry> ParseShellHistory(string path, string content, string user)
    {
        var lines = content.Split('\n');
        DateTime? pendingTs = null;
        int n = 0;
        for (int idx = 0; idx < lines.Length; idx++)
        {
            var line = lines[idx].TrimEnd('\r');
            if (line.Length == 0) continue;

            // bash HISTTIMEFORMAT marker: a line that is just "#<epoch>" preceding the command.
            if (Regex.IsMatch(line, @"^#\d{9,11}$"))
            {
                pendingTs = DateTime.UnixEpoch.AddSeconds(long.Parse(line[1..]));
                continue;
            }
            // zsh extended history: ": <epoch>:<elapsed>;<command>".
            var z = Regex.Match(line, @"^: (?<ts>\d{9,11}):\d+;(?<cmd>.*)$");
            DateTime? ts = pendingTs;
            string cmd = line;
            if (z.Success) { ts = DateTime.UnixEpoch.AddSeconds(long.Parse(z.Groups["ts"].Value)); cmd = z.Groups["cmd"].Value; }
            pendingTs = null;

            yield return new ShellHistoryEntry
            {
                User = user, HistoryFile = path, LineNumber = ++n, Command = cmd, Timestamp = ts,
            };
        }
```
