# R01 도구 출력 가공

### R01.01 가공 없이 전달

**구현.** 모델이 받는 `Execute` 응답은 스크립트가 `log`·`error`로 쓴 줄을 모은 문자열이다 [1].
SDK 메서드가 돌려준 값은 스크립트 안의 객체로 남고 스크립트가 출력에 쓴 부분만 응답에 실린다 [1].
가공 없이 전달하는 방식은 외부 도구의 출력을 문자열로 돌려주는 SDK 메서드에 있다.
toolkit 공통 함수 `ExecuteToolTextAsync`는 명령이 성공하면 표준 출력을 그대로 돌려준다 [2].
`GrepLinesAsync`는 일치한 줄을 줄 단위로 나눠 바꾸지 않고 돌려준다 [3].
`ReadFilesAsync`는 파일마다 경로와 내용을 짝지어 돌려준다 [4].
스크립트가 이 문자열을 `log`에 넘기면 서버는 바꾸지 않고 응답에 싣는다 [1].

**한계.** `ExecuteToolTextAsync`의 설명은 raw stdout을 돌려준다고 적는다 [2].
SSH 실행 환경은 표준 출력과 표준 오류의 앞뒤 공백을 지운 값을 돌려준다 [5].
그래서 SSH 환경에서는 출력 첫 줄의 들여쓰기와 끝의 빈 줄이 사라진다 [5].

### R01.02 구조화 파싱·필드 선택

**구현.** 대부분의 toolkit 메서드는 외부 도구 출력을 파싱해 필드가 정해진 모델 객체로 돌려준다.
JSON을 내는 도구는 `ExecuteToolAsync`가 표준 출력을 모델 형식으로 역직렬화한다 [6].
JSON lines 출력은 `ParseJsonLines`가 `{`로 시작하는 줄만 골라 역직렬화한다 [7].
CSV 출력은 열 이름으로 나눈 뒤 메서드마다 고른 열만 모델 필드에 옮긴다 [8].
EvtxECmd 레코드는 `EventLogEntry`에 선언한 15개 필드만 남는다 [9].
The Sleuth Kit처럼 글을 내는 도구는 메서드마다 파서가 줄을 나눠 필드로 만든다 [10].
workflow는 toolkit 결과에서 항목을 골라 보고서 모델 `Result`와 요약 문장 `Message`를 담은 `WorkflowResult<T>`로 돌려준다 [11].

`AnalyzeBrowserActivityAsync`는 사용자 프로필 아래에서 Chromium `History`, Firefox `places.sqlite`, `WebCacheV01.dat`를 찾아 URL·제목·방문 수·마지막 방문 시각을 `History`로, Chromium 다운로드를 `Downloads`로 모은다 [12].
`useHindsight`(기본값 거짓)가 참이면 Chrome 사용자 데이터 폴더에 Hindsight를 실행해 그 결과의 URL·제목·시각도 `History`에 더한다 [13].
Chromium `urls`와 Firefox `moz_places` 쿼리는 행마다 방문 수 `visit_count`와 마지막 방문 시각 하나만 읽는다 [14].
그래서 Chromium·Firefox에서 온 `History` 항목은 방문 하나하나의 기록이 아니고 방문 수가 2 이상인 항목의 이전 방문 시각은 결과에 없다 [14].

### R01.03 형식 변환·집계

**구현.** workflow와 이상 탐지 엔진이 출력을 묶어 값을 계산한다.
`AnalyzeWebServerLogsAsync`는 일치한 접근 로그 줄을 분류해 IP별 건수 순위, 범주별 건수, 복호화한 payload 목록을 만든다 [15].
`AnalyzeAuthLogAsync`는 SSH 로그인 성공·실패와 sudo 건수, 실패가 많은 출발 IP 순위를 센다 [16].
`AnomalyDetectionToolkit`은 timeline 사건에 탐지기마다 bit 단위 점수를 매기고 `Summarize`로 순위 목록 글을 만든다 [17].
이 bit는 드문 종류·드문 전이·건수 급증 탐지기에서는 확률에서 구한 surprisal이고 주기적 반복·내용 탐지기에서는 정한 식으로 낸 경험 점수이며 계산은 D06.03에서 본다.
탐지기에 넣기 전에 시각이 0 이하인 사건을 버리고 시간순으로 정렬한다 [18].
`highSignalOnly`가 참이면 EventLog·Registry·WebHistory·Lnk·Prefetch 사건만 남기고 남은 사건끼리 앞 사건과의 간격을 다시 잰다 [18][19].
이 값의 기본값은 workflow `TriageTimelineAsync`에서 참이고 스크립트 전역 `AnomalyDetectionToolkit.TriageTimeline`에서 거짓이다 [20][21].
스크립트의 `table` 함수는 받은 행을 고정 폭 ASCII 표로 바꾸고 칸 안의 줄바꿈·탭을 공백으로 바꾼다 [22].

**한계.** `AnalyzeAuthLogAsync`는 인증 로그에서 일치한 줄을 50,000줄까지만 읽는다 [16].
보고서의 `AcceptedLogins`·`FailedLogins`·`SudoCommands`는 이 줄로 센 값이지만 보고서에는 읽기가 상한에서 멈췄는지 알리는 필드가 없다 [23].
`Message`도 이 값을 로그 전체의 건수처럼 적는다 [23].

### R01.05 가공 사실·대상 표시

**구현.** workflow의 `Message`는 무엇을 어느 입력에서 처리했는지 문장으로 적는다 [23][24].
`AnalyzeAuthLogAsync`의 `Message`는 읽은 로그 경로와 센 건수를 적는다 [23].
`FindMalwareAsync`는 네트워크 단계나 rootkit 단계가 실패하면 그 단계를 건너뛰었다는 문구를 `Message` 끝에 붙인다 [24].
일부 보고서 모델은 처리한 입력 경로를 `LogPath`·`StorageFile` 필드에 싣는다 [25].
`Execute` 응답 끝에는 사건 ID와 실행 ID를 적은 `[audit]` 블록이 별도 content로 붙는다 [26].
사건 호출 기록 파일은 이 실행 ID로 스크립트 원문과 그 스크립트가 실행한 명령 줄을 남긴다 [27].
`Message`와 보고서 필드는 스크립트가 출력에 쓸 때만 응답에 실린다 [1].

**한계.** `TriageHostAsync`는 하위 분석이 실패하면 그 보고서를 `null`로 둔다 [28].
`Message`는 하위 분석의 실패 여부와 관계없이 계정·로그인·지속성·기록·파일을 모두 살폈다고 적는다 [28].

### R01.06 시간 변환 전 값 유지

**구현.** `TimelineEvent`는 Plaso가 낸 정수 시각 `Timestamp`를 바꾸지 않고 싣는다 [29].
`HayabusaAlert`의 `Timestamp`는 hayabusa가 낸 시각 문자열을 그대로 둔다 [30].
`GrepLinesAsync`·`ReadFilesAsync`처럼 줄을 그대로 돌려주는 메서드도 원래 시각 표기를 바꾸지 않는다 [3][4].

EZ Tools 출력을 읽는 모델은 다르다.
Shimcache 모델은 시각 문자열을 `EzParse.ToDate`로 바꾼 `DateTime`만 싣고 원래 문자열은 버린다 [8][31].

`AnalyzeBrowserActivityAsync`는 Chromium의 WebKit 마이크로초와 Firefox의 Unix 마이크로초를 UTC `DateTime`으로 바꾼 값만 `LastVisited`·`StartTime`에 싣고 원래 정수는 버린다 [32][14].
WebKit 값이 0 이하이거나 17,000,000,000,000,000 이상이면 시각을 비운다 [32].
Firefox 값은 0 이하일 때 시각을 비운다 [32].

### R01.07 정규화 시간과 변환 전 값 병기

**구현.** `TimelineEvent`는 원래 정수 `Timestamp` 옆에 그 값을 UTC `DateTimeOffset`으로 바꾼 `Time` 속성을 둔다 [29].
`Time`은 마이크로초 값을 1000으로 나눠 밀리초까지만 남긴다 [29].
`AnalyzeAuthLogAsync`의 `AuthEvent`는 syslog 시각을 바꾼 `Time`과 로그 줄 원문 `Raw`를 한 항목에 싣는다 [33].
syslog 시각에는 연도가 없어 서버가 올해나 작년 연도를 붙인다 [33].
응답은 연도를 가정했다는 것을 알리지 않아 R01.09에는 연결하지 않는다 [33].
`DetectTimelinePivotsAsync`는 hayabusa 경보를 그대로 둔 `Alert`와 그 시각을 바꾼 `PivotTime`을 한 항목에 싣는다 [34].

**한계.** 같은 보고서의 `Findings`에 서버가 만든 무차별 대입 항목은 `Time`이 비어 있고 `Raw`에 로그 줄이 아니라 서버가 쓴 문장이 들어간다 [35].
이 항목도 필드 이름이 `Raw`라 로그 원문 줄과 구별되지 않는다 [35].

### R01.08 시간대·단위·정밀도 표시

**구현.** `TimelineEvent`의 `Time`과 `TimelinePivot`의 `PivotTime`은 오프셋 0의 `DateTimeOffset`이라 값에 UTC가 들어 있다 [29][34].
Shimcache 모델의 `LastModifiedTimeUTC`는 필드 이름에 UTC를 적는다 [8].
`Timestamp`에는 단위와 시간대가 값이나 필드 이름에 없고 모델 주석과 schema 문서에만 UTC 마이크로초라고 적혀 있다 [29][36].

**한계.** 시간대 없는 시각 문자열을 바꾸는 파서는 그 값을 UTC로 가정한다.
`EzParse.ToDate`와 `ParseSyslogTime`은 `AssumeUniversal`로 문자열을 UTC 시각으로 읽는다 [31][33].
syslog 줄의 시각에는 시간대가 없고 서버는 그 호스트의 시간대를 확인하지 않는다 [33].
그래서 호스트 시간대가 UTC가 아니면 `AuthEvent`의 `Time`은 UTC 값으로 보이지만 실제 시각과 다르다 [33].

### R01.10 호출자 코드로 가공

**구현.** `Execute`의 응답은 모델이 보낸 JavaScript가 만든다 [37].
SDK 메서드는 도구 출력을 파싱한 객체를 스크립트에 돌려주고 스크립트가 그 객체에서 무엇을 골라 거르고 요약할지 정한다 [38].
스크립트가 `log()`·`table()` 등으로 출력한 글만 모여 응답의 첫 글 블록이 되고 그 뒤에 실행 ID 블록이 붙는다 [37][39].
서버는 응답 글의 형식·길이·필드를 정하지 않는다 [39].
`Execute` 도구 설명은 스크립트를 쓰기 전에 SDK 메서드 목록과 반환 값의 JSON schema를 담은 리소스를 읽으라고 지시한다 [40].
그래서 이 셀의 다른 상세와 R02~R06은 SDK 메서드가 스크립트에 돌려주는 객체를 기준으로 본다.
그 객체가 응답에 실리는지는 이 코드가 정한다.

    public async Task<string[]?> GrepLinesAsync(string path, IEnumerable<string> patterns, bool ignoreCase = true, int? maxMatches = null)
    {
        var pats = patterns.Where(p => !string.IsNullOrWhiteSpace(p)).ToArray();
        if (pats.Length == 0) return [];
        if (!auditEnvironment.FileExists(path)) return null;

        // Ship the pattern set as a base64 temp file so regex metacharacters never hit the shell; grep -f gives
        // OR semantics across the lines. rc==1 (no match) is normalised to success; rc>=2 (real error) propagates.
        var b64 = Convert.ToBase64String(System.Text.Encoding.UTF8.GetBytes(string.Join("\n", pats)));
        var tmp = "/tmp/camel_grep_" + Guid.NewGuid().ToString("N") + ".pat";
        var flags = ignoreCase ? "-E -i" : "-E";
        var cap = maxMatches is int n and > 0 ? $" | head -n {n}" : "";
        var script = $"echo {b64} | base64 -d > {tmp}; grep {flags} -f {tmp} {Q(path)}{cap}; rc=${{PIPESTATUS[0]}}; rm -f {tmp}; exit $((rc==1?0:rc))";
        var r = await auditEnvironment.ExecuteCommandAsync("bash", $"-c \"{script}\"", false);
        return r.IsCompleted ? r.Output.Split('\n', StringSplitOptions.RemoveEmptyEntries) : null;
    }

    private async Task<List<(string Path, string Content)>> ReadGlobAsync(string glob, bool sudo)
    {
        // Base64 the script so the glob/quoting never fights the SSH command shell (same trick as the EZ-tools
        // downloader). Each file is prefixed with a SOH byte + "<path>\n" then its bytes, so files come back in a
        // single command and split cleanly on the SOH delimiter (which text artifacts never contain).
        var script = $"for f in {glob}; do [ -f \"$f\" ] || continue; printf '\\001%s\\n' \"$f\"; cat -- \"$f\"; done";
        var b64 = Convert.ToBase64String(Encoding.UTF8.GetBytes(script));
        var r = await auditEnvironment.ExecuteCommandAsync("bash", $"-c \"echo {b64} | base64 -d | bash\"", sudo);
        var result = new List<(string, string)>();
        if (!r.IsCompleted || r.Output.Length == 0) return result;
        foreach (var chunk in r.Output.Split('', StringSplitOptions.RemoveEmptyEntries))
        {
            var nl = chunk.IndexOf('\n');
            if (nl < 0) continue;
            result.Add((chunk[..nl], chunk[(nl + 1)..]));
        }
        return result;
    }

    /// <summary>Parses newline-delimited JSON (one object per line) into <typeparamref name="T"/>[].</summary>
    protected static T[] ParseJsonLines<T>(string json) =>
        json.Split('\n', StringSplitOptions.RemoveEmptyEntries | StringSplitOptions.TrimEntries)
            .Select(l => l.TrimStart('﻿'))   // some tools (e.g. EvtxECmd) prefix the file with a BOM
            .Where(l => l.StartsWith('{'))
            .Select(l => System.Text.Json.JsonSerializer.Deserialize<T>(l, JsonLineOptions))
            .Where(x => x is not null).Select(x => x!).ToArray();

    // Parse "MMM d HH:mm:ss" (no year). Attach the most plausible year: this year, or last year if that would put
    // the date in the future (logs near a year boundary). Approximate, used only for ordering.
    private static DateTime? ParseSyslogTime(string ts)
    {
        ts = Regex.Replace(ts.Trim(), @"\s+", " ");
        foreach (var y in new[] { DateTime.UtcNow.Year, DateTime.UtcNow.Year - 1 })
            if (DateTime.TryParseExact($"{ts} {y}", "MMM d HH:mm:ss yyyy", CultureInfo.InvariantCulture,
                    DateTimeStyles.AssumeUniversal | DateTimeStyles.AdjustToUniversal, out var dt) && dt <= DateTime.UtcNow.AddDays(1))
                return dt;
        return null;
    }
