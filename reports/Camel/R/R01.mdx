# R01 결과 가공

### R01.01 가공 없이 전달

**구현.** 모델이 받는 `Execute` 응답은 스크립트가 `log`·`error`로 쓴 줄을 모은 문자열이다 [1].
SDK 메서드가 돌려준 값은 스크립트 안의 객체로 남고 스크립트가 출력에 쓴 부분만 응답에 실린다 [1].
가공 없이 전달하는 방식은 외부 도구의 출력을 문자열로 돌려주는 SDK 메서드에 있다.
toolkit 공통 함수 `ExecuteToolTextAsync`는 명령이 성공하면 표준 출력을 그대로 돌려준다 [2].
`GrepLinesAsync`는 일치한 줄을 줄 단위로 나눠 바꾸지 않고 돌려준다 [3].
`ReadFilesAsync`는 파일마다 경로와 내용을 한 항목에 묶어 돌려준다 [4].
스크립트가 이 문자열을 `log`에 넘기면 서버는 바꾸지 않고 응답에 싣는다 [1].

**한계.** `ExecuteToolTextAsync`의 설명은 raw stdout을 돌려준다고 적는다 [2].
SSH 실행 환경은 표준 출력과 표준 오류의 앞뒤 공백을 지운 값을 돌려준다 [5].
그래서 SSH 환경에서는 출력 첫 줄의 들여쓰기와 끝의 빈 줄이 사라진다 [5].

### R01.02 구조화 파싱·필드 선택

**구현.** 대부분의 toolkit 메서드는 외부 도구 출력을 파싱해 필드가 정해진 모델 객체로 돌려준다.
JSON을 내는 도구는 `ExecuteToolAsync`가 표준 출력을 모델 형식으로 역직렬화한다 [6].
JSON lines 출력은 `ParseJsonLines`가 `{`로 시작하는 줄만 골라 역직렬화한다 [7].
CSV 출력은 열 이름으로 나눈 뒤 메서드마다 고른 열만 모델 필드에 옮긴다 [8].
EvtxECmd 레코드는 `EventLogEntry`에 선언한 15개 필드만 남는다 [9].
The Sleuth Kit처럼 글을 내는 도구는 메서드마다 파서가 줄을 나눠 필드로 만든다 [10].
workflow는 toolkit 결과에서 항목을 골라 보고서 모델 `Result`와 요약 문장 `Message`를 담은 `WorkflowResult<T>`로 돌려준다 [11].

`AnalyzeBrowserActivityAsync`는 사용자 프로필 아래에서 Chromium `History`, Firefox `places.sqlite`, `WebCacheV01.dat`를 찾아 URL·제목·방문 수·마지막 방문 시각을 `History`로, Chromium 다운로드를 `Downloads`로 모은다 [12].
`useHindsight`(기본값 거짓)가 참이면 Chrome 사용자 데이터 폴더에 Hindsight를 실행해 그 결과의 URL·제목·시각도 `History`에 더한다 [13].
Chromium `urls`와 Firefox `moz_places` 쿼리는 행마다 방문 수 `visit_count`와 마지막 방문 시각 하나만 읽는다 [14].
그래서 Chromium·Firefox에서 온 `History` 항목은 방문 하나하나의 기록이 아니고 방문 수가 2 이상인 항목의 이전 방문 시각은 결과에 없다 [14].

### R01.03 형식 변환·건수 집계

**구현.** workflow와 이상 탐지 엔진이 출력을 묶어 값을 계산한다.
`AnalyzeWebServerLogsAsync`는 서명으로 분류한 접근 로그 줄을 묶어 IP별 건수 순위와 범주별 건수를 계산하고 복호화한 payload 목록을 만든다 [15].
`AnalyzeAuthLogAsync`는 SSH 로그인 성공·실패와 sudo 건수, 실패가 많은 출발 IP 순위를 센다 [16].
`AnomalyDetectionToolkit`의 `Summarize`는 이상 탐지 결과를 건수 요약과 탐지기별 건수, 상위 항목 목록을 담은 글로 바꾼다 [17].
스크립트의 `table` 함수는 받은 행을 고정 폭 ASCII 표로 바꾸고 칸 안의 줄바꿈·탭을 공백으로 바꾼다 [18].

**한계.** `AnalyzeAuthLogAsync`는 인증 로그에서 일치한 줄을 50,000줄까지만 읽는다 [16].
보고서의 `AcceptedLogins`·`FailedLogins`·`SudoCommands`는 이 줄로 센 값이지만 보고서에는 읽기가 상한에서 멈췄는지 알리는 필드가 없다 [19].
`Message`도 이 값을 로그 전체의 건수처럼 적는다 [19].

### R01.04 가공 사실·대상 표시

**구현.** workflow의 `Message`는 무엇을 어느 입력에서 처리했는지 문장으로 적는다 [19][20].
`AnalyzeAuthLogAsync`의 `Message`는 읽은 로그 경로와 센 건수를 적는다 [19].
`FindMalwareAsync`는 네트워크 단계나 rootkit 단계가 실패하면 그 단계를 건너뛰었다는 문구를 `Message` 끝에 붙인다 [20].
일부 보고서 모델은 처리한 입력 경로를 `LogPath`·`StorageFile` 필드에 싣는다 [21].
`Execute` 응답 끝에는 사건 ID와 실행 ID를 적은 `[audit]` 블록이 별도 content로 붙는다 [22].
사건 호출 기록 파일은 이 실행 ID로 스크립트 원문과 그 스크립트가 실행한 명령 줄을 남긴다 [23].
`Message`와 보고서 필드는 스크립트가 출력에 쓸 때만 응답에 실린다 [1].

**한계.** `TriageHostAsync`는 하위 분석이 실패하면 그 보고서를 `null`로 둔다 [24].
`Message`는 하위 분석의 실패 여부와 관계없이 계정·로그인·지속성·기록·파일을 모두 살폈다고 적는다 [24].

### R01.05 호출자 코드로 가공

**구현.** `Execute`의 응답은 모델이 보낸 JavaScript가 만든다 [25].
SDK 메서드는 도구 출력을 파싱한 객체를 스크립트에 돌려주고 스크립트가 그 객체에서 무엇을 골라 거르고 요약할지 정한다 [26].
스크립트가 `log()`·`table()` 등으로 출력한 글만 모여 응답의 첫 글 블록이 되고 그 뒤에 실행 ID 블록이 붙는다 [25][27].
서버는 응답 글의 형식·길이·필드를 정하지 않는다 [27].
`Execute` 도구 설명은 스크립트를 쓰기 전에 SDK 메서드 목록과 반환 값의 JSON schema를 담은 리소스를 읽으라고 지시한다 [28].
그래서 이 셀의 다른 상세는 SDK 메서드가 스크립트에 돌려주는 객체를 기준으로 본다.
그 객체가 응답에 실리는지는 이 코드가 정한다.

### R01.06 응답 항목 선별

**구현.** 서버가 정한 규칙으로 응답 목록에 실을 항목을 고르는 곳은 `TriageHostAsync`·`AnalyzeAuthLogAsync`·`BulkExtractorAsync`다 [29][30][31].
`TriageHostAsync`는 하위 분석 보고서 가운데 발견사항이나 의심 항목을 담은 목록만 골라 `TopFindings`에 한 줄씩 모은다 [29].
그 목록은 계정·로그인·인증 로그 분석의 `Findings`, 지속성·shell 기록 분석의 `Suspicious`, 파일 분석의 setuid 파일과 임시 폴더 실행 파일이다 [29].
계정·로그인 항목은 모두 싣고 인증 로그 항목은 10개, 지속성·shell 기록 항목은 15개, 파일 항목은 종류마다 10개까지 싣는다 [29].
항목마다 영역 머리표를 붙여 한 줄 문자열로 바꿀 뿐 하위 분석이 정한 판정을 바꾸거나 더하지 않는다 [29].
`AnalyzeAuthLogAsync`는 파싱한 인증 사건 가운데 `sshd-accepted`·`sshd-failed`·`sudo`·`useradd`·`usermod`·`new-ssh-key` 종류만 늦은 시각 차례로 골라 `Events`에 싣는다 [30].
`BulkExtractorAsync`는 bulk_extractor가 출력 폴더에 쓴 feature 파일 가운데 `*_histogram.txt`·`*_stopped.txt`와 주석이 아닌 줄이 없는 파일을 빼고 남은 파일만 돌려준다 [31].
남은 파일마다 주석이 아닌 줄의 수와 같은 범주 histogram 파일의 앞 5개 값을 싣는다 [31].
이 선별은 SDK 메서드 안에서 일어나므로 호출자 스크립트는 고른 뒤의 배열만 받는다 [31].

`AnalyzeBrowserActivityAsync`는 브라우저 기록을 읽는 SQL에 고정 조건을 넣어 행을 뺀다 [32].
Chromium `History`에서는 `last_visit_time>0`인 URL만, Firefox `places.sqlite`에서는 `last_visit_date IS NOT NULL`인 URL만 읽는다 [32].
읽은 행 가운데 URL이 빈 항목은 기록 목록에 싣지 않는다 [32].
`WebCacheV01.dat` 항목은 컨테이너 이름이 없거나 `History`가 들어 있는 것만 남기고 Hindsight 결과는 `url`과 `timestamp`가 있는 행만 남긴다 [33].

    public async Task<string[]?> GrepLinesAsync(string path, IEnumerable<string> patterns, bool ignoreCase = true, int? maxMatches = null)
    {
        var pats = patterns.Where(p => !string.IsNullOrWhiteSpace(p)).ToArray();
        if (pats.Length == 0) return [];
        if (!auditEnvironment.FileExists(path)) return null;

        // Ship the pattern set as a base64 temp file so regex metacharacters never hit the shell; grep -f gives
        // OR semantics across the lines. rc==1 (no match) is normalised to success; rc>=2 (real error) propagates.
        var b64 = Convert.ToBase64String(System.Text.Encoding.UTF8.GetBytes(string.Join("\n", pats)));
        var tmp = "/tmp/camel_grep_" + Guid.NewGuid().ToString("N") + ".pat";
        var flags = ignoreCase ? "-E -i" : "-E";
        var cap = maxMatches is int n and > 0 ? $" | head -n {n}" : "";
        var script = $"echo {b64} | base64 -d > {tmp}; grep {flags} -f {tmp} {Q(path)}{cap}; rc=${{PIPESTATUS[0]}}; rm -f {tmp}; exit $((rc==1?0:rc))";
        var r = await auditEnvironment.ExecuteCommandAsync("bash", $"-c \"{script}\"", false);
        return r.IsCompleted ? r.Output.Split('\n', StringSplitOptions.RemoveEmptyEntries) : null;
    }

    private async Task<List<(string Path, string Content)>> ReadGlobAsync(string glob, bool sudo)
    {
        // Base64 the script so the glob/quoting never fights the SSH command shell (same trick as the EZ-tools
        // downloader). Each file is prefixed with a SOH byte + "<path>\n" then its bytes, so files come back in a
        // single command and split cleanly on the SOH delimiter (which text artifacts never contain).
        var script = $"for f in {glob}; do [ -f \"$f\" ] || continue; printf '\\001%s\\n' \"$f\"; cat -- \"$f\"; done";
        var b64 = Convert.ToBase64String(Encoding.UTF8.GetBytes(script));
        var r = await auditEnvironment.ExecuteCommandAsync("bash", $"-c \"echo {b64} | base64 -d | bash\"", sudo);
        var result = new List<(string, string)>();
        if (!r.IsCompleted || r.Output.Length == 0) return result;
        foreach (var chunk in r.Output.Split('', StringSplitOptions.RemoveEmptyEntries))
        {
            var nl = chunk.IndexOf('\n');
            if (nl < 0) continue;
            result.Add((chunk[..nl], chunk[(nl + 1)..]));
        }
        return result;
    }

    /// <summary>Parses newline-delimited JSON (one object per line) into <typeparamref name="T"/>[].</summary>
    protected static T[] ParseJsonLines<T>(string json) =>
        json.Split('\n', StringSplitOptions.RemoveEmptyEntries | StringSplitOptions.TrimEntries)
            .Select(l => l.TrimStart('﻿'))   // some tools (e.g. EvtxECmd) prefix the file with a BOM
            .Where(l => l.StartsWith('{'))
            .Select(l => System.Text.Json.JsonSerializer.Deserialize<T>(l, JsonLineOptions))
            .Where(x => x is not null).Select(x => x!).ToArray();
