# L03 기록 실패 처리

### L03.04 알림 없이 계속

**구현.** Camel이 호출 기록을 쓰는 함수는 `AuditEvent`·`AuditExecution`·`AuditCommand` 셋이고 모든 도구와 실행 함수가 이 셋을 거친다(L01) [1].
세 함수는 반환값이 없고 Serilog 기록기 `_auditLogger`에 항목을 넘기는 것으로 끝난다 [1].
기록을 부르는 쪽은 기록 호출을 예외 처리로 감싸지 않고 쓰기 결과도 확인하지 않는다 [2][3].
`Execute`는 실행 전에 `started` 항목을 쓰지만 그 쓰기에 따라 실행을 멈추는 분기가 없다 [2].
명령 실행 함수도 명령을 마친 뒤 `AuditCommand`를 부르고 바로 결과를 돌려준다 [3].

쓰기가 실패할 때의 처리는 `_auditLogger`를 만든 Serilog 구성이 정한다 [4].
`WithAuditLog`는 `WriteTo.Map` 아래에 사건마다 `WriteTo.File` sink를 단다 [4].
Camel은 Serilog 본체를 직접 참조하지 않고 기록 sink 패키지가 Serilog를 끌어온다 [5].
그 패키지들이 요구하는 Serilog의 가장 높은 하한이 4.2.0이라 NuGet은 Serilog 4.2.0을 쓴다 [5][6].
Serilog 4.2.0은 `WriteTo`로 단 sink들을 `SafeAggregateSink`로 묶고 `AuditTo`로 단 sink만 예외를 부른 쪽으로 넘기는 `AggregateSink`로 묶는다 [7].
`SafeAggregateSink`는 sink가 낸 예외를 처리해 내부 진단 출력 `SelfLog`에만 적고 다시 던지지 않는다 [8].
`WriteTo.Map`의 sink는 사건별 파일 sink의 예외를 처리하지 않고 그대로 넘기므로 파일 sink의 예외도 `SafeAggregateSink`에서 멈춘다 [9].
Camel은 `AuditTo`를 쓰지 않고 `SelfLog`의 출력 대상도 정하지 않는다 [4].
그래서 파일을 열거나 쓰지 못해도 도구는 실행을 마치고 결과를 돌려주며 응답과 서버 로그 어디에도 기록 실패가 남지 않는다.

기록기가 없을 때도 세 함수는 `?.` 연산자로 쓰기를 건너뛰고 알리지 않는다 [1].
서버 종료 처리의 `CloseAndFlushAuditLog`가 기록기를 비운 뒤에 끝나는 호출이 이 경우다 [10].

[1] 기록 함수 셋은 반환값 없이 `_auditLogger?.`에 항목을 넘긴다.

```csharp
    [DebuggerStepThrough]
    public static void AuditCommand(string host, string command, string arguments, bool sudo, int? exitCode, long durationMs, bool completed) =>
        _auditLogger?.ForContext("EventType", "command")
            .Information("CMD {Host} {Command} {Arguments} (sudo={Sudo} exit={ExitCode} completed={Completed} {DurationMs}ms)",
                host, command, arguments, sudo, exitCode, completed, durationMs);

    /// <summary>
    /// Records an execution boundary (the <c>Execute</c> code-mode call that frames a set of tool
    /// executions) in the audit trail: the phase (<c>started</c>/<c>completed</c>/<c>failed</c>/<c>cancelled</c>),
    /// the script that ran, and — on completion — success and duration. Lets the trail group a case's tool
    /// executions under the agent step that drove them.
    /// </summary>
    [DebuggerStepThrough]
    public static void AuditExecution(string phase, string? script = null, bool? success = null, long? durationMs = null) =>
        _auditLogger?.ForContext("EventType", "execution")
            .Information("EXECUTION {Phase} (success={Success} {DurationMs}ms)\n{Script}", phase, success, durationMs, script);

    /// <summary>Records an arbitrary audit event (e.g. a case-id change) with a free-form message.</summary>
    [DebuggerStepThrough]
    public static void AuditEvent(string eventType, string messageTemplate, params object[] args) =>
        _auditLogger?.ForContext("EventType", eventType).Information(messageTemplate, args);
```

```csharp
        CallToolResult BuildExitResult()
```

```csharp
        CommandResult? r;
        var sw = System.Diagnostics.Stopwatch.StartNew();
        if (admin)
        {
            if (this.IsUnix)
            {
                r = await this.ExecuteAsync("sudo", command + " " + arguments);
            }
            else throw new NotImplementedException("ExecuteCommandAsAdmin is not implemented for Windows environments.");
        }
        else
        {
            r = await this.ExecuteAsync(command, arguments);
        }
        sw.Stop();
        // Record this command in the per-case audit trail. CaseId/ExecutionId/Toolkit/Operation/Workflow are
        // enriched ambiently from the log context, so this single chokepoint ties every tool execution to the

        if (r.Status == ProcessExecuteStatus.Completed)
        {
            Debug("The command {0} {1} executed successfully. Output: {2}", command, arguments, r.Output);
        }
        else
        {
            Debug("The command {0} {1} did not execute successfully. Output: {2}", command, arguments, r.Output);
        }
        return r;
```

```csharp
    public static void WithAuditLog(string auditDir)
    {
        System.IO.Directory.CreateDirectory(auditDir);
        _auditLogger = new LoggerConfiguration()
            .Enrich.FromLogContext()
            .MinimumLevel.Information()
            .WriteTo.Map(
                keyPropertyName: "CaseId",
                defaultKey: "unknown",
                configure: (caseId, wt) => wt.File(
                    new Serilog.Formatting.Compact.CompactJsonFormatter(),
                    System.IO.Path.Combine(auditDir, $"audit-{SanitizeCaseId(caseId)}.clef")))
            .CreateLogger();
    }
```
