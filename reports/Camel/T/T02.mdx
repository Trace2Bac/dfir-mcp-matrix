# T02 실행 허용 범위 제한

### T02.03 클라이언트 도구 선택

**구현.** `camel create-case`는 사건 폴더에 Claude Code 설정 `.claude/settings.json`을 쓴다 [1].
이 설정은 Camel MCP 도구 4개와 `Read`·`Glob`·`Grep`, `reports`·`exports` 폴더의 `Write`·`Edit`을 허용 목록에 둔다 [2].
거부 목록에는 `Bash`·`WebFetch`·`WebSearch`와 비밀 파일 읽기를 둔다 [2].
저장소 문서는 이 거부 목록으로 셸 도구를 숨겨 분석이 `Execute`만 거치게 한다고 적는다 [3].
Camel 도구 4개는 모두 허용 목록에 들어 있고 이 설정이 숨기는 Camel 도구는 없다 [2].
서버는 연결한 클라이언트와 관계없이 도구 4개를 모두 등록하고 호출할 때 클라이언트를 보지 않는다 [4].
`Execute`가 실행하는 명령의 범위는 이 설정이 아니라 T02.06·T02.08의 서버 쪽 방식이 정한다 [4].
서버에는 이 검사가 없어 다른 MCP 클라이언트나 이 설정이 없는 폴더의 Claude Code로 붙으면 이 제한이 적용되지 않는다 [4].

**예외.** `create-case`는 사건 폴더에 `.claude/settings.json`이 이미 있으면 템플릿을 쓰지 않고 있던 파일을 그대로 둔다 [1].

### T02.10 클라이언트 자체 도구 우회 차단

**구현.** 이 방식은 `camel create-case`가 사건 폴더에 쓰는 Claude Code 설정 `.claude/settings.json`에 있다 [1].
이 설정은 거부 목록에 `Bash`·`WebFetch`·`WebSearch`를 두어 Claude Code 세션이 셸로 포렌식 도구를 직접 실행하지 못하게 한다 [2].
저장소 문서는 이 거부로 포렌식 도구를 Camel SDK로만 부르게 하고 상위 설정이 허용해도 거부가 앞선다고 적는다 [3].
`Read`·`Glob`·`Grep`은 경로 조건 없이 허용 목록에 있고 거부 목록은 `secrets/` 아래와 `.key`·`.pem` 파일 읽기만 막는다 [2].
그래서 모델은 서버 호출 기록 `logs/audit-<사건 ID>.clef`를 비롯한 사건 폴더의 파일을 클라이언트 도구로 직접 읽을 수 있다 [2][5].
`Write`·`Edit`은 `reports`·`exports` 폴더만 허용 목록에 두고 다른 경로의 쓰기는 거부 목록에 두지 않는다 [2].
설정의 `defaultMode`는 `acceptEdits`다 [2].
서버는 `create-case`가 넘긴 `--case-dir`의 `logs/`에 호출 기록을 쓰고 이 폴더의 쓰기도 거부 목록에 없다 [5].
같은 설정의 Stop·SessionEnd 훅 `preserve-chatlog`는 클라이언트 대화 기록을 `logs/`로 복사하고 보고서 화면을 다시 만들 뿐 도구 호출을 막지 않는다 [6].
서버에는 이 검사가 없어 다른 MCP 클라이언트나 이 설정이 없는 폴더의 Claude Code로 붙으면 적용되지 않는다 [4].
`create-case`가 쓰는 `.mcp.json`에는 `camel` 서버 하나만 있고 허용·거부 목록은 다른 MCP 서버의 도구를 다루지 않는다 [2][7].

**예외.** `create-case`는 사건 폴더에 `.claude/settings.json`이 이미 있으면 템플릿을 쓰지 않으므로 그 폴더에는 이 거부 목록이 적용되지 않는다 [1].
거부 목록에는 `.claude/settings.json` 자체의 쓰기도 없다 [2].
`acceptEdits` 모드의 Claude Code가 모델이 `Edit`으로 이 설정 파일의 거부 목록을 지우는 것을 허용하는지는 확인하지 못했다 [2].

### T02.06 고정 명령·템플릿

**구현.** SDK 툴킷 메서드는 실행 파일과 인자 틀을 정해 두고 스크립트가 넘긴 값을 그 틀의 칸에 넣는다 [8][9].
실행 파일 경로와 `sudo` 여부는 툴킷마다 `appsettings.json`의 `Tools:<툴킷>:<도구>:Command`·`Sudo`에서 읽는다 [8].
예를 들어 `FlsAsync`는 `fls` 뒤에 선택 옵션과 이미지 경로, inode를 두고 `WindowsPsListAsync`는 Volatility 3에 `-f` 뒤의 메모리 이미지 경로와 플러그인 `windows.pslist`를 넘긴다 [9].
툴킷 메서드는 플러그인·모드를 메서드마다 고정해 스크립트가 플러그인 이름을 고르지 않는다 [9].
`RegRipperAsync`의 `plugin`처럼 실행할 연산을 값으로 받는 메서드도 있고 그 값을 목록과 대조하지 않는다 [10].
명령은 인자 목록이 아니라 한 줄 문자열로 만들어져 셸이 해석한다(T04.03) [11].

**예외.** `DiskAnalysis`·`WindowsAnalysis`·`Timeline`·`UnixTools`·`Yara` 툴킷의 따옴표 함수 `Q`는 값을 작은따옴표로 감싸기만 하고 값 안의 작은따옴표를 바꾸지 않는다 [12].
`MemoryAnalysis`·`LinuxAnalysis`·`PacketAnalysis` 툴킷의 `Q`는 작은따옴표를 바꿔 쓴다 [12].
`MemoryAnalysisToolkit`의 Volatility 메서드는 이미지 경로 `filename`을 `Q` 없이 `-f` 뒤에 붙인다 [13].
`ForemostAsync`의 `fileTypes`, `MactimeAsync`의 `timezone`, `RegRipperAsync`의 `plugin`, `PacketAnalysisToolkit.FieldsAsync`의 `fields`도 따옴표 없이 명령 문자열에 들어간다 [13].
이 값에 작은따옴표·공백·`;`·`$()`가 들어가면 셸이 명령의 구조를 바꿔 읽는다 [11][12][13].
실제 도구로 실행해 보지는 않았다.

### T02.08 질의 구조·연산 검사

**구현.** `Execute`는 모델이 쓴 JavaScript를 Jint 엔진으로 실행하고 엔진 설정 `StringCompilationAllowed = false`로 `eval`·`new Function` 같은 문자열 코드 생성을 끈다 [14].
엔진 설정에는 스크립트가 .NET 형식·네임스페이스에 직접 닿게 하는 설정(`AllowClr` 등)이 없다 [14].
스크립트가 부를 수 있는 이름은 서버가 엔진에 넣은 전역이다 [15].
전역은 출력·호출 기록 함수, `Session` 저장소, 작업 흐름 8개, `AnomalyDetectionToolkit`, 스크립트 본문에 이름이 나온 툴킷 8개 가운데 해당하는 것이다 [15].
저장소 문서는 이 구성으로 스크립트가 SDK 밖의 파일·네트워크·운영체제에 닿지 못한다고 적는다 [16].

`WindowsAnalysisToolkit.SqliteQueryAsync`는 모델이 쓴 SQL을 DB 사본에 `sqlite3 -readonly`로 실행해 쓰기 연산을 SQLite가 거부하게 한다 [17].
`PacketAnalysisToolkit.FieldsAsync`의 tshark 표시 필터와 `YaraToolkit.ScanAsync`의 룰 파일은 구조를 검사하지 않고 도구에 넘긴다 [18].

**예외.** 툴킷 기반 클래스는 실행 환경을 public 필드 `auditEnvironment`로 둔다 [19].
실행 환경의 `ExecuteCommandAsync`는 명령 이름·인자 문자열·`admin`(sudo) 여부를 받는 public 메서드다 [19].
툴킷의 `ExecuteToolTextAsync`도 public 메서드라 설정에 있는 도구를 임의의 인자로 실행한다 [20].
엔진 설정에는 바인딩한 객체의 public 필드·메서드를 숨기는 설정이 없다 [14].
고정 Jint 4.9.2 소스상 엔진은 묶은 객체의 공개 필드를 거르지 않고 드러내므로 스크립트는 `DiskAnalysisToolkit.auditEnvironment`를 거쳐 SDK 밖의 명령을 실행할 수 있다 [14][19][21].
이 경로를 실제로 실행해 시험하지는 않았다.
`sqlite3`가 SQL 인자로 받은 점 명령(`.shell` 등)을 실행하는지도 확인하지 못했다 [17].

    {

        await auditEnvironment.ExecuteCommandAsync("mkdir", $"-p {dir}", false);
        try
        {
            // Stage the DB plus any WAL/journal sidecars so sqlite3 can open it read-write off the read-only mount.
            await auditEnvironment.ExecuteCommandAsync("bash", $"-c \"cp {Q(dbFile)} {Q(dbFile)}-wal {Q(dbFile)}-shm {Q(dbFile)}-journal {dir}/ 2>/dev/null; true\"", false);

            var b64 = Convert.ToBase64String(System.Text.Encoding.UTF8.GetBytes(sql));
            // Ship the SQL base64-encoded to dodge all shell quoting of quotes/semicolons in the query.
            var r = await auditEnvironment.ExecuteCommandAsync("bash",
                $"-c \"sqlite3 -readonly -json {Q(staged)} \\\"$(echo {b64} | base64 -d)\\\"\"", false);

            if (json.Length == 0) return [];   // sqlite3 prints nothing for an empty result set
            return System.Text.Json.JsonSerializer.Deserialize<Dictionary<string, System.Text.Json.JsonElement>[]>(json, JsonLineOptionsPublic) ?? [];
        }
        catch { return []; }
        finally { try { auditEnvironment.ExecuteCommand("rm", $"-rf {dir}", out _, false); } catch { } }
