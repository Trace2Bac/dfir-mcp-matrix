# T04 실행 방식

### T04.01 서버 프로세스 안 라이브러리 호출

**구현.** `Execute`는 모델이 쓴 JavaScript를 서버 프로세스 안의 Jint 엔진에서 실행한다 [1].
`AnomalyDetectionToolkit`은 실행 환경 없이 서버 프로세스 안에서 시간선 사건을 계산하는 순수 계산 객체로 엔진에 들어간다 [2].
툴킷은 외부 도구의 출력을 서버 프로세스에서 JSON·CSV·텍스트로 파싱하고 작업 흐름은 그 결과를 서버 프로세스에서 묶어 판정한다 [3].
SSH 환경에서는 큰 출력 파일을 SCP로 서버 호스트에 내려받아 서버 프로세스가 읽는다 [3].

### T04.02 같은 권한의 별도 프로세스

**구현.** 이 방식은 Windows에서 실행되는 로컬 실행 환경에만 있다 [4].
Unix가 아니면 `NewProcessStartInfo`는 셸을 거치지 않고 명령을 실행 파일로, 인자 문자열을 `Arguments`로 둔 `ProcessStartInfo`를 만든다 [4].
로컬 환경의 `Execute`·`ExecuteAsync`는 `UseShellExecute`를 끄고 그 실행 파일을 서버와 같은 계정의 자식 프로세스로 실행한다 [5].
증거 해시를 계산할 때 Windows에서는 이 경로로 `certutil -hashfile`을 실행한다 [6].
저장소 설정의 도구 경로는 모두 Linux 경로이고 `sudo` 실행은 Windows에서 예외를 낸다 [7][8].
그래서 툴킷의 외부 도구를 Windows 로컬 환경에서 그대로 쓸 수 있는지는 이 실행 방식과 별개이고 실행해 보지 않아 확인하지 못했다.
Unix 로컬 환경과 SSH 환경은 셸 명령 문자열로 실행하며 T04.03에서 본다.

### T04.03 셸 명령 문자열 실행

**구현.** 툴킷의 외부 도구 실행은 모두 실행 환경의 `Execute`·`ExecuteAsync`로 모인다 [7].
로컬 환경은 Unix에서 명령과 인자를 한 문자열로 이어 `/bin/bash -c`의 인자 하나로 넘긴다 [4].
SSH 환경은 같은 문자열을 원격 호스트의 명령으로 실행해 원격 셸이 해석한다 [9].
툴킷은 이 셸 해석에 기대어 `>` 출력 방향 바꾸기, 파이프, `$(...)`, base64로 보낸 셸 스크립트를 명령에 쓴다 [10].
스크립트가 넘긴 경로·문자열 값이 이 명령 문자열에 들어간다.
MCP 도구 `SetEvidence`·`VerifyEvidence`가 받은 증거 경로도 SSH 환경의 `stat` 명령과 해시 명령 문자열에 들어가 셸이 해석한다 [11].

`sudo`로 도구의 권한을 바꾸는 경우는 T04.04에서 본다 [7].
툴킷이 쓰는 임시 폴더(`/tmp/camel_ez_*` 등)는 출력 파일을 받는 곳이고 도구의 작업 위치로 쓰지 않아 T04.05에는 연결하지 않는다 [12].

### T04.04 권한을 나눈 실행

**구현.** 이 방식은 설정 `Sudo`가 참인 도구와 호출 인자 `sudo`를 받는 툴킷 메서드의 호출에 적용된다 [8][13].
`admin`이 참이면 실행 환경은 명령 앞에 `sudo`를 붙여 그 도구를 접속 계정과 달리 root 권한으로 실행한다 [7].
도구마다 `sudo` 여부는 설정 `Sudo`에서 정하고 디스크·메모리·리눅스 도구 다수가 `true`다 [8].
`UnixToolsToolkit`·`LinuxAnalysisToolkit`·`PacketAnalysisToolkit`과 디스크 카빙 메서드는 설정 값과 호출 인자 `sudo` 가운데 하나라도 참이면 `sudo`를 붙인다 [13].
호출 인자로는 권한을 높이는 쪽만 고를 수 있고 설정 `Sudo`가 참인 도구를 낮춰 실행하지는 못한다 [13].
권한을 높이는 방향만 있고 권한을 낮추거나 다른 일반 계정으로 바꾸는 코드는 없다.
설정 `Sudo`가 거짓인 도구는 접속 계정 권한으로 실행되고 T04.03에 해당한다 [8].

### T04.07 SSH 원격 호스트 명령 실행

**구현.** 실행 환경은 설정 `SIFT:Environment`가 `Ssh`이면 `SshAuditEnvironment`, `Local`이면 `LocalEnvironment`로 만든다 [14].
저장소의 `appsettings.json`은 `Ssh`를 기본값으로 두고 접속할 SIFT 워크스테이션의 호스트·포트·계정·비밀번호를 설정에서 읽는다 [15].
`camel` CLI의 `--ssh`·`--local`·`--host` 등 시작 인자로 사용자가 이 값을 바꾼다 [16].
SSH 환경은 비밀번호 인증으로 접속하고 모든 외부 도구를 그 계정 권한으로 원격 호스트에서 실행한다 [17][9].
저장소 문서는 이 구성을 Camel이 다른 기계에서 실행되며 원격 SIFT 워크스테이션을 SSH로 다루는 방식으로 적는다 [18].
그래서 분석 도구는 서버 호스트의 파일·프로세스와 떨어진 기계에서 실행된다.
원격 호스트 안에서는 도구가 같은 계정과 `sudo`로 증거·마운트 지점·임시 폴더에 함께 닿는다 [7][8].
세션마다 실행 환경과 SSH 연결을 따로 만들지만 같은 접속 계정을 쓴다 [19].

    protected static T[] ParseJsonLines<T>(string json) =>
        json.Split('\n', StringSplitOptions.RemoveEmptyEntries | StringSplitOptions.TrimEntries)
            .Select(l => l.TrimStart('﻿'))   // some tools (e.g. EvtxECmd) prefix the file with a BOM

    /// <summary>
    /// Builds the <see cref="ProcessStartInfo"/> for a command. On Unix the toolkits compose <em>bash command
    /// lines</em> — globs, pipes (<c>| head</c>), redirects (<c>&gt; file</c>), command substitution (<c>$(...)</c>),
    /// single/double quoting, and escaped grouping (<c>\( \)</c>, e.g. in <c>find</c>). The SSH environment runs
    /// these by handing <c>"&lt;command&gt; &lt;arguments&gt;"</c> to the remote shell, so the local environment must
    /// do the same or those shell constructs are passed to the tool literally and fail (e.g. <c>FindFilesAsync</c>).
    /// We therefore run the line through <c>/bin/bash -c</c>, passing it as a single argv entry (ArgumentList) so no
    /// second round of quoting is applied. On Windows the tools are native executables (e.g. vol.exe) and this Unix
    /// shell syntax would not apply, so the command is executed directly as before.
    /// </summary>
    private ProcessStartInfo NewProcessStartInfo(string command, string arguments)
    {
        if (this.IsUnix)
        {
            var psi = new ProcessStartInfo("/bin/bash");
            psi.ArgumentList.Add("-c");
            psi.ArgumentList.Add(string.IsNullOrEmpty(arguments) ? command : command + " " + arguments);
            return psi;
        }
        return new ProcessStartInfo(command) { Arguments = arguments };
    }

    public static AuditEnvironment CreateFromConfig(IConfigurationRoot config)
    {
        var environmentType = Enum.Parse<EnvironmentType>(GetRequiredValue(config, "SIFT:Environment"));
        // Optional cap on concurrent async executions (0/absent = unlimited).
        int maxConcurrent = int.TryParse(config["SIFT:MaxConcurrentExecutions"], out var n) ? n : 0;
        AuditEnvironment env;
        if (environmentType == EnvironmentType.Local)
        {
            env = new LocalEnvironment();
        }
        else if (environmentType == EnvironmentType.Ssh)
        {
            var host = GetRequiredValue(config, "SIFT:Host");
            var port = Int32.Parse(GetRequiredValue(config, "SIFT:Port"));
            var user = GetRequiredValue(config, "SIFT:User");
            var password = GetRequiredValue(config, "SIFT:Password");
            env = new SshAuditEnvironment("camel", host, port, user, password, new OperatingSystem(PlatformID.Unix, new Version("24.04.4")), new LocalEnvironment());
        }
        else throw new Exception($"Invalid environment type specified in configuration: {environmentType.ToString()}");
        env.MaxConcurrentExecutions = maxConcurrent;
        return env;
    }
