# T07 도구 부재 처리

### T07.04 알림 없는 대체 실행

**구현.** `DiskAnalysisWorkflow.MountFileSystemAsync`는 NTFS 볼륨을 커널 드라이버 loopback 마운트로 먼저 마운트하고 실패하면 `ntfs-3g`의 `force` 마운트로 다시 시도한다 [1].
코드 주석은 두 번째 경로가 커널 드라이버가 거부한 더티·최대 절전 상태 볼륨을 위한 것이라고 적는다 [1].
성공 결과는 파일시스템 종류·마운트 위치·오프셋만 담고 어느 경로로 마운트했는지 밝히지 않는다 [1][2].

실행 환경의 파일 해시 계산은 해시 명령이 실패하면 같은 명령을 `sudo`로 다시 실행하고 `ewfverify`도 같은 방식으로 다시 실행한다 [3].
`VerifyEvidence` 응답 줄은 해시 값과 일치 여부만 적고 다시 실행했는지는 적지 않는다 [4].
호출 기록의 명령 항목에는 두 실행이 `sudo` 값과 함께 따로 남아 다시 실행한 것을 짐작할 수 있다 [5].
`WindowsAnalysisToolkit.ScheduledTasksAsync`는 작업 파일을 UTF-16에서 UTF-8로 바꾸지 못하면 원래 바이트를 그대로 읽고 어느 파일이 그랬는지 남기지 않는다 [6].

### T07.05 실행 환경별 경로 분기

**구현.** 로컬 환경은 Unix에서 명령을 `/bin/bash -c`로 실행하고 Windows에서는 실행 파일을 직접 실행한다 [7].
증거 해시 계산은 Windows면 `certutil`, Unix면 `md5sum`·`sha1sum`·`sha256sum`을 쓴다 [3].
고른 명령은 호출 기록의 명령 항목에 남고 응답에는 실리지 않는다 [4][5].

### T07.08 실행 전 부재 도구 자동 설치

**구현.** 툴킷 기반 클래스의 생성자는 도구 정의를 읽은 뒤 `InstallMissingTools`를 부른다 [8].
`DiskAnalysis`·`WindowsAnalysis`·`Timeline`·`Yara`·`PacketAnalysis` 툴킷이 이 함수를 덮어써 정해 둔 도구·참조 자료를 설치한다 [9].
설치 함수는 원격 호스트에서 `test -e`로 정해 둔 경로가 있는지 보고 없을 때만 `apt-get install`이나 `wget` 내려받기와 압축 풀기로 설치한다 [10].
설치 명령 다수는 `sudo`로 실행되고 인터넷에서 파일을 받는다 [10].
툴킷은 스크립트 본문에 그 이름이 나오거나 작업 흐름이 처음 닿을 때 세션마다 한 번 만들어지고 확인과 설치도 그때 한 번 일어난다 [11].
확인 대상은 설치 함수에 준 경로 하나다(예: `pst-utils`는 `/usr/bin/readpst`, Yara-Rules 룰 묶음은 `index.yar`) [9].
설치 대상이 아닌 도구(Volatility 3, Plaso, Sleuth Kit, 대부분의 EZ 도구)는 있는지 보지 않고 실행해 실패하면 `null`을 돌려준다 [12].
메모리 작업 흐름의 실패 문구는 이미지를 읽지 못했거나 심볼이 없을 수 있다고 적지만 무엇이 없는지 가리지 않아 T07.02에는 연결하지 않는다 [13].

**한계.** 설치 함수는 실패하면 서버 로그에 `Error`를 남기고 `false`를 돌려주지만 생성자는 그 값을 보지 않고 툴킷을 만든다 [8][10].
그 도구를 쓰는 메서드는 실행에 실패해 `null`을 돌려주고 응답에는 설치에 실패했다는 사실이 실리지 않는다 [12].
`PacketAnalysisToolkit`은 Suricata 룰 파일이 없을 때 `suricata-update`를 부르지만 결과를 보지 않아 룰을 받지 못해도 알리지 않고 Suricata를 실행한다 [14].

    {
        if (IsWindows)
        {
            var alg = type switch { HashType.MD5 => "MD5", HashType.SHA256 => "SHA256", _ => "SHA1" };
            var rw = await ExecuteCommandAsync("certutil", $"-hashfile \"{path}\" {alg}");

    private async Task<string> ComputeEwfContentHashAsync(string path, HashType type)
    {
        var algo = type switch { HashType.MD5 => "md5", HashType.SHA256 => "sha256", _ => "sha1" };
        // -q keeps the progress chatter down but still prints the hash summary; -d adds the non-MD5 digest.
        var args = (type == HashType.MD5 ? "" : $"-d {algo} ") + $"-q '{path}'";
        var hash = ParseEwfDigest((await ExecuteCommandAsync("ewfverify", args)).Output, algo);
        if (hash.Length == 0 && IsUnix)
            hash = ParseEwfDigest((await ExecuteCommandAsync("ewfverify", args, admin: true)).Output, algo);
        return hash;

        // can run one-time provisioning (Toolkit.InstallMissingTools = synchronous wget/apt for the EZ tools,
        // YARA rules pack, hayabusa, …). Binding every toolkit on every call would make the first call in a fresh
        // session block on installing tools the script never uses — e.g. a mount-only script (DiskAnalysis only)
        // would otherwise stall on the YARA/hayabusa downloads and exceed the client's tool timeout. Workflows

        void BindToolkitIfUsed(string name, Func<object> resolve)
