# T01 입력 검증

### T01.01 인자 구조·값 검사

**구현.** MCP 도구 `SetCaseId`는 빈 사건 ID를 받으면 세션 ID로 바꿔 쓴다 [1].
스크립트가 부르는 SDK 메서드 가운데 실행 전에 인자 값을 검사하는 것은 일부다.
`WindowsAnalysisToolkit`의 `MFTECmdCsvAsync`·`EvtxECmdAsync` 등은 출력 위치나 입력 파일·폴더 가운데 하나도 받지 못하면 `ArgumentException`을 던져 도구를 부르지 않는다 [2].
`TimelineAnalysisWorkflow.SearchTimelineAsync`는 검색어가 비어 있으면 psort를 부르지 않고 실패 결과를 돌려준다 [3].
나머지 SDK 메서드는 경로·문자열 인자의 형식이나 범위를 보지 않고 명령 문자열에 넣는다 [4].
`Execute`의 `script` 인자는 JavaScript 문자열 전체이고 서버는 그 내용을 검사하지 않고 엔진에 넘긴다 [5].

**한계.** 툴킷 기반 클래스의 `ExecuteToolTextAsync`·`ExecuteToolAsync`는 public 메서드이고 설정에 있는 도구 이름과 인자 문자열을 받아 검사 없이 실행한다 [6].
이 메서드로 `MFTECmd`·`EvtxECmd`를 부르면 위의 필수 인자 검사를 거치지 않는다 [2][6].
엔진 설정에는 바인딩한 .NET 객체의 public 메서드를 스크립트에서 숨기는 설정이 없다 [5].
스크립트가 이 메서드를 실제로 부를 수 있는지는 실행해 보지 않아 확인하지 못했다.

### T01.02 입력 존재·읽기 가능 검사

**구현.** `SetEvidence`는 등록하기 전에 실행 환경에서 증거 경로마다 파일이나 폴더가 있는지 보고 하나라도 없으면 등록하지 않고 오류를 돌려준다 [7][8].
SSH 환경은 이 확인을 원격 호스트의 `stat`으로 한다 [9].
SDK에서는 `DiskAnalysisToolkit.GrepLinesAsync`가 대상 파일이 없으면 `grep`을 부르지 않고 `null`을 돌려준다 [10].
`DiskAnalysisWorkflow.MountEwfImageAsync`는 `ewfinfo`로 이미지 정보를 먼저 읽고 실패하면 `ewfmount`를 부르지 않는다 [11].
`MountFileSystemAsync`는 `fsstat`이 그 위치에서 파일시스템 종류를 읽지 못하면 마운트하지 않는다 [11].
다른 SDK 메서드는 입력이 있는지 보지 않고 도구를 실행해 실패하면 `null`을 돌려준다 [6].

`SetEvidence`로 등록한 목록은 쓰기·삭제 대상이 증거인지 대조할 때만 쓰고 읽기 입력을 그 목록으로 좁히지 않는다 [12].
`LinuxAnalysisToolkit`의 `LastLoginsAsync`·`FailedLoginsAsync`는 경로를 주지 않으면 `rootDir` 기본값 `/` 아래의 `var/log/wtmp`·`var/log/btmp`를 읽고 `sudo` 기본값도 참이다 [13].
그래서 경로 없이 부르면 증거가 아니라 실행 환경 자신의 로그인 기록을 root 권한으로 읽는다 [13].
SSH 환경에서는 SIFT 워크스테이션의 기록이고 로컬 환경에서는 서버 호스트의 기록이다.
`AnalyzeLoginActivityAsync`는 마운트한 루트 아래 경로를 넘기지만 스크립트는 이름을 적은 `LinuxAnalysisToolkit`으로 두 메서드를 직접 부를 수 있다 [14].
읽기 경로를 실제 경로로 변환하거나 허용 폴더와 대조하는 코드는 없어 T01.04~T01.07에는 연결하지 않는다 [4].
