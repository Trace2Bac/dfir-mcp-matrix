# T05 분석 도구 검증

### T05.01 선언: 저장소·의존성 고정

**구현.** 이 방식은 판정 기대값 자료와 hayabusa 설치에 적용된다 [1][2].
작업 흐름이 프로세스 판정에 쓰는 기대값 자료 `process_expectations.yaml`은 저장소에 두고 어셈블리 리소스로 넣는다 [1].
툴킷이 원격 호스트에 없을 때 설치하는 도구 가운데 hayabusa는 내려받기 주소에 `v3.9.0` 버전을 적는다 [2].

그 밖의 설치는 버전을 고정하지 않는다.
`WindowsAnalysisToolkit`은 RECmd를 `net9` 최신 zip으로, `DFIRBatch.reb`를 `master` 가지에서, LOLBAS 자료를 공개 API의 현재 파일로 받는다 [3].
`YaraToolkit`은 Yara-Rules 룰 묶음을 `master` 가지 zip으로 받는다 [3].
`InstallAptPackage`는 버전 없이 `apt-get install -y`를 부르고 `PacketAnalysisToolkit`은 그때의 Suricata ET open 룰을 `suricata-update`로 받는다 [4].
내려받은 파일의 해시를 대조하는 코드는 없다 [3][4].
서버가 불러오는 .NET 라이브러리는 프로젝트 파일에 정확한 버전으로 적지만(`Jint` 4.9.2, `ModelContextProtocol` 1.4.0, `SSH.NET` 2025.1.0 등) 증거를 해석하지 않는 서버 실행용이라 이 방식으로 세지 않는다 [5].
SIFT 워크스테이션에 미리 깔린 Volatility 3·Plaso·Sleuth Kit·EZ 도구의 버전은 저장소가 정하지 않는다(T05.02).

**예외.** hayabusa 설치 함수는 `/usr/local/bin/hayabusa`가 이미 있으면 버전을 보지 않고 설치를 건너뛴다 [6].
도구 설정도 같은 경로를 실행하므로 워크스테이션에 먼저 있던 다른 버전의 hayabusa가 쓰일 수 있다 [6].

### T05.02 선언: 설정·호출 인자 지정

**구현.** 툴킷은 도구마다 실행 파일 위치를 `appsettings.json`의 `Tools:<툴킷>:<도구>:Command`에서 읽는다 [7].
설정은 위치만 적고 버전은 적지 않는다 [7].
`RegRipper`의 `rip.pl`과 EZ 도구의 `dotnet`은 경로 없이 이름만 적어 원격 호스트의 `PATH`가 실행 파일을 정한다 [8].
YARA 룰 파일, scalpel 설정 파일, log2timeline 필터 파일 같은 참조 자료는 스크립트가 호출 인자로 경로를 고른다 [9].
작업 흐름은 인자를 주지 않으면 설치한 룰 묶음과 Plaso 필터 파일의 기본 경로를 쓴다 [10].
경로로 받은 룰·설정 파일의 버전이나 내용은 확인하지 않는다 [9].
해시 계산 명령, `ewfverify`, `strings`처럼 설정을 거치지 않고 이름으로 부르는 명령도 있다 [11].

```csharp
    protected bool InstallAptPackage(string package, string checkPath)
    {
        if (auditEnvironment.ExecuteCommand("test", $"-e {checkPath}", out _, false))
            return true; // already installed — nothing to do

        Info($"Installing missing apt package {package} ...");
        // Refresh package lists first — a fresh SIFT image often has a stale/empty apt cache, which makes
        // 'apt-get install' fail with "Unable to locate package".
        auditEnvironment.ExecuteCommand("apt-get", "update", out _, true);
        if (!auditEnvironment.ExecuteCommand("apt-get", $"install -y {package}", out string o, true))
        { Error($"Failed to install apt package {package}: {o}"); return false; }
        return auditEnvironment.ExecuteCommand("test", $"-e {checkPath}", out _, false);
    }
```
