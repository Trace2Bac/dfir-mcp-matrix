# I04 서버 자격증명 처리

### I04.01 환경변수·설정 파일에 분리 보관

**구현.** 서버가 외부 연동에 쓰는 자격증명은 SIFT 워크스테이션에 붙는 SSH 실행 환경의 사용자 이름과 비밀번호다 [1].
서버는 실행 파일 폴더의 `appsettings.json`을 읽고 세션을 만들 때 `SIFT:User`·`SIFT:Password`로 SSH 연결을 연다 [1][2].
설정은 이 JSON 파일 하나에서만 읽고 환경변수에서 값을 읽는 단계는 없다 [2].
시작 인자 `--user`·`--pass`가 있으면 설정 파일 값을 덮어쓴다 [3].
저장소의 `appsettings.json`에는 `<sans-pw>` 같은 자리표시 값만 있다 [4].
README는 SSH를 쓰면 이 파일에 접속 정보를 적으라고 안내한다 [4].
인증은 `PasswordAuthenticationMethod` 하나만 쓰고 키 파일이나 SSH agent로 인증하는 코드는 없다 [5].
비밀번호는 `SshAuditEnvironment`의 비공개 필드 `ssh_client_pass`에 남아 SCP 연결을 만들 때 다시 쓰인다 [5][6].

**한계.** `create-case`에 `--pass`를 주면 `BuildServerArgs`가 그 값을 사건 폴더 `.mcp.json`의 서버 실행 인자에 평문으로 적는다 [7].
이 `.mcp.json`은 호출 기록·보고서를 두는 사건 폴더 안에 남는다 [7].
`camel create-case`가 사건 폴더에 함께 써 넣는 클라이언트 설정은 `Read`를 허용하고 `.mcp.json`을 막는 규칙을 두지 않는다 [8].
`--pass`로 실행한 서버 프로세스의 명령 행에도 비밀번호가 그대로 들어간다 [3][7].

SSH 실행 환경은 서버 호스트에서 명령을 실행하는 `LocalEnvironment`를 `public` 속성 `HostEnvironment`로 둔다 [9].
`LocalEnvironment`는 Unix에서 명령을 서버 호스트의 `/bin/bash -c`로 실행한다 [10].
스크립트는 툴킷의 `public` 필드 `auditEnvironment`를 거쳐 이 속성에 닿을 수 있다 [9][11].
그래서 SSH 모드에서도 스크립트는 서버 호스트에서 `cat`을 실행해 실행 파일 폴더의 `appsettings.json`에 적힌 SSH 비밀번호를 출력에 실을 수 있다 [2][9][10].
이 경로를 실제로 실행해 시험하지는 않았다.

### I04.02 도구 인자 수신 금지

**구현.** 이 방식은 MCP 도구 넷에 있다 [12].
`SetCaseId`·`SetEvidence`·`VerifyEvidence`·`Execute`의 인자는 사건 ID, 증거 목록, 스크립트뿐이고 자격증명을 받지 않는다 [12].
서버는 세션을 만들 때 설정에서 접속 정보를 읽어 SSH 연결을 연다 [1].
스크립트에 묶이는 툴킷의 `auditEnvironment` 필드는 `public`이지만 비밀번호를 담은 `ssh_client_pass`는 비공개 필드다 [5][11].
스크립트가 서버 호스트에서 명령을 실행해 설정 파일의 비밀번호를 읽는 경로는 I04.01 한계에서 본다.
관리자 권한 명령은 `sudo`를 붙여 실행할 뿐 비밀번호를 명령 문자열에 넣지 않는다 [13].
접속 로그는 호스트와 포트만 적고 호출 기록의 명령 행에는 명령과 인자만 적는다 [14].
응답·기록·오류 문구에서 비밀번호를 찾아 지우는 처리는 없다 [14].
`create-case`에 `--pass`를 주어 만든 사건에서는 모델이 클라이언트의 `Read` 도구로 `.mcp.json`의 비밀번호를 읽을 수 있다 [7][8].
