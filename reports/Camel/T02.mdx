# T02 실행 허용 범위 제한

### T02.03 클라이언트 도구 선택

**구현.** `camel create-case`는 사건 폴더에 Claude Code 설정 `.claude/settings.json`을 쓴다 [1].
이 설정은 Camel MCP 도구 4개와 `Read`·`Glob`·`Grep`, `reports`·`exports` 폴더의 `Write`·`Edit`을 허용 목록에 둔다 [2].
거부 목록에는 `Bash`·`WebFetch`·`WebSearch`와 비밀 파일 읽기를 둔다 [2].
저장소 문서는 이 거부 목록으로 셸 도구를 숨겨 분석이 `Execute`만 거치게 한다고 적는다 [3].
Camel 도구 4개는 모두 허용 목록에 들어 있고 이 설정이 숨기는 Camel 도구는 없다 [2].
서버는 연결한 클라이언트와 관계없이 도구 4개를 모두 등록하고 호출할 때 클라이언트를 보지 않는다 [4].
`Execute`가 실행하는 명령의 범위는 이 설정이 아니라 T02.06·T02.08의 서버 쪽 방식이 정한다 [4].

**예외.** 다른 MCP 클라이언트나 이 설정이 없는 폴더의 Claude Code로 서버에 붙으면 이 제한이 걸리지 않는다 [4].
`create-case`는 사건 폴더에 `.claude/settings.json`이 이미 있으면 템플릿을 쓰지 않고 있던 파일을 그대로 둔다 [1].

### T02.06 고정 명령·템플릿

**구현.** SDK 툴킷 메서드는 실행 파일과 인자 틀을 정해 두고 스크립트가 넘긴 값을 그 틀의 칸에 넣는다 [5][6].
실행 파일 경로와 `sudo` 여부는 툴킷마다 `appsettings.json`의 `Tools:<툴킷>:<도구>:Command`·`Sudo`에서 읽는다 [5].
예를 들어 `FlsAsync`는 `fls` 뒤에 선택 옵션과 이미지 경로, inode를 두고 `WindowsPsListAsync`는 Volatility 3에 `-f` 뒤의 메모리 이미지 경로와 플러그인 `windows.pslist`를 넘긴다 [6].
툴킷 메서드는 플러그인·모드를 메서드마다 고정해 스크립트가 플러그인 이름을 고르지 않는다 [6].
`RegRipperAsync`의 `plugin`처럼 실행할 연산을 값으로 받는 메서드도 있고 그 값을 목록과 대조하지 않는다 [7].
명령은 인자 목록이 아니라 한 줄 문자열로 만들어져 셸이 해석한다(T04.03) [8].

**예외.** `DiskAnalysis`·`WindowsAnalysis`·`Timeline`·`UnixTools`·`Yara` 툴킷의 따옴표 함수 `Q`는 값을 작은따옴표로 감싸기만 하고 값 안의 작은따옴표를 바꾸지 않는다 [9].
`MemoryAnalysis`·`LinuxAnalysis`·`PacketAnalysis` 툴킷의 `Q`는 작은따옴표를 바꿔 쓴다 [9].
`MemoryAnalysisToolkit`의 Volatility 메서드는 이미지 경로 `filename`을 `Q` 없이 `-f` 뒤에 붙인다 [10].
`ForemostAsync`의 `fileTypes`, `MactimeAsync`의 `timezone`, `RegRipperAsync`의 `plugin`, `PacketAnalysisToolkit.FieldsAsync`의 `fields`도 따옴표 없이 명령 문자열에 들어간다 [10].
이 값에 작은따옴표·공백·`;`·`$()`가 들어가면 셸이 명령의 구조를 바꿔 읽는다 [8][9][10].
실제 도구로 실행해 보지는 않았다.

### T02.08 질의 구조·연산 검사

**구현.** `Execute`는 모델이 쓴 JavaScript를 Jint 엔진으로 실행하고 엔진 설정 `StringCompilationAllowed = false`로 `eval`·`new Function` 같은 문자열 코드 생성을 끈다 [11].
엔진 설정에는 스크립트가 .NET 형식·네임스페이스에 직접 닿게 하는 설정(`AllowClr` 등)이 없다 [11].
스크립트가 부를 수 있는 이름은 서버가 엔진에 넣은 전역이다 [12].
전역은 출력·호출 기록 함수, `Session` 저장소, 작업 흐름 8개, `AnomalyDetectionToolkit`, 스크립트 본문에 이름이 나온 툴킷 8개 가운데 해당하는 것이다 [12].
저장소 문서는 이 구성으로 스크립트가 SDK 밖의 파일·네트워크·운영체제에 닿지 못한다고 적는다 [13].

`WindowsAnalysisToolkit.SqliteQueryAsync`는 모델이 쓴 SQL을 DB 사본에 `sqlite3 -readonly`로 실행해 쓰기 연산을 SQLite가 거부하게 한다 [14].
`PacketAnalysisToolkit.FieldsAsync`의 tshark 표시 필터와 `YaraToolkit.ScanAsync`의 룰 파일은 구조를 검사하지 않고 도구에 넘긴다 [15].

**예외.** 툴킷 기반 클래스는 실행 환경을 public 필드 `auditEnvironment`로 둔다 [16].
실행 환경의 `ExecuteCommandAsync`는 명령 이름·인자 문자열·`admin`(sudo) 여부를 받는 public 메서드다 [16].
툴킷의 `ExecuteToolTextAsync`도 public 메서드라 설정에 있는 도구를 임의의 인자로 실행한다 [17].
엔진 설정에는 바인딩한 객체의 public 필드·메서드를 숨기는 설정이 없다 [11].
스크립트가 `DiskAnalysisToolkit.auditEnvironment`를 거쳐 SDK 밖의 명령을 실행할 수 있는지는 실행해 보지 않아 확인하지 못했다 [16].
`sqlite3`가 SQL 인자로 받은 점 명령(`.shell` 등)을 실행하는지도 확인하지 못했다 [14].
