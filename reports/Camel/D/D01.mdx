# D01 파생물 보관

### D01.01 분석 도구 출력 파일 저장

**구현.** 이 방식은 SDK 메서드 `FlsBodyfileAsync`·`IcatAsync`·`IcatByAddrAsync`·`BlklsAsync`·`MactimeToFileAsync`·`Bunzip2Async`와 이 메서드를 부르는 워크플로에 적용된다 [1].
이 메서드들은 도구 명령 뒤에 셸 리다이렉션 `>`와 인자 `outputFile` 경로를 붙여 도구의 표준 출력을 그 파일에 쓰게 하고 호출이 끝난 뒤에도 그 파일을 지우지 않는다 [1].
도구는 출력 파일 경로를 받지 않고 표준 출력만 낸다.
로컬 실행 환경은 명령 줄 전체를 `/bin/bash -c`로 실행하고 SSH 실행 환경은 명령 줄을 원격 명령으로 넘기므로 `>`는 셸이 처리한다 [2].
`Bunzip2Async`는 `outputFile`이 없으면 원래 파일 이름에서 `.bz2`를 뗀 경로에 쓴다 [1].

서버 코드의 워크플로도 이 메서드로 파일을 남긴다.
`ListDeletedFilesAsync`는 `FlsBodyfileAsync`로 `/tmp/camel_deleted_<GUID>.body`에 bodyfile을 쓰고 삭제 항목 줄을 읽은 뒤 그 파일을 지우지 않는다 [3].
`RecoverDeletedFileAsync`는 `IcatByAddrAsync`로 삭제 파일의 내용을 인자 `outputFile`에 쓰고 그 경로를 결과로 돌려준다 [4].
`GenerateFilesystemTimelineAsync`는 인자 `bodyfilePath`가 없으면 `/tmp/camel_bodyfile_{offset}.txt`(오프셋이 없으면 0)에 bodyfile을 쓰고 지우지 않은 채 그 경로를 결과에 싣는다 [5].
`CarveUnallocatedSpaceAsync`는 `BlklsAsync`로 할당되지 않은 영역을 임시 파일에 받은 뒤 카빙이 끝나면 그 파일을 지운다 [6].
보관 기간·용량·대상을 정하는 설정이나 코드는 없다.

위 메서드를 거치지 않는 도구 실행의 표준 출력과 `Execute` 응답 본문은 파일로 남지 않는다 [7].
`Execute`는 스크립트가 `log`·`error`로 낸 줄을 메모리의 `StringBuilder`에 모아 응답으로만 돌려준다 [7].
사건 호출 기록 파일 `audit-<caseId>.clef`의 명령 항목에는 호스트·명령·인자·종료 코드·시간만 있고 출력은 없다 [7].
스크립트가 `auditInfo`로 넘긴 줄만 호출 기록에 함께 남는다 [8].
스크립트가 `Session`에 넣은 결과는 프로세스 메모리에만 있고 P04에서 본다 [9].

**예외.** 같은 `outputFile`로 다시 부르면 셸 `>`가 앞 파일을 덮어써 앞 실행의 출력이 남지 않는다 [1].
`GenerateFilesystemTimelineAsync`의 기본 bodyfile 이름은 오프셋으로만 정해져 같은 오프셋으로 다시 부르면 다른 이미지의 실행이라도 앞 bodyfile을 덮어쓴다 [5].
`ListDeletedFilesAsync`와 `GenerateFilesystemTimelineAsync`가 `/tmp`에 남긴 bodyfile이 언제까지 남는지는 서버 코드가 정하지 않아 확인하지 못했다 [3][5].

### D01.02 추출·생성 파일 보관

**구현.** 이 방식은 도구가 스스로 결과 파일을 쓰는 SDK 메서드에 적용된다 [10].
`ForemostAsync`·`TskRecoverAsync`·`DumpFilesAsync`·`ExportObjectsAsync`는 도구가 인자 `outputDir` 폴더에 복구하거나 꺼낸 파일을 쓰게 하고 호출이 끝난 뒤에도 그 폴더를 지우지 않는다 [10].
`TimelinerBodyfileAsync`는 Volatility 3에 `-o` 폴더를 넘겨 그 폴더에 bodyfile `volatility.body`를 쓰게 한다 [11].
`Log2TimelineAsync`는 Plaso 저장 파일을 인자 `storageFile` 경로에 만들고 타임라인 워크플로는 그 경로를 나중에 다시 걸러 볼 저장 파일로 돌려준다 [12].
이 경로는 명령을 실행하는 실행 환경(로컬 또는 SSH로 붙은 SIFT 워크스테이션)의 경로이고 서버는 폴더나 이름을 정하지 않는다 [10].
보관 기간·용량·대상을 정하는 설정이나 코드는 없다.

다른 메서드는 도구가 쓴 파일을 임시 경로로 받고 호출 안에서 지운다.
`ExecuteToolJsonAsync`와 `ExecuteToolJsonLinesFileAsync`는 `/tmp/camel_*` 아래 GUID 이름의 임시 폴더·파일에 도구 출력을 쓰게 한 뒤 읽고 `finally`에서 지운다 [13].

**예외.** 같은 경로로 다시 실행하면 앞 실행의 파생물이 따로 남지 않는다.
`Log2TimelineAsync`는 `storageFile`이 이미 있으면 그 파일에 이어 쓰고 `PsortTagAsync`는 저장 파일 안의 태그를 그 자리에서 고친다 [12][14].
다시 실행할 때 앞 파생물을 구분하는 방식은 D04에서 본다.

### D01.04 도구 출력·가공본 별도 보관

**구현.** 스크립트에 `MemoryAnalysisWorkflow`로 노출되는 메모리 타임라인 워크플로 `GenerateTimelineAsync`가 한 호출 안에서 원래 출력과 가공본을 함께 남긴다 [15].
이 메서드는 `TimelinerBodyfileAsync`로 타임라인 파일과 같은 폴더에 `volatility.body`를 쓰고 `MactimeToFileAsync`로 그 bodyfile을 정렬한 타임라인 파일을 쓴다 [16][11].
결과로 타임라인 파일 경로와 bodyfile 경로를 함께 돌려주고 bodyfile을 지우지 않는다 [16].
코드 설명은 이 중간 bodyfile을 필터를 바꿔 타임라인을 다시 만들 때 쓰도록 남긴다고 적는다 [16].
스크립트가 메서드를 따로 불러 만든 파일은 각 호출이 남기는 방식으로 본다.
Plaso 저장 파일과 `PsortAsync` 결과는 D01.02에서, `FlsBodyfileAsync`의 bodyfile과 `MactimeToFileAsync` 결과는 D01.01에서 본다 [1][12].

**예외.** bodyfile 이름은 `volatility.body`로 고정되어 같은 폴더에 다른 이름의 타임라인을 다시 만들면 두 타임라인이 bodyfile 경로 하나를 함께 쓴다 [11].
이때 앞 bodyfile이 남는지는 Volatility 3이 같은 이름의 파일을 어떻게 다루는지에 달려 있고 확인하지 못했다 [11].
같은 타임라인 경로로 다시 부르면 `MactimeToFileAsync`가 셸 `>`로 앞 타임라인 파일을 덮어쓴다 [1].

```csharp
    /// Builds the <see cref="ProcessStartInfo"/> for a command. On Unix the toolkits compose <em>bash command
    /// lines</em> — globs, pipes (<c>| head</c>), redirects (<c>&gt; file</c>), command substitution (<c>$(...)</c>),
    /// single/double quoting, and escaped grouping (<c>\( \)</c>, e.g. in <c>find</c>). The SSH environment runs
    /// these by handing <c>"&lt;command&gt; &lt;arguments&gt;"</c> to the remote shell, so the local environment must
    /// do the same or those shell constructs are passed to the tool literally and fail (e.g. <c>FindFilesAsync</c>).
    /// We therefore run the line through <c>/bin/bash -c</c>, passing it as a single argv entry (ArgumentList) so no
    /// second round of quoting is applied. On Windows the tools are native executables (e.g. vol.exe) and this Unix
    /// shell syntax would not apply, so the command is executed directly as before.
    /// </summary>
    private ProcessStartInfo NewProcessStartInfo(string command, string arguments)
    {
        if (this.IsUnix)
        {
            var psi = new ProcessStartInfo("/bin/bash");
            psi.ArgumentList.Add("-c");
            psi.ArgumentList.Add(string.IsNullOrEmpty(arguments) ? command : command + " " + arguments);
            return psi;
        }
        return new ProcessStartInfo(command) { Arguments = arguments };
    }
```

```csharp
    public async Task<WorkflowResult<FilesystemTimeline>> GenerateFilesystemTimelineAsync(
        string imageFile, int? offset = null, string timezone = "UTC", string? bodyfilePath = null)
    {
        bodyfilePath ??= $"/tmp/camel_bodyfile_{offset ?? 0}.txt";
        using var _audit = AuditScope();
        using var op = Begin("Generating filesystem timeline for {0} (offset {1})", imageFile, offset?.ToString() ?? "none");

        // Confirm a filesystem actually lives at the offset before walking it (avoids an empty/garbage timeline).
        var fs = await DiskAnalysis.FsStatAsync(imageFile, offset);
        if (fs is null || string.IsNullOrWhiteSpace(fs.FileSystemType))
            return WorkflowResult<FilesystemTimeline>.Failure(
                $"No valid filesystem found at sector offset {offset} of '{imageFile}'. " +
                $"Check the partition table (mmls) for a correct partition start sector.");

        // Walk the filesystem into a mactime bodyfile, then sort it into a timeline.
        if (!await DiskAnalysis.FlsBodyfileAsync(imageFile, bodyfilePath, offset))
            return WorkflowResult<FilesystemTimeline>.Failure(
                $"Failed to generate the fls bodyfile for '{imageFile}' (offset {offset}).");

        var entries = await DiskAnalysis.MactimeAsync(bodyfilePath, timezone);
        if (entries is null)
            return WorkflowResult<FilesystemTimeline>.Failure($"mactime failed to process bodyfile '{bodyfilePath}'.");

        op.Complete();
        return WorkflowResult<FilesystemTimeline>.Success(
            new FilesystemTimeline(bodyfilePath, entries),
            $"Generated {entries.Length} timeline entries for the {fs.FileSystemType} filesystem (offset {offset}).");
    }
```

```csharp
    /// Generates a mactime <em>bodyfile</em> of every timestamped artifact in <paramref name="image"/>
    /// (processes, threads, handles, sockets, registry keys, …) via <c>timeliner --create-bodyfile</c>, which
    /// writes <c>volatility.body</c> into <paramref name="outputDir"/> (the global <c>-o</c> directory;
    /// <c>-r none</c> suppresses the large, unneeded stdout table). The directory is created if missing. Feed
    /// the result to <c>mactime</c> to render a timeline. Returns the bodyfile path, or null on failure.
    /// </summary>
    public async Task<string?> TimelinerBodyfileAsync(string image, string outputDir)
    {
        auditEnvironment.FailIfEvidenceSpoliationRisk(outputDir);   // never write the bodyfile (and chown) onto evidence
        // Created as the login user so the (sudo'd) plugin can write into it.
        await auditEnvironment.ExecuteCommandAsync("mkdir", $"-p {outputDir}", false);

        if (await ExecuteToolTextAsync("Volatility3", $"-o {outputDir} -f {image} -r none timeliner --create-bodyfile") is null)
            return null;

        // The plugin runs under sudo, so the bodyfile lands root-owned; hand it back so a non-sudo mactime can read it.
        if (Tools["Volatility3"].Sudo)
            await auditEnvironment.ExecuteCommandAsync("chown", $"-R $(id -un):$(id -gn) {outputDir}", true);

        var bodyfile = $"{outputDir.TrimEnd('/')}/volatility.body";
        var test = await auditEnvironment.ExecuteCommandAsync("test", $"-s '{bodyfile}'", false);
        return test.IsCompleted ? bodyfile : null;
```

```csharp
    /// <summary>
    /// Generates a timeline of all artifacts in a Windows memory image and writes it to
    /// <paramref name="timelineOutputPath"/> on the workstation. Runs <c>timeliner --create-bodyfile</c> to
    /// produce a mactime bodyfile of every timestamped artifact Volatility can find (processes, threads,
    /// handles, network sockets, registry keys, …), then sorts it into a timeline with <c>mactime</c> (UTC).
    /// The intermediate bodyfile is written alongside the timeline and returned for re-rendering with filters.
    /// </summary>
    /// <param name="imageFile">Path to the Windows memory image to analyse.</param>
    /// <param name="timelineOutputPath">Workstation path to write the sorted timeline file to.</param>
    public async Task<WorkflowResult<MemoryTimeline>> GenerateTimelineAsync(string imageFile, string timelineOutputPath)
    {
        using var _audit = AuditScope();
        using var op = Begin("Generating memory timeline for {0} -> {1}", imageFile, timelineOutputPath);

        // The bodyfile (volatility.body) is written into the timeline's directory — which also ensures that
        // directory exists for the subsequent mactime output.
        int slash = timelineOutputPath.LastIndexOf('/');
        string outputDir = slash switch { > 0 => timelineOutputPath[..slash], 0 => "/", _ => "." };

        var bodyfile = await MemoryAnalysis.TimelinerBodyfileAsync(imageFile, outputDir);
        if (bodyfile is null)
            return WorkflowResult<MemoryTimeline>.Failure(
                $"timeliner failed to create a bodyfile for '{imageFile}'; the image may be unreadable or its symbols unavailable.");

        if (!await DiskAnalysis.MactimeToFileAsync(bodyfile, timelineOutputPath))
            return WorkflowResult<MemoryTimeline>.Failure(
                $"mactime failed to render the timeline from bodyfile '{bodyfile}'.");

        op.Complete();
        return WorkflowResult<MemoryTimeline>.Success(
            new MemoryTimeline(timelineOutputPath, bodyfile),
            $"Memory timeline written to '{timelineOutputPath}' (bodyfile: '{bodyfile}').");
    }
```
