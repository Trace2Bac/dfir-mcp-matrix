# D04 출력 경로 제한

### D04.01 서버가 출력 위치 결정

**구현.** 서버가 출력 위치를 정하는 방식은 `GenerateFilesystemTimelineAsync`가 `bodyfilePath` 인자 없이 불렸을 때 쓰는 기본 bodyfile 경로에만 있다 [1].
이때 메서드는 `/tmp/camel_bodyfile_{offset}.txt`(오프셋이 없으면 0) 경로에 fls bodyfile을 만든다 [1][2].
메서드는 이 파일을 지우지 않고 결과의 `BodyfilePath`에 그 경로를 담아 돌려준다 [1].
`bodyfilePath`를 넘기면 그 값을 검사 없이 목적지로 쓴다 [1][2].

다른 파생물 메서드는 목적지 경로를 `Execute` 스크립트가 넘긴 인자로 받아 그대로 명령에 넣는다 [3].
목적지를 허용 폴더와 대조하거나 경로 구분자·`..`·링크를 검사하는 코드가 없다 [3].
목적지에 거는 검사는 `FailIfEvidenceSpoliationRisk`가 그 경로가 등록한 원본 증거 파일이나 그 파일이 든 폴더와 같은지 보는 것 하나이고 E03에서 본다 [4].

이 메서드들에는 같은 작업을 다시 할 때 앞 파생물과 구분하는 장치도 없다.
표준 출력을 그 경로의 파일에 쓰는 메서드는 같은 경로로 다시 부르면 셸 `>`로 앞 파일을 알리지 않고 덮어쓴다 [5].
`Log2TimelineAsync`는 같은 저장 파일에 이어 쓰고 그 뒤 `PsortAsync`는 두 실행이 넣은 사건을 가리지 않고 함께 내보낸다 [6].
`RunToDirAsync`는 도구를 실행한 뒤 `outputDir`의 파일을 모두 나열해 돌려주므로 같은 폴더를 다시 쓰면 앞 실행의 파일이 이번 결과 목록에 섞인다 [7].
`ForemostAsync`·`BulkExtractorAsync`의 설명은 `outputDir`이 미리 없어야 한다고 적지만 서버 코드는 폴더가 있는지 보지 않고 외부 도구에 맡긴다 [8].
foremost와 bulk_extractor가 이미 있는 폴더를 거부하는지는 실행해 보지 않아 확인하지 못했다.

**예외.** `GenerateFilesystemTimelineAsync`의 기본 경로 이름은 오프셋으로만 정해져 같은 오프셋으로 다시 부르면 다른 이미지·다른 사건의 실행이라도 같은 파일을 쓴다 [1].
fls 출력은 셸 `>`로 이 파일에 쓰이므로 앞 bodyfile을 알리지 않고 덮어쓴다 [2].
그러면 앞 실행이 돌려받은 `BodyfilePath`는 나중 실행이 쓴 내용을 가리킨다 [1].

### D04.06 유일 파일명·시각·번호

**구현.** 유일한 이름을 쓰는 방식은 `ListDeletedFilesAsync`의 내부 bodyfile과 `RunIdsAsync`의 기본 출력 폴더에만 있다 [9][10].
`ListDeletedFilesAsync`는 삭제 항목을 찾으려고 `/tmp/camel_deleted_<GUID>.body`에 bodyfile을 만들고 그 파일을 지우지 않는다 [9].
이름에 호출마다 새로 만든 GUID가 들어가므로 다른 실행의 bodyfile과 겹치지 않는다 [9].
결과에는 이 경로를 싣지 않는다 [9].
`RunIdsAsync`는 `outDir`가 없으면 `/tmp/camel_suricata_<GUID>` 폴더를 만들어 Suricata 로그를 쓰고 그 폴더를 지우지 않는다 [10][11].
이 두 경로 밖의 파생물 이름은 스크립트가 정하고 서버는 앞 파생물과 구분하지 않는다(D04.01).
툴킷 공통 함수가 만드는 `/tmp/camel_ez_<GUID>` 같은 임시 폴더는 호출 안에서 지우므로 이 상세에 넣지 않는다 [12].

    public async Task<WorkflowResult<FilesystemTimeline>> GenerateFilesystemTimelineAsync(
        string imageFile, int? offset = null, string timezone = "UTC", string? bodyfilePath = null)
    {
        bodyfilePath ??= $"/tmp/camel_bodyfile_{offset ?? 0}.txt";
        using var _audit = AuditScope();
        using var op = Begin("Generating filesystem timeline for {0} (offset {1})", imageFile, offset?.ToString() ?? "none");

        // Confirm a filesystem actually lives at the offset before walking it (avoids an empty/garbage timeline).
        var fs = await DiskAnalysis.FsStatAsync(imageFile, offset);
        if (fs is null || string.IsNullOrWhiteSpace(fs.FileSystemType))
            return WorkflowResult<FilesystemTimeline>.Failure(
                $"No valid filesystem found at sector offset {offset} of '{imageFile}'. " +
                $"Check the partition table (mmls) for a correct partition start sector.");

        // Walk the filesystem into a mactime bodyfile, then sort it into a timeline.
        if (!await DiskAnalysis.FlsBodyfileAsync(imageFile, bodyfilePath, offset))
            return WorkflowResult<FilesystemTimeline>.Failure(
                $"Failed to generate the fls bodyfile for '{imageFile}' (offset {offset}).");

        var entries = await DiskAnalysis.MactimeAsync(bodyfilePath, timezone);
        if (entries is null)
            return WorkflowResult<FilesystemTimeline>.Failure($"mactime failed to process bodyfile '{bodyfilePath}'.");

        op.Complete();
        return WorkflowResult<FilesystemTimeline>.Success(
            new FilesystemTimeline(bodyfilePath, entries),
            $"Generated {entries.Length} timeline entries for the {fs.FileSystemType} filesystem (offset {offset}).");
    }

    public void FailIfEvidenceSpoliationRisk(string targetPath)
    {
        var evidence = FindEvidenceForPath(targetPath);
        if (evidence is not null) throw new EvidenceSpoliationRiskException(evidence, targetPath);
    }

    // The registered evidence that <paramref name="path"/> would put at risk (the evidence file itself or its
    // containing directory), or null if the path is not protected. Shared by the check and the guard so both
    // apply identical normalization and case-sensitivity rules.
    private EvidenceInfo? FindEvidenceForPath(string path)
    {
        if (string.IsNullOrWhiteSpace(path) || CaseEvidence.Length == 0) return null;
        var comparison = IsWindows ? StringComparison.OrdinalIgnoreCase : StringComparison.Ordinal;
        var normalized = NormalizeEvidencePath(path);
        return CaseEvidence.FirstOrDefault(e =>
        {
            var file = NormalizeEvidencePath(e.FilePath);
            return file.Equals(normalized, comparison) || GetEvidenceDirectory(file).Equals(normalized, comparison);
        });
    }

    // Runs a tool that writes files into outDir; creates the dir (as login user), runs, hands files back, lists them.
    private async Task<string[]?> RunToDirAsync(string outDir, bool sudo, Func<Task<string?>> run)
    {
        auditEnvironment.FailIfEvidenceSpoliationRisk(outDir);
        await auditEnvironment.ExecuteCommandAsync("mkdir", $"-p {Q(outDir)}", false);
        if (await run() is null) return null;
        if (sudo) await auditEnvironment.ExecuteCommandAsync("chown", $"-R $(id -un):$(id -gn) {Q(outDir)}", true);

        return find.IsCompleted
            ? find.Output.Split('\n', StringSplitOptions.RemoveEmptyEntries | StringSplitOptions.TrimEntries).ToArray()
            : [];
    }

    public async Task<WorkflowResult<DeletedFilesReport>> ListDeletedFilesAsync(string image, int? offset = null, int maxFiles = 2000)
    {
        using var _audit = AuditScope();
        using var op = Begin("Listing deleted files in {0} (offset {1})", image, offset?.ToString() ?? "none");

        var bodyfile = $"/tmp/camel_deleted_{Guid.NewGuid():N}.body";
        if (!await DiskAnalysis.FlsBodyfileAsync(image, bodyfile, offset))
            return WorkflowResult<DeletedFilesReport>.Failure(
                $"Failed to walk '{image}' (offset {offset}) for deleted files. Check the offset (mmls) and that a filesystem exists there.");

        // The bodyfile names every deleted entry with a "(deleted)" / "(deleted-realloc)" suffix; pull just those
        // server-side rather than transferring the whole bodyfile.
        var lines = await DiskAnalysis.GrepLinesAsync(bodyfile, ["deleted"], ignoreCase: false);
        if (lines is null)
            return WorkflowResult<DeletedFilesReport>.Failure($"Could not read the bodyfile '{bodyfile}'.");

        var entries = lines.Select(ParseDeletedRow).Where(e => e is not null).Select(e => e!)
            .OrderByDescending(e => e.Size).Take(maxFiles).ToArray();

        op.Complete();
        var report = new DeletedFilesReport { DeletedFiles = entries, Count = entries.Length };
        return WorkflowResult<DeletedFilesReport>.Success(report,
            entries.Length == 0
                ? $"No deleted files found in '{image}' (offset {offset})."
                : $"Found {lines.Length} deleted entry/entries in '{image}'; {entries.Count(e => e.Recoverable)} recoverable. " +
                  $"Largest: {string.Join("; ", entries.Take(3).Select(e => $"{e.Path} ({e.Size} bytes)"))}.");
    }

    {
