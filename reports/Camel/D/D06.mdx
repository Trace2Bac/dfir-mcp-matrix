# D06 결론 도출

### D06.01 규칙·키 기반 상관

**구현.** 결론을 만드는 곳은 스크립트가 부르는 워크플로 메서드이고 결과는 스크립트에 돌려줄 뿐 서버 저장소에 남지 않는다.
`FindHiddenProcessAsync`는 `windows.pslist`와 `windows.psscan` 결과를 PID로 맞춰 목록에 없는 프로세스를 숨은 프로세스와 끝난 프로세스로 나눈다 [1].
`FindMalwareAsync`는 여러 단계의 신호를 PID로 묶고 이미 지목된 PID에만 원격 연결을 덧붙인다 [2].
`ValidateProcessTreeAsync`는 내장 `process_expectations.yaml`의 자식 금지·의심 부모·허용 부모·경로·사용자 규칙과 프로세스마다 맞춰 보고 위반을 심각도와 함께 돌려준다 [3].
`HuntLateralMovementAsync`는 이벤트 ID 4624·4648·5140·4697·7045로 원격 로그온·명시적 자격 증명·관리 공유 접근·서비스 설치를 가른다 [4].
`CategorizeTimelineAsync`는 Plaso 태그 규칙 파일로 저장 파일에 태그를 붙이고 태그 이름별로 사건을 묶는다 [5].
`AnalyzeExecutionEvidenceAsync`와 `FindRegistryPersistenceMechanismsAsync`는 `LoadLolbasAsync`로 읽은 LOLBAS 자료를 정한 규칙에 써서 실행 파일과 지속성 항목을 의심 항목으로 가른다 [6][7].
LOLBAS에 이름이 있는 실행 파일이 폴더를 포함한 경로로 실행되고 그 경로가 LOLBAS의 정식 경로가 아니면 위장 실행 가능성을 `Reasons`에 적는다 [6][7].
LOLBAS에 정식 경로가 없는 실행 파일은 정식 경로에 있는 것으로 보아 이 규칙으로 표시하지 않는다 [8].
`FindRegistryPersistenceMechanismsAsync`는 정식 경로의 LOLBin을 실행하는 항목에는 다른 이유로 이미 의심 항목일 때만 그 사실을 이유로 덧붙인다 [7].
공격 단계(tactic)로 나누거나 흐름 문장을 만드는 코드는 없어 D06.06에는 연결하지 않는다.

**예외.** `ValidateProcessTreeAsync`가 `windows.pslist` 결과를 받으면 PPID의 이름을 같은 PID를 가진 마지막 행에서 찾는다 [9].
PID가 다시 쓰인 이미지에서는 실제 부모가 아닌 프로세스의 이름으로 부모 규칙을 판정한다 [9].
코드 주석도 PID가 다시 쓰이면 마지막 행을 쓴다고 적는다 [9].

`HuntLateralMovementAsync`는 System 로그 경로를 받았는데 그 파싱이 실패하면 빈 목록으로 바꿔 계속한다 [4].
그 경우 결과의 서비스 설치 목록에는 7045 이벤트가 빠지고 실패 사실은 결과에 실리지 않는다 [4].

`LoadLolbasAsync`는 설치된 `lolbas.json`을 읽지 못하거나 해석하지 못하면 `null`을 돌려준다 [10].
`AnalyzeExecutionEvidenceAsync`와 `FindRegistryPersistenceMechanismsAsync`는 이때 LOLBin 규칙을 빼고 계산하고 자료가 없었다는 사실을 결과와 요약 문구에 싣지 않는다 [6][7][11].
`FindRegistryPersistenceMechanismsAsync`의 코드 주석은 자료가 없으면 LOLBin 검사를 건너뛴다고 적는다 [7].

### D06.02 시간·공간 근접성 연결

**구현.** `DetectTimelinePivotsAsync`는 hayabusa 경보마다 그 시각 앞뒤 `sliceSizeMinutes`분의 저장 파일 사건을 잘라 경보와 묶는다 [12].
같은 분에 든 경보는 하나로 줄이고 이른 차례로 `maxPivots`개까지만 본다 [12].
`AutoPivotExpansionAsync`는 이상 탐지로 뽑은 상위 지점마다 같은 방식으로 앞뒤 사건을 붙인다 [13].
`DetectorEnsemble.Triage`는 탐지기마다 결과를 사건 종류 `Token`과 시각을 60초로 나눈 몫(`Ts / bucket`)이 같은 것끼리 한 묶음으로 합친다 [14].
이 묶음은 사건 사이 간격이 아니라 고정된 60초 칸으로 나뉘므로 몇 초 차이의 두 사건도 칸 경계를 넘으면 다른 묶음이 된다 [14].
인자 이름은 `episodeGapSeconds`이지만 코드는 이 값을 칸 크기로만 쓴다 [14].

**예외.** 두 메서드는 앞뒤 사건을 자르는 `PsortAsync`가 실패해 `null`을 돌려주면 빈 목록으로 바꿔 넣는다 [12][13].
그 경우 결과는 경보 주변에 사건이 없는 것과 구별되지 않는다 [12][13].

### D06.03 통계·점수 산정

**구현.** `TriageTimelineAsync`는 저장 파일의 사건을 정규화해 `AnomalyDetectionToolkit`의 탐지기 다섯(드문 종류·드문 전이·건수 급증·주기적 반복·내용)에 넣는다 [15].
탐지기는 사건마다 bit 단위 점수를 매기지만 계산 방식이 둘로 나뉜다.
드문 종류·드문 전이 탐지기는 기준 사건에서 센 빈도로 확률을 구해 그 `-log2` 값을 bit로 낸다 [16].
workflow는 같은 사건 목록을 기준과 대상으로 함께 넘겨 기준 사건은 분석하는 timeline 자신이다 [17][18].
별도 기준선은 스크립트 전역 `AnomalyDetectionToolkit.Triage`의 두 인자 형식으로만 줄 수 있다 [18].
기준에 공격 사건이 섞여 있으면 그 사건의 빈도도 기준 확률에 들어간다.
건수 급증 탐지기는 기준 도착률로 기대한 건수를 넘은 정도를 Poisson 꼬리 확률의 근사 지수로 바꿔 bit로 낸다 [19].
주기적 반복 탐지기의 bit는 규칙적인 간격 수 `regular`와 그 비율 `frac`의 곱에 0.6을 곱한 경험 점수다 [20].
내용 탐지기는 의심 키워드 하나에 4.0 bit를 주어 더한다 [21][22].
메시지 길이가 같은 종류의 평균보다 표준편차의 3배 넘게 길면 넘은 길이에 1을 더한 값의 `log2`를 더한다 [21].
이 두 탐지기의 bit는 확률에서 구한 값이 아닌 경험 점수다 [20][21].
`DetectorEnsemble.Triage`는 탐지기마다 D06.02의 60초 칸 묶음을 만들고 묶음 안에서 가장 큰 bit를 그 묶음의 값으로 둔다 [14].
탐지기마다 `budget`을 탐지기 수로 나눈 올림값 `quota`만큼 bit가 큰 묶음만 남긴다 [14].
그 뒤 여러 탐지기가 남긴 묶음 가운데 사건 종류와 칸이 같은 것을 하나로 합쳐 bit를 더하고 합한 값이 큰 차례로 `budget`개를 고른다 [14].
그래서 확률에서 나온 bit와 경험 점수가 한 합계에 함께 더해진다 [14].
`TriageTimelineAsync`는 고른 묶음마다 합한 값을 pivot의 `Bits`에 싣는다 [15].
`HuntPersistenceAsync`는 지속성 항목마다 방식별 기본 점수에 내용 서명이 맞을 때마다 정한 점수를 더해 `Score`를 매긴다 [23].
이 점수가 3 이상인 항목을 의심 항목으로 골라 점수 차례로 돌려준다 [24].
`HuntDnsTunnelingAsync`는 고유 하위 도메인 수·레이블 길이·엔트로피·레코드 종류·질의 수에 정한 점수를 더해 기준을 넘은 도메인을 돌려준다 [25].
`FindMalwareAsync`의 용의 프로세스는 신호 범주가 2개 이상이면 `IsHighConfidence`가 되고 범주 수·신호 수 차례로 정렬된다 [2][26].
스크립트는 `AnomalyDetectionToolkit`을 전역 객체로 직접 부를 수도 있다 [27].
`Camel.Inference`는 학습한 모델 없이 계산만 한다 [14].
문장 임베딩 모델을 쓰는 `Camel.Search`는 서버 프로젝트가 참조하지 않아 D06.04에는 연결하지 않는다 [28].

**예외.** `IEventDetector` 설명은 모든 탐지기가 surprisal을 bit로 내 같은 단위로 더할 수 있다고 적는다 [29].
주기적 반복 탐지기와 내용 탐지기의 bit는 확률에서 나온 값이 아니어서 이 설명과 다르다 [20][21].

`TriageTimelineAsync`는 `PsortReducedAsync`로 사건마다 메시지를 1,024자에서 자른 뒤 탐지기에 넣는다 [15][30].
내용 탐지기의 길이 판단과 이유 문장의 길이 값은 잘린 길이로 계산된다 [30][21].
`PsortReducedAsync` 설명은 키워드 신호에 영향이 없다고 적지만 1,024자 뒤에 있는 키워드는 잘린 메시지에서 빠져 세지 않는다 [30][21].
줄여 쓰는 스크립트는 JSON으로 읽지 못한 줄을 건너뛰고 그 수를 알리지 않는다 [30].

### D06.05 사용 근거·변환 기록

**구현.** 워크플로 메서드는 `AuditScope`로 워크플로·메서드 이름을 기록 문맥에 넣고 그 안에서 실행한 명령 항목마다 이 이름이 붙는다 [31].
그래서 결론을 돌려준 `Execute` 호출의 `ExecutionId`로 그 결론이 읽은 도구 명령과 인자를 사건 호출 기록에서 찾을 수 있다 [31][32].
결과에도 적용한 규칙이 실린다.
이상 탐지 결과의 항목마다 탐지기 이름과 이유 문장, 묶은 사건 번호가 실린다 [14].
`ValidateProcessTreeAsync`의 위반 항목은 규칙 종류와 기대값·실제값을 싣고 `HuntDnsTunnelingAsync`의 도메인 항목은 점수를 더한 이유를 싣는다 [3][25].

**예외.** `ValidateProcessTreeAsync`에 스크립트가 만든 `ProcessNode` 목록을 넘기거나 `AnomalyDetectionToolkit`을 스크립트에서 직접 부르면 명령이 실행되지 않아 결론의 입력이 명령 항목으로 남지 않는다 [3][27].
그 호출의 호출 기록에는 스크립트 원문만 남고 스크립트가 실행 중에 넘긴 값은 남지 않는다 [32].

        (new Regex(@"\bbase64\b", RegexOptions.Compiled), 2, "base64-encoded payload"),

        (new Regex(@"(python[0-9.]*|perl|ruby|php)\s+-(c|e)\b", RegexOptions.Compiled), 2, "inline interpreter one-liner"),
        (new Regex(@"\beval\b|\bexec\b", RegexOptions.Compiled), 1, "eval/exec"),
        (new Regex(@"chmod\s+[0-7]*[+]?x|chmod\s+777", RegexOptions.Compiled), 1, "makes a file executable"),
        (new Regex(@"\b(0\.0\.0\.0|\d{1,3}(\.\d{1,3}){3}:\d+)\b", RegexOptions.Compiled), 1, "hard-coded network endpoint"),
    ];

    private static (int Bonus, string[] Reasons) ScoreContent(string? text)
    {
        if (string.IsNullOrWhiteSpace(text)) return (0, []);
        int bonus = 0;
        var reasons = new List<string>();
