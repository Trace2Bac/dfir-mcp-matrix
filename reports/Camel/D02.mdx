# D02 파생물 계보

### D02.01 증거·호출·파생물 ID 참조

**구현.** 서버가 남기는 연결은 사건 호출 기록 파일 `audit-<caseId>.clef`의 항목이다 [1].
`Execute`는 호출마다 8자리 `ExecutionId`를 만들어 `CaseId`와 함께 기록 문맥에 넣고 응답 끝에 `[audit] case=… execution=…` 줄을 붙인다 [2].
실행 환경이 명령을 하나 실행할 때마다 `AuditCommand`가 호스트·명령·인자·sudo 여부·종료 코드·시간을 한 항목으로 쓰고 그 항목에 문맥의 `ExecutionId`가 붙는다 [1][3].
워크플로 메서드는 `AuditScope`로 `Workflow`·`WorkflowOperation`을, 툴킷 메서드는 `Toolkit`·`Operation`을 문맥에 넣어 같은 항목에 남긴다 [4][5].

파일 파생물은 이 명령 항목으로 실행과 입력에 이어진다.
D01에서 본 파일을 만드는 SDK 메서드는 입력 경로와 출력 경로를 명령 인자로 넘긴다 [6].
그래서 그 명령 항목의 `Arguments`에 파생물 경로와 소비한 입력 경로가 함께 있고 같은 항목의 `ExecutionId`가 파생물을 만든 `Execute` 호출을 가리킨다 [1][6].

발견사항은 근거 실행을 ID로 가리킨다.
`auditFinding`은 인자 `evidenceExecutionIds`를 `finding` 항목에 남기고 그 항목에는 발견사항을 기록한 `Execute` 호출의 `ExecutionId`도 붙는다 [2][7].

연결은 파생물에서 실행으로 가는 방향만 있고 실행에서 그 파생물이나 발견사항을 찾는 서버 도구는 없다.
`camel` CLI가 사건 폴더에 까는 `reports/report.html`은 발견사항의 근거 실행 ID를 눌러 그 실행의 스크립트와 명령 항목을 펼쳐 보여 주는 정적 화면이고 서버 구현이 아니다 [8].
앞 도구의 파생물을 뒤 도구가 입력으로 쓸 때 그 중간 입력의 버전이나 부모 관계를 따로 적는 필드는 없다.
명령 항목은 경로 문자열만 남기고 그 경로 내용의 해시나 크기는 남기지 않아 D02.02에는 연결하지 않는다 [1].

**예외.** 표준 출력을 경로로 돌려 쓰는 메서드는 같은 경로로 다시 부르면 파일을 덮어쓰고 `Log2TimelineAsync`는 같은 저장 파일에 이어 쓴다 [6].
그 뒤에는 앞 실행의 명령 항목이 나중 실행이 바꾼 파일을 가리킨다 [6].

`evidenceExecutionIds`는 자유 문자열이라 서버는 비어 있는지도, 그 ID가 호출 기록에 있는지도 보지 않는다 [7].
근거 심사는 D07에서 본다.

`SetCaseId`로 사건 ID를 바꾸면 그 뒤 항목은 새 ID의 파일에 쓰인다 [9].
한 세션에서 사건 ID를 바꾼 뒤 기록한 발견사항이 바꾸기 전의 실행을 인용하면 그 실행 항목은 다른 파일에 있다 [9].

    /// Records a structured forensic finding to the per-case audit trail as a <c>finding</c> event — observation
    /// and interpretation kept as distinct fields (forcing the agent to separate fact from inference), with the
    /// confidence level and the <c>execution</c> ids that prove it. Also echoes a one-line summary to the response.

    public string SetCaseId(string caseId, RequestContext<CallToolRequestParams> context)
    {
        var session = registry.GetOrCreate(SessionId(context.Server));
        var previous = session.CaseId;
        session.CaseId = string.IsNullOrWhiteSpace(caseId) ? session.SessionId : caseId.Trim();
        // Record the case association in the (new) case's audit file so the switch itself is auditable.
        using (PushAuditProperty("CaseId", session.CaseId))
            AuditEvent("case", "Case id set to {CaseId} (was {Previous}) for session {SessionId}",
                session.CaseId, previous, session.SessionId);
        return $"Case id set to '{session.CaseId}' for this session. Audit trail file: audit-{session.CaseId}.clef";
    }
