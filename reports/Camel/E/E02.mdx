# E02 증거 무결성 검증

### E02.02 도구를 요청해 기준값 계산

**구현.** 증거 해시는 모델이 도구나 메서드를 부를 때만 계산한다.
`SetEvidence`는 경로가 있는지와 크기만 보고 해시하지 않으므로 등록·첫 접근 때의 자동 해시(E02.01)는 없다 [1].
`Execute` 스크립트가 부르는 `UnixToolsToolkit`의 `Md5SumAsync`·`Sha1SumAsync`·`Sha256SumAsync`는 받은 파일 하나를 해시해 값을 돌려준다 [2].
해시는 모두 실행 환경에서 외부 명령으로 계산한다(`md5sum`·`sha1sum`·`sha256sum`, Windows 실행 환경은 `certutil`, E01 매체 데이터는 `ewfverify`) [2][3][4].
SDK 메서드가 돌려준 해시는 스크립트로 돌아갈 뿐 서버가 기준값으로 보관하지 않는다 [2].

증거 파일 전체가 아닌 범위를 해시하는 곳은 SDK 메서드 둘이다.
`DiskAnalysisToolkit.Sha256Async`는 마운트한 파일시스템 안의 파일 하나를 `sha256sum`으로 해시한다 [5].
Windows 분석 workflow는 크기가 같은 두 파일이 다른지 볼 때 이 메서드를 쓴다 [6].
`TimelineToolkit.Log2TimelineAsync`에 `hash`를 참으로 주면 plaso가 처리한 원천 파일마다 MD5·SHA-256을 계산해 이벤트에 붙인다 [7].
두 값 모두 결과로 돌아가기만 하고 서버는 기준값으로 보관하거나 다시 대조하지 않는다 [5][7].

### E02.09 도구를 요청해 검증

**구현.** 이 방식은 MCP 도구 `VerifyEvidence`와 SDK 메서드 `DiskAnalysisWorkflow.VerifyImageAsync`에 적용되고 모델이 부를 때만 대조한다 [8][9][10].
`VerifyEvidence`는 `SetEvidence`로 등록한 항목마다 등록 경로의 파일을 처음부터 끝까지 해시하는 명령에 넘긴다 [8][9][3].
등록 때 해시를 받은 항목은 같은 알고리즘으로 계산하고 받지 않은 항목은 SHA-1로 계산한다 [9].
경로가 `.e01`·`.ex01`로 끝나고 해시를 받은 항목은 `ewfverify`로 이미지에 담긴 매체 데이터의 해시를 계산한다 [9][3][4].
도구 설명은 그래서 E01의 수집 해시를 기준값으로 줄 수 있다고 적는다 [8].
해시를 받지 않은 E01은 `.E01` 파일 자체의 바이트를 SHA-1로 해시하므로 그 값은 매체 데이터의 해시가 아니다 [9].
해시를 받지 않은 E01과 분할 raw 이미지는 등록한 경로의 파일 하나만 해시하고 `.E02`·`.002` 같은 다른 조각은 해시하지 않는다 [3].
해시 명령이 실패하면 Unix 실행 환경에서는 `sudo`로 한 번 더 실행한다 [3][4].
다시 계산한 값을 등록 때 받은 값과 대소문자를 가리지 않고 견주고 응답은 항목마다 `OK`나 `MISMATCH`를 계산한 값과 함께 한 줄씩 적는다 [9][11].
`VerifyImageAsync`는 `EwfInfoAsync`로 E01 메타데이터를 읽고 `ewfverify`가 이미지 안에 저장된 해시와 다시 계산한 해시를 견준 결과를 읽어 돌려준다 [10][12].
기준값은 `VerifyEvidence`에서는 등록 때 모델이 준 값이고 `VerifyImageAsync`에서는 E01 안에 기록된 수집 해시다 [9][12].
서버가 분석 도구를 부르는 과정에서 스스로 대조하는 곳은 없어 E02.07에는 연결하지 않는다.
저장소의 실행 기록에서는 사건 설명에 해시가 없어 `VerifyEvidence`를 부르지 않았다 [13].

**예외.** 등록 때 해시를 받지 않은 항목은 대조하지 않고 늘 통과로 센다 [9][14].
이 항목의 해시를 계산하지 못해도 통과로 센다 [9][14].
`SetEvidence`는 폴더 경로도 받지만 `VerifyEvidence`는 폴더에도 파일 해시 명령을 그대로 실행한다 [1][3].
명령이 실패하면 해시 값은 빈 문자열이 되고 응답에는 `(unreadable)`로 적히지만 해시를 받지 않은 폴더 항목은 통과로 센다 [3][11][9].
도구 설명은 이 SHA-1을 기준값으로 기록한다고 적지만 서버는 값을 보관하지 않고 다음 `VerifyEvidence`에서 대조하지도 않는다 [8][9].
통과했을 때 호출 기록의 `evidence-verification` 사건에는 항목 수만 남고 계산한 해시는 남지 않는다 [15].
그래서 SHA-1 값은 그 응답에만 있다.
등록한 항목이 0개이면 아무것도 대조하지 않고 "Evidence verification passed."를 돌려준다 [9][15].

### E02.08 불일치 시 중단·경고

**구현.** `VerifyEvidence`는 받은 해시와 다르거나 해시를 계산하지 못한 항목이 하나라도 있으면 `IsError`로 응답하고 멈추라는 문구를 앞에 붙인다 [15].
호출 기록에는 어긋난 경로를 `evidence-spoliation` 사건으로 남긴다 [15].
`VerifyImageAsync`는 `ewfverify` 결과가 `SUCCESS`가 아니면 "INTEGRITY CHECK FAILED"와 두 MD5를 메시지에 적지만 workflow 결과는 성공으로 돌려준다 [10].
`camel` CLI가 사건 폴더에 써 두는 지침은 불일치가 나오면 멈추고 알리라고 모델에게 적는다 [16].

**예외.** 서버는 불일치를 세션 상태로 남기지 않아 그 뒤의 `Execute`는 그대로 실행된다 [15][17].
`ewfverify`가 0이 아닌 종료 코드로 끝나면 `ExecuteToolTextAsync`가 출력을 버리고 null을 돌려주므로 `VerifyImageAsync`는 불일치 대신 "did not complete" 실패를 돌려준다 [10][18].
이 도구가 불일치 때 어떤 종료 코드를 내는지는 확인하지 않았다.

```csharp
    // Computes the hex digest of a file on this environment with the given algorithm, or "" on failure. Unix uses
    // the coreutils sum tools (retrying under sudo for root-owned evidence on a forensic mount); Windows uses
    // certutil. The output is normalised to lower-case hex.
    private async Task<string> ComputeFileHashAsync(string path, HashType type)
    {
        if (IsWindows)
        {
            var alg = type switch { HashType.MD5 => "MD5", HashType.SHA256 => "SHA256", _ => "SHA1" };
            var rw = await ExecuteCommandAsync("certutil", $"-hashfile \"{path}\" {alg}");
            return rw.IsCompleted ? ExtractCertutilHash(rw.Output) : "";
        }
        var cmd = type switch { HashType.MD5 => "md5sum", HashType.SHA256 => "sha256sum", _ => "sha1sum" };
        var r = await ExecuteCommandAsync(cmd, $"'{path}'");
        if (!r.IsCompleted && IsUnix) r = await ExecuteCommandAsync(cmd, $"'{path}'", admin: true);   // root-owned evidence
        if (!r.IsCompleted) return "";
        // coreutils sum tools print "<hex>␣␣<path>"; take the leading hex token.
        var tok = r.Output.Split((char[]?)null, StringSplitOptions.RemoveEmptyEntries);
        return tok.Length > 0 ? tok[0].Trim().ToLowerInvariant() : "";
    }

    // True for an EWF/Expert Witness image whose content hash must be verified with ewfverify rather than by
    // file-hashing the container (.E01 = EWF1 first/only segment, .Ex01 = EWF2).
    private static bool IsEwfImage(string path) =>
        path.EndsWith(".e01", StringComparison.OrdinalIgnoreCase) ||
        path.EndsWith(".ex01", StringComparison.OrdinalIgnoreCase);
```

```csharp
    // Recomputes an EWF image's media-content digest with ewfverify and returns it as lower-case hex, or "" on
    // failure. ewfverify always calculates MD5; SHA-1/SHA-256 are requested with -d. Retries under sudo for
    // root-owned evidence on a forensic mount. Reads the whole image, so this can take minutes for a large disk.
    private async Task<string> ComputeEwfContentHashAsync(string path, HashType type)
    {
        var algo = type switch { HashType.MD5 => "md5", HashType.SHA256 => "sha256", _ => "sha1" };
        // -q keeps the progress chatter down but still prints the hash summary; -d adds the non-MD5 digest.
        var args = (type == HashType.MD5 ? "" : $"-d {algo} ") + $"-q '{path}'";
        var hash = ParseEwfDigest((await ExecuteCommandAsync("ewfverify", args)).Output, algo);
        if (hash.Length == 0 && IsUnix)
            hash = ParseEwfDigest((await ExecuteCommandAsync("ewfverify", args, admin: true)).Output, algo);
        return hash;
    }
```

```csharp
    public async Task<CaseEvidenceVerification> VerifyCaseEvidenceAsync()
    {
        var results = new List<EvidenceHashCheck>(CaseEvidence.Length);
        var success = true;
        foreach (var e in CaseEvidence)
        {
            var hasHash = e.HashType != HashType.None && !string.IsNullOrEmpty(e.HashValue);
            // With a supplied hash, recompute with that algorithm to compare; otherwise record SHA-1 as the baseline.
            // An E01 with a supplied hash is verified against its media-content digest (ewfverify), not the container.
            var current = hasHash && IsEwfImage(e.FilePath)
                ? await ComputeEwfContentHashAsync(e.FilePath, e.HashType)
                : await ComputeFileHashAsync(e.FilePath, hasHash ? e.HashType : HashType.SHA1);

            if (!matched) success = false;
            results.Add(new EvidenceHashCheck(e, current, matched));
        }
        return new CaseEvidenceVerification(success, results.ToArray());
```

```csharp
    {
        using var _audit = AuditScope();
        using var op = Begin("Verifying EWF image {0}", imageFile);

        var info = await DiskAnalysis.EwfInfoAsync(imageFile);
        if (info is null)
            return WorkflowResult<ImageVerification>.Failure(

        if (verify is null)
            return WorkflowResult<ImageVerification>.Failure($"ewfverify did not complete for '{imageFile}'.");

        // carried in IntegrityVerified so a caller can decide whether to proceed.

            new ImageVerification(info, verify),
            verify.Success
                ? $"Integrity verified: calculated hash matches the acquisition hash (MD5 {verify.CalculatedMD5})."
                : $"INTEGRITY CHECK FAILED: stored MD5 {verify.StoredMD5} != calculated {verify.CalculatedMD5}. Do not rely on this image.");
```
