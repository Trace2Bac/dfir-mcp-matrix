# E04 분석 입력 준비

### E04.01 작업 사본 생성

**구현.** 파일을 통째로 작업 위치에 옮기는 메서드는 두 종류다.
모델이 부르는 `UnixToolsToolkit`의 `Bunzip2Async`는 bzip2 파일을 받은 출력 경로에 풀고 원본 압축 파일은 그대로 둔다 [1].
`UnzipAsync`·`SevenZipExtractAsync`는 압축 파일 전체를 받은 출력 폴더에 풀고 같은 이름의 파일은 묻지 않고 덮어쓴다 [2][3].
`CopyFileAsync`·`CopyDirAsync`는 파일이나 폴더를 받은 위치로 `cp -p`·`cp -rp`로 복사한다 [4][5].
두 복사 메서드는 `verify`를 참으로 주면 복사 뒤 원본과 사본의 SHA-256을 견주고 기본값은 거짓이다 [4][5].

파서 쪽에서는 서버 코드가 스스로 사본을 만든다.
`SqliteQueryAsync`는 SQLite DB를, `RECmdSingleHiveAsync`는 하이브를, `UsbDeviceForensicsAsync`는 SYSTEM·SOFTWARE(주면 NTUSER.DAT까지) 하이브를 `/tmp` 아래 새 임시 폴더에 복사한 뒤 그 사본을 도구에 넘긴다 [6][7][8].
메서드가 끝나면 임시 폴더를 지운다 [6][7][8].
그 밖의 파서와 외부 도구에는 증거 경로나 마운트 아래 경로를 그대로 넘긴다(E03.03).

**한계.** `UnzipAsync`·`SevenZipExtractAsync`는 출력 폴더 전체를 `find`로 훑어 결과 목록을 만들므로 그 폴더에 이미 있던 파일도 이번에 푼 파일로 목록에 들어간다 [2][3].
`RECmdSingleHiveAsync`와 `UsbDeviceForensicsAsync`는 복사 명령의 결과를 보지 않고 바로 도구를 실행한다 [7][8].
`SqliteQueryAsync`는 복사 오류를 `2>/dev/null; true`로 버리고 결과 JSON을 읽다 예외가 나면 빈 배열을 돌려준다 [6].

### E04.02 선택 추출

**구현.** 이미지에서 고른 범위만 꺼내는 메서드는 모델이 inode·폴더 inode·이름 조건·PID를 주어 부른다.
`IcatAsync`·`IcatByAddrAsync`는 inode 하나의 내용을 모델이 정한 출력 파일로 꺼낸다 [9].
`DiskAnalysisWorkflow.RecoverDeletedFileAsync`는 삭제 파일의 inode 주소로 `IcatByAddrAsync`를 부른다 [10].
`TskRecoverAsync`는 `dirInode`를 주면 그 폴더 아래만, 주지 않으면 파일시스템의 할당 파일 전체(`all`이면 삭제 파일까지)를 출력 폴더로 꺼낸다 [11].
`TimelineToolkit.ImageExportAsync`는 plaso `image_export`에 이름 glob과 확장자 조건을 넘겨 맞는 파일을 꺼낸다 [12].
`UnzipAsync`·`SevenZipExtractAsync`는 `files`를 주면 그 항목만 푼다 [2][3].
메모리 이미지에서는 `DumpFilesAsync`·`DumpProcessExecutableAsync`·`DumpProcessMemoryAsync`가 Volatility 플러그인에 주소·PID·이름 정규식을 넘겨 고른 파일 객체·실행 파일·프로세스 메모리를 꺼낸다 [13].
조건을 어떻게 대조하는지는 각 외부 도구가 정하고 꺼낼 위치는 모델이 정한다.

### E04.03 전체·부분 마운트

**구현.** `DiskAnalysisWorkflow.MountEwfImageAsync`는 `ewfinfo`로 이미지를 확인하고 `ewfmount`로 원시 디스크 전체를 `<mountDir>/ewf1`에 올린 뒤 `mmls` 파티션 표를 돌려준다 [14].
`MountFileSystemAsync`는 모델이 고른 시작 섹터에서 `fsstat`으로 파일시스템을 확인한 뒤 그 파티션 하나만 올린다 [15].
`DDMountAsync`는 raw 이미지나 그 안의 파티션을 루프백으로 올리고 `BdeMountAsync`는 BitLocker 볼륨을 복호화해 `bde1` 장치로 올린다 [16][17].
마운트의 읽기 전용 여부는 E03.01에서 본다.

### E04.05 추출·생략 범위 기록

**구현.** 압축 풀기·복사 메서드는 꺼낸 파일마다 경로와 크기를 담은 `Files`와 합계 `TotalBytes`를 결과로 돌려준다 [2][18].
복사 메서드는 `verify`를 주면 `Verified`와 어긋난 경로 `Mismatches`를 더한다 [4][18].
`TskRecoverAsync`는 `tsk_recover` 출력에서 꺼낸 파일 수를 읽어 돌려주고 `RecoverFilesAsync`는 그 수를 메시지에 적는다 [11][19].
Volatility 덤프 메서드는 꺼낸 파일의 경로 목록을 돌려준다 [13].
`IcatAsync`·`ImageExportAsync`는 성공 여부만 돌려준다 [9][12].
이 값들은 `Execute` 스크립트로 돌아가고 스크립트가 `log` 등으로 출력한 것만 모델 응답에 들어간다 [20].
호출 기록에는 실행한 명령과 인자·종료 코드만 남고 꺼낸 파일 목록은 남지 않는다 [21].

**한계.** 압축 풀기 결과 목록은 출력 폴더 전체를 훑어 만들므로 앞서 있던 파일이 섞인다(E04.01의 예외) [2].
Volatility 덤프 메서드는 크기가 0인 덤프 파일을 목록에서 빼고 뺀 사실이나 개수를 결과에 적지 않는다 [13].
`TskRecoverAsync`는 출력에서 "Files Recovered" 줄을 찾지 못하면 0을 돌려준다 [11].

### E04.06 부속 자료 탐색

**구현.** 서버 코드가 부속 자료를 찾는 곳은 둘이다.
`RECmdSingleHiveAsync`는 하이브 경로 뒤에 `*`를 붙인 `cp`로 이름이 하이브 이름으로 시작하는 파일(트랜잭션 로그 `.LOG1`·`.LOG2` 등)을 하이브와 함께 임시 폴더에 복사한다 [7].
`SqliteQueryAsync`는 DB와 함께 같은 이름의 `-wal`·`-shm`·`-journal` 파일을 복사한다 [6].
`AmcacheParserAsync`·`AppCompatCacheParserAsync`는 하이브 경로만 넘기고 로그를 찾는 일은 도구에 맡긴다 [22].
`UsbDeviceForensicsAsync`는 하이브만 복사하고 로그는 옮기지 않는다 [8].
E01 분할 조각은 첫 조각만 넘기고 나머지를 잇는 일은 `ewfmount`·`ewfverify`에 맡긴다 [23].

**한계.** 두 경로 모두 복사 결과를 확인하지 않아 부속 자료 복사에 실패해도 결과나 응답에 드러나지 않는다 [6][7].
`RECmdSingleHiveAsync`의 glob은 대소문자를 가리므로 하이브와 대소문자가 다른 이름으로 남은 로그 파일은 복사하지 않는다 [7].
실제 이미지에서 로그 파일 이름이 하이브 이름과 대소문자까지 같은지는 확인하지 않았다.

### E04.08 로그 재생·복원

**구현.** 로그를 하이브에 적용하는 일은 RECmd·AmcacheParser·AppCompatCacheParser가 하고 서버 코드는 하지 않는다.
`RECmdSingleHiveAsync`는 로그를 함께 복사해 RECmd가 하이브에 적용하게 한다고 설명에 적는다 [7].
`AnalyzeExternalShareConnectionsAsync`는 이 메서드로 NTUSER.DAT를 읽는다 [24].
`AmcacheParserAsync`·`AppCompatCacheParserAsync`는 `ignoreTransactionLogs`가 참이면 `--nl`을 넘겨 도구의 로그 적용을 끈다 [22].
`GetExecutedBinariesFromAmcacheAsync`는 기본값으로 로그를 적용한다 [25].
`RegRipperAsync` 설명은 rip.pl이 로그를 적용하지 않는다고 적는다 [26].
SQLite DB에서는 `SqliteQueryAsync`가 DB와 함께 `-wal` 파일을 임시 폴더에 복사해 `sqlite3`가 그 사본을 열 때 WAL을 반영하게 한다고 설명에 적는다 [6].
복사 오류를 버리는 처리는 E04.01·E04.06 예외에서 본다.

**한계.** `GetKnownExecutablesFromShimcacheAsync`는 `ignoreTransactionLogs`의 기본값이 참이라 모델이 따로 주지 않으면 로그를 적용하지 않는다 [27].
두 workflow의 결과 메시지는 로그를 적용했는지 적지 않는다 [25][27].
외부 도구가 로그를 실제로 적용하는지는 실행해 확인하지 않았다.
`sqlite3`가 `-readonly`로 연 사본에 `-wal`의 내용을 실제로 반영하는지도 실행해 확인하지 않았다 [6].

```csharp
    /// Decompresses the bzip2 file <paramref name="file"/> (e.g. <c>memdump.raw.bz2</c>, <c>image.E01.bz2</c>)
    /// to <paramref name="outputFile"/> on the workstation, keeping the original archive. When
    /// <paramref name="outputFile"/> is null the destination is <paramref name="file"/> with a trailing
    /// <c>.bz2</c> stripped (or <c>.out</c> appended when it has no <c>.bz2</c> suffix). Streams via
    /// <c>bunzip2 -c</c> so the output path is chosen explicitly. Set <paramref name="sudo"/> when the source
    /// archive is root-owned (the decompressed output is still written as the login user via the redirect).
    /// Returns a <see cref="DecompressResult"/> describing the single decompressed file (with its size), or
    /// null on failure.
    /// </summary>
    public async Task<DecompressResult?> Bunzip2Async(string file, string? outputFile = null, bool sudo = false)
    {
        var output = outputFile ?? (file.EndsWith(".bz2", StringComparison.OrdinalIgnoreCase) ? file[..^4] : file + ".out");
        auditEnvironment.FailIfEvidenceSpoliationRisk(output);   // never decompress over registered evidence
        // Decompress to the chosen path, then list it (size\tpath) so the result carries the output size
        // back in one round-trip. The redirect/listing run in the remote shell, same as the disk icat path.
        return await RunAsync("Bunzip2",
                $"-c {Q(file)} > {Q(output)} && find {Q(output)} -type f -printf '%s\\t%p\\n'", sudo) is { } o
            ? DecompressResult.FromFindListing(file, output, o)
            : null;
    }
```

```csharp
    /// Copies the single file <paramref name="source"/> to <paramref name="dest"/> on the workstation
    /// (e.g. staging an image from an external/removable directory to <c>/mnt</c> or <c>/cases</c>),
    /// preserving mode and timestamps (<c>cp -p</c>). <paramref name="dest"/> is the full destination file
    /// path; its parent directory is created if missing. Set <paramref name="sudo"/> when the source or the
    /// destination tree is root-owned. When <paramref name="verify"/> is set the SHA-256 of the source and the
    /// copy are compared after the copy and reported via <see cref="CopyResult.Verified"/>. Returns a
    /// <see cref="CopyResult"/> describing the copied file (with its size), or null on failure.
    /// </summary>
    public async Task<CopyResult?> CopyFileAsync(string source, string dest, bool sudo = false, bool verify = false)
    {
        auditEnvironment.FailIfEvidenceSpoliationRisk(dest);   // never copy over registered evidence
        if (ParentDir(dest) is { Length: > 0 } parent)
            await auditEnvironment.ExecuteCommandAsync("mkdir", $"-p {Q(parent)}", sudo);
        if (await RunAsync("CopyFile",
                $"-p {Q(source)} {Q(dest)} && find {Q(dest)} -type f -printf '%s\\t%p\\n'", sudo) is not { } o)
            return null;
        var result = CopyResult.FromFindListing(source, dest, o);
        if (!verify) return result;
        var (ok, bad) = await VerifyFileAsync(source, dest, sudo);
        return result with { Verified = ok, Mismatches = bad };
    }
```

[6] `SqliteQueryAsync`는 DB와 `-wal`·`-shm`·`-journal`을 임시 폴더에 복사하며 복사 오류를 버린다.

```csharp
    /// <summary>
    /// Runs a read-only SQL query against a SQLite database (Chrome/Edge <c>History</c>, Firefox
    /// <c>places.sqlite</c>, …) with the <c>sqlite3</c> CLI in <c>-json</c> mode, returning the rows as raw
    /// key/value records. The database and any sidecar <c>-wal/-shm/-journal</c> files are staged into a writable
    /// temp directory first (a forensic mount is read-only, which blocks WAL recovery), then queried with
    /// <c>-readonly</c>. SQLECmd's EZ build is unusable on SIFT (missing <c>SQLite.Interop.dll</c>), so browser
    /// SQLite parsing goes through this. Returns null on failure.
    /// </summary>
    public async Task<Dictionary<string, System.Text.Json.JsonElement>[]?> SqliteQueryAsync(string dbFile, string sql)
    {
        string dir = "/tmp/camel_sqlite_" + Guid.NewGuid().ToString("N");
        await auditEnvironment.ExecuteCommandAsync("mkdir", $"-p {dir}", false);
        try
        {
            // Stage the DB plus any WAL/journal sidecars so sqlite3 can open it read-write off the read-only mount.
            await auditEnvironment.ExecuteCommandAsync("bash", $"-c \"cp {Q(dbFile)} {Q(dbFile)}-wal {Q(dbFile)}-shm {Q(dbFile)}-journal {dir}/ 2>/dev/null; true\"", false);
            string staged = $"{dir}/{System.IO.Path.GetFileName(dbFile)}";
            var b64 = Convert.ToBase64String(System.Text.Encoding.UTF8.GetBytes(sql));
            // Ship the SQL base64-encoded to dodge all shell quoting of quotes/semicolons in the query.
            var r = await auditEnvironment.ExecuteCommandAsync("bash",
                $"-c \"sqlite3 -readonly -json {Q(staged)} \\\"$(echo {b64} | base64 -d)\\\"\"", false);
            if (!r.IsCompleted) return null;
            var json = r.Output.Trim();
            if (json.Length == 0) return [];   // sqlite3 prints nothing for an empty result set
            return System.Text.Json.JsonSerializer.Deserialize<Dictionary<string, System.Text.Json.JsonElement>[]>(json, JsonLineOptionsPublic) ?? [];
        }
        catch { return []; }
        finally { try { auditEnvironment.ExecuteCommand("rm", $"-rf {dir}", out _, false); } catch { } }
    }
```
