# P04 조사 문맥 관리

### P04.01 사건 시작 시 ID 확정

**구현.** MCP 도구 `SetCaseId`가 지금 세션의 사건 ID를 정한다 [1].
빈 값을 주면 세션 ID를 쓰고 그 밖의 값은 앞뒤 공백만 지우고 검사 없이 받는다 [1].
`SetCaseId`를 부르지 않은 세션은 세션을 만들 때 넣은 세션 ID를 사건 ID로 쓴다 [2].
`SetEvidence`·`VerifyEvidence`·`Execute`는 호출을 시작할 때 세션의 사건 ID를 기록 문맥에 넣어 그 호출이 남기는 기록을 사건에 묶는다 [3].
`SetCaseId`는 언제든 다시 불러 사건을 바꿀 수 있고 도구 설명도 그렇게 안내한다 [1].
사건을 바꿔도 이미 시작한 `Execute`의 기록은 시작할 때의 사건에 남는다 [3].
`camel create-case`는 사건 ID가 영문자·숫자·`.`·`_`·`-`만 쓰는지 검사하고 사건 `CLAUDE.md`에 그 ID로 `SetCaseId`를 먼저 부르라고 적는다 [4][5].
서버는 `SetCaseId`를 부르지 않은 호출을 막지 않는다 [2].

**예외.** 4시간 넘게 호출이 없던 세션은 정리되고 같은 세션 ID로 온 다음 호출은 새 문맥을 받는다 [6][7].
새 문맥의 사건 ID는 세션 ID로 돌아가고 응답은 이를 알리지 않아 뒤의 기록이 `audit-<세션 ID>.clef`로 간다 [2][7].
stdio 연결은 세션 ID가 `default`라서 이때 기록은 `audit-default.clef`에 쌓인다 [8].

### P04.03 폴더·DB·manifest에 사건 ID 연결

**구현.** 호출 기록 파일은 사건 ID로 이름을 지은 `audit-<CaseId>.clef`이고 각 기록 항목에는 `CaseId`·`ExecutionId` 속성이 들어간다 [9].
`Execute`는 응답 끝에 `[audit] case=<사건 ID> execution=<실행 ID>` 줄을 붙인다 [10].
`create-case`는 사건 ID를 이름으로 한 사건 폴더를 만들고 그 폴더를 서버 실행 인자 `--case-dir`로 `.mcp.json`에 넣는다 [4][11].
서버는 `--case-dir` 아래 `logs/`를 호출 기록 폴더로 쓴다 [12].
`Execute` 스크립트가 만드는 파생물의 경로에는 사건 ID가 들어가지 않고 경로는 스크립트나 workflow 기본값이 정한다 [13].

**예외.** 기록 파일 이름은 파일 이름에 쓸 수 없는 문자와 공백을 `_`로 바꾼 값이다 [14].
`SetCaseId` 응답은 바꾸기 전의 ID로 파일 이름을 알려 공백이 든 ID를 주면 응답이 알린 파일과 실제 기록 파일 이름이 다르다 [1][14].
`Execute` 응답의 `case=` 값은 호출이 끝날 때 세션의 사건 ID를 읽고 기록 항목의 `CaseId`는 호출을 시작할 때 넣는다 [3][10].
실행 중에 `SetCaseId`가 처리되면 응답이 가리키는 사건과 실행 기록이 남은 파일이 다르다 [3][10].
`SessionContext` 주석은 세션 안의 호출이 차례로 처리된다고 적지만 서버 코드에 그렇게 막는 장치는 없다 [15].
서버가 쓰는 `ModelContextProtocol` 1.4.0은 같은 세션의 메시지마다 처리를 따로 시작하고 기다리지 않아 같은 세션의 호출이 겹쳐 실행될 수 있다 [16].

### P04.04 사건별 폴더·DB 분리

**구현.** `create-case`는 사건마다 `<상위 폴더>/<사건 ID>/` 아래 `logs`·`exports`·`reports`를 만든다 [4].
클라이언트는 그 사건의 `.mcp.json`에 적힌 `--case-dir`로 서버를 실행하므로 사건마다 서버 프로세스와 호출 기록 폴더가 따로 생긴다 [11][12].
한 서버 안에서도 호출 기록은 사건 ID마다 다른 파일로 나뉜다 [9].
`Session` 저장소와 등록한 증거는 사건이 아니라 세션에 묶인다 [17][18].
`Execute`가 워크스테이션에 만드는 파생물과 마운트 폴더는 스크립트가 준 경로에 쓰이고 사건별로 나누는 장치가 없다 [13].

**예외.** `SetCaseId`로 사건을 바꿔도 `Session` 저장소와 등록한 증거는 그대로 남아 앞 사건의 캐시 결과와 증거 보호 목록을 뒤 사건에서 쓴다 [1][17][18].
`camel-sdk-core`는 `Session` 저장소가 조사 사이에 공유되지 않는다고 적어 이 동작과 다르다 [19].
호출 기록 폴더는 서버를 시작할 때 한 번 정해져 바꾼 사건의 기록 파일도 처음 사건 폴더의 `logs/`에 생긴다 [12].
`SanitizeCaseId`는 공백과 금지 문자를 `_`로 바꾸므로 `a b`와 `a_b` 같은 서로 다른 사건 ID의 기록이 한 파일에 쌓인다 [14].
`DiskAnalysisWorkflow.GenerateFilesystemTimelineAsync`는 bodyfile 경로를 주지 않으면 `/tmp/camel_bodyfile_<오프셋>.txt`에 써서 같은 워크스테이션의 다른 사건이 같은 오프셋으로 만든 파일을 덮어쓴다 [13].

### P04.05 세션·프로세스 상태 분리

**구현.** `SessionRegistry`는 MCP 세션 ID마다 `SessionContext`를 하나씩 만든다 [2].
세션마다 실행 환경과 그 SSH 연결, 툴킷·workflow 객체, 사건 ID, 등록한 증거, `Session` 저장소를 따로 둔다 [17][18].
서버는 HTTP 전송을 상태를 두는 세션 모드로 설정하므로 여러 클라이언트가 한 서버 프로세스에 붙으면 이 분리가 쓰인다 [20].
stdio처럼 세션 ID가 없는 연결은 모두 `default` 세션을 쓴다 [8].
동시에 둘 수 있는 세션은 16개이고 넘으면 새 세션을 만들지 않고 예외를 던진다 [2][21].

**예외.** 호출 기록 로거는 프로세스에 하나이고 사건 ID로만 파일을 나눈다 [9].
두 세션이 같은 사건 ID를 쓰면 한 파일에 두 세션의 기록이 섞이고 `Execute`와 명령 기록 항목에는 세션 ID 속성이 없다 [3][9].
세션들은 같은 워크스테이션 파일 시스템을 쓰므로 P04.04에서 본 고정 임시 경로는 세션 사이에서도 겹친다 [13].

### P04.08 프로세스 메모리에만 보관

**구현.** 사건 ID, 마지막 호출 시각, `Session` 저장소는 `SessionContext`의 필드이고 등록한 증거 목록은 실행 환경 객체의 필드다 [17][18].
서버 프로세스가 끝나거나 세션이 정리되면 이 상태가 사라진다 [7].
`camel-sdk-core`는 `Session`을 `Execute` 호출 사이에 남는 저장소로 안내하고 비싼 결과를 캐시해 다시 쓰라고 권한다 [19].

### P04.09 조사 상태를 파일·DB에 저장

**구현.** 호출 기록 `audit-<CaseId>.clef`에는 `Execute`마다 실행한 스크립트 전문과 시작·끝 상태가 남는다 [22].
그 안에서 돈 명령마다 호스트·명령·인자·sudo 여부·종료 코드·걸린 시간도 남는다 [23].
`SetCaseId`·`SetEvidence`·`VerifyEvidence`의 결과와 모델이 `audit*` 함수로 적은 기록도 같은 파일에 남는다 [1][24].
서버는 이 파일을 다시 읽지 않아 사건 ID·등록한 증거·`Session` 저장소를 이 파일로 되살리지 않는다 [9].
그래서 P04.10에는 연결하지 않는다.
workflow가 만든 Plaso 저장 파일 같은 파생물도 워크스테이션에 남지만 그 보관은 D01에서 본다.

### P04.11 만료

**구현.** 서버 안의 `IdleSessionSweeper`가 1분마다 세션을 훑는다 [6].
15분 넘게 호출이 없으면 SSH 연결만 끊고 사건 ID·등록한 증거·`Session` 저장소는 남긴다 [6][7].
4시간 넘게 호출이 없으면 세션을 지워 그 상태를 모두 버린다 [6][7].
도구 호출이 진행 중인 세션은 건너뛴다 [7].
정리 사실은 서버 로그에만 남고 사건 호출 기록에는 남지 않는다 [7].

```csharp
    [McpServerTool(Name = "SetCaseId"), Description(
        "Set the case identifier for this session's audit trail. Call this ONCE at the start of an investigation " +
        "with a short, human-readable case id (e.g. 'srl-2018-rd01'). Every subsequent Execute tool " +
        "execution in this session is recorded in a per-case audit log file named for this id (audit-<caseId>.clef), " +
        "so findings can be traced to the exact tool executions that produced them. One case per session; call " +
        "again to switch cases. Returns the case id that was set.")]
    public string SetCaseId(string caseId, RequestContext<CallToolRequestParams> context)
    {
        var session = registry.GetOrCreate(SessionId(context.Server));
        var previous = session.CaseId;
        session.CaseId = string.IsNullOrWhiteSpace(caseId) ? session.SessionId : caseId.Trim();
        // Record the case association in the (new) case's audit file so the switch itself is auditable.
        using (PushAuditProperty("CaseId", session.CaseId))
            AuditEvent("case", "Case id set to {CaseId} (was {Previous}) for session {SessionId}",
                session.CaseId, previous, session.SessionId);
        return $"Case id set to '{session.CaseId}' for this session. Audit trail file: audit-{session.CaseId}.clef";
    }
```

```csharp
public sealed class IdleSessionSweeper : BackgroundService
{
    private readonly SessionRegistry registry;
    private readonly TimeSpan interval = TimeSpan.FromMinutes(1);
    // Release an idle session's SSH connection after 15 min (its in-memory Session storage is retained so a
    // returning client keeps its cached results) ...
    private readonly TimeSpan disconnectTtl = TimeSpan.FromMinutes(15);
    // ... and fully evict a session only after it has been abandoned for hours, to bound slot/memory growth.
    private readonly TimeSpan evictTtl = TimeSpan.FromHours(4);

    public IdleSessionSweeper(SessionRegistry registry) => this.registry = registry;

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        using var timer = new PeriodicTimer(interval);
        try
        {
            while (await timer.WaitForNextTickAsync(stoppingToken))
                registry.SweepIdle(disconnectTtl, evictTtl);
        }
        catch (OperationCanceledException) { /* shutting down */ }
    }
```

```csharp
    public void SweepIdle(TimeSpan disconnectTtl, TimeSpan evictTtl)
    {
        var now = DateTimeOffset.UtcNow;
        foreach (var kv in sessions)
        {
            if (!kv.Value.IsValueCreated) continue;
            var ctx = kv.Value.Value;
            if (ctx.IsBusy) continue;                       // a call in flight must keep its connection
            var idle = now - ctx.LastAccess;
            if (idle > evictTtl)
            {
                Runtime.Info("Evicting idle MCP session {0} (inactive longer than {1}).", kv.Key, evictTtl);
                End(kv.Key);
            }
            else if (idle > disconnectTtl && ctx.DisconnectIdle())
            {
                Runtime.Info("Released idle SSH connection for MCP session {0} (inactive longer than {1}); session state retained.",
                    kv.Key, disconnectTtl);
            }
        }
    }
```

```csharp
    private static string SanitizeCaseId(string caseId)
    {
        if (string.IsNullOrWhiteSpace(caseId)) return "unknown";
        var invalid = System.IO.Path.GetInvalidFileNameChars();
        var chars = caseId.Trim().Select(c => Array.IndexOf(invalid, c) >= 0 || c == ' ' ? '_' : c).ToArray();
        return new string(chars);
    }
```

```csharp
    private bool evidenceRegistered;

    /// <summary>
    /// Registers the original case evidence for this environment — once. Returns true if accepted; false if
    /// evidence was already registered, in which case nothing changes and the existing evidence stands. Evidence
    /// is deliberately write-once per session so an analyst (or a confused agent) cannot silently repoint the
    /// spoliation guard part-way through a case; changing it requires a fresh session. The caller (the

    /// </summary>
```
