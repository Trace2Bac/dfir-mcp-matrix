# F04 발견사항·결론 기록 관리

### F04.01 자유 노트

**구현.** 발견사항과 결론을 받는 곳은 `Execute` 스크립트가 부르는 전역 함수다 [1].
`auditFalsePositive`·`auditMissingEvidence`·`auditHallucination`·`auditReviewRec`·`auditInfo`는 문자열 하나를 받아 사건 호출 기록에 `false-positive`·`missing-evidence`·`hallucination`·`human-judgement-recommended`·`information` 종류의 항목으로 남긴다 [1][2].
같은 줄을 `Execute` 응답 본문에도 붙인다 [2].
배제한 단서, 증거 공백, 스스로 찾은 잘못, 사람 판단이 필요한 결정은 이 자유 글로만 남고 판정 필드는 없다 [2].
`auditReviewRec`의 코드 설명은 이 함수로 남기는 것을 근본 원인, 공격자 귀속, 침해 범위, 유출, 내부자 관여, 가설 배제 같은 결론으로 적는다 [2].
그래서 이런 결론도 판정 필드 없이 자유 글 한 줄로 남는다 [2].
사건 템플릿 `CLAUDE.md`는 이 함수들을 언제 부를지 안내한다 [3].
공격 흐름 서술이나 사건 전체 결론을 따로 받는 함수는 없다 [1].

### F04.02 발견사항 필드 구분 저장

**구현.** 전역 함수 `auditFinding(observation, interpretation, confidence, evidenceExecutionIds)`는 관찰·해석·확신도·근거 실행 ID를 따로 받아 `finding` 항목으로 남긴다 [4].
항목의 속성 이름은 메시지 틀에 따라 `Observation`·`Interpretation`·`Confidence`·`EvidenceExecutionIds`가 된다 [4].
`interpretation`에는 관찰에서 내린 해석이 들어가므로 한 `finding` 항목에 발견사항과 그 결론이 함께 남는다 [4].
MCP 리소스 `camel-sdk-discipline`은 결론을 `auditFinding`으로 남기라고 적는다 [5].
사건 템플릿은 확신도를 `SPECULATIVE`·`LOW`·`MEDIUM`·`HIGH` 가운데 하나로 쓰라고 안내한다 [3].
제목이나 심각도 필드는 따로 없다 [4].
서버는 네 인자의 형식을 검사하지 않아 확신도 값 목록은 안내문에만 있고 F04.10에는 연결하지 않는다 [4].
`confidence`에 정해진 네 값 밖의 문자열이나 빈 문자열을 넘겨도 그대로 남는다 [4].

### F04.03 근거 증거·호출 참조

**구현.** `finding` 항목은 근거 실행 ID 문자열 `EvidenceExecutionIds`와 그 발견사항을 기록한 `Execute` 호출의 `ExecutionId`를 함께 가진다 [4][6].
`ExecutionId`는 서버가 문맥에 넣는 값이고 `EvidenceExecutionIds`는 스크립트가 넘긴 값이다 [4][6].
근거 증거 파일이나 파생물 경로를 따로 받는 필드는 없다 [4].

**한계.** `evidenceExecutionIds`는 구분 형식이 정해지지 않은 자유 문자열 하나이고 서버는 비어 있는지도 보지 않는다 [4].
그 ID가 호출 기록에 있는지 보는 심사도 없다.

### F04.06 파일·DB에 저장

**구현.** 이 항목들은 서버 프로세스 밖의 사건별 파일 `audit-<caseId>.clef`에 JSON 한 줄씩 붙여 쓰므로 서버를 다시 시작해도 남는다 [7].
항목의 시각은 기록한 시각 하나이고 발견사항이 가리키는 사건 시각을 받는 인자는 없어 F04.04에는 연결하지 않는다 [4][7].
발견사항을 고치거나 철회하는 함수는 없고 새 항목을 덧붙이는 것뿐이라 F04.05에는 연결하지 않는다 [1].
가설을 따로 두거나 상태를 바꾸는 함수도 없다 [1].

### F04.12 관련 없음·배제 처분 기록

**구현.** 스크립트 전역 함수 `auditFalsePositive`는 확인한 뒤 정상으로 배제한 단서를 `false-positive` 종류의 항목으로 사건 호출 기록에 남긴다 [1][2].
코드 주석과 함수 설명은 이 항목을 확인한 뒤 benign으로 기각한 단서로 적는다 [1][2].
배제한 대상과 사유는 받은 문자열 하나에 함께 들어가고 따로 나뉜 필드는 없다 [2].
배제의 근거가 된 실행 ID를 받는 인자도 없다 [1].
항목에는 그 글을 기록한 `Execute` 호출의 `ExecutionId`가 붙는다 [6].
MCP 리소스 `camel-sdk-discipline`은 이상 탐지로 표시된 단서를 확인해 배제하면 `auditFalsePositive`로 남기라고 안내한다 [8].
사건 템플릿 `CLAUDE.md`도 정상으로 판정한 단서에 이 함수를 쓰라고 안내한다 [3].

```csharp
    /// <summary>
    /// Records a structured forensic finding to the per-case audit trail as a <c>finding</c> event — observation
    /// and interpretation kept as distinct fields (forcing the agent to separate fact from inference), with the
    /// confidence level and the <c>execution</c> ids that prove it. Also echoes a one-line summary to the response.
    /// </summary>
    protected void AuditFinding(string observation, string interpretation, string confidence, string evidenceExecutionIds, StringBuilder output)
    {
        AuditEvent("finding",
            "FINDING [{Confidence}] {Observation} => {Interpretation} (evidence: {EvidenceExecutionIds})",
            confidence, observation, interpretation, evidenceExecutionIds);
        output.AppendLine($"[finding {confidence}] {observation} => {interpretation} (evidence: {evidenceExecutionIds})");
    }
```

```csharp
    /// <summary>
    /// Configures the dedicated audit logger: a separate Serilog pipeline that writes structured CLEF (JSON)
    /// events, one file per <c>CaseId</c> (<c>audit-&lt;CaseId&gt;.clef</c> under <paramref name="auditDir"/>),
    /// routed by the <c>CaseId</c> property the MCP server pushes onto the <see cref="Serilog.Context.LogContext"/>.
    /// Because it also enriches <c>FromLogContext</c>, every audit event automatically carries the ambient
    /// <c>CaseId</c>, <c>ExecutionId</c>, <c>Workflow</c>, and <c>Toolkit</c>/<c>Operation</c> in scope — so a
    /// judge can trace any finding to the exact tool execution, on a per-case basis, from these files alone.
    /// Kept separate from the main (verbose) log so the audit trail is clean and reconstructable.
    /// </summary>
    public static void WithAuditLog(string auditDir)
    {
        System.IO.Directory.CreateDirectory(auditDir);
        _auditLogger = new LoggerConfiguration()
            .Enrich.FromLogContext()
            .MinimumLevel.Information()
            .WriteTo.Map(
                keyPropertyName: "CaseId",
                defaultKey: "unknown",
                configure: (caseId, wt) => wt.File(
                    new Serilog.Formatting.Compact.CompactJsonFormatter(),
                    System.IO.Path.Combine(auditDir, $"audit-{SanitizeCaseId(caseId)}.clef")))
            .CreateLogger();
    }
```
