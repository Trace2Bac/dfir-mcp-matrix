# F03 서버 안 모델 입력 구성

### 비적용

**판단.** Camel 서버는 처리 중에 모델 API를 부르지 않는다.
서버 프로젝트가 쓰는 패키지는 JavaScript 실행 엔진 `Jint`, MCP SDK `ModelContextProtocol`, 호스팅 라이브러리뿐이다 [1].
서버가 참조하는 프로젝트는 `Camel.Environments`·`Camel.Runtime`·`Camel.Toolkits`·`Camel.Inference`·`Camel.Workflows` 다섯이다 [1].
이 다섯 프로젝트의 패키지는 SSH·압축·로그·설정·JSON·YAML 라이브러리이고 모델 API 클라이언트가 없다 [2].
`Camel.Environments`가 참조하는 하위 모듈 `ext/Expect.NET`은 로컬 클론에 없어 그 코드를 확인하지 못했다 [2].
서버 코드는 이 라이브러리를 실행 환경의 명령 출력에서 sudo 비밀번호 요청이나 성공·실패 문자열을 기다리는 데 쓴다 [3].
이상 탐지를 하는 `Camel.Inference`는 패키지를 쓰지 않고 기본 탐지기 다섯으로 사건마다 점수를 계산한다 [4].
ONNX 문장 임베딩 모델을 실행하는 `Camel.Search`는 서버 프로젝트가 참조하지 않는다 [1][5].
서버 코드에는 MCP sampling으로 클라이언트 모델에게 생성을 요청하는 호출도 없다 [6].
분석은 클라이언트 모델이 써 보낸 `Execute` 스크립트가 SDK를 불러 진행하고 서버는 그 스크립트를 실행한다 [7].
그래서 서버가 모델에게 넘길 입력을 구성하는 경로가 없다.
