# R04 해석 한계 안내

### R04.01 도구별 정적 주의

**구현.** 이 절은 SDK 메서드가 Execute 스크립트에 돌려주는 객체를 결과로 본다.
그 객체가 응답 글에 실리는지는 호출자 코드가 정한다(R01.10).
정적 주의는 서버가 내놓는 MCP 리소스 `camel-sdk-discipline`에 있다 [1].
이 리소스는 증거나 결과가 없다는 것이 일이 없었다는 뜻은 아니라고 적는다 [2].
시간상 가까운 사건이 인과를 증명하지 않는다고도 적는다 [2].
이상 탐지 결과는 판정이 아닌 단서로 보라고 적는다 [2].
리소스 설명에도 같은 원칙이 짧게 들어 있다 [1].
SDK 문서 `camel-sdk-core`는 Linux 메모리 메서드가 심볼이 없으면 `null`을 돌려주며 이것이 빈 결과와 다르다고 적는다 [3].
이 주의는 `Execute`의 도구 설명과 응답에는 붙지 않는다 [4].
`Execute`의 도구 설명은 `camel-sdk-core`와 `camel-sdk-schema`를 먼저 읽으라고만 적고 `camel-sdk-core`가 `camel-sdk-discipline`을 함께 읽으라고 적는다 [4].

### R04.02 결과 조건별 주의

**구현.** 결과에 따라 고르는 주의는 무결성 확인과 Linux 악성코드 검사에 있다.
`VerifyImageAsync`는 ewfverify가 해시 불일치를 내면 `Message`에 이 이미지를 믿지 말라고 적는다 [5].
`VerifyEvidence`는 해시가 다르면 chain-of-custody 문제로 보고 멈추라는 문구를 응답에 싣는다 [6].
`ScanForMalwareAsync`는 ClamAV 탐지가 0건이면 보고서의 `Note`에 서명 DB가 최신인지 확인하라고 적는다 [7].

**예외.** `EwfVerifyAsync`는 `ExecuteToolTextAsync`로 ewfverify를 돌려 명령이 0이 아닌 종료 코드로 끝나면 `null`을 받는다 [8][9].
이때 `VerifyImageAsync`는 주의 문구 없이 ewfverify가 끝나지 않았다는 실패 결과를 돌려준다 [8].
ewfverify가 해시 불일치에서 어떤 종료 코드를 내는지는 저장소에서 확인하지 못했다.
`ScanForMalwareAsync`는 ClamAV 실행이 실패해도 결과를 빈 배열로 채우므로 `Note`가 ClamAV가 탐지하지 않았다고 적는다 [7].

### R04.03 추가 확인 도구·증거 추천

**구현.** `camel-sdk-discipline` 리소스는 발견사항을 기록하기 전에 메모리·디스크·이벤트 로그·timeline 가운데 독립된 출처 둘 이상으로 확인하라고 권한다 [10].
결과가 비어 있으면 로그가 지워졌거나 순환됐거나 켜지지 않았는지 확인하라고 권한다 [2].
`ScanForMalwareAsync`의 `Note`는 ClamAV 탐지가 0건일 때 freshclam으로 서명 DB를 확인하라고 권한다 [7].

**예외.** R04.02의 예외와 같이 ClamAV 실행이 실패한 경우에도 `Note`는 탐지가 없었다는 전제로 DB 확인만 권한다 [7].

### R04.04 불확실성·추정 범위 표시

**구현.** 판정을 내는 workflow가 확신 수준이나 점수를 값으로 싣는다.
`FindMalwareAsync`의 의심 프로세스 `MalwareSuspect`는 신호가 나온 방법론 단계 `Categories`를 싣고 단계가 둘 이상이면 `IsHighConfidence`를 참으로 둔다 [11].
보고서의 `HighConfidenceSuspects`는 그 부분 집합이다 [11].
`TriageTimelineAsync`의 pivot은 이상 정도를 surprisal 합 `Bits`로 싣는다 [12].
`HuntPersistenceAsync`의 지속성 항목은 의심 점수 `Score`와 그 이유 `Reasons`를 싣는다 [13].
`auditFinding`이 기록하는 확신 수준은 모델이 정한 값이라 D05에서 본다 [14].

**예외.** `FindMalwareAsync`는 네트워크 단계가 실패하면 빈 보고서로 대신하고 의심 프로세스에 `network` 범주를 더하지 못한다 [15].
그래도 의심 프로세스의 `IsHighConfidence`는 같은 기준으로 계산되고 항목에는 확인 단계 하나가 빠졌다는 표시가 없다 [11][15].
