# R04 도구 결과 해석 주의

### 미구현

**판단.** 도구 설명, 프롬프트, 응답 어디에도 도구 결과의 해석 한계나 결과를 확인하려면 더 볼 것을 적지 않는다.
도구 설명은 무엇을 잡거나 읽어 무엇을 돌려주는지만 적는다 [1].
서버는 초기화 지침과 리소스를 두지 않는다 [2].

응답의 고정 문구는 결과의 출처나 이름만 적는다.
`check_threats`와 `check_ip_threats`는 대조 결과 절에 `Threat check against URLhaus blacklist:` 머리를 붙이고 일치하면 `Potential threats:`나 `Potential threat detected in URLhaus blacklist.`를 싣는다 [3][4].
일치가 없을 때의 문구는 URLhaus 목록에서 찾지 못했다는 사실만 적고 그 목록에 없는 IP가 무엇을 뜻하는지는 적지 않는다 [3][4].
`extract_credentials`의 응답 끝에는 암호화된 자격증명을 John the Ripper나 hashcat으로 크래킹할 수 있다는 문구와 Kerberos 메시지 유형별 hashcat·john 모드가 늘 붙는다 [5].
이 문구는 다음에 쓸 도구를 적지만 추출한 결과가 증명하지 못하는 것이나 결과를 확인할 방법은 적지 않는다 [5].

프롬프트 7개는 분석할 내용을 번호 목록으로 적는다 [6].
`check_ip_threats_prompt`는 URLhaus 대조, IP 평판 평가, 알려진 악성 활동 확인, 보안 권고를 적고 `extract_credentials_prompt`는 평문 자격증명, Kerberos 인증 시도, 해시 추출, 보안 권고를 적는다 [6].
이 목록은 할 일을 적고 도구 결과의 해석 한계나 결과를 확정하기 전에 볼 다른 증거는 적지 않는다 [6].

다음 결과의 해석 조건은 설명, 프롬프트, 응답에 없다.
실시간 캡처 도구의 결과는 서버를 실행한 호스트의 인터페이스에서 `duration`초 동안 잡은 패킷만 담는다 [7].
`check_threats`는 IPv4 필드 `ip.src`·`ip.dst`만 대조하므로 IPv6 주소는 대조하지 않는다 [8].
서버는 URLhaus 목록의 줄마다 처음 나오는 IPv4 꼴 하나만 뽑아 대조하므로 도메인 이름으로 적힌 줄은 대조에 쓰이지 않는다 [3].
`get_conversations`의 결과는 TCP 대화만 담는다 [9].
