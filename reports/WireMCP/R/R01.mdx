# R01 결과 가공

### R01.01 가공 없이 전달

**구현.** 이 방식은 `get_summary_stats`와 `get_conversations`에 적용된다 [1][2].
두 도구는 `tshark -qz io,phs`와 `tshark -qz conv,tcp`의 표준 출력을 바꾸지 않고 머리 문구 한 줄 뒤에 붙여 돌려준다 [1][2].
루프백 캡처로 부르자 응답에는 `tshark`가 쓴 프로토콜 계층 표와 TCP 대화 표가 그대로 실렸다 [3].

### R01.02 구조화 파싱·필드 선택

**구현.** 이 방식은 `capture_packets`, `analyze_pcap`, `check_threats`, `extract_credentials`에 적용된다 [4][5][6][7].
서버는 도구마다 `tshark`에 `-e`로 읽을 필드를 정해 주고 그 필드만 담은 출력을 받는다 [4][5][6][7].
`capture_packets`는 프레임 번호, IP, TCP 포트와 플래그, 도착 시각, HTTP 메서드와 응답 코드 9개 필드를 고른다 [4].
`analyze_pcap`은 프레임 번호, IP, TCP·UDP 포트, HTTP 호스트와 URI, 프로토콜 목록 10개 필드를 고른다 [5].
두 도구는 `tshark`의 JSON을 `JSON.parse`로 해석한 뒤 다시 `JSON.stringify`로 만들어 싣는다 [4][5].
`check_threats`는 `ip.src`와 `ip.dst` 열만 받고 `extract_credentials`는 탭으로 나눈 필드 열을 해석해 자격증명 항목을 만든다 [6][7].
`analyze_pcap`의 IP, URL, 프로토콜 목록은 필드마다 첫 값만 쓰므로 한 프레임에 같은 필드가 여럿이면 뒤의 값은 목록에 들어가지 않는다 [8].

### R01.03 형식 변환·건수 집계

**구현.** 이 방식은 `capture_packets`, `analyze_pcap`, `check_threats`, `extract_credentials`에 적용된다 [4][5][6][7].
`capture_packets`와 `analyze_pcap`은 `tshark`가 들여쓰기로 낸 JSON을 공백 없는 한 줄 JSON으로 바꾼다 [4][5].
같은 pcap 파일에서 `tshark` 출력 20,360바이트가 응답에서 10,408자가 되었다 [3].
`analyze_pcap`은 패킷 JSON 앞에 중복을 뺀 IP 목록, `http://<http.host><http.request.uri>`로 이은 URL 목록, 중복을 뺀 `frame.protocols` 목록을 만든다 [8].
`check_threats`는 `ip.src`·`ip.dst` 값을 줄과 탭으로 나누고 중복을 뺀 목록을 만들어 URLhaus 목록과 대조한다 [6][9].
`extract_credentials`는 HTTP Basic 값을 base64로 디코딩해 `:` 앞뒤로 나누고 FTP의 `PASS`를 앞의 `USER` 항목에 붙이고 Telnet 값을 앞의 안내 문구에 따라 사용자 이름이나 비밀번호로 둔다 [7].
Kerberos 값은 `$krb5pa$23$`나 `$krb5asrep$23$`로 시작하는 해시 문자열과 hashcat 모드 문구로 바꾼다 [10].

**한계.** 코드가 적은 처리와 실제 결과가 다른 곳이 있다.
`tshark` 4.0.17은 `http.authbasic`에 이미 base64를 디코딩한 `사용자:비밀번호` 글을 싣는다 [11].
서버는 이 값을 한 번 더 base64로 디코딩하므로 사용자 이름은 알아볼 수 없는 글자가 되고 비밀번호는 `undefined`가 된다 [7][11].
지어낸 HTTP Basic 자격증명을 담은 시험 pcap으로 부르자 `HTTP Basic Auth:` 줄에 알아볼 수 없는 글자와 `undefined`가 실렸다 [3].

`tshark -T fields`는 한 프레임에 같은 필드가 여럿이면 값을 쉼표로 이어 한 칸에 낸다 [12].
`check_threats`는 탭으로만 나누므로 ICMP 오류 패킷처럼 IP 머리가 둘인 프레임은 `127.0.0.1,127.0.0.1` 같은 값 하나가 IP 목록에 들어간다 [6][3].
이 값은 URLhaus 목록의 어느 IP와도 같지 않다 [9].

Telnet 값은 `tshark`가 줄바꿈을 `\r\n` 글자로 바꿔 낸 그대로 쓰므로 사용자 이름과 비밀번호 뒤에 `\r\n`이 붙는다 [7][3].
비밀번호 안내 문구 뒤에 시험 서버가 보낸 환영 문구도 사용자 이름이 빈 Telnet 항목의 비밀번호로 실렸다 [3].
Kerberos 분기의 주석은 메시지 유형 30을 TGS-REQ로 적지만 RFC 4120에서 30은 KRB-ERROR이고 TGS-REQ는 12다 [10][13].
해시 문자열의 암호화 유형 자리는 받은 `kerberos.type` 값과 관계없이 23으로 고정된다 [10].
Kerberos를 담은 pcap으로는 실행하지 않았다.

### R01.04 가공 사실·대상 표시

**구현.** 이 방식은 `analyze_pcap`과 `extract_credentials`에 적용된다 [8][14].
두 도구는 응답 첫 줄에 `Analyzed PCAP: <pcapPath>`로 읽은 파일을 적고 서버가 만든 목록마다 `Unique IPs:`, `URLs:`, `Plaintext Credentials:` 같은 머리를 붙인다 [8][14].
`analyze_pcap`은 `tshark` 출력을 담은 절에 `Packet Data (JSON for LLM):` 머리를 붙인다 [8].
실시간 캡처 도구 4개의 응답은 캡처한 인터페이스와 캡처 시간을 싣지 않는다 [4][1][2][15].

### R01.06 응답 항목 선별

**구현.** 이 방식은 `check_threats`, `analyze_pcap`, `extract_credentials`가 서버 코드의 규칙으로 항목을 고르는 단계에 적용된다 [6][8][7][10].
`check_threats`는 빈 값과 `unknown`을 IP 목록에서 뺀다 [6].
`analyze_pcap`의 URL 목록은 `http.host`와 `http.request.uri`가 함께 있는 패킷만 싣는다 [8].
`extract_credentials`는 Telnet 값 가운데 `login:`이나 `password:`가 들어 있으면 안내 문구 항목으로 싣는다 [7].
그 밖의 Telnet 값은 공백이 없고 대문자 하나 뒤에 소문자와 `:`가 이어지는 꼴이 없을 때만 앞의 안내 문구에 따라 사용자 이름이나 비밀번호로 싣는다 [7].
Kerberos 값은 `kerberos.cipher`와 `kerberos.type`이 모두 있고 메시지 유형이 10, 30, 11일 때만 싣는다 [10].
응답에는 뺀 항목의 수나 적용한 규칙이 없다 [14].

        const kerberosLines = kerberosOut.split('\n').filter(line => line.trim());
        kerberosLines.forEach(line => {
          const [cname, realm, cipher, type, msgType, frameNumber] = line.split('\t');
          
          if (cipher && type) {
            let hashFormat = '';
            // Format hash based on message type
            if (msgType === '10' || msgType === '30') { // AS-REQ or TGS-REQ

              if (realm) hashFormat += `${realm}$`;
              hashFormat += cipher;
            }

            if (hashFormat) {
              credentials.encrypted.push({
                type: 'Kerberos',
                hash: hashFormat,
                username: cname || 'unknown',
                realm: realm || 'unknown',
                frame: frameNumber,
                crackingMode: msgType === '11' ? 'hashcat -m 18200' : 'hashcat -m 7500'
              });
            }
          }
        });
