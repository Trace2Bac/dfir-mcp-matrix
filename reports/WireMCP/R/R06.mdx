# R06 증거에서 추출한 민감정보 노출 제어

### 미구현

**판단.** 서버는 pcap에서 찾은 자격증명과 Kerberos 해시를 응답에 그대로 싣고 그 값을 가리거나 빼는 코드를 두지 않는다 [1][2].
`extract_credentials`는 HTTP Basic, FTP, Telnet 항목을 `<유형>: <사용자 이름>:<비밀번호> (Frame N)` 꼴로 싣는다 [1].
Kerberos 항목은 사용자 이름, realm, `$krb5pa$23$…`나 `$krb5asrep$23$…` 꼴의 해시 문자열 전체, hashcat 모드를 싣는다 [2][1].
Telnet 안내 문구 항목은 `tshark`가 낸 Telnet 데이터를 그대로 싣는다 [1].
지어낸 사용자 이름과 비밀번호를 FTP와 Telnet으로 보낸 시험 pcap으로 부르자 두 값이 응답에 그대로 실렸다 [3].
같은 pcap의 HTTP Basic 항목에는 알아볼 수 없는 글자와 `undefined`가 실렸다 [3].
이 값은 서버가 `tshark`가 이미 디코딩한 값을 다시 base64로 디코딩한 결과이고 값을 가리는 처리가 아니다 [4][5].
Kerberos를 담은 pcap으로는 실행하지 않았다.

다른 도구도 증거 값을 가리지 않는다.
`analyze_pcap`은 `http.host`와 `http.request.uri`로 만든 URL을 응답의 URL 목록에 싣고 서버의 표준 오류에도 `Found N URLs:` 줄로 모두 쓴다 [6].
URI의 질의 문자열에 들어 있는 값도 그대로 실린다 [6].
`extract_credentials`는 표준 오류에 찾은 항목의 수만 쓰고 값은 쓰지 않는다 [7].
서버 코드에는 값을 가리는 함수가 없고 서버는 보고서 파일을 쓰지 않는다 [8].
