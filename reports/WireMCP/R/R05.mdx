# R05 결과 출처 표시

### R05.01 증거·파일 ID

**구현.** 이 방식은 `analyze_pcap`과 `extract_credentials`에 적용된다 [1][2].
두 도구는 응답 첫 줄 `Analyzed PCAP: <pcapPath>`에 모델이 준 pcap 파일 경로를 그대로 싣는다 [1][2].
파일을 찾지 못한 오류에도 Node.js의 `ENOENT` 문구에 받은 경로가 들어간다 [3].

실시간 캡처 도구 4개의 응답은 캡처한 인터페이스, 캡처 시간, 호스트를 싣지 않는다 [4][5][6].
캡처한 패킷을 담은 `temp_capture.pcap`은 응답을 돌려주기 전에 지운다 [4][5].

`check_threats`와 `check_ip_threats`가 싣는 URLhaus 대조 결과는 참조 지식이다 [5][7].
응답은 그 절에 `Threat check against URLhaus blacklist:` 머리를 붙이지만 목록 주소, 일치한 목록 줄, 받은 시각을 싣지 않는다 [5][7].
이 절은 잡은 IP 절과 빈 줄로만 나뉘고 그 절이 증거 결과가 아니라고 밝히는 문구는 없다 [5].

### R05.03 레코드 키·번호

**구현.** 이 방식은 `capture_packets`, `analyze_pcap`, `extract_credentials`에 적용된다 [4][1][2].
`capture_packets`와 `analyze_pcap`은 `tshark`에 `-e frame.number`를 주어 패킷 JSON의 항목마다 pcap 안의 프레임 번호를 싣는다 [4][1].
`extract_credentials`는 자격증명과 Kerberos 항목마다 그 값이 나온 프레임 번호를 `(Frame N)`으로 싣는다 [2].
지어낸 자격증명을 담은 시험 pcap으로 부르자 FTP 항목은 `(Frame 13)`, Telnet 항목은 `(Frame 31)`로 실렸다 [8].
`check_threats`의 IP 목록과 `get_summary_stats`, `get_conversations`의 결과에는 프레임 번호가 없다 [5][6].

**한계.** `analyze_pcap`의 IP, URL, 프로토콜 목록에는 프레임 번호가 없다 [1].
FTP 항목의 프레임 번호는 `USER` 명령의 프레임이고 뒤에 붙이는 `PASS` 값의 프레임 번호는 싣지 않는다 [2].
Telnet 항목도 사용자 이름 프레임만 싣는다 [2].
`capture_packets`의 프레임 번호는 응답을 돌려주기 전에 지운 임시 파일 안의 번호이므로 그 패킷을 다시 찾을 파일이 남지 않는다 [4].
`capture_packets`의 패킷 JSON이 720,000자를 넘으면 뒤쪽 패킷은 번호와 함께 빠진다 [4].

      const maxChars = 720000;
      let jsonString = JSON.stringify(packets);
      if (jsonString.length > maxChars) {
        const trimFactor = maxChars / jsonString.length;
        const trimCount = Math.floor(packets.length * trimFactor);
        packets.splice(trimCount);
        jsonString = JSON.stringify(packets);
        console.error(`Trimmed packets from ${packets.length} to ${trimCount} to fit ${maxChars} chars`);

      const outputText = `Analyzed PCAP: ${pcapPath}\n\n` +

        `URLs:\n${urls.length > 0 ? urls.join('\n') : 'None'}\n\n` +
        `Protocols:\n${protocols.join('\n') || 'None'}\n\n` +
