# R03 분석 상태 알림

### R03.01 구조화 status·error

**구현.** 이 방식은 도구 7개의 오류 응답에 적용된다 [1][2].
처리기마다 예외가 나면 `Error: <예외 문구>`를 담은 글 블록과 `isError: true`를 돌려준다 [1].
성공 응답에는 `isError` 필드가 없다 [2][3].
`tshark`가 0이 아닌 코드로 끝난 오류 문구에는 Node.js가 만든 `Command failed: <명령 문자열>` 줄과 `tshark`의 표준 오류가 들어간다 [4][3].
없는 pcap 파일, 끝이 잘린 pcap 파일, 없는 인터페이스, 1 MiB를 넘는 출력으로 도구를 부르자 모두 `isError`가 참인 응답이 왔다 [3].

입력 schema 검사에서 거부된 호출은 MCP TypeScript SDK 1.15.0이 도구 결과 대신 JSON-RPC 오류 `-32602`로 돌려준다 [5].
`check_ip_threats`에 숫자 꼴이 없는 `ip`를 주자 이 오류가 왔다 [3].

빈 결과는 상태 값 없이 글로만 나타난다.
`capture_packets`는 패킷이 없으면 `[]`을, `analyze_pcap`의 URL 목록과 `extract_credentials`의 각 절은 `None`을 싣는다 [6][7][2].
`check_threats`와 `check_ip_threats`는 일치가 없으면 `No threats detected in URLhaus blacklist.`나 `No threat detected in URLhaus blacklist.`를 싣는다 [8][9].
실시간 캡처는 `duration`초 동안 끝나지 않지만 서버는 그동안 진행 알림을 보내지 않는다 [10].

**한계.** URLhaus 목록을 받지 못한 `check_threats`와 `check_ip_threats`는 `isError` 없이 일치가 없을 때와 같은 문구를 돌려준다 [8][9].
네트워크를 끈 컨테이너에서 두 도구를 부르자 이 응답이 왔다 [3].
`analyze_pcap`과 `capture_packets`는 패킷 JSON을 잘라도 응답에 그 사실을 싣지 않고 성공으로 돌려준다 [6][11].
`capture_packets`, `get_summary_stats`, `get_conversations`, `analyze_pcap`은 `tshark`가 표준 오류에 경고를 쓰고 0으로 끝나면 그 글을 서버의 표준 오류에만 남기고 성공 응답을 돌려준다 [6][11][12].
`check_threats`와 `extract_credentials`는 `tshark`의 표준 오류를 읽지 않는다 [13].
