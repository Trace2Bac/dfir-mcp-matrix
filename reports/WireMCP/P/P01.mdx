# P01 분석 방법 적합성 확인

### 미구현

**판단.** 서버는 증거 형식, OS, 대상 환경을 판별하지 않고 도구마다 정해 둔 명령을 대조 없이 실행한다 [1][2].
`tshark`를 실행하는 도구 6개는 도구마다 추출할 필드나 통계 종류를 코드에 고정해 두고 입력에 따라 바꾸지 않는다 [1][2][3].
`check_ip_threats`는 `tshark`를 실행하지 않고 받은 IP 하나를 URLhaus 목록과 대조한다 [4].
`analyze_pcap`과 `extract_credentials`는 받은 `pcapPath`에 `fs.access`로 파일이 있는지만 확인하고 `tshark -r`에 넘긴다 [2][3].
캡처 파일 형식은 서버 코드가 판별하지 않는다.
`tshark`는 읽기 형식을 정하지 않은 호출에서 Wireshark의 파일 읽기 라이브러리 wiretap으로 파일을 열며 형식을 스스로 알아낸다 [5].
`extract_credentials`는 HTTP, FTP, Telnet, Kerberos가 캡처 파일에 있는지 보지 않고 두 필드 추출 명령을 늘 실행한다 [3].

실시간 캡처 도구 4개(`capture_packets`, `get_summary_stats`, `get_conversations`, `check_threats`)는 인자 `interface`를 받고 값이 없으면 `en0`을 쓴다 [1].
서버는 받은 이름이 서버 호스트에 있는 인터페이스인지 확인하지 않고 그대로 `tshark -i`에 넘긴다 [1].
서버는 인터페이스 목록을 조회하는 도구를 두지 않는다 [6].
`findTshark`는 `process.platform`이 `win32`인지로 `tshark` 실행 파일을 찾을 경로 목록을 고른다 [7].
이 값은 분석 도구를 찾는 데만 쓰이고 증거나 분석 방법을 고르는 데 쓰이지 않는다 [7].

[7] `findTshark`는 `which`로 찾지 못하면 플랫폼에 따라 정해 둔 경로에서 `tshark`를 찾는다.

```javascript
async function findTshark() {
  try {
    const tsharkPath = await which('tshark');
    console.error(`Found tshark at: ${tsharkPath}`);
    return tsharkPath;
  } catch (err) {
    console.error('which failed to find tshark:', err.message);
    const fallbacks = process.platform === 'win32'
      ? ['C:\\Program Files\\Wireshark\\tshark.exe', 'C:\\Program Files (x86)\\Wireshark\\tshark.exe']
      : ['/usr/bin/tshark', '/usr/local/bin/tshark', '/opt/homebrew/bin/tshark', '/Applications/Wireshark.app/Contents/MacOS/tshark'];
    
    for (const path of fallbacks) {
      try {
        await execAsync(`${path} -v`);
        console.error(`Found tshark at fallback: ${path}`);
        return path;
      } catch (e) {
        console.error(`Fallback ${path} failed: ${e.message}`);
      }
    }
    throw new Error('tshark not found. Please install Wireshark (https://www.wireshark.org/download.html) and ensure tshark is in your PATH.');
  }
}
```
