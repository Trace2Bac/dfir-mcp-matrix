# P02 다음 작업 결정

### P02.01 고정 문서·프로필 반환

**구현.** 이 방식은 MCP 프롬프트 7개와 `extract_credentials` 응답 끝의 고정 안내문에 적용된다 [1][2].
서버는 도구마다 프롬프트를 하나씩 등록하고 프롬프트는 받은 인자를 넣은 사용자 메시지 하나를 돌려준다 [1].
메시지는 분석할 대상(인터페이스와 캡처 시간, IP, pcap 경로)을 적고 응답에 담을 항목을 번호를 매겨 4개나 5개 적는다 [1].
`check_threats_prompt`는 캡처한 IP를 URLhaus 목록과 대조하고 악성 활동과 우려되는 패턴을 찾아 보안 권고를 내라고 적는다 [1].
`extract_credentials_prompt`는 평문 자격증명을 찾고 Kerberos 인증 시도를 찾은 뒤 해시된 자격증명을 뽑아 권고를 내라고 적는다 [1].
나머지 프롬프트는 트래픽 유형, 프로토콜 분포, 활발한 IP 쌍, 이상 징후처럼 볼 관점을 적는다 [1].
프롬프트는 도구 이름을 적지 않고 도구 사이의 차례도 정하지 않는다 [1].
MCP SDK 클라이언트로 받은 프롬프트 7개의 글에 이 문구가 그대로 실렸다 [3].
서버 지침과 MCP 리소스는 없다 [3].

`extract_credentials`는 결과와 관계없이 응답 끝에 해시된 자격증명을 다루는 외부 도구를 안내하는 고정 문장을 붙인다 [2].
자격증명을 하나도 찾지 못한 응답에도 이 문장이 붙는다 [2].
도구 설명 7개는 도구가 하는 일만 한 문장으로 적고 다음에 부를 도구를 적지 않는다 [3].
프롬프트는 사용자가 클라이언트에서 고를 때만 모델에게 가고 서버는 모델이 그 항목을 따르는지 보지 않는다.

**한계.** 실시간 캡처 프롬프트 4개는 `duration`을 숫자 schema로 받는다 [1].
MCP SDK 1.15.0은 프롬프트 인자를 문자열로만 받고 서버에 등록한 schema로 검사해 맞지 않으면 오류를 돌려준다 [4].
그래서 이 4개 프롬프트에 캡처 시간을 주면 프롬프트 글이 돌아오지 않는다 [4].
`capture_packets_prompt`에 `duration`을 주자 숫자가 아니라 문자열을 받았다는 `Invalid arguments` 오류가 돌아왔다 [3].
인자를 주지 않으면 메시지는 인터페이스 `en0`과 5초를 적는다 [1][3].

### P02.02 규칙·조사 상태로 추천

**구현.** 이 방식은 `extract_credentials` 응답의 Kerberos 항목에 적용된다 [2].
`extract_credentials`는 Kerberos 필드를 추출한 줄마다 메시지 유형 `kerberos.msg_type`을 보고 항목을 만들지와 항목에 붙일 외부 도구 명령 문자열을 고른다 [2].
고른 명령 문자열은 그 항목 아래에 실린다 [2].
고르는 규칙은 메시지 유형 값 3개에 대한 분기이고 코드에 고정되어 있다 [2].
이 안내는 응답의 글이고 서버가 그 명령을 실행하거나 다음 호출을 대신 고르지 않는다 [2].
다른 도구 응답은 추출 결과나 대조 결과만 싣고 다음에 할 작업을 싣지 않는다 [5].

**한계.** Kerberos 항목은 그 줄에 `kerberos.cipher`와 `kerberos.type` 값이 모두 있을 때만 생긴다 [2].
Wireshark 4.0.17에서 `kerberos.type`은 SPAKE 사전 인증의 두 번째 인증 수단 유형 필드다 [6].
그래서 이 필드가 없는 Kerberos 교환에서는 항목도 명령 문자열도 실리지 않는다 [2][6].
코드 주석은 분기한 값 하나를 TGS-REQ로 적지만 Wireshark 4.0.17의 메시지 유형 표에서 그 값은 `krb-error`이고 TGS-REQ는 다른 값이다 [2][7].
서버는 암호화 유형 필드를 추출하지 않으므로 고른 명령 문자열을 실제 암호화 유형과 대조하지 않는다 [8][2].

### P02.04 서버 코드에 고정한 분석 절차

**구현.** 이 방식은 `check_threats`와 `extract_credentials`에 적용된다 [9][8].
`check_threats`는 정한 시간 동안 캡처하고 캡처 파일에서 출발지·목적지 IP를 뽑은 뒤 URLhaus 목록을 내려받아 대조하고 두 결과를 한 응답으로 합친다 [9].
`extract_credentials`는 평문 자격증명 필드와 Kerberos 필드를 두 명령으로 차례로 추출한다 [8].
그다음 HTTP Basic 인증, FTP, Telnet, Kerberos의 순서로 정해 둔 해석 규칙을 적용해 평문 목록과 암호화 목록 두 개로 합친다 [10].
FTP는 `PASS` 값을 앞서 나온 `USER` 항목 가운데 값이 비어 있는 마지막 항목에 붙이고 TCP 스트림으로 묶지 않는다 [10].
모델은 도구와 인자만 고르고 그 안의 단계와 합치는 방법은 서버 코드가 정한다.
다른 실시간 캡처 도구 3개는 캡처 뒤에 정해 둔 명령 하나로 파일을 읽고 `analyze_pcap`은 명령 하나의 출력에서 IP, URL, 프로토콜 목록을 만든다 [5].
서버 안에서 모델을 불러 계획을 세우는 경로는 없다.

**한계.** `check_threats`는 URLhaus 목록을 내려받지 못하면 그 예외를 처리하고 대조하지 않은 채 응답을 만든다 [9].
그래서 응답의 대조 결과는 위협이 없는 경우와 같은 문장이다 [9].
`extract_credentials`는 두 추출 명령 가운데 하나라도 실패하면 앞 단계의 결과 없이 오류 응답으로 끝난다 [8][11].
