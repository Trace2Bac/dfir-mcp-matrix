# D01 파생물 보관

### 미구현

**판단.** 서버는 도구 결과를 응답으로 돌려주기만 하고 성공한 호출이 끝난 뒤에 남기는 파일이나 DB가 없다.
실시간 캡처 도구 4개 `capture_packets`, `get_summary_stats`, `get_conversations`, `check_threats`는 tshark가 잡은 패킷을 서버 프로세스의 현재 폴더에 `temp_capture.pcap`이라는 이름으로 쓰게 한다 [1].
네 도구는 이 파일을 tshark로 다시 읽어 응답 글을 만들고 응답을 돌려주기 전에 `fs.unlink`로 지운다 [1][2].
캡처하는 동안 현재 폴더에 이 파일이 생겼고 성공한 호출이 끝난 뒤에는 남지 않았다 [3].
이 파일은 이름의 확장자와 달리 pcapng 형식이었다 [3].
서버 코드에는 이 파일을 다른 곳에 복사하거나 지우지 않고 남기는 경로가 없다 [1][2].

오류로 끝난 캡처 호출은 이 파일을 지우지 않는다.
네 도구의 `catch`는 오류 글을 `isError`와 함께 돌려주고 `fs.unlink`를 부르지 않는다 [4].
그래서 캡처가 끝난 뒤 파일을 읽는 단계가 실패하면 파일이 현재 폴더에 남는다 [4].
Node.js 22.17.0의 `exec`는 하위 프로세스의 표준 출력이 `maxBuffer` 기본값 `1024 * 1024`바이트를 넘으면 그 프로세스를 끝내고 오류를 낸다 [5].
루프백 인터페이스에 트래픽을 많이 보내는 동안 `capture_packets`를 부르자 응답은 `stdout maxBuffer length exceeded` 오류였고 18,983,592바이트의 `temp_capture.pcap`이 현재 폴더에 남았다 [3].
남은 파일은 다음 캡처 호출이 같은 이름으로 다시 쓴 뒤 그 호출이 성공하면서 지워졌다 [3].

`analyze_pcap`과 `extract_credentials`는 인자로 받은 pcap을 tshark로 읽기만 하고 파일을 쓰지 않는다 [6].
서버 로그는 `console.log`까지 표준 오류로 보내므로 파일로 남지 않는다 [7].
`check_ip_threats`를 뺀 도구 6개를 부르기 전과 뒤에 `/tmp`, `/root`, 서버 설치 폴더의 파일 목록이 같았다 [3].

        `${tsharkPath} -i ${interface} -w ${tempPcap} -a duration:${duration}`,

이어서 부른 `get_summary_stats`는 같은 inode의 파일을 284바이트로 다시 썼고 성공한 뒤 파일은 없었다.
`analyze_pcap`, `extract_credentials`, 없는 경로의 `analyze_pcap`을 부른 전후로 현재 폴더, `/tmp`, `/root`, 서버 설치 폴더의 목록이 같았다.
