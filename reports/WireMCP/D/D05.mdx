# D05 파생물 저장 실패 처리

### 비적용

**판단.** 서버는 도구 출력, 파생물, 보고 산출물을 저장하지 않고 응답으로만 돌려준다.
도구 7개는 결과를 응답 글로만 돌려준다 [1].
실시간 캡처 도구 4개가 tshark에 쓰게 하는 `temp_capture.pcap`은 응답 글을 만드는 데 쓰고 성공한 호출 안에서 지우는 중간 파일이다 [2].
`analyze_pcap`과 `extract_credentials`는 받은 pcap을 읽기만 하고 파일을 쓰지 않는다 [3].

이 중간 파일을 쓰는 캡처 명령이 0이 아닌 코드로 끝나면 `execAsync`가 오류를 내고 도구는 오류 글을 `isError`와 함께 돌려준다 [2][4].
없는 인터페이스로 `capture_packets`를 부르자 응답은 tshark의 실패 문장을 실은 오류였고 현재 폴더에 파일이 생기지 않았다 [5].

[4] `execAsync`는 `child_process.exec`를 `util.promisify`로 감싼 함수다.

```javascript
const { exec } = require('child_process');
const { promisify } = require('util');
const which = require('which');
const fs = require('fs').promises;
const execAsync = promisify(exec);
```

Node.js 22.17.0 문서는 이렇게 감싼 `exec`가 종료 코드가 0이 아니면 거부된 `Promise`를 돌려준다고 적는다: [`doc/api/child_process.md:290-295`](https://github.com/nodejs/node/blob/3567fa7d70fee8831ab2891e6940ca63be568b08/doc/api/child_process.md#L290-L295).

[5] (실행 확인) 네트워크를 끈 컨테이너에서 서버의 현재 폴더를 빈 폴더로 정하고 없는 인터페이스 이름으로 `capture_packets`를 불렀다.
응답은 `isError`가 참이고 `Command failed:`로 시작하는 오류 글이었으며 호출 뒤 현재 폴더는 비어 있었다.
