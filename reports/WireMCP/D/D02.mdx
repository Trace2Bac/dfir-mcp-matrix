# D02 파생물 추적

### 비적용

**판단.** 서버는 성공한 호출이 끝난 뒤에 남기는 파생물이 없다.
실시간 캡처 도구 4개가 쓰게 하는 `temp_capture.pcap`은 응답을 돌려주기 전에 지운다 [1].
`analyze_pcap`과 `extract_credentials`는 받은 pcap을 읽기만 하고 파일을 쓰지 않는다 [2].
서버는 호출 기록을 쓰지 않고 로그는 표준 오류로만 보낸다 [3].
`check_ip_threats`를 뺀 도구 6개를 부른 뒤 서버의 현재 폴더와 `/tmp`에 새 파일이 없었다 [4].

오류로 끝난 캡처 호출 뒤에는 `temp_capture.pcap`이 현재 폴더에 남는다 [5][4].
이 파일의 이름은 모든 호출에서 같고 서버는 그 파일을 만든 호출이나 인자를 따로 적어 두지 않는다 [1][3].

### 근거

[1] 실시간 캡처 도구 4개는 고정 이름의 파일에 캡처를 쓰게 하고 성공 경로에서 지운다.

```javascript

      const { interface, duration } = args;

        `${tsharkPath} -i ${interface} -w ${tempPcap} -a duration:${duration}`,

        `${tsharkPath} -r "${tempPcap}" -T json -e frame.number -e ip.src -e ip.dst -e tcp.srcport -e tcp.dstport -e tcp.flags -e frame.time -e http.request.method -e http.response.code`,

      );
```
