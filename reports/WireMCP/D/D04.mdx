# D04 출력 경로 제한

### D04.01 서버가 출력 위치 결정

**구현.** 이 방식은 실시간 캡처 도구 4개 `capture_packets`, `get_summary_stats`, `get_conversations`, `check_threats`가 tshark에 쓰게 하는 캡처 파일에 적용된다 [1].
네 도구는 코드에 정한 상대 이름 `temp_capture.pcap`을 tshark의 `-w`로 주고 같은 이름을 읽기와 삭제에 쓴다 [1][2].
이 이름에는 호출 인자가 들어가지 않는다 [1].
Node.js 22.17.0의 `exec`는 `cwd`를 주지 않으면 서버 프로세스의 현재 폴더에서 하위 프로세스를 실행하므로 파일은 그 폴더에 생긴다 [3][1].
서버의 현재 폴더를 빈 폴더로 정해 실행하자 캡처하는 동안 그 폴더에만 `temp_capture.pcap`이 생겼고 `/tmp`에는 새 파일이 없었다 [4].

`analyze_pcap`과 `extract_credentials`는 받은 pcap을 읽기만 하고 파일을 쓰지 않는다 [5].
출력 위치를 받는 호출 인자와 저장된 파일을 고치거나 지우는 도구는 없다 [6].

**한계.** 서버 코드는 현재 폴더를 정하거나 바꾸지 않으므로 이 폴더는 서버를 실행한 프로그램이 정한다 [7].
README의 클라이언트 등록 예시는 `command`와 `args`만 적고 현재 폴더를 정하지 않는다 [8].

실시간 캡처 도구의 `interface`와 `duration`은 따옴표 없이 캡처 명령 문자열에 들어간다 [1].
zod 검사는 `interface`가 문자열인지와 `duration`이 수인지만 본다 [6].
Node.js 22.17.0의 `exec`는 명령 문자열을 `/bin/sh`로 실행한다 [3].
그래서 공백이나 셸 메타 문자가 들어간 `interface`는 셸이 해석해 tshark에 넘기고 서버 코드는 그렇게 더해진 인자를 검사하지 않는다 [1][3].
셸 메타 문자를 넣은 `interface`로 `capture_packets`를 부르자 셸이 그 문자를 해석해 `tshark`가 아닌 명령이 서버의 현재 폴더에 파일을 만들었다 [9].
이 경로로 tshark에 출력 옵션을 더했을 때 서버가 정한 이름 밖에 파일이 생기는지는 실행으로 확인하지 않았다.

### 근거

[1] 실시간 캡처 도구 4개는 고정 상대 이름을 `-w`로 주고 `interface`와 `duration`을 명령 문자열에 그대로 넣는다.

```javascript
    try {
      const tsharkPath = await findTshark();
      const { interface, duration } = args;
      const tempPcap = 'temp_capture.pcap';
      console.error(`Capturing packets on ${interface} for ${duration}s`);

      await execAsync(
        `${tsharkPath} -i ${interface} -w ${tempPcap} -a duration:${duration}`,
        { env: { ...process.env, PATH: `${process.env.PATH}:/usr/bin:/usr/local/bin:/opt/homebrew/bin` } }
      );

      const { stdout, stderr } = await execAsync(
        `${tsharkPath} -r "${tempPcap}" -T json -e frame.number -e ip.src -e ip.dst -e tcp.srcport -e tcp.dstport -e tcp.flags -e frame.time -e http.request.method -e http.response.code`,
        { env: { ...process.env, PATH: `${process.env.PATH}:/usr/bin:/usr/local/bin:/opt/homebrew/bin` } }
      );
```
