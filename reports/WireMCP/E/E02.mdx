# E02 증거 무결성 검증

### 미구현

**판단.** 서버는 pcap 파일의 기준값을 계산하지도 대조하지도 않는다.
`analyze_pcap`과 `extract_credentials`가 `tshark`를 실행하기 전에 하는 확인은 받은 경로로 `fs.access`를 `mode` 없이 부르는 것뿐이다 [1].
Node.js 22.17.0의 `fsPromises.access`는 `mode`가 없으면 `F_OK`로 확인하고 `F_OK`는 파일이 보이는지만 확인하는 값이다 [2].
없는 경로를 주자 `analyze_pcap`은 `ENOENT` 오류 응답을 돌려주었다 [3].
서버 코드에는 해시를 계산하는 모듈을 불러오는 곳이 없다 [4].
서버가 실행하는 외부 프로그램은 `tshark`뿐이고 `capinfos` 같은 파일 정보 도구는 실행하지 않는다 [5].
두 도구가 `tshark`에 넘기는 인자는 패킷 필드를 고르는 `-e`와 출력 형식뿐이다 [1].
그래서 응답에는 파일 바이트의 해시나 크기가 실리지 않는다.

`extract_credentials`는 같은 경로로 `tshark`를 두 번 실행한다 [1].
두 실행 사이에 파일이 바뀌었는지는 확인하지 않는다 [1].
실시간 캡처 도구 4개가 쓰는 `temp_capture.pcap`도 해시하지 않고 읽은 뒤 지운다 [6].

[5] `tshark` 실행 파일을 찾는 함수이고 모든 `execAsync` 호출은 이 경로나 후보 경로의 `tshark`를 실행한다.

```javascript
async function findTshark() {
  try {
    const tsharkPath = await which('tshark');
    console.error(`Found tshark at: ${tsharkPath}`);
    return tsharkPath;
  } catch (err) {
    console.error('which failed to find tshark:', err.message);
    const fallbacks = process.platform === 'win32'
      ? ['C:\\Program Files\\Wireshark\\tshark.exe', 'C:\\Program Files (x86)\\Wireshark\\tshark.exe']
      : ['/usr/bin/tshark', '/usr/local/bin/tshark', '/opt/homebrew/bin/tshark', '/Applications/Wireshark.app/Contents/MacOS/tshark'];
    
    for (const path of fallbacks) {
      try {
        await execAsync(`${path} -v`);
        console.error(`Found tshark at fallback: ${path}`);
        return path;
      } catch (e) {
        console.error(`Fallback ${path} failed: ${e.message}`);
      }
    }
    throw new Error('tshark not found. Please install Wireshark (https://www.wireshark.org/download.html) and ensure tshark is in your PATH.');
  }
}
```
