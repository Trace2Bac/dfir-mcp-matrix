# F02 발견사항·결론 도출

### F02.01 규칙·키 기반 판정·상관

**구현.** 이 방식은 IP를 URLhaus 목록과 대조하는 `check_threats`·`check_ip_threats`와 tshark 필드를 자격증명 항목으로 묶는 `extract_credentials`에 적용된다 [1][2][3].
`check_threats`와 `check_ip_threats`는 부를 때마다 `https://urlhaus.abuse.ch/downloads/text/`를 내려받아 대조할 IP 목록을 만든다 [1][2].

- 내려받은 글의 줄마다 정규식으로 처음 나오는 IPv4 꼴 문자열 하나를 뽑고 IPv4 꼴 문자열이 없는 줄은 버린다 [1].
- `check_threats`는 캡처한 패킷에서 tshark로 `ip.src`·`ip.dst`를 뽑아 빈 값과 `unknown`을 뺀 고유 주소 목록을 만든다 [1].
- `check_threats`는 그 가운데 URLhaus 목록의 항목과 문자열이 같은 주소를 `Potential threats`로 싣고 하나도 없으면 `No threats detected in URLhaus blacklist.`를 싣는다 [1].
- `check_ip_threats`는 모델이 준 `ip`가 목록에 있으면 `Potential threat detected in URLhaus blacklist.`를, 없으면 `No threat detected in URLhaus blacklist.`를 싣는다 [2].

`extract_credentials`는 tshark로 HTTP·FTP·Telnet 필드와 Kerberos 필드를 두 번에 나눠 뽑은 뒤 서버 코드의 규칙으로 자격증명 항목을 만든다 [3].

- `http.authbasic` 값이 있으면 base64로 디코딩해 `:`로 나눈 첫째와 둘째 조각을 사용자 이름과 비밀번호로 둔다 [4].
- FTP는 `USER` 명령마다 항목을 만들고 `PASS` 명령의 인자를 아직 비밀번호가 없는 가장 최근 FTP 항목에 넣는다 [4].
- Telnet은 `telnet.data`에 대소문자를 가리지 않고 `login:`이나 `password:`가 들어 있으면 안내 항목으로 둔다 [5].
- 빈칸이 없고 대문자 하나 뒤에 소문자가 하나 이상 이어진 다음 `:`가 오는 꼴도 없는 Telnet 데이터는 가장 최근 안내가 `login:`을 담으면 사용자 이름으로, `password:`를 담으면 비밀번호로 둔다 [5].
- Kerberos 규칙은 `kerberos.cipher`와 `kerberos.type`에 모두 값이 있는 줄만 본다 [6].
- 그 줄의 `kerberos.msg_type`이 `10`이나 `30`이면 `$krb5pa$23$`로, `11`이면 `$krb5asrep$23$`로 시작하는 해시 문자열을 만들고 다른 값은 버린다 [6].
- Kerberos 항목에는 `msg_type`이 `11`이면 `hashcat -m 18200`을, 그 밖에는 `hashcat -m 7500`을 `crackingMode`로 붙인다 [6].

`capture_packets`, `get_summary_stats`, `get_conversations`, `analyze_pcap`은 tshark 출력이나 그 출력에서 모은 IP·URL·프로토콜 목록을 돌려줄 뿐 판정을 더하지 않는다 [7].

**한계.** URLhaus 목록을 내려받지 못하면 두 도구는 표준 오류에 실패를 적고 대조하지 않은 채 위협이 없다는 문장을 싣는다 [1][2].
네트워크를 끈 컨테이너에서 `check_ip_threats`를 부르자 응답은 `isError` 없이 `No threat detected in URLhaus blacklist.`였고 실패는 표준 오류의 `Failed to fetch URLhaus data` 줄에만 남았다 [8].
`check_threats`는 IPv4 필드 `ip.src`·`ip.dst`만 뽑으므로 IPv6 주소는 대조 대상에 들어가지 않는다 [1].
`check_threats`는 tshark 출력을 줄과 탭으로만 나눈다 [1].
tshark 4.0.17은 한 패킷에 같은 필드가 여러 번 나오면 기본값으로 모든 값을 쉼표로 이어 쓴다 [9].
그래서 한 패킷에 `ip.src`나 `ip.dst`가 여러 번 나오면 그 값은 쉼표가 들어간 문자열 그대로 목록 항목과 대조된다 [1][9].
닫힌 UDP 포트로 패킷을 보내는 동안 루프백 인터페이스로 `check_threats`를 부르자 쉼표로 이은 주소 문자열이 `Captured IPs:`에 한 항목으로 실렸다 [10].
`check_ip_threats`의 `ip` 정규식은 앞뒤를 고정하지 않아 IPv4 꼴 바로 앞뒤의 글자가 영문자, 숫자, 밑줄이 아니면 다른 글자가 붙은 값도 받는다 [2].
공백을 두고 앞뒤에 글자를 붙인 IPv4 주소와 자리마다 255를 넘는 IPv4 꼴 값이 이 검사를 통과했다 [10].
서버는 받은 글 전체를 목록 항목과 대조하므로 그런 글에는 목록에 있는 주소가 들어 있어도 위협이 없다는 문장이 실린다 [2].
README는 `check_ip_threats`가 여러 위협 정보 출처를 조회한다고 적지만 코드는 URLhaus 목록 하나만 내려받는다 [11][2].

Wireshark 4.0.17은 `http.authbasic`에 base64를 디코딩한 글을 싣는다 [12].
`extract_credentials`는 이 값을 base64로 한 번 더 디코딩한 뒤 `:`로 나눈다 [4].
그래서 지어낸 HTTP Basic 자격증명을 담은 시험 pcap에서 사용자 이름에는 알아볼 수 없는 글자가 실렸고 비밀번호에는 `undefined`가 실렸다 [10].
FTP와 Telnet 규칙은 TCP 스트림을 보지 않고 패킷 차례로만 항목을 잇는다 [3][4][5].
비밀번호 안내 뒤의 Telnet 데이터는 Telnet 서버가 보낸 글이어도 비밀번호로 둔다 [5].
같은 시험 pcap에서 비밀번호 안내 뒤에 Telnet 서버가 보낸 환영 문구가 사용자 이름이 빈 `Telnet` 항목의 비밀번호로 실렸다 [10].
Wireshark 4.0.17의 `kerberos.type`은 SPAKE 사전 인증의 `SPAKESecondFactor` 안에 있는 `type` 필드다 [13].
`extract_credentials`는 이 필드에 값이 없는 줄에서는 Kerberos 해시를 만들지 않는다 [6].
코드 주석은 `msg_type` `30`을 TGS-REQ로 적지만 RFC 4120의 메시지 유형 번호에서 30은 KRB-ERROR이고 TGS-REQ는 12다 [6][14].

### F02.05 사용 근거·변환 기록

**구현.** 이 방식은 `extract_credentials`의 항목별 프레임 번호와 `check_threats`·`check_ip_threats`의 대조 대상 표시에 적용된다 [15][1][2].

- `extract_credentials`는 응답 첫 줄에 읽은 pcap 경로를 적는다 [15].
- 같은 도구는 자격증명 항목마다 규칙 종류(`HTTP Basic Auth`, `FTP`, `Telnet Prompt`, `Telnet`, `Kerberos`)와 tshark 필드에서 읽은 프레임 번호를 싣는다 [4][5][6][15].
- Kerberos 항목은 사용자 이름, realm, 프레임 번호, 만든 해시 문자열, `crackingMode`를 함께 싣는다 [15].
- `check_threats`는 캡처에서 뽑은 고유 IP 목록 전체를 대조 결과 앞에 싣고 대조한 목록을 `URLhaus blacklist`로 적는다 [1].
- `check_ip_threats`는 대조한 IP와 목록 이름을 싣는다 [2].
- 두 도구는 표준 오류에 목록 주소, HTTP 응답 상태, 받은 글의 길이, 뽑은 IP 수, 앞의 IP 5개, 일치한 IP를 적는다 [1][2].

**한계.** FTP 항목의 프레임 번호는 `USER` 명령의 프레임이고 비밀번호를 가져온 `PASS` 명령의 프레임은 남지 않는다 [4].
Telnet 비밀번호를 앞 사용자 항목에 넣을 때도 비밀번호 데이터의 프레임 번호는 남지 않는다 [5].
`check_threats`와 `check_ip_threats`의 응답은 목록을 내려받은 시각, 목록 크기, 내려받기 성공 여부를 싣지 않는다 [1][2].
내려받기에 실패한 사실은 표준 오류에만 남는다 [1][2][8].

공백을 두고 앞뒤에 글자를 붙인 IPv4 주소와 자리마다 255를 넘는 IPv4 꼴 값을 준 `check_ip_threats`는 오류 없이 받은 값을 `IP checked:`에 그대로 실었다.
지어낸 HTTP Basic, FTP, Telnet 자격증명을 담은 pcap에서 `HTTP Basic Auth` 항목의 사용자 이름은 알아볼 수 없는 글자였고 비밀번호는 `undefined`였다.
Telnet 비밀번호 안내 뒤에 Telnet 서버가 보낸 환영 문구는 사용자 이름이 빈 `Telnet` 항목의 비밀번호로 실렸다.
