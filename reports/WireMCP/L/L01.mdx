# L01 기록 방식

### L01.02 도구별 기록 호출

**구현.** 이 방식은 도구 처리기 7개와 처리기가 부르는 `findTshark`에 적용된다 [1][2][3].
서버는 시작할 때 `console.log`를 `console.error`로 바꾸므로 서버가 쓰는 모든 줄은 프로세스의 표준 오류로 나간다 [4].
처리기마다 정해 둔 곳에서 `console.error`를 불러 항목을 쓴다 [1][2][3].
처리기는 시작할 때 받은 인자를 담은 줄을 쓴다 [1][2][3].
`capture_packets`는 `Capturing packets on <interface> for <duration>s`를, `analyze_pcap`은 `Analyzing PCAP file: <pcapPath>`를, `check_ip_threats`는 `Checking IP <ip> against URLhaus blacklist`를 쓴다 [1][2][3].
실행 중에는 찾은 `tshark` 경로, `tshark`의 표준 오류, 찾은 IP·URL·자격증명의 수, URLhaus 응답 상태와 앞 200자를 쓴다 [5][2][6].
처리기가 예외로 끝나면 `Error in <도구 이름>: <예외 문구>` 줄을 쓴다 [1][2].
처리기마다 쓰는 줄이 달라 모든 호출이 지나는 공통 단계는 없다 [1][2][3].

MCP TypeScript SDK 1.15.0의 도구 호출 처리기는 로그를 쓰지 않는다 [7].
서버는 로그 파일이나 DB를 열지 않고 표준 오류를 어디에 남길지는 서버를 실행한 MCP 클라이언트가 정한다 [8].
컨테이너에서 도구 호출 27번을 보내자 표준 오류에는 처리기까지 간 호출마다 위 줄들이 남았다 [9].

같은 저장소에는 MCP 도구 호출을 기록하는 클라이언트 코드, 설정, 훅, 사용자 CLI가 없다.
README는 Cursor와 다른 클라이언트에 `node index.js`를 등록하는 예시만 적는다 [10].

**한계.** 입력 schema 검사에서 거부된 호출은 처리기를 거치지 않아 항목이 남지 않는다 [7][9].
`check_ip_threats`에 숫자 꼴이 없는 `ip`를 준 호출은 표준 오류에 아무 줄도 남기지 않았다 [9].
