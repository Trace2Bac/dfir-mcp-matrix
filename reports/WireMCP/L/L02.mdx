# L02 기록 구성

### L02.01 MCP 요청 기록

**구현.** 이 방식은 도구 처리기 7개가 시작할 때 쓰는 줄에 적용된다 [1][2][3].
처리기는 SDK가 검사해 넘긴 인자를 바꾸기 전에 그 값을 끼워 넣은 줄을 표준 오류에 쓴다 [1][2][3].
`capture_packets`, `get_summary_stats`, `get_conversations`, `check_threats`는 `interface`와 `duration`을, `analyze_pcap`과 `extract_credentials`는 `pcapPath`를, `check_ip_threats`는 `ip`를 담는다 [1][2][3].
이 값은 MCP TypeScript SDK 1.15.0이 해석해 처리기에 넘긴 값이고 전송된 요청 원문 전체는 아니다 [4].
줄은 실행 명령과 따로 쓰인다 [1][2].
줄에는 도구 이름이 없고 도구마다 다른 문구로만 어느 도구의 줄인지 알 수 있다 [1][2][3].
인자 값과 문구는 한 줄의 글 안에 있고 따로 나뉜 칸에 기록되지 않는다 [1][2][3].
`console.error`는 받은 글만 쓰므로 줄에는 시각과 호출 ID가 없다 [1][5].
`analyze_pcap`을 부르자 `Analyzing PCAP file: /work/pcaps/creds.pcap`이, 셸 메타 문자를 넣은 `interface`로 `capture_packets`를 부르자 받은 값 전체가 들어간 `Capturing packets on … for 1s`가 남았다 [5].

**한계.** 인자를 빼고 부른 호출의 줄에는 모델이 보내지 않은 기본값이 남는다 [1][4].
입력 schema 검사에서 거부된 호출은 처리기에 오지 않아 이 줄이 남지 않는다 [4][5].

### L02.02 서버가 변환한 연산·인자 기록

**구현.** 이 방식은 실시간 캡처 도구 4개가 `interface`나 `duration`을 받지 않은 호출의 시작 줄에 적용된다 [6][7].
서버 코드는 입력 schema에 `interface`의 기본값 `en0`과 `duration`의 기본값 5를 적는다 [6].
MCP TypeScript SDK 1.15.0은 이 schema로 인자를 검사하면서 빠진 값을 기본값으로 채워 처리기에 넘긴다 [4].
처리기는 채운 값을 받은 인자와 같은 자리에 넣어 시작 줄에 쓴다 [7].
인자 없이 `capture_packets`를 부르자 `Capturing packets on en0 for 5s`가 남았다 [5].

**한계.** 줄만으로는 모델이 값을 보냈는지 SDK가 기본값을 채웠는지 구별할 수 없다 [7].

### L02.03 외부 실행 명령 기록

**구현.** 이 방식은 `tshark` 실행이 실패한 호출의 오류 줄에 적용된다 [8][9].
Node.js 22.17.0의 `exec`는 실패한 명령의 오류 문구를 `Command failed: <명령 문자열>`과 그 명령의 표준 오류로 만든다 [9].
처리기는 이 문구를 `Error in <도구 이름>: <문구>` 줄로 쓰므로 셸에 넘긴 `tshark` 명령 문자열 전체가 기록에 남는다 [8][9].
`findTshark`도 경로 목록의 시험이 실패하면 `Fallback <경로> failed: Command failed: <경로> -v` 줄을 쓴다 [10].
`findTshark`는 찾은 실행 파일 경로를 `Found tshark at: <경로>` 줄로 쓴다 [10].
끝이 잘린 pcap 파일로 `analyze_pcap`을 부르자 `Error in analyze_pcap: Command failed: /usr/bin/tshark -r "/work/pcaps/truncated.pcap" -T json …` 줄과 `tshark`의 오류 줄이 남았다 [5].

**한계.** 성공한 실행은 명령 문자열을 남기지 않는다 [1][2].
출력이 `maxBuffer`를 넘어 끝난 실행의 줄에는 `stdout maxBuffer length exceeded`만 있고 명령 문자열이 없다 [11][5].

### L02.06 결과 참조·요약값 기록

**구현.** 이 방식은 `analyze_pcap`, `check_threats`, `check_ip_threats`, `extract_credentials`, `capture_packets`가 결과를 만든 뒤 쓰는 줄에 적용된다 [2][12][3][13][1].
`analyze_pcap`은 고유 IP 수와 목록, URL 수와 목록, 프로토콜 목록을 쓴다 [2].
`check_threats`는 잡은 고유 IP 수와 목록, URLhaus에서 뽑은 IP 수, 일치한 IP 수와 목록을 쓴다 [12].
`check_ip_threats`는 URLhaus 목록에서 뽑은 IP 수와 받은 IP의 일치 여부(`Threat found` 또는 `No threat found`)를 쓴다 [3].
`extract_credentials`는 찾은 평문 항목 수와 암호화 항목 수를 쓴다 [13].
`capture_packets`와 `analyze_pcap`은 패킷 JSON을 잘랐을 때 `Trimmed packets from … to … to fit 720000 chars` 줄을 쓴다 [1][2].
결과의 해시나 저장 경로는 어느 줄에도 없다 [14].
`get_summary_stats`와 `get_conversations`는 결과에 대한 요약값을 쓰지 않는다 [15][16].

**한계.** 자르기 줄의 첫 숫자는 자르기 전 패킷 수가 아니라 자른 뒤 남은 패킷 수다 [1][2].
`analyze_pcap`은 `packets.splice`로 배열을 줄인 뒤, `capture_packets`는 `packets`에 자른 배열을 넣은 뒤 그 길이를 쓴다 [1][2].
패킷 468개를 410개로 자른 `analyze_pcap` 호출은 `Trimmed packets from 410 to 410 to fit 720000 chars`를 남겼다 [5].
`capture_packets`는 패킷 JSON을 자르지 않은 호출에서 결과에 대한 줄을 쓰지 않는다 [1].
