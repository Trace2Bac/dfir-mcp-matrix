# L04 기록 위변조 방지

### 미구현

**판단.** 서버 기록은 처리기가 `console.error`로 쓰는 줄이고 서버는 이 줄을 표준 오류로만 내보낸다 [1][2].
서버 코드에는 기록 파일이나 DB를 여는 곳이 없다 [2].
줄에는 시각, 일련번호, 앞 줄의 해시가 없고 처리기가 만든 글만 있다 [1][2].
표준 오류를 어디에 어떻게 남길지는 서버를 실행한 MCP 클라이언트가 정한다 [3].
저장소에는 Dockerfile이나 실행 구성이 없어 기록을 담을 위치를 따로 정하지 않는다 [4].
기록을 다시 계산해 어긋난 줄을 알려 주는 도구나 명령도 없다 [2][4].
그래서 서버 기록의 수정, 삭제, 순서 변경을 막거나 알아차리는 장치가 없다.

### 근거

[1] 서버는 `console.log`를 `console.error`로 바꾸고 처리기는 글만 쓴다.

```javascript
// Redirect console.log to stderr
const originalConsoleLog = console.log;
console.log = (...args) => console.error(...args);
```

[`index.js:12-14`](https://github.com/0xKoda/WireMCP/blob/7f45f8b2b4adeb76be8c6227eefb38533fdd6b1e/index.js#L12-L14)

[2] 서버 코드 전체에 기록 파일, DB, 해시 계산이 없다: [`index.js:1-663`](https://github.com/0xKoda/WireMCP/blob/7f45f8b2b4adeb76be8c6227eefb38533fdd6b1e/index.js#L1-L663).

[3] (실행 확인) MCP TypeScript SDK 클라이언트의 `StdioClientTransport`에 `stderr: "pipe"`를 주자 서버의 줄은 클라이언트가 연 파이프로 왔고 그 내용을 파일로 남긴 것은 시험 클라이언트였다.

[4] (실행 확인) 기준 커밋의 파일은 `.gitignore`, `LICENSE`, `README.md`, `Wire-MCP.png`, `index.js`, `package.json` 6개다.
