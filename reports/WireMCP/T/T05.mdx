# T05 분석 도구 검증

### 미구현

**판단.** 서버가 쓰는 분석 도구 `tshark`와 참조 자료 URLhaus 목록의 버전을 저장소가 고정하지도, 설정이나 인자로 정하지도, 실행할 때 확인하지도 않는다 [1][2][3].

`tshark`는 저장소에 설치 정의가 없다 [1].
`package.json`은 npm 의존성만 적고 README는 Wireshark를 설치해 `tshark`를 `PATH`에 두라고만 적는다 [1][4].
`findTshark`는 호출마다 `which('tshark')`로 `PATH`에서 실행 파일을 찾고 찾지 못하면 코드에 적은 경로를 차례로 시험한다 [2].
경로 목록의 실행 파일은 `-v`로 실행해 보지만 그 출력은 읽지 않고 실행이 성공했는지만 본다 [2].
`tshark`의 위치나 버전을 정하는 설정 파일, 환경변수, 인자는 없다 [2][5].
서버는 `tshark`의 버전을 읽지 않는다 [5].

URLhaus 목록은 `check_threats`와 `check_ip_threats`가 IP를 대조하는 IOC 목록이다 [3].
두 도구는 호출마다 코드에 적은 주소 `https://urlhaus.abuse.ch/downloads/text/`에서 그때의 목록을 내려받는다 [3].
서버는 받은 목록의 버전, 생성 시각, 해시를 읽거나 남기지 않고 대조에 쓴 목록을 저장하지도 않는다 [3].

`package.json`은 MCP TypeScript SDK, axios, zod, which를 `^1.8.0`처럼 범위로만 적고 저장소에는 잠금 파일이 없다 [1][6].
이 라이브러리들은 증거를 해석하지 않는 서버 실행용 라이브러리다 [1].
`package.json`이 적은 `child_process`와 `util`은 npm 패키지 이름이지만 Node.js는 `require`에 내장 모듈을 돌려준다 [1][7].

async function findTshark() {
  try {
    const tsharkPath = await which('tshark');
    console.error(`Found tshark at: ${tsharkPath}`);
    return tsharkPath;
  } catch (err) {
    console.error('which failed to find tshark:', err.message);
    const fallbacks = process.platform === 'win32'
      ? ['C:\\Program Files\\Wireshark\\tshark.exe', 'C:\\Program Files (x86)\\Wireshark\\tshark.exe']
      : ['/usr/bin/tshark', '/usr/local/bin/tshark', '/opt/homebrew/bin/tshark', '/Applications/Wireshark.app/Contents/MacOS/tshark'];
    
    for (const path of fallbacks) {
      try {
        await execAsync(`${path} -v`);
        console.error(`Found tshark at fallback: ${path}`);
        return path;
      } catch (e) {
        console.error(`Fallback ${path} failed: ${e.message}`);
      }
    }
    throw new Error('tshark not found. Please install Wireshark (https://www.wireshark.org/download.html) and ensure tshark is in your PATH.');
  }
}
