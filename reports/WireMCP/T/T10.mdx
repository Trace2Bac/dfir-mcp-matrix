# T10 도구 명세 구성

### T10.01 처리 함수에서 명세 생성

**구현.** 이 방식은 도구 7개와 프롬프트 7개에 적용된다 [1][2].
서버는 도구마다 `server.tool`에 이름, 설명, zod로 쓴 인자 꼴, 처리 함수를 넘긴다 [1].
MCP TypeScript SDK 1.15.0은 그 인자 꼴로 zod `object`를 만들어 두고 `tools/list`에는 `zodToJsonSchema`로 바꾼 입력 schema를, 도구 호출에는 같은 `object`로 검사한 인자를 쓴다 [3].
그래서 입력 schema와 처리 함수가 받는 인자는 같은 정의에서 나온다 [1][3].
`tools/list`의 입력 schema에는 zod에 적은 `default`(`en0`, 5), `describe`의 설명, `ip`의 정규식이 `pattern`으로 실렸다 [4].
도구에는 `title`과 annotation이 없다 [1][4].
프롬프트는 `server.prompt`에 이름과 zod 인자 꼴, 글을 만드는 함수를 넘기고 SDK가 그 꼴로 인자 목록을 만들고 인자를 검사한다 [2][5].
서버 코드에는 리소스를 등록하는 곳이 없고 `McpServer`에는 이름과 버전만 주어 초기화 지침이 없다 [6][4].

SDK는 도구를 등록할 때 `tools.listChanged`를 참으로 선언한다 [7].
서버는 연결하기 전에 도구 7개를 모두 등록하고 실행 중에 도구를 바꾸지 않는다 [1][8].
SDK는 연결된 뒤에만 목록 변경 알림을 보내므로 이 서버는 알림을 보내지 않는다 [7].
초기화 응답의 capabilities는 `tools.listChanged`와 `prompts.listChanged`가 참이었다 [4].

**한계.** 명세가 알리는 내용과 처리기의 동작이 다른 곳이 있다.
`get_conversations`의 설명은 TCP/UDP 대화 통계를 준다고 적지만 처리기는 `tshark -qz conv,tcp`만 실행한다 [9].
UDP 패킷이 있는 루프백 트래픽으로 부르자 응답에는 `TCP Conversations` 표만 있었다 [4].
`extract_credentials`의 설명은 HTTP Basic, FTP, Telnet을 적지만 처리기는 Kerberos 필드도 읽어 해시 문자열을 만든다 [10][11].

실시간 캡처 프롬프트 4개는 `duration`을 zod `number`로 적는다 [2].
MCP의 `prompts/get` 인자는 글자 값만 받으므로 `duration`을 준 호출은 SDK 검사에서 거부된다 [12][5].
`capture_packets_prompt`에 `duration` `"2"`를 주자 `Expected number, received string` 오류가 왔다 [4].
