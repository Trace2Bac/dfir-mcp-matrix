# T04 실행 방식

### T04.01 서버 프로세스 안 분석

**구현.** 이 방식은 URLhaus 대조와 `tshark` 출력을 받아 집계하거나 해석하는 도구에 적용된다 [1][2][3][4].
`check_threats`와 `check_ip_threats`는 axios로 받은 URLhaus 목록에서 줄마다 IPv4 꼴을 정규식으로 뽑고 받은 IP가 그 목록에 있는지 서버 코드로 찾는다 [1].
`check_threats`는 `tshark`가 낸 `ip.src`·`ip.dst` 열을 서버 코드로 나누고 중복을 뺀다 [2].
`analyze_pcap`은 `tshark`의 JSON을 해석해 고유 IP, URL, 프로토콜 목록을 서버 코드로 만든다 [3].
`extract_credentials`는 `tshark`가 낸 필드 열을 서버 코드로 해석해 HTTP Basic 값을 base64로 디코딩하고 FTP·Telnet 값을 사용자 이름과 비밀번호로 묶고 Kerberos 값을 해시 문자열로 만든다 [4].
패킷을 해석하는 일은 모두 `tshark` 하위 프로세스가 한다 [5].

### T04.03 셸 명령 문자열 실행

**구현.** 이 방식은 서버가 `tshark`를 실행하는 모든 경로에 적용된다 [5][6].
서버는 `child_process`의 `exec`를 `promisify`로 감싼 `execAsync`에 명령 문자열 하나를 넘긴다 [6].
Node.js 22.17.0의 `exec`는 `shell`을 참으로 두고 POSIX에서는 `/bin/sh -c`, Windows에서는 `cmd.exe /d /s /c`로 그 문자열을 실행한다 [7].
`findTshark`가 경로 목록의 실행 파일을 시험하는 `<경로> -v`도 같은 `execAsync`로 실행한다 [8].

도구가 실행하는 `tshark`는 서버와 같은 계정, 파일, 네트워크 권한을 가진다 [5].
`execAsync`에는 `cwd`를 주지 않아 `tshark`는 서버의 작업 폴더에서 실행되고 캡처 도구의 `temp_capture.pcap`도 그 폴더에 생긴다 [5].
환경변수는 서버의 환경 전체에 `PATH` 뒤 `:/usr/bin:/usr/local/bin:/opt/homebrew/bin`을 더해 넘긴다 [5].
`timeout`과 `maxBuffer`를 주지 않으므로 시간 제한은 없고 표준 출력과 표준 오류는 각각 Node.js 기본값 1 MiB까지 받는다 [5][9].
저장소에는 Dockerfile이나 실행 구성이 없고 README는 `node index.js`로 서버를 실행하라고 적는다 [10].
실행 확인에 쓴 컨테이너에서도 서버와 `tshark`는 같은 컨테이너의 root 계정으로 실행되었다 [11].
