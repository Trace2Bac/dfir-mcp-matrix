# T07 도구 부재 처리

### T07.01 실행 전 도구·참조 자료 가용성 검사

**구현.** 이 방식은 `tshark`를 실행하는 도구 6개에 적용된다 [1][2].
도구 처리기는 호출마다 맨 앞에서 `findTshark`를 부르고 그 결과로 받은 경로로 `tshark`를 실행한다 [1][2].
`findTshark`는 which 5.0.0의 `which('tshark')`로 서버의 `PATH`에서 실행 파일을 찾는다 [1].
찾지 못하면 운영체제별 경로 목록의 실행 파일을 하나씩 `-v`로 실행해 보고 처음 성공한 경로를 쓴다 [1].
모두 실패하면 예외를 던지고 처리기는 `tshark`를 실행하지 않는다 [1][2].
컨테이너에서 `tshark` 실행 파일을 옮긴 뒤 `analyze_pcap`을 부르자 `tshark`를 실행하지 않고 오류 응답이 왔다 [3].

URLhaus 목록은 실행 전에 받을 수 있는지 확인하지 않는다 [4].
`check_threats`는 캡처를 마친 뒤에 목록을 내려받고 `check_ip_threats`는 바로 내려받는다 [4][5].

**한계.** 경로 목록의 실행 파일을 시험하는 `<경로> -v`는 경로를 따옴표 없이 셸 명령 문자열에 넣는다 [1].
Windows 목록의 두 경로는 `C:\Program Files\…`처럼 공백을 담고 있다 [1].
Node.js의 `exec`는 Windows에서 명령 문자열을 `cmd.exe`에 넘긴다 [6].
공백이 있는 폴더에 둔 시험 명령 파일을 따옴표 없이 `exec`로 실행하자 `cmd.exe`가 첫 공백 앞까지를 명령 이름으로 읽어 실패했고 따옴표로 감싸자 실행되었다 [7].
그래서 Windows에서는 이 시험이 실행 파일이 있어도 실패할 수 있다 [1][7].
Windows에 Wireshark를 설치한 경로로는 실행하지 않았다.

### T07.02 대체 없는 실패 처리·도구 부재 알림

**구현.** 이 방식은 앞의 확인이 적용되는 도구 6개에 적용된다 [1][2].
`findTshark`는 `tshark`를 찾지 못하면 `tshark not found. Please install Wireshark (https://www.wireshark.org/download.html) and ensure tshark is in your PATH.` 문구의 예외를 던진다 [1].
처리기는 이 문구 앞에 `Error: `를 붙여 `isError` 참인 응답으로 돌려준다 [2].
`tshark`를 옮긴 컨테이너에서 `analyze_pcap`을 부르자 이 문구가 담긴 오류 응답이 왔다 [3].
`tshark`가 없어도 `check_ip_threats`는 영향을 받지 않고 실행되었다 [3].

### T07.03 알림 없는 대체 실행

**구현.** 이 방식은 `findTshark`가 `PATH`에서 `tshark`를 찾지 못했을 때 경로 목록의 실행 파일을 쓰는 경우에 적용된다 [1].
`findTshark`는 대체 경로를 쓴다는 사실을 `Found tshark at fallback: <경로>` 줄로 표준 오류에만 쓴다 [1].
도구 응답은 어느 경로의 `tshark`를 썼는지 싣지 않는다 [8].
`PATH`를 `/usr/local/bin` 하나로 줄여 서버를 실행하자 표준 오류에 `which failed to find tshark: not found: tshark`와 `Found tshark at fallback: /usr/bin/tshark`가 남았다 [3].
같은 서버의 `analyze_pcap` 응답은 `PATH`에서 찾았을 때와 같은 꼴이었다 [3].

### T07.04 실행 환경별 경로 분기

**구현.** 이 방식은 `findTshark`의 대체 경로 목록과 `tshark`를 실행할 때 넘기는 `PATH`에 적용된다 [1][9].
`findTshark`는 `process.platform`이 `win32`이면 `C:\Program Files\Wireshark\tshark.exe`와 `C:\Program Files (x86)\Wireshark\tshark.exe`를, 아니면 `/usr/bin/tshark`, `/usr/local/bin/tshark`, `/opt/homebrew/bin/tshark`, `/Applications/Wireshark.app/Contents/MacOS/tshark`를 이 차례로 시험한다 [1].
이 목록은 `which`가 `PATH`에서 찾지 못했을 때만 쓴다 [1].
`tshark`를 실행하는 `execAsync`에는 서버의 `PATH` 뒤에 `:/usr/bin:/usr/local/bin:/opt/homebrew/bin`을 붙인 환경을 넘긴다 [9].
`tshark`가 없는 컨테이너의 표준 오류에는 POSIX 목록 네 경로를 차례로 시험하고 실패한 줄이 남았다 [3].

**한계.** 더하는 `PATH` 값은 POSIX의 구분자 `:`로 이어 붙이므로 Windows에서는 폴더 목록으로 쓰이지 않는다 [9].
`tshark` 명령은 찾은 경로를 따옴표 없이 앞에 둔다 [9].
그래서 `which`가 공백이 있는 Windows 설치 경로를 돌려주면 그 뒤 `tshark` 실행도 같은 이유로 실패할 수 있다 [9][7].
Windows에 Wireshark를 설치한 경로로는 실행하지 않았다.

### T07.08 일부 제외 후 계속 실행

**구현.** 이 방식은 `check_threats`가 URLhaus 목록을 내려받지 못한 경우에 적용된다 [4].
`check_threats`는 axios 요청이나 목록 해석에서 예외가 나면 그 예외를 표준 오류에 쓰고 대조할 목록을 빈 배열로 둔다 [4].
그 뒤 대조를 실행하지 않은 채 잡은 IP 목록과 대조 결과 절을 만들어 성공 응답으로 돌려준다 [4][10].
대조 결과 절에는 목록에 있던 IP가 없을 때와 같은 `No threats detected in URLhaus blacklist.` 문구가 실린다 [10].
네트워크를 끈 컨테이너에서 `check_threats`를 부르자 잡은 IP 목록과 이 문구를 담은 응답이 `isError` 없이 왔다 [3].

`check_ip_threats`는 내려받기가 실패하면 대조를 실행하지 않고 일치가 없을 때와 같은 응답을 성공으로 돌려준다 [5][11].
이 도구에는 URLhaus 대조 말고 다른 단계가 없어 응답은 받은 IP와 `No threat detected in URLhaus blacklist.` 문구뿐이다 [5][11].
네트워크를 끈 컨테이너에서 `check_ip_threats`를 부르자 이 응답이 `isError` 없이 왔다 [3].

**한계.** 응답에는 목록을 받지 못했다는 사실이 없고 표준 오류의 `Failed to fetch URLhaus data:` 줄에만 남는다 [4][10].
그래서 응답만으로는 대조한 결과 일치가 없는지 대조하지 못했는지 구별할 수 없다 [10][11].

```javascript
async function findTshark() {
  try {
    const tsharkPath = await which('tshark');
    console.error(`Found tshark at: ${tsharkPath}`);
    return tsharkPath;
  } catch (err) {
    console.error('which failed to find tshark:', err.message);
    const fallbacks = process.platform === 'win32'
      ? ['C:\\Program Files\\Wireshark\\tshark.exe', 'C:\\Program Files (x86)\\Wireshark\\tshark.exe']
      : ['/usr/bin/tshark', '/usr/local/bin/tshark', '/opt/homebrew/bin/tshark', '/Applications/Wireshark.app/Contents/MacOS/tshark'];
    
    for (const path of fallbacks) {
      try {
        await execAsync(`${path} -v`);
        console.error(`Found tshark at fallback: ${path}`);
        return path;
      } catch (e) {
        console.error(`Fallback ${path} failed: ${e.message}`);
      }
    }
    throw new Error('tshark not found. Please install Wireshark (https://www.wireshark.org/download.html) and ensure tshark is in your PATH.');
  }
}
```
