# WireMCP 원고

이 파일은 서버 개요다. 셀마다 이 폴더 아래 축 폴더의 `<축>/<셀ID>.mdx`에 쓴다.
셀과 상세 항목의 정의는 `matrix/cells/<축>/<셀ID>.mdx`를 따른다.
상세 항목마다 **구현**을 쓰고 그 방식이 적용되지 않는 경로나 조건이 있으면 **한계**를 따로 쓴다.
본문의 [번호]는 그 파일 끝 **근거**의 같은 번호를 가리킨다.

**기준 커밋.** [`7f45f8b`](https://github.com/0xKoda/WireMCP/tree/7f45f8b2b4adeb76be8c6227eefb38533fdd6b1e)(2025-07-10).
줄 번호는 모두 이 커밋 기준이다.

**범위.** 저장소의 `index.js` 한 파일이 MCP 서버 하나다.
`index.js`는 MCP TypeScript SDK의 `McpServer`로 서버(이름 `wiremcp`, 버전 `1.0.0`)를 만들고 Node.js에서 stdio로 실행한다.
서버는 도구 7개와 프롬프트 7개를 등록하고 리소스와 초기화 지침은 두지 않는다(실행 확인).
도구 가운데 `capture_packets`, `get_summary_stats`, `get_conversations`, `check_threats`는 서버를 실행한 호스트의 네트워크 인터페이스에서 정한 시간 동안 패킷을 잡아 분석한다.
`analyze_pcap`과 `extract_credentials`는 인자로 받은 pcap 파일을 읽는다.
`check_threats`와 `check_ip_threats`는 URLhaus 목록을 내려받아 IP를 대조한다.
패킷 캡처와 해석은 서버가 하위 프로세스로 실행하는 tshark가 맡는다.
README, `Wire-MCP.png`, `LICENSE`는 서버 구현으로 보지 않는다.
저장소에는 시험 코드, MCP 클라이언트 설정 파일, 훅이 없고 README가 클라이언트 등록 예시만 적는다.
README의 설명은 코드로 확인한 것만 사실로 쓴다.

**확인 방법.** 코드는 기준 커밋을 `git show`로 읽었다.
라이브러리와 tshark의 동작은 아래 버전 기준의 소스로 확인했다.
근거의 "실행 확인"은 기준 커밋을 `git archive`로 풀어 둔 사본을 Docker 컨테이너에서 실행해 본 결과다.
컨테이너는 `node:22.17.0-bookworm-slim`에 Debian bookworm 패키지 tshark를 설치하고 사본에서 `npm install --omit=dev --before=2025-07-09T20:28:17Z`로 의존성을 설치한 것이다.
서버는 MCP TypeScript SDK 클라이언트로 `node index.js`를 stdio로 띄워 확인했다.
pcap 입력은 컨테이너 안에서 만든 시험 파일만 썼고 실시간 캡처는 컨테이너의 루프백 인터페이스에서만 했다.
컨테이너는 네트워크를 끈 상태(`--network none`)로 실행했으므로 URLhaus에는 연결하지 않았다.

**외부 도구 버전 기준.** `package.json`은 의존성을 `^1.8.0`처럼 범위로만 적고 저장소에 잠금 파일이 없다.
그래서 의존성은 기준 커밋 시각(2025-07-09 20:28Z) 전에 공개된 최신 버전을 쓴다(MCP TypeScript SDK 1.15.0, axios 1.10.0, zod 3.25.76, which 5.0.0).
하위 의존성도 같은 시각 기준으로 `npm install --before`가 고른 버전을 쓴다.
`package.json`이 적은 `child_process` 1.0.2와 `util` 0.12.5는 npm에 올라간 같은 이름의 패키지다.
Node.js는 `require('child_process')`와 `require('util')`에 이 패키지가 아니라 내장 모듈을 돌려준다.
Node.js 버전은 저장소가 정하지 않으므로 기준 시각 전 최신 LTS인 22.17.0을 쓴다.
tshark는 저장소가 버전을 정하지 않으므로 Wireshark-MCP 원고와 같은 Debian bookworm 패키지 4.0.17을 쓴다.

- MCP TypeScript SDK 1.15.0은 태그 `1.15.0`의 커밋 `1ac2e59`, Node.js 22.17.0은 태그 `v22.17.0`의 커밋 `3567fa7`, Wireshark 4.0.17은 태그 `v4.0.17`의 커밋 `882448b`로 확인한다.
- zod 3.25.76은 태그 `v3.25.76`의 커밋 `7baee4e`, axios 1.10.0은 태그 `v1.10.0`의 커밋 `73a836d`로 확인한다.
- axios가 쓰는 follow-redirects 1.15.9는 태그 `v1.15.9`의 커밋 `e4e55c7`, proxy-from-env 1.1.0은 태그 `v1.1.0`의 커밋 `96d01f8`로 확인한다.
- Kerberos 메시지 유형 값은 RFC 4120 7.5.7절, 셸의 큰따옴표 처리는 POSIX.1-2017 Shell Command Language 2.2.3절로 확인한다. 실행 컨테이너의 `/bin/sh`는 dash다(실행 확인).
- Windows에서 `exec`가 공백이 들어간 경로를 다루는 방식은 이 호스트의 Node.js 24.21.0으로 시험용 실행 파일만 실행해 확인했고 Windows 분기 코드는 22.17.0 소스로 확인했다.
- 원고에서 인용한 그 밖의 버전과 소스 커밋은 이 단락에 더한다.
