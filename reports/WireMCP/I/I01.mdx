# I01 외부 연동 대상 관리

### I01.03 기본 활성화

**구현.** 이 방식은 `check_threats`와 `check_ip_threats`가 URLhaus 목록을 내려받는 연결에 적용된다 [1].
`index.js`에서 `axios`를 부르는 곳은 이 두 도구의 `axios.get` 두 곳뿐이다 [1][2].
다른 도구는 tshark를 하위 프로세스로 실행해 패킷을 잡거나 pcap 파일을 읽고 서버 코드가 외부 연결을 열지 않는다 [2].
두 도구는 조건 없이 등록되어 늘 도구 목록에 있다 [3].
모델이 두 도구를 부르면 서버는 설정이나 자격증명 없이 목록을 요청한다 [1].
연결을 켜거나 끄는 설정 파일, 환경변수, 시작 인자는 없다 [2].
서버 코드는 환경변수를 tshark에 넘길 `env`를 만드는 데만 쓴다 [2].
`check_ip_threats`는 tshark를 찾거나 실행하지 않고 호출을 받으면 바로 목록을 요청한다 [1].
`check_threats`는 tshark로 캡처하고 캡처에서 IP를 뽑은 뒤에 목록을 요청한다 [4].
tshark를 찾지 못하거나 캡처 명령이 실패하면 `check_threats`는 오류 응답으로 끝나고 목록을 요청하지 않는다 [4].
두 도구는 받은 목록을 처리기 안의 변수 `urlhausData`에만 두고 저장하지 않는다 [1].
그래서 두 도구는 호출할 때마다 목록 전체를 새로 요청한다 [1][5].
네트워크를 끈 컨테이너에서 같은 서버에 `check_ip_threats`를 두 번 부르자 두 호출 모두 URLhaus 주소로 요청을 시도했다 [5].
두 요청은 모두 `urlhaus.abuse.ch`의 이름 해석 오류로 실패했다 [5].

### I01.05 고정 목적지

**구현.** 이 방식은 `check_threats`와 `check_ip_threats`가 URLhaus 목록을 내려받는 연결에 적용된다 [1].
두 처리기는 요청 주소 `https://urlhaus.abuse.ch/downloads/text/`를 처리기 안의 문자열 상수 `urlhausUrl`로 둔다 [1].
이 주소를 바꾸는 설정, 환경변수, 도구 인자는 없다 [2][3].
`check_threats`의 인자는 `interface`와 `duration`이고 `check_ip_threats`의 인자는 `ip`뿐이다 [3].
이 인자 값은 요청 주소에 들어가지 않는다 [1].
`check_ip_threats`는 받은 목록의 줄마다 IP 형식의 문자열을 뽑아 서버 프로세스 안에서 `ip`와 대조한다 [6].
두 처리기는 `axios.get`에 주소만 넘기고 요청 설정을 주지 않는다 [1].
axios 1.10.0은 기본 어댑터 목록 `xhr`, `http`, `fetch`에서 실행 환경이 지원하는 첫 어댑터를 쓴다 [7].
Node.js 22.17.0 컨테이너에는 `XMLHttpRequest`가 없었으므로 요청은 `http` 어댑터로 나간다 [7][5].
axios의 `timeout` 기본값은 0이고 이 값이 0이면 `http` 어댑터는 시간 제한을 두지 않는다 [8].
`maxRedirects`를 주지 않으면 `http` 어댑터는 follow-redirects 1.15.9로 요청하고 follow-redirects는 리다이렉트를 21번까지 따라간다 [9].
`proxy`를 주지 않으면 `http` 어댑터는 proxy-from-env 1.1.0으로 환경변수 `https_proxy`, `all_proxy`, `no_proxy` 등을 읽어 프록시를 정한다 [10].
`httpsAgent`를 주지 않으므로 HTTPS 연결은 Node.js 22.17.0의 기본값대로 서버 인증서를 확인한다 [11].

**한계.** 서버 코드에는 리다이렉트 대상이나 프록시를 확인하는 처리가 없다 [1].
URLhaus가 다른 호스트로 리다이렉트하면 axios는 그 호스트가 돌려준 응답을 목록으로 넘긴다 [9].
URLhaus가 리다이렉트 응답을 돌려주는지는 확인하지 않았다.
환경변수에 프록시가 있으면 axios는 고정 주소 대신 그 프록시에 연결하고 프록시가 돌려준 응답을 받는다 [10].
네트워크를 끈 컨테이너에서 `HTTPS_PROXY`를 로컬 수신 프로그램의 `http://` 주소로 주고 `check_ip_threats`를 부르자 요청은 그 수신 프로그램으로 갔다 [12].
수신 프로그램이 받은 요청은 목적지 URL 전체를 요청 줄에 적은 평문 HTTP 요청이었다 [12].
