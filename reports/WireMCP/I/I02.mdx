# I02 분석 도구 통신 차단

### 미구현

**판단.** 서버는 분석 도구 tshark를 하위 프로세스로 실행하고 tshark의 통신을 끊거나 끄는 장치를 두지 않는다 [1].
tshark를 실행하는 도구는 `check_ip_threats`를 뺀 6개다 [1].
서버가 패킷을 잡거나 읽으려고 만드는 tshark 명령 11개에는 이름 해석을 끄는 `-n`, 이름 해석 종류를 정하는 `-N`, 환경설정 값을 바꾸는 `-o`가 없다 [1].
Wireshark 4.0.17의 이름 해석 기본값은 네트워크 주소 이름 해석 `network_name`이 거짓이다 [2].
`network_name`이 거짓이면 tshark는 주소의 역방향 DNS 조회를 하지 않는다 [3].
tshark는 실행한 사용자의 환경설정 파일을 읽어 이 값을 정한다 [4].
서버는 tshark에 서버 프로세스의 환경변수를 모두 넘기고 `PATH`에 폴더만 더한다 [5].
사용자 환경설정에서 네트워크 이름 해석을 켠 경우에 서버 명령에는 이를 끄는 옵션이 없다 [1][4].
그런 환경설정에서 tshark가 DNS 조회를 보내는지는 이 서버로 실행해 확인하지 않았다.
저장소에는 tshark를 네트워크 없는 컨테이너나 network namespace에서 실행하는 구성이 없다 [6].
실시간 캡처 도구 4개는 모델이 준 `interface` 값을 tshark의 `-i` 값으로 넘긴다 [7].
원격 캡처 형식의 장치 이름을 주었을 때 tshark가 연결을 여는지는 확인하지 않았다.
URLhaus 목록을 받는 axios 요청은 서버 코드가 일부러 여는 연결이다 [8].
