# D01 파생물 보관

### D01.01 파생물 파일 보관

**구현.** 이 방식은 `ir-collect`의 `collect_triage_package`가 남기는 수집 ZIP, `work_on_copy`를 거짓으로 준 `ir-collect` 분석 도구에서 `IR_Collect.exe`가 증거 폴더에 쓰는 CSV, `IR_Collect.exe`와 Hayabusa가 자기 폴더에 쓰는 로그 파일에 적용된다 [1][2][3][4].
서버 코드에는 이 파일들을 호출 뒤에 지우는 곳이 없다.

`collect_triage_package`는 수집 폴더를 현재 폴더로 `IR_Collect.exe -c <evidence_id>`를 실행하고 그 폴더에 생긴 `<evidence_id>.zip`을 결과로 돌려준다 [1].
수집 폴더는 환경변수 `IRCOLLECT_COLLECT_DIR`가 가리키는 폴더이고 이 값이 없으면 작업 폴더 아래 `collections`다 [5].
`IR_Collect.exe` 0.24.2는 수집 자료를 `IR_Output_<ID>` 폴더에 모아 ZIP으로 묶고 ZIP의 SHA-256을 `<ID>.zip.sha256`에 쓴다 [6].
설정 `DeleteOutputDirAfterZip`이 `0`이나 `false`가 아니면 묶은 뒤 `IR_Output_<ID>` 폴더를 지운다 [6].
이 도구는 환경변수 `IRCOLLECT_ALLOW_COLLECTION`이 켜져 있고 호출 인자 `acknowledge_live_response`가 참일 때만 수집을 실행한다 [1].

`analyze_artifact_folder`·`correlate_hosts`·`expand_investigation_graph`는 `work_on_copy`가 참(기본값)이면 증거 폴더를 작업 폴더에 복사해 그 사본을 `IR_Collect.exe`에 넘긴다 [2][7].
`work_on_copy`를 거짓으로 주면 증거 폴더를 그대로 넘긴다 [2][7].
`IR_Collect.exe` 0.24.2의 `-analyze`·`-correlate`·`-graph`는 받은 폴더를 불러오면서 그 폴더 안에 파생 CSV를 쓴다 [8].
그 CSV는 원시 하이브와 SRUM DB에서 만든 `amcache_programs.csv`·`amcache_files.csv`·`shimcache_entries.csv`·`srum_*.csv`, EVTX 곁의 `<로그 이름>_filtered.csv`, `Registry/shellbags.csv`다 [8][9].
서버는 이때 응답의 `provenance.warning`에 증거 폴더에 파생 CSV가 쓰였을 수 있다고 적고 그 CSV를 지우지 않는다 [2].
시험용 실행 파일이 받은 폴더에 CSV를 쓰게 하고 `work_on_copy`를 거짓으로 부르자 그 CSV는 호출 뒤에도 증거 폴더에 남았다 [10].

`IR_Collect.exe` 0.24.2는 정보와 경고를 실행 파일 폴더의 `logs/ir_collect.log`에 이어 쓴다 [3].
`-analyze` 경로는 EVTX 필터 CSV를 다시 만든 건수와 실패를 이 파일에 적는다 [8].
Hayabusa 3.10.0은 실행 중 오류가 쌓이면 끝날 때 현재 폴더의 `logs/errorlog-<날짜>_<시각>.log`에 명령줄과 오류를 쓰고 `-Q`를 받으면 이 파일을 쓰지 않는다 [4].
`artifact-forensic`은 Hayabusa에 `-Q`를 주지 않고 Hayabusa 실행 파일의 폴더를 현재 폴더로 실행한다 [11].
시험용 실행 파일로 확인하자 Hayabusa 자리의 실행 파일이 받은 인자에는 `-Q`가 없었고 현재 폴더는 그 실행 파일의 폴더였다 [12].

그 밖의 도구 출력과 중간 자료는 호출 안에서 지운다.
`ir-collect`는 호출마다 작업 폴더 아래 `run_<난수>` 폴더를 만들어 증거 사본, ZIP을 푼 파일, `IR_Collect.exe`가 쓴 JSON을 두고 `finally`에서 그 폴더를 지운다 [7][13].
작업 폴더는 환경변수 `IRCOLLECT_WORK_DIR`가 가리키는 폴더이고 이 값이 없으면 시스템 임시 폴더 아래 `ir-collect-mcp`다 [5].
`artifact-forensic`은 Zimmerman 도구의 CSV, Hayabusa의 JSONL, capa와 YARA의 표준 출력을 작업 폴더 아래 호출마다 만든 폴더에 쓰고 응답을 만든 뒤 그 폴더를 지운다 [14][15].
ZIP 항목은 작업 폴더 아래 사본으로 꺼내 분석하고 응답을 돌려주기 전에 그 사본을 지운다 [16].
`local-forensic`은 Sysinternals 도구와 PowerShell의 표준 출력을 응답으로만 돌려주고 도구에 파일 출력 인자를 주지 않는다 [17].
`myirteam-core`는 저장소의 JSON 파일을 읽기만 한다 [18].
네 서버 모두 DB를 쓰지 않는다.
보관 기간, 용량, 대상을 정하는 설정이나 코드는 없다.
한 호출이 도구의 원래 출력과 그 가공본을 함께 남기는 경로는 없다.

`ir-collect`는 증거 사본을 `shutil.copy2`로 만들어 원본 파일의 읽기 전용 속성까지 복사한다 [7].
작업 폴더를 지우지 못하면 그 안의 파일이 호출 뒤에도 남는다 [7][13].
읽기 전용 파일이 들어 있는 증거 폴더를 `work_on_copy`가 참인 채로 분석하자 응답은 오류 없이 나갔고 그 파일의 사본과 `run_<난수>` 폴더가 호출 뒤에도 작업 폴더에 남았다 [10].

**한계.** `ir-collect-mcp/DESIGN.md`는 서버가 `IRCOLLECT_WORK_DIR`에만 쓰고 분석이 끝나면 정리하며 남기도록 설정할 수 있다고 적는다 [19].
`IR_Collect.exe`는 자기 폴더의 `logs`에도 쓰고 작업 폴더를 남기도록 고르는 설정은 코드에 없다 [3][5].
수집 ZIP과 `IR_Output_<ID>` 폴더를 실제로 남기는 과정은 `collect_triage_package`를 켜지 않아 실행하지 않았고 `IR_Collect.exe` 소스로만 확인했다 [6].

```python
def _prepare_folders(cfg: Config, folder_paths: list[str], work: Path, work_on_copy: bool) -> list[Path]:
    """Validate each folder against the allowlist and (optionally) copy to work dir."""
    if not folder_paths:
        raise ValueError("no folders provided.")
    targets: list[Path] = []
    for i, fp in enumerate(folder_paths):
        src = validate_evidence_dir(fp, cfg)  # raises ValueError
        if work_on_copy:
            dst = work / f"input_{i}_{src.name}"
            _safe_copy_evidence_tree(src, dst)
            targets.append(dst)
        else:
            targets.append(src)
    return targets
```
