# D03 파생물 무결성 검증

### D03.01 기준값 자동 계산

**구현.** 이 방식은 `ir-collect`의 `collect_triage_package`가 남기는 수집 ZIP에 적용된다 [1].
ZIP이 생기면 서버는 모델의 요청 없이 ZIP 내용 전체의 SHA-256을 계산해 응답의 `sha256`에 싣고 크기를 `size_bytes`에 싣는다 [1][2].
기준값은 ZIP 내용 전체의 SHA-256 하나다 [1].
서버는 이 값을 응답에만 싣고 파일이나 다른 저장소에 남기지 않는다 [1].
`IR_Collect.exe` 0.24.2도 ZIP을 묶은 뒤 그 SHA-256을 계산해 `<ID>.zip.sha256`에 16진수 문자열 하나로 쓴다 [3].
서버는 이 파일이 있는지만 `sha256_sidecar_present`로 알리고 그 값을 읽어 서버가 계산한 값과 대조하지 않는다 [1].
응답의 `next_step`은 해시 파일을 검증한 뒤 ZIP을 증거 폴더에 두고 `analyze_triage_zip`으로 분석하라고 안내한다 [1].

수집 ZIP을 기준값과 대조하는 경로는 증거를 다루는 도구에만 있다.
`artifact-forensic`의 `verify_sha256_manifest`는 이름 없이 해시만 적힌 `.sha256` 파일을 받으면 확장자를 뺀 같은 이름의 파일을 대상으로 SHA-256을 대조한다 [4].
이 도구는 manifest와 대상이 모두 `ARTIFACT_EVIDENCE_ROOTS` 아래에 있어야 대조하므로 수집 ZIP과 해시 파일을 증거 폴더로 옮겨야 쓸 수 있다 [4][5].
`analyze_triage_zip`은 분석 전후에 ZIP의 SHA-256을 계산해 둘이 다르면 경고를 싣지만 수집 때 계산한 값과는 대조하지 않는다 [6].

그 밖의 파생물에는 기준값을 계산하지 않는다.
증거 폴더를 복사하지 않고 분석할 때 분석 도구가 증거 폴더에 쓰는 CSV와 분석 도구의 로그 파일에는 서버가 해시를 계산하지 않는다.
`artifact-forensic`은 ZIP 항목 사본을 꺼낼 때와 분석한 뒤에 그 SHA-256을 계산해 대조하지만 이 사본은 분석 입력이고 응답 전에 지운다 [7].
Zimmerman 도구의 CSV 출력에는 이름과 크기만 응답에 싣고 해시를 계산하지 않는다 [8].

**한계.** 수집 ZIP의 해시 계산은 `collect_triage_package`를 켜지 않아 실행하지 않았고 서버 코드와 `IR_Collect.exe` 소스로만 확인했다 [1][3].

```python
def sha256_file(path: Path) -> str:
    h = hashlib.sha256()
    with open(path, "rb") as fh:
        for chunk in iter(lambda: fh.read(1024 * 1024), b""):
            h.update(chunk)
    return h.hexdigest()
```

def validate_artifact_file(path_str: str, cfg: Config) -> Path:
    if not path_str or not path_str.strip():
        raise ValueError("input_path is empty.")
    path = _resolve(path_str)
    if not cfg.evidence_roots:
        raise ValueError("no evidence roots configured (set ARTIFACT_EVIDENCE_ROOTS).")
