# T07 도구 부재 처리

### T07.01 실행 전 도구·참조 자료 가용성 검사

**구현.** 이 방식은 `artifact-forensic`의 분석 도구 실행 파일과 RECmd 배치 파일, YARA 룰, `ir-collect`의 `IR_Collect.exe`, `local-forensic`의 Sysinternals 도구와 PowerShell에 적용된다 [1][2][3][4][5][6].
`artifact-forensic`는 분석을 실행하기 전에 `executable_integrity`로 실행 파일이 있는지 보고 SHA-256을 계산한다 [1].
기대 해시가 없거나 계산한 해시와 다르면 실행하지 않는다 [1].
Hayabusa, capa, YARA·YARA-X, EZ Tools 5개가 모두 이 확인을 거친다 [1][7].
기대 해시는 `<도구>_EXPECTED_SHA256` 환경변수의 값이고 이 값이 없고 실행 파일이 저장소의 기본 경로에 있으면 코드에 적은 값이다 [8].
RECmd로 하이브를 읽을 때는 고른 배치 파일이 저장소의 `BatchExamples` 폴더에 있는지 보고 SHA-256을 코드에 적은 값과 대조한 뒤에 실행한다 [2].
YARA 도구는 `rules_path`가 `YARA_RULE_ROOTS` 아래에 있는지, `.yar`·`.yara` 파일이 1개 이상 64개 이하로 있는지 확인한 뒤에 실행한다 [3].

`ir-collect`의 분석 도구와 `collect_triage_package`는 실행 직전에 `ircollect_integrity_status`로 `IR_Collect.exe`가 있는지 보고 기대 해시가 있으면 SHA-256을 대조한다 [4].
기대 해시는 `IRCOLLECT_EXPECTED_SHA256`의 값이고 이 값이 없고 실행 파일이 기본 경로에 있으면 코드에 적은 값이다 [9].
`IRCOLLECT_EXE`로 다른 경로를 주고 `IRCOLLECT_EXPECTED_SHA256`을 주지 않으면 실행 파일이 있는지만 확인한다 [9][4].
`ingest_analysis_report`는 `IR_Collect.exe`를 실행하지 않으므로 이 확인을 거치지 않는다 [10].

`local-forensic`의 `run_sysinternals_tool`은 도구 이름이 정해 둔 4개 가운데 하나인지 보고 저장소의 `Sysinternals Suite` 폴더에 그 파일이 있는지 확인한 뒤에 실행한다 [5].
`run_powershell_json`은 `find_powershell`로 PowerShell 실행 파일을 `PATH`에서 찾고 찾지 못하면 실행하지 않는다 [6][11].
실행 확인에서 capa, Hayabusa, YARA·YARA-X, `IR_Collect.exe`, Sysinternals 도구가 없는 설정과 PowerShell을 찾지 못하게 바꾼 설정으로 부르면 모두 실행 없이 오류로 끝났다 [12].

**한계.** Hayabusa가 쓰는 룰 파일 `encoded_rules.yml`과 `rules_config_files.txt`는 `get_artifact_forensic_info`만 확인하고 분석 도구는 실행 전에 확인하지 않는다 [13][14].
서버는 EvtxECmd에 `--maps`를 넘기지 않고 EvtxECmd가 쓰는 `Maps` 폴더가 있는지도 실행 전에 확인하지 않는다 [15].
EvtxECmd 2026.5.0은 맵 폴더가 없으면 경고를 남기고 맵 없이 처리를 계속한다 [16].
`local-forensic`의 PowerShell 스크립트가 부르는 cmdlet이 있는지는 실행 전에 확인하지 않는다 [11].
`run_sysinternals_tool`은 파일이 있는지만 보고 실행할 수 있는 파일인지는 확인하지 않는다 [5].

### T07.02 대체 없는 실패 처리·도구 부재 알림

**구현.** 이 방식은 실행 전 확인을 거치는 모든 실행에 적용된다 [1][4][5][11].
`artifact-forensic`는 실행 파일이 없으면 `<도구> executable not found: <경로>`를, 기대 해시가 없으면 `<도구> exists but no expected SHA-256 is configured.`를 `error`에 싣고 확인 결과를 `integrity`에 함께 싣는다 [1][17].
YARA 도구는 쓸 수 있는 백엔드가 없으면 YARA-X와 YARA 각각의 오류를 적은 `No verified YARA backend is available.` 문구를 돌려준다 [18].
`ir-collect`는 `IR_Collect.exe not found at <경로>. Set IRCOLLECT_EXE.`처럼 경로를 정하는 환경변수를 적은 문구를 돌려준다 [4].
`local-forensic`은 Sysinternals 도구가 없으면 `Error: required tool not found: <경로>`를, PowerShell이 없으면 `PowerShell executable was not found.`를 돌려준다 [5][11].
`evidence_v1` 응답에서 이 문구를 결과 최상위에 그대로 돌려주는 도구는 `errors`의 `TOOL_ERROR` 항목과 `FAILED` 상태가 된다 [19].
PowerShell 결과를 `result`나 `host` 안에 담는 `local-forensic`의 `get_forensic_context`·`get_file_metadata`·`collect_event_log_events`·`list_wmi_subscriptions`·`collect_defender_context`·`list_local_users_and_admins`·`collect_network_context`와 채널마다 결과를 담는 `collect_ir_event_bundle`은 같은 문구가 있어도 `DEGRADED` 상태가 된다 [19][20].
실행 확인에서 Sysinternals 도구가 없을 때 `collect_autoruns`와 PowerShell이 없을 때 `list_services`의 응답 상태는 `FAILED`였고 `artifact-forensic`와 `ir-collect`는 위 문구를 `error`에 실었다 [12].

**한계.** `run_sysinternals_tool`은 실행 파일을 시작하지 못한 `OSError`를 `Error executing <도구> (Path: <경로>): <문구>` 문구로 돌려준다 [5].
`evidence_v1`은 `Error:`나 `File not found:`로 시작하는 글만 실패로 읽으므로 이 문구가 담긴 응답의 상태는 `SUCCESS`가 된다 [19][21].
실행 확인에서 실행 파일이 아닌 파일을 `autorunsc.exe` 자리에 두고 실행을 `OSError`로 끝나게 바꾸면 `collect_autoruns`의 응답 상태는 `SUCCESS`였고 `errors`가 비어 있었다 [12].

### T07.03 알림 없는 대체 실행

**구현.** 이 방식은 `artifact-forensic`의 YARA 백엔드 선택과 `local-forensic`의 PowerShell 선택에 적용된다 [18][6].
`scan_file_with_yara`와 `scan_archive_member_with_yara`는 `backend`가 기본값 `auto`이면 YARA-X를 먼저 확인하고 YARA-X가 없거나 해시가 맞지 않으면 YARA를 쓴다 [18].
응답의 `backend`와 `provenance.tool_name`에는 실제로 쓴 백엔드가 실리지만 YARA-X를 쓰지 못한 사실과 그 이유는 실리지 않는다 [22].
실행 확인에서 YARA-X가 없고 시험용 YARA만 있을 때 `auto`로 부르면 `backend`가 `yara`였고 `warnings`가 비어 있었다 [12].
두 백엔드의 결과 모양은 다르다.
YARA-X 결과는 일치한 룰마다 `identifier`, `namespace`, `tags`, `metadata`를 싣는다 [22].
YARA 결과는 출력 한 줄을 `raw_match_line` 하나로 싣고 `provenance.output_format`을 `bounded_text`로 둔다 [22].
도구 설명은 검증된 백엔드로 검사한다고만 적고 이 차례와 결과 모양의 차이를 적지 않는다 [23].

`local-forensic`의 `find_powershell`은 `pwsh.exe`가 없으면 `powershell.exe`를 쓴다 [6].
PowerShell로 읽는 도구의 응답에는 어느 PowerShell로 실행했는지 실리지 않는다 [11].

### T07.04 실행 환경별 경로 분기

**구현.** 이 방식은 `local-forensic`의 PowerShell 선택과 `artifact-forensic`의 YARA 백엔드 선택에 적용된다 [6][18].
`find_powershell`은 `PATH`에서 `pwsh.exe`, `powershell.exe`, `pwsh`, `powershell` 차례로 찾아 처음 찾은 실행 파일을 쓴다 [6].
YARA 백엔드는 `backend`가 `auto`이면 YARA-X, YARA 차례로 확인을 통과한 첫 실행 파일을 쓴다 [18].
`backend`에 `yara`나 `yara_x`를 주면 그 백엔드만 확인하고 확인에 실패하면 다른 백엔드로 바꾸지 않는다 [18].
실행 확인에서 YARA-X가 없을 때 `backend`를 `yara_x`로 주면 YARA를 쓰지 않고 `YARA-X executable not found` 오류가 왔다 [12].

다른 도구는 실행 파일을 찾는 경로가 하나다.
`artifact-forensic`와 `ir-collect`는 도구마다 환경변수의 경로를 쓰고 환경변수가 없으면 저장소 `External Tools` 아래의 정해 둔 경로를 쓴다 [8][9].
`local-forensic`의 Sysinternals 도구는 저장소의 `Sysinternals Suite` 폴더에서만 찾는다 [5].

### T07.08 일부 제외 후 계속 실행

**구현.** 이 방식은 `local-forensic`의 `collect_defender_context`, `list_local_users_and_admins`, `collect_network_context`, `get_forensic_context`, `get_file_metadata`, `list_scheduled_tasks`, `list_wmi_subscriptions`에 적용된다 [24][25][26][27][28].
앞의 세 도구의 PowerShell 스크립트는 cmdlet마다 따로 실행하고 실패하면 `<cmdlet>: <문구>`를 `errors`에 더한 뒤 나머지 cmdlet을 계속 실행한다 [24].
cmdlet이 없어 실패한 경우와 다른 이유로 실패한 경우를 나누지 않는다 [24].
`evidence_v1` 응답은 결과 안의 `errors`가 비어 있지 않으면 앞 10개를 이은 문구를 `limitations`의 `NESTED_TOOL_LIMITATION` 항목으로 싣고 상태를 `DEGRADED`로 둔다 [19].
실행 확인에서 `Get-LocalGroupMember`만 실패한 결과를 돌려주는 PowerShell 대체로 `list_local_users_and_admins`를 부르면 상태가 `DEGRADED`였고 실패 문구가 `limitations`에 실렸다 [29].

**한계.** 다음 경로는 일부를 빼고 계속하면서 뺀 사실을 응답에 싣지 않는다.

- `get_forensic_context`는 버전을 읽는 PowerShell 실행이 실패해도 `file_version`과 `product_version`을 `null`로 두고 실패를 싣지 않는다 [25].
- `get_file_metadata`는 대체 데이터 스트림을 읽지 못하면 `alternate_data_streams`를 빈 목록으로 둔다 [26].
- `list_scheduled_tasks`는 작업 하나의 `Get-ScheduledTaskInfo`가 실패하면 그 작업의 마지막 실행 시각, 다음 실행 시각, 마지막 결과를 `null`로 둔다 [27].
- `list_wmi_subscriptions`는 이벤트 필터 조회만 실패로 다루고 소비자와 연결 조회는 `-ErrorAction SilentlyContinue`로 실행해 실패하면 빈 목록으로 둔다 [28].

실행 확인에서 버전 조회만 실패하게 바꾼 PowerShell 대체로 `get_forensic_context`를 부르면 상태는 `SUCCESS`였고 `errors`와 `limitations`가 비어 있었다 [29].

### T07.09 별도 점검 도구로 가용성 알림

**구현.** 이 방식은 `artifact-forensic`의 `get_artifact_forensic_info`, `local-forensic`의 `get_external_tool_inventory`·`get_forensic_context`, `ir-collect`의 `get_ircollect_info`에 적용된다 [30][31][25][32].
`get_artifact_forensic_info`는 분석 도구마다 `available`과 확인 결과를 싣고 없는 필수 도구를 `Required analyzer unavailable: <도구>.` 경고로 적어 상태를 `DEGRADED`로 둔다 [13].
같은 응답은 Hayabusa의 룰 파일 `encoded_rules.yml`과 `rules_config_files.txt`가 있는지도 따로 싣는다 [13].
`get_external_tool_inventory`는 manifest의 도구마다 `exists`와 기대 해시와 대조한 결과를 싣는다 [33].
`get_forensic_context`는 Sysinternals 도구마다 `exists`를 싣는다 [25].
`get_ircollect_info`는 `IR_Collect.exe`가 없으면 `error`를 싣는다 [34].
네 도구는 확인 결과를 응답으로만 돌려주고 서버에 두지 않는다 [30][32][31][25].
분석 도구는 이 결과를 읽지 않고 실행할 때마다 실행 파일을 직접 확인하므로 이 결과가 분석 실행을 막지 않는다 [1][4][5].
서버는 도구를 내려받거나 설치하지 않고 `get_external_tool_inventory`의 응답도 그 사실을 적는다 [35].

```python
def executable_integrity(
    path: Path,
    expected_sha256: str | None,
    label: str,
    *,
    require_pin: bool = False,
) -> dict[str, Any]:
    if not path.is_file():
        return {
            "status": "FAILED",
            "error": f"{label} executable not found: {path}",
            "path": str(path),
            "verified": False,
        }
    actual = sha256_file(path)
    if require_pin and not expected_sha256:
        return {
            "status": "FAILED",
            "error": f"{label} exists but no expected SHA-256 is configured.",
            "path": str(path),
            "sha256": actual,
            "expected_sha256": None,
            "verified": False,
        }
    if expected_sha256 and actual.lower() != expected_sha256.lower():
        return {
            "status": "FAILED",
            "error": f"{label} SHA-256 does not match the configured value.",
            "path": str(path),
            "sha256": actual,
            "expected_sha256": expected_sha256,
            "verified": False,
        }
    return {
        "status": "SUCCESS",
        "path": str(path),
        "sha256": actual,
        "expected_sha256": expected_sha256,
        "verified": bool(expected_sha256),
    }
```

```python
def validate_rule_files(path_str: str, cfg: Config) -> list[Path]:
    if not path_str or not path_str.strip():
        raise ValueError("rules_path is empty.")
    path = _resolve(path_str)
    if not cfg.rule_roots:
        raise ValueError("no YARA rule roots configured (set YARA_RULE_ROOTS).")
    if not is_under_roots(path, cfg.rule_roots):
        raise ValueError(f"rules path is outside the configured YARA rule roots: {path}")
    if path.is_symlink():
        raise ValueError(f"symbolic-link rule paths are not accepted: {path}")
    if path.is_file():
        candidates = [path]
    elif path.is_dir():
        candidates = sorted(
            item.resolve()
            for item in path.rglob("*")
            if item.is_file() and not item.is_symlink() and item.suffix.lower() in {".yar", ".yara"}
        )
    else:
        raise ValueError(f"rules path does not exist: {path}")
    candidates = [item for item in candidates if item.suffix.lower() in {".yar", ".yara"}]
    if not candidates:
        raise ValueError(f"no .yar or .yara source files found: {path}")
    if len(candidates) > MAX_RULE_FILES:
        raise ValueError(f"rules path contains {len(candidates)} files; maximum is {MAX_RULE_FILES}.")
    if any(not is_under_roots(item, cfg.rule_roots) for item in candidates):
        raise ValueError("one or more resolved rule files escaped the configured rule roots.")
    return candidates
```

```python
def ircollect_integrity_status(cfg: Config) -> dict[str, Any]:
    """Verify the analysis executable immediately before an engine operation."""
    if not cfg.exe_path.is_file():
        return {
            "status": "FAILED",
            "error": f"IR_Collect.exe not found at {cfg.exe_path}. Set IRCOLLECT_EXE.",
        }
    try:
        digest = sha256_file(cfg.exe_path)
    except OSError as exc:
        return {"status": "FAILED", "error": f"could not hash IR_Collect.exe: {exc}"}
    if cfg.expected_sha256 and digest.lower() != cfg.expected_sha256.lower():
        return {
            "status": "FAILED",
            "error": "IR_Collect.exe SHA-256 does not match IRCOLLECT_EXPECTED_SHA256.",
            "sha256": digest,
            "expected_sha256": cfg.expected_sha256,
            "verified": False,
        }
    return {
        "status": "SUCCESS",
        "sha256": digest,
        "expected_sha256": cfg.expected_sha256,
        "verified": True if cfg.expected_sha256 else None,
    }
```
