# T01 입력 검증

### T01.01 인자 구조·값 검사

**구현.** 이 방식은 MCP SDK가 네 서버의 모든 도구에 하는 자료형 검사와 네 서버의 도구 함수가 하는 값 검사에 적용된다 [1][2][3][4].
MCP Python SDK 1.28.1의 `FastMCP`는 도구 함수의 매개변수 자료형으로 만든 pydantic 모델로 인자를 검사한 뒤 함수를 부른다 [1].
자료형이 맞지 않으면 함수를 부르지 않고 `Error executing tool`로 시작하는 `isError` 응답을 돌려준다 [1].
`expand_investigation_graph`의 `max_depth`와 `analyze_evtx_with_hayabusa`의 `max_records`에 정수로 읽을 수 없는 문자열을 주자 이 오류가 돌아왔다 [5][6].
서버 코드의 값 검사는 그 뒤에 이루어지고 어긋나면 도구 함수가 `error`를 담은 `dict`나 `Error:`로 시작하는 글을 돌려준다 [2][3][4].

`myirteam-core`의 `resolve_investigation_intent`는 `input_kind`를 소문자로 바꾸고 `-`를 `_`로 바꾼 뒤 허용 값 목록과 대조한다 [7].
허용 값 목록은 호출마다 읽는 `agent-manifest.json`의 경로 규칙들이 적은 `input_kinds`에 `auto`를 더한 것이다 [7].
목록에 없으면 `INVALID_INPUT_KIND` 오류를 돌려준다 [7].
`input_path`·`member_path`·`artifact_type`은 빈 문자열인지만 보고 경로를 열거나 있는지 확인하지 않는다 [8].
없는 경로를 `input_path`로 주자 경로 규칙이 고른 워크플로가 그대로 돌아왔다 [9].
`get_workflow`는 정규식 검사를 통과한 `workflow_id`를 호출마다 읽는 `agent-manifest.json`의 `workflows`에 적힌 ID 목록과 대조한다 [10].
목록에 없으면 `UNKNOWN_WORKFLOW` 오류와 함께 목록의 ID를 돌려준다 [10].
목록에 있으면 `workflows/<workflow_id>.json`을 읽고 문서의 `id`가 요청한 ID와 다르면 `WORKFLOW_ID_MISMATCH`로 거부한다 [10].
목록에 없는 ID를 주자 워크플로 6개의 ID와 함께 `UNKNOWN_WORKFLOW`가 돌아왔다 [9].

`local-forensic`의 도구 함수는 `build_process_tree_snapshot`을 빼면 PowerShell이나 Sysinternals 도구를 실행하기 전에 인자를 검사한다 [2].
`collect_autoruns`의 `category`는 `*`이거나 서버 코드가 정한 Autoruns 분류 글자 17개의 조합이어야 하고 겹친 글자는 하나로 줄인다 [11].
`collect_event_log_events`의 `channel`은 서버 코드의 이름 8개 가운데 하나여야 하고 서버는 그 이름을 정해 둔 이벤트 로그 이름으로 바꾼다 [2].
`event_ids`는 0에서 65535 사이의 정수만 받고 겹친 값을 뺀 뒤 64개까지 받는다 [12].
시각 인자는 ISO-8601 꼴이면서 시간대가 있어야 하고 서버가 UTC로 바꾼다 [12].
시작 시각이 끝 시각보다 늦거나 같으면 거부한다 [2].
`max_events`는 1에서 1000 사이여야 한다 [12].
`collect_ir_event_bundle`도 시각 인자와 채널별 건수 `max_events_per_channel`을 같은 함수로 검사한다 [13].
`list_scheduled_tasks`·`collect_defender_context`·`collect_network_context`의 건수 인자는 각각 1에서 500, 1에서 500, 1에서 1000 사이여야 한다 [14].
`list_services`·`list_scheduled_tasks`의 이름 목록은 항목마다 260자 이하이고 줄바꿈과 NUL이 없어야 하며 64개까지 받는다 [15].
`list_running_processes`·`build_process_tree_snapshot`의 프로세스 식별자 목록은 개수만 64개로 제한하고 값의 꼴은 보지 않는다 [15].
`list_network_connections`·`list_loaded_dlls`의 `process_identifier`는 영문자, 숫자, `_`, `.`, `-`로 된 260자 이하의 값이어야 한다 [16].
`list_open_handles`의 `target`은 520자 이하이고 줄바꿈과 NUL이 없어야 한다 [17].
`check_file_signatures_batch`는 겹친 경로를 뺀 뒤 32개까지 받는다 [18].
검사에 어긋난 인자를 주자 PowerShell과 Sysinternals 실행 함수를 부르지 않고 오류가 돌아왔다 [19].
`build_process_tree_snapshot`은 PowerShell로 프로세스 목록을 읽은 뒤에 식별자 개수를 검사한다 [20].
식별자 65개를 주자 PowerShell 실행 함수의 대체가 한 번 불린 뒤 `At most 64 process identifiers are allowed.` 오류가 돌아왔다 [21].

`ir-collect`의 `expand_investigation_graph`는 `seed_type`·`seed_value`가 비어 있지 않은지와 `max_depth`가 1에서 4 사이의 정수인지 확인한다 [3].
`seed_type`에는 허용 값 목록이 없고 서버는 받은 값을 `IR_Collect.exe`의 인자로 넘긴다 [3].
`IR_Collect.exe` 0.24.2도 seed 종류를 목록과 대조하지 않는다 [22].
목록에 없는 글자를 `seed_type`으로 주자 서버가 그 값을 시험용 실행 파일의 인자로 넘겼다 [5].
`correlate_hosts`는 폴더가 2개 이상인지 확인한다 [23].
`correlate_hosts`와 `expand_investigation_graph`는 폴더 수의 상한을 두지 않는다 [3][23].
`analyze_triage_zip`은 확장자가 `.zip`이 아니면 거부한다 [24].
`ingest_analysis_report`는 읽은 JSON이 객체가 아니거나 `export_schema`가 서버가 아는 3가지가 아니면 거부한다 [25].

`artifact-forensic`의 도구 함수는 건수 인자를 1부터 도구마다 정한 상한까지로 제한한다 [4].
상한은 `max_records` 1000, `max_strings` 500, `max_files` 5000, `max_members` 10000, `max_entries` 1000, `max_capabilities` 500, `max_matches` 1000이다 [4].
`min_level`은 Hayabusa 규칙 수준 이름 5개 가운데 하나여야 한다 [26].
`parse_windows_artifact_with_eztools`의 `artifact_type`은 `evtx`·`prefetch`·`amcache`·`registry`·`ntfs` 가운데 하나여야 한다 [27].
`evtx`는 `.evtx` 파일, `prefetch`는 `.pf` 파일, `amcache`는 이름이 `Amcache.hve`인 파일만 받는다 [28].
`registry`와 `ntfs`는 파일 이름이나 확장자를 보지 않는다 [28].
`profile`은 `artifact_type`이 `registry`일 때만 RECmd 프로필 이름 5개와 대조한다 [29].
`scan_file_with_yara`의 `backend`는 `auto`·`yara`·`yara_x`(`yarax`) 가운데 하나여야 한다 [30].
`parse_archive_member_with_eztools`는 `companion_member_paths`를 `registry`일 때만 받는다 [31].
이 목록은 2개까지이고 고른 하이브와 같은 폴더의 `.LOG1`·`.LOG2`만 받는다 [31].
입력 파일과 ZIP의 크기가 사용자가 환경변수로 정한 상한(`ARTIFACT_MAX_FILE_BYTES` 등)을 넘으면 거부한다 [32].
어긋난 인자를 주자 분석 도구를 실행하지 않고 `error`를 담은 결과가 돌아왔다 [6].

세 증거 서버의 `response_format`은 도구가 분석을 마친 뒤 응답을 만들 때 검사한다 [33].
`legacy`·`evidence_v1`이 아닌 값이면 분석 결과를 버리고 `Unsupported response_format` 오류를 돌려준다 [33].
허용하지 않는 `response_format`을 준 `collect_autoruns`와 `analyze_artifact_folder` 호출은 `autorunsc.exe` 실행 함수와 시험용 실행 파일을 먼저 실행한 뒤 이 오류를 돌려주었다 [19][5].

### T01.02 입력 존재·읽기 가능 검사

**구현.** 이 방식은 `local-forensic`의 서명 확인 도구와 `ir-collect`·`artifact-forensic`의 경로를 받는 도구에 적용된다 [34][35][36].
`local-forensic`의 `check_file_signatures`·`check_file_signatures_batch`는 경로가 파일이 아니면 `sigcheck.exe`를 실행하지 않고 `File not found`로 시작하는 글을 돌려준다 [34].
`get_file_metadata`는 서버 코드에서 경로를 확인하지 않고 정해 둔 PowerShell 스크립트 안에서 `Test-Path`로 확인한다 [37].
그래서 없는 경로를 주어도 PowerShell을 실행하고 결과의 `exists`가 거짓으로 돌아온다 [37].
없는 경로로 부른 `get_file_metadata`는 PowerShell 실행 함수를 불렀다 [19].

`ir-collect`는 폴더 인자가 폴더가 아니거나 보고서·ZIP 인자가 파일이 아니면 `IR_Collect.exe`를 실행하지 않고 거부한다 [35].
`analyze_artifact_folder`·`analyze_triage_zip`·`correlate_hosts`·`expand_investigation_graph`는 이 경로 확인보다 `IR_Collect.exe`의 존재와 해시 확인을 먼저 한다 [38][39].
그래서 실행 파일이 없으면 경로를 확인하기 전에 그 사실을 오류로 돌려준다 [38].

`artifact-forensic`의 파일 인자는 실제 경로로 변환한 뒤 일반 파일인지 확인하므로 허용 폴더 안을 가리키는 링크는 그 대상 파일로 받는다 [36].
`analyze_evtx_with_hayabusa`의 경로는 `.evtx` 파일이거나 하위에 `.evtx` 파일이 하나라도 있는 폴더여야 한다 [40].
`scan_file_with_yara`의 `rules_path`에는 `.yar`·`.yara` 파일이 1개 이상 64개 이하 있어야 한다 [41].
ZIP 항목 도구는 `member_path`와 이름이 같은 항목이 ZIP에 하나만 있어야 하고 그 항목이 폴더, 링크, 암호화 항목이 아니어야 한다 [42].
없는 항목 이름을 주자 `archive member was not found` 오류가 돌아왔다 [6].
`verify_sha256_manifest`는 목록 파일이 적은 대상이 없으면 그 항목을 `MISSING`으로 적고 다음 항목을 확인한다 [43].
서버는 읽기 권한을 미리 확인하지 않는다.

### T01.03 실제 경로로 변환해 허용 폴더 대조

**구현.** 이 방식은 `ir-collect`의 폴더·파일 인자와 `artifact-forensic`의 증거·규칙 경로 인자에 적용된다 [44][45].
두 서버는 받은 경로의 `~`와 환경변수를 값으로 바꾸고 상대 경로에 프로젝트 폴더를 붙인 뒤 `Path.resolve()`로 `..`와 링크를 해석한다 [44][45].
변환한 경로가 사용자가 환경변수로 정한 허용 폴더 아래에 있는지 대조하고 밖이면 거부한다 [44][45].
허용 폴더는 `IRCOLLECT_EVIDENCE_ROOTS`, `ARTIFACT_EVIDENCE_ROOTS`, `YARA_RULE_ROOTS`이고 서버가 시작할 때 같은 방식으로 실제 경로로 변환한다 [46].
허용 폴더를 정하지 않으면 모든 경로를 거부한다 [35][36].
대조를 통과한 뒤의 복사와 분석에는 변환한 경로를 쓴다 [47].
허용 폴더 밖의 파일, 상위 폴더 표기로 밖을 가리키는 경로, 허용 폴더 안의 junction을 거쳐 밖을 가리키는 경로를 주자 모두 변환한 경로와 함께 거부되었다 [5][6].

`ir-collect`의 `analyze_artifact_folder`·`correlate_hosts`·`expand_investigation_graph`는 기본값 `work_on_copy=True`에서 폴더를 작업 폴더로 복사한다 [48].
복사하면서 하위의 링크나 junction을 만나거나 받은 폴더 밖으로 변환되는 항목을 만나면 복사를 멈추고 거부한다 [48].
junction이 있는 폴더를 주자 `evidence tree contains a symbolic link or junction` 오류가 돌아왔다 [5].

`artifact-forensic`의 `scan_file_with_yara`는 규칙 폴더 안에서 찾은 규칙 파일마다 허용 폴더 안인지 다시 대조한다 [41].
`verify_sha256_manifest`는 목록 파일이 적은 대상 경로마다 같은 대조를 하고 밖이면 그 항목을 `INVALID`로 적는다 [43].
`inventory_evidence_path`는 하위 폴더를 훑을 때 링크와 junction을 건너뛰고 허용 폴더 밖으로 변환되는 항목도 건너뛴다 [49].
ZIP 항목 도구는 고른 항목을 새 작업 폴더에 복사한 뒤 그 폴더 하나만 허용 폴더로 둔 설정으로 분석 함수를 부른다 [50].

`local-forensic`은 파일 경로를 실제 경로로 변환하지만 허용 폴더를 두지 않고 서버를 실행한 호스트의 어느 경로든 읽는다 [51].
`myirteam-core`는 경로를 열지 않는다 [8].

**한계.** `work_on_copy=False`로 부르면 `ir-collect`는 폴더 경로만 대조하고 폴더 안의 링크를 확인하지 않은 채 원래 폴더를 `IR_Collect.exe`에 넘긴다 [47].
junction이 있는 폴더를 `work_on_copy=False`로 주자 서버가 그 폴더를 시험용 실행 파일의 인자로 넘겼다 [5].
`IR_Collect.exe` 0.24.2는 받은 폴더를 하위 폴더까지 열거하고 파일마다 전체 경로 문자열이 그 폴더 아래인지만 본다 [52].
이 열거가 junction이나 링크를 따라가는지는 확인하지 못했다.

`analyze_evtx_with_hayabusa`에 폴더를 주면 서버는 그 폴더 경로만 대조하고 하위 항목을 보지 않은 채 Hayabusa에 `-d`로 넘긴다 [40][53].
Hayabusa 3.10.0은 `-d`로 받은 폴더를 재귀로 열거하고 하위 항목이 폴더인지를 링크를 따라가 판단한다 [54].
그래서 하위의 링크나 junction이 가리키는 허용 폴더 밖의 폴더도 열거 대상이 된다 [54].
junction이 있는 폴더를 주자 서버가 그 폴더를 `-d` 인자로 넘겼다 [6].

`inventory_evidence_path` 처리기는 경로를 거부한 뒤에도 응답의 `target.type`을 정하려고 받은 경로가 파일인지 확인한다 [55].
허용 폴더 밖의 있는 파일과 없는 파일을 주자 둘 다 거부되었고 `target.type`은 각각 `artifact_file`과 `artifact_folder`였다 [6].

### T01.04 문자열 경로 검사

**구현.** 이 방식은 `artifact-forensic`의 ZIP 항목 이름 인자, `ir-collect`의 `evidence_id`, `myirteam-core`의 `workflow_id`에 적용된다 [56][57][58].
`artifact-forensic`의 `normalize_archive_member`는 `member_path`의 `\`를 `/`로 바꾼 뒤 파일시스템을 보지 않고 문자열로만 검사한다 [56].
빈 값, NUL, 2000자를 넘는 값, `/`나 드라이브 문자로 시작하는 절대 경로, 빈 단계나 `.`·`..` 단계가 있는 값을 거부한다 [56].
Windows 파일 이름에 쓸 수 없는 문자, 공백이나 `.`으로 끝나는 단계, `CON`·`NUL`·`COM1` 같은 예약 이름도 거부한다 [56].
`companion_member_paths`의 항목도 같은 함수로 검사한다 [31].
검사를 통과한 이름은 ZIP 항목 이름과 글자 그대로 대조한다 [42].
상위 폴더 단계가 있는 `member_path`를 주자 `unsafe traversal syntax` 오류로 거부되었다 [6].

`ir-collect`의 `collect_triage_package`는 ZIP 파일 이름이 되는 `evidence_id`가 영문자나 숫자로 시작하는 64자 이하의 영문자, 숫자, `.`, `_`, `-`인지 정규식으로 확인한다 [57].
이 도구는 기본으로 꺼져 있어 이 검사는 실행해 보지 않았다.

`myirteam-core`의 `get_workflow`는 `workflow_id`를 소문자로 바꾸고 소문자로 시작하는 64자 이하의 소문자, 숫자, `-`인지 정규식으로 확인한다 [58].
이 값은 `workflows/<workflow_id>.json` 경로의 파일 이름이 된다 [10].
경로 구분자를 넣은 `workflow_id`를 주자 `INVALID_WORKFLOW_ID` 오류가 돌아왔다 [9].

`local-forensic`의 `list_open_handles`는 경로 일부도 받는 `target`에 길이와 줄바꿈·NUL만 검사한다 [17].

def normalize_iso_time(value: str, field_name: str) -> str:
    normalized = value.strip()
    if not normalized:
        return ""
    candidate = normalized.replace("Z", "+00:00")
    try:
        parsed = datetime.fromisoformat(candidate)
    except ValueError as exc:
        raise ValueError(f"{field_name} must be ISO-8601.") from exc
    if parsed.tzinfo is None:
        raise ValueError(f"{field_name} must include a timezone offset or Z.")
    return parsed.astimezone(timezone.utc).isoformat()

def _resolve(value: str | Path, base_dir: Path = PROJECT_ROOT) -> Path:
    """Resolve configured paths from the project root, not the caller's CWD.

def _safe_copy_evidence_tree(source: Path, destination: Path) -> dict[str, int]:
    """Copy a directory without following symlinks or Windows junctions."""
    source = source.resolve()
    destination = destination.resolve()
    if _path_is_link_or_junction(source):
        raise ValueError(f"evidence folder cannot be a symbolic link or junction: {source}")
    if destination == source or destination.is_relative_to(source):
        raise ValueError("private work destination must not be inside the evidence source tree.")
    destination.mkdir(parents=True, exist_ok=False)
    copied_files = 0
    copied_bytes = 0
    for current, directory_names, file_names in os.walk(source, followlinks=False):
        current_path = Path(current)
        relative = current_path.relative_to(source)
        destination_current = destination / relative
        destination_current.mkdir(parents=True, exist_ok=True)
        for directory_name in directory_names:
            directory_path = current_path / directory_name
            if _path_is_link_or_junction(directory_path):
                raise ValueError(
                    f"evidence tree contains a symbolic link or junction: {directory_path}"
                )
            if not directory_path.resolve().is_relative_to(source):
                raise ValueError(f"evidence directory resolves outside its source root: {directory_path}")
        for file_name in file_names:
            source_file = current_path / file_name
            if _path_is_link_or_junction(source_file):
                raise ValueError(f"evidence tree contains a symbolic link: {source_file}")
            if not source_file.resolve().is_relative_to(source) or not source_file.is_file():
                raise ValueError(f"evidence file is unsafe or not regular: {source_file}")

def normalize_archive_member(member_path: str) -> str:
    """Return a canonical relative ZIP member path or reject unsafe syntax."""
    candidate = str(member_path or "").replace("\\", "/")
    if not candidate or not candidate.strip() or "\x00" in candidate:
        raise ValueError("member_path is empty or contains a NUL byte.")
    if len(candidate) > MAX_TEXT_FIELD:
        raise ValueError(f"member_path exceeds {MAX_TEXT_FIELD} characters.")
    if candidate.startswith("/") or re.match(r"^[A-Za-z]:", candidate):
        raise ValueError(f"member_path must be relative: {member_path!r}")
    raw_parts = candidate.split("/")
    if any(part in {"", ".", ".."} for part in raw_parts):
        raise ValueError(f"member_path contains unsafe traversal syntax: {member_path!r}")
    windows_reserved = {"CON", "PRN", "AUX", "NUL"} | {
        f"{prefix}{number}"
        for prefix in ("COM", "LPT")
        for number in range(1, 10)
    }
    for part in raw_parts:
        if any(character in part for character in '<>:"|?*') or part.endswith((" ", ".")):
            raise ValueError(f"member_path contains an unsafe Windows name: {member_path!r}")
        if part.split(".", 1)[0].upper() in windows_reserved:
            raise ValueError(f"member_path contains a reserved Windows name: {member_path!r}")
    pure = PurePosixPath(candidate)
    normalized = pure.as_posix()
    if not pure.name:
        raise ValueError(f"member_path does not name a file: {member_path!r}")
    return normalized
