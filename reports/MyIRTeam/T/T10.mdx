# T10 도구 명세 구성

### T10.01 처리 함수에서 명세 생성

**구현.** 이 방식은 네 서버가 등록하는 도구 45개 모두에 적용된다 [1].
네 서버는 도구 함수마다 `@mcp.tool()`만 붙이고 이름, 설명, 입력 schema를 따로 주지 않는다 [1].
MCP Python SDK 1.28.1의 FastMCP는 함수 이름을 도구 이름으로, docstring을 설명으로 쓰고 함수 서명에서 입력 schema를 만든다 [2].
실행 확인에서 도구 수는 `myirteam-core` 5개, `local-forensic` 19개, `ir-collect` 7개, `artifact-forensic` 14개였고 설명이 빈 도구는 없었다 [3].

입력 schema는 인자마다 `title`, 자료형, 기본값만 싣는다 [3].
정해 둔 값만 받는 인자도 schema에는 `enum` 없이 문자열로 실린다 [3].
`resolve_investigation_intent`의 `input_kind`, `collect_event_log_events`의 `channel`, `parse_windows_artifact_with_eztools`의 `artifact_type`·`profile`, `analyze_evtx_with_hayabusa`의 `min_level`, `scan_file_with_yara`의 `backend`가 그 인자다 [4].
`input_kind`, `artifact_type`, `profile`의 허용 값은 도구 설명에 적혀 있고 `channel`, `min_level`, `backend`의 허용 값은 처리 코드에만 있다 [4][3].
`collect_autoruns`의 `category`는 설명에 `all or selected categories`라고만 적혀 있고 처리 코드는 `*`나 `bcdeghiklmnoprstw` 글자의 조합만 받는다 [5].

세 증거 서버의 도구는 모두 `response_format`을 기본값 `evidence_v1`인 문자열로 받는다 [3].
처리 코드는 `legacy`와 `evidence_v1`만 받고 다른 값이면 허용 값 목록을 담은 `error`를 돌려준다 [6].
`local-forensic`과 `ir-collect`의 도구 설명은 `evidence_v1`을 주면 공통 응답 형식이 된다고 적고 `legacy`는 적지 않는다 [3].
`artifact-forensic`의 도구 설명은 `response_format`을 적지 않는다 [3].
실행 확인에서 `ingest_analysis_report`에 `response_format` `xml`을 주자 `isError`가 거짓인 `Unsupported response_format: 'xml'.` 응답이 왔다 [3].

`myirteam-core`의 도구 5개는 반환 자료형이 `dict[str, Any]`여서 SDK가 `additionalProperties`가 참인 객체 출력 schema를 싣는다 [7][8].
세 증거 서버의 도구는 반환 자료형이 `Any`여서 출력 schema가 없다 [3].
도구 annotation은 없고 초기화 응답의 `tools.listChanged`는 거짓이다 [3].
SDK가 리소스·프롬프트 처리기를 두므로 초기화 응답은 두 기능을 알리지만 서버가 등록한 리소스와 프롬프트는 없다 [9][8].
네 서버는 `FastMCP`를 만들 때 서버 지침 `instructions`를 준다 [10].
`myirteam-core`의 지침은 조사마다 `resolve_investigation_intent`를 먼저 부르라고 적고 나머지 세 서버의 지침은 `myirteam-core`가 워크플로를 고른 뒤에 쓰고 셸이나 CLI로 우회하지 말라고 적는다 [10].
`local-forensic`은 SDK에 서버 이름 `ForensicToolbox`를 주므로 초기화 응답의 `serverInfo.name`은 실행기 ID `local-forensic`과 다르다 [10][3].
`get_project_capabilities`가 돌려주는 `agent-manifest.json`은 서버마다 도구 이름을 적고 그 이름은 등록된 도구와 같다 [11][3].
환경변수는 도구 목록과 설명을 바꾸지 않는다.
`collect_triage_package`는 `IRCOLLECT_ALLOW_COLLECTION`이 꺼져 있어도 목록에 오른다 [3].

**한계.** 다음 도구는 설명이 알리는 것과 처리 코드의 동작이 다르다.

`build_process_tree_snapshot`의 설명은 같은 시점의 프로세스 목록과 부모 정보를 돌려준다고 적는다 [12].
처리 코드는 `list_running_processes`의 `evidence_v1` 응답 최상위에서 `processes`를 찾으므로 프로세스 0개를 돌려준다 [12][13].
실행 확인에서 PowerShell 대체가 프로세스 2개를 돌려줄 때 이 도구의 `process_count`는 0이었다 [14].

`list_open_handles`의 설명은 `target`에 PID, 프로세스 이름, 경로 조각을 받는다고 적는다 [15].
처리 코드는 숫자만 `-p`로 넘기고 프로세스 이름을 포함한 다른 값은 `handle.exe`의 이름 인자로 넘긴다 [15].
Handle 문서는 이름 인자를 열린 객체 이름에서 찾을 조각으로, `-p`를 대상 프로세스로 적는다 [16].
그래서 프로세스 이름을 주면 그 프로세스의 핸들이 아니라 이름에 그 글자가 들어 있는 객체의 핸들을 찾는다 [15][16].

`ingest_analysis_report`의 설명은 보고서의 schema를 찾아 검사하고 크기를 제한한다고 적는다 [17].
처리 코드는 보고서 파일 크기를 확인하지 않고 전체를 읽으며 `export_schema` 값만 확인한다 [17][18].
결과 목록의 개수는 정리 함수가 자른다 [19].
`scan_file_with_yara`의 설명은 검증된 백엔드로 검사한다고만 적고 `backend` 값과 YARA-X를 쓰지 못하면 YARA로 검사한다는 차례를 적지 않는다 [20][21].

```python
def list_open_handles(
    target: str,
    response_format: str = EVIDENCE_RESPONSE_FORMAT,
) -> Any:
    """Return raw Handle output for one explicit PID, process name, or path substring.
    Set response_format='evidence_v1' for the common Evidence Envelope."""
    value = target.strip().strip('"')
    if not value:
        return local_response(response_format, "list_open_handles", "Error: target is required.")
    if len(value) > MAX_HANDLE_TARGET_LENGTH or any(char in value for char in "\r\n\x00"):
        result = "Error: target contains unsupported characters or is too long."
        return local_response(response_format, "list_open_handles", result)
    args = ["-nobanner", "-p", value] if value.isdigit() else ["-nobanner", value]
    result = run_sysinternals_tool("handle.exe", args, timeout_seconds=180)
    target_type = "live_process" if value.isdigit() else "live_host"
    return local_response(response_format, "list_open_handles", result, target_type, value)
```

```python
def ingest_analysis_report_impl(cfg: Config, report_path: str) -> dict[str, Any]:
    try:
        p = validate_evidence_file(report_path, cfg)
    except ValueError as exc:
        return {"error": str(exc)}
    try:
        data = read_json_file(p)
    except (ValueError, OSError) as exc:
        return {"error": f"could not read/parse JSON report: {exc}"}
    if not isinstance(data, dict):
        return {"error": "report is not a JSON object."}
    schema = data.get("export_schema")
    shaper = SHAPERS.get(schema)
    if shaper is None:
        return {"error": f"unrecognized or missing export_schema: {schema!r}. Supported: {list(SUPPORTED_SCHEMAS)}"}
    return shaper(data, {"ingested": True, "source_report": str(p)})
```

```python
    normalized = str(requested or "auto").strip().lower().replace("-", "_")
    if normalized not in {"auto", "yara", "yara_x", "yarax"}:
        raise ValueError("backend must be one of: auto, yara, yara_x.")

    yarax_integrity = executable_integrity(
        cfg.yarax_exe_path,
        cfg.yarax_expected_sha256,
        "YARA-X",
        require_pin=True,
    )
    yara_integrity = executable_integrity(
        cfg.yara_exe_path,
        cfg.yara_expected_sha256,
        "YARA",
        require_pin=True,
    )
    if normalized in {"yara_x", "yarax"}:
        if yarax_integrity["status"] != "SUCCESS":
            raise ValueError(yarax_integrity["error"])
        return "yara_x", cfg.yarax_exe_path, yarax_integrity
    if normalized == "yara":
        if yara_integrity["status"] != "SUCCESS":
            raise ValueError(yara_integrity["error"])
        return "yara", cfg.yara_exe_path, yara_integrity
    if yarax_integrity["status"] == "SUCCESS":
        return "yara_x", cfg.yarax_exe_path, yarax_integrity
    if yara_integrity["status"] == "SUCCESS":
        return "yara", cfg.yara_exe_path, yara_integrity
    raise ValueError(
        "No verified YARA backend is available. "
        f"YARA-X: {yarax_integrity.get('error')}; YARA: {yara_integrity.get('error')}"
    )
```
