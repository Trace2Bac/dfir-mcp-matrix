# T09 대상 시스템 대응 조치 처리

### 미구현

**판단.** 서버에는 서버를 실행한 Windows 호스트의 상태를 바꾸는 경로가 하나 있지만 그 변경의 전후 상태, 변경 내역, 되돌릴 방법을 남기지 않는다.
그 경로는 `ir-collect`의 `collect_triage_package`가 실행하는 `IR_Collect.exe -c` 수집이다 [1].
서버는 대상 시스템의 격리, 차단, 프로세스 종료, 계정 잠금, 파일 삭제, 설정 변경을 하는 도구를 두지 않는다.
대상 시스템을 다루는 서버는 서버를 실행한 Windows 호스트를 읽는 `local-forensic`과 같은 호스트에서 수집을 실행하는 `ir-collect`의 `collect_triage_package`다 [2][1].

`collect_triage_package`는 기본으로 꺼져 있다 [3].
`ir-collect`는 시작할 때 환경변수 `IRCOLLECT_ALLOW_COLLECTION`을 읽고 값이 `1`·`true`·`yes`·`on`일 때만 수집을 켠다 [3].
저장소의 클라이언트 설정 생성 코드와 MCP 설정 예시에는 이 환경변수가 없다.
켜진 상태에서도 호출 인자 `acknowledge_live_response`가 참이어야 `IR_Collect.exe -c`를 실행한다 [1].
수집 결과는 `IRCOLLECT_COLLECT_DIR`(기본은 `%TEMP%\ir-collect-mcp\collections`) 폴더에 쓰이고 서버는 그 ZIP의 경로, 크기, SHA-256을 돌려준다 [1][4].
`IR_Collect` 0.24.2의 수집은 이 폴더 아래 `IR_Output_<ID>` 폴더에 조회 명령의 출력, `reg save`로 저장한 하이브, `fsutil usn readjournal`로 읽은 USN 저널 같은 파일을 쓰고 ZIP을 만든 뒤 그 폴더를 지운다 [5][6].
수집 단계가 부르는 명령에는 `wmic`, `schtasks /query`, `reg export`, `reg save`, `systeminfo`, `cmdkey /list`, `klist`, `fsutil` 같은 조회·내보내기 명령이 있다 [6].
`-c`는 실행 산출물 수집 단계를 조건 없이 실행하고 이 단계는 호스트의 `Amcache.hve`를 출력 폴더 아래로 복사한다 [7].
그 뒤 `AmcacheParser.ParseHive`가 복사본을 `reg load`로 그 호스트 레지스트리의 `HKU\IRCOL_AMCACHE_<GUID>` 키에 연결해 읽고 `reg unload`로 해제한다 [7][8].
`reg load`가 실패하면 하이브를 연결하지 않고 `ParserNotes`에 실패 문구를 남긴다 [8].
`reg unload`가 실패하면 `IR_Collect.exe`의 기록 파일에 경고만 남긴다 [8][9].
하이브를 연결하고 해제하는 일은 수집하려고 대상 호스트의 레지스트리 상태를 바꾸는 일이다.
메모리 수집은 `IR_Collect.exe` 옆 `config.ini`의 `MemoryAcquireEnabled`가 `1`일 때만 실행되고 기본값은 `0`이다 [10].
수집 폴더의 출력 파일과 `IR_Collect.exe`의 기록·임시 파일 쓰기는 격리·차단·종료·설정 변경 같은 조치가 아니다 [1][9].

서버는 이 변경을 기록하지 않는다.
`collect_triage_package`의 성공 응답에는 ZIP의 경로·크기·SHA-256, 관리자 권한 여부, `exit_code`, 실행 파일의 SHA-256, 정해 둔 안내 문구가 실리고 하이브 연결과 해제는 실리지 않는다 [11].
성공 응답에는 `IR_Collect.exe`의 표준 출력과 표준 오류도 실리지 않는다 [11].
도구 설명과 응답은 이 수집이 호스트에 출력을 쓰고 호스트를 바꾼다고 적지만 무엇을 바꾸는지는 적지 않는다 [1][11].
서버는 호출 기록을 남기지 않고 되돌리는 도구나 경로도 두지 않는다.

`local-forensic`의 도구 19개는 서버 코드에 정해 둔 PowerShell 스크립트나 Sysinternals 도구로 호스트를 읽는다 [2].
PowerShell 스크립트는 `Get-`으로 시작하는 조회 cmdlet과 `Test-Path`로 호스트를 읽고 `Select-Object`·`Where-Object`·`Sort-Object`·`ConvertTo-Json`으로 결과를 고르고 바꾼다 [2].
Sysinternals 도구에 넘기는 인자도 서버 코드가 정하고 `autorunsc.exe`는 `-a <분류> -ct`, `sigcheck.exe`는 `-a -h -i -ct`, `tcpvcon.exe`는 `-a -c -n`, `handle.exe`는 `-p <PID>`나 이름 조각으로 실행한다 [12].
Handle의 핸들 닫기 인자 `-c`처럼 대상 시스템을 바꾸는 인자는 넘기지 않는다 [12][13].
서버는 모든 Sysinternals 실행에 `-accepteula`를 붙인다 [14].
Sigcheck 문서는 이 인자를 사용권 동의 창 없이 동의하는 옵션으로 적고 동의를 어디에 남기는지는 적지 않는다 [15].
Autoruns, Handle, TCPView 문서는 이 인자를 적지 않으므로 이 인자가 호스트에 무엇을 남기는지는 확인하지 못했다 [16].

`ir-collect`의 다른 도구와 `artifact-forensic`는 증거 폴더, ZIP, 보고서 파일을 읽는다 [17][18].
두 서버가 쓰는 파일은 서버의 작업 폴더에 두고 호출이 끝나면 지운다 [17][18].
`myirteam-core`는 저장소의 자료 파일만 읽는다 [19].
