# T06 실행 환경정보 표시

### T06.01 응답 메타데이터에 버전 표시

**구현.** 이 방식은 `artifact-forensic`의 capa·YARA·YARA-X 분석 결과와 서버 안 코드로 만든 분석 결과, `ir-collect`의 `IR_Collect.exe` 분석 결과에 적용된다 [1][2][3][4].
`analyze_file_with_capa`와 `analyze_archive_member_with_capa`는 실행 파일의 SHA-256이 코드에 적은 `BUNDLED_CAPA_SHA256`과 같을 때 `tool_version`에 `7.1.0`을 싣는다 [1].
같은 응답의 `capa_result_meta.version`에는 capa가 JSON 결과의 `meta.version`에 적은 값을 옮긴다 [5].
capa 7.1.0은 이 필드에 자기 패키지 버전 `7.1.0`을 적는다 [6].

`scan_file_with_yara`와 `scan_archive_member_with_yara`는 고른 백엔드 실행 파일의 SHA-256이 코드에 적은 값과 같을 때 YARA면 `4.5.5`, YARA-X면 `1.19.0`을 `tool_version`에 싣는다 [2].
쓴 룰의 식별값으로는 룰 파일마다 경로와 SHA-256을 차례로 이어 계산한 SHA-256을 `rules.sha256`과 `provenance.rule_set_digest`에 싣는다 [2][7].

서버 안 코드로 분석하는 `inspect_binary_file`·`inventory_evidence_path`·`inventory_archive_members`·`verify_sha256_manifest`는 `provenance.tool_name`에 그 코드의 이름을, `tool_version`에 코드에 적은 `1.0.0`을 싣는다 [3].
ZIP 항목을 분석하는 도구는 항목 사본을 분석한 함수의 `provenance`를 그대로 두고 원본 ZIP과 항목의 정보만 더한다 [8].

`ir-collect`의 `analyze_artifact_folder`·`analyze_triage_zip`·`correlate_hosts`·`expand_investigation_graph`는 `IR_Collect.exe`가 쓴 결과 JSON에서 `tool_name`·`tool_version`·`export_schema`를 읽어 응답의 `provenance`에 싣는다 [4].
같은 `provenance`에 실행 직전에 계산한 `IR_Collect.exe`의 SHA-256 `analyzer_sha256`도 싣는다 [4].
`IR_Collect` 0.24.2는 결과 JSON의 `tool_version`에 실행 중인 어셈블리 버전의 앞 세 자리를 적는다 [9].
`ingest_analysis_report`는 다른 곳에서 만든 결과 JSON을 읽어 그 파일에 적힌 `tool_version`을 싣는다 [10].
실행 확인에서 결과 JSON에 `tool_version` `0.24.2`를 쓰는 시험용 실행 파일로 `analyze_artifact_folder`를 부르면 응답의 `provenance.tool_version`이 `0.24.2`였다 [11].

EZ Tools 결과에 싣는 버전은 실행한 도구와 묶이지 않는다 [12].
`parse_windows_artifact_with_eztools`와 `parse_archive_member_with_eztools`는 응답의 `provenance`에 도구 이름 `tool_name`, 버전 `tool_version`, 실행 파일의 SHA-256 `analyzer_sha256`을 싣는다 [12].
`tool_version`에는 실행한 실행 파일과 상관없이 코드 상수 `BUNDLED_EZTOOLS_VERSION`의 값 `2026.5.0`이 들어간다 [12].
사용자가 `PECMD_EXE`와 `PECMD_EXPECTED_SHA256` 같은 환경변수로 다른 실행 파일을 정해도 이 값은 바뀌지 않는다 [12][13].
실행 확인에서 시험용 실행 파일을 PECmd 자리에 두고 기대 해시를 그 파일의 해시로 맞춰 부르면 `tool_version`이 `2026.5.0`이었다 [11].
RECmd로 하이브를 읽으면 쓴 배치 파일의 이름 `profile`과 그 SHA-256 `profile_sha256`도 싣는다 [12].

세 증거 서버의 기본 응답 형식 `evidence_v1`은 결과의 `provenance`에서 `tool_name`·`tool_version`·`exit_code` 등 정해 둔 키 9개만 응답 최상위의 `provenance`로 옮긴다 [14].
`analyzer_sha256`, `profile_sha256`, `rule_set_digest`는 옮기지 않으므로 응답의 `data` 안에만 남는다 [14].

다음 결과에는 도구 버전이나 룰 식별값이 실리지 않는다.

- `analyze_evtx_with_hayabusa`와 `analyze_evtx_archive_member_with_hayabusa`의 `provenance.tool_version`은 언제나 `None`이고 Hayabusa가 쓴 룰의 식별값도 없다 [15].
- capa 결과에는 capa가 쓴 룰의 식별값이 없다 [1][5].
- `collect_triage_package`의 응답은 `IR_Collect.exe`의 SHA-256만 싣고 버전은 싣지 않는다 [16].

`collect_triage_package`가 남기는 ZIP과 SHA-256 파일은 `IR_Collect.exe`가 만들고 서버는 따로 버전을 적은 파일을 만들지 않는다 [16].
서버는 호출 기록을 남기지 않고 모델을 부르지 않는다.

**한계.** capa, YARA, YARA-X는 실행 파일의 SHA-256이 코드에 적은 값과 다르면 `tool_version`을 `None`으로 둔다 [1][2].
실행 확인에서 시험용 capa와 시험용 YARA의 `tool_version`은 `None`이었고 capa 응답의 `capa_result_meta.version`에는 시험용 실행 파일이 출력한 값이 그대로 실렸다 [11].
`ingest_analysis_report`가 싣는 `tool_version`은 보고서 파일에 적힌 값이고 서버는 그 보고서를 만든 실행 파일을 확인하지 않는다 [10].

### T06.04 환경 조회 도구에서만 반환

**구현.** 이 방식은 `local-forensic`의 `get_forensic_context`에 적용된다 [17].
`get_forensic_context`는 Sysinternals 도구 4개마다 경로, 존재 여부, 크기, SHA-256과 함께 PowerShell `Get-Item`이 읽은 파일 버전 `file_version`과 제품 버전 `product_version`을 돌려준다 [17].

`local-forensic`의 분석 결과에는 버전이 없다 [18][19].
`collect_autoruns`·`check_file_signatures`·`list_network_connections`·`list_open_handles`는 Sysinternals 도구의 출력 글을 그대로 돌려주고 서버는 이 도구들을 `-nobanner`와 함께 실행한다 [18].
Sigcheck 문서는 `-nobanner`를 시작 배너와 저작권 문구를 출력하지 않는 옵션으로 적는다 [20].
PowerShell로 읽는 도구의 응답에는 실행한 PowerShell의 경로나 버전이 없다 [19].
`get_external_tool_inventory`는 `External Tools/external_tools_manifest.json`의 도구마다 경로, 존재 여부, 기대 SHA-256, 실제 SHA-256을 돌려주고 manifest의 `version`은 싣지 않는다 [21].
실행 확인에서 실행 파일이 없는 사본으로 부르면 항목의 키는 `exists`, `expected_sha256`, `id`, `path`, `purpose`, `risk`였다 [11].

`ir-collect`의 `get_ircollect_info`와 `artifact-forensic`의 `get_artifact_forensic_info`도 실행 파일의 버전을 돌려준다 [22][23].
`get_ircollect_info`는 PE 파일의 버전 정보를, `get_artifact_forensic_info`는 Hayabusa의 `help`와 다른 도구의 `--version` 출력에서 찾은 버전 숫자를 싣는다 [22][23].
이 두 서버는 분석 결과에도 버전을 싣는다.

**한계.** 버전을 읽는 PowerShell 실행이 실패하면 `file_version`과 `product_version`은 `null`이 되고 응답에 실패 사실이 남지 않는다 [17].
실행 확인에서 버전 조회만 실패하게 바꾼 PowerShell 대체로 부르면 응답 상태는 `SUCCESS`였고 `errors`와 `limitations`가 비어 있었다 [11].

### T06.05 서버 자신의 버전 표시

**구현.** 이 방식은 `myirteam-core`의 도구 5개와 `artifact-forensic`의 `get_artifact_forensic_info`에 적용된다 [24][23].
`myirteam-core`는 성공 응답마다 코드 상수 `CORE_VERSION`의 값 `1.2.0`을 `core_version`에 싣는다 [24].
`get_project_capabilities`가 돌려주는 `agent-manifest.json`도 `project.core_version`에 `1.2.0`을 적는다 [25].
`get_artifact_forensic_info`는 `tool_name` `artifact-forensic`과 `tool_version` `1.5.0`을 싣는다 [23].
`local-forensic`과 `ir-collect`의 응답에는 서버 자신의 버전이 없다 [14].

네 서버는 `FastMCP`에 이름과 지침만 주고 버전을 주지 않는다 [26].
MCP Python SDK 1.28.1은 서버 버전이 없으면 `mcp` 패키지의 버전을 초기화 응답의 `serverInfo.version`에 넣는다 [27].
실행 확인에서 네 서버의 `serverInfo.version`은 모두 `1.28.1`이었다 [28].

**한계.** `myirteam-core`의 오류 응답은 `core_version`을 싣지 않는다 [29].
`CORE_VERSION`과 manifest의 `core_version`은 따로 적은 값이고 서버는 두 값을 대조하지 않는다 [24][25].

    digest = hashlib.sha256()
    for path in rule_files:
        digest.update(str(path).encode("utf-8", errors="replace"))
        digest.update(b"\0")
        digest.update(sha256_file(path).encode("ascii"))
        digest.update(b"\0")

    try:
        p = validate_evidence_file(report_path, cfg)
    except ValueError as exc:
        return {"error": str(exc)}
    try:
        data = read_json_file(p)
    except (ValueError, OSError) as exc:
        return {"error": f"could not read/parse JSON report: {exc}"}
    if not isinstance(data, dict):
        return {"error": "report is not a JSON object."}
    schema = data.get("export_schema")
    shaper = SHAPERS.get(schema)
    if shaper is None:
        return {"error": f"unrecognized or missing export_schema: {schema!r}. Supported: {list(SUPPORTED_SCHEMAS)}"}
    return shaper(data, {"ingested": True, "source_report": str(p)})
```

def pe_file_version(path: Path) -> str | None:
    """Read a Windows PE FileVersion (e.g. '0.24.2.0') via ctypes; None off Windows
    or on any failure. Used so get_ircollect_info can report a version despite the
    winexe stdout being unreadable headless."""
    if os.name != "nt":
        return None
    try:
        import ctypes
        from ctypes import wintypes

        ver = ctypes.windll.version
        size = ver.GetFileVersionInfoSizeW(str(path), None)
        if not size:
            return None
        buf = ctypes.create_string_buffer(size)
        if not ver.GetFileVersionInfoW(str(path), 0, size, buf):
            return None
        lp = ctypes.c_void_p()
        ln = wintypes.UINT()
        if not ver.VerQueryValueW(buf, "\\", ctypes.byref(lp), ctypes.byref(ln)):
            return None
        fixed = ctypes.cast(lp, ctypes.POINTER(ctypes.c_uint32 * 13)).contents
        ms, ls = fixed[2], fixed[3]
        return f"{(ms >> 16) & 0xFFFF}.{ms & 0xFFFF}.{(ls >> 16) & 0xFFFF}.{ls & 0xFFFF}"
    except Exception:
        return None
```
