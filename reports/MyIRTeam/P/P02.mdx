# P02 다음 작업 결정

### P02.01 고정 문서·프로필 반환

**구현.** 이 방식은 `myirteam-core`의 `get_workflow`, `get_bootstrap_instructions`, `get_project_capabilities`와 네 서버의 초기화 응답 `instructions`에 적용된다 [1][2][3].
`get_workflow`는 `agent-manifest.json`의 `workflows`에 선언된 ID만 받아 `workflows/<ID>.json` 문서를 그대로 돌려준다 [1].
선언된 워크플로는 `infection-investigation`, `event-investigation`, `file-investigation`, `deep-analysis`, `offline-artifact-investigation`, `offline-file-investigation` 6개다 [4].
워크플로 문서는 상태마다 부를 도구, 담당(`mcp_server`·`calling_ai_agent`·`user`), 다음 상태를 적고 끝에 `completion_criteria`와 `prohibited_actions`를 둔다 [5].
`deep-analysis` 문서는 상태 19개를 두고 ZIP 항목을 고르는 일과 원인 분석, 보고서 작성은 `calling_ai_agent`의 상태로 적는다 [5][6].
`get_bootstrap_instructions`는 `BOOTSTRAP.md`의 글을, `get_project_capabilities`는 `agent-manifest.json` 전체를 돌려준다 [2].
`myirteam-core`의 `instructions`는 조사마다 `resolve_investigation_intent`를 먼저 부르고 빠진 입력이 없으면 `get_workflow`를 부르라고 적는다 [3].
증거 서버 셋의 `instructions`는 `myirteam-core`가 워크플로를 고른 뒤에 쓰라고 적는다 [7].
세 도구는 호출마다 파일을 다시 읽고 앞선 호출이나 증거와 관계없이 같은 내용을 돌려준다 [1][2].
`get_workflow`는 문서의 `id`가 요청한 ID와 같은지만 확인한다 [1].
워크플로의 도구 이름과 상태 전이를 확인하는 코드는 시험 스크립트 `tests/static_validate.py`에 있고 서버 코드에는 없다 [8].
도구 설명과 서버 지침에는 클라이언트 문맥이 압축되거나 끊긴 뒤 다시 읽을 도구를 안내하는 글이 없다.

같은 저장소의 클라이언트 지침 `AGENTS.md`·`CLAUDE.md`·`BOOTSTRAP.md`도 `resolve_investigation_intent`, `get_workflow`, 워크플로 실행의 차례를 적는다 [9].
`.agents/workflows/`는 AGY 클라이언트에 같은 절차를 Markdown으로 준다 [10].

### P02.02 규칙·조사 상태로 추천

**구현.** 이 방식은 `myirteam-core`의 `resolve_investigation_intent`와 `ir-collect`의 `get_ircollect_info`·`collect_triage_package` 응답에 적용된다 [11][12][13].
`resolve_investigation_intent`의 규칙은 `agent-manifest.json`의 `intent_routing`에 있는 경로 7개다 [14].
경로마다 `priority`, `input_kinds`, `workflow_id`, `required_inputs`, `keywords`를 둔다 [14].
호출자가 `input_kind`를 주면 그 값을 가진 첫 경로를 고르고 `auto`이면 `priority`가 높은 경로부터 키워드가 요청 글에 들어 있는지 대소문자를 무시하고 찾는다 [11].
키워드는 부분 문자열로 찾고 처음 맞은 경로 하나만 고른다 [11].
고른 경로의 `required_inputs` 가운데 `input_path`·`member_path`·`artifact_type` 인자가 비어 있는 것을 `missing_inputs`에 싣는다 [15].
빠진 입력이 없으면 `execution_contract.next_tool`에 `myirteam-core/get_workflow`를 싣고 있으면 `null`과 `clarification_required` 참을 싣는다 [15][16].
맞는 경로가 없으면 `fallback`의 `investigation_target_or_evidence_path`를 빠진 입력으로 싣는다 [15].
"please parse this evtx"로 부르자 `offline-artifact-investigation`과 빠진 입력 `input_path`·`artifact_type`이 돌아왔고 "is my computer infected?"는 빠진 입력 없이 `infection-investigation`과 `get_workflow`를 돌려주었다 [17].
`execution_contract`의 나머지 값은 `agent-manifest.json`의 `policy`에 적어 둔 고정 값이다 [16].
이 안내는 응답 값이고 증거 서버는 `resolve_investigation_intent`를 거쳤는지 확인하지 않는다 [15].

`get_ircollect_info`는 기대 해시나 증거 폴더 설정이 없으면 그 사실과 분석 도구가 모든 경로를 거부한다는 문장을 `notes`에 싣는다 [12].
`collect_triage_package`는 꺼져 있으면 켜는 환경변수를, 확인 인자가 없으면 `acknowledge_live_response=true`로 다시 부르라는 문장을 오류에 싣는다 [13].
수집을 마치면 ZIP을 증거 폴더에 두고 `analyze_triage_zip`을 부르라는 `next_step`을 싣는다 [18].
`analyze_artifact_folder`·`analyze_triage_zip`과 `summary_v3` 보고서를 받은 `ingest_analysis_report`는 건수 상태와 관계없이 원시 ZIP의 범위는 `artifact-forensic`의 목록 도구로 보라는 고정 문장을 `coverage_reporting.note`에 싣는다 [19].

**한계.** `resolve_investigation_intent`는 경로 인자가 비어 있는지만 보고 그 경로가 있는지는 확인하지 않는다 [15].
없는 경로 문자열을 `input_path`로 주자 빠진 입력 없이 `next_tool`에 `get_workflow`가 실렸다 [17].

### P02.04 서버 코드에 고정한 분석 절차

**구현.** 이 방식은 `local-forensic`의 `collect_ir_event_bundle`에 적용된다 [20].
`collect_ir_event_bundle`은 Security, System, PowerShell, Defender, Task Scheduler, RDP 연결, RDP 세션, WMI 채널 8개를 차례로 질의하고 결과를 `queries` 하나에 모은다 [20].
채널마다 질의할 이벤트 ID는 코드에 정해 두고 모델은 시간 범위와 채널당 상한만 고른다 [20].
PowerShell 실행을 대체 함수로 바꾼 실행에서 `collect_ir_event_bundle`은 8번 질의해 채널 8개의 결과를 차례로 실었다 [21].
`build_process_tree_snapshot`은 프로세스 목록을 한 번 읽어 PID로 부모 프로세스를 찾고 부모의 이름·경로·명령 줄을 각 행에 붙이도록 짜여 있다 [22].
이 도구는 `list_running_processes`를 기본 응답 형식으로 불러 최상위에 `processes`가 없는 `evidence_v1` 응답을 받으므로 `process_count` 0과 빈 `processes`를 돌려준다 [22][21][23][24].

`ir-collect`의 분석 도구는 `IR_Collect.exe` 실행 한 번을 감싸고 그 안의 분석 단계는 `IR_Collect.exe`가 정한다 [25].
`artifact-forensic`의 도구는 호출마다 분석 도구 하나를 실행한다 [26].
여러 도구를 잇는 절차는 워크플로 문서에 적혀 있고 그 단계를 실행하는 것은 모델이다 [5].
서버 안에서 모델을 불러 계획을 세우는 경로는 없다.
