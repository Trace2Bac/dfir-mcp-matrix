# P05 사건 자료 정리

### P05.03 자동 정리

**구현.** 이 방식은 `ir-collect`의 IR_Collect 분석 도구 4개와 `artifact-forensic`의 EZ Tools·Hayabusa·capa·YARA 도구, ZIP 항목 도구가 호출 중에 만드는 작업 폴더에 적용된다 [1][2][3][4].
`ir-collect`의 `analyze_artifact_folder`, `analyze_triage_zip`, `correlate_hosts`, `expand_investigation_graph`는 호출마다 `IRCOLLECT_WORK_DIR`(없으면 `%TEMP%\ir-collect-mcp`) 아래 `run_<난수>` 폴더를 만든다 [1][5].
이 폴더에 증거 폴더의 사본, 풀어 낸 ZIP, `IR_Collect.exe`가 쓴 결과 JSON을 두고 `finally`에서 폴더째 지운다 [1].
`artifact-forensic`의 분석 도구는 `ARTIFACT_WORK_DIR`(없으면 `%TEMP%\artifact-forensic-mcp`) 아래 `eztool_`·`run_`·`capa_`·`yara_` 폴더에 분석 도구의 출력을 두고 `finally`에서 지운다 [2][6].
ZIP 항목 도구는 `archive_member_<난수>` 폴더에 항목과 로그의 사본을 꺼내고 분석이 끝나면 지운다 [3].
꺼내는 중에 예외가 나도 그 폴더를 지운다 [4].
시험용 분석 도구로 성공·실패 호출을 이어서 한 실행에서 호출이 끝날 때마다 두 작업 폴더는 비어 있었다 [7].
지운 사실은 서버 기록이나 응답의 값으로 남지 않고 ZIP 항목 도구의 응답에 사본을 지웠다는 고정 문장 `copy_note`만 실린다 [3].
서버가 종료할 때 따로 지우는 코드는 없다.

사건 자료를 지우거나 초기화하는 MCP 도구와 사용자 명령은 없다.
`collect_triage_package`가 남기는 수집 ZIP은 수집 폴더에 남고 서버는 이 파일을 지우지 않는다 [8].
이 도구는 기본으로 꺼져 있다 [8].

**한계.** 세 정리 경로 모두 `shutil.rmtree`를 `ignore_errors=True`로 부르므로 지우지 못한 증거 사본은 알리지 않고 작업 폴더에 남는다 [1][2][3].
`copy_note`는 지우기에 성공했는지와 관계없이 실린다 [3].
`analyze_artifact_folder`·`correlate_hosts`·`expand_investigation_graph`에 `work_on_copy`를 거짓으로 주면 `IR_Collect.exe`가 원본 폴더에 쓰는 파생 CSV는 작업 폴더 밖의 파일이므로 지우지 않는다 [9][10].
시험용 `IR_Collect.exe`가 입력 폴더에 파일을 쓰게 한 실행에서 그 파일은 호출 뒤에도 원본 폴더에 남았다 [7].

### P05.05 원본 증거를 삭제 대상에서 제외

**구현.** 이 방식은 자동 정리에 적용된다.
자동 정리가 지우는 대상은 그 호출이 이름에 난수를 붙여 새로 만든 작업 폴더다 [1][2][3].
`artifact-forensic`은 이 폴더를 이미 있으면 실패하는 방식으로 만든다 [2][3].
원본 증거는 사본을 만들거나 해시할 때 읽기만 하고 지우는 대상에 없다 [1][3].
