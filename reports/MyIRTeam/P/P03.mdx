# P03 조사 진척 판단

### P03.03 미조사 범위·생략 사유 보고

**구현.** 이 방식은 `artifact-forensic`의 ZIP 목록·ZIP 항목 도구와 목록·해시 도구, `ir-collect`의 IR_Collect 분석 도구, 세 증거 서버의 `evidence_v1` 응답에 적용된다 [1][2][3][4][5][6].
`inventory_archive_members`는 `evtx`, `prefetch`, `amcache`, `registry`, `ntfs`, `executable` 유형마다 `artifact_coverage`를 싣는다 [1].
유형마다 이름으로 찾은 항목이 있는지(`PRESENT`·`NOT_OBSERVED`), 분석할 수 있는 항목 수, 안전 조건 때문에 막힌 항목 수를 적고 `parse_status`는 `NOT_ATTEMPTED`로 둔다 [1].
막힌 항목의 사유는 항목마다 `safe_path`, `is_symlink`, `encrypted`, `duplicate_name`, `oversized`, `high_compression_ratio`로 싣고 그 수를 `warnings`에 적는다 [7].
목록을 `max_members`에서 자르면 그 사실을 `warnings`와 `truncated`에 싣는다 [8].
항목을 꺼내 분석하는 ZIP 도구는 고른 유형 하나의 `artifact_coverage`에 `parse_status`를 `PARSED`, `PARSED_WITH_LIMITATIONS`, `FAILED` 가운데 하나로 적는다 [2].
항목을 꺼내지 못하면 `collection_status`를 `UNCONFIRMED`로 둔다 [2].
다른 폴더의 로그를 주어 꺼내기가 실패한 호출에서 응답은 `collection_status` `UNCONFIRMED`와 `parse_status` `FAILED`를 실었다 [9].

`inventory_evidence_path`는 목록을 `max_files`에서 자른 것, 해시 바이트 한도를 넘어 해시하지 않은 것, 링크와 증거 폴더 밖을 가리키는 항목을 건너뛴 수를 `warnings`에 적는다 [3].
`verify_sha256_manifest`는 줄 수 상한으로 자른 것, 형식이 틀린 줄, 바이트 한도로 건너뛴 항목(`SKIPPED`)을 응답에 적는다 [4].

`ir-collect`의 IR_Collect 분석 도구는 `coverage_reporting`을 싣는다 [5].
출처별·개체 유형별 건수가 있으면 `AVAILABLE`, 사실이 0건이면 `EMPTY_ANALYSIS`, 건수가 없으면 `UNAVAILABLE`로 적고 `UNAVAILABLE`이 자료가 없다는 뜻이 아니라는 문장을 붙인다 [5].
`artifact_coverage`에는 늘 `NOT_PROVIDED_BY_SUMMARY_SCHEMA`를 적는다 [5].
`IR_Collect.exe`가 낸 `parser_notes`와 `load_warnings`는 50개까지 옮긴다 [5].

`evidence_v1` 응답을 만드는 공통 모듈은 도구 결과에서 실패한 하위 질의, 실패한 결과 행, 모듈 목록을 다 읽지 못한 프로세스, 결과의 `errors` 목록을 찾아 `errors`와 `limitations`에 "Evidence coverage is incomplete." 같은 영향 문장과 함께 싣고 `status`를 `DEGRADED`로 둔다 [6].
`local-forensic`의 `collect_ir_event_bundle`처럼 채널마다 질의하는 도구는 실패한 채널 수가 이 경로로 응답에 실린다 [6][10].

서버에 대상별로 해야 할 작업 목록이나 완료 조건을 두고 수행 기록과 대조하는 코드는 없다.
워크플로 문서의 `completion_criteria`는 모델에게 주는 글이고 서버는 그 조건을 확인하지 않는다 [11].
모델이 진행 기록을 적는 도구도 없다.

**한계.** `inventory_archive_members`의 `PRESENT`·`NOT_OBSERVED`는 항목 이름만으로 정한다 [1][12].
그래서 정해 둔 이름이 아닌 자료는 ZIP에 있어도 `NOT_OBSERVED`가 된다 [12].
`IR_Collect.exe` 0.24.2의 `summary_v3`에는 수집 단계별 완료·실패·건너뜀을 담는 `collection_coverage`와 `artifacts_count`가 있다 [13].
서버의 응답 모양은 이 두 값을 옮기지 않고 `artifact_coverage`에 `NOT_PROVIDED_BY_SUMMARY_SCHEMA`를 적는다 [5][13].
`IR_Collect.exe` 0.24.2는 `Amcache.hve`·`SYSTEM`에서 CSV를 만들지 못하면 관리자 권한으로 다시 실행하라는 문장을 `load_warnings`에 넣는다 [14].
공통 모듈은 `load_warnings`를 보지 않으므로 이런 생략이 있어도 `evidence_v1` 응답의 `status`를 `DEGRADED`로 바꾸지 않고 `limitations`에도 싣지 않는다 [5][6].

```python
def archive_member_candidate_types(member_path: str) -> list[str]:
    """Classify names only for analyst routing; this does not validate contents."""
    pure = PurePosixPath(member_path)
    name = pure.name.lower()
    suffix = pure.suffix.lower()
    candidates: list[str] = []
    if suffix == ".evtx":
        candidates.append("evtx")
    if suffix == ".pf":
        candidates.append("prefetch")
    if name == "amcache.hve":
        candidates.append("amcache")
    if name in {
        "system",
        "software",
        "sam",
        "security",
        "default",
        "ntuser.dat",
        "usrclass.dat",
    }:
        candidates.append("registry")
    if name in {"$mft", "mft_dump.bin", "mft.bin", "$j", "$boot", "$sds", "$i30"}:
        candidates.append("ntfs")
    if name.endswith((".log1", ".log2")):
        candidates.append("registry_log")
    if suffix in EXECUTABLE_MEMBER_SUFFIXES:
        candidates.append("executable")
    return candidates
```
