# P01 분석 방법 적합성 확인

### P01.01 이름·확장자 판별

**구현.** 이 방식은 `artifact-forensic`의 EVTX·EZ Tools 도구, ZIP 목록 도구, ZIP 항목 도구와 `ir-collect`의 `analyze_triage_zip`에 적용된다 [1][2][3][4][5].
`analyze_evtx_with_hayabusa`는 받은 경로가 파일이면 확장자가 `.evtx`일 때만 받고 폴더이면 그 아래 어디에든 `.evtx` 파일이 하나라도 있을 때만 받는다 [1].
`parse_windows_artifact_with_eztools`는 `evtx`·`prefetch`·`amcache` 유형의 입력을 확장자 `.evtx`·`.pf`와 파일 이름 `Amcache.hve`로 알아본다 [2].
`inventory_archive_members`는 ZIP 항목의 내용을 읽지 않고 이름만으로 `candidate_artifact_types`를 정한다 [3].
확장자 `.evtx`는 `evtx`, `.pf`는 `prefetch`, 이름 `amcache.hve`는 `amcache`, `system`·`software`·`sam`·`security`·`default`·`ntuser.dat`·`usrclass.dat`는 `registry`가 된다 [3].
`$mft`·`mft_dump.bin`·`$j` 같은 이름 7개는 `ntfs`, `.log1`·`.log2`로 끝나는 이름은 `registry_log`, 실행 파일 확장자 7개는 `executable`이 된다 [3].
이 도구는 이 분류로 유형별 `collection_status`를 `PRESENT`나 `NOT_OBSERVED`로 적고 응답의 `disclaimer`에 이 분류가 내용을 확인하지 않은 경로 안내라고 적는다 [6].
항목을 꺼내는 ZIP 항목 도구 5개는 꺼낸 항목의 `candidate_artifact_types`도 같은 함수로 정해 응답에 싣는다 [7].
`analyze_triage_zip`과 `artifact-forensic`의 ZIP 도구는 확장자가 `.zip`이 아닌 파일을 받지 않는다 [4][5].

`ir-collect`의 폴더·ZIP 분석에서 폴더 안 자료의 종류는 `IR_Collect.exe` 0.24.2가 파일 이름과 확장자로 정한다 [8].
서버 코드는 `IR_Collect.exe`에 넘기는 폴더 안의 파일을 판별하지 않는다 [9].

**한계.** 이름과 확장자가 맞으면 서버는 내용을 확인하지 않고 그 형식의 분석 도구를 실행한다 [1][2].
`inventory_archive_members`는 정해 둔 이름 밖의 하이브(`COMPONENTS`, `BCD` 등)나 이름을 바꾼 자료를 그 유형으로 세지 않는다 [3].
그런 자료만 있는 ZIP에서 그 유형의 `collection_status`는 `NOT_OBSERVED`가 된다 [6].

### P01.02 메타데이터 조회

**구현.** 이 방식은 `artifact-forensic`의 `analyze_evtx_with_hayabusa`에 적용된다 [1].
받은 경로가 파일이면 Hayabusa에 `-f`로, 폴더이면 `-d`로 넘긴다 [10].
서버가 증거의 OS나 파티션을 판별하는 코드는 없다.
`local-forensic`의 `get_forensic_context`는 서버를 실행한 호스트의 OS 이름·버전·빌드와 아키텍처를 응답에 싣는다 [11].
서버는 이 값으로 도구나 질의를 고르지 않는다 [11].

### P01.03 내용·헤더 검사

**구현.** 이 방식은 `artifact-forensic`의 `inspect_binary_file`·`inspect_archive_member_binary`, `ir-collect`의 `ingest_analysis_report`, ZIP을 여는 도구에 적용된다 [12][13][14].
`inspect_binary_file`은 파일 앞 64바이트를 읽어 앞 두 바이트가 `MZ`인 파일만 PE 구조를 읽는다 [12].
PE 서명이나 헤더를 확인하지 못하면 `is_pe`가 거짓인 결과와 경고를 싣는다 [12][15].
같은 64바이트의 서명으로 정한 `detected_format`은 분석 결과로 응답에 실린다 [12].
서버는 이 값으로 다른 처리를 고르지 않는다 [12].
`MZ`만 있는 202바이트 파일로 부르자 `detected_format`은 `dos_or_windows_pe`, `pe.is_pe`는 거짓, `status`는 `DEGRADED`였다 [16].
`inspect_archive_member_binary`는 ZIP 항목의 사본에 같은 함수를 부른다 [17].
`ingest_analysis_report`는 JSON 보고서의 `export_schema` 값이 `summary_v3`·`correlation_v1`·`graph_v1` 가운데 무엇인지로 응답을 만드는 함수를 고르고 값이 없거나 다르면 거부한다 [13].
`analyze_triage_zip`, `inventory_archive_members`, ZIP 항목 도구는 파일을 Python `zipfile`로 열고 ZIP 구조로 읽히지 않으면 오류를 돌려준다 [14].
확장자가 `.zip`인 글자 파일을 `analyze_triage_zip`에 주자 "could not extract ZIP: File is not a zip file" 오류가 돌아왔다 [16].

분석 도구가 스스로 하는 형식 확인도 있다.
capa 7.1.0은 입력 앞 256바이트로 지원 형식인지 확인하고 아니면 `UnsupportedFormatError`를 낸다 [18].
MFTECmd는 `-f` 파일의 앞 50바이트 서명으로 `$MFT`·`$J`·`$Boot`·`$SDS`와 폴더 인덱스 파일을 가린다 [19].

**한계.** `ingest_analysis_report`는 `export_schema` 값만 보고 나머지 구조는 확인하지 않는다 [13][20].
도구 설명은 보고서의 schema를 판별하고 검사한다고 적는다 [21].
`export_schema`가 `graph_v1`이고 `nodes`에 정수 두 개만 둔 JSON을 주자 오류 없이 그 값이 응답의 `nodes`에 실렸다 [16].

### P01.04 방법과 형식·OS 대조

**구현.** 이 방식은 `artifact-forensic`의 `parse_windows_artifact_with_eztools`와 `parse_archive_member_with_eztools`에 적용된다 [2][22].
모델이 `artifact_type`으로 고른 EZ Tools 도구를 입력 파일의 이름과 대조한다 [2].
`evtx`(EvtxECmd)는 확장자 `.evtx`, `prefetch`(PECmd)는 `.pf`, `amcache`(AmcacheParser)는 파일 이름 `Amcache.hve`가 아니면 도구를 실행하지 않고 오류를 돌려준다 [2].
`parse_archive_member_with_eztools`는 항목을 원래 파일 이름으로 작업 폴더에 꺼낸 뒤 같은 함수를 부르므로 항목 이름으로 같은 대조를 한다 [22][23].
`prefetch`로 `.evtx` 파일을 주거나 `amcache`로 `SYSTEM` 하이브를 주자 대체 실행 파일이 실행되지 않고 오류가 돌아왔고 ZIP 항목에서도 같았다 [16].

부속 입력도 대조한다.
`companion_member_paths`는 `artifact_type`이 `registry`일 때만 받는다 [22].
받은 항목은 고른 하이브와 같은 폴더의 `<하이브 이름>.LOG1`·`.LOG2`여야 하고 아니면 아무것도 꺼내지 않고 오류를 돌려준다 [24].
다른 폴더의 `.LOG1`을 주거나 `evtx` 유형에 로그를 주자 오류가 돌아왔다 [16].

다른 도구는 고른 방법을 입력과 대조하지 않는다.
capa와 YARA 도구는 받은 파일의 형식과 관계없이 실행한다 [25].
`myirteam-core`의 `resolve_investigation_intent`는 증거 경로를 열지 않고 요청 글의 낱말이나 호출자가 준 `input_kind`로 워크플로를 고르며 경로 인자는 비어 있는지만 본다 [26].

**한계.** `registry`와 `ntfs`는 입력의 이름이나 확장자를 대조하지 않는다 [2].
글자 파일을 `registry`와 `ntfs`로 주자 대체 RECmd와 MFTECmd가 실행되었다 [16].
`registry`의 프로필(`dfir`, `registry_aseps`, `system_aseps`, `software_aseps`, `user_activity`)은 하이브의 종류와 대조하지 않는다 [2].
대조는 이름만 보므로 이름이 맞으면 내용이 다른 형식인 파일에도 도구를 실행한다 [2].

def archive_member_candidate_types(member_path: str) -> list[str]:
    """Classify names only for analyst routing; this does not validate contents."""
    pure = PurePosixPath(member_path)
    name = pure.name.lower()
    suffix = pure.suffix.lower()
    candidates: list[str] = []
    if suffix == ".evtx":
        candidates.append("evtx")
    if suffix == ".pf":
        candidates.append("prefetch")
    if name == "amcache.hve":
        candidates.append("amcache")
    if name in {
        "system",
        "software",
        "sam",
        "security",
        "default",
        "ntuser.dat",
        "usrclass.dat",
    }:
        candidates.append("registry")
    if name in {"$mft", "mft_dump.bin", "mft.bin", "$j", "$boot", "$sds", "$i30"}:
        candidates.append("ntfs")
    if name.endswith((".log1", ".log2")):
        candidates.append("registry_log")
    if suffix in EXECUTABLE_MEMBER_SUFFIXES:
        candidates.append("executable")
    return candidates
```

def detect_file_format(header: bytes) -> str:
    if header.startswith(b"MZ"):
        return "dos_or_windows_pe"
    if header.startswith(b"\x7fELF"):
        return "elf"
    if header.startswith(b"%PDF-"):
        return "pdf"
    if header.startswith(b"PK\x03\x04"):
        return "zip_or_ooxml"
    if header.startswith(b"7z\xbc\xaf\x27\x1c"):
        return "7zip"
    if header.startswith(b"\x1f\x8b"):
        return "gzip"
    if header.startswith(b"Rar!\x1a\x07"):
        return "rar"
    if header.startswith(b"SQLite format 3\x00"):
        return "sqlite3"
    if header.startswith(b"regf"):
        return "windows_registry_hive"
    if header.startswith(b"ElfFile\x00"):
        return "windows_evtx"
    if header.startswith((b"#!", b"@echo off", b"@ECHO OFF")):
        return "script_text"
    return "unknown"
```

def validate_archive_companion_paths(
    primary_member: str,
    companion_member_paths: list[str] | None,
) -> list[str]:
    """Allow only adjacent Registry transaction logs for one selected hive."""
    companions = list(companion_member_paths or [])
    if len(companions) > MAX_ARCHIVE_COMPANION_MEMBERS:
        raise ValueError(
            f"companion_member_paths accepts at most {MAX_ARCHIVE_COMPANION_MEMBERS} entries."
        )
    primary = PurePosixPath(primary_member)
    allowed_names = {
        f"{primary.name}.LOG1".casefold(),
        f"{primary.name}.LOG2".casefold(),
    }
    normalized: list[str] = []
    seen: set[str] = set()
    for value in companions:
        candidate = normalize_archive_member(value)
        pure = PurePosixPath(candidate)
        if pure.parent != primary.parent or pure.name.casefold() not in allowed_names:
            raise ValueError(
                "Registry companions must be the selected hive's same-directory .LOG1/.LOG2 files."
            )
        folded = candidate.casefold()
        if folded in seen:
            raise ValueError(f"duplicate companion member requested: {candidate}")
        seen.add(folded)
        normalized.append(candidate)
    return normalized
