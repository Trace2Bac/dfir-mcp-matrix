# P04 조사 단위 관리

### 미구현

**판단.** 네 서버에는 사건 ID나 세션 ID처럼 조사를 묶는 단위가 없다.
도구 45개 가운데 사건이나 세션을 가리키는 인자를 둔 도구는 없고 증거 도구는 호출마다 파일이나 폴더의 경로를 받는다 [1].
`ir-collect`와 `artifact-forensic`은 시작할 때 환경변수 `IRCOLLECT_EVIDENCE_ROOTS`·`ARTIFACT_EVIDENCE_ROOTS`에서 증거 폴더 목록을 한 번 읽고 모든 호출이 그 목록을 함께 쓴다 [2][3].
사용자 CLI `portable_setup.py`는 증거 폴더를 주지 않으면 프로젝트 폴더 아래 `evidence`를 설정에 넣는다 [4].
두 서버는 호출마다 작업 폴더 아래 `run_`·`eztool_`·`archive_member_` 같은 앞말에 난수를 붙인 폴더를 만들고 호출이 끝나면 지운다 [5][6].
이 폴더 이름에는 조사를 가리키는 값이 없다 [5][6].
증거, 파생물, 호출 기록을 한 폴더 아래에 두는 배치는 서버 코드에 없다.

`evidence_v1` 응답의 `evidence_id`와 `snapshot_id`는 응답을 만들 때마다 새 난수로 만드는 값이고 서버는 이 값을 저장하거나 다른 호출과 잇지 않는다 [7].
`collect_triage_package`의 `evidence_id`는 수집 ZIP의 파일 이름이고 ZIP은 `IRCOLLECT_COLLECT_DIR`(없으면 작업 폴더 아래 `collections`)에 남는다 [8].
이 도구는 기본으로 꺼져 있다 [8].
`IR_Collect.exe` 0.24.2는 분석할 폴더마다 `Folder_<폴더 이름>_<시각>` 꼴의 `CaseID`를 만들고 `correlate_hosts`의 응답은 이 값을 호스트마다 `case_id`로 옮긴다 [9][10].
서버는 이 값을 받거나 검사하지 않는다 [10].
서버는 stdio 연결 하나를 받는 프로세스이고 연결이나 세션별로 상태를 나누는 코드는 없다.

같은 저장소의 클라이언트 지침은 조사를 대화 단위로 다룬다 [11].
새 조사 대화마다 `resolve_investigation_intent`를 먼저 부르고 도구를 고친 뒤에는 새 조사를 시작하라고 적는다 [11].
이 나눔은 모델이 지침을 따르는 것이고 서버를 다른 MCP 클라이언트로 부르면 적용되지 않는다.
