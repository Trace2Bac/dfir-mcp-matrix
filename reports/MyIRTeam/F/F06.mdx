# F06 보고 산출물 구성

### 비적용

**판단.** 서버 4개에는 사건 단위가 없고 보고 산출물을 만들거나 내보내는 도구도 없다.
도구는 호출마다 증거 경로나 이름을 인자로 받고 사건이나 조사 세션을 가리키는 ID를 받거나 만들지 않는다 [1].
호출 뒤에 남는 파일은 수집 ZIP과 해시 파일, `work_on_copy`를 거짓으로 줄 때 증거 폴더에 쓰이는 파생 CSV, 분석 도구의 로그 파일이고 서버는 작업 폴더를 응답 전에 지운다 [2][3][4].
`collect_triage_package`는 `IR_Collect.exe -c`로 대상 호스트의 수집 ZIP을 만들고 그 경로와 SHA-256을 돌려준다 [5].
이 ZIP은 수집한 증거이고 조사의 범위, 방법, 결과, 한계, 판단의 확정 상태를 담은 보고 산출물이 아니다 [5].
`ingest_analysis_report`는 다른 곳에서 만든 `IR_Collect.exe` JSON 보고서를 입력으로 읽고 새 파일을 쓰지 않는다 [6].

워크플로는 보고를 호출한 모델이 현재 대화에 돌려주는 단계로 적고 사용자가 원할 때만 HTML 보고서를 만들라고 적는다 [7].
같은 저장소의 `.agents/skills/forensic-report.md`는 모델이 `forensic_report_YYYYMMDD_HHMMSS.html` 이름으로 HTML 보고서를 쓰라고 적는다 [8].
이 보고서는 클라이언트 모델이 안내문에 따라 직접 쓰는 글이다.
같은 저장소에는 서버 응답을 정해진 코드로 가공해 보고 산출물을 만드는 사용자 CLI나 클라이언트 코드가 없다.
사용자 CLI `portable_setup.py`는 클라이언트별 MCP 설정 파일만 쓴다 [9].
`usb-collect/COLLECT.bat`는 `IR_Collect.exe -c`로 수집 ZIP을 만들고 `collection_log.txt`에 수집 한 줄을 덧붙이며 서버 응답을 읽지 않는다 [10].

[6] `ingest_analysis_report_impl`은 JSON 보고서를 읽어 형식별 정리 함수에 넘긴다.

```python
def ingest_analysis_report_impl(cfg: Config, report_path: str) -> dict[str, Any]:
    try:
        p = validate_evidence_file(report_path, cfg)
    except ValueError as exc:
        return {"error": str(exc)}
    try:
        data = read_json_file(p)
    except (ValueError, OSError) as exc:
        return {"error": f"could not read/parse JSON report: {exc}"}
    if not isinstance(data, dict):
        return {"error": "report is not a JSON object."}
    schema = data.get("export_schema")
    shaper = SHAPERS.get(schema)
    if shaper is None:
        return {"error": f"unrecognized or missing export_schema: {schema!r}. Supported: {list(SUPPORTED_SCHEMAS)}"}
    return shaper(data, {"ingested": True, "source_report": str(p)})
```
