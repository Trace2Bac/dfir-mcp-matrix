# F02 발견사항·결론 도출

### F02.01 규칙·키 기반 판정·상관

**구현.** 이 방식은 `artifact-forensic`의 `inspect_binary_file`과 `inspect_archive_member_binary`가 PE 구조를 읽어 싣는 `structural_observations`에 적용된다 [1][2].
두 도구는 파일 머리가 `MZ`로 시작할 때만 `parse_pe_structure`로 PE 헤더와 section 표를 읽는다 [1].
`MZ`로 시작하지 않는 파일에는 해시, 파일 전체 엔트로피, 형식 이름을 싣지만 이 표시는 붙이지 않는다 [1].
`parse_pe_structure`는 section마다 원본 범위의 엔트로피를 계산하고 7.2 이상이면 `high_entropy_section:<section 이름>`을 싣는다 [2].
마지막 section이나 헤더 뒤에 데이터가 남아 있으면 `data_after_last_section_or_headers`를 싣는다 [2].
section 원본 범위가 파일 밖으로 나가면 `section_raw_range_outside_file:<section 이름>`을, section 표가 잘렸으면 `section_table_truncated`를, COFF 시각을 날짜로 바꾸지 못하면 `coff_timestamp_out_of_range`를 싣는다 [2].
엔트로피가 7.64·7.10·0인 section 3개 뒤에 데이터를 붙인 시험 파일을 주자 `high_entropy_section:.hi`와 `data_after_last_section_or_headers`만 실렸다 [3].
응답의 `disclaimer`는 이 값들이 악성 판정이 아니라 구조 관찰이라고 적는다 [4].
`agent-manifest.json`의 `policy`는 서버가 판정을 돌려주지 않는다고 적는다 [5].

`ir-collect`의 분석 도구가 돌려주는 판정과 상관은 `IR_Collect.exe`가 만든다 [6].
`IR_Collect.exe` 0.24.2의 `-analyze`는 사실 저장소 `FactStore`를 만든 뒤 Guided Hunt 규칙 11개를 적용한다 [7].
규칙이 맞으면 `IR_Collect.exe`가 심각도, ATT&CK tactic과 기법, 근거 사실 ID, 가설 템플릿 ID를 정한다 [7].
`-correlate`는 둘 이상의 폴더에서 같은 개체와 같은 시간 구간에 나온 개체를 찾고 `-graph`는 시작 개체에서 관계 그래프를 넓힌다 [8].
`ir-collect`의 `shape_summary`는 규칙 일치에서 필드 일부를 고르고 근거 사실 ID를 개수로 바꾸고 증거 목록을 8개까지 자른다 [9].
같은 함수는 모든 규칙 일치에 고정값 `assessment_status` `UNCONFIRMED`와 `requires_correlation` 참을 붙인다 [9].
서버는 `IR_Collect.exe`가 정한 `severity`를 고치지 않고 규칙 일치를 다시 판정하거나 서로 잇지 않는다 [9].
저장소의 fixture 요약 파일을 `ingest_analysis_report`로 읽자 규칙 일치 5개가 `severity` `High` 그대로 `assessment_status` `UNCONFIRMED`와 함께 실렸다 [10].
`shape_correlation`과 `shape_graph`도 `IR_Collect.exe`가 낸 공유 개체, 시간 상관, 노드, 간선을 상한 개수까지만 옮긴다 [11].

다른 도구도 서버 코드의 규칙으로 판정하지 않는다.

- `artifact-forensic`의 Hayabusa, capa, YARA 도구가 싣는 규칙 일치는 그 분석 도구가 낸 것이고 서버는 필드를 고르고 개수를 자른다 [12].
- `local-forensic`의 도구는 Sysinternals 도구와 PowerShell 질의의 출력을 판정 값 없이 돌려준다 [13].
- `build_process_tree_snapshot`은 같은 프로세스 목록 안에서 부모 PID로 부모 행의 이름과 경로를 붙이도록 짜여 있고 판정 값을 싣는 코드는 없다 [14].
- `collect_ir_event_bundle`은 채널마다 정해 둔 이벤트 ID로 이벤트를 모으고 모은 이벤트에 판정이나 분류 이름을 붙이지 않는다 [15].

**한계.** 머리가 `MZ`로 시작해도 PE 서명, COFF 헤더, optional header를 읽지 못하거나 section 수가 96을 넘으면 `parse_pe_structure`는 표시 없이 `parse_error`만 돌려준다 [16].
그때 응답에는 PE로 검증하지 못했다는 경고만 실리고 section 엔트로피 표시는 실리지 않는다 [1][16].

### F02.05 사용 근거·변환 기록

**구현.** 이 방식은 `inspect_binary_file`과 `inspect_archive_member_binary`의 응답에 적용된다 [4][17].
응답의 `input`은 검사한 파일의 경로, 크기, MD5·SHA-1·SHA-256과 검사 뒤 SHA-256을 싣는다 [4].
`pe.sections`는 section마다 이름, 주소, 크기, 엔트로피를 싣고 `structural_observations`의 표시는 해당 section 이름을 함께 적는다 [2].
뒤에 남은 데이터는 `overlay_offset`과 `overlay_size`로 위치와 크기를 싣는다 [2].
`provenance`는 검사기 이름 `artifact-forensic-static-inspector`와 그 버전을 적는다 [4].
`inspect_archive_member_binary`는 ZIP 경로, 항목 경로, 항목 SHA-256, ZIP의 검사 전후 SHA-256을 `input`과 `provenance`에 더한다 [17].

**한계.** 응답은 엔트로피 표시의 문턱 7.2를 싣지 않는다 [2][4].
시험 파일의 응답에서 엔트로피 7.098인 section `.mid`는 표시 없이 엔트로피 값만 실렸다 [3].
