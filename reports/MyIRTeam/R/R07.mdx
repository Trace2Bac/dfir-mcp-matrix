# R07 증거 내용과 지시 구분

### R07.01 JSON 필드 분리

**구현.** 이 방식은 세 증거 서버가 `dict`를 돌려주는 도구 전체와 기본 형식 `evidence_v1`의 모든 응답에 적용된다 [1][2].
세 증거 서버의 도구는 반환 형식을 `Any`로 적으므로 MCP Python SDK 1.28.1은 결과를 `structuredContent` 없이 `text` 내용 하나로 보낸다 [1][3].
SDK는 `dict` 결과를 JSON 글로 바꾸고 문자열 결과는 그대로 싣는다 [1].
`evidence_v1` 응답은 도구 결과를 `data` 필드에 넣고 서버가 만든 상태, 오류, 제한 사항을 `status`·`errors`·`limitations`에 따로 둔다 [2].
그래서 `evidence_v1`에서는 Sysinternals 출력처럼 문자열인 결과도 `data`의 JSON 문자열 값으로 실린다 [2][4].
증거 값은 `processes`·`records`·`evidence` 같은 필드의 값으로 들어가고 서버 문구는 `note`·`disclaimer`·`warnings`에 따로 있다 [5][6][7].

네 서버의 초기화 지침, 도구 설명, 응답 어디에도 증거에서 온 글 속의 지시를 따르지 말라는 안내는 없다 [8].

**한계.** `legacy` 형식에서 `collect_autoruns`·`check_file_signatures`·`list_network_connections`·`list_open_handles`는 Sysinternals 출력을 JSON 없이 글 그대로 돌려준다 [4][9].
실행 파일이 0이 아닌 코드로 끝나면 `run_sysinternals_tool`은 서버 문장 `Error: <도구> exited with code N.` 뒤에 도구 출력을 이어 붙인 글 하나를 만든다 [9].
`evidence_v1`에서도 이 글은 `data` 값 하나와 `errors`의 `message` 하나로 실린다 [2][10].

서버 문장 안에 증거에서 온 글을 넣는 곳이 있다.
`ir-collect`의 `_safe_extract_zip`은 ZIP 항목 이름을 `unsafe ZIP member path (traversal): …` 같은 오류 문장 끝에 넣는다 [11].
`artifact-forensic`은 capa·YARA의 표준 오류를 `warnings`에 넣고 경고를 `; `로 이어 `note`를 만든다 [12].
`evidence_v1`은 이 `note`를 `limitations`의 `message`로 옮긴다 [10].
IR_Collect 0.24.2의 Guided Hunt `evidence` 줄은 사용자, 경로, 상세 설명을 `user=`·`path=`·`detail=` 머리말과 ` | `로 이은 문자열이고 서버는 이 줄을 그대로 싣는다 [13][5].
그래서 값 안에 ` | path=` 같은 글이 있으면 다른 칸과 구별되지 않는다 [13].
YARA 실행 파일(`yara64.exe`) 경로는 규칙 이름, 태그, 메타데이터, 파일 경로를 담은 출력 줄을 `raw_match_line` 하나로 싣는다 [14].

### R07.02 출처 필드 부여

**구현.** 이 방식은 `evidence_v1` 응답의 `tool`·`provenance`, `ir-collect`·`artifact-forensic` 결과의 `provenance`, EZ Tools 레코드의 `source_csv`, YARA 결과의 `backend`에 적용된다 [2][15][16][17][18].
`evidence_v1` 응답은 `tool`에 `<서버>/<도구>` 이름을, `provenance.producer`에 서버 이름을 싣는다 [2].
`artifact-forensic`은 `provenance.tool_name`에 결과를 만든 분석 도구 이름(`EvtxECmd`·`Hayabusa`·`capa`·`YARA-X` 등)을 싣는다 [15].
외부 분석 도구를 실행한 결과는 그 실행 파일의 SHA-256을 `provenance.analyzer_sha256`에 싣는다 [15].
`ir-collect`는 IR_Collect가 보고서에 적은 `tool_name`·`tool_version`·`export_schema`를 `provenance`에 옮긴다 [16].
`read_csv_outputs`는 레코드마다 그 행이 나온 CSV 파일 이름 `source_csv`를 싣는다 [17].
YARA 도구는 `backend`에 `yara_x`나 `yara`를 싣는다 [18].
`evidence_v1` 응답은 결과의 `provenance`에서 `tool_name`·`tool_version`·`evidence_digest` 등 9개 키를 최상위 `provenance`로 옮긴다 [2].

**한계.** `local-forensic`의 결과에는 `provenance`가 없어 `legacy` 형식에서는 출처를 적는 필드가 없다 [19].
`evidence_v1`에서도 `local-forensic`의 `provenance`에는 `producer`만 있고 PowerShell과 Sysinternals 가운데 어느 쪽이 값을 만들었는지는 없다 [2][19].
결과에는 값의 신뢰 수준을 적는 필드가 없다 [2].
