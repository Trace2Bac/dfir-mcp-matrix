# R02 대량 결과 전달

### R02.01 문자·항목 상한

**구현.** 이 방식은 `local-forensic`의 PowerShell 도구 일부, `ir-collect`의 보고서 정리 함수, `artifact-forensic`의 도구 전체에 적용된다 [1][2][3].
서버 전체에 응답 글자 수 상한은 없고 도구마다 항목 수 상한을 둔다.

`local-forensic`은 다음 상한을 둔다 [4][5].

- `collect_event_log_events`는 `max_events`(1~1,000, 기본값 200)개까지 읽는다 [1].
- `collect_ir_event_bundle`은 채널 8개마다 `max_events_per_channel`(1~1,000, 기본값 200)개까지 읽는다 [4].
- `list_scheduled_tasks`는 `max_tasks`(1~500)개, `collect_defender_context`는 탐지 `max_detections`(1~500)개, `collect_network_context`는 DNS 캐시·경로·이웃 항목을 각각 `max_entries`(1~1,000)개까지 싣는다 [5].
- `list_services`는 서비스 500개까지 싣는다 [5].

`ir-collect`의 정리 함수는 다음 상한을 둔다 [2].

- Guided Hunt 일치마다 `evidence` 줄 8개, `parser_notes`·`load_warnings` 각 50개
- `correlation_v1`의 `shared_entities` 100개, `temporal_correlations` 100개, `hosts` 50개
- `graph_v1`의 `nodes` 300개, `edges` 600개

`artifact-forensic`은 다음 상한을 둔다 [3].

- EZ Tools와 Hayabusa 레코드는 `max_records`(1~1,000, 기본값 500)개
- capa 규칙은 `max_capabilities`(1~500)개, YARA 일치는 `max_matches`(1~1,000)개
- 문자열은 `max_strings`(1~500)개, 파일 목록은 `max_files`(1~5,000)개, ZIP 항목은 `max_members`(1~10,000)개, 해시 목록 항목은 `max_entries`(1~1,000)개
- 해시 목록의 형식이 맞지 않는 줄과 CSV·JSONL 파싱 오류는 각 20개

`artifact-forensic`은 EZ Tools, capa, YARA·YARA-X를 실행할 때 표준 출력, 표준 오류, 출력 폴더의 파생물을 합쳐 16 MiB(`MAX_STATIC_OUTPUT_BYTES`)를 넘으면 그 도구를 멈춘다 [6].

응답 형식은 이 상한을 바꾸지 않는다.
`evidence_v1` 응답은 결과를 줄이지 않고 `data`에 넣는다 [7].

**한계.** `local-forensic`의 `collect_autoruns`·`check_file_signatures`·`list_network_connections`·`list_open_handles`·`list_running_processes`·`build_process_tree_snapshot`·`list_loaded_dlls`·`list_wmi_subscriptions`·`list_local_users_and_admins`·`get_file_metadata`는 출력이나 행 수에 상한을 두지 않는다 [8][9].
`check_file_signatures_batch`는 경로를 32개(`MAX_BATCH_FILES`)까지 받지만 경로마다의 Sigcheck 출력 길이에는 상한을 두지 않는다 [9].
`list_services`는 PowerShell에서 500개로 자르고 `service_count`에 자른 뒤의 수를 싣는다 [5].
`collect_event_log_events`의 `count`도 상한까지 읽은 수이고 상한에 닿았는지는 응답에 없다 [1].
`ir-collect`는 Guided Hunt 일치 수와 가설 틀 수에 상한을 두지 않는다 [2].
Hayabusa 레코드는 값 길이를 줄이지 않으므로 JSONL 한 줄이 2 MiB까지 그대로 실린다 [10].
그래서 Hayabusa 응답의 크기는 레코드 수 상한과 줄 길이 상한으로만 정해진다 [10].
Hayabusa는 `run_hayabusa`로 실행하므로 표준 출력, 표준 오류, JSONL 출력 파일의 크기에 상한이 없다 [11].
YARA 실행 파일(`yara64.exe`)에는 `-l`로 `max_matches`를 넘긴다 [12].
YARA 4.5.5의 `-l`은 그 수만큼 규칙이 일치하면 검사를 멈추므로 서버가 센 `match_count`는 `max_matches`를 넘지 않는다 [13][12].

### R02.02 전체·반환 건수 표시

**구현.** 이 방식은 `artifact-forensic`의 목록 결과와 `ir-collect`의 `correlation_v1`·`graph_v1` 결과에 적용된다 [3][2].
`artifact-forensic`은 상한을 둔 목록마다 전체 수와 반환 수를 따로 싣고 `truncated`를 둔다 [3].

- EZ Tools와 Hayabusa는 `record_count`와 `returned_record_count`
- capa는 `capability_count`와 `returned_capability_count`, YARA는 `match_count`와 `returned_match_count`
- `inventory_evidence_path`는 `discovered_file_count`와 `returned_file_count`, `inventory_archive_members`는 `member_count`와 `returned_member_count`
- `verify_sha256_manifest`는 `valid_entry_count`와 `returned_entry_count`

Hayabusa 도구를 뺀 도구는 목록을 자르면 `warnings`에 자른 상한을 적는 문구를 더하고 `status`를 `DEGRADED`로 둔다 [14].
`ir-collect`는 `shared_entity_count`·`temporal_correlation_count`에 자르기 전의 수를 싣고 둘 가운데 하나라도 100개를 넘으면 `truncated`를 참으로 둔다 [2].
`graph_v1` 결과는 IR_Collect가 적은 `node_count`·`edge_count`를 옮기고 `nodes`·`edges`를 자르면 `truncated`를 참으로 둔다 [2].
`shared_entities` 105개 보고서는 `shared_entity_count` 105, 실린 항목 100개, `truncated` 참으로, 노드 305개 보고서는 `node_count` 305, 실린 노드 300개, `truncated` 참으로 돌아왔다 [15].
`evidence_v1` 응답은 결과의 `note`를 `limitations`에 옮기므로 자른 상한을 적은 문구가 `limitations`에도 실린다 [7][15].

**한계.** `ir-collect`는 반환 수를 따로 싣지 않으므로 반환 수는 목록 길이로만 알 수 있다 [2].
`truncated`는 `shared_entities`와 `temporal_correlations` 가운데 어느 쪽을 잘랐는지 구별하지 않는다 [2].
`hosts`, `parser_notes`, `load_warnings`, Guided Hunt `evidence`를 자른 사실은 응답에 없다 [2].
IR_Collect 0.24.2는 규칙마다 정한 수(4~8개)까지만 사실을 골라 `fact_ids`와 `evidence`를 같은 수로 채우므로 이 버전의 요약에서는 `evidence`가 8줄에서 잘리지 않는다 [16][17].
다른 곳에서 만든 보고서의 `evidence`가 8줄을 넘으면 서버는 앞 8줄만 싣고 `fact_id_count`에는 `fact_ids` 전체의 수를 싣는다 [2].
`inventory_evidence_path`의 `returned_total_bytes`·`extension_counts`는 반환한 파일만 센 값이다 [18].
YARA 실행 파일 경로의 `match_count`는 `-l`에서 멈춘 수라서 `truncated`가 참이 되지 않는다 [12][13].
Hayabusa 도구는 레코드를 `max_records`에서 잘라도 `truncated`만 참으로 두고 `warnings`와 `status`는 바꾸지 않는다 [19].

### R02.05 상한 초과 시 거부

**구현.** 이 방식은 `artifact-forensic`의 capa 도구와 YARA 도구에 적용된다 [20][21].
두 도구는 외부 도구 출력이 16 MiB를 넘어 실행을 멈추면 결과를 싣지 않고 `error`와 표준 오류를 담은 `details`만 돌려준다 [20][21].

**한계.** 같은 상한을 쓰는 EZ Tools 도구는 거부하지 않는다 [14][6].
EZ Tools 도구는 상한에서 멈춘 뒤 그때까지 쓴 CSV를 읽어 돌려주고 경고 문구만 더한다 [14].

### R02.06 값 단위 잘림

**구현.** 이 방식은 `artifact-forensic`의 문자열 값, `local-forensic`의 사건 메시지, `artifact-forensic`·`ir-collect`의 오류 출력, `evidence_v1` 응답의 `target.identifier`에 적용된다 [22][1][23][24][7].
`artifact-forensic`의 `_bounded_text`는 값을 2,000자(`MAX_TEXT_FIELD`)에서 자르고 `...[TRUNCATED]`를 붙인다 [22].
EZ Tools CSV의 열 값, capa 규칙 필드, YARA-X 일치 필드, 경고 문구로 옮기는 외부 도구의 표준 오류에 이 함수가 적용된다 [22][25].
2,515자 `Payload` 값은 앞 2,000자 뒤에 `...[TRUNCATED]`가 붙은 2,014자로 실렸다 [15].
추출한 문자열은 500자, 해시 목록의 잘못된 줄은 500자, YARA 실행 파일의 출력 줄은 8,000자에서 같은 방식으로 자른다 [26].
`local-forensic`의 사건 조회 스크립트는 사건 메시지를 12,000자에서 자르고 `...[TRUNCATED]`를 붙인다 [1].
외부 도구가 결과 파일을 만들지 못하면 `artifact-forensic`은 표준 오류나 표준 출력의 앞 4,000자를, `ir-collect`는 앞 2,000자를 표시 없이 싣는다 [23][24].
`local-forensic`은 Sysinternals 도구와 PowerShell의 오류 출력을 자르지 않고 싣는다 [27].
`evidence_v1` 응답은 대상 식별자가 2,048자를 넘으면 자르고 끝에 원래 값의 SHA-256을 적는다 [7].
3,000자 경로를 준 호출의 `target.identifier`는 `...[TRUNCATED sha256=…]`로 끝나는 2,048자였다 [28].

**한계.** `local-forensic`의 사건 `properties` 값과 PowerShell 도구가 싣는 다른 문자열은 길이를 줄이지 않는다 [1][5].
`evidence_v1` 응답의 `errors` 문구와 `data` 안의 같은 경로는 줄이지 않는다 [7][28].

### R02.07 건수 없는 잘림 표시

**구현.** 이 방식은 `artifact-forensic`의 `inspect_binary_file`과 `inspect_archive_member_binary`의 문자열 목록에 적용된다 [29].
`extract_bounded_strings`는 `max_strings`개가 차면 읽기를 멈추고 `truncated`를 참으로 둔다 [29].
응답에는 반환한 수 `returned_string_count`만 있고 파일 전체의 문자열 수는 없다 [29].
`max_strings`를 2로 준 호출은 문자열 2개와 `truncated` 참, 경고 문구 `Returned strings were truncated at max_strings=2.`를 돌려줬다 [15].

def _bounded_identifier(value: Any) -> str:
    text = str(value or "unspecified").strip() or "unspecified"
    if len(text) <= MAX_TARGET_IDENTIFIER_LENGTH:
        return text
    digest = hashlib.sha256(text.encode("utf-8", errors="replace")).hexdigest()
    suffix = f"...[TRUNCATED sha256={digest}]"
    return text[: MAX_TARGET_IDENTIFIER_LENGTH - len(suffix)] + suffix

```python
def extract_bounded_strings(path: Path, max_strings: int) -> dict[str, Any]:
    values: list[dict[str, str]] = []
    seen: set[tuple[str, str]] = set()
    truncated = False
    carry = b""
    with open(path, "rb") as handle:
        for chunk in iter(lambda: handle.read(1024 * 1024), b""):
            data = carry + chunk
            for encoding, pattern in (("ascii", ASCII_STRING_RE), ("utf-16le", UTF16LE_STRING_RE)):
                for match in pattern.finditer(data):
                    raw = match.group(0)
                    text = raw.decode(encoding, errors="replace")
                    key = (encoding, text)
                    if key in seen:
                        continue
                    seen.add(key)
                    if len(values) >= max_strings:
                        truncated = True
                        break
                    values.append({"encoding": encoding, "value": _bounded_text(text, 500) or ""})
                if truncated:
                    break
            if truncated:
                break
            carry = data[-4096:]
    return {"strings": values, "returned_string_count": len(values), "truncated": truncated}
```
