# L01 기록 방식

### 미구현

**판단.** 네 서버 모두 MCP 도구 호출을 기록하는 코드가 없다 [1].
`myirteam-core`, `local-forensic`, `ir-collect`, `artifact-forensic`의 서버 파일과 공통 모듈 `myirteam_common/evidence.py`, 실행기 `portable_mcp.py`는 `logging` 모듈을 불러오지 않는다 [1].
네 서버 코드에서 파일을 쓰는 곳은 분석 도구의 출력을 받는 실행 폴더, 증거 폴더의 작업 사본, ZIP을 푼 폴더뿐이다 [2].
도구 호출을 적는 파일이나 DB는 없다 [2].

네 서버는 MCP Python SDK의 `FastMCP`로 도구를 등록한다 [3].
MCP Python SDK 1.28.1의 `FastMCP`는 만들어질 때 `configure_logging`으로 루트 로거를 `INFO` 수준으로 설정한다 [3].
이 설정은 `rich`가 없으면 형식 `%(message)s`의 `StreamHandler`를 붙인다 [3].
SDK의 요청 처리기는 요청마다 `Processing request of type CallToolRequest`처럼 요청 종류만 `INFO`로 쓴다 [4].
이 줄에는 도구 이름과 인자가 없다 [4].
목록에 없는 도구 이름이 오면 SDK는 그 이름을 담은 `WARNING` 줄을 쓴다 [4].
도구 함수에서 예외가 나면 SDK는 오류 결과를 돌려주고 로그를 쓰지 않는다 [5].
그래서 등록된 도구의 호출에는 도구 이름도 인자도 담지 않는 SDK의 진단 줄만 남는다 [4][5].
네 서버를 `portable_mcp.py`로 실행해 성공하는 호출, 오류 응답을 돌려주는 호출, 필수 인자를 뺀 호출, 목록에 없는 이름을 부른 호출을 보냈다 [6].
표준 오류에 남은 도구 호출의 줄은 `Processing request of type …` 줄과 목록에 없는 이름의 경고 줄뿐이었다 [6].
같은 실행에서 서버 사본 폴더와 작업 폴더에 새로 생긴 파일은 없었다 [6].

같은 저장소의 클라이언트 설정, 훅, 사용자 CLI에도 MCP 도구 호출을 기록하는 코드가 없다.
사용자 CLI `portable_setup.py`는 서버 4개의 실행 명령과 환경변수만 담은 클라이언트 설정 파일을 만든다 [7].
AGY 클라이언트용 지침 `.agents/agents.md`는 증거를 모으는 역할에게 도구 호출마다 시점과 범위를 기록하라고 적는다 [8].
같은 문서는 사용자가 요청하지 않으면 보고서 파일을 만들지 말고 대화에만 돌려주라고 적는다 [8].
이 기록은 클라이언트 모델이 안내문에 따라 대화에 쓰는 글이고 코드가 남기는 기록이 아니다.

현장 수집 스크립트 `usb-collect/COLLECT.bat`은 `IR_Collect.exe` 수집을 마치면 `collection_log.txt`에 시각, 호스트, 사용자 이름, 증거 파일 이름, 종료 코드를 한 줄 덧붙인다 [9].
이 줄은 MCP 서버를 거치지 않는 수집 실행의 기록이다 [9].
`IR_Collect.exe` 0.24.2는 실행 파일 옆 `logs/ir_collect.log`에 자기 정보, 경고, 오류 줄을 덧붙여 쓴다 [10][11].
이 파일은 분석 도구의 기록이다 [10].
