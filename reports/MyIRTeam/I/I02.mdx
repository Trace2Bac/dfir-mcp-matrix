# I02 분석 도구 통신 차단

### I02.02 DNS 조회 끄기

**구현.** 이 방식은 `local-forensic`의 `list_network_connections`가 실행하는 `tcpvcon.exe`에 적용된다 [1].
`list_network_connections`는 `tcpvcon.exe`에 `-a`, `-c`, `-n`을 넘기고 프로세스 식별자를 받으면 그 뒤에 붙인다 [1].
실행기 `run_sysinternals_tool`은 모든 Sysinternals 도구의 인자 앞에 `-accepteula`만 더한다 [2].
Microsoft 문서는 Tcpvcon의 `-n`을 주소를 이름으로 바꾸지 않는 옵션으로 적는다 [3].
같은 문서는 TCPView가 시작할 때 모든 IP 주소를 도메인 이름으로 바꾼다고 적는다 [3].
그래서 Microsoft 문서에 따르면 이 도구가 돌려주는 연결 목록의 주소는 이름으로 바뀌지 않는다 [1][3].
`safe_tool_path`가 인자를 기록하는 시험용 실행 파일을 돌려주게 바꿔 `list_network_connections`를 부르자 `-accepteula -a -c -n`이 기록되었다 [4].
PID를 주자 그 PID가 `-n` 뒤에 붙었다 [4].

서버가 실행하는 다른 분석 도구에는 통신을 끊거나 끄는 장치가 없다.
실행 함수 `run_sysinternals_tool`·`run_powershell_json`(`local-forensic`), `run_ircollect`(`ir-collect`), `run_hayabusa`·`run_static_tool`·`probe_version`(`artifact-forensic`)은 하위 프로세스의 네트워크를 끊는 설정을 주지 않는다 [2][5].
`run_powershell_json`은 서버 환경변수의 사본에 스크립트 값만 더해 넘긴다 [2].
나머지 실행 함수는 `env`를 주지 않아 하위 프로세스가 서버 환경을 그대로 물려받는다 [2][5].
저장소에는 분석 도구를 네트워크 없는 컨테이너나 방화벽 규칙 아래에서 실행하는 구성이 없다.

`local-forensic`의 다른 Sysinternals 도구에 넘기는 인자에는 통신을 끄는 옵션이 없다 [6].

- `sigcheck.exe`에는 `-a -h -i -ct -nobanner`와 파일 경로를 넘긴다 [6].
- Microsoft 문서는 Sigcheck의 `-r`을 인증서 폐기 확인을 끄는 옵션으로 적는다 [7].
- 서버는 `sigcheck.exe`에 `-r`을 넘기지 않는다 [6].
- 폐기 확인이 외부 통신을 여는지는 문서에 없어 확인하지 못했다 [7].
- `autorunsc.exe`에는 `-a`, 범주, `-ct`, `-nobanner`만 넘기고 서명 확인 `-s`와 VirusTotal 조회 `-v`는 넘기지 않는다 [6][8].
- `handle.exe`에는 `-nobanner`와 대상만 넘긴다 [6].

`artifact-forensic`의 분석 도구도 통신을 끄는 옵션 없이 실행된다 [9][10].

- Hayabusa 3.10.0에는 `json-timeline`과 출력·표시 옵션을 넘긴다 [9].
- Hayabusa 3.10.0에서 원격 요청은 GitHub API로 최신 버전을 묻고 규칙을 내려받는 `update-rules` 처리에만 있다 [11].
- 서버는 Hayabusa의 `update-rules`를 부르지 않는다 [9].
- EvtxECmd와 RECmd는 `--sync`를 줄 때만 GitHub에서 맵이나 배치 파일을 내려받는다 [12].
- `--sync`의 기본값은 거짓이다 [12].
- 서버는 EZ Tools에 `-f`, `-q`, `--bn`, `--nl`, `--csv`, `--csvf`만 넘기고 `--sync`를 넘기지 않는다 [10].
- PECmd, MFTECmd, AmcacheParser의 `Program.cs`에서는 내려받기 코드를 찾지 못했고 이 도구들이 쓰는 라이브러리는 확인하지 않았다 [13].
- capa 7.1.0의 `capa` 패키지, YARA-X 1.19.0의 `cli`·`lib`, YARA 4.5.5의 `cli`·`libyara`에서는 네트워크 연결 코드를 찾지 못했고 의존 라이브러리는 확인하지 않았다 [14].

`ir-collect`가 실행하는 `IR_Collect.exe` 0.24.2에서 HTTP 요청을 보내는 코드는 GUI에만 있고 `-analyze`, `-correlate`, `-graph`, `-c` 경로에는 없다 [15].
`IR_Collect.exe`는 서명을 확인할 때 `WinVerifyTrust`에 폐기 확인을 끄는 값을 스스로 넣는다 [16].
이 값은 분석 도구가 정한 것이고 서버가 넘기는 옵션이 아니다 [16].

`local-forensic`의 `get_file_metadata`·`check_file_signatures`·`check_file_signatures_batch`는 파일 경로 인자를 `normalize_file_path`로 정리하고 이 함수는 빈 값만 거부하므로 네트워크 공유를 가리키는 UNC 경로도 거부하지 않는다 [17].
그 경로를 PowerShell과 `sigcheck.exe`가 열 때 운영체제가 그 호스트로 네트워크 연결을 여는지는 실행해 보지 않아 확인하지 못했다 [17].

**한계.** Tcpvcon의 소스가 공개되어 있지 않아 `-n`을 주었을 때 이름 풀이를 전혀 하지 않는지는 Microsoft 문서로만 확인했고 실행 파일로 확인하지 못했다 [3].
