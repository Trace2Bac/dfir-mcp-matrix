# E04 분석 입력 준비

### E04.01 작업 사본 생성

**구현.** 이 방식은 `ir-collect`의 `analyze_artifact_folder`, `correlate_hosts`, `expand_investigation_graph`, `analyze_triage_zip`에 적용된다 [1][2][3].
세 폴더 도구는 `work_on_copy`가 참(기본값)이면 받은 폴더마다 작업 폴더 아래 `input_<이름>`(`correlate_hosts`·`expand_investigation_graph`는 `input_<번호>_<이름>`) 폴더로 전체를 복사하고 사본을 `IR_Collect.exe`에 넘긴다 [1][2].
복사는 링크와 접합점을 따라가지 않고 폴더 안에 링크나 일반 파일이 아닌 항목이 있으면 복사를 멈추고 오류를 돌려준다 [4].
`analyze_triage_zip`은 ZIP 항목 전체를 작업 폴더의 `extracted` 폴더에 풀고 그 폴더를 `IR_Collect.exe`에 넘긴다 [3].
풀기 전에 모든 항목의 경로, Windows 이름, 대소문자만 다른 중복, 링크, 암호화, 크기, 압축률, 항목 수를 검사하고 하나라도 맞지 않으면 아무것도 풀지 않는다 [5].
풀면서 항목마다 선언한 크기와 실제로 풀린 크기를 대조한다 [5].
사본과 풀어 낸 파일은 호출이 끝나면 작업 폴더째 지운다 [1][3].

`artifact-forensic`의 파일 도구는 원본을 제자리에서 분석 도구에 넘기고 사본을 만들지 않는다 [6].
서버에는 디스크 이미지를 마운트하는 코드가 없다.

**한계.** `work_on_copy`를 거짓으로 주면 사본을 만들지 않고 원본 폴더를 넘긴다 [2][7].
그 호출에서 시험용 `IR_Collect.exe`가 받은 경로는 원본 폴더였다 [8].

### E04.02 선택 추출

**구현.** 이 방식은 `artifact-forensic`의 ZIP 항목 도구 5개에 적용된다 [9].
`inspect_archive_member_binary`, `parse_archive_member_with_eztools`, `analyze_evtx_archive_member_with_hayabusa`, `analyze_archive_member_with_capa`, `scan_archive_member_with_yara`는 모델이 준 `member_path`와 정확히 같은 이름의 항목 하나를 고른다 [10].
같은 이름의 항목이 없거나 둘 이상이면 오류를 돌려준다 [10].
고른 항목은 경로·링크·암호화·크기·압축률을 검사하고 작업 폴더 아래 `archive_member_<난수>\member`에 원래 파일 이름으로 꺼낸다 [10][11].
`parse_archive_member_with_eztools`의 `registry`는 함께 고른 로그 항목도 같은 폴더에 꺼낸다 [11].
분석 함수는 꺼낸 사본이 있는 폴더만 증거 폴더로 둔 설정으로 부르므로 사본만 읽는다 [12].
`deep-analysis` 워크플로 문서는 모든 항목을 분석하지 말고 필요한 항목만 고르라고 적고 Shell이나 임시 스크립트로 항목을 풀지 말라고 적는다 [13].

### E04.04 추출·생략 범위 기록

**구현.** 이 방식은 `ir-collect`의 `analyze_artifact_folder`·`analyze_triage_zip`과 `artifact-forensic`의 ZIP 항목 도구에 적용된다 [1][3][14].
`analyze_artifact_folder`는 복사한 파일 수와 바이트 수를 `copy_summary`에 싣고 `provenance.analyzed_copy`에 사본을 분석했는지 적는다 [1].
`analyze_triage_zip`은 `archive_extraction`에 ZIP 크기, 항목 수, 풀어 낸 파일 수, 선언한 크기와 풀어 낸 바이트 수, 적용한 한도를 싣는다 [3][15].
ZIP 항목 도구는 응답 `input`에 ZIP 경로와 해시 전후, 항목 경로, 크기, 압축 크기, CRC32, 이름 분류, 사본 해시 전후를 싣는다 [14].
함께 꺼낸 로그 항목마다 경로, 크기, 압축 크기, CRC32, 이름 분류, 꺼낼 때 계산한 SHA-256을 싣는다 [14][16].
작업 폴더의 경로는 응답 글에서 `<ZIP 경로>::<항목 경로>`와 `[internal work directory]`로 바꾼다 [14].
시험용 ZIP으로 부른 실행에서 `archive_extraction`은 항목 8개와 풀어 낸 파일 8개를, 레지스트리 항목 응답은 로그 항목 2개의 크기·CRC32·해시를 실었다 [8].

`correlate_hosts`와 `expand_investigation_graph`는 `analyzed_copy`와 받은 폴더 경로만 싣고 복사한 파일 수를 싣지 않는다 [17].

**한계.** `copy_summary`와 `archive_extraction`은 건수와 바이트 수만 싣고 복사하거나 풀어 낸 파일의 목록은 싣지 않는다 [1][15].

### E04.07 로그 재생·복원

**구현.** 이 방식은 `artifact-forensic`의 `parse_archive_member_with_eztools`에서 `artifact_type`이 `registry`인 호출에 적용된다 [18].
모델이 `companion_member_paths`로 고른 하이브의 `.LOG1`·`.LOG2` 항목을 서버가 하이브 사본과 같은 폴더에 같은 이름으로 꺼낸다 [11][19].
로그를 하나라도 받으면 RECmd에 `--nl`을 넘기지 않고 받지 않으면 넘긴다 [18][20].
응답과 `provenance`의 `registry_transaction_logs_requested`에 로그를 받았는지를 싣는다 [20].
로그 두 개를 준 실행에서 시험용 RECmd가 받은 인자에는 `--nl`이 없었고 입력 폴더에는 `SYSTEM`, `SYSTEM.LOG1`, `SYSTEM.LOG2`가 있었다 [8].
로그를 주지 않은 실행에서는 `--nl`이 있었고 입력 폴더에는 `SYSTEM`만 있었다 [8].

RECmd 2026.5.0(`bcd0ac3`)은 하이브의 두 순서 번호가 다르면 같은 폴더에서 `<하이브 이름>.LOG?` 파일을 찾아 Registry 라이브러리로 메모리에서 적용한다 [21].
RECmd의 `--nl`은 dirty 하이브에 로그가 없어도 계속하라는 옵션이다 [22].
`--nl`이 없고 로그도 없으면 RECmd는 그 하이브를 처리하지 않고 `--nl`이 있으면 경고를 남기고 로그 없이 읽는다 [21].
로그가 있으면 `--nl`과 관계없이 적용한다 [21].
응답의 `registry_transaction_logs_requested`는 서버가 로그를 넘겼는지만 적고 하이브가 dirty였는지나 RECmd가 로그를 적용했는지는 적지 않는다 [20].

`amcache` 유형에는 로그를 함께 꺼내지 않는다 [18].
AmcacheParser 2026.5.0은 `--nl`이 없으면 dirty 하이브 옆에 로그가 없을 때 처리를 멈추고 서버는 AmcacheParser에 `--nl`을 넘기지 않는다 [23][20].
그래서 ZIP 항목의 dirty `Amcache.hve`는 AmcacheParser가 처리하지 않고 서버는 CSV가 없다는 오류를 돌려준다 [23][24].
ZIP이 아닌 `Amcache.hve`를 받으면 AmcacheParser가 증거 폴더에서 하이브 옆의 로그를 스스로 찾아 dirty 하이브에 적용한다 [23][20].
이 경로에서도 dirty 하이브 옆에 로그가 없으면 서버는 CSV가 없다는 오류를 돌려준다 [23][24].
EVTX·Prefetch·NTFS 유형에는 부속 자료를 다루는 처리가 없다.

**한계.** ZIP이 아닌 하이브를 받는 `parse_windows_artifact_with_eztools`는 `registry`에 늘 `--nl`을 넘기고 `registry_transaction_logs_requested`를 거짓으로 싣는다 [20].
이 경로의 RECmd는 증거 폴더에서 하이브 옆의 `.LOG1`·`.LOG2`를 스스로 찾아 dirty 하이브에 적용한다 [21].
그래서 dirty 하이브 옆에 로그가 있으면 `registry_transaction_logs_requested`가 거짓이어도 RECmd가 로그를 적용한 결과가 돌아온다 [20][21].
하이브 옆에 `SYSTEM.LOG1`을 둔 실행에서 시험용 RECmd가 받은 인자에는 `--nl`이 있었고 입력 폴더 목록에 `SYSTEM.LOG1`이 있었다 [8].
`AI_AGENT_GUIDE.md`는 로그 항목을 함께 고를 때만 RECmd가 로그를 적용한다고 적는다 [25].
RECmd가 남기는 dirty 하이브 경고는 RECmd의 출력에만 남고 서버는 CSV가 있으면 RECmd의 출력을 응답에 싣지 않는다 [24].
실제 RECmd와 AmcacheParser로 로그 적용을 실행해 확인하지 않았다.

```python
            dst = work / f"input_{i}_{src.name}"

            targets.append(dst)
```

```python
def select_zip_member(
    archive: zipfile.ZipFile,
    member_path: str,
    cfg: Config,
) -> tuple[zipfile.ZipInfo, str]:
    normalized = normalize_archive_member(member_path)
    if len(archive.infolist()) > MAX_ARCHIVE_MEMBERS:
        raise ValueError(
            f"archive contains more than the {MAX_ARCHIVE_MEMBERS}-member safety limit."
        )
    matches = [
        info
        for info in archive.infolist()
        if info.filename.replace("\\", "/") == normalized
    ]
    if not matches:
        raise ValueError(f"archive member was not found: {normalized}")
    if len(matches) != 1:
        raise ValueError(f"archive member name is ambiguous ({len(matches)} entries): {normalized}")
    info = matches[0]
    validate_zip_member_info(info, cfg)
    return info, normalized
```

```python
def validate_archive_companion_paths(
    primary_member: str,
    companion_member_paths: list[str] | None,
) -> list[str]:
    """Allow only adjacent Registry transaction logs for one selected hive."""
    companions = list(companion_member_paths or [])
    if len(companions) > MAX_ARCHIVE_COMPANION_MEMBERS:
        raise ValueError(
            f"companion_member_paths accepts at most {MAX_ARCHIVE_COMPANION_MEMBERS} entries."
        )
    primary = PurePosixPath(primary_member)
    allowed_names = {
        f"{primary.name}.LOG1".casefold(),
        f"{primary.name}.LOG2".casefold(),
    }
    normalized: list[str] = []
    seen: set[str] = set()
    for value in companions:
        candidate = normalize_archive_member(value)
        pure = PurePosixPath(candidate)
        if pure.parent != primary.parent or pure.name.casefold() not in allowed_names:
            raise ValueError(
                "Registry companions must be the selected hive's same-directory .LOG1/.LOG2 files."
            )
        folded = candidate.casefold()
        if folded in seen:
            raise ValueError(f"duplicate companion member requested: {candidate}")
        seen.add(folded)
        normalized.append(candidate)
    return normalized
```
