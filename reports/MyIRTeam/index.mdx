# MyIRTeam 원고

이 파일은 서버 개요다. 셀마다 이 폴더 아래 축 폴더의 `<축>/<셀ID>.mdx`에 쓴다.
셀과 상세 항목의 정의는 `matrix/cells/<축>/<셀ID>.mdx`를 따른다.
상세 항목마다 **구현**을 쓰고 그 방식이 적용되지 않는 경로나 조건이 있으면 **한계**를 따로 쓴다.
본문의 [번호]는 그 파일 끝 **근거**의 같은 번호를 가리킨다.

**기준 커밋.** [`5fcaf7b`](https://github.com/9-Security/MyIRTeam/tree/5fcaf7b80e2ade67b9eabacd93d64c0cdeba829c)(2026-07-27).
줄 번호는 모두 이 커밋 기준이다.

**범위.** 저장소에 있는 stdio MCP 서버 4개를 한 서버로 본다.
네 서버는 같은 공통 모듈, 같은 실행기, 같은 능력 목록 파일을 쓰는 한 제품이다.
원고는 문장마다 어느 서버의 동작인지 밝힌다.

- `myirteam-core`(`core-mcp/server.py`)는 조사 요청에 맞는 워크플로를 고르고 능력 목록, 워크플로, 증거 응답 schema를 돌려주는 도구 5개를 둔다.
- `local-forensic`(`mcp-server/autoruns_mcp.py`, SDK에 등록한 이름은 `ForensicToolbox`)은 서버를 실행한 Windows 호스트를 PowerShell과 Sysinternals 도구로 읽는 도구 19개를 둔다.
- `ir-collect`(`ir-collect-mcp/server.py`)는 수집해 둔 아티팩트 폴더와 ZIP을 `IR_Collect.exe`로 분석하는 도구 6개와 기본으로 꺼진 수집 도구 `collect_triage_package`를 둔다.
- `artifact-forensic`(`artifact-forensic-mcp/server.py`)는 증거 파일과 ZIP 안 항목을 Zimmerman 도구, Hayabusa, capa, YARA-X로 분석하는 도구 14개를 둔다.

네 서버는 모두 MCP Python SDK의 `FastMCP`로 도구 45개를 등록하고 MCP 리소스와 프롬프트를 두지 않는다.
네 서버 모두 초기화 응답의 `instructions`에 공통 진입점과 지켜야 할 규칙을 싣는다.
`myirteam_common/evidence.py`는 세 증거 서버가 기본으로 쓰는 응답 형식 `evidence_v1`을 만드는 공통 모듈이다.
`portable_mcp.py`는 서버 ID를 받아 정해 둔 진입점 하나를 실행하는 실행기이고 저장소의 설정 예시는 네 서버를 모두 이 실행기로 등록한다.
`agent-manifest.json`, `workflows/`, `schemas/`, `External Tools/external_tools_manifest.json`, `yara-rules/`는 서버가 읽는 자료다.
Sysinternals 도구(`autorunsc.exe`, `sigcheck.exe`, `tcpvcon.exe`, `handle.exe`), Windows PowerShell, `IR_Collect.exe`, Zimmerman 도구, Hayabusa, capa, YARA-X(`yr.exe`), YARA(`yara64.exe`)는 서버 프로세스가 하위 프로세스로 실행하는 분석 도구로 본다.
`IR_Collect.exe`의 소스는 별도 저장소 `9-Security/IR_Collect`에 있다.

같은 저장소의 `AGENTS.md`, `CLAUDE.md`, `BOOTSTRAP.md`, `AI_AGENT_GUIDE.md`는 조사하는 모델에게 주는 지침이고 `.agents/`는 AGY 클라이언트용 MCP 설정, skill, 워크플로 문서다.
`portable_setup.py`는 저장소 위치에 맞춰 여러 클라이언트의 MCP 설정 파일을 만드는 사용자 CLI다.
`usb-collect/`는 사용자가 조사 대상 단말에서 `IR_Collect.exe`로 수집하는 현장 수집 스크립트와 문서다.
이 클라이언트 지침, 설정, 사용자 CLI는 상세가 클라이언트 쪽 방식을 묻는 경우, 클라이언트가 MCP 도구 호출을 기록하는 경우, 클라이언트가 서버 응답으로 보고 산출물을 만드는 경우에만 구현으로 세고 그 밖에는 원고에 사실로만 적는다.
`tests/`와 각 서버 폴더의 `tests/`는 서버 구현으로 세지 않는다.

**확인 방법.** 코드는 기준 커밋을 `git show`로 읽었다.
`IR_Collect.exe`와 외부 분석 도구의 동작은 아래 버전 기준의 소스로 확인했다.
근거의 "실행 확인"은 Windows 11 Pro(10.0.26200)에서 기준 커밋을 `git archive`로 풀어 둔 사본을 CPython 3.13.14와 MCP Python SDK 1.28.1로 실행해 본 결과다.
도구는 `portable_mcp.py`로 띄운 서버에 MCP SDK 클라이언트로 부르거나 서버 모듈을 같은 프로세스에서 불러 확인했다.
그 환경에는 Sysinternals 도구, `IR_Collect.exe`, Zimmerman 도구, Hayabusa, capa, YARA-X, YARA가 없었다.
없는 분석 도구는 받은 인자와 실행 조건을 기록하는 시험용 실행 파일로 바꿔 서버 쪽 처리만 확인했다.
`local-forensic`의 도구는 실행한 호스트를 읽으므로 이 호스트를 대상으로 실행하지 않았고 PowerShell과 Sysinternals 실행을 시험용 대체로 바꾼 호출과 인자 검사에서 끝나는 호출만 했다.
`collect_triage_package`는 켜지 않았다.

**외부 도구 버전 기준.** `External Tools/external_tools_manifest.json`이 도구마다 버전과 실행 파일의 SHA-256을 적는다.
버전이 적힌 도구는 그 버전의 소스 태그를 기준으로 한다.
배포된 실행 파일과 소스 태그가 같은 빌드인지는 확인하지 않았다.

- `IR_Collect.exe`: 0.24.2(`9-Security/IR_Collect` 태그 `v0.24.2`, `b32c3d7`)다.
- Hayabusa: 3.10.0(`Yamato-Security/hayabusa` 태그 `v3.10.0`, `3e96ff7`)이다.
- capa: 7.1.0(`mandiant/capa` 태그 `v7.1.0`, `482686a`)이다.
- YARA-X: 1.19.0(`VirusTotal/yara-x` 태그 `v1.19.0`, `fe40349`)이다.
- YARA: manifest에는 버전이 없고 서버 코드의 상수 `BUNDLED_YARA_VERSION`이 4.5.5를 적는다. 4.5.5(`VirusTotal/yara` 태그 `v4.5.5`, `f44a895`)를 기준으로 한다.
- Zimmerman 도구: manifest는 2026.5.0을 적는다.
  - EvtxECmd는 `EricZimmerman/evtx` 태그 `2026.5.0`(`634edf4`), AmcacheParser는 `EricZimmerman/AmcacheParser` 태그 `2026.5.0`(`434d34c`)이다.
  - PECmd, RECmd, MFTECmd에는 이 버전의 태그가 없어 기준 커밋 날짜(2026-07-27)의 기본 브랜치 커밋으로 확인한다. PECmd는 `12bb864`, RECmd는 `bcd0ac3`, MFTECmd는 `6aadd87`이다.
- Sysinternals 도구: manifest에 버전이 없고 소스가 공개되어 있지 않다. 동작은 Microsoft 문서로만 확인한다.
- Windows PowerShell: `local-forensic`은 `pwsh.exe`를 먼저 찾고 없으면 `powershell.exe`를 쓴다. 확인 환경에는 Windows PowerShell 5.1만 있었다.
- MCP Python SDK: 네 서버의 `requirements.txt`는 `mcp>=1.27,<2`만 적는다. 기준 커밋 날짜에 이를 만족하는 최신 릴리스인 1.28.1(`modelcontextprotocol/python-sdk` 태그 `v1.28.1`, `777b8d0`)을 기준으로 한다.
- Python: 서버 README는 3.10 이상을 적는다. 실행 확인에는 CPython 3.13.14를 썼다.

**바뀔 수 있는 것.** 범위와 외부 도구 버전 기준은 조사하며 맞지 않는 곳이 나오면 검토를 거쳐 바꾼다.
