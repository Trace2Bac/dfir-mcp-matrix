# R07 증거 내용과 지시 구분

### R07.01 JSON 필드 분리

**구현.** 분류 도구 연산의 응답은 JSON 객체 하나를 글로 바꾼 것이다 [1].
도구 출력은 `result`에 담기고 서버가 쓴 해석 주의·다음 작업 권고·추론 상태·가공 표시는 `forensic_context`·`suggested_next_actions`·`reasoning`·`inference_constraint`에 따로 담긴다 [1].
파서가 고른 의심 항목은 `anomalies`의 `affected_items` 목록에 담긴다 [1].
실패한 호출은 도구의 표준 오류를 `error`에 싣는다 [2].
`register_finding`은 근거 출력에서 고른 줄을 `provenance_snippets`의 `snippet`에 싣는다 [3].

서버는 이 필드 값이 증거에서 온 데이터라는 표시를 붙이지 않는다 [1].
조사 절차 문서와 MCP 프롬프트에도 증거에서 온 글 속의 지시를 따르지 말라는 안내가 없다 [4].
`escapeHtml`은 공격자가 정한 파일 이름이 html 보고서에서 HTML로 해석되지 않게 바꾸는 함수이고 모델에게 가는 응답에는 쓰지 않는다 [5].

**예외.** 파서가 만드는 이상 징후의 `description`은 서버 문장 안에 증거 값을 끼워 넣는다 [6].
regipy 파서는 지속성 키를 찾으면 `Persistence-related registry key:` 뒤에 증거의 키 이름을 붙인다 [6].
이벤트 로그 파서의 `affected_items`도 로그온 실패마다 시각과 `user=` 뒤의 계정 이름을 한 문자열로 잇는다 [7].

서버 안 처리기의 결과는 서버가 쓴 문장(`message`·`note`·`suggestion`)과 앞선 출력에서 뽑은 값이 한 JSON 글에 함께 들어간다 [8].
이 JSON 글은 기본 처리를 거쳐 `result.raw`의 문자열 값 하나가 된다 [9].
예를 들어 `list_event_logs`는 `.evtx`가 든 `fls` 줄을 `files`에, `detect_hidden_data`는 `mmls` 줄을 서버 문장 `Unallocated space:` 뒤에 붙여 `evidence`에 넣는다 [8].
