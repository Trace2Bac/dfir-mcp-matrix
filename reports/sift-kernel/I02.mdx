# I02 분석 도구 통신 차단

### 미구현

**판단.** sift-kernel은 분석 도구를 실행할 때 그 도구의 통신을 끊거나 끄는 장치가 없다.
분석 도구는 모두 `ProcessExecutor`가 실행하고 `execute`·`extractToFile`은 서버 프로세스의 환경변수에 `PATH`만 바꿔 넘긴다 [1].
서버 코드에서 실행기를 부르는 곳은 어느 것도 `env` 옵션을 넘기지 않는다 [2].
그래서 분석 도구는 서버 프로세스와 같은 네트워크 설정과 프록시 환경변수로 돈다 [1].

Volatility 3 연산 11개는 `vol`에 메모리 파일(`-f`), 플러그인과 그 인자, 출력 형식만 넘기고 오프라인 옵션을 붙이지 않는다 [3].
`mount_evidence`가 메모리 이미지인지 확인하려고 `vol`을 실행할 때도 같다 [4].
`tshark`를 부르는 패킷 분석 연산 6개는 이름 풀이를 끄는 `-n`을 붙이지 않는다 [5].
저장소의 설치 스크립트는 `volatility3`·`wireshark-cli`를 배포판 패키지로 버전 없이 설치하고 서버의 의존성 파일에도 두 도구가 없다 [6].
그래서 서버가 부르는 Volatility 3가 로컬에 없는 심볼을 스스로 내려받는지와 `tshark`가 이 인자 없이 주소 이름을 외부에 묻는지는 확인하지 못했다 [6].

허용 목록에는 ClamAV 갱신 도구 `freshclam`이 있지만 서버 코드에서 이를 부르는 연산은 없다 [7].
저장소에는 분석 도구를 네트워크 없는 컨테이너나 network namespace에서 실행하는 구성이 없다.
서버 코드가 스스로 여는 외부 연결은 없고 그 판단은 I01에서 본다.
