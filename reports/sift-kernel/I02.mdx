# I02 분석 도구 통신 차단

### 미구현

**판단.** sift-kernel은 분석 도구를 실행할 때 그 도구의 통신을 끊거나 끄는 장치가 없다.
분석 도구는 모두 `ProcessExecutor`가 실행하고 `execute`·`extractToFile`은 서버 프로세스의 환경변수에 `PATH`만 바꿔 넘긴다 [1].
서버 코드에서 실행기를 부르는 곳은 어느 것도 `env` 옵션을 넘기지 않는다 [2].
그래서 분석 도구는 서버 프로세스와 같은 네트워크 설정과 프록시 환경변수로 돈다 [1].

Volatility 3 연산 11개는 `vol`에 메모리 파일(`-f`)과 플러그인, 그 인자를 넘기고 오프라인 옵션 `--offline`을 붙이지 않는다 [3].
그 가운데 10개가 붙이는 `--output json`은 Volatility 3 2.28.0에서 출력 형식이 아니라 `--output-dir`의 줄임으로 읽힌다 [4].
그래서 출력 폴더 안에 `json` 폴더가 없으면 이 10개 연산은 플러그인을 실행하기 전에 오류로 끝난다 [4].
Volatility 3 2.28.0 소스로 같은 인자를 실행해 보니 출력 폴더가 없다는 오류가 났다 [4].
`mount_evidence`가 메모리 이미지인지 확인하려고 `vol`을 실행할 때도 같다 [5].
`tshark`를 부르는 패킷 분석 연산 6개는 이름 풀이를 끄는 `-n`을 붙이지 않는다 [6].
저장소의 설치 스크립트는 `volatility3`·`wireshark-cli`를 배포판 패키지로 버전 없이 설치하고 서버의 의존성 파일에도 두 도구가 없다 [7].
Volatility 3 2.28.0은 `--offline`이 없으면 Windows 커널의 PDB 심볼 표가 로컬 심볼 폴더와 캐시에 없을 때 Microsoft 심볼 서버에서 PDB를 받아 변환한다 [4].
원격 ISF 목록 주소 `REMOTE_ISF_URL`은 기본값이 `None`이라 `-u`를 주지 않으면 그 목록은 조회하지 않는다 [4].
그래서 `dump_process`와 `mount_evidence`의 확인 실행처럼 플러그인까지 실행되는 경우 이미지에 맞는 심볼이 로컬에 없으면 Volatility 3는 Microsoft 심볼 서버에 접속한다 [3][5][4].
`tshark`는 `-n`·`-N`이 없으면 환경설정 값을 따르고 Wireshark 4.6.6의 기본값은 IP 주소 이름 풀이를 끈 `-N dmN`이다 [8].
그래서 기본 환경설정에서는 `tshark`가 주소 이름을 외부 DNS에 묻지 않는다 [8].
서버 계정의 Wireshark 환경설정이 `nameres.network_name`을 켜면 서버가 넘기는 인자로는 이를 끄지 못한다 [6][8].

허용 목록에는 ClamAV 갱신 도구 `freshclam`이 있지만 서버 코드에서 이를 부르는 연산은 없다 [9].
저장소에는 분석 도구를 네트워크 없는 컨테이너나 network namespace에서 실행하는 구성이 없다.
서버 코드가 스스로 여는 외부 연결은 없고 그 판단은 I01에서 본다.
