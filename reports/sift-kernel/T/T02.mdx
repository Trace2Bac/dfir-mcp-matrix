# T02 실행 허용 범위 제한

### T02.04 고정 명령·템플릿

**구현.** 외부 도구를 쓰는 분류 연산은 서버 코드의 매핑 `getToolBinaryMapping`이 실행 파일과 인자 배열의 모양을 정한다 [1].
모델 값은 매핑이 정한 자리에만 들어간다 [2].
`search_pcap`의 `filter`는 `-Y` 뒤에, `parse_registry_key`의 `plugin`은 `-p` 뒤에, `generate_timeline`의 `parsers`는 `--parsers` 뒤에 들어간다 [2].
실행기는 실행 파일 이름을 허용 목록 `ALLOWED_BINARIES`와 대조하고 목록 밖이면 실행하지 않는다 [3].
실행 파일 이름은 매핑이 정하므로 모델이 고르지 못한다 [1][3].
`mount_evidence`도 확장자에 따라 서버 코드가 마운트 명령과 인자를 고르고 받은 경로만 그 자리에 넣는다 [4].

**한계.** 위치 인자 자리에 들어가는 모델 값은 `-`로 시작하는지 보지 않고 앞에 `--`를 두어 옵션 해석을 끊는 곳도 없다 [5].
이미지 뒤에 붙는 `inode`·`start_inode`, `extract_strings`·`hash_and_lookup`·`parse_srum`·`parse_registry_key`의 `path`, `scan_yara`의 `rules`가 여기에 포함된다 [5].
`mount_evidence`의 `image_path`도 마운트 명령과 `fls`·`mmls`·`fsstat` 확인 명령의 위치 인자로 들어간다 [4][6].
Linux에서 Sleuth Kit 4.15.0의 `fls`·`mmls`·`istat`·`icat`·`fsstat`, libewf 20240506의 `ewfmount`, libesedb 20240420의 `esedbexport`, hashdeep 4.4, util-linux 2.42.2의 `mount`, GNU binutils 2.46.1의 `strings`는 glibc의 `getopt`·`getopt_long`으로 인자를 읽는다 [7][8].
glibc 2.43의 `getopt`는 `POSIXLY_CORRECT`가 없으면 인자 순서를 바꿔 가며 끝까지 읽으므로 위치 인자 뒤에 있어도 `-`로 시작하는 값을 옵션으로 읽는다 [9].
regipy 6.2.1의 `regipy-plugins-run`은 click으로 인자를 읽고 click 8.4.1도 `--`가 나오기 전까지 `-`로 시작하는 값을 옵션으로 읽는다 [10].
YARA 4.5.5의 `yara`는 자체 parser로 모든 인자를 읽어 `-`로 시작하는 값을 옵션으로 읽고 `--`를 옵션 끝으로 보지 않는다 [11].
evtx 0.12.2의 `evtx_dump`는 위치 인자 `INPUT`에 `-`로 시작하는 값을 허용하지 않아 이벤트 로그 연산의 `path`가 `-`로 시작하면 옵션으로 읽는다 [12][13].
`strings`는 `@`로 시작하는 인자를 그 파일에 적힌 인자 목록으로 바꾼다 [8].
옵션으로 읽힌 값은 위치 인자에서 빠지므로 `istat`·`icat`·`yara`·`regipy-plugins-run`은 대체로 인자 부족 오류로 끝난다 [7][10][11].
inode가 선택 인자인 `fls`는 그 값을 옵션으로 적용한 채 실행될 수 있다 [7].
마운트 명령 qemu-nbd와 affuse는 팀이 정한 기준 버전 목록에 없어 확인하지 못했다.

실행기는 실행 파일을 찾지 못하면 짝으로 정한 다른 실행 파일로 같은 인자 배열을 다시 실행한다 [14].
`regipy-plugins-run`이 없으면 regipy용으로 만든 `-o`·`-p` 인자 배열이 RegRipper의 `rip.pl`에 전달된다 [14][2].
`evtx_dump`가 없으면 `-o jsonl` 인자 배열이 `evtxexport`에 전달된다 [14][12].
RegRipper3.0의 `rip.pl`은 `Getopt::Long`에 `-o`를 정의하지 않아 `-o`를 알 수 없는 옵션으로 경고하고 넘긴다 [15].
`rip.pl`은 옵션 머리로 `-`와 `/`를 함께 받도록 설정해 `/`로 시작하는 절대 경로 인자도 알 수 없는 옵션으로 버린다 [15].
하이브 경로를 받는 `-r`가 없으므로 `rip.pl`은 `-p`의 플러그인을 실행하기 전에 하이브 경로를 달라는 오류로 끝난다 [15].
libevtx 20251118의 `evtxexport`는 옵션 문자열에 `o`가 없어 `-o`에서 오류를 내고 끝난다 [16].
그래서 짝으로 바꿔 부른 두 실행 파일은 이 인자 배열로 분석 결과를 내지 못한다.

### T02.05 연산·플러그인 허용 목록

**구현.** 분류 도구는 `operation`이 없으면 `MISSING_OPERATION`, 그 분류의 연산 목록에 없으면 `INVALID_OPERATION` 오류를 돌려주고 실행하지 않는다 [17].
연산 목록은 능력 명세 `TOOL_SPECS` 가운데 그 분류에 속하고 커널 도구가 아닌 연산이다 [18].
분류 도구를 거치지 않고 내부 연산 이름으로 직접 불러도 능력 대조 단계가 `TOOL_SPECS`에 없는 이름을 `Unknown tool`로 거부한다 [17][19].
그래서 명세 밖의 연산은 어느 호출 경로로도 실행되지 않는다.

목록 안의 연산 가운데 자유 값을 받는 연산이 있다 [20].
`search_pcap`의 tshark 표시 필터, `parse_registry_key`의 regipy 플러그인 이름, `generate_timeline`의 Plaso 파서 목록, `search_filename`의 정규식은 서버 코드가 구조나 이름을 검사하지 않는다 [20].
그런 질의를 좁히는 장치가 없어 T02.06에는 연결하지 않는다.

도구 단위로 좁히는 장치는 없다.
`ListTools`는 커널 도구와 분류 도구를 조건 없이 모두 낸다 [21].
시작 인자 `--all-tools`는 설정 값으로 읽어 두지만 서버 코드가 그 값을 쓰지 않는다 [22].
`activate_workflow`·`deactivate_workflow`는 활성 워크플로 집합을 바꾸고 `notifications/tools/list_changed`를 보내지만 `ListTools`와 호출 처리는 그 집합을 보지 않는다 [21][23].
도구 annotation `readOnlyHint`·`destructiveHint`는 도구 목록에 싣는 표시이고 호출을 막지 않는다 [21].

저장소 루트의 `CLAUDE.md`는 셸 실행이 불가능하다고 적는다 [24].
저장소에는 클라이언트 자체 도구를 막는 설정 파일이 없어 T02.02에는 연결하지 않는다.
