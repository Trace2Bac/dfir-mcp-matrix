# T09 대상 시스템 대응 조치 처리

### 비적용

**판단.** sift-kernel은 조사하는 대상 시스템에 접속하거나 그 상태를 바꾸는 도구를 두지 않는다.
분류 도구 연산이 실행하는 외부 도구는 연산마다 정한 Sleuth Kit·Plaso·Volatility·YARA·tshark·regipy·EZ Tools 같은 분석 도구이고 인자로 이미지·메모리 덤프·패킷 기록·꺼낸 파일의 경로를 받는다 [1].
파일을 만드는 도구에는 출력 폴더 아래 경로를 쓰기 위치로 준다 [1].
`mount_evidence`가 실행하는 `mount`·`ewfmount`·`qemu-nbd`·`affuse`는 서버가 실행되는 분석 호스트에 이미지를 붙이는 명령이다 [2].
실행기의 허용 목록에는 `umount`·`losetup`·`freshclam`·`journalctl`도 있지만 이 실행 파일을 부르는 연산은 없다 [1][3].
서버 안 처리기는 앞선 호출의 원래 출력과 발견사항을 읽어 결과를 만든다 [4].

서버 코드가 여는 연결은 `--transport http`일 때 MCP 클라이언트의 요청을 받는 HTTP 서버뿐이다 [5].
서버 코드가 파일을 쓰는 곳은 출력 폴더 아래의 원래 출력·보고서·비동기 작업 출력·꺼낸 파일과 SQLite 호출 기록이다 [6].
`reset_investigation`이 지우는 것도 서버 자신의 조사 상태와 호출 기록이다 [7].
그래서 조치 전후 상태·변경 내역·되돌림을 남길 대상 시스템 조치가 없다.
