# T07 도구 부재 처리

### T07.04 알림 없는 대체 실행

**구현.** 외부 도구를 실행하는 모든 경로는 공통 실행기를 거치고 실행기는 실행 파일이 없을 때 정해 둔 다른 이름으로 다시 실행한다.
서버는 실행 전에 실행 파일이나 참조 자료가 있는지 보지 않는다.
실행기에는 `which`로 실행 파일을 찾는 `isAvailable`이 있지만 서버는 이 함수를 부르지 않는다 [1].
실행 파일이 없으면 프로세스를 시작할 때 `ENOENT` 오류가 나고 실행기는 그 이름이 대체 목록에 있으면 대체 이름으로 같은 인자를 넘겨 다시 실행한다 [2][3].
목록은 `log2timeline`·`psort`·`pinfo`·`vol`과 그 `.py` 이름의 짝, 그리고 `evtx_dump`와 `evtxexport`, `regipy-plugins-run`과 `rip.pl`, `ewfverify`와 `img_stat`의 짝이다 [2].
뒤의 세 짝은 서로 다른 프로그램인데 원래 도구에 맞춰 만든 인자를 그대로 넘긴다 [2][3].
그래서 `regipy-plugins-run` 대신 부른 `rip.pl`은 하이브 경로 인자 `-r`가 없어 플러그인을 실행하기 전에 오류로 끝난다 [4].
`evtx_dump` 대신 부른 `evtxexport`는 옵션 `-o`를 알지 못해 오류로 끝난다 [5].
두 짝의 대체 실행은 결과를 내지 못하고 인자를 읽는 방식은 T02에서 본다.
`verify_integrity`는 `ewfverify`가 없으면 `img_stat`이 성공한 결과를 무결성 확인 성공으로 처리한다 [2].
이 성공으로 생기는 능력은 T03에서 본다.
대체로 실행해도 호출 기록에는 연산 이름과 인자만 남고 응답에도 실제로 실행한 실행 파일이 없다 [6].
목록의 짝은 서로를 대체 이름으로 가리키므로 두 이름이 모두 없으면 실행기는 두 이름을 번갈아 실행하며 끝나지 않는다 [2][3].
이 경로는 T08.02에서 본다.

대체 목록에 없는 실행 파일이 없으면 실행기는 종료 코드 없이 실패를 돌려주고 서버는 `Tool "<실행 파일>" exited with code null`이라는 문구를 오류로 싣는다 [3][7].
`ENOENT` 문구는 오류 객체의 `stderr`에만 있고 응답과 호출 기록에는 실리지 않는다 [7].
그래서 도구가 없다는 사실을 가리는 오류가 없어 T07.01·T07.02에는 연결하지 않는다.
참조 자료도 미리 보지 않는다.
`scan_yara`는 `rules`가 없으면 `/usr/share/yara/rules`를 넘기고 `scan_memory_yara`는 `rules`가 없으면 빈 문자열을 넘긴다 [8].
`--sudo`로 서버를 실행하면 실행기가 `spawn`에 넘기는 프로그램은 `sudo`라서 도구 실행 파일이 없어도 `ENOENT`가 나지 않고 이 대체도 일어나지 않는다 [9].

`mount_evidence`는 마운트 명령이 실패하면 `fls`로 이미지를 직접 읽어 보고 읽히면 성공으로 처리한다 [10].
이때 원래 출력 파일에는 Sleuth Kit로 직접 읽는다는 문구가 남는다 [10].
응답은 마운트에 성공한 경우와 같은 모양으로 마운트 지점 `/mnt/evidence/`, `read_only: true`, 마운트 방법을 적은 `note`를 싣는다 [11].

입력 경로를 찾지 못하거나 이미지에서 꺼내지 못해 다른 입력으로 실행하는 경로는 T01.08에서 본다.

### T07.05 실행 환경별 경로 분기

**구현.** 실행기는 서버 프로세스의 PATH 앞에 `/usr/local/bin`, `$HOME/.cargo/bin`, `$HOME/.local/bin`, `/opt/volatility3`, `/opt/CyberChef`를 차례로 붙인 PATH로 외부 도구를 실행한다 [12].
같은 이름의 실행 파일이 여러 곳에 있으면 이 순서에서 앞에 있는 폴더의 것이 실행된다.
코드 주석은 각 폴더를 SIFT의 Zimmerman 도구, cargo로 설치한 `evtx_dump`, pip로 설치한 regipy·Plaso, SIFT의 Volatility 위치로 적는다 [12].
이미지에서 파일을 꺼내는 `extractToFile`은 `/opt/CyberChef`를 뺀 같은 순서를 쓴다 [13].
고른 실행 파일의 경로는 응답과 호출 기록에 남지 않는다 [6].

**예외.** `--sudo`로 서버를 실행하면 실행기는 이 PATH를 `sudo` 프로세스의 환경으로 주고 도구 이름을 `sudo`의 인자로 넘긴다 [9].
이때 실행 파일을 찾는 것은 `sudo`이고 `sudo`가 넘겨받은 PATH를 쓰는지는 서버가 확인하지 않는다 [9].
이 경로에서 위의 순서가 적용되는지 확인하지 못했다.

export function executionError(
  tool: string,
  exitCode: number | null,
  stderr: string,
  timedOut: boolean,
): ExecutionError {
  const message = timedOut
    ? `Tool "${tool}" timed out`
    : `Tool "${tool}" exited with code ${exitCode}`;
  const guidance = timedOut
    ? `The tool took too long. Try with a smaller scope or increase timeout.`
    : `Check stderr for details: ${stderr.slice(0, 200)}`;
  // Mark as retriable if timedOut or if stderr hints at transient resource issues
  const retriable = timedOut || /EAGAIN|EBUSY|EIO|EMFILE|resource temporarily/i.test(stderr);
  return { kind: "EXECUTION_ERROR", tool, exitCode, stderr, timedOut, retriable, message, guidance };
}
