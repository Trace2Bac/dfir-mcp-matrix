# T10 도구 명세 구성

### T10.02 처리기와 따로 둔 명세

**구현.** 이 방식은 `ListTools`가 내는 커널 도구와 분류 도구 모두에 적용된다 [1].
서버는 MCP TypeScript SDK의 저수준 `Server`에 `ListTools` 처리기를 직접 달고 도구 목록을 코드로 만든다 [1].
커널 도구의 입력 schema는 `getToolInputSchema`의 손으로 쓴 표에서 오고 설명은 능력 명세 `TOOL_SPECS`의 `description`에서 온다 [1][2].
분류 도구의 설명과 입력 schema는 `TOOL_SPECS`와 연산별 인자 이름 표 `getInternalToolParams`, 공통 인자 표 `commonParams`에서 만든다 [3][4].
실제 처리는 이 표들과 따로 있는 실행 파일 매핑 `getToolBinaryMapping`과 서버 안 처리기가 한다 [5].
표와 처리 코드를 대조하는 장치는 없다 [1][3][5].
출력 schema를 만드는 함수 `getToolOutputSchema`는 정의만 있고 도구 목록에 싣지 않는다 [6].

**예외.** 아래 불일치는 코드만 읽어 확인했고 해당 호출을 실행해 보지는 않았다.
`get_investigation_protocol`·`list_workflows`·`activate_workflow`·`deactivate_workflow` 네 커널 도구는 `TOOL_SPECS`에 없어 설명이 도구 이름 그대로다 [1][2].
코드 주석은 `get_investigation_protocol`을 처음 부를 도구로 적지만 모델은 그 이름만 본다 [1][7].
timeline 분류의 schema는 시간 인자로 `time_start`·`time_end`를 알리지만 `filter_timeline`의 매핑은 `start`를, `get_timeline_context`의 매핑은 `timestamp`·`window_minutes`를 읽는다 [4][8].
그래서 schema대로 부르면 `filter_timeline`은 시간 범위 없이 `psort`를 부르고 `get_timeline_context`는 `--slice` 값을 빈 문자열로 넘긴다 [8].
`get_timeline_context`가 읽는 `timestamp`·`window_minutes`는 커널 도구용 표 `getToolInputSchema`에만 있고 분류 도구 schema에는 없다 [1][8].
같은 schema는 `parsers`를 쉼표로 이은 문자열로 알리지만 `generate_timeline`의 매핑은 배열로 보고 `join`을 부르므로 문자열 값으로는 인자 배열을 만들지 못한다 [4][8].
filesystem 분류의 schema는 `show_deleted`를 `true/false` 문자열로 알리지만 `list_directory`의 매핑은 값이 비어 있지 않으면 `fls`에 `-d`를 붙인다 [4][9].
Sleuth Kit 4.15.0의 `fls`에서 `-d`는 삭제된 항목만 보여 주는 옵션이므로 `"false"`를 넘기면 삭제된 항목만 나온다 [9].
YARA 룰 경로를 schema는 `yara_rules`로 알리지만 매핑은 `rules`를 읽고 이 결과는 T05의 예외에 적었다 [4][10].

도구 설명이 알리는 동작과 매핑이 하는 일이 다른 연산도 있다.
filesystem 분류 도구 설명은 `analyze_unallocated`를 미할당 영역에 `bulk_extractor`를 실행하는 연산으로 적는다 [3][11].
이 연산의 매핑은 조사 상태의 증거 이미지 경로를 그대로 `bulk_extractor`에 넘긴다 [12].
미할당 영역을 따로 꺼내거나 파티션 위치를 넘기는 단계는 없다 [12].
그래서 서버는 `bulk_extractor`가 읽는 범위를 미할당 영역으로 한정하지 않는다 [12].
memory 분류 도구 설명은 `get_command_history`가 명령줄 인자와 콘솔 이력을 돌려준다고 적는다 [3][11].
이 연산의 매핑은 Volatility 3 플러그인 `windows.cmdline.CmdLine` 하나만 부른다 [13].
Volatility 3 2.28.0의 이 플러그인은 프로세스마다 프로세스 환경 블록(PEB)의 `ProcessParameters.CommandLine` 값만 읽는다 [14].
같은 버전에 있는 콘솔 이력 플러그인 `windows.cmdscan.CmdScan`·`windows.consoles.Consoles`는 부르지 않는다 [5][14].
memory 분류 도구 설명은 `dump_process`가 프로세스 메모리를 파일로 덤프한다고 적는다 [3][11].
이 연산의 매핑이 부르는 `windows.dumpfiles.DumpFiles`는 그 프로세스의 핸들과 VAD가 가리키는 파일 객체의 캐시 내용을 꺼낸다 [13][15].
이 플러그인은 프로세스 주소 공간을 덤프하지 않는다 [15].

filesystem 분류 도구 schema는 `recover_deleted`·`carve_files`·`analyze_unallocated`의 인자로 이미지 안 경로 `path`를 알린다 [4].
세 매핑은 이 값을 읽지 않고 늘 증거 이미지 전체를 외부 도구에 넘긴다 [12].
`carve_files`의 매핑이 읽는 `file_types`는 분류 도구 schema에 없다 [4][12].

### T10.03 묶음 도구의 연산별 인자를 schema가 구분하지 않음

**구현.** 이 방식은 분류 도구 14개에 적용된다 [3].
분류 도구는 `operation` 인자로 그 분류의 연산을 고르고 서버는 `operation`을 뺀 나머지 인자를 그대로 그 연산에 넘긴다 [3][16].
`operation`의 허용 값 목록은 `TOOL_SPECS`에서 만든다 [3].
나머지 인자는 그 분류 연산들이 쓰는 인자를 모두 합친 평평한 목록이고 어느 연산이 어느 인자를 읽는지는 schema에 없다 [4].
도구 설명은 연산마다 이름과 한 줄 설명만 적고 연산별 인자는 적지 않는다 [3].
커널 도구 `get_investigation_protocol`이 돌려주는 문서도 분류별 연산 이름과 부르는 예만 적는다 [7].
연산 이름 대조는 T02.07에서, 연산별 인자 검사는 T01에서 본다.

### T10.06 도구 annotation 표시

**구현.** 이 방식은 `ListTools`가 내는 모든 도구에 적용된다 [1].
커널 도구는 `mount_evidence`·`reset_investigation`만 `readOnlyHint`를 거짓으로, 나머지는 참으로 싣고 `destructiveHint`는 `reset_investigation`만 참으로 싣는다 [1].
분류 도구 14개는 모두 `readOnlyHint` 참, `destructiveHint` 거짓으로 싣는다 [1].
MCP TypeScript SDK 1.29.0의 정의는 `readOnlyHint`가 참인 도구는 환경을 바꾸지 않는다고 적고 annotation은 힌트일 뿐이라고 적는다 [17].
이 표시는 호출을 막지 않으며 T02의 구현 단락에도 적었다.

**예외.** 쓰기를 하는 도구에도 `readOnlyHint`가 참이다 [1].
커널 도구 `generate_report`는 출력 폴더에 보고서 파일을 쓴다 [18].
filesystem 분류의 `carve_files`·`recover_deleted`와 timeline 분류의 `generate_timeline`도 출력 폴더에 파일을 만든다 [5].

### T10.07 실행 중 목록 변경 알림

**구현.** 이 방식은 워크플로를 켜거나 끄는 `activate_workflow`·`deactivate_workflow`와 능력을 얻을 때의 자동 활성화에 적용된다 [19][20].
서버는 능력 선언에 `tools.listChanged`를 참으로 싣는다 [19].
활성 워크플로 집합이 바뀌면 `notifications/tools/list_changed`를 보낸다 [19][20].

**예외.** `ListTools`는 활성 워크플로 집합을 보지 않고 늘 같은 커널 도구와 분류 도구를 낸다 [1].
그래서 알림 뒤에 클라이언트가 목록을 다시 받아도 바뀐 것이 없다 [1][20].
보이는 도구를 계산하는 `getVisibleTools`는 부르는 곳이 없다 [20].
목록과 호출이 이 집합을 보지 않는다는 점은 T02의 구현 단락에도 적었다.
