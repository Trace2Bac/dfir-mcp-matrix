# T04 실행 방식

### T04.01 서버 프로세스 안 라이브러리 호출

**구현.** 외부 실행 파일 매핑이 없는 분류 연산은 서버 프로세스 안의 처리기 함수가 수행한다 [1].
처리기는 이상 징후 탐지, 상관 분석, 지속성 점검 같은 연산을 서버의 TypeScript 코드로 계산한다 [2].
처리기의 재료는 앞선 호출이 저장한 원래 출력과 호출 기록·발견사항·가설이고 증거 파일을 직접 열지 않는다 [1].
외부 도구의 출력도 서버 프로세스 안에서 처리한다.
`parseToolOutput`이 도구별 파서로 출력을 구조화한다 [3].
`search_filename`의 결과는 서버가 정규식으로 거른다 [4].
`regipy-plugins-run`이 파일로 쓴 JSON 결과는 서버가 읽어 원래 출력으로 쓴다 [5].
추론 엔진 `ForensicReasoningEngine`도 서버 프로세스 안에서 도구 출력을 받아 가설 신념을 계산한다 [6].
이 계산은 저장소 안의 코드이고 분석용 외부 라이브러리를 불러오지 않는다 [7].

### T04.02 같은 권한의 별도 프로세스

**구현.** 외부 도구는 모두 `ProcessExecutor`가 `spawn`으로 실행한다 [8].
`spawn`에 실행 파일 이름과 인자 배열을 따로 넘기고 `shell: false`를 준다 [8].
자식 프로세스는 서버의 환경변수를 물려받고 작업 위치(`cwd`)는 조사 출력 폴더 하나다 [8][9].
계정을 바꾸거나 권한을 낮추는 인자를 주는 곳은 없어 외부 도구는 서버와 같은 계정·파일·네트워크 권한으로 실행된다 [8].
이미지 안 파일을 출력 폴더로 꺼내는 `extractToFile`과 비동기 작업도 같은 실행기로 실행한다 [10][11].
`mount_evidence`의 마운트 명령과 `fls`·`mmls`·`fsstat` 확인도 같은 실행기를 거친다 [12].

서버 코드에 셸 명령 문자열로 실행하는 곳은 없다 [8][10].
컨테이너·namespace 같은 분리 설정이나 호출마다 새 작업 폴더를 만드는 곳도 없다 [9].

### T04.04 권한을 나눈 실행

**구현.** 이 방식은 시작 인자 `--sudo`로 실행한 서버의 외부 도구 실행 전부에 적용된다 [8][10].
`--sudo`를 주면 실행기의 두 실행 경로가 모두 외부 도구를 `sudo <실행 파일> <인자>` 형태로 실행한다 [8][10].
그래서 외부 도구는 서버 계정과 달리 root 권한으로 실행된다.
권한을 높이는 방향이고 도구마다 고르지 않고 모두 바꾼다.
`--sudo`를 주지 않으면 외부 도구는 서버와 같은 권한으로 실행된다 [8].
