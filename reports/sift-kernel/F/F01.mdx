# F01 판단 지침

### F01.02 결론 서술 방식 안내

**구현.** 이 방식은 `build_attack_narrative` 연산 응답의 주의 문구, MCP 프롬프트 `start_investigation`, MCP 리소스 Windows IR 방법론에 있다 [1][2][3].
연산별 주의 표 `FORENSIC_GUIDANCE`의 `build_attack_narrative` 항목은 공격 서술이 근거 사슬을 따라야 하고 모든 주장이 근거가 연결된 등록 발견사항으로 이어져야 하며 교차 확인 없는 추측을 피하라고 적는다 [1].
서버는 이 문구를 그 연산 응답의 `forensic_context.guidance`로 붙이고 확인할 연산으로 `verify_chain`·`get_confidence_summary`를 함께 적는다 [1][4].
`start_investigation` 프롬프트는 모든 발견사항을 앞선 호출의 `ledger_entry_ids`에 잇고 도구 근거 없이 주장하지 말라고 적는다 [2].
Windows IR 방법론 리소스는 보고 단계에서 확신 등급을 매긴 보고서를 만들라고 적는다 [3].
MCP 프롬프트는 사용자가 클라이언트에서 골라야 모델에게 전달된다.

서버는 지침 `instructions`를 두지 않는다 [5].
MCP 리소스와 프롬프트는 조사 단계와 할 일을 적지만 부재가 무죄를 뜻하지 않는다는 원칙처럼 조사 전체에 걸치는 해석 원칙은 적지 않는다 [6].
부재를 어떻게 읽을지는 `parse_prefetch`·`detect_log_clearing` 연산 응답의 주의 문구와 `suggest_next_action`이 권고에 붙이는 판단 기준 `directive`의 `ifAbsent`에 연산마다 적는다 [7].
그래서 F01.01에는 연결하지 않는다.

**한계.** `build_attack_narrative` 항목은 `verify_chain`을 모든 발견사항에 근거가 있는지 확인하는 연산으로 적는다 [1].
`verify_chain`은 호출 기록의 해시 체인만 검사하고 발견사항을 읽지 않는다 [8].

### F01.03 발견사항·결론의 단서·확인 권고

**구현.** 이 방식은 커널 도구 `corroborate_finding`·`challenge_finding`·`get_questions_to_investigate`·`get_investigation_health`의 응답과 MCP 리소스 Windows IR 방법론, MCP 프롬프트 `start_investigation`·`deep_analysis`에 있다 [9][10][3][2].
`corroborate_finding`은 발견사항의 근거 호출이 속하지 않은 분류에서 분류마다 첫 연산 하나씩 3개까지 권한다 [9].
권하는 이유에는 다른 분류로 교차 확인하면 `CONFIRMED`로 오른다고 적는다 [9].
`challenge_finding`은 시간 대조·다른 설명·반증 이벤트 검색 3가지 전략과 그 도구를 돌려준다 [9].
`get_questions_to_investigate`는 근거가 하나뿐인 `INFERRED` 발견사항 2개까지 더 확인할 수 있는지 묻는 문장을 싣는다 [10].
`get_investigation_health`는 근거가 하나뿐인 발견사항이 있으면 `corroborate_finding`으로 보강하라고 적고 충돌이 있으면 최종 보고서를 만들기 전에 해결하라고 적는다 [10].
MCP 리소스 Windows IR 방법론은 보고 단계에 근거가 하나뿐인 발견사항을 교차 확인하라고 적는다 [3].
MCP 프롬프트 `start_investigation`·`deep_analysis`도 약한 발견사항을 `corroborate_finding`으로 보강하고 다른 분류와 대조하라고 적는다 [2].

**한계.** `challenge_finding`이 권하는 `detect_anti_forensics_summary`는 능력 명세에 없는 이름이다 [9][11].
명세의 연산 이름은 `get_anti_forensics_summary`다 [11].
`challenge_finding`의 전략 3가지는 발견사항의 내용과 관계없이 늘 같다 [9].

### F01.04 조사 상태에 따른 판단 편향 경고

**구현.** 분류 도구 연산의 응답에는 추론 엔진 상태로 고른 `self_correction_trigger`가 붙는다 [12].
증거 충돌도가 0.3을 넘으면 우세 가설을 다시 보라는 `CONFLICT`를, 엔트로피가 멈추면 우세 가설을 반증해 보라는 `STUCK`을, 엔트로피가 늘면 새 가설을 세우라는 `DIVERGING`을 싣는다 [12].
앞의 세 경우가 아니고 편향 경고가 있으면 다른 설명을 생각해 보라는 `BIAS`를 싣는다 [12].
편향 경고 `bias_warnings`는 6번 이상의 조사 행동 가운데 75%를 넘는 수가 우세 가설을 겨누면 확증 편향 위험을 적고 그 가설을 반증할 도구를 권한다 [13].
anchoring 경고는 8번 이상의 조사 행동에서 첫 행동 뒤 행동의 85%를 넘는 수가 첫 행동과 같은 분류일 때 붙는다 [14].
tunnel vision 경고는 8번 이상의 조사 행동 뒤 한 번도 겨누지 않은 가설이 12개 가운데 3개 이상일 때 붙는다 [14].
행동이 겨눈 가설은 모델이 밝힌 의도가 아니라 서버가 호출 분류별 후보 가운데 지금 신념이 가장 높은 가설로 추정한 값이다 [15].
분류별 후보에는 `ransomware`와 `benign_anomaly`가 없어 이 두 가설은 늘 겨누지 않은 가설로 세어진다 [15].
그래서 8번째 조사 행동부터는 나머지 가설 10개를 모두 한 번 이상 겨누지 않는 한 tunnel vision 경고가 붙는다 [14][15].
실행 흔적 연산은 분류 이름 `execution_artifacts`가 대상 가설 표에 없어 대상 가설이 `null`이 된다 [15].
실패한 호출과 규칙이 발화하지 않은 호출도 행동 이력에 들어가 편향 계산에 쓰인다 [16].
이 문구들은 이번 호출의 출력을 합친 뒤의 추론 상태와 그때까지의 호출 이력으로 고른다 [12][13].

**한계.** 수렴 상태는 규칙이 발화한 성공 호출에서만 갱신되고 실패한 호출과 규칙이 발화하지 않은 호출은 앞 상태를 그대로 돌려준다 [17][18].
그래서 앞선 호출로 상태가 `DIVERGING`이 되면 아무 신호가 없던 다음 호출의 응답에도 "new contradictory evidence found"라는 `DIVERGING` 문구가 그대로 붙는다 [12][18].
실패한 호출의 `isError` 응답도 같은 응답 객체에 오류만 더하므로 이 문구가 붙는다 [19].

/** Confirmation bias: >75% of actions target the leading hypothesis */
function checkConfirmationBias(
  history: readonly ActionRecord[],
  leadingHypothesis: string | null
): BiasWarning | null {
  if (!leadingHypothesis || history.length < 6) return null;

  const targetingLeading = history.filter(a => a.targetedHypothesis === leadingHypothesis).length;
  const ratio = targetingLeading / history.length;

  if (ratio > CONFIRMATION_THRESHOLD) {
    const severity = ratio > 0.9 ? "HIGH" as const : "MEDIUM" as const;
    return {
      type: "confirmation" as BiasType,
      severity,
      description: `${(ratio * 100).toFixed(0)}% of ${history.length} actions target the leading hypothesis "${leadingHypothesis}". ` +
        `Confirmation bias risk: investigating only what supports the current theory.`,
      suggestion: `Test alternative hypotheses. Run tools that could DISPROVE "${leadingHypothesis}" — ` +
        `e.g., if hypothesis is "insider threat", check for external C2 indicators that would suggest APT instead.`,
    };
  }
  return null;

/** Anchoring: first finding drives 85%+ of subsequent actions */
function checkAnchoring(history: readonly ActionRecord[]): BiasWarning | null {
  if (history.length < 8) return null;

  // Check if the category of the first finding dominates subsequent actions
  const firstCategory = history[0]?.category;
  if (!firstCategory) return null;

  const subsequent = history.slice(1);
  const sameCategoryCount = subsequent.filter(a => a.category === firstCategory).length;
  const ratio = sameCategoryCount / subsequent.length;

  if (ratio > ANCHORING_THRESHOLD) {
    return {
      type: "anchoring" as BiasType,
      severity: "MEDIUM",
      description: `${(ratio * 100).toFixed(0)}% of actions remain in the "${firstCategory}" category. ` +
        `Anchoring risk: first finding may be overly influencing investigation direction.`,
      suggestion: `Broaden investigation scope. Consider other artifact categories: ` +
        `registry, event logs, network, user activity. The first finding may not be the most significant.`,
    };
  }
  return null;
}

export function inferTargetedHypothesis(
  tool: string,
  category: string,
  activeHypotheses: readonly { id: string; belief: number }[]
): string | null {
  // Map tool categories to most-related hypothesis types
  const categoryHypothesisMap: Record<string, string[]> = {
    filesystem: ["apt_targeted", "apt_opportunistic", "insider_data_theft", "data_exfiltration"],
    registry: ["persistence_established", "apt_targeted", "credential_compromise"],
    event_logs: ["credential_compromise", "lateral_movement", "anti_forensics"],
    execution: ["apt_targeted", "apt_opportunistic", "persistence_established"],
    persistence: ["persistence_established", "apt_targeted", "supply_chain"],
    memory: ["apt_targeted", "apt_opportunistic"],
    network: ["apt_targeted", "data_exfiltration", "lateral_movement"],
    anti_forensics: ["anti_forensics", "apt_targeted"],
    user_activity: ["insider_data_theft", "insider_sabotage", "data_exfiltration"],
    browser: ["insider_data_theft", "credential_compromise"],
  };

  const candidates = categoryHypothesisMap[category] ?? [];
  if (candidates.length === 0) return null;

  // Return the highest-belief hypothesis from candidates
  const ranked = activeHypotheses
    .filter(h => candidates.includes(h.id))
    .sort((a, b) => b.belief - a.belief);

  return ranked[0]?.id ?? candidates[0] ?? null;
}
