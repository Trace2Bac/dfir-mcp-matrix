# E02 증거 무결성 검증

### E02.02 도구를 요청해 기준값 계산

**구현.** 증거 해시는 모델이 도구를 부를 때만 계산한다.
`persistence` 분류 도구의 `hash_and_lookup` 연산은 모델이 준 `path`를 `hashdeep -r -csha256`으로 해시한다 [1].
`path`는 이미지 안의 경로가 아니라 서버가 도는 호스트의 경로라서 증거 파일이나 서버가 꺼낸 파일을 넘기면 그 파일을 해시한다 [1].
`path` 아래 파일마다 처음부터 끝까지 SHA-256을 계산하므로 증거 이미지 경로를 넘기면 컨테이너 파일 자체의 해시가 된다 [1].
`hashdeep` 출력은 파일마다 크기·SHA-256·경로로 나뉘어 응답에 실린다 [2].
명세는 알려진 악성 코드 목록과 대조한다고 적지만 출력을 어떤 목록과도 대조하는 코드는 없다 [3][2].
계산한 값은 기준값으로 따로 보관하지 않고 원래 출력과 호출 기록의 출력 해시로만 남는다 [4].

`mount_evidence`는 증거 바이트를 해시하지 않아 E02.01에는 들지 않는다 [5].
호출 기록에 넣는 `outputHash`는 메모리 증거면 `vol` 출력, pcap이면 "PCAP: <경로>" 문자열, 디스크 이미지면 마운트 명령 출력의 해시다 [5].
`get_image_metadata`가 부르는 `img_stat`은 EWF 이미지 안에 기록된 MD5를 옮겨 적을 뿐 다시 계산하지 않는다 [6].

**예외.** 실행기는 시간 제한이나 출력 상한에 걸려 멈춘 실행도 표준 출력이 있으면 종료 코드 -1의 결과로 돌려주고 서버는 이를 성공으로 센다 [7][8].
`hash_and_lookup`은 비동기 실행 목록에 없어 기본 시간 제한 45초가 걸린다 [7][9].
`hashdeep`이 45초 안에 끝내지 못했는데 그때까지 출력이 넘어왔으면 남은 파일이 빠진 결과가 성공으로 남는다 [2][8][7].
응답에는 해시하지 못한 파일이 있다는 표시가 없다 [8].

### E02.09 도구를 요청해 검증

**구현.** 이 방식은 커널 도구 `verify_integrity`에 걸리고 모델이 이 도구를 불러야만 대조한다 [1].
`verify_integrity`는 조사 상태의 증거 경로를 외부 도구 `ewfverify`에 넘긴다 [1].
명세는 이 도구가 이미지 해시를 검증하고 기준값을 만든다고 적는다 [3].
`ewfverify`는 EWF 이미지에 담긴 매체 데이터 전체를 다시 해시해 이미지 안에 기록된 수집 해시와 대조한다 [10][11].
이 해시는 `.E01` 컨테이너 파일의 해시가 아니고 `.E02` 이후 조각은 `ewfverify`가 첫 조각 이름으로 찾아 함께 연다 [1][12].
대조가 맞으면 "SUCCESS"와 종료 코드 0을, 어긋나면 "FAILURE"와 종료 코드 1을 낸다 [13].
서버는 종료 코드 0이면 `verify_integrity`를 성공으로 세고 `integrity_verified` 능력을 더한다 [8].
기준값은 늘 이미지 안에 기록된 수집 해시이고 서버가 따로 받거나 앞서 계산해 둔 값은 없다 [4].
EWF가 아닌 원시 이미지·메모리 덤프·pcap은 `ewfverify`가 열지 못해 실패로 끝나므로 서버에서 대조할 방법이 없다 [14].
분석 연산을 부르는 과정에서 서버가 스스로 대조하는 곳은 없어 E02.07에는 연결하지 않는다.

**예외.** `verify_integrity`의 입력 형식은 `algorithm`(sha256·md5·sha1)을 받지만 인자 구성은 이 값을 쓰지 않는다 [1][15].
libewf 20240506의 `ewfverify`는 `-d`를 주지 않으면 이미지에 기록된 해시 종류를 계산하고 기록된 해시가 없을 때만 MD5를 계산한다 [10].
그래서 어느 `algorithm`을 골라도 이미지에 기록된 해시 종류로 검증한다 [1][10].

EWF 이미지에 수집 해시가 기록되어 있지 않으면 `ewfverify`는 대조 없이 SUCCESS를 낸다 [11].
서버는 이를 검증 성공으로 세어 `integrity_verified`를 준다 [8].

`ewfverify` 실행 파일이 없으면 실행기가 대신 `img_stat`을 부른다 [16].
`img_stat`은 이미지 정보를 출력하고 해시를 계산하지 않는데 서버는 종료 코드 0을 성공으로 세어 `integrity_verified` 능력을 준다 [6][16][8].
응답은 `img_stat` 출력을 그대로 싣고 대체 도구로 실행했다는 표시를 붙이지 않는다 [8].

`ewfverify`가 45초 시간 제한에 걸려 멈출 때 표준 출력이 있으면 서버는 해시를 마치지 않은 실행을 성공으로 센다 [8][7].
`ewfverify`는 시작할 때 버전 줄을, 도는 동안 진행 상태를 표준 출력에 쓴다 [10][17].
강제 종료 때까지 그 출력이 파이프로 넘어오는지는 확인하지 못했다.

`integrity_verified`는 증거와 묶이지 않는다 [18].
다른 이미지를 다시 마운트해도 능력이 남아 새 이미지는 대조 없이 분석 연산을 지난다 [18].

### E02.08 불일치 시 중단·경고

**구현.** 대조가 어긋나 `ewfverify`가 종료 코드 1로 끝나면 서버는 호출을 실패로 기록하고 `isError` 응답을 돌려준다 [8][19].
이때 `integrity_verified`가 생기지 않는다 [8].
`list_directory`·`carve_files`·`generate_timeline`처럼 이 능력을 요구하는 연산은 `CAPABILITY_BLOCKED`로 거부된다 [18][20].
메모리·네트워크 연산과 `get_image_metadata`·`list_partitions`는 `evidence_mounted`만 요구하므로 이 차단과 상관없이 실행된다 [18].

**예외.** 실행기는 0이 아닌 종료 코드면 표준 출력을 버리고 표준 오류만 남긴다 [7].
응답과 호출 기록의 오류 문구는 `Tool "ewfverify" exited with code 1`이라 해시 불일치와 이미지를 열지 못한 실패가 같은 문구로 남는다 [14][19].
`ewfverify`가 표준 출력에 쓴 "FAILURE"와 저장된 해시·계산한 해시는 응답에 실리지 않는다 [13][17].

앞서 받은 `integrity_verified`는 나중의 `verify_integrity`가 실패해도 지워지지 않는다 [18].
이미 검증을 통과한 서버에서는 불일치가 나와도 그 뒤 분석 연산이 그대로 실행된다.

  /** Produce capabilities after successful tool execution */
  produce(tool: string): readonly Capability[] {
    const spec = this.specs.get(tool);
    const produced: Capability[] = [];
    if (spec) {
      for (const cap of spec.produces) {
        if (!this.held.has(cap)) {
          this.held.add(cap);
          produced.push(cap);
        }
      }
    }
    return produced;
  }

  /** Grant a capability directly (for evidence-type-specific capabilities like linux_accessible, memory_profiled) */
  grant(capability: Capability): boolean {
    if (this.held.has(capability)) return false;
    this.held.add(capability);
    return true;
  }
