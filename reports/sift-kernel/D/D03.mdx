# D03 파생물 무결성 검증

### D03.01 기준값 자동 계산

**구현.** 이 방식은 `generate_report`의 마크다운·HTML 보고서와 `mount_evidence`의 원래 출력 파일에 적용된다 [1][2][3].
마크다운 보고서는 HMAC 절 앞까지의 본문으로 HMAC-SHA256을 계산하고 그 값을 HMAC 절에 적어 파일에 쓴다 [1].
HTML 보고서는 보고서에 실은 발견사항·커버리지·해시 체인 결과·호출 수·생성 시각 다섯 값을 담은 객체의 JSON 문자열로 HMAC-SHA256을 계산한다 [2].
그 값은 HTML 파일의 HMAC 칸에 들어가고 파일의 나머지 내용은 계산 대상이 아니다 [2][4].
HMAC 키는 환경 변수 `SIFT_KERNEL_HMAC_SECRET`이고 없으면 서버 객체를 만들 때마다 32바이트 난수를 새로 만든다 [5].
HTTP 전송은 요청마다 서버 객체를 새로 만들므로 이 환경 변수가 없으면 보고서마다 다른 키가 쓰이고 그 키는 어디에도 남지 않는다 [6].
두 형식의 응답은 보고서 파일 경로 `path`와 HMAC 값 `hmac_seal`을 싣고 크기는 싣지 않는다 [7].
보고서 생성은 호출 기록에 항목을 남기지 않아 보고서 HMAC은 호출 기록에 없다 [8].

`mount_evidence`의 디스크·메모리 분기는 원래 출력 문자열을 JSON 문자열로 바꾼 값의 SHA-256을 호출 기록 항목의 `outputHash`에 넣고 같은 문자열을 원래 출력 파일에 쓴다 [9][3].
해시 대상은 원래 출력 파일에 쓰는 문자열 전체이고 파일 바이트를 다시 읽어 해시하지 않는다 [9][3].
그래서 대조하려면 파일 내용을 같은 방식으로 JSON 문자열로 바꿔야 한다 [9].
응답에는 호출 기록 항목 ID `ledger_entry_id`만 실리고 `outputHash`는 실리지 않는다 [10].

다른 호출의 `outputHash`는 파서 결과를 두 번 JSON 문자열로 바꾼 값의 SHA-256이다 [11][9].
파서 결과는 응답의 `result`가 되는 값이고 원래 출력 파일의 내용이 아니라서 이 해시는 보관한 파생물의 기준값으로 세지 않는다 [11].
비동기 연산의 항목은 `outputHash`를 빈 문자열로 둔다 [12].
이미지에서 꺼낸 파일, 비동기 출력 파일, 외부 도구가 만든 폴더·파일에는 해시가 없다.
파생물 곁에 manifest 파일을 두지 않는다.

서버는 남긴 해시나 HMAC을 다시 계산해 대조하지 않아 D03.09·D03.11에 연결할 시점이 없다.
`verify_chain`은 호출 기록 항목 자체의 해시 체인만 다시 계산하고 원래 출력 파일을 읽지 않는다 [13].
`register_finding`은 근거 항목의 원래 출력 파일을 읽어 설명의 낱말이 있는지만 보고 `outputHash`와 대조하지 않는다 [14].
HMAC 값은 보고서 파일 안에 함께 있다 [1][4].
`hash_and_lookup`은 받은 경로를 `hashdeep`으로 해시하는 범용 도구라서 D03.02에 연결하지 않는다 [15].

**한계.** `format`을 `json`으로 주면 보고서에 해시나 HMAC을 붙이지 않는다 [16].

`mount_evidence`의 pcap 분기는 `PCAP: <경로>` 문자열의 해시를 `outputHash`에 넣고 원래 출력 파일에는 `PCAP loaded: <경로>`를 쓴다 [17].
그래서 pcap 마운트의 원래 출력 파일에는 그 파일 내용의 해시가 남지 않는다.
