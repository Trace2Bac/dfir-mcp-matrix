# D07 발견사항 근거 검증

### D07.01 근거 참조 존재 확인

**구현.** 이 방식은 발견사항을 받는 커널 도구 `register_finding`과 근거를 더하는 `reassess_finding`에 있다 [1][2].
두 도구는 인용한 호출 ID가 모두 호출 기록에 있어야 발견사항을 받거나 근거를 더한다 [1][3].
인자 값을 대조하는 방식은 T01.06에서 본다.

호출 기록에는 실패한 호출과 서버 안 처리기 호출도 항목으로 들어가므로 그 ID도 근거로 받는다 [4].

저장소의 조사 스크립트 `scripts/run-investigation.ts`는 미리 적은 설명으로 발견사항을 등록하고 근거로 앞선 호출 ID 목록의 앞 5개 같은 구간을 넘긴다 [5].
이 근거는 존재 확인을 통과하지만 발견사항 설명과 관계없이 호출 순서로 고른 ID다 [5].

### D07.02 도구 출력과 내용 대조

**구현.** 이 방식은 `register_finding`이 발견사항을 등록하는 경로에 있다 [6].
서버는 발견사항을 저장한 뒤 설명을 낱말로 나누고 4자 이상인 낱말 가운데 정해 둔 흔한 낱말을 뺀다 [6].
인용한 호출마다 원래 출력에 그 낱말이 하나라도 있으면 맞은 근거로 센다 [6].
모든 근거가 맞으면 `VERIFIED`, 일부만 맞으면 `PARTIAL`, 하나도 맞지 않으면 `UNVERIFIED`다 [6].
원래 출력을 읽지 못한 근거는 맞지 않은 것으로 센다 [6].
대조 결과와 낱말이 가장 많이 겹친 줄(`provenance_snippets`)은 등록 응답에만 실린다 [6][7].
결과가 `UNVERIFIED`여도 발견사항은 이미 저장되어 있고 등급도 바뀌지 않으며 대조 결과는 발견사항에 저장되지 않는다 [6].

**한계.** `reassess_finding`으로 더하는 근거는 이 대조를 거치지 않는다 [3].
그래서 처음 등록 때 대조한 근거와 나중에 더해 등급을 올린 근거가 구별되지 않는다 [3][8].

### D07.03 출처 수·범주로 등급 산정

**구현.** 이 방식은 `register_finding`과 `reassess_finding`이 발견사항의 `confidence`를 정하는 경로에 있다 [8].
`computeConfidence`는 근거 호출이 하나면 `INFERRED`, 둘 이상이고 근거 호출의 도구 분류가 둘 이상이면 `CONFIRMED`, 분류가 하나면 `SUPPORTED`로 정한다 [8].
분류는 근거 호출 항목의 도구 이름을 연산 명세의 `category`로 바꾼 값이다 [2][9].
`register_finding`은 등급을 계산하기 전에 같은 ID를 하나로 줄인다 [10].
입력 스키마에 등급 인자가 없어 모델은 등급을 정하지 못한다 [11].
README는 Rough-set으로 확신 등급을 정한다고 적지만 `roughApproximation`·`shouldStopInvestigating`·`generateDecisionRules`는 `src/reasoning/index.ts`가 내보내기만 하고 MCP 도구 경로에서 부르는 곳이 없어 등급은 위 건수 규칙으로만 정해진다 [12].

`generate_report`는 `min_confidence`(기본 `INFERRED`)보다 낮은 등급과 `CONFLICTED` 발견사항을 보고서에서 뺀다 [13].
등록할 때 근거가 없으면 거부하므로 등록된 발견사항은 모두 `INFERRED` 이상이고 기본값으로는 모두 보고서에 실린다 [1][13].
`get_unsupported_findings`와 `get_investigation_health`는 `INFERRED` 발견사항을 근거가 모자란 발견사항으로 센다 [14].
`corroborate_finding`·`challenge_finding`은 교차 확인 연산과 전략을 권할 뿐 발견사항을 바꾸지 않는다(R04) [15][16].
교차 확인·반론 결과로 서버가 확정 여부를 정하는 장치는 없어 D07.04에는 연결하지 않는다.

**한계.** `reassess_finding`은 기존 근거와 더한 근거를 그대로 이어 붙여 등급을 다시 계산하고 같은 ID를 줄이지 않는다 [3].
그래서 근거 호출이 하나인 발견사항에 같은 ID를 다시 주면 근거 수가 2가 되어 `INFERRED`가 `SUPPORTED`로 오른다 [3][8].
분류를 셀 때 근거 호출의 종류를 가리지 않는다 [9].
`mount_evidence` 호출 항목은 `acquisition` 분류로 세고 실패한 호출도 그 도구의 분류로 센다 [4][9].
등록된 발견사항을 읽어 요약하는 `get_investigation_summary` 같은 `correlation` 분류 호출도 하나의 분류로 센다 [9][17].
그래서 파일 목록 호출 하나와 `mount_evidence` 항목을 인용한 발견사항도 `CONFIRMED`가 된다 [8][9].
등급 자료형에는 `CONFLICTED`가 있고 보고서는 그 등급을 빼지만 발견사항에 `CONFLICTED`를 넣는 코드는 없다 [13][18].
충돌 검사(`get_contradictions`)는 결과를 돌려주기만 해 서로 충돌하는 발견사항도 원래 등급으로 보고서에 실린다 [13][19].

```typescript
export function reassessFinding(
  finding: Finding,
  additionalEvidence: readonly LedgerEntryId[],
  existingLedgerIds: ReadonlySet<string>,
  getCategoryForEntry: (id: LedgerEntryId) => ArtifactCategory | undefined,
): Result<Finding, FindingError> {
  // Validate new evidence
  const missingEvidence = additionalEvidence.filter(
    (id) => !existingLedgerIds.has(id as string),
  );
  if (missingEvidence.length > 0) {
    return err(
      findingError(
        "reassess",
        `Additional evidence IDs not found: ${missingEvidence.join(", ")}`,
        "Provide valid ledger entry IDs.",
        finding.id,
      ),
    );
  }

  const allEvidence = [...finding.evidence, ...additionalEvidence];
  const newConfidence = computeConfidence(allEvidence, getCategoryForEntry);

  return ok({
    ...finding,
    evidence: allEvidence,
    confidence: newConfidence,
    lastReassessed: new Date().toISOString(),
  });
```

```typescript
export function computeConfidence(
  evidence: readonly LedgerEntryId[],
  getCategoryForEntry: (id: LedgerEntryId) => ArtifactCategory | undefined,
): ConfidenceLevel {
  if (evidence.length === 0) return "HYPOTHESIZED";
  if (evidence.length === 1) return "INFERRED";

  // Check if evidence comes from different artifact categories
  const categories = new Set<ArtifactCategory>();
  for (const id of evidence) {
    const cat = getCategoryForEntry(id);
    if (cat) categories.add(cat);
  }

  if (categories.size >= 2) return "CONFIRMED";
  return "SUPPORTED";
}
```

```typescript
    const existingCategories = new Set<string>();
    const allEntries = ledgerStore.getAllEntries();

    }
    // Suggest tools from categories NOT already used as evidence
```

```typescript
export function findingsConflict(a: Finding, b: Finding): boolean {
  // Same temporal range, same hosts, but different conclusions about same technique
  if (a.mitreTechnique && b.mitreTechnique && a.mitreTechnique === b.mitreTechnique) {
    // Same technique but one supports and one contradicts the same hypothesis
    const aSupports = new Set(a.supportsHypotheses.map(String));
    const bContradicts = new Set(b.contradictsHypotheses.map(String));
    for (const h of aSupports) {
      if (bContradicts.has(h)) return true;
    }
    const bSupports = new Set(b.supportsHypotheses.map(String));
    const aContradicts = new Set(a.contradictsHypotheses.map(String));
    for (const h of bSupports) {
      if (aContradicts.has(h)) return true;
    }
  }
  return false;
}
```
