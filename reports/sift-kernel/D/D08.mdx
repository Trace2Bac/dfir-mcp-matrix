# D08 검토 보고 산출물 구성

### D08.02 수행·누락 범위 포함

**구현.** 이 방식은 커널 도구 `generate_report`가 만드는 markdown·html·json 보고서에 있다 [1].
세 형식 모두 호출 기록 항목 수와 방법론 커버리지 백분율을 싣는다 [1][2][3].
markdown·html은 방법론 상태 기계의 상태와 조사 단계도 싣는다 [1][2].
보고서는 부른 연산의 목록이나 인자, 실패한 연산을 따로 싣지 않는다 [1][2][3].
커버리지는 증거 종류에 맞는 분석 분류의 연산 가운데 성공한 연산의 비율이다 [4].
비동기 연산은 작업을 시작한 순간 성공한 연산으로 기록된다 [5].

markdown·html에는 상태 기계가 `REPORT`가 아니면 아직 시도하지 않은 연산을 5~6개까지 적는 경고 절이 있다 [6][2].

**예외.** `generate_report`는 상태 기계가 `REPORT`가 아니면 발견사항이 없고 실행할 연산이 남은 경우만 거부하고 나머지 경우는 상태를 `REPORT`로 옮긴 뒤 보고서를 만든다 [7].
그래서 보고서를 만들 때 상태는 늘 `REPORT`이고 시도하지 않은 연산을 적는 경고 절은 실리지 않는다 [6][7].
커버리지 계산은 실패한 연산을 분모에서 뺀다 [4].
실행 파일이 없어 연산 대부분이 실패해도 성공한 몇 개만으로 커버리지가 높게 실리고 실패한 연산은 보고서 어디에도 나오지 않는다 [1][4].

### D08.03 발견사항과 근거 링크 포함

**구현.** 이 방식은 `generate_report`의 markdown·json 보고서에 있다 [8][3].
markdown 보고서는 발견사항마다 등급·종류·설명·MITRE tactic·기법과 근거 호출 ID 목록을 싣는다 [8].
json 보고서는 발견사항 객체를 그대로 싣고 그 안의 `evidence`가 근거 호출 ID 목록이다 [3][9].
근거 호출 ID는 호출 기록 항목의 ID이고 원래 출력 파일 이름이다 [10].
보고서는 그 파일의 경로를 싣지 않고 `trace_provenance`가 발견사항 ID로 근거 호출 항목을 돌려준다 [10].
등록할 때 낸 낱말 대조 결과와 근거 줄은 발견사항에 저장되지 않아 보고서에 실리지 않는다 [9].

**예외.** html 보고서는 발견사항마다 근거 수만 싣고 근거 호출 ID를 싣지 않는다 [11].
발견사항은 모델이 준 `evidence` 배열을 같은 ID까지 그대로 저장한다 [9].
보고서의 근거 수는 이 배열의 길이라서 같은 ID를 두 번 준 발견사항은 근거가 둘로 실린다 [8][11].

### D08.04 검증·한계 포함

**구현.** 이 방식은 `generate_report`의 세 형식 보고서와 html 보고서의 정답 대조 절에 있다 [12].
보고서를 만들 때 서버는 호출 기록 해시 체인을 다시 검사하고 그 결과를 markdown의 `Chain Integrity`·`Audit Trail`, html의 감사 절, json의 `chain_valid`에 싣는다 [12][13][3].
발견사항마다 서버가 근거 수와 분류로 정한 등급이 실리고 markdown·html은 등급별 수를 싣는다 [8][11].
증거 이미지의 해시 검증 결과와 연산별 해석 주의(`forensic_context`)는 보고서에 싣지 않는다 [1][2].
markdown의 "All findings trace to tool executions via evidence IDs"와 html의 `Append-Only SHA-256`·`SANS IR (DAG-Enforced)`는 조사와 관계없는 고정 문구다 [12][13].

html 보고서의 정답 대조 절은 사용자가 설치 폴더의 `ground-truth`에 넣은 정답 파일과 보고서의 발견사항을 대조한다 [14][15].
이 폴더 위치는 서버 코드 파일 위치로 정해지고 바꾸는 설정·인자는 없다 [14].
저장소에는 시험 이미지 두 개(`base-wkstn-01`·`rocba-cdrive`)의 정답 파일이 들어 있다 [14].
서버는 이미지 이름과 정답 파일 이름을 소문자로 바꾸고 `-`·`_`·공백을 지운 뒤 정답 파일 이름이 이미지 이름 안에 들어 있는 파일을 고른다 [14].
정답 파일의 `iocs`와 `mitre_ttps`로 IOC 탐지율·기법 탐지율·오탐 수·기대 판정을 계산해 싣는다 [15].
정답 IOC는 발견사항 설명·IOC에 그 값이 없어도 같은 MITRE 기법을 가진 발견사항이 있으면 탐지로 센다 [15].
`False Positives`는 보고서 발견사항 수에서 탐지한 정답 IOC 수를 뺀 값이다 [15].

**예외.** html 형식의 도구 응답은 `chain_valid`에 체인 검사 함수가 오류 없이 끝났는지를 싣는다 [16].
해시 체인 검사가 실패해도 그 값은 `true`이고 html 파일 본문은 감사 절에 `INTEGRITY VIOLATION`을 싣는다 [13][16].
정답 대조 절은 이미지 이름에 맞는 정답 파일이 없으면 폴더 목록의 첫 파일을 쓴다 [14].
그래서 정답 파일을 넣지 않은 사건의 보고서에도 다른 사건의 정답과 대조한 탐지율이 그 사건 이름과 함께 실린다 [14][15].
정답 파일을 읽다 오류가 나면 이 절은 알림 없이 빠진다 [14].

### D08.05 내보내기

**구현.** 이 방식은 `generate_report`에 있다 [17].
`format`에 따라 markdown(`.md`)·html(`.html`)·json(`.json`) 파일을 서버 출력 폴더에 쓰고 그 경로를 응답에 싣는다 [17][18][19].
파일 이름은 증거 이미지 파일 이름과 보고서 생성 시각으로 만든다 [17].
html 보고서의 `Export PDF` 단추는 브라우저 인쇄 창을 연다 [20].
`export_audit_log`는 호출 기록을 JSON이나 CSV 문자열로 응답에만 싣고 파일로 쓰지 않는다 [21].
보고서 본문에는 증거 경로·해시·크기와 도구·서버 버전이 없어 D08.01에는 연결하지 않는다 [1][2][3].
markdown·html 보고서의 HMAC은 D03에서 본다.
