# E01 증거 등록 관리

### E01.01 증거 ID·등록 목록

**구현.** 증거를 등록하는 경로는 커널 도구 `mount_evidence`와 서버를 실행할 때 주는 `--evidence` 인자 둘이다 [1][2].
서버는 증거를 서버 메모리의 조사 상태 `investigationState` 한 칸에 둔다 [1].
조사 상태에는 증거 경로 `imagePath`, 증거 종류 `evidenceType`, 형식 `imageFormat`, 파티션 시작 위치 `partitionOffset`, 파일시스템 종류 `filesystemType`이 들어간다 [1].
`--evidence`로 준 경로는 서버를 만들 때 `imagePath`의 처음 값이 된다 [1][2].
목록이 아니라 한 칸이라 증거를 여럿 두지 못하고 증거마다 따로 매긴 식별자도 없다 [1].
증거는 경로 문자열로만 구별한다.

`mount_evidence`는 받은 `image_path`의 확장자로 증거 종류를 가른다 [3][4].
메모리 확장자이고 경로에 `drive`·`disk`가 없으며 `vol windows.info.Info`가 성공하면 메모리 증거로 조사 상태를 덮어쓴다 [3].
pcap 확장자면 바로 네트워크 캡처로 조사 상태를 덮어쓴다 [3].
디스크 이미지는 마운트 명령을 실행하고 실패하면 `fls`로 이미지를 직접 읽을 수 있는지 본다 [4].
직접 읽히면 그 경로와 `fsstat`으로 알아낸 파일시스템 종류를 조사 상태에 적는다 [4].

분석 연산은 조사 상태의 `imagePath`를 증거 경로로 써서 외부 도구 인자를 만든다 [5].
조사 상태를 모델에게 돌려주는 도구는 없다 [6].
`get_investigation_state`는 단계·능력·발견사항 수만 돌려주고 증거 경로는 싣지 않는다 [6].
`mount_evidence` 호출마다 호출 기록에 `image_path`와 형식을 적은 항목이 남지만 이것은 호출 기록이고 L02에서 본다 [7].
조사 상태에는 증거의 크기·등록 시각·등록한 주체가 없어 E01.03에는 해당하지 않는다 [1].

조사 상태는 메모리에만 있다.
HTTP 전송은 요청마다 서버를 새로 만들어 조사 상태가 `--evidence`의 값으로 돌아간다 [8].
상태가 얼마나 남는지는 P04에서 본다.

**예외.** 디스크 이미지의 마운트 명령이 성공하면 조사 상태의 `imagePath`가 비었을 때만 새 경로를 적는다 [9].
`--evidence`를 주었거나 앞서 다른 증거를 등록한 서버에서는 새 이미지가 조사 상태에 오르지 않는다 [1][9].
응답은 새 경로를 `image_path`로 적고 "mounted"라고 알리지만 분석 연산은 앞의 경로를 읽는다 [5][9].
이 경로에서는 `fsstat`을 실행하지 않아 응답의 `evidence_type`도 앞 증거의 값이다 [9].

`reset_investigation`은 능력·발견사항·호출 기록을 지우고 새 사건을 시작할 수 있다고 알리지만 조사 상태는 지우지 않는다 [10].
그래서 초기화 뒤에도 앞 사건의 증거 경로와 파티션 시작 위치가 남고 위의 마운트 성공 경로로는 새 증거가 오르지 않는다 [9][10].

`--memory` 인자는 도움말에 메모리 덤프 경로로 적혀 있고 서버 설정 `memoryPath`에 들어간다 [11].
서버 코드에서 `memoryPath`를 읽는 곳은 없어 이 인자로 준 메모리 덤프는 조사 상태에 오르지 않는다 [11].
이 사실을 알리는 응답이나 기록은 없다.

pcap 증거는 받은 경로에 파일이 있는지 보지 않고 조사 상태에 적는다 [3].
없는 경로로 부르더라도 응답은 "mounted"다 [3].

### E01.02 수집 위치와 저장 위치 기록

**구현.** 조사 상태의 `imagePath`는 `mount_evidence`가 받은 문자열이나 `--evidence` 값을 그대로 담는다 [1][3][4].
서버는 경로를 실제 경로로 풀거나 정규화하지 않는다 [3][4].
서버는 증거를 다른 곳으로 옮기지 않으므로 이 경로는 증거가 놓인 저장 위치다.
조사 상태에는 마운트 지점을 담는 `mountPoint`가 있지만 이 값을 적는 코드는 없다 [1].
마운트 응답은 마운트 지점을 `/mnt/evidence/`로 적지만 분석 연산은 그 지점을 쓰지 않는다(E03) [9].
서버에는 단말에서 증거를 수집하는 기능이 없어 증거를 어디서 가져왔는지는 남기지 않는다.
새 이미지가 조사 상태에 오르지 않는 경우는 E01.01의 예외와 같다.
