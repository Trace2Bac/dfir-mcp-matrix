# P05 사건 자료 정리

### P05.01 모델 도구로 삭제·초기화

**구현.** 커널 도구 `reset_investigation`은 인자 없이 조사를 초기화한다 [1].
능력 집합, 방법론 상태 기계, 켠 workflow, 추론 엔진, 발견사항, 가설을 비우고 `ledger.db`의 `ledger` 표 행을 모두 지운다 [1][2][3].
모델이 부를 수 있는 이 도구 하나로 호출 기록 전체가 지워진다 [1][3].
도구 가운데 이 도구만 `destructiveHint`가 참이고 명세 설명은 모든 상태를 지우고 새 조사를 시작한다고 적는다 [4].
응답은 지운 발견사항·가설·호출 기록 항목의 수를 알린다 [1].
지운 대상과 시각을 남기는 기록은 없다 [1][3].
지운 뒤 첫 호출 기록 항목은 앞 항목이 없어 처음 해시로 체인을 다시 시작한다 [5].
원래 출력 파일, 보고서, 이미지에서 꺼낸 파일, 백그라운드 작업 출력은 지우지 않는다 [1].
진행 중인 조사에서 발견사항 한 건을 지우는 도구는 없다.

**예외.** 명세 설명과 달리 조사 상태의 이미지 경로·파티션 오프셋·증거 종류는 지우지 않는다 [1][6].
방법론 상태 기계도 `reset`에서 증거 종류와 열린 가설 수를 그대로 둔다 [2].
초기화한 뒤 다른 이미지를 마운트 명령으로 마운트하면 조사 상태의 이미지 경로가 비어 있지 않아 바뀌지 않고 분석 연산은 앞 이미지를 읽는다 [7].
백그라운드 작업 목록과 권고 추종 집계, HMAC 키도 그대로 남는다 [1][6].

### P05.02 운영자 명령으로 삭제·초기화

**구현.** 출력 폴더의 파일을 지우는 기능은 시작 인자 `--fresh`뿐이다 [8].
`--fresh`를 주면 서버를 만들기 전에 출력 폴더를 하위 폴더까지 지운다 [8].
`ledger.db`, `raw/`, 보고서, 이미지에서 꺼낸 파일, 백그라운드 작업 출력은 모두 이 폴더 안에 놓이므로 함께 지워진다 [8].
모델 도구 `reset_investigation`은 이 파일들을 지우지 못한다 [1].
지운 사실은 `--verbose`일 때 표준 오류에 한 줄 찍히고 다른 기록은 남지 않는다 [8].
README와 사용 안내의 MCP 클라이언트 설정 예시는 이 인자를 넣어 둔다 [9].

### P05.03 자동 정리

**구현.** 레지스트리 연산은 `regipy-plugins-run`이 출력 폴더에 쓴 `regipy_out.json`을 읽은 뒤 곧바로 지운다 [10].
지운 사실은 기록하지 않는다 [10].
이 파일의 내용은 그 연산의 원래 출력으로 `raw/`에 남는다 [10][11].
이미지에서 꺼낸 파일과 백그라운드 작업 출력을 스스로 지우는 코드는 없다.

### P05.04 원본 증거까지 삭제 대상에 포함

**구현.** `--fresh`는 `--output`으로 받은 경로를 검사 없이 하위 폴더까지 지운다 [8].
그 경로가 증거를 담은 폴더이거나 `--evidence`로 준 이미지를 담고 있어도 막지 않는다 [8].
이 삭제는 MCP 서버를 시작하기 전에 일어나 모델 도구로는 부를 수 없다.

### P05.05 원본 증거를 삭제 대상에서 제외

**구현.** `reset_investigation`이 지우는 것은 프로세스 메모리의 상태와 `ledger.db`의 `ledger` 표 행이다 [1][3].
파일을 지우지 않으므로 증거 경로는 대상에 없다 [1].
자동 정리가 지우는 `regipy_out.json`도 서버가 출력 폴더 안에 정한 고정 경로다 [10].
