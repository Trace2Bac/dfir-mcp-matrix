# T05 분석 도구 검증

### T05.02 선언: 설정·호출 인자 지정

**구현.** 이 방식은 YARA 룰에만 있다.
`scan_yara`는 호출 인자 `rules`로 룰 경로를 받고 주지 않으면 `/usr/share/yara/rules`를 쓴다 [1].
`scan_memory_yara`는 `rules`를 Volatility의 `--yara-file` 값으로 넘긴다 [1].
서버는 받은 경로를 넘기기만 하고 그 룰의 버전이나 내용을 읽지 않는다 [1].

다른 도구와 참조 자료는 버전도 위치도 설정으로 정하지 않는다.
매핑은 외부 도구를 실행 파일 이름으로만 적고 실행기는 `/usr/local/bin`, 서버 계정 홈의 `.cargo/bin`·`.local/bin`, `/opt/volatility3`, `/opt/CyberChef`를 원래 `PATH` 앞에 두고 그 이름을 찾는다 [2].
실행 파일을 찾지 못하면 짝으로 정한 다른 실행 파일로 바꿔 실행한다(`ewfverify` 대신 `img_stat`, `regipy-plugins-run` 대신 `rip.pl` 등) [3].
`foremost`는 설정 파일 인자 없이 불러 설치된 기본 설정을 쓴다 [4].
Volatility 연산은 심볼 위치를 주지 않아 Volatility가 심볼을 스스로 찾는다 [4].
저장소의 설치 스크립트는 `pacman`으로 Sleuth Kit·Volatility 3·wireshark-cli·foremost·hashdeep을 버전 없이 설치한다 [5].
README는 도구 실행 환경으로 SIFT Workstation을 전제할 뿐 도구 버전을 적지 않는다 [6].
`package.json`은 서버가 불러오는 npm 라이브러리의 버전을 정확히 적지만 그 가운데 증거를 분석하는 라이브러리는 없다 [7].
실행 중에 외부 도구나 룰의 버전을 묻는 코드는 없다.

**예외.** 분류 도구가 모델에게 알리는 입력 schema는 YARA 룰 경로 인자의 이름을 `yara_rules`로 적는다 [8].
매핑은 `rules`만 읽으므로 schema대로 `yara_rules`를 넘기면 그 값은 쓰이지 않는다 [1][8].
이때 `scan_yara`는 기본 룰 폴더로 실행하고 `scan_memory_yara`는 빈 `--yara-file` 값으로 실행한다 [1].
