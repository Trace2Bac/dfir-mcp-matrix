# R08 시간값 처리

### R08.01 시간 변환 전 값 유지

**구현.** 외부 도구 출력의 시각은 서버가 바꾸지 않는다.
기본 처리는 출력 글을 그대로 담는다 [1].
`fls`의 시각 열은 Sleuth Kit이 출력한 문자열 그대로 `name`·`path` 글 안에 남는다 [2][3].
`istat` 파서는 시각 문자열을 `value`에 그대로 둔다 [4].
이벤트 로그 파서는 `SystemTime` 값을, regipy 파서는 플러그인이 낸 `timestamp`·`last_write` 값을 문자열로 옮긴다 [5][6].

서버가 결과를 다시 만드는 처리기는 다르다.
`detect_timestomping`은 앞선 `istat` 출력에서 시각 문자열의 괄호 속 시간대를 떼고 `Date.parse`로 밀리초 값을 만든다 [7].
결과에는 그 값을 `toISOString()`으로 바꾼 문자열만 들어가고 원래 문자열은 없다 [8].

### R08.02 정규화 시간과 변환 전 값 병기

**구현.** `istat` 파서는 시각마다 원래 문자열 `value`와 `Date.parse`로 변환한 밀리초 값 `epoch`를 한 항목에 둔다 [4].
괄호 속 `(UTC)`만 ` UTC`로 바꾸고 다른 시간대 표기는 바꾸지 않은 채 `Date.parse`에 넘긴다 [4].
응답은 `epoch`가 서버가 계산한 값이라는 것을 알리지 않는다 [4].

Plaso 파서의 JSON 분기는 정수 시각을 ISO 문자열로 바꾸고 원래 객체를 `extra`에 남긴다 [9].
매핑된 `filter_timeline`은 l2tcsv 글을 내므로 이 분기에 닿지 않는다 [10][9].

**한계.** `Date.parse`가 해석하지 못한 시각은 `epoch`를 0으로 적는다 [4].
응답에는 1970-01-01 시각과 해석 실패를 가르는 값이 없다 [4].
파서는 이때 `epoch_zero_timestamp` 이상 징후를 붙이고 조작이나 해석 실패일 수 있다고 적는다 [11].

### R08.03 시간대·단위·정밀도 표시

**구현.** Sleuth Kit은 시각 문자열 끝에 괄호로 시간대 약칭을 붙인다 [3].
서버는 `fls`·`istat`에 시간대 인자 `-z`를 넘기지 않으므로 그 약칭은 서버 프로세스 환경의 지역 시간대다 [12][3].
`fls`의 `name`과 `istat`의 `value`는 이 문자열을 그대로 싣는다 [2][4].
`detect_timestomping`이 만든 시각 문자열은 `toISOString()`이 붙인 UTC 표기 `Z`로 끝난다 [8].
`istat`의 `epoch`는 단위를 필드 이름이나 값에 적지 않는다 [4].
이벤트 로그·regipy 시각은 도구가 낸 표기를 따른다 [5][6].

function extractTimestamp(raw: string, section: string, field: string): number | null {
  // Match istat timestamp format: "2021-01-01 12:00:00 (UTC)" or ISO "2021-01-01T12:00:00Z"
  const sectionRegex = new RegExp(`\\$${section}[\\s\\S]*?${field}[:\\s]+([\\d\\-T:.Z+\\s]+?)(?:\\s*\\(|\\n|$)`, "i");
  const match = raw.match(sectionRegex);
  if (match?.[1]) {
    const cleaned = match[1].trim().replace(/\s*\(.*\)$/, "");
    const ts = Date.parse(cleaned);
    return isNaN(ts) ? null : ts;
  }
  return null;
}
