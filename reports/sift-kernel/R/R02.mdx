# R02 대량 결과 전달

### R02.01 문자·항목 상한

**구현.** 외부 도구 실행기는 표준 출력을 50 MiB와 50만 줄에서 끊는다 [1].
서버는 연산에 따라 더 작은 줄 상한을 준다.
`search_filename`은 5만 줄, 재귀 `list_directory`는 2만 줄, 이벤트 로그 연산은 3천 줄이다 [2].
실행기는 줄을 출력 조각 단위로 세므로 상한을 넘은 조각까지 모은 뒤 프로세스를 끊는다 [3].
상한이나 시간 제한에 걸려 끊어도 모은 출력이 있으면 실행기는 종료 코드 -1과 출력을 돌려준다 [4].
서버는 이 결과를 성공으로 처리한다 [5].
전용 파서가 없는 연산의 출력은 기본 처리에서 1만 자로 자른다 [6].
서버 안 처리기도 목록을 앞에서 자른다 [7][8][9].
`list_event_logs`는 50개, `correlate_logon_events`는 세션 20개, `check_services`는 서비스 30개, `check_scheduled_tasks`는 호출 기록 항목마다 10줄까지 싣는다 [7][8].
Linux 로그 처리기는 100줄까지, `parse_bash_history`는 200줄까지 싣는다 [9].
모델은 이 상한들을 호출 인자로 바꿀 수 없다 [2][6].

줄 상한이나 시간 제한에서 끊긴 결과에는 잘림 표시도 건수도 없다 [4][5].
파일 60,000개가 든 이미지에서 `search_filename`은 50,015건을 잘림 표시 없이 돌려줬다 [10].
외부 도구 출력의 전용 파서 단계에는 건수 상한이 없다.
서버는 원래 출력을 `raw` 폴더에 파일로 보관하지만 그 파일을 읽어 주는 도구는 없어 R02.04·R02.08에는 연결하지 않는다 [11].

**한계.** regipy 연산은 표준 출력 대신 결과 JSON 파일을 크기 제한 없이 읽으므로 외부 도구 결과인데도 실행기의 출력 상한이 적용되지 않는다 [12].

### R02.02 전체·반환 건수 표시

**구현.** 이 방식은 서버 안 처리기 `list_event_logs`에 적용된다 [13].
`list_event_logs`는 앞서 실행한 나열 출력에서 찾은 `.evtx` 줄 수 `evtx_files_found`, 앞 50개 목록 `files`, 50개를 넘으면 반환 범위를 적은 `note`를 함께 돌려준다 [13].
`correlate_logon_events`·`check_services`와 Linux 로그 처리기는 전체 수 필드와 잘린 목록만 주고 반환 범위를 알리는 문장은 없다 [7][8][9].

**한계.** 처리기가 만든 JSON 글이 1만 자를 넘으면 기본 처리에서 잘려 `note`와 목록 뒷부분이 사라지고 남은 글은 JSON으로 읽을 수 없다 [6][13].
맨 앞의 `evtx_files_found`는 남으므로 전체 수는 보이지만 몇 개를 돌려줬는지는 보이지 않는다 [13].
줄 하나가 약 195자를 넘으면 50개만으로 1만 자를 넘는다.
처리기 코드를 떼어 실행해 보니 352자 줄 55개를 넣었을 때 `note`가 사라졌다 [13].
`evtx_files_found`는 앞선 나열 출력의 줄을 중복 제거 없이 세므로 같은 폴더를 두 번 나열하면 실제 파일 수보다 커진다 [13].
`check_scheduled_tasks`의 `tasks_found`는 호출 기록 항목마다 10줄로 자른 뒤의 수라 전체 수가 아니다 [8][14].

### R02.06 값 단위 잘림

**구현.** 이벤트 로그 파서는 사건마다 `message`를 500자, 원래 줄 `raw`를 1,000자에서 자른다 [15].
`register_finding` 응답의 근거 줄 `provenance_snippets.snippet`은 200자에서 자른다 [16].
비동기 작업 결과 `result`는 2,000자에서 자르고 전체 출력 파일 경로 `outputPath`를 함께 둔다 [17].
레지스트리·Plaso 파서는 이상 징후의 `affected_items`에 넣는 값을 80~200자에서 자른다 [18].
레지스트리 파서는 결과 항목의 `key`·`value`·`data`는 자르지 않는다 [18].
어느 경우에도 값이 잘렸다는 표시는 없다.

### R02.07 건수 없는 잘림 표시

**구현.** 1만 자에서 자른 출력 끝에는 `...[truncated]`를 붙인다 [6].
이 표시는 파서가 없는 연산의 1만 자 잘림에만 붙는다 [6].
기본 처리는 전체 줄 수 `recordCount`와 잘렸는지를 뜻하는 `rawTruncated`도 만든다 [6].
서버는 파서 결과에서 `data`만 응답에 넣으므로 이 두 값은 모델에게 가지 않는다 [19].

    e.tool === "list_directory" || e.tool === "search_filename" || e.tool === "get_filesystem_info"
  );

  const evtxFiles: string[] = [];

    const raw = ctx.rawOutputs.get(entry.id as string) ?? "";

        evtxFiles.push(line.trim());
