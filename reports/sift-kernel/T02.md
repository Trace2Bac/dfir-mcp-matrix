# T02 실행 허용 범위 제한

### T02.06 고정 명령·템플릿

**구현.** 외부 도구를 쓰는 분류 연산은 서버 코드의 매핑 `getToolBinaryMapping`이 실행 파일과 인자 배열의 모양을 정한다 [1].
모델 값은 매핑이 정한 자리에만 들어간다 [2].
`search_pcap`의 `filter`는 `-Y` 뒤에, `parse_registry_key`의 `plugin`은 `-p` 뒤에, `generate_timeline`의 `parsers`는 `--parsers` 뒤에 들어간다 [2].
실행기는 실행 파일 이름을 허용 목록 `ALLOWED_BINARIES`와 대조하고 목록 밖이면 실행하지 않는다 [3].
실행 파일 이름은 매핑이 정하므로 모델이 고르지 못한다 [1][3].
`mount_evidence`도 확장자에 따라 서버 코드가 마운트 명령과 인자를 고르고 받은 경로만 그 자리에 넣는다 [4].
셸을 거치지 않는 실행 방식은 T04에서 본다.

**예외.** 위치 인자 자리에 들어가는 모델 값은 `-`로 시작하는지 보지 않고 앞에 `--`를 두어 옵션 해석을 끊는 곳도 없다 [5].
이미지 뒤에 붙는 `inode`·`start_inode`, `extract_strings`·`hash_and_lookup`·`parse_srum`·`parse_registry_key`의 `path`, `scan_yara`의 `rules`가 여기에 든다 [5].
`mount_evidence`의 `image_path`도 마운트 명령과 `fls`·`mmls`·`fsstat` 확인 명령의 위치 인자로 들어간다 [4][6].
이 값들이 하이픈으로 시작할 때 각 외부 도구가 옵션으로 읽는지는 확인하지 못했다.

실행기는 실행 파일을 찾지 못하면 짝으로 정한 다른 실행 파일로 같은 인자 배열을 다시 실행한다 [7].
`regipy-plugins-run`이 없으면 regipy용으로 만든 `-o`·`-p` 인자 배열이 RegRipper의 `rip.pl`에 넘어간다 [7][2].
`evtx_dump`가 없으면 `-o jsonl` 인자 배열이 `evtxexport`에 넘어간다 [7][8].
바꿔 부른 실행 파일이 이 인자를 어떻게 읽는지는 확인하지 못했다.

### T02.07 연산·플러그인 허용 목록

**구현.** 분류 도구는 `operation`이 없으면 `MISSING_OPERATION`, 그 분류의 연산 목록에 없으면 `INVALID_OPERATION` 오류를 돌려주고 실행하지 않는다 [9].
연산 목록은 능력 명세 `TOOL_SPECS` 가운데 그 분류에 속하고 커널 도구가 아닌 연산이다 [10].
분류 도구를 거치지 않고 내부 연산 이름으로 직접 불러도 능력 대조 단계가 `TOOL_SPECS`에 없는 이름을 `Unknown tool`로 거부한다 [9][11].
그래서 명세 밖의 연산은 어느 호출 경로로도 실행되지 않는다.

목록 안의 연산 가운데 자유 값을 받는 연산이 있다 [12].
`search_pcap`의 tshark 표시 필터, `parse_registry_key`의 regipy 플러그인 이름, `generate_timeline`의 Plaso 파서 목록, `search_filename`의 정규식은 서버 코드가 구조나 이름을 검사하지 않는다 [12].
그런 질의를 좁히는 장치가 없어 T02.08에는 연결하지 않는다.

도구 단위로 좁히는 장치는 없다.
`ListTools`는 커널 도구와 분류 도구를 조건 없이 모두 낸다 [13].
시작 인자 `--all-tools`는 설정 값으로 읽어 두지만 서버 코드가 그 값을 쓰지 않는다 [14].
`activate_workflow`·`deactivate_workflow`는 활성 워크플로 집합을 바꾸고 `notifications/tools/list_changed`를 보내지만 `ListTools`와 호출 처리는 그 집합을 보지 않는다 [13][15].
도구 annotation `readOnlyHint`·`destructiveHint`는 도구 목록에 싣는 표시이고 호출을 막지 않는다 [13].
