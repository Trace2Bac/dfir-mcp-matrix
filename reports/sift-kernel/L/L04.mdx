# L04 기록 위변조 방지

### L04.01 해시 체인

**구현.** 이 방식은 호출 기록 `ledger.db`의 `ledger` 표 항목 전부에 적용된다 [1].
항목을 쓰는 다섯 곳은 모두 마지막 항목을 읽어 `hashEntry`로 SHA-256을 구하고 그 값을 새 항목의 `prevHash`에 넣는다 [2][3].
호출 기록이 비어 있으면 문자열 `GENESIS`의 SHA-256을 `prevHash`로 쓴다 [2][3].
`hashEntry`가 해시하는 직렬화에는 `prevHash`를 포함해 항목의 필드가 모두 들어간다 [2].
그래서 중간 항목의 필드를 고치거나 항목을 지우거나 순서를 바꾸면 다음 항목의 `prevHash`와 어긋난다 [2][4].

항목 순서는 SQLite `rowid`로 정하고 항목에는 일련번호 필드가 없다 [5][1].
해시 체인 끝 값을 호출 기록 밖에 두지 않아 마지막 항목을 고치거나 지운 것은 해시 체인만으로 드러나지 않는다 [4].
`generate_report`는 보고 시점의 호출 기록 항목 수를 보고서에 적는다 [6].
그래서 보고 뒤에 마지막 항목을 지운 것은 보고서의 항목 수와 지금 항목 수를 사람이 견주어 알아볼 수 있다.
항목 수를 그대로 둔 채 고친 것은 이 대조로 드러나지 않고 보고서는 호출 기록과 같은 출력 폴더에 쓰는 파일이다 [6][7].
해시 체인에는 원래 출력 파일의 경로만 들어 있고 `outputHash`는 파서 결과를 직렬화한 값의 해시라 원래 출력 파일 내용을 고친 것도 해시 체인에 드러나지 않는다 [2][8].

**한계.** 커널 도구 `reset_investigation`은 인자 없이 `ledger` 표의 항목을 모두 지운다 [9].
지운 뒤 쓰는 첫 항목은 다시 `GENESIS` 해시로 시작하고 빈 호출 기록도 새로 쌓은 호출 기록도 유효하다고 검증된다 [3][4].
그래서 모델이 이 도구로 호출 기록 전체를 지우고 새로 쌓은 것은 해시 체인으로 드러나지 않는다 [4][9].

### L04.03 검증 도구

**구현.** 이 방식은 커널 도구 `verify_chain`과 `generate_report`에 적용된다 [10][6].
`verify_chain`은 인자 없이 호출 기록 항목을 `rowid` 차례로 모두 읽어 첫 항목의 `prevHash`가 `GENESIS` 해시인지와 이후 항목마다 앞 항목의 해시와 같은지 확인한다 [4][5][10].
어긋나면 `valid`를 거짓으로 하고 어긋난 항목의 차례를 문구에 담아 돌려준다 [4][10].
`generate_report`는 같은 검증을 실행해 그 결과를 보고서의 해시 체인 상태로 적는다 [6].
검증은 앞뒤 항목의 연결만 보므로 마지막 항목의 변경과 호출 기록 전체의 재생성은 찾아내지 못한다 [4].

**한계.** HTML 형식의 `generate_report` 응답은 `chain_valid`를 검증 결과의 `valid`가 아니라 검증이 오류 없이 끝났는지로 채운다 [11].
그래서 해시 체인이 끊겨도 그 응답의 `chain_valid`는 참이다 [11].
같은 호출이 쓴 HTML 보고서 본문은 검증 결과의 `valid`를 적는다 [11][6].

/** Serialize a ledger entry deterministically for hashing */
export function serializeEntry(entry: LedgerEntry): string {
  return JSON.stringify({
    id: entry.id,
    tool: entry.tool,
    params: entry.params,
    outputHash: entry.outputHash,
    rawOutputPath: entry.rawOutputPath,
    timestamp: entry.timestamp,
    prevHash: entry.prevHash,
    capabilitiesHeld: [...entry.capabilitiesHeld].sort(),
    findingsProduced: [...entry.findingsProduced],
    anomaliesFlagged: [...entry.anomaliesFlagged],
    durationMs: entry.durationMs,
    success: entry.success,
    errorMessage: entry.errorMessage,
  });
}

/** Compute hash of a serialized entry */
export function hashEntry(entry: LedgerEntry): string {
  return createHash("sha256").update(serializeEntry(entry)).digest("hex");
}

        valid: false,
        brokenAt: i,
        message: `Chain broken at entry ${i}. Expected prevHash: ${expectedPrevHash}, Got: ${entries[i]!.prevHash}`,
      };
    }
  }
