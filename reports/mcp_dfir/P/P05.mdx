# P05 사건 자료 정리

### P05.01 모델 도구로 삭제·초기화

**구현.** 이 방식은 `run_find`에 적용된다 [1].
서버에는 사건 자료를 지우거나 초기화하려고 둔 MCP 도구가 없다 [2].
`run_find`는 인자 목록을 공백으로 이은 문자열에 `-exec`가 들어 있는지만 확인하고 나머지 인자는 받은 대로 컨테이너의 `find`에 넘긴다 [1].
그래서 모델이 `-delete`를 주면 `find`가 찾은 파일을 지운다 [1][3].
`/artifacts` 아래에 만든 파일의 경로와 `-delete`를 `run_find`에 주자 그 파일이 지워졌다 [3].
지우는 호출은 다른 명령과 같은 모양으로 명령 기록에 남는다 [3][4].
명령 기록에는 `find` 명령 문자열과 종료 코드가 남고 지운 파일의 목록은 남지 않는다 [3][4].
분석 메모나 명령 기록 항목을 지우는 도구는 없다 [2].

### P05.02 사용자 명령으로 삭제·초기화

**구현.** 이 방식은 시작 인자 `--clear-case-dir`와 `--clear-docker`에 적용된다 [5].
`--clear-case-dir`는 사건 폴더를 지워도 되는지 묻고 사용자가 `yes`를 입력해야 지운다 [6].
다른 값을 입력하면 지우지 않고 종료 코드 1로 끝난다 [6][7].
`yes`를 받으면 사건 폴더 아래 `artifacts`, `analysis`, `evidence`, `symbols` 폴더를 하위 폴더까지 지운다 [6].
`--case-dir`를 주지 않으면 서버를 실행한 현재 작업 폴더가 대상이다 [8].
서버는 받은 폴더가 서버가 만든 사건 폴더인지 확인하지 않고 그 아래 네 이름의 폴더를 지운다 [6].
명령 기록과 분석 메모는 `analysis`에, 파생물은 `artifacts`에, 내려받은 심볼은 `symbols`에 있으므로 모두 함께 지워진다 [6][9].
사건 폴더 자체와 그 아래 다른 파일은 남는다 [7].
지운 뒤에는 `Case directory cleared`를 출력하고 서버를 시작하지 않고 끝난다 [6].
지우기 전에 자료를 다른 곳으로 옮기거나 복사하지 않고 지운 사실을 남기는 기록도 없다 [6].
`shutil.rmtree`를 `ignore_errors=True`로 부르므로 지우지 못한 파일이 있어도 알리지 않는다 [6].
이 인자는 그 사건 폴더의 컨테이너를 지우지 않는다 [6][7].
서버는 그 사건 폴더를 쓰는 다른 서버 프로세스가 있는지 확인하지 않는다 [6].

`--clear-docker`는 컨테이너를 멈추고 지우는 `clear_forensic_container`를 부른 뒤 서버를 시작하지 않고 끝난다 [10][11].
README의 인자 설명에는 `--init`, `--clear-case-dir`, `--clear-docker`가 없다 [12].

서버는 끝날 때 컨테이너를 멈추기만 하고 지우지 않는다 [13].
서버가 종료나 작업 완료 때 사건 자료를 스스로 지우는 코드는 없다.

**한계.** `--clear-docker`를 실행해도 컨테이너는 지워지지 않는다 [14].
`clear_forensic_container`는 `self.container`가 `None`이 아닐 때만 컨테이너를 멈추고 지운다 [11].
`self.container`는 객체를 만들 때 `None`이고 `start_forensic_container`가 값을 정한다 [15].
`--clear-docker` 경로는 `start_forensic_container`를 부르지 않으므로 `clear_forensic_container`는 아무 일도 하지 않고 프로세스는 종료 코드 0으로 끝난다 [10][14].
컨테이너가 있는 사건 폴더에 `--clear-docker`를 실행한 뒤에도 그 컨테이너가 남아 있었다 [14].
`--clear-docker` 경로는 `config.load`와 `data_manager` 모듈을 거치므로 사건 폴더에 없는 하위 폴더를 만든다 [16].
빈 폴더에 `--clear-docker`를 실행하자 아무것도 지우지 않고 그 폴더에 `analysis`, `artifacts`, `evidence`, `symbols`와 `analysis/command_history`, `analysis/analyst_notes`를 만들었다 [14].
두 인자의 도움말은 서버를 시작하기 전에 지운다고 적지만 두 경로 모두 서버를 시작하지 않고 끝난다 [5][6][10].

### P05.04 원본 증거까지 삭제 대상에 포함

**구현.** 이 방식은 `--clear-case-dir`에 적용된다 [6].
지우는 폴더 넷에 원본 증거를 두는 `evidence`가 들어 있다 [6].
README는 메모리 덤프와 디스크 이미지 같은 증거 파일을 사건 폴더의 `evidence/`에 두라고 적는다 [17].
그래서 사용자가 README대로 둔 증거 파일은 `--clear-case-dir`로 함께 지워진다 [6][7].
확인 문구는 사건 폴더 경로와 되돌릴 수 없다는 것을 적고 증거가 지워진다는 것은 적지 않는다 [6].
지울 대상에서 `evidence`를 빼는 인자는 없다 [5][6].

### P05.05 원본 증거를 삭제 대상에서 제외

**구현.** 이 방식은 `run_find`의 `-delete`처럼 컨테이너에서 실행되는 삭제에 적용된다 [1][18].
서버는 컨테이너를 만들 때 `evidence`와 `analysis` 폴더를 읽기 전용으로 연결하고 `symbols`와 `artifacts`만 쓸 수 있게 연결한다 [18].
그래서 연결한 네 폴더 가운데 컨테이너의 명령이 지울 수 있는 것은 `artifacts`와 `symbols` 아래의 파일이다 [18][19].
`/evidence` 아래 파일의 경로와 `-delete`를 `run_find`에 주자 `find`가 `Read-only file system` 오류로 끝났고 파일은 남았다 [19].
`/analysis` 아래의 결과 본문 파일에 `-delete`를 주었을 때도 같은 오류로 끝났다 [19].

**한계.** 서버는 같은 이름의 컨테이너가 이미 있으면 그 컨테이너의 연결 설정을 확인하지 않고 다시 쓴다 [20].
`evidence`를 쓸 수 있게 연결한 같은 이름의 컨테이너를 미리 만들어 두고 서버를 실행하자 `run_find`의 `-delete`가 호스트의 `evidence` 폴더에 있는 파일을 지웠다 [21].
