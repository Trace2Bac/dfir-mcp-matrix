# P01 분석 방법 적합성 확인

### 미구현

**판단.** 서버는 증거 형식이나 OS를 판별하지 않고 모델이 정한 도구, 플러그인, 인자를 대조 없이 컨테이너 안 분석 도구에 넘긴다 [1][2].
`list_files`는 `evidence` 폴더의 파일마다 이름, 컨테이너 안 경로, 크기만 돌려주고 파일의 종류를 정하지 않는다 [3].
`run_volatility_command`는 받은 인자 목록 앞에 `vol -s /symbols -r jsonl`만 붙여 실행한다 [1].
증거 경로를 주는 `-f` 인자와 `windows.`·`linux.`로 시작하는 플러그인 이름은 모델이 정한다 [1].
`run_sleuthkit_command`는 `tool`이 코드에 적어 둔 Sleuth Kit 명령 30개 가운데 하나인지만 확인하고 파일 시스템 종류나 파티션 시작 위치 같은 인자는 받은 대로 넘긴다 [2].
`run_strings`·`run_grep`·`run_find`·`get_hash`도 받은 경로가 어떤 파일인지 확인하지 않는다 [4][5].
`untar_file`은 압축 방식을 파일 이름이나 내용으로 정하지 않고 `compression` 인자로 받는다 [6].

심볼을 준비하는 도구도 증거와 대조하지 않는다.
`download_windows_symbol`은 모델이 준 `pdb_name`, `guid`, `age`로 내려받을 주소와 저장 경로를 만든다 [7].
서버는 이 값이 분석할 메모리 이미지의 커널에서 나온 값인지 확인하지 않는다 [7].
`search_linux_symbols`는 모델이 준 정규식을 심볼 맵의 배너 문자열과 맞추고 메모리 이미지에서 배너를 읽지 않는다 [8].

도구 설명은 맞는 입력을 안내하기만 한다.
`run_volatility_command`의 설명은 `-f /evidence/example.mem`처럼 파일을 지정하라는 것과 심볼을 따로 내려받아야 할 수 있다는 것을 적는다 [1].

메모리 이미지의 계층과 심볼을 찾는 일은 Volatility 3가 스스로 한다.
분석 도구가 0이 아닌 종료 코드로 끝나면 서버는 입력을 다시 판별하지 않고 그 종료 코드를 기록해 정상 응답으로 돌려준다 [9].
텍스트 파일을 `-f`로 주고 `windows.info`를 실행하자 `exit_code`가 1인 응답이 돌아왔고 결과 본문에는 `Unsatisfied requirement` 문구가 남았다 [10].

```python
    ctx: Context, file_path: str, algorithm: Literal["md5", "sha1", "sha256", "sha512"]
```

```python
def untar_file(
    ctx: Context,
    source_file: str,
    destination_dir: str,
    compression: None | Literal["gz", "bz2", "xz", "lzip", "lzma", "lzop", "zstd"] = None,
) -> CommandRecordSummary:
    """Runs: tar -xf <SOURCE_FILE> -C /artifacts/<DESTINATION_FILE_NAME>"""
    if source_file.find("..") != -1 or destination_dir.find("..") != -1:
        raise RuntimeError("Invalid file path, Path traversal is not allowed")
    if not Path(source_file).is_file():
        raise FileNotFoundError("Source file not found")
    if not destination_dir.startswith("/artifacts/"):
        raise RuntimeError("Destination directory must be in /artifacts")
    if compression is None:
        return docker_manager.exec_stream(ctx=ctx, command_list=["tar", "-xf", source_file, "-C", destination_dir])
    if compression in TAR_COMPRESSION_FLAGS:
        return docker_manager.exec_stream(
            ctx=ctx, command_list=["tar", "-x", TAR_COMPRESSION_FLAGS[compression], source_file, "-C", destination_dir]
        )
    else:
        raise ValueError(f"Unsupported compression type, {compression} is not supported")
```

```python
def download_windows_symbol(
    ctx: Context, pdb_name: str, guid: str, age: int, overwrite: bool = False
) -> tuple[CommandRecordSummary, CommandRecordSummary]:
    """Downloads windows symbols for volatility to `/symbols`"""

    # Set correct naming convention and directory tree for volatility parsing
    output_file_name = f"{guid}-{age}.json.xz"
    output_file_external_path = config.windows_symbols_directory / pdb_name / output_file_name
    output_file_internal_path = f"/symbols/windows/{pdb_name}/{output_file_name}"
    if output_file_external_path.exists() and not overwrite:
        raise RuntimeError(
            f"File {output_file_internal_path} already exists, it can be used by volatility with the `-s /symbols` "
            "argument, set overwrite to True to overwrite this file"
        )
    else:
        output_file_external_path.parent.mkdir(mode=500, parents=True, exist_ok=True)
```
