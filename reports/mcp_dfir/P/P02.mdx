# P02 다음 작업 결정

### P02.01 고정 문서·프로필 반환

**구현.** 이 방식은 서버 지침(`instructions`)에 적용된다 [1].
서버는 `FastMCP` 객체를 만들 때 지침 문자열을 넘기고 MCP 초기화 응답의 `instructions`에 그 문자열이 실린다 [1][2][3].
지침은 분석을 시작하기 전에 늘 할 일 3가지를 적는다 [1].
첫째는 모든 증거의 목록을 만들고 증거를 언제, 어디서, 어떻게 확보했는지 사용자에게 묻는 것이다 [1].
둘째는 이미 실행한 명령을 모두 검토하는 것이다 [1].
지침은 증거가 바뀌었거나 명령을 잘못 실행한 경우가 아니면 명령을 다시 실행하지 말라고 덧붙인다 [1].
셋째는 분석 메모를 모두 검토해 같은 분석을 되풀이하지 않는 것이다 [1].

지침은 분석하는 동안 지킬 규칙 4가지도 적는다 [1].
지침은 발견사항마다 정상이든 악성이든 추가 조사가 필요하든 markdown 형식의 분석 메모를 만들라고 적는다 [1].
지침은 가정하지 말고 발견사항이 정상인지 악성인지 결론을 내릴 수 없으면 추가 조사가 필요하다고 명시하라고 적는다 [1].
지침은 파일을 읽을 때 직접 만든 bash나 python 스크립트를 쓰지 말고 명령 결과를 볼 때 도구에 있는 `head`·`tail`·정규식·잘라 읽기 옵션만 쓰라고 적는다 [1].
지침은 파생물을 모두 `/artifacts` 아래에 저장하라고 적는다 [1].

지침은 서버 객체를 만들 때 정한 문자열이라 사건이나 조사 상태와 관계없이 같다 [1].
지침은 검토할 때 부를 도구의 이름을 적지 않는다 [1].
이미 실행한 명령은 `get_command_history`가, 분석 메모 목록은 `show_analyst_notes_summary`가 돌려준다 [4].
저장소 예시 사건의 Claude Code 기록에서 모델은 `list_files`, `get_command_history`, `show_analyst_notes_summary`를 이 차례로 먼저 불렀다 [5].
지침의 검토 항목은 분석을 시작하기 전에 할 일로 적혀 있고 클라이언트 문맥이 압축되거나 끊긴 경우를 따로 가리키지 않는다 [1].
서버는 MCP 리소스와 프롬프트를 두지 않는다 [3].

서버는 지침을 따르지 않은 호출을 막지 않는다.
같은 명령을 다시 부르면 서버는 거부하지 않고 새 번호를 매겨 다시 실행한다 [6].
README는 명령 기록이 남으므로 에이전트가 이미 마친 명령을 다시 실행하지 않는다고 적는다 [7].
쓰는 위치가 `/artifacts` 아래인지 서버 코드가 확인하는 도구는 `unzip_file`과 `untar_file`뿐이다 [8].

### P02.02 규칙·조사 상태로 추천

**구현.** 이 방식은 `download_windows_symbol`의 오류 응답 두 곳에 적용된다 [9][10].
`download_windows_symbol`은 받은 `pdb_name`, `guid`, `age`에 맞는 심볼 파일이 사건 폴더의 `symbols` 아래에 이미 있고 `overwrite`가 거짓이면 내려받지 않는다 [9].
이때 오류 문구는 그 파일을 Volatility에서 `-s /symbols` 인자로 쓸 수 있다는 것과 덮어쓰려면 `overwrite`를 `True`로 주라는 것을 적는다 [9][11].
`run_volatility_command`는 늘 `-s /symbols`를 붙여 실행하므로 모델이 이 인자를 따로 주지 않아도 `/symbols`가 Volatility의 심볼 폴더로 전달된다 [12].
Microsoft 심볼 서버가 404를 돌려주면 서버는 `pdb_name`과 `guid`가 맞는지 확인하라는 문구와 요청한 주소를 오류로 돌려준다 [10].
두 문구는 오류 응답의 글이고 서버는 다음 호출을 대신 고르지 않는다 [9][10].

그 밖의 응답은 다음에 부를 도구를 싣지 않는다.
명령을 실행하는 도구는 번호, 명령, 실행 시각, 종료 코드만 돌려주고 결과를 읽는 `get_command_result`를 응답에 적지 않는다 [13].
`unzip_file`과 `untar_file`의 거부 문구는 거부한 이유만 적는다 [8].
서버 안에서 모델을 불러 계획을 세우는 경로는 없다.

`download_windows_symbol`은 PDB 내려받기, `pdbconv` 변환, 심볼 파일 안의 PDB 이름 고치기를 한 호출에서 차례로 실행한다 [14].
이 세 단계는 Volatility가 읽을 심볼 파일 하나를 만드는 일이고 증거를 분석한 결과를 합치지 않는다 [14].

**한계.** `download_windows_symbol`은 심볼 파일이 있는지만 보고 그 파일이 Volatility가 읽을 수 있는 심볼인지 확인하지 않는다 [9].
내용이 6바이트인 파일을 그 경로에 두고 부르자 그 파일을 Volatility에서 쓸 수 있다는 같은 문구가 돌아왔다 [11].
