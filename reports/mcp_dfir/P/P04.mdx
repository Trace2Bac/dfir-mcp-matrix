# P04 조사 단위 관리

### P04.04 사건별 폴더·DB 분리

**구현.** 이 방식은 서버가 시작할 때 정하는 사건 폴더와 그 폴더마다 만드는 컨테이너에 적용된다 [1][2].
조사 단위는 사건 폴더 하나다.
사용자는 시작 인자 `--case-dir`로 사건 폴더를 정하고 서버 프로세스 하나는 그 폴더 하나만 쓴다 [1][3].
`config.load`는 사건 폴더 아래에 `analysis`, `artifacts`, `symbols`, `evidence` 폴더를 만들고 명령 기록, 분석 메모, 심볼의 경로를 모두 이 폴더 아래로 정한다 [2].
`--init`은 이 폴더들을 만든 뒤 서버를 시작하지 않고 끝낸다 [3].
서버는 네 폴더를 컨테이너의 `/evidence`, `/analysis`, `/symbols`, `/artifacts`에 연결한다 [4][5].
컨테이너 이름은 사건 폴더 이름의 공백을 `_`로 바꾸고 뒤에 `-forensics`를 붙여 만든다 [6].
그래서 사건 폴더마다 증거, 명령 기록과 분석 메모, 파생물, 심볼, 컨테이너가 따로 있다 [2][4][6].
서버에는 사건을 만들거나 바꾸는 MCP 도구가 없어 모델은 실행 중인 서버의 사건 폴더를 바꿀 수 없다 [7].

서버가 정하거나 검사하는 사건 ID는 없다.
명령 기록 항목과 분석 메모에는 사건을 가리키는 필드가 없고 저장물은 놓인 폴더로만 사건에 묶인다 [8].
`--case-dir`의 기본값은 서버를 실행한 프로세스의 현재 작업 폴더다 [1].
`--case-dir` 없이 `--init`을 실행하자 현재 작업 폴더에 네 폴더가 생겼다 [9].
README의 Claude Desktop 설정 예시는 `--case-dir` 없이 `python -m mcp_dfir`만 적는다 [10].
사건 폴더가 없으면 서버는 폴더를 만들지 않고 `FileNotFoundError`로 끝난다 [2][9].
사건 폴더 이름에 Docker가 컨테이너 이름으로 받지 않는 글자가 있으면 서버는 컨테이너를 만들지 못하고 MCP 세션을 열기 전에 끝난다 [11].
서버는 `--case-dir`로 받은 경로를 절대 경로로 바꾸지 않고 컨테이너에 연결할 호스트 쪽 경로와 컨테이너 이름에 쓴다 [1][2].
`--case-dir`에 상대 경로를 주자 그 경로 아래에 네 폴더가 생긴 뒤 `docker run`이 볼륨 이름에 쓸 수 없는 글자가 있다는 오류와 종료 코드 125로 끝났고 서버는 MCP 세션을 열기 전에 끝났다 [12].
사건 폴더 안에서 `--case-dir .`을 주자 컨테이너 이름이 `-forensics`가 되어 `docker container inspect`가 인자가 없다는 오류로 끝났다 [6][12].

**한계.** 컨테이너 이름은 사건 폴더의 전체 경로가 아니라 마지막 이름만으로 만든다 [6].
서버는 같은 이름의 컨테이너가 이미 있으면 그 컨테이너에 연결된 폴더를 확인하지 않고 다시 쓴다 [13].
그래서 위치가 다르고 이름이 같은 두 사건 폴더는 컨테이너 하나를 함께 쓴다 [6][13].
이름이 같은 두 사건 폴더를 다른 위치에 두고 차례로 서버를 실행하자 뒤 실행의 컨테이너 안 `/evidence`에는 앞 사건 폴더의 증거가 보였다 [14].
이때 `list_files`는 뒤 사건 폴더의 파일을 돌려주었고 그 가운데 앞 사건 폴더에 없는 파일의 경로로 부른 `get_hash`는 파일이 없다는 오류로 끝났다 [14].
두 폴더에 이름이 같은 파일이 있으면 `get_hash`는 앞 사건 폴더의 파일을 해시하고 그 결과는 뒤 사건 폴더의 명령 기록에 남는다 [14].
뒤 실행에서 컨테이너의 `/artifacts`에 쓴 파일은 앞 사건 폴더의 `artifacts`에 생겼다 [14].
공백을 `_`로 바꾸므로 이름이 `a b`인 폴더와 `a_b`인 폴더도 같은 컨테이너 이름을 쓴다 [6].

```python
    def load(self, working_directory: Path):

        # Directories
        self.working_directory = working_directory

        self.analysis_directory = self.working_directory / "analysis"
        self.analysis_directory.mkdir(mode=500, parents=False, exist_ok=True)

        self.artifact_directory = self.working_directory / "artifacts"
        self.artifact_directory.mkdir(mode=500, parents=False, exist_ok=True)

        self.symbols_directory = self.working_directory / "symbols"
        self.symbols_directory.mkdir(mode=500, parents=False, exist_ok=True)

        self.evidence_directory = self.working_directory / "evidence"
        self.evidence_directory.mkdir(mode=500, parents=False, exist_ok=True)

        # Command history
        self.command_history_json = self.analysis_directory / "command_history.json"
        self.command_record_directory = self.analysis_directory / "command_history"

        # Analyst notes
        self.analyst_notes_list_json = self.analysis_directory / "analyst_notes.json"
        self.analyst_notes_directory = self.analysis_directory / "analyst_notes"

        # Symbols
        self.windows_symbols_directory = self.symbols_directory / "windows"
        self.linux_symbols_directory = self.symbols_directory / "linux"
        self.linux_symbol_map_json = self.linux_symbols_directory / "symbol_map.json"
```

[12] (실행 확인) Windows 호스트에서 사건 폴더의 상위 폴더를 현재 작업 폴더로 두고 `python -m mcp_dfir --case-dir <폴더 이름>`을 실행하면 그 폴더에 `analysis`, `artifacts`, `evidence`, `symbols`가 생긴다.
이어 `--volume <폴더 이름>\evidence:/evidence:ro`를 넘긴 `docker container run`이 `includes invalid characters for a local volume name`과 종료 코드 125로 끝나고 서버 프로세스는 표준 출력에 아무것도 쓰지 않은 채 종료 코드 1로 끝난다.
사건 폴더를 현재 작업 폴더로 두고 `--case-dir .`을 주면 `docker container inspect -forensics`가 `requires at least 1 argument`로 끝나고 서버 프로세스는 종료 코드 1로 끝난다.
두 실행 뒤 `docker ps -a`에 새 컨테이너는 없다.

[14] (실행 확인) 이름이 같은 사건 폴더 둘을 다른 위치에 만들어 증거를 다르게 두고 첫째 폴더로 서버를 실행했다가 끝낸 뒤 둘째 폴더로 서버를 실행했다.
둘째 실행에서 `run_find`로 `/evidence`를 훑으면 첫째 폴더의 증거 파일이 나오고 `docker inspect`의 연결 정보도 첫째 폴더를 가리킨다.
둘째 폴더에만 있는 파일에 `get_hash`를 부르면 `exit_code`가 1이다.
두 폴더에 내용이 다른 같은 이름의 파일을 두고 `get_hash`를 부르면 첫째 폴더에 있는 파일의 SHA-256이 둘째 폴더의 `analysis/command_history`에 남는다.
`run_find`의 `-fprint`로 `/artifacts`에 쓴 파일은 첫째 폴더의 `artifacts`에 생기고 둘째 폴더의 `list_files` 응답에는 없다.
