# R02 대량 결과 전달

### R02.01 문자·항목 상한

**구현.** 이 방식은 저장한 출력을 읽는 `get_command_result`에 적용된다 [1].
이 도구는 범위와 정규식으로 고르고 남은 글의 길이를 인자 `byte_limit`과 비교한다 [1].
`byte_limit`의 기본값은 상수 `COMMAND_MAX_OUTPUT_BYTES`이고 값은 `25 * 1024`인 25,600이다 [2][3].
상수 옆의 주석은 이 값을 `2 KB`라고 적는다 [3].
길이는 `len()`으로 센 글자 수다 [1].
한글 10,000자가 들어 있는 30,100바이트 출력은 10,100자로 세어 기본 상한 아래였다 [4].
비교가 `>=`여서 길이가 상한과 같은 글도 상한을 넘은 것으로 처리한다 [1].
86자 결과 본문은 `byte_limit` 86에서 오류가 됐고 87에서 돌아왔다 [4].
상한에 닿은 글은 잘리지 않고 호출이 오류로 끝난다 [1].

다른 조회 도구에는 응답의 길이나 항목 수 상한이 없다.
`get_command_history`는 명령 기록의 항목 전체를, `list_files`는 고른 폴더 아래의 파일 전체를 돌려준다 [5][6].
`show_analyst_note`는 메모 본문 파일의 글 전체를, `show_analyst_notes_summary`는 메모 요약 전체를 돌려준다 [7].

**한계.** 모델은 호출 인자 `byte_limit`으로 상한을 바꾸거나 끈다 [2].
도구 설명은 `None`으로 주면 상한을 건너뛴다고 적고 코드는 `None`이면 길이를 비교하지 않는다 [2][1].
`byte_limit`을 `null`로 주자 85,006자가 응답 하나로 왔다 [8].
`byte_limit`에는 자료형 표기가 없어 MCP Python SDK 1.27.0은 입력 schema에 이 인자를 `string`으로 싣고 받은 값의 자료형은 검사하지 않는다 [2][9].
도구 목록의 `byte_limit`은 `{"default": 25600, "title": "byte_limit", "type": "string"}`이었다 [4].
문자열 `"null"`은 SDK가 JSON으로 먼저 읽어 `None`으로 바꾸므로 상한이 꺼진다 [9][4].

### R02.04 파일·리소스로 전체 결과 조회

**구현.** 이 방식은 명령을 실행하는 도구의 응답과 `get_command_result`에 적용된다 [10][11].
실행기 `exec_stream`을 거치는 도구의 응답은 `CommandRecordSummary` 하나이고 결과 본문을 싣지 않는다 [10][11].
`CommandHistoryManager`는 메모리에 둔 목록의 길이에 1을 더해 번호를 정하고 결과 본문 전체를 사건 폴더의 결과 본문 파일 `analysis/command_history/<번호>.txt`에 쓴다 [12].
`exec_stream`과 `CommandHistoryManager`는 결과 본문의 길이를 확인하지 않는다 [10][12].
`find /usr/lib -type f`의 출력 85,006자는 모두 저장됐다 [8].
모델은 `get_command_result`에 번호를 주어 저장한 결과 본문을 읽는다 [1].
결과 본문이 25,600자보다 짧으면 범위 인자와 `regex`를 `null`로 준 호출 하나가 결과 본문 전체를 돌려준다 [1][8].
그보다 긴 결과 본문은 `byte_limit`을 `null`이나 더 큰 수로 주면 호출 하나로 전체가 돌아온다 [2][8].
`get_command_history`는 번호와 명령을 담은 명령 기록의 항목 전체를 돌려준다 [5].
`CommandHistoryManager`는 서버가 시작될 때 `command_history.json`을 읽으므로 이전 세션의 번호로도 결과 본문을 읽는다 [13][8].

**한계.** 표준 출력에 UTF-8이 아닌 바이트가 있는 명령은 `exec_stream`이 `CommandHistoryManager`를 부르기 전에 예외로 끝나 번호와 결과 본문이 남지 않는다 [10][14].
종료 코드 0으로 끝난 명령의 표준 오류는 `exec_stream`이 모으지 않아 저장되지 않는다 [10].

### R02.05 상한 초과 시 거부

**구현.** 이 방식은 `get_command_result`에 적용된다 [1].
이 도구는 고르고 남은 글의 길이가 `byte_limit` 이상이면 글을 자르지 않고 `RuntimeError`를 낸다 [1].
MCP Python SDK 1.27.0은 도구 함수의 예외를 `isError`가 참인 결과로 바꾼다 [15].
85,006자 결과 본문을 범위 인자 없이 읽자 `Error executing tool get_command_result: Output exceeds maximum size, output was 85006 bytes`가 왔다 [8].
문구의 수는 고르고 남은 글의 글자 수이고 문구는 그 단위를 `bytes`로 적는다 [1].
문구에는 상한 값과 저장한 결과 본문 전체의 길이가 없다 [1].
예시 사건의 Claude Code 기록에는 `strings` 출력에 `regex`를 준 호출이 `output was 42864 bytes` 오류를 받은 줄이 있다 [16].

**한계.** `byte_limit`을 `null`로 주면 코드가 길이를 비교하지 않아 길이와 관계없이 글 전체가 돌아온다 [1][8].
입력 schema에 맞춰 `byte_limit`을 문자열 `"1000"`으로 주면 코드가 정수와 문자열을 비교하다 예외가 난다 [1][4].
이때는 글의 길이와 관계없이 호출이 `'>=' not supported between instances of 'int' and 'str'` 오류로 끝난다 [4].
`byte_limit`을 0으로 주면 빈 글도 `output was 0 bytes` 오류가 된다 [4].

### R02.08 보관한 출력의 일부 재조회

**구현.** 이 방식은 `get_command_result`에 적용된다 [1].
이 도구는 저장한 결과 본문에서 줄 범위, 글자 범위, 정규식의 차례로 일부를 고른다 [1].
`head`는 앞에서부터 그 수만큼의 줄을 남긴다 [1].
`head_bytes`는 앞에서부터, `tail_bytes`는 뒤에서부터 그 수만큼의 글자를 남긴다 [1].
`regex`는 `re.search`가 맞는 줄만 남긴다 [1].
`regex`는 줄 범위와 글자 범위로 줄인 글에 적용된다 [1].
세 줄 결과 본문에 `head` 1과 둘째 줄에만 있는 낱말을 `regex`로 주자 빈 글이 돌아왔다 [4].
`head`와 `tail`을 함께 주거나 `head_bytes`와 `tail_bytes`를 함께 주면 예외를 낸다 [17].
범위 인자 네 개와 `regex`에는 기본값이 없어 모델은 호출마다 다섯 값을 모두 주어야 한다 [2].
`command_number`만 주고 부르자 SDK가 다섯 인자가 빠졌다는 검사 오류를 돌려줬다 [4].
도구 설명이 적는 인자 가운데 읽기 시작할 위치를 정하는 인자나 다음 범위를 가리키는 커서는 없고 응답도 그런 값을 싣지 않는다 [2][1].
응답은 고른 글만 싣고 결과 본문 전체의 줄 수나 일부만 실었다는 표시를 싣지 않는다 [1].
서버 지침은 명령 결과를 볼 때 직접 짠 스크립트를 쓰지 말고 이 도구의 `head`·`tail`·`regex` 선택 인자만 쓰라고 적는다 [18].

**한계.** `tail`은 도구 설명과 다르게 동작한다 [2][1].
설명은 `tail`을 뒤에서부터 돌려줄 줄 수라고 적는다 [2].
코드는 줄 목록을 `[tail:]`로 잘라 앞에서부터 그 수만큼의 줄을 뺀 나머지를 남긴다 [1].
세 줄 결과 본문에 `tail` 1을 주자 뒤 두 줄이, `tail` 2를 주자 마지막 한 줄이 돌아왔다 [4].
`tail` 1과 `head_bytes` 30을 함께 주자 둘째 줄의 앞 30자가 돌아왔다 [4].
설명은 `head_bytes`와 `tail_bytes`를 바이트 수라고 적지만 코드는 글자 수로 자른다 [2][1].
범위 인자는 0이면 조건이 거짓이 되어 적용되지 않는다 [1].
`head`를 0으로 주자 결과 본문 전체가 돌아왔다 [4].
범위 인자는 음수도 받고 코드는 음수를 그대로 자를 위치로 쓴다 [1].
줄 끝이 `\n`인 네 줄 결과 본문에 `tail` -2를 주자 마지막 한 줄이 돌아왔고 `tail` -1을 주자 빈 글이 돌아왔다 [4].
`head_bytes` -3은 끝의 세 글자를 뺀 글을, `tail_bytes` -3은 앞의 세 글자를 뺀 글을 돌려줬다 [4].

    content = command_history_manager.get_command(command_number=command_number).result

    # Truncate for head/tail
    if head:
        content = "\n".join(content.split("\n")[:head])
    elif tail:
        content = "\n".join(content.split("\n")[tail:])

    # Truncate for head/tail bytes

        content = content[:head_bytes]
    elif tail_bytes:

    # Regex search
    output = []

        if regex is None or re.search(regex, line):
            output.append(line)

    output_str = "\n".join(output)

    if byte_limit is not None and len(output_str) >= byte_limit:
        raise RuntimeError(f"Output exceeds maximum size, output was {len(output_str)} bytes")

    return output_str
```

        if self.container is None:

        ctx.report_progress(f"Running command {' '.join(command_list)}")
        output = []
        exit_code = 0
        try:
            for stream, data in self.docker.execute(self.container, command_list, stream=True):
                if stream == "stdout":
                    output.append(data.decode())
        except DockerException as ex:
            exit_code = ex.return_code if ex.return_code is not None else 1
            output.append(str(ex))
        result = "".join(output)
        return command_history_manager.add_command(
            CommandRecord(
                command=" ".join(command_list),
                result=result,
                exit_code=exit_code,
            )
        )
```
