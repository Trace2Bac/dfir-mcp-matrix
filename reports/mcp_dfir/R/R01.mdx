# R01 결과 가공

### R01.01 가공 없이 전달

**구현.** 이 방식은 컨테이너 안에서 명령을 실행하는 도구 8개의 출력과 그 출력을 읽는 `get_command_result`에 적용된다 [1][2].
`run_strings`·`run_grep`·`run_find`·`unzip_file`·`untar_file`·`get_hash`·`run_volatility_command`·`run_sleuthkit_command`는 실행기 `exec_stream`으로 명령을 실행한다 [1][2].
`exec_stream`은 명령의 표준 출력을 줄마다 UTF-8로 풀어 이어 붙이고 그 글을 `CommandHistoryManager`의 `add_command`에 넘긴다 [1].
`CommandHistoryManager`는 그 글을 사건 폴더의 결과 본문 파일 `analysis/command_history/<번호>.txt`에 쓴다 [3].
도구를 부른 직후의 응답에는 출력이 아니라 번호, 명령, 시각, 종료 코드를 담은 `CommandRecordSummary`가 실린다 [1][4].
`get_command_result`는 번호를 받아 저장한 글을 읽고 범위 인자와 `regex`가 모두 `null`이면 그 글 전체를 돌려준다 [5].
서버는 출력을 파싱하거나 필드를 고르거나 다른 형식으로 바꾸지 않는다 [1][5].
`fls -r -l`·`istat`·`strings -t d`·`find`를 실행하고 읽은 글은 같은 명령을 컨테이너에서 직접 실행한 표준 출력과 SHA-256이 같았다 [6].
`run_volatility_command`는 Volatility를 늘 `-r jsonl`로 실행한다 [7].
Volatility 3는 이 렌더러에서 행마다 JSON 객체 한 줄을 출력하고 서버는 그 줄을 JSON으로 읽지 않고 글로 저장한다 [7][1].
MCP Python SDK 1.27.0은 `get_command_result`가 돌려준 글을 `content`의 글 항목 하나와 `structuredContent`의 `result`에 함께 싣는다 [8][6].

컨테이너를 거치지 않는 심볼 도구는 서버가 만든 글을 같은 명령 기록에 결과 본문으로 저장한다 [9].
`download_windows_symbol`의 내려받기 단계와 `download_linux_symbol`의 결과 본문은 내려받은 경로를 적은 문장 하나다 [9].
`search_linux_symbols`는 심볼 맵에서 `regex`에 맞은 항목을 `SymbolSearchResult` 목록으로 모아 `json.dumps`에 넘긴다 [10].
`json.dumps`는 이 pydantic 모델을 JSON으로 바꾸지 못해 일치가 하나라도 있으면 예외가 나고 호출은 오류 결과로 끝난다 [10][11].
일치가 없으면 결과 본문 `[]`가 저장된다 [11].
`list_files`는 외부 도구를 실행하지 않고 서버가 호스트의 폴더를 훑어 파일마다 `name`·`path`·`size`를 만든다 [12].

**한계.** 종료 코드가 0이 아닌 명령의 결과 본문에는 도구 출력이 아닌 글이 붙는다 [1].
`exec_stream`은 `DockerException`이 나면 그때까지 모은 표준 출력 뒤에 예외 글을 이어 붙여 저장한다 [1].
python-on-whales 0.81.0의 예외 글은 실행한 `docker` 명령 줄, 종료 코드, 표준 오류 전체를 영어 문장에 넣은 것이다 [13].
없는 파일에 `fls`를 실행한 명령 기록의 결과 본문은 호스트의 `docker` 실행 파일 경로와 컨테이너 ID가 들어 있는 이 예외 글이었다 [14].
Volatility가 실패한 명령 기록의 결과 본문은 Volatility가 표준 출력에 쓴 안내문 뒤에 같은 예외 글이 이어졌다 [14].

`exec_stream`은 스트림에서 `stdout`만 모은다 [1].
그래서 종료 코드 0으로 끝난 명령이 표준 오류에 쓴 글은 응답에도 결과 본문 파일에도 남지 않는다 [1].
`find`에 `-warn`과 조건 뒤에 둔 `-maxdepth`를 주어 실행하자 `find`가 표준 오류에 쓰는 경고는 결과 본문에 없고 찾은 경로 한 줄만 있었다 [6].
종료 코드 0으로 끝난 Volatility 실행의 결과 본문에는 빈 줄 하나와 JSON 줄만 있었다 [6].

표준 출력에 UTF-8이 아닌 바이트가 있으면 `decode`가 예외를 내고 호출은 명령 기록을 남기지 않은 채 오류 결과로 끝난다 [1][15].
`img_cat`으로 디스크 이미지를 출력하게 하자 `'utf-8' codec can't decode byte`가 들어 있는 오류 결과가 왔고 명령 번호는 늘지 않았다 [15].
`run_sleuthkit_command`의 설명은 `icat`·`blkcat`·`img_cat`·`mmcat`을 내용을 출력하는 도구로 소개한다 [16].

`CommandHistoryManager`는 결과 본문 파일을 `newline` 인자 없이 text mode로 쓰고 읽으므로 줄 끝 글자가 바뀐다 [3].
Python의 `open`은 `newline`을 주지 않으면 쓸 때 `\n`을 운영체제의 줄 끝 글자로 바꾸고 읽을 때 `\r\n`과 `\r`을 `\n`으로 바꾼다 [17].
Windows 호스트에서 `\r\n`으로 끝나는 두 줄을 출력한 `grep`의 결과 본문 파일에는 `\r\r\n`이 저장됐고 `get_command_result`는 `line one\n\nline two\n\n`을 돌려줬다 [18].
줄 가운데에 `\r`이 있는 `last\rcr-only` 줄은 `last\ncr-only\n` 두 줄로 돌아왔다 [18].
Linux 호스트에서는 실행하지 않았다.

```python
    def exec_stream(self, ctx: Context, command_list: list[str]) -> CommandRecordSummary:
        if self.container is None:
            raise RuntimeError("No docker container is currently running")

        ctx.report_progress(f"Running command {' '.join(command_list)}")
        output = []
        exit_code = 0
        try:
            for stream, data in self.docker.execute(self.container, command_list, stream=True):
                if stream == "stdout":
                    output.append(data.decode())
        except DockerException as ex:
            exit_code = ex.return_code if ex.return_code is not None else 1
            output.append(str(ex))
        result = "".join(output)
        return command_history_manager.add_command(
            CommandRecord(
                command=" ".join(command_list),
                result=result,
                exit_code=exit_code,
            )
        )
```
