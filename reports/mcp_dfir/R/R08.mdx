# R08 시간값 처리

### R08.01 시간 변환 전 값 유지

**구현.** 이 방식은 명령을 실행하는 도구의 결과 본문에 적용된다 [1][2].
실행기 `exec_stream`은 표준 출력을 그대로 저장하고 `get_command_result`는 저장한 글에서 고른 글을 돌려준다 [1][2].
두 함수에는 시각 값을 찾거나 바꾸는 코드가 없다 [1][2].
`fls -l`의 결과 본문은 줄마다 `2026-09-29 04:56:24 (UTC)` 꼴의 시각 네 개를 실었다 [3].
`istat`의 결과 본문은 `2026-09-29 04:56:24.000000000 (UTC)` 꼴의 시각을 실었다 [3].
`fls -m`의 결과 본문은 줄마다 시각 네 개를 `1790657784` 같은 정수로 실었다 [3].
`icat`으로 읽은 `auth.log`의 줄은 `Sep 29 10:00:01`처럼 연도와 시간대가 없는 원래 표기 그대로였다 [3].
예시 사건의 `windows.pslist` 결과 본문은 `CreateTime`을 `2017-05-12T21:21:55+00:00`으로 싣는다 [4].

### R08.03 시간대·단위·정밀도 표시

**구현.** 이 방식은 Volatility와 Sleuth Kit 도구의 결과 본문에 적용된다 [5][3].
`run_volatility_command`는 Volatility를 늘 `-r jsonl`로 실행한다 [5].
Volatility 3의 JSON 렌더러는 `datetime` 값을 `isoformat()` 문자열로 출력하고 JSONL 렌더러는 이 렌더러를 물려받는다 [6].
Volatility 3는 Windows FILETIME과 Unix 시각을 UTC 시간대가 붙은 `datetime`으로 바꾸므로 이 문자열 끝에는 `+00:00`이 붙는다 [7][4].
FILETIME이 0이면 Volatility는 값 대신 해당 없음 표시를 내고 JSON 렌더러는 이를 `null`로 출력한다 [6][7].
예시 사건의 `windows.pslist` 결과 본문에서 `System` 행의 `CreateTime`은 `null`이다 [4].
Volatility의 시각 열은 예시 사건의 명령 기록과 Volatility 소스로 확인했고 시험용 메모리 이미지에서는 맞는 심볼이 없어 시각 열을 내는 플러그인을 실행하지 못했다.

`fls -l`·`istat`·`fsstat`의 결과 본문에서는 시각마다 괄호 안에 시간대 이름이 붙는다 [3].
The Sleuth Kit 4.12.1은 시각을 프로세스의 지역 시각으로 바꿔 시간대 이름과 함께 출력한다 [8].
`Dockerfile`은 시간대를 정하지 않고 컨테이너 안의 시각은 UTC였다 [9][3].
`run_sleuthkit_command`는 시간대를 정하는 인자를 더하지 않고 모델이 준 인자만 넘긴다 [10].
모델이 `fls -l`에 `-z EST5EDT`를 주자 같은 시각이 `2026-09-29 00:56:24 (EDT)`로 실렸다 [3].

실행 도구의 응답과 `get_command_history`에 실리는 `date_run`은 도구 출력에서 온 시각이 아니라 서버가 명령 기록을 만들 때 적는 시각이다 [11].
`date_as_str`은 `datetime.now()`를 `%d/%m/%Y %H:%M:%S`로 적으므로 이 값은 시간대 표기가 없는 호스트 지역 시각이다 [11].
`date_run`은 일, 월, 연도 순서이고 응답에는 이 순서를 알리는 값이나 필드가 없다 [11].
한국 표준시 호스트에서 실행한 응답의 `date_run`은 `12/10/2026 13:46:50`이었고 그 명령이 컨테이너 안에서 출력한 시각은 `2026-10-12 04:46 UTC`였다 [3].
출력 schema가 싣는 `date_run`의 예시는 `01/01/2024 12:00:00`이어서 일과 월의 순서를 가를 수 없다 [11][3].

**한계.** 결과 본문의 시각 표기는 실행한 명령과 인자가 정하고 서버는 시간대나 단위가 없는 표기에 아무것도 보태지 않는다 [1][2].
`fls -m`의 결과 본문에 실린 정수 시각에는 단위와 시간대 표기가 없었다 [3].
`icat`으로 읽은 로그 파일의 시각에는 시간대가 없었다 [3].

[1] `exec_stream`은 표준 출력을 이어 붙인 글로 `CommandRecord`를 만들어 `CommandHistoryManager`에 넘긴다.

```python
    def exec_stream(self, ctx: Context, command_list: list[str]) -> CommandRecordSummary:
        if self.container is None:
            raise RuntimeError("No docker container is currently running")

        ctx.report_progress(f"Running command {' '.join(command_list)}")
        output = []
        exit_code = 0
        try:
            for stream, data in self.docker.execute(self.container, command_list, stream=True):
                if stream == "stdout":
                    output.append(data.decode())
        except DockerException as ex:
            exit_code = ex.return_code if ex.return_code is not None else 1
            output.append(str(ex))
        result = "".join(output)
        return command_history_manager.add_command(
            CommandRecord(
                command=" ".join(command_list),
                result=result,
                exit_code=exit_code,
            )
        )
```

def date_as_str() -> str:
    return datetime.now().strftime("%d/%m/%Y %H:%M:%S")


class CommandRecordSummary(BaseModel):
    number: int = Field(examples=[1])
    command: str = Field(examples=["vol -f capture.mem linux.pslist"])
    date_run: str = Field(default_factory=date_as_str, examples=["01/01/2024 12:00:00"])
    exit_code: int = Field(examples=[0])


class CommandRecord(BaseModel):
    command: str = Field(examples=["vol -f capture.mem linux.pslist"])
    date_run: str = Field(default_factory=date_as_str, examples=["01/01/2024 12:00:00"])
