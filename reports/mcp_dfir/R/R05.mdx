# R05 결과 출처 표시

### R05.01 증거·파일 ID

**구현.** 이 방식은 명령을 실행하는 도구의 응답, `get_command_history`, `list_files`에 적용된다 [1][2][3].
실행기 `exec_stream`은 실행한 명령과 인자를 공백으로 이은 글을 명령 기록의 `command`에 넣는다 [1].
모델이 증거 파일을 가리켜 준 경로 인자는 이 글 안에 그대로 있다 [1].
`fls -r -l /evidence/disk.dd`를 실행한 응답의 `command`는 그 명령 줄이었다 [4].
`run_volatility_command`의 설명은 분석할 파일을 `-f /evidence/example.mem`처럼 주라고 적는다 [5].
경로는 컨테이너 안의 경로이고 `/evidence`는 사건 폴더의 `evidence`를 읽기 전용으로 연결한 곳이다 [6].
`get_command_result`의 응답은 결과 본문에서 고른 글만 싣고 번호나 `command`를 싣지 않는다 [7].
`get_command_history`는 번호마다 `command`를 돌려주므로 모델은 결과 본문을 읽을 때 쓴 번호로 증거 경로를 찾는다 [2][4].
`list_files`는 `evidence`·`artifacts`·`symbols` 가운데 고른 폴더의 파일마다 컨테이너 안 경로 `path`와 `name`·`size`를 싣는다 [3][4].
`get_hash`의 결과 본문은 `sha256sum` 같은 해시 명령의 출력이라 해시 값 뒤에 파일 경로가 있다 [8][4].

증거에서 꺼낸 파일을 분석한 명령 기록의 `command`에는 `/artifacts` 아래 경로만 있다 [1].
그 파일이 어느 증거에서 나왔는지는 파일을 꺼낸 명령을 적은 명령 기록에 있다 [4].

참조 자료를 조회하는 도구는 `search_linux_symbols` 하나다 [9].
이 도구는 일치한 심볼마다 커널 배너 `symbol_name`과 심볼 저장소 안의 파일 경로 목록 `file_path_list`를 담은 결과를 만든다 [9].
일치가 하나라도 있으면 이 결과를 JSON 글로 바꾸다 예외가 나므로 이 항목은 모델에게 전달되지 않는다 [9][10].
`download_linux_symbol`의 결과 본문은 내려받은 URL을 적는다 [11].
심볼 도구가 남기는 항목도 명령 기록에 같은 번호 순서로 들어가고 `command`가 `mcp_dfir:tools:volatility:`로 시작한다 [11][10].

**한계.** `command`는 인자를 공백 하나로 이어 붙인 글이고 따옴표를 넣지 않는다 [1].
빈 문자열 인자를 준 `grep`의 `command`는 `grep -a  /evidence/ko.txt`였다 [4].
그래서 경로에 공백이 있으면 `command`에서 그 경로와 다른 인자의 경계가 남지 않는다 [1].

### R05.02 증거 내부 경로

**구현.** 이 방식은 디스크 이미지의 파일 이름을 출력하는 Sleuth Kit 도구의 결과 본문에 적용된다 [12][7].
`run_sleuthkit_command`는 고른 도구에 모델이 준 인자를 그대로 넘기고 `get_command_result`는 그 출력을 바꾸지 않고 돌려준다 [12][7].
서버는 경로 표기를 정하는 인자를 더하지 않으므로 전체 경로는 모델이 그 인자를 준 실행의 결과 본문에만 실린다 [12].
모델이 `-p`를 준 `fls -r -p`의 결과 본문은 줄마다 `home/user/.bash_history`처럼 이미지 안 전체 경로를 실었다 [13].
모델이 `-m /`를 준 `fls -r -m /`의 결과 본문도 줄마다 `/home/user/.bash_history` 꼴의 전체 경로를 실었다 [13].
`tsk_recover`로 꺼낸 파일을 `list_files`로 보면 `path`는 `/artifacts/rec/home/user/.bash_history`처럼 파일을 꺼내 둔 폴더의 경로다 [13].

**한계.** `-p`나 `-m` 없이 실행한 `fls`의 결과 본문은 줄마다 이름만 싣는다 [13].
`fls -r -l`의 결과 본문은 폴더 깊이를 줄 앞의 `+`로 표시했고 상위 폴더의 이름은 앞선 줄에 있었다 [13].
`get_command_result`에 `regex`를 주면 맞은 줄만 돌아온다 [7].
이 결과 본문에서 `regex`로 한 줄을 고르자 이름만 있는 줄 하나가 왔고 상위 폴더의 줄은 응답에 없었다 [13].

### R05.03 레코드 키·번호

**구현.** 이 방식은 Sleuth Kit 도구와 Volatility의 결과 본문에 적용된다 [12][5][7].
`fls`의 결과 본문은 `-l`, `-p`, `-m` 가운데 어느 인자로 실행해도 줄마다 inode 번호를 실었고 `istat`의 결과 본문은 첫 줄에 `inode: 17`을 실었다 [13].
이 번호를 `icat`의 인자로 주자 그 파일의 내용이 결과 본문으로 저장됐다 [13].
`run_volatility_command`는 Volatility를 `-r jsonl`로 실행하므로 결과 본문의 줄마다 열 이름을 키로 한 JSON 객체가 실린다 [5][14].
예시 사건의 `windows.pslist` 결과 본문은 줄마다 `PID`와 `PPID`를 싣는다 [15].
명령 기록의 `number`는 서버가 출력을 저장하면서 매긴 번호이고 증거 안의 레코드 번호가 아니다 [16].

### R05.04 바이트·섹터·행 오프셋

**구현.** 이 방식은 위치 값을 출력하는 명령의 결과 본문에 적용된다 [1][7].
서버는 모델이 준 인자를 그대로 넘기고 위치 값을 출력하게 하는 인자를 더하거나 막지 않는다 [17].
모델이 `-t d`를 준 `strings`의 결과 본문은 문자열마다 파일 안 바이트 오프셋을 줄 앞에 실었다 [18].
모델이 `-n -b`를 준 `grep`의 결과 본문은 일치한 줄 앞에 줄 번호 3과 바이트 오프셋 1045를 실었다 [18].
Volatility의 `banners.Banners`는 모델이 인자를 더하지 않아도 행마다 `Offset` 열을 낸다 [18].
Volatility 3의 이 플러그인은 주소 변환 계층을 받으면 그 아래의 메모리 계층을 훑고 찾은 위치를 `Offset`으로 낸다 [19].
`istat`의 결과 본문은 인자를 더하지 않아도 파일의 데이터 블록 번호를 실었고 `fsstat`의 결과 본문은 블록 크기를 실었다 [13].
예시 사건의 `windows.pslist` 결과 본문에 있는 `Offset(V)`는 가상 주소다 [15].

**한계.** `strings`와 `grep`의 결과 본문에는 모델이 위치 인자를 주지 않으면 오프셋과 줄 번호가 없다 [17].
같은 파일에 `-t` 없이 실행한 `strings`의 결과 본문에는 문자열만 있었다 [18].

```python
    def exec_stream(self, ctx: Context, command_list: list[str]) -> CommandRecordSummary:
        if self.container is None:
            raise RuntimeError("No docker container is currently running")

        ctx.report_progress(f"Running command {' '.join(command_list)}")
        output = []
        exit_code = 0
        try:
            for stream, data in self.docker.execute(self.container, command_list, stream=True):
                if stream == "stdout":
                    output.append(data.decode())
        except DockerException as ex:
            exit_code = ex.return_code if ex.return_code is not None else 1
            output.append(str(ex))
        result = "".join(output)
        return command_history_manager.add_command(
            CommandRecord(
                command=" ".join(command_list),
                result=result,
                exit_code=exit_code,
            )
        )
```
