# R04 도구 결과 해석 주의

### 미구현

**판단.** 서버의 도구 설명, 서버 지침, 응답 어디에도 도구 결과의 해석 한계나 추가 확인이 필요하다는 점을 적지 않는다.
도구 18개 가운데 11개에 설명이 있고 `list_files`·`get_hash`·`get_command_history`와 메모 도구 4개에는 설명이 없다 [1].
설명은 실행하는 명령의 꼴, 인자의 뜻, 도구가 하는 일을 적는다 [2].
`run_volatility_command`의 설명은 분석할 파일을 `-f`로 주라는 것과 Volatility 3에 내장 심볼이 적어 심볼을 따로 내려받아야 할 수 있다는 것을 적는다 [3].
이 문구는 인자 사용법과 호출 순서를 안내한다 [3].
`run_sleuthkit_command`의 설명은 Sleuth Kit 도구 30개가 하는 일을 도구마다 한 줄로 적는다 [4].
`get_command_result`의 설명은 인자 7개의 뜻을 적는다 [5].

서버 지침 `instructions`는 분석 전에 할 일 3개와 분석 중 지킬 규칙 4개를 적는다 [6].
규칙 2는 가정하지 말고 발견사항이 정상인지 악성인지 결론을 내릴 수 없으면 추가 조사가 필요하다고 표시하라고 적는다 [6].
이 규칙은 발견사항의 판정을 적는 방식을 정하고 어느 도구의 결과가 무엇을 증명하지 못하는지는 적지 않는다 [6].
나머지 항목은 증거 목록 확인과 수집 경위 질문, 이전 명령과 메모 검토, 메모 작성, 명령 결과를 읽는 방법, 파생물을 둘 곳을 적는다 [6].

명령을 실행하는 도구의 응답은 `CommandRecordSummary`의 네 필드뿐이고 `get_command_result`의 응답은 저장한 결과 본문에서 고른 글뿐이다 [7][8].
두 응답을 만드는 코드에는 결과에 따라 주의 문구를 붙이는 분기가 없다 [7][8].
서버 코드가 내는 오류 문구 가운데 안내가 들어 있는 것은 심볼 내려받기의 두 문구다 [9].
PDB를 찾지 못하면 `pdb_name`과 `guid`가 맞는지 확인하라고 적고 심볼 파일이 이미 있으면 `overwrite`를 참으로 주라고 적는다 [9].
이 문구는 인자 사용법을 안내한다 [9].
서버는 `add_tool`로 도구만 등록하고 MCP 리소스와 프롬프트는 등록하지 않는다 [10][1].
