# R06 증거에서 추출한 민감정보 노출 제어

### 미구현

**판단.** 서버는 증거에서 나온 값을 응답과 명령 기록에 그대로 싣고 그 가운데 비밀 값을 가리거나 빼는 코드를 두지 않는다.
실행기 `exec_stream`은 명령의 표준 출력을 모아 그대로 `CommandHistoryManager`의 `add_command`에 넘긴다 [1].
`CommandHistoryManager`는 그 글을 사건 폴더의 결과 본문 파일 `analysis/command_history/<번호>.txt`에 쓰고 `get_command_result`는 그 파일에서 읽은 글을 돌려준다 [2][3].
세 곳 어디에도 값을 검사하거나 바꾸는 코드가 없다 [1][2][3].
`secret_token=FAKE-TOKEN-123` 줄이 들어 있는 시험용 tar 파일에 `grep`을 실행하자 그 줄이 결과 본문 파일에 저장됐고 `get_command_result`의 응답에 그대로 실렸다 [4].
시험용 디스크 이미지의 `.bash_history`와 `auth.log`를 `icat`으로 읽은 결과 본문도 파일 내용 그대로였다 [4].
`run_volatility_command`는 Volatility 플러그인 이름을 제한하지 않고 모델이 준 인자를 그대로 넘긴다 [5].
그래서 어느 플러그인의 출력이든 같은 경로로 저장되고 응답에 실린다 [5][1].

모델이 인자로 준 값은 명령 기록의 `command`에 그대로 남는다 [1].
`command`는 명령 기록 목록 `command_history.json`에 저장되고 `get_command_history`의 응답에 실린다 [6][4].
메모 도구는 모델이 쓴 `description`을 메모 본문 파일에 그대로 쓰고 `show_analyst_note`는 그 파일 내용을 그대로 돌려준다 [7][4].
서버에는 보고서를 만드는 도구가 없다 [8].

### 근거

[1] `exec_stream`은 표준 출력을 이어 붙인 글과 명령 줄을 `CommandHistoryManager`에 넘긴다.

```python
    def exec_stream(self, ctx: Context, command_list: list[str]) -> CommandRecordSummary:
        if self.container is None:
            raise RuntimeError("No docker container is currently running")

        ctx.report_progress(f"Running command {' '.join(command_list)}")
        output = []
        exit_code = 0
        try:
            for stream, data in self.docker.execute(self.container, command_list, stream=True):
                if stream == "stdout":
                    output.append(data.decode())
        except DockerException as ex:
            exit_code = ex.return_code if ex.return_code is not None else 1
            output.append(str(ex))
        result = "".join(output)
        return command_history_manager.add_command(
            CommandRecord(
                command=" ".join(command_list),
                result=result,
                exit_code=exit_code,
            )
        )
```
