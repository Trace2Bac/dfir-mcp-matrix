# T02 실행 허용 범위 제한

### T02.04 고정 명령·템플릿

**구현.** 이 방식은 `get_hash`, `unzip_file`, `untar_file`, `download_windows_symbol`의 `pdbconv` 실행, `run_volatility_command`의 앞 인자에 적용된다 [1][2][3][4].
`get_hash`는 `<algorithm>sum`과 `file_path` 두 칸으로 된 명령 배열을 만든다 [1].
`unzip_file`은 `unzip -X -K <source_file> -d <destination_dir>` 배열을 만든다 [2].
`untar_file`은 `compression`을 주지 않으면 `tar -xf <source_file> -C <destination_dir>` 배열을 만들고 주면 `tar -x <압축 옵션> <source_file> -C <destination_dir>` 배열을 만든다 [2].
압축 옵션은 `compression` 값 7개를 `--gzip`·`--bzip2`·`--xz`·`--lzip`·`--lzma`·`--lzop`·`--zstd`로 바꾼 것이다 [5].
`download_windows_symbol`은 받은 PDB를 Volatility 심볼 파일로 바꿀 때 `pdbconv -f <PDB 경로> -g <guid> -o <출력 경로>`를 실행하고 두 경로는 서버가 `pdb_name`·`guid`·`age`로 만든다 [3].
`run_volatility_command`는 `vol -s /symbols -r jsonl`을 앞에 고정하고 그 뒤에 `arguments`를 그대로 붙인다 [4].
모든 실행 도구는 명령을 문자열 list로 `exec_stream`에 넘긴다 [6].
list의 첫 칸인 실행 파일 이름은 서버 코드에 적은 이름이거나 서버 코드의 목록으로 제한한 값이다 [1][7][8].
`unzip_file`과 `untar_file`의 `destination_dir`은 `/artifacts/`로 시작해야 하고 `source_file`은 서버가 호스트에서 그 이름의 파일을 찾아야 통과한다 [2].

`run_strings`·`run_grep`·`run_find`·`run_sleuthkit_command`는 실행 파일 이름 뒤에 모델이 준 `arguments`를 그대로 붙인다 [7][8].
이 네 도구와 `run_volatility_command`에서는 옵션, 플러그인, 대상 경로, 출력 위치를 모두 모델이 정한다 [4][7][8].
`run_find`의 `-fprintf`는 모델이 준 글을 컨테이너의 파일로 쓰고 `run_volatility_command`의 `--plugin-dirs`는 모델이 고른 폴더의 파이썬 파일을 Volatility 플러그인으로 읽게 한다 [9].
`-fprintf`로 `/artifacts`에 파이썬 파일을 만든 뒤 `--plugin-dirs /artifacts`와 그 파일의 플러그인 이름을 주자 그 파일의 코드가 컨테이너에서 실행되어 결과 행이 저장되었다 [9].
저장소에는 MCP 클라이언트 구성이 없고 README는 Claude Desktop에 서버를 등록하는 예시만 적는다 [10].
서버의 실행 인자는 `--case-dir`·`--init`·`--clear-case-dir`·`--clear-docker`이고 도구를 끄는 인자나 환경변수는 없다 [11].

**한계.** `untar_file`에 `compression`을 주어 만든 배열에는 `-f`가 없다 [2].
도구 설명은 `tar -xf <SOURCE_FILE> -C /artifacts/<DESTINATION_FILE_NAME>`을 실행한다고 적는다 [2].
`compression`을 `gz`로 주자 `tar -x --gzip <source_file> -C /artifacts/t`가 실행되어 `gzip: stdin: unexpected end of file`과 종료 코드 2가 기록되었다 [12].
`get_hash`는 `file_path` 앞에 옵션의 끝을 알리는 `--`를 두지 않고 값이 `-`로 시작하는지도 보지 않는다 [1].
`file_path`에 `--help`를 주자 `md5sum --help`가 실행되어 도움말이 결과로 저장되었고 `--version`을 주자 `sha1sum`의 버전 문구가 저장되었다 [12].
`run_volatility_command`의 `arguments`에 `-r csv`를 주자 앞에 고정한 `-r jsonl`이 아니라 CSV로 출력되었다 [12].
`unzip_file`과 `untar_file`은 `source_file`을 호스트에서 확인하므로 컨테이너 경로 `/evidence/sample.zip`과 `/evidence/sample.tar`를 주자 `Source file not found`로 끝나 배열이 실행되지 않았다 [2][12].
호스트 경로를 주어 그 확인을 통과한 `unzip_file`은 이미지에 `unzip` 실행 파일이 없어 종료 코드 127로 끝났다 [12].

### T02.05 연산·플러그인 허용 목록

**구현.** 이 방식은 `run_sleuthkit_command`의 `tool`과 `get_hash`의 `algorithm`에 적용된다 [13][1].
`run_sleuthkit_command`는 실행 파일 이름이 되는 `tool`을 The Sleuth Kit 명령 이름 30개로 제한한다 [13].
같은 30개가 매개변수의 `Literal`과 함수 안에서 대조하는 `SLEUTHKIT_COMMANDS` 두 곳에 적혀 있다 [13].
MCP 호출에서 목록 밖의 값은 FastMCP가 `Literal` 검사로 먼저 거부한다 [14].
`tool`에 `rm`을 주자 허용 값 30개를 적은 오류가 왔고 명령 기록은 생기지 않았다 [14].
함수를 직접 불러 `rm`을 주면 함수 안의 대조가 오류 문구를 만들다 `AttributeError`로 끝나고 명령은 실행되지 않는다 [13][14].
목록에는 도구 설명이 파일을 내보낸다고 적은 `tsk_recover`와 SQLite DB를 만든다고 적은 `tsk_loaddb`가 들어 있다 [13].
`get_hash`의 `algorithm`은 `md5`·`sha1`·`sha256`·`sha512` 네 값으로 제한되고 이 값에 `sum`을 붙인 이름이 실행 파일이 된다 [1].
두 도구 모두 목록을 바꾸는 설정이나 인자는 없다 [13][1].
목록 안의 명령에 넘기는 `arguments`는 서버가 검사하지 않는다 [13].
`run_volatility_command`는 플러그인 이름을 목록과 대조하지 않는다 [4].

**한계.** 목록에 없는 실행 파일도 `run_find`와 `run_volatility_command`를 이어 불러 컨테이너에서 실행할 수 있다 [7][4].
`run_sleuthkit_command`의 `tool`에 `id`를 주자 FastMCP가 거부했다 [9].
`subprocess.run`으로 `id -un`을 부르는 플러그인 파일을 `run_find`의 `-fprintf`로 만들어 `--plugin-dirs`로 실행하자 결과 행에 `analyst`가 저장되었다 [9].

### T02.06 질의 구조·연산 검사

**구현.** 이 방식은 `run_find`의 `arguments`에 적용된다 [7].
`run_find`는 `arguments`를 공백으로 이어 붙인 글에 `-exec`가 들어 있으면 `RuntimeError`로 거부한다 [7].
이 검사는 글자열이 들어 있는지만 보므로 `-execdir`도 거부하고 `-name`의 값 `*-executor*`처럼 `-exec`가 들어 있는 다른 인자도 거부한다 [15].
`find`의 다른 동작은 검사하지 않는다 [7].
`-fprint`와 `-fprintf`를 주자 `/artifacts`와 컨테이너의 `/tools`에 파일이 만들어졌고 `-delete`를 주자 그 파일이 지워졌다 [15].
같은 동작을 `/evidence`와 `/analysis`에 주자 `find`가 `Read-only file system` 오류로 끝났고 서버는 이 호출을 거부하지 않았다 [15].
`run_strings`·`run_grep`·`run_volatility_command`·`run_sleuthkit_command`의 `arguments`에는 이런 검사가 없다 [7][4][8].

**한계.** `-ok`와 `-okdir`는 `-exec`처럼 명령을 실행하는 동작인데 이 검사를 통과한다 [16].
`-ok cat {} ;`와 `-okdir cat {} ;`를 주자 `find`가 실행되어 종료 코드 0이 기록되었다 [16].
두 호출의 결과 본문은 비어 있어 `cat`의 출력은 없었다 [16].
서버가 쓰는 python-on-whales 0.81.0은 `interactive`를 주지 않으면 `docker exec`에 `--interactive`를 붙이지 않고 서버는 이 값을 주지 않는다 [17][6].
표준 입력으로 확인 답을 받은 `find`가 명령을 실행하는 경우는 확인하지 못했다 [16].

`-exec` 없이 `run_find`와 `run_volatility_command`를 이어 불러도 컨테이너에서 다른 명령이 실행된다 [7][4].
`-exec id -un ;`을 준 `run_find`는 거부되었다 [9].
`-fprintf`로 만든 플러그인 파일을 `--plugin-dirs`로 실행하자 그 파일이 부른 `id -un`의 출력 `analyst`가 결과에 저장되었다 [9].

def unzip_file(ctx: Context, source_file: str, destination_dir: str) -> CommandRecordSummary:
    """Runs: unzip -X -K <SOURCE_FILE> -d /artifacts/<DESTINATION_FILE_NAME>"""
    if source_file.find("..") != -1 or destination_dir.find("..") != -1:
        raise RuntimeError("Invalid file path, Path traversal is not allowed")
    if not Path(source_file).is_file():
        raise FileNotFoundError("Source file not found")
    if not destination_dir.startswith("/artifacts/"):
        raise RuntimeError("Destination directory must be in /artifacts")
    return docker_manager.exec_stream(ctx=ctx, command_list=["unzip", "-X", "-K", source_file, "-d", destination_dir])
```

def untar_file(
    ctx: Context,
    source_file: str,
    destination_dir: str,
    compression: None | Literal["gz", "bz2", "xz", "lzip", "lzma", "lzop", "zstd"] = None,
) -> CommandRecordSummary:
    """Runs: tar -xf <SOURCE_FILE> -C /artifacts/<DESTINATION_FILE_NAME>"""
    if source_file.find("..") != -1 or destination_dir.find("..") != -1:
        raise RuntimeError("Invalid file path, Path traversal is not allowed")
    if not Path(source_file).is_file():
        raise FileNotFoundError("Source file not found")
    if not destination_dir.startswith("/artifacts/"):
        raise RuntimeError("Destination directory must be in /artifacts")
    if compression is None:
        return docker_manager.exec_stream(ctx=ctx, command_list=["tar", "-xf", source_file, "-C", destination_dir])
    if compression in TAR_COMPRESSION_FLAGS:
        return docker_manager.exec_stream(
            ctx=ctx, command_list=["tar", "-x", TAR_COMPRESSION_FLAGS[compression], source_file, "-C", destination_dir]
        )
    else:
        raise ValueError(f"Unsupported compression type, {compression} is not supported")
```

```python
    def exec_stream(self, ctx: Context, command_list: list[str]) -> CommandRecordSummary:
        if self.container is None:
            raise RuntimeError("No docker container is currently running")

        ctx.report_progress(f"Running command {' '.join(command_list)}")
        output = []
        exit_code = 0
        try:
            for stream, data in self.docker.execute(self.container, command_list, stream=True):
                if stream == "stdout":
                    output.append(data.decode())
        except DockerException as ex:
            exit_code = ex.return_code if ex.return_code is not None else 1
            output.append(str(ex))
        result = "".join(output)
        return command_history_manager.add_command(
            CommandRecord(
                command=" ".join(command_list),
                result=result,
                exit_code=exit_code,
            )
        )
```
