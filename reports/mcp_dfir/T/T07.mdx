# T07 도구 부재 처리

### T07.02 대체 없는 실패 처리·도구 부재 알림

**구현.** 이 방식은 `download_windows_symbol`이 Microsoft 심볼 서버에서 PDB 파일을 받는 단계에 적용된다 [1].
`_download_windows_pdb`는 심볼 서버의 응답 상태가 404이면 `PDB not found on symbol server. Check that pdb_name and guid are correct.` 문구와 요청한 URL을 담은 `RuntimeError`를 낸다 [1].
서버는 다른 주소나 다른 심볼로 바꿔 다시 요청하지 않는다 [1].
MCP Python SDK 1.27.0의 FastMCP는 이 예외 문구를 `Error executing tool <도구>: ` 뒤에 붙여 `isError` 응답으로 돌려준다 [2].
심볼 서버에 없는 이름과 GUID를 주자 이 문구와 URL을 담은 `isError` 응답이 왔다 [3].
이 문구로 PDB가 심볼 서버에 없다는 사실이 다른 실패와 구별된다 [1].
심볼 서버가 404가 아닌 오류 상태를 돌려주면 `raise_for_status`가 낸 예외 문구가 그대로 응답에 실린다 [1].

서버의 다른 경로에서는 도구나 참조 자료가 없다는 사실이 다른 실패와 구분되어 응답에 실리지 않는다.
`exec_stream`은 컨테이너 객체가 없으면 `No docker container is currently running` 문구의 `RuntimeError`를 내지만 서버는 컨테이너를 준비한 뒤에야 MCP 요청을 받으므로 도구 호출은 이 분기에 닿지 않는다 [4][5].
`download_linux_symbol`은 응답 상태를 `raise_for_status`로만 확인한다 [6].
심볼 저장소에 없는 경로를 주자 `requests`의 예외 문구 `404 Client Error: Not Found for url: …`이 그대로 `isError` 응답에 실렸다 [3].
컨테이너에서 명령을 실행하는 도구는 그 실행 파일이 컨테이너 안에 있는지 실행 전에 확인하지 않는다 [4].
`unzip_file`은 `unzip`을 실행하지만 이미지의 `Dockerfile`이 설치하는 패키지는 `binutils`, `sleuthkit`, `git`이다 [7][8].
이미지 안에는 `unzip`이 없었고 `unzip_file` 호출은 `exit_code`가 127인 `CommandRecordSummary`를 `isError`가 거짓인 응답으로 돌려주었다 [3].
`executable file not found in $PATH` 문구는 이 응답에 없고 `get_command_result`로 읽는 결과 본문에만 있었다 [3].
`untar_file`이 `compression` 값에 따라 쓰는 압축 프로그램 7개 가운데 이미지 안에 있는 것은 `gzip` 하나였다 [3][9].
`compression`을 `xz`로 준 실행은 `tar`가 `xz`를 실행하지 못해 종료 코드 2로 끝났고 서버는 이 실행을 다른 실패와 같은 모양으로 기록했다 [3].
Volatility 심볼이 있는지도 서버는 실행 전에 확인하지 않는다 [10].
맞는 심볼이 없는 메모리 이미지에 `linux.pslist.PsList`를 실행하자 Volatility가 심볼 요구 조건을 채우지 못했다는 글을 내고 종료 코드 1로 끝났고 서버는 이 실행을 다른 실패와 같은 모양으로 기록했다 [3].
`run_volatility_command`의 도구 설명은 심볼을 따로 받아야 할 수 있다고만 적는다 [10].
PDB를 받은 뒤 `pdbconv` 변환이 실패해 심볼 파일이 생기지 않으면 `download_windows_symbol`은 그 파일을 읽다가 `FileNotFoundError`로 끝난다 [11].
내려받기 함수가 PDB가 아닌 내용을 돌려주게 바꾼 상태에서 `download_windows_symbol` 함수를 부르면 성공한 내려받기 기록과 종료 코드 1의 `pdbconv` 기록이 남았고 함수는 사건 폴더의 호스트 경로를 담은 `FileNotFoundError`로 끝났다 [3].

### T07.07 실행 전 부재 도구 자동 설치

**구현.** 이 방식은 서버가 시작할 때 준비하는 포렌식 컨테이너와 `search_linux_symbols`가 읽는 Linux 심볼 맵에 적용된다 [5][12].
`runner.main`은 MCP 서버를 실행하기 전에 `start_forensic_container`를 부른다 [5].
이 함수는 `<사건 폴더 이름>-forensics` 컨테이너를 `inspect`로 조회한다 [13][14].
컨테이너가 실행 중이면 그대로 쓰고 멈춰 있으면 시작한다 [13].
컨테이너가 없으면 `androsh7/forensics-docker:<VERSION>` 이미지로 `docker run`을 실행해 만든다 [13][14].
서버는 이 호출에 `pull` 인자를 주지 않는다 [13].
python-on-whales 0.81.0의 `run`은 `pull`의 기본값이 `missing`이고 이 값이면 이미지를 `inspect`로 조회해 로컬에 없을 때 `docker image pull`로 받는다 [15].
이미지의 `Dockerfile`은 `binutils`, The Sleuth Kit, Volatility 3를 설치한다 [8].
`runner.main`은 컨테이너 준비가 끝난 뒤에 `mcp.run`을 부르므로 이미지를 받는 동안 서버는 MCP 요청에 응답하지 않는다 [5].
컨테이너가 없는 사건 폴더로 서버를 시작하자 서버 로그에 `Forensics container does not exist, creating one`이 남고 컨테이너가 만들어졌다 [3].
멈춘 컨테이너가 있는 사건 폴더로 시작하자 `Forensics container exists but is stopped, starting it`이 남았다 [3].
이미지 태그 상수를 Docker Hub에 없는 값으로 바꿔 시작하자 `Unable to find image '…' locally` 줄이 나온 뒤 `docker image pull`이 실패했고 서버는 종료 코드 1로 끝났다 [3].

`search_linux_symbols`는 사건 폴더의 `symbols/linux/symbol_map.json`이 없으면 `LINUX_SYMBOL_MAP_SOURCE` 주소에서 심볼 맵을 받아 저장한 뒤 검색한다 [12].
이 주소는 GitHub 저장소 `Abyss-W4tcher/volatility3-symbols`의 `banners/banners_plain.json`이다 [16].
맵이 없는 사건 폴더에서 처음 부르자 3,523,417바이트의 `symbol_map.json`이 생겼고 같은 인자로 다시 부른 호출은 0.1초 안에 응답했다 [3].

서버가 실행 전에 받아 두는 참조 자료는 이 심볼 맵뿐이다.
Volatility 심볼 파일은 모델이 `download_windows_symbol`이나 `download_linux_symbol`을 불러야 `symbols` 폴더에 생긴다 [11][6].
컨테이너 안에 없는 실행 파일을 설치하는 코드는 없고 서버는 컨테이너를 네트워크 `none`으로 만든다 [13].

Docker가 없을 때의 처리는 없다.
`start_forensic_container`는 `NoSuchContainer`만 처리하므로 Docker 데몬에 닿지 못해 난 `DockerException`은 `runner.main` 밖으로 나간다 [13][5].
`DOCKER_HOST`를 닫힌 포트로 주고 서버를 시작하자 서버는 표준 오류에 `DockerException` traceback을 내고 표준 출력에 아무것도 쓰지 않은 채 종료 코드 1로 끝났다 [3].
`docker` 실행 파일이 없는 `PATH`로 시작하자 python-on-whales의 `ClientNotFoundError` traceback을 내고 같은 종료 코드로 끝났다 [3].

**한계.** 같은 이름의 컨테이너가 있으면 서버는 그 컨테이너를 만든 이미지와 연결된 폴더를 확인하지 않고 쓴다 [13].
폴더를 연결하지 않고 같은 이름으로 만들어 둔 컨테이너를 서버가 그대로 썼고 `get_hash`는 `/evidence/notes.txt`가 없다는 `md5sum` 오류를 기록했다 [3].
컨테이너를 만드는 `docker run`이 실패해 난 `DockerException`도 `start_forensic_container`는 처리하지 않는다 [13].
컨테이너가 없는 사건 폴더로 서버 프로세스 둘을 동시에 시작하자 한 프로세스의 `docker run`이 `Conflict. The container name … is already in use` 오류로 끝났고 그 프로세스의 초기화는 실패했다 [3].
다른 프로세스는 컨테이너를 만들고 초기화를 마쳤다 [3].
컨테이너 확인은 서버가 시작할 때 한 번뿐이다 [5].
`exec_stream`은 `self.container`가 `None`인지만 보고 컨테이너의 상태를 조회하지 않는다 [4].
세션 중에 컨테이너를 멈추거나 지운 뒤 부른 도구는 컨테이너를 다시 시작하거나 만들지 않았다 [3].
그 호출은 `is not running`이나 `No such container` 문구를 결과 본문에 담은 종료 코드 1의 명령 기록을 남겼다 [3].
이미지가 로컬에 없으면 python-on-whales는 `Unable to find image` 줄을 `print`로 쓰고 `docker image pull`의 출력을 가로채지 않는다 [15].
두 출력은 서버의 표준 출력으로 나가고 이 표준 출력은 stdio 전송이 MCP 메시지를 보내는 통로다 [15][5].
이미지 태그 상수를 Docker Hub에는 있고 로컬에는 없는 `0.1.1`로 바꿔 MCP Python SDK 1.27.0 클라이언트로 서버를 시작하자 `docker image pull`의 출력 4줄이 MCP 메시지보다 먼저 클라이언트에 왔다 [3].
이 클라이언트는 4줄을 JSON-RPC 메시지로 읽지 못했다고 기록한 뒤 초기화를 마쳤고 뒤이은 `get_hash` 호출도 성공했다 [3].
다른 MCP 클라이언트가 이 줄을 받았을 때 연결이 성립하는지는 확인하지 못했다.
`search_linux_symbols`는 `symbol_map.json`이 있으면 내용을 확인하지 않고 다시 받지 않는다 [12].
내용이 `{` 한 글자인 `symbol_map.json`을 둔 호출은 JSON 해석 오류로 끝났고 서버는 맵을 다시 받지 않았다 [3].

def unzip_file(ctx: Context, source_file: str, destination_dir: str) -> CommandRecordSummary:
    """Runs: unzip -X -K <SOURCE_FILE> -d /artifacts/<DESTINATION_FILE_NAME>"""
    if source_file.find("..") != -1 or destination_dir.find("..") != -1:
        raise RuntimeError("Invalid file path, Path traversal is not allowed")

        raise FileNotFoundError("Source file not found")
    if not destination_dir.startswith("/artifacts/"):

        logger.info("Starting forensics docker container")

        try:
            self.container = self.docker.container.inspect(config.docker_config.container_name)

            if self.container.state.running:
                logger.info("Forensics container already running")
                return

            logger.info("Forensics container exists but is stopped, starting it")
            self.docker.container.start(config.docker_config.container_name)
            return

        except NoSuchContainer:
            logger.info("Forensics container does not exist, creating one")

        volumes = [
            (volume_mount.external_path, volume_mount.internal_path, volume_mount.permissions)
            for volume_mount in list(config.docker_volumes)
        ]
        self.container = self.docker.run(
            config.docker_config.image_name,
            name=config.docker_config.container_name,
            detach=True,
            remove=False,
            volumes=volumes,
            networks=["none"],
