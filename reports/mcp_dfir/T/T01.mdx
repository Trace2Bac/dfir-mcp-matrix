# T01 입력 검증

### T01.01 인자 구조·값 검사

**구현.** 이 방식은 서버 코드가 허용 값을 정해 둔 인자 5개와 `get_command_result`의 인자 조합에 적용된다 [1][2].
서버는 도구 함수 18개를 FastMCP에 등록한다 [3].
MCP Python SDK 1.27.0의 FastMCP는 함수 매개변수의 자료형으로 만든 pydantic 모델로 인자를 검사한 뒤 함수를 부르고 검사에서 난 예외를 `Error executing tool`로 시작하는 오류로 바꾼다 [4].
서버 코드는 `get_hash`의 `algorithm`, `run_sleuthkit_command`의 `tool`, `list_files`의 `path`, `untar_file`의 `compression`, 분석 메모의 `status`를 `Literal`로 적어 허용 값 목록을 정한다 [1].
목록 밖의 값을 주면 FastMCP가 함수를 부르지 않고 오류 응답을 돌려준다 [4][5].
`algorithm`에 `sha3`과 대문자 `SHA256`, `tool`에 `rm`, `path`에 `analysis`와 `../evidence`, `compression`에 `rar`, `status`에 `suspicious`를 주자 모두 허용 값을 적은 `literal_error` 오류가 왔다 [5].
자료형이 다른 값과 빠진 필수 인자도 같은 단계에서 거부된다 [5].
FastMCP는 정수로 읽히는 문자열을 정수로 바꾸고 list를 적은 JSON 문자열을 list로 바꿔 넘기며 입력 schema에 없는 인자는 버린다 [4][5].

서버 코드는 네 도구 함수 안에서 같은 값을 다시 검사한다 [6].
`get_hash`는 `algorithm`을 소문자로 바꿔 `HASHING_ALGORITHMS`에서 찾고 `run_sleuthkit_command`는 `tool`을 `SLEUTHKIT_COMMANDS`에서 찾는다 [6].
`list_files`는 `path`를 설정의 볼륨 이름 4개에서 찾고 `untar_file`은 `compression`을 `TAR_COMPRESSION_FLAGS`에서 찾는다 [6].
MCP 호출에서는 FastMCP가 먼저 거부하므로 목록 밖의 값이 이 검사에 전달되지 않는다 [5].
도구 함수를 직접 부르면 `get_hash`는 `KeyError`로, `list_files`는 `RuntimeError`로, `untar_file`은 `ValueError`로 거부한다 [7].
`run_sleuthkit_command`는 오류 문구를 만들 때 list인 `SLEUTHKIT_COMMANDS`에 `.keys()`를 불러 `AttributeError`로 끝나고 명령은 실행하지 않는다 [6][7].
`list_files`의 `Literal`은 `artifacts`·`symbols`·`evidence` 3개이고 함수 안의 검사는 `analysis`도 받는다 [1][6][7].

`get_command_result`는 `head`와 `tail`을 함께 주거나 `head_bytes`와 `tail_bytes`를 함께 주면 `RuntimeError`로 거부한다 [2][5].
이 도구의 `head`·`head_bytes`·`tail`·`tail_bytes`·`regex`에는 기본값이 없어 하나라도 빠지면 FastMCP가 `Field required`로 거부한다 [2][5].
`head`와 `tail`의 값 범위는 검사하지 않는다 [2].
`regex`는 컴파일해 보지 않고 `re.search`에 넘기므로 닫지 않은 괄호를 주면 검색에서 난 예외 문구가 오류로 돌아온다 [2][5].
`byte_limit`에는 자료형을 적지 않아 FastMCP가 값을 검사하지 않고 함수에 넘긴다 [2].
이 인자에 문자열 `"10"`을 주자 길이를 비교하는 줄에서 난 `TypeError` 문구가 오류로 돌아왔다 [5].

실행 도구의 `arguments`는 문자열 list인지만 검사한다 [8][5].
`run_find`가 `-exec` 글자열을 찾는 것 말고는 서버 코드가 그 안의 값을 검사하지 않는다 [8].
`download_windows_symbol`의 `pdb_name`·`guid`와 `download_linux_symbol`의 `symbol_path`는 문자열인지만 검사하고 형식은 검사하지 않는다 [9].

### T01.02 입력 존재·읽기 가능 검사

**구현.** 이 방식은 `unzip_file`과 `untar_file`의 `source_file`에 적용된다 [10].
두 도구는 `Path(source_file).is_file()`이 거짓이면 `FileNotFoundError`로 거부하고 컨테이너에서 명령을 실행하지 않는다 [10].
다른 실행 도구는 입력 파일이 있는지 확인하지 않고 명령을 실행한다 [8].
없는 파일을 `get_hash`와 `run_sleuthkit_command`의 `fls`에 주자 명령이 실행되어 종료 코드 1인 명령 기록이 남았다 [11].

**한계.** 이 확인은 서버 프로세스가 호스트의 파일 시스템에서 하고 `source_file`은 컨테이너 안에서 `unzip`과 `tar`가 읽을 경로다 [10].
서버는 사건 폴더의 `evidence`를 컨테이너의 `/evidence`에 연결하므로 같은 파일의 호스트 경로와 컨테이너 경로가 다르다 [12].
컨테이너에 있는 `/evidence/sample.zip`과 `/evidence/sample.tar`를 주자 두 도구가 `Source file not found`로 거부했다 [11].
호스트 경로 `<사건 폴더>/evidence/sample.tar`를 주자 확인을 통과했고 그 경로를 그대로 받은 `tar`가 컨테이너에서 종료 코드 128로 끝났다 [11].
그래서 이 확인은 컨테이너의 도구가 읽을 파일이 아니라 호스트에 같은 경로 문자열로 있는 파일을 본다 [10][12].

### T01.04 문자열 경로 검사

**구현.** 이 방식은 `unzip_file`과 `untar_file`의 `source_file`과 `destination_dir`에 적용된다 [10].
두 도구는 두 인자 가운데 하나라도 `..`이 들어 있으면 `RuntimeError`로 거부한다 [10].
`destination_dir`이 `/artifacts/`로 시작하지 않아도 거부한다 [10].
두 검사는 파일 시스템을 보지 않고 문자열만 본다 [10].
검사는 `..` 확인, 호스트의 파일 확인, 접두어 비교 순서로 이루어진다 [10].
그래서 `/tmp/z`를 `destination_dir`로 주어도 `source_file`이 호스트에 없으면 `Source file not found`가 먼저 돌아온다 [11].
끝에 `/`가 없는 `/artifacts`는 거부되고 `/artifacts/`는 통과한다 [7][11].
`source_file`은 `..`만 없으면 어느 폴더의 경로든 받는다 [10].

경로를 받는 다른 인자에는 경로 검사가 없다 [8].
`get_hash`의 `file_path`와 `run_strings`·`run_grep`·`run_find`·`run_volatility_command`·`run_sleuthkit_command`의 `arguments`에 들어 있는 경로는 검사 없이 명령 인자가 된다 [8].
`get_hash`와 `run_grep`에 `/etc/passwd`를, `run_strings`에 `/etc/hostname`을 주자 사건 폴더를 연결한 네 폴더 밖의 컨테이너 파일을 읽고 종료 코드 0으로 끝났다 [13].
`run_grep`에 `/analysis/command_history.json`을 주자 서버가 쓰는 명령 기록 목록도 읽혔다 [13].
`download_linux_symbol`의 `symbol_path`는 내려받을 주소의 경로가 되는데 서버는 이 값에 `..`이 있는지 검사하지 않는다 [9].
경로를 실제 경로로 변환해 허용 폴더와 대조하는 코드는 없다.

### T01.05 등록된 ID와 대조

**구현.** 이 방식은 `get_command_result`의 `command_number`와 분석 메모 도구 `show_analyst_note`·`update_analyst_note`의 `title`에 적용된다 [14][15].
`get_command_result`는 `command_number`를 서버가 명령 기록마다 매긴 번호의 목록 `command_summary_list`에서 찾고 없으면 `KeyError`로 거부한다 [14].
번호가 있으면 결과 본문 파일 `command_history/<번호>.txt`를 읽는다 [14].
`show_analyst_note`는 `title`이 메모 목록 `note_list`에 있을 때만 `analyst_notes/<title>.md`를 읽고 없으면 `KeyError`로 거부한다 [15].
`update_analyst_note`도 `title`을 같은 목록에서 찾고 없으면 `KeyError`로 거부한다 [15].
없는 번호 999와 없는 제목 `../command_history`를 주자 `Could not find command with number 999`와 `No note with title` 오류가 왔다 [16].
두 목록은 서버가 시작할 때 사건 폴더의 `command_history.json`과 `analyst_notes.json`에서 읽어 들인다 [17].
메모 목록의 제목은 `add_analyst_note`가 받은 `title`이고 이 도구는 그 값을 검사하지 않고 목록에 더한다 [15].
`update_note`는 반복 변수 `note`가 인자 `note`를 가려 목록에서 찾은 `AnalystNoteSummary`에 `summary()`를 부른다 [15].
그래서 목록에 있는 `title`로 부른 `update_analyst_note`는 대조를 통과한 뒤 `'AnalystNoteSummary' object has no attribute 'summary'` 오류로 끝났고 메모 본문은 바뀌지 않았다 [16].

### T01.06 고정 입력 경로 사용

**구현.** 이 방식은 `list_files`와 `search_linux_symbols`에 적용된다 [18][19].
`list_files`는 경로를 받지 않고 `path`로 받은 이름 `artifacts`·`symbols`·`evidence`를 사건 폴더 아래 같은 이름의 폴더로 바꿔 그 폴더만 훑는다 [18][12].
사건 폴더는 사용자가 실행 인자 `--case-dir`로 정하고 주지 않으면 서버를 실행한 작업 폴더다 [20].
`search_linux_symbols`는 경로 인자 없이 사건 폴더의 `symbols/linux/symbol_map.json`만 읽는다 [19].
`list_files`에 `evidence`를 주자 사건 폴더의 `evidence`에 둔 파일 5개가 `/evidence/` 경로로 돌아왔다 [5].
`get_command_history`와 `show_analyst_notes_summary`는 인자가 없고 서버가 메모리에 둔 `command_summary_list`와 `note_list`를 돌려준다 [21].
컨테이너에서 명령을 실행하는 도구 8개는 모델이 준 경로를 읽는다 [8].

def unzip_file(ctx: Context, source_file: str, destination_dir: str) -> CommandRecordSummary:
    """Runs: unzip -X -K <SOURCE_FILE> -d /artifacts/<DESTINATION_FILE_NAME>"""
    if source_file.find("..") != -1 or destination_dir.find("..") != -1:
        raise RuntimeError("Invalid file path, Path traversal is not allowed")
    if not Path(source_file).is_file():
        raise FileNotFoundError("Source file not found")
    if not destination_dir.startswith("/artifacts/"):
        raise RuntimeError("Destination directory must be in /artifacts")
    return docker_manager.exec_stream(ctx=ctx, command_list=["unzip", "-X", "-K", source_file, "-d", destination_dir])
