# T05 분석 도구 검증

### T05.01 저장소·의존성 고정

**구현.** 이 방식은 분석 도구를 담은 컨테이너 이미지에 적용된다 [1].
서버 코드는 이미지 이름을 `androsh7/forensics-docker:<VERSION>`으로 만들고 `VERSION`은 상수 `0.1.2`다 [1].
서버는 그 사건의 컨테이너가 없으면 이 이름으로 `docker.run`을 불러 컨테이너를 만든다 [2].
서버에는 이미지를 따로 내려받거나 만드는 코드가 없다 [2].
python-on-whales 0.81.0의 `run`은 `pull`의 기본값이 `missing`이고 서버는 이 값을 바꾸지 않아 `docker run`에 `--pull` 인자가 붙지 않는다 [3][2].
이미지 이름에는 태그만 있고 다이제스트는 없다 [1].
서버는 이미지의 다이제스트를 읽거나 대조하지 않는다 [2].

태그가 가리키는 이미지 안의 도구 버전은 저장소가 정하지 않는다 [4].
`Dockerfile`은 `python:3.12-slim`에서 시작해 `sleuthkit`과 `binutils`를 버전 없이 `apt-get install`로 설치한다 [4].
Volatility 3는 태그나 커밋을 적지 않고 `git clone`으로 받은 기본 브랜치를 `pip install -e ".[full]"`로 설치한다 [4].
저장소의 workflow는 PyPI 배포와 테스트 둘이고 이미지를 만들거나 올리는 workflow는 없다 [5].
Docker Hub에서 받은 `0.1.2` 이미지에는 Volatility 3의 `develop` 브랜치 커밋 `9424c3a`(패키지 버전 2.28.1)와 The Sleuth Kit 4.12.1이 있었다 [6].
저장소의 예시 사건 폴더에 남은 실패 기록의 버전 줄은 `Volatility 3 Framework 2.28.0`이고 그 기록에는 명령을 실행한 이미지의 태그가 없다 [7].
`pyproject.toml`은 `attrs`·`loguru`·`mcp`·`python_on_whales`·`requests`를 버전 없이 이름만 적고 저장소에 잠금 파일은 없다 [8].

심볼은 고정하지 않는다 [9].
Linux 심볼과 심볼 맵은 `Abyss-W4tcher/volatility3-symbols` 저장소의 `refs/heads/master` 주소에서 받는다 [9].
Windows 심볼은 Microsoft 심볼 서버에서 받는다 [9].
서버는 실행 중에 이미지, Volatility, The Sleuth Kit의 버전을 묻거나 읽지 않는다.

**한계.** 서버는 같은 이름의 컨테이너가 이미 있으면 그 컨테이너를 만든 이미지를 확인하지 않고 다시 쓴다 [2].
다른 이미지 이름으로 만든 컨테이너를 같은 이름으로 미리 두고 서버를 시작하자 서버는 그 컨테이너에서 도구를 실행했다 [10].
그래서 `VERSION`이 다른 서버를 같은 사건 폴더 이름으로 실행해도 앞서 만든 컨테이너가 남아 있으면 그 컨테이너의 도구가 실행된다 [1][2].
컨테이너 안의 Volatility 소스 폴더는 실행 계정 `analyst`의 소유라서 도구 호출이 그 안의 파일을 만들고 지울 수 있다 [4][11].
`run_find`로 Volatility 플러그인 폴더에 만든 파일은 서버를 다시 시작한 뒤에도 남아 플러그인으로 실행되었다 [11].

### T05.02 설정·호출 인자로 지정

**구현.** 이 방식은 Volatility가 쓰는 심볼에 적용된다 [12][13][14].
`run_volatility_command`는 심볼 폴더를 `-s /symbols`로 정해 넘긴다 [12].
이 폴더는 사용자가 실행 인자 `--case-dir`로 정한 사건 폴더의 `symbols`이고 README는 이 폴더를 심볼을 내려받으면 채워지는 곳으로 설명한다 [15][16].
`Dockerfile`은 환경변수 `VOLATILITY_SYMBOLS`에 심볼 폴더 경로를 적는다 [17].
서버 코드와 이미지 안 Volatility 3 소스에는 이 이름을 읽는 곳이 없었고 그 값이 가리키는 폴더도 이미지에 없었다 [6].
`download_windows_symbol`은 호출 인자 `pdb_name`·`guid`·`age`로 받을 PDB를 정한다 [13].
서버는 `<심볼 서버>/<pdb_name>/<guid><age>/<pdb_name>` 주소에서 PDB를 받아 `pdbconv`로 바꾸고 결과를 `symbols/windows/<pdb_name>/<guid>-<age>.json.xz`에 둔다 [13].
서버는 `guid`와 `age`를 증거에서 읽지 않고 모델이 준 값을 그대로 쓴다 [13].
`download_linux_symbol`은 호출 인자 `symbol_path`를 심볼 저장소 주소 뒤에 붙여 받고 경로의 마지막 조각을 이름으로 `symbols/linux`에 둔다 [14].
`download_linux_symbol`에는 `overwrite` 인자가 없고 `symbols/linux`에 같은 이름의 파일이 이미 있는지 확인하지 않고 받은 내용을 쓴다 [14].
파일 이름은 `symbol_path`의 마지막 조각이라 폴더가 다르고 이름이 같은 두 경로는 같은 파일에 쓰인다 [14].
마지막 조각이 `README.md`인 두 경로를 차례로 주자 `symbols/linux/README.md`가 7,465바이트에서 5,752바이트로 바뀌었고 두 호출 모두 종료 코드 0인 명령 기록을 남겼다 [18].
`search_linux_symbols`는 심볼 맵에서 정규식에 맞는 배너와 그 심볼 파일 경로를 찾는다 [19].
심볼 맵 `symbol_map.json`은 사건 폴더에 없을 때만 받고 그 뒤에는 다시 받지 않는다 [19].
서버는 받은 PDB와 심볼 파일을 쓰기 전에 HTTP 상태 코드만 확인하고 해시, 크기, 형식은 확인하지 않는다 [13][14].
`run_volatility_command`의 `arguments`에 `--plugin-dirs /artifacts`를 주자 이미지에 없는 플러그인 파일이 실행되었다 [20].
이미지 이름이나 분석 도구의 버전을 정하는 실행 인자, 환경변수, 설정 파일은 없다 [21].

**한계.** `download_linux_symbol`은 `symbol_path`를 검사하지 않아 `..`이 들어 있는 값은 심볼 저장소 밖의 주소가 된다 [14].
`symbol_path`에 `../../../../../volatilityfoundation/volatility3/<커밋>/README.md`를 주자 다른 저장소의 README가 `symbols/linux/README.md`로 저장되었다 [22].
이 호출의 결과 본문은 `Successfully downloaded symbol file README.md`로 시작했다 [22].

`search_linux_symbols`는 맞는 배너가 있으면 찾은 항목의 list를 `json.dumps`로 바꾸는 줄에서 `TypeError`로 끝나 심볼 파일 경로를 돌려주지 못한다 [19][23].
심볼 맵에 있는 커널 버전에 맞는 정규식을 주자 `Object of type SymbolSearchResult is not JSON serializable` 오류가 왔고 심볼 맵에 없는 문자열을 주었을 때만 명령 기록이 생겼다 [23].

def download_linux_symbol(ctx: Context, symbol_path: str) -> CommandRecordSummary:
    """Download a symbol map from the Abyss-W4tcher/volatility3-symbols repository"""

    # Download json file from repo
    url = f"{LINUX_SYMBOL_REPO_BASE_URL}/{symbol_path}"
    ctx.report_progress(f"Downloading symbol from {url}")
    response = requests.get(url=url)
    response.raise_for_status()

    # Save json file
    config.linux_symbols_directory.mkdir(mode=500, parents=True, exist_ok=True)
    file_name = symbol_path.rsplit("/", maxsplit=1)[-1]
    file_path = config.linux_symbols_directory / file_name
    file_path.write_bytes(response.content)

    return command_history_manager.add_command(
        CommandRecord(
            command=f'mcp_dfir:tools:volatility:download_linux_symbol(symbol_path="{symbol_path}")',
            result=f"Successfully downloaded symbol file {file_name} ({file_path.stat().st_size} bytes) from {url}",
            exit_code=0,
        )
    )
```

def search_linux_symbols(ctx: Context, regex: str) -> CommandRecordSummary:
    """Load linux symbol map from Abyss-W4tcher/volatility3-symbols and search for symbols matching the regex"""

    # Download symbol map if it doesn't exist
    if not config.linux_symbol_map_json.exists():
        ctx.report_progress("Downloading linux symbol map from github.com/Abyss-W4tcher/volatility3-symbols")
        response = requests.get(url=LINUX_SYMBOL_MAP_SOURCE)
        response.raise_for_status()
        config.linux_symbols_directory.mkdir(mode=500, parents=True, exist_ok=True)
        config.linux_symbol_map_json.write_bytes(response.content)

    # Parse the symbol map
    with open(config.linux_symbol_map_json, encoding="utf-8") as symbol_map_file:
        symbol_map: dict = json.load(symbol_map_file)

    # Return the a list of matches
    out_list = []
    for symbol_name, file_path_list in symbol_map.items():
        if re.search(regex, symbol_name):
            out_list.append(SymbolSearchResult(symbol_name=symbol_name, file_path_list=file_path_list))

    return command_history_manager.add_command(
        CommandRecord(
            command=f'mcp_dfir:tools:volatility:search_linux_symbols(regex="{regex}")',
            result=json.dumps(out_list, indent=4),
            exit_code=0,
        )
    )
```
