# T08 실행 종료 판별

### T08.01 종료 코드 확인

**구현.** 이 방식은 `exec_stream`으로 컨테이너에서 명령을 실행하는 도구 8개와 `download_windows_symbol`의 `pdbconv` 실행에 적용된다 [1][2].
8개는 `run_strings`, `run_grep`, `run_find`, `unzip_file`, `untar_file`, `get_hash`, `run_volatility_command`, `run_sleuthkit_command`다 [2].
`exec_stream`은 python-on-whales의 `docker.execute`를 `stream=True`로 불러 `docker exec`의 출력을 끝까지 읽는다 [1].
python-on-whales 0.81.0은 `docker exec` 프로세스의 종료 코드가 0이 아니면 종료 코드와 표준 오류를 담은 `DockerException`을 낸다 [3].
서버는 이 예외가 나면 예외의 `return_code`를 `exit_code`로 정하고 값이 없으면 1로 정한다 [1].
예외가 나지 않으면 `exit_code`는 0이다 [1].
`exit_code`는 응답인 `CommandRecordSummary`와 명령 기록 목록 `command_history.json`에 실린다 [1][4].
`download_windows_symbol`은 끝까지 실행되면 `pdbconv` 기록과 내려받기 기록의 `CommandRecordSummary` 둘을 돌려준다 [5].
서버는 `exit_code`가 0이 아니어도 MCP 오류 결과를 쓰지 않고 `CommandRecordSummary`를 정상 응답으로 돌려준다 [1].
없는 이미지 파일에 `fsstat`을 실행하자 `isError`가 거짓이고 `exit_code`가 1인 응답이 왔다 [6].

실패한 실행의 결과 본문은 그때까지 모은 표준 출력 뒤에 예외 글을 붙인 것이다 [1].
예외 글에는 실행한 `docker exec` 명령, 종료 코드, 표준 오류 전체가 들어 있다 [3].
`exec_stream`은 스트림에서 표준 출력 조각만 모으므로 종료 코드 0으로 끝난 실행의 표준 오류는 결과 본문에 남지 않는다 [1].
응답에는 결과 본문이 없어 실패 문구는 `get_command_result`로 따로 읽어야 한다 [4][6].
서버는 결과 본문의 내용을 읽어 실패나 빈 결과를 정하지 않는다 [1].

서버는 종료 코드가 0이 아닌 까닭을 가리지 않는다 [1].
일치하는 줄이 없는 `grep -c`는 종료 코드 1로 끝났고 결과 본문은 `0` 한 줄 뒤에 예외 글이 붙은 글이었다 [6].
`exit_code`는 `docker exec` 프로세스의 종료 코드라서 Docker 쪽 실패도 같은 필드에 실린다 [3].
컨테이너 안에 없는 `unzip`을 실행한 호출은 127이 되었고 세션 중에 멈추거나 지운 컨테이너에서 실행한 호출은 1이 되었다 [6].
`tar`가 보관 파일 안의 파일 2개를 모두 푼 뒤 대상 폴더의 시각과 권한을 바꾸지 못해 종료 코드 2로 끝난 실행도 다른 실패와 같은 모양으로 기록되었다 [6].

컨테이너에서 명령을 실행하지 않는 도구는 종료 코드를 받지 않는다.
`download_windows_symbol`의 내려받기 단계, `download_linux_symbol`, `search_linux_symbols`는 끝까지 실행되었을 때만 `exit_code`를 0으로 적은 명령 기록을 남긴다 [7].
서버 코드는 이 도구들이 서버 프로세스 안에서 낸 예외를 처리하지 않으므로 예외는 FastMCP에 전달되어 `isError` 응답이 되고 명령 기록은 남지 않는다 [7][8].
`search_linux_symbols`가 맞는 항목을 JSON으로 바꾸다 낸 `TypeError`는 `isError` 응답으로 왔고 명령 기록에 그 호출은 없었다 [6].

서버는 실행에 시간 제한을 두지 않는다 [1].
`exec_stream`에는 시간 제한 인자가 없고 `docker.execute` 호출에도 시간 제한을 주지 않는다 [1].
심볼을 받는 `requests.get` 호출 3곳에도 `timeout` 인자가 없다 [9].
도구 함수는 모두 동기 함수이고 MCP Python SDK 1.27.0의 FastMCP는 동기 함수를 이벤트 루프에서 직접 부른다 [2][10].
그래서 명령 하나가 끝날 때까지 서버는 다른 요청을 처리하지 않는다 [10].
4.2 GB 메모리 이미지에 `grep -c`를 실행한 호출은 27.8초 뒤에 응답했고 그 호출을 보내고 3초 뒤에 보낸 `get_command_history`는 24.8초 뒤에 응답했다 [6].
끝나지 않는 명령 `strings /dev/zero`를 실행한 호출은 15초 동안 응답이 없었다 [6].
클라이언트가 기다리기를 끊은 뒤 보낸 `get_command_history`도 10초 동안 응답이 없었다 [6].
실행 중인 명령을 끊는 코드는 없고 서버가 끝날 때 `stop_forensic_container`가 컨테이너를 멈추는 것이 컨테이너 안 프로세스를 끝내는 유일한 경로다 [11].
`strings /dev/zero`가 실행 중일 때 세션을 닫자 호스트의 서버 프로세스와 `docker exec` 프로세스는 끝났지만 컨테이너는 실행 상태로 남았고 그 안에서 `strings` 프로세스가 계속 실행되었다 [6].
실행 중인 명령이 없을 때 세션을 닫으면 컨테이너는 2.2초 뒤에 `Exited (137)` 상태로 보였다 [6].

**한계.** `exec_stream`이 처리하는 예외는 `DockerException`뿐이다 [1].
표준 출력 조각을 UTF-8로 읽지 못하면 `UnicodeDecodeError`가 `exec_stream` 밖으로 나가 서버는 종료 코드를 받지 못하고 명령 기록도 남기지 않는다 [1].
`img_cat`으로 디스크 이미지를 그대로 출력하게 하자 `'utf-8' codec can't decode byte` 문구의 `isError` 응답이 왔고 명령 기록에 그 호출은 없었다 [6].
`download_windows_symbol`은 `pdbconv` 실행이 돌려준 `exit_code`를 보지 않고 변환된 심볼 파일을 읽는다 [5].
내려받기 함수가 PDB가 아닌 내용을 돌려주게 바꾼 상태에서 이 함수를 부르면 `pdbconv` 기록의 `exit_code`는 1이었고 함수는 `FileNotFoundError`로 끝났으며 앞선 내려받기 기록은 `exit_code` 0으로 남았다 [6].
변환된 심볼 파일이 이미 있고 `overwrite`가 참이면 `pdbconv`가 실패해도 함수는 앞서 있던 파일을 읽어 다시 쓰고 두 기록을 정상 응답으로 돌려준다 [5].
내려받기 함수를 같은 방식으로 바꾸고 심볼 파일을 미리 둔 뒤 `overwrite`를 참으로 주자 함수는 예외 없이 `exit_code`가 1인 `pdbconv` 기록과 `exit_code`가 0인 내려받기 기록을 돌려주었고 앞서 있던 심볼 파일이 그 자리에 남았다 [6].
끝나지 않는 명령은 종료 코드가 정해지지 않아 응답도 명령 기록도 남지 않는다 [1][6].

```python
    def exec_stream(self, ctx: Context, command_list: list[str]) -> CommandRecordSummary:
        if self.container is None:
            raise RuntimeError("No docker container is currently running")

        ctx.report_progress(f"Running command {' '.join(command_list)}")
        output = []
        exit_code = 0
        try:
            for stream, data in self.docker.execute(self.container, command_list, stream=True):
                if stream == "stdout":
                    output.append(data.decode())
        except DockerException as ex:
            exit_code = ex.return_code if ex.return_code is not None else 1
            output.append(str(ex))
        result = "".join(output)
        return command_history_manager.add_command(
            CommandRecord(
                command=" ".join(command_list),
                result=result,
                exit_code=exit_code,
            )
        )
```
