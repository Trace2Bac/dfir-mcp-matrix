# T06 실행 환경정보 표시

### 미구현

**판단.** 서버는 컨테이너 안의 Volatility 3와 The Sleuth Kit 같은 분석 도구로 결과를 내지만 응답, 명령 기록 목록, 결과 본문 파일 어디에도 그 도구의 버전을 필드로 싣지 않는다.
실행 도구의 응답은 `CommandRecordSummary`이고 필드는 `number`, `command`, `date_run`, `exit_code` 넷이다 [1].
명령 기록 목록 `command_history.json`에는 같은 네 값이 남고 결과 본문 파일 `<번호>.txt`에는 `result` 글만 남는다 [2].
`command`에는 실행한 명령 글이 있어 프로그램 이름은 보이지만 버전은 없다 [3].

Volatility가 쓰는 버전 줄은 성공한 실행의 결과 본문에 남지 않는다.
서버는 Volatility를 `-r jsonl`로 실행한다 [4].
이미지 안의 Volatility 3 2.28.1은 JSON 계열 출력 형식을 고르면 `Volatility 3 Framework <버전>` 줄을 표준 출력이 아니라 표준 오류에 쓴다 [5].
`exec_stream`은 `docker exec`의 출력 가운데 표준 출력만 결과로 모은다 [3].
`frameworkinfo.FrameworkInfo`를 실행해 종료 코드 0으로 끝난 결과 본문에는 이 줄이 없었다 [6].
실행이 0이 아닌 종료 코드로 끝나면 python-on-whales 0.81.0이 표준 오류 전체를 예외 글에 넣고 서버는 그 예외 글을 결과 본문 끝에 붙인다 [3][7].
그래서 종료 코드 1로 끝난 Volatility 실행의 결과 본문에는 `Volatility 3 Framework 2.28.1` 줄이 있었다 [6].
저장소의 예시 사건 폴더에 있는 실패 기록에는 같은 자리에 `Volatility 3 Framework 2.28.0` 줄이 있다 [8].
이 기록에는 명령을 실행한 컨테이너의 ID만 있고 그 컨테이너를 만든 이미지의 태그는 없다 [8].
이 줄은 도구가 쓴 출력이 결과 본문에 남은 것이고 서버는 이 줄을 읽어 필드로 옮기지 않는다 [3].
이미지의 `Dockerfile`은 volatility3 저장소를 버전을 정하지 않고 받아 설치하고 서버는 이미지 안 Volatility의 버전을 조회하지 않는다 [9][3].

심볼의 식별값은 심볼을 받은 호출의 명령 기록에만 있다.
`download_windows_symbol`은 PDB 이름, GUID, age를 내려받기 기록의 `command`에 적고 변환 명령 `pdbconv`의 인자에도 GUID를 넣는다 [10].
`download_linux_symbol`은 받은 심볼의 경로를 명령 기록의 `command`에, 파일 이름과 URL을 `result`에 적는다 [11].
이 URL은 심볼 저장소의 `master` 브랜치를 가리키고 명령 기록에는 그 저장소의 커밋이 남지 않는다 [11].
그 심볼로 실행한 Volatility 호출의 명령 기록에는 `vol -s /symbols`로 시작하는 명령 글만 남고 서버는 어느 심볼 파일이 쓰였는지를 싣지 않는다 [4].
예시 사건 폴더의 `windows.info` 결과처럼 플러그인이 심볼 파일 위치를 출력하면 그 값이 결과 본문에 남는다 [12].

서버에는 분석 도구나 실행 환경의 버전을 돌려주는 도구가 없다 [13].
`list_files`는 파일 이름, 컨테이너 경로, 크기만 돌려준다 [14].
Windows 심볼 파일의 이름은 `<GUID>-<age>.json.xz`여서 `symbols` 목록에는 이 값이 파일 이름으로 보인다 [14].
`run_sleuthkit_command`로 `fiwalk -V`를 실행하자 `SleuthKit Version: 4.12.1` 줄이 결과 본문으로 남았다 [6].
이 인자는 모델이 정한 것이고 `run_sleuthkit_command`는 받은 인자를 그대로 실행할 뿐 버전을 조회하는 명령을 따로 두지 않는다 [15].

서버 자신의 버전도 응답과 명령 기록에 싣지 않는다.
서버 버전 상수 `VERSION`은 `0.1.2`이고 명령 행 `--version`의 출력과 컨테이너 이미지의 태그에 쓰인다 [16][17].
컨테이너를 만든 이미지의 이름과 태그는 응답과 명령 기록에 실리지 않는다 [1][3].
서버는 `FastMCP`에 이름과 지침만 준다 [18].
MCP Python SDK 1.27.0은 버전을 받지 못하면 초기화 응답의 `serverInfo.version`에 `mcp` 패키지의 버전을 넣는다 [19].
초기화 응답의 `serverInfo.version`은 `1.27.0`이었고 `--version`은 `mcp-dfir v0.1.2`를 출력했다 [6].
서버는 모델을 부르지 않는다.

```python
    def exec_stream(self, ctx: Context, command_list: list[str]) -> CommandRecordSummary:
        if self.container is None:
            raise RuntimeError("No docker container is currently running")

        ctx.report_progress(f"Running command {' '.join(command_list)}")
        output = []
        exit_code = 0
        try:
            for stream, data in self.docker.execute(self.container, command_list, stream=True):
                if stream == "stdout":
                    output.append(data.decode())
        except DockerException as ex:
            exit_code = ex.return_code if ex.return_code is not None else 1
            output.append(str(ex))
        result = "".join(output)
        return command_history_manager.add_command(
            CommandRecord(
                command=" ".join(command_list),
                result=result,
                exit_code=exit_code,
            )
        )
```
