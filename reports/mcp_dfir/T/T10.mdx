# T10 도구 명세 구성

### T10.01 처리 함수에서 명세 생성

**구현.** 이 방식은 서버가 등록하는 도구 18개 모두에 적용된다 [1].
서버는 도구 함수마다 `mcp.add_tool(<함수>)`만 부르고 이름, 설명, 입력 schema를 따로 주지 않는다 [1].
MCP Python SDK 1.27.0의 FastMCP는 함수 이름을 도구 이름으로, docstring을 설명으로 쓰고 함수 서명에서 입력 schema를 만들며 `Context` 자료형의 인자는 schema에서 뺀다 [2].
docstring이 없는 함수의 설명은 빈 문자열이 된다 [2].
도구 목록은 18개였고 그 가운데 `list_files`, `get_hash`, `get_command_history`와 분석 메모 도구 4개는 설명이 비어 있었다 [3].
인자 설명을 적은 도구는 `get_command_result` 하나이고 그 설명은 docstring의 `Args` 부분에 글로만 있다 [4].
입력 schema는 인자마다 `title`과 자료형을 싣고 인자의 뜻을 적은 글은 싣지 않았다 [3].
서버 코드가 `Literal`로 적은 인자는 schema에 `enum`으로 실렸다 [3].
분석 메모를 받는 두 도구의 `note`는 `AnalystNote`의 필드 넷을 필드마다 `examples`와 함께 실었다 [5][3].
`list_files`의 `path`는 3개, `get_hash`의 `algorithm`은 4개, `untar_file`의 `compression`은 7개, `run_sleuthkit_command`의 `tool`은 30개 값이다 [3].
`get_command_result`의 `head`, `head_bytes`, `tail`, `tail_bytes`, `regex`는 서명에 기본값이 없어 schema의 `required`에 들어 있고 값으로 `null`을 받는다 [4][3].
`byte_limit`은 서명에 자료형 없이 기본값 `COMMAND_MAX_OUTPUT_BYTES`만 있다 [4].
SDK는 자료형이 없는 인자의 schema를 `string`으로 적으므로 `byte_limit`의 schema는 `type`이 `string`이고 `default`가 25600이다 [6][3].
SDK는 반환 자료형에서 출력 schema도 만든다 [2].
실행 도구의 출력 schema는 `CommandRecordSummary`의 필드 넷이고 `get_command_result`는 문자열 `result` 하나이며 분석 메모를 쓰는 두 도구는 `null`인 `result` 하나였다 [3].
annotation을 가진 도구는 없었고 초기화 응답의 `tools.listChanged`는 거짓이었다 [3].
서버는 `FastMCP`를 만들 때 서버 지침 `instructions`를 주고 이 글은 초기화 응답으로 전달된다 [7][3].
지침은 분석 전에 할 일 3가지와 분석 중에 지킬 규칙 4가지를 적는다 [7].
서버 코드는 MCP 리소스와 프롬프트를 등록하지 않는다 [1][7].
서버의 실행 인자는 사건 폴더와 초기화·정리 동작만 정하고 도구 목록, 설명, schema를 바꾸는 인자나 환경변수는 없다 [8].

**한계.** 다음 도구는 설명이나 schema가 알리는 것과 처리 함수의 동작이 다르다.
`get_command_result`의 설명은 `tail`을 끝에서부터 돌려줄 줄 수라고 적지만 코드는 결과를 `[tail:]`로 잘라 앞에서 `tail`줄을 뺀 나머지를 돌려준다 [4][9].
60줄인 결과에 `tail` 3을 주자 끝의 3줄이 아니라 넷째 줄부터 끝까지 57줄이 왔다 [3].
같은 설명은 `head_bytes`, `tail_bytes`, `byte_limit`을 바이트 수라고 적지만 코드는 문자열의 글자 수로 자르고 센다 [4][9].
`byte_limit`의 schema는 `string`이지만 코드는 결과 길이와 이 값을 `>=`로 비교하므로 문자열 값을 주면 비교에서 예외가 난다 [9].
`byte_limit`에 문자열 `"10"`을 주자 `'>=' not supported between instances of 'int' and 'str'` 오류가 왔고 정수와 `null`은 받아들여졌다 [3].
결과 길이가 `byte_limit`과 같을 때도 `Output exceeds maximum size` 오류가 왔다 [3].
상한 상수 `COMMAND_MAX_OUTPUT_BYTES`의 주석은 `2 KB`이고 값은 25,600이다 [10].
설명은 `regex`를 `An optional regex search`라고 적지만 schema에서 `regex`는 필수 인자다 [4][3].

`unzip_file`의 설명은 `unzip -X -K <SOURCE_FILE> -d /artifacts/<DESTINATION_FILE_NAME>`을 실행한다고 적는다 [11].
코드는 `destination_dir`이 `/artifacts/`로 시작하는지 확인한 뒤 그 값을 그대로 `-d`에 넘긴다 [11].
코드는 `source_file`이 있는지를 컨테이너가 아니라 서버 프로세스가 실행되는 호스트에서 `Path(source_file).is_file()`로 확인한다 [11].
`list_files`가 돌려준 컨테이너 경로 `/evidence/sample.zip`을 주자 `Source file not found` 오류가 왔다 [3].
호스트에 있는 경로를 주자 이 확인은 통과했지만 이미지 안에 `unzip`이 없어 종료 코드 127이 기록되었다 [3].
`untar_file`도 같은 확인을 호스트에서 한다 [12].
`untar_file`의 설명은 `tar -xf <SOURCE_FILE> -C /artifacts/<DESTINATION_FILE_NAME>`을 실행한다고 적지만 `compression`을 주면 코드는 `-f` 없이 `tar -x <압축 옵션> <source_file> -C <destination_dir>`을 실행한다 [12].
호스트 쪽 확인이 통과하게 바꾼 상태에서 `compression`을 `gz`로 주고 함수를 부르자 `gzip: stdin: unexpected end of file`과 종료 코드 2가 기록되었다 [3].

`search_linux_symbols`의 설명은 정규식에 맞는 심볼을 찾는다고 적는다 [13].
코드는 맞는 항목을 pydantic 모델 `SymbolSearchResult`의 list로 모아 `json.dumps`에 넘기고 `json.dumps`는 이 객체를 JSON으로 바꾸지 못한다 [13].
심볼 맵에 있는 커널 버전에 맞는 정규식을 주자 `Object of type SymbolSearchResult is not JSON serializable` 오류가 왔다 [3].
맞는 항목이 없는 정규식을 주면 결과 본문이 `[]`인 명령 기록이 남았다 [3].
그래서 이 도구는 맞는 심볼이 있을 때 그 경로를 돌려주지 못했다 [3].

`update_analyst_note`의 입력 schema는 바꿀 분석 메모의 `title`과 새 내용 `note`를 받는다 [3].
`AnalystNoteManager.update_note`는 반복 변수 `note`가 인자 `note`를 가려 목록에 있는 `AnalystNoteSummary`에 `summary`를 부른다 [14].
있는 제목을 주자 `'AnalystNoteSummary' object has no attribute 'summary'` 오류가 왔고 그 분석 메모의 내용은 바뀌지 않았다 [3].

`run_find`의 설명은 `Runs: find <arguments>`이고 인자를 이어 붙인 글에 `-exec`가 있으면 거부한다는 조건은 설명에 없다 [15].
서버 지침의 셋째 규칙은 명령 결과를 볼 때 `head/tail/regex/truncate` 옵션만 쓰라고 적지만 `get_command_result`에 `truncate`라는 인자는 없다 [7][4].

### T10.03 묶음 도구의 연산별 인자를 schema가 구분하지 않음

**구현.** 이 방식은 `run_sleuthkit_command`와 `run_volatility_command`에 적용된다 [16][17].
`run_sleuthkit_command`는 `tool`로 The Sleuth Kit 프로그램 30개 가운데 하나를 고르고 `arguments`의 문자열을 그 프로그램의 인자로 그대로 넘긴다 [16].
입력 schema는 `tool`을 30개 값의 `enum`으로, `arguments`를 문자열 배열로 알린다 [3].
프로그램마다 다른 옵션과 위치 인자는 schema에 없다 [3].
도구 설명은 프로그램마다 하는 일을 한 줄씩 적고 인자는 적지 않는다 [16].
`run_volatility_command`는 `vol -s /symbols -r jsonl` 뒤에 `arguments`를 붙여 실행하고 실행할 플러그인의 이름과 그 플러그인의 옵션은 모두 `arguments` 안에 들어간다 [17].
입력 schema는 `arguments`를 문자열 배열로만 알리고 도구 설명은 `-f`로 파일을 정하라는 것과 심볼을 따로 받아야 할 수 있다는 것만 적는다 [17][3].
쓸 수 있는 플러그인의 이름과 플러그인별 옵션은 schema와 설명에 없다 [17][3].
서버에는 프로그램이나 플러그인의 사용법을 알리는 MCP 리소스와 프롬프트가 없다 [1].
`run_strings`, `run_grep`, `run_find`도 `arguments` 문자열 배열 하나를 받지만 도구마다 프로그램 하나만 실행한다 [15].

def get_command_result(
    command_number: int,
    head: int | None,
    head_bytes: int | None,
    tail: int | None,
    tail_bytes: int | None,
    regex: str | None,
    byte_limit=COMMAND_MAX_OUTPUT_BYTES,
) -> str:
    """Allows for parsing of the command result

    Args:
        command_number: The command number
        head: The number of lines from the start to return
        head_bytes: The number of bytes to read from the start (Applied after running head/tail)
        tail: The number of lines from the rear to return
        tail_bytes: The number of bytes to read from the end (Applied after running head/tail)
        regex: An optional regex search
        byte_limit: The maximum number of bytes in the output before throwing an error (set to None to bypass the limit)

    Returns:
        The command result
    """

    # Truncate for head/tail
    if head:
        content = "\n".join(content.split("\n")[:head])
    elif tail:
        content = "\n".join(content.split("\n")[tail:])

    # Truncate for head/tail bytes
    if head_bytes:
        content = content[:head_bytes]
    elif tail_bytes:
        content = content[-tail_bytes:]

    # Regex search
    output = []
    for line in content.split("\n"):
        if regex is None or re.search(regex, line):
            output.append(line)

    output_str = "\n".join(output)

    if byte_limit is not None and len(output_str) >= byte_limit:
        raise RuntimeError(f"Output exceeds maximum size, output was {len(output_str)} bytes")

    return output_str

def unzip_file(ctx: Context, source_file: str, destination_dir: str) -> CommandRecordSummary:
