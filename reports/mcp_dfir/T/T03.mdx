# T03 실행 조건 확인

### 미구현

**판단.** 서버에는 앞선 작업 상태, 승인, 호출자 신원, 실행 자원으로 호출을 막거나 미루는 코드가 없다.
실행 도구는 인자 검사를 마치면 바로 `exec_stream`으로 컨테이너에서 명령을 실행한다 [1].
`exec_stream`은 컨테이너 객체가 없을 때만 `RuntimeError`로 거부한다 [2].
서버는 MCP 연결을 받기 전에 컨테이너를 시작하므로 이 조건은 앞선 도구 호출이 만드는 상태가 아니다 [3].

서버 지침은 분석 전에 증거 목록을 만들고 이미 실행한 명령과 분석 메모를 검토하라고 적는다 [4].
같은 지침은 증거가 바뀌었거나 잘못 실행한 경우가 아니면 명령을 다시 실행하지 말라고 적는다 [4].
README는 명령 기록 기능을 `the agent never re-runs commands already completed`로 설명한다 [5].
서버 코드는 새 명령을 명령 기록에 있는 명령과 대조하지 않고 목록 길이에 1을 더한 번호를 매겨 저장한다 [6].
같은 인자로 `get_hash`를 두 번 부르자 두 번 모두 실행되어 번호 36과 37이 붙었다 [7].
새 사건 폴더에서 증거 목록이나 명령 기록을 조회하지 않고 처음부터 `get_hash`를 불러도 명령이 실행되었다 [7].

`download_windows_symbol`은 같은 심볼 파일이 이미 있으면 `overwrite`가 참일 때만 다시 받는다 [8].
이 조건은 이미 있는 파일을 덮어쓸지 고르는 인자이고 호출마다 받는 승인이 아니다 [8].
승인 토큰이나 승인 기록을 요청과 대조하는 코드는 없다.
서버는 `auth=None`으로 FastMCP를 만들고 stdio로만 실행되어 원격 MCP 연결을 받지 않는다 [9].
메모리, CPU, 디스크 여유 공간을 확인하는 코드는 없다.
심볼을 내려받는 세 도구는 요청 사이에 간격을 두지 않고 `requests.get`을 부른다 [10].

동시 실행 수를 정하는 장치도 없다.
도구 함수는 모두 동기 함수이고 MCP Python SDK 1.27.0의 FastMCP는 동기 함수를 이벤트 루프에서 바로 부른다 [1][11].
`exec_stream`은 `docker exec`의 출력을 끝까지 읽은 뒤에 돌아오므로 한 명령이 끝날 때까지 다른 요청은 처리되지 않는다 [2][11].
혼자 부르면 0.96초 뒤에 응답하는 `run_volatility_command` 호출 3개를 동시에 보내자 마지막 응답이 2.82초 뒤에 왔다 [12].
그 호출을 보내고 0.2초 뒤에 보낸 `get_command_history`는 앞 호출이 끝난 1.01초 뒤에 응답했다 [12].
이는 서버가 정한 제한이 아니라 SDK가 동기 함수를 부르는 방식에서 생기는 동작이다.

```python
    def exec_stream(self, ctx: Context, command_list: list[str]) -> CommandRecordSummary:
        if self.container is None:
            raise RuntimeError("No docker container is currently running")

        ctx.report_progress(f"Running command {' '.join(command_list)}")
        output = []
        exit_code = 0
        try:
            for stream, data in self.docker.execute(self.container, command_list, stream=True):
                if stream == "stdout":
                    output.append(data.decode())
        except DockerException as ex:
            exit_code = ex.return_code if ex.return_code is not None else 1
            output.append(str(ex))
        result = "".join(output)
        return command_history_manager.add_command(
            CommandRecord(
                command=" ".join(command_list),
                result=result,
                exit_code=exit_code,
            )
        )
```
