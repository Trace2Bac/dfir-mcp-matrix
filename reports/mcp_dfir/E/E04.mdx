# E04 분석 입력 준비

### E04.01 작업 사본 생성

**구현.** 이 방식은 `unzip_file`, `untar_file`, 그리고 `run_sleuthkit_command`로 실행하는 `tsk_recover`에 적용된다 [1][2][3].
`unzip_file`은 컨테이너에서 `unzip -X -K <source_file> -d <destination_dir>`을 실행해 zip 보관 파일의 내용 전체를 목적지에 풀도록 명령을 만든다 [1].
`untar_file`은 `compression`이 없으면 `tar -xf <source_file> -C <destination_dir>`을 실행한다 [2].
`compression`이 있으면 `gz`, `bz2`, `xz`, `lzip`, `lzma`, `lzop`, `zstd`에 맞는 `tar` 옵션을 넣어 실행한다 [2][4].
`unzip_file`과 `untar_file`은 명령을 실행하기 전에 세 가지를 확인한다 [1][2].
두 경로 가운데 하나에 `..`이 있으면 거부한다 [1][2].
`Path(source_file).is_file()`이 거짓이면 `Source file not found`로 거부한다 [1][2].
`destination_dir`이 `/artifacts/`로 시작하지 않으면 거부한다 [1][2].
`tar`를 `-v` 없이 실행하므로 결과 본문 파일에도 푼 파일의 이름이 남지 않는다 [2].
README는 `unzip`과 `tar`로 보관 파일을 푸는 기능이 있다고 적는다 [5].

디스크 이미지 안의 파일은 `run_sleuthkit_command`로 `tsk_recover`를 실행해 꺼낸다 [3].
`run_sleuthkit_command`가 허용하는 명령 30개에 `tsk_recover`가 들어 있고 도구 설명은 이 명령이 이미지의 파일을 폴더로 내보낸다고 적는다 [3][6].
서버는 `tsk_recover` 뒤에 받은 인자를 그대로 붙여 실행하므로 꺼낼 범위와 출력 폴더는 모델이 정한다 [3].
The Sleuth Kit 4.12.1의 `tsk_recover`는 옵션이 없으면 비할당 파일만, `-a`를 주면 할당 파일만, `-e`를 주면 둘 다 꺼낸다 [7].
`tsk_recover`는 폴더 항목과 크기가 0인 파일을 건너뛴다 [8].
`tsk_recover`와 `-e /evidence/disk.dd /artifacts/rec` 인자를 주자 파일 3개가 사건 폴더의 `artifacts/rec` 아래에 생겼고 `list_files`가 그 파일을 돌려주었다 [9].
옵션 없이 부른 호출의 결과는 `Files Recovered: 0`이었다 [9].
꺼낸 파일의 경로를 `run_strings`와 `get_hash`에 주자 두 명령이 종료 코드 0으로 끝났다 [9].
결과는 파일 단위로 꺼낸 사본이고 이미지 전체의 바이트 사본이 아니다 [8].

컨테이너의 `/artifacts`는 사건 폴더의 `artifacts`에 연결되어 있고 `list_files`는 이 폴더의 파일도 돌려준다 [10][11].
서버는 풀거나 꺼낸 파일을 같은 호출에서 다른 분석에 넘기지 않는다 [1][2][3].
세 경로의 응답은 명령 번호, 명령 문자열, 실행 시각, 종료 코드이고 풀거나 꺼낸 파일의 목록이나 수를 싣지 않는다 [12].
서버는 꺼낸 파일의 목록을 따로 만들지 않고 `tsk_recover`의 결과 본문 파일에는 `Files Recovered: 3` 한 줄만 남는다 [3][9].

`icat`처럼 내용을 표준 출력으로 내는 명령의 출력은 `exec_stream`이 문자열로 바꿔 결과 본문 파일에 저장한다 [13].
출력이 UTF-8로 읽히지 않으면 그 호출은 오류로 끝나고 결과가 저장되지 않는다 [13][14].
파티션 시작 위치는 서버가 정하지 않고 모델이 Sleuth Kit 명령의 인자로 준다 [3].
메모리 이미지와 디스크 이미지는 모델이 준 경로 그대로 분석 도구에 전달된다 [3][15].
서버 코드에는 분할 이미지 조각이나 트랜잭션 로그 같은 부속 자료를 찾는 코드가 없다.

**한계.** `unzip_file`과 `untar_file`은 `source_file`이 있는지를 컨테이너가 아니라 서버 프로세스가 실행되는 호스트에서 확인한다 [1][2].
`source_file`은 컨테이너에서 실행할 명령에 넣는 경로다 [1][2].
그래서 `list_files`가 돌려준 `/evidence/` 아래 경로는 호스트의 같은 경로에 파일이 없으면 이 확인에서 거부된다 [1][2][16].
`/evidence/sample.zip`과 `/evidence/sample.tar`를 주자 두 도구 모두 `Source file not found`를 돌려주었다 [16].
서버가 만드는 연결에서 증거의 호스트 경로는 사건 폴더의 `evidence` 아래이고 컨테이너 경로는 `/evidence` 아래다 [17].
보관 파일이 풀리려면 같은 경로 문자열이 호스트와 컨테이너 양쪽에서 그 파일을 가리켜야 한다 [1][2].
서버의 작업 폴더에만 있고 컨테이너에는 없는 상대 경로를 주자 이 확인을 지나 컨테이너에서 명령이 실행되었고 `tar`는 파일을 열 수 없다는 오류로 끝났다 [16].
서버의 작업 폴더와 컨테이너의 작업 폴더 `/tools`에 같은 이름의 tar 파일을 따로 두고 그 이름을 `source_file`로 주자 `tar`가 보관 파일 안의 파일 2개를 사건 폴더의 `artifacts`에 풀었다 [18].
`Dockerfile`은 `binutils`, `sleuthkit`, `git`만 설치하고 `unzip`은 설치하지 않는다 [19].
호스트 확인을 지난 `unzip_file` 호출은 컨테이너에 `unzip` 실행 파일이 없어 종료 코드 127로 끝났다 [16].
`compression`이 있는 `untar_file`은 `tar`에 `-f`를 넘기지 않으므로 `tar`가 보관 파일을 `source_file`이 아니라 표준 입력에서 읽는다 [2].
이 경로로 실행된 `tar`는 `gzip: stdin: unexpected end of file` 오류로 끝났다 [16].
`compression` 값 7개에 맞는 압축 프로그램 가운데 이미지에 있는 것은 `gzip` 하나이고 `bzip2`, `xz`, `lzip`, `lzma`, `lzop`, `zstd`는 없다 [20].
`tar`는 `-C`로 받은 폴더가 없으면 실패하고 서버는 목적지 폴더를 만들지 않는다 [2][20].
`tsk_recover`는 파일을 쓰지 못해도 다음 파일로 계속하고 종료 코드 0으로 끝난다 [8][21].
읽기 전용인 `/evidence` 아래를 출력 폴더로 주자 응답의 `exit_code`는 0이었고 결과에는 `Files Recovered: 0`만 남았다 [21].

```python
def unzip_file(ctx: Context, source_file: str, destination_dir: str) -> CommandRecordSummary:
    """Runs: unzip -X -K <SOURCE_FILE> -d /artifacts/<DESTINATION_FILE_NAME>"""
    if source_file.find("..") != -1 or destination_dir.find("..") != -1:
```

```python
def untar_file(
    ctx: Context,
    source_file: str,
    destination_dir: str,
    compression: None | Literal["gz", "bz2", "xz", "lzip", "lzma", "lzop", "zstd"] = None,
) -> CommandRecordSummary:
    """Runs: tar -xf <SOURCE_FILE> -C /artifacts/<DESTINATION_FILE_NAME>"""
    if source_file.find("..") != -1 or destination_dir.find("..") != -1:
        raise RuntimeError("Invalid file path, Path traversal is not allowed")
    if not Path(source_file).is_file():
        raise FileNotFoundError("Source file not found")
    if not destination_dir.startswith("/artifacts/"):
        raise RuntimeError("Destination directory must be in /artifacts")
    if compression is None:
        return docker_manager.exec_stream(ctx=ctx, command_list=["tar", "-xf", source_file, "-C", destination_dir])
    if compression in TAR_COMPRESSION_FLAGS:
        return docker_manager.exec_stream(
            ctx=ctx, command_list=["tar", "-x", TAR_COMPRESSION_FLAGS[compression], source_file, "-C", destination_dir]
        )
    else:
        raise ValueError(f"Unsupported compression type, {compression} is not supported")
```

`which`로 찾으면 `tar`와 `gzip`만 있고 `unzip`, `bzip2`, `xz`, `lzip`, `lzma`, `lzop`, `zstd`는 없다.
`tar -xf /evidence/sample.tar -C /artifacts/newdir`은 `Cannot open: No such file or directory`로 끝난다.
`tar -x --gzip /evidence/sample.tar.gz -C /artifacts/`는 표준 입력이 비어 `gzip: stdin: unexpected end of file`로 끝난다.

[21] (실행 확인) `run_sleuthkit_command`에 `tsk_recover`와 `["-e", "/evidence/disk.dd", "/evidence/rec"]`를 주면 `exit_code`가 0이고 결과가 `Files Recovered: 0`이며 호스트의 `evidence` 폴더에는 새 파일이 없다.
