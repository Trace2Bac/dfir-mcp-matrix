# E01 증거 등록 관리

### 미구현

**판단.** 서버는 사용자가 사건 폴더의 `evidence` 폴더에 둔 파일을 증거로 받지만 증거를 식별하는 목록이나 등록 정보를 따로 남기지 않는다 [1][2].
README는 서버를 시작하기 전에 증거 파일을 `evidence/`에 두라고 적는다 [3].
증거를 등록하는 MCP 도구는 없다 [4].
`list_files`는 부를 때마다 호스트의 `evidence` 폴더를 하위 폴더까지 훑어 파일마다 이름, 컨테이너 안 경로, 크기를 응답으로 돌려준다 [2].
이 목록은 호출마다 새로 만들고 저장하지 않는다 [2].
항목에는 식별자, 등록 시각, 해시, 증거를 확보한 곳이 없다 [5].
`list_files` 호출은 명령 기록에 남지 않는다 [6].
분석 도구는 받은 경로가 `evidence` 폴더의 파일인지 확인하지 않고 컨테이너 안의 어느 경로든 받는다 [7].
명령 기록에는 증거 경로가 명령 문자열의 일부로 남는다 [8].

서버 지침은 분석을 시작하기 전에 증거 목록을 만들고 증거를 언제, 어디서, 어떻게 확보했는지 사용자에게 물으라고 적는다 [9].
모델이 만든 증거 목록이나 사용자가 답한 확보 경위를 받아 두는 전용 도구나 필드는 서버에 없다 [4][10].
저장소의 예시 사건에서 모델은 증거 파일의 경로, 크기, SHA-256, 확보 경위를 분석 메모 하나에 적었다 [11].
이 메모는 모델이 `add_analyst_note`로 쓴 글이고 서버는 메모 본문을 읽어 증거 목록으로 쓰지 않는다 [10].

`list_files`는 호스트의 사건 폴더를 읽고 분석 도구는 컨테이너에 연결된 폴더를 읽는다 [2][12].
서버가 다른 사건 폴더에 연결된 같은 이름의 컨테이너를 다시 쓴 실행에서는 `list_files`가 돌려준 파일이 컨테이너 안 `/evidence`에 없었다 [13].

```python
def list_files(path: Literal["artifacts", "symbols", "evidence"]) -> list[FileDetails]:
    valid_paths = [volume.name for volume in config.docker_volumes]

    # Select volume
    selected_volume = None
    for volume in config.docker_volumes:
        if volume.name == path:
            selected_volume = volume
            break
    if selected_volume is None:
        raise RuntimeError(f"Invalid path {path}, valid paths are {valid_paths}")

    out_list = []
    for dir_path, _, file_name_list in selected_volume.external_path.walk():
        for file_name in file_name_list:
            external_file_path = Path(dir_path / file_name)
            internal_file_path = (
                f"/{path}/{str(external_file_path.relative_to(selected_volume.external_path)).replace('\\', '/')}"
            )
            out_list.append(
                FileDetails(
                    name=file_name,
                    path=internal_file_path,
                    size=external_file_path.stat().st_size,
                )
            )
    return out_list
```
