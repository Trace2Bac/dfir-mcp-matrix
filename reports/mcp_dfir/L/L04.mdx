# L04 기록 위변조 방지

### L04.02 일련번호

**구현.** 이 방식은 `command_history.json`의 모든 항목에 적용된다 [1].
`add_command`는 메모리 목록의 길이에 1을 더한 값을 항목의 `number`로 매긴다 [1].
서버 프로세스 하나가 빈 명령 기록에서 쓰기 시작하면 번호는 1부터 빠짐없이 이어진다 [1].
`command_history.json`에서 2번 항목을 지우고 서버를 다시 시작하자 `get_command_history`가 1번 다음에 3번이 오는 목록을 돌려줬다 [2].
번호가 이어지는지 확인하는 코드는 서버에 없다 [3].
`load`는 항목마다 필드의 자료형만 확인하고 번호의 차례나 중복은 확인하지 않는다 [3][4].
항목에는 앞 항목의 해시나 서명이 없고 항목 수를 명령 기록 밖에 남기는 곳도 없다 [4].
서버는 명령 기록 목록에 항목을 덧붙이지 않고 `"w"` 모드로 파일 전체를 다시 쓴다 [1].
명령 기록을 다시 읽어 대조하는 도구나 사용자 CLI 인자도 없다 [5].
손으로 고친 `command`와 `exit_code`, 바꿔 쓴 결과 본문 파일은 서버를 다시 시작한 뒤 고친 그대로 읽혔다 [2].
`date_run`을 지운 항목은 서버가 파일을 읽은 시각으로 채워졌고 다음 쓰기에서 그 값이 파일에 남았다 [2][4].

**한계.** 번호를 마지막 번호가 아니라 목록 길이로 정하므로 중간 항목이 지워진 명령 기록 목록에 서버가 이어 쓰면 번호가 겹친다 [1].
2번 항목을 지운 명령 기록 목록에 명령 하나를 더 실행하자 9번 항목이 둘이 되고 `9.txt`가 새 출력으로 바뀌었다 [2].
같은 사건 폴더로 서버 프로세스 둘을 실행하자 두 프로세스가 같은 번호를 썼다 [6].
끝 항목을 지운 명령 기록 목록과 번호를 다시 매긴 명령 기록 목록은 번호만으로는 원래 것과 가를 수 없다.

### L04.04 실행 환경의 기록 쓰기 차단

**구현.** 이 방식은 모델이 도구로 컨테이너에서 실행하는 명령에 적용된다 [7].
서버는 컨테이너를 만들 때 사건 폴더의 `analysis`를 컨테이너의 `/analysis`에 `ro`로 연결한다 [7][8].
명령 기록 목록과 결과 본문 파일은 모두 이 폴더 아래에 있다 [9].
실행기 `exec_stream`을 거치는 도구 8개의 명령은 모두 이 컨테이너 안에서 실행된다 [10].
`run_find`로 `/analysis`의 `command_history.json`에 `-delete`를 실행하자 `Read-only file system` 오류로 끝났고 파일은 그대로였다 [11].
`tsk_recover`의 출력 폴더를 `/analysis/command_history/x`로 주자 복구된 파일이 0개였다 [11].
컨테이너 안에서 명령 기록 목록을 읽는 명령은 실행된다 [11].
서버 프로세스는 호스트 쪽 `analysis` 폴더에 직접 쓰고 명령 기록 목록과 결과 본문 파일의 권한이나 추가 전용 속성을 정하지 않는다 [1].
`analysis` 폴더는 `mkdir(mode=500)`으로 만들고 이 값은 8진수가 아닌 10진수 500이다 [12].
그래서 호스트에서 서버와 같은 계정으로 실행되는 프로그램은 명령 기록 목록과 결과 본문 파일을 그대로 고칠 수 있다.

**한계.** 서버는 같은 이름의 컨테이너가 이미 있으면 연결 설정을 확인하지 않고 그 컨테이너를 쓴다 [13].
폴더를 연결하지 않고 미리 만들어 둔 같은 이름의 컨테이너가 있을 때 서버는 그 컨테이너에서 명령을 실행했다 [14].

컨테이너 밖 서버 프로세스에서 파일을 쓰는 도구에는 이 읽기 전용 연결이 적용되지 않는다.
`download_linux_symbol`은 `symbol_path`의 마지막 `/` 뒤 조각을 파일 이름으로 삼아 서버 프로세스에서 `symbols/linux` 아래에 쓴다 [15].
Windows 호스트에서 `symbol_path`를 `README.md?x=/..\..\analysis\command_history\1.txt`로 주자 내려받은 내용이 1번 항목의 결과 본문 파일을 덮어썼다 [16].
같은 방법으로 `command_history.json`을 가리키자 그 호출이 끝난 뒤 파일에는 `add_command`가 메모리 목록으로 다시 쓴 항목들이 남아 있었다 [15][16].

### 근거

[1] `add_command`는 목록 길이에 1을 더해 번호를 매기고 `dump`는 파일 전체를 `"w"` 모드로 다시 쓴다.

```python
    def dump(self, command: CommandRecord | None, command_number: int | None = None):
        # Write to command history
        with open(file=config.command_history_json, mode="w", encoding="utf-8") as command_summary_file:
            json.dump(
                [record.model_dump() for record in self.command_summary_list],
                command_summary_file,
                indent=4,
            )

        # Write to command file
        if command is not None and command_number is not None:
            with open(
                file=config.command_record_directory / f"{command_number}.txt", mode="w", encoding="utf-8"
            ) as command_file:
                command_file.write(command.result)

    def load(self):
        with open(file=config.command_history_json, encoding="utf-8") as command_file:
            for command_summary_dict in json.load(command_file):
                self.command_summary_list.append(CommandRecordSummary.model_validate(command_summary_dict))

    def add_command(self, command_record: CommandRecord) -> CommandRecordSummary:
        number = len(self.command_summary_list) + 1
        summary = command_record.summary(number=number)
        self.command_summary_list.append(summary)
        self.dump(command_record, number)
        return summary
```

def download_linux_symbol(ctx: Context, symbol_path: str) -> CommandRecordSummary:
    """Download a symbol map from the Abyss-W4tcher/volatility3-symbols repository"""

    # Download json file from repo
    url = f"{LINUX_SYMBOL_REPO_BASE_URL}/{symbol_path}"
    ctx.report_progress(f"Downloading symbol from {url}")
    response = requests.get(url=url)
    response.raise_for_status()

    # Save json file
    config.linux_symbols_directory.mkdir(mode=500, parents=True, exist_ok=True)
    file_name = symbol_path.rsplit("/", maxsplit=1)[-1]
    file_path = config.linux_symbols_directory / file_name

        CommandRecord(
            command=f'mcp_dfir:tools:volatility:download_linux_symbol(symbol_path="{symbol_path}")',
            result=f"Successfully downloaded symbol file {file_name} ({file_path.stat().st_size} bytes) from {url}",
