# L03 기록 실패 처리

### L03.01 실행 후 응답 차단

**구현.** 이 방식은 항목을 쓰는 모든 호출에 적용된다 [1].
`exec_stream`은 컨테이너 명령을 끝까지 실행한 뒤 `add_command`를 부르고 그 반환값을 도구 결과로 돌려준다 [2].
심볼 도구도 내려받은 파일을 저장한 뒤에 `add_command`를 부른다 [3].
`add_command`가 부르는 `dump`는 `command_history.json`을 `"w"` 모드로 열어 목록 전체를 다시 쓰고 이어서 결과 본문 파일을 쓴다 [1].
`dump`와 `add_command`, 이 둘을 부르는 `exec_stream`과 도구 본문에는 쓰기 예외를 처리하는 코드가 없다 [1][2].
그래서 쓰기가 실패하면 예외가 도구 본문 밖으로 나가고 FastMCP가 그 예외를 오류 결과로 바꾼다 [4].
실행 결과인 번호와 종료 코드는 응답에 실리지 않는다 [2].
`command_history.json`을 읽기 전용으로 바꾼 뒤 `run_sleuthkit_command`로 `tsk_recover`를 실행하자 `/artifacts`에 파일 3개가 복구됐고 응답은 `Permission denied` 오류 결과였다 [5].
오류 문구에는 명령 기록 목록의 호스트 쪽 전체 경로가 들어 있었다 [5].
서버의 표준 오류에는 명령 기록 쓰기 실패를 알리는 줄이 남지 않았다 [5].

`add_command`는 파일에 쓰기 전에 항목을 메모리 목록에 먼저 더한다 [1].
그래서 쓰기가 실패한 항목도 그 서버 프로세스의 `get_command_history` 응답에는 나오고 다음 항목의 번호는 그 항목 다음으로 매겨진다 [1][5].
그 뒤의 쓰기가 성공하면 `dump`가 목록 전체를 쓰므로 앞서 실패한 항목이 결과 본문 파일 없이 `command_history.json`에 남는다 [1][6].
서버 코드에는 실패한 항목을 따로 다시 쓰거나 다른 곳에 남기는 처리가 없다 [1].
쓰기가 다시 성공하기 전에 서버를 다시 시작하자 실패한 항목은 목록에서 사라졌다 [5].
결과 본문 파일 쓰기만 실패한 호출은 항목이 `command_history.json`에 남고 응답은 오류 결과로 끝났다 [6].

`dump`는 임시 파일을 거치지 않고 `command_history.json`을 비운 뒤 쓴다 [1].
쓰는 도중에 프로세스가 끝나면 파일은 비거나 중간까지만 남는다 [1].
`CommandHistoryManager`는 서버를 시작할 때 이 파일을 `json.load`로 읽고 예외를 처리하지 않는다 [7].
파일을 절반만 남기거나 비운 뒤 서버를 실행하자 서버 프로세스가 MCP 연결을 받기 전에 예외로 끝났다 [8].
쓰는 도중에 프로세스가 끝난 상태는 재현하지 않고 파일을 직접 잘라 확인했다.

### 근거

[1] `add_command`는 항목을 목록에 더한 뒤 `dump`를 부르고 `dump`는 예외 처리 없이 두 파일을 `"w"` 모드로 쓴다.

```python
    def dump(self, command: CommandRecord | None, command_number: int | None = None):
        # Write to command history
        with open(file=config.command_history_json, mode="w", encoding="utf-8") as command_summary_file:
            json.dump(
                [record.model_dump() for record in self.command_summary_list],
                command_summary_file,
                indent=4,
            )

        # Write to command file
        if command is not None and command_number is not None:
            with open(
                file=config.command_record_directory / f"{command_number}.txt", mode="w", encoding="utf-8"
            ) as command_file:
                command_file.write(command.result)

    def load(self):
        with open(file=config.command_history_json, encoding="utf-8") as command_file:
            for command_summary_dict in json.load(command_file):
                self.command_summary_list.append(CommandRecordSummary.model_validate(command_summary_dict))

    def add_command(self, command_record: CommandRecord) -> CommandRecordSummary:
        number = len(self.command_summary_list) + 1
        summary = command_record.summary(number=number)
        self.command_summary_list.append(summary)
        self.dump(command_record, number)
        return summary
```

```python
    def exec_stream(self, ctx: Context, command_list: list[str]) -> CommandRecordSummary:
        if self.container is None:
            raise RuntimeError("No docker container is currently running")

        ctx.report_progress(f"Running command {' '.join(command_list)}")
        output = []
        exit_code = 0
        try:
            for stream, data in self.docker.execute(self.container, command_list, stream=True):
                if stream == "stdout":
                    output.append(data.decode())
        except DockerException as ex:
            exit_code = ex.return_code if ex.return_code is not None else 1
            output.append(str(ex))
        result = "".join(output)
        return command_history_manager.add_command(
            CommandRecord(
                command=" ".join(command_list),
                result=result,
                exit_code=exit_code,
            )
        )
```
