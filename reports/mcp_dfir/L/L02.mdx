# L02 기록 구성

### L02.01 MCP 요청 기록

**구현.** 이 방식은 `search_linux_symbols`와 `download_linux_symbol`이 남기는 항목에 적용된다 [1].
두 도구는 항목의 `command`에 모듈 경로, 함수 이름, 받은 인자를 `mcp_dfir:tools:volatility:download_linux_symbol(symbol_path="…")` 꼴의 문자열로 적는다 [1].
함수 이름은 FastMCP가 등록한 MCP 도구 이름과 같다 [2].
인자 값은 도구 본문이 받은 값 그대로이고 서버가 바꾼 값이 아니다 [1].
이 값은 MCP SDK가 해석해 도구 본문에 넘긴 값이고 전송된 요청 원문 전체는 아니다.
두 도구는 외부 명령을 실행하지 않으므로 이 항목의 `command`에는 실행 명령이 섞이지 않는다 [1].
컨테이너에서 명령을 실행하는 도구의 항목에는 MCP 도구 이름과 받은 인자를 담는 필드가 없다 [3].
호출자를 가르는 필드와 호출 ID도 항목에 없다 [3].

**한계.** 인자 값을 따옴표 처리 없이 문자열에 끼워 넣으므로 값에 큰따옴표나 괄호가 있으면 `command`만으로 인자의 경계를 가를 수 없다 [1].
`search_linux_symbols`에 `zzzqq", extra="1`을 주자 `command`가 `mcp_dfir:tools:volatility:search_linux_symbols(regex="zzzqq", extra="1")`로 남았다 [4].

### L02.02 서버가 변환한 연산·인자 기록

**구현.** 이 방식은 `download_windows_symbol`이 PDB를 내려받은 뒤 남기는 항목에 적용된다 [5].
이 항목의 `command`에는 MCP 도구 이름 대신 내부 함수 이름 `_download_windows_pdb`와 그 함수가 쓴 인자가 들어간다 [5].
`guid`는 붙임표를 뺀 뒤의 값으로 남는다 [5].
`guid`를 `42332028-2DB8-42E7-BA2B-0BFC86A84D75`로 주자 항목에는 `guid="423320282DB842E7BA2B0BFC86A84D75"`가 남았다 [6].
모델이 준 `overwrite` 값은 항목에 없다 [5][7].
같은 호출이 이어서 남기는 `pdbconv` 항목에는 붙임표를 빼지 않은 `guid`가 명령 인자로 남는다 [6][7].
두 항목을 한 호출로 묶는 ID는 없다 [3].
두 항목의 번호는 이어지고 `date_run`은 내려받기가 끝난 때와 변환이 끝난 때로 서로 다르다 [6].
저장소의 예시 사건 폴더에도 한 호출이 남긴 두 항목이 3번과 4번으로 있다 [8].

### L02.03 외부 실행 명령 기록

**구현.** 이 방식은 실행기 `DockerManager.exec_stream`이 쓰는 항목에 적용된다 [9].
항목의 필드는 `number`·`command`·`date_run`·`exit_code` 넷이다 [3].
`exec_stream`은 컨테이너에서 실행한 인자 배열을 공백으로 이어 `command`에 넣는다 [9].
이 배열에는 서버가 붙인 실행 파일 이름과 고정 인자가 들어 있어 `run_volatility_command`의 항목은 `vol -s /symbols -r jsonl`로 시작한다 [9][10].
`get_hash`는 `<알고리즘>sum`을, `run_sleuthkit_command`는 `tool` 인자를 실행 파일 이름으로 넣는다 [10].
서버 프로세스가 실제로 실행하는 것은 `docker exec <컨테이너>` 뒤에 이 배열을 붙인 Docker CLI 명령이다 [11].
`docker exec`와 컨테이너 ID는 `command`에 남지 않는다 [9].
명령이 실패한 항목의 결과 본문 파일에는 `DockerException` 문구가 붙어 Docker CLI 명령 줄 전체와 표준 오류가 남는다 [9][12][13].
심볼 도구가 남기는 항목의 `command`는 외부 명령이 아니라 함수 호출 꼴의 문자열이다 [1][5].

**한계.** 인자 배열을 공백으로 이으므로 공백이 들어 있는 인자 하나와 인자 여러 개를 항목에서 가를 수 없다 [9].
`run_grep`에 `["-c", "second line", "/evidence/notes.txt"]`를 주자 `command`가 `grep -c second line /evidence/notes.txt`로 남았다 [13].

### L02.05 결과 상태·실행 시점 기록

**구현.** 이 방식은 서버가 쓰는 모든 항목에 적용된다 [3].
항목은 종료 코드 `exit_code`와 시각 `date_run`을 담는다 [3].
`exec_stream`은 출력 스트림을 끝까지 읽으면 0을 남기고 `DockerException`이 나면 예외의 `return_code`를 남기며 그 값이 없으면 1을 남긴다 [9].
python-on-whales 0.81.0은 `docker exec` 프로세스가 0이 아닌 코드로 끝나면 그 코드를 `return_code`에 담아 `DockerException`을 낸다 [11].
없는 파일을 준 `grep`은 2, 맞는 줄이 없는 `grep`은 1, 맞는 줄이 있는 `grep`은 0이 남았다 [13].
심볼 도구의 항목은 일을 마친 뒤에만 쓰이고 `exit_code`는 코드에 적힌 0이다 [1][5].
`date_run`은 `CommandRecord`를 만들 때의 `datetime.now()`를 `%d/%m/%Y %H:%M:%S` 형식으로 적은 문자열이다 [3].
`exec_stream`은 명령이 끝난 뒤에 `CommandRecord`를 만들므로 이 시각은 실행이 끝난 때다 [9].
`date_run`에는 시간대 표시가 없고 서버 호스트의 지역 시각이 초 단위로 남는다 [3].
시작 시각과 소요 시간을 담는 필드는 없다 [3].
항목은 실행이 끝난 뒤 한 번 쓰이므로 실행 중인 호출은 명령 기록에 나타나지 않는다 [9].

**한계.** `exit_code`는 `docker exec` 프로세스의 종료 코드여서 컨테이너 안 명령의 실패와 Docker CLI 자체의 실패가 같은 필드에 남는다 [9][11].
서버 실행 중에 컨테이너를 멈춘 뒤 `get_hash`를 부르자 `md5sum`은 실행되지 않았지만 `command`가 `md5sum /evidence/notes.txt`이고 `exit_code`가 1인 항목이 남았다 [14].
그 항목의 결과 본문에는 컨테이너가 실행 중이 아니라는 Docker 오류 문구가 남았다 [14].

### L02.06 결과 참조·요약값 기록

**구현.** 이 방식은 서버가 쓰는 모든 항목에 적용된다 [15].
항목의 `number`는 보관한 결과 본문 파일 `analysis/command_history/<number>.txt`를 가리킨다 [15].
`add_command`는 메모리 목록의 길이에 1을 더해 번호를 정하고 같은 번호로 결과 본문 파일을 쓴다 [15].
`get_command_result`는 이 번호로 목록에서 항목을 찾아 같은 번호의 파일을 읽는다 [16].
실행 도구의 응답은 결과 본문 없이 이 항목만 돌려준다 [9].
컨테이너 명령의 결과 본문은 표준 출력이고 표준 오류는 명령이 실패했을 때의 예외 문구 안에만 남는다 [9][12].
심볼 도구의 결과 본문은 내려받은 파일이 아니라 저장 경로나 크기를 적은 문장과 검색 결과다 [1][5].
항목에는 결과 본문의 해시, 크기, 행 수가 없다 [3].

**한계.** 번호가 겹치면 항목과 결과 본문 파일이 서로 다른 실행의 것이 된다 [15][16].
같은 사건 폴더로 서버 프로세스 둘을 실행하자 두 프로세스가 각각 1번 항목을 썼고 `1.txt`에는 나중에 쓴 쪽의 출력이 남았다 [17].
먼저 쓴 프로세스에서 `get_command_result`로 1번을 읽자 `md5sum` 항목의 결과로 다른 프로세스가 실행한 `sha1sum`의 출력이 돌아왔다 [17].
`command_history.json`에서 중간 항목 하나를 지우고 서버를 다시 시작하자 새 항목이 마지막 항목과 같은 번호를 받아 그 번호의 결과 본문 파일을 덮어썼다 [18].
명령 기록 목록이나 결과 본문 파일 쓰기가 실패한 항목은 나중에 `command_history.json`에 남아도 그 번호의 결과 본문 파일이 없다 [15][19].

```python
def date_as_str() -> str:
    return datetime.now().strftime("%d/%m/%Y %H:%M:%S")


class CommandRecordSummary(BaseModel):
    number: int = Field(examples=[1])
    command: str = Field(examples=["vol -f capture.mem linux.pslist"])
    date_run: str = Field(default_factory=date_as_str, examples=["01/01/2024 12:00:00"])

class CommandRecord(BaseModel):
    command: str = Field(examples=["vol -f capture.mem linux.pslist"])
    date_run: str = Field(default_factory=date_as_str, examples=["01/01/2024 12:00:00"])
    result: str = Field(

        ],
    )
    exit_code: int = Field(examples=[0])

    def summary(self, number: int) -> CommandRecordSummary:
        return CommandRecordSummary(
            number=number,
            command=self.command,
            date_run=self.date_run,
            exit_code=self.exit_code,
        )
```

[9] `exec_stream`은 실행이 끝난 뒤 인자 배열을 공백으로 이은 `command`, 모은 출력, 종료 코드로 `CommandRecord`를 만든다.

```python
    def exec_stream(self, ctx: Context, command_list: list[str]) -> CommandRecordSummary:
        if self.container is None:
            raise RuntimeError("No docker container is currently running")

        ctx.report_progress(f"Running command {' '.join(command_list)}")
        output = []
        exit_code = 0
        try:
            for stream, data in self.docker.execute(self.container, command_list, stream=True):
                if stream == "stdout":
                    output.append(data.decode())
        except DockerException as ex:
            exit_code = ex.return_code if ex.return_code is not None else 1
            output.append(str(ex))
        result = "".join(output)
        return command_history_manager.add_command(
            CommandRecord(
                command=" ".join(command_list),
                result=result,
                exit_code=exit_code,
            )
        )
```

```python
        # Write to command history

            ) as command_file:

    def load(self):
        with open(file=config.command_history_json, encoding="utf-8") as command_file:
            for command_summary_dict in json.load(command_file):
                self.command_summary_list.append(CommandRecordSummary.model_validate(command_summary_dict))

    def add_command(self, command_record: CommandRecord) -> CommandRecordSummary:
        number = len(self.command_summary_list) + 1
        summary = command_record.summary(number=number)
        self.command_summary_list.append(summary)
        self.dump(command_record, number)
        return summary
```
