# L01 기록 방식

### L01.02 도구별 기록 호출

**구현.** 이 방식은 심볼 도구 `search_linux_symbols`·`download_linux_symbol`·`download_windows_symbol`에 적용된다 [1].
`search_linux_symbols`와 `download_linux_symbol`은 도구 본문 끝에서 기록 함수 `command_history_manager.add_command`를 직접 부른다 [1].
`download_windows_symbol`은 PDB를 내려받는 내부 함수 `_download_windows_pdb`가 파일을 저장한 뒤 같은 함수를 부른다 [1].
`add_command`는 항목을 메모리 목록에 더하고 사건 폴더의 명령 기록 목록 `analysis/command_history.json`을 다시 쓴 뒤 결과 본문을 결과 본문 파일 `analysis/command_history/<번호>.txt`에 쓴다 [2].
항목의 `command`에는 `mcp_dfir:tools:volatility:search_linux_symbols(regex="…")`처럼 함수 이름과 인자를 적은 문자열이 들어간다 [1].
`download_windows_symbol`은 `_download_windows_pdb`에 이어 `pdbconv`를 컨테이너에서 실행하므로 호출 한 번이 항목 둘을 남긴다 [3].
`download_windows_symbol`을 한 번 부르자 `_download_windows_pdb` 항목과 `pdbconv` 항목이 이어진 번호로 남았다 [4].
서버는 도구 18개를 `mcp.add_tool`로 등록하고 모든 호출이 지나는 단계에 기록하는 래퍼를 두지 않는다 [5].

**한계.** 세 도구는 일을 마친 뒤에만 `add_command`를 부르므로 그 앞에서 예외가 나면 항목이 남지 않는다 [1].
`search_linux_symbols`는 맞는 심볼이 하나라도 있으면 `json.dumps`가 `SymbolSearchResult` 객체를 직렬화하지 못해 `add_command`를 부르기 전에 예외로 끝난다 [6].
맞는 심볼이 있는 정규식으로 부른 호출은 오류 결과로 끝나고 항목을 남기지 않았다 [7].
맞는 심볼이 없는 정규식으로 부른 호출은 결과 본문이 `[]`인 항목을 남겼다 [7].
심볼 서버가 404로 답한 `download_windows_symbol`·`download_linux_symbol` 호출은 요청을 보낸 뒤 오류 결과로 끝나고 항목을 남기지 않았다 [7].
이미 있는 심볼 파일 때문에 거부된 `download_windows_symbol` 호출과 정규식 오류로 끝난 `search_linux_symbols` 호출도 항목을 남기지 않았다 [7].

### L01.03 공통 실행 함수에서 기록

**구현.** 이 방식은 컨테이너에서 명령을 실행하는 도구 8개와 `download_windows_symbol`의 `pdbconv` 실행에 적용된다 [8].
8개는 `run_strings`·`run_grep`·`run_find`·`unzip_file`·`untar_file`·`get_hash`·`run_volatility_command`·`run_sleuthkit_command`다 [8].
이 도구들은 실행할 인자 배열을 실행기 `DockerManager.exec_stream`에 넘긴다 [8].
`exec_stream`은 컨테이너에서 명령을 실행하고 출력 스트림이 끝나면 `add_command`로 항목을 쓴다 [9].
명령이 0이 아닌 코드로 끝나 `DockerException`이 나도 종료 코드와 예외 문구를 담은 항목을 쓴다 [9].
항목의 `command`에는 MCP 도구 이름이 아니라 컨테이너에서 실행한 명령 줄이 들어간다 [9].
없는 파일로 `get_hash`를 부르자 `exit_code`가 1인 항목이 남았다 [10].

나머지 도구 7개는 `exec_stream`을 거치지 않고 `add_command`도 부르지 않는다 [11].
`list_files`, `get_command_history`, `get_command_result`와 메모 도구 `show_analyst_notes_summary`·`show_analyst_note`·`add_analyst_note`·`update_analyst_note`가 그 도구다 [11].
이 7개를 부른 뒤 `command_history.json`의 항목 수는 그대로였다 [12].

서버 프로세스의 표준 오류에는 MCP 도구 이름과 인자를 담은 줄이 남지 않는다.
서버 코드가 `loguru`로 쓰는 줄은 컨테이너를 시작하고 멈추고 지울 때의 안내뿐이다 [13].
MCP Python SDK 1.27.0은 요청마다 `Processing request of type CallToolRequest` 줄을 쓰고 이 줄에는 도구 이름과 인자가 없다 [14].
등록되지 않은 도구 이름이 오면 SDK가 그 이름을 담은 경고 한 줄을 쓴다 [14].
FastMCP는 도구 본문의 예외를 오류 결과로 바꾸고 로그에는 쓰지 않는다 [15].
도구를 차례로 부른 실행의 표준 오류에는 이 줄들과 `coroutine 'Context.report_progress' was never awaited` 경고만 있었다 [12].
저장소에는 MCP 도구 호출을 기록하는 클라이언트 코드, 훅, 사용자 CLI가 없다.

**한계.** 도구 본문의 검사에서 예외가 나면 `exec_stream`을 부르지 않으므로 항목이 남지 않는다 [16].
`run_find`의 `-exec` 거부와 `unzip_file`·`untar_file`의 `..` 거부, 원본 파일 확인, `/artifacts/` 밖 대상 거부가 그 검사다 [16].
`unzip_file`·`untar_file`은 컨테이너 안 경로로 받은 `source_file`을 서버 프로세스 쪽 파일 시스템에서 `Path(source_file).is_file()`로 확인한다 [16].
Windows 호스트에서 실행한 서버에 `/evidence/sample.tar`와 `/evidence/sample.zip`을 주자 두 도구 모두 `Source file not found` 오류로 끝나고 항목을 남기지 않았다 [17].
FastMCP가 인자 모델 검사에서 거부한 호출과 등록되지 않은 도구 이름을 부른 호출은 도구 본문이 실행되지 않아 항목이 남지 않는다 [15][17].
`exec_stream`은 표준 출력 조각을 `data.decode()`로 읽고 `DockerException`만 처리한다 [9].
그래서 UTF-8로 읽히지 않는 바이트를 출력한 명령은 실행된 뒤 `UnicodeDecodeError`로 끝나 항목이 남지 않는다 [9].
`run_sleuthkit_command`로 `blkcat /evidence/disk.dd 1`을 실행하자 오류 결과가 돌아오고 항목이 남지 않았다 [18].

    def dump(self, command: CommandRecord | None, command_number: int | None = None):
        # Write to command history
        with open(file=config.command_history_json, mode="w", encoding="utf-8") as command_summary_file:
            json.dump(
                [record.model_dump() for record in self.command_summary_list],
                command_summary_file,
                indent=4,
            )

        # Write to command file
        if command is not None and command_number is not None:
            with open(
                file=config.command_record_directory / f"{command_number}.txt", mode="w", encoding="utf-8"
            ) as command_file:
                command_file.write(command.result)

    def load(self):
        with open(file=config.command_history_json, encoding="utf-8") as command_file:
            for command_summary_dict in json.load(command_file):
                self.command_summary_list.append(CommandRecordSummary.model_validate(command_summary_dict))

    def add_command(self, command_record: CommandRecord) -> CommandRecordSummary:
        number = len(self.command_summary_list) + 1
        summary = command_record.summary(number=number)
        self.command_summary_list.append(summary)
        self.dump(command_record, number)
        return summary
```

    def exec_stream(self, ctx: Context, command_list: list[str]) -> CommandRecordSummary:
        if self.container is None:
            raise RuntimeError("No docker container is currently running")

        ctx.report_progress(f"Running command {' '.join(command_list)}")
        output = []
        exit_code = 0
        try:
            for stream, data in self.docker.execute(self.container, command_list, stream=True):
                if stream == "stdout":
                    output.append(data.decode())
        except DockerException as ex:
            exit_code = ex.return_code if ex.return_code is not None else 1
            output.append(str(ex))
        result = "".join(output)
        return command_history_manager.add_command(
            CommandRecord(
                command=" ".join(command_list),
                result=result,
                exit_code=exit_code,
            )
        )
```
