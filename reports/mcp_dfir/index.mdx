# mcp_dfir 원고

이 파일은 서버 개요다. 셀마다 이 폴더 아래 축 폴더의 `<축>/<셀ID>.mdx`에 쓴다.
셀과 상세 항목의 정의는 `matrix/cells/<축>/<셀ID>.mdx`를 따른다.
상세 항목마다 **구현**을 쓰고 그 방식이 적용되지 않는 경로나 조건이 있으면 **한계**를 따로 쓴다.
본문의 [번호]는 그 파일 끝 **근거**의 같은 번호를 가리킨다.

**기준 커밋.** [`305fcad`](https://github.com/Androsh7/mcp_dfir/tree/305fcadb784f4f3e80cc8f8287b0ea57a007f8a5)(2026-04-11, v0.1.2).
줄 번호는 모두 이 커밋 기준이다.

**범위.** `mcp_dfir/` 패키지를 서버로 본다.
서버는 stdio MCP 서버 하나다.
`mcp_dfir/server.py`가 MCP Python SDK의 `FastMCP`로 도구 18개를 등록하고 `mcp_dfir/runner.py`의 `main`이 실행 인자를 읽어 서버를 시작한다.
서버는 MCP 리소스와 프롬프트를 두지 않는다.

포렌식 도구는 서버 프로세스가 아니라 Docker 컨테이너 안에서 실행된다.
서버는 시작할 때 이미지 `androsh7/forensics-docker:<서버 버전>`으로 컨테이너를 만들거나 있던 컨테이너를 다시 시작하고 도구 호출마다 그 컨테이너에서 명령을 실행한다.
컨테이너 안의 Volatility 3, The Sleuth Kit, `strings`·`grep`·`find`·`tar`·해시 명령은 서버가 부르는 분석 도구로 본다.
저장소의 `Dockerfile`은 그 이미지를 만드는 정의이고 저장소가 지원하는 실행 환경으로 본다.
`runner.py`의 실행 인자 `--case-dir`·`--init`·`--clear-case-dir`·`--clear-docker`는 사용자가 서버를 다루는 CLI로 본다.
저장소에는 MCP 클라이언트 설정 파일이나 훅이 없고 README가 클라이언트 등록 예시만 적는다.
`examples/tryhackme_volatility/`는 저장소에 커밋된 예시 사건 폴더이고 코드가 만든 기록의 실제 모양으로 인용한다.
`run_dev.py`와 `tests/`는 서버 구현으로 보지 않는다.

**확인 방법.** 코드는 기준 커밋을 `git show`로 읽었다.
MCP Python SDK, python-on-whales, Volatility 3, The Sleuth Kit의 동작은 아래 버전 기준의 소스로 확인했다.
근거의 "실행 확인"은 Windows 11 호스트에서 기준 커밋의 소스를 Python 3.13.14로 실행해 본 결과다.
포렌식 도구는 Docker Desktop(엔진 29.7.2)이 Docker Hub에서 받은 이미지 `androsh7/forensics-docker:0.1.2`의 컨테이너에서 실행했다.
Linux 호스트에서는 실행하지 않았다.

저장소에는 증거 표본 파일이 없어 다음 입력을 썼다.

- 직접 만든 8MB ext4 디스크 이미지, 글 파일, zip·tar·tar.gz 보관 파일
- 4.2GB Linux 메모리 이미지 하나. 이 이미지에서는 종료 코드, 행 수, 열 이름, 걸린 시간만 확인하고 내용은 원고에 옮기지 않았다.

확인한 것은 다음과 같다.

- MCP Python SDK 클라이언트 세션(stdio)으로 서버를 실행해 초기화 응답의 `instructions`, 도구 18개의 설명·입력 schema·출력 schema·annotation, 리소스와 프롬프트 목록을 확인했다.
- 도구 18개를 모두 불러 응답의 `isError`·`content`·`structuredContent`와 사건 폴더의 `analysis` 파일을 대조했다.
- 목록 밖의 값, 자료형이 다른 값, 빠진 인자를 주어 FastMCP가 거부하는 호출과 서버 코드가 거부하는 호출을 갈랐다.
- `fls`·`istat`·`strings`·`find`의 결과 본문을 같은 이미지의 컨테이너에서 직접 실행한 출력과 SHA-256으로 대조했다.
- `get_command_result`를 `head`·`tail`·`head_bytes`·`tail_bytes`·`regex`·`byte_limit`의 여러 조합과 음수 값, 85,006자 출력, 한글 출력으로 불러 적용 순서, 상한, 길이를 세는 방식을 확인했다.
- 종료 코드가 0이 아닌 명령, 표준 오류만 내고 종료 코드 0으로 끝나는 명령, UTF-8이 아닌 출력을 내는 명령을 실행해 응답과 기록을 확인했다.
- 끝나지 않는 명령을 실행한 채 다른 도구를 부르고 세션을 닫아 응답 여부와 컨테이너·프로세스 상태를 확인했다.
- `progressToken`을 붙여 실행 도구와 심볼 도구를 불러 진행 알림이 오는지 확인했다.
- `run_find`에 `-exec`·`-execdir`·`-ok`·`-okdir`·`-fprint`·`-fprintf`·`-delete`를 주어 검사가 막는 범위를 확인하고 `-fprintf`로 만든 파일을 `run_volatility_command --plugin-dirs`로 실행했다.
- 서버가 만든 컨테이너의 계정, 네트워크, 폴더 연결, capability를 `docker inspect`와 컨테이너 안 명령으로 확인하고 `/evidence`·`/analysis`에 쓰기와 삭제를 시도했다.
- 컨테이너 안에서 밖으로 HTTPS 요청과 TCP 연결을 시도했다.
- `unzip_file`·`untar_file`을 컨테이너 경로, 호스트 경로, `..`이 들어간 경로, `/artifacts` 밖 목적지, 링크를 지나는 목적지, `compression` 값으로 불러 검사 순서와 실행 결과를 확인했다.
- `tsk_recover`로 디스크 이미지의 파일을 `/artifacts`에 꺼내고 읽기 전용 경로를 출력 위치로 주었을 때의 종료 코드를 확인했다.
- 분석 메모 도구 넷을 불러 필드 검사, 같은 제목 두 번 더하기, `update_analyst_note`의 오류, 경로 구분자와 `..`이 들어간 제목을 확인했다.
- `search_linux_symbols`를 일치 항목이 있는 정규식과 없는 정규식, 심볼 맵이 없을 때와 손상됐을 때로 불렀다.
- `download_linux_symbol`을 실제 심볼 경로, 없는 경로, `..`과 역슬래시가 들어간 경로로 불러 요청이 가는 곳과 파일이 쓰이는 곳을 확인했다.
- `download_windows_symbol`을 실제 PDB, 없는 PDB, 이미 받은 심볼, `overwrite`를 켠 채 변환이 실패하는 경우로 불렀다.
- 서버를 끝내고 같은 사건 폴더로 다시 시작해 명령 기록과 분석 메모가 읽히고 번호가 이어지는지, 멈춘 컨테이너를 다시 시작하는지 확인했다.
- 명령 기록 파일을 손상시키거나 손으로 고치거나 쓸 수 없게 만든 뒤 서버 시작과 도구 호출의 결과를 확인했다.
- 같은 사건 폴더에 서버 프로세스 둘을 붙여 컨테이너, 명령 번호, 기록 파일이 어떻게 되는지 확인했다.
- 이름이 같은 사건 폴더 둘을 다른 위치에 두고 차례로 실행해 어느 폴더의 증거가 보이는지 확인했다.
- 같은 이름의 컨테이너를 다른 네트워크·계정·폴더 연결로 미리 만들어 두고 서버를 실행했다.
- 상대 경로, 없는 폴더, 공백과 한글이 들어간 이름을 `--case-dir`로 주어 서버를 시작했다.
- `--init`, `--clear-docker`, `--clear-case-dir`를 실행해 종료 코드, 남는 폴더, 컨테이너 유무를 확인했다.
- `DOCKER_HOST`를 닫힌 포트로, `PATH`를 `docker`가 없는 값으로, 이미지 태그를 Docker Hub에 없는 값과 받아 두지 않은 값으로 바꿔 서버를 시작했다.
- 세션 중에 컨테이너를 멈추거나 지운 뒤 실행 도구를 불렀다.
- 이미지 안에서 실행 파일 유무, Volatility 3의 커밋과 버전, The Sleuth Kit 버전을 확인했다.
- 설치본의 MCP Python SDK, python-on-whales, requests 파일이 아래 고정 커밋의 원문과 같은지 대조했다.

다음은 실행으로 확인하지 않았다.

- Linux 호스트에서의 동작(폴더 권한, 호스트 계정과 컨테이너 계정의 uid 차이, 줄 끝)
- 심볼이 맞는 메모리 이미지에서 Volatility 플러그인이 내는 시각 열
- `unzip_file`이 압축을 푸는 경로(이미지에 `unzip`이 없다)
- Python 3.11에서의 서버 시작
- Docker 데몬이 다른 호스트에 있는 구성과 다른 MCP 클라이언트의 동작

원고에서 이 부분은 정적 분석 결과다.

**외부 도구 버전 기준.** 서버는 분석 도구를 이미지 태그로 정한다.
`pyproject.toml`은 파이썬 의존성의 이름만 적고 잠금 파일이 없다.
그래서 이미지는 서버 버전의 태그로 Docker Hub에 올라 있는 것을, 파이썬 의존성은 기준 커밋 날짜(2026-04-11)에 나와 있던 최신 정식 릴리스를 기준으로 한다.

- 이미지: `androsh7/forensics-docker:0.1.2`(다이제스트 `sha256:85239eb962eb444609d7e85d75d030f23dd249c87caabbb2fab3bd9b711bf2f3`, 2026-04-11 생성)다.
- Volatility 3: 이미지 안의 `volatilityfoundation/volatility3` `develop` 브랜치 커밋 `9424c3a`(패키지 버전 2.28.1)다. `Dockerfile`은 버전을 정하지 않고 저장소를 받는다.
- The Sleuth Kit: 이미지 안의 4.12.1(`sleuthkit/sleuthkit` 태그 `sleuthkit-4.12.1`, `b42c1cf`)이다.
- MCP Python SDK: `mcp` 1.27.0(`modelcontextprotocol/python-sdk` 태그 `v1.27.0`, `6524782`)이다.
- python-on-whales: 0.81.0(`gabrieldemarmiesse/python-on-whales` 태그 `v0.81.0`, `059d89a`)이다.
- requests: 2.33.1(`psf/requests` `111d2b7`)이다.
- Python: `pyproject.toml`은 3.11 이상만 정한다. 저장소의 배포 워크플로가 쓰는 3.13의 CPython 3.13.14를 실행 확인 환경으로 썼다.
- `attrs` 26.1.0, `loguru` 0.7.3, `pydantic` 2.12.5는 같은 날짜 기준으로 설치된 버전이다.
- Docker 엔진 29.7.2는 실행 확인 환경의 버전이고 기준 커밋 날짜의 버전으로 맞추지 않았다.

**바뀔 수 있는 것.** 범위와 외부 도구 버전 기준은 조사하며 맞지 않는 곳이 나오면 검토를 거쳐 바꾼다.
