# D01 파생물 보관

### D01.01 파생물 파일 보관

**구현.** 이 방식은 컨테이너에서 명령을 실행하는 도구 8개와 심볼 도구 3개가 남기는 명령 결과, 그리고 컨테이너 안 분석 도구가 `/artifacts`에 만드는 파일에 적용된다 [1][2].
컨테이너 명령 도구 `run_strings`·`run_grep`·`run_find`·`unzip_file`·`untar_file`·`get_hash`·`run_volatility_command`·`run_sleuthkit_command`는 모두 `exec_stream`으로 명령을 실행한다 [2].
`exec_stream`은 명령의 표준 출력 조각을 이어 붙인 글을 `CommandRecord.result`에 담아 `command_history_manager.add_command`에 넘긴다 [1].
`add_command`는 명령 번호를 정하고 `dump`는 그 글을 결과 본문 파일 `analysis/command_history/<번호>.txt`에 UTF-8로 쓴다 [3][4].
실행 도구의 응답은 번호, 명령, 시각, 종료 코드만 담은 `CommandRecordSummary`라서 결과 본문은 이 파일에만 남는다 [1][5].
서버는 결과 본문을 자르거나 고치지 않고 쓰며 크기 상한을 두지 않는다 [1][3].
예시 사건 폴더의 `command_history`에는 결과 본문 파일 20개가 있고 가장 큰 `15.txt`는 9,680,429바이트다 [6].
표준 출력이 비어 있는 명령도 0바이트 파일로 남았다 [7].
명령이 0이 아닌 코드로 끝나면 `exec_stream`은 모은 표준 출력 뒤에 `DockerException`의 글을 붙여 저장한다 [1].
그 글에는 실행한 `docker exec` 명령 줄, 종료 코드, 표준 오류가 들어 있었다 [7].
심볼 도구 `download_windows_symbol`·`download_linux_symbol`·`search_linux_symbols`는 서버 코드가 만든 글을 `add_command`에 넘겨 같은 폴더에 남긴다 [8].
`download_linux_symbol`의 결과 본문 파일에는 내려받은 파일 이름과 크기, 주소를 적은 문장 한 줄이 남았다 [7].

분석 도구가 직접 만드는 파일은 사건 폴더의 `artifacts`에 남는다 [9][7].
서버는 사건 폴더의 `artifacts`를 컨테이너의 `/artifacts`에 읽기·쓰기로 연결한다 [9].
모델이 실행 도구의 인자로 `/artifacts` 아래를 출력 위치로 주면 분석 도구가 만든 파일이 호스트의 그 폴더에 생긴다 [9][7].
`tsk_recover`가 복구한 파일 3개, Volatility `timeliner`가 `-o /artifacts`로 쓴 bodyfile, `find -fprint`의 출력 파일이 호출 뒤에도 사건 폴더의 `artifacts`에 남아 있었다 [7].
`/symbols`도 읽기·쓰기로 연결되어 있어 `find -fprint`의 출력 위치를 `/symbols` 아래로 주자 그 파일이 사건 폴더의 `symbols`에 남았다 [9][7].
`untar_file`과 `unzip_file`은 `/artifacts/` 아래에 압축을 풀도록 `tar`와 `unzip`을 실행하는 도구다 [10].
서버 코드에는 이 파일들을 호출 뒤에 지우거나 기간이나 용량에 따라 정리하는 곳이 없다.

볼륨 밖의 경로에 쓴 파일은 컨테이너의 파일 시스템에 남는다.
`-o` 없이 실행한 Volatility `timeliner`의 bodyfile은 컨테이너의 `/tools`에, `find -fprint /tmp/fd-marker.txt`의 파일은 컨테이너의 `/tmp`에 생겼다 [7].
서버는 끝날 때 컨테이너를 멈추기만 하고 다음에 시작할 때 같은 이름의 컨테이너를 다시 쓴다 [11].
서버를 끝내고 다시 실행한 뒤에도 두 파일은 컨테이너 안에 남아 있었다 [7].
`/usr`와 `/` 바로 아래를 출력 위치로 준 `find -fprint`는 `Permission denied`로 끝났다 [7].

분석 메모는 `analysis/analyst_notes.json`과 `analysis/analyst_notes/` 아래 markdown 파일로 남는다 [12].
명령 기록 목록 `analysis/command_history.json`에는 번호, 명령, 시각, 종료 코드만 들어가고 출력은 들어가지 않는다 [3][5].
`get_command_result`가 줄 수나 정규식으로 골라 돌려준 글은 따로 저장하지 않는다 [13].
서버는 DB를 쓰지 않는다.
`download_windows_symbol`이 받은 PDB, `pdbconv`가 그 PDB를 변환해 만든 심볼 파일, `download_linux_symbol`이 받은 파일, `search_linux_symbols`가 받은 Linux 심볼 맵은 사건 폴더의 `symbols` 아래에 남는다 [14].
네 가지 모두 증거에서 나온 자료가 아니라 Volatility가 읽는 심볼과 그 목록이다 [14].

**한계.** `exec_stream`은 표준 출력 조각마다 `decode()`를 부르고 `UnicodeDecodeError`를 처리하지 않는다 [1].
`blkcat`으로 이미지의 블록 하나를 읽자 `'utf-8' codec can't decode byte` 오류로 끝났고 그 호출은 명령 기록 목록에도 결과 본문 파일에도 남지 않았다 [7].
`search_linux_symbols`는 정규식에 맞는 심볼이 있으면 `SymbolSearchResult` 목록을 `json.dumps`에 넘기다 오류로 끝나 결과를 남기지 못한다 [8][7].
`exec_stream`은 스트림에서 `stdout` 조각만 모으므로 0으로 끝난 명령의 표준 오류는 저장하지 않는다 [1].
읽기 전용인 `/evidence` 아래를 출력 폴더로 준 `tsk_recover`는 0으로 끝났고 결과 본문은 `Files Recovered: 0` 한 줄이었다 [7].
같은 명령을 이미지에서 직접 실행하자 표준 오류에 폴더를 만들지 못했다는 줄이 나왔다 [7].
`dump`는 결과 본문 파일을 text mode로 열어 쓰므로 Windows 호스트에서는 결과의 줄 끝 `\n`이 `\r\n`으로 저장된다 [3][7].
`unzip_file`과 `untar_file`은 `source_file`이 서버 프로세스가 실행되는 호스트에 파일로 있는지 확인한다 [10].
컨테이너 안 경로 `/evidence/sample.tar`를 `source_file`로 주자 `Source file not found` 오류로 끝나 압축을 푼 파일이 남지 않았다 [7].
호스트에 있는 `sample.tar`의 경로를 주자 이 확인은 통과했지만 컨테이너에 그 경로가 없어 `tar`가 종료 코드 128로 끝났고 압축을 푼 파일은 생기지 않았다 [7].
이미지에는 `unzip` 실행 파일이 없어 호스트에 있는 경로를 `source_file`로 준 `unzip_file`은 종료 코드 127로 끝났다 [7].
서버는 사건 폴더의 `artifacts`와 `symbols`를 `mkdir(mode=500)`으로 만든다 [15].
이미지의 Python 3.12에서 같은 호출로 만든 폴더의 권한은 `0o744`였고 그 폴더의 소유자가 아닌 `analyst` 계정은 그 안에 파일을 만들지 못했다 [7].
컨테이너의 분석 도구는 UID가 1000인 `analyst` 계정으로 실행된다 [7].
Linux 호스트에서 서버를 실행한 계정의 UID가 1000이 아닐 때 분석 도구가 `/artifacts`에 파일을 남기는지는 확인하지 못했다 [9].

    def exec_stream(self, ctx: Context, command_list: list[str]) -> CommandRecordSummary:
        if self.container is None:
            raise RuntimeError("No docker container is currently running")

        ctx.report_progress(f"Running command {' '.join(command_list)}")
        output = []
        exit_code = 0
        try:
            for stream, data in self.docker.execute(self.container, command_list, stream=True):
                if stream == "stdout":
                    output.append(data.decode())
        except DockerException as ex:
            exit_code = ex.return_code if ex.return_code is not None else 1
            output.append(str(ex))
        result = "".join(output)
        return command_history_manager.add_command(
            CommandRecord(
                command=" ".join(command_list),
                result=result,
                exit_code=exit_code,
            )
        )
```

    def dump(self, command: CommandRecord | None, command_number: int | None = None):
        # Write to command history
        with open(file=config.command_history_json, mode="w", encoding="utf-8") as command_summary_file:
            json.dump(
                [record.model_dump() for record in self.command_summary_list],
                command_summary_file,
                indent=4,
            )

        # Write to command file
        if command is not None and command_number is not None:
            with open(
                file=config.command_record_directory / f"{command_number}.txt", mode="w", encoding="utf-8"
            ) as command_file:
                command_file.write(command.result)

    def load(self):
        with open(file=config.command_history_json, encoding="utf-8") as command_file:
            for command_summary_dict in json.load(command_file):
                self.command_summary_list.append(CommandRecordSummary.model_validate(command_summary_dict))

    def add_command(self, command_record: CommandRecord) -> CommandRecordSummary:
        number = len(self.command_summary_list) + 1
        summary = command_record.summary(number=number)
        self.command_summary_list.append(summary)
        self.dump(command_record, number)
        return summary
```
