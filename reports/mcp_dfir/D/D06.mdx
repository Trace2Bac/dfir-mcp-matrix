# D06 산출물 식별·재생성 처리

### D06.01 실행 ID별 위치

**구현.** 이 방식은 결과 본문 파일에 적용된다 [1].
`add_command`는 명령을 기록할 때마다 목록 길이에 1을 더한 번호를 매기고 `dump`는 결과를 `command_history/<번호>.txt`에 쓴다 [1].
번호는 그 실행의 목록 항목 `number`와 같고 실행 도구의 응답으로 모델에게 전달된다 [1][2].
같은 명령을 다시 실행해도 새 번호를 받으므로 앞 결과 본문 파일은 남는다 [1].
`tsk_recover -e /evidence/disk.dd /artifacts/fd-rec`를 두 번 실행하자 3번과 4번 항목이 따로 생겼고 `3.txt`와 `4.txt`가 모두 남았다 [3].
서버는 같은 명령이 이미 목록에 있는지 확인하지 않는다 [1].
저장소 README는 명령 기록이 남아 모델이 끝난 명령을 다시 실행하지 않는다고 적고 서버 지침은 앞서 실행한 명령을 먼저 살피라고 적는다 [4].
`download_windows_symbol`은 호출 한 번에 내려받기 항목과 `pdbconv` 항목을 따로 남겨 번호 두 개를 쓴다 [5].
이 도구의 `overwrite` 인자는 변환한 심볼 파일이 이미 있을 때 다시 받을지를 정한다 [5].
변환한 심볼 파일은 증거에서 나온 자료가 아니라 Volatility가 읽는 심볼이고 `overwrite`는 결과 본문 파일에 적용되지 않는다 [5].

다른 파생물의 이름에는 실행마다 다른 값이 들어가지 않는다.
분석 메모의 본문 파일은 `<title>.md`이고 이름에 번호나 시각이 들어가지 않는다 [6].
같은 제목으로 다시 더하면 서버는 알리지 않고 본문 파일을 덮어쓰고 목록에는 같은 제목의 항목을 하나 더 넣는다 [6][3].
이미 있는 결과를 알아채 다시 만들지 않거나 덮어쓸지를 고르게 하는 인자는 실행 도구와 `add_analyst_note`에 없다 [6][7].
컨테이너 안 분석 도구가 `/artifacts`에 만드는 파일의 이름은 모델이 준 인자와 그 도구가 정한다 [7].
`tsk_recover`를 같은 출력 폴더로 다시 실행하자 같은 이름의 파일은 덮어쓰였고 앞 실행에만 있던 파일은 그대로 남았다 [3].
이미지 안 GNU tar 1.35도 같은 폴더에 다시 풀자 같은 이름의 파일을 덮어썼다 [3].
`tsk_loaddb`와 `sorter`처럼 파일을 쓰는 다른 Sleuth Kit 도구가 같은 이름을 어떻게 다루는지는 확인하지 못했다 [7].

**한계.** 번호는 프로세스 메모리에 있는 목록의 길이에서 나오고 `dump`는 그 번호의 파일이 이미 있는지 확인하지 않고 쓰기 모드로 연다 [1].
같은 사건 폴더에 서버 프로세스 둘을 붙이자 두 프로세스가 같은 번호 1을 매겼고 나중 프로세스의 출력이 `1.txt`를 덮어썼다 [3].
앞 프로세스의 결과는 어느 파일에도 남지 않았다 [3].
명령 기록 목록도 프로세스마다 자기 목록으로 전체를 다시 쓰므로 다른 프로세스의 항목이 사라진다 [1][3].

### D06.03 버전·이력 보존

**구현.** 이 방식은 서버 코드가 아니라 `run_volatility_command`가 실행하는 Volatility 3의 파일 쓰기에 적용된다 [7][8].
Volatility 3의 파일 핸들러는 출력 폴더에 같은 이름의 파일이 있으면 이름과 확장자 사이에 `-1`, `-2`처럼 번호를 붙인 새 이름으로 쓴다 [8].
`-o /artifacts`와 `timeliner.Timeliner --create-bodyfile`로 두 번 실행하자 사건 폴더의 `artifacts`에 `volatility.body`와 `volatility-1.body`가 남았다 [3].
출력 폴더는 `-o`로 정하고 그 폴더가 없으면 Volatility가 종료 코드 2로 끝난다 [8][3].
`-o`를 주지 않으면 출력 폴더는 Volatility를 실행한 현재 폴더이고 컨테이너에서는 `/tools`다 [8][3].
두 실행에서 붙은 번호는 파일 이름에만 있었고 두 명령 기록 항목의 `command`는 출력 폴더까지 같았다 [3].

```python
    def dump(self, command: CommandRecord | None, command_number: int | None = None):
        # Write to command history
        with open(file=config.command_history_json, mode="w", encoding="utf-8") as command_summary_file:
            json.dump(
                [record.model_dump() for record in self.command_summary_list],
                command_summary_file,
                indent=4,
            )

        # Write to command file
        if command is not None and command_number is not None:
            with open(
                file=config.command_record_directory / f"{command_number}.txt", mode="w", encoding="utf-8"
            ) as command_file:
                command_file.write(command.result)

    def load(self):
        with open(file=config.command_history_json, encoding="utf-8") as command_file:
            for command_summary_dict in json.load(command_file):
                self.command_summary_list.append(CommandRecordSummary.model_validate(command_summary_dict))

    def add_command(self, command_record: CommandRecord) -> CommandRecordSummary:
        number = len(self.command_summary_list) + 1
        summary = command_record.summary(number=number)
        self.command_summary_list.append(summary)
        self.dump(command_record, number)
        return summary
```

`docker run`으로 이미지에서 `tsk_recover`를 같은 폴더로 두 번 실행하며 그 사이에 복구된 파일 하나의 내용을 바꾸고 새 파일 하나를 더하자 둘째 실행 뒤 바꾼 파일은 이미지의 내용이었고 더한 파일은 남아 있었다.
같은 방법으로 GNU tar 1.35에 같은 tar 파일을 같은 폴더로 두 번 풀게 하자 그 사이에 바꾼 파일이 tar 파일의 내용으로 돌아왔다.
같은 제목으로 `add_analyst_note`를 두 번 부르자 응답은 둘 다 `{"result": null}`이었고 본문 파일에는 둘째 글만 있었으며 목록에는 같은 제목의 항목이 둘 있었다.
같은 사건 폴더에 서버 프로세스 둘을 붙여 첫째에서 `md5sum`, 둘째에서 `sha256sum` 해시를 구하자 두 응답의 `number`가 모두 1이었고 `1.txt`에는 `sha256sum`의 출력만 있었다.
첫째 프로세스가 명령을 하나 더 실행하자 `command_history.json`에는 첫째 프로세스의 항목 2개만 있었다.
`vol -s /symbols -r jsonl -q -o /artifacts -f /evidence/disk.dd timeliner.Timeliner --create-bodyfile`을 두 번 부르자 사건 폴더의 `artifacts`에 `volatility.body`와 `volatility-1.body`가 있었다.
`-o /artifacts/fd-novol`을 준 같은 명령은 `exit_code` 2로 끝났다.
`-o` 없이 부른 같은 명령 뒤 `find /tools -maxdepth 1 -name *.body`의 결과는 `/tools/volatility.body`였다.
두 Volatility 항목의 `command`는 글자 하나까지 같았다.

```python
def download_windows_symbol(
    ctx: Context, pdb_name: str, guid: str, age: int, overwrite: bool = False
) -> tuple[CommandRecordSummary, CommandRecordSummary]:
    """Downloads windows symbols for volatility to `/symbols`"""

    # Set correct naming convention and directory tree for volatility parsing
    output_file_name = f"{guid}-{age}.json.xz"
    output_file_external_path = config.windows_symbols_directory / pdb_name / output_file_name
    output_file_internal_path = f"/symbols/windows/{pdb_name}/{output_file_name}"
    if output_file_external_path.exists() and not overwrite:
        raise RuntimeError(
            f"File {output_file_internal_path} already exists, it can be used by volatility with the `-s /symbols` "
            "argument, set overwrite to True to overwrite this file"
        )
    else:
        output_file_external_path.parent.mkdir(mode=500, parents=True, exist_ok=True)

    # Download pdb
    internal_path, download_output = _download_windows_pdb(ctx=ctx, pdb_name=pdb_name, guid=guid, age=age)

    # Run conversion to symbol file
    pdbconv_output = _run_volatility_pdbconv_command(
        ctx=ctx,
        arguments=["-f", internal_path, "-g", guid, "-o", output_file_internal_path],
    )
```
