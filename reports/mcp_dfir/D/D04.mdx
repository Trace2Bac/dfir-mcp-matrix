# D04 출력 경로 제한

### D04.01 서버가 출력 위치 결정

**구현.** 이 방식은 결과 본문 파일과 분석 메모의 목록 파일, 본문 파일에 적용된다 [1].
서버는 `--case-dir`로 받은 사건 폴더 아래 `analysis` 폴더를 만들고 그 안의 `command_history/`, `analyst_notes.json`, `analyst_notes/`를 경로로 정한다 [1][2].
`--case-dir`를 주지 않으면 서버를 실행한 현재 폴더가 사건 폴더다 [2].
결과 본문 파일의 이름은 서버가 매긴 번호에 `.txt`를 붙인 것이고 호출 인자는 경로에 들어가지 않는다 [3].
분석 메모의 목록 파일은 이름이 정해져 있고 본문 파일은 `analyst_notes/` 아래 `<title>.md`다 [4].
`title`은 `add_analyst_note`가 받은 메모의 제목이다 [4].
저장된 명령 결과나 분석 메모를 지우는 도구는 없다 [5].
`update_analyst_note`는 고칠 메모를 경로가 아니라 `title`로 고르고 본문 파일의 경로는 새 메모의 `title`로 만든다 [6].
이 도구는 있는 제목으로 부르면 오류로 끝나 저장한 파일을 고치지 못한다 [6][7].
사용자 CLI의 `--clear-case-dir`는 사용자가 `yes`를 입력하면 `--case-dir` 아래 `artifacts`·`analysis`·`evidence`·`symbols` 폴더를 지운다 [8].

**한계.** `AnalystNoteManager.dump`는 `title`에 경로 구분자, `..`, 절대 경로가 있는지 검사하지 않고 `analyst_notes` 폴더 경로 뒤에 붙인다 [4].
제목 `../fd-up-one`은 `analysis/fd-up-one.md`에, `../../artifacts/fd-in-artifacts`는 `artifacts/fd-in-artifacts.md`에 쓰였다 [7].
제목 `../../../fd-outside-case`는 사건 폴더의 상위 폴더에 `fd-outside-case.md`를 만들었다 [7].
사건 폴더의 `artifacts` 아래를 가리키는 절대 경로를 제목으로 주자 그 경로에 `.md`를 붙인 파일이 생겼다 [7].
파일 이름 끝에는 늘 `.md`가 붙는다 [4].
없는 하위 폴더를 가리키는 제목은 `No such file or directory` 오류로 끝났다 [7].

다른 도구가 호출 인자로 만든 경로로 결과 본문 파일을 덮어쓰는 경우도 있다.
`download_linux_symbol`은 `symbol_path`의 마지막 `/` 뒤 조각을 검사 없이 `symbols/linux` 폴더 경로 뒤에 붙여 그 경로에 내려받은 내용을 쓴다 [9].
Windows 호스트에서 `symbol_path`를 `README.md?x=/..\..\analysis\command_history\1.txt`로 주자 내려받은 내용이 1번 명령의 결과 본문 파일을 덮어썼다 [7].
그 뒤 `get_command_result`는 1번 명령의 결과로 내려받은 글을 돌려주었다 [7].

### D04.04 이름·확장자·충돌 검사

**구현.** 이 방식은 `unzip_file`과 `untar_file`의 목적지 인자 `destination_dir`에 적용된다 [10].
두 도구는 `source_file`이나 `destination_dir`에 `..`가 들어 있으면 `Invalid file path, Path traversal is not allowed` 오류로 거부한다 [10].
`destination_dir`가 `/artifacts/`로 시작하지 않으면 `Destination directory must be in /artifacts` 오류로 거부한다 [10].
두 검사는 문자열 비교이고 링크를 해석한 실제 경로로 바꾸지 않는다 [10].
두 검사 사이에는 `source_file`이 서버 프로세스가 실행되는 호스트에 파일로 있는지 확인하는 단계가 있다 [10].
컨테이너 안 경로 `/evidence/sample.tar`를 `source_file`로 주자 `Source file not found` 오류로 끝나 목적지 검사에 닿지 않았다 [7].
호스트에 있는 `sample.tar`의 경로를 `source_file`로 주고 `destination_dir`에 `/tmp/fd-untar`와 끝에 `/`가 없는 `/artifacts`를 주자 둘째 오류로, `/artifacts/../tmp`를 주자 첫째 오류로 거부되었다 [7].
`/artifacts/`는 통과해 `tar -xf <source_file> -C /artifacts/`가 컨테이너에서 실행되었다 [7].
이 호출의 `source_file`은 컨테이너에 없는 호스트 경로여서 `tar`는 종료 코드 128로 끝났고 파일을 풀지 않았다 [7].
압축 안 항목의 이름은 서버가 검사하지 않고 `tar`와 `unzip`에 맡긴다 [10].
이미지 안 GNU tar 1.35는 이름에 `..`가 들어 있는 항목을 풀지 않고 오류로 끝났다 [7].

다른 실행 도구는 출력 위치를 검사하지 않는다.
`run_volatility_command`·`run_sleuthkit_command`·`run_find`·`run_grep`·`run_strings`는 모델이 준 인자를 그대로 명령에 붙인다 [11].
Volatility의 `-o`, `tsk_recover`의 출력 폴더, `find`의 `-fprint`처럼 파일을 쓰는 위치도 인자 그대로 전달된다 [11][7].
`-o`로 준 폴더와 `tsk_recover`의 출력 폴더 안에 생기는 파일의 이름은 Volatility와 `tsk_recover`가 정한다 [7].

**한계.** 검사가 문자열 비교라서 `/artifacts/` 아래에 다른 폴더를 가리키는 심볼릭 링크가 있으면 그 링크를 거치는 `destination_dir`를 가리지 못한다 [10].
`/symbols`를 가리키는 링크 `/artifacts/lnk`를 만들어 두고 `destination_dir`를 `/artifacts/lnk/`로 주자 검사를 통과했고 푼 파일이 사건 폴더의 `symbols`에 생겼다 [12].
`/evidence`를 가리키는 링크로 같은 호출을 하자 검사는 통과했고 `tar`가 `Read-only file system` 오류로 끝나 사건 폴더의 `evidence`에는 파일이 생기지 않았다 [12].

### D04.06 실행 환경의 쓰기 위치 제한

**구현.** 이 방식은 컨테이너에서 명령을 실행하는 도구가 파일을 쓰는 위치에 적용된다 [13].
이 도구들은 출력 위치를 검사하지 않고 호스트에 파일을 남길 수 있는 위치는 컨테이너의 볼륨 설정이 정한다 [11][13].
볼륨은 `/evidence`와 `/analysis`를 읽기 전용으로, `/symbols`와 `/artifacts`를 읽기·쓰기로 연결한다 [13].
`/evidence` 아래를 준 `find -fprint`는 `Read-only file system` 오류로 끝났고 `/analysis` 아래를 준 `tsk_recover`는 파일을 하나도 만들지 못했다 [7].
`/symbols` 아래를 준 `find -fprint`의 파일은 사건 폴더의 `symbols`에 생겼다 [7].
볼륨 밖의 `/tmp`와 `/tools`에 쓴 파일은 컨테이너 안에만 생겼다 [7].
컨테이너의 명령은 `analyst` 계정으로 실행되어 `/usr`와 `/` 바로 아래에 쓰려 한 `find -fprint`는 `Permission denied`로 끝났다 [7].

**한계.** 서버는 같은 이름의 컨테이너가 이미 있으면 그 컨테이너의 볼륨 설정을 확인하지 않고 다시 쓴다 [14].

```python
def unzip_file(ctx: Context, source_file: str, destination_dir: str) -> CommandRecordSummary:
    """Runs: unzip -X -K <SOURCE_FILE> -d /artifacts/<DESTINATION_FILE_NAME>"""
    if source_file.find("..") != -1 or destination_dir.find("..") != -1:
        raise RuntimeError("Invalid file path, Path traversal is not allowed")
    if not Path(source_file).is_file():
        raise FileNotFoundError("Source file not found")
    if not destination_dir.startswith("/artifacts/"):
        raise RuntimeError("Destination directory must be in /artifacts")
    return docker_manager.exec_stream(ctx=ctx, command_list=["unzip", "-X", "-K", source_file, "-d", destination_dir])
```
