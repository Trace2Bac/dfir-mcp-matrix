# F01 판단 지침

### F01.02 결론 서술 방식 안내

**구현.** 이 방식은 서버 지침(`instructions`)에 적용된다 [1].
서버는 `FastMCP`를 만들 때 조사 전에 할 일 3개와 분석 중에 지킬 규칙 4개를 적은 글을 `instructions`로 넘긴다 [1].
MCP 클라이언트 세션으로 받은 `initialize` 응답의 `instructions`에 이 글 1,040자가 실렸다 [2].
분석 중 규칙의 둘째 항목은 가정하지 말라고 적는다 [1].
같은 항목은 발견사항이 정상인지 악성인지 결론을 내릴 수 없으면 추가 조사가 필요하다고 명시해 표시하라고 적는다 [1].
첫째 항목은 발견사항마다 정상이든 악성이든 추가 조사가 필요하든 markdown 형식의 분석 메모를 만들라고 적는다 [1].
지침은 결론을 내리지 못한 발견사항을 분석 메모의 어느 값으로 표시할지는 적지 않는다 [1].
분석 메모의 `status`가 받는 값은 `benign`·`malicious`·`unknown`이고 이 목록은 `add_analyst_note`의 입력 schema에 `enum`으로 실린다 [3][2].
같은 schema는 `description`의 예시로 어느 명령을 실행해 찾았는지와 후속 분석이 필요하다는 점을 적은 글을 싣는다 [3][2].

지침의 나머지 항목은 조사 절차와 도구 사용 규칙이다 [1].
조사 전 항목은 증거 목록을 만들고 수집 경위를 사용자에게 묻고 앞서 실행한 명령과 분석 메모를 먼저 살피라고 적는다 [1].
분석 중 규칙의 셋째와 넷째 항목은 직접 만든 스크립트로 파일을 파싱하지 말고 파생물을 모두 `/artifacts` 아래에 저장하라고 적는다 [1].
지침에는 증거나 아티팩트가 무엇을 뜻하는지에 관한 원칙이 없다 [1].
분석 메모를 만들기 전에 근거가 된 명령 결과를 다시 확인하거나 다른 출처로 확인하라는 항목도 없다 [1].

도구 설명과 응답에는 판단에 관한 안내가 없다.
분석 메모 도구 `show_analyst_notes_summary`·`show_analyst_note`·`add_analyst_note`·`update_analyst_note`는 함수에 docstring이 없어 도구 설명이 빈 문자열이다 [4][2].
설명이 있는 도구 11개는 실행하는 명령의 모양, 인자의 뜻, 도구가 하는 일을 적는다 [2][5].
서버는 `mcp.add_tool`로 도구 18개만 등록하고 MCP 리소스와 프롬프트를 등록하지 않는다 [6].
`add_analyst_note`는 값을 돌려주지 않아 메모를 받은 응답에 보완할 점이 실리지 않는다 [4][2].
모델이 지침을 따랐는지는 서버가 확인하지 않는다.

### 근거

[1] 서버 지침의 글이다.

```python
mcp = FastMCP(
    "llm-forensics",
    auth=None,
    instructions="""\
You are a host forensics agent tasked with performing memory, disk, and artifact forensics.

Before beginning analysis always perform the following tasks:
1. Perform an inventory of all evidence, ask the user for specific details on how, when, and where the evidence was acquired
2. Review all previous commands that have already been run, commands should never be re-run unless the evidence has been updated or the commands were run incorrectly
3. Review all analyst notes to not perform duplicate analysis

While performing analysis follow these rules:
1. Create an analyst note (markdown format) after every finding whether benign, malicious, or if additional research is needed
2. Never make any assumptions, if a conclusion cannot be reached on whether a finding is benign or malicious explicitly mark it as needing additional research
3. Never use custom bash or python scripts to parse files, only use the built-in head/tail/regex/truncate options when going through command results
4. All artifacts should be saved under /artifacts
""",
)
```

`initialize` 응답의 `instructions`는 1,040자였다.
도구 목록에서 분석 메모 도구 4개와 `list_files`·`get_hash`·`get_command_history`의 `description`은 빈 문자열이었다.
`add_analyst_note`의 입력 schema에서 `status`는 `enum` `["benign", "malicious", "unknown"]`이었고 `description`에는 `examples`가 실려 있었다.
`add_analyst_note`의 응답은 `content`가 비어 있고 `structuredContent`가 `{"result": null}`이었다.

[3] 분석 메모의 필드와 schema에 실리는 예시다.

```python
class AnalystNote(BaseModel):
    title: str = Field(examples=["Found WannaCry ransomware executable"])
    status: Literal["benign", "malicious", "unknown"] = Field(examples=["malicious"])
    tags: list[str] = Field(examples=[["malware", "ransomware", "executable"]])
    description: str = Field(
        examples=[
            "# Found WannaCry ransomware executable\nFound WannaCry executable after running <COMMAND>, follow-on analysis needed"
        ]
    )
```

def show_analyst_notes_summary() -> list[AnalystNoteSummary]:
    return analyst_note_manager.note_list


def show_analyst_note(title: str) -> AnalystNote:
    return analyst_note_manager.get_note(title=title)


def add_analyst_note(note: AnalystNote) -> None:
    analyst_note_manager.add_note(note=note)


def update_analyst_note(title: str, note: AnalystNote) -> None:
    analyst_note_manager.update_note(title=title, note=note)
