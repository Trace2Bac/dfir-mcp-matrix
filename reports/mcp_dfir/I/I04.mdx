# I04 서버 자격증명 처리

### 비적용

**판단.** 서버 코드는 자격증명이 필요한 외부 연동을 하지 않는다.
심볼 도구는 `requests.get`에 주소만 넘기고 인증 헤더나 `auth` 인자를 주지 않는다 [1].
Microsoft 심볼 서버와 GitHub의 심볼 저장소 파일은 자격증명 없이 받았다 [2].
서버 코드는 환경변수를 읽지 않고 설정 파일도 읽지 않는다 [3].
기준 커밋의 `mcp_dfir/`에는 `environ`·`getenv`·`token`·`password`가 들어 있는 줄이 없다 [4].
Docker 데몬에는 `DockerClient()`가 실행하는 Docker CLI로 접속하고 서버 코드는 데몬 주소나 TLS 인증서를 넘기지 않는다 [5].
데몬에 접속할 수 있는지는 서버를 실행한 계정이 Docker 소켓에 가진 권한이 정한다.
이미지를 받을 때의 레지스트리 인증은 Docker CLI의 설정을 따르고 서버 코드는 자격증명을 넘기지 않는다 [5].
`FastMCP`에 넘기는 `auth=None`은 서버를 부르는 호출자의 인증 설정이다 [6].
requests 2.33.1은 `trust_env`가 참이고 요청에 `auth`가 없으면 사용자의 `.netrc`에서 그 호스트의 항목을 찾아 인증에 쓴다 [7].
서버 코드는 이 동작을 끄지 않는다 [1].
