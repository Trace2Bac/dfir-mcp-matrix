# I01 외부 연동 대상 관리

### I01.03 기본 활성화

**구현.** 이 방식은 서버 코드가 여는 연결 세 가지에 모두 적용된다 [1][2][3].
세 가지는 심볼 도구의 HTTP 요청, Docker 데몬 접속, 컨테이너 이미지 받기다.
연결을 켜거나 끄는 설정 파일, 환경변수, 시작 인자는 없다 [4].
심볼 도구 `download_windows_symbol`·`search_linux_symbols`·`download_linux_symbol`은 늘 도구 목록에 있고 모델이 부르면 `requests.get`으로 요청을 보낸다 [1].
`search_linux_symbols`는 심볼 맵 `symbols/linux/symbol_map.json`이 없을 때만 이 파일을 받는다 [1].
같은 사건 폴더에서 이 도구를 다시 불렀을 때 `symbol_map.json`의 수정 시각은 바뀌지 않았다 [5].
`download_windows_symbol`은 변환한 심볼 파일이 이미 있고 `overwrite`가 거짓이면 요청을 보내지 않고 예외로 끝난다 [6].
서버는 시작할 때 `DockerClient()`가 실행하는 Docker CLI로 데몬에 컨테이너 상태를 묻고 컨테이너를 시작하거나 만든다 [2].
그 뒤 실행 도구를 부를 때마다 `docker exec`가 데몬에 접속한다 [7][8].
python-on-whales 0.81.0의 `run`은 `pull` 기본값이 `missing`이어서 이미지가 로컬에 없으면 `docker image pull`을 먼저 실행한다 [3].
이미지가 이미 있는 호스트에서는 이미지를 받지 않는다 [3].
이미지 태그 상수를 Docker Hub에는 있고 로컬에는 없는 `0.1.1`로 바꿔 서버를 시작하자 `docker image pull`이 실행되어 이미지를 받았고 초기화 응답은 2.6초 뒤에 왔다 [9].
`--init`과 `--clear-case-dir`는 Docker를 다루는 모듈을 불러오기 전에 끝난다 [10].

### I01.05 고정 목적지

**구현.** 이 방식은 심볼 도구의 요청 주소와 컨테이너 이미지 이름에 적용된다 [11][12].
Microsoft 심볼 서버 주소 `https://msdl.microsoft.com/download/symbols`와 GitHub의 Linux 심볼 저장소 주소 `https://raw.githubusercontent.com/Abyss-W4tcher/volatility3-symbols/refs/heads/master`는 `constants.py`의 상수다 [11].
이 주소를 바꾸는 설정, 환경변수, 도구 인자는 없다 [4][11].
`download_windows_symbol`은 `pdb_name`·`guid`·`age`를 이 주소 뒤의 경로 `/<pdb_name>/<guid><age>/<pdb_name>`에 넣는다 [13].
`download_linux_symbol`은 `symbol_path`를 주소 뒤의 경로에 그대로 붙인다 [14].
`search_linux_symbols`가 받는 심볼 맵의 주소는 인자와 관계없이 `banners/banners_plain.json`이다 [1][11].
인자 값은 주소의 경로에만 들어가고 접속할 호스트는 바뀌지 않는다 [13][14][15].
이미지 이름은 `androsh7/forensics-docker:<VERSION>`이고 `VERSION`은 코드 상수 `0.1.2`다 [12].
이미지 이름에 레지스트리 호스트가 없으므로 받을 곳은 Docker가 기본으로 쓰는 레지스트리다 [12].
세 요청은 모두 `requests.get`에 주소만 넘긴다 [1].
requests 2.33.1은 이 경우 인증서를 확인하고 시간 제한 없이 응답을 기다리며 리다이렉트를 30번까지 따라간다 [16].
requests 2.33.1은 `trust_env`가 기본으로 참이어서 환경변수에 정한 프록시도 쓴다 [16].

**한계.** 서버는 경로에 넣는 인자를 검사하지 않는다 [13][14].
requests는 주소의 `..` 조각을 해석한 뒤 요청하므로 `symbol_path`에 `..`를 넣으면 같은 호스트의 다른 저장소 파일을 받는다 [15][17].
`symbol_path`를 `../../../../../volatilityfoundation/volatility3/9424c3a601edac0cb2c21d064a7e737c8741aa94/README.md`로 주자 Volatility 3 저장소의 `README.md`가 `symbols/linux/README.md`로 저장됐다 [17].
Microsoft 심볼 서버는 PDB 요청에 다른 호스트를 가리키는 302 응답을 돌려줬다 [18].
requests가 이 응답을 따라가므로 PDB 본문은 응답이 정한 호스트에서 받는다 [16][18].
서버 코드에는 리다이렉트 대상을 확인하는 처리가 없다 [13].

### I01.06 설정으로 목적지 지정

**구현.** 이 방식은 Docker 데몬 접속에 적용된다 [2].
서버는 `DockerClient()`를 인자 없이 만들어 접속할 데몬의 주소를 넘기지 않는다 [2].
python-on-whales 0.81.0은 `host`나 `context`를 받지 않으면 `docker` 명령에 `--host`와 `--context`를 붙이지 않는다 [19].
그래서 접속할 데몬은 Docker CLI의 설정과 환경변수 `DOCKER_HOST`가 정한다 [19][20].
`DOCKER_HOST`를 `tcp://127.0.0.1:1`로 주고 서버를 실행하자 Docker CLI가 그 주소로 접속하다 실패했고 서버 프로세스가 예외로 끝났다 [20].
도구 인자와 서버의 시작 인자에는 데몬 주소를 받는 것이 없다 [4].

    """Downloads a pdb file and returns the internal path"""
    guid = guid.replace("-", "")  # Normalize path

    output_file_name = f"{guid}_{pdb_name}"

    if response.status_code == HTTPStatus.NOT_FOUND:
        raise RuntimeError(
