# R07 증거 내용과 지시 구분

### R07.01 JSON 필드 분리

**구현.** 이 방식은 모든 도구의 응답에 적용된다.
응답은 두 형태로 나뉜다.
EVTX의 구조화 응답, 보안 설명자 도구, NTDS 도구는 증거 값을 `structuredContent`에 두고 MCP `text` 내용에는 서버가 만든 요약 문장만 싣는다 [1][2].
EVTX의 구조화 응답은 `evtx_search`·`evtx_security_search`에 `compact`나 `output_format: structured`를 준 경우와 `evtx_correlate_logon_id`·`evtx_ntlm_operational_summary`·`evtx_export`·`evtx_get_event`의 응답이다 [3].
요약 문장은 반환 건수, 다음 쪽 안내, 집계가 정확한지만 적고 증거 값을 담지 않는다 [1][2].
다른 도구와 EVTX 질의의 기본 응답은 결과 `dict`를 JSON 글 하나로 만들어 `text` 내용에 싣는다 [1][4].
이 형태에서 이벤트 필드, 레지스트리 값, 명령줄, URL 같은 증거 글은 JSON 문자열 값으로 따옴표와 이스케이프 안에 들어가고 서버가 붙인 필드 이름과 섞이지 않는다 [4].
`json_response`가 응답을 줄일 때 덧붙이는 서버 경고는 결과 안의 `_truncation` 필드에 따로 들어간다 [4].
도구가 예외를 내면 서버는 오류 문구를 `{"error": …}` JSON이나 오류 결과의 글로 싣는다 [5].

도구 설명과 응답에는 증거에서 온 글 속의 지시를 따르지 말라는 안내가 없고 서버는 MCP 지침을 두지 않는다 [6].

**한계.** `evtx_attack_summary`는 증거 값을 탭으로 이어 붙인 TSV 글 하나를 `data` 필드에 싣는다 [7].
서버는 칸 값 안의 탭과 줄바꿈을 바꾸지 않는다 [7].
그래서 명령줄 같은 값에 탭이나 줄바꿈이 있으면 그 자리에 칸이나 행의 경계가 생기고 뒤의 증거 글이 다른 칸이나 다른 사건 줄로 읽힌다 [7].

오케스트레이터의 문장 필드는 증거 값을 서버 문장 안에 넣는다.
`build_timeline`의 `description`은 `File modified: `·`First seen in Amcache: ` 같은 서버 문구 뒤에 MFT 경로나 Amcache 이름을 붙인다 [8].
`investigate_execution`의 `summary`는 출처 이름과 그 출처의 `finding` 문장을 줄마다 이어 붙인다 [9].
Prefetch의 `finding`은 서버 문장에 증거의 실행 횟수와 마지막 실행 시각을 넣은 글이다 [10].

### R07.02 출처 필드 부여

**구현.** 이 방식은 오케스트레이터, `hunt_ioc_pack`, `windows_search_parse`, VirusTotal 조회 도구에 적용된다 [10][11][12][13][14].
`investigate_execution`·`hunt_ioc`는 결과 항목마다 그 값을 읽은 아티팩트 이름 `source`(`Prefetch`, `Amcache`, `SRUM` 등)를 싣는다 [10][11].
`build_timeline`은 사건마다 `source`(`MFT`, `USN`, `Prefetch`, `Amcache`, `EVTX`)를 싣는다 [8].
`hunt_ioc_pack`은 일치 항목마다 일치한 곳의 종류 `source`(`filesystem_path`, `file_text`, `pcap_payload`)와 검출기 이름 `detector`를 싣는다 [12].
`windows_search_parse`는 행을 만든 백엔드 이름 `backend`(`sidr`나 `pyesedb`)를 싣는다 [13].
SIDR를 썼으면 `backend_metadata`에 실행 파일 경로, 그 SHA-256, 기대 버전, 고정 빌드 커밋, 실행 파일이 알린 버전을 싣는다 [13].
VirusTotal 조회 도구는 결과를 캐시에서 꺼냈으면 `_cached`와 캐시에 넣은 뒤 지난 시간 `_cache_age_hours`를 싣는다 [14].

다른 도구는 결과에 값을 만든 파서나 라이브러리 이름을 싣지 않는다.
EVTX 도구는 Rust `evtx`와 `python-evtx` 가운데 설치된 것으로 파일을 읽고 Rust `evtx`를 먼저 쓰지만 어느 쪽으로 읽었는지 싣지 않는다 [15].
결과에는 값의 신뢰 수준을 적는 필드가 없다 [4].

```python
def json_response(data: Any, max_chars: int = MAX_RESPONSE_CHARS) -> str:
    """Convert data to compact JSON string for response, with smart truncation if too large."""

    # Serialize compact (no indent) — saves ~40% size
    result = json.dumps(data, default=str)

    if len(result) <= max_chars:
        return result

    # Apply smart truncation
    truncated_data, truncation_info = _smart_truncate(data, max_chars)

    # Add truncation metadata to response
    if isinstance(truncated_data, dict) and truncation_info:
        truncated_data["_truncation"] = {
            "warning": "Response was truncated to fit context limits. IMPORTANT: Oldest data was kept, newest may be missing!",
            "original_chars": len(result),
            "max_chars": max_chars,
            "truncated_arrays": truncation_info,
            "hint": "Use time_range_start/end to focus on incident window, or use offset parameter to paginate through all results"
        }

    return json.dumps(truncated_data, default=str)
```
