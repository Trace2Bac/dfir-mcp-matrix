# R06 증거에서 추출한 민감정보 노출 제어

### R06.01 값 가림·필드 제외

**구현.** 이 방식은 NTDS 도구 4개 `ntds_get_object_by_sam`·`ntds_get_object_sid`·`ntds_get_domain_info`·`ntds_get_trusts`에 적용된다 [1].
NTDS 파서는 읽을 속성을 논리 이름과 물리 열 이름의 짝으로 고정한 허용 목록 `_ATTRS`로 정한다 [1].
이 목록에는 이름, SAM 계정 이름, SID, 객체 클래스, 삭제 여부, 도메인·신뢰 관계 속성만 있고 비밀번호 해시나 신뢰 인증 비밀을 담는 열은 없다 [1].
코드 주석은 손상된 스키마가 논리 속성을 자격증명 열로 바꾸어 가리키지 못하게 물리 열 이름을 고정했다고 적는다 [1].
스키마 레코드가 목록과 다른 열 번호를 알리면 서버는 그 레코드를 스키마 오류로 세고 그 속성을 읽을 목록에 넣지 않는다 [2].
레코드를 읽을 때는 이 목록과 구조 열만 읽고 행 전체를 꺼내지 않는다 [3].
`ntds_get_object_by_sam`의 `fields`는 `dnt`·`dn`·`name`·`sam_account_name`·`object_sid`·`object_classes`·`deleted`·`recycled` 가운데에서만 고를 수 있다 [4].
도구 설명은 자격증명 속성을 내보내지 않고 신뢰 인증 비밀을 빼고 싣는다고 적는다 [5].

이 제외는 NTDS 도구에만 적용된다.
레지스트리 도구는 키의 값을 이름, 형식, 자료 그대로 싣고 가리는 처리를 두지 않는다 [6].
`registry_get_key`로 SAM 하이브의 사용자 키를 읽으면 암호화된 비밀번호 해시를 담은 `V` 값이 16진 문자열로 실린다 [7].
같은 도구로 SECURITY 하이브의 `Policy\Secrets` 아래를 읽으면 LSA secret의 `CurrVal` 값도 실린다 [7].
`registry_get_users`는 SAM 사용자 키의 `F` 값에서 시각, 로그인 횟수, 계정 플래그만 꺼내고 `V` 값을 읽지 않는다 [8].
