# R04 도구 결과 해석 주의

### R04.01 도구별 정적 주의

**구현.** 이 방식은 일부 도구의 도구 설명과 응답의 고정 필드에 적용된다.
`windows_search_parse`의 설명은 추출이 완전하지 않은 상태의 0건 결과는 결론이 아니라고 적는다 [1].
`disk_parse_srum`의 설명은 자원 카운터를 실행 시간으로 해석하지 않는다고 적는다 [2].
`registry_get_usb_history`의 설명은 `first_connected`가 USBSTOR 키의 마지막 쓰기 시각이라고 적는다 [3].
응답도 장치마다 `first_connected_source`에 `usb_stor_key_last_write`를 싣는다 [4].
`evtx_correlate_logon_id`의 설명은 로그온 ID가 같다는 것만으로 호스트나 재부팅을 넘어 같은 세션이라고 할 수 없다고 적는다 [5].
`security_descriptor_decode`의 설명은 실제 접근 권한을 추론하지 않는다고 적는다 [5].
`ntds_get_domain_info`의 설명은 로컬 도메인 판정에 관계와 활성 상태의 불확실성이 남는다고 적는다 [6].
`evtx_ntlm_operational_summary`의 `unusual_only` 인자 설명은 빈도가 낮다는 것이 공격 판정이 아니라고 적는다 [7].

결과와 관계없이 응답에 늘 붙는 문구도 있다.
`evtx_ntlm_operational_summary`의 응답은 `rarity_note`에 같은 문구를, `rarity_basis`에 빈도를 센 기준을 싣는다 [8].
`windows_search_parse`의 응답은 `completeness_scope`에 이 결과가 파서 추출 범위만 말하고 Windows Search가 모든 파일을 색인하지는 않는다고 적는다 [9].

`file_analyze_pe`의 도구 설명과 `check_signatures` 인자 설명은 `Authenticode metadata`를 싣는다고만 적는다 [10].
응답의 `authenticode`에는 서명을 검증하지 않았다는 필드나 문구가 없다 [11].
신뢰 여부를 판단하지 않는다는 말은 `get_authenticode_info`의 docstring에만 있고 도구 명세에는 없다 [11][10].

서버는 MCP 리소스·프롬프트와 서버 지침을 두지 않는다 [12].

**한계.** SRUM 자원 카운터에 대한 주의는 `disk_parse_srum`의 설명에만 있다 [2].
같은 SRUM 기록을 읽는 `investigate_execution`의 설명은 실행 파일이 얼마나 실행되었는지 답한다고 적는다 [13].
이 도구는 포그라운드 cycle time의 합을 초로 바꿔 `Foreground time`으로 응답에 싣고 해석 주의를 붙이지 않는다 [14].

### R04.02 결과 조건별 주의

**구현.** 이 방식은 `windows_search_parse`, NTDS 도메인 조회, EVTX 구조화 응답에 적용된다 [15][16][17].
`windows_search_parse`는 SIDR가 없어 `pyesedb` 대체 파서를 쓰면 진단 목록에 긴 값과 압축된 검색 내용을 읽지 못하므로 0건이 결론이 아니라는 문구를 넣는다 [15].
SIDR 기록이 데이터베이스가 정상 종료되지 않았다고 알리면 결과가 부정확하거나 불완전할 수 있다는 문구를 넣는다 [18].
분석 중에 원본 파일의 해시가 바뀌면 결과를 믿을 수 없다는 문구를 넣는다 [19].
`ntds_get_domain_info`는 로컬 도메인 연결을 찾았지만 연결의 활성 상태나 읽기 완료를 확인하지 못하면 `local_domain.status`를 `candidate`로 두고 그 이유를 `reason`에 적는다 [16].
연결을 하나로 정하지 못하면 `status`를 `unknown`으로 두고 이유를 적는다 [16].
`forest_root`는 읽기가 끝나지 않았거나 `configuration` 객체와 도메인 `crossRef`의 연결을 하나로 정하지 못하면 `status`를 `unknown`으로 두고 `reason`에 완전하고 모호하지 않은 연결이 없다고 적는다 [20].
루트 도메인과 이름이 같은 신뢰 객체의 SID가 루트 도메인의 SID와 다르면 `unknown`으로 두고 `reason`에 그 모순을 적는다 [20].
EVTX 구조화 응답의 첫 글 블록은 일치 수가 정확하지 않을 때 그 수가 하한이라고 적는다 [17].
NTLM 요약에서는 그 수가 하한도 아닐 수 있으므로 정확하지 않다고만 적는다 [17].

**한계.** `windows_search_parse`의 대체 파서 경로는 데이터베이스 상태를 확인하지 않아 `database_state`가 `unknown`으로 남는다 [9][15].
이 경로에서는 데이터베이스가 정상 종료되지 않은 경우의 문구가 붙지 않는다 [15][18].

    unknown = {'status': 'unknown', 'domain_dn': None, 'dns_name': None, 'object_sid': None, 'evidence': [],
               'reason': 'A complete, unambiguous configuration/domain cross-reference chain is unavailable'}
    if not complete:
        return unknown
    configurations = [node for node in snapshot['nodes'].values() if _live(node) and _class(node, 'configuration')]
    if len(configurations) != 1:
        return unknown
    root_candidates = [domain for domain in domains if domain['dnt'] == configurations[0]['parent']]
    if len(root_candidates) != 1:
        return unknown
    root = root_candidates[0]
    if root['crossref_dnt'] is None or root['crossref_ambiguous'] or root['trust_parent_dnt'] is not None or root['root_trust_dnt'] is not None or not root['object_sid']:
        return unknown
