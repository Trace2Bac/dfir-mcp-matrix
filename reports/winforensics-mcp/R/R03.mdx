# R03 분석 상태 알림

### R03.01 구조화 status·error

**구현.** 이 방식은 서버 호출 처리기 `call_tool`과 MCP Python SDK 1.25.0의 입력 검사에 적용된다 [1][2].
`call_tool`은 EVTX·NTDS·보안 설명자 도구 12개에서 예외가 나면 `evtx_error_response`로 `isError`가 참인 결과를 돌려준다 [1][3].
이 결과의 글은 예외 문구를 800자 안에서 줄인 것이다 [3].
나머지 도구에서 예외가 나면 `call_tool`은 `{"error": "<예외 문구>"}` 글 블록 하나를 돌려준다 [1].
SDK는 목록에 오른 도구의 인자를 `inputSchema`로 검사하고 맞지 않으면 도구를 부르지 않고 `isError`가 참인 결과를 돌려준다 [2].
SDK는 서버 처리기가 돌려준 `CallToolResult`는 그대로, 글 블록 목록은 `isError`가 거짓인 결과로 내보낸다 [2].

여러 파서와 처리 분기도 실패를 결과 `dict`의 `error` 필드에 싣는다 [4].
선택 라이브러리가 없을 때, `diec`가 60초 안에 끝나지 않을 때, VirusTotal 조회가 실패할 때가 그런 경우다 [4].
NTDS 도구는 결과의 상태를 `status` 필드에 싣는다 [5].

**한계.** `isError`는 EVTX·NTDS·보안 설명자 도구 12개의 예외와 SDK 입력 검사 실패에만 쓰인다 [1][2].
나머지 62개 도구의 실패는 `isError`가 거짓인 결과로 나가고 `error` 필드로만 성공과 갈린다 [1][6].
목록에 없는 도구 이름도 SDK가 검사하지 않고 처리기로 넘기며 처리기는 `{"error": "Unknown tool: …"}`를 `isError`가 거짓인 결과로 돌려준다 [2][6][7].
`error` 필드는 문구만 담고 실패 종류를 가르는 값은 없다 [1][4].

### R03.02 찾지 못함과 실패 구분

**구현.** 이 방식은 NTDS 도구, EVTX 질의, 오케스트레이터의 원천별 결과에 적용된다.
NTDS 계정·도메인 조회는 `status`를 `found`·`not_found`·`ambiguous`·`incomplete` 가운데 하나로 싣는다 [5].
읽기가 끝까지 되지 않았거나 스키마·데이터베이스 상태를 확인하지 못하면 찾지 못했더라도 `not_found`가 아니라 `incomplete`가 된다 [5][8].
EVTX 질의는 일치가 없으면 `events`가 빈 정상 결과를 돌려주고 파일을 읽지 못하면 `isError`가 참인 결과를 돌려준다 [1][9].
`hunt_ioc`는 원천마다 쓸 수 없음(`available` 거짓), 검색하지 않음(`searched` 거짓), 일치 없음(`found` 거짓), 예외(`error`)를 필드로 나눠 싣는다 [10].
`windows_search_parse`는 일치 0건을 `matched_records` 0으로, 실패를 `error`와 `complete` 거짓으로 싣는다 [11].
`registry_get_network`는 인터페이스 키를 열거나 읽다가 예외가 나면 그때까지 모은 목록을 오류 표시 없이 돌려준다 [12].

**한계.** `hunt_ioc`의 요약 목록과 요약 문장은 예외가 난 원천을 일치가 없는 원천과 같이 다룬다 [13].
예외 결과도 `searched`가 참이고 `found`가 거짓이므로 `sources_searched_no_match`에 들어간다 [10][13].
`investigate_execution`의 요약 문장도 예외가 난 원천을 "증거를 찾지 못한" 원천으로 적는다 [14].
손상된 `Amcache.hve`로 두 도구를 부르자 원천 항목에는 `error`가 실렸지만 요약은 `hunt_ioc`가 "not found in any of the 1 sources searched", `investigate_execution`이 "No execution evidence found … in Amcache"였다 [15].
`hunt_ioc`의 EVTX 원천은 파일을 읽다가 예외가 나면 그 파일을 건너뛰고 오류를 싣지 않는다 [16].
그래서 EVTX 파일을 모두 읽지 못한 경우도 일치 없음과 같은 결과가 된다 [16].
`build_timeline`의 EVTX 원천은 늘 사건을 0건 만들고 상태를 `processed`로 적으므로 일치 없음과 처리 실패가 갈리지 않는다 [17][18].

### R03.03 입력별 성공·실패·생략 목록

**구현.** 이 방식은 여러 원천이나 입력을 한 번에 처리하는 도구에 적용된다.
`hunt_ioc`는 원천마다 결과 항목을 싣고 일치가 있는 원천·검색했지만 일치가 없는 원천·쓸 수 없는 원천을 이름 목록으로 나눠 싣는다 [10][13].
검색하지 않은 원천(YARA를 켜지 않은 경우, 그 원천이 지원하지 않는 IOC 종류)은 `searched` 거짓과 `note`로 표시한다 [10].
`investigate_execution`은 Prefetch·Amcache·SRUM마다 `available`·`found`·`error`를 싣는다 [14].
`build_timeline`은 원천마다 `processed`·`not found`·`error: …` 상태를 `sources_info`에 싣는다 [17].
`remote_collect_artifacts`는 수집한 아티팩트마다 `success`·`local_path`·`size_bytes`·`error`를 싣는다 [19].
`disk_parse_prefetch`의 폴더 결과는 파싱하지 못한 파일마다 경로와 오류를 `errors`에 싣는다 [20].
`registry_get_persistence`는 하이브마다 읽지 못하면 `software_error`·`winlogon_error`·`ntuser_error`·`system_error`를 따로 싣고 읽은 하이브의 결과는 함께 돌려준다 [21].

**한계.** `build_timeline`은 원천의 사건 생성기가 예외를 스스로 처리해 아무것도 내지 않아도 상태를 `processed`로 둔다 [17][18].
`yara_scan_directory`는 파일별 오류를 앞 10개만 싣고 오류의 전체 수는 싣지 않는다 [22].

### R03.04 시간 초과·부분 완료 표시

**구현.** 이 방식은 읽기 상한이 있는 EVTX·NTDS 도구, `evtx_export`, `windows_search_parse`, `pcap_get_stats`에 적용된다 [8][9][11][23][24].
EVTX 질의는 파일 끝까지 읽었는지 `scan_complete`, 읽기 상한에 닿았는지 `scan_limit_hit`, 파싱하지 못한 레코드 수 `parse_errors`를 싣는다 [9].
`evtx_export`는 읽기 상한, 행 상한 `max_rows`, 파싱 오류, 시간 조건 오류가 없을 때만 `export_complete`를 참으로 둔다 [23].
NTDS 도구는 `scan_complete`·`schema_complete`·`database_clean`이 모두 참이고 파싱 오류가 없을 때만 `results_complete`를 참으로 둔다 [8].
`windows_search_parse`는 SIDR 실행이 시간 제한 `timeout`을 넘거나 실패하면 `error`를 싣고 `complete`를 거짓으로 둔다 [11].
SIDR 기록에 오류나 경고가 있거나, 데이터베이스가 정상 종료되지 않은 상태이거나, 대체 파서를 썼을 때도 `complete`를 거짓으로 둔다 [11][25].
`pcap_get_stats`는 패킷 수가 `max_packets`를 넘으면 `truncated`를 참으로 두고 분석한 패킷 수를 싣는다 [24].

**한계.** 같은 `MAX_SCAN_EVENTS`(100,000개) 읽기 상한을 쓰는 `evtx_get_stats`·`evtx_attack_summary`·`hunt_ioc`·`build_timeline`의 EVTX 경로는 상한에 닿았는지 싣지 않는다 [26].
`die_analyze_file`·`die_scan_directory`의 `diec` 시간 초과는 `error` 문구로만 알린다 [4].

```python
def _generate_summary(
    target: str,
    execution_confirmed: bool,
    confidence: str,
    evidence_results: list[dict],
) -> str:
    """Generate human-readable summary"""
    if not execution_confirmed:
        sources_searched = [r["source"] for r in evidence_results if r.get("available", True)]
        return f"No execution evidence found for '{target}' in {', '.join(sources_searched)}"

    findings = []
    for result in evidence_results:
        if result.get("found") and result.get("finding"):
            findings.append(f"- {result['source']}: {result['finding']}")

    summary = f"Execution of '{target}' confirmed ({confidence} confidence):\n"
    summary += "\n".join(findings)

    return summary
```
