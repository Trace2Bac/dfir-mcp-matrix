# E02 증거 무결성 검증

### E02.01 등록 시 기준값 자동 계산

**구현.** 이 방식은 `windows_search_parse`와 EVTX·NTDS 파일을 읽는 도구에 적용된다 [1][2][3].
`windows_search_parse`는 받은 `Windows.edb`를 복사하기 전에 모델의 요청 없이 파일 전체의 SHA-256을 계산한다 [1].
이 값은 응답의 `evidence_sha256_before`에 실리고 서버에 따로 보관하지 않는다 [1][4].

EVTX·NTDS 파일을 읽는 도구는 파일을 읽기 전에 상태 값 묶음을 계산한다 [2][3].
묶음은 실제 경로, 크기, 수정 시각 `st_mtime_ns`, 장치 번호, inode, 변경 시각 `st_ctime_ns`이고 내용 해시는 들어 있지 않다 [2][3].
서버는 이 묶음을 파싱 결과 캐시의 키로 쓴다 [5].
묶음의 SHA-256은 사건 참조 `event_ref`와 이어 읽기 커서 안의 `query_ref`에 들어간다 [2][6].
NTDS 응답과 `evtx_describe_security_descriptor` 응답은 같은 SHA-256을 `source_ref`로 싣는다 [3][7].
EVTX 조회 응답의 `source`에는 경로, 크기, 수정 시각만 실린다 [6].

`file_analyze_pe`와 `vt_lookup_file`은 받은 파일의 MD5·SHA1·SHA256을 계산해 응답에 싣는다 [8][9].
서버는 이 값을 보관하거나 다시 대조하지 않는다.

**한계.** 두 기준값 모두 도구를 부를 때마다 그 시점의 파일에서 새로 계산한다 [1][2].
그래서 서버가 읽기 전에 바뀐 증거는 바뀐 상태가 기준값이 된다.
EVTX·NTDS 도구를 커서나 `event_ref` 없이 새로 부르면 그때의 상태 값 묶음이 새 기준값이 된다 [6].
`windows_search_parse`의 SHA-256은 그 호출 안에서만 쓰이고 다음 호출과 대조하지 않는다 [1].

### E02.03 도구 호출 중 자동 검증

**구현.** 이 방식은 EVTX 파일을 읽는 도구, NTDS 도구, `windows_search_parse`에 적용된다 [5][10][11].
EVTX 파일을 읽는 도구는 모두 파싱 결과 캐시를 거친다 [5].
캐시를 채운 뒤에는 상태 값 묶음을 다시 읽어 읽기 전 값과 비교한다 [5].
조회 도구는 결과 행을 꺼내기 전과 꺼낸 뒤에도 같은 비교를 한다 [12].
이어 읽기 커서와 `event_ref`를 받으면 그 안의 값을 지금 파일의 묶음에서 만든 값과 비교한다 [6][13].
`evtx_export`는 질의를 준비한 뒤, 파일을 다 쓴 뒤, 파일을 새 이름으로 내기 직전과 낸 뒤에 묶음을 비교한다 [14].
`evtx_describe_security_descriptor`는 사건 값을 읽기 전후에 비교한다 [7].
NTDS 도구는 데이터베이스를 다 읽은 뒤와 캐시에서 꺼낸 뒤에 비교한다 [3][10].
`ntds_get_trusts`의 커서는 묶음을 담은 `query_ref`로 비교한다 [10].

`windows_search_parse`는 복사본의 SHA-256을 복사 전 값과 비교한다 [1].
파싱을 마치면 원본의 SHA-256을 다시 계산해 복사 전 값과 비교하고 결과를 `evidence_sha256_after`와 `evidence_unchanged`에 싣는다 [11].

레지스트리 하이브, MFT, USN 저널, Prefetch, Amcache, SRUM, 브라우저 기록, LNK, PE, pcap을 읽는 도구는 증거를 기준값과 비교하지 않는다.

실행 확인에서 EVTX 파일의 수정 시각만 바꾸자 앞서 받은 커서와 `event_ref`가 모두 거부되었다 [15].
내용 1바이트를 바꾼 뒤 수정 시각을 되돌린 파일도 변경 시각이 달라져 커서가 거부되었다 [15].

**한계.** EVTX·NTDS 도구의 비교는 상태 값만 보고 내용을 다시 해시하지 않는다 [2][3].
그래서 상태 값 묶음이 같은 채 내용이 바뀌면 알아채지 못한다.
상태 값 묶음이 캐시 키와 같으면 파일을 다시 읽지 않고 앞서 파싱한 결과를 쓴다 [5].

### E02.05 불일치 시 중단·경고

**구현.** 이 방식은 위의 비교가 어긋날 때 적용된다.
EVTX·NTDS 도구는 `ValueError`를 내고 그 호출을 끝낸다 [5][6][13].
문구는 "EVTX source changed during scan; retry the query", "Cursor source or query changed; restart without a cursor", "event_ref belongs to a different or changed source" 같은 것이다 [5][6][13].
`call_tool`은 EVTX 조회·내보내기·보안 설명자 도구와 NTDS 도구 12개의 예외를 `isError`가 참인 응답으로 돌려준다 [16][17].
`evtx_get_stats`와 `evtx_attack_summary`의 같은 예외는 `isError` 없이 `{"error": …}` 글로 돌아간다 [16].
`evtx_export`는 비교가 어긋나면 임시 파일과 이미 낸 파일을 지우고 결과 파일을 남기지 않는다 [14].

`windows_search_parse`는 복사본 해시가 다르면 기록을 읽지 않고 응답의 `error`에 "Evidence changed while copying; retry from a stable copy"를 싣는다 [1][18].
파싱 뒤 원본 해시가 다르면 `complete`를 거짓으로 두고 진단에 "Evidence hash changed during parsing; results are unreliable"을 더한다 [11].
이 응답은 `isError` 없는 일반 응답이고 이미 고른 기록도 그대로 싣는다 [11][18].

불일치는 응답으로만 알린다.
서버는 불일치를 기억하지 않으므로 커서 없이 다시 부르면 그때 상태를 기준으로 조회가 실행된다 [6].

def get_file_hashes(file_path: Path) -> dict[str, str]:
    """Calculate MD5, SHA1, SHA256 hashes of a file"""
    md5 = hashlib.md5()
    sha1 = hashlib.sha1()
    sha256 = hashlib.sha256()

    with open(file_path, "rb") as f:
        while chunk := f.read(65536):
            md5.update(chunk)
            sha1.update(chunk)
            sha256.update(chunk)

    return {
        "md5": md5.hexdigest(),
        "sha1": sha1.hexdigest(),
        "sha256": sha256.hexdigest(),
    }

def get_evtx_event(evtx_path: str | Path, event_ref: str, include_raw: bool = False) -> dict[str, Any]:
    """Return a normalized event within the first 1,000,000 physical records.

    Backend raw text is included only when include_raw is explicitly true.
    """
    check_evtx_available()
    if type(include_raw) is not bool:
        raise ValueError("include_raw must be a boolean")
    path = Path(evtx_path)
    source = _cache_key(path)
    decoded = _decode_token(event_ref, "event_ref")
    if set(decoded) != {"v", "s", "r"} or decoded["s"] != _digest(source):
        raise ValueError("event_ref belongs to a different or changed source")
    _validate_integer(decoded["r"], "event_ref record", 1)
    ordinal = decoded["r"]
    if ordinal > 1_000_000:
        raise ValueError("event_ref record exceeds the detail lookup limit of 1000000")
    # Prefer an existing scan; on a cache miss, stop at the referenced record.
    cached = next((entry for key, entry in reversed(_evtx_cache.items())
                   if key[:-2] == source and key[-1] == EVTX_RUST_AVAILABLE
                   and ordinal in entry.ordinals), None)
    if cached is None:
        cached = _get_cached(path, ordinal)
    try:
        index = cached.ordinals.index(ordinal)
    except ValueError as exc:
        raise ValueError("event_ref does not identify a readable record") from exc
    if _cache_key(path) != source:
        raise ValueError("EVTX source changed during lookup; retry the query")
