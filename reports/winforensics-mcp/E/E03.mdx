# E03 원본 변경 방지

### E03.02 서버 코드의 원본 쓰기 제한

**구현.** 이 방식은 서버 코드가 증거 파일을 직접 여는 경로에 적용된다.
이 경로에서 서버 코드는 증거를 읽기 모드로만 연다.
브라우저 기록 도구는 SQLite DB를 `mode=ro` URI로 연다 [1].
NTDS 도구는 ESE 헤더를 `rb`로 읽는다 [2].
`windows_search_parse`는 원본을 `rb`로 읽어 해시하고 `shutil.copyfile`로 사본을 만든다 [3].
USN 저널, LNK 헤더, PE, APMX, CSV를 읽는 코드와 IoC 묶음 검색, `vt_lookup_file`의 해시 계산도 `rb`·`r`나 `read_bytes`로 읽는다 [4].
증거를 읽는 이 경로들에는 파일을 쓰는 호출이 없다 [4].

파일을 쓰는 도구는 `evtx_export`, `remote_collect_artifacts`, `triage_dir`를 받은 `vt_lookup_behavior`다 [5][6][7].
세 도구 모두 출력 폴더가 증거 폴더와 겹치는지 확인하지 않는다 [5][6][7].
`evtx_export`는 같은 폴더에 임시 파일을 만든 뒤 새 이름에 링크를 거는 방식으로 내므로 이미 있는 파일을 덮어쓰지 않는다 [5].
`remote_collect_artifacts`는 `output_dir` 아래 `evtx/Security.evtx`, `registry/SYSTEM` 같은 정해 둔 이름에 `write_bytes`로 써서 같은 이름의 파일을 덮어쓴다 [6].
`vt_lookup_behavior`는 `triage_dir` 아래 `vt-behavior-<해시 앞 12자>.json`에 `write_text`로 써서 같은 이름의 파일을 덮어쓴다 [7].

`remote_collect_artifacts`가 읽는 원격 대상의 파일에는 변경을 막는 장치가 없다 [8].
이 도구는 대상에서 PowerShell로 파일을 `ReadAllBytes`로 읽는다 [8].
읽기에 실패하면 대상의 `C:\` 볼륨에 VSS 섀도 복사본을 만들고 설치 시각이 가장 늦은 섀도 복사본에서 파일을 읽은 뒤 그 섀도 복사본을 지운다 [8].
스크립트는 섀도 복사본 만들기의 결과를 확인하지 않는다 [8].
그래서 만들기가 실패하면 대상에 이미 있던 가장 최근 섀도 복사본을 읽고 지우는 흐름이 된다 [8].
이 수집 경로는 실행해 확인하지 않았다.

**한계.** 브라우저 기록 도구는 `browser`가 기본값 `auto`이면 종류를 판별하려고 사본이 아닌 원본 DB를 `mode=ro`로 연다 [1][9].
실행 확인에서 WAL 모드 DB를 이렇게 열자 원본 폴더의 `-shm` 파일 내용이 바뀌었다 [10].
`-shm`이 없던 경우에는 원본 폴더에 새 `-shm` 파일이 생겼다 [10].
DB 파일과 `-wal` 파일은 바뀌지 않았다 [10].
`browser`를 `chrome`으로 지정한 호출에서는 원본 폴더의 파일이 바뀌지 않았다 [10].
`hunt_ioc`는 찾은 브라우저 기록을 늘 `browser="auto"`로 넘긴다 [11].

### E03.03 외부 도구·플랫폼에 위임

**구현.** 이 방식은 증거 파일 경로를 파서 라이브러리나 외부 실행 파일에 넘기는 도구에 적용된다.
이 도구들의 서버 코드는 원본을 직접 열지 않고 경로를 넘긴다 [12].
원본을 지키는 것은 서버 개요의 버전 기준대로 설치된 라이브러리가 파일을 읽기 모드로 연다는 동작이다.

레지스트리·Amcache·ShellBags 도구는 `python-registry` 1.3.1의 `Registry.Registry`에 경로를 넘긴다 [12].
이 라이브러리는 파일을 `rb`로 열어 내용 전체를 메모리로 읽는다 [13].
EVTX 도구는 `evtx` 0.11.0의 `PyEvtxParser`에, `disk_parse_mft`는 `mft` 0.7.0의 `PyMftParser`에 경로를 넘긴다 [12].
두 Rust 바인딩은 경로를 받으면 읽기 전용인 `File::open`으로 연다 [14].
Prefetch 도구는 `libscca-python`의 `pyscca`에, SRUM·NTDS 도구는 `libesedb-python`의 `pyesedb`에 경로를 넘긴다 [12].
두 바인딩의 `open`은 모드를 주지 않으면 `'r'`로 연다 [15].
PE 도구는 `pefile` 2024.8.26에 경로를 넘기고 `pefile`은 `rb`로 연 파일을 메모리에 매핑한다 [12][16].
Unix에서는 `MAP_PRIVATE`로, Windows에서는 `ACCESS_READ`로 매핑하므로 메모리의 변경이 파일에 쓰이지 않는다 [16].
LNK 도구는 `pylnk3` 0.4.3에, pcap 도구는 `scapy` 2.7.0의 `PcapNgReader`·`PcapReader`에 경로를 넘기고 두 라이브러리는 `rb`로 연다 [12][16].
YARA 도구는 `yara-python` 4.5.4의 `match`에 경로를 넘기고 libyara는 파일을 `O_RDONLY`로 열어 매핑한다 [12][16].
DiE 도구는 `diec` 명령에 경로를 인자로 넘긴다 [17].
`windows_search_parse`는 SIDR에 원본이 아니라 임시 폴더의 사본이 들어 있는 폴더를 넘긴다 [18].

증거를 읽기 전용으로 마운트하거나 서버를 읽기 전용 환경에서 실행하는 경로는 저장소에 없다.

**한계.** `pyscca`와 `pyesedb`는 바인딩의 기본 모드가 `'r'`인 것까지 확인했고 libyal C 라이브러리가 그 모드로 파일을 여는 코드는 소스로 확인하지 않았다 [15].
Detect It Easy 3.21의 `diec`가 파일을 읽기 모드로 여는지는 소스로 확인하지 못했다 [17].
그래서 `die_analyze_file`·`die_scan_directory` 경로의 실제 보호는 확인하지 못했다(실제 보호 미확인) [17].

```python
def _sha256(path: Path) -> str:
    digest = hashlib.sha256()
    with path.open("rb") as stream:
        for block in iter(lambda: stream.read(1024 * 1024), b""):
            digest.update(block)
    return digest.hexdigest()
```
