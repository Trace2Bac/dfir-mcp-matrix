# E01 증거 등록 관리

### 미구현

**판단.** 서버는 이벤트 로그, 레지스트리 하이브, `$MFT`, Prefetch, SRUM, NTDS, PE, pcap 같은 증거 파일과 수집물 폴더를 도구마다 경로 인자로 받아 그 호출에서만 읽는다 [1].
증거를 등록하는 MCP 도구는 없고 증거를 식별하는 목록이나 등록 정보도 남기지 않는다.

EVTX 도구와 NTDS 도구는 읽은 파일의 파싱 결과를 서버 메모리 캐시에 둔다 [2][3].
캐시 항목의 키는 파일의 실제 경로, 크기, 수정 시각, 장치 번호, inode, 변경 시각과 읽은 레코드 상한이다 [2][3].
EVTX 캐시는 10개, NTDS 캐시는 2개를 넘으면 오래된 항목부터 지운다 [2][3].
이 캐시는 같은 파일을 다시 파싱하지 않으려고 두는 것이고 캐시 내용을 돌려주는 도구가 없다.
그래서 이 캐시는 증거 등록 목록에 해당하지 않는다.

`evtx_list_files`는 받은 폴더 아래 `.evtx` 파일마다 경로, 이름, 크기, 수정 시각을 응답으로 돌려주고 저장하지 않는다 [4].

서버가 시작하는 수집도 서버 쪽 목록에 오르지 않는다.
`remote_collect_artifacts`는 WinRM으로 대상 Windows의 정해 둔 이벤트 로그 8개와 레지스트리 하이브 5개를 읽어 `output_dir` 아래 `evtx`·`registry` 폴더에 쓴다 [5][6].
응답은 항목마다 이름, 성공 여부, 로컬 경로, 크기, 오류를 싣고 이 목록을 파일로 남기지 않는다 [5].
수집 결과 객체 `CollectionResult`에 있는 원격 경로와 수집 시각 `timestamp`는 응답에 싣지 않는다 [5][7].

```python
def _get_cached(evtx_path: Path, max_scan: int = MAX_SCAN_EVENTS) -> _EvtxCacheEntry:
    source = _cache_key(evtx_path)
    key = source + (max_scan, EVTX_RUST_AVAILABLE)
    if key not in _evtx_cache:
        entry = _populate_cache(evtx_path, max_scan)
        if _cache_key(evtx_path) != source:
            raise ValueError("EVTX source changed during scan; retry the query")
        _evtx_cache[key] = entry
    _evtx_cache.move_to_end(key)
    while len(_evtx_cache) > MAX_CACHE_FILES:
        _evtx_cache.popitem(last=False)
    return _evtx_cache[key]
```
