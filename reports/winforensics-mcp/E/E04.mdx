# E04 분석 입력 준비

### E04.01 작업 사본 생성

**구현.** 이 방식은 브라우저 기록을 읽는 경로와 `windows_search_parse`에 적용된다 [1][2].
브라우저 기록을 읽는 함수 넷은 SQLite DB 파일 전체를 `tempfile.mkdtemp`로 만든 임시 폴더에 복사하고 그 사본을 연다 [1][3].
이 함수들은 `browser_get_history`와 `hunt_ioc`·`investigate_user_activity`의 브라우저 단계가 부른다 [3].
읽기를 마치면 임시 폴더를 지운다 [4].
`windows_search_parse`는 받은 `Windows.edb`를 임시 폴더의 `input/Windows.edb`로 복사하고 사본의 SHA-256이 원본과 같은지 확인한다 [2].
SIDR나 대체 경로인 `pyesedb`는 이 사본을 읽는다 [2][5].

다른 파서는 받은 경로의 원본을 제자리에서 읽고 사본을 만들지 않는다.
서버에는 디스크 이미지를 마운트하거나 보관 파일을 디스크에 푸는 코드가 없다.

**한계.** 브라우저 기록 도구는 `browser`가 기본값 `auto`이면 종류를 판별할 때 사본이 아니라 원본 DB를 연다 [6].

### E04.02 선택 추출

**구현.** 이 방식은 수집물 폴더 `artifacts_dir`를 받는 오케스트레이터 도구와 `hunt_ioc_pack`, APMX 도구에 적용된다 [7][8][9].
`investigate_execution`·`build_timeline`·`hunt_ioc`는 `artifacts_dir` 아래에서 정해 둔 상대 경로 목록을 차례로 확인해 처음 있는 경로를 아티팩트별 입력으로 고른다 [7][10].
예를 들어 Prefetch는 `Windows/Prefetch`·`prefetch` 같은 폴더, Amcache는 `Windows/AppCompat/Programs/Amcache.hve`, SRUM은 `Windows/System32/sru/SRUDB.dat`를 찾는다 [7].
`build_timeline`은 여기에 `$MFT`, `$Extend/$J`·`$J` 같은 USN 저널 이름, 이벤트 로그 폴더를 더한다 [10][11].
`hunt_ioc`는 `$MFT`, `$Extend/$UsnJrnl_$J`·`$J` 같은 USN 저널 이름, 이벤트 로그 폴더, 사용자별 브라우저 기록 경로를 더한다 [10][11].
`investigate_user_activity`는 사용자 이름이나 `*`를 넣은 glob으로 브라우저 기록, `Recent` 폴더, `UsrClass.dat`, `NTUSER.DAT`를 찾는다 [12].
모델이 아티팩트별 경로 인자를 주면 그 경로가 찾은 경로를 대신한다 [13].
고른 파일은 제자리에서 읽고 브라우저 기록만 사본을 만든다.
`hunt_ioc`의 YARA 단계는 IOC에서 폴더 부분을 뗀 파일 이름을 `artifacts_dir.rglob`의 패턴으로 넘겨 처음 나온 파일을 고른다 [14].
그런 파일이 없으면 `artifacts_dir` 아래 모든 파일에서 대소문자를 무시하고 이름이 같은 첫 파일을 고른다 [14].
서버는 이렇게 고른 파일 하나만 YARA로 검사한다 [15].

`hunt_ioc_pack`은 `artifacts_dir` 아래 모든 파일을 훑어 `max_file_size` 이하인 파일을 `max_files`개까지 고른다 [8].
`max_files`는 응답에 싣는 일치 항목의 수가 아니라 검사 대상으로 고르는 파일 수의 상한이다 [8].
서버는 `rglob`이 돌려준 차례대로 파일을 세고 그 목록을 정렬하지 않는다 [8].
고른 파일은 모두 상대 경로를 파일 이름 규칙과 대조한다 [8].
고른 파일 가운데 확장자가 정해 둔 텍스트 확장자인 파일은 내용을, `.pcap`·`.pcapng`·`.cap` 파일은 패킷 내용을 검사한다 [8].

APMX 도구는 캡처 파일 전체를 메모리로 읽고 `PK` 서명 뒤의 ZIP 부분을 메모리에서 연다 [9].
그 안에서 `info`, `process/<번호>/info`·`calls`·`data`, `definitions`, `log/monitoring.txt` 같은 이름의 항목만 골라 읽는다 [9][16].

**한계.** `hunt_ioc`의 브라우저 경로 탐색은 `Users/*/…` 꼴 경로를 `artifacts_dir` 바로 아래 폴더를 사용자 폴더로 삼아 맞춘다 [17].
그래서 `artifacts_dir`가 수집물 루트이고 기록이 `Users/<이름>/AppData/…`에 있으면 브라우저 기록을 찾지 못한다 [18].
Firefox 경로는 별표가 두 개라 둘째 별표가 글자 그대로 남아 어느 배치에서도 찾지 못한다 [17][18].
이때 응답은 브라우저 기록이 없다고 적는다 [19].
`investigate_user_activity`는 사용자 이름을 받지 않으면 glob이 찾은 첫 기록 하나만 쓰고 다른 사용자의 기록은 읽지 않는다 [12].
`hunt_ioc_pack`의 `max_files`는 확장자와 관계없이 크기 상한 이하의 모든 파일을 센다 [8].
그래서 내용 검사 대상이 아닌 파일이 먼저 나오면 뒤의 텍스트·pcap 파일은 내용을 읽지 않는다 [8].
`build_timeline`과 `hunt_ioc`의 USN 저널 후보 이름은 루트의 `$J`만 같다 [11].
그래서 저널을 `$Extend/$UsnJrnl_$J`로 둔 수집물에서는 `hunt_ioc`만, `$Extend/$J`로 둔 수집물에서는 `build_timeline`만 저널을 찾는다 [11].
`artifacts_dir` 아래에 이름이 같은 파일이 여럿이면 `hunt_ioc`의 YARA 단계는 `rglob`이 먼저 돌려준 하나만 검사한다 [14][15].
응답에는 검사한 파일의 경로 `file_scanned`만 실리고 이름이 같은 다른 파일을 검사하지 않았다는 표시는 없다 [15].
서버는 IOC의 파일 이름을 `glob.escape` 같은 처리 없이 `rglob`의 패턴 인자로 넘긴다 [14].
CPython 3.12.15의 `rglob`은 인자를 패턴으로 받아 경로 요소마다 패턴으로 컴파일해 대조한다 [20].
그래서 이름에 들어 있는 `[`·`]`·`*`·`?`는 글자 그대로가 아니라 패턴 문법으로 쓰인다 [14][20].

### E04.04 추출·생략 범위 기록

**구현.** 이 방식은 `investigate_execution`, `investigate_user_activity`, `hunt_ioc`, `build_timeline`에 적용된다 [19][21][22][23].
앞의 세 도구는 아티팩트별로 입력을 찾았는지를 `artifacts_searched`에 참·거짓으로 싣는다 [19][21][22].
찾지 못한 아티팩트는 결과 목록에 "Prefetch directory not found", "Amcache.hve not found" 같은 오류와 `available: false`로 실린다 [21][19].
`build_timeline`은 요청한 출처마다 경로와 `processed`·`not found`·오류 상태를 `sources_info`에 싣는다 [23].

`hunt_ioc_pack`은 훑은 파일 수, 크기 상한이나 `max_files` 때문에 건너뛴 파일, 검사한 pcap 수를 응답에 싣지 않는다 [8][24].
브라우저 기록 도구는 사본을 만들었는지와 함께 복사한 부속 파일을 응답에 적지 않는다 [1].

**한계.** `artifacts_searched`는 경로가 있는지만 적고 어느 경로를 골랐는지는 적지 않는다 [21][22].
`hunt_ioc`가 경로 탐색 문제로 브라우저 기록을 찾지 못한 경우에도 기록이 없다고 적는다 [19].

### E04.05 부속 자료 탐색

**구현.** 이 방식은 브라우저 기록을 읽는 경로에 적용된다.
서버 코드는 DB 파일을 복사한 뒤 같은 폴더에 같은 이름으로 `-wal`·`-shm`·`-journal`이 붙은 파일이 있으면 사본 옆으로 함께 복사한다 [1].

`windows_search_parse`는 `Windows.edb`만 복사하고 같은 폴더의 ESE 트랜잭션 로그와 체크포인트 파일은 옮기지 않는다 [2].
SIDR는 사본 하나만 들어 있는 폴더를 받는다 [5].
SRUM·NTDS 도구는 받은 데이터베이스 경로만 `pyesedb`에 넘기고 트랜잭션 로그를 찾지 않는다 [25].
레지스트리 도구는 하이브 경로만 `python-registry`에 넘기고 `.LOG1`·`.LOG2`를 찾지 않는다 [25].

### E04.06 부속 자료 누락·로그 미반영 표시

**구현.** 이 방식은 NTDS 도구와 `windows_search_parse`에 적용된다 [26][27].
NTDS 도구는 ESE 헤더의 상태 값과 예비 헤더의 같은 값을 읽어 `database_state`, `database_clean`, `header_copies_consistent`로 응답에 싣는다 [26][28].
정상 종료 상태가 아니거나 두 헤더가 다르면 진단 `database_not_clean_or_header_disagreement`를 더하고 `results_complete`를 거짓으로 둔다 [26][28].
이때 응답 글은 "Source/query is incomplete; inspect diagnostics."로 끝난다 [29].
`ntds_get_trusts`의 설명은 로그를 재생하거나 데이터베이스를 고치지 않는다고 적는다 [30].

`windows_search_parse`는 SIDR 출력에 "not clean"·"dirty database"가 있거나 보고서 파일 이름에 `_dirty`가 있으면 `database_state`를 `dirty`로 둔다 [27].
이때 `complete`를 거짓으로 두고 진단에 "Dirty ESE database: results may be inaccurate or incomplete."를 더한다 [27].
dirty 표시가 없으면 `database_state`는 `no_dirty_warning`이다 [27].

SRUM·레지스트리·브라우저 기록 도구는 데이터베이스나 하이브의 상태와 부속 자료 유무를 응답에 적지 않는다.

**한계.** `windows_search_parse`가 SIDR 없이 `pyesedb`로 읽으면 데이터베이스 상태를 보지 않아 `database_state`가 `unknown`으로 남는다 [31].
이 경로는 결과를 늘 불완전으로 표시하지만 그 이유로 싣는 진단은 긴 값과 압축 내용을 읽지 못한다는 것이다 [31].
NTDS 도구의 상태 값은 헤더 체크섬을 확인하지 않은 값이고 응답은 `header_checksum_verified`를 늘 거짓으로 싣는다 [26].

### E04.07 로그 재생·복원

**구현.** 이 방식은 브라우저 기록을 읽는 경로에 적용된다.
서버 코드는 `-wal` 파일을 사본 옆으로 함께 복사한다 [1].
Python에 묶인 SQLite는 사본을 열 때 그 WAL을 읽는다 [3].
실행 확인에서 체크포인트하지 않아 `-wal`에만 있던 방문 기록이 응답에 실렸다 [32].
`-shm`이 없는 경우에도 같았다 [32].
서버는 WAL이 있었는지나 반영했는지를 응답에 적지 않는다 [1].

ESE 데이터베이스와 레지스트리 하이브의 트랜잭션 로그는 서버 코드가 적용하지 않는다 [25].

**한계.** 사본 옆에 롤백 저널 `-journal`이 함께 복사된 경우에 SQLite가 읽기 전용 연결에서 그 저널을 어떻게 처리하는지는 실행해 확인하지 않았다 [1][3].

```python
def _copy_to_temp(db_path: Path) -> Path:
    """
    Copy database to temp location to avoid SQLite locking issues.
    Browser databases are often locked when the browser is running.
    """
    temp_dir = tempfile.mkdtemp(prefix="browser_history_")
    temp_path = Path(temp_dir) / db_path.name
    shutil.copy2(db_path, temp_path)

    # Also copy any WAL/SHM files if present
    for suffix in ['-wal', '-shm', '-journal']:
        wal_path = db_path.parent / (db_path.name + suffix)
        if wal_path.exists():
            shutil.copy2(wal_path, temp_path.parent / (temp_path.name + suffix))

    return temp_path
```

```python
def _find_file_in_artifacts(
    artifacts_dir: Path,
    filename: str,
) -> Optional[Path]:
    """
    Search for a file by name within the artifacts directory.
    Returns the first match found.
    """
    # Extract just the filename if path was provided
    if '\\' in filename:
        filename = filename.split('\\')[-1]
    if '/' in filename:
        filename = filename.split('/')[-1]

    # Search recursively for the file
    for found_file in artifacts_dir.rglob(filename):
        if found_file.is_file():
            return found_file

    # Also try case-insensitive search
    filename_lower = filename.lower()
    for found_file in artifacts_dir.rglob("*"):
        if found_file.is_file() and found_file.name.lower() == filename_lower:
            return found_file

    return None
```

def _header(path):
    with path.open('rb') as stream:
        raw = stream.read(240)
        if len(raw) < 240 or struct.unpack_from('<I', raw, 4)[0] != 0x89ABCDEF:
            raise ValueError('Not a supported ESE database header')
        version = struct.unpack_from('<I', raw, 8)[0]
        page_size = struct.unpack_from('<I', raw, 236)[0]
        if version != 0x620 or page_size not in (2048, 4096, 8192, 16384, 32768):
            raise ValueError('Unsupported ESE format version or page size')
        state = struct.unpack_from('<I', raw, 52)[0]
        stream.seek(page_size)
        backup = stream.read(240)
    consistent = len(backup) == 240 and all(raw[a:b] == backup[a:b] for a, b in ((4, 12), (52, 56), (236, 240)))
    names = {1: 'just_created', 2: 'dirty_shutdown', 3: 'clean_shutdown', 4: 'being_converted', 5: 'force_detach'}
    return {'database_state': names.get(state, 'unknown'), 'database_state_code': state,
            'database_clean': state == 3 and consistent, 'header_copies_consistent': consistent,
            'header_checksum_verified': False, 'ese_version': version, 'page_size': page_size}
