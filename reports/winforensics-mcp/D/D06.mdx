# D06 산출물 식별·재생성 처리

### D06.02 입력·작업별 고유 이름

**구현.** 이 방식은 `evtx_export`와 `vt_lookup_behavior`의 파일 이름에 적용된다 [1][2].
`evtx_export`는 파일 이름에 `uuid4` 난수를 넣는다 [1].
그래서 같은 원본과 같은 조건으로 다시 내보내도 앞 파일과 다른 이름의 새 파일이 생기고 앞 파일은 그대로 남는다 [1][3].
`vt_lookup_behavior`는 파일 이름에 조회한 해시의 앞 12자를 넣는다 [2].
이 값은 입력마다 같은 값이라 다른 해시의 결과와는 구별하지만 같은 해시를 다시 조회한 결과는 구별하지 않는다 [2].

`remote_collect_artifacts`는 `output_dir` 아래 `evtx/Security.evtx`, `registry/SAM`처럼 아티팩트 종류별 고정 이름으로 쓴다 [4].
이름에 대상 호스트나 수집 시각이 들어가지 않아 같은 `output_dir`에 다른 호스트나 다시 수집한 결과를 쓰면 앞 파일을 알리지 않고 덮어쓴다 [4][5].
이미 있는 결과를 알아채 다시 만들지 않거나 덮어쓸지를 고르게 하는 인자는 세 도구 모두 없다.

**한계.** `vt_lookup_behavior`는 같은 해시를 같은 `triage_dir`로 다시 조회하면 앞 파일을 알리지 않고 덮어쓴다 [2][5].
해시 앞 12자가 같은 다른 해시의 결과도 같은 이름에 쓰인다 [2].
