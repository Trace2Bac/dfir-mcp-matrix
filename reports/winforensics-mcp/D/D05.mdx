# D05 파생물 저장 실패 처리

### D05.01 오류·부분 완료 표시

**구현.** 이 방식은 `evtx_export`, `triage_dir`을 준 `vt_lookup_behavior`, `remote_collect_artifacts`의 파일 쓰기에 적용된다 [1][2][3].

`evtx_export`는 폴더 만들기, 임시 파일 만들기와 쓰기, `fsync`, 게시에서 난 예외를 처리하지 않고 호출한 쪽으로 넘긴다 [1][4].
쓴 바이트 수가 쓰려던 길이보다 짧으면 `OSError`를 일으킨다 [1].
실패하면 이 호출이 만든 임시 파일과 게시하려던 이름만 inode를 대조해 지운다 [4].
`call_tool`은 `evtx_export`에서 난 예외를 `isError`가 참인 결과로 바꿔 돌려준다 [5].

`vt_lookup_behavior`는 `triage_dir` 폴더 만들기와 파일 쓰기에서 난 `OSError`를 처리하지 않는다 [2].
도구 분기는 `ValueError`·`RuntimeError`만 처리하므로 `OSError`는 `call_tool`까지 올라간다 [6].
`call_tool`은 이 예외를 `{"error": …}` 한 칸짜리 JSON 글로 돌려주고 `isError`는 세우지 않는다 [5].
이때 요약 결과를 담은 응답은 나가지 않는다 [7].

`remote_collect_artifacts`는 아티팩트마다 원격 명령 실패, base64 풀기, 로컬 파일 쓰기에서 난 예외를 처리해 그 아티팩트의 `success`를 거짓으로, `error`에 예외 문구를 담는다 [3].
응답은 아티팩트마다 이 두 값을 담은 목록이다 [8].
`output_dir`과 그 아래 폴더를 만들다 난 예외는 처리하지 않아 호출 전체가 `{"error": …}` 글로 끝난다 [9][5][7].

**한계.** `vt_lookup_behavior`와 `remote_collect_artifacts`는 목적지 파일에 바로 쓰고 실패했을 때 쓰다 만 파일을 지우지 않는다 [2][3].
`write_text`와 `write_bytes`는 파일을 쓰기 모드로 열어 기존 내용을 먼저 비우므로 쓰기 도중 실패하면 그 이름에 있던 앞 파일도 남지 않는다 [2][3][10].
`remote_collect_artifacts`는 일부 아티팩트를 쓰지 못해도 `isError`를 세우지 않는다 [8][5].
`collect_file`은 원격 명령의 표준 출력 전체를 앞뒤 공백만 떼고 `validate` 인자 없이 `base64.b64decode`에 넘긴다 [3].
CPython 3.12.15의 `b64decode`는 `validate`가 거짓이면 Base64 알파벳이 아닌 글자를 버린 뒤에 푼다 [11].
그래서 표준 출력에 스크립트가 낸 Base64 말고 다른 글자가 섞여 있어도 풀기가 예외 없이 끝나면 그 아티팩트는 `success`가 참인 채 파일로 쓰인다 [3][11].

### D05.02 저장 확인·검증

**구현.** 이 방식은 `evtx_export`에 적용된다 [4].
`evtx_export`는 행을 `.part` 임시 파일에 다 쓰고 `flush`·`fsync`한 뒤에야 게시 이름을 붙인다 [1][4].
게시하기 전에 쓴 행 수가 쿼리가 고른 행 수와 같은지, 원본 EVTX의 식별값이 쓰기 전과 같은지 확인하고 다르면 게시하지 않는다 [12].
게시하기 전에 응답을 미리 만들어 출력 스키마로 검사한다 [13].
응답이 크기 상한에 맞지 않거나 검사에 실패하면 게시하지 않는다 [13][14].
게시 이름을 붙인 뒤 원본 식별값이 바뀐 것을 알면 게시한 이름도 지우고 오류로 끝낸다 [4].
응답의 `path`는 게시가 끝난 뒤에만 나간다 [4].
쓴 파일을 다시 읽어 해시를 대조하지는 않는다 [1].

```python
def evtx_export_response(data: dict[str, Any], *, max_chars: int = COMPACT_RESPONSE_CHARS) -> CallToolResult:
    """Budget only a preview; validate before the exporter publishes its file."""
    validate_budget(max_chars)
    result_data = {
        **data, "preview": list(data["preview"]),
        "preview_available": len(data["preview"]), "preview_returned": len(data["preview"]),
        "preview_clipped": False, "payload_clipped": False,
        "serialized_chars": 0, "returned_chars": 0,
    }
    result = _measure(result_data, True, original=True)
    if result_data["returned_chars"] <= max_chars:
        return result
    original_chars = result_data["serialized_chars"]
    while result_data["preview"]:
        result_data["preview"].pop()
        result_data["preview_returned"] = len(result_data["preview"])
        result_data["preview_clipped"] = result_data["payload_clipped"] = True
        result_data["serialized_chars"] = original_chars
        result = _measure(result_data, True)
        if result_data["returned_chars"] <= max_chars:
            return result
    raise ValueError(
        "Export metadata exceeds max_chars; increase max_chars or shorten query/path metadata. "
        "No export file was published."
    )
```
