# T04 실행 방식

### T04.01 서버 프로세스 안 분석

**구현.** 이 방식은 DiE 도구 2개, SIDR를 쓰는 `windows_search_parse`, WinRM 도구 2개를 뺀 도구에 적용된다 [1][2].
EVTX는 `evtx`, 레지스트리 하이브는 `python-registry`, PE는 `pefile`, Prefetch는 `libscca-python`, SRUM·NTDS는 `libesedb-python`, MFT는 `mft`, LNK는 `pylnk3`, ShellBags는 `libfwsi-python`, PCAP은 `scapy`, YARA는 `yara-python`으로 서버 프로세스 안에서 읽는다 [1].
브라우저 기록과 Windows API 정의 DB는 표준 라이브러리 `sqlite3`로 읽는다 [1].
APMX 캡처, USN 저널, 보안 설명자, CSV는 서버 자체 코드가 해석한다 [2].
`windows_search_parse`도 SIDR를 찾지 못하면 `libesedb-python`으로 서버 프로세스 안에서 읽는다 [3].
조사 묶음 도구는 같은 프로세스의 파서 함수를 차례로 부른다 [4].

### T04.02 같은 권한의 별도 프로세스

**구현.** 이 방식은 `diec`을 실행하는 `die_analyze_file`·`die_scan_directory`와 SIDR를 실행하는 `windows_search_parse`에 적용된다 [5][6].
두 경로 모두 `subprocess.run`에 인자 목록을 넘기고 셸을 거치지 않는다 [5][6].
자식 프로세스는 서버와 같은 계정과 권한으로 실행된다.
`diec` 실행에는 60초 시간 제한이 있고 작업 위치는 서버의 작업 위치를 그대로 쓴다 [5].
SIDR 실행에는 `timeout` 인자(기본 120초, 1~3600초)가 시간 제한으로 쓰이고 버전 확인에는 그 값과 10초 가운데 작은 값이 쓰인다 [6][7].

### T04.05 실행별 작업 폴더

**구현.** 이 방식은 SIDR를 실행하는 `windows_search_parse`에 적용된다 [8].
서버는 호출마다 `tempfile.TemporaryDirectory`로 `winforensics-search-` 접두어의 임시 폴더를 만들고 그 아래에 `input`·`output` 폴더를 둔다 [8].
원본 EDB를 `input/Windows.edb`로 복사하고 복사본의 SHA-256이 원본과 같은지 확인한 뒤 SIDR를 실행한다 [8].
SIDR의 작업 위치(`cwd`)와 출력 폴더는 그 호출의 `output` 폴더다 [6].
호출이 끝나면 임시 폴더를 지운다 [8].
`diec` 실행은 이 방식을 쓰지 않는다 [5].

### T04.07 원격 호스트 명령 실행

**구현.** 이 방식은 WinRM으로 원격 Windows 호스트에 PowerShell 스크립트를 실행하는 `remote_collect_artifacts`·`remote_get_system_info`에 적용된다 [9][10].
두 도구는 `pywinrm`이 설치되어 있을 때만 목록에 오른다 [11].
`WinRMCollector`는 `http://<host>:5985/wsman` 주소로 NTLM 인증 세션을 만들고 `run_ps`로 스크립트를 보내 표준 출력, 표준 오류, 종료 코드를 받는다 [9].
`password` 대신 `ntlm_hash`를 주면 그 해시로 인증한다 [9].
스크립트는 원격 호스트에서 접속 계정의 권한으로 실행된다.
`remote_get_system_info`는 컴퓨터 이름, 도메인, 운영체제, 마지막 부팅 시각, 로컬 계정 목록을 JSON으로 받는다 [10].
`remote_collect_artifacts`는 수집 대상 파일마다 파일 바이트를 Base64로 출력하는 스크립트를 실행하고 받은 값을 풀어 `output_dir`에 쓴다 [12].
파일을 바로 읽지 못하면 그 스크립트가 원격 호스트의 `C:` 볼륨에 섀도 복사본을 만든다 [12].
그 뒤 설치 시각이 가장 늦은 섀도 복사본에서 파일을 읽고 그 섀도 복사본을 지운다 [12].
저장소에는 SSH·SMB 수집 클래스도 있지만 어느 MCP 도구도 그 클래스를 쓰지 않는다 [13].
