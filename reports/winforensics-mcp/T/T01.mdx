# T01 입력 검증

### T01.01 인자 구조·값 검사

**구현.** 이 방식은 목록에 오른 도구의 모든 호출과 EVTX·NTDS·보안 설명자 도구 11개의 처리기에 적용된다 [1][2].
서버가 쓰는 MCP Python SDK 1.25.0의 `Server.call_tool`은 도구 목록에서 그 도구의 `inputSchema`를 찾아 `jsonschema.validate`로 인자를 검사한다 [1].
어긋나면 처리기를 부르지 않고 `Input validation error`로 시작하는 오류 결과를 돌려준다 [1][3].
그래서 서버 코드의 `inputSchema`에 적은 허용 값 목록(`enum`), 최솟값·최댓값, 길이 제한, `additionalProperties: False`가 실행 전 검사 기준이 된다 [3].
EVTX 질의 인자의 `where`는 연산자가 `eq`·`neq`·`in`·`exists`·`gt`·`gte`·`lt`·`lte` 가운데 하나인 객체만 받고 `limit`는 1에서 1000, `max_scan`은 1에서 1000000으로 정한다 [4].
NTDS 도구의 `fields`는 계정 메타데이터 이름 8개만 받는다 [5].

EVTX·NTDS·보안 설명자 도구 가운데 `evtx_get_event`를 뺀 11개의 처리기는 SDK 검사와 별도로 `validate_json_schema`로 인자를 다시 검사한다 [2].
이 12개 도구의 처리기는 응답 글자 예산 `max_chars`가 1024에서 40000 사이의 정수인지 `validate_budget`로 확인한다 [6].
`cursor`와 `offset`을 함께 주면 거부한다 [2].
EVTX 질의 준비 함수는 `where`의 피연산자 자료형, `fields`의 필드 이름, 시각 인자의 시간대 표시, 시작이 끝보다 늦지 않은지를 확인하고 어긋나면 `ValueError`로 거부한다 [7][8].
`evtx_correlate_logon_id`는 `logon_id`가 uint64 범위의 정수나 10진·`0x` 16진 문자열인지와 시간 범위가 7일 이하인지 확인한다 [9].
EVTX·NTDS·보안 설명자 도구가 낸 예외는 `isError`가 참인 짧은 오류 결과가 된다 [10].

EVTX 질의 결과의 레코드 참조값 `event_ref`와 다음 쪽 요청값 `cursor`도 처리 함수가 값을 검사한다 [11].
`evtx_search`·`evtx_security_search`는 결과 행마다 원본 파일의 실제 경로·크기·수정 시각·장치·inode·변경 시각의 SHA-256 digest와 레코드 순번을 담은 `event_ref`를 붙인다 [11].
`evtx_get_event`·`evtx_describe_security_descriptor`는 받은 `event_ref`의 digest를 지금 `evtx_path`의 같은 값과 대조하고 다르면 거부한다 [12].
그 순번의 레코드를 읽지 못해도 거부한다 [12].
`cursor`에는 원본 식별값과 질의 조건으로 만든 `query_ref`가 들어 있고 다음 요청의 `query_ref`와 다르면 거부한다 [13].
NTDS의 `ntds_get_trusts`도 `cursor`를 같은 방식으로 대조한다 [14].
서버는 발급한 참조값 목록을 따로 두지 않고 요청 때마다 원본의 식별값을 다시 계산해 대조한다 [11][12].
다른 원본 파일 경로에 같은 `event_ref`를 주면 `event_ref belongs to a different or changed source`가, 다른 질의에 `cursor`를 주면 `Cursor source or query changed`가 돌아왔다 [3].

다른 도구 일부도 처리 함수 안에서 값을 검사한다.
`registry_query`는 `match_mode`, `bool` 인자, `offset`·`limit`·`diagnostic_limit` 범위, `fields` 이름을 검사하고 정규식을 컴파일하지 못하면 거부한다 [15].
`windows_search_parse`는 `report_type`, `offset`·`limit`·`timeout` 범위, `fields` 개수, 시각 순서를 검사한다 [16].
`vt_lookup_hash`·`vt_lookup_behavior`는 해시 길이가 32·40·64자가 아니면 VirusTotal에 요청하지 않고 오류를 돌려준다 [17].

`inputSchema`가 자료형만 정하고 서버 코드도 값을 보지 않는 인자도 있다 [18].
`registry_get_key`의 `max_depth`와 `evtx_attack_summary`의 `limit`에는 최솟값·최댓값이 없다 [18].
이 도구들이 낸 예외는 `isError` 없이 `{"error": …}` 글로 돌아간다 [10].

**한계.** 목록에 없는 도구 이름으로 부르면 SDK가 인자를 검사하지 않고 처리기를 부른다 [19].
선택 의존성이나 `diec`이 없어 목록에서 빠진 도구도 `_execute_tool`의 분기는 남아 있다 [20].
`diec`이 없는 환경에서 목록에 없는 `die_get_packer_info`에 정수 `packer_name`과 schema에 없는 인자를 보내면 검사 없이 처리기가 실행되어 `AttributeError` 문구가 돌아왔다 [3].

### T01.02 입력 존재·읽기 가능 검사

**구현.** 이 방식은 파일이나 폴더 경로를 받는 도구 대부분에 적용된다 [21].
파서는 파일을 열기 전에 경로가 있는지 확인하고 없으면 `FileNotFoundError`나 오류 `dict`를 돌려준다 [21].
`die_analyze_file`은 파일이 없으면 `diec`을 실행하지 않는다 [22].
`windows_search_parse`는 `edb_path`가 파일이 아니면 SIDR를 찾거나 실행하지 않고 결과의 `error`에 그 사실을 적는다 [16].
`disk_parse_prefetch`는 `path`가 파일이면 한 파일을, 폴더면 폴더를 파싱하고 둘 다 아니면 `Path not found` 오류를 돌려준다 [23].
EVTX 질의 도구는 따로 존재를 확인하지 않고 원본 식별값을 만들려고 `stat`을 부를 때 파일이 없으면 파싱 전에 오류로 끝난다 [24].
조사 묶음 도구(`investigate_execution`·`hunt_ioc`·`build_timeline`·`investigate_user_activity`)는 자료 경로가 없으면 그 자료만 쓸 수 없다고 적고 나머지 자료로 계속한다 [25].
서버는 읽기 권한을 미리 확인하지 않는다.

**한계.** `die_analyze_file`과 `yara_scan_file`은 `exists`만 확인하므로 파일 대신 폴더를 넘겨도 거부하지 않는다 [22][26].
`die_analyze_file`은 폴더 경로로 `diec`을 실행한다 [22].
`yara_scan_file`에 폴더를 넘기면 규칙을 모두 컴파일한 뒤 매칭 단계에서 `could not open file` 오류가 돌아왔다 [26].

### T01.07 입력 부재 시 다른 입력으로 대체

**구현.** 이 방식은 `artifacts_dir`를 받는 조사 묶음 도구가 자료 파일을 고르는 단계에 적용된다 [27].
모델이 자료별 경로를 따로 주지 않으면 서버는 `artifacts_dir` 아래의 후보 상대 경로를 차례로 확인해 처음 있는 것을 입력으로 쓴다 [27][28].
후보에는 `Windows/prefetch`와 `Windows/Prefetch`, `Windows/appcompat/Programs/Amcache.hve`와 `Windows/AppCompat/Programs/Amcache.hve`처럼 대소문자만 다른 경로가 있다 [27].
`artifacts_dir` 바로 아래의 `Prefetch`·`Amcache.hve`·`SRUDB.dat`처럼 위치가 다른 후보도 있다 [27].
`hunt_ioc`·`build_timeline`·`investigate_user_activity`도 각자의 후보 목록으로 같은 방식을 쓴다 [29].
`user_parse_shellbags`는 `ntuser_path`를 주지 않으면 `UsrClass.dat`의 상위 폴더를 한 단계씩 올라가며 다섯 단계까지 `NTUSER.DAT`를 찾고 처음 있는 것을 함께 읽는다 [30].
`investigate_execution`·`hunt_ioc`의 응답 항목 `artifacts_searched`는 자료마다 입력을 찾았는지를 참·거짓으로 적는다 [25].

```python
def _validate_times(start_time, end_time):
    normalized = []
    for name, value in (("start_time", start_time), ("end_time", end_time)):
        if value is not None:
            if not isinstance(value, datetime):
                raise ValueError(f"{name} must be a datetime")
            if value.tzinfo is None or value.utcoffset() is None:
                raise ValueError(f"{name} must include a timezone")
            value = value.astimezone(timezone.utc)
        normalized.append(value)
    if all(value is not None for value in normalized) and normalized[0] > normalized[1]:
        raise ValueError("start_time must not be after end_time")
    return normalized
```

```python
def validate_where(where: Any, case_sensitive: bool = True) -> None:
    """Validate predicates even when the source or base-filtered set is empty."""
    if type(case_sensitive) is not bool:
        raise ValueError("where_case_sensitive must be a boolean")
    if where is None:
        return
    if not isinstance(where, dict):
        raise ValueError("where must map fields to operator dictionaries")
    for field, predicates in where.items():
        if not isinstance(field, str) or not field or len(field) > 512:
            raise ValueError("where fields must be nonempty field names")
        if not isinstance(predicates, dict) or not predicates:
            raise ValueError(f"where[{field}] must be a nonempty operator dictionary")
        for op, operand in predicates.items():
            if op not in _OPERATORS:
                raise ValueError(f"Unknown where operator: {op}")
            if op == "exists":
                if type(operand) is not bool:
                    raise ValueError(f"where[{field}].exists requires a boolean")
            elif op == "in":
                if not isinstance(operand, list) or not operand or not all(_scalar(v) for v in operand):
                    raise ValueError(f"where[{field}].in requires a nonempty list of scalar values")
            elif op in ("eq", "neq"):
                if not _scalar(operand):
                    raise ValueError(f"where[{field}].{op} requires a finite scalar value")
            elif field in ("TimeCreated", "System.TimeCreated"):
                _timestamp(operand, f"where[{field}].{op}")
            elif type(operand) not in (int, float) or (isinstance(operand, float) and not math.isfinite(operand)):
                raise ValueError(f"where[{field}].{op} requires a finite numeric operand")
```

```python
def _find_ntuser(usrclass_path: Path) -> Optional[Path]:
    """
    Locate the NTUSER.DAT belonging to the same profile as a UsrClass.dat.

    UsrClass.dat sits at <profile>/AppData/Local/Microsoft/Windows/UsrClass.dat,
    so the profile root is five levels up.
    """
    if usrclass_path.name.upper().startswith("NTUSER"):
        return None

    candidates = []
    profile = usrclass_path.parent
    for _ in range(5):
        profile = profile.parent
        candidates.append(profile / "NTUSER.DAT")

    for candidate in candidates:
        if candidate.exists():
            return candidate
    return None
```
