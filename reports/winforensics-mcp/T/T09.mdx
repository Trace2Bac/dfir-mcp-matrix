# T09 대상 시스템 대응 조치 처리

### 미구현

**판단.** 서버에는 가동 중인 Windows 단말의 상태를 바꾸는 경로가 하나 있지만 그 변경의 전후 상태, 변경 내역, 되돌릴 방법을 남기지 않는다.
`remote_collect_artifacts`는 WinRM으로 원격 단말에 접속해 이벤트 로그 8개와 레지스트리 하이브 5개를 PowerShell로 읽어 온다 [1][2].
파일마다 실행하는 스크립트는 파일을 바로 읽어 보고 읽지 못하면 `Win32_ShadowCopy`의 `Create`로 C 드라이브의 섀도 복사본을 만든다 [3].
그다음 `InstallDate`가 가장 늦은 섀도 복사본을 골라 그 안의 같은 경로를 읽고 그 섀도 복사본을 `Delete`로 지운다 [3].
스크립트는 `Create`의 결과를 확인하지 않고 지울 섀도 복사본을 만든 복사본의 ID가 아니라 만든 시각 순서로 고른다 [3].
바로 읽기가 실패하는 파일은 모두 이 경로로 읽힌다 [3].
섀도 복사본을 만들고 지우는 일은 조사 대상 단말의 저장소 상태를 바꾼다.

서버는 이 변경을 기록하지 않는다.
응답은 아티팩트마다 이름, 성공 여부, 로컬 경로, 크기, 오류만 싣고 섀도 복사본을 만들었는지, 어느 복사본을 지웠는지 싣지 않는다 [2].
`CollectionResult`의 원격 경로와 시각 필드는 응답에 옮겨지지 않는다 [4][2].
서버는 호출 기록을 남기지 않고 원격에서 실행한 스크립트도 남기지 않는다 [2].
되돌리는 도구나 경로도 없다.
도구 설명은 WinRM으로 아티팩트를 모은다고만 적고 섀도 복사본을 만들고 지운다는 사실을 적지 않는다 [5].

`remote_get_system_info`는 WMI로 운영체제, 도메인, 사용자 계정 정보를 읽기만 한다 [6].
나머지 도구는 사용자가 넘긴 증거 파일을 읽어 분석하고 대상 시스템에 접속하지 않는다.

    def get_system_info(self) -> dict[str, Any]:
        ps_script = '''
        @{
            ComputerName = $env:COMPUTERNAME
            Domain = (Get-WmiObject Win32_ComputerSystem).Domain
            OS = (Get-WmiObject Win32_OperatingSystem).Caption
            Version = (Get-WmiObject Win32_OperatingSystem).Version
            Architecture = (Get-WmiObject Win32_OperatingSystem).OSArchitecture
            LastBoot = (Get-WmiObject Win32_OperatingSystem).LastBootUpTime
            Users = (Get-WmiObject Win32_UserAccount | Select-Object Name, SID, Disabled)
        } | ConvertTo-Json
        '''
        stdout, stderr, exit_code = self.run_command(ps_script)
        
        if exit_code != 0:
            raise RuntimeError(f"Failed to get system info: {stderr}")

        return json.loads(stdout)
