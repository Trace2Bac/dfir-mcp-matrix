# T10 도구 명세 구성

### T10.02 처리기와 따로 둔 명세

**구현.** 이 방식은 도구 74개 모두에 적용된다.
서버는 MCP Python SDK의 저수준 `Server`를 쓰고 도구 74개의 이름, 설명, 입력 schema를 `list_tools` 안의 `Tool` 정의에 손으로 적는다 [1].
도구의 처리는 `_execute_tool`이 도구 이름으로 나눈 분기에 따로 있다 [2].
EVTX 질의, 보안 설명자, NTDS 도구의 입력 schema는 `_evtx_query_properties`·`_ntds_schema` 같은 함수가 만들고 처리 분기도 같은 함수로 인자를 `jsonschema`로 다시 검사한다 [3][4].
도구 10개는 출력 schema `outputSchema`를 싣는다 [5].
NTDS 도구 4개, `evtx_correlate_logon_id`, `evtx_export`, `evtx_ntlm_operational_summary`, 보안 설명자 도구 2개, `evtx_get_event`가 그 도구다 [5].
이 도구들은 처리 분기가 `CallToolResult`를 직접 돌려준다 [4].
MCP Python SDK 1.25.0은 처리기가 `CallToolResult`를 돌려주면 출력 schema 검사를 하지 않는다 [6].
그래서 처리 분기가 돌려주기 전에 `structuredContent`를 그 schema로 직접 검사한다 [4].
`evtx_search`·`evtx_security_search`는 `compact`나 `output_format`에 따라 구조화 결과와 글 결과를 모두 내므로 출력 schema를 싣지 않고 구조화 결과일 때만 서버가 직접 검사한다 [7].
도구 annotation은 없고 서버는 `tools.listChanged`를 거짓으로 알린다 [8].
서버는 MCP 리소스, 프롬프트, 서버 지침을 두지 않는다 [8].
목록에 오르는 도구의 수는 설치된 선택 의존성에 따라 달라지지만 목록에 오른 도구의 설명과 schema는 바뀌지 않는다 [1].

**한계.** `hunt_ioc`의 입력 schema는 `time_range_start`·`time_range_end`를 그 시각 앞뒤 사건을 거르는 인자로 알린다 [9].
처리 분기는 이 두 인자를 `hunt_ioc` 함수에 넘기지만 함수는 출처 검색 함수에 이 값을 넘기지 않고 다른 곳에서도 쓰지 않는다 [9][10].
그래서 이 인자를 주어도 결과는 시각으로 걸러지지 않는다.
`hunt_ioc`의 도구 설명은 해시를 포함한 IOC를 Prefetch, Amcache, SRUM, MFT, USN 저널, 브라우저 기록, EVTX에서 찾는다고 적는다 [11].
함수는 MD5나 SHA256 값을 어느 출처에서도 해시로 대조하지 않고 Amcache에서 파일 이름의 부분 문자열로 검색한다 [12].

`investigate_user_activity`의 입력 schema도 `time_range_start`·`time_range_end`를 사건을 거르는 인자로 알린다 [13].
함수는 이 값을 브라우저 단계에만 넘기고 `keyword`를 함께 주면 브라우저 단계에서도 쓰지 않는다 [14].
ShellBags, LNK, RecentDocs 단계는 시간 범위를 받지 않는다 [14].

`remote_collect_artifacts`의 설명은 WinRM으로 원격 Windows에서 아티팩트를 모은다고만 적는다 [15].
처리 경로는 파일을 바로 읽지 못하면 대상 단말에 섀도 복사본을 만들어 읽고 지우지만 설명과 schema에는 이 동작이 없다 [15][16].

`file_analyze_pe`의 입력 schema는 `extract_strings`를 문자열을 뽑는 인자로 알린다 [17].
처리 함수는 `pefile`이 연 파일 내용 `__data__`의 원소를 정수와 비교하다가 `TypeError`를 낸다 [18].
Windows 11의 `notepad.exe`와 `shell32.dll`에 이 인자를 참으로 주자 다른 분석 결과 없이 `{"error": "'<=' not supported between instances of 'int' and 'bytes'"}`만 돌아왔다 [19].
같은 schema는 `detail_level`의 `verbose`를 모든 자료를 싣는 수준으로 알리지만 `verbose`에서도 import는 DLL마다 20개까지만 실린다 [17][20].
`api_analyze_imports`의 schema는 `enrich_from_db`를 API 정의를 더하는 인자로 알린다 [21].
처리 함수는 import 이름이 API 정의 DB에 있는지만 세어 찾은 수와 비율을 `enrichment`에 싣고 정의 내용은 싣지 않는다 [22].

`disk_parse_mft`의 입력 schema는 `output_mode`의 `full`을 전체 자료, `summary`를 기본 정보로 알린다 [23].
처리 함수는 이 값이 `timestomping_only`인지만 보므로 `full`과 `summary`의 결과가 같다 [24].
같은 도구의 `detect_timestomping`은 처리 함수가 받기만 하고 쓰지 않는다 [24].
`disk_parse_amcache`의 schema는 `time_range_start`·`time_range_end`를 항목을 거르는 인자로 알리지만 옛 형식 하이브를 읽는 경로는 이 값을 받기만 하고 쓰지 않는다 [25][26].

EVTX 질의의 `contains`·`not_contains`는 정규화한 필드 값이 아니라 파서 라이브러리가 돌려준 레코드 원문 문자열 전체에 대조한다 [27].
`evtx_search`의 schema에는 두 인자의 설명이 없고 `evtx_attack_summary`의 schema는 그 문자열이 든 사건을 고른다고만 적는다 [28].
원문에는 필드 이름도 들어 있어 필드 이름을 주면 그 필드가 있는 사건이 모두 일치한다 [27][19].
표본 EVTX 2,261건에서 `contains`에 `SubjectUserSid`를 주자 2,089건이, `#attributes`를 주자 2,261건이 일치했다 [19].
`fields`는 schema 설명에 없는 이름 `_raw_xml`도 받는다 [29].
`evtx_attack_summary`의 도구 설명은 사건 종류 5개 가운데 3개의 열만 적는다 [30].

### T10.03 묶음 도구의 연산별 인자를 schema가 구분하지 않음

**구현.** 이 방식은 `disk_parse_usn_journal`, `browser_get_history`, `user_parse_shellbags`, `user_parse_lnk_files`에 적용된다 [31][32].
`disk_parse_usn_journal`은 `output_mode` 값으로 세 함수 가운데 하나를 실행한다 [31].
`records`는 `parse_usn_journal`, `summary`는 `get_file_operations_summary`, `deleted_files`는 `find_deleted_files`를 부른다 [31].
입력 schema는 모든 인자를 한 목록에 두고 어느 연산이 어느 인자를 쓰는지 구분하지 않는다 [33].
`filename_filter`·`reason_filter`·`interesting_only`·`files_only`는 `records`에서만 쓰이고 `summary`는 `limit`도 쓰지 않는다 [31].
`extension_filter`만 설명에 `deleted_files` 모드용이라고 적는다 [33].

플래그나 경로의 종류로 실행할 함수를 바꾸는 도구도 같은 방식이다.

- `browser_get_history`는 `dangerous_only`가 참이면 다운로드 함수를 부르고 `url_filter`·`include_downloads`를 쓰지 않는다 [32].
- `user_parse_shellbags`는 `suspicious_only`가 참이면 `find_suspicious_folders`를 부르고 `path_filter`·`ntuser_path`·`include_ntuser`를 쓰지 않는다 [32].
- `user_parse_lnk_files`는 `path`가 파일인지, 사용자 프로필인지, 폴더인지에 따라 세 함수 가운데 하나를 부르고 `recursive`·`target_filter`는 폴더일 때, `extension_filter`는 프로필일 때만 쓴다 [32].
