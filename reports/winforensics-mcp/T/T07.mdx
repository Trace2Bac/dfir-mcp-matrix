# T07 도구 부재 처리

### T07.01 실행 전 도구·참조 자료 가용성 검사

**구현.** 이 방식은 선택 의존성 라이브러리, Detect It Easy 실행 파일 `diec`, SIDR 실행 파일, Windows API 정의 DB, 저장소에 들어 있는 YARA 규칙을 쓰는 도구에 적용된다 [1][2][3][4][5].
파서 모듈은 불러올 때 `pefile`·`yara`·`vt`·`scapy`·`pyscca`·`pyesedb`·`mft`·`pylnk3`·`winrm`을 `import`로 시험하고 결과를 `*_AVAILABLE` 플래그에 둔다 [1].
`list_tools`는 플래그가 거짓인 라이브러리를 쓰는 도구를 목록에 올리지 않는다 [6].
`_execute_tool`은 그 도구가 불리면 플래그를 다시 보고 실행하지 않는다 [7].
`diec`는 모듈을 불러올 때 `PATH`와 정해 둔 설치 경로 6곳에서 찾고 찾지 못하면 `DIE_AVAILABLE`을 거짓으로 둔다 [2].
`windows_search_parse`는 SIDR 후보 경로마다 실행 권한이 있는 파일인지 확인한다 [3].
고른 실행 파일은 `--version`으로 시험 실행하고 종료 코드가 0이 아니거나 출력에 `0.9.2`가 없으면 분석을 실행하지 않는다 [8].
`api_lookup`·`api_search_category`는 API 정의 DB 파일 `data/api_definitions.db`가 있는지 먼저 확인한다 [4].
`yara_scan_file`·`yara_scan_directory`는 규칙 경로를 받지 않으면 패키지의 `rules` 폴더에 `.yar` 파일이 있는지 확인한다 [5].
`investigate_execution`·`hunt_ioc`·`investigate_user_activity`는 아티팩트 출처마다 그 출처를 읽는 라이브러리의 플래그를 보고 플래그가 거짓이면 그 출처를 읽지 않는다 [9].

**한계.** 다음 경로는 라이브러리나 참조 자료가 없을 때 그 단계를 실행하지 않고 그 사실을 응답에 싣지 않는다.

- `hunt_ioc_pack`은 `scapy`가 없으면 `scan_pcap`이 참이어도 PCAP 검사를 건너뛰고 그 규칙의 PCAP 결과를 빈 목록으로 둔다 [10].
- `build_timeline`은 `mft`, `pyscca`, `evtx` 라이브러리가 없으면 그 출처에서 사건을 만들지 않고 출처 상태를 `processed`로 둔다 [11].
- `api_analyze_imports`는 `enrich_from_db`가 참이어도 DB 파일이 없으면 보강 단계를 빼고 `enrichment` 필드 없이 응답한다 [12].

`diec` 확인은 모듈을 불러올 때 한 번만 한다 [2].
서버가 실행되는 중에 `diec`가 지워지면 `die_analyze_file`은 실행 파일을 찾지 못한 예외를 `Failed to run diec` 문구로 돌려준다 [13].

### T07.02 대체 없는 실패 처리·도구 부재 알림

**구현.** 이 방식은 선택 의존성이 필요한 도구, `diec`를 쓰는 도구, SIDR을 명시하거나 대체 라이브러리도 없는 `windows_search_parse`, API 정의 DB를 쓰는 도구에 적용된다 [7][14][15][4].
라이브러리가 없으면 `_execute_tool`은 다른 경로로 바꾸지 않고 `pefile library not installed. Install with: pip install pefile`처럼 라이브러리 이름과 설치 명령을 적은 `error`를 돌려준다 [7].
`diec`가 없으면 `diec (Detect It Easy CLI) not found`와 내려받을 주소를 적은 `error`를 돌려준다 [14].
실행 확인에서 `diec`가 없는 환경으로 `die_analyze_file`을 부르면 목록에 없는 도구인데도 이 문구가 응답으로 왔다 [16].
`windows_search_parse`는 사용자가 `sidr_path`를 주었는데 그 파일이 없거나, 찾은 SIDR이 없고 `pyesedb`도 없으면 분석하지 않는다 [15].
이때 응답의 `error`는 확인한 경로, `scripts/build_sidr.sh`로 빌드하거나 `WINFORENSICS_SIDR_PATH`를 정하라는 안내, `No backend was run` 문장을 싣는다 [15][16].
SIDR 버전이 다르면 `SIDR 0.9.2 is required; observed …` 문구로 실패를 알린다 [8][16].
`api_lookup`·`api_search_category`는 DB 파일이 없으면 그 경로와 DB를 먼저 만들라는 안내를 `error`로 돌려준다 [4].
`investigate_execution`·`hunt_ioc`·`investigate_user_activity`는 라이브러리가 없는 출처를 `available: false`와 `libscca-python not installed` 같은 `error`로 응답의 출처 목록에 싣는다 [9].

**한계.** 이 알림들은 MCP 오류 결과가 아니라 `isError`가 거짓인 정상 응답 글이다 [16].
EVTX 라이브러리가 없을 때의 문구는 `python-evtx library not installed. Install with: pip install evtx`이다 [17].
서버가 먼저 쓰는 라이브러리는 `evtx`이고 `python-evtx`는 그 라이브러리가 없을 때 쓰는 다른 라이브러리이므로 문구의 이름과 설치 명령이 가리키는 라이브러리가 다르다 [17].

### T07.03 알림 없는 대체 실행

**구현.** 이 방식은 EVTX를 읽는 모든 도구에 적용된다 [17].
EVTX 파서 모듈은 불러올 때 Rust로 만든 `evtx` 라이브러리를 먼저 시험하고 없으면 순수 Python 라이브러리 `python-evtx`의 `Evtx`를 시험한다 [17].
레코드를 읽을 때 `evtx`가 있으면 그 라이브러리의 JSON 출력을, 없으면 `Evtx`의 XML 출력을 사건으로 바꾼다 [18].
EVTX 도구의 응답과 사건에는 어느 라이브러리로 읽었는지 적는 필드가 없다 [18].
`pyproject.toml`의 필수 의존성에는 `evtx`가 있고 `python-evtx`는 없다 [19].
그래서 이 대체는 `evtx`가 설치되지 않고 `python-evtx`가 따로 설치된 환경에서만 일어난다 [17][19].

### T07.04 실행 환경별 경로 분기

**구현.** 이 방식은 `windows_search_parse`의 SIDR 선택과 DiE 도구의 `diec` 선택에 적용된다 [3][2].
`windows_search_parse`는 `sidr_path`를 받으면 그 경로만 본다 [3].
받지 않으면 환경변수 `WINFORENSICS_SIDR_PATH`, 저장소의 `.tools/sidr`(ARM64)나 `.tools/sidr_x86`(x86_64), `PATH`의 `sidr` 차례로 보고 실행 권한이 있는 첫 파일을 쓴다 [3].
저장소의 실행 파일은 `platform.machine()`이 `aarch64`·`arm64`이면 `sidr`, `x86_64`·`amd64`이면 `sidr_x86`을 고르고 그 밖의 아키텍처에서는 후보에서 빠진다 [3].
응답은 확인한 경로 목록을 `checked_sidr_locations`에, 실행한 파일의 경로와 SHA-256을 `backend_metadata`에 싣는다 [15][20].
실행 확인에서 x86_64 WSL로 경로를 주지 않고 부르면 `.tools/sidr_x86`이 골라지고 그 경로가 두 필드에 실렸다 [16].
`diec`는 `PATH`를 먼저 보고 없으면 `/usr/bin/diec`, `/usr/local/bin/diec`, `/opt/die/diec`, `/opt/detect-it-easy/diec`, `~/.local/bin/diec`, `~/DIE/diec` 차례로 실행 파일을 찾는다 [2].
DiE 도구의 응답에는 고른 `diec`의 경로가 없다 [21].

### T07.05 대체 사실을 응답·기록에 표시

**구현.** 이 방식은 `windows_search_parse`에 적용된다 [15].
`sidr_path`를 받지 않았고 SIDR 후보 경로에 실행 파일이 없으며 `pyesedb`가 있으면 서버는 `pyesedb`로 `PropertyStore` 표를 직접 읽는다 [15][22].
이때 응답의 `backend`는 `pyesedb`이고 SIDR로 읽으면 `sidr`이다 [22][20].
`checked_sidr_locations`에는 SIDR을 찾으려고 확인한 경로가 남는다 [15].
도구 설명도 SIDR이 없으면 부분 대체 경로를 쓴다고 적는다 [23].

**한계.** 실행 확인에서 대체 경로가 ESE 형식이 아닌 파일을 읽으면 응답의 `error`에 여는 단계의 오류가 아니라 `pyesedb_file_close: unable to close file` 문구가 실렸다 [16].
`_fallback_rows`는 `open`이 실패해도 `finally`에서 `close`를 부르고 `close`가 낸 예외가 앞선 예외를 대신한다 [22].

### T07.06 대체에 따른 검증·입력 범위 변화 표시

**구현.** 이 방식은 `windows_search_parse`의 `pyesedb` 대체 경로에 적용된다 [22].
대체 경로는 시작할 때 `complete`와 `content_filter_complete`를 거짓으로 둔다 [22].
진단 목록 `diagnostics`의 첫 줄에 긴 값과 압축된 검색 내용을 읽지 못하고 일치 0건이 결론이 되지 않는다는 문장을 싣는다 [22].
읽지 못한 긴 값의 수는 `unsupported_long_values`에 센다 [22].
`System_Search_AutoSummary` 열은 압축되어 있을 수 있어 대체 경로가 읽지 않는다 [22].
실행 확인에서 대체 경로로 실행하면 `complete`와 `content_filter_complete`가 모두 거짓이었고 위 문장이 진단 첫 줄에 실렸다 [16].

```python
def _find_diec() -> Optional[str]:
    """Find diec executable in PATH or common locations."""
    # Check PATH first
    diec_path = shutil.which("diec")
    if diec_path:
        return diec_path

    # Check common installation locations
    common_paths = [
        "/usr/bin/diec",
        "/usr/local/bin/diec",
        "/opt/die/diec",
        "/opt/detect-it-easy/diec",
        os.path.expanduser("~/.local/bin/diec"),
        os.path.expanduser("~/DIE/diec"),
    ]

    for path in common_paths:
        if os.path.isfile(path) and os.access(path, os.X_OK):
            return path

    return None
```

```python
def _resolve_sidr(explicit: str | None) -> tuple[Path | None, list[str]]:
    machine = platform.machine().casefold()
    bundled_name = None
    if machine in {"aarch64", "arm64"}:
        bundled_name = "sidr"
    elif machine in {"x86_64", "amd64"}:
        bundled_name = "sidr_x86"
    candidates = (
        [explicit]
        if explicit
        else [
            os.environ.get("WINFORENSICS_SIDR_PATH"),
            str(REPO_ROOT / ".tools" / bundled_name) if bundled_name else None,
            shutil.which("sidr"),
        ]
    )
    checked = []
    for candidate in candidates:
        if not candidate:
            continue
        path = Path(candidate).expanduser().resolve()
        checked.append(str(path))
        if path.is_file() and os.access(path, os.X_OK):
            return path, checked
    return None, checked
```
