# P04 조사 단위 관리

### 미구현

**판단.** 서버에는 사건 ID나 세션 ID가 없다.
도구는 호출마다 증거 파일이나 자료 폴더의 경로를 인자로 받고 그 경로가 어느 조사에 속하는지 구별하지 않는다 [1].
서버가 파일을 쓰는 도구는 저장 위치를 호출마다 인자로 받는다.
`evtx_export`는 `output_dir`, `remote_collect_artifacts`는 `output_dir`, `vt_lookup_behavior`는 `triage_dir`에 쓴다 [2][3][4].
`config.py`에는 자료 기준 경로와 출력 폴더를 담는 `ForensicsConfig`가 있지만 서버 코드는 이 설정을 읽지 않는다 [5].
EVTX 이어 읽기 값 `next_cursor`는 원본 파일의 식별 정보와 질의 조건으로 만든 `query_ref`에 묶이고 조사 단위에는 묶이지 않는다 [6].
EVTX·NTDS 파싱 결과와 VirusTotal 조회 결과를 담는 프로세스 메모리 캐시는 파일 식별 정보나 조회 대상만 키로 쓰므로 모든 호출이 함께 쓴다 [7][8][9].
서버는 stdio 연결 하나를 받는 프로세스이고 세션별로 상태를 나누는 코드는 없다 [10].

def _cache_key(evtx_path: Path) -> tuple:
    stat = evtx_path.stat()
    return (str(evtx_path.resolve()), stat.st_size, stat.st_mtime_ns,
            stat.st_dev, stat.st_ino, stat.st_ctime_ns)
