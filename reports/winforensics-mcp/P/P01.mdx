# P01 분석 방법 적합성 확인

### P01.01 이름·확장자 판별

**구현.** 이 방식은 오케스트레이터 4개의 자료 찾기, IoC 묶음 검색의 파일 고르기, 파일 하나와 폴더를 함께 받는 파서 도구 몇 개에 적용된다.
`investigate_execution`은 `find_artifact_paths`로 `artifacts_dir` 아래 정해 둔 상대 경로(`Windows/Prefetch`, `Amcache.hve`, `SRUDB.dat` 등)를 차례로 확인해 Prefetch 폴더, Amcache 하이브, SRUM DB를 정한다 [1].
`hunt_ioc`는 이 경로 표에 `$MFT`, `$UsnJrnl_$J`, 브라우저 기록 경로, `winevt/Logs` 같은 경로를 더한 `IOC_ARTIFACT_PATHS`로 같은 일을 한다 [2].
`build_timeline`은 `TIMELINE_ARTIFACT_PATHS`로, `investigate_user_activity`는 사용자 이름을 끼우는 `USER_ARTIFACT_PATHS`로 자료를 정한다 [3][4].
네 도구 모두 경로마다 그 이름의 파일이나 폴더가 있는지만 본다 [1][3][4].
`hunt_ioc`는 EVTX 폴더 안에서도 `Security.evtx`, Sysmon, PowerShell, DNS-Client 로그 이름을 먼저 고른다 [5].

`hunt_ioc_pack`은 확장자가 `TEXT_EXTENSIONS`에 있는 파일만 글로 읽어 정규식을 맞춘다 [6].
`hunt_ioc_pack`은 확장자가 `.pcap`·`.pcapng`·`.cap`인 파일만 패킷 검색으로 넘긴다 [6].
`die_scan_directory`는 확장자가 `.exe`·`.dll`·`.sys`·`.ocx`·`.scr`·`.drv`·`.cpl`인 파일만 Detect It Easy로 넘긴다 [7].
`disk_parse_prefetch`는 파일 하나를 받으면 확장자가 `.pf`가 아닐 때 거부한다 [8].
`user_parse_lnk_files`는 받은 경로가 확장자 `.lnk`인 파일이면 LNK 파일 하나로 읽는다 [9].
`user_parse_shellbags`는 받은 하이브의 파일 이름이 `NTUSER`로 시작하면 NTUSER.DAT의 BagMRU 키를, 아니면 UsrClass.dat의 BagMRU 키를 읽는다 [10].
APMX 파서는 확장자가 `.apmx86`이면 호출 위치 표의 포인터 크기를 4바이트로, 그 밖이면 8바이트로 정하고 확장자로 32비트·64비트 표시를 정한다 [11].

**한계.** `hunt_ioc`의 브라우저 기록 찾기는 `Users/*/…` 경로에서 `*` 앞부분의 부모 폴더인 `artifacts_dir` 바로 아래 폴더를 사용자 폴더로 본다 [12].
그래서 `artifacts_dir/Users/<사용자>/AppData/…/History`처럼 놓인 Chrome·Edge 기록은 찾지 못하고 `artifacts_dir/<폴더>/AppData/…/History`에 놓인 기록만 찾는다 [12][13].
Firefox 경로는 `Profiles/*/places.sqlite`의 두 번째 `*`를 글자 그대로 경로로 붙이므로 찾지 못한다 [12].
찾지 못한 브라우저 기록은 `No browser history found`로 응답에 실린다 [13].
`investigate_user_activity`는 `username`을 주지 않으면 `Users/*/…` 경로에서 처음 찾은 사용자의 자료 하나만 쓴다 [4][14].
`user_parse_shellbags`는 하이브 파일 이름만 보고 읽을 키를 정하므로 이름을 바꾼 NTUSER.DAT는 UsrClass.dat로 읽는다 [10].
APMX 파서는 확장자가 `.apmx64`가 아니어도 `.apmx86`만 아니면 8바이트 포인터로 읽는다 [11].

### P01.02 메타데이터 조회

**구현.** 이 방식은 경로의 종류나 함께 있는 파일로 처리 방법을 고르는 도구 3개에 적용된다.
`disk_parse_prefetch`는 받은 경로가 파일이면 Prefetch 파일 하나로, 폴더면 그 안의 Prefetch 파일 목록으로 읽는다 [8].
`user_parse_lnk_files`는 받은 경로가 폴더이고 그 안에 `AppData` 폴더가 있으면 사용자 프로필로 보고 `Recent` 폴더의 최근 파일을 읽는다 [9].
`AppData`가 없는 폴더는 LNK 파일을 담은 폴더로 보고 하위 폴더까지 읽는다 [9].
`user_parse_shellbags`는 UsrClass.dat를 받고 `ntuser_path`가 없으면 UsrClass.dat가 있는 폴더의 상위 폴더 다섯 개에서 `NTUSER.DAT`를 찾아 함께 읽는다 [15].
찾은 하이브와 읽지 못한 하이브는 응답의 `hives_parsed`와 `warnings`에 실린다 [16].
서버가 증거의 OS 버전이나 파티션을 판별해 방법을 고르는 코드는 없다.

### P01.03 내용·헤더 검사

**구현.** 이 방식은 브라우저 기록, CSV 가져오기, Amcache, NTDS, APMX 파서에 적용된다.
`browser_get_history`는 `browser`가 `auto`이면 SQLite DB의 표 이름을 읽어 `moz_places`가 있으면 Firefox로, `urls`와 `visits`가 있으면 Chromium 계열로 본다 [17].
Chromium 계열에서는 `edge_urls` 표가 있으면 Edge로 본다 [17].
판별하지 못하면 `unknown`이 되고 파서는 지원하지 않는 형식이라는 오류를 낸다 [18].
`ingest_parsed_csv`는 `csv_type`이 `auto`이면 CSV 머리 줄의 열 이름을 `CSV_SIGNATURES`의 필수 열과 맞춰 MFTECmd·PECmd·AmcacheParser·SrumECmd 출력 가운데 하나로 정한다 [19].
맞는 유형이 없으면 읽지 않고 찾은 열 이름과 지원 유형을 돌려준다 [20].
`disk_parse_amcache`는 하이브에 `Root\InventoryApplicationFile` 키가 있으면 새 형식 파서로, 없고 `Root\File` 키가 있으면 옛 형식 파서로 읽는다 [21].
옛 형식으로 읽은 응답에는 `format`이 `legacy`로 실린다 [22].
두 키가 모두 없으면 읽지 않고 오류와 빈 `entries`를 돌려준다 [21].
NTDS 도구는 파일 앞 240바이트를 읽어 ESE 서명 `0x89ABCDEF`, 형식 버전 `0x620`, 페이지 크기를 확인하고 맞지 않으면 읽지 않는다 [23].
이어서 `datatable` 표와 스키마 판별에 쓰는 열이 있는지 확인하고 없으면 지원하지 않는 NTDS 스키마라는 오류를 낸다 [24].
APMX 파서는 파일에서 ZIP 서명 `PK\x03\x04`를 찾지 못하면 APMX 파일이 아니라는 오류를 낸다 [25].

**한계.** `browser`나 `csv_type`을 호출자가 정해 주면 표 이름이나 열 이름을 확인하지 않고 그 형식의 파서를 쓴다 [18][20].
APMX 파서는 파일 어디에서든 처음 나오는 ZIP 서명부터 ZIP으로 연다 [25].
`ingest_parsed_csv`는 `InterfaceLuid` 열이 있는 SrumECmd 네트워크 CSV를 `srumemd`로 판별하지만 그 유형의 필드 표에는 인터페이스와 프로필 열이 없어 그 값은 응답에 실리지 않는다 [19][26].

### P01.04 방법과 형식·OS 대조

**구현.** 이 방식은 NTDS 도구 4개에 적용된다.
NTDS 파서는 읽을 메타데이터 속성마다 물리 열 이름을 `_ATTRS`에 정해 둔다 [27].
스키마 레코드를 읽을 때 그 속성의 `attributeID`가 정해 둔 열 번호와 같고 그 열이 표에 있을 때만 그 속성을 읽을 대상에 넣는다 [28].
다르면 그 스키마 레코드를 오류로 세고 그 속성은 읽지 않는다 [28].
읽을 대상에 넣지 못한 속성은 `metadata_schema_incomplete` 진단으로 응답에 실리고 `schema_complete`가 거짓이 된다 [28].
코드 주석은 손상된 스키마가 메타데이터 속성을 자격증명 열로 바꿔 가리키지 못하게 하려는 것이라고 적는다 [27].

다른 도구는 고른 방법을 입력과 대조하지 않는다.
`browser`나 `csv_type`을 호출자가 정하면 그 값과 판별 결과를 비교하지 않는다 [18][20].
`user_parse_shellbags`는 이름으로 고른 키가 그 하이브에 맞는지 확인하지 않는다 [10].

def _find_ntuser(usrclass_path: Path) -> Optional[Path]:
    """
    Locate the NTUSER.DAT belonging to the same profile as a UsrClass.dat.

    UsrClass.dat sits at <profile>/AppData/Local/Microsoft/Windows/UsrClass.dat,
    so the profile root is five levels up.

    if usrclass_path.name.upper().startswith("NTUSER"):
        return None

    candidates = []
    profile = usrclass_path.parent
    for _ in range(5):
        profile = profile.parent
        candidates.append(profile / "NTUSER.DAT")

    for candidate in candidates:
        if candidate.exists():
            return candidate
    return None
