# P05 사건 자료 정리

### P05.03 자동 정리

**구현.** 이 방식은 `windows_search_parse`, 브라우저 기록 파서, `evtx_export`가 호출 중에 만드는 작업 파일에 적용된다 [1][2][3].
`windows_search_parse`는 `TemporaryDirectory` 안에 원본 `Windows.edb`의 사본과 SIDR 출력 폴더를 만들고 호출이 끝나면 폴더째 지운다 [1].
브라우저 기록 파서는 SQLite DB와 `-wal`·`-shm`·`-journal` 파일을 `mkdtemp`로 만든 임시 폴더에 복사해 읽고 `finally`에서 그 폴더를 지운다 [2][4].
`evtx_export`는 내보내기 폴더에 `mkstemp`로 만든 `.part` 파일에 사건을 쓰고 새 이름으로 하드링크를 만든 뒤 `.part` 파일을 지운다 [3].
내보내기가 실패하면 `.part` 파일과 이번 호출이 만든 결과 파일 후보를 지운다 [3].
지운 사실은 응답이나 기록에 남지 않는다 [1][4][3].
서버가 종료될 때 따로 지우는 코드는 없다.
사건 자료를 지우거나 초기화하는 MCP 도구는 없다.
서버 메모리의 EVTX 캐시를 비우는 함수 `evtx_clear_cache`는 있지만 MCP 도구로 등록되어 있지 않다 [5].

**한계.** 브라우저 기록 파서는 임시 폴더를 `ignore_errors=True`로 지우므로 지우지 못해도 알리지 않고 증거 DB 사본이 임시 폴더에 남는다 [4].
브라우저 기록 파서는 임시 폴더를 만든 뒤 DB나 부속 파일을 복사하다 예외가 나면 그 폴더를 지우지 않는다 [2][6].
`-wal` 파일 복사가 실패하게 한 실행에서 DB 사본이 들어간 임시 폴더가 남았다 [7].

### P05.05 원본 증거를 삭제 대상에서 제외

**구현.** 이 방식은 자동 정리에 적용된다.
자동 정리가 지우는 대상은 그 호출이 `TemporaryDirectory`, `mkdtemp`, `mkstemp`로 만든 폴더와 파일이다 [1][2][3].
`evtx_export`는 파일을 지우기 전에 장치 번호와 inode가 이번 호출이 만든 `.part` 파일과 같은지 확인하고 다르면 지우지 않는다 [8].
원본 증거는 사본을 만들 때 읽기만 하고 지우는 대상에 없다 [1][2].

```python
def _copy_to_temp(db_path: Path) -> Path:
    """
    Copy database to temp location to avoid SQLite locking issues.
    Browser databases are often locked when the browser is running.
    """
    temp_dir = tempfile.mkdtemp(prefix="browser_history_")
    temp_path = Path(temp_dir) / db_path.name
    shutil.copy2(db_path, temp_path)

    # Also copy any WAL/SHM files if present
    for suffix in ['-wal', '-shm', '-journal']:
        wal_path = db_path.parent / (db_path.name + suffix)
        if wal_path.exists():
            shutil.copy2(wal_path, temp_path.parent / (temp_path.name + suffix))

    return temp_path
```
