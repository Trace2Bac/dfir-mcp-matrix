# P03 조사 진척 판단

### P03.03 미조사 범위·생략 사유 보고

**구현.** 이 방식은 오케스트레이터 도구 `investigate_execution`, `investigate_user_activity`, `hunt_ioc`, `build_timeline`에 적용된다 [1][2][3][4].
네 도구는 출처마다 찾았는지를 `artifacts_searched`나 `sources_info`에 싣는다 [1][2][3][4].
`investigate_execution`과 `investigate_user_activity`는 찾지 못한 출처를 `available`이 거짓인 항목으로 `evidence`에 넣고 `Prefetch directory not found`처럼 찾지 못한 자료를 `error`에 적는다 [1][2].
`hunt_ioc`는 출처를 찾지 못한 경우와 IOC 유형 때문에 검색하지 않은 경우를 나눠 적는다 [3].
찾지 못한 출처는 `sources_unavailable`에 모인다 [3].
검색하지 않은 출처는 `searched`가 거짓인 항목에 `Prefetch does not contain file hashes`나 `YARA scanning disabled` 같은 사유를 `note`로 적는다 [3][5].
`build_timeline`은 요청한 출처마다 `processed`, `not found`, `error: …` 가운데 하나를 `sources_info`의 `status`에 적는다 [4].
`hunt_ioc_pack`은 일치한 규칙만 응답에 싣고 읽지 않은 파일이나 건너뛴 검사를 알리지 않는다 [6].
서버에 수행할 작업 목록이나 완료 조건을 두는 도구, 모델이 진행 기록을 적는 도구는 없다.

**한계.** `investigate_execution`과 `investigate_user_activity`는 파싱이 실패한 출처를 `available`이 참인 항목으로 남긴다 [7][8].
그래서 응답의 `summary`는 그 출처를 검색했지만 흔적이 없는 출처로 적는다 [8].
`hunt_ioc`도 파싱이 실패한 출처를 `searched`가 참인 항목으로 남겨 `sources_searched_no_match`에 넣는다 [9][3].
오류 문구는 출처 항목의 `error`에만 남는다 [7][9].
`hunt_ioc`는 MD5·SHA256 값을 Amcache에서 해시가 아니라 파일 이름의 부분 문자열로 검색한다 [10].
이때 Amcache는 `searched`가 참인 항목으로 남아 일치가 없으면 `sources_searched_no_match`와 요약의 검색한 출처 수에 포함된다 [10][3].
`investigate_user_activity`는 `username`을 주지 않으면 처음 찾은 사용자 한 명의 자료만 읽고 다른 사용자의 자료가 있다는 사실을 알리지 않는다 [11][12].
`hunt_ioc`는 `artifacts_dir/Users/<사용자>/…`에 놓인 브라우저 기록이 있어도 `No browser history found`로 적는다 [13].
`build_timeline`은 출처마다 사건 수 상한을 두고 상한에 닿아 읽지 않은 사건이 있어도 그 출처의 `status`를 `processed`로 적는다 [4][14].
