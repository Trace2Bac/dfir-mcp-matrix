# P02 다음 작업 결정

### P02.01 고정 문서·프로필 반환

**구현.** 이 방식은 `forensics_list_important_events`, `forensics_list_registry_keys`, `die_get_packer_info`에 적용된다 [1][2].
`forensics_list_important_events`는 Security·System·PowerShell·Sysmon 채널마다 살펴볼 이벤트 ID와 이름을 `IMPORTANT_EVENT_IDS`에서 골라 돌려준다 [1][3].
`forensics_list_registry_keys`는 지속성, 서비스, 네트워크, USB, 사용자 활동, 시스템 정보 분류마다 살펴볼 레지스트리 키 경로를 `FORENSIC_REGISTRY_KEYS`에서 돌려준다 [1][4].
분류를 주지 않으면 도구 정의의 분류 6개에 없는 `shimcache`·`amcache` 분류까지 모두 돌려준다 [4][5].
`die_get_packer_info`는 패커 이름을 받아 코드에 적어 둔 표에서 패킹 해제 난이도와 패킹을 해제할 때 쓸 도구(`unpack_tool`)를 돌려준다 [2].
표에 없는 이름이면 온라인에서 패킹 해제 자료를 찾아보라는 `note`를 돌려준다 [2].
세 도구가 돌려주는 내용은 코드에 정한 값이라 증거나 앞선 호출과 관계없이 같다 [1][3][4][2].
서버는 서버 지침, MCP 리소스, MCP 프롬프트를 두지 않는다 [6].
도구 설명에도 클라이언트 문맥이 압축되거나 끊긴 뒤 상태를 다시 읽으라는 안내가 없다.

**한계.** `die_get_packer_info`는 Detect It Easy 실행 파일을 쓰지 않지만 `diec`가 설치되어 있을 때만 도구 목록에 오른다 [7].
`die_get_packer_info`는 표의 키와 같은 이름이 없으면 키와 이름 가운데 한쪽이 다른 쪽에 들어 있는 첫 항목을 돌려준다 [8].

### P02.02 규칙·조사 상태로 추천

**구현.** 이 방식은 `ingest_parsed_csv`와 `hunt_ioc`의 응답 두 곳에 적용된다 [9][10].
`ingest_parsed_csv`는 CSV 유형을 판별하지 못하면 `csv_type`을 정해 다시 부르라는 오류와 함께 찾은 열 이름과 지원 유형을 돌려준다 [9].
`hunt_ioc`는 `yara_scan`을 켜지 않은 호출의 YARA 항목에 `yara_scan=True`로 켜라는 `note`를 싣는다 [10].
이 안내는 응답 문자열이고 서버가 다음 호출을 대신 고르거나 안내를 따르지 않은 호출을 막지는 않는다.
그 밖의 도구 응답은 분석 결과만 싣고 다음에 부를 도구를 싣지 않는다.

**한계.** `ingest_parsed_csv`가 안내하는 지원 유형 목록에는 `csv_type`으로 받지 않는 이름 `amcache_alt`·`srumemd_network`가 들어 있다 [9][11].
도구 정의의 `csv_type`은 이 두 이름을 enum에 두지 않는다 [11].

### P02.04 서버 코드에 고정한 분석 절차

**구현.** 이 방식은 오케스트레이터 도구 `investigate_execution`, `investigate_user_activity`, `hunt_ioc`, `build_timeline`과 `hunt_ioc_pack`, `registry_get_persistence`에 적용된다 [12][13][14][15][16][17].
`investigate_execution`은 Prefetch, Amcache, SRUM을 이 차례로 찾아 읽고 실행 흔적을 찾은 출처 수로 `confidence`를 정한다 [12][18].
`investigate_user_activity`는 브라우저 기록, ShellBags, Recent 폴더의 LNK 파일, NTUSER.DAT의 RecentDocs를 이 차례로 읽고 찾은 활동의 시각을 시간표 하나로 모은다 [13].
`hunt_ioc`는 IOC 유형을 판별한 뒤 Prefetch, Amcache, SRUM, MFT, USN Journal, 브라우저 기록, EVTX를 차례로 검색하고 `yara_scan`이 참이면 YARA 검사를 더한다 [14].
`build_timeline`은 `sources`(기본값 `mft`·`usn`·`prefetch`·`amcache`)의 출처를 차례로 읽어 같은 사건을 하나로 줄이고 시각의 역순으로 합친다 [15].
`hunt_ioc_pack`은 IoC 묶음의 규칙마다 파일 경로·글 내용·패킷 검사를 실행하고 규칙 가중치로 점수를 매긴다 [16].
`registry_get_persistence`는 SOFTWARE·NTUSER.DAT의 Run 키, SOFTWARE의 Winlogon 값, SYSTEM의 서비스를 차례로 읽어 한 응답으로 합친다 [17].
모델은 이 도구와 인자(대상, 시간 범위, 자료 경로)만 고르고 그 안의 단계는 서버 코드가 정한다.
서버 안에서 모델을 불러 계획을 세우는 경로는 없다.

**한계.** 오케스트레이터는 자료 경로 인자를 주지 않으면 정해 둔 경로 이름으로만 자료를 찾으므로 다른 위치에 놓인 자료의 단계는 실행하지 않는다 [12][13][14].
`hunt_ioc`에는 브라우저 기록 경로 인자가 없다 [14].
`hunt_ioc`는 `artifacts_dir/Users/<사용자>/…`에 놓인 브라우저 기록을 찾지 못해 브라우저 기록 검색 단계를 실행하지 않는다 [19].
`investigate_user_activity`는 `username`을 주지 않으면 처음 찾은 사용자 한 명의 자료로 모든 단계를 실행한다 [20].
`build_timeline`은 기본값에 EVTX를 넣지 않아 `sources`에 `evtx`를 주어야 EVTX 단계를 실행한다 [15].
`investigate_user_activity`의 시간표에는 브라우저 방문 기록과 LNK 출처의 사건이 들어가지 않는다 [21][22][23].
시간표를 만드는 코드는 브라우저 결과의 `visits`와 LNK 항목의 최상위 `access_time`·`creation_time`을 읽는다 [21].
브라우저 파서는 방문 기록을 `history`에 싣고 LNK 파서는 시각을 `timestamps` 아래에 싣는다 [22][23].

```python
def _calculate_confidence(evidence_results: list[dict]) -> str:
    """Calculate confidence level based on evidence"""
    sources_found = sum(1 for r in evidence_results if r.get("found"))
    sources_available = sum(1 for r in evidence_results if r.get("available", True))

    if sources_found == 0:
        return "NONE"
    elif sources_found >= 3:
        return "HIGH"
    elif sources_found >= 2:
        return "MEDIUM"
    elif sources_found == 1 and sources_available >= 2:
        return "LOW"
    else:
        return "LOW"
```
