# reports/ — 서버별 원고

서버마다 폴더 하나, 그 안에 **셀 하나 = 파일 하나**다.
각 파일에 그 서버가 셀의 어느 상세 항목에 드는지와 그 구현·예외를 기준 커밋 코드 근거와 함께 쓴다.

```
reports/
└─ trudi/
   ├─ index.mdx     서버 머리: 저장소, 기준 커밋, 확인 방법
   ├─ E03.mdx       셀 E03
   ├─ T03.mdx
   └─ …
```

조사하지 않은 셀은 파일을 두지 않는다. 화면에서 `미확인`으로 보인다.

## index.mdx

```markdown
---
server: trudi                                       # 폴더 이름과 같게
repo: nebulae/trudi                                 # GitHub 저장소
commit: 88fbca78186b6a0ca40423cf5e37a9dc46ae051e    # 원고가 인용하는 기준 커밋(40자)
---

# trudi 시범 전환 원고

**기준 커밋.** [`88fbca7`](https://github.com/nebulae/trudi/tree/88fbca7…)(날짜).
줄 번호는 모두 이 커밋 기준이다.

**확인 방법.** 코드를 어떻게 읽고 무엇을 실행했는지.
```

## \<셀ID\>.mdx

```markdown
---
cell: E03
details:                  # 이 서버가 드는 상세. 차례대로 아래 ### 소제목과 맞춘다
- id: E03.01
  exception: true         # true면 화면에 †가 붙고 **예외.**를 반드시 쓴다
- id: E03.02
  exception: false
---

# E03 원본 변경 방지

### E03.01 실행 환경의 읽기 전용 강제

**구현.** 그 방식이 어느 도구·경로에 있고 어떻게 동작하는지 쓴다 [1].
문장 하나를 한 줄에 쓴다 [2].

이어지는 단락은 머리말 없이 빈 줄 뒤에 쓴다.

**예외.** 구현에 적은 적용 범위 안에서 그 방식이 걸리지 않는 경로 [3].

### E03.02 서버 코드의 원본 쓰기 제한

**구현.** … [4].

### 근거

[1] 확인할 동작을 한 문장으로 쓴다.

@발췌 src/server.py:120-128

[2] 코드 위치가 셋 이상이면 링크만 둔다: [`src/a.py:10-12`](…), [`src/b.py:40`](…), [`src/c.py:7-9`](…).
```

어느 상세에도 들지 않으면 머리말을 `details: [{id: 미구현}]`(또는 `비적용`)로 하고 본문에 `### 미구현`과 `**판단.** 왜 그런지 [1].`을 쓴다.

## 규칙

- **문장 하나를 한 줄에 쓴다.** 단락 사이에만 빈 줄을 둔다. 화면은 그 줄바꿈을 그대로 보여 준다.
- 문장은 "~다"로 끝나는 평서문으로 쓴다. 코드 이름이 든 문장에는 근거 표지 `[번호]`를 단다.
- `[번호]`는 파일마다 1부터 본문에 처음 나온 차례로 매긴다. 문장을 옮겼으면 `python tools/pilot.py renumber <서버>`.
- 코드 블록은 `### 근거` 안에만 둔다. **발췌를 손으로 쓰지 않는다.** `@발췌 경로:시작-끝` 한 줄을 두고 `python tools/pilot.py fill <서버>`로 채운다(`check`가 기준 커밋 원문과 글자 그대로 대조한다).
- 링크는 기준 커밋 고정 링크(`/blob/<40자 커밋>/`)만 쓴다.
- **근거에 발췌를 붙이는 기준.** 근거가 가리키는 코드 위치가 한두 곳이고 각 범위가 30줄 이하이면 위치마다 `@발췌`를 둔다. 링크만 두는 근거는 아래 넷뿐이다. 이때도 첫 줄에 무엇을 확인할지 쓴다. `check`가 기준에 어긋난 근거를 경고로 알린다.
  - 코드가 아닌 근거: 실행 확인(근거 첫 줄에 `(실행 확인)`을 붙이고 무엇을 돌려 봤는지는 `index.mdx`의 확인 방법에 쓴다), 문서(`.mdx`·`.txt`), 예시 로그.
  - 코드 위치가 세 곳 이상인 근거: 흩어진 분기·호출 지점을 한꺼번에 가리킬 때.
  - 30줄을 넘는 범위: 함수 흐름 전체를 가리킬 때. 판단에 필요한 부분이 따로 있으면 그 부분을 발췌한다.
  - 같은 셀 파일의 다른 근거에 이미 발췌한 범위.
- 소제목은 `### <상세 번호> <상세 이름>`이다. 번호로 연결하므로 이름이 정의와 달라도 오류가 아니라 경고다.
- †를 붙이는 기준은 [CONTRIBUTING.md](https://github.com/Trace2Bac/dfir-mcp-architecture-matrix-v2/blob/main/CONTRIBUTING.md#판단-기준)에 있다.

## 새 서버 원고를 시작한다

1. `matrix/config.yaml`의 `servers`에 이름이 있는지 본다.
2. `reports/<서버>/index.mdx`를 위 모양으로 만든다.
3. `pilot_cells`의 셀마다 `<셀ID>.mdx`를 만든다.
4. `fill <서버>` → `check <서버>` → `build`.
