# F06 보고 산출물 구성

### F06.01 증거·환경 manifest 포함

**구현.** 이 방식은 사용자가 `scripts/verdict`나 `scripts/find_evil_auto.py`를 실행해야 만들어지는 `verdict.json`과 `REPORT.md`, 그 실행이 `findevil-agent-mcp`의 `manifest_finalize`로 쓰게 하는 `run.manifest.json`에 적용된다 [1][2][3].
다른 MCP 클라이언트로 붙으면 서버가 쓰는 산출물은 `manifest_finalize`의 `run.manifest.json`뿐이고 그 `extra`에는 호출자가 준 값이 그대로 들어간다 [3][4].
클라이언트 엔진 `find_evil_auto.py`는 두 서버의 응답과 호출 기록을 모아 `verdict.json`을 쓰고 `render_report.py`로 보고서를 만든다 [5][2].

- `verdict.json`에는 증거 경로, 증거 종류, 사건 ID, 실행 ID, 시작·마감 시각과 증거 목록 `evidence_inventory`가 실린다 [5].
- `evidence_inventory`는 증거가 폴더일 때 엔진이 파일마다 경로, SHA-256, 크기를 적은 목록이다 [6][5].
- 엔진은 `manifest_finalize`의 `extra`에 증거 경로, 증거 종류, 서명 방식, 증거 목록의 SHA-256과 요약을 넣는다 [7].
- `REPORT.md` 머리에는 사건 ID, 실행 ID, 시작·마감 시각, 증거 파일 이름, Merkle root, 호출 기록 끝 해시, 서명 종류와 서명한 본문의 SHA-256이 실린다 [8].

**한계.** `REPORT.md`에는 증거의 해시와 크기가 없고 증거 경로도 파일 이름만 실린다 [8].
증거가 파일 하나이면 `evidence_inventory`가 없어 `verdict.json`에도 증거 해시가 실리지 않는다 [5].
서버와 분석 도구의 버전은 세 산출물 어디에도 실리지 않는다 [5][7][8].
`extra`의 `model` 값은 실행과 관계없이 `find-evil-auto`로 정해져 있다 [7].

### F06.02 수행·누락 범위 포함

**구현.** 이 방식은 사용자가 엔진을 실행해야 만들어지는 `verdict.json`, `coverage_manifest.json`, `REPORT.md`에 적용된다 [5][9][10].
`verdict.json`의 `tool_calls`에는 엔진이 부른 `findevil-mcp` 도구마다 `tool_call_id`, 도구 이름, 출력 해시, 인자가 실린다 [11][5].
`coverage_manifest`는 아티팩트 분류마다 있었는지, 시도했는지, 파싱했는지, 실패했는지, 지원하지 않는지, 받지 못했는지와 시도한 도구를 싣는다 [10].
`REPORT.md`의 `Coverage Manifest` 절은 이 표와 지원하지 않은 증거 경로를 20개까지 싣고 이 행들이 깨끗한 결과가 아니라 범위의 빈 곳이라고 적는다 [10].
`run.manifest.json`의 Merkle leaf는 호출 기록의 `tool_call_output` 기록마다 `tool_call_id`와 출력 해시를 싣는다 [12].
시험 입력으로 `REPORT.md`를 만들자 `Coverage Manifest` 절에 파싱한 분류와 시도한 도구 `hashset_lookup`, 지원하지 않은 메모리 증거 경로가 실렸다 [13].

**한계.** `REPORT.md`는 `tool_calls`를 표로 싣지 않고 분류마다 시도한 도구 이름만 싣는다 [10][14].

### F06.03 발견사항과 근거 링크 포함

**구현.** 이 방식은 사용자가 엔진을 실행해야 만들어지는 `REPORT.md`·`REPORT.html`과 `verdict.json`에 적용된다 [2][5].
`REPORT.md`의 `Detailed Findings`는 발견사항마다 등급, pool, ATT&CK 기법, 설명, `tool_call_id`, 아티팩트 경로를 싣는다 [15].
`verify_finding`이 출력에서 다시 읽은 값이 있으면 그 경로와 값을 증거에서 읽은 값으로 따로 싣는다 [15][16].
CONFIRMED 발견사항에는 `grep <tool_call_id> audit.jsonl`을 실행해 호출 기록을 찾으라는 줄을 붙인다 [17].
`REPORT.html`에는 `audit.jsonl` 전체를 base64로 넣어 내려받을 수 있게 하고 그 SHA-256을 적는다 [18].
`Reproducibility Appendix`는 발견사항마다 다시 실행한 도구, 결과 분류, 일치 여부, 기대 해시와 실제 해시 앞 12자를 싣는다 [19].
사용자 CLI `scripts/trace-finding`은 사건 폴더에서 발견사항마다 `tool_call_id`, 호출 기록 줄, Merkle leaf를 찾아 표준 출력에 낸다 [20].
시험 입력으로 만든 `REPORT.md`의 CONFIRMED 발견사항에는 `tool_call_id`, 다시 읽은 해시 값, `grep tc-1 audit.jsonl` 줄이 실렸다 [13].

**한계.** HYPOTHESIS·INFERRED 발견사항에는 호출 기록을 찾는 줄이 붙지 않는다 [17].
`REPORT.md`에는 `audit.jsonl`이 들어가지 않고 `grep` 줄이 가리키는 기록은 `REPORT.html`이나 같은 폴더의 `audit.jsonl`에서 찾아야 한다 [17][18].
pandoc이 없으면 `REPORT.html`이 만들어지지 않는다 [18][21].

### F06.04 검증·한계 포함

**구현.** 이 방식은 사용자가 엔진을 실행해야 만들어지는 `REPORT.md`, `REPORT-internal.md`, `verdict.json`에 적용된다 [2][22][5].
`REPORT.md`에는 다음 검증 결과와 한계가 실린다 [15][19][23][24].

- `Reproducibility Appendix`는 발견사항마다 다시 실행한 결과가 기록 해시와 같았는지 싣는다 [19].
- 발견사항마다 `verify_finding`이 출력에서 다시 읽은 값을 싣는다 [15][16].
- `Verifier-Rejected Leads`는 다시 실행에서 거부된 발견사항을 20개까지 사유, 결과, 사용자 조치와 함께 싣고 최종 발견사항에서 뺐다고 적는다 [23].
- `Limitations`는 엔진이 정리한 이 사건에서 말할 수 없는 것과 분석 한계를 중복 없이 싣는다 [24].
- `Coverage Manifest`는 시도하지 못했거나 지원하지 않은 분류를 싣는다 [10].

`REPORT-internal.md`는 엔진의 보고서 점검 결과, 공개를 막는 사유, `manifest_verify` 결과, 서명 방식, 전문가 승인 상태를 싣는다 [22][25].
시험 입력으로 만든 `REPORT.md`에는 분석 한계 한 줄, 거부된 발견사항 한 줄, 다시 실행 결과 한 줄이 실렸다 [13].

**한계.** `REPORT.md`의 `Integrity Verification` 절은 실행과 관계없이 늘 같은 검증 방법 안내이고 이번 실행의 `manifest_verify` 결과는 싣지 않는다 [26].
변조 시험은 실행하지 않았다는 문구도 늘 같다 [26].

### F06.05 내보내기

**구현.** 이 방식은 사용자가 `scripts/verdict`나 `find_evil_auto.py`를 실행할 때와 `findevil-agent-mcp`의 `manifest_finalize`를 부를 때 쓰는 파일에 적용된다 [1][3].
`manifest_finalize`는 호출자가 준 `output_path`에 `run.manifest.json`을 쓰고 그 경로를 `manifest_path`로 돌려준다 [3][27].
엔진은 사건 폴더의 `audit.jsonl`, `run.manifest.json`, `verdict.json`을 호스트의 `tmp/auto-runs/<사건 ID>/`로 가져오고 `timeline.json`, `timeline.csv`, `coverage_manifest.json`, `evidence_inventory.json` 같은 파일을 더 쓴다 [9].
`--no-report`를 주지 않았고 엔진의 보고서 점검이 전문가 검토로 넘길 수 있다고 정했을 때만 `render_report`를 불러 `REPORT.md`, `REPORT.html`, `REPORT.pdf`, `REPORT-internal.md`를 쓴다 [2][28].
`render_report`는 `verdict.json`으로 STIX 2.1 공격 흐름 `incident.attack-flow.json`과 ATT&CK Navigator 층 `navigator-layer.json`을 `attack-flow/`에 쓴다 [29][30].
`REPORT.html`은 pandoc으로, `REPORT.pdf`는 Chrome으로 만들고 둘이 없으면 만들지 않는다 [21].
시험 입력으로 `write_markdown`을 부르자 사건 폴더에 `REPORT.md`와 `REPORT-internal.md`가 생겼다 [13].

**한계.** 엔진은 `render_report`에서 예외가 나면 보고서를 건너뛰었다고 표준 출력에 적고 실행을 마친다 [2].
공격 흐름 파일을 만들다 예외가 나도 표준 오류에 적고 빈 글로 보고서를 계속 만든다 [30].

### F06.07 판단의 확정 상태 표시

**구현.** 이 방식은 사용자가 엔진을 실행해야 만들어지는 `REPORT.md`와 `verdict.json`에 적용된다 [2][5].
`REPORT.md`의 `Case Summary`는 합친 발견사항 수를 CONFIRMED, INFERRED, HYPOTHESIS로 나눠 싣고 Pool A·B 모순 수와 상관 분석에서 유지·하향한 수를 싣는다 [31].
`Detailed Findings`는 발견사항마다 등급을 소제목에 싣고 등급마다 정한 뜻을 붙인다 [15].
CONFIRMED는 인용한 도구 출력이 재현된다는 뜻이고 귀속이나 전체 범위를 뜻하지 않는다고 적는다 [15].
INFERRED는 확인된 사실에서 끌어낸 것이라 조치 전에 확인하라고 적는다 [15].
HYPOTHESIS는 출처 하나의 단서라 대응 전에 보강하라고 적는다 [15].
`verdict.json`의 `findings_summary`는 등급별 수와 조사 범위로 깎은 점수 `coverage_discounted_confidence`를 싣는다 [5].
`Self-Correction` 절은 실행 중 등급이 바뀐 발견사항마다 앞 등급과 바뀐 등급, 계기가 된 `tool_call_id`, 바꾼 방식, 사유를 20개까지 싣고 넘는 것은 수만 적는다 [32].
시험 입력으로 만든 `REPORT.md`에는 CONFIRMED 1개와 HYPOTHESIS 1개가 나뉘어 실리고 등급마다 정한 뜻이 붙었다 [13].

```python
def entailment_evidence_lines(finding: dict[str, Any]) -> list[str]:
    """Markdown bullet lines naming the value the parser read from evidence for
    each confirmed asserted value, or ``[]`` when the finding carries no
    entailment slice. Malformed matched entries are skipped, never raised on."""
    artifact = finding.get("replay_artifact") or {}
    slice_ = artifact.get("entailment") or {}
    matched = slice_.get("matched") or []
    lines: list[str] = []
    for m in matched:
        if not isinstance(m, dict):
            continue
        path = str(m.get("path", "?"))
        actual = str(m.get("actual", ""))
        lines.append(
            f"- read from evidence (entailment-confirmed, not transcribed): "
            f"`{path}` = `{actual}`"
        )
    return lines
```

```python
def confirmed_reverify_affordance(finding: dict[str, Any]) -> list[str]:
    """Copy-paste offline re-verification line for a CONFIRMED finding.

    Returns Markdown lines giving a reader a one-line ``grep <tool_call_id>
    audit.jsonl`` they can run against the audit.jsonl embedded in ``REPORT.html``,
    so a CONFIRMED finding can be re-verified fully offline with no server. Returns
    an empty list for any non-CONFIRMED finding (leads must never be dressed up as
    reproducible) or a finding without a usable ``tool_call_id``. Presentation-only:
    it never changes the finding, its confidence, or the verdict.
    """
    if str(finding.get("confidence", "")).strip().upper() != "CONFIRMED":
        return []
    tcid = str(finding.get("tool_call_id") or "").strip()
    if not tcid or tcid.lower() == "n/a":
        return []
    # Keep the id safe inside a backtick code span; tool_call_ids are audit-chain
    # identifiers, so this only guards against an accidental span break.
    safe_tcid = tcid.replace("`", "'")
    return [
        f"- re-verify offline: `grep {safe_tcid} audit.jsonl` — runs against the "
        "embedded audit.jsonl in this report (see Offline Re-Verification below).",
    ]
```

```python
def _emit_attack_flow(case_dir: "Path") -> str:
    """Render attack-flow + process-tree panels. Presentation only.

    Never raises: a visualization failure must not break the custody report.
    Returns an HTML snippet to embed, or "" on any failure.
    """
    try:
        # Import attackflow as a TOP-LEVEL package (its parent dir on sys.path), NOT
        # as findevil_agent.attackflow — the deterministic engine runs under host
        # python3 (may be 3.10), where findevil_agent/__init__.py -> config.py pulls
        # 3.11-only names (StrEnum, datetime.UTC) and would fail. attackflow itself is
        # pure stdlib + relative imports, so it loads cleanly on 3.10 this way.
        attackflow_parent = (
            Path(__file__).resolve().parents[1]
            / "services"
            / "agent"
            / "findevil_agent"
        )
        if str(attackflow_parent) not in sys.path:
            sys.path.insert(0, str(attackflow_parent))
        from attackflow import emit as _emit

        return _emit(Path(case_dir)).html_snippet
    except Exception as exc:  # noqa: BLE001 - viz must never break the report
        try:
            print(f"[attack-flow] skipped: {exc}", file=sys.stderr)
        except Exception:
            pass
        return ""
```
