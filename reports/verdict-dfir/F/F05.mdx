# F05 발견사항·결론 근거 검증

### F05.01 근거 참조 존재 확인

**구현.** 이 방식은 `findevil-agent-mcp`의 `manifest_finalize`와 `verify_finding`에 적용된다 [1][2].
`manifest_finalize`는 서명하기 전에 `audit.jsonl`을 처음부터 읽어 `finding_approved` 기록마다 `tool_call_id`가 그보다 앞선 `tool_call_output` 기록에 있는지 대조한다 [3].
`tool_call_id`가 비었거나 앞선 출력 기록에 없는 발견사항이 하나라도 있으면 `UncitedFindingError`로 manifest를 만들지 않는다 [4][1].
`verify_finding`은 발견사항의 `tool_call_id`가 비었거나 호출자가 넘긴 `tool_call_index`에 없으면 다시 실행하지 않고 `rejected`를 돌려준다 [5][6].
CONFIRMED·INFERRED 발견사항은 `Finding` schema가 빈 `tool_call_id`를 거부하고 `verify_finding`은 이 거부를 `rejected`로 바꿔 돌려준다 [7][2].
인용한 호출이 없는 `finding_approved` 기록과 출력 기록보다 앞에 놓인 `finding_approved` 기록은 manifest 봉인이 거부되었다 [8].
인용한 출력 기록이 앞에 있는 기록은 봉인되었다 [8].
목록에 없는 `tool_call_id`를 인용한 발견사항은 `verify_finding`이 `rejected`로 돌려줬다 [8].

**한계.** `tool_call_output` 기록도 호출자가 `audit_append`로 아무 `tool_call_id`와 해시로 남길 수 있다 [9].
`manifest_finalize`는 그 호출이 `findevil-mcp`에서 실제로 있었는지 대조하지 않는다 [3].
지어낸 `tool_call_id`로 출력 기록을 먼저 남기고 그 ID를 인용한 `finding_approved` 기록은 봉인되었다 [8].
`verify_finding`의 `tool_call_index`는 호출자가 넘긴 값이고 서버는 이 목록을 `audit.jsonl`과 대조하지 않는다 [2][6].
INFERRED 발견사항이 기대는 사실의 ID `derived_from`은 어느 경로에서도 대조하지 않는다 [3][6].
기록에 없는 ID를 `derived_from`에 적은 INFERRED 발견사항도 `verify_finding`에서 `approved`로 나왔다 [8].
`FIND_EVIL_REQUIRE_TOOL_CALL_ID`를 `0`으로 두면 `Finding` schema의 빈 `tool_call_id` 검사가 꺼진다 [7].

### F05.02 근거 내용 대조

**구현.** 이 방식은 `findevil-agent-mcp`의 `verify_finding`에 적용된다 [2].
`verify_finding`은 호출마다 호출자가 준 명령 `findevil_mcp_command`로 `findevil-mcp`를 새로 실행하고 `tool_call_index`에서 찾은 도구와 인자로 인용한 호출을 다시 실행한다 [2][10].
다시 실행한 도구는 증거를 다시 읽는다 [10].
서버 안의 MCP 클라이언트는 받은 응답 글의 SHA-256을 계산해 기록된 `output_sha256`과 대조한다 [11][12].
해시가 같으면 발견사항의 `asserted_values`마다 경로로 출력 JSON의 값을 찾아 `exact`, `contains`, `iso_ts`, `int`, `record` 방식으로 기대값과 대조한다 [13][14].

- 해시나 IP 주소처럼 식별값인 기대값이 출력에 없으면 등급과 관계없이 `rejected`다 [13][15].
- 그 밖의 기대값이 없으면 CONFIRMED는 `rejected`, `downgrade_on_drift`를 참으로 주거나 아래 등급이면 `downgraded`다 [13].
- `count`로 주장한 수보다 맞는 값이 적으면 `downgraded`다 [13].
- 해시가 다르면 CONFIRMED는 `rejected`, `downgrade_on_drift`를 참으로 주거나 아래 등급이면 `downgraded`다 [16].
- 다시 실행하다 오류가 나면 `rejected`다 [17].

`approved`의 사유에는 출력에서 다시 읽은 값을 적고 `replay_artifact`에 그 값을 싣는다 [13].
`FIND_EVIL_REQUIRE_EXPECTATION`을 `1`로 두면 발견사항이 적은 예측 `expectation`이 출력의 값과 어긋날 때도 같은 처분을 한다 [18].
`FIND_EVIL_REQUIRE_ARTIFACT_REBIND`를 `1`로 두면 발견사항의 `artifact_path`가 인용한 호출의 `*_path` 인자와 다를 때 다시 실행하기 전에 `rejected`를 돌려준다 [19].
`judge_findings`는 받은 검증 결과가 `rejected`인 발견사항을 빼고 `downgraded`인 발견사항의 등급을 한 단계 낮춘다 [20].
`hashset_lookup` 호출을 인용한 시험 발견사항에서 맞는 해시와 판정 값은 `approved`, 틀린 해시는 `rejected`, 틀린 판정 값은 CONFIRMED에서 `rejected`와 INFERRED에서 `downgraded`가 나왔다 [8].
기록 해시를 다르게 준 CONFIRMED 발견사항은 `rejected`, `downgrade_on_drift`를 함께 주자 `downgraded`가 나왔다 [8].

**한계.** `tool_call_index`의 도구, 인자, 기대 해시와 실행할 명령 `findevil_mcp_command`는 모두 호출자가 넘긴다 [2].
서버는 이 값을 `audit.jsonl`에서 읽지 않으므로 기대 해시가 호출 기록과 같은지는 호출자에 달려 있다 [2][6].
서버는 `findevil_mcp_command`가 가리키는 프로그램을 검사하지 않고 그 프로그램의 응답 글을 다시 실행한 출력으로 대조한다 [2][21].
HYPOTHESIS 발견사항은 `asserted_values` 없이 해시만 대조한다 [7][13].
INFERRED 발견사항도 `derived_from`만 있으면 `asserted_values` 없이 해시만 대조한다 [7][13].
`FIND_EVIL_REQUIRE_ASSERTED_VALUES`를 `0`으로 두면 CONFIRMED도 `asserted_values` 없이 받는다 [7].
`asserted_values`는 발견사항을 낸 쪽이 고르고 설명 글 `description`은 대조하지 않는다 [13][14].
`contains` 방식에 빈 기대값을 주면 경로에 값이 하나만 있어도 맞는 것으로 본다 [22].
빈 기대값을 `contains`로 적은 CONFIRMED 발견사항은 `approved`로 나왔다 [8].
`verify_finding`은 처분을 응답으로만 돌려주고 `judge_findings`는 호출자가 넘긴 검증 결과를 다시 확인하지 않는다 [2][20].

### F05.03 출처 수·범주로 등급 산정

**구현.** 이 방식은 `findevil-agent-mcp`의 `correlate_findings`에 적용된다 [23].
`correlate_findings`는 발견사항의 설명 글에서 Prefetch, Amcache, ShimCache, UserAssist, EDR, 네트워크, 프로세스, 로그온, 레지스트리 같은 아티팩트 분류를 정규식으로 찾는다 [24].
실행 주장은 Prefetch와 Amcache·ShimCache·UserAssist 가운데 하나, 또는 EDR 기록이 있어야 등급을 유지한다 [25].
전술 검사는 기법마다 정한 분류 조합 가운데 하나를 채워야 등급을 유지한다 [26].
채우지 못하면 등급을 한 단계 낮추고 빠진 분류를 `missing_classes`에 싣는다 [27].
그다음 등급 상한 표를 적용해 Logon Type 3·10 기록이 없는 횡적 이동 주장과 덤프 흔적 없이 LSASS 접근만 적은 주장을 INFERRED를 넘지 않게 낮춘다 [28].
`FIND_EVIL_REQUIRE_TEMPORAL_COUPLING`을 `1`로 두면 실행 시각을 등록 시각류 출처로만 적었거나 실행 시각 출처끼리 300초 넘게 어긋나는 주장도 한 단계 낮춘다 [29][30].
시험 입력에서 Amcache만 적은 CONFIRMED 실행 주장과 Logon Type 없는 횡적 이동 주장은 INFERRED로, Prefetch와 Amcache를 함께 적은 실행 주장은 CONFIRMED로 나왔다 [31].
등록 시각만 적은 주장과 실행 시각 출처가 두 시간 어긋난 주장은 이 환경변수를 켜자 INFERRED로 나왔다 [32].

**한계.** 분류는 설명 글의 낱말로 정하고 인용한 호출의 도구나 출력은 보지 않는다 [24][25].
그래서 Prefetch와 Amcache라는 낱말을 적은 주장은 그 두 아티팩트를 조회한 호출이 없어도 등급을 유지한다 [25].
따옴표 안 낱말은 `FIND_EVIL_NEUTRALIZE_QUOTED_CLASSES`를 `1`로 두어야 분류에서 빠진다 [33].
기본값에서는 증거에서 옮겨 적은 따옴표 안 글도 분류를 찾는 데 쓴다 [33].
따옴표 안에만 Prefetch와 Amcache를 적은 실행 주장은 기본값에서 CONFIRMED를 유지했고 이 환경변수를 켜자 INFERRED로 나왔다 [32].
실행 주장도 전술 검사 대상도 아닌 발견사항은 분류를 보지 않고 그대로 둔다 [23][31].
`correlate_findings`는 낮춘 등급을 응답으로만 돌려주고 그 등급을 쓸지는 호출자가 정한다 [23].

### F05.04 교차 확인·반론 검토

**구현.** 이 방식은 환경변수를 켰을 때 `findevil-agent-mcp`의 `verify_finding`, `correlate_findings`를 포함해 `Finding` schema로 발견사항을 받는 도구에 적용된다 [7][2][34].
`FIND_EVIL_REQUIRE_COUNTER_HYPOTHESIS_FINDING`을 `1`로 두면 배제한 다른 설명 `counter_hypothesis`가 빈 CONFIRMED 발견사항을 `Finding` schema가 거부한다 [7].
같은 상태에서 `verify_finding`은 이 필드가 빈 CONFIRMED 발견사항을 schema 검사에서 거부하고 다시 실행하지 않은 채 `rejected`로 돌려준다 [2][7].
`correlate_findings`는 이 필드가 빈 INFERRED·HYPOTHESIS 실행 주장을 다른 분류 검사보다 먼저 한 단계 낮춘다 [34].
이 필드가 빈 CONFIRMED 발견사항이 하나라도 들어가면 `correlate_findings`, `judge_findings`, `detect_contradictions`는 schema 검사에서 처리를 멈추고 `error` 응답 글을 돌려준다 [7][35].
환경변수를 켜자 `counter_hypothesis`가 빈 CONFIRMED 발견사항은 `verify_finding`에서 schema 거부 사유와 함께 `rejected`로 나왔고 같은 조건의 INFERRED 실행 주장은 `correlate_findings`에서 한 단계 낮춰졌다 [36].

**한계.** 이 환경변수는 기본값에서 꺼져 있다 [7].
서버는 `counter_hypothesis`가 비었는지만 보고 그 내용이 근거와 맞는지는 대조하지 않는다 [7][34].

```python
def _uncited_findings(audit_log: AuditLog) -> list[str]:
    """finding_approved records whose tool_call_id is absent from the chain
    so far. Chain order matters: a finding cannot cite a future tool call."""
    seen_tool_calls: set[str] = set()
    uncited: list[str] = []
    for record in audit_log.iter_records():
        if record.kind == "tool_call_output":
            tcid = str(record.payload.get("tool_call_id") or "")
            if tcid:
                seen_tool_calls.add(tcid)
        elif record.kind == "finding_approved":
            cited = str(record.payload.get("tool_call_id") or "")
            if not cited or cited not in seen_tool_calls:
                uncited.append(str(record.payload.get("finding_id") or f"seq-{record.seq}"))
    return uncited
```
