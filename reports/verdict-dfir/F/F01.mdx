# F01 판단 지침

### F01.02 결론 서술 방식 안내

**구현.** 이 방식은 `findevil-agent-mcp`의 `verify_finding`이 입력 schema의 `finding` 인자 설명에 적는 안내에 적용된다 [1].
이 설명은 CONFIRMED·INFERRED 발견사항이 주장하는 구조화한 사실을 `asserted_values`에 경로, 기대값, 대조 방식으로 적으라고 안내한다 [1].
식별값인 해시나 IP가 틀리면 바로 거부된다고 적는다 [1].
수를 주장하면서 `count`를 두었는데 근거 줄이 모자라면 등급이 내려간다고도 적는다 [1].

두 서버는 서버 지침, MCP 리소스, MCP 프롬프트를 두지 않는다 [2].
등급마다 무엇을 갖춰야 하는지, HYPOTHESIS 설명 앞에 `hypothesis:`를 붙이라는 것, CONFIRMED 실행 주장에 배제한 다른 설명을 `counter_hypothesis`로 적으라는 것은 클라이언트 자료 `agent-config/SOUL.md`에 있다 [3].
이 자료는 클라이언트가 읽는 문서이고 서버가 내놓지 않는다 [2][3].

**한계.** `verify_finding`의 `finding` 인자 schema는 `dict` 하나여서 `counter_hypothesis`, `why_not_higher`는 schema와 도구 설명 어디에도 나오지 않고 `derived_from`은 `judge_findings` 설명에만 나온다 [1][4].
환경변수로 `counter_hypothesis` 검사를 켜면 `verify_finding`은 이 필드가 빈 CONFIRMED 발견사항을 거부하고 이 필드 이름을 적은 사유 글을 돌려준다 [5][6].

### F01.03 발견사항별 보완 안내

**구현.** 이 방식은 `findevil-agent-mcp`의 `correlate_findings`와 `detect_contradictions` 응답에 적용된다 [7][8].
`correlate_findings`는 발견사항마다 `outcomes`에 적용한 검사 `gate`, 그 검사가 받는 아티팩트 분류 조합 `required_pairs`, 가장 가까운 조합을 채우려면 더할 분류 `missing_classes`를 싣는다 [7][9].
Amcache만 적은 실행 주장에는 Amcache의 `LastModified`는 실행 시각이 아니라는 사유를 싣는다 [9].
`detect_contradictions`는 어떤 흔적이 있다는 발견사항에 함께 있어야 할 다른 흔적이 전체 발견사항에 없으면 빠진 흔적을 적고 결론 전에 보강하라는 문구를 붙인 기록을 낸다 [10].
시험 입력에서 Amcache만 적은 실행 주장에는 `missing_classes`로 `prefetch`가, Logon Type 기록 없는 횡적 이동 주장에는 `logon`이 실렸다 [11].
EID 1102 로그 삭제를 적은 발견사항에는 삭제된 기록이 빠져 있다는 단서와 결론 전에 보강하라는 문구가 실렸다 [11].

**한계.** 실행 주장이나 전술 검사에 해당하지 않는 발견사항은 `non-execution claim` 사유만 받고 보완할 분류를 받지 않는다 [9][11].

### F01.04 공통 확인 절차 안내

**구현.** 이 방식은 `findevil-agent-mcp`의 `verify_finding`, `judge_findings`, `manifest_finalize` 도구 설명에 적용된다 [12][13][14].
`verify_finding`의 설명은 두 pool이 발견사항을 낸 뒤 `judge_findings` 전에 이 도구로 인용한 호출을 다시 실행하라고 적는다 [12].
`judge_findings`의 설명은 `verify_finding`과 `detect_contradictions`를 먼저 부르라고 적는다 [13].
`manifest_finalize`의 설명은 모든 발견사항을 검증하고 모순을 해결한 뒤 부르라고 적는다 [14].
세 문구는 발견사항의 내용과 관계없이 늘 같다 [12][13][14].

async def _handle(inp: BaseModel) -> DetectContradictionsOutput:
    assert isinstance(inp, DetectContradictionsInput)
    pool_a = [Finding.model_validate(f) for f in inp.pool_a]
    pool_b = [Finding.model_validate(f) for f in inp.pool_b]

    pairs = detect_contradictions(pool_a, pool_b)
    events = to_events(
        pairs,
        case_id=inp.case_id,
        resolution_required=inp.resolution_required,
    )

    # Cross-source anti-forensics 'something is missing' leads, scanned over the
    # COMBINED finding set and surfaced through the same resolution path so the
    # engine's existing contradiction consumer picks them up unchanged.
    leads = detect_antiforensics(pool_a + pool_b)
    af_events = antiforensics_to_events(
        leads,
        case_id=inp.case_id,
        resolution_required=inp.resolution_required,
    )

    records = [_to_record(ev) for ev in events] + [_to_record(ev) for ev in af_events]
    return DetectContradictionsOutput(
        contradictions=records,
        pool_a_count=len(pool_a),
        pool_b_count=len(pool_b),
        antiforensics_count=len(af_events),
    )
