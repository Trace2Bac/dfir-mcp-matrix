# E04 분석 입력 준비

### E04.01 작업 사본 생성

**구현.** 이 방식은 `findevil-mcp`의 `pst_parse`·`srum_parse`에 적용된다 [1][2].
`pst_parse`는 `pffexport -m all`로 PST 메일 보관 파일의 항목 전체를 사건 폴더의 `extracted/pst/pst-export-<UUID>/` 아래에 꺼내고 그 폴더를 읽어 메시지 요약을 돌려준다 [1].
`srum_parse`는 `esedbexport`로 `SRUDB.dat`의 표 전체를 사건 폴더의 `_xartifact/` 아래 작업 폴더에 내보내고 그 가운데 네트워크 사용량 표 파일을 해석한다 [2].
시험용 `pffexport`로 `pst_parse`를 부르자 내보낸 파일이 사건 폴더에 남았다 [3].

**한계.** `pst_parse`의 응답에는 꺼낸 폴더의 경로가 없다 [4].
`srum_parse`는 해석을 마치면 성공과 실패 모두 내보낸 작업 폴더를 지운다 [2].

### E04.02 선택 추출

**구현.** 이 방식은 `findevil-mcp`의 `disk_extract_artifacts`에 적용된다 [5].
`disk_extract_artifacts`는 `fls -r -p`로 이미지의 파일 목록을 읽고 경로와 이름으로 아티팩트 종류를 정한다 [6][7].
모델이 `artifact_kinds`로 고른 종류, 주지 않으면 정해 둔 26종 가운데 해당하는 파일만 후보로 삼는다 [8][7].
후보는 종류 우선순위 차례로 돌아가며 하나씩 골라 `limit`(기본 500)개까지 뽑고 이벤트 로그는 `Security.evtx` 같은 주요 로그를 먼저 고른다 [9][10].
고른 파일은 `icat`으로 inode 내용을 꺼내 사건 폴더의 `extracted/disk/<extract_id>/<종류>/` 아래에 이미지 안 경로대로 쓴다 [11].
`recover_deleted`가 참(기본값)이면 삭제됐지만 inode가 남은 항목도 꺼내 `__deleted__/<inode>/` 아래에 둔다 [12][11].
꺼낸 파일의 경로는 응답에 실리고 도구 설명은 이 경로를 `registry_query`·`evtx_query` 같은 파서에 주라고 적는다 [13][14].
시험용 `fls`·`icat`으로 실행하자 레지스트리 하이브가 꺼내져 응답에 실렸고 inode가 다시 쓰인 삭제 항목은 꺼내지 않았다 [15].

**한계.** `disk_mount`를 `mode: mock`으로 부르면 서버는 마운트하지 않고 호출 인자 `mount_point`의 폴더를 자원의 `fs_root`로 적는다 [16].
`disk_extract_artifacts`는 이 자원의 이미지를 Sleuth Kit으로 읽지 못하면 `fs_root` 폴더의 파일을 아티팩트로 복사한다 [17].
이때 항목의 `source_path`는 이미지 안 경로가 아니라 그 폴더 안 경로이고 응답은 이를 따로 표시하지 않는다 [18][19].
크기 상한 `max_artifact_bytes`(기본 512 MiB)는 `icat`이 파일을 다 쓴 뒤 크기를 보고 지우는 방식이라 상한을 넘는 파일도 한 번은 사건 폴더에 쓰인다 [11].
도구 설명은 상한을 넘는 파일을 복사하기 전에 건너뛴다고 적는다 [13].

### E04.03 전체·부분 마운트

**구현.** 이 방식은 `findevil-mcp`의 `disk_mount`와 `disk_extract_artifacts`에 적용된다 [20][5].
`disk_mount`는 raw 이미지를 `ro,loop`로 마운트하고 실패하면 `mmls`로 고른 가장 긴 파일 시스템 파티션의 시작 위치를 `offset`으로 붙여 다시 마운트한다 [20][21].
EWF 이미지는 `ewfmount`로 연 뒤 그 안의 NTFS 볼륨을 시작 위치 0이나 같은 파티션 위치로 `ntfs3` loop 마운트한다 [22][23].
`disk_extract_artifacts`는 마운트를 쓰지 않고 서버가 고른 파티션의 섹터 위치를 `fls`·`icat`의 `-o` 인자로 넘겨 그 파티션만 읽는다 [24][21].
마운트 위치는 사건 폴더의 `mounts/<mount_id>`이고 `mount_point`를 주면 그 위치를 쓴다 [25].
시험용 `mmls`가 파티션 3개를 내자 `disk_mount`는 가장 긴 파티션의 위치로 마운트했고 `fls`·`icat`은 `-o 1026048`을 받았다 [15].

`vss_mount`는 `vshadowmount`로 볼륨 섀도 복사본마다 `vssN` 볼륨 파일을 드러내고 그 경로 목록을 돌려준다 [26].
이 파일은 파일 시스템이 아닌 볼륨 이미지이고 서버는 그 안의 파일 시스템을 마운트하지 않는다 [26].

**한계.** 다른 파일 시스템 파티션은 `partitions`에 실리기만 하고 마운트나 꺼내기 대상이 되지 않는다 [21][24].
`ewfmount`는 있는데 NTFS 볼륨을 마운트하지 못하면 EWF 컨테이너만 마운트한 채 `mounted`로 등록한다 [22].
`ewfmount`가 없으면 마운트 없이 `mounted` 항목을 등록한다 [27].
`mmls`가 실패하거나 파티션 표가 없으면 시작 위치 0으로 읽는다 [21][24].

### E04.04 추출·생략 범위 기록

**구현.** 이 방식은 `findevil-mcp`의 `disk_mount`·`disk_extract_artifacts` 응답과 사건 폴더의 `session_resources.json`에 적용된다 [28][29][30].
`disk_extract_artifacts`의 응답에는 꺼낸 파일마다 종류, 이미지 안 경로, 꺼낸 경로, 크기, 삭제 항목 여부가 실린다 [28].
크기 상한으로 건너뛴 수, 본 삭제 항목 수, 꺼낸 삭제 항목 수, inode가 다시 쓰여 건너뛴 수, 내용을 읽지 못한 삭제 항목 수도 함께 실린다 [28].
같은 꺼낸 파일 목록은 부모 마운트 ID, 출력 폴더, 실행 명령과 함께 `session_resources.json`의 `disk_extract_artifacts` 항목에 남는다 [30].
`disk_mount`는 파티션 표의 파일 시스템 파티션을 `partitions`에 싣고 마운트한 위치와 명령을 `note`·`command`에 싣는다 [29].

**한계.** `limit`에 닿아 고르지 않은 후보 수는 응답과 기록에 남지 않는다 [9][28].
`limit` 4로 실행하자 고르지 않은 후보 5개는 응답 어디에도 나타나지 않았다 [31].
삭제되지 않은 파일의 `icat`이 실패하면 그 파일을 빼고 따로 세지 않는다 [11].
`artifacts_seen`은 이름과 달리 꺼낸 파일 수와 같다 [28].
`mode: mock` 자원의 폴더에서 복사한 경우에도 `session_resources.json`의 꺼내기 항목은 `command`를 `fls`·`icat`으로 적고 `note`에 이미지에서 Sleuth Kit으로 꺼냈다고 적는다 [32].

### E04.05 부속 자료 탐색

**구현.** 이 방식은 `findevil-mcp`의 분할 EWF 조각 탐색 `segment_paths_for_image`에 적용된다 [33].
이 함수는 첫 조각과 같은 폴더에서 이름 줄기가 같고 확장자가 `E`·`Ex`와 번호로 된 파일을 모아 번호 차례로 늘어놓는다 [33].
`case_open`은 모은 조각 전체를 이어 해시하고 `disk_mount`·`disk_extract_artifacts`는 모은 조각을 `ewfmount`, `mmls`, `fls`, `icat`의 인자로 함께 넘긴다 [34][35][11].
`E01`·`E02` 두 조각을 둔 폴더에서 첫 조각으로 `case_open`을 부르자 두 조각이 `image_segments`에 실렸다 [36].

**한계.** `bulk_extract`, `vss_list`, `vss_mount`는 받은 경로 하나만 외부 도구에 넘긴다 [37].
`disk_extract_artifacts`는 레지스트리 트랜잭션 로그 `.LOG1`·`.LOG2`를 `reg_txlog` 종류로 꺼내지만 하이브와 묶지 않는다 [7].
`registry_query`는 트랜잭션 로그를 읽지 않고 하이브 파일만 해석한다 [38].
`browser_history`는 SQLite 기록 파일을 `immutable=1`로 열어 옆의 `-wal` 파일을 반영하지 않는다 [39].

### E04.06 부속 자료 누락·로그 미반영 표시

**구현.** 이 방식은 분할 EWF 조각 탐색에 적용된다 [33].
`segment_paths_for_image`는 보이는 가장 큰 번호보다 작은 번호의 조각이 빠져 있으면 오류로 끝난다 [33].
`case_open`·`disk_mount`·`disk_extract_artifacts`는 이 오류를 `EwfSegmentSet` 오류로 바꾸고 서버는 JSON-RPC 오류 코드 `-32602`로 돌려준다 [34][40].
`E01`과 `E03`만 둔 폴더에서 `case_open`을 부르자 `missing split EWF segment before visible later segment` 오류가 돌아왔다 [36].

**한계.** 마지막 번호 뒤의 조각이 빠지면 알아채지 못한다 [33].
레지스트리 트랜잭션 로그와 SQLite `-wal`을 반영하지 않는다는 사실은 응답에 실리지 않는다 [38][39].

fn tsk_list(
    image_paths: &[PathBuf],
    sector_offset: Option<u64>,
) -> Result<Vec<FlsEntry>, DiskError> {
    let bin = std::env::var("FINDEVIL_FLS_BIN").unwrap_or_else(|_| "fls".to_string());
    let mut command = Command::new(&bin);
    command.args(["-r", "-p"]);
    if let Some(offset) = sector_offset {
        command.arg("-o").arg(offset.to_string());
    }
    append_image_args(&mut command, image_paths);

        path: PathBuf::from(&bin),
        source,

    if !output.status.success() {

            status: output.status.to_string(),
            stderr_tail: tail_utf8_lossy(&output.stderr),
        });
    }
    Ok(String::from_utf8_lossy(&output.stdout)
        .lines()
        .filter_map(parse_fls_line)
        .collect())
