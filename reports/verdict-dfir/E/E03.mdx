# E03 원본 변경 방지

### E03.01 실행 환경의 읽기 전용 강제

**구현.** 이 방식은 사용자 CLI `scripts/verdict`의 `--docker` 실행과 `--sift` 실행, `findevil-mcp`의 `disk_mount`에 적용된다 [1][2][3].
`--docker` 실행이 부르는 `scripts/run-dfir-container.sh`는 증거 경로를 컨테이너의 `/evidence`에 `:ro`로 연결하고 두 서버를 그 컨테이너 안에서 실행한다 [1][4].
`--sift` 실행은 SIFT 가상 머신 안의 증거 경로를 그대로 쓸 때 `findmnt`로 그 경로가 읽기 전용 마운트 위에 있는지 확인하고 아니면 실행을 멈춘다 [2][5].
`disk_mount`는 raw 이미지를 `ro,loop` 옵션으로, EWF 안의 NTFS 볼륨을 `ntfs3` 드라이버의 `ro,loop` 옵션으로 마운트한다 [3][6].
도구 설명은 `registry_query`·`mac_triage` 같은 도구에 마운트한 이미지 안의 파일을 주라고 적는다 [7].
시험용 `mount`로 `disk_mount` 자동 모드를 실행하자 `-o ro,loop`와 `-o ro,loop,offset=…` 인자가 넘어갔다 [8].

**한계.** 저장소의 기본 클라이언트 설정 `.mcp.json`은 두 서버를 같은 호스트에서 `scripts/run-mcp-rust.sh`·`scripts/run-mcp-python.sh`로 실행하고 증거를 읽기 전용으로 연결하지 않는다 [9].
`run-dfir-container.sh`는 증거 인자를 주지 않으면 `/evidence`를 연결하지 않는다 [1].
저장소 폴더는 컨테이너의 `/workspace`에 읽고 쓰기로 연결되므로 저장소 안에 둔 증거는 `/workspace` 경로로 읽으면 읽기 전용이 적용되지 않는다 [1].
`--sift` 실행에서 호스트의 증거는 가상 머신의 작업 폴더로 복사되고 그 사본에는 읽기 전용 확인을 하지 않는다 [10].
`disk_extract_artifacts`는 마운트를 쓰지 않고 기록된 이미지 파일을 `fls`·`icat`으로 직접 읽는다 [11].
`disk_mount`를 `mode: mock`으로 부르면 서버는 마운트하지 않고 호출 인자 `mount_point`의 폴더를 자원의 `fs_root`로 적는다 [12].
`disk_extract_artifacts`는 이 자원의 이미지를 Sleuth Kit으로 읽지 못하면 `fs_root` 폴더의 파일을 아티팩트로 복사한다 [13].
`ewfmount`가 없으면 `disk_mount`는 마운트 없이 `mounted` 항목만 등록한다 [14].

### E03.02 서버 코드의 원본 쓰기 제한

**구현.** 이 방식은 `findevil-mcp`의 `case_open`, `browser_history`·`hashset_lookup`, 서버 코드가 증거를 직접 열어 해석하는 도구, 작업 폴더를 쓰는 `srum_parse`·`pst_parse`·`bulk_extract`·`disk_extract_artifacts`에 적용된다 [15][16][17][18][19][20][21].
`case_open`은 증거를 `File::open`으로 읽기 모드로 열어 해시하고 링크인 경로는 일반 파일이 아니라며 거부한다 [15].
`browser_history`는 SQLite 기록 파일을 `immutable=1` URI와 읽기 전용 플래그로 연다 [16].
`hashset_lookup`도 SQLite 해시 목록을 같은 방식으로 연다 [17].
`usnjrnl_query`·`bits_parse`·`oe_dbx_parse`·`email_parse`·`exif_parse`·`wmi_persist_parse`는 외부 도구 없이 증거를 `File::open`으로 읽기 모드로 연다 [18].
`thumbcache_parse`·`registry_query`는 `fs::read`로, `zeek_summary`·`cloud_audit`는 `fs::read_to_string`으로 증거 파일 내용을 읽기만 한다 [19].
`srum_parse`·`pst_parse`·`bulk_extract`는 외부 도구의 출력 위치를 사건 폴더 아래 작업 폴더로 정하고 증거 경로는 입력 인자로만 넘긴다 [20].
`disk_extract_artifacts`는 이미지 안 파일을 사건 폴더의 `extracted/` 아래에 쓰고 이미지 안 경로의 `..`와 빈 조각을 버린 뒤 붙인다 [21].
`mode: mock` 마운트의 폴더에서 꺼내기를 두 번 실행한 뒤 그 폴더의 파일 목록은 실행 전과 같았다 [22].

**한계.** `disk_mount`·`vss_mount`는 모델이 준 `mount_point`를 증거 경로와 대조하지 않고 그 위치에 폴더를 만든다 [23].
`findevil-agent-mcp`의 `audit_append`·`memory_remember`·`manifest_finalize`·`expert_miss_capture`는 모델이 준 경로에 파일을 만들거나 덧붙이고 그 경로를 증거 경로와 대조하지 않는다 [24].
`argsafe`의 `validate_passthrough_args`는 출력 옵션 값이 증거 폴더 아래이면 거부하는 함수지만 이 함수를 부르는 도구는 없다 [25].

### E03.03 외부 도구·플랫폼에 위임

**구현.** 이 방식은 `findevil-mcp`가 실행하는 Volatility 3, Sleuth Kit, Hayabusa, Plaso, EZ 도구, `ewfmount`, `vshadowmount`, `bulk_extractor`, `esedbexport`, `pffexport` 같은 외부 도구에 적용된다 [26][11].
서버는 이 도구들에 증거 경로를 입력 인자로 넘기고 도구가 원본을 여는 방식에는 관여하지 않는다 [26][11].

**한계.** 서버 개요의 버전 기준으로 Volatility 3 2.11.0과 Sleuth Kit 4.15.0의 소스를 확인했다.
Volatility 3 2.11.0의 `FileLayer`는 이미지를 `rb` 모드로 연다 [27].
Sleuth Kit 4.15.0은 raw 이미지를 `O_RDONLY`로 열고 EWF 이미지는 libewf의 `LIBEWF_OPEN_READ`로 연다 [28][29].
Hayabusa, Plaso, EZ 도구, `ewfmount`, `vshadowmount`, `bulk_extractor`, `esedbexport`, `pffexport`, `mac_apt`, Suricata, Zeek, tshark, `journalctl`, `last`, `ausearch`, `nfdump`, Velociraptor는 원본을 읽기 모드로 여는지 확인하지 못해 실제 보호 미확인이다 [26].

    let mut hasher = Sha256::new();
    let mut buf = vec![0u8; SHA_BUFFER_SIZE];
    for path in paths {
        let file = File::open(path).map_err(|source| CaseOpenError::ImageUnreadable {
            path: path.clone(),
            source,
        })?;
        let mut reader = BufReader::with_capacity(SHA_BUFFER_SIZE, file);
        loop {
            let n = reader
                .read(&mut buf)
                .map_err(|source| CaseOpenError::ImageUnreadable {
                    path: path.clone(),
                    source,
                })?;
            if n == 0 {
                break;
            }
            hasher.update(&buf[..n]);
        }
    }
    let digest = hasher.finalize();
    Ok(hex_encode(&digest))
}

    let mut dest = base.to_path_buf();
