# T05 분석 도구 검증

### T05.01 저장소·의존성 고정

**구현.** 이 방식은 `findevil-mcp`가 서버 안에서 쓰는 해석 크레이트와 저장소의 설치 정의가 설치하는 외부 분석 도구 일부에 적용된다 [1][2][3][4].
- `services/mcp/Cargo.toml`은 `evtx` 0.11.2, `frnsc-prefetch` 0.13.3, `mft` 0.6.1, `yara-x` 1.12.0, `usnjrnl-forensic` 0.7.3, `rusqlite` 0.32.1, `cfb` 0.14.0, `kamadak-exif` 0.6.1, `mail-parser` 0.11.4를 `=` 버전으로 고정하고 `Cargo.lock`이 같은 버전을 담는다 [1].
- 설치 스크립트 `scripts/install-dfir-tools.sh`는 Volatility 3 2.11.0, Hayabusa 2.19.0, Velociraptor 0.74.6을 기본 버전으로 정한다 [2].
- `requirements.txt`는 Volatility 3을 2.27.0으로 고정한다 [3].
- 컨테이너 이미지 정의 `docker/dfir.Dockerfile`은 Volatility 3 2.27.0, Hayabusa 2.19.0, Velociraptor 0.74.6을 정한다 [4].
두 설치 정의는 Chainsaw 2.13.0도 설치하지만 서버에는 Chainsaw를 실행하는 도구가 없다 [2][4].
`findevil-agent-mcp`가 판단에 쓰는 AI 도구 흔적 서명표 `_SIGNATURE_TABLE`은 서버 코드에 들어 있어 기준 커밋이 내용을 정한다 [5].
설치 정의는 내려받은 파일의 해시를 기대값과 대조하지 않는다 [2][4].

다른 도구와 참조 자료는 저장소가 버전을 정하지 않는다.
- 설치 스크립트는 plaso와 INDXParse를 버전 없이 `pip3 install --user`로 설치하고 tshark, Sleuth Kit은 시스템 패키지 설치를 안내만 한다 [6].
- 컨테이너 이미지는 INDXParse를 Git 저장소의 기본 가지에서, Eric Zimmerman 도구를 버전 없는 내려받기 주소에서, plaso를 GIFT PPA의 `plaso-tools`에서 받는다 [7].
- 컨테이너 이미지 정의의 주석은 Eric Zimmerman 도구의 주소가 그때의 빌드를 내준다고 적는다 [7].
- Hayabusa 규칙은 두 설치 정의 모두 `hayabusa update-rules`로 설치할 때의 규칙을 받는다 [2][4].
- mac_apt는 설치 정의가 없고 설치 스크립트는 있을 때 알리기만 한다 [6].
- Volatility 3의 심볼은 설치 정의가 정하지 않고 서버는 `vol`에 심볼 경로를 넘기지 않는다 [4][8].

**한계.** 설치 정의 세 곳이 Volatility 3의 버전을 다르게 정한다 [2][3][4].
설치 스크립트는 2.11.0, `requirements.txt`와 컨테이너 이미지는 2.27.0이다 [2][3][4].
설치 스크립트는 `vol`·`hayabusa` 같은 실행 파일이 이미 있으면 버전을 보지 않고 설치를 건너뛴다 [2].
설치 스크립트의 버전 값은 `VOLATILITY_VERSION`, `HAYABUSA_VERSION` 같은 환경변수로 바꿀 수 있다 [2].

### T05.02 설정·호출 인자로 지정

**구현.** 이 방식은 `findevil-mcp`가 실행하는 외부 도구의 실행 파일과 참조 자료 위치에 적용된다 [9][10][11].
- 도구마다 실행 파일을 환경변수로 받는다: `VOLATILITY_BIN`, `HAYABUSA_BIN`, `VELOCIRAPTOR_BIN`, `TSHARK_BIN`, `ZEEK_BIN`, `JOURNALCTL_BIN`, `LAST_BIN`, `AUSEARCH_BIN`, `NFDUMP_BIN`, `SURICATA_BIN`, `INDXPARSE_BIN`, `MAC_APT`, 폴더를 받는 `EZTOOLS_DIR`·`PLASO_DIR` [9].
- 이 값이 파일을 가리키면 그 파일을 쓰고 아니면 `PATH`에서 `vol`·`volatility3`처럼 도구마다 정한 이름을 차례로 찾는다 [9].
- `FINDEVIL_BULK_EXTRACTOR_BIN`, `FINDEVIL_ESEDBEXPORT_BIN`, `FINDEVIL_PFFEXPORT_BIN`은 이름이나 경로를 받는다 [10].
- 디스크 도구의 `EWF_MOUNT_BIN`, `FINDEVIL_MOUNT_BIN`, `FINDEVIL_UMOUNT_BIN`, `FINDEVIL_FLS_BIN`, `FINDEVIL_ICAT_BIN`과 `vss_list`·`vss_mount`의 `FINDEVIL_VSHADOWINFO_BIN`·`FINDEVIL_VSHADOWMOUNT_BIN`은 파일인지 보지 않고 값을 그대로 실행 파일 이름으로 쓴다 [10].
- `mmls`와 `sudo`는 환경변수 없이 `PATH`의 이름으로 실행한다 [12].
참조 자료의 위치도 설정이나 호출 인자로 정한다.
- `hayabusa_scan`은 `HAYABUSA_RULES_BASE`, `XDG_DATA_HOME/hayabusa-mcp`, `~/.local/share/hayabusa-mcp` 가운데 `rules/config`가 있는 첫 폴더를 규칙 폴더로 쓰고 호출 인자 `rule_set`이 있으면 `-r`로 넘긴다 [11].
- `yara_scan`은 호출 인자 `rules_path`의 YARA 규칙 파일이나 폴더를 컴파일한다 [13].
- `hashset_lookup`은 호출 인자 `hashset_paths`가 있으면 그 해시 목록을, 없으면 `FINDEVIL_HASHSET_DIR` 아래 `known_good`·`known_bad`의 파일을 쓴다 [14].
- `bulk_extract`는 호출 인자 `keyword_file`이나 `FINDEVIL_BULK_KEYWORD_FILE`의 키워드 목록을 쓴다 [15].
서버 시작 스크립트가 읽는 `scripts/lib/project-env.sh`는 `HAYABUSA_RULES_BASE`를 실행 상태 폴더 아래로 정한다 [16].
`.mcp.json.sift`는 `VOLATILITY_BIN`, `HAYABUSA_BIN`, `VELOCIRAPTOR_BIN`을 서버 명령 앞에 붙이고 `docker/dfir.Dockerfile`은 실행 파일과 규칙 폴더의 환경변수 15개를 이미지에 정한다 [17].
`findevil-agent-mcp`의 `verify_finding`은 다시 실행할 `findevil-mcp`의 실행 명령을 호출 인자 `findevil_mcp_command`로 받는다 [18].
서버는 `bulk_extract`를 빼면 이렇게 고른 실행 파일과 참조 자료의 버전을 읽지 않는다 [9][19].

**한계.** 실행 파일 환경변수가 파일이 아닌 경로를 가리키면 서버는 알리지 않고 `PATH`에서 찾은 실행 파일을 쓴다 [9].
`VOLATILITY_BIN`을 없는 경로로 정하고 `PATH`에 다른 `vol`을 두자 `vol_run`과 `vol_pslist`는 `PATH`의 `vol`을 실행했고 응답에는 그 사실이 없었다 [20].

### T05.03 실행 시 버전 조회

**구현.** 이 방식은 `bulk_extract`에 적용된다 [19].
`bulk_extract`는 스캔하기 전에 같은 실행 파일을 `--version`으로 실행하고 표준 출력의 첫 줄을 응답의 `engine_version`에 넣는다 [19].
이 실행이 실패하면 `engine_version`을 `unknown`으로 두고 스캔은 그대로 실행한다 [19].
시험용 `bulk_extractor`로 부르자 `--version` 실행이 스캔보다 먼저 기록되었고 `engine_version`은 그 출력의 첫 줄이었다 [21].
다른 외부 도구 실행 경로는 도구의 버전을 묻지 않는다.
`disk_mount`가 `ewfmount -h`를 실행하는 것은 실행할 수 있는지만 보는 확인이다 [22].

    let mut candidates: Vec<PathBuf> = Vec::new();

/// Capture `bulk_extractor --version` (first stdout line, trimmed).
/// `unknown` when the probe fails — this string is part of the hashed
/// body so a silent engine change is visible to replay.
fn capture_version(binary: &Path) -> String {
    match Command::new(binary).arg("--version").output() {
        Ok(out) if out.status.success() => String::from_utf8_lossy(&out.stdout)
            .lines()
            .next()
            .unwrap_or("")
            .trim()
            .to_string(),
        _ => "unknown".to_string(),
    }
}
