# T10 도구 명세 구성

### T10.01 처리 함수에서 명세 생성

**구현.** 이 방식은 `findevil-mcp`의 도구 43개와 `findevil-agent-mcp`의 도구 14개의 입력 schema에 적용된다 [1][2].
`findevil-mcp`는 `ToolEntry`마다 입력 구조체를 `schema_for`에 넘겨 입력 schema를 만든다 [3].
같은 항목의 처리 함수는 그 구조체로 `parse_args`를 불러 인자를 해석한다 [3].
입력 schema는 `schemars`가 입력 구조체에서 만들고 구조체 필드의 문서 주석이 속성 설명이 된다 [4].
`findevil-agent-mcp`의 `ToolSpec.input_schema`는 입력 모델의 `model_json_schema()`를 돌려준다 [2].
`call_tool`은 처리 함수를 부르기 전에 같은 입력 모델의 `model_validate`로 인자를 해석하고 그 결과를 처리 함수에 넘긴다 [5].

### T10.02 처리기와 따로 둔 명세

**구현.** 이 방식은 `findevil-mcp`의 도구 43개와 `findevil-agent-mcp`의 도구 14개에 적용된다 [1][2].
`findevil-mcp`는 MCP SDK 없이 `build_registry`의 `ToolEntry` 표에 도구마다 이름, 설명 문자열, annotation, 입력 schema를 만드는 함수, 처리 함수를 적는다 [1].
`tools/list`는 이 표에서 `name`, `description`, `inputSchema`, `annotations`를 만든다 [6].
도구 설명은 처리 함수와 따로 표에 적은 글이다 [1].

`findevil-agent-mcp`는 도구 모듈마다 `ToolSpec`으로 이름, 설명, 입력 모델, 출력 모델, 처리 함수를 묶어 `SPEC`으로 내보낸다 [2].
`list_tools`는 `name`, `description`, 입력 모델의 `model_json_schema()` 결과만 싣고 출력 모델은 명세에 싣지 않는다 [7].
MCP Python SDK 1.27.0의 저수준 `Server`는 처리 함수를 부르기 전에 인자를 이 입력 schema와 대조한다 [8].
실행 확인에서 `audit_append`에 schema에 없는 인자를 주자 `isError`가 참인 `Input validation error: Additional properties are not allowed` 응답이 왔다 [9].

두 서버의 입력 schema는 모두 최상위 `additionalProperties`가 거짓이었다 [10].
`findevil-agent-mcp`의 `verify_finding`, `judge_findings`, `correlate_findings`, `detect_contradictions`는 발견사항을 필드 없는 객체로 받고 넣어야 할 필드는 설명 글에만 적는다 [11][10].
`vol_run`의 `plugin`, `ez_parse`의 `tool`, `plaso_parse`의 `parser`는 입력 schema에서 `enum`이 없는 문자열이고 허용 목록은 설명 글과 처리 코드에만 있다 [12][10].
초기화 응답의 도구 능력은 `findevil-mcp`가 빈 객체, `findevil-agent-mcp`가 `listChanged` 거짓이었다 [10].

**한계.** 설명과 schema, 설명과 처리 코드를 대조하는 장치는 없다.
`judge_findings`의 설명은 0초 제한을 주면 첫 차례에 실패한다고 적지만 입력 모델은 `budget_seconds`가 0보다 커야 한다 [13].
실행 확인에서 `budget_seconds`에 0을 주자 SDK가 `0 is less than or equal to the minimum of 0.0`으로 거부했다 [9].
`verify_finding`의 설명은 출력 해시가 달라지면 `downgraded`라고 적지만 처리 코드는 `downgrade_on_drift`가 거짓인 `CONFIRMED` 발견사항을 `rejected`로 정한다 [14].
같은 설명은 `findevil_mcp_command`의 기본값을 적지만 입력 모델에서 이 인자는 기본값 없는 필수 인자다 [14][10].
`case_open`의 설명은 `Idempotent per image hash`라고 적은 뒤 같은 파일로 두 번 부르면 새 `case_id`가 나온다고 적고 annotation의 `idempotentHint`는 거짓이다 [15].

### T10.03 묶음 도구의 연산별 인자를 schema가 구분하지 않음

**구현.** 이 방식은 `findevil-mcp`의 `vol_run`과 `vel_collect`에 적용된다 [12][16].
`vol_run`은 Volatility 3 플러그인 이름 `plugin`을 받아 허용 목록의 플러그인 42개 가운데 하나를 실행한다 [12].
입력 schema는 모든 플러그인에 같은 선택 인자 `pid`를 두고 그 설명은 프로세스 단위 플러그인에서만 쓸 수 있다고 적는다 [12][10].
서버는 플러그인을 가리지 않고 `pid`가 있으면 `--pid`를 붙인다 [12].
실행 확인에서 `windows.netscan`에 `pid` 4를 주자 시험용 `vol`이 받은 인자 끝에 `--pid 4`가 있었다 [17].
`vel_collect`는 아티팩트 이름 `artifact`와 문자열 값만 담는 `args`를 받아 `--args 키=값`으로 넘긴다 [16].
`args`의 설명은 아티팩트마다 다른 매개변수의 schema는 Velociraptor 쪽에 있다고 적고 입력 schema는 값이 문자열인 객체로만 알린다 [16][10].

### T10.06 도구 annotation 표시

**구현.** 이 방식은 `findevil-mcp`의 도구 43개에 적용된다 [1][18].
`ToolEntry`마다 `title`, `readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint` 다섯 값을 손으로 적고 `tools/list`가 그대로 싣는다 [18][6].
실행 확인에서 `readOnlyHint`가 거짓인 도구는 `case_open`, `disk_mount`, `disk_extract_artifacts`, `disk_unmount` 4개였다 [10].
`destructiveHint`는 모든 도구가 거짓이고 `openWorldHint`는 `vel_collect`만 참이었다 [10].
`idempotentHint`가 거짓인 도구는 위 4개와 `vss_mount`였다 [10].
`findevil-agent-mcp`의 도구 14개에는 annotation이 없다 [7][10].
이 서버의 `audit_append`, `manifest_finalize`, `memory_remember`, `expert_miss_capture`, `pool_handoff`는 파일에 쓰는 도구다 [19][20].
`accuracy_compare`와 `memory_recall`도 `audit_log_path`를 주면 호출 기록에 항목을 더하고 `memory_recall`은 `store_path`에 파일이 없으면 SQLite 파일을 만든다 [21].

**한계.** 몇 도구의 annotation 값은 처리 코드의 동작과 다르다.
`bulk_extract`는 `readOnlyHint`와 `idempotentHint`가 참이지만 사건 폴더 아래 이미지 이름의 작업 폴더가 이미 있으면 지우고 다시 만들어 결과 파일을 쓴다 [22].
`ToolAnnotations`의 주석은 서버가 증거와 그 파생물을 지우지 않으므로 `destructiveHint`를 늘 거짓으로 둔다고 적는다 [18].
`vss_mount`는 `readOnlyHint`가 참이지만 사건 폴더 아래에 마운트 폴더를 만들고 `vshadowmount`를 실행한다 [23].
`pst_parse`와 `srum_parse`도 `readOnlyHint`가 참이지만 사건 폴더 아래에 내보내기 폴더를 만든다 [24].
`vel_collect`는 `readOnlyHint`가 참이지만 아티팩트를 가리지 않고 실행한다 [25].

class ToolSpec:
    """Static metadata + handler for one MCP tool."""

    name: str
    """Tool name as exposed to the MCP client. Snake-case."""

    description: str
    """Human-readable summary. Shown to Claude Code at tool-pick time."""

    input_model: type[BaseModel]

    Must use ``model_config = ConfigDict(extra="forbid")`` so unknown
    fields surface as errors, not silent drops.

    """Pydantic v2 model the handler must return."""

    handler: Handler
    """Async coroutine. Takes the validated input model, returns the output model."""

        """JSON Schema for the input model — emitted to the MCP client."""
        return self.input_model.model_json_schema()

struct ToolAnnotations {
    /// Short human-readable display name (e.g. "Open Evidence Case").
    title: &'static str,
    /// True when the tool does not modify the environment (most of
    /// our DFIR tools are read-only over evidence; only `case_open`

    read_only: bool,

    open_world: bool,
}
