# T02 실행 허용 범위 제한

### T02.04 고정 명령·템플릿

**구현.** 이 방식은 외부 도구를 실행하는 `findevil-mcp`의 도구와 `findevil-agent-mcp`의 `memory_recall`·`expert_miss_capture`에 적용된다 [1][2][3].
`findevil-mcp`의 도구는 실행 파일 이름과 인자 배열의 모양을 코드에 정해 두고 모델 값은 정한 자리에 인자 하나로 넣는다 [1].
- `vol_run`은 `-f <메모리> -r json -q <플러그인>`에 `pid`가 있으면 `--pid <번호>`를 붙이고 `vol_pslist` 같은 나머지 Volatility 도구 4개는 플러그인 이름까지 코드에 둔다 [4].
- `hayabusa_scan`은 `json-timeline --no-wizard -d <폴더> -o <임시 파일> -q --ISO-8601`에 `-r <rule_set>`과 `-m <등급>`을 붙인다 [5].
- `pcap_triage`의 tshark 실행은 `-r <pcap> -c <limit> -T fields`와 출력할 필드 11개를 코드에 둔다 [6].
- `vel_collect`는 `artifacts collect <artifact> --format jsonl`에 `args`의 항목마다 `--args <키>=<값>`을 붙인다 [7].
- `disk_mount`·`disk_extract_artifacts`·`disk_unmount`는 `mount -o ro,loop`, `ewfmount`, `fls -r -p`, `icat`, `umount`의 인자를 코드에 둔다 [8].
서버는 실행 파일과 인자 배열을 따로 넘기고 셸 명령 문자열을 만들지 않는다 [1].
`findevil-mcp`에는 모델이 실행 파일 이름이나 자유로운 인자 목록을 넘기는 도구 인자가 없다 [1].
자유 인자 목록을 검사하려고 만든 `validate_passthrough_args`는 정의만 있고 도구에서 부르지 않는다 [9].
`vol_run`, `vel_collect`, `bulk_extract`를 부르자 시험용 실행 파일은 코드에 정한 배열에 모델 값만 들어간 인자를 받았다 [10].

모델 값이 옵션으로 읽히지 않게 막는 검사는 두 도구에 있다.
`vel_collect`는 `args`의 키가 영문이나 밑줄로 시작하는 64자 이하의 영문·숫자·밑줄 이름인지 보고 아니면 거부한다 [11].
`bulk_extract`는 파일 이름이 `-`로 시작하는 이미지를 거부하고 인자 배열에서 이미지 경로 앞에 옵션 끝 표시 `--`를 둔다 [12].
`--x` 키와 `-dash.raw` 이미지는 모두 `-32602`로 거부되었다 [10].

`findevil-agent-mcp`의 `memory_recall`은 SQL 문을 코드에 두고 모델 값은 매개변수로 넘긴다 [2].
`query`는 큰따옴표로 감싼 구문 검색어로 바꾸어 넘기므로 FTS5 연산자가 해석되지 않는다 [2].
`expert_miss_capture`는 `gh issue create --label miss/<edit_type> --title <제목> --body <본문>` 배열로 GitHub CLI를 실행한다 [3].
`FINDEVIL_MISS_GH_ENABLED=1`로 시작한 서버에서 시험용 `gh`는 이 배열을 받았다 [13].

**한계.** `findevil-agent-mcp`의 `verify_finding`은 모델이 넘긴 `findevil_mcp_command` 배열을 검사하지 않고 자식 프로세스로 실행한다 [14][15].
이 배열은 다시 실행할 MCP 서버의 실행 명령이지만 어떤 실행 파일과 인자든 받는다 [14].
그래서 모델은 이 도구로 분석 도구의 실행 파일을 코드에 정한 인자 배열 밖의 인자로 실행할 수 있다 [14][15].
시험용 `vol` 실행 파일과 임의 인자를 이 배열로 주자 서버가 그 인자로 실행했다 [13].
`vel_collect`는 `artifact`의 형식만 보므로 형식에 맞는 어떤 아티팩트 이름이든 Velociraptor에 넘기고 `args`의 값은 검사하지 않는다 [7][11].
형식만 맞춘 임의 이름 `Some.Made.Up.Artifact`는 거부되지 않고 Velociraptor 실행 인자가 되었다 [10].
`indx_parse`, `srum_parse`, `pst_parse`, `vss_list`, `vss_mount`, `plaso_parse`, `mac_triage`와 디스크 도구의 `mount`·`ewfmount`·`mmls`·`fls`·`icat`은 경로를 옵션 끝 표시 없이 위치 인자로 넘기고 `-`로 시작하는 이름을 거부하지 않는다 [16][17].

### T02.05 연산·플러그인 허용 목록

**구현.** 이 방식은 `findevil-mcp`의 `vol_run`·`plaso_parse`·`ez_parse`·`mac_triage`·`cloud_audit`·`bulk_extract`·`pcap_triage`·`disk_mount`·`disk_unmount`·`disk_extract_artifacts`와 `findevil-agent-mcp`의 `manifest_finalize`에 적용된다 [18][19][20][21][22].
- `vol_run`은 `plugin`을 Volatility 3 플러그인 이름 42개의 목록 `ALLOWED_PLUGINS`와 정확히 대조한다 [18].
- `plaso_parse`는 `parser`를 plaso 파서 16개, `ez_parse`는 `tool`을 Eric Zimmerman 도구 7개, `mac_triage`는 `module`을 mac_apt 모듈 15개의 목록과 대조한다 [19].
- `cloud_audit`는 서버 안에서 쓸 로그 해석 방식 `provider`를 8개 값의 목록과 대조한다 [19].
다섯 도구는 이 대조를 파일 검사와 외부 도구 실행보다 먼저 하고 목록에 없으면 `-32602`로 거부한다 [18][19][23].
- `bulk_extract`의 `scanners`는 bulk_extractor 스캐너 18개의 열거형이라 목록 밖 값은 인자 해석 단계에서 `-32602`가 된다 [20].
- `disk_mount`·`disk_unmount`의 `mode`는 `auto`·`mock`, `disk_extract_artifacts`의 `artifact_kinds`는 아티팩트 종류 26개의 열거형이라 목록 밖 값은 인자 해석 단계에서 `-32602`가 된다 [21].
- `mock`은 마운트 명령을 실행하지 않고 자원만 등록하는 모드이고 이 값을 막는 설정은 없다 [24].
- `pcap_triage`의 `analyzer`는 `auto`·`tshark`·`zeek` 가운데 하나여야 하고 `auto`는 설치된 tshark, Zeek 차례로 고른다 [20].
- `manifest_finalize`의 `signer`는 `stub`·`ed25519`·`sigstore`의 `Literal`이라 다른 값은 SDK의 입력 schema 검사에서 거부된다 [22].
목록 밖 플러그인·파서·도구·모듈·`provider`·`scanners`·`analyzer`·`signer`를 주자 모두 거부되었고 외부 도구는 실행되지 않았다 [10][25].
목록은 서버 코드의 상수이고 이를 바꾸는 설정이나 인자는 없다 [18][19].

`vel_collect`에는 아티팩트 목록이 없다 [7].
Velociraptor 아티팩트 이름은 형식만 검사한다 [11].

**한계.** `verify_finding`은 모델이 넘긴 실행 파일과 인자를 그대로 실행하므로 Volatility 실행 파일을 이 목록 밖 플러그인으로 실행하는 데 이 목록이 적용되지 않는다 [14][15].
시험용 `vol`과 목록에 없는 인자를 `findevil_mcp_command`로 주자 그대로 실행되었다 [13].

### T02.08 설정으로 도구 끄기

**구현.** 이 방식은 `findevil-agent-mcp`의 작업 세 가지에 적용된다 [26][27][3].
- `manifest_finalize`의 시험용 서명 `signer: "stub"`은 환경변수 `FINDEVIL_ALLOW_STUB_SIGNER`가 `1`·`true`·`yes`·`on`일 때만 쓰인다 [26].
- 이 값이 없으면 서버는 요청을 거부하지 않고 `ed25519` 서명으로 바꾸며 그 사실을 응답의 `fallback_reason`에 적는다 [26].
- `manifest_finalize`의 `anchor_transparency: true`는 `FINDEVIL_REKOR_ENABLE`이 비어 있거나 `0`·`false`·`no`·`off`이면 `RekorAnchorDisabledError`로 끝난다 [27].
- `expert_miss_capture`는 `FINDEVIL_MISS_GH_ENABLED`가 `1`일 때만 GitHub 이슈를 만들고 아니면 `github_issue_url`을 `null`로 둔다 [3].
세 값은 처리기가 호출마다 읽고 기본값은 모두 꺼진 상태다 [26][27][3].
도구는 값과 관계없이 목록에 남는다.
세 값 없이 시작한 서버에서 `stub` 요청은 `ed25519`로 바뀌었고 `anchor_transparency` 요청은 `RekorAnchorDisabledError` 오류 글로 끝났으며 `expert_miss_capture`는 `gh`를 실행하지 않았다 [13].
`findevil-mcp`에는 도구나 작업을 끄는 시작 인자, 환경변수, 설정 파일이 없다 [28].

**한계.** `manifest_finalize`는 `anchor_transparency`의 설정 값을 manifest 파일을 쓴 뒤에 확인한다 [27].
그래서 이 요청이 거부되어도 `output_path`에는 서명된 manifest가 남는다 [27].
`anchor_transparency: true` 요청이 거부된 뒤 `output_path`의 파일이 남아 있었다 [13].

### T02.09 실행 파일 이름 거부 목록

**구현.** 이 방식은 외부 도구를 실행하는 `findevil-mcp`의 도구 가운데 `vol_run`, `plaso_parse`, `ez_parse`, `mac_triage`, `srum_parse`, `pst_parse`, `bulk_extract` 7개에 적용된다 [29].
이 도구들은 실행 직전에 `argsafe::guard_spawn`을 거친다 [29].
`guard_spawn`은 실행 파일 경로의 마지막 이름을 소문자로 바꾸고 끝의 `.exe`나 `.py`를 뗀 값을 서버 코드의 거부 목록 `DENIED_BINARIES` 66개와 대조한다 [30][31].
목록에는 `rm`·`dd` 같은 파일 변경 도구, `curl`·`ssh` 같은 네트워크 도구, `bash`·`python3` 같은 셸과 인터프리터, `sudo`·`kill` 등이 들어 있다 [30].
목록에 있으면 실행하지 않고 오류를 돌려준다 [30].
실행 파일은 `VOLATILITY_BIN` 같은 환경변수나 `PATH`에서 찾으므로 이 대조는 사용자가 정한 실행 파일에 적용된다 [30].
`VOLATILITY_BIN`을 이름이 `python3`인 파일로 정하자 `vol_run`은 그 파일을 실행하지 않고 `-32603`으로 끝났다 [32].

**한계.** `vol_pslist`·`hayabusa_scan`·`vel_collect`·`pcap_triage`·`disk_mount` 같은 다른 외부 도구 실행은 `guard_spawn`을 거치지 않는다 [29].
같은 서버에서 `vol_pslist`는 이름이 `python3`인 파일을 실행했다 [32].
`findevil-agent-mcp`의 `verify_finding`은 모델이 넘긴 `findevil_mcp_command` 배열의 실행 파일을 이 목록과 대조하지 않고 실행한다 [14][15].

/// True if the resolved binary's file name is on the spawn denylist
/// (case-insensitive; a trailing `.exe`/`.py` is stripped first).
#[must_use]
pub fn binary_basename_denied(binary: &Path) -> bool {
    let Some(name) = binary.file_name().and_then(OsStr::to_str) else {
        return false;
    };
    let lower = name.to_ascii_lowercase();
    let stem = lower
        .strip_suffix(".exe")
        .or_else(|| lower.strip_suffix(".py"))
        .unwrap_or(&lower);
    DENIED_BINARIES.contains(&stem)
}
