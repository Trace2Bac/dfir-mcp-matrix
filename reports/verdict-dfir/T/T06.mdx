# T06 실행 환경정보 표시

### T06.01 응답 메타데이터에 버전 표시

**구현.** 이 방식은 `findevil-mcp`의 `bulk_extract`에 적용된다 [1].
`bulk_extract`는 디스크 이미지를 검사하기 전에 `capture_version`으로 같은 실행 파일을 `--version` 인자로 한 번 실행한다 [1].
그 표준 출력의 첫 줄을 응답 필드 `engine_version`에 싣는다 [1][2].
`bulk_extractor`를 찾지 못해 검사를 하지 않은 응답에서는 `engine_version`이 빈 문자열이다 [2].
`findevil-mcp`는 응답 본문의 SHA-256을 `_meta.output_sha256`에 싣고 이 해시는 `engine_version`이 들어간 본문 전체에 대해 계산한다 [3].
실행 확인에서 `--version`에 `bulk_extractor 2.1.1-fake`를 출력하는 시험용 실행 파일을 두자 응답의 `engine_version`이 그 문자열이었다 [4].
실행 파일을 두지 않은 호출의 응답은 `bulk_extractor_available`이 거짓이고 `engine_version`이 빈 문자열이었다 [4].

다른 도구의 응답에는 도구와 참조 자료의 버전이 실리지 않는다.
`findevil-mcp`의 `_meta`에는 도구 이름 `tool`과 `output_sha256`만 있다 [3].
Volatility 3, Hayabusa, Velociraptor를 실행하는 도구는 표준 오류의 끝부분을 `stderr_tail`에 담아 넘기고 서버는 이 글을 해석하지 않는다 [5].
`pcap_triage`는 `tshark`와 `zeek`의 표준 오류를 응답에서 빼고 코드 주석은 실행마다 달라지는 버전 문구를 그 이유로 적는다 [6].
`hashset_lookup`의 응답은 해시 집합마다 이름, 종류, 판정, 경로와 읽기 오류만 싣고 `yara_scan`의 응답은 컴파일한 룰 파일 수만 싣는다 [7].
`findevil-agent-mcp`는 처리기가 돌려준 출력 모델을 JSON 글 하나로 바꿔 돌려주고 응답에 `_meta`를 붙이지 않는다 [8].
이 서버의 도구 14개의 출력 모델에는 버전 필드가 없다 [8].

호출 기록과 파생물에도 도구 버전은 실리지 않는다.
`audit_append`는 호출자가 준 `kind`와 `payload`를 그대로 호출 기록에 더한다 [9].
`find_evil_auto.py`가 남기는 `bulk_extract` 호출 기록에는 `bulk_extractor_available`과 `features_seen`만 있고 `engine_version`은 없다 [10].
`manifest_finalize`가 쓰는 `run.manifest.json`의 `version`은 manifest 형식 번호 `1`이다 [11].
manifest의 `extra`에는 호출자가 준 값이 그대로 들어가고 `find_evil_auto.py`는 이미지 경로, 고정 문자열 `find-evil-auto`를 담은 `model`, 증거 유형, 서명 방식을 넘긴다 [11][12].

서버 자신의 버전도 응답과 기록에 실리지 않는다.
`findevil-mcp`는 크레이트 버전 `CRATE_VERSION`을 초기화 응답의 `serverInfo.version`, `--version` 출력, 시작 로그에만 쓴다 [13].
`lib.rs`의 주석은 이 값이 호출 기록에도 실린다고 적지만 그렇게 쓰는 코드는 없다 [13].
`findevil-agent-mcp`는 `SERVER_VERSION` 값 `0.1.0`을 시작 로그에만 쓰고 SDK의 저수준 `Server`에는 이름만 준다 [14].
MCP Python SDK 1.27.0의 저수준 `Server`는 버전이 없으면 초기화 응답의 `serverInfo.version`에 `mcp` 패키지 버전을 넣는다 [15].
실행 확인에서 `serverInfo.version`은 `findevil-mcp`가 `0.1.0`, `findevil-agent-mcp`가 `1.27.0`이었다 [16].
두 서버는 서버 안에서 모델을 부르지 않는다.

**한계.** `engine_version`은 검사를 실행한 프로세스가 아니라 검사 전에 따로 실행한 버전 확인의 출력이다 [1].
버전 확인 실행이 실패하거나 종료 코드가 0이 아니어도 검사는 그대로 진행되고 `engine_version`만 `unknown`이 된다 [1].

/// Capture `bulk_extractor --version` (first stdout line, trimmed).
/// `unknown` when the probe fails — this string is part of the hashed
/// body so a silent engine change is visible to replay.
fn capture_version(binary: &Path) -> String {
    match Command::new(binary).arg("--version").output() {
        Ok(out) if out.status.success() => String::from_utf8_lossy(&out.stdout)
            .lines()
            .next()
            .unwrap_or("")
            .trim()
            .to_string(),
        _ => "unknown".to_string(),
    }
}

[3] 모든 도구 응답은 본문을 직렬화한 글의 SHA-256과 도구 이름만 `_meta`에 싣는다.

```rust
fn finalize_tool_output(name: &str, payload: &Value) -> Result<Value, ToolError> {
    let (payload, sanitized) = crate::sanitize::sanitize_value(payload);
    let payload_text = serde_json::to_string(&payload)
        .map_err(|e| ToolError::Internal(format!("serialize tool output: {e}")))?;
    let sha = sha256_hex(payload_text.as_bytes());

    let mut meta = json!({
        "tool": name,
        "output_sha256": sha,
    });
    if !sanitized.is_empty() {
        meta["sanitized"] = sanitized.to_json();
        // Mirror the `_meta.sanitized` counts into the best-effort, counts-only
        // injection-alert SIDECAR ledger. This runs AFTER hashing and never
        // touches `payload`, `sha`, or `meta`, so the sealed output and a
        // verify_finding replay are unaffected — the ledger is not the audit
        // chain. `sha` is recorded as the correlation key (the same sanitized
        // -output digest the audit chain stores), never the payload.
        injection_ledger::record_neutralization(name, &sha, &sanitized);
    }
    Ok(json!({
        "content": [
            {
                "type": "text",
                "text": payload_text,
            }
        ],
        "_meta": meta,
    }))
}
```
