# T07 도구 부재 처리

### T07.01 실행 전 도구·참조 자료 가용성 검사

**구현.** 이 방식은 `findevil-mcp`가 외부 실행 파일을 부르는 도구 20개와 `disk_mount`, 참조 자료를 받는 `hayabusa_scan`·`yara_scan`·`bulk_extract`, `findevil-agent-mcp`의 `accuracy_compare`와 시간 기록 경로에 적용된다 [1][2][3][4][5][6][7].
외부 실행 파일을 부르는 도구는 실행하기 전에 도구마다 정한 함수 `resolve_binary`(`pst_parse`는 `resolve_pffexport`)로 실행 파일을 찾는다 [1].
이 함수는 환경변수가 가리키는 경로와 `PATH`의 폴더마다 정해 둔 이름의 파일이 있는지 `is_file`로 확인하고 찾지 못하면 실행하지 않고 오류를 돌려준다 [1].
이 확인을 거치는 도구는 `vol_pslist`, `vol_psscan`, `vol_psxview`, `vol_malfind`, `vol_run`, `hayabusa_scan`, `vel_collect`, `ausearch`, `journalctl_query`, `login_accounting`, `nfdump_query`, `suricata_eve`, `indx_parse`, `mac_triage`, `ez_parse`, `plaso_parse`, `pcap_triage`, `bulk_extract`, `pst_parse`, `srum_parse`다 [1][2].
`plaso_parse`는 `log2timeline.py`와 `psort.py`를 둘 다 찾은 뒤에 첫 단계를 실행한다 [2].
`disk_mount`는 E01 이미지를 마운트하기 전에 `ewfmount -h`를 실행해 보고 실행 파일이 없다는 오류가 나면 없는 것으로 본다 [3].
`hayabusa_scan`은 호출자가 준 룰 폴더 `rule_set`이 없으면 실행하지 않고 `yara_scan`은 `rules_path`가 없거나 룰 파일이 하나도 없으면 실행하지 않는다 [4].
`bulk_extract`는 호출 인자 `keyword_file`이나 환경변수 `FINDEVIL_BULK_KEYWORD_FILE`이 가리키는 키워드 목록 파일이 일반 파일이 아니면 `KeywordFileNotFound`로 거부하고 bulk_extractor를 실행하지 않는다 [5].
`accuracy_compare`는 채점 전에 정답 파일 `expected-findings.json`을 찾고 없으면 `FileNotFoundError`를 낸다 [6].
`manifest_finalize`의 시간 기록 경로는 RFC 3161 시간 기록을 요청하기 전에 `openssl version`을 실행해 `openssl`이 있는지 확인한다 [7].

`vss_list`, `vss_mount`, `disk_extract_artifacts`, `disk_unmount`는 실행 파일을 미리 찾지 않고 바로 실행한다 [8].
`findevil-agent-mcp`의 `verify_finding`도 호출자가 준 명령 `findevil_mcp_command`가 있는지 미리 확인하지 않는다 [9].

**한계.** `resolve_binary`는 파일이 있는지만 보고 실행 권한은 보지 않는다 [1].
실행 권한이 없는 파일이 먼저 찾아지면 실행 단계에서 `spawn failed` 문구를 담은 `SubprocessFailed`가 된다 [1].
`hayabusa_scan`은 Hayabusa가 읽는 `rules/config` 폴더를 `HAYABUSA_RULES_BASE`, `XDG_DATA_HOME`, `HOME` 아래에서 찾고 찾지 못해도 작업 폴더를 바꾸지 않은 채 Hayabusa를 실행한다 [10].

### T07.02 대체 없는 실패 처리·도구 부재 알림

**구현.** 이 방식은 `findevil-mcp`가 외부 실행 파일을 부르는 도구와 `vss_list`·`vss_mount`, `findevil-agent-mcp`의 `accuracy_compare`, `manifest_finalize`의 시간 기록 경로, `manifest_verify`의 RFC 3161 확인에 적용된다 [11][12][13][6][14][15].
실행 파일을 찾지 못한 도구는 오류 종류 `BinaryNotFound`를 내고 그 문구에는 경로를 바꾸는 환경변수가 들어 있다 [11].
`pcap_triage`를 뺀 도구의 문구에는 설치 안내도 들어 있다 [11][16].
`findevil-mcp`는 이 오류를 JSON-RPC 오류 코드 -32603과 `<도구 이름>: <문구>` 형식의 글로 돌려준다 [11].
실행 확인에서 `PATH`에 Volatility가 없을 때 `vol_pslist`는 -32603과 `volatility binary not on PATH (set $VOLATILITY_BIN to override)`로 시작하는 문구를 돌려주었다 [17].
`ez_parse`의 `jlecmd`도 같은 조건에서 `JLECmd`를 찾지 못했다는 문구와 설치 안내를 돌려주었다 [17].

`bulk_extract`, `pst_parse`, `srum_parse`, `vss_list`, `vss_mount`는 실행 파일이 없으면 오류 대신 성공 응답을 돌려주고 `*_available` 필드를 거짓으로 둔다 [12][13].
`bulk_extract`의 응답은 `note`에 설치되지 않았다는 사실과 환경변수를 적고 나머지 네 도구는 문구 없이 필드 값으로만 알린다 [12][13].
실행 확인에서 실행 파일이 없을 때 `bulk_extract`, `pst_parse`, `srum_parse`의 응답은 각각 `bulk_extractor_available`, `pffexport_available`, `esedbexport_available`이 거짓이었다 [17].
`accuracy_compare`는 정답 파일이 없으면 `no expected-findings.json golden found`와 `golden_path`를 직접 주라는 안내를 담은 오류 글을 돌려준다 [6].
실행 확인에서 이 오류 글은 `{"error":{"kind":"handler",...}}` 형태였고 MCP 응답의 `isError`는 거짓이었다 [18].

`verify_finding`은 `findevil-mcp`를 실행하지 못한 경우를 따로 구분하지 않는다 [9].
실행 오류는 다시 실행한 결과의 분류 `replay_error`가 되고 `verify_finding`은 발견사항을 `rejected`로 정한다 [9].
실행 확인에서 없는 경로를 `findevil_mcp_command`로 주자 응답의 `action`은 `rejected`, `reason`은 `mcp replay error: could not spawn MCP server`로 시작했다 [18].

`manifest_finalize`의 시간 기록 경로는 `openssl`이 없으면 RFC 3161 시간 기록을 요청하지 않고 manifest의 `transparency_log`에 종류 `none`과 `openssl not found on PATH`가 들어간 `fallback_reason`을 남긴다 [14].
`manifest_verify`는 RFC 3161 시간 기록을 확인할 때 `openssl`이 없으면 `transparency_ok`를 거짓으로 두고 `transparency_ok_detail`에 확인하지 못했다는 문구를 싣는다 [15][19].

**한계.** `findevil-mcp`에서 도구 부재와 다른 실행 실패는 같은 오류 코드 -32603으로 나가고 오류 글로만 구별된다 [11].
`vss_list`와 `vss_mount`는 실행 파일이 없는 경우 말고 다른 이유로 실행하지 못한 경우에도 `*_available`을 거짓으로 둔다 [13].

### T07.03 알림 없는 대체 실행

**구현.** 이 대체는 `findevil-mcp`가 환경변수로 실행 파일 경로를 받는 도구 17개와 `disk_mount`의 raw 이미지 마운트와 E01 안 NTFS 볼륨 마운트, 파티션 조회에 적용된다 [1][20][21][22].
`VOLATILITY_BIN`, `HAYABUSA_BIN`, `VELOCIRAPTOR_BIN` 같은 환경변수가 없는 파일을 가리키면 `resolve_binary`는 그 값을 쓰지 않고 `PATH`에서 같은 도구를 찾는다 [1].
응답에는 실행한 파일의 경로나 환경변수 값을 쓰지 못했다는 사실이 실리지 않는다 [1].
실행 확인에서 `VOLATILITY_BIN`에 없는 경로를 주고 `PATH`에 시험용 `vol`을 두자 `vol_pslist`는 `PATH`의 `vol`로 실행되었고 응답은 프로세스 목록과 빈 `stderr_tail`뿐이었다 [17].
`bulk_extract`와 `pst_parse`는 환경변수 값이 폴더 구분자를 담은 경로이면 그 파일만 보고 `PATH`로 넘기지 않는다 [23].

`disk_mount`는 raw 이미지를 `mount -o ro,loop`로 마운트하다 실패하면 `mmls`로 찾은 주 파티션 위치를 붙여 다시 마운트하고 마운트 실행 파일 이름이 기본값 `mount`이면 그것도 실패할 때 `sudo -n`을 붙여 다시 실행한다 [20].
응답의 `command`와 `note`에는 성공한 시도만 적히고 앞의 시도가 실패했다는 사실은 적히지 않는다 [20].
E01 컨테이너 안의 NTFS 볼륨도 위치 0으로 마운트하지 못하면 `sudo -n mmls`로 찾은 위치로 다시 마운트하고 응답의 `command`에는 성공한 명령만 남긴다 [21].
파티션 목록을 만드는 `mmls`도 실패하면 `sudo -n mmls`로 다시 실행한다 [22].
실행 확인에서 시험용 `mmls`와 `sudo`가 모두 실패하자 두 실행이 차례로 기록되었고 `disk_mount` 응답의 `partitions`는 빈 목록이었다 [24].

### T07.04 실행 환경별 경로 분기

**구현.** 이 분기는 `findevil-mcp`의 실행 파일 탐색, `pcap_triage`의 분석기 선택, `hayabusa_scan`의 룰 폴더 탐색, `disk_mount`의 마운트 방식 선택에 적용된다 [1][25][10][26].
`resolve_binary`는 환경변수의 경로를 먼저 보고 그다음 `PATH`의 폴더마다 정해 둔 이름을 차례로 찾는다 [1].
Volatility는 `vol`, `volatility3`, `volatility`, `vol.py` 차례이고 Windows에서는 `vol.exe`, `volatility3.exe`, `volatility.exe`, `vol.py` 차례로 찾는다 [1].
`ez_parse`는 `EZTOOLS_DIR`, `plaso_parse`는 `PLASO_DIR`, `mac_triage`는 `MAC_APT`를 먼저 본다 [2].
`pcap_triage`는 `analyzer`가 `auto`이면 `tshark`가 있을 때 `tshark`를, 없고 `zeek`가 있을 때 `zeek`를 실행하고 응답의 `analyzer`에 실행한 분석기를 적는다 [25].
`zeek`로 실행한 응답은 요청별 출발지와 쿠키를 담는 `http_requests`를 비워 둔다 [25].
`hayabusa_scan`은 `HAYABUSA_RULES_BASE`, `$XDG_DATA_HOME/hayabusa-mcp`, `~/.local/share/hayabusa-mcp` 차례로 `rules/config`가 있는 폴더를 찾아 Hayabusa의 작업 폴더로 쓴다 [10].
시작 스크립트가 읽는 `project-env.sh`는 `HAYABUSA_RULES_BASE`를 실행 상태 폴더 아래로 정해 둔다 [10].
`disk_mount`의 `auto` 방식은 Windows에서 실행을 거부하고 그 밖에서는 이미지가 E01 첫 조각이면 `ewfmount`로, 아니면 `mount`로 마운트한다 [26].

### T07.05 대체 사실을 응답·기록에 표시

**구현.** 이 표시는 `findevil-mcp`의 `ez_parse`와 `disk_mount`, `findevil-agent-mcp`의 `manifest_finalize`에 적용된다 [27][28][29][30].
`ez_parse`는 인자 `tool`이 `lecmd`이고 `LECmd`가 없으면 서버 안의 경로 이름 검사로 대신한다 [27].
이 대체는 LNK 파일 경로에 `/recent/`나 `/nethood/`와 정해 둔 낱말이 함께 있을 때만 행을 하나 내고 그 행의 `Fallback Basis`에 `path_name`을 적는다 [27].
응답의 `stderr_tail`에는 `LECmd`가 없어 경로 이름 대체를 썼다는 문구가 들어간다 [27].
실행 확인에서 `Recent` 폴더 아래 `staging`이 들어간 이름의 시험 파일로 부르자 응답의 `stderr_tail`과 행의 `Fallback Basis`, `Fallback Warning`이 위 내용대로였다 [17].

`disk_mount`는 E01 이미지에서 `ewfmount`가 없거나 `sudo` 아래에서 찾지 못하면 마운트하지 않고 Sleuth Kit으로 이미지를 직접 읽는 자원으로 등록한다 [28].
이때 응답과 사건 폴더의 `session_resources.json`에는 `command`가 `direct-tsk`로, `note`가 마운트하지 않은 사실과 그 이유로 남는다 [28].
실행 확인에서 `ewfmount`가 없는 환경으로 `disk_mount`를 부르자 응답과 `session_resources.json`의 `note`가 모두 `ewfmount not found`를 담았다 [24].

`manifest_finalize`는 `sigstore` 서명이 실패하면 Ed25519 서명으로, Ed25519 서명이 실패하면 시험용 `stub` 서명으로 바꾼다 [29].
`FallbackSigner`는 바꾼 이유를 `fallback_reason`에 남기고 manifest의 `signature`에는 실제 서명 종류 `kind`와 `fallback_reason`이 들어간다 [29].
응답은 실제 서명 종류를 `signer_effective`에, 이유를 `fallback_reason`에 싣는다 [29].
호출자가 `stub`을 요청하면 `FINDEVIL_ALLOW_STUB_SIGNER`가 켜져 있지 않은 한 Ed25519로 바꾸고 그 사실도 `fallback_reason`에 적는다 [29].
실행 확인에서 네트워크가 없는 상태로 `sigstore`를 요청하자 응답의 `signer_effective`는 `ed25519`, `fallback_reason`은 `primary signer failed, degraded to ed25519: Failed to refresh TUF metadata`였고 manifest의 `signature`에도 같은 값이 있었다 [18].
`anchor_transparency`를 켠 호출은 Rekor 기록이 실패하면 RFC 3161 시간 기록으로 바꾸고 manifest의 `transparency_log`에 실제 종류 `kind`와 `fallback_reason`을 남긴다 [30].

**한계.** `ez_parse`의 대체에서 경로 조건이 맞지 않으면 행이 없고 대체 사실은 `stderr_tail`에만 남는다 [27].
`disk_mount`가 `direct-tsk`로 등록한 응답의 `status`는 실제 마운트와 같은 `mounted`이고 `fs_root`는 이미지 파일 경로다 [28][24].

### T07.06 대체에 따른 검증·입력 범위 변화 표시

**구현.** 이 표시는 `findevil-mcp`의 `ez_parse` 대체와 `disk_mount`의 E01 마운트, `findevil-agent-mcp`의 `stub` 서명에 적용된다 [27][31][32].
`ez_parse` 대체 행의 `Fallback Warning`은 경로만 낸 것이고 대상 정보와 볼륨 일련번호를 디코딩하지 않았다고 적는다 [27].
`disk_mount`는 E01 컨테이너를 마운트한 뒤 NTFS 볼륨을 마운트하지 못하면 컨테이너만 등록하고 `note`에 NTFS 볼륨을 마운트하지 못했다는 문구와 `custody-only`를 적는다 [31].
`manifest_verify`는 서명 종류가 `stub`이면 응답의 `signature_verified`를 거짓으로 두고 `signature_verified_detail`에 암호 증명이 아닌 시험용 값이라는 문구를 싣는다 [32][19].

**한계.** `sigstore`에서 Ed25519로 바뀐 경우 응답과 manifest는 서명 종류와 실패 이유만 적고 서명자 신원과 투명성 기록이 빠졌다는 사실은 따로 적지 않는다 [29].
`manifest_verify`는 서명 종류가 `stub`이나 `sigstore`이면 서명이 검증되지 않아도 다른 대조가 통과할 때 `overall`을 참으로 두므로 `stub`으로 대체된 서명의 manifest도 `overall`이 참이 된다 [33].
NTFS 볼륨을 마운트하지 못한 경로는 실제 마운트가 필요해 실행으로 확인하지 않았다.

### T07.08 일부 제외 후 계속 실행

**구현.** 이 방식은 `findevil-mcp`의 `hashset_lookup`과 `disk_mount`의 파티션 목록, `findevil-agent-mcp`의 `expert_miss_capture`에 적용된다 [34][22][35].
`hashset_lookup`은 해시 집합 파일마다 읽기를 시도하고 읽지 못한 집합은 그 항목의 `error`에 이유를 적은 뒤 나머지 집합으로 조회를 계속한다 [34].
실행 확인에서 없는 파일을 집합으로 주자 응답의 `sets_loaded` 항목에 `open failed`로 시작하는 `error`가 있었고 조회한 해시는 `unknown`이었다 [17].
`disk_mount`는 `mmls`로 파티션 목록을 얻지 못해도 마운트를 계속하고 `partitions`를 빈 목록으로 둔다 [22][24].
`expert_miss_capture`는 `FINDEVIL_MISS_GH_ENABLED`가 켜져 있으면 `gh`로 GitHub 이슈를 만들려 하고 `gh`가 없거나 실패하면 이슈 없이 기록만 남긴다 [35].
실행 확인에서 `gh`가 없는 환경으로 부르자 기록은 남았고 응답의 `github_issue_url`은 `null`이었다 [18].

**한계.** `FINDEVIL_HASHSET_DIR`이 없으면 `hashset_lookup`은 집합 없이 조회하고 모든 해시를 `unknown`으로 돌려준다 [34].
실행 확인에서 이 경우 응답의 `sets_loaded`는 빈 목록이었고 집합이 없다는 문구는 없었다 [17].
`disk_mount`와 `expert_miss_capture`의 응답은 빠진 부분이 있다는 사실이나 그 이유를 적지 않는다 [22][35].

```python
class FallbackSigner:
    """Tries a primary signer (real sigstore) and honestly degrades to a
    fallback (stub) when the primary fails — the typical offline / no-token
    case. The returned bundle carries ``kind="stub"`` and a non-empty
    ``fallback_reason`` so the release gate reads the *effective* signer, not
    the *requested* one, and never crashes a run just because Fulcio/Rekor
    (or an OIDC token) was unavailable.
    """

    def __init__(self, primary: Signer, fallback: Signer) -> None:
        self._primary = primary
        self._fallback = fallback

    def sign(self, payload: bytes) -> SignedBundle:
        try:
            return self._primary.sign(payload)
        except Exception as exc:  # degrade on ANY primary-signer failure
            bundle = self._fallback.sign(payload)
            reason = f"primary signer failed, degraded to {bundle.kind}: {exc}"
            if bundle.fallback_reason:  # nested fallback — keep the inner story
                reason = f"{reason} (after: {bundle.fallback_reason})"
            return replace(bundle, fallback_reason=reason)
```
