# D03 파생물 무결성 검증

### D03.01 기준값 자동 계산

**구현.** 이 방식은 `findevil-agent-mcp`의 `manifest_finalize`가 쓰는 manifest와 그 leaf인 발견사항 기록, `expert_miss_capture`의 수정 기록, `findevil-mcp`의 `bulk_extract`가 남기는 특징 파일에 적용된다 [1][2][3][4].
`manifest_finalize`는 서명 블록과 `transparency_log`를 뺀 manifest 본문을 정규화한 바이트에 서명하고 서명 묶음과 그 바이트의 SHA-256 `payload_sha256`을 manifest의 `signature`에 넣는다 [1].
`signer`의 기본값 `ed25519`는 `FINDEVIL_SIGNING_KEY`나 `~/.findevil/signing.key`의 로컬 키로 서명하고 키 파일이 없으면 새로 만든다 [5].
`signer`에 `sigstore`를 주면 Fulcio·Rekor 서명을 먼저 시도한다 [6].
`finding_approved` 기록마다 그 기록 줄의 SHA-256을 leaf로 계산해 leaf 목록과 Merkle root를 manifest에 넣는다 [2].
`tool_call_output` leaf는 호출한 쪽이 기록에 넣은 응답 해시 `output_hash`다 [2].
`expert_miss_capture`는 줄마다 앞 줄의 SHA-256을 `prev_hash`로 넣어 쓰고 쓴 줄의 해시를 응답의 `line_hash`로 돌려준다 [3].
모델이 해시 도구를 부르지 않아도 서버가 계산한다.
manifest의 기준값은 manifest 파일 안과 `manifest_finalize` 응답에 남는다 [1][7].
`bulk_extract`는 특징 파일(`.txt`)마다 내용 전체의 SHA-256을 계산해 응답의 `staged_files`에 싣는다 [4].
이 해시는 응답에만 있고 서버가 파일로 남기지 않으며 `report.xml`과 `find_regexes.txt`는 해시하지 않는다 [4].
에이전트 서버로 manifest를 만들자 `signer_effective`가 `ed25519`였고 시험용 `bulk_extractor`로 `bulk_extract`를 부르자 응답에 특징 파일 둘의 SHA-256이 실렸다 [8].

`disk_extract_artifacts`가 꺼낸 파일과 `pst_parse`의 내보내기 폴더, `case.json`, `session_resources.json`에는 기준값이 없다 [9].
`memory_remember`의 `sha256`은 호출 인자로 받은 값이고 서버가 계산하지 않는다 [10].

**한계.** 서명 키를 읽거나 만들지 못하면 `stub` 서명으로 바꾸고 이유를 `fallback_reason`에 적은 뒤 manifest를 쓴다 [6].
`stub` 서명은 본문 SHA-256과 `run_id`로 만든 값이고 키를 쓰지 않는다 [11].
키 경로를 쓸 수 없는 곳으로 두고 `manifest_finalize`를 부르자 `signer_effective`가 `stub`이고 `fallback_reason`에 실패 이유가 실린 manifest가 생겼다 [8].
`signer`에 `stub`을 주면 `FINDEVIL_ALLOW_STUB_SIGNER`가 켜져 있을 때만 그대로 쓰고 아니면 `ed25519`로 바꾼다 [12].
`anchor_transparency`로 붙이는 `transparency_log`는 서명 뒤에 manifest를 다시 써서 넣으므로 서명 대상이 아니다 [7][1].

### D03.03 도구를 요청해 검증

**구현.** 이 방식은 `findevil-agent-mcp`의 `manifest_verify`가 manifest를 검증할 때 적용된다 [13].
`manifest_verify`는 manifest의 `leaves`로 Merkle root를 다시 계산해 `merkle_root_hex`와 대조한다 [14].
호출 기록 파일을 다시 읽어 체인을 확인하고 기록 수, 마지막 줄 해시, leaf 목록을 다시 만들어 manifest에 적힌 값과 대조한다 [15].
대조할 호출 기록 파일은 인자 `audit_log_path`, manifest와 같은 폴더의 같은 이름 파일, manifest에 적힌 경로 순서로 고른다 [15].
`ed25519` 서명이면 manifest에서 서명 블록과 `transparency_log`를 뺀 본문을 정규화해 서명 묶음 안의 공개 키로 서명을 검증한다 [16].
결과는 항목마다 참·거짓과 이유를 담고 체인, Merkle root, leaf 수, 서명 유무를 묶은 `overall`을 함께 돌려준다 [17][13].
`ed25519` manifest의 `extra`를 고친 뒤 부르자 `signature_verified`와 `overall`이 거짓이었다 [8].
봉인 뒤 호출 기록에 한 줄을 더하고 부르자 기록 수가 다르다는 이유로 `audit_chain_ok`가 거짓이었다 [8].
`audit_verify`는 받은 경로의 해시 체인을 다시 계산하므로 `expert_misses.jsonl`의 체인도 이 도구로 검증한다 [18].
검증 결과는 그 도구의 응답에만 실리고 서버는 다른 도구 호출에서 이 결과를 쓰지 않는다.

`bulk_extract` 특징 파일의 해시를 대조하는 도구는 없다 [4].
`verify_finding`은 인용한 호출을 다시 실행해 새 응답의 해시를 호출한 쪽이 준 `output_sha256`과 대조하고 보관한 파생물의 기준값은 쓰지 않는다 [19].

**한계.** `ed25519` 서명은 manifest의 서명 묶음에 들어간 공개 키로만 검증하고 정해 둔 키와 대조하지 않는다 [16].
다시 쓴 호출 기록을 다른 키로 봉인한 manifest는 `manifest_verify`에서 `signature_verified`와 `overall`이 참이었다 [20].
`stub`과 `sigstore` 서명은 검증하지 않고 `signature_verified`에 이유만 적으며 `overall`은 이 두 서명이 있는지만 본다 [17][21].
서명 종류는 manifest에 적힌 `signature.kind` 값으로 정하고 이 값은 서명 대상 밖이다 [22][16].
`ed25519`로 봉인한 manifest의 본문과 서명 종류 값을 함께 고치자 `overall`이 참이었다 [23].
`stub` manifest의 `case_id`를 고친 뒤 부르자 체인과 Merkle root는 맞아 `overall`이 참이었다 [8].
키를 쓰지 못해 `stub`으로 서명된 manifest도 `overall`이 참이었다 [8].
README는 `manifest_verify`가 전체 체인을 오프라인으로 확인한다고 적는다 [24].

```python
def _to_json_safe(manifest: RunManifest, *, exclude_signature: bool = False) -> dict[str, Any]:
    """Convert the dataclass to a JSON-safe dict.

    Used both for canonicalizing-then-signing (with
    ``exclude_signature=True``) and for the on-disk write (with
    the signature included).
    """
    out: dict[str, Any] = asdict(manifest)
    if exclude_signature:
        out.pop("signature", None)
        # The transparency anchor is attached AFTER signing, so it must never be
        # part of the signed bytes — strip it on the sign/verify path exactly
        # like ``signature``. The on-disk write (exclude_signature=False) keeps
        # both, so a re-write that adds the anchor does not invalidate the
        # already-computed signature.
        out.pop("transparency_log", None)
    return out
```
