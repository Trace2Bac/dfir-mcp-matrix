# D01 파생물 보관

### D01.01 파생물 파일 보관

**구현.** 이 방식은 `findevil-mcp`의 `case_open`·`disk_mount`·`disk_extract_artifacts`·`bulk_extract`·`pst_parse`와 `findevil-agent-mcp`의 `audit_append`·`manifest_finalize`·`expert_miss_capture`에 적용된다 [1][2][3][4][5][6][7][8].
`findevil-mcp`의 사건 폴더는 `$FINDEVIL_HOME/cases/<case_id>/`이고 `case_open`이 이 폴더를 만든다 [1].
`case_open`은 증거 경로, 증거 SHA-256, 크기, 등록 시각, `label`을 사건 폴더의 `case.json`에 쓴다 [1].
`disk_mount`와 `disk_extract_artifacts`는 마운트와 추출을 사건 폴더의 `session_resources.json`에 JSON 목록으로 남긴다 [2].
`disk_unmount`는 이 파일에서 마운트 항목의 상태, 갱신 시각, 실행 명령을 해제할 때의 값으로 고쳐 쓴다 [2].
그래서 마운트할 때 실행한 명령은 해제 뒤 이 파일에 남지 않는다 [2].
`disk_extract_artifacts`는 Sleuth Kit `icat`이 증거 이미지에서 꺼낸 파일을 사건 폴더의 `extracted/disk/<extract_id>/<분류>/` 아래에 이미지 안 경로대로 둔다 [3].
삭제된 항목에서 복구한 파일은 같은 분류 폴더의 `__deleted__/<inode>/` 아래에 둔다 [3].
꺼낸 파일이 `max_artifact_bytes`(기본 512 MiB)보다 크면 그 파일을 지우고 개수만 응답에 싣는다 [3].
`bulk_extract`는 `bulk_extractor`의 출력 폴더를 사건 폴더의 `extracted/bulk_extract/<이미지 파일 이름>/out/`으로 정하고 호출이 끝나도 지우지 않는다 [4].
이 폴더에는 `bulk_extractor`가 쓴 특징 파일과 `report.xml`이 남고 그 위 폴더에는 서버가 정규식 인자를 적은 `find_regexes.txt`가 남는다 [4][9].
`pst_parse`는 `pffexport`의 내보내기 결과를 사건 폴더의 `extracted/pst/pst-export-<UUID>/`에 두고 성공한 호출에서는 지우지 않는다 [5].
시험용 실행 파일로 네 도구를 부르자 사건 폴더에 `case.json`, `session_resources.json`, 꺼낸 파일, 특징 파일, 내보내기 폴더가 남았다 [10].

`findevil-agent-mcp`의 `audit_append`는 호출 인자 `path`의 JSONL 파일에 호출한 쪽이 준 `kind`와 `payload`를 해시 체인 한 줄로 덧붙인다 [6][11].
같은 저장소의 사용자 CLI `find_evil_auto.py`는 발견사항 전체를 `finding_approved` 기록의 `payload`로 이 파일에 쓰므로 발견사항 기록은 이 JSONL 파일에 남는다 [12].
`manifest_finalize`는 서명한 manifest를 호출 인자 `output_path`에 JSON 파일로 쓴다 [7][13].
`expert_miss_capture`는 검토자가 고친 보고서 내용을 호출 인자 `ledger_path`의 JSONL 파일에 같은 해시 체인 형식으로 덧붙인다 [8].
`pool_handoff`는 호출 인자 `audit_path`의 JSONL 파일에, `memory_remember`·`memory_recall`·`accuracy_compare`는 선택 인자 `audit_log_path`를 줄 때만 그 파일에 역할 사이 메시지나 조회·점수 기록을 같은 형식으로 덧붙인다 [14].
에이전트 서버를 실행해 `audit_append`, `manifest_finalize`, `expert_miss_capture`를 부르자 받은 경로에 `audit.jsonl`, `run.manifest.json`, `expert_misses.jsonl`이 생겼다 [15].

`ez_parse`, `mac_triage`, `pcap_triage`, `suricata_eve`, `hayabusa_scan`, `plaso_parse`는 분석 도구의 출력을 임시 폴더에 쓰고 읽은 뒤 지운다 [16].
`srum_parse`는 사건 폴더의 `_xartifact/srum-<pid>-<나노초>/`에 내보낸 뒤 호출이 끝나면 지운다 [17].
두 서버의 나머지 도구는 결과를 응답으로만 돌려준다.
두 서버는 응답에서 주입 문자열을 바꾼 호출이 있으면 도구 이름, 응답 SHA-256, 바꾼 개수를 `injection_alerts.jsonl`에 덧붙이고 응답 내용은 남기지 않는다 [18].
보관 기간이나 보관 대상을 정하는 설정과 코드는 없고 보관한 파일을 지우는 MCP 도구도 없다.

`find_evil_auto.py`는 실행마다 자기 실행 폴더를 정하고 그 안의 `audit.jsonl`과 `run.manifest.json` 경로를 위 도구의 인자로 넘긴다 [19].
같은 CLI가 직접 쓰는 `verdict.json`, `status.json` 같은 파일은 사용자 CLI의 동작이라 서버 구현으로 보지 않는다 [19].

**한계.** `case_open`은 응답의 `db_path`에 사건 폴더의 `evidence.ddb`를 적지만 이 파일을 만드는 코드는 두 서버에 없다 [20].
`disk_mount`를 `mode: mock`으로 부르면 서버는 마운트하지 않고 호출 인자 `mount_point`의 폴더를 자원의 `fs_root`로 적는다 [21].
`disk_extract_artifacts`는 이 자원의 이미지를 Sleuth Kit으로 읽지 못하면 `fs_root` 폴더의 파일을 아티팩트로 복사한다 [21].

### D01.02 객체 저장소·DB 보관

**구현.** 이 방식은 `findevil-agent-mcp`의 `memory_remember`에 적용된다 [22].
`memory_remember`는 호출 인자 `store_path`의 SQLite 파일을 열고 FTS5 가상 테이블 `memories`에 사건 ID, 종류, 키, 값, `sha256`, 시각을 한 행으로 넣는다 [22][23].
행의 시각 `ts`는 호출자가 주면 그 값이고 주지 않으면 서버가 정한 시각이다 [22][23].
같은 호출에서 `meta` 테이블에 사건 ID별 사건 경로와 처음·마지막 기록 시각을 남긴다 [23].
넣는 값은 호출 인자로 받은 IOC, 해시, 공격 기법, 호스트 이름, 발견사항 요약이고 서버가 도구 출력에서 뽑은 값이 아니다 [22].
`find_evil_auto.py`는 CONFIRMED 발견사항마다 이 도구를 불러 요약을 넣는다 [24].
같은 키로 두 번 부르자 두 행이 모두 남았고 `memory_recall`이 둘을 시각과 함께 돌려주었다 [15].

`findevil-mcp`는 DB를 쓰지 않는다 [20].

```rust
fn write_find_regexes(
    regexes: &[String],
    staging: &Path,
) -> Result<Option<PathBuf>, BulkExtractError> {
    if regexes.is_empty() {
        return Ok(None);
    }
    for (index, regex) in regexes.iter().enumerate() {
        if regex.contains('\n') || regex.contains('\r') || regex.contains('\0') {
            return Err(BulkExtractError::InvalidRegex { index });
        }
    }
    let path = staging.join("find_regexes.txt");
    let body = regexes.join("\n");
    std::fs::write(&path, body).map_err(|source| BulkExtractError::Io {
        path: path.clone(),
        source,
    })?;
    Ok(Some(path))
}
```

```python
    def append(self, kind: str, payload: dict[str, Any], *, ts: str | None = None) -> AuditRecord:
        """Append one record. Thread-safe. fsyncs before returning."""
        with self._lock:
            record = AuditRecord(
                seq=self._next_seq,
                ts=ts or _utc_iso(),
                kind=kind,
                prev_hash=self._last_hash,
                payload=payload,
            )
            line = canonicalize_json(record.to_canonical_dict())
            self.path.parent.mkdir(parents=True, exist_ok=True)
            with self.path.open("ab") as f:
                f.write(line + b"\n")
                f.flush()
                os.fsync(f.fileno())
            self._last_hash = hash_line(line)
            self._next_seq += 1
            return record
```

def write_manifest(manifest: RunManifest, path: Path) -> Path:
    """Write the manifest to ``path`` as canonical pretty JSON."""
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(
        json.dumps(_to_json_safe(manifest), indent=2, sort_keys=True) + "\n",
        encoding="utf-8",
    )

/// Create a fresh per-case staging directory under
/// `$FINDEVIL_HOME/cases/<case_id>/_xartifact/srum-<pid>-<nanos>`. Derived
/// entirely at runtime; never beside the read-only evidence.
fn prepare_staging_dir(case_id: &str) -> Result<PathBuf, SrumError> {
    let case = case_dir(case_id)?;
    let staging =
        case.join("_xartifact")
            .join(format!("srum-{}-{}", std::process::id(), nanosecond_tag()));
