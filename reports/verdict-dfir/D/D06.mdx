# D06 산출물 식별·재생성 처리

### D06.01 실행 ID별 위치

**구현.** 이 방식은 `findevil-mcp`의 `case_open`, `disk_mount`, `disk_extract_artifacts`, `pst_parse`에 적용된다 [1][2][3][4].
`case_open`은 호출마다 UUIDv4 `case_id`를 새로 짓고 그 이름의 사건 폴더를 만든다 [1].
같은 증거로 다시 부르면 다른 사건 폴더가 생기고 앞 사건 폴더는 그대로 남는다 [1].
`disk_mount`는 `disk-mount-<UUID>`, `disk_extract_artifacts`는 `disk-extract-<UUID>`를 호출마다 매기고 그 ID로 `mounts/`와 `extracted/disk/` 아래 폴더를 나눈다 [2][3].
`pst_parse`는 호출마다 `pst-export-<UUID>` 폴더를 새로 만든다 [4].
한 추출 안에서 삭제 항목은 `__deleted__/<inode>/` 아래에 두어 이미지 안 경로가 같은 삭제되지 않은 파일과 겹치지 않는다 [3].
같은 증거로 `case_open`을 두 번, 같은 마운트로 추출을 두 번, 같은 파일로 `pst_parse`를 두 번 부르자 각각 다른 ID의 폴더가 따로 남았다 [5].

**한계.** `disk_mount`와 `vss_mount`에 `mount_point`를 주면 마운트 지점은 ID로 나뉘지 않고 받은 경로를 쓴다 [2][6].

### D06.02 입력·작업별 고유 이름

**구현.** 이 방식은 `findevil-mcp`의 `bulk_extract`에 적용된다 [7].
출력 폴더 이름은 입력 이미지의 파일 이름을 폴더 이름 한 조각으로 바꾼 값이고 UUID나 시각이 들어가지 않는다 [7][8].
그래서 파일 이름이 다른 이미지의 결과와는 구별되지만 같은 이미지를 다시 실행한 결과는 구별하지 않는다 [7].
같은 이름의 출력 폴더가 있으면 알리지 않고 지운 뒤 새로 만든다 [7].
코드 주석은 같은 이미지의 기록 경로가 실행마다 같도록 UUID를 넣지 않는다고 적는다 [7].

**한계.** 이름에는 이미지의 경로가 아니라 파일 이름만 들어가므로 다른 폴더의 같은 이름 이미지는 같은 출력 폴더를 쓴다 [8].
다른 폴더의 같은 이름 이미지로 `bulk_extract`를 이어 부르자 첫 호출의 `find_regexes.txt`가 사라졌고 두 응답의 `staged_files`는 같은 경로를 실었다 [9].

### D06.03 버전·이력 보존

**구현.** 이 방식은 `findevil-agent-mcp`의 `memory_remember`와 해시 체인 파일에 덧붙이는 `audit_append`·`expert_miss_capture`·`pool_handoff`에 적용된다 [10][11].
`memory_remember`는 같은 사건·종류·키로 다시 불러도 앞 행을 바꾸지 않고 새 행을 시각과 함께 넣는다 [10].
`memory_recall`은 같은 키의 행을 모두 각 행의 시각과 함께 돌려준다 [12].
같은 키로 두 번 부르자 두 값이 모두 남았고 조회 결과에 각 행의 시각이 실렸다 [13].
해시 체인 파일에 덧붙이는 도구는 파일 끝에 순번 `seq`와 시각 `ts`를 붙인 줄을 더하고 앞 줄을 바꾸지 않는다 [11].
그래서 같은 `finding_id`의 `finding_approved` 기록을 다시 쓰면 앞 기록 뒤에 새 기록이 붙는다 [11].

`manifest_finalize`는 같은 `output_path`로 다시 부르면 앞 manifest를 알리지 않고 덮어쓴다 [14].
같은 경로로 두 번 부르자 파일은 하나였고 둘째 호출의 `run_id`가 들어 있었다 [13].
`anchor_transparency`를 켜면 서명한 manifest를 같은 경로에 한 번 더 쓴다 [14].
`findevil-mcp`의 `session_resources.json`은 새 마운트와 추출 항목을 더해 다시 쓰고 앞 항목을 남긴다 [15].

**한계.** `memory_remember`와 `audit_append`는 호출 인자 `ts`가 있으면 그 값을 행이나 기록 줄의 시각으로 쓰고 없을 때만 서버가 시각을 정한다 [10][11][16].
서버는 받은 `ts`의 형식과 앞 행보다 늦은 시각인지를 검사하지 않는다 [10][11][16].

```rust
/// A filesystem-safe, deterministic stem for the staging directory.
///
/// Derived from the image file name at runtime (never a baked-in
/// literal). Keeps ASCII alphanumerics, `.`, `-`, `_`; folds everything
/// else to `_`. Empty input yields `image`.
#[must_use]
pub fn sanitize_stem(image: &Path) -> String {
    let raw = image
        .file_name()
        .and_then(|n| n.to_str())
        .unwrap_or("image");
    let cleaned: String = raw
        .chars()
        .map(|c| {
            if c.is_ascii_alphanumeric() || matches!(c, '.' | '-' | '_') {
                c
            } else {
                '_'
            }
        })
        .collect();
    if cleaned.is_empty() {
        "image".to_string()
    } else {
        cleaned
    }
}
```

```rust
fn read_ledger(path: &Path) -> Result<SessionLedger, DiskError> {
    if !path.exists() {
        return Ok(SessionLedger::default());
    }
    let text = fs::read_to_string(path).map_err(|source| DiskError::Io {
        path: path.to_path_buf(),
        source,
    })?;
    serde_json::from_str(&text).map_err(DiskError::Serialize)
}

fn write_ledger(path: &Path, ledger: &SessionLedger) -> Result<(), DiskError> {
    let text = serde_json::to_string_pretty(ledger)?;
    fs::write(path, text).map_err(|source| DiskError::Io {
        path: path.to_path_buf(),
        source,
    })
}

fn upsert_resource(path: &Path, resource: SessionResource) -> Result<(), DiskError> {
    let mut ledger = read_ledger(path)?;
    ledger.resources.retain(|r| r.id != resource.id);
    ledger.resources.push(resource);
    write_ledger(path, &ledger)
}
```
