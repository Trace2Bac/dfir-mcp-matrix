# I02 분석 도구 통신 차단

### 미구현

**판단.** `findevil-mcp`는 Volatility 3, Velociraptor, `tshark`, Zeek, Sleuth Kit, Plaso 같은 분석 도구를 하위 프로세스로 실행하고 그 통신을 끊거나 끄는 옵션이나 장치를 두지 않는다 [1][2][3].
저장소에는 분석 도구를 네트워크 없는 컨테이너나 network namespace에서 실행하는 구성이 없다.
컨테이너 실행 스크립트 `scripts/run-dfir-container.sh`의 `docker run`에도 네트워크를 끊는 옵션이 없다 [4].
컨테이너 이미지 정의 `docker/dfir.Dockerfile`은 Volatility 3가 처음 쓸 때 Windows PDB 심볼을 내려받는다고 주석에 적고 심볼 폴더에 모든 사용자의 쓰기 권한을 준다 [5].

Volatility 3는 통신을 끄지 않은 채 실행된다.

- `vol_pslist`, `vol_psscan`, `vol_psxview`, `vol_malfind`, `vol_run`은 `vol`에 `-f`, `-r json`, `-q`, 플러그인 이름만 넘기고 `--offline`을 붙이지 않는다 [1][6].
- 시험용 `vol`을 두고 `vol_pslist`를 부르자 받은 인자는 `-f <파일> -r json -q windows.pslist`뿐이었다 [7].
- 버전 기준인 Volatility 3 2.11.0에서 온라인 여부를 정하는 `constants.OFFLINE`의 기본값은 거짓이고 명령 행의 `--offline`이 이 값을 켠다 [8][9].
- 이 값이 꺼져 있으면 Volatility 3는 Windows 커널의 심볼 표가 로컬 캐시에 없을 때 `http://msdl.microsoft.com/download/symbols`에서 PDB를 받아 변환한다 [10].
- Volatility 3 2.11.0의 오프라인 처리기는 `OFFLINE`이 켜졌을 때만 http·https 요청을 막는다 [11].
- Volatility 3 2.11.0의 명령 행은 사용자 홈의 `.config/volatility3/vol.json`을 인자 기본값으로 읽으므로 그 파일이 `offline`을 정하면 동작이 달라진다 [12].

`vel_collect`는 모델이 고른 Velociraptor 아티팩트 이름과 인자를 `velociraptor artifacts collect`에 넘기고 아티팩트를 목록과 대조하지 않는다 [2].
서버는 이 도구의 `openWorldHint`를 참으로 알리고 코드 주석은 일부 아티팩트가 외부 시스템에 닿는다고 적는다 [13].
이 표시는 클라이언트에 알리는 값이고 Velociraptor의 통신을 막지 않는다 [13][2].

`pcap_triage`는 `tshark`에 이름 해석을 끄는 `-n`을 붙이지 않는다 [3].
시험용 `tshark`가 받은 인자에도 `-n`이 없었다 [7].
`login_accounting`은 `last`에 `-f`, `-F`, `-w`만 넘기고 코드 주석은 `last`가 `-d`를 주지 않으면 DNS 조회를 하지 않는다고 적는다 [14].
`argsafe`의 실행 금지 목록에는 `curl`, `wget`, `ssh` 같은 네트워크 프로그램이 있지만 이 목록은 실행할 프로그램 이름만 검사하고 실행한 분석 도구의 통신은 막지 않는다 [15].

`findevil-agent-mcp`는 분석 도구를 직접 실행하지 않는다 [16].
`findevil-agent-mcp`의 `verify_finding`은 호출 인자 `findevil_mcp_command`로 `findevil-mcp`를 하위 프로세스로 실행해 근거 도구 호출을 다시 실행하므로 이때도 `findevil-mcp`의 같은 명령으로 분석 도구가 실행된다 [17].
이 서버가 쓰는 sigstore 라이브러리의 연결은 서버 코드가 인자로 켜는 서명과 투명성 기록 연결이다 [18].
Volatility 3 말고 서버가 실행하는 분석 도구와 서버에 링크한 라이브러리가 스스로 통신하는지는 확인하지 않았다.

```rust
//! `last` invocation (deliberately minimal, FIXED argv):
//!   `last -f <wtmp_path> -F -w`
//!     -f  read this accounting file instead of /var/log/wtmp
//!     -F  full login/logout times (so we get a parseable absolute date)
//!     -w  wide — never truncate the user / host columns
//!
//! We deliberately do NOT pass `-R` (`--nohostname`): that flag suppresses the
//! host field entirely, which would discard the remote SSH/RDP source host that
//! is the whole point of this tool (an interactive login from an unexpected
//! host is the lateral-movement signal). `last` displays the host string AS
//! RECORDED in `wtmp` and does no live DNS lookup by default (that is opt-in via
//! `-d`), so keeping the host column is both useful and network-safe.
```
