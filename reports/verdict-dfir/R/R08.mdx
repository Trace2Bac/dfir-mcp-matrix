# R08 시간값 처리

### R08.01 시간 변환 전 값 유지

**구현.** 이 방식은 `findevil-mcp`에서 외부 도구나 파일의 시각 문자열을 바꾸지 않고 싣는 도구에 적용된다 [1][2][3][4][5][6].
Volatility 도구는 `CreateTime`과 `ExitTime` 문자열을 `create_time_iso`와 `exit_time_iso`에 그대로 싣는다 [1].
`evtx_query`와 `sysmon_network_query`는 레코드의 `SystemTime` 속성 문자열을 `ts`에 그대로 싣는다 [2].
`vss_list`의 `creation_time`, `pst_parse`의 `delivery_time`, `exif_parse`의 `datetime_original`과 `datetime`은 도구나 파일이 낸 문자열 그대로다 [3].
`login_accounting`은 `last -F`가 출력한 시각 문자열을 `login_iso`와 `logout_iso`에 싣고 원래 줄을 `raw`에 함께 싣는다 [4].
`suricata_eve`, `vol_run`, `nfdump_query`, `journalctl_query`, `vel_collect`, `cloud_audit`, `ez_parse`, `mac_triage`, `indx_parse`, `plaso_parse`는 외부 도구 출력이나 원래 레코드의 시각 값을 바꾸지 않는다 [5].
`zeek_summary`는 Zeek 기록의 `ts` 문자열을 그대로 싣는다 [6].
시험에서 `vol_pslist`는 시험용 Volatility 실행 파일이 낸 `2026-01-02 03:04:05.123456`을 `create_time_iso`에 그대로 실었다 [7].

**한계.** Volatility 도구와 `login_accounting`의 필드 이름은 `_iso`로 끝나지만 값은 바꾸지 않은 문자열이라 ISO 8601이 아닐 수 있다 [1][4][7].
`pst_parse`는 전달 시각이 없으면 제출 시각을 `delivery_time`에 싣고 어느 값인지 적지 않는다 [8].
`evtx_query`는 `SystemTime`이 없으면 빈 문자열을 싣는다 [2].
`ausearch`는 기록의 `msg=audit(…)` 시각을 공백으로 나눈 낱말 가운데 날짜 부분만 `msg`에 싣고 전체 시각은 `raw`에만 남는다 [9].

### R08.03 시간대·단위·정밀도 표시

**구현.** 이 방식은 `findevil-mcp`에서 서버가 시각을 바꿔 싣는 도구에 적용된다 [10][11][12][13][14][15].
`prefetch_parse`, `registry_query`, `thumbcache_parse`는 Windows FILETIME을 UTC로 바꿔 `Z`를 붙인 `%Y-%m-%dT%H:%M:%SZ` 문자열로 싣는다 [10].
`mft_timeline`과 `usnjrnl_query`도 시각을 같은 꼴로 싣는다 [11].
`browser_history`는 Chrome의 1601년 기준 마이크로초와 Firefox의 1970년 기준 마이크로초를 같은 꼴로 바꾼다 [12].
`hayabusa_scan`은 Hayabusa의 ISO 8601 값을 UTC 마이크로초 RFC 3339 문자열(`Z`)로 다시 쓴다 [13].
`email_parse`는 mail-parser 0.11.4의 `to_rfc3339`로 날짜 머리글의 시간대 오프셋을 붙인 문자열을 싣고 오프셋이 0이면 `Z`를 붙인다 [14][15].
변환한 필드의 이름은 `_iso`로 끝난다 [10][11][12][13].

**한계.** 서버가 바꾼 FILETIME 값은 초 아래를 버리고 원래 정수를 싣지 않는다 [10][11].
`browser_history`도 초 아래를 버리고 원래 마이크로초 값을 싣지 않는다 [12].
그래서 응답의 시각 정밀도가 원래 값보다 낮고 응답에는 그 사실이 없다.
`prefetch_parse`는 1970년 이전이거나 바꿀 수 없는 실행 시각을 목록에서 빼고 `registry_query`와 `thumbcache_parse`는 같은 경우에 값을 비워 싣는다 [10].
`browser_history`는 0 이하의 값을 비워 싣는다 [12].
`hayabusa_scan`은 Hayabusa가 낸 소수 7자리 시각을 마이크로초 6자리로 줄이고 원래 값을 싣지 않는다 [16].
`hayabusa_scan`은 RFC 3339로 읽지 못한 값을 바꾸지 않고 `timestamp_iso`에 싣는다 [13].
`email_parse`는 날짜 머리글을 해석하지 못하면 값을 비우고 원래 머리글을 싣지 않는다 [14].
`pcap_triage`는 HTTP 요청의 첫 시각과 마지막 시각을 소수 세 자리 epoch 초 문자열로 싣고 필드 이름과 값에 단위를 적지 않는다 [17].

fn webkit_micros_to_iso(webkit_micros: i64) -> Option<String> {
    if webkit_micros <= 0 {
        return None;
    }
    let unix_micros = webkit_micros - WEBKIT_UNIX_OFFSET_SECS * 1_000_000;
    unix_micros_to_iso(unix_micros)
}

/// Unix microseconds (since 1970) -> UTC ISO-8601Z. Zero/negative -> None.
fn unix_micros_to_iso(unix_micros: i64) -> Option<String> {
    if unix_micros <= 0 {
        return None;
    }
    let secs = unix_micros.div_euclid(1_000_000);
    let nanos = u32::try_from(unix_micros.rem_euclid(1_000_000) * 1_000).unwrap_or(0);
    chrono::DateTime::from_timestamp(secs, nanos)
        .map(|dt| dt.format("%Y-%m-%dT%H:%M:%SZ").to_string())
}

/// the downstream timeline accepts it. Even with `--ISO-8601`, hayabusa emits
/// 100-ns (7-digit) fractions (`2022-02-22T10:10:10.1234567Z`); Python 3.10's

fn normalize_iso8601(raw: &str) -> String {

        |_| raw.to_string(),
        |dt| {

                .to_rfc3339_opts(chrono::SecondsFormat::Micros, true)
        },
    )
}
