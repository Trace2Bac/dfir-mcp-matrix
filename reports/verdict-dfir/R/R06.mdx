# R06 증거에서 추출한 민감정보 노출 제어

### 미구현

**판단.** 두 서버는 증거에서 나온 비밀 값을 응답에 싣고 그 값을 가리거나 빼는 처리를 두지 않는다 [1][2].
두 서버가 응답에 공통으로 적용하는 정리 처리는 보이지 않는 문자와 정해 둔 역할 토큰만 바꾸고 값의 종류를 가리지 않는다 [3].

`findevil-mcp`의 여러 도구가 비밀 값을 그대로 싣는다 [4][5][6].
`vol_run`의 허용 목록에는 `windows.registry.hashdump`, `windows.registry.lsadump`, `windows.registry.cachedump`가 들어 있고 도구 설명은 이 플러그인을 자격증명 항목으로 적는다 [4][5].
`vol_run`은 이 플러그인의 행을 열을 고르지 않고 `rows`에 싣는다 [6].
시험용 Volatility 실행 파일이 낸 `hashdump` 행의 해시 열은 응답에 그대로 실렸다 [7].
`registry_query`는 SAM과 SECURITY 하이브를 받고 이진 값을 4,096바이트까지 16진 문자열로 싣는다 [8][9].
`bulk_extract`의 `accts` 스캐너가 찾은 계좌 번호 같은 값은 `feature`와 `context`에 그대로 실린다 [10].
`cloud_audit`은 원래 레코드 전체를 `raw`에 싣고 `ausearch`는 Linux audit 기록 줄 전체를 `raw`에 싣는다 [11][12].
`pcap_triage`는 HTTP 쿠키 값을 싣지 않고 쿠키가 있었는지만 `has_cookie`에 싣는다 [13].
같은 도구는 질의 문자열이 들어간 요청 URI를 뒤쪽 256바이트까지 싣는다 [13].

`findevil-agent-mcp`의 `find_ai_signatures`는 읽은 파일의 일치 부분을 최대 400자 너비의 미리보기로 싣고 미리보기 안의 값을 가리지 않는다 [14].
`audit_append`는 모델이 넘긴 `payload`를 가리지 않고 호출 기록에 남긴다 [15].
사용자 CLI와 보고서 생성 스크립트가 있는 `scripts/*.py`에도 비밀 값을 가리는 함수가 없다 [16].
`scripts/regenerate-sample-run.py`의 `scrub_text`는 표본 실행 결과를 옮길 때 실행 폴더 접두어와 사용자 폴더 경로만 바꾼다 [17].

```rust
/// Neutralize one string: strip invisible code points, then replace role tokens.
pub fn sanitize_str(input: &str, counts: &mut Counts) -> String {
    // 1) Remove invisible/control code points first, so a token cannot be split
    //    by a zero-width character to evade step 2.
    let mut stripped = String::with_capacity(input.len());
    for c in input.chars() {
        if is_invisible_control(c) {
            counts.bump("invisible_unicode");
        } else {
            stripped.push(c);
        }
    }
    // 2) Replace chat/role control tokens (case-insensitive) with an inert marker.
    neutralize_tokens(&stripped, counts)
}
```

```python
def _make_preview(text: str, start: int, end: int, preview_chars: int) -> str:
    """Bounded, whitespace-collapsed snippet centered on a match.

    Newlines/tabs are collapsed to single spaces so a multi-line match renders
    as one inert line. The snippet is purely informational; the MCP output
    boundary still neutralizes any chat/role control tokens it contains.
    """
    width = max(0, min(preview_chars, MAX_PREVIEW_CHARS))
    pad = max(0, (width - (end - start)) // 2)
    lo = max(0, start - pad)
    hi = min(len(text), end + pad)
    snippet = text[lo:hi]
    return re.sub(r"\s+", " ", snippet).strip()
```

[17] `scrub_text`는 실행 폴더 접두어와 사용자 폴더 경로만 바꾼다.

```python
    """Relativize machine-specific paths in TEXT. Returns ``(scrubbed, count)``.

    Two passes, in order:

    1. Replace the literal absolute ``--from`` run-dir prefix (``run_dir_abs``)
       with the repo-relative destination (``dest_rel``), so the run's own
       case-id temp path becomes a stable repo-relative reference.
    2. Replace each ``/home/<user>`` / ``/Users/<user>`` prefix (evidence paths,
       case-home mounts, etc.) with ``home_placeholder``.

    Only those two path classes are touched. SHA digests, ISO-8601 timestamps,
    and enum tokens carry no such substring, so they pass through unchanged. Pure
    and deterministic: the same input always yields the same output.
    """
    count = 0
    if run_dir_abs and dest_rel:
        hits = text.count(run_dir_abs)
        if hits:
            text = text.replace(run_dir_abs, dest_rel)
            count += hits

    def _replace(_match: re.Match[str]) -> str:
        nonlocal count
        count += 1
        return home_placeholder

    text = HOME_PREFIX_RE.sub(_replace, text)
    return text, count
```
