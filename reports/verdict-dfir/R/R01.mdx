# R01 결과 가공

### R01.01 가공 없이 전달

**구현.** 이 방식은 `findevil-mcp`의 `suricata_eve`, `vol_run`, `nfdump_query`, `journalctl_query`, `vel_collect`, `plaso_parse`, `ez_parse`, `mac_triage`, `indx_parse`, `evtx_query`가 외부 도구나 파서의 레코드를 싣는 경로에 적용된다 [1][2][3][4][5][6].
`suricata_eve`는 `eve.json`의 줄마다 JSON 객체를 읽어 필드를 바꾸지 않고 `events`에 싣는다 [1].
`vol_run`은 Volatility 3가 낸 JSON 행을 열을 고르지 않고 `rows`에 싣는다 [2].
`nfdump_query`와 `journalctl_query`는 외부 도구가 낸 JSON 객체를 그대로 `rows`에 싣는다 [3].
`vel_collect`는 Velociraptor가 낸 행 객체를 바꾸지 않고 `rows`의 항목마다 `fields`에 싣는다 [3].
`ez_parse`와 `mac_triage`는 외부 도구가 쓴 CSV의 행을 머리글 열 이름과 값을 바꾸지 않은 `column -> value` 맵으로 싣는다 [4].
`plaso_parse`는 psort가 낸 `json_line` 사건 객체를 `events`에 싣는다 [5].
`evtx_query`는 레코드마다 `evtx` 크레이트가 만든 레코드 JSON 전체를 `data`에 싣는다 [6].
시험용 `suricata` 실행 파일이 쓴 `eve.json`의 필드는 응답 `events`에 같은 이름과 값으로 실렸다 [7].

**한계.** 두 서버는 응답을 내보내기 전에 모든 JSON 문자열 값에서 정해 둔 보이지 않는 문자를 지우고 정해 둔 역할 토큰을 `[neutralized:<id>]`로 바꾼다 [8][9].
그래서 이 경로의 문자열 값도 그런 문자나 토큰이 들어 있으면 바뀐 값으로 실린다 [7].
`plaso_parse`는 사건을 싣기 전에 문자열 값 안의 분석 대상 경로를 그 경로의 마지막 이름으로 바꾼다 [10].

### R01.02 구조화 파싱·필드 선택

**구현.** 이 방식은 `findevil-mcp`에서 외부 도구 출력이나 증거 파일을 서버 안 파서로 읽어 정해 둔 필드로 나눠 싣는 도구와 `findevil-agent-mcp`의 `find_ai_signatures`에 적용된다 [11][12][6][13][14][15][16][17].
`vol_pslist`는 Volatility 행에서 PID, PPID, 이미지 이름, 생성·종료 시각, 스레드 수, 핸들 수, 세션, WoW64만 골라 싣고 나머지 열은 싣지 않는다 [11].
`vol_malfind`는 VAD 시작·끝 주소, 보호 속성, MZ 표시를 고르고 `Hexdump` 같은 열의 문자열에서 16진 숫자가 아닌 글자를 지운 앞 128자를 `sample_hex`로 싣는다 [12].
`evtx_query`는 레코드 JSON에서 이벤트 ID, `SystemTime`, 채널을 꺼내 별도 필드로 싣는다 [6].
`hayabusa_scan`은 Hayabusa JSON에서 6개 필드를 별칭 목록으로 골라 싣고 나머지 키는 `details`에 옮긴다 [13].
`cloud_audit`은 제공자마다 정한 경로로 시각, 행위자, IP, 동작, 대상, 결과를 고르고 원래 레코드를 `raw`에 함께 싣는다 [14].
`login_accounting`은 `last` 출력 줄을 위치로 나눠 필드를 만들고 원래 줄을 `raw`에 싣는다 [15].
`mft_timeline`은 MFT 항목마다 첫 `$STANDARD_INFORMATION`과 Win32 이름 공간을 앞세워 고른 `$FILE_NAME` 하나에서 시각과 이름을 싣는다 [16].
`find_ai_signatures`는 서명마다 일치 횟수와 첫 일치의 위치, 미리보기만 골라 싣는다 [17].

`findevil-mcp`는 도구가 돌려준 Rust 구조체를 JSON으로 직렬화해 `content`의 글 블록 하나에 싣는다 [8].
`findevil-agent-mcp`는 pydantic 출력 모델을 `model_dump()`로 바꾼 뒤 키를 정렬한 JSON 글 블록 하나로 싣는다 [18].
두 서버 모두 응답에 `structuredContent`를 싣지 않는다 [7][19].

**한계.** `vol_pslist`는 숫자 열이 `u32` 범위를 넘거나 없으면 0을 싣고 문자열 열이 `N/A`나 `-`이면 값이 없는 것으로 싣는다 [11].
`mft_timeline`은 읽지 못한 속성을 건너뛰고 건너뛴 수를 응답에 싣지 않는다 [16].

### R01.03 형식 변환·건수 집계

**구현.** 이 방식은 `findevil-mcp`의 `registry_query`, `usnjrnl_query`, `zeek_summary`, `pcap_triage`, `email_parse`, `srum_parse`와 `findevil-agent-mcp`의 `find_ai_signatures`에 적용된다 [20][21][22][23][24][25][17].
`registry_query`는 값 형식마다 UTF-16 문자열, `|`로 이은 다중 문자열, 10진 수, 16진 문자열로 바꿔 `data_str`에 싣는다 [20].
`usnjrnl_query`는 사유 비트를 이름 목록 `reason_flags`로 바꾼다 [21].
`zeek_summary`는 Zeek 기록 종류마다 줄 수를 세고 많이 나온 호스트, DNS 질의, HTTP 호스트를 10개씩 싣는다 [22].
`pcap_triage`는 tshark 필드 출력을 대화, DNS 질의, HTTP 호스트, HTTP 요청으로 묶어 건수를 싣는다 [23].
`email_parse`는 메시지 머리글에서 보낸 사람, 받는 사람, 제목, 첨부 이름의 중복을 없앤 목록을 만든다 [24].
`srum_parse`는 보낸 바이트와 받은 바이트의 합계와 보낸 바이트가 많은 앱 20개를 계산해 싣는다 [25].
`find_ai_signatures`는 서명과 출처마다 일치 횟수를 세고 첫 일치의 위치와 미리보기 하나만 싣는다 [17].

**한계.** `registry_query`는 알 수 없는 값 형식을 모두 `REG_BINARY`로, `REG_DWORD_BIG_ENDIAN`을 `REG_DWORD`로 적고 원래 형식 번호를 싣지 않는다 [20].
같은 함수는 길이가 모자란 DWORD와 QWORD 값을 `0`으로 싣는다 [20].
`usnjrnl_query`는 이름을 정해 둔 15개 비트만 `reason_flags`에 싣고 원래 사유 정수를 싣지 않는다 [21].
`zeek_summary`는 파일 이름이 정해 둔 이름(`conn.log` 등)과 같을 때만 종류별 건수를 늘리고 다른 이름의 기록 줄은 `rows_seen`에만 센다 [22].
`zeek_summary`는 연결 기록의 IP 주소와 TLS 기록의 서버 이름을 같은 `top_hosts` 집계에 센다 [22].
`pcap_triage`는 출발 주소, 호스트, 메서드가 같은 HTTP 요청을 하나로 묶고 처음 본 비어 있지 않은 URI 하나만 `uri`에 싣는다 [26].

### R01.04 가공 사실·대상 표시

**구현.** 이 방식은 `findevil-mcp`의 `vol_run`, `ez_parse`, `mac_triage`, `pcap_triage`, `plaso_parse`, `bulk_extract`, `cloud_audit` 응답에 적용된다 [2][4][23][5][27][14].
`vol_run`은 실행한 플러그인 이름을 `plugin`에 싣는다 [2].
`ez_parse`는 실행한 EZ 도구를 `tool`에, `mac_triage`는 실행한 모듈을 `module`에 싣는다 [4].
`ez_parse`와 `mac_triage`는 행을 읽은 CSV 파일 이름을 `csv_files`에 싣는다 [4].
`pcap_triage`는 결과를 만든 분석기(`tshark`나 `zeek`)를 `analyzer`에 싣는다 [23].
`plaso_parse`는 실행한 plaso 파서 이름을 `parser`에 싣는다 [5].
`bulk_extract`는 실행한 `bulk_extractor`의 버전을 `engine_version`에, 스캔 범위와 실행 방식과 정렬을 적은 고정 문장을 `note`에 싣는다 [27].
같은 도구는 사건 폴더에 남긴 특성 파일마다 경로, SHA-256, 줄 수를 `staged_files`에 싣는다 [28].
`cloud_audit`은 해석한 기록 형식을 `provider`에 싣는다 [14].

서버 코드가 외부 도구 대신 결과를 만든 경우에도 그 사실을 응답에 적는다.
`plaso_parse`는 `recycle_bin_info2`에서 plaso를 실행하지 않고 서버 안의 문자열 검색으로 사건을 만든다 [29].
이 사건마다 `fallback_basis`를 `info2_path_string`으로 적고 `stderr_tail`에 대체 경로를 썼다는 문장을 싣는다 [29].
`ez_parse`는 LECmd 실행 파일이 없으면 LNK 파일 경로에 정해 둔 폴더와 낱말이 함께 있을 때만 경로 이름으로 행 하나를 만들고 `Fallback Basis`와 `Fallback Warning` 열에 그 사실을 적는다 [30][31].

그 밖의 도구 응답에는 가공에 쓴 외부 도구나 플러그인의 이름을 적는 필드가 없다 [11][12].
`findevil-agent-mcp`의 응답도 가공 사실을 적는 필드를 두지 않는다 [18].

**한계.** `ez_parse`와 `mac_triage`는 여러 CSV의 행을 한 `rows` 목록으로 합치고 행마다 어느 CSV에서 왔는지 적지 않는다 [4].

### R01.06 응답 항목 선별

**구현.** 이 방식은 `findevil-mcp`의 `disk_mount`, `disk_extract_artifacts`, `thumbcache_parse`, `email_parse`, `bulk_extract`와 `plaso_parse`의 `recycle_bin_info2` 경로에 적용된다 [32][33][34][35][36][37].
`disk_mount`는 `mmls` 출력에서 `meta`나 `unallocated`가 들어간 줄과 정해 둔 파일 시스템 이름이 없는 줄을 빼고 `partitions`에 싣는다 [32].
`disk_extract_artifacts`는 `fls` 목록에서 정해 둔 26개 분류에 맞는 경로만 꺼낸다 [33].
같은 도구는 정규 파일이 아닌 항목과 inode가 다른 파일에 다시 쓰인 삭제 항목을 뺀다 [38].
`thumbcache_parse`는 CMMM 형식에서 해시와 크기가 모두 0인 칸을 뺀다 [34].
`email_parse`는 보낸 사람, 받는 사람, 제목, 날짜, 첨부가 하나도 없는 메시지를 `messages`에서 뺀다 [35].
`bulk_extract`는 `*_histogram` 파일의 줄을 `features`에 싣지 않는다 [36].
`plaso_parse`의 `recycle_bin_info2` 경로는 `:\`가 들어 있고 정해 둔 7개 확장자로 끝나는 문자열만 사건으로 싣는다 [37].
뺀 항목은 응답에 없을 뿐이고 남은 항목의 뜻은 바뀌지 않는다.

### R01.07 응답 선별 사실·건수 표시

**구현.** 이 방식은 `disk_extract_artifacts`와 `bulk_extract`에 적용된다 [39][36].
`disk_extract_artifacts`는 inode가 다시 쓰여 뺀 삭제 항목 수를 `deleted_skipped_realloc`에, 목록에서 본 삭제 항목 수를 `deleted_entries_seen`에 싣는다 [39][38].
`bulk_extract`는 줄을 싣지 않은 histogram 파일도 `staged_files`에 파일 경로, SHA-256, 줄 수와 함께 싣는다 [36][28].

**한계.** `disk_extract_artifacts`는 분류에 맞지 않아 뺀 경로의 수와 정규 파일이 아니어서 뺀 항목의 수를 싣지 않는다 [33][38].
`disk_mount`, `thumbcache_parse`, `email_parse`, `plaso_parse`의 `recycle_bin_info2` 경로도 뺀 항목의 수나 적용한 규칙을 응답에 싣지 않는다 [32][34][35][37].
