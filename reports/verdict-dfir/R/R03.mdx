# R03 분석 상태 알림

### R03.01 구조화 status·error

**구현.** 이 방식은 두 서버의 모든 도구 호출에 적용되고 서버마다 실패를 담는 자리가 다르다 [1][2].
`findevil-mcp`는 도구 처리기가 오류를 돌려주면 `result` 대신 JSON-RPC `error` 객체로 답한다 [1].
없는 파일이나 허용 목록 밖의 값처럼 입력에서 온 오류는 `-32602`로, 외부 도구 실패와 그 밖의 오류는 `-32603`으로 보낸다 [3].
처리기가 중단되면 `catch_unwind`가 받아 `-32603`과 중단 문구로 보낸다 [4].
인자가 입력 구조체에 맞지 않으면 `parse_args`가 `-32602`를 보낸다 [5].
`findevil-mcp`는 도구 결과에 MCP 오류 결과 `isError`를 쓰지 않는다 [6].
시험에서 없는 pcap 경로는 `-32602`, 실패하는 외부 도구는 `-32603`, 모르는 인자는 `-32602`로 돌아왔고 성공 응답에는 `isError`가 없었다 [6].

`findevil-agent-mcp`는 서버 코드가 다루는 실패를 `isError`가 거짓인 응답의 `error` 객체로 보낸다 [2].
이 객체의 `kind`는 없는 도구 `unknown_tool`, pydantic 입력 검사 실패 `validation`, 처리기 예외 `handler` 가운데 하나다 [2].
MCP Python SDK 1.27.0은 입력 schema 검사에 실패한 호출과 서버 코드 밖으로 나온 예외를 `isError`가 참인 결과로 돌려준다 [7].
시험에서 필수 인자가 빠진 호출만 `isError`가 참이었고 없는 도구, pydantic 검사 실패, 처리기 예외는 `isError`가 거짓인 `error` 객체였다 [8].

`findevil-agent-mcp`의 일부 도구는 결과 안에 상태 필드를 둔다 [9][10][11].
`audit_verify`는 `ok`와 `error`를, `manifest_verify`는 `overall`과 검사마다의 참거짓 값을 싣는다 [9][10].
`verify_finding`은 `action`에 `approved`, `rejected`, `downgraded`를 싣고 재실행 오류를 `replay_error`에 싣는다 [11].
두 서버 모두 실행 중에 MCP 진행 알림을 보내지 않는다 [1][2].

**한계.** `findevil-mcp`는 오류 종류를 JSON-RPC 코드 두 개로만 나눈다 [1].
외부 도구의 시간 초과, 실행 파일 없음, 출력 해석 실패가 모두 `-32603`이고 문구로만 갈린다 [3][12].
`findevil-mcp`는 모르는 메서드와 해석할 수 없는 JSON에도 `-32602`를 쓴다 [13].
시험에서 해석할 수 없는 줄은 `id`가 `null`인 `-32602`로, `resources/list`는 모르는 메서드 `-32602`로 돌아왔다 [6].

`findevil-agent-mcp`의 서버 코드가 다룬 실패는 `isError`가 거짓이므로 `isError`만 보는 클라이언트는 성공 응답과 구별하지 못한다 [2][8].
같은 도구의 입력 오류라도 SDK의 schema 검사에서 실패하면 `isError` 참의 문장으로, pydantic 검사에서 실패하면 `error` 객체로 나간다 [7][8].

`disk_mount`는 파일 시스템을 마운트하지 못하고 EWF 컨테이너만 연결한 경우와 마운트 없이 Sleuth Kit 직접 읽기로 등록한 경우에도 `status`를 `mounted`로 싣는다 [14].
`disk_mount`를 `mode: mock`으로 부르면 서버는 마운트하지 않고 `status`를 `mounted`로 싣는다 [14].
이 차이는 `note` 문장으로만 알린다 [14].
`manifest_verify`는 서명 종류가 `stub`이나 `sigstore`이면 서명이 검증되지 않아도 다른 대조가 통과할 때 `overall`을 참으로 둔다 [15].
`manifest_verify`의 `overall`은 `entailment_ok`와 `transparency_ok`를 반영하지 않는다 [15].

### R03.02 찾지 못함과 실패 구분

**구현.** 이 방식은 `findevil-mcp`의 `registry_query`, `ausearch`, `hashset_lookup`과 외부 도구가 없을 때의 상태를 따로 싣는 도구, `findevil-agent-mcp`의 `audit_verify`, `memory_recall`에 적용된다 [16][17][18][19][9][20].
`registry_query`는 키가 없으면 오류 대신 빈 `entries`와 `key_present` 거짓을 싣는다 [16].
하이브 파일이 없으면 `-32602` 오류를 보낸다 [3].
`ausearch`는 `ausearch`가 종료 코드 1과 `<no matches>`를 내면 빈 `rows`로 답하고 다른 0이 아닌 종료는 오류로 보낸다 [17].
`hashset_lookup`은 읽은 해시 집합에 없는 해시를 `unknown`으로 싣고 집합을 읽지 못한 사실은 `sets_loaded`의 `error`에 싣는다 [18].
`pst_parse`, `srum_parse`, `bulk_extract`, `vss_list`, `vss_mount`는 외부 도구가 없으면 오류 대신 `*_available` 거짓으로 답한다 [19].
`srum_parse`는 내보낸 자료에 네트워크 사용 표가 없으면 `table_found` 거짓을 따로 싣는다 [19].
`audit_verify`는 호출 기록 파일이 없으면 `ok` 참과 0건으로 답하고 체인이 끊기면 `ok` 거짓과 `error`를 싣는다 [9].
`memory_recall`은 일치가 없으면 빈 `hits`를 싣고 도구 설명에 그 뜻을 적는다 [20].
시험에서 없는 호출 기록 파일에 `audit_verify`는 `ok` 참과 `record_count` 0을, 빈 기억 저장소에 `memory_recall`은 빈 `hits`를 돌려주었다 [8].

**한계.** 다음 도구는 실패를 결과 없음과 같은 값으로 돌려준다.
`vss_list`는 `vshadowinfo`가 0이 아닌 종료 코드로 끝나면 종료 코드와 표준 오류를 버리고 저장소가 없다는 결과를 싣는다 [21].
`vss_list`는 실행 파일이 없는 경우와 다른 실행 오류를 같은 `vshadowinfo_available` 거짓으로 싣는다 [21].
`exif_parse`는 EXIF를 읽다 난 모든 오류를 `has_exif` 거짓으로 싣는다 [22].
`disk_mount`는 `mmls` 실패를 빈 `partitions`로 싣는다 [23].
Volatility 도구, `indx_parse`, `hayabusa_scan`, `nfdump_query`, `journalctl_query`, `vel_collect`는 외부 도구가 표준 출력에 아무것도 쓰지 않고 0으로 끝나면 빈 목록을 싣는다 [24].
`hashset_lookup`은 `FINDEVIL_HASHSET_DIR`이 없으면 `sets_loaded`를 비우고 모든 해시를 `unknown`으로 싣는다 [18].
`yara_scan`은 검사하지 못한 파일을 `scan_errors` 수로만 싣는다 [25].
`disk_extract_artifacts`는 삭제되지 않은 파일을 꺼내지 못하면 그 파일을 응답에서 빼고 실패 수를 싣지 않는다 [26].
`vss_mount`는 `vshadowmount`가 0이 아닌 종료로 끝나면 저장소가 없을 때와 같은 `unavailable` 상태를 싣는다 [27].
`registry_query`의 `parse_errors`는 늘 0으로 실린다 [28].

### R03.03 입력별 성공·실패·생략 목록

**구현.** 이 방식은 `findevil-mcp`의 `hashset_lookup`과 `findevil-agent-mcp`의 `manifest_verify`, `find_ai_signatures`에 적용된다 [18][10][29].
`hashset_lookup`은 읽으려 한 해시 집합마다 이름, 형식, 판정, 경로, 실패 사유를 `sets_loaded`에 싣는다 [18].
`manifest_verify`는 호출 기록 체인, Merkle 루트, 리프 수, 서명, 함의 검사, 투명성 기록마다 참거짓 값과 설명을 싣는다 [10].
`find_ai_signatures`는 읽지 못한 경로마다 경로와 사유를 `read_errors`에 싣는다 [29].
시험에서 없는 파일을 함께 준 `find_ai_signatures` 호출은 그 경로를 `read_errors`에 싣고 다른 파일의 일치를 돌려주었다 [8].

**한계.** `find_ai_signatures`는 실패한 경로만 싣고 검사한 경로는 `sources_scanned` 수로만 싣는다 [29].
`truncated`가 참일 때 검사하지 않은 경로도 목록에 싣지 않는다 [29].
`hashset_lookup`은 집합 하나를 읽다 중간에 실패하면 실패 사유만 싣고 어느 해시까지 대조했는지 싣지 않는다 [18].

### R03.04 시간 초과·부분 완료 표시

**구현.** 이 방식은 `findevil-agent-mcp`의 `judge_findings`와 `findevil-mcp`의 `thumbcache_parse`, `hashset_lookup`에 적용된다 [30][31][18].
`judge_findings`는 병합이 `budget_seconds`를 넘으면 빈 `merged`와 함께 `budget_exceeded` 참과 `budget_detail`을 싣는다 [30].
`thumbcache_parse`는 레코드가 파일 끝을 넘거나 검사 상한에 닿아 일부만 읽은 사실을 `parse_errors`에 싣는다 [31].
`hashset_lookup`은 집합을 읽다 실패해도 그 전까지 찾은 일치를 싣고 그 집합의 `error`에 실패를 적는다 [18].

**한계.** 외부 도구의 시간 초과는 결과 필드가 아니라 JSON-RPC 오류 문구로만 알린다.
`vol_run`과 `plaso_parse`는 시간 제한(기본 1,800초와 3,600초)이 지나면 하위 프로세스를 끝내고 `-32603` 오류와 시간 제한을 넘었다는 문구를 보낸다 [12].
이때 그 전까지 나온 행은 응답에 실리지 않는다 [12].
나머지 외부 도구 실행 경로에는 시간 제한이 없다 [32].
`pst_parse`는 내보낸 폴더 항목 500,000개에서 읽기를 멈추고 그때까지 읽은 메시지를 표시 없이 싣는다 [33].
