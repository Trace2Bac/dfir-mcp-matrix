# P01 분석 방법 적합성 확인

### P01.01 이름·확장자 판별

**구현.** 이 방식은 `findevil-mcp`의 디스크 이미지 도구 `case_open`·`disk_mount`·`disk_extract_artifacts`와 `yara_scan`·`zeek_summary`에 적용된다 [1][2][3].
`is_first_ewf_segment`는 확장자의 글자 부분이 `E`·`Ex`이고 숫자가 1이면 분할 EWF의 첫 조각으로 본다 [1].
`disk_mount`는 자동 모드에서 이 판별로 EWF 경로(`ewfmount`와 `ntfs3` loop 마운트)와 raw 경로(`mount -o ro,loop`)를 고른다 [2].
`case_open`과 `disk_extract_artifacts`도 같은 판별로 옆 조각을 모아 해시하거나 Sleuth Kit에 넘긴다 [1][4].
`disk_extract_artifacts`는 이미지 안 파일의 경로와 이름을 `classify_artifact_path`로 `mft`, `registry`, `evtx`, `prefetch` 같은 종류로 나누고 종류마다 꺼낼지 정한다 [3].
`classify_artifact_path`는 Windows 고유 이름을 먼저 보고 Linux 경로, macOS 경로, Windows 일반 경로 차례로 본다 [3].
`yara_scan`은 규칙 폴더에서 확장자가 `.yar`·`.yara`·`.yarx`인 파일만 규칙으로 모은다 [5].
`zeek_summary`는 폴더에서 확장자가 `.log`인 파일만 Zeek 로그로 모은다 [6].

`findevil-agent-mcp`에는 증거 형식이나 OS를 판별하는 도구가 없다 [7].
같은 저장소의 `findevil_agent/playbook.py`는 확장자와 이름으로 증거 유형과 아티팩트 종류를 정하는 `detect_evidence_type`·`classify_artifact_path`를 두고 사용자 CLI `scripts/find_evil_auto.py`가 이 모듈을 불러 쓴다 [8][9].
`findevil-agent-mcp` 프로세스를 시작한 뒤 불러온 `findevil_agent` 하위 모듈 30개에 `findevil_agent.playbook`은 없었다 [10].

**한계.** `is_first_ewf_segment`는 확장자만 보고 파일 내용이 EWF인지 확인하지 않는다 [1].
확장자가 `.E01`인 raw 이미지는 EWF 경로로 처리되고 확장자가 `.s01`·`.L01`인 분할 이미지는 raw 경로로 처리된다 [1][2].
`classify_artifact_path`는 이름이 `system`·`software`·`sam` 같은 파일을 경로와 관계없이 레지스트리 하이브로 분류한다 [3].
`yara_scan`은 규칙 경로에 파일 하나를 주면 확장자를 보지 않는다 [5].

### P01.02 메타데이터 조회

**구현.** 이 방식은 `findevil-mcp`의 `disk_mount`·`disk_extract_artifacts`에 적용된다 [11][12].
두 도구는 이미지에 `mmls`를 실행하고 파티션 표에서 대소문자를 가리지 않고 `ntfs`, `fat`, `linux`, `hfs`, `apfs`가 들어간 행만 파일 시스템 파티션으로 본다 [12].
분석 대상 파티션은 그 가운데 길이가 가장 긴 파티션으로 정한다 [12].
`disk_mount`는 이 파티션의 시작 위치로 loop 마운트를 다시 시도하고 응답의 `partitions`에 파일 시스템 파티션 전체를 싣는다 [11][13].
`disk_extract_artifacts`는 같은 시작 위치를 `fls`·`icat`의 `-o` 인자로 넘긴다 [14].
파티션 표 행 3개를 내는 시험용 `mmls`에서 `disk_mount`는 가장 긴 파티션의 시작 위치로 마운트했고 `fls`·`icat`도 그 위치를 받았다 [15].

**한계.** 다른 파일 시스템 파티션은 `partitions`에만 실리고 꺼내기 대상이 되지 않는다 [12][14].
`mmls`를 실행하지 못하거나 파티션 표가 없으면 시작 위치 0으로 읽는다 [12][14].
Sleuth Kit 4.15.0의 `mmls`는 DOS 파티션 표의 스왑 파티션과 LVM 파티션 설명에도 `Linux`를 넣으므로 두 도구는 이 행도 파일 시스템 파티션으로 본다 [12][16].
이 행이 가장 길면 두 도구는 그 시작 위치로 마운트하고 파일을 꺼낸다 [12].
파티션의 파일 시스템 종류나 OS를 보고 꺼낼 아티팩트 종류를 바꾸지는 않는다 [3].

### P01.03 내용·헤더 검사

**구현.** 이 방식은 `findevil-mcp`의 `thumbcache_parse`·`bits_parse`·`browser_history`·`hashset_lookup`에 적용된다 [17][18][19][20].
`thumbcache_parse`는 파일 앞 바이트가 OLE 복합 파일 서명이면 XP `Thumbs.db` 해석 경로를, `CMMM`이면 Vista 이후 해석 경로를 고른다 [17].
`bits_parse`는 5~8번째 바이트가 ESE 서명이면 문자열을 찾지 않고 형식만 알리는 경로로 간다 [18].
`browser_history`는 SQLite 파일에 `urls`·`visits` 표가 있으면 Chrome으로, `moz_places` 표가 있으면 Firefox로 보고 각 형식의 질의를 실행한다 [19].
두 구조가 모두 없으면 `UnknownSchema` 오류로 끝난다 [19].
참조 해시 목록을 받는 `hashset_lookup`은 파일 앞 16바이트가 SQLite 서명이면 SQLite 목록으로, 아니면 글 목록으로 읽는다 [20].

볼륨 섀도 복사본, 메모리, 이벤트 로그 도구는 받은 경로의 형식을 서버가 따로 확인하지 않고 외부 도구나 해석 라이브러리에 넘긴다.
`vol_run`은 허용 목록에 Windows, Linux, macOS 플러그인을 함께 두고 메모리 이미지의 OS와 고른 플러그인을 대조하지 않는다 [21].
`findevil-agent-mcp`의 도구는 발견사항, 호출 기록, 기억 저장소를 다루며 증거 형식을 확인하지 않는다 [7].

fn first_segment_extension(path: &Path) -> Option<SegmentExtension> {

fn parse_segment_extension(ext: &str) -> Option<SegmentExtension> {
    let digit_start = ext.find(|c: char| c.is_ascii_digit())?;
    let (prefix, digits) = ext.split_at(digit_start);
    if prefix.is_empty() || digits.is_empty() || !digits.chars().all(|c| c.is_ascii_digit()) {
        return None;
    }
    let prefix_lower = prefix.to_ascii_lowercase();
    if prefix_lower != "e" && prefix_lower != "ex" {
        return None;
    }
    let number = digits.parse::<u32>().ok()?;
    if number == 0 {
        return None;
    }
    Some(SegmentExtension {
        prefix: prefix.to_string(),
        number,
        width: digits.len(),
    })
}

fn detect_container(path: &Path) -> Result<Container, String> {
    let mut file = std::fs::File::open(path).map_err(|e| format!("open failed: {e}"))?;
    let mut magic = [0u8; 16];
    match file.read_exact(&mut magic) {
        Ok(()) if &magic == SQLITE_MAGIC => Ok(Container::Sqlite),
        Ok(()) => Ok(Container::Text),
        Err(e) if e.kind() == std::io::ErrorKind::UnexpectedEof => Ok(Container::Text),
        Err(e) => Err(format!("read failed: {e}")),
    }
}
