# P04 조사 단위 관리

### P04.01 사건 시작 시 ID 확정

**구현.** 이 방식은 `findevil-mcp`의 `case_open`에 적용된다 [1].
`case_open`은 호출마다 UUID4를 새로 만들어 사건 ID로 정하고 `FINDEVIL_HOME/cases/<사건 ID>/` 폴더를 만든다 [1].
`FINDEVIL_HOME`이 없으면 `$HOME/.findevil`을 쓰고 저장소의 시작 스크립트는 이 값을 실행 상태 폴더 아래 `findevil`로 정한다 [2][3].
응답은 사건 ID와 사건 폴더 경로를 돌려주고 도구 설명은 이후 모든 호출에 이 ID를 넘기라고 적는다 [1][4].
같은 파일로 `case_open`을 두 번 부르자 사건 ID와 사건 폴더가 둘 생겼다 [5].

`findevil-agent-mcp`는 사건을 만들거나 열지 않는다 [6].
이 서버의 도구는 호출 기록 파일, 기억 DB, 사건 폴더를 모델이 준 경로로 받는다 [7][8].

### P04.02 호출마다 사건 ID 전달·검사

**구현.** 이 방식은 `findevil-mcp`에서 사건 폴더를 쓰는 `disk_mount`·`disk_extract_artifacts`·`disk_unmount`·`bulk_extract`·`pst_parse`·`srum_parse`·`vss_mount`에 적용된다 [9][10][11].
이 도구들은 `case_id`가 영문자, 숫자, `-`, `_`로만 된 값인지 `is_valid_case_id`로 검사한다 [12].
그다음 `FINDEVIL_HOME/cases/<case_id>` 폴더가 있는지 보고 없으면 사건을 찾지 못했다는 오류로 거부한다 [9][10][11].
`disk_extract_artifacts`·`disk_unmount`는 받은 `mount_id`를 그 사건 폴더의 `session_resources.json`에서만 찾는다 [13].
등록하지 않은 사건 ID와 경로 구분자가 들어간 사건 ID는 `disk_mount`에서 거부되었다 [5].
사건 A의 `mount_id`를 사건 B의 ID와 함께 `disk_unmount`에 주자 `mount resource not found`로 거부되었다 [5].

**한계.** 서버는 지금 조사하는 사건을 따로 두지 않으므로 `case_open`으로 만든 다른 사건의 ID도 그 사건 폴더가 있으면 통과한다 [9].
`bulk_extract`·`pst_parse`·`srum_parse`는 외부 도구를 먼저 찾고 찾지 못하면 사건 폴더를 확인하기 전에 빈 결과를 돌려준다 [14].
그래서 외부 도구가 없는 실행 환경에서는 등록하지 않은 사건 ID로도 성공 응답이 돌아온다 [14].
`case_id`를 받는 나머지 분석 도구는 그 값을 쓰지 않고 사건 폴더도 확인하지 않는다 [15].
등록하지 않은 사건 ID로 `zeek_summary`를 부르자 성공 응답이 돌아왔다 [5].
`disk_mount`는 받은 이미지 경로가 그 사건의 `case.json`에 등록한 이미지인지 대조하지 않는다 [16].

### P04.03 폴더·DB·manifest에 사건 ID 연결

**구현.** 이 방식은 `findevil-mcp`의 사건 폴더와 `findevil-agent-mcp`의 `manifest_finalize`·`memory_remember`에 적용된다 [1][17][18].
`case_open`은 사건 ID를 폴더 이름으로 쓰고 같은 폴더의 `case.json`의 `id`에 적는다 [1][19].
`disk_mount`·`disk_extract_artifacts`·`disk_unmount`의 응답은 받은 `case_id`를 그대로 싣는다 [20].
`manifest_finalize`는 모델이 준 `case_id`를 서명할 manifest 본문에 넣는다 [17].
`memory_remember`는 모델이 준 `case_id`를 기억 DB의 행과 사건 표 `meta`에 적는다 [18][21].

**한계.** `manifest_finalize`와 `memory_remember`의 `case_id`는 형식과 존재를 검사하지 않는 문자열이다 [17][18].
`memory_remember`에 `../anything`을 `case_id`로 주자 그대로 저장되었다 [22].
`findevil-agent-mcp`의 호출 기록 파일 경로는 사건 ID와 관계없이 모델이 정한다 [7].

### P04.04 사건별 폴더·DB 분리

**구현.** 이 방식은 `findevil-mcp`의 사건 폴더에 적용된다 [1].
`case.json`, 마운트 기록 `session_resources.json`, 마운트 폴더 `mounts/`, `disk_extract_artifacts`·`pst_parse`·`bulk_extract`가 꺼낸 파일을 두는 `extracted/`, `srum_parse`의 작업 폴더 `_xartifact/`가 모두 사건 폴더 아래에 생긴다 [1][13][23][24][25].
`case_open`과 마운트·꺼내기를 실행한 뒤 이 파일과 폴더는 사건마다 다른 폴더 아래에 있었다 [5][26].

**한계.** `disk_mount`·`vss_mount`는 모델이 `mount_point`를 주면 사건 폴더 밖에 마운트 폴더를 만든다 [27].
`mode: mock` 마운트에서 `mount_point`로 준 사건 폴더 밖 경로가 그대로 마운트 기록에 남았다 [26].
`ez_parse`·`mac_triage`·`pcap_triage`·`suricata_eve`·`hayabusa_scan`·`plaso_parse`는 사건과 관계없이 실행 환경의 임시 폴더에 작업 파일을 쓴다 [28].
주입 문구를 정리한 횟수를 남기는 `injection_alerts.jsonl`은 두 서버 모두 `FINDEVIL_HOME` 바로 아래 파일 하나에 쌓는다 [29][30].
`findevil-agent-mcp`의 기억 DB는 모델이 준 `store_path`의 파일 하나에 여러 사건의 행을 함께 두고 사건마다 나누지 않는다 [8][21].

### P04.13 사건 사이 공유 기억 저장소

**구현.** 이 방식은 `findevil-agent-mcp`의 `memory_remember`와 `memory_recall`에 적용된다 [8][31].
두 도구는 모델이 준 `store_path`의 SQLite 파일을 기억 DB로 쓴다 [8][31].
`memory_remember`는 받은 `case_id`, `kind`, `key`, `value`, `sha256`을 FTS5 표 `memories`의 한 행으로 적는다 [21].
이 표는 사건 ID를 열 하나로 두고 여러 사건의 행을 함께 담는다 [21].
`memory_recall`은 사건 ID를 인자로 받지 않는다 [31].
`memory_recall`은 `query`로 표 전체에서 행을 찾고 `kind`로만 거른다 [32].
찾은 행마다 그 행을 남긴 사건의 `case_id`를 함께 돌려준다 [33].
도구 설명은 앞선 사건에서 본 IOC, 해시, TTP인지 확인하는 데 이 도구를 쓰라고 적는다 [34].
사건 `case-A`로 기억에 적은 값을 다른 사건의 호출 기록 경로를 준 `memory_recall`이 그대로 돌려주었다 [22].
사용자 CLI `scripts/find_evil_auto.py`는 `CONFIRMED` 발견사항마다 설명을 `kind`가 `finding_summary`인 행으로 `memory_remember`에 넘긴다 [35].

```rust
fn resolve_findevil_home() -> Result<PathBuf, CaseOpenError> {
    if let Ok(v) = std::env::var("FINDEVIL_HOME") {
        if !v.is_empty() {
            return Ok(PathBuf::from(v));
        }
    }
    // Unix-ish HOME first; fall back to Windows USERPROFILE.
    if let Ok(h) = std::env::var("HOME") {
        if !h.is_empty() {
            return Ok(PathBuf::from(h).join(".findevil"));
        }
    }
    if let Ok(p) = std::env::var("USERPROFILE") {
        if !p.is_empty() {
            return Ok(PathBuf::from(p).join(".findevil"));
        }
    }
    Err(CaseOpenError::NoFindEvilHome)
}
```

```rust
/// Whether a `case_id` is safe to use as a single path component.
///
/// True iff non-empty and every character is ASCII alphanumeric, `-`, or
/// `_`. Excludes `/`, `\`, `.` (so `.`/`..` traversal), and NUL.
#[must_use]
pub fn is_valid_case_id(case_id: &str) -> bool {
    !case_id.is_empty()
        && case_id
            .chars()
            .all(|c| c.is_ascii_alphanumeric() || c == '-' || c == '_')
}
```
