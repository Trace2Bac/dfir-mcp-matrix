# P03 조사 진척 판단

### P03.03 미조사 범위·생략 사유 보고

**구현.** 이 방식은 `findevil-mcp`의 `disk_mount`·`disk_extract_artifacts`, 외부 도구가 없을 때 빈 결과를 돌려주는 `srum_parse`·`pst_parse`·`bulk_extract`·`vss_list`·`vss_mount`, 해석하지 못한 레코드나 파일을 응답에 싣는 해석 도구와 `findevil-agent-mcp`의 `find_ai_signatures`에 적용된다 [1][2][3][4][5].
`disk_mount`는 파티션 표의 파일 시스템 파티션을 모두 `partitions`에 싣고 마운트한 파티션은 `note`와 `command`로 알린다 [1][6].
`disk_extract_artifacts`는 크기 상한 `max_artifact_bytes`를 넘어 꺼내지 않은 파일 수를 `artifacts_skipped_oversize`에 싣는다 [2].
삭제된 항목은 본 수 `deleted_entries_seen`, inode가 다른 파일에 다시 쓰여 건너뛴 수 `deleted_skipped_realloc`, 내용을 읽지 못한 수 `deleted_recovery_failed`로 나눠 싣는다 [2][7].
시험용 `fls`가 삭제 항목 2개를 내자 응답은 `deleted_entries_seen` 2, `deleted_skipped_realloc` 1, `deleted_recovery_failed` 1을 실었다 [8].
`srum_parse`·`pst_parse`·`bulk_extract`는 외부 도구를 찾지 못하면 오류 없이 `esedbexport_available`·`pffexport_available`·`bulk_extractor_available`을 거짓으로 둔 빈 결과를 돌려준다 [3].
`vss_list`·`vss_mount`도 같은 경우 `vshadowinfo_available`·`vshadowmount_available`을 거짓으로 둔다 [9].
`evtx_query`·`mft_timeline`·`usnjrnl_query`·`sysmon_network_query`·`zeek_summary`는 해석하지 못해 뺀 레코드 수를 `parse_errors`에 싣고 `yara_scan`은 검사하지 못한 파일 수를 `scan_errors`에 싣는다 [4].
`thumbcache_parse`는 해석을 멈추거나 건너뛴 사유를 `parse_errors` 목록에 싣는다 [10].
`findevil-agent-mcp`의 `find_ai_signatures`는 읽지 못해 건너뛴 경로와 크기 상한을 넘어 앞부분만 읽은 경로를 `read_errors`에, 결과 수가 상한에 닿았는지를 `truncated`에 싣는다 [5].
`registry_query`의 응답에도 `parse_errors`가 있지만 이 값을 늘리는 코드가 없어 늘 0이다 [11].

이 값은 그 호출 한 번의 결과다.
두 서버에는 대상 유형마다 해야 할 작업 목록, 조사 단계, 완료 조건이 없고 앞선 호출을 모아 남은 작업을 알리는 도구도 없다.
`findevil-agent-mcp`의 `accuracy_compare`는 끝난 사건의 `verdict.json`을 정답 파일과 대조해 점수를 돌려주는 도구이고 조사 중의 진척을 다루지 않는다 [12].

사용자 CLI `scripts/find_evil_auto.py`는 아티팩트 종류마다 시도, 해석, 실패, 지원하지 않음, 주어지지 않음 상태를 모은 `coverage_manifest`를 만든다 [13].
이 집계는 CLI가 자기 호출 목록으로 하므로 다른 MCP 클라이언트로 붙으면 만들어지지 않는다 [13].

**한계.** `disk_extract_artifacts`는 꺼낼 개수 상한 `limit`에 닿아 고르지 않은 후보 수를 응답에 싣지 않는다 [14].
상한 4로 실행하자 꺼낸 3개와 크기 상한으로 건너뛴 1개만 응답에 실리고 고르지 않은 Prefetch 파일 3개, 레지스트리 트랜잭션 로그, 이벤트 로그 1개는 응답에 없었다 [15].
삭제되지 않은 파일의 `icat`이 실패하면 그 파일을 결과에서 빼고 따로 세지 않는다 [7].
시험용 `icat`이 실패하게 한 `SOFTWARE` 하이브는 응답의 어느 수에도 들어가지 않았다 [8].
`artifacts_seen`은 이름과 달리 꺼낸 파일 수와 같다 [2].
`disk_extract_artifacts`는 `partitions`에 실린 파티션 가운데 가장 긴 파티션만 읽고 나머지를 꺼내지 않았다는 사실을 응답에 적지 않는다 [16].
`evtx_query`는 `limit`에 닿으면 읽기를 멈추고 남은 레코드가 있다는 사실을 싣지 않는다 [17].
`find_ai_signatures`는 결과 수가 상한에 닿으면 남은 경로를 읽지 않고 그 경로를 따로 싣지 않는다 [5].

### P03.04 모델이 적은 진행 기록 보관

**구현.** 이 방식은 `findevil-agent-mcp`의 `audit_append`에 적용된다 [18].
`audit_append`는 모델이 준 종류 `kind`와 내용 `payload`를 해시 체인 JSONL 파일의 한 줄로 덧붙인다 [18][19].
도구 설명은 도구 호출과 함께 계획 변경과 분석가 결정을 적으라고 하고 `plan_proposed`·`agent_message`를 예로 든다 [20].
`kind`와 `payload`에는 형식 제한이 없어 모델이 마친 작업이나 확인하지 못한 범위를 문장으로 적을 수 있다 [18].
`plan_proposed`와 `agent_message` 두 줄을 적고 서버를 다시 시작해 한 줄을 더 적자 파일에 세 줄이 차례대로 남았다 [21].
저장 위치는 모델이 준 경로 `path`이고 도구 설명은 절대 경로를 주라고 적지만 서버는 이를 검사하지 않는다 [18].

**한계.** 서버는 이 기록을 다시 읽어 수행한 작업이나 남은 작업으로 돌려주지 않는다.
`audit_verify`는 해시 체인을 검증하고 줄 수만 돌려준다 [22].
기록한 작업이 실제 도구 호출과 맞는지 서버는 대조하지 않는다 [18].

```python
    def append(self, kind: str, payload: dict[str, Any], *, ts: str | None = None) -> AuditRecord:
        """Append one record. Thread-safe. fsyncs before returning."""
        with self._lock:
            record = AuditRecord(
                seq=self._next_seq,
                ts=ts or _utc_iso(),
                kind=kind,
                prev_hash=self._last_hash,
                payload=payload,
            )
            line = canonicalize_json(record.to_canonical_dict())
            self.path.parent.mkdir(parents=True, exist_ok=True)
            with self.path.open("ab") as f:
                f.write(line + b"\n")
                f.flush()
                os.fsync(f.fileno())
            self._last_hash = hash_line(line)
            self._next_seq += 1
            return record
```
