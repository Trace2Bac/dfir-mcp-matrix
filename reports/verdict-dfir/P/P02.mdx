# P02 다음 작업 결정

### P02.02 규칙·조사 상태로 추천

**구현.** 이 방식은 `findevil-mcp`의 `srum_parse`·`pst_parse`가 사건 폴더를 찾지 못했을 때의 오류 응답과 `findevil-agent-mcp`의 `correlate_findings` 응답에 적용된다 [1][2][3].
두 도구는 받은 `case_id`의 사건 폴더가 `FINDEVIL_HOME/cases` 아래에 없으면 `case_open`을 먼저 부르라는 문구를 오류에 싣는다 [1][2].
서버는 이 오류를 JSON-RPC 오류 코드 `-32602`로 돌려준다 [4].
등록하지 않은 사건 ID로 `srum_parse`를 부르자 `(run case_open first)`가 붙은 오류가 돌아왔다 [5].
이 안내는 오류 문자열이고 서버가 다음 호출을 대신 고르거나 안내를 따르지 않은 호출을 막지는 않는다.
`correlate_findings`는 검사 규칙을 채우지 못해 등급을 낮춘 발견사항마다 가장 가까운 조합을 채우려면 더할 아티팩트 분류를 `missing_classes`에 싣는다 [3][6].
이 값은 더할 자료의 분류이고 부를 도구는 정하지 않는다 [3].

같은 사건 폴더 확인을 하는 `disk_mount`·`disk_extract_artifacts`·`disk_unmount`·`bulk_extract`·`vss_mount`는 사건을 찾지 못했다는 사실만 알리고 다음 작업을 적지 않는다 [7][8].
두 서버 모두 MCP 리소스, 프롬프트, 초기화 지침을 두지 않는다.
도구 설명의 "Use AFTER case_open", "FIRST tool to call" 같은 순서 문구는 도구 하나의 설명에 적힌 안내다 [9].
`findevil-mcp`의 분석 도구는 결과에 따라 다음에 부를 도구를 응답에 싣지 않는다 [10].
`findevil-agent-mcp`의 `detect_contradictions`는 다른 흔적이 뒷받침하지 않는 발견사항을 빠진 대상(`missing`) 문구와 함께 단서로 싣지만 부를 도구나 작업은 정하지 않는다 [11].

조사 절차와 도구 차례는 사용자 CLI `scripts/find_evil_auto.py`가 정한다 [12].
이 CLI는 LLM 없이 증거 유형을 판별하고 `investigate_inventory`에 정한 증거 종류 차례대로 두 서버의 도구를 MCP 클라이언트로 부른다 [13].
CLI의 머리 설명은 유형별 playbook 도구 차례를 실행한다고 적는다 [12].
`findevil_agent/playbook.py`의 유형별 도구 차례 `TOOL_SEQUENCES`는 이 CLI도 두 서버도 불러 쓰지 않는다 [14][15][16].
`investigate_inventory`의 차례는 사용자 CLI 코드에 있으므로 다른 MCP 클라이언트로 붙으면 적용되지 않는다 [13].

### P02.04 서버 코드에 고정한 분석 절차

**구현.** 이 방식은 `findevil-mcp`의 `disk_mount` 자동 모드와 `disk_extract_artifacts`에 적용된다 [17][18][19].
`disk_mount`는 EWF 이미지이면 `ewfmount`로 연 뒤 시작 위치 0과 `mmls`로 고른 파티션 위치 차례로 `ntfs3` 읽기 전용 loop 마운트를 시도한다 [17].
`disk_mount`는 raw 이미지이면 `ro,loop` 마운트가 실패할 때 `mmls`로 고른 파티션 위치를 붙여 다시 마운트한다 [18].
`disk_extract_artifacts`는 `mmls`로 파티션 위치를 정하고 `fls`로 파일 목록을 읽어 종류를 나눈 뒤 종류마다 돌아가며 고른 파일을 `icat`으로 꺼내고 건너뛴 수와 함께 돌려준다 [19].
모델은 이미지 경로, 마운트 위치, 꺼낼 종류, 개수 상한, 크기 상한, 삭제 항목 복구 여부만 고르고 단계와 그 차례는 서버 코드가 정한다 [17][19].

```python
def _evaluate(
    present: frozenset[str], alternatives: tuple[_Alternative, ...]
) -> tuple[bool, tuple[str, ...]]:
    """Return (satisfied, missing_classes).

    A gate holds when ANY alternative has every slot satisfied. When none holds,
    ``missing_classes`` describes the unsatisfied slots of the CLOSEST (fewest
    missing) alternative — deterministic: ties break toward the earlier-listed
    alternative.
    """
    best_missing: list[_Slot] | None = None
    for alt in alternatives:
        missing = [slot for slot in alt if not any(c in present for c in slot)]
        if not missing:
            return True, ()
        if best_missing is None or len(missing) < len(best_missing):
            best_missing = missing
    return False, tuple("|".join(slot) for slot in (best_missing or ()))
```
