# P05 사건 자료 정리

### P05.03 자동 정리

**구현.** 이 방식은 `findevil-mcp`의 `ez_parse`·`mac_triage`·`pcap_triage`·`suricata_eve`·`hayabusa_scan`·`plaso_parse`·`srum_parse`·`pst_parse`가 호출마다 만드는 작업 파일과 작업 폴더에 적용된다 [1][2][3][4][5][6][7][8].
`ez_parse`·`mac_triage`·`suricata_eve`는 실행 환경의 임시 폴더에 호출마다 출력 폴더를 만들고 외부 도구의 CSV나 `eve.json`을 읽은 뒤 폴더째 지운다 [1][2][4].
`pcap_triage`는 Zeek로 분석할 때 만든 임시 폴더를 요약을 마친 뒤 지운다 [3].
`hayabusa_scan`은 임시 폴더에 쓴 JSON 결과 파일을 읽은 뒤 지우고 `plaso_parse`는 저장 파일, 결과 파일, 로그 파일 4개를 지운다 [5][6].
`srum_parse`는 사건 폴더 아래 `_xartifact/srum-<pid>-<시각>`에 `esedbexport` 결과를 두고 해석을 마치면 성공과 실패 모두 그 폴더를 지운다 [7].
`pst_parse`는 사건 폴더 아래 `extracted/pst/pst-export-<UUID>`에 `pffexport` 결과를 두고 외부 도구 실행이 실패할 때만 그 폴더를 지운다 [8].
시험용 `esedbexport`·`pffexport`로 실행하자 `_xartifact` 아래 작업 폴더는 사라졌고 `pst-export-<UUID>` 폴더와 그 안의 내보낸 파일은 남았다 [9].
지운 사실은 응답이나 기록에 남지 않는다 [1][7].

사건 자료를 지우거나 초기화하는 MCP 도구는 두 서버 모두 없다.
`disk_unmount`는 마운트 기록의 상태를 `unmounted`로 바꾸고 마운트 폴더와 기록 항목은 지우지 않는다 [10].
`findevil-agent-mcp`의 호출 기록, 기억 DB, manifest 파일을 지우는 코드는 없다 [11].

같은 저장소의 사용자 CLI `scripts/verdict`는 끝날 때 `verdict.json`이 없는 자기 실행 폴더를 지운다 [12].
이 폴더는 CLI가 사건마다 저장소의 `tmp/auto-runs` 아래에 만든 표시 파일이 있는 폴더이고 서버의 `FINDEVIL_HOME/cases`와는 다르다 [12][13].
`--sift` 실행은 SIFT 가상 머신에 복사한 증거 사본 폴더를 끝날 때 지우고 `--keep-sift-staging`을 주면 남긴다 [14][15].
이 정리는 사용자 CLI가 하므로 서버를 다른 MCP 클라이언트로 부르면 일어나지 않는다.

**한계.** `ez_parse`·`mac_triage`는 외부 도구를 실행하지 못하면 출력 폴더를 지우지 않고 오류를 돌려준다 [1][2].
실행 권한이 없는 시험용 `AmcacheParser`로 `ez_parse`를 부르자 오류가 돌아왔고 임시 폴더에 `ez-amcacheparser-…` 폴더가 남았다 [16].
`pcap_triage`도 Zeek를 시작하지 못하거나 요약이 실패하면 임시 폴더를 지우지 않는다 [3].
`hayabusa_scan`은 결과 파일을 읽지 못하면 지우지 않고 오류를 돌려준다 [5].
지우기에 실패해도 알리지 않는다 [1][7].

### P05.05 원본 증거를 삭제 대상에서 제외

**구현.** 이 방식은 위의 자동 정리에 적용된다 [1][7].
지우는 대상은 그 호출에서 서버가 이름을 지어 만든 임시 폴더나 파일, 사건 폴더 아래 작업 폴더다 [1][2][3][4][5][6][7][8].
증거 경로는 외부 도구의 입력 인자로만 쓰이고 지우는 대상에 포함되지 않는다 [7][8].
작업 폴더를 지운 뒤 증거 폴더의 파일 목록은 부르기 전과 같았다 [9].
