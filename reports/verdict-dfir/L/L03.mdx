# L03 기록 실패 처리

### L03.01 실행 후 응답 차단

**구현.** 이 방식은 `findevil-agent-mcp`의 `memory_remember`, `memory_recall`, `accuracy_compare`, `pool_handoff`, `expert_miss_capture`가 해시 체인 항목을 쓰는 호출에 적용된다 [1][2][3][4][5].
`AuditLog.append`는 파일을 열고 쓰고 `fsync`하는 동안 난 예외를 처리하지 않는다 [6].
`AuditLog`는 만들어질 때 기존 파일의 마지막 줄이 JSON이 아니거나 줄 수와 마지막 `seq`가 맞지 않으면 `AuditLogError`를 올린다 [7].
도구 본문도 이 예외를 처리하지 않는다 [1][2][3][4][5].
그래서 예외는 `call_tool`까지 올라가고 `call_tool`은 도구 결과 대신 `kind`가 `handler`인 오류 결과를 돌려주며 표준 오류에 항목을 쓴다 [8].

`memory_remember`, `memory_recall`, `accuracy_compare`는 실행을 마친 뒤 항목을 쓴다 [1][2][3].
`pool_handoff`는 항목을 쓰는 일이 곧 실행이다 [4].
`expert_miss_capture`도 항목을 쓰는 일이 곧 기록 도구의 실행이다 [5].
`audit_log_path`에 폴더 경로를 준 `memory_remember`는 `IsADirectoryError`를 담은 오류 결과를 받았다 [9].
중간 줄 하나를 지운 기록 파일로 `audit_append`를 부르자 `seq-count mismatch`를 담은 오류 결과를 받았고 파일에 줄이 더해지지 않았다 [10].
이 오류 결과는 `isError`가 거짓인 보통 결과이고 글이 `error` 객체다 [8][9].
엔진 `scripts/find_evil_auto.py`의 MCP 클라이언트는 이 모양의 결과를 따로 `_error`로 바꿔 처리한다 [11].

**한계.** 항목을 쓰기 전에 실행을 마친 도구는 결과를 돌려주지 않아도 실행한 효과가 남는다.
`memory_remember`는 기억 저장소에 행을 쓴 뒤 항목을 쓰므로 항목 쓰기가 실패해도 그 행은 남는다 [1].
`audit_log_path`에 폴더 경로를 주어 오류 결과를 받은 `memory_remember` 호출 뒤에 같은 키로 `memory_recall`을 부르자 그 행이 찾아졌다 [9].

### L03.03 알림 없이 계속

**구현.** 이 방식은 두 서버가 `injection_alerts.jsonl`에 줄을 쓰는 호출에 적용된다 [12][13].
`findevil-mcp`의 `append_record`는 폴더를 만들거나 파일을 열지 못하면 아무것도 하지 않고 돌아가고 쓰기 결과도 버린다 [12].
`findevil-agent-mcp`의 `record_neutralization`은 쓰기에서 `OSError`가 나면 `None`을 돌려준다 [13].
이 함수를 부르는 `_to_text_content`는 돌려받은 값을 쓰지 않는다 [14].
두 경로 모두 응답과 서버 로그에 쓰기 실패를 남기지 않고 결과를 그대로 돌려준다 [12][13][14].
`FINDEVIL_INJECTION_LEDGER`에 폴더 경로를 준 두 서버에서 무력화가 일어나는 호출을 보내자 응답은 정상으로 돌아왔고 줄은 쓰이지 않았다 [15].
두 서버의 표준 오류에는 쓰기 실패를 알리는 줄이 없었다 [15].
`findevil-agent-mcp`의 표준 오류에는 쓰기 전에 남긴 `agent_mcp_sanitized_tool_output` 항목만 있었다 [15].

### L03.05 실행 전 중단

**구현.** 이 방식은 `FINDEVIL_MISS_GH_ENABLED`가 `1`일 때 `findevil-agent-mcp`의 `expert_miss_capture`가 GitHub 이슈를 만드는 경로에 적용된다 [16].
`expert_miss_capture`는 받은 요청 값을 담은 `expert_miss` 항목을 먼저 쓰고 그 뒤에 `gh issue create`를 실행한다 [5][16].

    def _load_tail(self) -> None:
        """Populate ``_next_seq`` + ``_last_hash`` from any existing file."""
        if not self.path.is_file():
            return
        last_line: bytes | None = None
        count = 0
        with self.path.open("rb") as f:
            for raw in f:
                raw = raw.rstrip(b"\n")
                if not raw:
                    continue
                last_line = raw
                count += 1
        if last_line is None:
            return
        try:
            obj = json.loads(last_line)
        except json.JSONDecodeError as exc:
            raise AuditLogError(
                f"audit log {self.path}: last line is not valid JSON: {exc}"
            ) from exc
        if not isinstance(obj, dict) or "seq" not in obj:
            raise AuditLogError(f"audit log {self.path}: last line is not an audit record")

        self._last_hash = hash_line(last_line)
        if count != self._next_seq:
            raise AuditLogError(
                f"audit log {self.path}: seq-count mismatch "

```python
def _error_content(message: str, *, kind: str) -> list[TextContent]:
    """Stable error shape returned to the MCP client.

    ``kind`` is one of:
      - ``"validation"``: input failed pydantic validation.
      - ``"unknown_tool"``: name not in the registry.
      - ``"handler"``: the handler raised an unexpected exception.
    """
    # Error messages interpolate exception/validation text that can echo raw
    # evidence bytes, so the error path is an injection channel just like a
    # successful tool body. The success path neutralizes via ``_to_text_content``;
    # route the human-readable message through the SAME sanitizer here so
    # attacker-controlled chat/role tokens and invisible Unicode never reach the
    # model un-neutralized (mirrors ``make_error_response`` in
    # services/mcp/src/server.rs). Only the message string is sanitized -- the
    # ``kind`` and the error shape are unchanged, and a JSON-RPC error is a
    # protocol error, not a hashed tool output, so no audit-chain or
    # ``_meta.sanitized`` accounting is touched. The tally is intentionally
    # discarded.
    counts: dict[str, int] = {}
    safe_message = sanitize_str(message, counts)
    payload = {"error": {"kind": kind, "message": safe_message}}
    return [
        TextContent(
            type="text",
            text=json.dumps(payload, sort_keys=True, separators=(",", ":")),
        )
    ]
```
