# L01 기록 방식

### L01.01 공통 요청 처리 단계에서 기록

**구현.** 이 방식은 `findevil-agent-mcp`의 도구 호출 처리기 `call_tool`과 결과 변환 함수 `_to_text_content`, `findevil-mcp`의 결과 처리 함수 `finalize_tool_output`에 적용된다 [1][2][3].
`findevil-agent-mcp`의 `call_tool`은 모든 도구 호출을 받아 도구를 고르고 입력 모델로 인자를 검사한 뒤 처리기를 부른다 [1].
등록되지 않은 도구 이름이면 `agent_mcp_unknown_tool` 항목을 쓴다 [1].
입력 모델 검사에서 거부하면 `agent_mcp_validation_error` 항목을, 처리기가 예외를 올리면 `agent_mcp_handler_exception` 항목을 쓴다 [1].
세 항목 모두 `tool` 필드에 도구 이름을 담는다 [1].
이 항목은 실패한 호출에만 남고 성공한 호출에는 남지 않는다 [1].
서버는 structlog 로거가 항목을 JSON 한 줄로 바꿔 표준 오류에 쓰도록 설정한다 [4].
그래서 항목은 파일이 아니라 서버 프로세스의 표준 오류로 나가고 그 출력을 어디에 남길지는 서버를 실행한 쪽이 정한다 [4].
등록되지 않은 도구 이름을 부른 호출과 처리기가 예외로 끝난 호출은 표준 오류에 이 항목을 남겼다 [5].

`_to_text_content`는 성공한 호출의 결과 글에서 모델 지시 토큰을 무력화했을 때만 `agent_mcp_sanitized_tool_output` 항목을 표준 오류에 쓴다 [2].
이 항목에는 패턴별 건수만 있고 도구 이름은 없다 [2].
같은 때에 `record_neutralization`이 도구 이름과 결과 글의 SHA-256을 담은 줄을 `injection_alerts.jsonl`에 덧붙인다 [2][6].
`findevil-mcp`의 `finalize_tool_output`은 모든 도구의 성공 결과가 지나는 곳이고 무력화한 토큰이 있을 때만 `tool_call_id`가 없는 같은 종류의 줄을 `injection_alerts.jsonl`에 덧붙인다 [3][7][8].
두 서버 모두 이 파일의 경로를 환경변수 `FINDEVIL_INJECTION_LEDGER`에서 먼저 찾고 없으면 `FINDEVIL_HOME` 아래에 둔다 [6][7].
`kind`에 모델 지시 토큰을 넣은 `audit_append` 호출은 이 파일에 `tool`이 `audit_append`인 줄을 남겼다 [5].
제목에 같은 토큰이 있는 `.eml` 파일을 읽은 `email_parse` 호출은 `tool`이 `email_parse`인 줄을 남겼다 [9].

`findevil-mcp`는 이 밖에 도구 호출을 기록하지 않는다 [10][11].
요청 처리 함수 `dispatch`는 등록되지 않은 도구, 인자 오류, 처리기 오류를 JSON-RPC 오류 응답으로만 돌려준다 [10].
`main`은 서버가 시작할 때와 끝날 때만 표준 오류에 줄을 쓴다 [11].
등록되지 않은 도구, 모르는 인자, 없는 파일로 부른 호출 3개는 오류 응답만 받았고 표준 오류에는 시작과 끝의 두 줄만 남았다 [9].
`vol_pslist`처럼 `case_id`를 받는 도구의 입력 설명은 이 값을 호출 기록 대조용으로 받는다고 적지만 서버는 이 값을 기록하지 않는다 [12][3].

**한계.** `findevil-agent-mcp`에서 MCP Python SDK 1.27.0의 `Server`는 처리기를 부르기 전에 입력 스키마로 인자를 검사한다 [13].
스키마에 맞지 않으면 처리기를 부르지 않은 채 `isError`가 참인 결과를 돌려준다 [13].
그래서 스키마에 없는 인자를 준 호출은 `call_tool`에 닿지 않아 `agent_mcp_validation_error` 항목을 남기지 않았다 [5].
SDK는 요청마다 요청 종류만 적은 `Processing request of type CallToolRequest` 줄을 같은 표준 오류에 쓴다 [5].
처리기가 예외 없이 실패를 담은 결과를 돌려주는 호출도 항목을 남기지 않는다 [1].
`audit_verify`가 끊어진 체인을 `ok`가 거짓인 결과로 돌려준 호출은 표준 오류에 항목을 남기지 않았다 [14].
로그 수준은 `FINDEVIL_LOG_LEVEL`로 정하고 이 값을 `ERROR`로 올리면 `WARNING` 수준인 등록되지 않은 도구 항목, 입력 검사 항목, 무력화 항목은 출력되지 않는다 [4][1][2].
`injection_alerts.jsonl`은 `FINDEVIL_INJECTION_LEDGER`와 `FINDEVIL_HOME`이 모두 없으면 쓰이지 않는다 [6][7].
저장소의 두 시작 스크립트가 읽는 `project-env.sh`는 `FINDEVIL_HOME`을 실행 상태 폴더 아래로 정한다 [15].

### L01.02 도구별 기록 호출

**구현.** 이 방식은 `findevil-agent-mcp`의 `memory_remember`, `memory_recall`, `accuracy_compare`, `pool_handoff`, `expert_miss_capture`에 적용된다 [16][17][18][19][20].
이 도구들은 공통 단계가 아니라 도구 본문에서 `AuditLog.append`를 불러 인자로 받은 경로의 JSONL 파일에 항목 하나를 덧붙인다 [21].
`memory_remember`, `memory_recall`, `accuracy_compare`는 선택 인자 `audit_log_path`가 있을 때만 각각 `memory_remember`, `memory_recall`, `accuracy_diagnostic` 항목을 쓴다 [16][17][18].
`pool_handoff`는 필수 인자 `audit_path`의 파일에 `acp_handoff` 항목을 쓰고 이 항목 자체가 역할 사이에 넘기는 메시지다 [19].
`expert_miss_capture`는 필수 인자 `ledger_path`의 파일에 `expert_miss` 항목을 쓴다 [20].
`memory_remember`, `memory_recall`, `pool_handoff`를 같은 `audit.jsonl` 경로로 부르자 세 항목이 앞 항목에 이어 차례로 남았다 [5].

`audit_append`는 호출한 쪽이 준 `kind`와 `payload`를 그대로 항목으로 쓰고 자기 호출을 따로 기록하지 않는다 [22].
도구 14개 가운데 나머지 8개인 `audit_verify`, `manifest_finalize`, `manifest_verify`, `verify_finding`, `detect_contradictions`, `judge_findings`, `correlate_findings`, `find_ai_signatures`는 항목을 쓰지 않는다 [23].
`findevil-mcp`의 `disk_mount`, `disk_extract_artifacts`, `disk_unmount`는 사건 폴더의 `session_resources.json`에 마운트와 추출 자원의 상태를 남긴다 [24][25].
이 파일은 자원마다 항목 하나를 두고 `disk_unmount`는 마운트 항목의 상태와 명령을 고쳐 쓴다 [24].
`findevil-mcp`의 다른 도구 본문에는 호출 기록을 쓰는 곳이 없다 [26].

**한계.** 기록 위치는 호출 인자가 정하고 서버는 그 경로가 사건 폴더의 기록 파일인지 대조하지 않는다 [16][19].
그래서 `memory_remember`, `memory_recall`, `accuracy_compare`는 `audit_log_path`를 빼고 부르면 항목을 남기지 않는다 [16][17][18].
도구 본문이 `AuditLog.append`에 이르기 전에 예외로 끝난 호출도 항목을 남기지 않는다 [16][17].

### L01.04 클라이언트의 MCP 호출 기록

**구현.** 이 방식은 사용자 CLI `scripts/verdict`가 실행하는 엔진 `scripts/find_evil_auto.py`로 조사할 때만 적용된다 [27].
다른 MCP 클라이언트로 서버에 붙으면 이 기록은 남지 않는다.
엔진은 두 서버를 MCP 클라이언트로 실행하고 `findevil-mcp` 도구를 부를 때마다 `_record_tool`로 `findevil-agent-mcp`의 `audit_append`를 두 번 부른다 [28][29].
첫 항목 `tool_call_start`에는 엔진이 차례로 매긴 호출 ID `tool_call_id`, 도구 이름, 인자가 들어간다 [28].
둘째 항목 `tool_call_output`에는 같은 `tool_call_id`와 출력 해시 `output_hash`가 들어간다 [28].
`_record_tool`은 도구 호출이 끝난 뒤에 두 항목을 이어서 쓴다 [28][30].
`output_hash`는 엔진이 응답의 `content` 글을 SHA-256으로 계산한 값이다 [31][30].
인자 가운데 이름이 `_path`로 끝나는 값은 사건 폴더나 저장소 기준의 상대 경로로 바꿔 기록한다 [28][32].
모델 에이전트 단계에서 오류로 끝난 호출은 `output_hash`가 빈 값이고 오류 문구를 담은 항목으로 기록한다 [30].
이 항목은 `findevil-agent-mcp`의 `AuditLog`가 쓰므로 서버 도구가 쓰는 항목과 같은 해시 체인 파일에 들어간다 [29][21].

엔진은 `findevil-agent-mcp` 도구의 호출에는 `tool_call_start` 항목을 쓰지 않는다 [33].
`correlate_findings`처럼 일부 도구의 결과를 `correlation_outcomes` 같은 항목으로 기록한다 [33].

저장소의 Claude Code 설정은 `Write`, `Edit`, `Read` 도구에만 경로 검사 훅을 두고 MCP 도구 호출을 기록하는 훅은 없다 [34].
`audit_append`의 도구 설명은 모든 도구 호출 뒤에 이 도구를 부르라고 클라이언트 모델에게 안내한다 [22].
이 안내에 따라 남는 항목은 클라이언트 모델이 쓰는 것이고 코드가 남기는 기록이 아니다.

**한계.** 엔진의 `_audit`은 `audit_append` 호출의 결과를 확인하지 않는다 [29].
엔진의 MCP 클라이언트는 호출 실패를 예외 대신 `_error`를 담은 값으로 돌려준다 [35].
그래서 기록 쓰기가 실패해도 엔진은 조사를 계속하고 그 호출은 기록에 남지 않는다 [29][35].
README는 `audit.jsonl`이 모든 도구 호출과 발견사항을 담는다고 적지만 서버는 도구 호출을 이 파일에 스스로 기록하지 않고 엔진이나 모델이 `audit_append`로 써야 남는다 [36][22].

```python
    async def call_tool(name: str, arguments: dict[str, Any]) -> list[TextContent]:
        spec = specs.get(name)
        if spec is None:
            log.warning("agent_mcp_unknown_tool", tool=name)
            return _error_content(f"unknown tool: {name!r}", kind="unknown_tool")

        try:
            validated = spec.input_model.model_validate(arguments)
        except ValidationError as exc:
            log.warning(
                "agent_mcp_validation_error",
                tool=name,
                errors=exc.errors(include_url=False),

                "agent_mcp_handler_exception",
                tool=name,
                exc_type=type(exc).__name__,
                exc=str(exc),
            )
            return _error_content(f"{type(exc).__name__}: {exc}", kind="handler")

        return _to_text_content(result, tool=name)
```

```rust
fn finalize_tool_output(name: &str, payload: &Value) -> Result<Value, ToolError> {
    let (payload, sanitized) = crate::sanitize::sanitize_value(payload);
    let payload_text = serde_json::to_string(&payload)
        .map_err(|e| ToolError::Internal(format!("serialize tool output: {e}")))?;
    let sha = sha256_hex(payload_text.as_bytes());

    let mut meta = json!({
        "tool": name,
        "output_sha256": sha,
    });
    if !sanitized.is_empty() {
        meta["sanitized"] = sanitized.to_json();
        // Mirror the `_meta.sanitized` counts into the best-effort, counts-only
        // injection-alert SIDECAR ledger. This runs AFTER hashing and never
        // touches `payload`, `sha`, or `meta`, so the sealed output and a
        // verify_finding replay are unaffected — the ledger is not the audit
        // chain. `sha` is recorded as the correlation key (the same sanitized
        // -output digest the audit chain stores), never the payload.
        injection_ledger::record_neutralization(name, &sha, &sanitized);
    }
    Ok(json!({
        "content": [
            {
                "type": "text",
                "text": payload_text,
            }
        ],
        "_meta": meta,
    }))
}
```

```python
def _configure_logging() -> structlog.BoundLogger:
    """Send logs to stderr — stdio is the JSON-RPC channel.

    Stdout pollution corrupts the protocol stream; this function is
    the single place that controls log destination. Tests can
    monkeypatch the returned logger.
    """
    level_name = os.environ.get("FINDEVIL_LOG_LEVEL", "INFO").upper()
    level = getattr(logging, level_name, logging.INFO)
    logging.basicConfig(stream=sys.stderr, level=level, format="%(message)s")
    structlog.configure(
        processors=[
            structlog.processors.add_log_level,
            structlog.processors.TimeStamper(fmt="iso", utc=True),
            structlog.processors.JSONRenderer(),
        ],
        wrapper_class=structlog.make_filtering_bound_logger(level),
        logger_factory=structlog.WriteLoggerFactory(file=sys.stderr),
        cache_logger_on_first_use=True,
    )
```

```python
def resolve_ledger_path() -> Path | None:
    """Resolve the sidecar ledger path, or ``None`` when no contained home exists.

    Order:

      1. ``FINDEVIL_INJECTION_LEDGER`` -- explicit ledger-file override.
      2. ``FINDEVIL_HOME`` -- a ``injection_alerts.jsonl`` sibling of the case
         store (where the contained runtime state already lives).

    There is deliberately **no** ``$HOME`` fallback: a stray neutralization must
    never write outside a contained run (CLAUDE.md containment). ``None`` means
    "nowhere safe to write" and the caller no-ops.
    """
    override = os.environ.get("FINDEVIL_INJECTION_LEDGER")
    if override:
        return Path(override)
    home = os.environ.get("FINDEVIL_HOME")
    if home:
        return Path(home) / LEDGER_FILENAME
    return None
```
