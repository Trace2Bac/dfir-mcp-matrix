# L02 기록 구성

### L02.01 MCP 요청 기록

**구현.** 이 방식은 `findevil-agent-mcp`의 `memory_remember`, `memory_recall`, `pool_handoff`, `expert_miss_capture`가 도구 본문에서 쓰는 해시 체인 항목에 적용된다 [1][2][3][4].
항목은 `seq`, `ts`, `kind`, `prev_hash`, `payload` 다섯 필드로 이루어진다 [5].
`memory_remember`는 `payload`에 받은 `case_id`, `kind`, `key`, `sha256`을 그대로 넣는다 [1].
`memory_recall`은 받은 `query`와 `kind`를 넣는다 [2].
`pool_handoff`는 받은 `from_role`, `to_role`, `payload`를 넣는다 [3].
`expert_miss_capture`는 받은 `case_id`, `finding_id`, `edit_type`, `edit_text`, `expert_name`을 넣는다 [4].
`memory_remember`와 `memory_recall` 항목의 `kind`는 도구 이름과 같고 `pool_handoff`와 `expert_miss_capture` 항목의 `kind`는 각각 `acp_handoff`와 `expert_miss`다 [1][2][3][4].
`memory_remember`, `memory_recall`, `pool_handoff`를 부르자 `audit.jsonl`의 항목에 받은 인자 값이 바뀌지 않고 남았다 [6].

`findevil-agent-mcp`의 `call_tool`이 표준 오류에 쓰는 항목은 도구 이름을 담는다 [7].
입력 모델 검사에서 거부한 항목은 pydantic 오류 목록 `errors`를 함께 담고 이 목록의 `input`에는 거부된 인자 값이 들어간다 [7][8].
나머지 두 항목은 인자를 따로 담지 않는다 [7].
두 서버가 쓰는 `injection_alerts.jsonl`의 줄에도 인자가 없다 [9][10].
두 서버 모두 외부 프로그램에 넘긴 실행 인자를 호출 기록에 남기지 않는다.
`disk_mount`와 `disk_unmount`가 실행한 명령 목록은 자원 상태 파일 `session_resources.json`의 `command`에 남는다 [11].
서버는 도구 호출을 처리하며 모델 API를 부르지 않는다.

**한계.** 도구 본문이 받은 인자 가운데 일부만 항목에 넣는다.

- `memory_remember`는 기억 저장소에 쓴 값 `value`와 `store_path`, `ts`, `case_path`를 넣지 않는다 [1].
- `memory_recall`은 `store_path`와 `limit`를 넣지 않는다 [2].
- `pool_handoff`는 `audit_path`를, `expert_miss_capture`는 `ledger_path`를 넣지 않는다 [3][4].

`memory_remember`의 항목에는 저장소에 쓴 `value` 값이 없었다 [6].
그래서 항목만으로는 모델이 보낸 요청을 모두 되살릴 수 없다.

### L02.02 서버가 변환한 연산·인자 기록

**구현.** 이 방식은 `pool_handoff`와 `accuracy_compare`가 쓰는 항목에 적용된다 [3][12].
`pool_handoff`는 `correlation_id`를 받지 않으면 메시지 모델 `ACPMessage`가 만든 UUID4 값을 항목의 `payload`에 넣는다 [3].
메시지 시각 `ts`도 서버가 정한 값을 `payload`와 항목의 `ts`에 넣는다 [3].
`correlation_id` 없이 부른 `pool_handoff`의 항목에는 서버가 만든 `correlation_id`와 응답과 같은 시각이 남았다 [6].
`accuracy_compare`는 `golden_path`를 받지 않으면 사건 폴더 `verdict.json`의 `case_id`로 찾은 정답 파일 경로를 `golden`에 넣는다 [12][13].
`accuracy_compare`의 항목에는 모델이 `golden_path`를 주었는지가 따로 남지 않는다 [12].

### L02.05 결과 상태·실행 시점 기록

**구현.** 이 방식은 `findevil-agent-mcp`의 `call_tool`이 표준 오류에 쓰는 항목에 적용된다 [7].
항목의 `event`는 결과 상태를 나타낸다 [7].

- `agent_mcp_unknown_tool`은 등록되지 않은 도구 이름으로 거부한 호출이다 [7].
- `agent_mcp_validation_error`는 입력 모델 검사에서 거부한 호출이다 [7].
- `agent_mcp_handler_exception`은 처리기가 예외로 끝난 호출이고 예외 종류 `exc_type`과 문구 `exc`를 함께 담는다 [7].

structlog 설정은 항목마다 수준 `level`과 UTC 시각 `timestamp`를 붙인다 [14].
처리기가 예외로 끝난 `audit_append`와 `memory_remember` 호출은 `level`이 `error`이고 시각이 붙은 항목을 남겼다 [6].
성공한 호출은 이 항목을 남기지 않는다 [7].

도구 본문이 쓰는 해시 체인 항목에는 결과 상태 필드가 없고 항목을 쓴 시각 `ts`만 있다 [5][15].
`injection_alerts.jsonl`의 줄에도 결과 상태가 없고 쓴 시각과 무력화 건수만 있다 [9][10].

**한계.** MCP Python SDK 1.27.0의 `Server`가 입력 스키마로 거부한 호출은 `call_tool`에 닿지 않아 이 항목을 남기지 않는다 [16][6].
`FINDEVIL_LOG_LEVEL`을 `ERROR`로 올리면 `WARNING` 수준인 등록되지 않은 도구 항목과 입력 검사 항목은 출력되지 않는다 [14][7].

### L02.06 결과 참조·요약값 기록

**구현.** 이 방식은 두 서버의 `injection_alerts.jsonl` 줄과 `memory_recall`, `accuracy_compare`의 항목에 적용된다 [9][10][2][12].
`injection_alerts.jsonl` 줄은 `output_sha256`에 결과 글의 SHA-256을 담고 `patterns`와 `total`에 무력화한 패턴별 건수와 합계를 담는다 [9][10].
`findevil-mcp`의 `output_sha256`은 무력화를 마친 결과 JSON을 직렬화한 글의 해시이고 응답의 `_meta.output_sha256`과 같은 값이다 [17].
`findevil-agent-mcp`의 `output_sha256`은 무력화를 마친 결과를 키 정렬 JSON으로 바꾼 응답 글의 해시다 [18].
그래서 두 해시는 분석 도구의 원래 출력이 아니라 서버가 파싱해 돌려준 결과 글의 해시다 [17][18].
`email_parse` 호출이 남긴 줄의 `output_sha256`은 그 응답의 `_meta.output_sha256`과 같았다 [19].
`findevil-agent-mcp`의 줄에는 `tool_call_id` 필드가 있지만 서버는 이 값을 넘기지 않아 `null`로 남았다 [10][18][6].

`memory_recall` 항목은 찾은 건수 `hit_count`와 찾은 항목마다 `case_id`, `ts`, `confidence`를 담고 `key`와 `value`는 담지 않는다 [2].
`accuracy_compare` 항목은 재현율, 정밀도, F1, 통과 여부 같은 점수 요약값을 담는다 [12].

**한계.** `findevil-agent-mcp`의 건수는 정리 함수가 토큰을 찾은 횟수이고 원래 글의 토큰을 실제로 바꾼 횟수와 다를 수 있다 [20].
정리 함수는 소문자로 바꾼 글에서 찾은 위치를 원래 글에 그대로 쓰므로 소문자로 바꿀 때 길이가 달라지는 글에서는 위치가 어긋난다 [20].
그런 문자가 토큰 앞에 있는 파일을 읽은 시험에서 토큰은 응답에 그대로 실렸고 장부 줄에는 `im_start` 1회가 남았다 [21].

@dataclass(frozen=True)
class AuditRecord:
    """One line of the audit log before hashing.

    ``seq`` is 0-based and monotonic. ``prev_hash`` is the SHA-256
    of the preceding line (empty string for the first record). The
    ``payload`` dict is the domain-specific event body — tool calls,
    findings, contradictions, etc.
    """

    seq: int
    ts: str  # UTC ISO-8601Z
    kind: str
    prev_hash: str
    payload: dict[str, Any]

    def to_canonical_dict(self) -> dict[str, Any]:
        """Dict shape written to disk. Field order matters for audit readability
        but doesn't affect hashing — JCS canonicalization sorts anyway.
        """
        return {
            "seq": self.seq,
            "ts": self.ts,
            "kind": self.kind,
            "prev_hash": self.prev_hash,
            "payload": self.payload,
        }

def _resolve_golden(case_dir: Path, override: str | None) -> Path | None:
    """Resolve the golden without depending on the process CWD.

    The shared ``resolve_golden`` looks under a relative ``goldens/`` directory.
    An MCP server's CWD is not guaranteed to be the repo root, so when no explicit
    override is given we also try the repo's ``goldens/`` resolved from this
    module's location (services/agent_mcp/.../tools -> repo root).
    """
    found = resolve_golden(case_dir, override)
    if found is not None or override is not None:
        return found
    # Fallback: anchor goldens/ at the repo root relative to this file.
    repo_root = Path(__file__).resolve().parents[4]
    verdict = case_dir / "verdict.json"
    if not verdict.is_file():
        return None
    try:
        import json

        cid = json.loads(verdict.read_text(encoding="utf-8")).get("case_id")
    except (OSError, ValueError):
        cid = None
    if cid:
        cand = repo_root / "goldens" / str(cid) / "expected-findings.json"
        if cand.is_file():
            return cand

fn finalize_tool_output(name: &str, payload: &Value) -> Result<Value, ToolError> {
    let (payload, sanitized) = crate::sanitize::sanitize_value(payload);
    let payload_text = serde_json::to_string(&payload)
        .map_err(|e| ToolError::Internal(format!("serialize tool output: {e}")))?;
    let sha = sha256_hex(payload_text.as_bytes());

    let mut meta = json!({
        "tool": name,
        "output_sha256": sha,
    });
    if !sanitized.is_empty() {
        meta["sanitized"] = sanitized.to_json();
        // Mirror the `_meta.sanitized` counts into the best-effort, counts-only
        // injection-alert SIDECAR ledger. This runs AFTER hashing and never
        // touches `payload`, `sha`, or `meta`, so the sealed output and a
        // verify_finding replay are unaffected — the ledger is not the audit
        // chain. `sha` is recorded as the correlation key (the same sanitized
        // -output digest the audit chain stores), never the payload.
        injection_ledger::record_neutralization(name, &sha, &sanitized);
    }
    Ok(json!({
        "content": [
            {
                "type": "text",
                "text": payload_text,
            }
        ],
        "_meta": meta,
    }))
}
