# F06 보고 산출물 구성

### 비적용

**판단.** 서버에는 사건 단위가 없고 보고 산출물을 만들거나 내보내는 도구도 없다.
도구는 호출마다 키워드나 파일·폴더 경로를 인자로 받고 사건이나 조사 세션을 가리키는 식별자를 받거나 만들지 않는다 [1].
서버는 호출 사이에 발견사항이나 호출 기록을 모아 두지 않는다 [2].

`generate_forensic_report`의 설명은 파일 메타데이터와 로그 분석을 묶은 구조화된 포렌식 보고서를 만든다고 적는다 [3].
이 도구는 `correlate_file_and_logs`의 결과에 `status`를 붙인 `dict`를 응답으로만 돌려주고 파일을 쓰지 않는다 [3][2].
응답에 실리는 값은 `status`, `filename`, `keyword`, `file_modified_time`, 로그 줄 앞 10개 `log_hits`, `correlation_found`다 [3].
분석한 파일의 해시나 크기, 조사 범위, 방법, 한계, 판단의 확정 상태는 실리지 않는다 [3][4].
MCP SDK 클라이언트로 부른 이 도구의 응답 키는 위의 6개였다 [4].

같은 저장소의 사용자 CLI `cli_demo.py`는 `generate_forensic_report`의 결과를 표준 출력에 적고 파일을 쓰지 않는다 [5].
README가 예시로 가리키는 `docs/forensic_analysis_report.md`는 저장소에 둔 문서이고 서버 코드와 CLI에는 이 파일을 쓰는 코드가 없다 [6][2][5].

```python
    """
    Generate a structured forensic report by combining file metadata and log analysis.

    This tool uses both `file_metadata` and `scan_syslog` to check whether the specified file's
    modification time aligns with log entries containing the provided keyword. It outputs
    a structured dictionary summarizing findings for programmatic consumption.

    Parameters:
        filename (str): Full path to the file to investigate.
        keyword (str): Keyword to search in system logs (default is 'modified').

    Returns:
        dict: A structured forensic report with file info, logs, and correlation status.
    """
```
