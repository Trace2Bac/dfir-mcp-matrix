# R08 시간값 처리

### R08.01 시간 변환 전 값 유지

**구현.** 이 방식은 `scan_syslog`의 로그 줄과 두 묶음 도구의 `log_hits`에 적용된다 [1][2].
서버는 로그 줄 안의 시각을 읽거나 바꾸지 않고 줄 전체를 그대로 싣는다 [1].
시험 로그의 `Jun 10 10:00:00` 꼴 시각이 줄 안에 그대로 돌아왔다 [3].

`file_metadata`는 시각을 바꾼 값만 싣는다 [4].
`os.stat`의 `st_ctime`과 `st_mtime`을 `datetime.fromtimestamp`로 바꾸고 `isoformat()`의 글을 `created_at`과 `modified_at`에 싣는다 [4].
Python 3.11의 `fromtimestamp`는 `tz`가 없으면 서버 호스트의 지역 시각으로 바꾼 naive `datetime`을 돌려준다 [5].
`isoformat()`은 UTC 오프셋이 없는 `datetime`에 오프셋을 붙이지 않는다 [5].
원래 epoch 값과 시간대는 싣지 않는다 [4].
같은 파일을 `TZ`만 바꾼 두 서버로 보자 `modified_at`이 `2020-01-01T00:00:00`과 `2020-01-01T09:00:00`으로 달랐고 두 값 모두 오프셋이 없었다 [3].
`correlate_file_and_logs`와 `generate_forensic_report`는 이 `modified_at`을 `file_modified_time`에 옮긴다 [2].

`created_at`은 `st_ctime`이다 [4].
Python 3.11 문서는 `st_ctime`을 Unix에서 마지막 메타데이터 변경 시각, Windows에서 생성 시각으로 적는다 [6].
수정 시각을 2020년으로 바꾼 파일의 `created_at`은 바꾼 시점의 시각이었고 `modified_at`보다 늦었다 [3].
