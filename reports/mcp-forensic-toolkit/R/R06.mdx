# R06 증거에서 추출한 민감정보 노출 제어

### 미구현

**판단.** 서버는 대상 호스트의 로그 줄을 그대로 응답에 싣고 그 안의 비밀 값을 가리거나 빼는 코드를 두지 않는다 [1][2].
`scan_syslog`는 키워드가 들어 있는 줄을 바꾸지 않고 돌려준다 [1].
`correlate_file_and_logs`와 `generate_forensic_report`도 그 줄을 `log_hits`에 그대로 싣는다 [2].
어떤 줄이 응답에 실릴지는 모델이 준 `keyword`가 정한다 [1].
시험 로그에 `password=` 뒤에 합성 값을 둔 줄을 넣고 그 줄에 있는 낱말로 `scan_syslog`를 부르자 합성 값이 그대로 돌아왔다 [3].

`file_metadata`와 `hash_directory`는 파일 내용 대신 크기, 시각, SHA-256을 싣는다 [4][5].
서버 코드에는 값을 가리는 함수가 없고 서버는 호출 기록이나 보고서 파일을 쓰지 않는다 [6].

```python
    results = {}
    for root, _, files in os.walk(path):
        for f in files:
            full_path = os.path.join(root, f)
            try:
                with open(full_path, "rb") as fp:
                    content = fp.read()
                    results[full_path] = hashlib.sha256(content).hexdigest()
            except Exception as e:
                results[full_path] = f"Error: {str(e)}"
    return results
```
