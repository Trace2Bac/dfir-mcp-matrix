# R02 대량 결과 전달

### R02.01 문자·항목 상한

**구현.** 이 방식은 `scan_syslog`와 `correlate_file_and_logs`·`generate_forensic_report`의 `log_hits`에 적용된다 [1][2].
`scan_syslog`는 키워드가 들어 있는 줄을 모두 모은 뒤 마지막 100줄(`lines[-100:]`)만 돌려준다 [1].
Linux에서는 `/var/log/syslog`를 처음부터 끝까지 읽어 맞는 줄을 모두 메모리에 모은다 [1].
macOS에서는 `log show`에 `--last 10m`을 넘기고 받은 줄에 같은 100줄 상한을 적용한다 [1].
`correlate_file_and_logs`는 그 100줄 가운데 다시 앞 10줄(`log_hits[:10]`)만 싣고 `generate_forensic_report`는 그 값을 옮긴다 [2].
키워드가 들어 있는 줄이 150줄인 시험 로그로 부르자 `scan_syslog`는 51번째부터 150번째 줄까지 100줄을 돌려주었다 [3].
같은 키워드로 `correlate_file_and_logs`를 부르자 `log_hits`는 51번째부터 60번째 줄까지 10줄이었다 [3].
두 응답에는 잘렸다는 표시나 전체 건수가 없다 [1][2][3].
줄 하나의 길이에는 상한이 없다 [1].
나머지 결과를 이어서 읽는 도구나 보관한 파일은 없다 [4].

`hash_directory`에는 상한이 없다 [5].
파일 500개가 있는 폴더로 부르자 키 500개를 담은 48,394자의 JSON 글 하나가 돌아왔다 [3].
`file_metadata`의 응답은 필드 4개로 정해진 꼴이다 [6].

[5] `hash_directory`는 폴더 아래 모든 파일을 결과에 넣는다.

```python
    results = {}
    for root, _, files in os.walk(path):
        for f in files:
            full_path = os.path.join(root, f)
            try:
                with open(full_path, "rb") as fp:
                    content = fp.read()
                    results[full_path] = hashlib.sha256(content).hexdigest()
            except Exception as e:
                results[full_path] = f"Error: {str(e)}"
    return results
```
