# R01 결과 가공

### R01.01 가공 없이 전달

**구현.** 이 방식은 `scan_syslog`가 돌려주는 로그 줄과 `correlate_file_and_logs`·`generate_forensic_report`의 `log_hits`에 적용된다 [1][2].
Linux에서는 `/var/log/syslog`에서 키워드가 대소문자 구분 없이 들어 있는 줄을 줄 끝 개행까지 바꾸지 않고 싣는다 [1].
macOS에서는 `log`의 표준 출력을 줄로 나누고 빈 줄과 `Timestamp`로 시작하는 줄을 뺀 나머지를 바꾸지 않고 싣는다 [1].
MCP Python SDK 1.9.3의 FastMCP는 도구가 돌려준 `list`의 문자열마다 `TextContent`를 하나씩 만든다 [3].
그래서 `scan_syslog`의 응답은 로그 줄마다 `TextContent` 하나가 있는 목록이다 [1][3].
키워드가 들어 있는 줄이 150줄인 시험 로그로 부르자 `TextContent` 100개가 돌아왔고 각 글은 시험 파일의 줄과 같았다 [4].
`correlate_file_and_logs`는 `scan_syslog`가 돌려준 줄 가운데 앞 10개를 바꾸지 않고 `log_hits`에 넣고 `generate_forensic_report`는 그 값을 옮겨 싣는다 [2].

### R01.02 구조화 파싱·필드 선택

**구현.** 이 방식은 `file_metadata`와 그 결과를 쓰는 두 묶음 도구에 적용된다 [5][2].
`file_metadata`는 `os.stat` 결과에서 `st_size`, `st_ctime`, `st_mtime`만 골라 `size_bytes`, `created_at`, `modified_at`에 싣는다 [5].
같은 응답의 `sha256`에는 파일 전체의 SHA-256을 싣는다 [5].
`st_atime`, 소유자, 권한 같은 다른 `os.stat` 값은 싣지 않는다 [5].
`correlate_file_and_logs`는 이 결과에서 `modified_at`만 골라 `file_modified_time`에 싣는다 [2].
`hash_directory`는 파일 경로를 키로, SHA-256을 값으로 둔 `dict`를 돌려준다 [6].
FastMCP 1.9.3은 도구가 돌려준 `dict`를 들여쓴 JSON 글 하나로 바꿔 `TextContent` 하나에 싣는다 [3].

```python
    results = {}
    for root, _, files in os.walk(path):
        for f in files:
            full_path = os.path.join(root, f)
            try:
                with open(full_path, "rb") as fp:
                    content = fp.read()
                    results[full_path] = hashlib.sha256(content).hexdigest()
            except Exception as e:
                results[full_path] = f"Error: {str(e)}"
    return results
```
