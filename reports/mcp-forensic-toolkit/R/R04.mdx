# R04 도구 결과 해석 주의

### 미구현

**판단.** 도구 설명, 리소스, 프롬프트, 응답 어디에도 도구 결과의 해석 한계나 결과를 확인하려면 더 볼 것을 적지 않는다.
도구 설명은 무엇을 읽고 무엇을 돌려주는지만 적는다 [1].
리소스 `toolkit://about`은 서버 기능과 `SAFE_BASE` 설정만 적는다 [2].
서버는 초기화 지침을 두지 않는다 [3].
응답은 결과 값과 오류 문구만 싣는다 [4].

프롬프트 4개는 부를 도구와 결과로 판단할 내용을 적는다 [5].
`investigate-file`은 시각과 크기로 변조 흔적이나 의심스러운 시각을 판단하라고 적는다 [5].
`correlate-log-and-file`은 `scan_syslog`와 `file_metadata`를 차례로 부르고 수정 시각이 의심스러운 로그 줄과 맞는지 분석하라고 적는다 [5].
`explain-correlation`은 `correlate_file_and_logs`의 결과로 변조 가능성을 100단어 안으로 설명하라고 적는다 [5].
이 프롬프트들은 호출 순서와 판단할 내용만 적고 결과가 증명하지 못하는 것이나 결과를 확인할 다른 도구나 증거는 적지 않는다 [5].

다음 결과의 해석 조건은 설명, 프롬프트, 응답에 없다.
`correlation_found`는 파일 이름이 로그 줄에 문자열로 들어 있는지만 계산한 값이다 [6].
`created_at`은 `st_ctime`이고 Python 3.11 문서는 이 값을 Unix에서 마지막 메타데이터 변경 시각으로 적는다 [7][8].
`scan_syslog`의 결과는 Linux에서 `/var/log/syslog` 한 파일, macOS에서 `--last 10m`을 준 `log show`의 결과다 [9].
