# P03 조사 진척 판단

### P03.03 미조사 범위·생략 사유 보고

**구현.** 이 방식은 `hash_directory`에 적용된다 [1].
`hash_directory`는 읽지 못한 파일을 결과에서 빼지 않고 그 경로의 값에 `Error: `와 예외 문구를 싣는다 [1].
읽기 권한이 없는 파일과 대상이 없는 링크를 둔 시험 폴더에서 두 경로의 값은 `Permission denied`와 `No such file or directory`가 들어간 문구였다 [2].

이 보고는 그 호출 한 번의 범위에 그친다.
서버에는 대상별로 해야 할 작업 목록, 조사 단계, 완료 조건이 없고 모델이 진행 기록을 적는 도구도 없다 [3].

다음 도구는 다루지 못한 범위를 응답에 싣지 않는다.

- `scan_syslog`는 키워드에 맞는 줄이 100개를 넘으면 마지막 100줄만 돌려주고 뺀 줄 수를 싣지 않는다 [4].
- `correlate_file_and_logs`는 대조에 쓴 로그 줄 가운데 앞 10개만 `log_hits`에 싣고 나머지를 뺐다는 사실을 싣지 않는다 [5].
- 키워드에 맞는 줄 151개를 둔 시험에서 `scan_syslog`는 100줄을 돌려주었고 `log_hits`는 10줄이었다 [2].

**한계.** `hash_directory`는 `os.walk`를 기본 인자로 부른다 [1].
Python 3.11.9의 `os.walk`는 기본 인자에서 목록을 읽지 못한 폴더를 오류 없이 건너뛰고 폴더를 가리키는 링크를 따라가지 않는다 [6].
그래서 그런 폴더 아래 파일은 결과에 없고 건너뛴 사실도 실리지 않는다 [1][6].
권한을 없앤 하위 폴더와 폴더 링크를 둔 시험 폴더에서 두 곳은 오류 문구 없이 결과에서 빠졌다 [2].
받은 폴더 자체의 목록을 읽지 못해도 `hash_directory`는 거부하지 않고 빈 `dict`를 돌려준다 [1][6].
목록을 읽을 수 없게 둔 폴더를 주자 빈 폴더를 준 경우와 같은 빈 `dict`가 돌아왔다 [7].

```python
@mcp.tool()
def hash_directory(path: str) -> dict:
    """
    Recursively compute SHA-256 hashes for all files in a directory.
    """
    if not os.path.isdir(path):
        return {"error": "Provided path is not a directory."}

    results = {}
    for root, _, files in os.walk(path):
        for f in files:
            full_path = os.path.join(root, f)
            try:
                with open(full_path, "rb") as fp:
                    content = fp.read()
                    results[full_path] = hashlib.sha256(content).hexdigest()
            except Exception as e:
                results[full_path] = f"Error: {str(e)}"
    return results
```
