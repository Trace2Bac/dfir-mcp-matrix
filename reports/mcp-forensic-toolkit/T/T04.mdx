# T04 실행 방식

### T04.01 서버 프로세스 안 분석

**구현.** 이 방식은 `file_metadata`, `hash_directory`, `correlate_file_and_logs`, `generate_forensic_report`와 Linux에서 실행하는 `scan_syslog`에 적용된다 [1][2][3][4].
`file_metadata`는 `os.stat`으로 메타데이터를 읽고 파일 전체를 메모리로 읽어 `hashlib.sha256`으로 해시를 계산한다 [1].
`hash_directory`는 `os.walk`로 폴더를 훑으며 파일마다 전체를 읽어 같은 방식으로 해시를 계산한다 [2].
`scan_syslog`는 Linux에서 `/var/log/syslog`를 서버 프로세스에서 열어 줄마다 소문자로 바꾼 키워드가 들어 있는지 본다 [3].
`correlate_file_and_logs`는 파일 이름을 소문자로 바꿔 로그 줄에 들어 있는지 서버 코드로 계산한다 [4].
그래서 이 분석은 서버와 같은 계정, 메모리, 파일 권한으로 실행된다 [1][2][3].

### T04.02 같은 권한의 별도 프로세스

**구현.** 이 방식은 macOS에서 실행하는 `scan_syslog`에 적용된다 [5].
서버는 `log show` 인자 목록을 `subprocess.run`에 넘겨 자식 프로세스로 실행하고 표준 출력과 표준 오류를 글로 받는다 [5].
`shell`을 주지 않으므로 셸을 거치지 않는다 [5][6].
실행 파일은 `PATH`에서 찾은 `log`이고 서버는 계정, 작업 폴더, 환경변수를 따로 정하지 않는다 [5].
그래서 `log`는 서버와 같은 계정과 환경으로 실행된다 [5].
`platform.system()`이 `Darwin`을 돌려주게 하고 받은 인자를 기록하는 시험용 `log`를 `PATH` 앞에 두자 서버가 그 실행 파일을 실행했다 [7].

README는 기능 목록에 `SAFE_BASE`와 격리된 실행 환경(`sandboxed environment`)을 적는다 [8].
저장소에는 서버나 `log`를 격리된 환경에서 실행하는 구성(Dockerfile, 실행 스크립트)이 없다 [9].

```python
    results = {}
    for root, _, files in os.walk(path):
        for f in files:
            full_path = os.path.join(root, f)
            try:
                with open(full_path, "rb") as fp:
                    content = fp.read()
                    results[full_path] = hashlib.sha256(content).hexdigest()
            except Exception as e:
                results[full_path] = f"Error: {str(e)}"
    return results
```
