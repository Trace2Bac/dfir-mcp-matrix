# T03 실행 조건 확인

### 미구현

**판단.** 서버에는 도구 인자 밖의 조건으로 호출을 막거나 미루는 코드가 없다.
도구 함수는 받은 인자로 바로 로그나 파일을 읽는다 [1].
프롬프트 `correlate-log-and-file`은 `scan_syslog`를 먼저 부르고 이어서 `file_metadata`를 부르라고 적지만 이 순서를 확인하는 코드는 없다 [2].
`correlate_file_and_logs`와 `generate_forensic_report`는 필요한 함수를 그 호출 안에서 부르고 앞선 호출이 있었는지 보지 않는다 [3].
서버는 앞선 호출의 결과를 저장하지 않는다 [1].
호출자를 확인하는 코드와 실행 전에 메모리나 디스크 같은 자원 상태를 확인하는 코드도 없다 [1].
`server.py`에는 진입점이 없고 서버가 쓰는 전송 방식을 정하는 코드도 없다 [1].
MCP Python SDK 1.9.3의 `FastMCP.run`은 전송 방식을 주지 않으면 stdio로 실행한다 [4].

동시 실행 수를 정하는 장치도 없다.
도구 함수가 모두 동기 함수라서 MCP Python SDK 1.9.3의 FastMCP는 이벤트 루프에서 함수를 await 없이 바로 부른다 [5].
한 호출이 끝날 때까지 같은 이벤트 루프의 다른 요청은 처리되지 않으므로 도구 호출은 하나씩 차례로 실행된다 [5].
이는 서버가 정한 제한이 아니라 SDK가 동기 함수를 부르는 방식에서 생기는 동작이다.
