# T10 도구 명세 구성

### T10.01 처리 함수에서 명세 생성

**구현.** 이 방식은 서버가 등록하는 도구 5개 모두에 적용된다 [1].
서버는 도구 함수마다 `@mcp.tool()`만 붙이고 이름, 설명, 입력 schema를 따로 주지 않는다 [1].
MCP Python SDK 1.9.3의 FastMCP는 함수 이름을 도구 이름으로, docstring 전체를 설명으로 쓰고 함수 서명에서 입력 schema를 만든다 [2].
도구 목록의 항목에는 이름, 설명, 입력 schema만 있었고 입력 schema는 인자마다 `title`, 자료형, 기본값만 실었다 [3].
`correlate_file_and_logs`와 `generate_forensic_report`의 `keyword`는 기본값 `modified`를 싣는다 [3].
`file_metadata`와 `hash_directory`의 설명은 한 문장이다 [1].
도구 annotation은 없고 초기화 응답의 `tools.listChanged`는 거짓이다 [3].
서버는 초기화 지침을 두지 않는다 [3].

서버는 리소스 `toolkit://about`과 프롬프트 4개를 둔다 [4][5].
리소스는 서버 기능, `SAFE_BASE` 설정, 기본 폴더를 적는다 [4].
프롬프트는 부를 도구와 인자, 결과로 판단할 내용을 적고 프롬프트 목록의 설명은 비어 있다 [5][3].
등록된 명세를 실행 설정이나 클라이언트에 따라 바꾸는 코드는 없다 [6].

**한계.** 다음 명세는 처리 코드의 동작과 다르다.
리소스 `toolkit://about`은 기본 폴더가 `~/Desktop`이라고 적지만 서버 코드에는 기본값이 없고 `SAFE_BASE`가 없으면 서버가 시작하지 않는다 [4][7].
`generate_forensic_report`의 설명은 파일의 수정 시각이 키워드가 들어 있는 로그 줄과 맞는지 확인한다고 적는다 [8].
처리 코드는 시각을 대조하지 않고 파일 이름이 로그 줄에 들어 있는지만 계산한다 [9].
`file_metadata`의 설명은 `SAFE_BASE` 폴더 안의 파일을 다룬다고 적는다 [10].
경로 대조는 문자열 접두어 비교라서 이름 앞부분이 같은 형제 폴더의 파일과 폴더 밖을 가리키는 링크도 받는다 [11].
프롬프트 `investigate-file`은 `file_metadata`가 생성 시각을 돌려준다고 적지만 `created_at`은 `st_ctime`이다 [5][12].
Python 3.11 문서는 `st_ctime`을 Unix에서 마지막 메타데이터 변경 시각으로 적는다 [13].
수정 시각을 2020년으로 바꾼 파일의 `created_at`은 바꾼 시점의 시각이었고 `modified_at`보다 늦었다 [14].

다음 명세는 처리 코드가 정한 범위를 적지 않는다.
`scan_syslog`의 설명은 최대 100줄을 돌려준다고 적지만 맞는 줄이 100줄을 넘으면 마지막 100줄을 돌려준다는 점은 적지 않는다 [15].
같은 설명은 macOS에서 `log show`로 찾는다고 적지만 `log show`에 넘기는 `--last 10m`은 적지 않는다 [15].
`hash_directory`의 설명은 폴더의 모든 파일을 해시한다고 적고 `SAFE_BASE`와 대조하지 않는다는 점은 적지 않는다 [16].
