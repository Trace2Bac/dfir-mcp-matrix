# T01 입력 검증

### T01.02 입력 존재·읽기 가능 검사

**구현.** 이 방식은 `hash_directory`의 `path`와 Linux에서 실행하는 `scan_syslog`에 적용된다 [1][2].
`hash_directory`는 `os.path.isdir`로 `path`가 폴더인지 먼저 보고 아니면 폴더를 훑지 않고 `error`에 `Provided path is not a directory.`를 담은 `dict`를 돌려준다 [1].
없는 경로와 파일 경로를 주자 모두 이 `error`가 돌아왔다 [3].
`scan_syslog`는 Linux에서 `/var/log/syslog`가 있는지 `os.path.exists`로 보고 없으면 파일을 열지 않고 `Log file '/var/log/syslog' not found.` 한 줄을 돌려준다 [2].
`/var/log/syslog`를 두지 않은 컨테이너에서 부르자 이 한 줄만 돌아왔다 [3].
두 도구 모두 읽기 권한은 미리 보지 않는다 [1][2].
`/var/log/syslog`를 서버 계정이 읽을 수 없게 두자 `Error reading logs: [Errno 13] Permission denied`로 시작하는 한 줄이 돌아왔다 [3].

`file_metadata`는 파일이 있는지 미리 보지 않는다 [4].
`os.stat`이나 `open`이 낸 예외 문구를 `error`에 담아 돌려준다 [4].
없는 파일, 폴더, 읽기 권한이 없는 파일을 주자 각각 `[Errno 2]`, `[Errno 21]`, `[Errno 13]`으로 시작하는 `error`가 돌아왔다 [3].

### T01.04 문자열 경로 검사

**구현.** 이 방식은 `file_metadata`의 `path`와 이 함수를 부르는 `correlate_file_and_logs`·`generate_forensic_report`의 `filename`에 적용된다 [5][6].
`is_safe_path`는 받은 경로와 `SAFE_BASE`를 각각 `os.path.abspath`로 절대 경로로 바꾼 뒤 받은 경로의 문자열이 `SAFE_BASE`의 문자열로 시작하는지 본다 [5].
Python 3.11의 `os.path.abspath`는 상대 경로이면 작업 폴더를 앞에 붙이고 `normpath`로 `..`과 겹친 구분자를 문자열로 정리하며 심볼릭 링크는 해석하지 않는다 [7].
시작하지 않으면 `file_metadata`는 파일을 열지 않고 `error`에 `Access denied: path is outside the allowed directory scope.`를 담아 돌려준다 [5].
`SAFE_BASE` 밖의 절대 경로와 `SAFE_BASE` 아래에서 `..`로 밖을 가리키는 경로를 주자 모두 이 `error`가 돌아왔다 [8].
상대 경로는 서버 프로세스의 작업 폴더를 기준으로 바꾼 뒤 대조한다 [5][7].
두 묶음 도구는 `file_metadata`의 `error`를 `File error: `를 붙여 돌려준다 [6].

`SAFE_BASE`는 환경변수나 `load_dotenv`가 읽은 `.env`에서 정한다 [9].
값이 없으면 서버 모듈을 불러올 때 `RuntimeError`가 나 서버가 시작하지 않는다 [9].
`SAFE_BASE` 없이 서버 모듈을 불러오자 `SAFE_BASE is not set`으로 시작하는 `RuntimeError`로 끝났다 [8].
README는 `SAFE_BASE`가 모든 파일 작업을 제한하고 모든 도구가 경로를 `SAFE_BASE`와 대조한다고 적는다 [10].
`hash_directory`의 `path`에는 이 대조가 없다 [1].
`SAFE_BASE` 밖의 폴더를 주자 그 폴더 아래 파일의 경로와 SHA-256이 돌아왔다 [8].
`scan_syslog`는 경로 인자를 받지 않는다 [11].

**한계.** 대조는 문자열 접두어 비교라서 경로 구분자의 경계를 보지 않는다 [5].
그래서 이름 앞부분이 `SAFE_BASE`와 같은 형제 폴더의 파일도 대조를 통과한다 [5].
그런 형제 폴더의 파일을 주자 거부되지 않고 크기, 시각, SHA-256이 돌아왔다 [8].
심볼릭 링크를 해석하지 않으므로 `SAFE_BASE` 안의 링크가 밖의 파일을 가리켜도 대조를 통과하고 `open`은 링크가 가리키는 파일을 연다 [5][7].
`SAFE_BASE` 안에 둔 링크가 밖의 파일을 가리키게 하고 그 링크를 주자 밖의 파일의 크기와 SHA-256이 돌아왔다 [8].
두 묶음 도구는 `file_metadata`가 경로를 대조하기 전에 `scan_syslog`를 먼저 불러 시스템 로그를 읽는다 [6].
`SAFE_BASE` 밖의 파일로 `correlate_file_and_logs`를 부르자 거부 응답이 돌아오기 전에 `scan_syslog`가 한 번 실행되었다 [12].

### T01.06 고정 입력 경로 사용

**구현.** 이 방식은 `scan_syslog`와 이 함수를 부르는 두 묶음 도구의 로그 읽기에 적용된다 [11][13].
`scan_syslog`는 경로 인자 없이 `keyword` 하나만 받는다 [11][14].
Linux에서는 코드에 적은 `/var/log/syslog` 한 파일을 읽고 macOS에서는 `log show`로 그 호스트의 로그를 읽는다 [11].
읽는 곳은 서버를 실행한 호스트이고 이 위치를 바꾸는 설정이나 인자는 없다 [11][9].
Linux에서는 `/var/log/syslog` 밖의 로그 파일을 읽지 않는다 [11].
`correlate_file_and_logs`는 `scan_syslog`를 불러 같은 로그를 읽고 `generate_forensic_report`는 `correlate_file_and_logs`를 부른다 [13].

[1] `hash_directory`는 폴더인지만 보고 `SAFE_BASE`와 대조하지 않고 폴더를 훑는다.

```python
@mcp.tool()
def hash_directory(path: str) -> dict:
    """
    Recursively compute SHA-256 hashes for all files in a directory.
    """
    if not os.path.isdir(path):
        return {"error": "Provided path is not a directory."}

    results = {}
    for root, _, files in os.walk(path):
        for f in files:
            full_path = os.path.join(root, f)
            try:
                with open(full_path, "rb") as fp:
                    content = fp.read()
                    results[full_path] = hashlib.sha256(content).hexdigest()
            except Exception as e:
                results[full_path] = f"Error: {str(e)}"
    return results
```
