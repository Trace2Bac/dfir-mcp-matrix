# T02 실행 허용 범위 제한

### T02.04 고정 명령·템플릿

**구현.** 이 방식은 `scan_syslog`가 macOS에서 실행하는 `log` 명령에 적용된다 [1].
서버 코드는 인자 목록을 `log`, `show`, `--predicate`, 술어 문자열, `--last`, `10m`의 6개로 정해 둔다 [1].
모델의 `keyword`는 술어 문자열 `eventMessage contains[c] "<keyword>"`의 큰따옴표 안에만 들어간다 [1].
서버는 이 목록을 셸 없이 `subprocess.run`에 넘기므로 `keyword`는 늘 술어 자리의 인자 하나가 되고 옵션 자리에 놓이지 않는다 [1][2].
`platform.system()`이 `Darwin`을 돌려주게 하고 받은 인자를 기록하는 시험용 `log`를 둔 시험에서 `--`로 시작하는 키워드를 주자 `log`가 받은 인자는 실행 파일 이름을 빼고 5개였고 키워드는 술어 안에만 있었다 [3].

모델은 실행할 명령이나 읽을 로그 원천을 고르지 못한다 [1].
Linux 경로와 다른 도구는 외부 명령을 실행하지 않고 서버 프로세스 안에서 파일을 읽는다 [4].
도구를 끄거나 작업을 좁히는 설정은 없다 [5].

**한계.** 서버는 `keyword`를 술어 문자열에 넣기 전에 따옴표나 술어 문법에 쓰이는 문자를 검사하거나 바꾸지 않는다 [1].
같은 시험에서 큰따옴표가 들어간 키워드를 주자 `log`가 받은 술어 문자열의 큰따옴표가 정해 둔 2개가 아니라 3개였다 [3].
그래서 술어 문자열의 구조는 모델이 준 값에 따라 바뀐다 [1][3].
macOS의 `log`가 이렇게 바뀐 술어를 어떻게 해석하는지는 실행하지 않아 확인하지 못했다 [3].

기록한 인자는 개수, 고정된 자리의 값, 술어가 정해 둔 꼴과 같은지, 술어 안 큰따옴표 수만 출력했다.
