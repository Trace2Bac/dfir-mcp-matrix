# E03 원본 변경 방지

### E03.02 서버 코드의 원본 쓰기 제한

**구현.** 이 방식은 서버 코드가 파일을 직접 여는 `scan_syslog`의 Linux 경로, `file_metadata`, `hash_directory`에 적용된다 [1][2][3].
이 서버에서 원본은 서버를 실행한 호스트의 시스템 로그와 도구 인자로 받은 파일이다 [1][2][3].
`scan_syslog`는 `/var/log/syslog`를 `"r"`로 열어 줄마다 키워드를 찾는다 [1].
`file_metadata`와 `hash_directory`는 파일을 `"rb"`로 열어 내용 전체를 읽는다 [2][3].
`correlate_file_and_logs`와 `generate_forensic_report`는 `scan_syslog`와 `file_metadata`를 불러 같은 방식으로 읽는다 [4].
서버 코드에는 파일을 쓰거나 지우거나 이름을 바꾸는 호출이 없다 [5].
시험 파일과 시험용 `/var/log/syslog`로 도구를 모두 부른 뒤 새로 생기거나 바뀐 파일이 없었다 [6].
저장소에는 증거를 읽기 전용으로 연결하거나 서버를 읽기 전용 환경에서 실행하는 실행 구성이 없다 [7].

### E03.03 외부 도구·플랫폼에 위임

**구현.** 이 방식은 macOS에서 `scan_syslog`가 실행하는 `log` 명령에 적용된다 [8].
서버는 `log show`에 술어 `--predicate`와 `--last 10m`을 붙인 인자 목록을 셸 없이 `subprocess.run`에 넘긴다 [8].
하위 명령 `show`와 다른 인자는 코드에 정해 두었고 모델이 준 `keyword`는 술어 문자열 안에만 들어간다 [8].
`platform.system()`이 `Darwin`을 돌려주게 바꾸고 시험용 `log` 실행 파일을 둔 시험에서 그 실행 파일이 받은 인자는 `show`, `--predicate`, 술어 문자열, `--last`, `10m`의 5개였다 [9].
통합 로그 저장소를 바꾸지 않는 것은 `log` 명령의 동작에 맡긴다 [8].

**한계.** Apple 문서는 `log` 도구가 명령줄에서 로그 메시지를 가져온다고만 적는다 [10].
`log`는 소스가 공개되지 않았고 `log show`가 통합 로그 저장소를 읽기만 하는지는 확인하지 못했다(실제 보호 미확인) [10].
