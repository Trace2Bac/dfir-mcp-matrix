# E01 증거 등록 관리

### 미구현

**판단.** 서버는 증거를 등록하는 도구를 두지 않고 증거를 식별하는 목록이나 등록 정보를 남기지 않는다.
`file_metadata`, `hash_directory`, `correlate_file_and_logs`, `generate_forensic_report`는 파일이나 폴더의 경로를 호출마다 인자로 받아 그 호출에서만 읽는다 [1].
`scan_syslog`는 Linux에서 코드에 정한 `/var/log/syslog`를 읽고 macOS에서 `log show`의 출력을 읽는다 [2].
`file_metadata`가 받는 경로는 환경변수 `SAFE_BASE`와 대조되지만 이 값은 읽을 수 있는 범위를 정하는 설정이고 증거 항목을 적은 것이 아니다 [3].

`file_metadata`는 파일 하나의 크기, 두 시각, SHA-256을 응답으로만 돌려준다 [4].
`hash_directory`는 받은 폴더 아래 파일마다 전체 경로를 키로 SHA-256을 담은 `dict`를 응답으로만 돌려준다 [5].
서버 코드에는 파일을 쓰는 호출이 없어 이 목록은 서버에 남지 않는다 [6][7].
같은 파일을 다시 넘기면 서버는 파일을 다시 읽어 새 응답을 만들고 앞선 호출을 가리키는 값을 싣지 않는다 [4][5].

```python
@mcp.tool()
def hash_directory(path: str) -> dict:
    """
    Recursively compute SHA-256 hashes for all files in a directory.
    """
    if not os.path.isdir(path):
        return {"error": "Provided path is not a directory."}

    results = {}
    for root, _, files in os.walk(path):
        for f in files:
            full_path = os.path.join(root, f)
            try:
                with open(full_path, "rb") as fp:
                    content = fp.read()
                    results[full_path] = hashlib.sha256(content).hexdigest()
            except Exception as e:
                results[full_path] = f"Error: {str(e)}"
    return results
```
