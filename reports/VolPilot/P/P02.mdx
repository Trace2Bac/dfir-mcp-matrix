# P02 다음 작업 결정

### P02.01 고정 문서·프로필 반환

**구현.** 이 방식은 서버의 초기화 지침에 적용된다 [1].
서버는 `FastMCP`를 만들 때 초기화 지침을 `instructions`로 등록한다 [1].
지침의 권장 절차는 세 단계다 [1].
첫 단계는 `windows_info`로 OS 정보와 이미지 SHA-256을 보는 것이다 [1].
둘째 단계는 `windows_pslist`로 프로세스를 보고 교차 분석 도구 `detect_hidden_processes`와 `detect_process_anomalies`로 분류하는 것이다 [1].
셋째 단계는 보고서를 만들기 전에 `verify_image_integrity`를 부르는 것이다 [1].
stdio로 서버를 시작해 초기화하자 이 지침이 `instructions`로 돌아왔다 [2].

도구 설명도 `Forensic context` 아래에 다음에 부를 도구를 적는다 [3].
`windows_info`의 설명은 이 도구를 먼저 부르고 이어서 `windows_pslist`를 부르라고 적는다 [3].
`detect_hidden_processes`의 설명은 숨은 프로세스마다 `triage_process`를 부르라고 적는다 [3].
절차는 모델에게 주는 글이고 서버는 모델이 그 순서를 따르는지 확인하지 않는다 [4].
`windows_info`의 설명은 이 도구를 먼저 불러야 설정이 만들어진다고 적지만 설정은 어느 플러그인이든 `run()`까지 처음 실행된 호출에서 저장된다 [3][5].

### P02.02 규칙·조사 상태로 추천

**구현.** 이 방식은 덤프 도구 2개와 `windows_strings`가 입력 조건을 채우지 못했을 때의 응답에 적용된다 [6][7].
`VOL_DUMP_DIR` 없이 시작한 서버에서 `windows_dumpfiles`와 `windows_pedump`는 플러그인을 실행하기 전에 예외로 끝난다 [6].
예외 문구는 덤프 도구를 부르기 전에 `claude_desktop_config.json`에서 `VOL_DUMP_DIR`을 기존 폴더로 정하라고 적는다 [6].
FastMCP는 이 예외를 도구 이름을 붙인 `isError` 응답으로 돌려준다 [8].
`windows_dumpfiles`를 부르자 `Error executing tool windows_dumpfiles: VOL_DUMP_DIR is not configured.`로 시작하는 오류 응답이 돌아왔다 [9].
`windows_strings`는 `strings_file`이 비었으면 플러그인을 실행하지 않고 빈 결과와 `error`를 돌려준다 [7].
`error`는 `strings -a -t d` 같은 도구로 오프셋이 붙은 문자열 목록 파일을 먼저 만들고 그 절대 경로를 주라고 적는다 [7].
이 문구는 응답의 글이고 서버가 다음 호출을 대신 고르지 않는다.
그 밖의 도구 응답은 플러그인 결과나 교차 분석 결과만 싣고 다음에 부를 도구를 싣지 않는다 [10].

### P02.04 서버 코드에 고정한 분석 절차

**구현.** 이 방식은 교차 분석 도구 7개에 적용된다 [10].
`detect_hidden_processes`는 `pslist`와 `psscan`을 실행하고 `pslist`에 없는 PID의 `psscan` 행을 숨은 프로세스로 모은다 [11].
`detect_process_anomalies`는 `pslist` 결과에 코드에 적은 부모 프로세스 표, 이름 편집 거리, 하나만 있어야 하는 프로세스, Session 0 프로세스의 규칙 4개를 적용한다 [12].
`triage_process`는 받은 PID가 `pslist`에 있으면 `cmdline`, `dlllist`, `handles`, `netscan`, `malware.malfind`를 실행해 그 PID의 행만 모은다 [13].
`detect_dll_injection`은 `malware.ldrmodules`, `malware.malfind`, `dlllist`를 실행하고 연결 목록에서 빠진 DLL과 `malfind` 영역을 징후로 모은다 [14].
`network_process_correlation`은 `netscan` 행마다 `pslist`의 프로세스 이름, 부모 PID, 생성 시각과 `cmdline`의 명령줄을 붙인다 [15].
`detect_service_tampering`은 `svcscan`과 `svclist`를 비교하고 `svclist` 결과가 있을 때만 `malware.svcdiff`를 더한다 [16].
`build_timeline`은 `pslist`, `psscan`, `netscan`, `shimcachemem`, `registry.userassist`의 시각을 사건으로 모아 시각 차례로 정렬한다 [17].
하위 플러그인 결과는 세션의 결과 캐시를 거치므로 앞서 실행한 플러그인은 다시 실행하지 않는다 [10][18].
모델은 도구와 PID만 고르고 그 안의 단계는 서버 코드가 정한다.
서버 안에서 모델을 불러 계획을 세우는 경로는 없다.

**한계.** `triage_process`와 `detect_dll_injection`은 `pslist`에 없는 PID를 받으면 나머지 단계를 실행하지 않고 `error`를 담은 결과를 돌려준다 [13][14].
`detect_hidden_processes`가 찾는 숨은 프로세스는 `pslist`에 없는 PID이고 그 설명은 숨은 프로세스마다 `triage_process`를 부르라고 적는다 [11][3].
시험용 플러그인 결과로 `detect_hidden_processes`가 찾은 PID 666을 `triage_process`에 주자 `PID 666 not found in pslist`가 돌아왔다 [19].
`detect_dll_injection`의 코드 설명은 `dlllist`와 `ldrmodules`의 모듈 수 차이를 세 번째 신호로 적지만 코드는 두 수를 응답에 싣기만 하고 징후로 만들지 않는다 [14].
`dlllist`에 3개, `ldrmodules`에 1개를 둔 시험에서 `injection_indicator_count`는 0이었다 [19].
`build_timeline`은 시각 문자열을 정해 둔 형식 4개로 해석하지 못하면 그 사건을 뺀다 [20].
Volatility 3 2.28.0은 Windows 시각을 UTC 시간대가 붙은 `datetime`으로 돌려주고 서버는 이를 `2019-04-17 18:40:00+00:00` 꼴의 문자열로 바꾼다 [21][22].
이 꼴의 생성 시각을 담은 시험용 `pslist` 결과로 `build_timeline`을 부르자 `total_events`가 0이었고 시간대를 뺀 같은 시각으로는 1이었다 [23].
도구 설명은 시각이 없는 사건만 뺀다고 적는다 [24].

```python
    def run_plugin(self, plugin_name: str, **kwargs) -> dict:
        """Run a plugin by name, returning cached results if available.

        Extra kwargs are forwarded to the plugin's runner function and used
        to key the cache, so calling the same parameterized plugin twice
        with identical arguments returns the cached result, while different
        arguments trigger a fresh run.
        """
        cache_key = (plugin_name, frozenset(kwargs.items())) if kwargs else plugin_name
        if cache_key in self._cache:
            return self._cache[cache_key]
        if plugin_name not in PLUGIN_MAP:
            raise ValueError(f"Unknown plugin: {plugin_name}")
        result = PLUGIN_MAP[plugin_name](self, **kwargs)
        self._cache[cache_key] = result
        return result
```

```python
def _parse_timestamp(val: str | None) -> str | None:
    """Normalize a Volatility3 timestamp string to ISO 8601, or None."""
    if not val or val == "N/A" or val == "None":
        return None
    val = val.strip()
    # Already ISO-ish: "2026-03-15 14:22:01.000000" → "2026-03-15T14:22:01"
    try:
        from datetime import datetime
        # Handle "YYYY-MM-DD HH:MM:SS.ffffff" (most common vol3 format)
        for fmt in ("%Y-%m-%d %H:%M:%S.%f", "%Y-%m-%d %H:%M:%S", "%Y-%m-%dT%H:%M:%S.%f", "%Y-%m-%dT%H:%M:%S"):
            try:
                dt = datetime.strptime(val, fmt)
                return dt.isoformat()
            except ValueError:
                continue
    except Exception:
        pass
    return None
```

```python
def _serialize_value(val: Any) -> Any:
    """Convert a volatility3 rendered value to a JSON-serializable type."""
    if isinstance(val, BaseAbsentValue):
        return None
    if isinstance(val, format_hints.Hex):
        return hex(val)
    if isinstance(val, format_hints.MultiTypeData):
        return _serialize_multitypedata(val)
    if isinstance(val, renderers.LayerData):
        return _serialize_layerdata(val)
    if isinstance(val, renderers.Disassembly):
        return _bytes_to_hex(val.data)
    if isinstance(val, bytes):
        # Covers format_hints.HexBytes too (a plain bytes subclass).
        return _bytes_to_hex(val)
    if isinstance(val, (int, float, bool, str)):
        return val
    return str(val)
```
