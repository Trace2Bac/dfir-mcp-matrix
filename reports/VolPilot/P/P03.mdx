# P03 조사 진척 판단

### P03.03 미조사 범위·생략 사유 보고

**구현.** 이 방식은 `detect_service_tampering`에 적용된다 [1].
`svclist` 결과가 비면 이 도구는 `os_compatible`을 거짓으로, `svclist_count`를 `null`로 두고 `svclist`와의 비교와 `malware.svcdiff` 실행을 건너뛴다 [1].
도구 설명은 `svclist`가 64비트 Windows 10 빌드 15063 이상에서만 동작한다고 적는다 [2].
그 설명은 `os_compatible`이 거짓이면 비교를 하지 못한 것이니 `svcscan` 결과만 쓰고 보고서에 그 한계를 적으라고 적는다 [2].
`svclist`를 빈 결과로 둔 시험에서 응답은 `os_compatible`이 거짓이고 `svclist_count`가 `null`이었다 [3].

이 보고는 그 호출 한 번의 범위에 그친다.
서버에는 대상별로 해야 할 작업 목록, 조사 단계, 완료 조건이 없고 모델이 진행 기록을 적는 도구도 없다 [4].

다음 도구는 다루지 못한 범위를 응답에 싣지 않는다.
`windows_crashinfo`는 이미지가 crash dump가 아니어서 플러그인이 특정 `RuntimeError`로 끝나면 사유 없이 빈 결과를 돌려준다 [5].
`windows_virtmap`은 `SymbolError`가 나면 사유 없이 빈 결과를 돌려준다 [6].
`build_timeline`은 시각을 해석하지 못한 사건을 빼고 뺀 사건 수를 싣지 않는다 [7].
응답의 `sources`는 타임라인에 넣은 사건만 종류별로 센 값이다 [7].

**한계.** `os_compatible`은 OS를 판별한 값이 아니라 `svclist` 결과가 비었는지이므로 `svclist`가 빈 결과를 내면 OS와 관계없이 거짓이 된다 [1].
`os_compatible`이 참이어도 `malware.svcdiff`가 예외로 끝나면 `svcdiff_results`를 빈 목록으로 두고 그 사실을 싣지 않는다 [1].
`malware.svcdiff`가 예외를 내게 한 시험에서 응답의 `svcdiff_results`는 빈 목록이었고 오류 표시는 없었다 [3].

### 근거

[1] `detect_service_tampering`은 `svclist` 결과의 건수로 `os_compatible`을 정하고 `malware.svcdiff`의 예외를 빈 목록으로 둔다.

```python
    svcscan_data = session.run_plugin("svcscan")
    svcscan_services = svcscan_data["results"]

    # Attempt svclist — may return empty on incompatible OS
    svclist_data = session.run_plugin("svclist")
    svclist_services = svclist_data["results"]

    os_compatible = len(svclist_services) > 0
```

```python
    Note: svclist requires 64-bit Windows 10 build 15063+. On older or
    32-bit systems, only svcscan results are returned and the comparison
    is unavailable (os_compatible will be false).

    Returns a dict with:
    - "plugin": "detect_service_tampering"
    - "results": {
        "svcscan_count": services found by pool scanning (int),
        "svclist_count": services found by list walk (int or null if
          OS-incompatible),
        "os_compatible": whether svclist produced results (bool),
        "hidden_count": services in svcscan but not svclist (int),
        "hidden_services": list of dicts with svcscan fields plus
          "source": "svcscan_only" (list),
        "svcdiff_results": output from malware.svcdiff if available (list)
      }

    Forensic context:
    - A non-zero hidden_count means service records were deliberately
      unlinked from SCM's doubly-linked list — strong rootkit evidence
    - Check the Binary field of hidden services to identify the malicious
      executable and cross-reference with windows_filescan or windows_dumpfiles
    - When os_compatible is false, the comparison cannot be performed;
      rely on svcscan alone and note the limitation in the report
```
