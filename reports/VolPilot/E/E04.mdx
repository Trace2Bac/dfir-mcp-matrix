# E04 분석 입력 준비

### E04.02 선택 추출

**구현.** 이 방식은 메모리에서 파일이나 PE를 꺼내 `VOL_DUMP_DIR`에 쓰는 `windows_dumpfiles`와 `windows_pedump`에 적용된다 [1][2].
`windows_dumpfiles`는 모델이 준 PID, 파일 이름 정규식, `_FILE_OBJECT`의 가상 주소나 물리 주소를 Volatility 3 `windows.dumpfiles` 플러그인의 설정으로 넘긴다 [1].
`windows_pedump`는 모델이 준 PE 기준 주소, PID, 커널 모듈 여부를 `windows.pedump` 플러그인의 설정으로 넘긴다 [2].
조건에 맞는 파일 객체나 PE를 찾고 그 바이트를 읽는 일은 Volatility 3가 한다 [1][2].
플러그인이 연 파일은 서버의 덤프 파일 처리기가 메모리에 모았다가 닫을 때 `VOL_DUMP_DIR` 아래에 쓴다 [3].
`VOL_DUMP_DIR` 없이 시작한 서버에서는 두 도구가 플러그인을 실행하기 전에 오류로 끝난다 [4][5].
두 도구의 설명은 꺼낸 파일을 IDA, Ghidra, YARA 같은 외부 도구로 분석하라고 적는다 [6].
서버는 꺼낸 파일을 다른 도구에 넘기지 않는다 [1][2].
응답에는 플러그인이 낸 표가 행마다 실리고 행의 `Result`나 `File output`은 쓴 파일 이름이나 실패 문구다 [1][2][7].
서버는 꺼낸 파일의 목록이나 개수를 따로 정리하지 않는다 [1][2].

나머지 도구는 분석 입력을 따로 준비하지 않는다.
이미지는 `VOL_IMAGE_PATH`의 경로를 `file://` URI로 바꿔 Volatility 3에 넘기고 사본을 만들지 않는다 [8].
`windows_strings`는 사용자가 미리 만든 문자열 목록 파일의 경로를 받아 플러그인 설정에 넘기고 그 파일을 만들지 않는다 [9].
Volatility 3 2.28.0은 이미지 이름이 `.vmem`으로 끝나면 같은 이름의 `.vmss`나 `.vmsn` 파일을 스스로 찾아 연다 [10].
서버 코드는 이런 부속 자료를 찾지 않는다 [8].

**한계.** `windows_dumpfiles`는 인자를 모두 기본값으로 두면 모델이 고른 조건 없이 플러그인을 실행한다 [1].
저장한 설정이 없으면 Volatility 3가 찾은 파일 객체를 모두 꺼낸다 [1].
도구 설명은 인자 없이 부르면 파일이 수백에서 수천 개 생길 수 있다고 적는다 [11].
저장한 설정에 `pid` 값이 있으면 인자를 비운 호출에도 그 값이 플러그인 설정으로 들어간다 [12].
이미지 옆 설정 파일에 `pid` 4만 적어 두고 인자 없이 덤프 플러그인을 실행하자 플러그인 설정의 `pid`는 4였다 [13].
