# F04 발견사항·결론 기록 관리

### 비적용

**판단.** 서버에는 발견사항, 결론, 가설, 단서 메모를 받아 남기는 도구가 없다.
도구 96개 가운데 81개는 인자가 없고 나머지 15개의 인자는 PID, 주소, 플러그인 선택지, 검색 패턴, YARA 규칙, 문자열 파일 경로 같은 실행 조건이다 [1].
발견사항이나 메모를 받는 인자는 없다 [1].

교차 분석 도구 7개가 만드는 판정은 응답으로만 돌려준다 [2].
`Session.run_plugin`은 도구 결과를 플러그인 이름과 인자로 만든 키로 프로세스 메모리의 `dict`에 두고 같은 호출에 다시 돌려준다 [2].
이 캐시는 플러그인과 교차 분석 함수의 결과만 담고 모델이 낸 발견사항을 받지 않는다 [2].
캐시는 프로세스 메모리에만 있어 서버를 다시 시작하면 남지 않는다 [2].
서버가 쓰는 파일은 덤프 도구가 `VOL_DUMP_DIR`에 쓰는 파일과 이미지 곁의 Volatility 3 설정 파일 `<이미지 경로>.vol3cfg.json`이다 [3][4].
두 파일 모두 증거에서 꺼낸 자료나 플러그인 설정을 담고 발견사항을 담지 않는다 [3][4].

### 근거

[1] (실행 확인) 무작위 바이트 파일을 이미지로 주어 서버를 stdio로 실행하고 MCP SDK 1.27.0 클라이언트로 도구 96개의 입력 schema 인자 이름을 모았다.
인자가 있는 도구는 15개였고 인자 이름은 `pid`, `base`, `kernel_module`, `filter`, `filter_ignore_case`, `virtaddr`, `physaddr`, `physical_offsets`, `pattern`, `maxsize`, `yara_rule`, `strings_file`, `no_registry`, `source`, `module`, `symbols`, `addresses` 17가지였다.

[2] `Session.run_plugin`은 결과를 프로세스 메모리의 캐시에 둔다.

```python
    def run_plugin(self, plugin_name: str, **kwargs) -> dict:
        """Run a plugin by name, returning cached results if available.

        Extra kwargs are forwarded to the plugin's runner function and used
        to key the cache, so calling the same parameterized plugin twice
        with identical arguments returns the cached result, while different
        arguments trigger a fresh run.
        """
        cache_key = (plugin_name, frozenset(kwargs.items())) if kwargs else plugin_name
        if cache_key in self._cache:
            return self._cache[cache_key]
        if plugin_name not in PLUGIN_MAP:
            raise ValueError(f"Unknown plugin: {plugin_name}")
        result = PLUGIN_MAP[plugin_name](self, **kwargs)
        self._cache[cache_key] = result
        return result
```
