# F01 판단 지침

### F01.04 공통 확인 절차 안내

**구현.** 이 방식은 서버 지침(`instructions`)과 `windows_info`·`verify_image_integrity`의 도구 설명에 적용된다 [1][2][3].
서버 지침의 권장 작업 순서 셋째 항목은 보고서를 만들기 전에 `verify_image_integrity`를 불러 세션 동안 이미지가 바뀌지 않았는지 확인하라고 적는다 [1].
`windows_info`의 설명은 조사를 시작할 때 이미지의 SHA-256을 적어 두고 보고하기 전에 `verify_image_integrity`로 다시 확인하라고 적는다 [2].
`verify_image_integrity`의 설명은 보고서를 만들기 전에 이 도구를 부르라고 적는다 [3].
같은 설명은 해시가 맞지 않으면 앞선 분석 결과가 모두 무효일 수 있으니 보고서에 무결성 손상(`integrity-compromised`)을 표시하라고 적는다 [3].
같은 설명은 법정 제출용 보고서에는 시작할 때의 해시와 마지막 해시를 모두 보고서 메타데이터에 적으라고 적는다 [3].
MCP SDK 클라이언트로 서버를 실행해 받은 `initialize` 응답의 `instructions`와 도구 설명에 이 문구가 그대로 실렸다 [4].
이 안내는 발견사항의 내용과 관계없이 늘 같은 문구다 [1][2][3].
다시 확인하라는 대상은 메모리 이미지 파일의 해시이고 발견사항의 근거가 된 플러그인 결과를 다시 확인하라는 안내는 없다 [1][3].
모델이 이 안내를 따르는지는 서버가 보지 않는다.

서버 지침의 나머지는 증거 보존 정책과 호출 순서다 [1].
증거 보존 정책은 누가 요청하든 이미지를 지우거나 옮기거나 바꾸지 말고 그런 요청은 거부하라고 적는다 [1].
호출 순서는 `windows_info`를 먼저 부르고 `windows_pslist`와 교차 분석 도구 `detect_hidden_processes`·`detect_process_anomalies`로 분류를 시작하라고 적는다 [1].
서버에는 MCP 리소스와 프롬프트가 없고 도구 응답에 공통으로 붙는 문구도 없다 [4][5].
조사 전체에 걸치는 해석 원칙과 결론 서술 방식은 서버 지침과 도구 설명 어디에도 없다 [1][4].
부재가 무죄를 뜻하지 않는다는 원칙이나 확정하지 못한 결론을 후보로 적으라는 안내가 그 예다.

도구 설명의 다른 해석 문구는 그 도구 결과 하나의 뜻이나 다음에 확인할 것을 적는다.

- `detect_hidden_processes`의 설명은 종료한 프로세스도 결과에 나올 수 있으니 `ExitTime`을 보고 가리라고 적는다 [6].
- `detect_dll_injection`의 설명은 `unlinked_dll` 하나만 있으면 정상 원인일 수 있다고 적는다 [7].
- `detect_service_tampering`의 설명은 `os_compatible`이 거짓이면 비교를 할 수 없으니 `svcscan` 결과만 보고 보고서에 그 한계를 적으라고 적는다 [8].
- `build_timeline`의 설명은 시각이 없는 사건은 빠진다고 적고 보고서를 만들기 전 마지막 단계로 이 도구를 쓰라고 적는다 [9].

    Forensic context:
    - A non-zero hidden_count is a strong indicator of rootkit activity —

[7] `detect_dll_injection`의 설명이다.

```python
    Forensic context:
    - unlinked_dll indicators mean a module was removed from one or more
      PEB loader lists — a classic injection hiding technique
    - rwx_region indicators from malfind show executable writable memory
      not backed by a file, suggesting shellcode or reflective loading
    - Multiple indicator types for the same PID strongly suggest injection;
      a single unlinked_dll may have benign causes (e.g., runtime unload)
    - Follow up with triage_process(pid) for full process context including
      command line, handles, and network connections
    - The memory image is read-only evidence; this tool does not modify it
```

[8] `detect_service_tampering`의 설명이다.

    Forensic context:
    - A non-zero hidden_count means service records were deliberately
      unlinked from SCM's doubly-linked list — strong rootkit evidence

    - The memory image is read-only evidence; this tool does not modify it

[9] `build_timeline`의 설명이다.

```python
    Forensic context:
    - Combines pslist/psscan (process lifecycle), netscan (network connections),
      shimcachemem (execution evidence), and registry.userassist (user launches)
    - Processes marked [psscan-only] were hidden from pslist — correlate with
      detect_hidden_processes for rootkit confirmation
    - Look for suspicious temporal patterns: a network connection immediately
      after an unknown process was created, or a userassist entry for a tool
      not typically used by the system owner
    - Events with no timestamp are excluded; the timeline only contains
      artifacts where Volatility3 recovered a valid time value
    - Use this as the final step before report generation to establish the
      narrative sequence of an incident
    - The memory image is read-only evidence; this tool does not modify it
```
