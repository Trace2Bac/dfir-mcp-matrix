# T07 도구 부재 처리

### T07.01 실행 전 도구·참조 자료 가용성 검사

**구현.** 이 방식은 선택 의존성 `yara-python`(또는 `yara-x`)이 필요한 도구 6개와 `pycryptodome`이 필요한 도구 3개에 적용된다 [1][2][3].
플러그인 모듈은 그 의존성을 불러오는 Volatility 플러그인 모듈을 `try`로 불러오고 `ImportError`가 나면 `_HAS_YARA`나 `_HAS_PYCRYPTODOME`을 거짓으로 둔다 [1][2].
이 값이 거짓이면 그 실행 함수를 `PLUGIN_MAP`에 넣지 않는다 [1][2].
`mcp_server.py`는 이름이 `PLUGIN_MAP`에 있을 때만 그 도구에 `@mcp.tool()`을 붙인다 [3].
그래서 의존성이 없으면 그 도구는 등록되지 않아 모델이 부를 수 없다 [3].
확인은 서버가 모듈을 불러올 때 한 번 하고 호출마다 다시 하지 않는다 [1][2].
`yara`와 `yara_x`를 불러오지 못하게 한 프로세스에서는 도구가 90개였고 `windows_vadyarascan`, `windows_mftscan` 3개, `windows_malware_direct_system_calls`, `windows_malware_indirect_system_calls`가 빠졌다 [4].
`Crypto`와 `Cryptodome`을 막자 `windows_registry_hashdump`, `windows_registry_lsadump`, `windows_registry_cachedump`가 빠진 93개였고 둘 다 막자 87개였다 [4].
서버는 빠진 도구를 응답이나 표준 오류로 알리지 않는다 [3][4].
빠진 도구의 설명에는 선택 의존성이 없으면 등록되지 않는다고 적혀 있지만 이 설명은 등록된 경우에만 모델에게 보인다 [5].

다른 의존성과 참조 자료에는 이 확인이 없다.
`capstone`은 확인하지 않아 `capstone`을 막아도 도구 96개가 모두 등록되었다 [4].
서버는 플러그인을 실행하기 전에 Windows 심볼이 있는지 확인하지 않는다 [6].
Volatility 2.28.0은 automagic 단계에서 심볼을 찾고 없으면 Microsoft 심볼 서버에서 PDB를 받아 변환한다 [7].
요구 사항을 채우지 못하면 Volatility가 플러그인을 만들 때 `PluginRequirementException`을 내고 FastMCP는 이를 `isError`가 참인 응답으로 돌려준다 [8][9].
무작위 바이트 이미지로 부른 플러그인 도구는 모두 `The plugin configuration failed to validate` 오류였고 서버의 표준 오류에는 `No suitable kernels found during pdbscan`이 남았다 [10].
`windows_virtmap`은 Volatility가 필요한 커널 심볼을 찾지 못해 `SymbolError`를 내면 빈 `results`를 돌려주고 그 사실을 싣지 않는다 [11][12].

**한계.** `windows_malware_direct_system_calls`와 `windows_malware_indirect_system_calls`는 `capstone`도 있어야 결과를 낸다 [13][14].
Volatility 2.28.0의 `direct_system_calls`는 `capstone`이 없으면 경고를 기록하고 행 없이 끝난다 [13].
서버는 이 경우 빈 `results`를 성공 응답으로 돌려준다 [15].
두 도구의 설명은 이 동작을 적는다 [14].

### T07.08 일부 제외 후 계속 실행

**구현.** 이 방식은 `detect_service_tampering`에 적용된다 [16].
이 도구는 `svcscan` 결과를 얻은 뒤 `svclist`를 실행한다 [16].
`svclist` 결과가 비면 이 플러그인을 쓸 수 없는 OS로 보고 `os_compatible`을 거짓으로 둔다 [16].
그 경우 두 목록의 대조와 `malware.svcdiff` 실행을 빼고 `svcscan` 건수만 담아 돌려준다 [16].
Volatility 2.28.0의 `svclist`는 64비트 Windows 10 15063 이상이 아니면 경고를 기록하고 행 없이 끝난다 [17].
가짜 결과로 `svclist`를 비우자 `malware.svcdiff`는 불리지 않았고 `os_compatible`이 거짓, `svclist_count`가 `null`인 결과가 돌아왔다 [18].

**한계.** `svclist` 결과가 빈 이유를 구분하지 않으므로 지원하는 OS에서 행이 0개인 경우도 같은 결과가 된다 [16].
`malware.svcdiff`에서 어떤 예외가 나도 서버는 그 예외를 처리하고 `svcdiff_results`를 빈 `list`로 둔다 [16].
응답에는 `svcdiff`가 실패했다는 사실이 없다 [16].
가짜 `malware.svcdiff`가 예외를 내게 하자 `svcdiff_results`가 빈 `list`이고 오류 표시가 없는 결과가 돌아왔다 [18].

```python
def run_virtmap(session: Session) -> dict:
    """Run windows.virtmap and return virtual mapped sections.

    Some Windows builds' kernel PDB lacks both symbols volatility3 knows
    how to read the system VA layout from (MiVisibleState,
    MiSystemVaType); the plugin raises SymbolError uncaught in that case
    instead of returning empty like similarly version-gated plugins
    (e.g. svclist). Caught here and translated into an empty result.
    """
    try:
        treegrid = run_plugin(session, virtmap.VirtMap)
    except exceptions.SymbolError:
        return {"plugin": "virtmap", "results": []}
    return {"plugin": "virtmap", "results": parse_treegrid(treegrid)}
```
