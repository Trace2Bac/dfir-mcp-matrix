# T02 실행 허용 범위 제한

### T02.04 고정 명령·템플릿

**구현.** 이 방식은 도구 96개 가운데 Volatility 플러그인을 실행하는 도구 95개에 적용된다 [1][2].
도구 함수마다 실행 함수 이름을 코드에 정해 `session.run_plugin`에 넘긴다 [1].
실행 함수는 플러그인 클래스 하나를 코드에 정해 두고 받은 인자를 그 플러그인의 설정 이름(`pid`, `pattern`, `yara_string` 등)에 넣는다 [2][3].
모델은 플러그인 이름이나 설정 이름을 고르지 못하고 그 설정 값만 채운다 [1][3].
`Session.run_plugin`은 받은 이름을 `PLUGIN_MAP`에서 찾고 없으면 `ValueError`로 거부하지만 이 이름은 모두 도구 함수에 적힌 상수다 [4][1].
Volatility는 서버 프로세스 안에서 라이브러리로 실행되므로 인자가 명령 줄 옵션으로 읽히는 경로는 없다 [3].
`verify_image_integrity`는 플러그인을 실행하지 않고 서버 코드로 이미지 해시를 다시 계산한다 [5].

교차 분석 도구 7개도 실행할 플러그인과 차례를 코드에 정해 둔다 [6].
`triage_process`와 `detect_dll_injection`이 받는 `pid`는 플러그인 설정에 넣지 않고 결과를 거르는 데만 쓴다 [6].

설정 값 가운데 세 인자는 모델이 쓴 정규식이나 룰 글이다 [3].
`windows_vadregexscan`의 `pattern`은 정규식으로, `windows_vadyarascan`의 `yara_rule`은 YARA 룰 글이나 문자열로, `windows_dumpfiles`의 `filter`는 파일 이름 정규식으로 그대로 들어간다 [3].
서버 코드는 이 값의 구조나 크기를 검사하지 않는다 [3].

### T02.08 설정으로 도구 끄기

**구현.** 이 방식은 추출 파일을 쓰는 `windows_dumpfiles`와 `windows_pedump`에 적용된다 [7][8].
두 도구의 실행 함수는 플러그인에 넘길 파일 처리기를 `session.file_handler`에서 얻는다 [7].
사용자가 환경변수 `VOL_DUMP_DIR`를 정하지 않으면 이 속성이 `RuntimeError`를 내므로 플러그인은 실행되지 않는다 [8][9].
`VOL_DUMP_DIR` 없이 시작한 서버에서 두 도구를 부르자 `VOL_DUMP_DIR is not configured`로 시작하는 오류가 돌아왔다 [10].
두 도구는 이 값이 없어도 도구 목록에 남는다 [10].
다른 도구를 끄는 설정이나 인자는 없다 [9][11].

```python
    @property
    def file_handler(self):
        """FileHandler class bound to ``dump_dir`` for use with dump plugins.

        Raises RuntimeError if ``VOL_DUMP_DIR`` was not set when the server
        started, so the Claude-visible MCP tool can return a clear message.
        """
        if self._file_handler is None:
            raise RuntimeError(
                "VOL_DUMP_DIR is not configured. Set the VOL_DUMP_DIR "
                "environment variable in claude_desktop_config.json to "
                "an existing directory before calling any dump tool."
            )
        return self._file_handler
```
