# T04 실행 방식

### T04.01 서버 프로세스 안 분석

**구현.** 이 방식은 서버의 모든 도구에 적용된다 [1][2].
서버는 Volatility 3 2.28.0을 Python 라이브러리로 불러 플러그인 클래스를 서버 프로세스 안에서 만들고 실행한다 [1].
공통 함수 `run_plugin`은 automagic을 실행해 계층과 심볼을 정한 뒤 플러그인 객체를 만들고 `run()`이 돌려준 결과 표를 서버 코드가 `dict`의 `list`로 바꾼다 [1].
`Session`은 서버를 시작할 때 Volatility 문맥 `contexts.Context` 하나를 만들고 모든 도구 호출이 그 문맥을 함께 쓴다 [2].
교차 분석 도구 7개는 플러그인 결과를 서버 코드로 대조하고 `verify_image_integrity`는 서버 코드로 이미지 해시를 계산한다 [3][4].
추출 도구가 쓰는 파일도 서버 프로세스 안의 파일 처리기가 `VOL_DUMP_DIR`에 쓴다 [5].

서버 코드에는 하위 프로세스를 실행하는 곳이 없다 [6].
서버는 Volatility의 병렬 처리 설정을 바꾸지 않고 Volatility 2.28.0의 기본값은 `Parallelism.Off`다 [6][7].
Volatility 2.28.0은 맞는 Windows 심볼이 없으면 Microsoft 심볼 서버에서 PDB를 받아 변환하는데 이 처리도 플러그인을 실행하는 서버 프로세스 안에서 일어난다 [8].
그래서 분석은 서버와 같은 계정, 메모리, 파일, 네트워크 권한으로 실행된다.

    def _compute_sha256(file_path: str) -> str:
        """Compute SHA-256 hash of a file, reading in 64 KiB chunks."""
        h = hashlib.sha256()
        with open(file_path, "rb") as f:
            while chunk := f.read(65536):
                h.update(chunk)
        return h.hexdigest()
