# T10 도구 명세 구성

### T10.01 처리 함수에서 명세 생성

**구현.** 이 방식은 서버가 등록하는 도구 96개 모두에 적용된다 [1].
서버는 도구 함수마다 `@mcp.tool()`만 붙이고 이름, 설명, 입력 schema를 따로 주지 않는다 [1].
MCP Python SDK 1.27.0의 FastMCP는 함수 이름을 도구 이름으로, docstring 전체를 설명으로 쓰고 함수 서명에서 입력 schema를 만든다 [2].
docstring은 `Use this tool when the user asks about:`, `Returns a dict with:`, `Forensic context:` 단락으로 쓰여 있고 인자가 있는 도구는 `Arguments:`나 `Args:` 단락도 둔다 [3].
실행 확인에서 도구는 96개였고 설명이 빈 도구는 없었다 [4].
입력 schema가 있는 도구는 15개이고 인자마다 `title`, 자료형, 기본값만 싣는다 [4].
출력 schema와 도구 annotation은 없고 초기화 응답의 `tools.listChanged`는 거짓이다 [4].
서버는 리소스와 프롬프트를 두지 않고 `FastMCP`를 만들 때 서버 지침 `instructions`를 준다 [5][4].

선택 의존성이 없으면 도구 9개는 등록되지 않는다 [6].
`mcp_server.py`는 그 도구 함수를 `if "<이름>" in PLUGIN_MAP:` 아래에 두고 이 조건이 참일 때만 `@mcp.tool()`을 붙인다 [6].
`yara`와 `pycryptodome`을 불러오지 못하게 한 프로세스에서 도구는 87개였고 등록된 도구의 이름, 설명, schema를 바꾸는 다른 설정은 없다 [4][7].

**한계.** 다음 도구는 설명이 알리는 것과 처리 코드의 동작이 다르다.

`pid`를 받는 도구 가운데 4개의 설명은 `pid`가 0이면 모든 프로세스를 본다고 적는다 [8].
실행 함수는 `pid`가 0이 아닐 때만 그 값을 Volatility 설정에 넣고 0이면 아무것도 넣지 않는다 [9].
공통 함수 `run_plugin`은 저장된 설정이 있으면 플러그인을 실행할 때마다 그 플러그인의 설정 위치를 저장된 설정으로 바꾼 뒤 받은 값을 넣는다 [10][11].
저장된 설정은 그 이미지에서 `run()`까지 처음 실행된 플러그인의 `build_configuration()` 결과이고 Volatility 2.28.0의 이 함수는 그 호출의 인자 값도 모은다 [10][12].
그래서 그 호출에 `pid`가 있었으면 그 뒤 `pid`를 0으로 준 호출과 `pid` 인자가 없는 도구의 플러그인도 그 `pid`를 설정으로 받는다 [10][12].
Volatility 2.28.0의 `hollowprocesses`, `malfind`, `pslist`는 설정의 `pid`로 프로세스를 거른다 [13].
저장된 설정의 `pid`가 999 하나가 들어간 목록인 세션에서 `malware.hollowprocesses`를 `pid` 1234로 부른 뒤 `pid` 없이 부르자 설정 `plugins.HollowProcesses.pid`와 이어서 부른 `pslist`의 `plugins.PsList.pid`가 모두 999 하나가 들어간 목록이었다 [14].
저장된 설정은 `<이미지 경로>.vol3cfg.json`에 남아 서버를 다시 시작해도 같은 이미지에 다시 적용된다 [15][11].
`pid`만 적은 설정 파일을 두고 시작하자 `pslist`, `malware.malfind`, `malware.hollowprocesses`의 설정 `pid`가 모두 그 값이었다 [16].
저장된 설정이 아직 없는 세션에서는 같은 Volatility 문맥에 앞선 호출이 넣은 값이 같은 플러그인의 다음 호출에 남는다 [10][11].
이런 세션에서 `windows_malware_hollowprocesses`를 `pid` 1234로 부른 뒤 0으로 부르자 설정 `plugins.HollowProcesses.pid`는 1234 하나가 들어간 목록으로 남았다 [16].
`windows_malware_psxview`의 `physical_offsets`도 참으로 부른 뒤 거짓으로 부르자 설정이 참으로 남았다 [16].
`windows_dumpfiles`의 설명은 0이나 빈 값을 주면 그 인자를 쓰지 않는다고 적지만 이 도구의 인자도 같은 방식으로 설정에 넣는다 [17][9].

`windows_pedump`의 설명은 `pid`를 기본값 0인 선택 인자로 적고 `kernel_module`이 참이면 `pid`를 쓰지 않는다고 적는다 [18].
Volatility 2.28.0의 `pedump`는 `pid`와 `kernel_module`이 함께 있거나 함께 없으면 오류를 기록하고 행 없이 끝난다 [19].
그래서 `pid` 0과 `kernel_module` 거짓, `pid`와 `kernel_module` 참의 두 조합은 빈 `results`를 돌려준다 [19][9].

`detect_hidden_processes`의 설명은 숨은 프로세스마다 `triage_process(pid)`를 부르라고 적는다 [20].
`triage_process`는 `pslist`에 없는 `PID`를 거부하고 숨은 프로세스는 `pslist`에 없는 `PID`다 [21].
가짜 결과로 `detect_hidden_processes`가 돌려준 `PID`를 `triage_process`에 주자 `not found in pslist` 오류가 돌아왔다 [22].

`detect_dll_injection`의 설명은 `rwx_region`을 실행과 쓰기가 함께 허용된 메모리로 적는다 [23].
처리 코드는 `malware.malfind`의 행을 보호 속성과 관계없이 모두 `rwx_region`으로 넣는다 [24].
Volatility 2.28.0의 `malfind`는 쓰기 권한이 없는 실행 영역도 바뀐 페이지가 있으면 결과로 낸다 [25].

`build_timeline`의 설명은 플러그인 다섯 개의 시각을 ISO 8601로 바꿔 시간순으로 싣고 시각이 없는 사건만 뺀다고 적는다 [26].
Volatility 2.28.0은 Windows 시각을 UTC 시간대가 붙은 `datetime`으로 내고 서버는 이 값을 `str`로 바꿔 `results`에 담는다 [27][28].
`_parse_timestamp`가 대조하는 네 형식에는 시간대 표기가 없어 `+00:00`이 붙은 값은 `None`이 되고 그 사건은 빠진다 [29].
Volatility 2.28.0에서 다섯 원천의 시각 열은 모두 이 `datetime`이므로 `build_timeline`은 Volatility가 낸 결과로는 사건을 하나도 만들지 않는다 [27][30].
Volatility의 시각 변환 함수가 낸 값을 서버의 변환 함수에 넣자 `2024-01-17 21:20:00+00:00`이 되었고 `_parse_timestamp`는 `None`을 돌려주었다 [31].
`shimcachemem` 사건을 만들 때 `name`은 `Path` 열에서 읽지만 Volatility 2.28.0의 열 이름은 `File Path`다 [32][33].
`File Path`가 있는 가짜 행으로 부르자 그 사건의 `name`은 빈 문자열이었다 [31].

다음 도구는 설명이 적은 값과 응답 값이 다르다.

- `windows_malware_malfind`, `windows_malware_ldrmodules`, `windows_malware_drivermodule`, `windows_malware_skeleton_key_check`의 설명은 `plugin` 값을 `malware.` 없이 적지만 응답의 `plugin`은 `malware.`로 시작한다 [34].
- `windows_vadregexscan`의 설명은 `Hex`를 바이트 객체의 `repr` 글로 적지만 서버는 바이트 값을 16진 문자열로 바꾼다 [35][36].
- `windows_info`와 `verify_image_integrity`의 설명은 이미지 경로를 절대 경로로 적지만 응답에는 `VOL_IMAGE_PATH`의 값이 그대로 실린다 [37].
- `VOL_IMAGE_PATH`를 상대 경로로 주자 `verify_image_integrity`의 `image_path`도 그 상대 경로였다 [38].
- `windows_dumpfiles`의 `Result`와 `windows_pedump`의 `File output`은 설명이 추출 파일의 최종 경로(`final on-disk path`)라고 적지만 응답에는 폴더 없이 Volatility가 지은 파일 이름이 실리고 서버가 번호를 붙여 쓴 경우에도 번호가 없는 이름이 실린다 [39].

```python
def run_malware_hollowprocesses(session: Session, pid: int = 0) -> dict:
    """Run windows.malware.hollowprocesses to detect process hollowing.

    pid: optional filter to a single process ID. 0 (default) inspects every process.
    """
    extra: dict = {}
    if pid:
        extra["pid"] = [pid]
    treegrid = run_plugin(session, hollowprocesses.HollowProcesses, extra_config=extra or None)
    return {"plugin": "malware.hollowprocesses", "results": parse_treegrid(treegrid)}
```

```python
def _parse_timestamp(val: str | None) -> str | None:
    """Normalize a Volatility3 timestamp string to ISO 8601, or None."""
    if not val or val == "N/A" or val == "None":
        return None
    val = val.strip()
    # Already ISO-ish: "2026-03-15 14:22:01.000000" → "2026-03-15T14:22:01"
    try:
        from datetime import datetime
        # Handle "YYYY-MM-DD HH:MM:SS.ffffff" (most common vol3 format)
        for fmt in ("%Y-%m-%d %H:%M:%S.%f", "%Y-%m-%d %H:%M:%S", "%Y-%m-%dT%H:%M:%S.%f", "%Y-%m-%dT%H:%M:%S"):
            try:
                dt = datetime.strptime(val, fmt)
                return dt.isoformat()
            except ValueError:
                continue
    except Exception:
        pass
    return None
```
