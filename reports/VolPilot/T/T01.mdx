# T01 입력 검증

### T01.01 인자 구조·값 검사

**구현.** 이 방식은 서버 코드가 `windows_strings`의 `strings_file`과 `windows_pe_symbols`의 `addresses`에 하는 값 검사에 적용된다 [1][2].
이와 별도로 MCP Python SDK 1.27.0의 FastMCP는 모든 도구에서 도구 함수의 서명으로 만든 pydantic 모델로 인자를 검사하고 맞지 않으면 함수를 부르지 않고 `Error executing tool`로 시작하는 오류를 돌려준다 [3].
`windows_malware_hollowprocesses`의 `pid`에 문자열 `abc`를 주자 `int_parsing` 오류가 돌아왔다 [4].

`windows_strings`는 `strings_file`이 빈 문자열이면 플러그인을 실행하지 않고 빈 `results`와 `error` 문구를 돌려준다 [1].
`strings_file` 없이 부르자 `isError`가 거짓이고 문자열 파일을 먼저 만들라는 `error`가 담긴 응답이 돌아왔다 [4].
`windows_pe_symbols`는 `addresses`를 쉼표로 나누고 조각마다 `int(..., 0)`으로 정수로 바꾼 뒤 플러그인을 부른다 [2].
정수로 읽히지 않는 조각이 있으면 이 변환에서 난 `ValueError`로 끝나고 플러그인은 실행되지 않는다 [2][5].
`addresses`에 `zz`를 주자 `invalid literal for int() with base 0` 오류가 돌아왔다 [4].

다른 인자는 서버 코드가 값을 보지 않고 Volatility 플러그인 설정에 넣는다 [6].
`pid`, `base`, `virtaddr`, `physaddr`, `maxsize`는 범위를 보지 않는다 [6].
`pid`에 -1을 주자 서버 코드에서 거부되지 않고 Volatility 플러그인을 만드는 단계까지 실행되었다 [4][7].
`windows_vadregexscan`의 `pattern`, `windows_vadyarascan`의 `yara_rule`, `windows_dumpfiles`의 `filter`는 꼴을 보지 않고 넘긴다 [6].
`windows_pe_symbols`의 설명은 `source`에 `kernel`이나 `processes`를 주라고 적고 서버 코드는 이 값을 대조하지 않는다 [2][8].
Volatility 2.28.0의 `pe_symbols`는 `source`를 두 값 가운데 하나를 고르는 요구 사항으로 정의한다 [9].
`windows_pedump`의 `pid`와 `kernel_module`의 조합도 서버 코드가 보지 않는다 [10].
Volatility 2.28.0의 `pedump`는 두 값이 모두 있거나 모두 없으면 오류를 기록하고 행 없이 끝난다 [11].

### T01.02 입력 존재·읽기 가능 검사

**구현.** 이 방식은 `triage_process`와 `detect_dll_injection`의 `pid`에 적용된다 [12].
두 도구는 먼저 `pslist` 결과에서 같은 `PID`를 찾고 없으면 다른 플러그인을 실행하지 않는다 [12].
그때는 `results`에 `pid`와 `PID <번호> not found in pslist` 문구를 담은 `error`를 넣어 돌려준다 [12].
이 확인을 하려고 `pslist` 플러그인은 실행한다 [12].
가짜 `pslist` 결과를 주고 목록에 없는 `pid`로 두 함수를 부르자 `pslist`만 실행되고 `error`가 담긴 결과가 돌아왔다 [13].

`windows_strings`의 `strings_file`은 파일이 있는지 서버가 확인하지 않는다 [1].
Volatility가 그 파일을 연다 [14].

**한계.** 대조 대상은 `pslist`가 연결 목록을 따라 찾은 프로세스뿐이다 [12].
`detect_hidden_processes`가 숨은 프로세스로 돌려주는 것은 `psscan`에 있고 `pslist`에 없는 `PID`다 [15].
그래서 그 `PID`로 두 도구를 부르면 이 확인에서 거부된다 [12][15].
가짜 결과로 `detect_hidden_processes`가 돌려준 `PID`를 두 함수에 주자 모두 `not found in pslist` 오류가 돌아왔다 [16].

### T01.06 고정 입력 경로 사용

**구현.** 이 방식은 메모리 이미지를 읽는 플러그인 도구 88개와 교차 분석 도구 7개, `verify_image_integrity`에 적용된다 [17][18].
사용자는 서버를 시작할 때 환경변수 `VOL_IMAGE_PATH`로 이미지 하나를 정한다 [17].
값이 없거나 그 경로가 파일이 아니면 서버는 시작하지 않고 종료 코드 1로 끝난다 [17].
`Session`은 이 경로를 `file` URI로 바꿔 Volatility 설정 `automagic.LayerStacker.single_location`에 넣고 모든 플러그인 실행이 이 설정을 쓴다 [18].
도구의 입력 schema에는 이미지 경로를 받는 인자가 없다 [4].
이미지를 바꾸는 도구도 없어 다른 이미지를 읽으려면 서버를 다시 시작해야 한다 [17][18].

모델이 경로를 주는 도구는 `windows_strings` 하나다 [1].
`strings_file`은 `Path.resolve`로 실제 경로로 바꾼 `file` URI로 Volatility에 넘기고 서버는 허용 폴더나 금지 폴더와 대조하지 않는다 [1].

**한계.** Volatility 2.28.0의 `build_configuration`은 메모리 계층의 `location` 값도 모으므로 서버가 이미지 옆에 저장하는 `.vol3cfg.json`에는 저장할 때의 이미지 위치가 들어간다 [19].
서버를 다시 시작할 때 이 값과 `VOL_IMAGE_PATH`가 가리키는 파일이 다르면 Volatility가 어느 파일을 읽는지는 확인하지 못했다 [17].

```python
def run_strings(session: Session, strings_file: str = "") -> dict:
    """Run windows.strings and return strings mapped to processes.

    strings_file: absolute path to a pre-generated strings-with-offsets
        file, e.g. produced by `strings -a -t d <image> > strings.txt`.
        This is a hard (non-optional) requirement of the underlying
        plugin -- without it, plugin construction itself fails
        validation before run() is ever reached, so an empty string
        here returns an empty result with an explanatory error instead
        of letting that exception propagate.
    """
    if not strings_file:
        return {
            "plugin": "strings",
            "results": [],
            "error": (
                "strings_file is required by windows.strings and was not "
                "provided. Generate one first (e.g. `strings -a -t d "
                "<image> > strings.txt` on Linux/WSL, or any tool that "
                "emits 'offset:string' lines) and pass its absolute path."
            ),
        }
    extra_config = {"strings_file": Path(strings_file).resolve().as_uri()}
    try:
        treegrid = run_plugin(session, strings.Strings, extra_config=extra_config)
    except exceptions.PluginRequirementException as e:
        return {"plugin": "strings", "results": [], "error": str(e)}
    return {"plugin": "strings", "results": parse_treegrid(treegrid)}
```

```python
def run_pe_symbols(
    session: Session,
    source: str,
    module: str,
    symbols: str = "",
    addresses: str = "",
) -> dict:
    """Run windows.pe_symbols to resolve PE symbol names <-> addresses.

    source: "kernel" or "processes".
    module: target module name (e.g., "ntoskrnl.exe", "ntdll.dll").
    symbols: optional comma-separated symbol names to resolve (name -> address).
    addresses: optional comma-separated hex/decimal addresses (address -> name).
    One of the two is effectively required: if both are empty the plugin
    logs an error and returns zero rows rather than listing every symbol.
    """
    extra: dict = {"source": source, "module": module}
    sym_list = [s.strip() for s in symbols.split(",") if s.strip()] if symbols else None
    if sym_list:
        extra["symbols"] = sym_list
    addr_list = [int(a.strip(), 0) for a in addresses.split(",") if a.strip()] if addresses else None
    if addr_list:
        extra["addresses"] = addr_list
    treegrid = run_plugin(session, pe_symbols.PESymbols, extra_config=extra)
    return {"plugin": "pe_symbols", "results": parse_treegrid(treegrid)}
```
