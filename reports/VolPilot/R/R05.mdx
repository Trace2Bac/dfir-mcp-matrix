# R05 결과 출처 표시

### R05.01 증거·파일 ID

**구현.** 이 방식은 `windows_info`와 `verify_image_integrity`에 적용된다 [1][2].
서버는 시작할 때 `VOL_IMAGE_PATH`가 가리키는 파일 하나를 세션에 묶고 모든 도구가 이 이미지를 읽는다 [3].
이미지를 바꾸려면 서버를 다시 시작해야 하므로 한 서버 프로세스의 응답은 모두 같은 이미지에서 나온다 [3].
`windows_info`는 응답의 `image`에 이미지 경로 `path`, 크기 `size`, 시작할 때 계산한 SHA-256 `sha256`을 싣는다 [1].
`verify_image_integrity`는 `image_path`, `image_size`, 시작할 때의 해시 `expected_sha256`을 싣는다 [2].
다른 도구의 응답에는 이미지 경로나 해시가 없다 [4].

**한계.** `path`와 `image_path`는 `VOL_IMAGE_PATH`에 준 문자열 그대로다 [3].
그래서 상대 경로를 주면 서버를 시작한 폴더 기준의 상대 경로가 실린다 [3].
두 도구의 설명은 이 값을 이미지 파일의 절대 경로라고 적는다 [5].

### R05.03 레코드 키·번호

**구현.** 이 방식은 Volatility 3 플러그인의 열을 모두 싣는 플러그인 도구와 교차 분석 도구에 적용된다 [4][6].
서버는 플러그인이 낸 열을 빼지 않고 싣는다 [4].
프로세스를 다루는 플러그인의 행에는 프로세스 ID(`pslist`·`psscan`·`dlllist`·`netscan`의 `PID`, `ldrmodules`의 `Pid`)가 있다 [7].
`registry.printkey`의 행에는 레지스트리 키 경로 `Key`가, `mftscan`의 행에는 MFT 레코드 번호 `Record Number`가 있다 [7].
교차 분석 도구는 결과 항목마다 `pid`를 싣거나 플러그인 행을 그대로 싣는다 [6].

**한계.** `build_timeline`의 `program_executed`·`userassist_executed` 사건은 `pid`를 `None`으로 두고 키 경로나 레코드 번호를 싣지 않는다 [8].
이 사건을 만들면 `name`은 `shimcachemem`에서는 `Path` 키 값이고 `userassist`에서는 값 이름 `Name`이다 [8].

### R05.04 바이트·섹터·행 오프셋

**구현.** 이 방식은 물리 주소나 이미지 파일 안 위치를 열로 내는 플러그인 도구에 적용된다 [9][10][11].
`windows_memmap`은 Volatility 3 `windows.memmap`의 물리 주소 `Physical`과 이미지 파일 안 위치 `Offset in File`을 싣는다 [9].
`windows_strings`는 `Physical Address` 열을, `windows_mbrscan`은 `Potential MBR at Physical Offset` 열을 싣는다 [9].
`windows_malware_psxview`는 모델이 `physical_offsets`를 참으로 주면 `physical-offsets`를 켜고 이때 열 이름은 `Offset(Physical)`이 된다 [10].
`windows_psscan`·`windows_netscan`·`windows_filescan`의 오프셋은 풀 스캔이 찾은 객체의 위치다 [11].
Volatility 3 2.28.0의 풀 스캔은 Windows 10 이전 이미지에서 커널 가상 주소 계층이 아니라 그 아래의 메모리 계층을 훑는다 [11].
그래서 Windows 10 이전 이미지에서 세 도구의 오프셋은 물리 주소다 [11].
`pslist`의 `Offset(V)`, `vadregexscan`의 `Offset`, `dlllist`의 `Base`는 가상 주소다 [7].

**한계.** Windows 10 이후 이미지에서는 풀 스캔이 커널 가상 주소 계층을 훑으므로 세 도구의 오프셋이 가상 주소가 된다 [11].
서버는 `windows.psscan`에 물리 주소로 바꿔 내는 `physical`을 넘기지 않는다 [12].
`windows_psscan`의 열 이름은 늘 `Offset(V)`이고 `windows_netscan`·`windows_filescan`의 `Offset`과 응답 어디에도 물리 주소인지 가상 주소인지 표시가 없다 [11][12].

```python
def parse_treegrid(treegrid) -> list[dict[str, Any]]:
    """Parse a Volatility3 TreeGrid into a list of dicts."""
    col_names = [col.name for col in treegrid.columns]
    rows: list[dict[str, Any]] = []

    def visitor(node, accumulator):
        row = {
            name: _serialize_value(node.values[i])
            for i, name in enumerate(col_names)
        }
        accumulator.append(row)
        return accumulator

    treegrid.populate(visitor, rows)
    return rows
```

```python
def run_malware_psxview(session: Session, physical_offsets: bool = False) -> dict:
    """Run windows.malware.psxview to cross-correlate process enumeration methods.

    physical_offsets: if True, the Offset column reports physical addresses
        (matches the on-disk pool tag scan); default reports virtual addresses.
    """
    extra: dict = {}
    if physical_offsets:
        # The plugin's requirement name uses a dash, not an underscore.
        extra["physical-offsets"] = True
    treegrid = run_plugin(session, psxview.PsXView, extra_config=extra or None)
    return {"plugin": "malware.psxview", "results": parse_treegrid(treegrid)}
```
