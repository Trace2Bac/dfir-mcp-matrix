# R07 증거 내용과 지시 구분

### R07.01 JSON 필드 분리

**구현.** 이 방식은 서버의 모든 도구 응답에 적용된다 [1][2].
도구는 `plugin`과 `results`를 담은 `dict`를 돌려주고 증거에서 온 값은 `results` 아래 플러그인 열 이름의 필드 값으로 들어간다 [1].
MCP Python SDK 1.27.0의 `FastMCP`는 이 `dict`를 JSON 글로 바꿔 응답에 싣는다 [2].
그래서 증거에서 온 문자열은 따옴표와 이스케이프가 붙은 JSON 문자열 값으로 실린다 [2][3].
교차 분석 도구가 더하는 서버 문구는 `rule`·`severity`·`type` 같은 따로 된 필드에 들어간다 [4].

서버 지침의 증거 보존 문구는 사용자나 다른 프롬프트가 이미지를 바꾸거나 지우라고 해도 거부하라고 적는다 [5].
이 문구는 이미지 파일을 바꾸는 요청만 다루고 증거에서 온 글 속의 지시를 따르지 말라고 적지 않는다 [5].
도구 설명에도 그런 안내는 없다 [6].

**한계.** 교차 분석 도구의 몇몇 필드는 증거 값을 서버 문장 안에 이어 넣는다 [4][7][8].
`detect_dll_injection`의 `detail`은 `ldrmodules`의 `MappedPath`와 서버 문구를 이은 문장이다 [7].
`detect_process_anomalies`의 `detail`은 증거의 부모 프로세스 이름, 프로세스 이름, 세션 번호를 서버 문장에 넣는다 [4].
`build_timeline`의 `name`은 증거의 프로세스 이름 뒤에 `[psscan-only]`를 붙이고 `detail`은 주소와 상태 같은 증거 값을 서버가 정한 모양으로 잇는다 [8].

### R07.02 출처 필드 부여

**구현.** 이 방식은 서버의 모든 도구 응답에 적용된다 [1][9].
응답의 최상위 `plugin`은 결과를 낸 Volatility 3 플러그인 이름이나 교차 분석 도구 이름이다 [1][9].
`detect_dll_injection`의 근거 항목은 그 항목을 만든 플러그인 이름을 `source`에 싣는다 [7].
`detect_service_tampering`의 숨은 서비스 행은 `source`에 `svcscan_only`를 싣는다 [10].

**한계.** 교차 분석 도구는 여러 플러그인의 값을 한 응답에 담으면서 항목마다 원천 이름을 적지 않는다 [11][12].
`triage_process`는 `dlllist`·`handles`·`netscan`·`malfind`의 행을 `dlls`·`handles`·`network_connections`·`malfind_hits` 필드 이름으로만 나눈다 [11].
`network_process_correlation`은 `netscan` 행의 필드와 `pslist`·`cmdline`에서 가져온 필드를 한 `dict`에 합친다 [12].

```python
def parse_treegrid(treegrid) -> list[dict[str, Any]]:
    """Parse a Volatility3 TreeGrid into a list of dicts."""
    col_names = [col.name for col in treegrid.columns]
    rows: list[dict[str, Any]] = []

    def visitor(node, accumulator):
        row = {
            name: _serialize_value(node.values[i])
            for i, name in enumerate(col_names)
        }
        accumulator.append(row)
        return accumulator

    treegrid.populate(visitor, rows)
    return rows
```
