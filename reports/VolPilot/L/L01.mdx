# L01 기록 방식

### 미구현

**판단.** 서버 코드에는 MCP 도구 호출을 기록하는 코드가 없다 [1].
서버 코드에서 로거를 쓰는 곳은 `Session._verify_read_only` 하나다 [2].
이 함수는 서버를 시작할 때 이미지 파일에 쓰기 권한이 있으면 경고 한 줄을 남긴다 [2].
서버 코드가 파일을 쓰는 곳은 이미지 옆의 Volatility 3 설정 파일 `<이미지 경로>.vol3cfg.json`과 `VOL_DUMP_DIR`의 덤프 파일뿐이다 [3][4].
도구 호출을 적는 파일이나 DB는 없다 [3][4].

서버는 MCP Python SDK 1.27.0의 `FastMCP`를 기본 로그 설정으로 만든다 [5].
SDK 1.27.0의 `FastMCP`는 만들어질 때 루트 로거를 `INFO` 수준으로 설정하고 표준 오류로 내보낸다 [5].
SDK의 요청 처리기는 요청마다 `Processing request of type CallToolRequest`처럼 요청 종류만 `INFO`로 쓴다 [6].
이 줄에는 도구 이름과 인자가 없다 [6].
목록에 없는 도구 이름이 오면 SDK는 그 이름을 담은 `WARNING` 줄을 쓴다 [6].
도구 함수에서 예외가 나면 SDK는 오류 결과를 돌려주고 로그를 쓰지 않는다 [7].
루트 로거가 `INFO`로 설정되므로 Volatility 3가 플러그인을 실행하며 쓰는 `Running automagic: …` 같은 진단 줄도 표준 오류로 나간다 [8].
서버를 실행해 성공하는 호출, 오류 결과를 돌려주는 호출, 형식이 틀린 인자의 호출, 목록에 없는 이름의 호출을 보냈다 [8].
표준 오류에 남은 도구 호출의 줄은 `Processing request of type …` 줄, 목록에 없는 이름의 경고 줄, Volatility 3의 진단 줄뿐이었다 [8].
그래서 등록된 도구의 호출에는 도구 이름도 인자도 담지 않는 진단 줄만 남는다 [6][7][8].

저장소에는 MCP 클라이언트 설정 파일, 훅, 사용자 CLI가 없다.
README는 클라이언트에 서버를 등록하는 예시만 적는다 [9].
`evaluation/rq4/live/`의 평가 하네스는 모델이 요청한 도구 호출을 `events.jsonl`에 남기고 서버를 감싼 `audit_server.py`로 파일 열기 사건을 기록한다 [10].
이 하네스는 연구 평가용 자료이고 서버 구현이 아니다 [10].
