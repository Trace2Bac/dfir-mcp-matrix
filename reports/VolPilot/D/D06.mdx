# D06 산출물 식별·재생성 처리

### D06.02 입력·작업별 고유 이름

**구현.** 이 방식은 덤프 도구 `windows_dumpfiles`·`windows_pedump`가 쓰는 파일 이름에 적용된다 [1][2].
이 이름 규칙은 서버 코드가 아니라 Volatility 3 2.28.0의 `dumpfiles`와 `pedump`가 정한다 [1][2].
`dumpfiles`는 `FILE_OBJECT` 주소, 캐시 객체 주소, 캐시 종류, 이미지 안 파일 이름을 이름에 넣는다 [1].
`pedump`는 프로세스 객체 주소, PID, 기준 주소를 이름에 넣는다 [2].
이 값은 꺼낸 객체마다 다르므로 서로 다른 객체에서 꺼낸 파일은 이름이 다르다 [1][2].
입력마다 같은 값을 쓰는 규칙이라 같은 객체를 다시 꺼내면 플러그인이 정한 이름이 같다 [1][2].
이름에 시각, 실행 번호, 이미지를 가리키는 값은 들어가지 않는다 [1][2].
같은 이름이 이미 있을 때의 처리는 서버의 `DumpFileHandler`가 맡는다 [3].

### D06.03 버전·이력 보존

**구현.** 이 방식은 서버의 `DumpFileHandler`가 덤프 파일을 쓸 때 적용된다 [3].
`DumpFileHandler.close`는 `VOL_DUMP_DIR`에 같은 이름의 파일이 있으면 확장자 앞에 `-1`, `-2`처럼 번호를 붙여 아직 없는 이름을 찾은 뒤 그 이름으로 쓴다 [3].
앞 파일은 지우거나 덮어쓰지 않는다 [3].
같은 이름으로 두 번 쓰자 앞 파일은 내용이 그대로 남고 새 내용은 `-1`이 붙은 이름으로 생겼다 [4].
번호가 붙은 파일과 앞 파일을 가르는 것은 이름의 번호뿐이고 서버는 어느 호출이 어느 파일을 썼는지 남기지 않는다 [3][5].

**한계.** 응답의 `Result`와 `File output`에는 번호가 붙기 전의 이름이 실린다 [3][1][2].
인자가 다른 두 호출이 같은 객체를 꺼내자 두 번째 호출의 `Result`는 번호가 없는 첫 파일의 이름이었다 [6].

### D06.04 덮어쓰기 선택·충돌 감지

**구현.** 이 방식은 `Session.run_plugin`을 거치는 도구의 결과 캐시와 설정 파일 `<이미지 경로>.vol3cfg.json`에 적용된다 [5][7].
`Session.run_plugin`은 플러그인 이름과 호출 인자로 캐시 키를 만들고 같은 키의 결과가 있으면 플러그인을 다시 실행하지 않고 그 결과를 돌려준다 [5].
그래서 같은 서버 프로세스에서 덤프 도구를 같은 인자로 다시 부르면 파일을 다시 쓰지 않고 첫 호출의 응답을 돌려준다 [5].
덤프 플러그인을 가짜 클래스로 바꾼 시험에서 같은 인자의 두 번째 호출은 플러그인을 실행하지 않았고 첫 호출과 같은 결과 객체를 돌려주었다 [6].
인자가 하나라도 다르면 다시 실행해 번호를 붙인 새 파일을 쓴다 [5][3][6].
설정 파일은 서버를 시작할 때 이미 있으면 읽어 쓰고 다시 쓰지 않는다 [7][8].
설정 파일이 있는 이미지로 새 세션을 만들자 `has_config`가 참이었고 다음 호출 뒤에도 파일 내용은 바뀌지 않았다 [6].
덮어쓸지 다시 만들지를 호출 인자로 고르게 하는 도구는 없다.

**한계.** 캐시는 덤프 파일이 아직 있는지 보지 않는다 [5].
덤프 파일 하나를 지운 뒤 같은 인자로 다시 부르자 플러그인은 실행되지 않았고 응답은 첫 호출과 같았으며 지운 파일은 다시 생기지 않았다 [6].
캐시는 프로세스 메모리에만 있어 서버를 다시 시작하면 같은 인자의 덤프도 다시 실행되고 번호를 붙인 새 파일이 생긴다 [5][3].
설정 파일은 이미지 경로로만 찾고 서버가 계산한 이미지 해시와 대조하지 않는다 [7][9].
같은 경로에 다른 이미지가 놓여도 앞 이미지의 설정 파일을 읽어 플러그인 설정에 덧붙인다 [7][8].

```python
    def run_plugin(self, plugin_name: str, **kwargs) -> dict:
        """Run a plugin by name, returning cached results if available.

        Extra kwargs are forwarded to the plugin's runner function and used
        to key the cache, so calling the same parameterized plugin twice
        with identical arguments returns the cached result, while different
        arguments trigger a fresh run.
        """
        cache_key = (plugin_name, frozenset(kwargs.items())) if kwargs else plugin_name
        if cache_key in self._cache:
            return self._cache[cache_key]
        if plugin_name not in PLUGIN_MAP:
            raise ValueError(f"Unknown plugin: {plugin_name}")
        result = PLUGIN_MAP[plugin_name](self, **kwargs)
        self._cache[cache_key] = result
        return result
```
