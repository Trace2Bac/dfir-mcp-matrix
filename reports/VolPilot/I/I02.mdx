# I02 분석 도구 통신 차단

### 미구현

**판단.** 서버는 Volatility 3를 Python 라이브러리로 불러 플러그인을 실행하고 그 통신을 끄는 설정이나 장치를 두지 않는다 [1][2].
`run_plugin`은 Volatility 3가 쓸 수 있다고 알린 automagic 가운데 플러그인에 맞는 것을 모두 실행한다 [1].
Volatility 3 2.28.0에서 온라인 여부를 정하는 전역 값 `OFFLINE`의 기본값은 거짓이다 [3].
서버 코드는 이 값을 바꾸지 않는다 [2].
서버 모듈을 불러온 뒤에도 `OFFLINE`은 거짓이었다 [4].

Volatility 3 2.28.0은 Windows 커널의 PDB 심볼 표가 로컬 심볼 폴더와 캐시에 없으면 `SYMBOL_SERVER_URL`에서 PDB를 받아 ISF로 바꿔 심볼 폴더에 쓴다 [5].
`SYMBOL_SERVER_URL`의 값은 `http://msdl.microsoft.com/download/symbols`이고 서버는 이 값을 바꾸지 않는다 [3][2].
커널 PDB를 찾는 automagic `KernelPDBScanner`가 이 내려받기 함수를 부른다 [6].
심볼 폴더는 패키지 안 `symbols` 폴더와 캐시 폴더 아래 `symbols`이고 내려받은 파일은 쓸 수 있는 첫 폴더에 쓴다 [3][5].
캐시 폴더는 `XDG_CACHE_HOME`이나 `~/.cache` 아래 `volatility3`이고 Windows에서는 `APPDATA` 아래 `volatility3`이다 [3].
원격 ISF 목록 주소 `REMOTE_ISF_URL`은 기본값이 `None`이라 서버가 실행하는 Volatility 3는 그 목록을 조회하지 않는다 [3][7].
Volatility 3 2.28.0의 오프라인 처리기는 `OFFLINE`이 켜졌을 때만 http·https 요청을 막는다 [8].

서버 코드 주석은 세션에서 컨텍스트 하나를 다시 써서 호출마다 PDB를 다시 받지 않게 한다고 적는다 [9].
README는 처음 분석할 때 맞는 Windows 심볼을 내려받을 수 있다고 적는다 [10].
저장소에는 서버나 Volatility 3를 네트워크 없는 컨테이너나 network namespace에서 실행하는 구성이 없다.
네트워크를 끈 컨테이너에서 무작위 바이트 이미지로 실행했을 때는 `KernelPDBScanner`가 커널을 찾지 못해 내려받기 함수까지 가지 않았다 [11].
그래서 내려받기 경로는 Volatility 3 소스로만 확인했다.
