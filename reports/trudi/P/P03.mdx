# P03 조사 진척 판단

### P03.01 기준 작업 목록 대조

**구현.** 서버는 기준 목록 세 가지를 호출 기록과 대조한다.
첫째는 공격 단계 목록이다 [1].
지속성, 권한 상승, 내부 이동, 실행 흔적, 유출 다섯 단계마다 그 단계를 보여 주는 산출물 출처와 출처를 알아보는 정규식을 둔다 [1].
단계마다 그 단계를 세우는 CONFIRMED·LIKELY 발견사항이 있으면 `established`, SUSPECTED뿐이면 `suspected`, 부정 발견사항이 있으면 `ruled_out`으로 정한다 [2].
발견사항이 없을 때 성공한 호출의 명령줄이나 도구 이름이 출처 정규식에 맞으면 `examined`, 아무것도 없으면 `not_examined`로 정한다 [2].
`reason.readiness_status`와 `reason.pre_report_check`는 `not_examined` 단계를 경고로 싣고 단계별 결과를 `lifecycle_coverage`로 돌려준다 [3].
`misc.write_final_report`는 이 결과를 단계, 상태, 살펴본 출처 수를 적은 표로 보고서에 붙인다 [4].

둘째는 `dair.assess`가 내린 작업 지시다 [5].
서버는 모든 `dair_call`의 `priority_tools`를 모아 성공한 호출이나 도구 처분과 대조하고 남은 도구를 보고를 막는 사유로 싣는다 [5].
단계를 떠날 때도 그 단계의 작업 지시를 같은 방식으로 대조한다(P02.02).

셋째는 IOC마다의 탐지 범위다 [6].
`misc.record_ioc`로 기록한 IOC의 ATT&CK 기법마다 탐지 전략이 요구하는 데이터 구성 요소를 펼치고 `data/fk/attack_coverage.yaml`이 그 구성 요소를 살필 도구를 정한다 [6].
그 도구가 성공한 호출의 명령줄이나 자기 출력, 그 출력을 읽은 `read.output` 질의에 IOC 값이 나오면 `covered`로 본다 [7].
처분이 있으면 `dispositioned`, 사건이 필요한 증거 종류를 갖지 않으면 `not_applicable`, 둘 다 아니면 `open`이다 [6].
`misc.list_iocs`와 `dair.assess`가 이 표를 돌려주고 `reason.pre_report_check`는 열린 항목을 경고로 싣는다 [8][9][10].
세 대조 모두 호출 기록에서 다시 계산하므로 서버를 다시 시작해도 결과가 같다.

여러 호출의 호출 기록이나 작업 상태로 대상마다 시도·성공·실패·생략을 집계하는 도구는 없어 P03.02에는 연결하지 않는다.
`ez.recmd_batch`가 하이브마다 성공과 실패를 세어 돌려주지만 도구 하나의 묶음 상태라 T08.04에서 본다 [11].

**한계.** 공격 단계의 `examined`는 성공한 호출의 명령줄과 도구 이름이 정규식에 맞는지로만 정하고 어느 증거 항목을 읽었는지는 보지 않는다 [2].
같은 낱말이 여러 단계의 출처에 들어 있어 `srum`이 든 호출 하나가 실행 흔적과 유출 두 단계를 `examined`로 만든다 [1].
작업 지시의 대조도 도구 이름에서 뽑은 실행 파일 낱말이 성공한 명령줄 어디에든 들어 있는지로 정한다 [5][12].
그래서 `SOFTWARE` 하이브를 보라고 작업 지시에 넣은 `ez.recmd_hive`는 다른 하이브를 읽은 RECmd 호출 하나로 끝난 것이 된다 [5][12].
IOC 탐지 범위의 `not_applicable`은 판별이 정해졌는지 보지 않고 그때까지 찾은 증거 종류만 본다 [6][13].
증거 폴더에서 아무것도 찾지 못했고 호출 기록에 캡처를 다룬 성공한 도구 호출도 없으면 캡처가 필요한 항목을 사건이 캡처를 갖지 않는다는 사유로 `not_applicable`에 넣는다 [6][13].

### P03.03 단계 상태·완료 조건 대조

**구현.** DAIR 단계는 Triage, Collect, Analyze, Scan, Report이고 서버는 단계 스택을 호출 기록의 `dair_call`과 `phase_transition`으로 관리한다 [14].
`dair.assess`의 모델이 Report 단계로 옮기라고 권해도 옮길지는 서버가 정한다 [14].
기록한 발견사항이 하나도 없으면 서버는 모델이 권한 Report 전이를 거부하고 지금 단계에 머문다 [15].
Collect와 Analyze를 거치지 않았으면 그 단계로 넣고 후보 호스트가 있으면 Scan도 거쳐야 한다 [16].
거친 단계는 서버가 받아들인 전이만 세고 에이전트가 보낸 단계 스택은 세지 않는다 [17].

`reason.readiness_status`와 `reason.pre_report_check`는 같은 판단 함수 `assess_readiness`로 보고 준비 상태를 정한다 [18][19].
`reason.plan`과 `reason.synthesize`를 불렀는지, 거쳐야 할 단계를 거쳤는지, 열린 검증 과제가 남았는지 본다 [20][21].
작업 지시에 넣은 도구와 막히거나 실패한 도구가 모두 다시 실행됐거나 처분됐는지, 백그라운드 작업이 끝났는지도 본다 [22][23].
사유가 하나도 없으면 `ready_to_report`가 참이다 [24].
`reason.pre_report_check`는 결과를 호출 기록에 남기고 Report 단계에서 준비가 안 됐으면 Collect로 옮긴다 [19].
보고서 쓰기 도구가 이 결과로 쓰기를 막는 일은 T03에서 본다.
`reason.synthesize` 검토가 두 번(`TRUDI_SYNTH_ROUND_CAP`) 끝난 뒤에는 남은 반론이 막는 사유에서 빠지고 보고서에 미해결로 실린다 [25].

**한계.** `assess_readiness`의 검사는 하나하나 `except Exception`으로 감싸 오류가 나면 표준 오류에 경고만 쓰고 그 검사 없이 판단한다 [21][22].
거쳐야 할 단계 검사나 작업 지시 검사가 오류로 빠져도 `ready_to_report`는 참이 될 수 있다 [21][22][24].
백그라운드 작업 검사는 서버 프로세스 안의 작업 목록만 본다 [23].
`net.tcpxtract_streams`가 시작하는 파일 기반 작업은 이 목록에 포함되지 않아 진행 중이어도 보고를 막지 않는다 [23][26].
서버 프로세스 안의 작업 목록은 메모리에만 있어 서버를 다시 시작하면 끝나지 않은 작업도 검사에서 사라진다 [27].

### P03.04 미조사 범위·생략 사유 보고

**구현.** `coverage.report`는 호출 기록의 발견사항에 나온 ATT&CK 기법을 `checked`와 `found`로, DAIR의 `recommended_actions`에 나왔지만 뒤의 발견사항에 다시 나오지 않은 기법을 `skipped`로 센다 [28].
모델이 고른 전술(고르지 않으면 전체)에 속하지만 발견사항에 나오지 않은 기법은 `gaps`로 돌려준다 [28].
`reason.pre_report_check`는 보지 않은 공격 단계, 따라가지 않은 후보와 IOC, 검토 모델이 보지 못한 세부 사항, 근거가 약한 처분을 경고로 싣는다 [3][10][29].
`misc.write_final_report`는 공격 단계 표, IOC별 살펴보지 않은 탐지 출처와 그 사유, 다시 볼 처분, 검토 모델이 보지 못한 세부 사항, 미해결 반론을 보고서 절로 붙인다 [30].
선택 실행 파일이 없는 도구는 `tool_unavailable`로 끝나고 처분으로 정리하라고 응답에 적는다 [31].

**한계.** `coverage.report`의 설명은 `skipped`를 작업 지시에 들어간 뒤 그 기법으로 도구를 부르지 않은 기법이라고 적는다 [32].
코드는 도구 호출을 보지 않고 작업 지시 뒤의 발견사항에 그 기법 번호가 나왔는지만 본다 [28].
그래서 도구를 실행했지만 발견사항을 쓰지 않은 기법도 `skipped`로 센다 [28].
`misc.write_final_report`는 모델이 쓴 본문에 `attack-lifecycle coverage`나 `## indicators of compromise` 같은 제목 글자가 이미 있으면 그 절을 붙이지 않는다 [30].
본문에 그 글자만 있어도 서버가 계산한 살펴보지 않은 출처 표가 빠진다 [30].

### P03.05 모델이 적은 진행 기록 보관

**구현.** `misc.record_disposition`은 모델이 출처, 도구, 검증 과제, 계정, 호스트, 장치, 가설, IOC 탐지 항목을 발견사항 없이 정리한 사유를 적는 도구다 [33].
서버는 대상 종류와 사유를 정해진 값과 대조하고 대상 종류마다 쓸 수 있는 사유만 받는다 [34].
`excluded`·`ruled_out`·`refuted`처럼 증거에 관한 사실을 말하는 사유와 출처의 `absent_from_evidence`는 근거 호출 번호를 요구하고 그 번호가 증거 도구 호출인지 확인한다 [33][34].
증거 도구 호출은 명령 문자열 앞부분으로만 정하므로 증거를 읽지 않는 `misc.knowns_pattern_generate` 호출 번호도 이 근거로 받는다 [35][36].
이 판정은 D07.01에서 본다.
`dair_call`이 없으면 처분을 받지 않는다 [33].
처분은 호출 기록의 `disposition` 항목으로 남는다 [37].
작업 지시와 막히거나 실패한 도구의 대조는 `inapplicable`·`absent_from_evidence`·`out_of_scope`·`tool_unavailable` 같은 도구 처분을 끝난 것으로 본다 [38].
`out_of_scope`로 닫은 검증 과제와 인용한 근거가 주장 낱말을 거의 담지 않은 처분은 다시 볼 처분으로 경고와 보고서에 실린다 [39][30].
IOC 탐지 항목의 처분은 보고서에 살펴보지 않은 출처로 사유와 함께 실린다 [30].
도구 처분 자체는 보고서의 별도 절에 실리지 않는다 [30].

    """Successful calls of a mapped tool that examined its data FOR this IOC:
    its command or its own output names the IOC, or a traced read over its
    output queried for it. A tool that merely ran somewhere does not count."""
    tools = set(spec.get("tools") or [])

                any(path == p or path.startswith(p.rstrip("/") + "/") for p in produced)

# Reasons that settle a manifest source / tool / challenge without running it.
SOURCE_WAIVER_REASONS_ALL = ("absent_from_evidence", "inapplicable", "out_of_scope",
                             "verified", "tool_unavailable", "present_unparseable")

# Reasons that assert a fact about the evidence and therefore need it cited.
EVIDENCE_REQUIRED = frozenset({"excluded", "ruled_out", "refuted", "not_a_principal",
                               "same_as"})
# `same_as`: the contested identity is the SAME person/account as an already
# established principal (an alias, a registered-owner string, the account the
# prime subject uses) — not a second actor. Cite the artifacts that tie them.
# It is the honest vocabulary where "refuted" would be backwards.

# (target_kind, reason) pairs that also assert a fact about the evidence.
# "Absent from evidence" for a source or coverage row is a claim about what
# the image holds (a 2026-09-23 run declared Telegram absent while its data
# sat in the profile) — cite the listing / search that shows it absent.
EVIDENCE_REQUIRED_FOR = frozenset({
    ("source", "absent_from_evidence"), ("coverage", "absent_from_evidence"),
    ("source", "present_unparseable"), ("coverage", "present_unparseable"),
    ("challenge", "verified"),
})

def tool_waived(didx, tool: str, aliases=()) -> bool:
    """A typed disposition settles the tool: target_kind="tool", target_id any
    spelling of the MCP tool (ez.pecmd / ez_pecmd / ez_pecmd) or of its binary
    (pe-scanner / pe_scanner), reason inapplicable | absent_from_evidence |
    out_of_scope. `aliases`: other names of the same call (its mcp_tool stamp)."""
    sig = _binary_sig(tool)
    keys: set = set()
    for n in (tool, *aliases):
        keys |= _tool_keys(n)
    table = getattr(didx, "dispositions", None) or {}
    for (kind, _norm), rows in table.items():
        if kind != "tool":
            continue
        for d in rows:
            if str(d.get("reason") or "").lower() not in SOURCE_WAIVER_REASONS_ALL:
                continue
            tid = str(d.get("target_id") or "")
            if _binary_sig(tid) == sig or (_tool_keys(tid) & keys):
                return True
    return False

def dispositions_to_review(entries) -> list:
    """[{call_id, target_kind, target_id, reason, why, overlap}] for the report."""
    by = {e.get("call_id"): e for e in entries or [] if isinstance(e, dict)}
    out = []
    for d in entries or []:
        if not isinstance(d, dict) or d.get("type") != "disposition":
            continue
        tk, rs = str(d.get("target_kind") or ""), str(d.get("reason") or "")
        tid = str(d.get("target_id") or "")
        row = {"call_id": d.get("call_id"), "target_kind": tk, "target_id": tid[:200], "reason": rs}
        if tk == "challenge" and rs == "out_of_scope":
            out.append({**row, "why": "challenge closed out_of_scope — no evidence required or cited"})
            continue
        if rs not in REVIEW_REASONS or not d.get("evidence_call_ids"):
            continue
        claim = tid.split(":", 1)[-1] if tk == "challenge" else tid
        terms = _terms(claim)
        if len(terms) < 2:
            continue                       # too little to judge relevance on
        text = _evidence_text(by, d.get("evidence_call_ids"))
        hit = sorted(t for t in terms if t in text)
        if len(hit) * 3 <= len(terms):
            out.append({**row, "overlap": f"{len(hit)}/{len(terms)}",
                        "why": (f"cited evidence (calls {d.get('evidence_call_ids')}) mentions "
                                f"{len(hit)} of {len(terms)} claim terms")})
    return out
