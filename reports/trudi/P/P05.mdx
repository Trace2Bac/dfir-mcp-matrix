# P05 사건 자료 정리

### P05.01 모델 도구로 삭제·초기화

**구현.** 모델이 부를 수 있는 `misc.clear_case_run(case_dir)`가 사건을 새 조사용으로 초기화한다 [1].
`case_dir`의 `analysis/`·`exports/`·`reports/` 안 항목을 숨김 항목까지 모두 지운다 [1].
사건 폴더의 기본 배치에서 그 안에는 호출 기록, 원래 출력 사본 `.tool_output/`, 도구 출력 파일, 보고서가 들어 있다 [1].
캐시 폴더의 `session.json`과 `~/.claude/projects/<인코딩한 case_dir>/memory/` 아래 Claude Code 프로젝트 메모리 파일도 지운다 [1].
응답은 지운 경로 목록 `cleared`와 오류 목록 `errors`를 돌려준다 [1].
도구에는 확인 인자가 없다 [1].
저장소의 Claude Code 명령 `/trudi-clear-case`는 지울 목록을 보여 주고 사용자에게 확인을 받은 뒤 이 도구를 부르라고 적지만 이 확인은 클라이언트 구성이고 T03에서 본다 [2].
호출 번호 카운터와 훅 상태 파일은 이 도구가 지우지 않고 P05.02의 사용자 명령이 초기화한다 [1][3].
진행 중인 조사에서 발견사항 한 건을 거두는 도구는 D05에서 본다.

**한계.** 도구 설명은 `session.json`을 지워 이전 호출 기록에 다시 붙지 않게 하고 새 조사가 이전 출력을 읽지 않게 한다고 적는다 [1].
서버가 그 사건의 `analysis/` 아래 호출 기록으로 설정된 채 이 도구를 부르면 미들웨어가 이 호출을 기록하면서 지운 파일을 되살린다 [4][5].
기록 함수는 호출 기록 파일이 사라졌으면 메모리의 모든 항목으로 파일을 다시 만들고 `session.json`도 다시 쓴다 [5].
이 호출의 출력도 `.tool_output/`에 다시 쓴다 [4][6].
메모리의 단계 스택, 항목 목록, 알림 판단 상태도 그대로 남아 다음 호출이 이전 조사의 상태로 이어진다 [7].
그래서 이 도구를 부른 뒤에도 이전 호출 기록과 이어 붙일 사건 정보가 남는다 [5][7].
다시 만든 호출 기록에는 지운 경로 목록을 담은 이 호출 항목과 `trace_file_missing_at_flush` 항목이 남지만 삭제를 따로 기록하는 장치는 없어 P05.07에는 연결하지 않는다 [4][5].

### P05.02 사용자 명령으로 삭제·초기화

**구현.** 사용자 명령 `python -m tools.trudi_reset --case-dir <사건>`이 사건의 호출 기록과 캐시를 초기화한다 [3].
캐시 폴더의 `hook.lock`에 배타 잠금을 획득한 채 다음을 한다 [8].
사건 `CLAUDE.md`의 Case ID로 `analysis/<Case ID>_trace.json`을, 없으면 `analysis/`의 이름순 첫 `*_trace.json`을 고른다 [9].
그 호출 기록과 `dashboard.url`을 P05.06의 보관 폴더로 옮기거나 지운다 [8][10].
`--keep-trace`를 주면 호출 기록을 남기고 `--purge-outputs`를 주면 `analysis/`·`exports/`·`reports/` 안 항목을 모두 치운다 [11].
`session.json`, `hook_state.json`, `session_owner.json`은 `session.json`이 이 사건을 가리키거나 비어 있을 때만 지운다 [12].
호출 번호 카운터를 `{"next": 1}`로 되돌리고 해시 캐시는 남긴다 [13].
한 일은 표준 출력에 적고 따로 남기지 않는다 [14].
진행 중인 세션이 있으면 초기화를 거부하는 장치는 P05.09에서 본다.
같은 출력 폴더는 모델 도구 `misc.clear_case_run`으로도 지울 수 있지만 카운터와 훅 상태 파일은 이 명령만 초기화한다 [1][13].

**한계.** 서버가 실행 중이면 다음 기록 때 메모리의 항목으로 호출 기록을 다시 만들고 `session.json`도 다시 쓴다 [5].
그래서 서버를 끄지 않고 이 명령을 실행하면 지운 호출 기록과 `session.json`이 되살아난다 [5][8].

### P05.03 자동 정리

**구현.** `misc.usbdeviceforensics`는 하이브를 가리키는 심볼릭 링크만 담은 임시 폴더를 만들어 도구를 실행하고 끝나면 그 폴더를 지운다 [15][16].
`net.http_session_inventory`와 `net.pcap_identity_timeline`은 tcpdump 출력을 `/tmp`의 임시 파일로 받아 읽은 뒤 지운다 [17].
`monitor.end_investigation`은 조사 호출 기록을 보고서로 내보내고 사건 전체 호출 기록으로 바꾼 뒤 열린 조사 표시 파일 `_open_investigation.json`을 지운다 [18].
`monitor.stop_watcher`는 감시 프로세스를 멈춘 뒤 PID 파일을 지운다 [19].
이 정리는 호출 기록에 따로 남지 않는다.
파생물과 호출 기록을 기간이나 작업 완료로 지우는 코드는 없다.

### P05.05 원본 증거를 삭제 대상에서 제외

**구현.** `misc.clear_case_run`이 지우는 폴더는 `case_dir`의 `analysis/`·`exports/`·`reports/` 세 곳이고 `evidence/`와 마운트 지점은 대상이 아니다 [1].
폴더는 `shutil.rmtree`로, 파일과 심볼릭 링크는 `os.remove`로 지운다 [1].
CPython 3.10.12의 `shutil.rmtree`는 안의 심볼릭 링크를 따라가지 않고 링크만 지운다 [20].
그래서 출력 폴더 안에 증거를 가리키는 링크가 있어도 증거 파일은 남는다 [1][20].
`tools.trudi_reset`이 지우거나 옮기는 것도 호출 기록, `dashboard.url`, 세 출력 폴더 안 항목, 캐시 파일이다 [8][11][12].
P05.03의 `misc.usbdeviceforensics` 임시 폴더도 링크만 담아 같은 이유로 하이브 파일은 남는다 [15][16][20].
대상 제한은 폴더 이름에 기댄다.
`misc.clear_case_run`에 붙은 `@output_safe`는 출력 인자 이름 8개만 검사해 `case_dir`가 증거 위치인지 보지 않는다 [1][21].
그래서 증거 폴더 안을 `case_dir`로 주면 그 아래 `analysis/`·`exports/`·`reports/` 이름의 폴더를 지운다 [1][21].

**한계.** `misc.batch_run`은 모델이 준 인자 목록을 허용 목록 없이 실행하므로 모델이 `rm`으로 `evidence/` 아래 파일을 직접 지울 수 있다 [22].

### P05.06 삭제 전 보관

**구현.** `tools.trudi_reset`은 기본으로 호출 기록과 `dashboard.url`을 `<사건>/.trace-backups/<UTC 시각>/`으로 옮긴 뒤 지운다 [10].
`--purge-outputs`를 주면 `analysis/`·`exports/`·`reports/` 안 항목을 같은 폴더 아래로 옮긴다 [11].
`.trace-backups/`는 세 출력 폴더 밖이라 이 명령과 `misc.clear_case_run`이 지우지 않는다 [1][11].
`misc.clear_case_run`은 보관 없이 지운다 [1][2].

**한계.** `--no-backup`을 주면 호출 기록과 세 출력 폴더 안 항목을 보관 없이 지운다 [11][23].

### P05.09 진행 중인 세션이 있는 사건의 초기화 거부

**구현.** 이 방식은 사용자 명령 `python -m tools.trudi_reset`에 적용된다 [24].
`reset`은 캐시 폴더의 `hook.lock`에 배타 잠금을 획득한 뒤 `_live_owner`로 이 사건을 쓰는 세션이 진행 중인지 판단한다 [8][24].
진행 중인지는 캐시 폴더의 `session.json`과 `session_owner.json`으로 판단한다 [24].
`session.json`이 가리키는 호출 기록이 이 사건 폴더 아래에 있고 `session_owner.json`의 `last_seen`(없으면 `claimed_ts`)이 `_OWNER_TTL_SEC` 안이면 진행 중으로 본다 [24].
`_OWNER_TTL_SEC`는 환경변수 `TRUDI_OWNER_TTL_SEC`로 정하고 기본값은 600초다 [25].
`session_owner.json`은 Claude Code 훅이 호출 기록에 쓰는 세션을 적는 파일이다 [26].
진행 중이면 아무것도 지우지 않고 `success`가 거짓인 결과에 거부 사유를 `error`로 담아 끝낸다 [24].
거부 문구는 진행 중인 조사의 훅이 쓴 호출 기록 항목을 잃고 그 훅이 멈춘다는 사유와 그 세션을 먼저 멈추거나 `--force`를 주라는 안내를 적는다 [24].
명령은 이 문구를 표준 오류에 쓰고 종료 코드 1로 끝난다 [14].
`session.json`이 다른 사건의 호출 기록을 가리키면 이 사건에는 진행 중인 세션이 없다고 본다 [24].
사건에 자료나 호출 기록이 남았는지는 보지 않는다 [24].

**한계.** `--force`를 주면 진행 중인 세션이 있어도 `actions`에 경고 한 줄만 남기고 초기화를 계속한다 [27].
`session.json`이나 `session_owner.json`을 읽지 못하거나 JSON으로 풀지 못하면 `_live_owner`가 `None`을 돌려주어 초기화가 진행된다 [24].
`session_owner.json`의 시각 값이 비었거나 ISO 형식이 아닐 때도 같다 [24].
거부 조건은 Claude Code 훅의 세션 소유 기록만 보고 MCP 서버가 그 호출 기록을 열어 두었는지는 보지 않는다 [24][26].

```python
"""Atomic reset of TRUDI cache + case trace state.

This is the only sanctioned way to "start over" a TRUDI investigation. Manual
editing of ~/.cache/trudi/call_id.counter or session.json can leave the counter
out of sync with the trace, which (after the F1 fix in core/execution_log.py)
is now self-healing but logs a noisy WARN — better to reset cleanly.

Usage:
    python -m tools.trudi_reset --case-dir ~/cases/example-case
    python -m tools.trudi_reset --case-dir ~/cases/example-case --keep-trace
    python -m tools.trudi_reset --case-dir ~/cases/example-case --purge-outputs

What it does (under the shared fcntl lock so no in-flight write races):
    1. Backs up the active trace JSON + dashboard.url to
       <case_dir>/.trace-backups/<timestamp>/  (unless --no-backup).
       With --purge-outputs, the full contents of analysis/, exports/, and
       reports/ are moved into the backup instead.
    2. Removes <case_dir>/analysis/<CASE>_trace.json (unless --keep-trace)
    3. Removes <case_dir>/analysis/dashboard.url
    4. Clears ~/.cache/trudi/session.json
    5. Clears ~/.cache/trudi/hook_state.json and session_owner.json
    6. Resets ~/.cache/trudi/call_id.counter to {"next": 1}
    7. Preserves ~/.cache/trudi/hash_cache.json (evidence-hash memoisation,
       no investigative state)

Exit code is 0 on success, 1 on any error (so it's safe to chain in scripts).
```

def _backup(case_dir: str, trace_path: str | None) -> str | None:
    """Move trace + dashboard.url into a timestamped backup directory.
    Returns the backup dir path, or None if there was nothing to back up."""
    if not trace_path or not os.path.exists(trace_path):
        # Still back up dashboard.url if it exists alone
        dash = os.path.join(case_dir, "analysis", "dashboard.url")
        if not os.path.exists(dash):
            return None
    ts = datetime.datetime.now(datetime.timezone.utc).strftime("%Y%m%dT%H%M%SZ")
    backup_dir = os.path.join(case_dir, ".trace-backups", ts)
    os.makedirs(backup_dir, exist_ok=True)
    moved = []
    if trace_path and os.path.exists(trace_path):
        dst = os.path.join(backup_dir, os.path.basename(trace_path))
        shutil.move(trace_path, dst)
        moved.append(os.path.basename(trace_path))
    dash = os.path.join(case_dir, "analysis", "dashboard.url")
    if os.path.exists(dash):
        shutil.move(dash, os.path.join(backup_dir, "dashboard.url"))
        moved.append("dashboard.url")
    if not moved:
        # Nothing was actually moved — clean up the empty dir
        try:
            os.rmdir(backup_dir)
        except OSError:
            pass
        return None
    return backup_dir

def _live_owner(case_dir: str | None = None) -> dict | None:
    """The session currently owning the trace beacon, if its claim is within
    the TTL — resetting underneath it loses that session's hook-authored trace
    entries (they live only on disk) and silences its hooks (beacon cleared).
    Scoped to `case_dir`: the owner file is machine-global, so a live claim on
    ANOTHER case's trace must not block this reset."""

        try:
            with open(_SESSION_FILE) as f:
                beacon_path = os.path.abspath(json.load(f).get("path") or "")
        except (OSError, ValueError):
            return None                      # no active beacon → nothing to protect

        if seen.tzinfo is None:

    except ValueError:
        return None

    return {**o, "age_sec": int(age)} if age <= _OWNER_TTL_SEC else None
