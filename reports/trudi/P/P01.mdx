# P01 분석 방법 적합성 확인

### P01.01 이름·확장자 판별

**구현.** 서버가 사건의 증거 종류를 정하는 공통 코드는 `core/evidence_kinds.py`이다 [1].
`dair.assess`는 이 판별로 작업 지시에서 뺄 도구를 정하고 IOC 탐지 범위 계산은 이 판별로 적용할 수 없는 항목을 정한다 [2][3].
`classify_name`은 파일 이름의 확장자로 `memory`·`pcap`·`disk_image`·`triage`를 정한다 [1].
`.vmem`·`.mem`·`.lime`·`.dmp`는 메모리로, `.pcap`·`.pcapng`·`.cap`은 패킷 캡처로, `.e01`·`.dd`·`.001`·`.vmdk`는 디스크 이미지로 본다 [1].
`.img`는 파일 이름에 `mem`이 있으면 메모리로, 없으면 디스크 이미지로 본다 [1].
`.raw`·`.aff4`와 이름에 `mem`이 든 `.bin`은 메모리와 디스크 이미지 둘 다로 센다 [1].
사건 폴더의 `evidence/`를 훑을 때 파일 이름이 `$MFT`이면 `triage`, `Manifest.db`이면 `mobile`로 본다 [4].
폴더 경로가 `windows/system32/config`로 끝나면 `triage`, `var/mobile`이나 `data/data`로 끝나면 `mobile`로 본다 [4].
호출 기록에서도 종류를 더한다 [5].
성공한 `tool_call`의 namespace가 `vol`이면 메모리, `net`이면 캡처, `tsk`·`ewf`·`img`이면 디스크 이미지, `ez`·`af`이면 `triage`로 보고 명령줄 토큰의 확장자도 같은 규칙으로 읽는다 [5].
판별은 종류를 더하기만 하고 결과를 `kinds`·`determined`·`live_monitoring`으로 돌려준다 [6].
`reason.plan`·`reason.audit_findings`를 뺀 `reason.*` 도구는 이와 별도로 호출 기록의 성공한 명령을 정규식으로 훑어 수집한 증거 종류를 검토 모델 입력 머리에 붙인다 [7].
이 정규식은 `.img`·`.dd`·`.e0N`과 `mmls`·`fsstat`을 디스크 이미지로, `.vmem`·`.dmp`·`.lime`과 `vol`을 메모리 이미지로 본다 [7].

도구 안에서 이름으로 처리 경로를 정하는 곳도 있다.
`ez.evtxecmd`는 받은 경로가 `.evtx`로 끝나면 파일로 보고 `-f`를, 아니면 폴더로 보고 `-d`를 EvtxECmd에 넘긴다 [8].
`ez.lecmd`는 경로가 `.lnk`로 끝나는지, `ez.jlecmd`는 경로에 `automaticDestinations`·`customDestinations`가 있는지로 `-f`와 `-d`를 고른다 [9].
`ez.rbcmd`는 경로가 `$I`로 시작하거나 `/$I`를 담는지, `ez.bstrings`는 마지막 경로 조각에 `.`이 있는지로 `-f`와 `-d`를 고른다 [9].
이 다섯 도구는 그 경로가 실제로 파일인지 확인하지 않는다 [8][9].
`ez.sqlecmd`는 이와 달리 경로가 실제 폴더인지 확인해 고른다 [9].
`ez.recmd_batch`는 폴더 아래에서 `ntuser.dat`·`sam`·`system`·`software` 같은 하이브 파일 이름을 대소문자 구별 없이 찾아 하이브마다 RECmd를 실행한다 [10].

**한계.** `ez.evtxecmd`의 확장자 비교는 대소문자를 구별한다 [8].
그래서 이름이 `.EVTX`로 끝나는 파일도 폴더로 보고 `-d`를 넘긴다 [8].
`ez.lecmd`의 비교도 대소문자를 구별해 이름이 `.LNK`로 끝나는 파일을 폴더로 본다 [9].
`ez.bstrings`는 메모리 덤프처럼 확장자가 없는 파일을 폴더로, 이름에 점이 있는 폴더를 파일로 본다 [9].
`.img` 파일은 `core/evidence_kinds.py`가 이름에 `mem`이 있으면 메모리로 보지만 `reason.*`의 정규식은 늘 디스크 이미지로 본다 [1][7].
README가 증거 예시로 드는 `memory.img`를 Volatility 도구로 읽으면 `dair.assess`의 판별은 메모리만 더하지만 검토 모델 입력 머리에는 디스크 이미지도 수집했다고 적힌다 [1][5][7][11].

### P01.02 메타데이터 조회

**구현.** `core/evidence_kinds.py`는 사건 폴더의 `mnt/` 아래 하위 폴더를 조회해 디스크 이미지가 있는지 정한다 [12].
하위 폴더가 마운트 지점이거나 안에 항목이 하나라도 있으면 `disk_image`로 본다 [12].
`ewf.mount_full_image`는 `ewfmount`로 붙인 장치에서 `mmls`로 파티션 표를 읽는다 [13].
Meta 줄과 미할당 줄을 뺀 파티션을 설명에 NTFS가 든 것부터, 그다음 크기가 큰 것부터 줄 세운다 [13].
줄 세운 파티션마다 `fsstat`을 실행해 `File System Type`이 NTFS인 첫 파티션의 오프셋으로 마운트한다 [14].
`tsk.fsstat` 같은 Sleuth Kit 도구는 파티션을 스스로 고르지 않고 모델이 준 오프셋을 그대로 쓴다 [15].
디스크 이미지의 OS를 따로 판별하는 코드는 없다.

**한계.** `mnt/` 하위 폴더를 읽다 `PermissionError`가 나면 내용을 확인하지 않고 `disk_image`로 센다 [12].
다른 `OSError`가 나면 그 폴더를 건너뛰고 판별 결과에 그 사실을 남기지 않는다 [12].

### P01.03 내용·헤더 검사

**구현.** `misc.evtx_dump`와 `misc.evtx_filter`는 입력 파일의 앞 12바이트를 읽어 이벤트 로그 형식을 정한다 [16].
0번 오프셋이 `ElfFile\x00`이면 EVTX로, 4번 오프셋이 `LfLe`이면 옛 EVT로 보고 둘 다 아니면 `unknown`으로 둔다 [16].
`ez.evtxecmd`는 같은 이벤트 로그를 받지만 헤더를 보지 않는다 [8].

**한계.** 파일을 열거나 읽다 `OSError`가 나면 `unknown`으로 두고 EVTX 경로로 진행한다 [16].
`misc.evtx_dump`는 응답의 `log_format`에 `unknown`을 싣는다 [17].
`misc.evtx_filter`는 판별 결과를 응답에 싣지 않고 `evtx_dump.py`를 그대로 실행한다 [18].

### P01.04 방법과 형식·OS 대조

**구현.** `dair.assess`는 다음 작업 지시를 만드는 DAIR 모델이 낸 `priority_tools`와 검증 과제를 사건의 증거 종류와 대조한다 [19].
`tools/tool_capabilities.py`는 도구마다 필요한 증거 종류를 표로 둔다 [20].
`vol.`은 `memory`, `net.`은 `pcap`, `tsk.`·`ewf.`·`img.`은 `disk_image`, `ez.`·`af.`는 `disk_image`나 `triage`를 요구한다 [20].
`plaso.create_timeline`·`misc.evtx_filter`처럼 도구 하나하나에 따로 적은 요구도 있다 [20].
표에 없는 도구는 어느 사건에나 맞는 것으로 본다 [21].
사건이 요구 종류를 하나도 갖지 않으면 그 도구를 작업 지시에서 빼고 `server_filtered_tools`로 응답과 호출 기록에 남긴다 [19][22].
검증 과제는 방법 도구가 모두 맞지 않으면 빼고 일부만 맞으면 맞는 도구만 남긴다 [23].
DAIR 모델에게 보내는 도구 목록도 사건이 가진 종류에 맞는 도구만 남긴다 [24].
거르기는 `evidence/`나 `mnt/`에서 종류를 하나라도 찾아 판별이 정해졌을 때만 하고 live-monitoring 호출 기록에서는 하지 않는다 [25].
작업 지시의 도구를 모두 실행했는지 세는 검사도 같은 표로 맞지 않는 도구를 뺀다 [26].

이 대조는 `dair.assess`의 작업 지시에만 적용된다 [19].
모델이 증거 종류에 맞지 않는 도구를 직접 부르면 서버는 막지 않는다.
`reason.plan`·`reason.advise`가 돌려주는 `priority_tools`는 증거 종류와 대조하지 않는다 [27].
증거 종류에는 OS가 없어 Linux 디스크 이미지에도 `ez.`·`af.` 같은 Windows 산출물 도구가 맞는 것으로 남는다 [20].
실시간 감시 도구와 `live.*` 도구는 대상 단말의 OS를 확인하지 않는다 [28][29].
`monitor.baseline_capture`는 `client_id`의 접두어만 검사하고 Linux 산출물 `Linux.Sys.Pslist`·`Linux.Network.Netstat`을 수집한다 [28].
`live.*` 도구는 `ps`·`/proc`·`lsof` 같은 Linux 명령을 고정해 실행한다 [29].
`velo.list_clients`는 단말의 `os_info.system`을 돌려주지만 감시 도구는 이 값을 읽지 않는다 [30].

이벤트 로그 도구는 내용·헤더 검사로 판별한 결과로 방법을 고른다.
`misc.evtx_dump`는 EVT로 판별한 파일을 `evtx_dump.py` 대신 libevt의 `evtexport`로 파싱한다 [17].
`misc.evtx_filter`는 EVT 파일이면 실행하지 않고 `misc.evtx_dump`를 쓰라고 돌려준다 [18].
`ewf.mount_full_image`는 NTFS 파티션을 찾지 못하면 마운트하지 않고 조사한 파티션과 파일 시스템 종류를 응답에 싣는다 [14].

**한계.** `evidence/` 탐색은 깊이 8, 폴더 2,000개, 1.5초 가운데 하나에 닿으면 멈추고 그때까지 찾은 종류로 판별을 정한다 [31].
멈췄다는 사실은 결과에 남지 않아 일부만 훑은 목록으로도 `determined`가 참이 되어 도구를 거른다 [6][31].
같은 `evidence/` 폴더의 결과는 폴더 수정 시각이 같으면 300초 동안 다시 쓴다 [32].
사건 폴더는 호출 기록 파일 경로의 두 단계 위로 정한다 [33].
호출 기록을 `<사건>/analysis/` 밖에 두면 다른 폴더의 `evidence/`·`mnt/`를 보고 판별한다 [33].
`case_context`에 `live=true`나 `endpoint_host`라는 글자가 있으면 모델이 쓴 문장만으로 `live` 종류를 더한다 [6].
서버를 다시 시작한 뒤 다른 기록 호출보다 먼저 부른 `dair.assess`는 호출 기록을 다시 읽기 전의 빈 기록으로 판별한다 [34].
그때는 사건 폴더도 정해지지 않아 판별이 정해지지 않은 것으로 보고 아무 도구도 거르지 않는다 [33][34].

```python
def classify_name(name: str) -> set:
    """Kinds a single evidence file NAME implies (by extension)."""
    n = str(name or "").strip().strip("'\"").lower()
    if not n or "." not in n:
        return set()
    if n.endswith(_PCAP_EXT):
        return {"pcap"}
    if n.endswith(_MEM_EXT):
        return {"memory"}
    if n.endswith(".img"):
        return {"memory"} if "mem" in os.path.basename(n) else {"disk_image"}
    if n.endswith(_DISK_EXT):
        return {"disk_image"}
    if n.endswith(_AMBIGUOUS_EXT):
        if n.endswith(".bin") and "mem" not in os.path.basename(n):
            return set()
        return {"memory", "disk_image"}
    if n.endswith("$mft") or os.path.basename(n) == "$mft":
        return {"triage"}
    return set()
```

```python
def _dir_marker(rel_lower: str) -> str:
    """Kind a directory's relative path (lower-case, '/'-joined) marks, or ''."""
    if rel_lower.endswith("windows/system32/config"):
        return "triage"

        return "mobile"
    return ""
```

```python
def _trace_kinds(entries) -> set:
    kinds: set = set()
    for e in entries or []:
        if not isinstance(e, dict) or e.get("type") != "tool_call" or e.get("success") is not True:
            continue
        if str(e.get("source") or "").startswith("claude_code"):
            continue                    # agent shell commands are not evidence signals
        mcp = str(e.get("mcp_tool") or "").lower()
        ns_kind = _NS_KIND.get(mcp.split("_", 1)[0]) if mcp else None
        if ns_kind:
            kinds.add(ns_kind)
        for tok in str(e.get("cmd") or "").split():
            if "sectionobject" in tok.lower():
                continue                # vol.dumpfiles output (…ImageSectionObject….img)
            k = classify_name(tok)
            if k == {"memory", "disk_image"} and ns_kind in ("memory", "disk_image"):
                k = {ns_kind}           # an ambiguous .raw fed to vol/tsk/img says which
            # Produced output is not evidence — except a capture or RAM image
            # the agent extracted from an archive in evidence/ (a disk-image
            # extension there is a carved/dumped file, never a new image).
            if any(p in tok for p in _PRODUCED_DIRS):
                k = {x for x in k if x in ("pcap", "memory")} \
                    if tok.lower().endswith(_PCAP_EXT + _MEM_EXT) else set()
            kinds |= k
    return kinds
```

```python
def _mmls_partitions(stdout: str) -> list[dict]:
    """Real partitions from an mmls table, largest first.

    Skips the Meta and Unallocated rows and keeps every data partition whatever
    its description: a GPT table calls them "Basic data partition", so matching
    the word NTFS in the description finds nothing at all.
    """
    out = []
    for line in (stdout or "").splitlines():
        m = _MMLS_ROW_RE.match(line.strip())
        if not m:
            continue
        slot, start, end, length, desc = m.groups()
        if not slot[0].isdigit():      # Meta / ------- rows carry no partition
            continue
        out.append({"slot": slot, "start": int(start), "end": int(end),
                    "length": int(length), "description": desc.strip()})
    # A description that names the filesystem is the strongest hint; size breaks ties.
    return sorted(out, key=lambda p: ("ntfs" in p["description"].lower(), p["length"]),
                  reverse=True)
```

```python
    evd = os.path.join(case_dir, "evidence")

        return set()
    try:
        key = (os.path.realpath(evd), os.stat(evd).st_mtime)
    except OSError:
```
