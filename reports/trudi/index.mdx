# trudi 원고

셀 원고의 머리다. 셀마다 이 폴더 아래 축 폴더의 `<축>/<셀ID>.mdx`에 쓴다.
셀과 상세 항목의 정의는 `matrix/cells/<축>/<셀ID>.mdx`를 따른다.
상세 항목마다 **구현**을 쓰고 그 방식이 적용되지 않는 경로나 조건이 있으면 **한계**를 따로 쓴다.
본문의 [번호]는 그 파일 끝 **근거**의 같은 번호를 가리킨다.

**기준 커밋.** [`88fbca7`](https://github.com/nebulae/trudi/tree/88fbca78186b6a0ca40423cf5e37a9dc46ae051e)(2026-09-24).
줄 번호는 모두 이 커밋 기준이다.

**범위.** `server.py`가 실행하는 stdio MCP 서버를 본다.
`server.py`는 `tools/`의 모듈 25개를 namespace로 붙이고 모델에게 보이는 MCP 도구는 288개다.
저장소의 `claude/hooks`(Claude Code 훅), `opencode/`(OpenCode 플러그인), `bin/`의 `trudi` 실행기·대시보드·경보 대기 스크립트 `trudi-alert-waiter.py`, `pilot/`(실행기 본체와 호출 기록을 vera 사건 파일로 옮기는 `pilot.mirror`), `demo/`는 이 서버를 쓰는 클라이언트와 운영 구성이고 `install.sh`가 훅을 Claude Code 설정에 등록한다.
`monitoring/artifacts/`의 탐지 틀, `response/recipes/`의 대응 recipe, 감시 프로세스 `bin/trudi-velo-watcher.py`는 서버 도구(`monitor.start_watcher`·`respond.suggest_containment`)가 직접 읽거나 실행하므로 서버 동작으로 본다.
상세가 클라이언트 쪽 방식을 묻는 경우(예: T02.03)나 같은 저장소의 CLI·클라이언트가 서버 기록으로 산출물을 만드는 경우(F06)에만 이 구성을 구현으로 세고, 그 밖에는 원고에 사실로만 적는다.

**실행 프로필.** `server.py`를 직접 실행할 때 환경변수 `TRUDI_SLIM_TOOL_DESCRIPTIONS`가 `1`이면 모든 도구 설명을 첫 단락으로 줄이고 300자 안에서 자른다.
`misc.record_finding`·`dair.assess`·`reason.evaluate_finding`·`misc.record_agent_message`·`reason.hypothesize` 다섯 도구의 설명은 코드에 정해 둔 요약으로 바꾸고 이 요약에는 300자 상한을 적용하지 않는다.
입력 schema는 바꾸지 않는다.
코드 주석은 OpenCode 등록 스크립트가 이 값을 켜고 Claude Code에는 켜지 않는다고 적는다.
원고가 인용한 도구 설명은 이 값을 켜지 않은 전체 설명이다.
이 축약이 바꾸는 것과 그대로 두는 것은 T10.04에서 본다.

**확인 방법.** 코드는 기준 커밋을 `git show`로 읽었다.
서버를 실행하지 않았고 조사를 진행하지 않았다.
저장소 `cases/`의 조사 실행 기록은 기준 커밋 이전 코드로 남은 것이 있고 도구 버전을 알 수 없어 근거로 쓰지 않았다.
도구 이름은 네임스페이스와 함수 이름을 이은 것이다(예: `misc.record_finding`).

**외부 도구 버전 기준.** 서버는 외부 도구 버전을 고정하지 않는다(T05).
`install.sh`는 SANS SIFT Workstation에서 실행한다고 전제하고 apt·pip로 도구를 더 설치하며 pip 의존성은 `>=` 범위로만 적는다.
그래서 기준 커밋 전 마지막 정식 SIFT Workstation 설치 정의인 `teamdfir/sift-saltstack` v2026.04.21(Ubuntu 22.04)을 기준 환경으로 삼는다.
저장소 안의 설치·배포 정의(`install.sh`, `demo/`의 Dockerfile)가 버전을 고정한 도구는 그 버전을 먼저 쓴다.
그다음은 SIFT 설치 정의가 고정한 버전, Ubuntu 22.04 저장소의 패키지 버전 차례다.
GIFT PPA·pip처럼 받는 때에 따라 버전이 달라지는 것은 공개 시각이 기준 커밋 시각(2026-09-24 21:35Z)보다 앞선 최신 릴리스를 쓴다.
공개 시각은 PyPI 업로드 시각이나 GitHub 릴리스 공개 시각이고 태그 이름의 날짜가 아니며 공개 시각을 알 수 없으면 기준 커밋 날짜의 전날까지 나온 릴리스만 센다.
SIFT가 버전 없이 최신 바이너리나 기본 브랜치를 받는 도구는 기준 커밋 시각 전 마지막 소스 커밋으로 확인한다.
이때 배포된 바이너리가 그 커밋으로 빌드됐다는 보장은 없다.
원고가 인용한 도구 버전은 이 문단에 모아 적는다.
저장소가 고정한 버전으로는 Chainsaw v2.10.2(`install.sh`)와 Velociraptor v0.76.1(`demo/live-monitoring`의 Dockerfile)을 쓴다.
Ubuntu 22.04 패키지로는 Sleuth Kit 4.11.1(GIFT PPA 4.11.1+gift-1ppa1~jammy), tcpdump 4.99.1(4.99.1-3ubuntu0.2), hashdeep 4.4(4.4-7.1), glibc 2.35, OpenSSH 8.9p1, Python 3.10.12를 썼다.
기준 커밋 시각 전 최신 릴리스로는 yara-python 4.5.4, Anthropic Python SDK 1.8.0, python-dotenv 1.2.3, machinae 1.4.11, Volatility 3 2.28.2, Plaso 20260720을 썼다.
FastMCP는 기준 날짜의 최신 릴리스가 4.0.9이지만 4.0.0부터 trudi가 불러오는 `fastmcp.tools.tool` 모듈 이름이 없어져 서버 일부가 동작하지 않으므로 3.x의 마지막 릴리스인 3.4.7(2026-08-10)을 쓴다(T08).
FastMCP 3.4.7이 쓰는 MCP Python SDK는 `mcp<2.0` 범위에서 기준 커밋 시각 전 최신 릴리스인 1.30.0을 쓴다.
버전 없이 받는 도구로는 machinae 설정 파일을 기본 브랜치 커밋 `d5deae8`로, RECmd와 rla를 소스 커밋 `bcd0ac3`(2026.5.0)으로 확인했다.

**바뀔 수 있는 것.** 범위와 외부 도구 버전 기준은 조사하며 맞지 않는 곳이 나오면 검토를 거쳐 바꾼다.
