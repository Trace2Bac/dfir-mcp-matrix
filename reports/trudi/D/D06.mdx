# D06 결론 도출

### D06.01 규칙·키 기반 상관

**구현.** 이 방식은 앞선 호출의 출력을 호출 기록에서 다시 읽어 결과 항목을 잇는 `correlate.process_to_file`·`correlate.network_to_process`·`af.prefetch_deletion`·`af.event_log_clear`, 발견사항의 기법 ID를 나누는 `coverage.report`, 파일 하나의 행이나 사건을 정한 규칙으로 지표로 나누는 `af.timestomp_drift`·`af.usn_gaps`·`af.sysmon_evasion`·`misc.device_install_inventory`·`misc.parse_scheduled_tasks`에 있다 [1][2][3][4][5][6].
`correlate.*` 도구는 호출 기록의 `tool_call` 항목 가운데 명령 문자열에 정한 낱말이 든 항목을 최근 50개까지 고른다 [1].
`correlate.process_to_file`은 명령에 `vol`이 든 호출의 출력 줄에서 PID와 경로를 뽑고 `fls`·`MFTECmd`가 든 호출의 출력 줄로 경로 색인을 만든다 [7].
같은 경로가 색인에 없으면 파일 이름이 같은 경로로 잇고 결과 항목에 PID·경로·두 호출 ID·두 출력 줄을 싣는다 [8].
`correlate.network_to_process`는 `pslist`·`psscan` 출력 줄의 첫 숫자를 PID로 보고 `netscan`·`netstat` 출력 줄에서 고른 PID에 그 프로세스 이름을 붙인다 [9].
`af.prefetch_deletion`은 `pecmd` 출력에 나온 실행 파일 이름 집합을 만들고 AppCompatCache·Amcache 출력에는 나왔지만 그 집합에 없는 이름을 프리페치 삭제 후보로 싣는다 [10].
`af.event_log_clear`는 EvtxECmd 호출 출력에서 이벤트 ID 1102·104가 든 줄을 찾아 로그 삭제 사건으로 싣는다 [11].
`coverage.report`는 현재 발견사항 설명의 기법 ID를 모으고 CONFIRMED·LIKELY 발견사항에 든 것과 `dair.assess`가 권했지만 뒤의 발견사항에 나오지 않은 것을 나눈다 [12].
`af.timestomp_drift`는 MFTECmd CSV의 행마다 `LastModified0x10`과 `LastModified0x30` 열의 시각 차이가 `threshold_seconds`(기본 1초)를 넘으면 그 행을 `drift_records`에 싣는다 [2].
`af.usn_gaps`는 CSV의 `Usn` 값을 정렬하고 이웃한 두 값의 차이가 `gap_threshold`(기본 100)를 넘으면 그 쌍을 간격으로 싣는다 [3].
`af.sysmon_evasion`은 RECmd CSV에서 키 경로에 `sysmon`이 든 `Start` 값이 4 이상인 행과 Sysmon Operational 로그 키의 `MaxSize` 값이 100KB보다 작은 행을 `indicators`에 싣는다 [4].
`misc.device_install_inventory`는 장치 설치 로그의 사건을 장치 경로에서 뽑은 값으로 만든 식별 키마다 한 장치로 모은다 [5].
HID와 대용량 저장 장치 종류를 함께 가진 장치와 제조사·제품 이름·식별 키에 키 입력 주입 장치 이름이 든 장치에는 `flag_reasons`를 붙여 `flagged`에 싣는다 [5].
`misc.parse_scheduled_tasks`는 예약 작업 파일마다 주입 장치 payload 정규식이 맞으면 `injector_payload`를 표시한다 [6].

**예외.** 호출 기록을 다시 읽는 상관 도구는 앞선 호출의 출력을 호출 기록 항목의 `stdout_excerpt`에서만 읽는다 [1][10][11].
호출 기록은 이 값에 표준 출력의 앞 600자만 남긴다 [13].
그래서 출력의 600자 뒤에 있는 행은 상관에 들어가지 않는다.
`af.prefetch_deletion` 설명은 AppCompatCache·Amcache에 있고 프리페치 파일이 없는 실행 파일을 찾는다고 적는다 [14].
코드는 `pecmd` 출력의 앞 600자에 이름이 없으면 그 실행 파일을 프리페치가 없는 것으로 세고 결과의 `cross_ref_complete`를 늘 참으로 둔다 [10][15].

`af.timestomp_drift` 설명은 `$STANDARD_INFORMATION` 시각과 `$FILE_NAME` 시각을 비교한다고 적지만 코드는 수정 시각 한 쌍만 비교한다 [16][2].
설명은 `max_records`(기본 200)를 돌려줄 `drift_records` 수의 상한이라고 적지만 코드는 그 수에 닿으면 CSV 읽기를 멈춘다 [16][2].
그래서 결과의 `total_checked`와 `drift_count`는 읽기를 멈춘 곳까지만 센 값이다 [2].
행이 1,000,000개를 넘을 때도 알리지 않고 읽기를 멈춘다 [2].
`af.sysmon_evasion` 설명은 `SysmonDrv`의 `Start`가 1이 아닌지도 검사한다고 적지만 코드는 `Start` 값이 4 이상인지만 본다 [17][4].
`misc.parse_scheduled_tasks` 설명은 작업마다 payload 서명을 찾는다고 적지만 코드는 작업 파일마다 앞 16,384바이트만 읽어 정규식을 댄다 [18][6].

### D06.03 통계·점수 산정

**구현.** 이 방식은 `attribution.attribute_actors`, `correlate.mitre_map`, `accuracy.compare`에 있다 [19][20][21].
`attribution.attribute_actors`는 현재 CONFIRMED·LIKELY 발견사항의 설명에서 ATT&CK 기법 ID를 정규식으로 뽑는다 [19].
위협 그룹마다 관찰한 기법과 그룹 기법의 겹침으로 정밀도·재현율·F1을 구하고 겹친 기법의 tactic 수에 0.1을 곱해 더한 값을 `score`로 둔다 [22].
겹친 기법이 5개 이상이고 tactic이 3개 이상이면 `HIGH`, 기법 3개·tactic 2개 이상이면 `MEDIUM`, 기법 2개 이상이면 `LOW`다 [23].
상위 그룹이 `HIGH`면 `LIKELY`, `MEDIUM`이면 `SUSPECTED` 등급의 발견사항 문안을 응답에 싣는다 [24].
`correlate.mitre_map`은 글에 맞은 기법 키워드 수를 그 기법의 키워드 수로 나눈 값을 점수로 두고 점수 차례로 후보 기법을 돌려준다 [20].
`accuracy.compare`는 운영자가 준 정답 파일의 기대 발견사항과 기록된 발견사항을 낱말 집합의 Jaccard 유사도로 짝짓고 정밀도·재현율·F1을 계산한다 [21].

**예외.** `attribution.attribute_actors`는 tactic 수를 기법 표의 `tactic` 문자열을 공백으로 나눈 낱말 수로 센다 [25].
`install.sh`가 기본 위치로 복사하는 저장소의 기법 표는 `tactic`에 `Credential Access`처럼 공백이 든 이름을 둔다 [26].
그래서 `Credential Access` 기법 하나가 tactic 2개로 세어지고 이 수가 `score`의 가산점과 `HIGH`·`MEDIUM` 판정에 들어간다 [22][23][25].
응답의 발견사항 문안은 겹친 기법 수와 함께 관찰한 전체 기법의 tactic 수를 적지만 등급 판정에는 겹친 기법의 tactic 수를 쓴다 [22][24].

### D06.04 모델 추론·서술

**구현.** 이 방식은 서버 안에서 모델을 부르는 `reason.synthesize`, `reason.hypothesize`, `reason.audit_findings`, `dair.assess`에 있다 [27].
`reason.*` 도구는 `REASON_BACKEND`, `dair.assess`는 `DAIR_BACKEND`가 비어 있으면 `ANTHROPIC_API_KEY`가 있을 때 Anthropic API를, 호환 서버 주소만 있을 때 OpenAI 호환 API를 쓴다 [27].
`reason.synthesize`는 Report 단계에서만 실행되고 기록된 현재 발견사항의 등급·호출 ID·typed claim·설명과 모델이 준 서술을 검토 모델에 보낸다 [28].
검토 모델은 공격 사슬에서 근거가 없는 단계, 서로 어긋나는 발견사항, 근거보다 강하게 쓴 설명을 차단 항목과 권고로 나눠 답한다 [29].
서버는 그 답을 typed issue로 바꿔 호출 기록에 저장한다 [30].
`reason.hypothesize`는 관찰 하나에 대해 악성·정상 가설을 가능성 차례로 만들게 하고 `mode`가 `absence`이면 아직 보지 않은 자료 범주를 정보 이득 차례로 고르게 한다 [31][32].
`dair.assess`는 모델에게 조사 단계와 다음 작업을 정하게 하고 Triage 단계에서는 결론을 다시 확인할 검증 과제를 내게 한다 [33].
`reason.audit_findings`는 호출 기록의 모델 서술(`investigation_narration`) 가운데 아직 감사하지 않은 것을 `narration_window`(기본 60)개까지 고른다 [34].
고른 서술과 현재 발견사항 전체를 검토 모델에 보내 서술에만 있고 발견사항으로 기록되지 않은 사실 주장을 후보로 받는다 [35].
서버는 후보를 응답에 실어 돌려줄 뿐 발견사항으로 기록하지 않는다 [36].
검토 모델의 판정으로 발견사항 기록을 정하거나 보고서를 막는 방식은 D07.05에서 본다.

### D06.05 사용 근거·변환 기록

**구현.** 이 방식은 `reason.*` 호출 기록 항목, `correlate.*`·`af.event_log_clear`·`af.prefetch_deletion` 결과 항목, 스스로 기록하는 `misc.device_install_inventory`·`misc.parse_scheduled_tasks`의 호출 기록 항목, 서버 안 파이썬 도구의 기본 호출 기록 항목에 있다 [37].
`reason.*` 도구는 호출이 인용한 `input_call_ids`와 모델에게 보낸 사용자 메시지를 `reason_call` 항목에 남긴다 [37].
모델 입력 기록의 구성은 L02에서 본다.
`reason.synthesize`는 모델이 행을 가져올 수 있는 호출 ID로, 모델이 준 ID에 현재 발견사항과 그 근거 호출 ID를 더해 넘긴다 [38].
`correlate.process_to_file` 결과 항목에는 짝지은 메모리 호출 ID와 디스크 호출 ID가 실린다 [8].
`correlate.network_to_process`는 `netscan_call_id`·`pslist_call_id`를, `af.event_log_clear`는 `source_call_id`를, `af.prefetch_deletion`은 `appcompat_call_id`를 싣는다 [39].
서버 안 파이썬 도구가 스스로 호출 기록을 남기지 않으면 미들웨어가 결과 전체를 JSON으로 저장 출력에 남기는 `tool_call` 항목을 만든다 [40].
이 항목의 `input_call_ids`에는 마지막 `dair.assess` 호출 ID가 들어간다 [40][41].
코드 설명은 이 값을 지금 도구 묶음을 지시한 DAIR 항목이라고 정의하고 필드에 든 값은 그 정의와 맞다 [41].
결론 도구가 실제로 읽은 호출은 `netscan_call_id`처럼 결과 항목의 호출 ID 필드에만 남는다 [8][39].
`misc.device_install_inventory`와 `misc.parse_scheduled_tasks`는 읽은 파일 경로를 자기 호출 기록 항목의 `cmd`에 남긴다 [42].
`af.timestomp_drift`·`af.usn_gaps`·`af.sysmon_evasion`은 결과에 읽은 CSV 경로를 싣지 않고 미들웨어 항목의 `cmd`도 도구 이름뿐이어서 어느 파일에서 지표를 뽑았는지 남지 않는다 [43][40].
`attribution.attribute_actors`와 `coverage.report` 결과에는 기법 ID를 가져온 발견사항의 호출 ID가 없다 [22][12].
`reason.audit_findings`는 `input_call_ids`를 받지 않으면 이번에 모델에 보낸 서술과 발견사항의 호출 ID를 `input_call_ids`로 넘겨 `reason_call` 항목에 남긴다 [44][37].

**예외.** `reason.audit_findings`는 모델이 `input_call_ids`를 주면 그 값을 그대로 넘기고 이번에 모델에 보낸 서술과 발견사항의 호출 ID는 남기지 않는다 [44].
이 도구는 인용한 호출의 출력을 프롬프트에 붙이지 않으므로 남은 ID는 모델이 실제로 읽은 입력과 다를 수 있다 [45].
미들웨어 항목의 `input_call_ids`에 든 마지막 `dair.assess` 호출 ID는 코드 설명이 정한 뜻과 맞으므로 이 예외와 다르다 [40][41].

### D06.06 규칙 기반 공격 단계 분류·흐름 서술

**구현.** 이 방식은 `reason.pre_report_check`의 공격 생애주기 범위 계산, `misc.write_final_report`가 붙이는 범위 표, `correlate.mitre_map`에 있다 [46][47][20].
범위 계산은 지속성·권한 상승·측면 이동·실행·유출 다섯 단계를 정해 두고 단계마다 그 단계를 세우는 typed claim의 `category`·`act`와 원천 자료의 명령 정규식을 둔다 [48].
단계의 `category`·`act`에 맞는 현재 발견사항 가운데 CONFIRMED·LIKELY 긍정 발견사항이 있으면 `established`, SUSPECTED 긍정 발견사항만 있으면 `suspected`, 부재 발견사항이 있으면 `ruled_out`이다 [49].
맞는 발견사항이 없으면 성공한 호출의 명령과 MCP 도구 이름에 원천 자료 정규식이 맞는지로 `examined`와 `not_examined`를 가른다 [49].
`reason.pre_report_check`가 이 결과를 남기고 `misc.write_final_report`가 단계별 상태와 확인한 원천 자료 수를 표로 붙인다 [46][47].
`correlate.mitre_map`은 키워드가 맞은 기법의 ID·이름·tactic을 돌려준다 [20].
시간 차례로 공격 흐름 문장을 만드는 코드는 없다.

**예외.** 보고서 범위 표의 설명은 근거 있는 부재 발견사항으로 단계를 배제한다고 적는다 [47].
코드는 등급과 관계없이 그 단계의 부재 발견사항이 하나라도 있으면 `ruled_out`으로 둔다 [49].
부재 발견사항의 필수 출처 대조는 UNCONFIRMED 등급에만 적용된다(D07.07) [50].
그래서 출처 대조를 거치지 않은 SUSPECTED 부재 발견사항 하나로도 보고서에 그 단계가 `ruled out`으로 실린다 [47][49][50].

```python
def _recent_tool_stdouts(tool_substring: str, max_entries: int = 50) -> list[dict]:
    """Return recent tool_call entries whose cmd contains tool_substring.

    Used by correlation tools to look up the actual output the agent collected.
    Returns a list of {call_id, cmd, stdout_excerpt, success} dicts.
    """
    from core.execution_log import log
    matches = []
    for e in reversed(log._entries):
        if e.get("type") != "tool_call":
            continue
        cmd = e.get("cmd", "") or ""
        if tool_substring not in cmd:
            continue
        matches.append({
            "call_id": e.get("call_id"),
            "cmd": cmd,
            "stdout_excerpt": e.get("stdout_excerpt", "") or "",
            "success": e.get("success", False),
        })
        if len(matches) >= max_entries:
            break
    return list(reversed(matches))
```
