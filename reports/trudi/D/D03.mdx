# D03 파생물 무결성 검증

### D03.01 기준값 자동 계산

**구현.** 이 방식은 발견사항 검토에 인용된 출력과 보고 직전 호출 기록 항목이 가리키는 출력 파일에 적용된다.
파생물을 만들거나 보관할 때는 해시를 계산하지 않고 호출 기록 항목에는 출력의 글자 수와 줄 수만 들어간다 [1].
기준값은 모델이 발견사항 검토를 부를 때 서버가 스스로 계산한다.
`reason.evaluate_finding`과 `misc.submit_finding`은 인용한 호출의 출력 바이트를 읽어 SHA-256 `output_sha256`을 evidence packet에 담는다 [2].
같은 packet에 읽은 파일과 출력 폴더의 버전(장치·inode·크기·수정 시각·변경 시각)과 인용 항목의 내용 digest를 담는다 [3][4].
출력은 하나마다 앞 64 MiB, packet 전체로 256 MiB까지만 해시하고 넘으면 앞부분만 해시한 뒤 `scan_truncated`를 적는다 [5].
키를 쓰지 않는 해시이고 packet은 검토 항목의 `evidence_packet`으로 호출 기록 파일에 남는다 [6].

`reason.pre_report_check`는 보고 전 상태를 묶은 해시 `readiness_fingerprint`를 계산해 자기 호출 기록 항목에 남긴다 [7].
`readiness_fingerprint`는 현재 항목들과 각 항목의 `stdout_path`·`output_path`가 가리키는 파일의 크기·수정 시각·변경 시각·inode를 묶은 SHA-256이다 [8].
이 값은 파일 내용을 해시하지 않는다 [8].
보고서와 호출 기록 내보내기를 쓴 호출의 항목은 이 값에서 뺀다 [8].

해시를 계산하는 때가 파생물을 만들 때가 아니라 검토와 보고 직전이다.
모델이 해시 도구를 부르는 방식이 아니어서 이 상세에 연결했다.
검토에 인용되지 않은 출력과 보고서 파일에는 기준값이 없다.
`hash.file`은 증거와 파생물을 가리지 않는 해시 도구라 D03.02에는 연결하지 않았다 [9].

### D03.09 도구 호출 중 자동 검증

**구현.** 이 방식은 검토를 거친 CONFIRMED·LIKELY 발견사항 기록, `misc.submit_finding`, `reason.evaluate_finding`, 최종 보고서와 호출 기록 내보내기에 적용된다 [10][11][12][13].
`packet_current`는 지금 파일 버전, 인용 항목의 digest, 사건 식별값, 검토 정책 digest를 packet의 값과 대조한다 [10].
내용을 다시 해시하지 않으며 `output_sha256`은 다시 대조하지 않는다 [10].
`misc.record_finding`은 CONFIRMED·LIKELY 발견사항에 쓰려는 검토 통과 기록 `review_receipt`가 지금 상태와 맞는지 이 함수로 본다 [11].
`misc.submit_finding`은 packet을 만든 직후와 발견사항을 기록하기 직전에 대조하고 `reason.evaluate_finding`은 검토가 끝난 뒤 대조한다 [12][6].
`misc.write_final_report`와 `misc.export_execution_log`는 지금 `readiness_fingerprint`를 다시 계산해 마지막 `reason.pre_report_check`의 값과 대조한다 [13].

기준값은 검토 항목과 보고 직전 점검 항목에 들어가므로 인용된 출력 파일과 다른 파일에 남는다.
인용 항목의 digest는 그 항목과 같은 호출 기록 파일에 들어가므로 호출 기록 파일을 고치면 둘이 함께 바뀔 수 있다 [4][6].
파일 버전 대조는 파일 메타데이터 비교라서 내용이 바뀌어도 장치·inode·크기·수정 시각·변경 시각이 그대로면 알아채지 못한다 [3].

**한계.** `receipt_required`와 `review_receipt`가 둘 다 없는 검토 항목으로 CONFIRMED·LIKELY 발견사항을 기록하면 packet 대조를 거치지 않는다 [14].
이 서버의 `reason.evaluate_finding`은 모든 검토 항목에 `receipt_required`를 붙이므로 이런 항목은 다른 코드가 쓴 호출 기록 파일을 이어 쓸 때 생긴다 [6].
`monitor.end_investigation`은 같은 호출 기록 내보내기를 `readiness_fingerprint` 대조 없이 한다 [15].
이 경로는 T03.03에서 본다.

### D03.10 불일치 시 중단·경고

**구현.** 대조가 어긋나면 그 출력을 근거로 삼는 기록과 보고를 멈춘다.
`misc.record_finding`은 `review_receipt` 게이트로 발견사항을 거부하고 인용 출력이 검토 뒤에 바뀌었다고 응답에 적는다 [16].
`misc.submit_finding`은 발견사항을 기록하지 않고 `retryable-review-failure`를 돌려준다 [12].
`reason.evaluate_finding`은 검토 결과를 실패로 바꾸고 `review_receipt`를 붙이지 않는다 [6].
`misc.write_final_report`와 `misc.export_execution_log`는 파일을 쓰지 않고 `pre_report_check_required` 게이트로 거부한다 [13].

def file_version(path):
    try:
        st = os.stat(path)
        return [st.st_dev, st.st_ino, st.st_size, st.st_mtime_ns, st.st_ctime_ns]
    except OSError:
        return None


def entry_identity(entry):
    return digest({k: v for k, v in entry.items() if k not in _VOLATILE})

def state_fingerprint(entries, case_id='', include_synthesis=True, scope='full') -> str:
    """scope='full' binds the pre-report approval to the whole semantic state;
    scope='claims' is the synthesis staleness key (claims + dispositions)."""
    records, files = [], {}
    for e in current_entries(entries):
        typ, tool = e.get('type'), e.get('tool')
        if typ in _IGNORED_TYPES or tool in _IGNORED_TOOLS:
            continue
        if scope == 'claims' and typ not in _CLAIM_TYPES and not (
                include_synthesis and tool == 'reason_synthesize'):
            continue
        if tool == 'reason_synthesize' and not include_synthesis:
            continue
        if typ == 'tool_call' and any(t in e.get('cmd', '') for t in (
                'misc_write_final_report', 'misc_export_execution_log', 'misc_serve_dashboard')):
            continue
        # Timestamps and accounting are not changes to the evidence or claim.
        records.append({k: v for k, v in e.items() if k not in {
            'ts', 'input_tokens', 'output_tokens', 'elapsed_seconds', 'backend_meta',
            'inputs', 'dair_phase', 'dair_depth', 'readiness_fingerprint'}})
        for k in ('stdout_path', 'output_file', 'output_path'):
            path = e.get(k)
            if isinstance(path, str):
                try:
                    st = Path(path).stat()
                    files[path] = [st.st_size, st.st_mtime_ns, st.st_ctime_ns, st.st_ino]
                except OSError:
                    files[path] = 'unavailable'

def _record_hash_result(result: dict, source_version: str) -> dict:
    """Retain the typed hash result as evidence, rather than an invocation log."""
    from core.execution_log import log
    try:
        path = os.path.abspath(result['file'])
        stat = os.stat(path)
    except OSError as exc:
        return {'success': False, 'error': str(exc), 'file': result['file']}
    if _cache_key(stat, path) != source_version:
        return {'success': False, 'error': 'File changed while hashing; retry', 'file': result['file']}
    version = [stat.st_dev, stat.st_ino, stat.st_size, stat.st_mtime_ns, stat.st_ctime_ns]
    payload = {k: result[k] for k in ('file', 'size_bytes', 'md5', 'sha1', 'sha256')}
    cid = log.record_tool_call(cmd=f"hash.file {result['file']}", success=True,
                               truncated=False, retries=0, exit_code=0,
                               stdout_full=json.dumps(payload), stdout_excerpt=json.dumps(payload))
    log.annotate_tool_call(cid, hash_result=payload, source_version=source_version,
                           hashed_file_version=version,
                           source_hashes={result['file']: result['sha256']})
    return {**result, '_trudi_call_id': cid}
