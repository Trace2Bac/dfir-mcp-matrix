# D08 보고 산출물 구성

### D08.01 증거·환경 manifest 포함

**구현.** 이 방식은 `misc.export_execution_log`가 내보내는 호출 기록 JSON과 사용자가 실행할 때만 만들어지는 `pilot.mirror`의 vera 사건 파일에 있다 [1][2].
`misc.start_execution_log`는 호출 기록을 열 때마다 서버가 불러온 코드의 git 커밋·브랜치·변경 여부와 `core`·`tools` 파이썬 파일의 SHA-256 요약을 `run_profile` 항목으로 남긴다 [3][4].
코드 정보는 서버가 모듈을 불러올 때 한 번 계산한다 [3].
모델 호출 항목에는 쓴 모델 이름이 들어간다 [5].
서버가 실행한 외부 도구의 버전은 서버 코드 정보만 담는 `run_profile` 항목에도, 호출 기록 내보내기와 최종 보고서에도 실리지 않는다 [4][6].
`misc.export_execution_log`는 호출 기록 항목 전체를 JSON 파일로 쓰고 같은 항목을 markdown으로도 쓴다 [1].
markdown은 `run_profile` 항목을 따로 그리지 않고 알 수 없는 종류로 보아 항목 JSON의 앞 120자만 싣는다 [7].
호출 기록 내보내기와 최종 보고서에는 분석한 증거의 경로·해시·크기를 모은 절이 없고 해시 결과는 개별 `tool_call` 항목으로만 남는다 [6].
`pilot.mirror`는 설명에 `hash.verify_evidence_hash` 호출을 vera 사건 파일의 증거 행(이름과 SHA-256)으로 옮긴다고 적는다 [2].

**예외.** 코드 정보의 커밋과 브랜치는 `git` 명령이 실패하거나 아무것도 출력하지 않으면 `?`로 남고 그 사실은 기록되지 않는다 [3].
`pilot.mirror`는 명령에 `verify_evidence_hash`가 든 `tool_call` 항목만 증거 행으로 옮긴다 [2].
그런데 `hash.verify_evidence_hash`는 호출 기록에 `hash.file <경로>` 명령의 `tool_call`과 `reason_call`만 남긴다 [8].
미들웨어는 도구가 스스로 항목을 남긴 호출에는 기본 `tool_call` 항목을 쓰지 않는다 [9].
그래서 vera 사건 파일에는 설명과 달리 증거 행이 생기지 않는다 [2][8].

### D08.02 수행·누락 범위 포함

**구현.** 이 방식은 `misc.export_execution_log`의 호출 기록과 `misc.write_final_report`가 보고서에 붙이는 범위 절에 있다 [1][10].
호출 기록 markdown은 `tool_call`마다 명령과 `OK`·`FAIL`·`TIMEOUT`, 재시도 수, `[TRUNCATED]`를 싣고 실패한 호출은 표준 오류도 싣는다 [11].
거부된 발견사항도 그 게이트와 함께 항목으로 실린다 [12].
`misc.write_final_report`의 본문은 클라이언트 모델이 넘긴 `content`이고 서버가 그 뒤에 절을 붙여 파일로 쓴다 [10].
서버가 붙이는 공격 생애주기 범위 표는 단계마다 상태와 확인한 원천 자료 수를 싣고 보지 않은 단계를 `NOT examined`로 적는다 [13].
IOC가 기록되어 있으면 IOC 표와 함께 ATT&CK 탐지 원천 가운데 확인한 수와 확인하지 않은 원천의 표를 싣는다 [14].
증거 레지스트리 절은 메일·대화 저장소와 패킷 분석에서 나온 상대방·신원·주체와 그 정리 상태를 싣는다 [15].
최종 보고서에는 부른 도구 목록이나 실패한 호출을 모은 절이 없다 [6].
`coverage.report`는 확인한 기법·찾은 기법·건너뛴 기법·보지 않은 기법을 markdown으로 만들어 응답에만 싣는다 [16].
사용자가 실행하는 `pilot.mirror`는 `tool_call`마다 명령, 도구 이름, 종료 코드, 출력을 vera 사건 파일의 action 행으로 옮기고 실패한 호출에는 `FAILED`와 표준 오류 400자를 적는다 [17].
출력은 저장 파일에서 262,144자까지 읽고 넘으면 잘렸다는 표시와 저장 파일 경로를 붙인다 [18].

**예외.** 서버는 모델이 쓴 `content`에 `attack-lifecycle coverage`, `registry inventory`, `## indicators of compromise` 같은 제목 글이 이미 있으면 그 절을 붙이지 않는다 [13][14][15].
그래서 모델 본문이 그 제목만 쓰고 다른 내용을 적으면 서버가 계산한 범위 표가 보고서에 실리지 않는다 [13][14].
이 절들의 재료를 보고서 전 점검 항목에서 읽다가 예외가 나면 레지스트리 목록을 비운 채 알리지 않고 보고서를 쓴다 [19].
`pilot.mirror`는 저장 파일을 읽지 못하면 앞 600자 발췌를 발췌라는 표시 없이 출력으로 싣는다 [18].
`pilot.mirror`는 vera 사건 파일에 이미 있는 호출 번호를 건너뛰는데 `tools.trudi_reset`은 호출 번호 카운터를 1로 되돌리고 사건 폴더 바로 아래의 vera 사건 파일은 지우거나 옮기지 않는다 [20][21].
그래서 초기화 뒤 같은 사건 파일로 다시 옮기면 앞 조사와 번호가 겹치는 새 호출이 실리지 않는다 [17][20].
이 경로는 코드로만 따라갔다.

### D08.03 발견사항과 근거 링크 포함

**구현.** 이 방식은 `misc.export_execution_log`가 내보내는 호출 기록 JSON·markdown에 있다 [1].
JSON의 발견사항 항목에는 `linked_call_id`, `input_call_ids`, typed claim의 근거 호출 ID, 게이트가 찾은 검토 호출 ID가 그대로 실린다 [22].
markdown은 발견사항마다 `linked_call_id`가 가리키는 호출의 번호·명령·성공 여부·출력 요약을 `Evidence Chain`으로 싣는다 [23].
markdown은 `input_call_ids`를 싣지 않으므로 `linked_call_id`가 0인 발견사항에는 근거 줄이 없다 [23].
`misc.write_final_report`가 붙이는 `Current recorded findings` 절은 발견사항 ID·호출 번호·등급·설명만 싣고 근거 호출 ID를 싣지 않는다 [24].
최종 보고서의 IOC 표는 IOC마다 근거 호출 ID를 6개까지 싣는다 [14].
사용자가 실행하는 `pilot.mirror`는 발견사항을 vera 사건 파일의 finding 행으로 옮기며 `linked_call_id`의 호출을 action 행으로 잇고 `input_call_ids`와 typed claim의 근거 호출 ID를 속성으로 싣는다 [25].

**예외.** `pilot.mirror`는 이미 옮긴 발견사항의 호출 번호도 건너뛰므로 초기화 뒤 같은 사건 파일로 다시 옮기면 앞 조사와 번호가 겹치는 새 발견사항이 실리지 않는다 [20][21].
이 경로는 코드로만 따라갔다.

### D08.04 검증·한계 포함

**구현.** 이 방식은 `misc.write_final_report`가 붙이는 검토 절, 호출 기록 markdown, `accuracy.export_report`에 있다 [26][27][28].
최종 보고서는 보고서 전 점검이 남긴 미해결 이의와 판정한 한계를 `Reviewer limitations and unresolved objections` 절로 붙인다 [26].
검토 모델이 볼 수 없었던 세부, 근거가 약한 처분, 교차 검토의 권고도 각각 절로 붙인다 [29].
호출 기록 markdown은 `dair.assess`의 검증 과제와 그 결과, 거부된 발견사항과 그 게이트를 싣는다 [27][12].
`accuracy.export_report`는 사용자가 준 정답 파일과 기록된 발견사항을 대조해 정밀도·재현율·F1, 짝지은 발견사항, 놓친 항목, 오탐, 등급 미달 목록을 markdown 파일로 쓴다 [28].
정답 파일의 부재 단언과의 대조는 `accuracy.compare`가 계산하지만 이 파일에는 싣지 않는다 [30][28].
증거 이미지의 해시 검증 결과를 모은 절은 없다 [6].

**예외.** 볼 수 없었던 세부·처분 검토·권고 절은 모델 본문에 같은 제목 글이 있으면 붙지 않는다 [29].
미해결 이의 목록을 보고서 전 점검 항목에서 읽다가 예외가 나면 목록을 비운 채 보고서를 쓴다 [26].

### D08.05 내보내기

**구현.** 이 방식은 `misc.write_final_report`, `misc.export_execution_log`, `accuracy.export_report`와 사용자가 실행할 때만 파일을 만드는 `pilot.mirror`에 있다 [31][1][28][32].
`misc.write_final_report`는 보고서 전 점검이 통과했고 DAIR 단계가 Report일 때 markdown 파일을 `output_path`에 쓰고 경로와 바이트 수를 돌려준다 [31][10].
`misc.export_execution_log`는 같은 점검을 거친 뒤 `<output_path>.json`과 `<output_path>.md`를 쓰고 두 경로를 돌려준다 [33].
`accuracy.export_report`는 정답 대조 결과를 markdown 파일로 쓰고 경로를 돌려준다 [28].
`pilot.mirror`는 사용자가 직접 실행하거나 `trudi --mirror`로 함께 시작할 때 호출 기록을 사건 폴더의 `<사건 ID>.vera` 파일로 옮기고 호출 기록이 늘 때마다 다시 옮긴다 [32].
이 파일은 사용자가 vera를 따로 내려받아 설치했을 때만 만들어진다 [34].

사용자가 따로 실행하는 `trudi-dashboard`는 사건 폴더의 호출 기록을 브라우저로 보여 주는 HTTP 서버이고 파일을 내보내지 않는다 [35].

```python
def _mirror_evidence(case: Case, entry: dict, known_labels: set[str]) -> bool:
    """A verify_evidence_hash call is the custody record: one Evidence row."""
    cmd = entry.get("cmd", "")
    parts = cmd.split()
    label = next((p for p in parts[1:] if not p.startswith("-")), "")
    if not label or label in known_labels:
        return False
    sha = _SHA256.search(entry.get("stdout_excerpt", "") or "")
    case.add_evidence(label=label, kind="image",
                      source="TRUDI hash.verify_evidence_hash",
                      sha256=sha.group(0) if sha else "",
                      notes=f"[trudi:cid {entry.get('call_id')}]")
    known_labels.add(label)
    return True
```

```python
def _code_identity() -> str:
    """Which server code is running: git commit, dirty flag, and a digest of
    core/ + tools/ as they were when this server process imported them. Edits
    landing on disk mid-run do not change the loaded code, so the trace must
    say what was loaded, not what is on disk now."""
    import hashlib
    import subprocess
    from pathlib import Path
    root = Path(__file__).resolve().parents[1]
    h = hashlib.sha256()
    for p in sorted([*root.glob("core/**/*.py"), *root.glob("tools/**/*.py")]):
        h.update(str(p.relative_to(root)).encode())
        h.update(p.read_bytes())
    def git(*args):
        try:
            return subprocess.run(["git", "--no-optional-locks", "-C", str(root), *args], capture_output=True,
                                  text=True, timeout=5).stdout.strip()
        except Exception:
            return ""
    dirty = " dirty" if git("status", "--porcelain", "--", "core", "tools") else ""
    return (f"commit {git('rev-parse', '--short', 'HEAD') or '?'} "
            f"branch {git('rev-parse', '--abbrev-ref', 'HEAD') or '?'}{dirty} "
            f"code_sha256 {h.hexdigest()[:16]}")


_CODE_IDENTITY = _code_identity()
```

```python
def _action_output(entry: dict) -> str:
    """The fullest retained output for a tool_call, within a size bound.

    Prefers the persisted stdout sidecar over the excerpt. A clip is stated in
    the text with the sidecar path, so the action never reads as complete
    output when it is not.
    """
    excerpt = entry.get("stdout_excerpt", "") or ""
    path = entry.get("stdout_path")
    text = excerpt
    if path:
        try:
            with open(path, errors="replace") as fh:
                text = fh.read(MIRROR_OUTPUT_CHARS + 1)
        except OSError:
            text = excerpt
    if len(text) > MIRROR_OUTPUT_CHARS:
        total = entry.get("stdout_chars")
        text = (text[:MIRROR_OUTPUT_CHARS].rstrip() +
                f"\n… [clipped at {MIRROR_OUTPUT_CHARS} chars"
                + (f" of {total}" if total else "") +
                f"; full output retained at {path}]")
    elif path and entry.get("truncated"):
        text += f"\n… [tool output was truncated when captured; sidecar {path}]"
    return text
```

```python
def spawn_mirror(case_dir: str) -> None:
    """Start the trace→vera mirror in follow mode, detached — the live
    record grows alongside the session (pilot/mirror.py is standalone and

    from pilot.bootstrap import parse_case_md

        [sys.executable, "-m", "pilot.mirror", trace, vera, "--follow"],
```
