# D04 출력 경로 제한

### D04.01 서버가 출력 위치 결정

**구현.** 이 방식은 호출마다 남기는 출력 텍스트 파일, 검토 모델의 추가 행 요청 결과, 작업 폴더, live monitoring 파일, 조사별 호출 기록과 보고서에 적용된다.
`.tool_output` 폴더는 서버가 호출 기록 파일 옆으로 정하고 파일 이름은 호출 ID다 [1].
검토 모델이 더 요청한 행은 같은 폴더의 `fetch-<호출 ID>-<n>.txt`에 쓴다 [2].
`net.tcpxtract_streams` 작업은 서버 캐시 폴더의 `jobs/<작업 ID>.d/` 아래 `stdout`·`stderr`·`exit` 파일에 출력을 쓴다 [3].
live monitoring 도구는 `TRUDI_CASES_ROOT/<case_id>/monitoring/` 아래에 baseline·watcher·alert 파일을 둔다 [4].
`monitor.start_investigation`과 `monitor.end_investigation`은 조사 호출 기록을 `analysis/<case_id>_<investigation_id>_trace.json`으로, 보고서를 `reports/<case_id>_<investigation_id>`에 `.json`·`.md`를 붙인 이름으로 정한다 [5].
`misc.chat_db_export`는 `output_dir`을 주지 않으면 `./exports/chat`에 쓴다 [6].

그 밖의 도구는 모델이 준 `output_path`·`output_dir`·`output_file`·`storage_file` 등을 출력 위치로 그대로 쓴다 [7].
`@output_safe`와 `assert_output_safe`는 실제 경로가 `/cases/`·`/mnt/`·`/media/` 아래이거나 경로에 `evidence` 폴더가 있는지만 보고 그 밖의 경로는 받는다 [7].
서버 지시문은 출력 경로를 analysis·exports·reports 안에 두라고 적지만 코드는 그 폴더와 대조하지 않는다 [8][7].
증거 위치를 거부하는 이 검사는 허용 폴더와 대조하지 않는다.
`ez.*`는 `output_dir`과 `output_file`을 따로 외부 도구에 넘기고 검사는 두 값을 서버 작업 폴더 기준으로 따로 풀어 본다 [9][7].
두 값을 합친 경로는 검사하지 않아 `output_file`에 `..`가 들어가도 거부하지 않는다 [9][7].
`misc.batch_run`은 모델이 준 명령을 출력 경로 검사 없이 실행한다 [10].
`misc.clear_case_run`은 모델이 준 `case_dir` 아래 analysis·exports·reports를 검사 없이 지운다 [11].
마운트 도구 `ewf.mount`·`ewf.mount_ntfs`·`ewf.mount_full_image`·`img.vshadow_mount`·`img.bde_mount`·`img.xmount_image`는 모델이 준 마운트 지점에 서버 계정으로 폴더를 만든 뒤 sudo로 그 위에 마운트한다 [12].
`@output_safe`가 보는 인자 이름에는 마운트 지점 인자가 없고 `ewf.*` 마운트 도구에는 `@output_safe`도 붙지 않는다 [13][12].
그래서 마운트 지점은 출력 경로 검사를 받지 않는다 [13][12].
해제 도구 `ewf.umount`·`ewf.umount_filesystem`·`img.vshadow_umount`·`img.losetup_detach`는 모델이 준 경로나 장치를 검사 없이 sudo로 실행하는 `umount`·`losetup -d`에 넘긴다 [14].

**한계.** 서버가 정한 위치가 모델 인자를 따라가는 경로가 있다.
`.tool_output` 폴더는 `misc.start_execution_log`의 `output_path`로 정한 호출 기록 파일의 위치를 따라가고 그 경로는 증거 위치 검사만 받는다 [15][1].
조사 호출 기록과 보고서 이름에 들어가는 `investigation_id`는 접두어만 검사해서 `/`·`..`가 들어간 값을 주면 사건 폴더 밖에 쓴다 [16][5].
이 경로는 코드로만 따라갔고 실행하지 않았다.

### D04.03 파생물 ID로만 수정·삭제

**구현.** 이 방식은 발견사항의 수정과 철회에 적용된다.
`misc.record_finding`과 `misc.submit_finding`은 `supersedes`로 서버가 매긴 발견사항 호출 ID를 받아 고칠 대상을 고른다 [17].
대상이 지금 버전이 아니거나 수정이 갈라지거나 명제 필드가 다르면 거부한다 [17].
`misc.retract_finding`은 지금 유효한 발견사항의 호출 ID와 사유, 호출 기록에 있는 근거 호출 ID를 받아야 철회 항목을 더한다 [18].
두 경로 모두 앞 항목을 지우지 않고 새 항목을 더한다 [18][19].
출력 파일을 지우는 모델 도구는 ID가 아니라 모델이 준 폴더 경로로 대상을 고른다 [11].

### D04.04 이름·확장자·충돌 검사

**구현.** 이 방식은 live monitoring과 조사 도구가 경로에 넣는 식별자와 작업 ID에 적용된다.
live monitoring 경로의 `case_id`는 비었거나 `/`·`..`가 들어 있으면 거부한다 [4].
실제 경로로 변환하지 않는 문자열 검사다 [4].
`investigation_id`는 `INV-`로 시작하는지 보고 `client_id`는 `C.`로 시작하는지 본다 [16][20].
두 값 모두 접두어 뒤는 검사하지 않는다 [16][20].
작업 ID는 도구 이름의 `/`·`.`을 `_`로 바꾼 뒤 난수를 붙여 만든다 [3].

**한계.** `investigation_id`는 접두어 뒤를 검사하지 않아 사건 폴더 밖 경로를 만들 수 있다 [16][5].
`monitor.baseline_capture`도 `client_id`의 접두어 뒤를 검사하지 않고 baseline 파일 이름에 넣는다 [20].
baseline 파일은 Velociraptor 수집이 끝난 뒤에 쓰므로 그런 값이 수집 단계를 지나는지는 확인하지 못했다 [20].

### D04.05 서버가 파일 이름 결정

**구현.** 이 방식은 `misc.chat_db_export`, `misc.hindsight_chrome`, `misc.srum_export`와 하이브별로 실행하는 `ez.recmd`에 적용된다 [21][22][23][24].
네 도구는 목적지 폴더를 모델이 준 `output_dir`로 받고 그 안의 이름은 서버 코드가 정한다 [21][22][23][24].
`misc.chat_db_export`는 `output_dir` 아래에 `messages.csv`·`transfers.csv`·`participants.csv`를 쓴다 [21].
`misc.hindsight_chrome`은 출력 이름 `hindsight_chrome`과 로그 파일 `hindsight.log`를 `output_dir`에 붙여 `hindsight.py`에 넘긴다 [22].
`misc.srum_export`는 `output_dir` 아래 `srudb`를 `esedbexport`의 대상 이름으로 넘기고 내보낸 폴더는 그 이름에 `.export`가 붙은 폴더다 [23].
`ez.recmd`는 하이브마다 `output_dir` 아래에 하이브의 상위 폴더 이름과 하이브 파일 이름을 이은 폴더를 정해 RECmd에 넘긴다 [24].
이름이 고정이거나 증거 경로에서 나오므로 같은 `output_dir`로 다시 부르면 같은 이름에 쓴다 [21][23][24].
`misc.chat_db_export`는 파일을 쓰기 모드로 열어 같은 이름의 앞 파일을 덮어쓴다 [21].
이름이 이미 있는지 확인해 새 이름을 짓는 코드는 없다.
`output_dir`은 증거 위치인지만 검사받는다 [7].

```python
def output_safe(func):
    """Decorator that validates any output_* / storage_file kwarg against the
    evidence read-only policy before calling the wrapped function.

    Apply BELOW @mcp.tool() so MCP introspects the original signature:

        @mcp.tool()
        @output_safe
        def my_tool(image: str, output_dir: str) -> dict: ...
    """
    sig = inspect.signature(func)
    relevant = tuple(n for n in _OUTPUT_PARAM_NAMES if n in sig.parameters)
    if not relevant:
        return func

    @wraps(func)
    def wrapper(*args, **kwargs):
        try:
            bound = sig.bind_partial(*args, **kwargs)
        except TypeError:
            # Signature mismatch — let the wrapped function raise its own error.
            return func(*args, **kwargs)
        for name in relevant:
            value = bound.arguments.get(name)
            if value:
                assert_output_safe(value)
        return func(*args, **kwargs)

    return wrapper
```

```python
@mcp.tool()
@output_safe
@trace_transaction
def retract_finding(finding_call_id: int, reason: str, input_call_ids: list[int]) -> dict:
    """Withdraw a current finding explicitly; retain the full audit history."""
    from core.execution_log import log, _utcnow
    from core.findings import active_findings
    active = {e['call_id'] for e in active_findings(log._entries)}
    if finding_call_id not in active or not reason.strip():
        return {"success": False, "error": "Retraction needs a current finding and a reason"}
    if not input_call_ids or any(cid not in log.index().by_call_id for cid in input_call_ids):
        return {"success": False, "error": "Retraction needs real supporting call IDs"}
    cid = log._next_id()
    log._append_entry({"type": "finding_retracted", "call_id": cid, "ts": _utcnow(),
                       "finding_call_id": finding_call_id, "reason": reason,
                       "input_call_ids": input_call_ids})
    return {"success": True, "_trudi_call_id": cid, "retracted": finding_call_id}
```
