# T07 도구 부재 처리

### T07.01 실행 전 도구·참조 자료 가용성 검사

**구현.** 이 방식은 선택 실행 파일 표 `_OPTIONAL_BINARIES`에 있는 도구 11개에 적용된다 [1].
표에 있는 도구는 Chainsaw, capa, FLOSS, olevba, mraptor, densityscout, Hindsight, usnparser, pffexport, readpst, esedbexport를 실행하는 도구다 [1].
이 도구들은 실행 전에 `shutil.which`로 표의 후보 이름이나 경로를 찾고 하나도 없으면 외부 도구를 부르지 않고 `tool_unavailable` 결과를 돌려준다 [2][3].
찾은 경우에는 찾은 실행 파일 경로로 명령을 만든다 [3].
서버는 같은 표로 설치되지 않은 도구를 DAIR와 추론 도구가 받는 도구 목록에서 뺀다 [4].

그 밖의 도구는 실행 전에 실행 파일이 있는지 보지 않는다.
Volatility는 `/usr/local/bin/vol`, EZ Tools는 `dotnet`과 `/opt/zimmermantools` 아래 DLL, `misc.analyzemft_parse`는 `/usr/local/bin/analyzemft`를 바로 실행한다 [5].
실행 파일이 없으면 실행기는 `FileNotFoundError`를 처리해 표준 오류 칸에 `Tool not found:` 문구를 담고 `success`가 거짓인 결과를 돌려준다 [6].
yara-python은 `yara.*` 도구 안에서 불러오고 불러오지 못하면 그 예외 문구를 실패로 돌려준다 [7].
capa 룰, ClamAV 시그니처, EZ Tools 맵과 배치 파일 같은 참조 자료도 실행 전에 있는지 보지 않는다.

**한계.** `misc.chainsaw_hunt`는 실행 파일만 확인하고 Sigma 룰 폴더를 찾지 못하면 그 사실을 알리지 않고 룰과 매핑 없이 실행한다 [8].
`misc.batch_run`은 모델이 준 명령 배열을 실행기로 바로 실행하므로 표에 있는 실행 파일도 이 경로로는 확인 없이 실행된다 [9].

### T07.02 대체 없는 실패 처리·도구 부재 알림

**구현.** 표에 있는 도구의 `tool_unavailable` 결과는 `status`, `binary`, 설치 안내를 담은 `error`, 도구가 없다는 사실로는 증거에 대해 아무것도 정할 수 없다는 `note`를 싣는다 [2].
이 결과는 외부 도구를 실행하지 않은 응답이라 미들웨어가 실패 항목으로 호출 기록에 남긴다 [10].
EZ Tools 래퍼는 실행이 실패하고 DLL 파일이 없으면 결과에 `tool_unavailable`과 설치되지 않았다는 `error`를 붙인다 [11].
PECmd, AmcacheParser, AppCompatCacheParser의 DLL이 없으면 같은 증거를 읽을 다른 도구 이름을 `fallback` 문구로 알리고 서버가 그 도구를 대신 실행하지는 않는다 [11][12].
EZ Tools가 네이티브 라이브러리를 불러오지 못해 .NET 예외를 출력하면 서버는 출력에서 이를 읽어 `tool_unavailable`로 표시한다 [13].
`ez.pecmd`는 대체 파서가 쓰는 `pyscca`도 없으면 Prefetch 파서가 없다는 `tool_unavailable` 결과를 돌려준다 [14].

**한계.** `misc.batch_run`으로 실행하면 표에 있는 실행 파일이 없어도 실행기의 일반 실패만 돌아오고 `tool_unavailable` 표시가 없다 [6][9].

### T07.03 알림 없는 대체 실행

**구현.** 이 방식은 `ewf.mount_ntfs`와 `ewf.mount_full_image`가 쓰는 NTFS 읽기 전용 마운트에 있다 [15].
`-t` 없이 마운트하는 시도가 실패하면 서버는 `-t ntfs-3g`로 다시 마운트한다 [15].
두 번째 시도가 성공하면 응답은 두 번째 실행의 결과이고 첫 시도의 오류는 싣지 않는다 [15].
바꿔 실행했다는 사실은 응답의 명령 문자열 `cmd`와 호출 기록에 따로 남은 두 실행 항목으로만 알 수 있다 [15][16].

### T07.04 실행 환경별 경로 분기

**구현.** NTFS 마운트는 `/usr/bin/lowntfs-3g`가 있을 때만 대소문자를 가리지 않는 `lowntfs-3g` 마운트를 먼저 시도한다 [15][17].
`misc.chainsaw_hunt`는 Sigma 룰 폴더 세 곳을 정해 둔 차례로 찾는다 [8].
`misc.olevba_scan`과 `misc.mraptor_scan`은 이름 뒤에 `3`이 붙은 실행 파일도 후보로 두고 `misc.densityscout_scan`은 PATH의 이름과 `/usr/local/bin` 경로를 차례로 본다 [1].
`tsk.indxparse`는 PATH에서 `INDXParse.py`를 찾고 없으면 `/usr/local/bin/INDXParse.py`를 실행한다 [18].
`ez.pecmd`의 대체 파서는 가상 환경에서 `pyscca`를 불러오지 못하면 `/usr/lib/python3/dist-packages`에서 불러온다 [14][19].
고른 실행 파일과 Sigma 룰 폴더는 명령 문자열에 남는다 [3][8].
`pyscca`를 어느 폴더에서 불러왔는지는 응답과 호출 기록에 남지 않는다 [20].

### T07.05 대체 사실을 응답·기록에 표시

**구현.** `ez.pecmd`는 PECmd가 플랫폼을 이유로 실행을 거부하거나 `tool_unavailable`이거나 실패하면 같은 입력으로 `pyscca` 파서를 실행한다 [21].
그 응답은 `parser: libscca`, PECmd가 실행되지 않았다는 `parser_note`, `pecmd_unavailable`, `pecmd_reason`과 PECmd 결과의 `tool_unavailable`·`fallback` 값을 싣는다 [20].
호출 기록에는 실패한 PECmd 실행 항목과 명령 문자열이 `pyscca prefetch parse`인 대체 실행 항목이 따로 남는다 [11][20].
PECmd가 플랫폼 문구 없이 실패하고 `error` 값도 없으면 `pecmd_reason`은 빈 문자열이다 [20].
NTFS 마운트는 `lowntfs-3g` 시도가 실패해 다른 마운트 방법을 쓰면 그 오류를 `lowntfs_attempt_stderr`로 싣는다 [22].

### T07.06 대체에 따른 검증·입력 범위 변화 표시

**구현.** NTFS 마운트가 `lowntfs-3g`가 아닌 방법으로 성공하면 응답은 `case_insensitive: false`와 `path_case_note`를 싣는다 [22].
`path_case_note`는 Windows 경로를 찾지 못해도 대소문자가 다른 이름으로 있을 수 있으니 상위 폴더를 먼저 보라고 적는다 [22].
`ez.pecmd`의 대체 파서는 Prefetch 파일 수 `files_seen`, 읽은 파일 수 `files_parsed`, 파일마다의 실패 `parse_failures`를 싣는다 [20].
대체 파서가 쓰는 CSV의 열은 서버 코드가 정한 10개다 [23].

```python
def optional_binary(tool_id: str, which=None) -> str | None:
    """Resolved binary for an optional-binary tool; None when none is installed.
    Tools outside the table are always considered available ("")."""
    spec = _OPTIONAL_BINARIES.get(tool_id)
    if not spec:
        return ""
    which = which or shutil.which
    return next((b for b in (which(n) for n in spec[0]) if b), None)


def tool_unavailable_result(tool_id: str, which=None) -> dict | None:
    """Typed fail-fast result when `tool_id`'s binary is missing, else None."""
    if optional_binary(tool_id, which) is not None:
        return None
    names, hint = _OPTIONAL_BINARIES[tool_id]
    return {"success": False, "status": "tool_unavailable", "tool_unavailable": True,
            "binary": names[0],
            "error": f"{names[0].rsplit('/', 1)[-1]} not installed — {hint}",
            "note": ("An uninstalled tool establishes nothing about the evidence; "
                     "settle it with misc.record_disposition(target_kind='tool', "
                     "reason='inapplicable') or use another parser.")}
```

```python
def _ez(dll: str, args: list[str], output_dir: Optional[str] = None, timeout: int = 300) -> dict:
    if output_dir:
        assert_output_safe(output_dir)
    result = run_dotnet(dll, args, timeout=timeout, output_dir=output_dir,
                        classify=_classify_dotnet_crash)
    # Missing-binary detection: the .dll not being on disk is the unambiguous
    # signal (dotnet's exit 145 also fires for genuine runtime faults). Augment
    # the recorded result — the failed tool_call still lands in the trace, but
    # now with an actionable fallback instead of a raw dotnet stack.
    if not result.get("success") and not os.path.exists(dll):
        name = os.path.basename(dll)
        result["tool_unavailable"] = True
        result["error"] = f"{name} is not installed in this deployment ({dll} not found)"
        fb = _EZ_FALLBACKS.get(name)
        if fb:
            result["fallback"] = fb
    return result
```

```python
def _classify_dotnet_crash(result: dict, stdout: str, stderr: str) -> None:
    """EZ tools print an .NET 'Unhandled exception' and can still exit 0 (SQLECmd
    without a native SQLite.Interop on Linux): the run parsed nothing, so it
    must not be recorded as a success."""
    text = f"{stdout}\n{stderr}"
    if "Unhandled exception" not in text and "DllNotFoundException" not in text:
        return
    result["success"] = False
    m = re.search(r"DllNotFoundException: Unable to load shared library '([^']+)'", text)
    if m:
        result["status"] = "tool_unavailable"
        result["tool_unavailable"] = True
        dll = next((t for t in str(result.get("cmd", "")).split()
                    if t.lower().endswith(".dll")), "EZ tool")
        result["error"] = (f"{os.path.basename(dll)} "
                           f"crashed: native library {m.group(1)!r} is not available "
                           f"on this host — NOTHING was parsed.")
    else:
        m = re.search(r"Unhandled exception[.:]?\s*([^\n]{0,200})", text)
        result["status"] = "error"
        result["error"] = ("EZ tool crashed with an unhandled .NET exception — "
                           "output is incomplete: " + (m.group(1).strip() if m else ""))
    result["exit_meaning"] = result["error"][:200]
```

```python
def _import_system_pyscca():
    """pyscca ships as a Debian package (python3-libscca) in the system
    dist-packages, which a venv does not see. Borrow it from there when the
    interpreter matches; None when libscca is genuinely absent."""
    import sys
    sysdir = "/usr/lib/python3/dist-packages"
    if not os.path.isdir(sysdir):
        return None
    added = sysdir not in sys.path
    if added:
        sys.path.append(sysdir)
    try:
        import pyscca
        return pyscca
    except ImportError:
        return None
    finally:
        if added:
            sys.path.remove(sysdir)
```
