# T02 실행 허용 범위 제한

### T02.03 클라이언트 도구 선택

**구현.** 이 방식은 저장소가 함께 내놓는 Claude Code 사건 설정 견본과 OpenCode 설정에 있다 [1][2].
사건 설정 견본은 허용 목록에 `mcp__trudi-sift__*` 하나를 두어 trudi 도구 전부를 확인 없이 쓰게 한다 [1].
같은 견본은 거부 목록에 포렌식 실행 파일 74개의 `Bash(<이름>:*)` 규칙을 둔다 [1].
막는 trudi 도구는 없다 [1].
이 설정은 사용자가 `case-template`을 사건 폴더로 복사해 그 폴더에서 Claude Code를 실행할 때만 적용된다 [3].
`install.sh`는 OpenCode가 있으면 `register_opencode.py`로 OpenCode 전역 설정에 `trudi-sift*` 허용과 같은 `bash` 거부 규칙을 넣는다 [2].
같은 스크립트는 OpenCode 내장 도구 `task`·`todowrite`·`todoread`를 끄고 사용자가 명시적으로 켠 값은 그대로 둔다 [4].
코드 주석은 이 설정의 목적을 로컬 백엔드의 토큰 사용을 줄이는 것으로 적는다 [4].
서버에는 이 검사가 없어 다른 MCP 클라이언트로 붙으면 이 설정이 적용되지 않는다 [5].
거부 규칙이 셸로 분석 도구를 직접 실행하는 경로를 얼마나 막는지는 T02.10에서 본다.

### T02.10 클라이언트 자체 도구 우회 차단

**구현.** 이 방식은 저장소가 함께 내놓는 Claude Code 사건 설정 견본, Claude Code PreToolUse 훅, OpenCode 설정과 플러그인에 있다 [1][5][2].
사건 설정 견본 `case-template/.claude/settings.json`은 허용 목록에 `mcp__trudi-sift__*`를 두고 거부 목록에 포렌식 실행 파일 74개의 `Bash(<이름>:*)` 규칙을 둔다 [1].
이 설정은 사용자가 `case-template`을 사건 폴더로 복사해 그 폴더에서 Claude Code를 실행할 때만 적용된다 [3].
`install.sh`는 `guard_pretooluse.py`를 사용자 전역 Claude Code 설정에 `Bash|Write|Edit|MultiEdit|NotebookEdit` matcher의 PreToolUse 훅으로 등록한다 [5].
훅은 활성 사건의 trace를 가진 세션이고 작업 폴더가 그 사건 폴더 안일 때만 검사한다 [6].
그 세션의 `Bash` 명령이 포렌식 실행 파일 이름 패턴에 맞으면 훅은 호출을 거부하고 대신 쓸 MCP 도구 이름을 알려 준다 [7].
`Bash`가 `analysis/`·`exports/`·`reports/`의 데이터 파일이나 Claude Code의 MCP 결과 캐시를 읽기 명령 16개(`cat`·`grep`·`python` 등)로 읽는 명령도 거부하고 `read.output`을 쓰게 한다 [8].
`Bash`의 리다이렉트·`tee`·`cp`·`mv`·`install`·`rsync`로 이 세 폴더에 쓰는 명령과 `Write`·`Edit`·`MultiEdit`·`NotebookEdit`로 그 아래 파일을 쓰는 호출도 거부한다 [9].
`install.sh`는 OpenCode가 있으면 `register_opencode.py`로 OpenCode 전역 설정에 `trudi-sift*` 허용과 사건 설정 견본의 거부 목록에서 뽑은 `bash` 거부 규칙을 넣는다 [2].
OpenCode 플러그인 `trudi.js`는 도구 실행 전에 같은 `guard_pretooluse.py`를 불러 거부 응답이 오면 예외를 던져 호출을 막는다 [10].

포렌식 실행 파일 패턴과 읽기 명령에 맞지 않는 다른 `Bash` 명령은 이 구성이 막지 않는다 [7][8].
사건 설정 견본과 훅은 다른 MCP 서버의 도구를 다루지 않는다 [1][5].
서버에는 이 검사가 없어 다른 MCP 클라이언트로 붙으면 이 설정과 훅이 적용되지 않는다 [5].
서버 쪽에서는 발견사항 게이트 `mcp_routing`이 `Bash`로 포렌식 실행 파일을 실행한 호출 기록을 근거로 든 발견사항을 거부한다 [11].
클라이언트 도구 호출을 trace에 옮기는 PostToolUse 훅은 L01에서 본다.

**예외.** 환경변수 `TRUDI_GUARD_DISABLE=1`이면 훅이 검사 없이 끝난다 [12].
훅은 입력을 읽지 못하거나 세션 판정, 정규식 검사, 모듈 불러오기에서 오류가 나면 호출을 통과시킨다 [13].
OpenCode 플러그인도 훅을 실행하지 못하거나 응답을 해석하지 못하면 호출을 통과시킨다 [13].
훅의 `Bash` 쓰기 검사는 대상이 `reports/`·`exports/`·`analysis/`나 `./`로 시작하는 상대 경로일 때만 맞으므로 절대 경로나 `cd` 뒤의 상대 경로로 쓰는 명령은 거부하지 않는다 [9].
`rm`·`ln`·`dd`는 쓰기 검사의 명령 목록에 없어 이 폴더의 파일을 지우거나 덮어쓰는 명령도 통과한다 [9].
`Bash` 읽기 검사는 읽기 명령 16개만 보므로 `nl`·`od`처럼 목록에 없는 명령으로 같은 파일을 읽으면 이 검사가 명령을 거부하지 않는다 [8].
훅의 matcher와 검사 대상 도구에는 `Read`·`Grep`·`Glob`이 없어 이 도구들로 `analysis/`·`exports/`·`reports/`의 산출물을 직접 읽는 호출은 막지 않는다 [5][14].
훅의 실행 파일 패턴은 Volatility 3를 `/usr/local/bin/vol` 경로나 `vol.py`로만 맞추므로 사건 설정 견본이 없는 세션에서 경로 없이 `vol`로 실행한 명령은 이 패턴에 맞지 않는다 [15].
사건 설정 견본의 `Bash(<이름>:*)` 규칙이 `sudo`나 전체 경로를 붙인 명령도 맞추는지는 Claude Code 동작을 확인하지 못했다 [1].

### T02.04 외부 플랫폼 권한에 위임

**구현.** 이 방식은 Velociraptor 서버에 VQL을 보내는 `velo.*` 도구에 있다 [16].
서버는 사용자가 환경변수 `TRUDI_VELO_API_CONFIG`로 정한 API 설정 파일을 붙여 `velociraptor` 실행 파일로 VQL을 보낸다 [16].
`velo.query`는 모델이 쓴 VQL 문장을 검사하지 않고 그대로 보낸다 [17].
`velo.collect_artifact`는 이름이 비지 않고 `/`가 없으면 어느 아티팩트든 대상 단말에서 수집하게 한다 [18].
`velo.update_client_event_table`은 모델이 넘긴 아티팩트 이름 목록으로 전역 감시 표를 바꾼다 [19].
`velo.upload_artifact_yaml`은 YAML 첫 줄이 `name:`으로 시작하고 `Custom.TRUDI.`를 담는지만 보고 모델이 쓴 아티팩트 정의를 Velociraptor 서버에 등록한다 [20].
서버는 이 요청들의 연산을 좁히지 않고 코드 설명은 VQL을 Velociraptor 자체의 아티팩트 ACL로만 막는다고 적는다 [21].

**예외.** 실제 보호 미확인.
API 설정에 준 역할이 이 요청들을 실제로 막는지는 운영 배포의 설정에 달려 있고 저장소는 운영 배포의 역할을 정하지 않는다 [21].
저장소의 데모 구성은 `administrator` 역할로 API 설정을 만든다 [22].

### T02.06 고정 명령·템플릿

**구현.** 이 방식은 외부 도구를 실행하는 래퍼 도구 대부분과 `live.*`, 대응 조치 실행, `velo.*`의 조회·수집 도구에 있다 [23][24][25][26].
래퍼 도구는 실행 파일과 옵션을 인자 목록으로 정해 두고 모델 값을 정한 칸에 넣는다 [23].
`live.*`는 도구마다 원격 명령의 인자 목록을 정해 두고 모델이 정하는 값은 대상 호스트 키, PID, 시간 범위, 바이트 수, 줄 수, 파일 경로, 유닛 이름, YARA 룰 경로와 검사 폴더뿐이다 [24].
대응 조치 실행은 조치 종류마다 원격 명령의 인자 목록을 코드 표 `ACTION_BUILDERS`에 정해 두고 검사를 통과한 증거 값만 넣는다 [25].
`velo.*`의 조회·수집 도구는 VQL 틀을 코드에 두고 모델 값을 `json.dumps`로 감싸 문자열 값으로 넣는다 [26].

`misc.batch_run`은 모델이 준 인자 목록을 실행 파일부터 그대로 실행하므로 틀이 없다 [27].
`velo.query`도 틀이 없고 T02.04에서 본다 [17].
셸을 거치는지는 T04에서 본다.

**예외.** `net.tcpdump_read`·`net.tcpdump_write_filtered`는 모델이 넘긴 `filter_expr`를 공백으로 나눠 인자 목록 끝에 붙이고 `sudo`로 tcpdump를 실행한다 [28].
Ubuntu 22.04 패키지의 tcpdump 4.99.1은 옵션을 `getopt_long`으로 읽고 옵션 문자열이 `+`로 시작하지 않는다 [29].
같은 환경의 glibc 2.35에서 `getopt_long`은 기본으로 옵션이 아닌 인자 뒤에 온 옵션도 읽는다 [30].
그래서 `filter_expr`의 `-`로 시작하는 토큰은 필터식이 아니라 tcpdump 옵션으로 읽힌다 [28][29][30].
`velo.collect_artifact`는 `parameters`의 키를 따옴표 처리 없이 VQL 백틱 사이에 넣고 키에 든 백틱을 막지 않는다 [18].
그런 키가 VQL 구조를 바꾸는지는 실행해 보지 않아 확인하지 못했다.
모델 값이 `-`로 시작하는지 따로 보는 코드는 없다 [31].
`net.ngrep_search`의 `pattern`, `tsk.mmls`의 `image`, `live.read_file`의 `path`는 옵션 값이 아닌 위치 인자로 들어간다 [31].
이 값들이 `-`로 시작할 때 각 외부 도구가 옵션으로 읽는지는 확인하지 못했다 [31].

### T02.07 연산·플러그인 허용 목록

**구현.** 이 방식은 대응 조치 실행과 `hash.hashdeep_audit`의 감사 방식 선택에 있다 [25][32].
모델은 `respond.suggest_containment`에 탐지기 이름 `detector`를 넘기고 서버는 저장소의 `response/recipes/<detector>.yaml` 레시피로 후보 조치를 만든다 [33].
모델은 후보의 `action_id`를 골라 `respond.execute_action`·`respond.revert_action`을 부른다 [34].
실행할 때 서버는 조치의 `action_template`을 코드 표 `ACTION_BUILDERS`의 이름 13개와 대조하고 없으면 SSH 명령을 만들지 않고 거부한다 [25].
레시피 파일 경로는 `detector`를 검사 없이 이어 만들어 레시피 폴더 밖의 YAML도 읽히지만 거기 적힌 조치도 실행할 때 같은 표 대조를 거친다 [33][25].
조치 실행의 승인 조건은 T03에서 본다.

`hash.hashdeep_audit`는 감사 방식을 고르는 `mode`를 코드 표의 세 값(`audit`·`match`·`negative`)으로 옵션 `-a`·`-m`·`-X`에 맞추고 표에 없는 값은 거부하지 않고 기본 감사 `-a`로 실행한다 [32].

실행할 연산을 고르는 다른 값은 목록과 대조하지 않는다.
`misc.regripper_hive`의 `plugin`, `plaso.create_timeline`의 `parsers`, `misc.pff_export`의 `mode`는 검사 없이 옵션 값으로 넘긴다 [35].

**예외.** `misc.batch_run`은 모델이 준 인자 목록을 그대로 실행하므로 모델이 `ssh`를 직접 실행해 같은 단말에 원격 명령을 보내면 `ACTION_BUILDERS` 대조를 거치지 않는다 [27].
이 경로는 코드로만 따라갔다.

### T02.09 사전 등록된 백엔드 작업만 호출

**구현.** 이 방식은 감시 도구 `monitor.baseline_capture`·`monitor.start_watcher`에 있다 [36][37].
`monitor.baseline_capture`는 코드에 둔 아티팩트 `Linux.Sys.Pslist`·`Linux.Network.Netstat`과 저장소에 둔 `Custom.TRUDI.PersistenceSnapshot` 정의만 수집한다 [36].
`monitor.start_watcher`는 모델이 고른 탐지기 이름마다 저장소 `monitoring/artifacts/`의 `<이름>.yaml.tmpl` 틀을 기준선 값으로 채워 Velociraptor에 올리고 감시 표에 넣는다 [37][38].
틀 파일이 없으면 예외가 나 호출이 끝난다 [38].
모델은 탐지기 이름만 고르고 아티팩트 정의는 보내지 않는다 [37].
같은 Velociraptor 서버를 `velo.*`로 직접 다루는 경로는 T02.04에서 본다 [16].

**예외.** `monitor.start_watcher`는 탐지기 이름을 검사하지 않고 파일 경로에 이어 붙이므로 `../`가 든 이름은 틀 폴더 밖의 `.yaml.tmpl` 파일을 읽어 `velo.upload_artifact_yaml`에 넘긴다 [37][38].

```python
def _bash_permission(ban: list[str]) -> dict:
    """OpenCode bash permission map. Order matters (last match wins), so the
    catch-all allow comes first and the denies after it. Two patterns per
    binary: bare invocation and with-arguments."""
    perm: dict[str, str] = {"*": "allow"}
    for b in ban:
        perm[b] = "deny"
        perm[f"{b} *"] = "deny"
    return perm
```

```python
def build_argv(action_template: str, raw_params: dict) -> list[str]:
    """Validate every required evidence value, then build the structured remote
    argv. `raw_params` may carry extra keys (the whole evidence dict) — only the
    keys the template needs are read and validated.

    Raises ParamValidationError on an unknown template or any failed validation.
    """
    spec = ACTION_BUILDERS.get(action_template)
    if spec is None:
        raise ParamValidationError(f"unknown action_template {action_template!r}")
    validated: dict[str, str] = {}
    for key, validator in spec["params"].items():
        if key not in (raw_params or {}) or raw_params[key] is None:
            raise ParamValidationError(
                f"action {action_template!r} requires evidence key {key!r}")
        validated[key] = validator(raw_params[key])
    return spec["argv"](validated)
```

```python
def render_template(name: str, baseline: Mapping[str, Any]) -> str:
    """Render the artifact whose source file is ``<name>.yaml.tmpl``.

    name: artifact name (e.g. "Custom.TRUDI.NewProcess").
    baseline: dict with the allowlist fields the template expects.

    The mapping the renderer feeds Template.substitute is built up from
    well-known baseline keys, falling back to empty arrays if absent so
    a partial baseline still produces a valid YAML (the resulting filter
    just allows nothing through, which is conservative).
    """
    src = ARTIFACTS_DIR / f"{name}.yaml.tmpl"
    if not src.exists():
        raise FileNotFoundError(f"artifact template not found: {src}")
```
