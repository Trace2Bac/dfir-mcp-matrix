# T01 입력 검증

### T01.01 인자 구조·값 검사

**구현.** 서버 코드가 인자 값을 실행 전에 검사하는 곳은 일부 도구다.
`live.recent_logins`·`live.read_file`·`live.event_log_tail`은 `hours`·`max_bytes`·`lines`가 정한 범위 밖이면 SSH 명령을 보내지 않고 거부한다 [1].
`velo.client_info`·`velo.collect_artifact`·`velo.get_client_event_table`·`velo.update_client_event_table`은 `client_id`가 `C.`로 시작하지 않으면 거부한다 [2].
`velo.wait_for_flow`·`velo.get_collection_results`는 `flow_id`가 `F.`로 시작하는지만 보고 `client_id`는 검사하지 않고 VQL 문자열 값으로 넣는다 [2].
`velo.collect_artifact`는 아티팩트 이름이 비었거나 `/`를 담으면 거부하고 `velo.query`는 `fmt`가 `jsonl`·`json`·`csv`가 아니면 거부한다 [2].
`strings.grep`은 `pattern`이 정규식으로 컴파일되지 않거나 `encoding`이 코드의 표에 없으면 `strings`를 실행하지 않고 거부한다 [3].
`hash.directory`는 `algorithm`이 `md5`·`sha1`·`sha256`·`sha512`가 아니면 거부한다 [4].
`misc.evtx_filter`는 `event_ids`에서 숫자를 하나도 읽지 못하면 거부한다 [5].
`misc.hindsight_chrome`은 `output_format`이 허용한 세 값과 별칭에 없으면 `jsonl`로 바꿔 실행한다 [6].
`ewf.mount_ntfs`는 `read_only`가 거짓이면 마운트하지 않고 거부한다 [7].

대응 조치를 실행하는 `respond.execute_action`·`respond.revert_action`은 원격 명령을 만들기 전에 조치에 필요한 증거 값을 검사한다 [8].
조치 종류마다 필요한 값을 정해 두고 값이 없거나 형식 검사에 어긋나면 SSH 명령을 만들지 않고 거부한다 [8].
PID와 포트는 정수 범위로, IPv4 주소와 systemd 유닛 이름은 앵커를 건 정규식으로 검사한다 [9].
경로 값의 검사는 T01.04에서 본다.

사용자 설정과 인자를 대조하는 도구도 있다.
`live.*`와 대응 조치 실행은 `host`를 호스트 주소가 아니라 사용자 설정 파일 `live_hosts.json`의 키로 받는다 [10].
서버는 그 키가 설정에 없거나 `user`·`host`가 비었거나 인증 키 파일이 정해지지 않았으면 SSH를 실행하지 않고 거부한다 [10].
설정 파일이 없거나 JSON으로 읽히지 않으면 빈 설정으로 보고 모든 호스트를 거부한다 [10].
대응 조치는 사건 설정 `monitoring/config.json`의 `host`나 `live_hosts.json`에 하나뿐인 호스트를 대상으로 삼고 그런 호스트가 없으면 거부한다 [11].

그 밖의 도구 대부분은 인자를 검사하지 않고 외부 도구의 인자 목록에 넣는다.

### T01.02 입력 존재·읽기 가능 검사

**구현.** 실행 전에 입력이 있는지 보고 없으면 실행하지 않는 도구는 일부다.
`strings.extract`·`strings.grep`은 파일 경로를 대소문자를 가리지 않고 찾은 뒤 그 파일이 없으면 `strings`를 실행하지 않고 오류를 돌려준다 [12].
`misc.cs_beacon_config`는 `path`가 없거나 `memmap_listing`이 파일이 아니면 분석 함수를 부르지 않는다 [13].
`af.timestomp_drift`·`af.sysmon_evasion`·`af.usn_gaps`는 받은 CSV 경로가 없으면 거부한다 [14].
`hash.directory`는 `directory`가 폴더가 아니면 거부한다 [4].
`read.output`·`read.mail`은 T01.03의 대조를 통과한 경로에 파일이 없으면 거부한다 [15].

나머지 도구는 입력 경로가 있는지 보지 않고 외부 도구나 라이브러리에 넘긴다 [16].

### T01.03 실제 경로로 변환해 허용 폴더 대조

**구현.** 이 방식은 서버가 만든 출력을 다시 읽는 `read.output`·`read.mail`에 있다 [15].
두 도구는 경로를 `assert_readable_output`으로 검사한다 [15].
이 함수는 경로를 절대 경로로 바꿔 대소문자를 가리지 않고 찾은 뒤 `os.path.realpath`로 `..`과 심볼릭 링크를 푼다 [17].
푼 경로가 `/cases/`·`/mnt/`·`/media/`로 시작하거나 경로 조각에 `evidence`가 있으면 거부한다 [17].
푼 경로의 조각 가운데 `analysis`·`exports`·`reports`가 하나도 없어도 거부한다 [17].
허용하는 곳은 사건 폴더의 세 폴더가 아니라 이름이 그 셋 가운데 하나인 폴더 어디나다 [17].
두 도구는 검사를 통과한 푼 경로로 파일을 연다 [15].

증거·룰 경로를 받는 다른 도구는 이 대조를 하지 않고 받은 경로를 외부 도구나 라이브러리에 넘긴다 [16].
`vol.*`·`tsk.*`의 `image`, `plaso.*`의 `evidence_path`, `yara.*`의 `rules_path`, `live.read_file`의 원격 `path`가 그 예다 [16].

**한계.** `read.mail`에 폴더를 주면 그 아래의 `.eml`·`.mbox` 파일과 `Message*` 폴더를 `glob`로 찾아 열고 찾은 파일마다 허용 폴더 대조를 다시 하지 않는다 [18].
찾은 파일을 고르는 `os.path.isfile`과 여는 `open`은 심볼릭 링크를 따라가므로 그 폴더 안의 링크가 가리키는 바깥 파일도 읽는다 [18].

### T01.04 문자열 경로 검사

**구현.** 이 방식은 대응 조치 실행의 경로 값에 있다 [19].
`quarantine_image`·`restore_quarantined_image`의 `image_path`와 `remove_cron_entry`·`restore_cron_entry`의 `path`는 원격 단말에서 옮기거나 지울 파일의 경로다 [19].
서버는 이 값이 `/`로 시작하는지, 글자·숫자와 `_./@+-`만 담는지, `..`이 없는지를 문자열로 본다 [19].
격리 대상 경로는 `/tmp/`·`/var/tmp/`·`/home/`·`/opt/`·`/srv/`·`/usr/local/` 가운데 하나로 시작해야 하고 cron 경로는 `/etc/cron.`이나 `/etc/cron/`으로 시작해야 한다 [19].
어긋나면 SSH 명령을 만들지 않고 거부한다 [8].
검사는 원격 파일시스템을 보지 않으므로 허용 접두어 아래의 심볼릭 링크를 해석하지 않는다 [19].

**한계.** 모델이 `misc.batch_run`으로 `ssh`를 직접 실행하면 이 경로 검사 없이 원격 단말의 파일을 옮기거나 지울 수 있다 [20].
이 경로는 코드로만 따라갔다.

### T01.05 등록된 ID와 대조

**구현.** 이 방식은 발견사항을 검토하거나 기록하는 도구 다섯 개에 있다.
발견사항을 검토하는 `reason.evaluate_finding`과 검토해 기록하는 `misc.submit_finding`은 근거를 파일 경로가 아니라 호출 기록의 호출 ID(`input_call_ids`, `linked_call_id`, 주장 안의 호출 ID 목록)로 받는다 [21][22].
서버는 그 ID가 이 사건의 호출 기록에 없으면 거부한다 [21].
`reason.evaluate_finding`이 검토할 글은 인용한 호출의 저장된 출력과 그 호출이 쓴 출력 파일에서 읽는다 [21].
바이트 범위 선택자도 인용한 호출과 그 호출의 출력 경로만 가리킬 수 있다 [21].
인용한 호출이 실패했거나 모델이 직접 쓴 파일을 가리키면 거부한다 [21].
`misc.submit_finding`은 검토 묶음을 만들기 전에 인용한 ID가 기록에 있는지 한 번 더 본다 [22].

발견사항을 기록하는 `misc.record_finding`은 `lineage_required` 게이트에서 `input_call_ids`에 호출 기록에 없는 ID가 있으면 거부한다 [23].
같은 도구의 증거 강도 게이트 묶음은 `linked_call_id`가 0이 아니면 그 ID가 호출 기록에 있는지 본다 [24].
발견사항을 거두는 `misc.retract_finding`과 단서를 정리하는 `misc.record_disposition`도 인용한 ID가 기록에 없으면 거부한다 [25][26].

**한계.** `reason.evaluate_finding`을 `input_call_ids` 없이 부르면 호출 ID 대조 없이 모델이 넘긴 `supporting_evidence` 글을 검토 모델에 보낸다 [27].

### T01.06 고정 입력 경로 사용

**구현.** 이 방식은 앞선 도구 출력을 서로 잇는 `correlate.process_to_file`·`correlate.network_to_process`와 `af.event_log_clear`·`af.prefetch_deletion`에 있다 [28][29].
이 도구들은 입력 경로 인자를 받지 않고 지금 사건의 호출 기록에서 앞선 도구 호출 항목을 골라 읽는다 [28][29].
두 `correlate` 도구는 명령 문자열에 `vol`·`fls`·`MFTECmd`·`netscan`·`pslist` 같은 글자가 든 최근 항목을 글자마다 50개까지 고른다 [28].
두 `af` 도구는 EZ Tools 도구 이름으로 색인한 항목을 고르고 없으면 명령 문자열에 그 이름이 든 항목을 찾는다 [29].
읽는 내용은 각 항목에 남은 출력 앞 600자다 [28][30].
고를 항목이 없으면 두 `af` 도구는 거부하고 두 `correlate` 도구는 빈 결과를 돌려준다 [28][29].

**한계.** 항목을 명령 문자열로 고르므로 모델이 인자 목록 전체를 정하는 `misc.batch_run`으로 남긴 호출 항목도 그 글자를 담으면 입력이 된다 [28][20].
실행기는 `misc.batch_run`의 명령도 같은 형식의 호출 항목으로 남긴다 [20].

### T01.07 입력 부재 시 다른 입력으로 대체

**구현.** 이 방식은 `strings.extract`·`strings.grep`과 `read.output`·`read.mail`의 경로 풀이에 있다 [12][17].
`resolve_path_ci`는 경로 조각마다 이름이 같은 항목이 있으면 그 항목을 쓰고 없으면 대소문자만 다른 항목 가운데 `os.listdir`이 먼저 돌려준 것으로 바꾼다 [31].
그래서 요청한 경로가 없을 때 거부하지 않고 대소문자만 다른 경로의 파일을 입력으로 읽는다 [31].
대소문자를 가리는 파일시스템에서는 그 파일이 요청한 파일과 다른 파일이다.
`strings.extract`는 바꾼 경로를 `path_resolved`로 응답에 싣는다 [32].
`strings.grep`은 응답의 `file`에 바꾼 경로를 싣지만 바꿨다는 표시는 두지 않는다 [12].
`read.*`는 응답의 `path`에 바꾼 경로를 싣는다 [15].
네 도구 모두 실행 명령이나 호출 기록의 명령 문자열에 바꾼 경로가 남는다 [12][15].

```python
def build_argv(action_template: str, raw_params: dict) -> list[str]:
    """Validate every required evidence value, then build the structured remote
    argv. `raw_params` may carry extra keys (the whole evidence dict) — only the
    keys the template needs are read and validated.

    Raises ParamValidationError on an unknown template or any failed validation.
    """
    spec = ACTION_BUILDERS.get(action_template)
    if spec is None:
        raise ParamValidationError(f"unknown action_template {action_template!r}")
    validated: dict[str, str] = {}
    for key, validator in spec["params"].items():
        if key not in (raw_params or {}) or raw_params[key] is None:
            raise ParamValidationError(
                f"action {action_template!r} requires evidence key {key!r}")
        validated[key] = validator(raw_params[key])
    return spec["argv"](validated)
```

```python
def _recent_tool_stdouts(tool_substring: str, max_entries: int = 50) -> list[dict]:
    """Return recent tool_call entries whose cmd contains tool_substring.

    Used by correlation tools to look up the actual output the agent collected.
    Returns a list of {call_id, cmd, stdout_excerpt, success} dicts.
    """
    from core.execution_log import log
    matches = []
    for e in reversed(log._entries):
        if e.get("type") != "tool_call":
            continue
        cmd = e.get("cmd", "") or ""
        if tool_substring not in cmd:
            continue
        matches.append({
            "call_id": e.get("call_id"),
            "cmd": cmd,
            "stdout_excerpt": e.get("stdout_excerpt", "") or "",
            "success": e.get("success", False),
        })
        if len(matches) >= max_entries:
            break
    return list(reversed(matches))
```

```python
def resolve_path_ci(path: str) -> tuple[str, bool]:
    """Walk path components case-insensitively on the real filesystem.

    Returns (resolved_path, was_corrected). was_corrected=True means at least
    one component was case-folded to match an actual directory entry.
    If a component has no match the original path is returned with was_corrected=False
    so callers can report a clean not-found error.
    """
    path = os.path.normpath(os.path.expanduser(path))
    parts = Path(path).parts          # e.g. ('/', 'mnt', 'rd01', 'Windows', ...)
    current = parts[0]                # '/'
    corrected = False
    for part in parts[1:]:
        try:
            entries = os.listdir(current)
        except (PermissionError, NotADirectoryError, FileNotFoundError):
            return path, False
        if part in entries:
            current = os.path.join(current, part)
        else:
            lower = part.lower()
            matches = [e for e in entries if e.lower() == lower]
            if matches:
                current = os.path.join(current, matches[0])
                corrected = True
            else:
                return path, False    # component missing — caller handles not-found
    return current, corrected
```
