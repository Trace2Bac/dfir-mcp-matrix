# T05 분석 도구 검증

### T05.01 저장소·의존성 고정

**구현.** 이 방식은 설치 스크립트가 받는 Chainsaw와, 저장소에 들어 있는 Velociraptor 탐지 아티팩트와 YARA 룰에 적용된다.
`install.sh`는 `/usr/local/bin/chainsaw`가 없을 때 Chainsaw v2.10.2 x86_64 릴리스 묶음을 내려받아 실행 파일과 `mappings` 폴더를 설치한다 [1].
받은 묶음의 해시를 대조하는 코드는 없다 [1].
설치 스크립트 주석은 묶음에 Sigma 룰이 함께 든다고 적는다 [1].
v2.10.2 x86_64 묶음에는 실행 파일, `mappings` 폴더의 매핑 파일 두 개, README, LICENCE만 있어 설치 스크립트는 Sigma 룰을 설치하지 않는다 [2].
`monitor.start_watcher`는 저장소의 `monitoring/artifacts/*.yaml.tmpl` 틀에 기준선 값을 채워 탐지 아티팩트를 만들고 Velociraptor 서버에 올린다 [3].
기준선 수집 도우미 `Custom.TRUDI.PersistenceSnapshot`도 저장소의 YAML 파일을 그대로 올린다 [4].
탐지 아티팩트가 단말에서 읽는 YARA 룰 파일은 기준선에 `yara_rules_path`가 없으면 `/rules/trudi-demo.yar`이고 서버는 그 파일의 내용을 정하지 않는다 [5].
저장소의 `rules/` 폴더에 들어 있는 YARA 룰은 모델이 그 경로를 `rules_path`로 넘길 때만 쓰인다 [6].

그 밖의 도구는 저장소가 버전을 고정하지 않는다.
`requirements.txt`는 서버가 불러오거나 실행하는 `yara-python`, `flare-capa`, `flare-floss`, `oletools`를 `>=` 하한으로만 적는다 [7].
`install.sh`는 Sleuth Kit, ewf-tools, pff-tools, pst-utils 같은 apt 패키지를 버전 없이 설치하고 이미 있으면 건너뛴다 [8].
Volatility 3, EZ Tools, Plaso 같은 SIFT 도구는 저장소가 설치하지 않고 `install.sh`는 `python3`와 `dotnet`이 있는지만 본다 [9].
서버는 Volatility를 `/usr/local/bin/vol`로, EZ Tools를 `/opt/zimmermantools` 아래 DLL로 부른다 [10].
Prefetch 대체 파서가 쓰는 `pyscca`는 `requirements.txt`에 없고 서버는 가상 환경에서 불러오지 못하면 시스템 패키지 폴더에서 불러온다 [7][11].
`requirements.txt`의 `fastmcp`, `httpx`, `anthropic`, `python-dotenv`는 증거를 해석하지 않는 서버 실행용 라이브러리라 이 방식으로 세지 않는다 [7].
도구나 참조 자료를 쓰기 직전에 실제 파일의 해시, 서명, 컨테이너 digest를 기대값과 대조하는 코드는 없다.

서버 코드가 판단에 쓰는 지식 데이터도 저장소에 들어 있다.
`data/fk`의 YAML 시트는 서버가 저장소 안 경로로 읽으므로 기준 커밋이 그 내용을 정한다 [12][13].
이 시트는 응답에 붙는 해석 주의와 발견사항 등급 상한을 정한다 [12][13].
MITRE ATT&CK 기법 표는 `install.sh`가 저장소의 `cases/.common/mitre_techniques.json`을 `~/cases/.common/`으로 복사하고 서버는 그 복사본을 읽는다 [14][15].
이 기법 표는 발견사항 게이트의 판단에 쓰이고 `correlate.mitre_map`·`correlate.mitre_validate`의 조회 결과로 모델에게도 돌아간다 [16].
저장소 기법 표의 `_meta`는 버전을 `v15`로, 출처를 MITRE CTI 저장소 `master` 브랜치의 묶음 주소로 적는다 [17].
같은 `_meta`의 `patches`에는 손으로 더한 기법 묶음 2건이 적혀 있다 [17].
서버가 쓰는 그룹 표 `mitre_groups.json`과 탐지 표 `mitre_detection.json`은 `install.sh`가 설치하지 않는다 [14][15].
그룹 표는 저장소에 있지만 `install.sh`는 기법 표만 복사하고 탐지 표는 저장소에 없다 [14].
두 표는 손으로 실행하는 `tools.mitre.build_mitre_cache`가 MITRE CTI 저장소 `master` 브랜치의 묶음을 내려받아 만들고 받는 묶음의 버전은 고정하지 않는다 [18].
탐지 표를 쓰는 `core/iocs.py`의 모듈 설명은 그 자료를 ATT&CK v18 analytics라고 적는다 [19].
이 v18은 모듈 설명 문구로만 확인했고 탐지 표 파일이 저장소에 없어 실제 버전은 확인하지 못했다.

**한계.** `install.sh`는 `/usr/local/bin/chainsaw`가 이미 있으면 그 버전을 보지 않고 설치를 건너뛴다 [1].
내려받는 주소가 x86_64용 묶음 하나로 정해져 있어 아키텍처를 가리지 않고 그 묶음을 설치한다 [1].
`misc.chainsaw_hunt`는 `chainsaw`를 PATH에서 찾으므로 PATH에서 `/usr/local/bin`보다 앞선 폴더에 다른 `chainsaw`가 있으면 그것을 실행한다 [20].
`install.sh`는 `~/cases/.common/mitre_techniques.json`이 이미 있으면 내용을 보지 않고 복사를 건너뛰므로 서버는 저장소와 다른 MITRE 표를 쓸 수 있다 [14].
`velo.upload_artifact_yaml`은 이름이 `Custom.TRUDI.`로 시작하는 아티팩트를 모델이 준 YAML로 Velociraptor 서버에 등록하거나 바꾼다 [21].
그래서 감시 중에 같은 이름의 탐지 아티팩트를 저장소의 틀과 다른 내용으로 바꿀 수 있다 [21].

### T05.02 설정·호출 인자로 지정

**구현.** 이 방식은 YARA 룰, Chainsaw Sigma 룰, EZ Tools의 맵과 배치 파일, Volatility 심볼 폴더, Velociraptor 실행 파일에 적용된다.
`yara.*` 도구는 필수 인자 `rules_path`로 룰 파일이나 룰 폴더를 받는다 [22].
`vol.vadyarascan`과 `vol.yarascan`은 `yara_rules`로 룰 파일 경로나 룰 본문을 받는다 [23].
`live.yara_scan`은 단말에 미리 둔 룰의 경로를 `rules_path`로 받는다 [24].
`misc.chainsaw_hunt`는 `sigma_dir`로 Sigma 룰 폴더를 받고 주지 않으면 `/opt/chainsaw/sigma`, `/usr/local/share/chainsaw/sigma`, `/usr/share/chainsaw/sigma` 가운데 처음 있는 폴더를 쓴다 [25].
매핑 파일은 그 폴더 옆의 `mappings/sigma-event-logs-all.yml`로 정한다 [25].
세 폴더가 모두 없으면 `-s`와 `--mapping` 없이 `chainsaw hunt`를 실행한다 [25].
`ez.evtxecmd`와 `ez.sqlecmd`는 `maps_dir`로, `ez.recmd_hive`와 `ez.recmd_dir`는 `batch_file`로 위치를 받고 기본값은 `/opt/zimmermantools` 아래 SIFT 설치 경로다 [26].
Volatility 심볼 폴더는 환경변수 `VOLATILITY_SYMBOLS`로 정하고 값이 없으면 `~/.cache/volatility3/symbols`를 쓴다 [10].
Velociraptor 실행 파일은 환경변수 `TRUDI_VELO_BIN`으로 정하고 값이 없으면 PATH의 `velociraptor`를 쓴다 [27].
MITRE 기법·탐지·그룹 표는 환경변수 `TRUDI_MITRE_TABLE`·`TRUDI_MITRE_DETECTION`·`TRUDI_MITRE_GROUPS`로 위치를 정하고 값이 없으면 `~/cases/.common/` 아래 파일을 쓴다 [15].
`correlate.mitre_map`과 `correlate.mitre_validate`는 인자 `table_path`로 기법 표의 위치를 호출마다 받고 주지 않으면 환경변수나 기본 경로의 표를 쓴다 [28].
발견사항 게이트와 `misc.record_ioc`는 이 인자 없이 기본 위치의 표만 쓴다 [29].
서버는 받은 위치에 있는 룰, 맵, 심볼의 버전이나 내용을 읽지 않는다.

**한계.** `vol.vadyarascan` 설명은 `yara_rules`가 룰 파일 경로나 룰 본문이라고 적는다 [30].
서버는 값이 있는 파일이 아니고 `rule `과 `{`를 담지 않으면 그 값을 `--yara-string` 검색 문자열로 넘긴다 [23].
그래서 없는 룰 파일 경로를 넘기면 오류 없이 그 경로 글자를 찾는 검사가 실행된다 [23].
`yara.*` 도구는 폴더를 받으면 하위 폴더까지 룰 파일을 모으면서 파일 이름을 키로 삼는다 [22].
이름이 같은 룰 파일이 여러 하위 폴더에 있으면 그 가운데 하나만 컴파일되고 응답은 빠진 파일을 알리지 않는다 [22].

### T05.04 참조 자료 버전·식별값 조회

**구현.** 이 방식은 `vol.symbol_check`와 검토·보고 전 점검이 만드는 정책 값에 있다 [31][32][33].
`vol.symbol_check`는 심볼 폴더의 `windows/ntkrnlmp.pdb`와 `windows/ntoskrnl.pdb` 아래 `*.json.xz` 파일 이름을 읽어 `cached_guids`로 돌려준다 [31].
읽는 대상은 캐시에 있는 Windows 커널 심볼 전부이고 메모리 이미지가 요구하는 심볼과 대조하지 않는다 [31].
`symbols_ready`는 그런 파일이 하나라도 있으면 참이다 [31].
도구 설명은 심볼이 없으면 `vol.info`를 한 번 불러 내려받으라고 안내한다 [34].
메모리 플러그인을 실행하는 `vol.*` 도구는 이 확인을 거치지 않고 심볼 폴더 경로만 Volatility에 넘긴다 [35].
Linux 커널 심볼과 그 밖의 심볼 폴더는 보지 않는다 [31].

`reason.evaluate_finding`과 `misc.submit_finding`이 evidence packet을 만들 때 서버는 `data/fk` 아래 YAML 시트와 게이트 코드 파일의 SHA-256을 계산해 packet의 정책 값 `policy`에 넣는다 [32].
발견사항을 기록하기 전에 이 값을 다시 계산해 packet의 값과 견주고 다르면 그 packet을 지금 상태가 아닌 것으로 본다 [36].
보고서 전 점검도 `data/fk/tiering.yaml`과 게이트 코드 파일의 SHA-256을 `readiness_fingerprint`에 넣는다 [33].
MITRE 표의 버전이나 식별값은 읽지 않는다.

외부 도구 실행 파일의 버전을 실행 중에 묻는 코드는 없어 T05.03에는 연결하지 않는다.
`strings.exiftool_metadata`는 오히려 `--ExifToolVersion`으로 출력의 버전 줄을 뺀다 [37].

```bash
CHAINSAW_BIN="/usr/local/bin/chainsaw"
CHAINSAW_VERSION="2.10.2"

if [ -x "$CHAINSAW_BIN" ]; then
    ok "chainsaw already installed at $CHAINSAW_BIN"
else
    CHAINSAW_URL="https://github.com/WithSecureLabs/chainsaw/releases/download/v${CHAINSAW_VERSION}/chainsaw_x86_64-unknown-linux-gnu.tar.gz"
    TMPDIR=$(mktemp -d)
    if curl -fsSL "$CHAINSAW_URL" -o "$TMPDIR/chainsaw.tgz" 2>/dev/null; then
        # Guard extraction: a corrupt download must degrade to the optional-skip
        # path, not abort the whole install under `set -e`.
        # Release ships as chainsaw/chainsaw + sigma rules
        if ! tar -xzf "$TMPDIR/chainsaw.tgz" -C "$TMPDIR" 2>/dev/null; then
            warn "chainsaw archive corrupt — skipping (TRUDI works without it)"
        elif [ -f "$TMPDIR/chainsaw/chainsaw" ]; then
            sudo install -m 0755 "$TMPDIR/chainsaw/chainsaw" "$CHAINSAW_BIN"
            # Create the share dir once, before either optional copy — so a
            # release that ships mappings/ but no sigma/ (or vice versa) can't
            # leave the parent missing and fail a copy under `set -e`.
            sudo mkdir -p /usr/local/share/chainsaw
            if [ -d "$TMPDIR/chainsaw/sigma" ]; then
                sudo cp -r "$TMPDIR/chainsaw/sigma" /usr/local/share/chainsaw/sigma
            fi
            if [ -d "$TMPDIR/chainsaw/mappings" ]; then
                sudo cp -r "$TMPDIR/chainsaw/mappings" /usr/local/share/chainsaw/mappings
            fi
            ok "Installed chainsaw v${CHAINSAW_VERSION} → $CHAINSAW_BIN"
```

def _import_system_pyscca():
    """pyscca ships as a Debian package (python3-libscca) in the system
    dist-packages, which a venv does not see. Borrow it from there when the
    interpreter matches; None when libscca is genuinely absent."""
    import sys
    sysdir = "/usr/lib/python3/dist-packages"
    if not os.path.isdir(sysdir):
        return None
    added = sysdir not in sys.path
    if added:
        sys.path.append(sysdir)
    try:
        import pyscca
        return pyscca
    except ImportError:
        return None
    finally:
        if added:
            sys.path.remove(sysdir)

def _yara_args(yara_rules: str) -> list[str]:
    """Volatility 2.27 takes --yara-file (a rules file) or --yara-string (a
    pattern); there is no --yara-rules. Inline rule text goes to a temp file."""
    if os.path.isfile(yara_rules):
        return ["--yara-file", yara_rules]
    if "rule " in yara_rules and "{" in yara_rules:
        import tempfile
        fd, path = tempfile.mkstemp(prefix="trudi-yara-", suffix=".yar")
        with os.fdopen(fd, "w") as fh:
            fh.write(yara_rules)
        return ["--yara-file", path]
    return ["--yara-string", yara_rules]

    # No secrets/endpoints in the receipt. The model and deliberate review
    # settings participate in identity; source hashes cover prompt/gate changes.
    from tools import reasoning as R
    root = Path(__file__).resolve().parents[1]
    policy = {}
    for pattern in ('core/evidence_packets.py', 'core/finding_submission.py',
                    'tools/reasoning.py', 'tools/_llm_parse.py', 'tools/_output_reader.py',
                    'tools/_gates/*.py', 'data/fk/**/*.yaml'):

def _vol(image: str, plugin: str, extra: list[str] | None = None,
         output_dir: str | None = None, timeout: int = VOL_TIMEOUT) -> dict:
    # -o OUTPUT_DIR is a global Volatility flag — must come before the plugin name.
    # Plugin-specific args (--pid, --dump, etc.) go in extra, after the plugin.
    if output_dir:
        os.makedirs(output_dir, exist_ok=True)   # Volatility refuses a missing -o dir
    out_flags = ["-o", output_dir] if output_dir else []
    cmd = [VOL, "-s", vol3_symbols()] + out_flags + ["-f", image, "-r", "json", plugin] + (extra or [])
    return run(cmd, timeout=timeout)
