# T09 대상 시스템 대응 조치 처리

### T09.02 변경 내역 기록

**구현.** 이 방식은 대응 조치를 실행하는 `respond.execute_action`과 되돌리는 `respond.revert_action`에 있다 [1][2].
`respond.execute_action`은 서버 코드의 명령표로 만든 명령을 SSH로 단말에 실행한 뒤 사건 폴더의 `monitoring/response/executions/<action_id>.json`에 실행 기록을 쓴다 [1].
실행 기록에는 조치 템플릿, 분류, 모드, 대상 호스트, 실행한 명령 배열과 문자열, 표준 출력, 표준 오류, 종료 코드, 성공 여부, 조치 인자, 승인 토큰, 실행 시각이 들어간다 [1].
대상 호스트는 사건 감시 설정의 `host`이고 값이 없으면 하나만 등록된 호스트다 [3].
`ssh_run_write`는 실행한 명령을 호출 기록에 `tool_call` 항목으로 남긴다 [4].
`respond.execute_action`은 조치 이름, 분류, 명령, 호스트, 결과, 되돌림 명령을 한 줄로 적은 서술 항목도 호출 기록에 남긴다 [5].
`respond.revert_action`은 같은 실행 기록에 `reverted`, `reverted_at_utc`, `revert_stderr`를 더해 다시 쓴다 [2].
`monitor.end_investigation`은 실행 기록으로 만든 대응 조치 표를 조사 보고서에 붙인다 [6].

조치하기 전과 뒤에 대상의 프로세스, 연결, 차단 규칙 같은 상태를 읽어 남기는 코드는 없다.
대응 조치 도구는 사건에 기준선 파일이 있어야 실행되지만 그 기준선은 감시를 시작할 때 한 번 모으는 것이고 조치마다 읽는 상태가 아니다 [7].
`velo.update_client_event_table`은 Velociraptor의 단말 감시 표를 바꾸고 `velo.upload_artifact_yaml`은 Velociraptor 서버에 아티팩트를 등록한다 [8].
`velo.collect_artifact`와 `velo.query`는 수집할 아티팩트 이름과 VQL을 제한하지 않는다 [8].
이 경로들은 실행 기록 파일과 되돌림 명령을 남기지 않고 호출 기록 항목만 남긴다 [8].

**한계.** `ssh_run_write`가 쓰는 `_log_ssh_tool`은 호출 기록 쓰기가 실패하면 표준 오류에 경고만 출력하고 호출 ID를 0으로 둔다 [9].
`_log_narration`은 서술 항목을 쓰지 못하면 예외를 호출한 쪽으로 넘기지 않고 `None`을 돌려주며 응답은 조치의 성공 여부를 그대로 싣는다 [10].
`misc.batch_run`은 받은 argv를 그대로 실행하므로 모델이 이 도구로 `ssh`를 직접 실행하면 단말을 바꿀 수 있다 [11].
이때 서버는 실행기의 `tool_call` 항목만 남기고 실행 기록 파일과 서술 항목을 쓰지 않는다 [11].

### T09.03 되돌림 명령 기록

**구현.** `respond.suggest_containment`가 쓰는 조치 제안 기록은 조치마다 되돌림 템플릿 `revert_template`을 담는다 [12].
되돌림 템플릿은 서버 코드의 표가 조치 템플릿마다 정한다 [13].
`respond.execute_action`은 실행 기록에 `rollback_template`과 실제 인자를 넣은 되돌림 명령 `rollback_command`를 쓰고 응답과 서술 항목에도 되돌림 명령을 싣는다 [1][5][14].
프로세스 종료와 메모리 덤프는 되돌림 템플릿이 없고 서술 항목에 되돌림이 없다고 적는다 [5][13].
조사 보고서의 대응 조치 표에도 조치마다 되돌림 명령이 들어간다 [6].

**한계.** 실행 파일 격리와 cron 항목 삭제는 단말의 `/var/quarantine/`에 원래 파일 이름으로 옮기거나 복사해 두고 되돌림은 그 이름의 파일을 원래 자리로 되돌린다 [15].
이름이 같은 파일을 두 번 격리하거나 삭제하면 앞의 사본을 덮어쓰므로 먼저 기록한 되돌림 명령은 다른 파일을 되돌린다 [15].
격리의 되돌림 명령은 원래 권한을 기록하지 않고 `chmod 755`로 권한을 정한다 [15].
이 경우에도 되돌림 명령은 종료 코드 0으로 끝나 성공으로 기록된다 [2][15].
`velo.update_client_event_table`은 등록된 모든 단말의 감시 표를 바꾸지만 되돌림 명령을 남기지 않는다 [8].
`velo.query`·`velo.collect_artifact`는 VQL과 아티팩트를 제한하지 않아 단말을 바꾸는 질의나 아티팩트도 실행할 수 있고 그 경우에도 되돌림 명령을 남기지 않는다 [8].
`misc.batch_run`으로 `ssh`를 직접 실행해 바꾼 단말 상태에도 되돌림 명령이 남지 않는다 [11].

### T09.04 되돌림 실행

**구현.** `respond.revert_action`은 실행 기록의 되돌림 템플릿과 조치 인자로 명령을 만들어 같은 SSH 실행 경로로 단말에 실행한다 [2].
이미 되돌린 조치, 성공하지 못한 조치, 되돌림 템플릿이 없는 조치는 실행하지 않고 거부한다 [2].
되돌림도 조치 실행과 같은 승인 확인을 거치고 그 확인은 T03에서 본다 [2].

**한계.** 실행 파일 격리와 cron 항목 삭제는 여러 명령을 `&&`로 이은 셸 명령이라 앞 명령만 실행된 채 실패할 수 있다 [15].
이렇게 일부만 실행된 조치는 실패로 기록되고 `respond.revert_action`은 성공하지 못한 조치라며 되돌림을 거부한다 [1][2].
SSH 실행이 시간 제한을 넘은 조치도 단말에서 끝났는지와 관계없이 실패로 기록되어 같은 거부를 받는다 [2][16].
T09.03의 한계와 같이 `velo.update_client_event_table`과 임의 VQL로 바꾼 단말 설정은 되돌리는 도구가 없다 [8].

### T09.05 실패·부분 복구 기록

**구현.** 조치가 실패하면 실행 기록에 `success: false`, 종료 코드, 표준 오류가 남고 서술 항목에 `FAILED`와 오류 앞부분이 적힌다 [1][5].
되돌림이 실패하면 실행 기록의 `reverted`를 거짓으로 두고 `revert_stderr`와 시각을 남긴다 [2].
조사 보고서의 대응 조치 표는 실패한 조치를 `execution FAILED`로 적는다 [6].
실패나 일부 실행 뒤에 단말에 남은 상태는 읽어 남기지 않는다.

def _log_ssh_tool(result: dict) -> None:
    """Mirror core.executor._log_tool — writes a tool_call trace entry."""
    try:
        from core.execution_log import log
        cid = log.record_tool_call(
            cmd=result["cmd"],
            success=result["success"],
            truncated=result["truncated"],
            retries=result["retries"],
            exit_code=result["exit_code"],
            stderr=result["stderr"],
            elapsed_seconds=result.get("elapsed_seconds", 0.0),
            stdout_excerpt=result.get("stdout", ""),
            timed_out=result.get("timed_out", False),
        )
        result["_trudi_call_id"] = cid
    except Exception as e:  # noqa: BLE001
        import sys
        print(f"[TRUDI WARN] _log_ssh_tool failed: {e}", file=sys.stderr)
        result.setdefault("_trudi_call_id", 0)

def _log_narration(content: str, input_call_ids: list[int]) -> Optional[int]:
    try:
        from core.execution_log import log
        cids = [c for c in input_call_ids if isinstance(c, int) and c > 0]
        return log.record_agent_message(content=content, input_call_ids=cids or None)

        return None
