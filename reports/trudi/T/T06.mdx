# T06 실행 환경정보 표시

### T06.01 응답 메타데이터에 버전 표시

**구현.** 이 방식은 `reason.evaluate_finding`의 응답에 있다 [1].
이 도구는 검토 모델 입력에 넣은 FK 지식 시트의 이름을 응답의 `fk_sheets`에 싣는다 [1].
evidence packet으로 한 검토가 성공하면 검토를 통과했다는 기록 `review_receipt`의 `policy`에 `data/fk` 지식 시트와 게이트 코드 파일들의 SHA-256, 모델 이름과 검토 설정을 묶은 digest를 싣는다 [2][3].
이 값은 여러 파일을 묶은 digest 하나라서 어느 시트가 어떤 내용이었는지는 읽을 수 없고 같은 파일로 다시 계산해 맞는지만 볼 수 있다 [3].
분석 도구의 응답에는 도구나 참조 자료의 버전이 실리지 않는다.
MITRE 표를 읽어 참조 지식을 돌려주는 `correlate.mitre_map`·`correlate.mitre_validate`·`attribution.attribute_actors`의 응답에도 표의 버전이 없다 [4][5].
표 파일의 `_meta`에는 버전과 만든 시각이 있지만 세 도구는 표의 `techniques`나 `groups`만 읽고 `_meta`를 응답에 넣지 않는다 [4][5][6].

**예외.** evidence packet 없이 부르거나 검토가 실패하면 `review_receipt`가 없어 시트 이름만 남고 시트 내용을 가리키는 값은 실리지 않는다 [1][2].

### T06.02 호출 기록 메타데이터에 버전 표시

**구현.** `reason.evaluate_finding`은 `fk_sheets`와 `review_receipt`를 그 검토의 호출 기록 항목에도 더한다 [1][2].
그래서 항목의 `review_receipt.policy`로 그 판정을 낸 지식 시트와 게이트 코드 묶음을 다시 계산해 대조할 수 있다 [3].
분석 도구의 호출 기록 항목에는 도구나 참조 자료의 버전이 없다.

**예외.** T06.01과 같이 evidence packet 없이 부르거나 검토가 실패한 항목에는 `review_receipt`가 없다 [2].

### T06.04 환경 조회 도구에서만 반환

**구현.** 분석에 쓰는 참조 자료의 식별값을 돌려주는 곳은 Volatility 심볼 캐시를 보는 `vol.symbol_check` 하나다 [7].
이 도구는 캐시에 있는 Windows 커널 심볼의 파일 이름을 `cached_guids`로 돌려준다 [7].
서버 안에서 도는 도구라 미들웨어가 응답 전체를 그 호출의 호출 기록 항목에 남긴다 [8].
그 심볼로 메모리 플러그인을 실행한 `vol.*` 호출의 응답과 호출 기록에는 명령 문자열의 심볼 폴더 경로만 남는다 [9].
`vol.symbol_check`가 읽는 값은 캐시 전체이고 어느 실행이 어느 심볼을 썼는지 가리지 않는다(T05.04) [7].

외부 도구와 룰의 버전은 분석 응답, 호출 기록, 파생물 어디에도 실리지 않는다.
실행기가 돌려주는 결과는 성공 여부, 표준 출력, 표준 오류, 종료 코드, 걸린 시간, 잘림 여부, 명령 문자열 같은 키로 이루어지고 버전 키가 없다 [10].
호출 기록 항목도 명령 문자열, 성공 여부, 종료 코드, 걸린 시간, 표준 오류 같은 필드를 담고 버전 필드가 없다 [11].
도구가 표준 출력에 자기 버전을 적으면 그 줄은 호출 기록의 표준 출력 사본 파일에 남지만 서버는 그 줄을 읽지 않는다 [12].
`strings.exiftool_metadata`와 `strings.exiftool_batch`는 `--ExifToolVersion`으로 ExifTool의 버전 줄을 출력에서 뺀다 [13].
룰은 경로만 남는다.
`misc.chainsaw_hunt`는 Sigma 룰 폴더와 매핑 파일의 경로를, `vol.yarascan`은 YARA 룰 파일 경로나 룰 본문을 담은 임시 파일 경로를 명령 문자열에 남긴다 [14].
서버 안에서 yara-python으로 도는 `yara.*` 호출은 호출 기록의 명령 문자열이 `<py>:<도구 이름>`이다 [8].

### T06.05 서버 자신의 버전 표시

**구현.** `misc.start_execution_log`는 호출 기록을 열 때 `run_profile` 항목을 하나 쓴다 [15][16].
이 항목의 `code_identity`에는 서버 코드의 git 커밋, 가지, 수정 여부와 `core/`·`tools/` 아래 파이썬 파일의 SHA-256 앞 16자가 들어간다 [15].
값은 서버 프로세스가 `tools/misc.py`를 불러올 때 한 번 계산하므로 실행 중에 디스크의 코드가 바뀌어도 불러온 코드의 값이 남는다 [15].
`misc.export_execution_log`가 내보내는 JSON은 호출 기록 항목을 모두 담으므로 `run_profile` 항목도 들어간다 [17].
`server.py`는 FastMCP 서버 객체에 이름 `trudi-sift`만 주고 버전을 주지 않는다 [18].
그래서 초기화 응답의 `serverInfo`에 실리는 버전은 서버 코드가 정하지 않고 그 값은 확인하지 않았다 [18].

**예외.** 수정 여부는 `git status`를 `core`와 `tools`에만 돌려 정하고 해시도 두 폴더의 파이썬 파일만 담는다 [15].
서버가 불러오는 `server.py`, 대응 조치 게이트 `response/`, 탐지 틀 `monitoring/`, 심사 자료 `data/fk`를 고쳐도 `run_profile`은 같은 커밋과 같은 해시를 적는다 [19].
`monitor.start_investigation`은 조사마다 새 호출 기록 파일로 옮기지만 그 파일에 `run_profile`을 쓰지 않는다 [20].
서버를 다시 띄운 뒤 `misc.start_execution_log`를 부르지 않으면 호출 기록은 세션 파일이 가리키는 이전 파일에 자동으로 다시 붙고 새 프로세스의 `run_profile`은 남지 않는다 [21].
git을 실행하지 못하면 커밋과 가지는 `?`로 남는다 [15].

### T06.06 모델·버전 표시

**구현.** `reason.*` 도구와 `dair.assess`는 서버 안에서 Claude API나 OpenAI 호환 API로 모델을 부른다 [22][23].
Claude 백엔드는 요청 전에 `call_initiated` 항목의 `inputs.model`에 모델 이름을 적는다 [22][23].
모델 이름은 `REASON_MODEL`·`DAIR_MODEL`이 비어 있으면 `claude-haiku-4-5-20251001`이다 [23][24].
OpenAI 호환 백엔드는 모델 이름을 `call_initiated` 항목과 결과의 `backend_meta.model`에 싣는다 [25].
`backend_meta`는 `reason_call` 항목에 그대로 남는다 [26].
OpenAI 호환 백엔드에 모델 이름을 주지 않으면 서버는 `/v1/models`가 돌려준 첫 ID를 쓴다 [27].

**예외.** 두 백엔드 모두 요청에 넣은 모델 이름을 적고 응답 본문이 담은 모델 이름은 읽지 않는다 [28].
서버 코드 주석은 llama.cpp와 LM Studio가 요청의 `model` 값을 무시한다고 적는다 [27].
그런 백엔드에서는 기록한 모델 이름이 실제로 답한 모델과 묶이지 않는다 [27][28].
Claude 백엔드의 `reason_call` 항목에는 모델 이름이 없고 앞선 `call_initiated` 항목에만 있다 [22][28].

def review_policy():
    # No secrets/endpoints in the receipt. The model and deliberate review
    # settings participate in identity; source hashes cover prompt/gate changes.
    from tools import reasoning as R
    root = Path(__file__).resolve().parents[1]
    policy = {}
    for pattern in ('core/evidence_packets.py', 'core/finding_submission.py',
                    'tools/reasoning.py', 'tools/_llm_parse.py', 'tools/_output_reader.py',

                   R.MAX_TOKENS_EVALUATE, R.COMPAT_EVIDENCE_ROUNDS, R.COMPAT_EVIDENCE_MODE,
                   digest(R.REASON_URL), R.COMPAT_EXTRA_BODY_RAW, R.REASON_FK,

def _vol(image: str, plugin: str, extra: list[str] | None = None,
         output_dir: str | None = None, timeout: int = VOL_TIMEOUT) -> dict:
    # -o OUTPUT_DIR is a global Volatility flag — must come before the plugin name.
    # Plugin-specific args (--pid, --dump, etc.) go in extra, after the plugin.
    if output_dir:

    out_flags = ["-o", output_dir] if output_dir else []
    cmd = [VOL, "-s", vol3_symbols()] + out_flags + ["-f", image, "-r", "json", plugin] + (extra or [])
    return run(cmd, timeout=timeout)

def _code_identity() -> str:
    """Which server code is running: git commit, dirty flag, and a digest of
    core/ + tools/ as they were when this server process imported them. Edits
    landing on disk mid-run do not change the loaded code, so the trace must
    say what was loaded, not what is on disk now."""
    import hashlib
    import subprocess
    from pathlib import Path
    root = Path(__file__).resolve().parents[1]
    h = hashlib.sha256()
    for p in sorted([*root.glob("core/**/*.py"), *root.glob("tools/**/*.py")]):
        h.update(str(p.relative_to(root)).encode())
        h.update(p.read_bytes())
    def git(*args):
        try:
            return subprocess.run(["git", "--no-optional-locks", "-C", str(root), *args], capture_output=True,
                                  text=True, timeout=5).stdout.strip()
        except Exception:
            return ""
    dirty = " dirty" if git("status", "--porcelain", "--", "core", "tools") else ""
    return (f"commit {git('rev-parse', '--short', 'HEAD') or '?'} "
            f"branch {git('rev-parse', '--abbrev-ref', 'HEAD') or '?'}{dirty} "
            f"code_sha256 {h.hexdigest()[:16]}")


_CODE_IDENTITY = _code_identity()

def _discover_compat_model(url: str, headers: dict, fallback: str) -> str:
    """Resolve the served model id when none is pinned in the environment.

    vLLM/SGLang reject a request whose `model` does not match the served name
    (404), and llama.cpp/LM Studio silently ignore it — so a hard-coded default
    is either fatal or misleading in the trace. Ask the server via
    GET /v1/models, cached per URL for COMPAT_MODEL_DISCOVERY_TTL seconds.
    """
    import time
    cached = _compat_model_cache.get(url)
    if cached and (time.monotonic() - cached[1]) < COMPAT_MODEL_DISCOVERY_TTL:
        return cached[0]
    model = fallback
    try:
        import httpx
        resp = httpx.get(f"{url.rstrip('/')}/v1/models", headers=headers,
                         timeout=COMPAT_MODEL_DISCOVERY_TIMEOUT)
        resp.raise_for_status()
        data = resp.json().get("data") or []
        ids = [d.get("id") for d in data if isinstance(d, dict) and d.get("id")]
        if ids:
            model = ids[0]
