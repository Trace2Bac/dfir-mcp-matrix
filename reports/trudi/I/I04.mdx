# I04 서버 자격증명 처리

### I04.01 환경변수·설정 파일에 분리 보관

**구현.** 서버가 외부 연동에 쓰는 자격증명은 모델 백엔드와 IOC 조회의 API 키, 원격 단말 SSH 키 파일, Velociraptor API 설정 파일이다 [1][2][3].
API 키는 환경변수 `ANTHROPIC_API_KEY`·`REASON_API_KEY`·`DAIR_API_KEY`·`VIRUSTOTAL_API_KEY`·`ABUSEIPDB_API_KEY`에서 읽는다 [1].
`REASON_API_KEY`·`DAIR_API_KEY`가 비어 있으면 옛 이름 `HF_TOKEN`을 읽는다 [1].
`server.py`는 도구 모듈을 불러오기 전에 `load_dotenv()`를 부른다 [4].
python-dotenv 1.2.3의 `load_dotenv()`는 인자가 없으면 부른 파일의 폴더부터 위로 올라가며 `.env`를 찾는다 [5].
이미 있는 환경변수는 덮지 않고 나머지 값을 환경변수로 올린다 [5].
`install.sh`는 `.env.example`을 복사해 저장소 폴더에 `.env`를 만들고 사용자에게 그 파일에 키를 넣으라고 안내한다 [6].
`.gitignore`는 `.env`를 저장소에서 빼고 `.env.example`의 키 칸은 비어 있다 [6][7].
코드에는 키 값이 없다 [1].

SSH는 `live_hosts.json` 항목의 `identity`나 환경변수 `TRUDI_LIVE_SSH_KEY`에 적은 키 파일 경로를 `ssh -i`로 넘기고 키 내용은 읽지 않는다 [2].
`ssh`는 `BatchMode=yes`로 실행해 암호를 묻지 않는다 [2].
Velociraptor 도구는 API 설정 파일 경로를 `velociraptor --api_config`로 넘긴다 [3].
저장소의 데모 구성은 이 파일을 `administrator` 역할로 만들고 파일 권한을 644로 둔다 [8].
서버는 키 파일이나 설정 파일의 소유자와 권한을 검사하지 않는다.

호출 기록에 남는 SSH 명령은 키 파일 경로를 빼고 적는다 [9].
Velociraptor 명령은 API 설정 파일 경로를 `<redacted>`로 바꿔 적는다 [3].
API 설정 파일이 없을 때 돌려주는 오류 문구에는 그 경로가 그대로 들어간다 [3].

### I04.02 도구 인자 수신 금지

**구현.** 어느 도구도 API 키·키 파일 경로·API 설정 파일 경로를 인자로 받지 않고 서버가 환경변수와 설정 파일에서 직접 읽는다 [10].
`live.*` 도구는 접속할 호스트를 `live_hosts.json`의 이름으로만 받고 `live.hosts`도 이름만 돌려준다 [11].
API 키는 요청 헤더(`x-apikey`·`Key`·`Authorization`)와 Anthropic SDK 클라이언트에만 넣는다 [12].
조회 도구의 응답은 조회 결과 필드만 담고 키는 담지 않는다 [13].
모델 호출 기록은 모델 이름과 OpenAI 호환 주소, 보낸 사용자 메시지를 남기고 키는 남기지 않는다 [14].
검토 정책 식별값도 모델 주소를 해시로만 넣고 키는 넣지 않는다 [15].
조회나 모델 호출이 실패하면 서버는 예외 문구를 응답의 `error`와 기록에 그대로 싣고 문구에서 비밀값을 찾아 지우는 처리는 없다 [16].

**한계.** 외부 도구 실행기는 `env`를 따로 받지 않으면 `subprocess.run`에 `env=None`을 넘긴다 [17].
Python 3.10의 `subprocess`는 이때 서버 프로세스의 환경변수를 그대로 자식 프로세스에 물려준다 [17].
`load_dotenv()`가 `.env`의 키를 환경변수로 올렸으므로 서버가 실행하는 외부 도구는 모두 API 키를 물려받는다 [4][17].
`misc.batch_run`은 모델이 준 argv를 허용 목록 없이 이 실행기로 실행한다 [18].
실행기는 표준 출력을 응답에 담고 전체 표준 출력을 호출 기록에 남긴다 [19].
그래서 모델이 `misc.batch_run`으로 `env` 같은 명령을 실행하면 키 값이 응답과 호출 기록에 들어간다 [18][19].

```python
def _build_ssh_argv(resolved: dict, cmd_argv: list[str]) -> list[str]:
    """Construct the full local argv: ssh + opts + user@host + -- + remote argv.

    The `--` separator tells SSH that everything after is the remote command
    as discrete argv tokens, not a single shell string. SSH still concatenates
    them, but each token is properly shell-quoted by ssh's own quoting layer,
    so an operand like `'; rm -rf /'` is passed as a literal filename, not
    parsed as a separator.
    """
    argv = ["ssh"] + _SSH_OPTS + [
        "-i", resolved["identity"],
        "-p", str(resolved["port"]),
        f"{resolved['user']}@{resolved['host']}",
        "--",
    ]
```
