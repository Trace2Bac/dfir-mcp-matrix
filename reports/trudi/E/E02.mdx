# E02 증거 무결성 검증

### E02.02 도구를 요청해 기준값 계산

**구현.** 증거 해시는 모델이 `hash` namespace의 도구를 부를 때만 계산한다 [1].
증거를 받는 분석 도구는 경로를 외부 도구에 넘길 뿐 해시하지 않으므로 등록이나 첫 접근 때의 자동 해시(E02.01)는 없다 [2].
전역 지침은 증거 파일마다 사건당 한 번 `hash.verify_evidence_hash`를 부르라고 모델에게 적는다 [3].
서버는 다른 도구를 실행하기 전에 그 호출이 있었는지 보지 않는다.
`respond.execute_action`이 단말에 만든 프로세스 메모리 덤프는 서버가 해시하지 않는다 [4].
`hash` 도구는 분석 서버에 있는 파일 경로만 읽는다 [1].

`hash.file`은 받은 경로의 파일을 처음부터 끝까지 64 KiB씩 읽어 MD5·SHA-1·SHA-256을 한 번에 계산한다 [1].
해시 범위는 파일 하나의 바이트이고 E01을 주면 매체 데이터가 아니라 그 조각 파일 하나의 바이트를 해시한다 [1].
결과는 그 호출의 기록 항목에 `hash_result`(경로·크기·세 해시)와 `hashed_file_version`(장치 번호·inode·크기·수정 시각·변경 시각) annotation으로 남는다 [5].
해시하는 동안 파일의 상태 값이 바뀌면 값을 버리고 다시 하라고 돌려준다 [5].
같은 값은 경로·크기·수정 시각·변경 시각·inode를 키로 해시 캐시 `hash_cache.json`에도 저장된다 [6][7].
캐시에 같은 키가 있으면 파일을 다시 읽지 않고 저장된 값을 `cache_hit`을 참으로 해 돌려준다 [8].
키가 파일 상태 값이므로 상태 값은 그대로 두고 내용만 바뀐 파일은 캐시 값으로 답한다 [6][8].
캐시 파일은 사건마다 나뉘지 않는 `~/.cache/trudi` 아래에 있고 환경변수 `TRUDI_HASH_CACHE`로 위치를 바꾼다 [6].
기록 항목의 `hashed_file_version`은 발견사항 심사가 이 해시 호출을 인용할 때 기준값으로 쓰인다(E02.07) [9].

`hash.directory`는 폴더 아래 파일마다 고른 알고리즘 하나의 해시를 계산한다 [10].
파일 수·바이트·시간 상한에 닿으면 멈추고 `truncated`와 이어 할 위치 `next_start_path`를 돌려주며 상한보다 큰 파일은 `skipped`에 적는다 [10].
이 도구는 `hash_result`·`hashed_file_version` annotation을 남기지 않는다 [5][10].
`hash.hashdeep_compute`·`hash.md5deep_scan`은 외부 도구 `hashdeep`·`md5deep`의 출력을 돌려주고 `output_path`를 주면 그 출력을 파일로 쓴다 [11].
이 목록 파일은 `hash.hashdeep_audit`의 기준값으로 쓸 수 있다(E02.09) [12].

분석 도구가 결과에 덧붙이는 해시로는 plaso가 있다.
`plaso.create_timeline`·`plaso.create_targeted`는 `log2timeline.py`에 `--hashers`를 넘기지 않는다 [13].
plaso 20260720의 `log2timeline`은 `--hashers`의 기본값이 `sha256`이고 hasher가 처리할 파일 크기에 상한이 없다 [14].
서버는 이 값을 기준값으로 보관하거나 대조하지 않는다 [13].

**예외.** `hash.directory`는 이름이 점으로 시작하는 파일과 폴더, 심볼릭 링크인 파일을 건너뛰고 그 사실을 `skipped`나 `errors`에 적지 않는다 [15].
도구 설명은 폴더의 파일을 해시한다고 적고 숨김 항목과 링크를 뺀다는 말은 없다 [10].

### E02.07 도구 호출 중 자동 검증

**구현.** 이 방식은 발견사항을 심사하고 기록하는 `misc.submit_finding`과 `reason.evaluate_finding`에 적용된다 [16][17].
두 도구는 근거로 인용한 호출로 심사 묶음을 만들고 인용한 호출이 `hash_result`와 `hashed_file_version`을 가진 해시 호출이면 그 파일의 지금 상태 값을 해시 때 값과 견준다 [9].
견주는 값은 장치 번호·inode·크기·수정 시각·변경 시각이고 파일 내용은 다시 해시하지 않는다 [9].
기준값은 `hash.file`이나 `hash.verify_evidence_hash`가 해시하면서 기록 항목에 남긴 상태 값이다 [5].
`misc.submit_finding`은 심사 모델의 답을 받은 뒤 발견사항을 기록하기 직전에 같은 비교를 한 번 더 한다 [18].
`misc.record_finding`으로 CONFIRMED·LIKELY 발견사항을 기록할 때도 검토 통과 기록 `review_receipt`를 확인하면서 같은 비교를 한다 [19].
모델이 해시 호출을 근거로 인용하지 않은 증거와 해시하지 않은 증거는 견주지 않는다.
분석 도구가 증거를 읽을 때는 서버가 대조하지 않는다 [2].

**예외.** `misc.record_finding`으로 SUSPECTED·UNCONFIRMED 발견사항을 바로 기록하면 해시 호출을 인용해도 `review_receipt` 확인을 건너뛰어 이 비교가 일어나지 않는다 [19].

### E02.09 도구를 요청해 검증

**구현.** 이 방식은 `hash.verify_evidence_hash`·`ewf.verify`·`hash.hashdeep_audit`에 적용되고 모델이 부를 때만 대조한다 [20][21][12].
`hash.verify_evidence_hash`는 `hash.file`로 파일을 해시한 뒤 모델이 준 `expected_md5`·`expected_sha1`과 대소문자를 가리지 않고 견준다 [20].
견준 결과는 `md5_match`·`sha1_match`와 둘을 묶은 `integrity_verified`로 응답에 실린다 [20].
기준값은 모델이 준 값뿐이고 서버가 앞서 계산해 둔 해시를 꺼내 견주지 않는다 [20].
기대값을 주지 않으면 해시만 계산하고 대조하지 않는다 [20].
`hash.file`과 같은 캐시를 거치므로 상태 값이 같은 파일은 다시 읽지 않고 저장된 값으로 견준다 [8].
E01을 주면 그 조각 파일 하나의 바이트를 해시하므로 수집 도구가 남긴 매체 데이터 해시와 맞지 않는다 [1].

`ewf.verify`는 `ewfverify`를 실행하고 출력에서 이미지에 저장된 해시(`stored in file`), 데이터에서 계산한 해시(`calculated over data`), 판정 줄을 읽는다 [21].
기준값은 이미지 형식 안에 든 수집 해시이고 어느 범위를 해시하는지는 `ewfverify`가 정한다 [21].
`hash.hashdeep_audit`은 모델이 준 목록 파일 `manifest_file`을 기준값으로 폴더를 `hashdeep` 감사 모드로 견준다 [12].
hashdeep 4.4의 감사 모드는 목록에 없는 파일, 옮겨진 파일, 목록에만 있는 항목이 하나라도 있으면 실패로 판정한다 [22].
서버가 다른 도구를 실행하는 과정에서 증거 해시를 다시 계산해 대조하는 곳은 없다 [2].

**예외.** `hash.verify_evidence_hash`는 기대값과 어긋나도 응답의 `success`를 참으로 두고 호출 기록에 `VERIFIED: <경로> sha256=…` 결론을 성공으로 남긴다 [23].
기대값을 주지 않아 대조하지 않은 호출도 같은 `VERIFIED` 결론을 남긴다 [23].
도구 설명은 이 기록으로 다른 도구가 검증 여부를 찾는다고 적지만 그 기록을 찾는 `has_evidence_been_verified`를 부르는 서버 코드는 없다 [24][25].

### E02.08 불일치 시 중단·경고

**구현.** 불일치를 알리는 곳은 E02.07의 상태 값 비교와 `ewf.verify`다 [9][21].
상태 값이 어긋나면 `misc.submit_finding`은 상태 `needs-evidence`와 `Hashed source changed after call …; hash it again` 오류를 돌려주고 발견사항을 기록하지 않는다 [9][26].
`reason.evaluate_finding`은 심사하지 않고 `evidence_packet` 게이트 실패를 돌려준다 [17].
이 실패는 미들웨어가 그 도구 호출을 실패로 기록할 때 오류 문구와 함께 호출 기록에 남는다 [27].
서버는 불일치를 세션 상태로 남기지 않으므로 그 뒤의 분석 도구 호출은 그대로 실행된다.

`ewf.verify`는 `ewfverify`가 판정 줄을 남기고 끝나면 실패 판정이어도 호출을 성공으로 두고 `verified`를 거짓, `status`를 `verification_failed`로 적는다 [21].
`exit_meaning`에는 검증 실패와 MD5 불일치 여부가 적히고 이 값은 호출 기록 항목에도 들어간다 [21][28].
이 결과도 이후의 호출을 막지 않는다.

`hash.hashdeep_audit`은 hashdeep 4.4가 감사에 실패하면 `Audit failed`를 출력하고 종료 코드 1로 끝나므로 서버의 기본 종료 코드 처리에 따라 실패 응답이 된다 [22][29].
이 응답은 `hashdeep`이 실행되지 못한 경우와 같은 모양이다 [29].
`hash.verify_evidence_hash`는 불일치 때 결과 값만 돌려주고 알리지 않는다(E02.09의 예외) [23].

```python
def _record_hash_result(result: dict, source_version: str) -> dict:
    """Retain the typed hash result as evidence, rather than an invocation log."""
    from core.execution_log import log
    try:
        path = os.path.abspath(result['file'])
        stat = os.stat(path)
    except OSError as exc:
        return {'success': False, 'error': str(exc), 'file': result['file']}
    if _cache_key(stat, path) != source_version:
        return {'success': False, 'error': 'File changed while hashing; retry', 'file': result['file']}
    version = [stat.st_dev, stat.st_ino, stat.st_size, stat.st_mtime_ns, stat.st_ctime_ns]
    payload = {k: result[k] for k in ('file', 'size_bytes', 'md5', 'sha1', 'sha256')}
    cid = log.record_tool_call(cmd=f"hash.file {result['file']}", success=True,
                               truncated=False, retries=0, exit_code=0,
                               stdout_full=json.dumps(payload), stdout_excerpt=json.dumps(payload))
    log.annotate_tool_call(cid, hash_result=payload, source_version=source_version,
                           hashed_file_version=version,
                           source_hashes={result['file']: result['sha256']})
    return {**result, '_trudi_call_id': cid}
```

```python
def trudi_cache_dir() -> str:
```

```python
def _iter_files(directory: str, recursive: bool, start_after: str = ""):
    """Deterministic (sorted) walk so a capped run can be resumed from
    `next_start_path`. Yields absolute file paths; symlinks are not followed."""
    root = os.path.abspath(directory)
    # Hidden entries are skipped, as the previous glob("**/*") walk did.
    if not recursive:
        try:
            names = sorted(n for n in os.listdir(root) if not n.startswith("."))
        except OSError:
            return
        for n in names:
            p = os.path.join(root, n)
            if os.path.isfile(p) and not os.path.islink(p) and p > start_after:
                yield p
        return
    for dirpath, dirnames, filenames in os.walk(root, followlinks=False):
        dirnames[:] = sorted(d for d in dirnames if not d.startswith("."))
        for n in sorted(f for f in filenames if not f.startswith(".")):
            p = os.path.join(dirpath, n)
            if p <= start_after:
                continue
            if os.path.isfile(p) and not os.path.islink(p):
                yield p
```
