# E04 분석 입력 준비

### E04.01 작업 사본 생성

**구현.** 보관 파일을 통째로 풀거나 이미지 안 파일시스템 하나의 파일을 한꺼번에 꺼내는 도구는 `misc.pff_export`·`misc.readpst_extract`·`tsk.recover`다 [1][2][3].
`misc.pff_export`는 PST·OST 메일 보관 파일을 `pffexport`로 풀어 메시지마다 폴더를 만든다 [1].
코드 설명은 `pffexport`가 출력 폴더 이름 뒤에 `.export`를 붙인다고 적고 서버는 실제로 생긴 폴더를 `output_path`로 돌려주며 `read.mail`로 읽으라는 안내를 붙인다 [1].
`misc.readpst_extract`는 PST를 `readpst`로 mbox 또는 메시지별 파일로 바꿔 출력 폴더에 쓴다 [2].
`tsk.recover`는 `include_unallocated`가 거짓이면 `-a`로, 참이면 `-e`로 `tsk_recover`를 실행해 파일시스템 하나의 파일을 출력 폴더로 꺼낸다 [3].
도구 설명은 `include_unallocated`가 참이면 삭제·비할당 파일까지 꺼낸다고 적는다 [3].
결과는 출력 폴더 `output_dir` 아래에 꺼낸 파일들이고 이미지 전체의 바이트 사본이 아니다 [3].
`tsk.recover`는 늘 서버 안 백그라운드 작업으로 실행된다 [4].
출력 위치는 모델이 정하고 서버는 그 위치가 증거 위치인지만 검사한다(E03.02) [5].
파서와 외부 도구 대부분은 이런 사본 없이 증거 경로나 마운트 아래 경로를 그대로 받는다 [6].

### E04.02 선택 추출

**구현.** 모델이 고른 범위만 꺼내는 도구는 `tsk.icat`·`vol.dumpfiles`·`vol.memmap`이다 [7][8].
`tsk.icat`은 모델이 준 inode 하나(ADS면 `번호-형식-ID`)의 내용을 모델이 정한 `output_path`에 쓴다 [7].
`vol.dumpfiles`는 모델이 준 가상 주소나 PID로 메모리 안 파일 객체를 `output_dir`에 꺼내고 `vol.memmap`은 `dump`가 참이면 그 PID의 메모리를 꺼낸다 [8].
조건을 대조하는 일은 Sleuth Kit과 Volatility가 한다 [7][8].

서버 코드가 이름으로 파일을 골라 입력을 좁히는 도구는 `ez.recmd_batch`와 `misc.usbdeviceforensics`다 [9][10].
`ez.recmd_batch`는 `per_hive`가 참이면 폴더 아래에서 이름이 `ntuser.dat`·`usrclass.dat`·`sam`·`system`·`software`·`security`·`amcache.hve`·`default`인 파일을 대소문자를 가리지 않고 찾고 트랜잭션 로그 확장자는 뺀다 [9].
찾은 하이브는 폴더를 이름 차례로 순회한 순서대로 `max_hives`(기본 64개)까지 하나씩 RECmd에 넘기고 파일을 옮기거나 복사하지 않는다 [9][11].
`misc.usbdeviceforensics`는 받은 config 폴더에서 `SYSTEM`·`SOFTWARE`와 두 단계 위 `INF` 폴더의 `setupapi.dev.log`를 이름으로 골라 임시 폴더에 심볼릭 링크로 모은다 [10].
그 임시 폴더를 `usbdeviceforensics`에 넘기고 도구가 끝나면 지운다 [12].
`SYSTEM`을 찾지 못하면 받은 경로를 그대로 넘긴다 [10][12].

**예외.** `ez.recmd_batch`에 `per_hive`를 거짓으로 주면 서버가 하이브를 고르지 않고 폴더 전체를 RECmd의 `-d`로 넘긴다 [11].

### E04.03 전체·부분 마운트

**구현.** 파일시스템으로 마운트하는 도구는 서버가 파티션을 고르는 `ewf.mount_full_image`와 모델이 시작 위치를 주는 `ewf.mount_ntfs`다 [13][14].
이 도구는 `ewfmount`로 E01을 붙여 원시 디스크 `ewf1`을 만들고 `mmls`로 파티션 표를 읽는다 [13].
파티션은 설명에 `ntfs`가 든 것을 앞에 두고 그다음 크기가 큰 차례로 늘어놓는다 [15].
그 차례대로 `fsstat`을 실행해 파일시스템 종류가 NTFS인 첫 파티션을 고르고 시작 섹터에 `mmls`가 알린 섹터 크기를 곱해 오프셋을 정한다 [16].
고른 파티션 하나만 읽기 전용으로 마운트하고 응답에 오프셋과 `ewf1` 경로를 적는다 [16].
NTFS 파티션이 없으면 마운트하지 않고 살펴본 파티션과 파일시스템 종류를 실패 응답에 적는다 [16].
파티션은 호출마다 새로 고르고 서버는 고른 값을 저장하지 않는다 [16].
`ewf.mount_ntfs`는 모델이 정한 시작 위치 `offset_bytes`로 NTFS 파일시스템 하나를 마운트한다 [14].

나머지 마운트 도구는 파일시스템을 마운트하지 않는다.
`img.vshadow_mount`는 모델이 준 볼륨 오프셋으로 `vshadowinfo`를 먼저 실행해 섀도 복사본이 없으면 마운트하지 않고 있으면 그 수만큼 `vss1`부터의 경로를 돌려준다 [17].
`img.losetup_create`도 모델이 준 오프셋으로 loop 장치를 만든다 [18].
`ewf.mount`와 `img.xmount_image`는 이미지 전체를 원시 디스크 파일 하나로 보이게 하고 파티션을 고르지 않는다 [19][20].
`img.bde_mount`는 BitLocker 볼륨을 붙이고 도구 설명은 그 뒤 `mount_ntfs`를 오프셋 0으로 부르라고 적는다 [21].
마운트의 읽기 전용 여부는 E03.01에서 본다.

**예외.** `ewf.mount_full_image`는 NTFS 파티션이 여럿이어도 첫 하나만 마운트하고 성공 응답에 나머지 파티션을 적지 않는다 [16].

### E04.05 추출·생략 범위 기록

**구현.** 준비한 입력의 범위를 남기는 도구는 `misc.usbdeviceforensics`와 `ez.recmd_batch`다 [12][22].
`misc.usbdeviceforensics`는 임시 폴더에 모은 원래 파일 경로를 `Staged input:` 줄로 출력 앞에 붙이고 그 줄은 응답과 호출 기록의 전체 출력에 함께 남는다 [12].
응답에는 같은 경로 목록이 `staged_inputs`로도 실린다 [12].
`ez.recmd_batch`는 찾은 하이브 수 `hives_found`, 성공·실패 수, 하이브마다의 경로·성공 여부·오류와 상한에 닿았는지를 뜻하는 `capped`를 응답에 돌려준다 [22].
하이브마다의 RECmd 실행은 따로 호출 기록에 남는다 [22].
`capped`는 찾은 하이브 수가 상한과 같기만 해도 참이 되고 상한 밖에 하이브가 몇 개 남았는지는 적지 않는다 [22].

`tsk.icat`·`tsk.recover`·`vol.dumpfiles`·`misc.pff_export`·`misc.readpst_extract`는 꺼낸 파일의 목록이나 개수를 서버가 따로 정리하지 않는다 [1][2][3][7][8].
`ewf.mount_full_image`도 마운트하지 않은 파티션을 성공 응답에 적지 않는다(E04.03의 예외) [16].

### E04.07 부속 자료 누락·로그 미반영 표시

**구현.** 이 방식은 SQLite 채팅 DB를 읽는 `misc.chat_db_export`에 적용된다 [23].
서버는 DB를 `mode=ro&immutable=1`로 열고 코드 설명은 이 모드가 체크포인트되지 않은 `-wal` 프레임을 읽지 못한다고 적는다 [24].
DB와 같은 이름의 `-wal` 파일이 있으면 응답에 `wal_present`를 참으로 두고 최근 행이 빠졌을 수 있다는 경고를 싣는다 [25][23].
성공한 호출이면 이 경고가 호출 기록에 남는 요약에도 들어간다 [23].
서버는 `-wal`이 있는지만 보고 반영하거나 함께 옮기지 않는다 [25].
SQLite 증거를 외부 도구에 넘기는 `ez.sqlecmd`·`ez.wxtcmd`·`misc.hindsight_chrome`은 `-wal` 파일을 따로 보지 않는다 [26].
서버 코드가 입력 옆의 부속 파일을 찾아 입력과 함께 넘기는 곳은 없어 E04.06에는 연결하지 않았다.

### E04.08 로그 재생·복원

**구현.** 트랜잭션 로그를 적용하는 외부 도구에 로그를 넘기는 도구는 `ez.rla`다 [27].
`ez.rla`는 하이브와 `.LOG1`·`.LOG2`가 든 폴더를 `rla`의 `-d`로 넘기고 도구 설명은 로그를 재생해 최신 상태의 하이브를 얻는다고 적는다 [27].
적용은 `rla`가 하고 서버는 로그가 적용됐는지 확인하지 않는다 [27].

RECmd를 쓰는 `ez.recmd_hive`·`ez.recmd_dir`·`ez.recmd_batch`는 하이브 경로나 폴더만 넘기고 로그 처리는 RECmd에 맡긴다 [28][9].
RECmd 2026.5.0은 더티 하이브를 만나면 같은 폴더에서 `<하이브 이름>.LOG?` 파일을 찾아 메모리에서 적용한다 [29].
로그가 없으면 `--nl`을 주지 않은 경우 경고를 출력하고 그 하이브를 건너뛴다 [29].
서버는 `--nl`을 넘기지 않고 로그를 적용했는지나 하이브를 건너뛰었는지를 응답에 따로 적지 않는다 [28].

**예외.** `rla` 2026.5.0의 인자는 `-f`·`-d`·`--out`·`--ca`·`--cn`·`--nop`·`--debug`·`--trace`이고 서버가 넘기는 `--csv`·`--csvf`는 없다 [30].
`rla`는 로그를 적용한 하이브를 `--out` 폴더에 쓰고 `-f`나 `-d`를 받았는데 `--out`이 없으면 처리하지 않고 끝난다 [30][31].
서버는 `--out`을 넘기지 않으므로 `ez.rla`는 로그를 적용한 하이브를 만들지 못한다 [27].
이 호출의 실제 출력과 종료 코드는 실행해 확인하지 않았다.

```python
def readpst_extract(pst_path: str, output_dir: str, format_mbox: bool = True) -> dict:
    """
    Convert a PST file to mbox (default) or per-message MIME using readpst.

    format_mbox: True → -o mbox; False → -e (per-message .eml files).
    """
    missing = tool_unavailable_result("misc.readpst_extract", _bin_or_warn)
    if missing:
        return missing
    binary = optional_binary("misc.readpst_extract", _bin_or_warn)
    os.makedirs(output_dir, exist_ok=True)
    # -q: quiet — only error messages on stdout (progress banner otherwise
    # dominates the trace excerpt; converted mail is written under output_dir).
    cmd = [binary, "-q", "-o", output_dir]
    if not format_mbox:
        cmd.append("-e")
    cmd.append(pst_path)
    return run(cmd, timeout=1800)
```

```python
@mcp.tool()
@output_safe
def tsk_icat(
    image: str,
    inode: str,
    output_path: str,
    offset_sectors: Optional[int] = None,
    recover_deleted: bool = False,
    slack_space: bool = False,
) -> dict:
    """
    Extract file content by inode number to output_path.
    inode: can be a number or 'number-stream-id' for ADS (e.g. '11-128-4').
    recover_deleted: attempt recovery of deleted file data.
    slack_space: extract file slack space.
    """
    cmd = ["icat"]
    if recover_deleted:
        cmd.append("-r")
    if slack_space:
        cmd.append("-s")
    if offset_sectors:
        cmd += ["-o", str(offset_sectors)]
    cmd += [image, str(inode)]
    return run_with_output_file(
        cmd, output_path=output_path, mode="wb", timeout=120, needs_sudo=True,
    )
```

```python
def _mmls_partitions(stdout: str) -> list[dict]:
    """Real partitions from an mmls table, largest first.

    Skips the Meta and Unallocated rows and keeps every data partition whatever
    its description: a GPT table calls them "Basic data partition", so matching
    the word NTFS in the description finds nothing at all.
    """
    out = []
    for line in (stdout or "").splitlines():
        m = _MMLS_ROW_RE.match(line.strip())
        if not m:
            continue
        slot, start, end, length, desc = m.groups()
        if not slot[0].isdigit():      # Meta / ------- rows carry no partition
            continue
        out.append({"slot": slot, "start": int(start), "end": int(end),
                    "length": int(length), "description": desc.strip()})
    # A description that names the filesystem is the strongest hint; size breaks ties.
    return sorted(out, key=lambda p: ("ntfs" in p["description"].lower(), p["length"]),
                  reverse=True)
```
