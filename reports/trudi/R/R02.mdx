# R02 대량 결과 전달

### R02.01 문자·항목 상한

**구현.** 외부 도구 실행기는 표준 출력을 51,200자에서 자르고 그다음 150줄에서 자른다 [1][2].
두 상한은 사용자가 환경변수 `TRUDI_OUTPUT_CAP`·`TRUDI_OUTPUT_LINE_CAP`로 정하고 모델은 바꾸지 못한다 [1].
서버 안에서 결과 목록을 만드는 도구에는 도구별 건수 인자가 있다.
예를 들어 `evtx_filter`는 `max_results`(기본 200)에 이르면 읽기를 멈춘다 [3].
`hash.ssdeep_hash`·`hash.ssdeep_compare`·`hash.ssdeep_scan_directory`·`hash.hashdeep_compute`·`hash.hashdeep_audit`·`hash.md5deep_scan`은 줄 상한을 끄고 실행하므로 문자 상한만 적용된다 [4].

**한계.** `evtx_filter`의 `max_results`처럼 서버가 만든 목록의 상한은 모델이 인자로 올린다 [3].

### R02.02 전체·반환 건수 표시

**구현.** 줄 상한에서 자른 출력 끝에는 생략한 줄 수를 적은 꼬리말을 붙인다 [5].
`strings_grep`은 상한을 넘어서도 센 전체 일치 수 `match_count`와 돌려준 수 `returned`를 나누어 싣고 상한에 걸리면 두 수를 적은 안내를 붙인다 [6].
`misc.cs_beacon_config`는 찾은 비컨 설정 수 `match_count`와 그 가운데 앞 10건을 `matches`에 싣는다 [7].
전체 건수와 반환 건수를 함께 싣는 도구는 일부다.

**한계.** 줄 상한 꼬리말의 생략 줄 수는 문자 상한으로 먼저 자른 뒤에 센 값이다 [2][5].
두 상한이 함께 걸리면 원래 출력의 줄 수를 알 수 없다.
`misc.cs_beacon_config`의 분석 함수는 일치를 50건 찾으면 파일 훑기를 멈추고 결과에 `match_cap_hit`를 남긴다 [8].
응답은 `match_cap_hit`를 싣지 않는다 [7].
그래서 `match_count`가 50이면 그 수가 전체 수인지 상한에서 멈춘 수인지 응답으로 알 수 없다 [7][8].

### R02.03 페이지·커서 조회

**구현.** 이 방식은 `hash.directory`와 `monitor.check_alerts`에 적용된다 [9][10].
`hash.directory`는 파일 수·바이트·시간 상한에 닿으면 멈추고 마지막으로 처리한 파일 경로를 `next_start_path`로 돌려주며 그 값을 `start_after`로 넘겨 다시 부르라고 안내한다 [9].
이어 부르면 경로 문자열이 `start_after`보다 큰 파일만 처리한다 [11].
`monitor.check_alerts`는 순번이 `since_seq`보다 큰 경보를 순번 차례로 `max_alerts`(기본 50)개까지 돌려준다 [10].
경보마다 순번 `seq`가 실려 있어 마지막 경보의 순번을 다음 `since_seq`로 넘기면 이어 읽는다 [10][12].
응답에는 남은 경보가 있는지 알리는 표시가 없다 [10].
`monitor.ack_alert`는 경보 파일에 `consumed`를 쓰기만 하고 `monitor.check_alerts`는 이 값으로 경보를 거르지 않는다 [10][13].

**한계.** `hash.directory`의 재귀 순회는 폴더마다 파일을 이름순으로 내보낸 뒤 하위 폴더로 내려가지만 재개 필터는 전체 경로의 문자열 크기로 처리한 파일을 가린다 [11].
그래서 `z.txt`와 `a/one.txt`가 있는 폴더를 `max_files=1`로 해싱하면 첫 응답은 `z.txt`에서 멈추고 그 값으로 이어 부른 응답은 `a/one.txt` 없이 `truncated`가 거짓인 성공으로 끝난다 [9][11].
커서가 하위 폴더의 파일이면 경로가 커서보다 큰 상위 폴더 파일은 이어 부를 때 다시 해싱된다 [11].
`output_manifest`를 주고 이어 부르면 결과를 목록 파일 끝에 덧붙이므로 다시 해싱한 파일은 목록에 두 번 들어간다 [14].
다시 해싱하는 경로는 코드로만 확인했고 실행하지는 않았다.
도구 주석은 이어 부르면 빠지거나 겹치는 파일이 없다고 적는다 [15].

### R02.06 값 단위 잘림

**구현.** `evtx_filter`는 맞는 이벤트의 XML을 2,000자에서 잘라 싣는다 [3].
잘린 이벤트에는 표시가 없다 [3].
`read.output`은 돌려주는 행을 1,200자, 표 형식 파일의 필드를 400자에서 자르고 `…[row truncated]`·`…[field truncated]`를 붙인다 [16].
두 상한은 사용자가 환경변수 `TRUDI_REASON_ROW_CHARS`·`TRUDI_REASON_FIELD_CHARS`로 정한다 [16].

### R02.07 건수 없는 잘림 표시

**구현.** 문자 상한만 넘은 출력에는 `truncated: true`만 붙는다 [2].
실행기는 원래 길이 `_stdout_chars`를 계산하지만 호출 기록에만 쓰고 응답에서 뺀다 [17].
`evtx_filter`는 상한에 이르면 `cap_hit`를 싣고 돌려준 개수만 `matches_found`로 적는다 [3].

**한계.** `read.output` 응답의 `truncated`는 본문에 `[truncated]`나 `[row cap]`이 있을 때만 참이다 [18].
그래서 행·필드 상한에서 잘려 `…[row truncated]`·`…[field truncated]`만 붙은 본문에서는 `truncated`가 거짓이다 [16][18].

### R02.08 보관한 출력의 일부 재조회

**구현.** 실행기는 잘리기 전의 표준 출력 전체를 호출 기록 옆 `analysis/.tool_output/<호출 ID>.txt`에 남긴다 [19].
도구 응답에는 그 호출 ID `_trudi_call_id`가 실린다 [20].
`read.output`은 경로 조각에 `analysis`·`exports`·`reports`가 있는 파일을 읽어 질의어가 많이 들어간 줄부터 한 번에 `max_chars`까지 돌려준다 [21].
`max_chars`의 기본값은 20,000자이고 위쪽 한계는 실행기의 문자 상한(기본 51,200자)이다 [21].
줄 위치를 지정해 이어 읽는 인자가 없어 보관한 출력 전체를 끝까지 다시 읽지는 못한다 [21].
도구 응답은 사이드카 경로를 싣지 않고 그 경로는 저장소의 클라이언트 훅 안내 문구에 있다 [22].

**한계.** 사이드카 파일은 8,388,608자까지만 남기므로 그보다 긴 출력은 보관본도 잘린다 [19].
`velo.*` 도구는 공통 실행기를 쓰지 않고 자기 실행 함수에서 표준 출력을 문자 상한과 줄 상한으로 자른다 [23].
그 뒤 기록 함수에 잘린 `stdout`만 넘기고 잘리기 전의 출력은 넘기지 않는다 [23].
기록 함수는 전체 출력을 받지 못하면 받은 `stdout`을 사이드카 파일에 쓰므로 Velociraptor 실행의 보관본도 잘린 출력이다 [24].

```python
def _apply_line_cap(text: str, max_lines: int) -> tuple[str, bool]:
    """Trim text to max_lines, appending a footer if trimmed."""
    lines = text.splitlines(keepends=True)
    if len(lines) <= max_lines:
        return text, False
    omitted = len(lines) - max_lines
    return "".join(lines[:max_lines]) + _TRUNCATION_FOOTER.format(n=omitted), True
```

```python
@output_safe
def check_alerts(case_id: str, since_seq: int = 0, max_alerts: int = 50) -> dict:
    """Return alerts with seq > since_seq, oldest first, capped at max_alerts.

    Does NOT mark consumed — that's `ack_alert`'s job. Idempotent reads
    are useful for the /loop pattern: each tick pulls the same un-acked
    alerts until they're processed.

    alerts_dir = _alerts_dir(case_id)
    alerts: list[dict] = []
    for path in sorted(alerts_dir.glob("*_*.json")):
        try:

            seq = int(seq_str)
        except (ValueError, IndexError):

        if seq <= since_seq:
            continue
        try:

        except (OSError, json.JSONDecodeError):
            continue
        data["_path"] = str(path)
        alerts.append(data)
        if len(alerts) >= max_alerts:
            break
    return {"success": True, "alerts": alerts, "count": len(alerts)}
```

```python
def _iter_files(directory: str, recursive: bool, start_after: str = ""):
    """Deterministic (sorted) walk so a capped run can be resumed from
    `next_start_path`. Yields absolute file paths; symlinks are not followed."""
    root = os.path.abspath(directory)
    # Hidden entries are skipped, as the previous glob("**/*") walk did.
    if not recursive:
        try:
            names = sorted(n for n in os.listdir(root) if not n.startswith("."))
        except OSError:
            return
        for n in names:
            p = os.path.join(root, n)
            if os.path.isfile(p) and not os.path.islink(p) and p > start_after:
                yield p
        return
    for dirpath, dirnames, filenames in os.walk(root, followlinks=False):
        dirnames[:] = sorted(d for d in dirnames if not d.startswith("."))
        for n in sorted(f for f in filenames if not f.startswith(".")):
            p = os.path.join(dirpath, n)
            if p <= start_after:
                continue
            if os.path.isfile(p) and not os.path.islink(p):
                yield p
```

```python
_FIELD_MARK = " …[field truncated]"
_ROW_MARK = " …[row truncated]"


def _cap_line(s: str) -> tuple[str, bool]:
    if len(s) <= _ROW_CHARS:
        return s, False
    return s[:_ROW_CHARS].rstrip() + _ROW_MARK, True


def _cap_fields(cells: list, delim: str) -> tuple[str, bool]:
    """Cap each cell, then the joined row. Returns (text, clipped)."""
    out, clipped = [], False
    for c in cells:
        if len(c) > _FIELD_CHARS:
            out.append(c[:_FIELD_CHARS].rstrip() + _FIELD_MARK); clipped = True
        else:
            out.append(c)
    text, row_clipped = _cap_line(delim.join(out))
    return text, clipped or row_clipped


def _cap_row_text(s: str, delim: str | None) -> tuple[str, bool]:
    """Line-scan row cap: per-field when the file is tabular (delimiter known),
    else a plain line cap."""
    if delim and delim in s:
        return _cap_fields(s.split(delim), delim)
    return _cap_line(s)
```
