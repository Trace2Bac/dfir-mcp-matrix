# R01 도구 출력 가공

### R01.01 가공 없이 전달

**구현.** 외부 도구를 감싼 도구 가운데 많은 수가 공통 실행기 `run`의 결과를 그대로 돌려준다 [1].
`tsk.fls`·`vol.pstree`·`net.tcpdump_read`가 이렇게 실행기 결과를 바로 돌려주는 도구의 예다 [1].
`run`은 외부 도구의 표준 출력 바이트를 UTF-8 문자열로 풀어 `stdout`에 싣고 내용을 바꾸지 않는다 [2].
출력을 파일로 보내는 `run_with_output_file`은 `stdout` 자리에 파일 경로를 적은 문장만 싣는다 [3].
`read.output`의 설명은 `ez.*` 같은 추출 도구가 레코드를 파일에 쓰고 배너와 경로만 돌려주므로 그 파일을 이 도구로 읽으라고 적는다 [3].
미들웨어는 결과에 해석 필드 `_metadata`와 알림 키를 더하지만 도구가 돌려준 키는 바꾸지 않는다 [4].

**한계.** `tsk.blkcat`·`tsk.mmcat`·`tsk.jcat`의 설명은 데이터 블록·파티션·저널 항목의 원래 내용을 내놓는다고 적는다 [5].
이 도구들도 `run`을 거치므로 UTF-8로 풀 수 없는 바이트는 대체 문자 U+FFFD로 바뀐다 [2][5].
응답에는 바이트를 바꿨다는 표시가 없다 [2].

### R01.02 구조화 파싱·필드 선택

**구현.** 서버 안에서 출력이나 파일을 파싱해 필드로 나누는 도구가 있다.
`misc.chat_db_export`는 Skype DB에서 정한 열만 골라 메시지마다 `ts_utc`·`author`·`chat`·`partner`·`body` 필드로 만들고 본문의 XML 태그를 지운다 [6].
`misc.device_install_inventory`는 setupapi.dev.log의 장치 경로에서 VID·PID·제조사·제품 이름과 장치 종류를 뽑아 필드로 둔다 [7].
`net.pcap_identity_timeline`은 tcpdump ASCII 출력에서 패킷마다 시각·출발지·목적지와 URL 인자·쿠키·전자우편 주소 같은 신원 값을 뽑아 행으로 만든다 [8].
`ewf.verify`는 ewfverify 출력에서 저장된 해시와 계산한 해시, 섹터 오류 범위를 뽑아 `stored_md5`·`computed_md5`·`sector_errors` 필드를 `stdout` 옆에 더한다 [9].
`misc.evtx_filter`는 evtx_dump.py 출력을 이벤트 단위로 나눠 이벤트 XML의 목록으로 돌려준다 [10].
이 도구가 이벤트를 고르는 기준인 이벤트 ID는 모델이 인자로 준 값이다 [10].

### R01.03 형식 변환·집계

**구현.** 여러 레코드를 묶거나 값을 계산해 응답하는 도구가 있다.
`net.tcpdump_extract_ips`는 tcpdump 출력에서 IP 주소 모양의 문자열을 모아 중복을 뺀 목록 `unique_ips`와 그 수 `count`를 돌려준다 [11].
`misc.device_install_inventory`는 같은 장치로 본 기록을 하나로 묶고 가장 이른 시각과 늦은 시각을 `first_seen`·`last_seen`에 둔다 [12].
`misc.chat_db_export`는 DB 행을 CSV 파일로 바꿔 쓰고 응답에는 메시지·파일 전송·참여자 수와 시각 범위를 적은 `summary`를 싣는다 [13].
`read.output`은 질의어가 든 행을 서로 다른 질의어를 많이 담은 순서로 다시 늘어놓아 돌려준다 [14].
도구 설명도 행을 이 기준으로 순위를 매긴다고 적는다 [14].
`af.timestomp_drift`는 MFTECmd CSV에서 $SI와 $FN 수정 시각의 차이를 초로 계산하고 `af.usn_gaps`는 이웃한 USN 번호 사이의 간격을 계산한다 [15].
`attribution.attribute_actors`는 발견사항의 ATT&CK 기법과 그룹의 기법이 겹치는 정도로 그룹마다 점수를 매긴다 [16].

**한계.** `net.tcpdump_extract_ips`의 설명은 PCAP의 모든 고유 IP 주소를 돌려준다고 적는다 [11].
코드는 실행기 `run`이 문자 상한과 줄 상한(기본 150줄)으로 자른 `stdout`에서 주소를 모으고 실행기가 적은 `truncated`를 응답에 옮기지 않는다 [11][2].
그래서 출력이 상한을 넘는 PCAP에서는 앞쪽 패킷의 주소만 세고 잘렸다는 표시도 없다 [11].
`af.prefetch_deletion`의 설명은 PECmd 출력을 AppCompatCache·Amcache 출력과 대조한다고 적는다 [17].
코드는 그 도구들이 쓴 CSV가 아니라 호출 기록에 남은 표준 출력 앞 600자에서 `.exe`로 끝나는 이름을 뽑아 대조한다 [17][18].

### R01.04 모델 요약

**구현.** `reason.*` 도구는 서버 안에서 Anthropic API나 OpenAI 호환 API로 모델을 불러 그 답을 응답으로 돌려준다 [19].
모델에게 보내는 글에는 호출자가 `input_call_ids`로 인용한 호출의 출력이 들어간다 [20].
서버는 인용한 호출마다 명령과 표준 출력 발췌를 넣거나, 출력 파일이 있으면 질의어가 든 행을 그 파일에서 읽어 넣는다 [20].
`reason.*` 도구는 모델 답에서 정해진 블록을 떼어 낸 나머지 문장을 `conclusion`에 싣는다 [21].
`reason.advise`는 여기에 더해 모델 답의 `advice`를 싣는다 [22].

### R01.05 가공 사실·대상 표시

**구현.** 미들웨어는 서버가 더하는 해석 문구를 결과의 `_metadata` 아래에 따로 두고 도구가 돌려준 키와 섞지 않는다 [4].
코드 주석은 인용하는 도구 결과를 증거로 깨끗이 남기려고 해석 필드를 떼어 놓았다고 적는다 [4].
`reason.*`의 응답은 모델 답을 어느 경로로 파싱했는지 `parse_path`에 적는다 [21].
증거를 모델에게 보내는 방식이 pull이면 보낸 행 수와 그 행이 나온 호출 ID를 `evidence_pushed`에 싣는다 [23].
`ez.pecmd`는 PECmd를 실행하지 못해 libscca로 대신 파싱하면 `parser`·`parser_note`·`pecmd_unavailable`·`pecmd_reason`으로 대체 사실을 알린다 [24].
`net.pcap_identity_timeline`은 신원 행을 뽑은 tcpdump 호출의 ID를 `raw_call_id`에, PCAP 경로를 `pcap`에 싣는다 [25].
`af.event_log_clear`는 찾은 이벤트마다 읽은 호출의 ID를 `source_call_id`로 붙인다 [26].
`misc.chat_db_export`·`misc.device_install_inventory`의 응답에는 파싱한 원래 파일의 경로가 없고 `_trudi_call_id`가 가리키는 호출 기록의 `cmd`에만 그 경로가 있다 [27].

**한계.** `af.event_log_clear`의 `events_examined`는 읽은 이벤트 수가 아니라 EvtxECmd 호출 기록마다 남은 표준 출력 발췌의 줄 수를 더한 값이다 [26].
`ez.evtxecmd`는 EvtxECmd에 `--csv` 폴더와 `--csvf` 파일 이름을 넘긴다 [28].
`af.event_log_clear`는 그 CSV 파일을 열지 않는다 [26].
이 도구가 읽는 것은 호출 기록의 앞 600자 발췌뿐이다 [18][26].
그래서 응답은 읽은 대상과 그 양을 실제와 다르게 알린다 [26].

```python
def _classify_ewfverify(result: dict, stdout: str, stderr: str) -> None:
    """ewfverify exits 1 both when it cannot run AND when a completed
    verification found a mismatch. The latter is a successful run with a
    negative result — keep it citable. Only a verdict line counts as completed."""
    verdict = re.search(r"ewfverify:\s*(SUCCESS|FAILURE)", stdout)
    hashes = {(m.group(1).lower(), m.group(2)): m.group(3).lower()
              for m in _EWF_HASH_RE.finditer(stdout)}
    result["stored_md5"] = hashes.get(("md5", "stored in file"))
    result["computed_md5"] = hashes.get(("md5", "calculated over data"))
    sha1_stored = hashes.get(("sha1", "stored in file"))
    if sha1_stored is None:
        m = re.search(r"Additional hash values:.*?^SHA1:\s*([0-9a-fA-F]{40})",
                      stdout, re.S | re.M)
        sha1_stored = m.group(1).lower() if m else None
    result["stored_sha1"] = sha1_stored
    result["computed_sha1"] = hashes.get(("sha1", "calculated over data"))
    result["sector_errors"] = [
        {"start": int(m.group(1)), "end": int(m.group(2)),
         "count": int(m.group(3)), "segment": (m.group(4) or "").strip()}
        for m in _EWF_SECTOR_RE.finditer(stdout)]
```

[11] 실행기 결과의 `stdout`에서 주소를 모으고 `truncated`는 옮기지 않는다.

```python
@mcp.tool()
@output_safe
def tcpdump_extract_ips(pcap_file: str) -> dict:
    """
    Extract all unique IP addresses from a PCAP.
    Returns sorted unique source and destination addresses.
    """
    import re
    result = run(["tcpdump", "-r", pcap_file, "-nn", "-q"], needs_sudo=True, timeout=120)
    if not result["success"]:
        return {
            "success": False,
            "pcap": pcap_file,
            "error": result.get("stderr", ""),
            "_trudi_call_id": result.get("_trudi_call_id"),
        }
    ips = set(re.findall(r'\b(?:\d{1,3}\.){3}\d{1,3}\b', result.get("stdout", "")))
    return {
        "success": True,
        "pcap": pcap_file,
        "unique_ips": sorted(ips),
        "count": len(ips),
        "_trudi_call_id": result.get("_trudi_call_id"),
```
