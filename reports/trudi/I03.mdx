# I03 외부 전송 범위 구성

### I03.01 해시 전송

**구현.** 이 방식은 `enrich.vt_lookup_hash`와 `enrich.machinae_lookup`에 있다 [1][2].
`enrich.vt_lookup_hash`는 인자 `file_hash`를 VirusTotal 파일 조회 주소의 경로에 넣어 보내고 파일 내용은 올리지 않는다 [1].
`enrich.machinae_lookup`은 인자 `indicator`를 machinae에 넘긴다 [2].
machinae 1.4.11은 32·40·64·128자리 16진수 값을 해시로 보고 설정에서 해시를 받는 사이트에 그 값을 보낸다 [3].
SIFT가 깔아 두는 machinae 설정에서 해시를 받는 기본 사이트는 5곳이다 [4].
VirusTotal 조회는 API 키가 있을 때만 나가고 그 조건은 I01에서 본다.

**예외.** `enrich.vt_lookup_hash`는 `file_hash`가 해시 형식인지 검사하지 않고 받은 문자열을 그대로 주소에 넣는다 [1].
그래서 해시가 아닌 문자열도 VirusTotal로 나간다 [1].
`enrich.machinae_lookup`도 `indicator`를 검사하지 않는다 [2].
machinae는 해시 형식이 아닌 값을 IP 주소·URL·도메인 같은 다른 종류로 보고 그 종류를 받는 사이트에 보낸다 [3].

### I03.02 메타데이터·추출 값 전송

**구현.** 이 방식은 IOC 조회 도구, `dair.assess`의 모델 요청, SSH와 Velociraptor 접속에 있다 [5][6][7][8].
`enrich.vt_lookup_ip`·`enrich.vt_lookup_domain`은 IP 주소와 도메인을 VirusTotal 주소의 경로에 넣고 `enrich.abuseipdb_check`는 IP 주소와 조회 기간을 질의 값으로 보낸다 [5].
`enrich.machinae_lookup`은 IP 주소·도메인·URL 같은 지표를 machinae에 넘기고 machinae가 그 종류를 받는 기본 사이트에 보낸다 [2][3].
`indicator_type`을 주면 서버는 `-t <종류>`를 덧붙이지만 machinae 1.4.11에는 `-t` 옵션이 없다 [2][9].
machinae는 첫 지표 뒤의 인자를 모두 조회 대상으로 받으므로 `-t`와 종류 이름도 도메인으로 보고 도메인 조회 사이트에 보낸다 [9][10].

`dair.assess`는 모델이 쓴 결과 요약과 사건 맥락을 그대로 모델 백엔드에 보낸다 [6].
분석 단계가 Analyze 이후이면 기록된 IOC에서 고른 ATT&CK 항목마다 IOC 값을 3개까지 붙인다 [11].

SSH 접속은 원격 명령과 그 피연산자를 보낸다 [7].
`live.*` 도구의 피연산자는 모델이 준 PID·경로·서비스 이름이다 [7].
`respond.*`의 대응 조치는 사건 증거에서 꺼낸 PID·IP 주소·경로 같은 값을 정규식으로 형식만 검사한 뒤 명령에 넣는다 [12].
Velociraptor에는 VQL과 클라이언트 ID, 아티팩트 이름, 매개변수를 보낸다 [13].
`velo.query`는 모델이 쓴 VQL을 그대로 보낸다 [8].
`monitor.start_watcher`는 기준선의 프로세스 이름·실행 파일 경로를 탐지 아티팩트 정의에 넣어 Velociraptor 서버에 올린다 [14].

어느 연결도 보내기 전에 내부 주소나 사용자 이름을 빼거나 가리지 않는다.

**예외.** `enrich.vt_lookup_ip`·`enrich.vt_lookup_domain`·`enrich.abuseipdb_check`·`enrich.machinae_lookup`은 인자의 형식을 검사하지 않는다 [2][5].
그래서 IP 주소나 도메인이 아닌 문자열도 그대로 VirusTotal·AbuseIPDB·machinae 조회 사이트로 나간다 [2][5].

### I03.03 증거 내용·파일 전송

**구현.** 이 방식은 모델 백엔드로 가는 검토 요청에 있다 [15].
`reason.*` 검토 도구는 모델이 인자로 쓴 발견사항과 근거 글을 그대로 프롬프트에 넣는다 [16].
`reason.plan`·`reason.audit_findings`를 뺀 검토 도구는 모델이 `input_call_ids`로 인용한 호출의 출력을 서버가 읽어 프롬프트에 덧붙인다 [15][17].
기본 방식 `pull`에서 서버는 인용한 호출을 12개까지 고르고 호출마다 그 도구의 출력 파일이나 전체 표준 출력 사이드카에서 주장의 낱말에 맞는 행을 6행까지 붙인다 [18][19].
첫 요청에 붙이는 행은 모두 3500자까지다 [18].
600바이트 이하인 출력은 통째로 붙이고 출력 파일이 없는 호출은 명령줄과 기록에 남은 표준 출력 발췌를 붙인다 [19][20].
검토 모델이 답에 `EVIDENCE_REQUEST`로 호출 ID와 검색어를 적으면 서버는 인용한 호출의 출력에서 행을 찾아 붙이고 다시 묻는다 [21].
한 회차에 요청 4개와 12000자까지이고 3회차까지 한다 [18].
`reason.evaluate_finding`과 `misc.submit_finding`은 인용한 출력을 호출마다 64MB까지 읽어 고른 구간을 32000자까지 담은 evidence packet을 JSON으로 붙인다 [15][22].
이 내용은 백엔드를 고르기 전에 붙이므로 Claude 백엔드와 OpenAI 호환 백엔드가 같은 내용을 받는다 [15].
한도와 방식은 `TRUDI_REASON_*` 환경변수로 바꾸고 `.env` 견본은 인용한 출력을 붙이는 설정이 모든 백엔드에서 기본으로 켜져 있다고 적는다 [18][23].

보낼 행을 고르는 방식은 I03.04에서 본다.
OpenAI 호환 백엔드의 주소를 로컬 서버로 두면 이 내용은 그 서버로만 간다.

### I03.04 보낼 부분 선택 후 전송

**구현.** 이 방식은 검토 도구가 인용한 호출의 출력을 모델 백엔드 요청에 붙이는 단계에 있다 [15][19].
서버는 출력을 통째로 보내지 않고 주장의 낱말에 맞는 행을 골라 호출마다 6행, 첫 요청 전체 3500자까지만 붙인다 [18][19].
검토 모델이 `EVIDENCE_REQUEST`로 더 요청하면 인용한 호출 안에서 검색어에 맞는 행만 회차마다 12000자까지 더 보낸다 [18][21].
`reason.evaluate_finding`과 `misc.submit_finding`의 evidence packet은 주장의 식별자와 낱말이 많이 맞는 행을 고르거나 모델이 준 바이트 범위를 담아 32000자까지 보낸다 [22][24].
600바이트 이하인 출력은 고르지 않고 통째로 붙이고 출력 파일이 없는 호출은 기록에 남은 표준 출력 발췌를 붙인다 [19][20].
모델이 인자로 쓴 발견사항과 근거 글은 고르지 않고 그대로 보낸다 [16].
고른 행 안의 내부 주소나 사용자 이름은 빼거나 가리지 않으므로 I03.05에는 연결하지 않았다 [19].

```python
def _ioc_coverage_block(current_phase: str, limit: int = 20) -> str:
    """Open ATT&CK coverage items for the recorded IOCs, as Scan leads. Only
    from Analyze on: before then the IOC set is still forming. Advisory — the
    items are warnings, never a transition gate."""
    if current_phase not in ("Analyze", "Scan", "Report"):
        return ""
    try:
        from core.execution_log import log
        from core.iocs import coverage
        cov = coverage(getattr(log, "_entries", None) or [])
    except Exception:
        return ""
    if not cov["open"] and not any(i["status"] == "advisory" for i in cov["items"]):
        return ""
    lines = ["\nIOC COVERAGE LEADS (ATT&CK detection strategies for the recorded IOCs; "
             "each open item is a data source that could confirm or scope the technique "
             "and has not been examined — prescribe the listed tools in Scan, or settle "
             "with misc.record_disposition(target_kind=\"coverage\", "
             "target_id=\"<technique>:<component>\")):"]
    for it in cov["open"][:limit]:
        lines.append(f"- {it['technique']} {it['technique_name']} / {it['component']} "
                     f"[{', '.join(it['iocs'][:3])}] — {it.get('artifacts', '')}; "
                     f"tools: {', '.join(it.get('examine_with', [])[:5])}")
```

```python
def build_argv(action_template: str, raw_params: dict) -> list[str]:
    """Validate every required evidence value, then build the structured remote
    argv. `raw_params` may carry extra keys (the whole evidence dict) — only the
    keys the template needs are read and validated.

    Raises ParamValidationError on an unknown template or any failed validation.
    """
    spec = ACTION_BUILDERS.get(action_template)
    if spec is None:
        raise ParamValidationError(f"unknown action_template {action_template!r}")
    validated: dict[str, str] = {}
    for key, validator in spec["params"].items():
        if key not in (raw_params or {}) or raw_params[key] is None:
            raise ParamValidationError(
                f"action {action_template!r} requires evidence key {key!r}")
        validated[key] = validator(raw_params[key])
    return spec["argv"](validated)
```
