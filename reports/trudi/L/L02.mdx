# L02 기록 구성

### L02.03 외부 실행 명령 기록

**구현.** 외부 도구 실행기는 실제로 실행한 argv를 공백으로 이어 결과의 `cmd`에 둔다 [1].
`sudo`가 붙은 명령이면 `sudo`까지 들어간다 [1].
실행기는 명령이 끝난 뒤 이 `cmd`로 `tool_call` 항목을 만든다 [2].
항목에는 `cmd`와 함께 호출 ID·끝난 시각·성공 여부·종료 코드가 들어간다 [3].
SSH와 Velociraptor 실행기는 인자마다 셸 따옴표를 쳐서 잇는다 [4].
Velociraptor는 API 설정 파일 경로를 `<redacted>`로 바꾼다 [4].
서버 안 파이썬 함수로 구현한 도구는 명령을 실행하지 않아 이 항목의 적용 범위가 아니고 기본 항목에 `<py>:<도구 이름>`만 적는다 [5].
`tool_call` 항목에는 그 명령을 일으킨 MCP 도구 이름이 `mcp_tool`로 함께 들어간다 [6].
MCP 요청의 인자 값은 항목에 남지 않는다 [7][5].
처리 중 예외가 나면 인자 이름과 자료형만 오류 문구에 들어간다 [7].

**한계.** 외부 도구 실행기의 `cmd`는 argv를 공백으로 이어 공백이 들어간 인자 하나와 인자 여러 개를 기록에서 가를 수 없다 [1].

### L02.04 모델 호출의 입력·응답 기록

**구현.** 서버 안에서 모델을 부르는 `reason.*` 도구는 모델에게 보낸 사용자 메시지 전체와 최대 토큰 수, 시스템 프롬프트 종류를 `inputs`로 만든다 [8].
호출 전에는 모델 이름을 적은 `call_initiated` 항목을 남긴다 [9].
호출이 끝나면 `reason_call` 항목에 도구 이름·성공 여부·모델 답에서 뽑은 결론과 지시·입출력 토큰 수·`inputs`를 넣는다 [10].
호출이 실패하면 오류 문구도 넣는다 [10].
`reason.evaluate_finding`이 성공하면 인용한 출력의 해시와 심사 정책 식별값을 담은 evidence packet과 review receipt를 같은 항목에 덧붙인다 [11].
심사 정책 식별값은 프롬프트·게이트 소스 파일의 해시와 모델 이름, 토큰 상한 같은 검토 설정을 합친 값이다 [12].

`dair.assess`도 서버 안에서 모델을 부르고 호출 전에 모델 이름을 적은 `call_initiated` 항목을 남긴다 [13].
모델에게 보낸 사용자 메시지 전체와 단계 스택, 사건 문맥, 도구 목록 버전, 증거 종류는 `inputs`로 모은다 [14].
성공하면 `dair_call` 항목에 모델 답에서 뽑은 단계 판단과 지시, 입출력 토큰 수, `inputs`, `backend` 정보 `backend_meta`, 답을 해석한 경로 `parse_path`를 넣는다 [15][16].
서버가 모델 판단을 바꾸면 그 내역을 `server_override`에 남긴다 [15][16].
서버가 거른 도구와 검증 과제는 `server_filtered_tools`·`server_filtered_challenges`에 남긴다 [15][16].
형식 복구를 한 번 요청한 뒤에도 답이 형식 검사를 통과하지 못하면 오류와 모델 답 원문 앞 20,000자 `raw_answer`를 `reason_call` 형식 항목으로 남긴다 [17].

**한계.** `reason.*`의 모델 호출 기록에는 시스템 프롬프트 본문이 없고 종류 이름만 있다 [8].
`dair.assess`는 증거 종류로 시스템 프롬프트를 만들고 그 본문은 기록하지 않는다 [14].
두 경로 모두 모델 답 원문은 형식 오류가 났을 때만 남긴다 [18][17].
정책 식별값은 `reason.evaluate_finding`의 성공한 검토에만 붙는다 [11].

### L02.05 결과 상태·실행 시점 기록

**구현.** 외부 도구 실행의 `tool_call` 항목은 끝난 시각 `ts`, 성공 여부 `success`, 종료 코드 `exit_code`, 소요 시간 `elapsed_seconds`를 담는다 [3].
시간 초과이면 `timed_out`도 남긴다 [19].
서버 모델 호출도 완료 항목의 `success`·`ts`와 실패 때의 오류 문구를 남긴다 [10].
미들웨어는 단계 게이트, 반복 호출 검사, DAIR 참여 게이트가 실행 전에 막은 호출을 도구 이름과 이유를 담은 `tool_blocked` 항목으로 남긴다 [20].
클라이언트가 취소한 호출은 도구 이름과 이유를 담은 `call_abandoned` 항목으로 남긴다 [21].
서버 프로세스 안에서 실행되는 도구가 실패 응답에 게이트 ID를 실으면 기본 항목에 그 값을 `gate`로 남긴다 [22].
이는 실행이 끝난 뒤 상태와 시점을 남기는 방식이며 시작·끝 항목 둘이 있어야 하는 것은 아니다.
별도 프로세스로 시작한 작업의 최종 실행 항목은 완료 작업을 처음 조회할 때 남으므로 조회하지 않은 작업에는 그 항목이 없다 [23].

### L02.06 결과 참조·요약값 기록

**구현.** 외부 실행의 `tool_call` 항목은 캡처한 표준 출력의 문자 수 `stdout_chars`와 줄 수 `stdout_lines`를 남긴다 [19].
출력을 별도 파일에 쓰면 `stdout_path`를, 도구가 만든 출력 파일을 받으면 `output_path`를 남긴다 [19][24].
문자 수·줄 수는 캡처한 문자열의 값이며 바이트 수나 출력 파일 전체의 크기는 아니다 [19].
검토 중 추가 조회한 결과도 요청별 행 수·문자 수와 별도 파일 경로를 남긴다 [25].
검토 성공 항목에 덧붙이는 evidence packet에는 검토 때 읽은 보관 출력 바이트의 `output_sha256`이 담긴다 [11][26].
읽기 용량 상한으로 앞부분만 읽을 수 있으므로 이 값이 실행 출력 전체의 해시인지는 읽은 범위와 함께 확인해야 한다 [26].

### L02.07 호출 ID로 항목 연결

**구현.** 이 방식은 서버 모델 검토 중 추가 근거를 조회하는 경로의 기록에 적용된다 [25][27].
추가 조회 항목 `reason_evidence_fetch`는 그 조회를 요청한 검토 항목의 호출 ID를 `reason_call_id`에 남긴다 [25].
그래서 같은 검토 중 남긴 조회 항목을 원래 검토 항목과 연결할 수 있다 [27].
다른 분석 호출을 근거로 가리키는 `input_call_ids`는 별도 호출 사이의 추적이다 [25].

**한계.** 모델 호출의 시작 항목 `call_initiated`와 끝 항목 `reason_call`은 각각 새 `call_id`를 받고 같은 요청을 묶는 ID를 공유하지 않는다 [28][10].
시작 기록을 부르는 곳도 반환된 ID를 끝 기록에 넘기지 않으므로 도구 이름과 시각만으로 어느 시작 기록이 어느 끝 기록과 이어지는지 짐작한다 [29].

def _arg_shapes(args: dict | None) -> str:
    """Argument NAMES and python types — never values — so a validation
    failure is diagnosable from the trace (which field, which type)."""
    try:
        return ", ".join(f"{k}:{type(v).__name__}" for k, v in (args or {}).items()
                         if not str(k).startswith("_"))[:400]
    except Exception:
        return ""
```

def _trace_exception(tool_name: str, exc: Exception, elapsed: float,
                     args: dict | None = None) -> None:
    tb = traceback.format_exc()
    # The exception MESSAGE first (a traceback head tells the auditor nothing
    # about WHICH field failed), then arg names/types, then the traceback tail.
    msg = f"{type(exc).__name__}: {str(exc)[:700]}"
    shapes = _arg_shapes(args)
    head = (f"Unhandled {msg} in {tool_name}"
            + (f" | args: {shapes}" if shapes else "")
            + f"\n--- traceback tail ---\n{tb[-1500:]}")
```

def review_policy():
    # No secrets/endpoints in the receipt. The model and deliberate review
    # settings participate in identity; source hashes cover prompt/gate changes.
    from tools import reasoning as R
    root = Path(__file__).resolve().parents[1]
    policy = {}
    for pattern in ('core/evidence_packets.py', 'core/finding_submission.py',
                    'tools/reasoning.py', 'tools/_llm_parse.py', 'tools/_output_reader.py',
                    'tools/_gates/*.py', 'data/fk/**/*.yaml'):
        for path in root.glob(pattern):
            policy[str(path.relative_to(root))] = hashlib.sha256(path.read_bytes()).hexdigest()
    return digest([VERSION, policy, R._active_backend(), R.REASON_MODEL,
                   R.MAX_TOKENS_EVALUATE, R.COMPAT_EVIDENCE_ROUNDS, R.COMPAT_EVIDENCE_MODE,
                   digest(R.REASON_URL), R.COMPAT_EXTRA_BODY_RAW, R.REASON_FK,
