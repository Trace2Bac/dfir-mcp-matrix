# L02 기록 구성

### L02.03 외부 실행 명령 기록

**구현.** 외부 도구 실행기는 실제로 실행한 argv를 공백으로 이어 결과의 `cmd`에 둔다 [1].
`sudo`가 붙은 명령이면 `sudo`까지 들어간다 [1].
실행기는 명령이 끝난 뒤 이 `cmd`로 `tool_call` 항목을 만든다 [2].
항목에는 `cmd`와 함께 호출 ID·끝난 시각·성공 여부·종료 코드가 들어간다 [3].
SSH와 Velociraptor 실행기는 인자마다 셸 따옴표를 쳐서 잇는다 [4].
Velociraptor는 API 설정 파일 경로를 `<redacted>`로 바꾼다 [4].
서버 안 파이썬 함수로 구현한 도구는 명령을 실행하지 않아 이 항목의 적용 범위가 아니고 기본 항목에 `<py>:<도구 이름>`만 적는다 [5].

**예외.** 외부 도구 실행기의 `cmd`는 argv를 공백으로 이어 공백이 든 인자 하나와 인자 여러 개를 기록에서 가를 수 없다 [1].

### L02.05 모델 호출의 입력·응답 기록

**구현.** 서버 안에서 모델을 부르는 `reason.*` 도구는 모델에게 보낸 사용자 메시지 전체와 최대 토큰 수, 시스템 프롬프트 종류를 `inputs`로 만든다 [6].
호출 전에는 모델 이름을 적은 `call_initiated` 항목을 남긴다 [7].
호출이 끝나면 `reason_call` 항목에 도구 이름·성공 여부·모델 답에서 뽑은 결론과 지시·입출력 토큰 수·`inputs`를 넣는다 [8].
호출이 실패하면 오류 문구도 넣는다 [8].
`reason.evaluate_finding`이 성공하면 인용한 출력의 해시와 심사 정책 식별값을 담은 evidence packet과 review receipt를 같은 항목에 덧붙인다 [9].
심사 정책 식별값은 프롬프트·게이트 소스 파일의 해시와 모델 이름, 토큰 상한 같은 검토 설정을 합친 값이다 [10].

**예외.** 모델 호출 기록에는 시스템 프롬프트 본문이 없고 종류 이름만 있다 [6].
모델 답 원문은 형식 오류가 났을 때만 남긴다 [11].
정책 식별값은 `reason.evaluate_finding`의 성공한 검토에만 붙는다 [9].

### L02.06 결과 상태·실행 시점 기록

**구현.** 외부 도구 실행의 `tool_call` 항목은 끝난 시각 `ts`, 성공 여부 `success`, 종료 코드 `exit_code`, 소요 시간 `elapsed_seconds`를 담는다 [3].
시간 초과이면 `timed_out`도 남긴다 [12].
서버 모델 호출도 완료 항목의 `success`·`ts`와 실패 때의 오류 문구를 남긴다 [8].
이는 실행이 끝난 뒤 상태와 시점을 남기는 방식이며 시작·끝 항목 둘이 있어야 하는 것은 아니다.
별도 프로세스로 시작한 작업의 최종 실행 항목은 완료 작업을 처음 조회할 때 남으므로 조회하지 않은 작업에는 그 항목이 없다(L01.09) [13].

### L02.10 결과 참조·요약값 기록

**구현.** 외부 실행의 `tool_call` 항목은 캡처한 표준 출력의 문자 수 `stdout_chars`와 줄 수 `stdout_lines`를 남긴다 [12].
출력을 별도 파일에 쓰면 `stdout_path`를, 도구가 만든 출력 파일을 받으면 `output_path`를 남긴다 [12][14].
문자 수·줄 수는 캡처한 문자열의 값이며 바이트 수나 출력 파일 전체의 크기는 아니다 [12].
파일 쓰기 실패 때 경로 대신 남는 오류와 파일 용량 상한은 D09·D01에서 본다 [14].
검토 중 추가 조회한 결과도 요청별 행 수·문자 수와 별도 파일 경로를 남긴다 [15].
검토 성공 항목에 덧붙이는 evidence packet에는 검토 때 읽은 보관 출력 바이트의 `output_sha256`이 담긴다 [9][16].
읽기 용량 상한으로 앞부분만 읽을 수 있으므로 이 값이 실행 출력 전체의 해시인지는 읽은 범위와 함께 확인해야 한다 [16].

### L02.08 호출 ID로 항목 연결

**구현.** 이 방식은 서버 모델 검토 중 추가 근거를 조회하는 경로의 기록에 적용된다 [15][17].
추가 조회 항목 `reason_evidence_fetch`는 그 조회를 요청한 검토 항목의 호출 ID를 `reason_call_id`에 남긴다 [15].
그래서 같은 검토 중 남긴 조회 항목을 원래 검토 항목과 연결할 수 있다 [17].
다른 분석 호출을 근거로 가리키는 `input_call_ids`는 별도 호출 사이의 추적이므로 D02에서 본다 [15].

**예외.** 모델 호출의 시작 항목 `call_initiated`와 끝 항목 `reason_call`은 각각 새 `call_id`를 받고 같은 요청을 묶는 ID를 공유하지 않는다 [18][8].
시작 기록을 부르는 곳도 반환된 ID를 끝 기록에 넘기지 않으므로 도구 이름과 시각만으로 짝을 짐작한다 [19].

```python
    def _write_stdout_sidecar(self, cid: int, text: str, entry: dict) -> None:
        """Persist the complete stdout for `cid`. Called from record_tool_call
        between _next_id() and _append_entry() — no lock is held across the
        write and the filename is unique per cid, so the _flush re-entrancy
        hazard does not apply. Never raises: a failed sidecar is recorded on
        the entry (`stdout_sidecar_error`) and the entry is still written."""
        final, partial, err = self._write_sidecar_text(f"{cid}.txt", text)
        if final:
            entry["stdout_path"] = final
            if partial:
                entry["stdout_partial"] = True
        elif err:
            _warn(f"stdout sidecar for call {cid} failed: {err}")
            entry["stdout_sidecar_error"] = err
```

```python
    def record_reason_evidence_fetch(
        self,
        reason_call_id: int,
        requests: list[dict],
        input_call_ids: list[int] | None = None,
        results: list[str] | None = None,
    ) -> int:
        """One entry per EVIDENCE_REQUEST round: what the reviewer asked for and
        what came back (call_id, query, columns, file, rows_returned,
        total_rows, status). This is the grounding record behind a verdict —
        "CHALLENGED after inspecting the 4720 rows" vs "on a 600-char excerpt".

        `results[i]` is the text returned to the reviewer for `requests[i]`.
        It is persisted as a sidecar (`.tool_output/fetch-<cid>-<n>.txt`,
        `result_path` on the request) with a short inline `result_excerpt`,
        so the entry stays small and the dashboard can show the exact rows.
        Fail-open: never breaks a reviewer call."""
        try:
            with self._lock:
                if self._path is None:
                    return 0
                cid = self._next_id()
                entry: dict = {
                    "call_id": cid,
                    "type": "reason_evidence_fetch",
                    "ts": _utcnow(),
                    "reason_call_id": int(reason_call_id or 0),
                    "requests": [
                        {k: r.get(k) for k in ("call_id", "query", "columns", "file",
                                               "rows_returned", "total_rows", "bytes",
                                               "status", "source_kind", "source_complete",
                                               "clipped_rows", "truncation_reason",
                                               "missing_columns", "columns_ignored",
                                               "scan_incomplete") if k in r}
                        for r in (requests or []) if isinstance(r, dict)
                    ],
                }
                texts = list(results or [])
                for i, req in enumerate(entry["requests"]):
                    text = texts[i] if i < len(texts) else ""
```
