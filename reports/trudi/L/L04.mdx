# L04 기록 위변조 방지

### L04.03 일련번호

**구현.** 이 방식은 호출 기록 trace의 모든 항목에 적용된다 [1].
항목의 `call_id`는 캐시 폴더의 `call_id.counter` 하나에서 받는 번호로 늘어나기만 한다 [1].
그래서 번호 차례로 항목의 순서가 바뀐 것을 볼 여지가 있다.
번호만으로는 끝 항목을 지우거나 파일 전체를 새로 만든 것은 드러나지 않는다.

이 밖의 위변조 방지 장치는 없다.
호출 기록은 사건마다 하나인 trace JSON 파일이고 `schema_version`·`case_id`·`entry_count`·`entries`로 이루어진다 [2].
항목에는 앞 항목과 잇는 해시도 서명도 없다 [3].
서버는 기록할 때마다 디스크의 파일을 읽어 메모리 목록과 합친 뒤 파일 전체를 임시 파일에 써서 바꿔 놓으므로 덧붙이기 전용 파일도 아니다 [4].
`entry_count`는 같은 파일 안의 값이라 항목과 함께 고칠 수 있다 [2].
서버도 이미 쓴 항목에 필드를 더하고 고친 발견사항의 앞 항목에 `superseded_by`를 단다 [5].

실행 중인 서버는 자기 메모리 사본으로 파일을 다시 쓴다.
`_flush`는 파일이 사라졌으면 메모리 목록으로 파일을 다시 만들고 `trace_file_missing_at_flush` 범주의 `system_error` 항목을 남긴다 [6].
디스크에서 고친 서버 항목은 같은 `call_id`의 메모리 사본으로 덮인다 [7].
새 `call_id`로 끼워 넣은 항목은 훅 항목으로 보고 그대로 합친다 [7].
발견사항 기록처럼 `transaction()`을 쓰는 쓰기에서는 반대로 같은 `call_id`의 디스크 사본이 메모리 사본을 덮는다 [8].
이 동작은 그 서버 프로세스가 실행 중인 동안만 있고 서버를 다시 시작하면 `configure`가 디스크의 파일을 그대로 읽는다 [9].
지운 파일을 다시 만들 때 디스크에만 있던 훅 항목은 돌아오지 않는다 [6].
이 동작은 실행 중에 trace가 사라진 경우를 복구하는 운영 장치이고 위변조를 막는 장치로 세지 않는다.

저장소의 Claude Code PreToolUse 훅은 trace를 가진 세션의 `Write`·`Edit`·`MultiEdit`·`NotebookEdit`가 사건의 `analysis/`·`exports/`·`reports/`에 쓰는 것을 거부한다 [10].
Bash에서는 이 폴더로 가는 리다이렉트와 `tee`·`cp`·`mv`·`install`·`rsync`를 거부한다 [10].
`rm`은 이 정규식에 없고 `TRUDI_GUARD_DISABLE=1`이면 훅이 꺼진다 [10].
이 훅은 클라이언트 구성이고 서버 프로세스와 MCP 도구의 쓰기는 막지 않는다.

**예외.** `TRUDI_CACHE_DIR`를 정하지 않으면 이 카운터를 기계 전체가 함께 쓴다 [1][11].
실시간 감시 도구는 사건 전체 trace와 조사별 trace를 오가며 같은 카운터를 이어 쓰므로 정상 동작에서도 한 trace 안의 번호가 빈다 [12].
번호가 빈 곳이나 차례를 검사하는 코드는 찾지 못했다.
그래서 빈 번호로 중간 항목의 삭제를 가를 수 없다.
모델이 부를 수 있는 도구로 trace를 지우는 경로도 있다(P05.01).
`misc.clear_case_run`은 받은 사건 폴더의 `analysis/`·`exports/`·`reports/` 안을 숨김 항목까지 모두 지우고 `session.json`도 지운다 [13].
`misc.batch_run`은 모델이 준 argv를 허용 목록 없이 `run`으로 실행한다 [14].
trace는 사건 폴더 안의 보통 파일이고 서버 밖의 훅 프로세스도 같은 파일 전체를 다시 쓴다 [15].

```python
def trudi_cache_dir() -> str:
    """Return the TRUDI shared cache dir: $TRUDI_CACHE_DIR, else ~/.cache/trudi.

    Single resolution point for session.json, call_id.counter, hook.lock,
    hash_cache.json, jobs/ and dashboard.url. The default dir is SHARED with
    any live investigation (the MCP server and the Claude hooks) — the call-id
    counter there is machine-global. Test suites and ad-hoc smoke scripts MUST
    set TRUDI_CACHE_DIR to a temp dir before importing core/tools modules, or
    they consume call ids from (and can reroute the beacon of) a live run.
    Module-level path constants are resolved at import time.
    """
    return os.path.expanduser(os.environ.get("TRUDI_CACHE_DIR") or "~/.cache/trudi")
```
