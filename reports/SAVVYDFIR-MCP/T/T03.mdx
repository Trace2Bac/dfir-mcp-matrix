# T03 실행 조건 확인

### T03.01 선행 결과 대조

**구현.** 이 방식은 분석 lane의 진행 상태를 기록하는 `record_analysis_lane`과 보고서를 쓰는 `generate_report`에 적용된다 [1][2].
lane은 증거 접근, 메모리, 이벤트·인증처럼 서버가 정해 둔 조사 갈래 7개다 [3].
`record_analysis_lane`은 lane을 `COMPLETE`나 `COMPLETE_WITH_GAPS`로 기록하기 전에 앞선 실행 기록을 확인한다 [1].
재시도가 필요하다고 남은 파서 실행이 그 뒤 같은 파서의 성공한 실행으로 해소되지 않았으면 거부한다 [1].
`event_auth` lane은 `summarize_evtx` 실행이나 그 발견사항이 사건 상태에 없으면 거부한다 [4].
`COMPLETE`로 기록할 때는 그 lane이 맡은 도구 출력 가운데 추출만 하고 발견사항으로 이어지지 않은 것(analysis debt)이 있으면 거부한다 [5].
EVTX 증거가 없는 빈 사건에서 `event_auth`를 `COMPLETE`로 기록하자 거부되었다 [6].

`generate_report`는 보고서 파일을 쓰기 전에 다음 조건을 차례로 본다 [2].
- 처리하지 않은 하위 에이전트 위임 파일이 있으면 `needs_delegate`로 거부한다 [2].
- 사건의 그래프 파일 `graph.html`이나 `graph.json`이 없으면 `needs_graph`로 거부한다 [7].
- 서버 안에서 `sigma_scan`과 `coverage_report`를 실행하고 둘 가운데 하나가 오류이면 멈춘다 [7].
- lane별 담당 에이전트가 발견사항을 낸 기록이 없으면 `needs_specialist_contribution`으로 거부한다 [8].
- `CONFIRMED` 발견사항이 있거나 발견사항이 25개 이상이거나 서버 안 `sigma_scan`이 성공했는데 기록된 가설이 없으면 `needs_hypothesis`로 거부한다 [9].
- 필수 도구 실행 결과와 analysis debt를 보는 적용 범위 검사를 통과하지 못하면 `needs_coverage`로 거부한다 [10].
- `CONFIRMED` 발견사항에 재추출 표시가 있거나 대안 가설 처분이 비어 있으면 거부한다 [10].
그래프 파일이 없는 사건에서 `generate_report`를 부르자 `needs_graph`가 돌아왔다 [6].

그 밖의 도구에는 앞선 결과로 호출을 막는 검사가 없다.
`start_investigation`의 응답은 `environment_preflight`를 마치기 전에 수집을 시작하지 말라는 `do_not_start_artifact_collection_until`과 보고서 필수 도구 목록을 담지만 다른 도구는 이 값을 보지 않는다 [11].
`environment_preflight`의 결과도 사건 상태에 저장되지 않고 다른 도구가 읽지 않는다 [12].
발견사항을 기록하는 도구는 사건 상태를 불러오지 않았으면 `CaseStateError`로 끝나지만 디스크·메모리 도구는 외부 도구를 실행한 뒤 발견사항을 쓰는 단계에서 이 오류를 낸다 [13][14].

저장소의 Claude Code 훅 `workflow-enforce-pre.py`에도 순서 검사가 있다 [15].
이 훅은 `generate_report` 전에 사건 상태의 실행 기록에서 필수 도구 15개가 성공했거나 부재로 기록되었는지 보고 아니면 거부한다 [15].
같은 훅에는 `sigma_hunt`·`hayabusa_hunt`·`compare_disk_and_memory` 전에 디스크 도구 8개를 요구하는 검사도 있다 [15].
그러나 `.claude/settings.json`의 PreToolUse matcher는 `generate_report`와 `record_analysis_lane`만 맞추므로 탐지 도구 앞의 검사 `_check_phase3_entry_gate`는 실행되지 않는다 [15][16].
`record_analysis_lane`에 대한 훅 검사는 판단을 기록만 하고 거부하지 않는다 [15].
이 훅은 클라이언트 쪽 설정이라 다른 MCP 클라이언트로 붙으면 적용되지 않는다.

**한계.** `generate_report`의 인자 `allow_partial`이 참이면 위임 파일, 그래프 파일, 담당 에이전트 기여, 적용 범위, 재추출·대안 가설 검사를 거부 없이 건너뛴다 [2][7][8][10].
이 인자는 모델이 호출에 넣는 값이다 [17].
발견사항과 실행 기록이 없는 빈 사건에서 `allow_partial`을 참으로 주자 보고서 파일이 쓰였다 [6].
가설 검사는 `allow_partial`과 관계없이 실행되지만 환경변수 `SAVVYDFIR_SKIP_HYPOTHESIS_GATE=1`로 끈다 [18].
`record_analysis_lane`은 analysis debt를 계산하다 예외가 나면 debt가 없는 것으로 보고 통과시킨다 [5].
`COMPLETE_WITH_GAPS`로 기록하면 analysis debt 검사를 하지 않는다 [5].

### T03.10 동시 실행 수 제한

**구현.** 이 방식은 `run_analysis`의 질의 평가 프로세스에 적용된다 [19].
`run_analysis`는 분석 작업 프로세스를 모듈 전역 잠금 `_ANALYSIS_LOCK` 안에서 실행해 한 번에 하나만 실행한다 [19].
잠금을 얻지 못한 호출은 거부되지 않고 기다리며 기다리는 시간에 상한은 없다 [19].
코드 주석은 이 제한의 목적을 작업 프로세스의 메모리 상한 계산을 지키는 것으로 적는다 [19].
같은 프로세스의 두 스레드에서 `run_analysis`를 동시에 부르자 두 번째 호출은 첫 호출이 끝난 뒤에 끝났다 [20].

FastMCP 4.0.9는 동기 도구 함수를 스레드 풀에서 실행하므로 다른 도구 호출은 동시에 실행될 수 있다 [21].
외부 도구를 실행하는 다른 도구에는 동시 실행 수를 세는 장치가 없다 [22].
서버 메모리를 읽는 `_memory_watchdog`는 도구가 끝난 뒤 RSS가 4096MB나 6144MB를 넘으면 호출 기록에 경고를 남기고 실행을 막거나 미루지 않는다 [23].
