# T10 도구 명세 구성

### T10.01 처리 함수에서 명세 생성

**구현.** 이 방식은 서버의 MCP 도구 65개, 리소스 1개, 리소스 템플릿 1개에 적용된다 [1][2].
`server.py`는 FastMCP 4.0.9 서버 `savvydfir-mcp`를 만들고 함수마다 `@mcp.tool()`이나 `@mcp.resource(...)`를 붙여 등록한다 [3][2].
FastMCP 4.0.9는 함수 이름을 도구 이름으로, docstring의 설명 부분을 도구 설명으로 쓴다 [4].
docstring의 `Parameters` 절에 적힌 인자 설명은 함수 서명에서 만든 입력 schema의 각 인자 `description`에 넣는다 [4].
`Returns` 절은 도구 설명과 schema에 들어가지 않는다 [4][1].
실행 확인에서 `sigma_hunt`의 도구 설명은 docstring 첫 단락들이었고 `max_entries` 같은 인자의 설명은 입력 schema에 있었다 [1].
`dict`를 돌려주는 도구의 출력 schema는 추가 속성을 허용하는 `object` 하나였다 [1].

서버는 초기화 지침(`instructions`)에 도구 수와 사용 환경을 적은 한 문장을 둔다 [3].
도구 annotation은 없고 실행 확인에서 annotation을 가진 도구는 0개였다 [1].
초기화 응답의 `tools.listChanged`는 참이었다 [1].
이 값은 FastMCP가 모든 서버에 기본으로 선언하는 값이고 서버는 실행 중에 도구를 더하거나 빼지 않는다 [5][2].
환경변수 `SAVVYDFIR_DISABLE_TOOLS`에 적은 도구도 목록에서 빠지지 않고 호출할 때 `disabled` 상태를 돌려준다 [6].
`describe_tool_catalog`는 도구마다 영역, 아티팩트 종류, 결과 종류를 적은 코드 안의 표 `TOOL_CATALOG`를 영역별로 묶어 돌려주는 도구다 [7][8].
이 표에는 도구 설명이나 입력 schema가 없고 실행 확인에서 표의 도구 65개는 등록된 도구 이름과 모두 맞았다 [8][1].
리소스 `file:///attack_routing/techniques`와 템플릿 `file:///attack_routing/technique/{technique_id}`는 `sift_mcp/routing/attack_routing.yaml`을 읽어 ATT&CK 기법 목록과 기법마다 부를 도구 목록 `required_artifacts`를 돌려준다 [2][9].
프롬프트는 없다 [1].

**한계.** 초기화 지침과 `server.py` 모듈 docstring은 도구가 43개라고 적지만 실행 확인에서 도구 목록은 65개였다 [3][1].
모듈 docstring과 `start_investigation`의 다음 도구 목록은 마운트 도구로 `mount_image`를 적는다 [10][11].
`mount_image`에는 `@mcp.tool()`이 없어 도구 목록에 없고 바로 앞의 보조 함수 `_ntfs_mount_argv`에 `@mcp.tool()`이 붙어 있다 [12].
`extract_shellbags` 등 사용자 활동 도구의 설명도 `mount_image` 다음에 쓰라고 적는다 [13].
`_ntfs_mount_argv`는 읽기 전용 NTFS 마운트 명령의 인자 목록을 만들어 돌려줄 뿐 마운트하지 않는다 [12].
실행 확인에서 `_ntfs_mount_argv`를 MCP로 부르면 `/usr/bin/mount -t ntfs-3g -o ro,loop,...` 인자 목록이 결과로 돌아왔다 [1].
`TOOL_CATALOG`도 `_ntfs_mount_argv`를 `mounting` 영역의 도구로 적는다 [8].
`extract_prefetch`의 `max_entries` 설명은 돌려줄 기록 수의 상한이라고 적지만 코드는 이 값으로 읽을 `.pf` 파일 수를 정한다 [14][15].
그래서 기본값 200이면 파일 이름 차례로 앞 200개 `.pf` 파일만 읽고 `records_count`도 그 파일 수 안에서 센다 [14][15].
`sigma_hunt`의 인자 설명은 Sigma 룰 폴더 기본값을 `/opt/sigma/rules/windows`, 매핑 파일 기본값을 `/opt/chainsaw/mappings/sigma-mapping.yml`로 적는다 [16].
코드는 룰 폴더를 `/opt/sigma-rules/rules/windows`부터, 매핑 파일을 저장소의 `rules/chainsaw-sigma-mapping.yml`부터 찾는다 [17].
리소스 템플릿 설명은 `required_artifacts`를 부를 MCP 도구 이름이라고 적지만 값은 `disk.extract_prefetch`, `detection.extract_srum`처럼 영역 접두어가 붙은 `TOOL_CATALOG`의 이름이다 [9][18].
도구 목록에 등록된 이름에는 이 접두어가 없다 [1].

### T10.03 묶음 도구의 연산별 인자를 schema가 구분하지 않음

**구현.** 이 방식은 `run_analysis`에 적용된다 [19].
`run_analysis`의 입력 schema는 파일 경로 `data_path`, pandas 식 문자열 `query`, 출력 형식 `output_format`이고 `query`의 자료형은 `string` 하나다 [19][1].
작업 프로세스는 CSV나 JSON 파일을 `df`로 불러 `query` 식을 계산하고 식 안에서 쓸 수 있는 이름은 `df`, `pd`, `np`와 기본 함수 몇 개다 [20].
식에 쓸 수 있는 연산과 막는 문자열 목록 `BLOCKED_PATTERNS`는 schema에 없고 도구 설명에는 예시 식 세 개만 있다 [19][21].

@mcp.tool()
def describe_tool_catalog(domain: Optional[str] = None) -> dict[str, Any]:
    """Return the authoritative MCP tool-domain catalog for integration planning.

    This is a read-only introspection tool. It exposes the stable catalog used
    by response contracts and finding normalization so future orchestration can
    scope tools by concern without reverse-engineering source files.

    Parameters
    ----------
    domain:
        Optional domain filter such as ``"disk"``, ``"memory"``, or
        ``"timeline"``.

    Returns
    -------
    dict
        status, domain_filter, domain_count, tool_count, catalog.
    """
    try:
        grouped = group_tool_catalog(domain=domain)
    except ValueError as exc:
        return {"status": "error", "error": str(exc), "tool": "describe_tool_catalog"}

    return {
        "status": "ok",
        "tool_name": "state.describe_tool_catalog",
        "domain_filter": domain.lower() if isinstance(domain, str) and domain else None,
        "domain_count": len(grouped),
        "tool_count": sum(len(entries) for entries in grouped.values()),
        "catalog": grouped,
    }
```

# ===========================================================================
# EVIDENCE MOUNTING NAMESPACE (2 tools)
# ===========================================================================


@mcp.tool()
def _ntfs_mount_argv(device: str, offset_sectors: Optional[int], disk_mount: str,
                     *, use_sudo: bool = True) -> list[str]:
    """Pinned read-only ntfs-3g mount argv (dual-path NTFS mount fix).

    offset 0 / None -> ntfs-3g directly on the device; offset != 0 -> mount -t
    ntfs-3g with loop,offset (the proven Step-3 mechanism). Options:
      ro          - the controlling no-write guarantee (zero evidence writes)
      norecover   - do NOT replay/clear $LogFile on the dirty live volume
                    (replaces the deprecated 'force'; ro already prevents writes)
      allow_other - the MCP user's disk tools can read root's mount
      streams_interface=windows - expose ADS (Zone.Identifier)
    """
    common = "norecover,allow_other,streams_interface=windows"
    off = int(offset_sectors or 0)
    if off != 0:
        argv = ["/usr/bin/mount", "-t", "ntfs-3g", "-o",
                f"ro,loop,offset={off * 512},{common}", str(device), str(disk_mount)]
    else:
        argv = ["/usr/bin/ntfs-3g", "-o", f"ro,{common}", str(device), str(disk_mount)]
    if use_sudo and hasattr(os, "geteuid") and os.geteuid() != 0 and Path("/usr/bin/sudo").exists():
        argv = ["/usr/bin/sudo", "-n", *argv]
    return argv
```
