# T02 실행 허용 범위 제한

### T02.01 클라이언트 도구 선택

**구현.** 이 방식은 저장소 루트의 Claude Code 설정 `.claude/settings.json`에 있다 [1].
이 설정은 허용 목록에 `mcp__savvydfir__*`를 두어 서버 도구 전부를 확인 없이 쓰게 하고 막는 서버 도구는 없다 [1].
같은 허용 목록에는 `fls`·`icat`·`mmls`·`yara`·`vol3`·`log2timeline.py`·`MFTECmd`·`EvtxECmd` 같은 분석 도구와 `python3`·`cp`·`mv`·`chmod`·`dotnet`의 `Bash` 실행이 들어 있다 [1].
거부 목록은 `rm`·`dd`·`mkfs`·`shred`·`format`·`fdisk`·`parted`·`wget`·`curl`·`nc`·`netcat`의 `Bash` 실행만 막는다 [1].
그래서 이 설정은 서버가 감싼 분석 도구를 클라이언트 셸로 직접 실행하는 것을 막지 않는다 [1].
`install.sh`는 이 설정을 사용자 전역 설정에 복사하지 않고 저장소 폴더에서 Claude Code를 실행해야 적용된다고 적는다 [2].
서버에는 이 목록이 없어 다른 MCP 클라이언트로 붙거나 다른 폴더에서 Claude Code를 실행하면 이 설정이 적용되지 않는다 [1][2].

### T02.04 고정 명령·템플릿

**구현.** 이 방식은 외부 도구를 실행하는 모든 도구에 적용된다 [3][4].
실행기 하위 클래스와 실행기를 거치지 않는 도구는 실행 파일과 옵션을 인자 목록으로 정해 두고 모델 값을 정한 자리에 넣는다 [3][4].
Volatility 도구는 도구마다 플러그인 이름이 코드에 정해져 있고 모델은 덤프 경로와 일부 도구의 `pid`만 넘긴다 [5].
모델이 고르는 옵션은 `extract_registry_run_keys`의 `sync_batch`처럼 정해 둔 플래그를 붙일지 정하는 값이다 [6].
`sync_batch`가 참이면 RECmd에 `--sync`를 붙여 배치 정의를 네트워크에서 받게 한다 [6].

`SafeRunner.run`은 실행 전에 실행 파일 이름을 거부 목록 `DENIED_COMMANDS`(`rm`·`dd`·`wget`·`curl`·`ssh`·`scp`·`mkfs`·`fdisk`·`shred`)와 대조하고 목록에 있으면 `CommandDeniedError`로 실행하지 않는다 [7].
이 대조는 전체 경로로 준 실행 파일도 이름으로 맞춘다 [7][8].
실행 파일 이름은 실행기 코드가 정하므로 모델 값은 이 목록과 대조되지 않는다 [3].
실행기를 거치지 않는 도구는 이 대조를 거치지 않는다 [4].
`server.py`에도 명령 거부 목록 `BLOCKED_CMDS`가 정의되어 있지만 서버 코드 어디에서도 읽지 않는다 [9].

**한계.** 위치 인자로 들어가는 모델 값은 `-`로 시작하는지 보지 않고 앞에 `--`를 두는 곳도 없다 [3][4].
`list_deleted_files`의 `image_path`, `extract_windows_artifacts`의 `image_path`·`tsk_device_path`, `scan_files`·`scan_memory`의 `rules_path`와 검사 대상, `build_timeline`의 `source_path`, `query_timeline`의 `plaso_path`, `verify_integrity`의 `image_path`가 여기에 포함된다 [3][4].
`list_deleted_files`의 `image_path`에 `-`로 시작하고 `/`가 없는 값을 주자 Sleuth Kit `fls`가 그 값을 이미지 경로가 아니라 옵션으로 읽어 성공으로 끝났다 [10].
다른 도구가 이런 값을 옵션으로 읽는지는 실행해 보지 않아 확인하지 못했다.
`query_timeline`은 모델이 쓴 `filter_expr`를 검사하지 않고 `psort.py --filter`에 넣고 `start`·`end`는 따옴표 처리 없이 `date >= '<값>'` 틀에 넣는다 [11].
그래서 `start`·`end`에 작은따옴표가 들어가면 필터식의 구조가 바뀐다 [11].
같은 도구의 `output_format`도 목록과 대조하지 않고 `psort.py -o`에 넘긴다 [11].
`hayabusa_hunt`의 `min_level`은 값 목록과 대조하지 않고 `-m` 뒤에 넣는다 [12].

### T02.05 연산·플러그인 허용 목록

**구현.** 이 방식은 `extract_windows_artifacts`의 추출 대상 선택과 `sigma_scan`의 탐지기 선택에 적용된다 [13][14].
`extract_windows_artifacts`는 `families`를 서버 코드의 목록 `_RAW_ARTIFACT_FAMILIES`(`evtx`·`registry`·`amcache`·`prefetch`·`mft`·`srum`·`usn`) 7개와 대조한다 [13].
목록에 없는 값이 있거나 빈 목록이면 `ValueError`로 추출하지 않는다 [13].
`sigma_scan`이 실행할 탐지기는 `start_investigation`이 읽은 사건 manifest의 `enabled_detectors`로 정한다 [14][15].
`start_investigation`은 이 manifest를 모델이 넘긴 `manifest_path`의 파일에서 읽는다 [15].
서버는 이 값을 `STABLE_DETECTORS`의 탐지기 10개와 대조하고 목록에 없는 이름이나 빈 목록은 거부한다 [14].
목록을 바꾸는 설정이나 인자는 없다.

### T02.06 질의 구조·연산 검사

**구현.** 이 방식은 모델이 pandas 식을 써서 넘기는 `run_analysis`의 `query`에 적용된다 [16][17].
서버는 질의를 소문자로 바꾼 글자와 공백을 지운 글자에서 차단 문자열 목록 `BLOCKED_PATTERNS`를 찾고 있으면 거부한다 [16].
목록에는 `import `·`exec(`·`eval(`·`__`·`open(`·`os.`·`subprocess`, `pd.read_csv` 같은 pandas 읽기 함수 15개, `.to_csv(` 같은 쓰기 메서드 9개, `getattr(`·`dir(`가 들어 있다 [16].
통과한 질의는 asteval의 `Interpreter`를 `minimal=True`, `builtins_readonly=True`로 만들어 평가한다 [17].
서버는 평가 환경에 `df`, `np`, `pd`와 `len`·`int`·`str` 같은 내장 함수 15개를 넘긴다 [17].
asteval 1.0.10의 `Interpreter`는 이 밖에 자체 내장 이름과 numpy 함수를 평가 환경에 함께 둔다 [18].
`__`·`import `·`.to_csv(`가 들어간 질의는 거부되었다 [19].
평가는 별도 작업 프로세스에서 하고 결과는 500행까지만 돌려준다 [17][20].

**한계.** 검사는 정해 둔 문자열 목록과의 대조이므로 목록에 없는 함수와 메서드는 통과한다 [16].
목록에 없는 pandas 쓰기 메서드에 파일 경로를 준 질의는 거부되지 않았고 그 파일이 생겼다 [19].
목록에 없는 pandas 읽기 함수를 부른 질의는 차단 검사를 통과해 pandas 함수 호출까지 실행되었다 [21].
asteval을 불러오지 못하면 내장 함수를 비운 파이썬 `eval`로 질의를 평가한다 [17].

### T02.08 설정으로 도구 끄기

**구현.** 이 방식은 환경변수 `SAVVYDFIR_DISABLE_TOOLS`에 적용된다 [22].
사용자는 서버를 시작하기 전에 끌 도구 이름을 쉼표로 나눠 적는다 [22].
`extract_shimcache`와 `extract_srum`은 자기 이름이 이 값에 있으면 실행하지 않고 `status: disabled`를 돌려준다 [23].
끈 도구도 도구 목록에는 그대로 나온다 [24].

**한계.** 이 값을 확인하는 도구는 `extract_shimcache`·`extract_srum` 둘뿐이다 [23].
다른 도구 이름을 적어도 그 도구는 실행된다 [24].
`run_analysis`를 함께 적은 서버에서 `extract_shimcache`는 `disabled`를 돌려주었고 `run_analysis`는 질의 결과를 돌려주었다 [24].

[13] `families`는 서버 코드의 목록과 대조한다.

```python
_RAW_ARTIFACT_FAMILIES = {"evtx", "registry", "amcache", "prefetch", "mft", "srum", "usn"}


def _normalize_artifact_families(families: Optional[Any]) -> set[str]:
    """Normalize MCP list/string family input for raw Windows extraction."""
    if families is None:
        return set(_RAW_ARTIFACT_FAMILIES)
    if isinstance(families, str):
        values = [part.strip().lower() for part in families.split(",")]
    else:
        values = [str(part).strip().lower() for part in families]
    normalized = {value for value in values if value}
    if not normalized:
        raise ValueError("families must be omitted/null or a non-empty allow-list.")
    unknown = normalized - _RAW_ARTIFACT_FAMILIES
    if unknown:
```

```python
def normalize_enabled_detectors(value: Any) -> set[str]:
    """Return the enabled detector allow-list using v6 manifest semantics."""
    if value is None:
        return set(STABLE_DETECTORS)
    if not isinstance(value, list):
        raise ValueError("enabled_detectors must be omitted/null or a non-empty list.")
    normalized = {str(item).strip() for item in value if str(item).strip()}
    if not normalized:
        raise ValueError("enabled_detectors=[] is invalid; omit/null to enable all detectors.")
    unknown = normalized - STABLE_DETECTORS
    if unknown:
        raise ValueError(f"Unknown enabled_detectors: {sorted(unknown)}")
    return normalized
```
