# T01 입력 검증

### T01.01 인자 구조·값 검사

**구현.** 이 검사는 발견사항·가설·lane을 기록하는 도구와 일부 조회·분석 도구의 인자에 적용된다 [1][2][3].
`add_finding`·`submit_finding`은 받은 값으로 `Finding` 모델을 만들어 `confidence`가 0~1인지, `execution_id`가 `E-NNN` 꼴인지, `disposition`이 정한 값인지 보고 어긋나면 거부한다 [1].
발견사항 상태는 정한 값 목록과 별칭으로 대조해 목록에 없으면 거부한다 [1].
`confidence` 1.5, 목록에 없는 상태, `E-NNN` 꼴이 아닌 실행 ID를 준 `add_finding`은 거부되었다 [4].
`submit_finding`은 `timestamp_observed`를 ISO-8601 시각으로 읽지 못하면 거부하지 않고 그 값을 버린다 [5].
`record_hypotheses`는 가설마다 `Hypothesis` 모델로 검사하고 어긋난 가설만 빼서 `rejected`에 적은 뒤 `partial` 상태를 돌려준다 [2].
`record_analysis_lane`은 `lane_id`, `status`, 담당 에이전트 이름을 서버 코드의 목록과 대조해 어긋나면 거부한다 [3].

조회와 분석 도구도 일부 인자의 값을 검사한다.
- `get_provenance`는 `finding_id`가 `F-NNN` 꼴이 아니면 거부한다 [6].
- `get_heuristic`은 `artifact`와 `topic`이 정한 목록에 없으면 유효한 값 목록을 붙여 거부한다 [7].
- `describe_tool_catalog`는 `domain`이 정한 목록에 없으면 거부한다 [8].
- `sigma_hunt`·`query_sigma_results`는 `response_format`이 `summary`·`detailed`가 아니거나 `severity`가 다섯 값 밖이면 거부한다 [9][10].
- `query_sigma_results`는 음수 `offset`을 거부하고 `limit`은 1~200 안으로 바꾼다 [10].
- `get_findings`는 `limit`이 1 미만이거나 `offset`이 음수이면 거부하고 `limit`은 200으로 줄인다 [11].
- `list_dlls`는 `pid`가 0 이상의 정수가 아니면 Volatility를 실행하지 않는다 [12].
- `summarize_evtx`는 `event_ids`의 항목을 정수로 바꾸지 못하면 오류로 끝낸다 [13].
- `verify_integrity`는 빈 `image_path`를 거부한다 [14].
자료형이 다른 인자와 정의하지 않은 인자는 FastMCP가 처리기 전에 거부했다 [15].

검사하지 않는 값도 있다.
`summarize_evtx`의 `start_date`·`end_date`, `hayabusa_hunt`의 `min_level`, `detect_injection`의 `pid`, `query_timeline`의 `start`·`end`·`output_format`은 꼴이나 범위를 보지 않고 외부 도구 인자에 넣는다 [16].
결과 수를 정하는 `max_entries`의 범위도 검사하지 않는다 [16].

### T01.02 입력 존재·읽기 가능 검사

**구현.** 이 검사는 Windows 아티팩트 추출 도구, 이벤트 로그 탐지 도구, 경로를 받는 일부 도구에 적용된다 [17][18][19].
디스크 아티팩트 도구는 입력 경로를 정한 뒤 그 경로가 없으면 외부 도구를 실행하지 않고 `extract_windows_artifacts`를 먼저 부르라는 오류를 돌려준다 [17].
사용자 활동 도구는 `image_path`가 `Windows`·`Users` 폴더를 가진 Windows 볼륨 루트가 아니면 거부한다 [18].
`sigma_hunt`·`hayabusa_hunt`는 EVTX 경로가 없으면 거부하고 `hayabusa_hunt`는 룰 폴더가 없어도 거부한다 [19].
`analyze_vss`, `load_memory`, `run_analysis`, `query_sigma_results`, `serve_graph`는 받은 경로가 없으면 거부한다 [19][20].
`detect_triage_layout`도 받은 경로가 없으면 `path_not_found`로 끝낸다 [21].
`start_investigation`은 manifest 파일이 없거나 manifest의 메모리 덤프 파일이 없으면 거부한다 [22].
서버는 읽기 권한을 미리 확인하지 않는다.

입력이 있는지 보지 않는 도구도 있다.
Volatility를 실행하는 메모리 도구, YARA 도구, Plaso 도구, `list_deleted_files`, `verify_integrity`는 경로를 그대로 외부 도구에 넘긴다 [16].
없는 파일을 준 `verify_integrity`는 `ewfverify`를 실행한 뒤 상태 `success`, `verified` 거짓을 돌려주었다 [23].
없는 덤프를 준 `detect_profile`은 존재 검사 없이 Volatility 실행 단계까지 갔다 [23].
`extract_usn_journal`의 `mft_path`도 검사 없이 MFTECmd `-m`에 넘긴다 [16].

**한계.** `extract_windows_artifacts`는 사건 폴더에 이미 추출해 둔 사본을 먼저 찾고 고른 종류가 모두 있으면 이미지 경로가 있는지 보기 전에 그 사본으로 응답한다 [24].
`start_investigation`은 메모리 덤프가 없어 거부하기 전에 사건 상태를 진행 중으로 바꾸고 lane과 탐지기 설정을 쓴다 [22].

### T01.03 실제 경로로 변환해 허용 폴더 대조

**구현.** 이 방식은 `load_memory`의 `dump_path`, `run_analysis`의 `data_path`, `query_sigma_results`의 `output_path`에 적용된다 [25][20].
`validate_path`는 경로를 `os.path.realpath`로 실제 경로로 바꿔 `/evidence/`·`/mnt/`·`/cases/`·`/tmp/` 가운데 하나로 시작하는지 대조하고 아니면 거부한다 [25].
세 도구는 그 뒤 `Path.resolve()`로 바꾼 경로로 파일을 열거나 작업 프로세스에 넘긴다 [20].
`/etc` 아래 파일, `/cases/..`로 상위 폴더를 거치는 경로, `/tmp` 안에서 `/etc` 파일을 가리키는 링크는 `run_analysis`에서 거부되었다 [26].
`query_sigma_results`는 이 대조에 실패해도 경로가 서버 분석 폴더 `_ANALYSIS_DIR` 아래이면 받는다 [10][27].

다른 경로 인자는 허용 폴더와 대조하지 않는다.
디스크·메모리·YARA·Plaso 도구의 입력, `extract_windows_artifacts`의 `image_path`, `start_investigation`의 `manifest_path`, 그래프 도구의 상태·호출 기록 경로가 그 예다 [16][28].
`.mcp.json`은 `EVIDENCE_BASE`·`MOUNT_BASE`·`OUTPUT_BASE`를 서버 환경에 주지만 서버 코드가 읽는 것은 출력 위치를 정하는 `OUTPUT_BASE`뿐이다 [29].
실행기 `SafeRunner.run`의 경로 검사는 허용 폴더와 대조하지 않는다 [30].

**한계.** `query_sigma_results`의 분석 폴더 대조는 실제 경로가 `_ANALYSIS_DIR` 문자열로 시작하는지만 보고 구분자를 붙이지 않는다 [27].
`_ANALYSIS_DIR` 이름 뒤에 글자를 더 붙인 이웃 폴더의 파일을 주자 받아 읽었다 [31].

### T01.04 문자열 경로 검사

**구현.** 이 방식은 `extract_shimcache`·`extract_srum`이 사건 폴더의 추출 사본을 찾는 경로에 적용된다 [32].
두 도구는 `case_id`에서 글자·숫자와 `._-`가 아닌 글자를 `_`로 바꾸고 앞뒤의 `.`·`_`를 지운 값을 사건 폴더 이름으로 쓴다 [32].
값이 비면 `UNKNOWN`을 쓴다 [32].
그래서 경로 구분자나 `..`가 들어간 `case_id`도 `OUTPUT_BASE` 아래의 폴더 이름 하나가 된다 [32].
이 검사는 파일시스템을 보지 않는다.

디스크 아티팩트 도구는 추출 사본 경로에 인자 `case_id` 대신 불러온 사건 상태의 사건 ID를 그대로 잇는다 [33][29].

### T01.05 등록된 ID와 대조

**구현.** 이 방식은 사건 ID를 받는 상태 도구, 발견사항 ID를 받는 도구, `record_analysis_lane`에 적용된다 [34][35][3].
상태 관리자 `load`는 `state.json`의 `case_id`와 요청의 `case_id`가 다르면 거부한다 [34].
`read_state`·`get_finding`·`get_findings`·`compare_disk_and_memory`·`record_analysis_lane`·`coverage_report`·`record_hypotheses`·`prepare_hypothesis_context`·`sigma_scan`·`get_investigation_gates`·`generate_report`가 이 대조를 거친다 [34].
`get_finding`과 `flag_discrepancy`는 발견사항 ID가 사건 상태에 없으면 거부한다 [35].
`record_analysis_lane`은 `execution_ids`·`finding_ids`가 사건 상태에 없으면 빠진 ID를 돌려주며 거부한다 [3].
다른 사건 ID로 부른 `read_state`, 상태에 없는 발견사항 ID, 상태에 없는 실행 ID를 준 lane 기록은 거부되었다 [36].

발견사항의 근거 ID를 받는 다른 도구는 이 대조를 하지 않는다.
`add_finding`·`submit_finding`은 `execution_id`의 꼴만 보고 사건 상태에 있는지는 보지 않는다 [1][37].
상태에 없는 `E-999`를 준 `add_finding`은 그 값을 그대로 발견사항에 저장했다 [4].
`execution_id`를 비우면 서버가 같은 도구의 최근 실행이나 전체 최근 실행 ID를 넣는다 [37].
`add_finding`의 `corroborated_by`, `record_hypotheses`의 관련 발견사항 ID와 문맥 참조 ID도 있는지 보지 않는다 [1][2].
`get_provenance`는 호출 기록 파일이 있으면 없는 발견사항 ID에도 빈 실행 사슬과 `success`를 돌려준다 [6].

**한계.** `load`는 `state.json`이 없으면 받은 `case_id`로 새 사건 상태를 만든다 [34].
그래서 사건 상태 파일이 없는 서버에서는 어느 사건 ID든 첫 호출에서 받아들인다 [34].

### T01.06 고정 입력 경로 사용

**구현.** 이 방식은 사건 상태와 호출 기록으로 계산하는 도구와 지식 문서를 읽는 도구에 적용된다 [38][39][40].
`compare_disk_and_memory`는 경로 인자 없이 사건 상태의 발견사항과 앞선 MFT·Amcache·USN·SRUM 실행 기록에 남은 CSV 경로를 읽는다 [38].
CSV는 실행 기록의 `raw_evidence_refs`에서 가장 최근 것을 고르고 `/tmp/savvydfir_` 아래 경로와 없는 파일은 건너뛴다 [38].
`sigma_scan`·`find_temporal_clusters`·`coverage_report`도 사건 상태의 발견사항만 입력으로 쓴다 [39].
`export_trace`는 서버 분석 폴더의 `audit.jsonl`을 읽는다 [40].
`get_heuristic`·`prepare_hypothesis_context`는 저장소의 정해진 지식 문서만 읽고 모델은 아티팩트 이름과 주제만 고른다 [41].

### T01.07 입력 부재 시 다른 입력으로 대체

**구현.** 이 방식은 Windows 아티팩트 경로를 찾는 디스크 도구, `extract_shimcache`·`extract_srum`, `extract_pca`, `scan_processes`, `analyze_vss`에 적용된다 [42][32][43][44][45].
디스크 도구의 경로 해석 `_ci_resolve`는 경로 조각마다 대소문자를 가리지 않고 같은 이름의 항목을 찾아 쓴다 [42].
`extract_pca`도 `Windows/appcompat/pca`가 없으면 대소문자만 다른 폴더 세 개를 차례로 찾아 쓴다 [43].
대소문자를 가리는 파일시스템에서 소문자 `windows` 폴더만 둔 경로를 `extract_pca`에 주자 그 폴더를 읽었다 [46].
`extract_shimcache`·`extract_srum`은 받은 마운트 경로에 하이브나 `SRUDB.dat`가 없으면 `OUTPUT_BASE` 아래 사건 폴더의 추출 사본을 대신 쓴다 [32].
`scan_processes`는 덤프별 `pslist` CSV가 없으면 덤프를 구별하지 않는 옛 `pslist.csv`를 대조 입력으로 쓴다 [44].

디스크 도구는 입력이 없을 때만이 아니라 모델이 준 경로에 파일이 있어도 서버가 정한 입력을 먼저 쓴다 [47][42].
`summarize_evtx`·`extract_prefetch`·`extract_mft_timeline` 같은 도구는 사건 폴더의 `artifacts/raw` 아래 추출 사본이 있으면 `image_path`보다 그 사본을 쓴다 [47].
Windows 볼륨 루트를 찾을 때도 `/mnt/disk`가 있으면 `image_path`보다 먼저 후보로 둔다 [42].
고른 경로는 호출 기록의 명령과 응답의 경로에 남지만 대체했다는 표시는 없다 [47].

**한계.** `analyze_vss`는 E01 이미지를 받으면 `/proc/mounts`에서 마운트 위치 이름에 `ewf`가 들어간 첫 항목의 장치를 대상으로 쓴다 [45].
주석은 이 이미지의 장치를 찾는다고 적지만 그 장치가 받은 이미지에서 온 것인지 대조하지 않는다 [45].
그래서 다른 이미지를 마운트해 둔 서버에서는 그 이미지의 섀도 복사본 목록을 읽는다 [45].
`scan_processes`가 쓰는 옛 `pslist.csv`도 다른 덤프에서 만든 것일 수 있다 [44].

### T01.08 실제 경로로 변환해 금지 폴더 대조

**구현.** 이 방식은 실행기 `SafeRunner.run`으로 외부 도구를 실행하는 도구와 디스크 도구 6개의 `/tmp` 입력 확인에 적용된다 [48][49].
실행기를 쓰는 도구는 Zimmerman 도구, Sleuth Kit, Volatility 3, Plaso, YARA를 실행하는 도구다 [48].
실행기는 인자를 `os.path.realpath`로 실제 경로로 바꿔 금지 폴더 `/dev/`·`/proc/`·`/sys/`로 시작하면 `PathDeniedError`로 실행하지 않는다 [30].
실제 경로로 바꾸지 못한 인자도 거부한다 [30].
오류 문구는 허용 경로 5개를 적지만 실행기는 그 목록과 대조하지 않는다 [30].
`/proc` 아래 경로는 거부되었고 `/etc` 아래 파일과 상위 폴더 상대 경로는 실행되었다 [50].
`sigma_hunt`·`hayabusa_hunt`·`analyze_vss`·`extract_shimcache`·`extract_srum`·`extract_windows_artifacts`·`load_memory`는 외부 도구를 `subprocess`로 직접 실행해 이 대조를 거치지 않는다 [51].

`extract_prefetch`·`get_amcache`·`extract_mft_timeline`·`extract_usn_journal`·`summarize_evtx`·`extract_registry_run_keys`는 입력 경로를 실제 경로로 바꿔 `_unsafe_runtime_tmp_input`으로 확인하고 해당하면 외부 도구를 실행하지 않고 거부한다 [52][49].
이 확인의 금지 경로는 `/tmp` 자체, `/tmp` 바로 아래 EVTX 파일 3개, `/tmp/registry`·`/tmp/amcache`·`/tmp/Prefetch` 폴더와 그 아래다 [52].

**한계.** 실행기는 `/`가 들어 있거나 `./`·`../`로 시작하는 인자만 대조한다 [30].
옵션 이름에 붙여 한 인자로 넘긴 경로는 실제 경로가 금지 폴더 아래여도 거부되지 않았다 [50].
대조를 통과한 인자는 실제 경로가 아니라 받은 문자열 그대로 실행 파일에 전달된다 [53].

```python
def _unsafe_runtime_tmp_input(path: str) -> bool:
    """Reject broad or ad hoc /tmp artifact sources created by manual recovery."""
    try:
        resolved = str(Path(path).resolve())
    except (OSError, RuntimeError, ValueError):
        resolved = str(path)
    normalized = resolved.rstrip("/")
    tmp_exact = {
        "/tmp",
        "/tmp/Security.evtx",
        "/tmp/System.evtx",
        "/tmp/Microsoft-Windows-Sysmon%4Operational.evtx",
    }
    if normalized in tmp_exact:
        return True
    return any(
        normalized == prefix or normalized.startswith(prefix + "/")
        for prefix in ("/tmp/registry", "/tmp/amcache", "/tmp/Prefetch")
    )
```
