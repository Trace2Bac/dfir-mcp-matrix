# F06 보고 산출물 구성

### F06.02 수행·누락 범위 포함

**구현.** 이 방식은 `generate_report`가 쓰는 `report.html`·`report.json`에 적용된다 [1][2].
보고서의 분석 갈래 표는 갈래마다 상태, 필수 여부, 맡은 하위 에이전트, 실행 ID 목록, 발견사항 ID 목록, 요약을 싣는다 [2].
ATT&CK 표는 발견사항이 다룬 tactic과 다루지 못한 tactic을 나누고 다루지 못한 tactic마다 실행할 도구를 싣는다 [2][3].
`Data Gaps` 절은 하위 에이전트 기록이 없는 갈래, 그래프가 없는 상태, 추출했지만 발견사항이 인용하지 않은 실행 결과를 싣는다 [4].
`Full Finding Index`는 모든 발견사항의 도구 이름과 실행 ID를 싣는다 [5].
보고서에는 서버가 실행한 도구 호출 전체나 실패한 호출을 모은 절이 없다 [2].
`summarize_run`은 호출 기록을 단계별로 묶은 시간표, 필수 도구의 마지막 실행 결과, 보고서 생성 시도, 최근 실패 다섯 건을 markdown으로 만들어 응답으로만 돌려준다 [6].
`export_trace`는 호출 기록 항목 전체를 응답으로만 돌려준다 [7].

### F06.03 발견사항과 근거 링크 포함

**구현.** 이 방식은 `generate_report`의 보고서와 `generate_graph`가 쓰는 `graph.html`·`graph.json`에 적용된다 [5][8][9].
보고서의 `Full Finding Index`는 발견사항마다 ID, 상태, 확신도, 인식 구분, 기법, 도구 이름, 실행 ID, 설명 앞 160자를 싣는다 [5].
CONFIRMED 발견사항 카드는 실행 ID, 인식 구분, 처분, 대안 설명, 배제한 관찰, 근거로 쓴 지식 묶음 ID, `corroborated_by`를 싣는다 [8].
보고서에는 실행 ID에서 그 호출 기록으로 가는 연결이 없다 [5][8].
그래프는 발견사항 노드마다 `provenance`에 실행 ID와 그 실행의 명령, 결과 요약, 종료 코드를 호출 기록에서 찾아 싣는다 [9].
`contradicted_by`·`corroborated_by`·`related_finding_ids`는 발견사항 사이의 선으로 그린다 [9].

**한계.** ACTIVE 발견사항 카드에는 실행 ID가 없고 색인 표에만 있다 [8][5].
그래프는 탐지 규칙 결과 발견사항과 확신도 0.80 미만이면서 CONFIRMED가 아니고 기법도 없는 발견사항을 그리지 않는다 [9].
뺀 수와 기준은 생성기의 `_graph_meta`에 담기지만 이 값은 `graph.json`의 `meta`에 들어가지 않는다 [9][10].
그래프의 증거 노드는 상태 파일의 `manifest`에서 읽는데 서버는 상태 파일에 `manifest`를 남기지 않아 증거 경로 대신 `(evidence disk)` 같은 자리 표시 노드가 생긴다 [9][11].
실행 ID가 서버가 채운 가장 최근 실행이면 그래프는 그 관계없는 실행의 명령을 근거로 보여 준다 [9][10].

### F06.04 검증·한계 포함

**구현.** 이 방식은 `generate_report`의 보고서에 적용된다 [2].
CONFIRMED 발견사항이 없으면 여러 출처로 확정된 발견사항이 없다는 경고 절을 싣는다 [2].
요약 문단은 그 조사에서 계산한 단서를 싣는다 [12].
단서는 `corroborated_by`가 없는 CONFIRMED 발견사항 수, 풀리지 않은 모순 수, 탐지기의 심각·높음 판정 수다 [12].
요약 문단은 킬체인 단계 가운데 발견사항이 없는 단계 수도 싣는다 [12].
`Data Gaps`, `Anti-Forensics Warnings`, `Orchestration Warnings` 절과 상태 표시값은 그 조사의 상태 파일과 탐지기 결과에서 만든다 [2][4].
보고서를 쓰기 전 확정 검사와 범위 검사를 통과하지 못하면 보고서를 쓰지 않는다 [1].

**한계.** 확정 검사가 등급을 낮춘 사유 `confirmed_gate_blocks`는 보고서에 싣지 않는다 [2][8].
`allow_partial=True`로 쓴 보고서도 사건 상태를 `COMPLETE`로 바꾸고 HTML에 부분 보고서라는 표시를 싣지 않는다 [1][13].
검사를 막은 응답은 부분 보고서가 빠진 갈래를 분명히 표시한다고 적지만 실제 보고서에는 그런 표시가 없었다 [1][13].
`allow_partial=True`로 쓴 `report.json`에는 막지 않은 분석 부채가 `analysis_debt.blocking_non_defensible`로 들어가고 HTML은 이 값을 싣지 않는다 [14].
근거 실행을 찾지 못해 검사를 막은 응답은 `allow_partial=True`로 쓰면 그 발견사항을 따로 나눈 절에 싣는다고 적지만 보고서를 그리는 코드에 그 절이 없다 [15].

### F06.05 내보내기

**구현.** 이 방식은 `generate_report`, `generate_graph`, `merge_host_graphs`, `build_reports_index`와 저장소의 사용자 CLI 셋에 적용된다 [1][16][17].
`generate_report`는 서버가 실행된 폴더의 `reports/<case_id>/` 아래에 `report.html`과 `report.json`을 쓰고 두 경로를 돌려준다 [1].
`generate_graph`는 같은 폴더에 `graph.html`과 `graph.json`을 쓰고 `generate_report`는 그래프가 없으면 `allow_partial` 없이는 보고서를 쓰지 않는다 [9][1].
`merge_host_graphs`는 여러 사건의 `graph.json`을 묶은 통합 그래프를, `build_reports_index`는 사건 목록 `index.html`을 쓴다 [16].
PDF와 대화 기록 화면은 사용자가 CLI를 실행해야 생긴다 [17].
`scripts/render_report_pdf.sh`는 headless Chromium으로 `report.html`을 `report.pdf`로 바꾼다 [17].
`scripts/render_session_trace.py`는 Claude Code 세션 JSONL을 `claude-code-log`로 바꿔 `trace.html`을 쓰고 보고서는 그 파일이 있을 때만 연결을 단다 [17][18].
`scripts/summarize_run.py`는 `--out`을 주면 실행 요약을 파일로 쓴다 [17].

**한계.** `generate_report`와 `generate_graph`의 기본 출력 폴더는 서버 프로세스의 작업 폴더 기준 `./reports`이고 `build_reports_index`의 기본 폴더는 저장소 루트의 `reports`다 [1][9][16].
서버를 다른 작업 폴더에서 실행하면 사건 목록이 그 사건의 보고서를 찾지 못한다 [9][16].
이 경로는 코드로만 따라갔다.

### F06.06 미해결 반론·열린 가설 포함

**구현.** 이 방식은 `generate_report`의 보고서에 적용된다 [2].
`Recorded Hunting Hypotheses` 절은 가설마다 ID, 공격 유형, 판정, 연결한 발견사항 ID, 기법을 싣는다 [2][19].
ACTIVE·INVESTIGATING 가설이 남아 있으면 남은 수와 전체 수를 적은 문구를 절 위에 싣는다 [2][19].
`report.json`의 `unresolved_discrepancies`는 `contradicted_by`가 있고 REJECTED가 아닌 발견사항 전체를 싣는다 [1][20].
보고서 화면에는 그 수만 싣는다 [2].
가설 둘 가운데 INVESTIGATING 하나가 남은 시험 사건의 보고서에 `1 of 2`라는 문구가 실렸다 [13].

**한계.** `Open Questions` 절은 상태 파일의 `open_questions`를 싣는데 이 목록을 채우는 MCP 도구가 없어 늘 비어 있다 [2][21].

### F06.07 판단의 확정 상태 표시

**구현.** 이 방식은 `generate_report`의 보고서에 적용된다 [2].
보고서는 확신도 순으로 고른 발견사항을 `Top Confirmed Findings`와 `Active Leads & Recommended Pivots`로 나눠 싣는다 [2][22].
두 번째 절 앞에는 이 항목들이 확정되지 않은 단일 출처 관찰과 단서라는 문구를 싣는다 [2].
발견사항 카드와 `Full Finding Index`는 발견사항마다 상태 태그를 싣고 색인 표 앞에 CONFIRMED와 ACTIVE·OBSERVATION의 뜻을 적는다 [8][5][2].
상태별 수는 `Findings Status Breakdown`과 요약 숫자 칸에 싣는다 [2].
CONFIRMED 상태는 확정 검사를 통과한 발견사항에만 남는다.

**한계.** 보고서는 `corroborated_by`가 비어 있는 CONFIRMED 발견사항도 여러 출처로 확정된 항목 절에 싣는다 [2][12].
요약 문단은 그 수를 단서로 따로 적는다 [12].
