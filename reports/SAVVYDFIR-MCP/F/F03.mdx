# F03 서버 안 모델 입력 구성

### 비적용

**판단.** 이 서버는 처리 중에 모델 API를 부르지 않는다.
`requirements.txt`가 적은 의존성은 `fastmcp`, `pydantic`, `pandas`, `tabulate`, `mitreattack-python`, `asteval`, `pyyaml`과 사용자 CLI가 쓰는 `claude-code-log`뿐이고 모델 API 클라이언트가 없다 [1].
기준 커밋의 `sift_mcp/`와 서버 도구가 실행하는 `scripts/investigation_graph.py`, `scripts/merge_graphs.py`, `scripts/build_index.py`에서 `anthropic`, `openai`, `ctx.sample`, `create_message`, `messages.create`를 찾았고 나오지 않았다 [2].
`LLM`이라는 낱말은 주석과 독스트링에만 있다 [2].
가설 묶음을 만드는 `prepare_hypothesis_context`는 상태 파일의 발견사항과 지식 파일 조각을 모아 응답으로 돌려주고 가설은 클라이언트 모델이 `record_hypotheses`로 넘긴다 [3].
보고서의 요약 문단도 `_render_executive_summary`가 저장된 필드로 조립한다 [4].
그래서 서버가 모델에게 넘길 입력을 구성하는 경로가 없다.
