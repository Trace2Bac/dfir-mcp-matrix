# E01 증거 등록 관리

### 미구현

**판단.** 서버는 디스크 이미지, 메모리 덤프, 마운트된 폴더, 수집물 폴더를 경로 인자로 받아 외부 도구에 넘기지만 증거를 식별하는 목록이나 등록 정보를 따로 남기지 않는다 [1].
증거를 등록하는 MCP 도구는 없다.

등록 목록에 가장 가까운 것은 사용자가 쓰는 매니페스트 JSON이다.
견본 매니페스트는 `disk_images`와 `memory_dumps` 항목마다 `path`·`host`를 적고 디스크 이미지에는 `image_type`을 적는다 [2].
`start_investigation`은 이 두 목록을 읽어 응답에 그대로 싣고 디스크 이미지와 메모리 덤프마다 먼저 부를 도구를 권한다 [3].
메모리 덤프 경로는 파일이 있는지 확인하고 하나라도 없으면 오류를 돌려준다 [4].
사건 상태에 남기는 것은 메모리 덤프가 있는지를 나타내는 `memory_present` 값 하나이고 두 목록과 항목의 경로·호스트는 저장하지 않는다 [4][5].
`start_investigation` 뒤 `state.json`의 최상위 키에 증거 목록이 없고 `memory_present`만 있는 것을 실행으로 확인했다 [6].
`models/case.py`에 디스크 이미지와 메모리 덤프를 나타내는 `DiskImage`·`MemoryDump` 모델이 있지만 `start_investigation`은 이 모델로 매니페스트를 읽지 않는다 [7][3].
매니페스트는 사용자가 쓰고 서버는 읽기만 하므로 서버가 남기는 등록 목록으로 보지 않는다.

증거 경로가 남는 곳은 도구 호출의 기록이다.
도구 응답이 정리될 때 `_collect_raw_evidence_refs`가 응답의 `image_path` 같은 경로를 모아 `role`이 `input`인 참조로 실행 기록의 `raw_evidence_refs`에 붙인다 [8].
이 참조는 그 실행이 받은 경로이고 증거마다 식별자나 크기, 등록 시각을 두지 않는다 [8].
`verify_integrity`는 받은 이미지 경로와 해시 대조 결과를 발견사항 하나로 남긴다 [9].
이 발견사항은 모델이 이 도구를 부른 파일에만 생긴다 [9].
