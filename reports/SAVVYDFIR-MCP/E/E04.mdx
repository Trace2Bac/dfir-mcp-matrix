# E04 분석 입력 준비

### E04.01 작업 사본 생성

**구현.** 이 방식은 `load_memory`에 적용된다 [1].
`load_memory`는 받은 덤프가 ZIP으로 판별되면 `7z x`로 보관 파일 전체를 `output_dir`에 푼다 [1].
푼 폴더에서 메모리 덤프로 고른 파일의 경로를 `raw_dump_path`로 돌려주고 모델은 이 경로를 메모리 도구에 넘긴다 [1][2].
ZIP이 아니면 사본을 만들지 않고 받은 경로를 그대로 돌려준다 [1].

**한계.** 덤프는 이번에 푼 파일이 아니라 `output_dir` 전체에서 확장자로 찾는다 [1].
`output_dir`의 기본값은 호출마다 같은 `/evidence/memory`이므로 앞서 다른 ZIP에서 푼 덤프가 그 폴더에 남아 있으면 그 파일을 고를 수 있다 [3][1].
`7z` 실행 파일 경로는 `/usr/bin/7z`로 고정되어 있다 [1].
`7z`가 없는 실행 환경에서 ZIP 파일을 넘기자 `[Errno 2] No such file or directory: '/usr/bin/7z'` 오류가 돌아와 푸는 단계는 실행하지 못했다 [4].

### E04.02 선택 추출

**구현.** 이 방식은 `extract_windows_artifacts`, `summarize_evtx`, `extract_browser_history`, 하이브를 읽는 레지스트리 도구에 적용된다 [5][6][7][8].
`extract_windows_artifacts`는 `fls -r -p`로 이미지의 파일 목록을 받는다 [5].
경로가 `windows/system32/winevt/logs/` 아래 `.evtx`, `windows/system32/config/`의 하이브, 사용자 폴더의 `ntuser.dat`, `Windows/Prefetch`의 `.pf`, `$MFT`, `SRUDB.dat`, `$J`처럼 정해 둔 형태이면 종류를 정한다 [9].
종류가 정해진 파일만 `icat`으로 메타데이터 주소를 지정해 `OUTPUT_BASE/<case_id>/artifacts/raw/<종류>/`에 꺼낸다 [5].
`families` 인자로 꺼낼 종류를 고를 수 있다 [10].
ext4 이미지에서 `SYSTEM`·`SOFTWARE`·`SYSTEM.LOG1`·`alice_NTUSER.DAT`·`alice_NTUSER.DAT.LOG1`·`Security.evtx`·`.pf` 하나가 꺼내졌고 같은 이미지의 `Documents/notes.txt`는 꺼내지지 않았다 [4].
꺼낸 파일은 디스크 도구가 입력 인자 없이 불릴 때 받은 경로보다 먼저 입력으로 쓰인다 [11].

`summarize_evtx`는 파일 이름으로 기준 채널 4개와 고가치 채널 10개를 정해 두고 기록이 있는 그 채널 파일만 임시 폴더에 복사해 EvtxECmd에 넘긴다 [6].
`extract_browser_history`는 사용자 폴더 아래 Chrome·Edge의 `History`와 Firefox의 `places.sqlite`를 경로로 찾아 DB마다 임시 폴더에 복사한다 [7].
레지스트리 도구는 읽을 하이브를 하나씩 임시 폴더에 복사해 외부 도구에 넘긴다 [8].

**한계.** `extract_windows_artifacts`는 꺼낼 위치의 파일 이름이 같은 파일이 둘 이상이면 처음 것만 꺼낸다 [12].
`summarize_evtx`는 `channel` 인자를 받았거나 고를 채널이 없으면 고르지 않고 원래 폴더 전체를 EvtxECmd에 넘긴다 [6].

### E04.03 전체·부분 마운트

**구현.** 이 방식은 `analyze_vss`에 적용된다 [13].
`analyze_vss`는 `partition_offset_sectors`가 없으면 `mmls` 출력에서 파티션 하나를 골라 그 시작 위치를 바이트로 바꿔 `vshadowinfo`와 `vshadowmount`의 `-o`에 넘긴다 [13][14].
EWF 이미지는 `ewfmount`로 임시 폴더에 원시 장치로 드러내 `vshadowinfo`에만 넘기고 `vshadowmount`에는 원래 이미지 경로를 넘긴다 [15][16][14][17].
`vshadowmount`가 끝나면 서버는 마운트 폴더의 `vss<N>` 아래에 정해 둔 상대 경로가 있는지 보고 해제한다 [18].
`extract_windows_artifacts`와 `list_deleted_files`는 파티션 시작 위치를 모델이 준 `partition_offset_sectors`로만 받고 서버가 고르지 않는다 [5][19].
이미지를 파일시스템으로 마운트하는 `mount_image` 함수는 도구로 등록되어 있지 않다 [20][4].

**한계.** 파티션을 고를 때 파일시스템 종류를 보지 않고 시작 섹터가 0보다 큰 `mmls` 줄 가운데 넷째 칸인 끝 섹터가 가장 큰 줄을 고르므로 미할당 영역의 시작 위치를 넘길 수 있다 [13][21].
두 파티션 뒤에 미할당 영역을 둔 MBR 이미지에서 `vshadowinfo`에 미할당 영역의 시작 위치가 넘어갔다 [22].
EWF 이미지이면 `/proc/mounts`에서 `ewf`가 들어간 마운트 지점이나 `/mnt/ewf`·`/mnt/disk-ewf`의 장치를 먼저 찾아 쓰고 그 장치가 받은 이미지에서 나온 것인지는 대조하지 않는다 [23].
도구 설명은 `vshadowmount`가 드러낸 `vss<N>`을 다시 마운트해 파일을 읽으라고 적지만 서버는 `vss<N>` 아래의 상대 경로를 바로 찾는다 [24][18].
시험용 `vshadowmount`가 마운트 폴더에 `vss1` 파일을 만들게 하자 정해 둔 8개 경로가 모두 `artifacts_missing`에 들어갔다 [17].
`vss<N>`이 볼륨 파일로 드러나는지는 libvshadow 소스로 확인하지 못했다 [24].
`vshadowmount`가 0이 아닌 코드로 끝나면 복사본마다 찾은 파일과 못 찾은 파일 목록이 모두 빈 값으로 남고 사유도 싣지 않는다 [25][18].
libvshadow 도구와 `ewfmount`는 받은 인자를 기록하는 시험용 실행 파일로 바꿔 서버 쪽 처리만 확인했다 [17].

### E04.04 추출·생략 범위 기록

**구현.** 이 방식은 `extract_windows_artifacts`, `summarize_evtx`, `load_memory`에 적용된다 [26][27][1].
`extract_windows_artifacts`의 응답은 종류별로 꺼낸 파일 경로 `extracted`, 꺼낸 파일 수 `total_artifacts_staged`, 파일이 없는 종류 `families_empty`, 실패한 파일 `failures`와 `critical_failures`를 싣는다 [26].
꺼낸 파일이 없는 종류와 중요한 파일의 실패는 `data_gaps`에 사유와 함께 싣는다 [26][28].
앞서 꺼낸 파일을 다시 쓴 종류는 `reused_families`, 새로 꺼낸 종류는 `extracted_families`로 나눈다 [26].
호출 기록 요약에도 꺼낸 파일 수, 파일이 있는 종류 수, 실패 수가 남는다 [26].
ext4 이미지의 응답에서 7개 종류 가운데 `amcache`·`mft`·`srum`·`usn`이 `families_empty`와 `data_gaps`에 실렸다 [4].
`summarize_evtx`는 복사한 채널 이름 `extracted_channels`와 고른 방식 `channel_selection_mode`를 응답에 싣는다 [27].
`load_memory`는 푼 경우 `was_extracted`와 고른 덤프 경로를, 덤프를 찾지 못하면 푼 파일 목록 `extracted_files`를 싣는다 [1].

**한계.** 중요한 파일의 실패를 `data_gaps`에 따로 싣는 것은 25건까지이고 그 뒤는 건수 한 줄로 묶는다 [28].
`load_memory`의 `extracted_files`도 이번에 푼 파일이 아니라 `output_dir` 바로 아래의 목록이다 [1].

### E04.05 부속 자료 탐색

**구현.** 이 방식은 `extract_windows_artifacts`, 하이브 로그 재생 함수 `replay_hive_with_rla`, `extract_browser_history`에 적용된다 [9][29][7].
`extract_windows_artifacts`는 `SYSTEM`·`SOFTWARE`·`SECURITY`·`SAM`·`DEFAULT` 하이브와 `ntuser.dat`의 `.LOG`·`.LOG1`·`.LOG2`, `Amcache.hve`의 `.LOG1`·`.LOG2`를 하이브와 같은 종류로 정해 함께 꺼낸다 [9].
사용자 하이브의 로그 파일은 하이브와 같은 사용자 이름 접두어를 붙여 꺼내 로그가 하이브 옆에 같은 이름으로 놓이게 한다 [30].
`SYSTEM.LOG1`은 `SYSTEM` 옆에, `NTUSER.DAT.LOG1`은 `alice_NTUSER.DAT.LOG1`로 `alice_NTUSER.DAT` 옆에 꺼내졌다 [4].
`replay_hive_with_rla`는 하이브 폴더에서 `<하이브>.LOG1`·`.LOG2`를 대소문자 구별 없이 찾아 하이브 사본과 같은 임시 폴더에 하이브 이름에 맞춰 복사한다 [29].
`extract_browser_history`는 DB 옆의 `-wal`·`-shm`을 DB 사본과 같은 임시 폴더에 복사한다 [7].

**한계.** `replay_hive_with_rla`는 `.LOG` 파일을 찾지 않는다 [29].
`extract_browser_history`는 `-journal` 파일을 복사하지 않는다 [7].

### E04.06 부속 자료 누락·로그 미반영 표시

**구현.** 이 방식은 `extract_shellbags`와 `extract_registry_fileaccess`에 적용된다 [31][32].
두 도구는 `rla` 재생이 0이 아닌 종료 코드로 끝나거나 예외로 끝나면 그 하이브를 `parser_failures`에 `replay_error`와 사유로 싣는다 [31][32].
그 하이브에서 읽은 행에는 `parser_status`로 `replay_error`를 적는다 [31].
`replay_hive_with_rla`는 하이브 폴더를 읽지 못해 로그를 찾지 못한 경우도 재생 실패로 돌려준다 [29].
`extract_shimcache`는 AppCompatCacheParser가 CSV를 만들지 않으면 하이브에 로그가 반영되지 않았을 수 있다는 사유를 부재 기록에 적는다 [33].
`extract_registry_run_keys`는 재생 결과를 응답에 표시하지 않는다 [8].

**한계.** `replay_hive_with_rla`는 하이브 폴더에 `.LOG1`·`.LOG2`가 없어도 `rla`가 0으로 끝나면 재생 성공으로 돌려주므로 두 도구는 로그가 없는 하이브에 표시를 싣지 않는다 [29].

### E04.07 로그 재생·복원

**구현.** 이 방식은 하이브를 읽는 레지스트리 도구와 `extract_browser_history`에 적용된다 [8][31][32][33][7].
레지스트리 도구는 하이브와 로그 사본을 `dotnet /opt/zimmermantools/rla.dll -d <입력> --out <출력>`으로 실행해 로그를 적용한 하이브를 만든다 [29].
`rla`가 만든 파일이 있으면 그 파일을, 없으면 하이브 사본을 외부 파서에 넘긴다 [29].
`extract_registry_run_keys`는 `rla`가 예외로 끝나면 원래 하이브와 `.LOG1`·`.LOG2`를 함께 RECmd 입력 폴더에 복사해 RECmd가 로그를 적용할 수 있게 한다 [8].
`extract_browser_history`는 DB 사본과 `-wal`을 같은 폴더에 두고 SQLite로 열어 WAL에만 있는 행도 읽게 한다 [7].
WAL에만 행 하나가 있는 Chromium 형식 DB에서 본 DB의 행과 WAL의 행이 모두 CSV에 실렸다 [4].

**한계.** `extract_registry_run_keys`와 `extract_shimcache`는 `rla`의 종료 코드를 받지 않는다 [8][33][29].
`rla`가 0이 아닌 코드로 끝나 출력이 없으면 로그를 적용하지 않은 하이브 사본을 넘기고 이때 RECmd 입력 폴더에는 로그가 복사되지 않는다 [8][29].
실행 환경에 레지스트리 로그 재생 도구가 없어 하이브 재생 경로는 실행하지 못했다.

```python
def _normalize_artifact_families(families: Optional[Any]) -> set[str]:
    """Normalize MCP list/string family input for raw Windows extraction."""
    if families is None:
        return set(_RAW_ARTIFACT_FAMILIES)
    if isinstance(families, str):
        values = [part.strip().lower() for part in families.split(",")]
    else:
        values = [str(part).strip().lower() for part in families]
    normalized = {value for value in values if value}
    if not normalized:
        raise ValueError("families must be omitted/null or a non-empty allow-list.")
    unknown = normalized - _RAW_ARTIFACT_FAMILIES
    if unknown:
        raise ValueError(
            f"Unknown artifact families: {sorted(unknown)}. "
            f"Valid families: {sorted(_RAW_ARTIFACT_FAMILIES)}"
        )
    return normalized
```
