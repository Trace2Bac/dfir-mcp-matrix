# E03 원본 변경 방지

### E03.02 서버 코드의 원본 쓰기 제한

**구현.** 이 방식은 서버 코드가 증거 파일을 직접 읽는 도구와 하이브·브라우저 DB·EVTX를 사본으로 처리하는 경로에 적용된다 [1][2][3][4].
`extract_recycle_bin`·`extract_pca`·`extract_scheduled_tasks`는 증거 파일을 `read_bytes`로, `extract_powershell_history`는 `read_text`로 읽는다 [1].
`extract_browser_history`는 DB와 `-wal`·`-shm`을 임시 폴더에 복사하고 그 사본을 SQLite `mode=ro`로 연다 [2].
`replay_hive_with_rla`는 하이브와 `.LOG1`·`.LOG2`를 임시 입력 폴더에 복사하고 `rla`가 정리한 하이브를 임시 출력 폴더에 쓰게 한다 [3].
레지스트리를 읽는 `extract_registry_run_keys`·`extract_shellbags`·`extract_registry_fileaccess`·`extract_shimcache`는 이 사본 폴더를 외부 도구에 넘긴다 [3][5].
`summarize_evtx`는 `channel` 인자가 없으면 고른 EVTX 파일을 임시 폴더에 복사해 EvtxECmd에 넘긴다 [4].
브라우저 DB를 읽은 뒤 증거 폴더의 DB·`-wal`·`-shm` 크기는 그대로였다 [6].

**한계.** `extract_registry_run_keys`는 사본을 준비하다 예외가 나면 원래 하이브 폴더를 RECmd에 넘긴다 [5].
`summarize_evtx`는 `channel`을 받았거나 고를 채널이 없으면 원래 EVTX 폴더를 EvtxECmd에 넘긴다 [4].
이 두 경로에서 외부 도구가 원본을 읽기 모드로 여는지는 확인하지 못했다.

### E03.03 외부 도구·플랫폼에 위임

**구현.** 이 방식은 외부 도구가 이미지나 증거 파일을 직접 읽는 도구에 적용된다 [7][8][9][10].
`extract_windows_artifacts`·`list_deleted_files`는 이미지 경로를 Sleuth Kit `fls`·`icat`에, `verify_integrity`는 `ewfverify`에, 메모리 도구는 Volatility 3에 넘긴다 [7][8][9].
`extract_mft_timeline`·`get_amcache`·`summarize_evtx` 같은 디스크 도구는 받은 경로나 꺼낸 사본의 경로를 EZ Tools에 넘긴다 [10].
`analyze_vss`는 EWF 이미지를 임시 폴더에 `ewfmount`로 드러내 `vshadowinfo`에 넘기고 해제한 뒤 원래 이미지 경로를 `vshadowmount`에 넘긴다 [11][12][13].
이 경로들에는 원본 쓰기를 막는 서버 코드나 실행 환경의 장치가 없다.

외부 프로그램을 실행하는 `SafeRunner.run`은 명령 이름이 거부 목록(`rm`·`dd`·`curl` 등)에 있거나 인자가 `/dev/`·`/proc/`·`/sys/` 아래면 실행하지 않는다 [14].
`SafeRunner`의 주석은 증거 폴더에 쓰지 못하게 한다고 적지만 `WRITE_PROTECTED_PATHS`는 정의만 있고 쓰는 곳이 없다 [14][15].
`extract_windows_artifacts`의 `fls`·`icat`, `analyze_vss`, `load_memory`의 `7z`, `extract_shimcache`의 AppCompatCacheParser, `rla`는 `SafeRunner`를 거치지 않고 `subprocess`로 실행한다 [7][11][16][17][3].
출력은 `OUTPUT_BASE`(기본 `/cases`) 아래 사건 폴더와 임시 폴더에 쓰지만 그 위치가 원본과 겹치는지는 보지 않는다 [18].
읽기 전용 `ntfs-3g` 마운트 명령을 만드는 `_ntfs_mount_argv`는 도구로 등록되어 있지만 명령 목록을 돌려줄 뿐 마운트하지 않는다 [19][20].
그 명령으로 마운트하는 `mount_image`는 도구로 등록되어 있지 않다 [19][20].

**한계.** Sleuth Kit 4.11.1은 원시 이미지를 `O_RDONLY`로, EWF 이미지를 `LIBEWF_OPEN_READ`로 연다 [21].
Volatility 3 2.28.2의 `FileLayer`는 덤프 파일을 `rb`로 연다 [22].
EZ Tools, ewf-tools, libvshadow, 7-Zip이 원본을 읽기 모드로 여는지는 소스로 확인하지 못했다.
`load_memory`는 ZIP을 풀 폴더 `output_dir`를 검사하지 않고 기본값은 증거 경로 `/evidence/memory`다 [16].
그래서 기본값으로 부르면 원본 파일을 고치지는 않지만 증거 폴더 아래에 푼 파일을 만든다 [16].

    """Copy a sqlite DB + its -wal/-shm sidecars into ``dest_dir`` (locks)."""
    dest = dest_dir / db_path.name
    shutil.copy2(str(db_path), str(dest))
    for suffix in ("-wal", "-shm"):
        sidecar = db_path.parent / (db_path.name + suffix)
        if _path_exists(sidecar) and _path_is_file(sidecar):
            try:
                shutil.copy2(str(sidecar), str(dest_dir / sidecar.name))
            except OSError:
                pass
    return dest
