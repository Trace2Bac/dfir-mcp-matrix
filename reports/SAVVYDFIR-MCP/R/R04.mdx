# R04 도구 결과 해석 주의

### R04.01 도구별 정적 주의

**구현.** 이 방식은 응답에 `_forensic_envelope`의 값을 더하는 도구와 도구 설명에 해석 한계를 적은 도구에 적용된다 [1].
`_forensic_envelope`를 부르는 도구는 디스크 추출 도구 14개, `scan_processes`·`scan_network`·`detect_injection`·`list_dlls`, `sigma_hunt`·`hayabusa_hunt`·`query_sigma_results`, `analyze_vss`, `extract_shimcache`, `extract_srum`이다 [1].
`_forensic_envelope`는 도구 이름에 연결한 FK 지식 YAML의 `does_not_prove` 항목을 `; `로 이어 `forensic_caveat`에 싣는다 [2][3].
`forensic_caveat`은 같은 도구를 몇 번째 부르든 붙는다 [2].
(실행 확인) `extract_powershell_history`의 `forensic_caveat`은 기록이 명령 입력만 증명하고 실행이나 사람이 입력했다는 것을 증명하지 않는다고 적었다 [4].
`extract_mft_timeline`에는 YAML 항목 뒤에 볼륨 사이 복사와 이동에서 시각이 이어지는 경우 같은 네 문장을 코드에서 더한다 [5].
사건이 열려 있으면 `_attach_heuristic_slice`가 `.claude/agents/<아티팩트>-analyst.md`의 정해 둔 절을 `applicable_heuristics`로 붙인다 [6].
이 절은 아티팩트별로 늘 같은 해석 원칙을 담는다 [6].
도구 설명에도 해석 한계를 적은 도구가 있다.
`extract_prefetch`의 설명은 `.pf` 파일의 생성·수정 시각이 정확한 실행 시각이 아니라고 적는다 [7].
`extract_powershell_history`의 설명은 기록이 실행이나 사람이 입력했다는 것을 증명하지 않는다고 적는다 [8].
`_forensic_envelope`를 부르지 않는 `list_processes`, `extract_pca`, `sigma_scan`, `scan_files`·`scan_memory`, `list_deleted_files`, `build_timeline`·`query_timeline`, `run_analysis`에는 `forensic_caveat`이 없다 [1][9].

**한계.** `_forensic_envelope`를 부르는 래퍼는 `status`가 `error`인 결과에는 값을 더하지 않는다 [10].

### R04.02 결과 조건별 주의

**구현.** 이 방식은 `sigma_hunt`, 사용자 활동 도구, `_warn_if_empty`를 거치는 추출 도구, `extract_registry_run_keys`, `extract_windows_artifacts`에 적용된다 [11][12][13][14][15][16].
`sigma_hunt`는 hit이 0건이면 Chainsaw가 읽은 문서 수와 규칙 수에 따라 다른 `zero_hit_diagnostic`을 붙인다 [11].
문서와 규칙을 모두 읽었는데 0건이면 0건만으로 깨끗하다고 판단하지 말고 Sigma 양성 대조로 매핑을 확인하라고 적는다 [11].
사용자 활동 도구는 아티팩트를 찾았지만 파싱이 실패해 0행이면 부재가 증명되지 않았다는 문장을 `note`에 싣는다 [12].
일부 출처의 파싱이 실패하면 빠진 출처를 활동이 없다고 보지 말라는 문장을 `note`에 싣는다 [13].
`_warn_if_empty`는 결과가 0건이고 입력 경로가 있으면 마운트와 인자를 확인하라는 `warning`을 붙인다 [14].
`extract_registry_run_keys`는 SYSTEM이나 SOFTWARE 하이브가 없으면 Run 키와 서비스가 결과에서 빠진다는 `critical_hive_warning`을 붙인다 [15].
`extract_windows_artifacts`는 중요한 파일을 꺼내지 못한 원인이 압축 해제 오류로 보이면 `data_gaps`에 이 판단이 표준 오류 문구로 추정한 것이라는 문장을 싣는다 [16].

### R04.03 추가 확인 도구·증거 추천

**구현.** 이 방식은 `_forensic_envelope`를 부르는 도구, `build_contract_response`를 거치는 도구, 일부 탐지·추출 도구, MCP 리소스에 적용된다 [2][4][17][18][19][20][16][21][22].
`_forensic_envelope`는 FK YAML의 `corroborate_with`를 그대로 `corroborate_with`에 싣는다 [2].
(실행 확인) `extract_powershell_history`의 `corroborate_with`는 PowerShell EVTX 4104, Prefetch, 보안 로그 4688, Amcache, `$MFT`를 함께 보라고 적었다 [4].
같은 함수는 FK YAML의 `corroboration_escalation`에서 단독일 때와 함께 볼 때의 판단 문구를 `advisory_corroboration`에 싣는다 [17].
`build_contract_response`를 거치는 도구는 다음에 부를 도구와 인자, 이유를 `follow_up_options`에 싣는다 [18].
예를 들어 `extract_prefetch`는 `get_amcache`, 4688을 고른 `summarize_evtx`, `extract_mft_timeline`을 권한다 [18].
`sigma_hunt`는 시간 제한 때문에 채널 하나만 검사했으면 남은 주요 채널별 호출을 `recommended_next_calls`에 싣는다 [19].
`extract_shimcache`는 ShimCache CSV가 나오지 않으면 Prefetch·Amcache·EVTX 4688·Sysmon 1로 실행을 확인하라는 `alternative`를 싣는다 [20].
`extract_windows_artifacts`는 압축 해제 오류로 보이는 실패에 `next_required_tool` `disk.analyze_vss`를 싣는다 [16].
MCP 리소스 템플릿 `file:///attack_routing/technique/{technique_id}`는 ATT&CK 기법마다 확인할 도구 `required_artifacts`와 함께 볼 흔적 `corroboration_sources`를 돌려준다 [21].
(실행 확인) `T1003.001`을 읽자 `required_artifacts`와 EVTX·메모리·MFT·레지스트리 흔적 목록이 돌아왔다 [21].
서버 지침(`instructions`)에는 추가 확인을 권하는 문구가 없고 서버는 MCP 프롬프트를 등록하지 않는다 [22].

**한계.** `_forensic_envelope`는 도구마다 호출 횟수를 세어 처음 3번에만 `corroborate_with`와 `advisory_*` 값을 싣는다 [2][17].
(실행 확인) `_forensic_envelope("disk.extract_prefetch")`를 다섯 번 부르자 넷째 호출부터 `corroborate_with`와 `advisory_corroboration`이 빠졌다 [2].
`advisory_*` 값은 서버 프로세스 전체에서 6,000자까지만 더하고 그 뒤에는 처음 3번의 호출에도 붙지 않는다 [17].

def get_attack_technique_routing(technique_id: str) -> str:
    """Get routing details for a specific ATT&CK technique.

    Returns JSON with:
    - name: technique name
    - tactics: list of ATT&CK tactic IDs
    - required_artifacts: MCP tool names to invoke
    - corroboration_sources: artifact-specific evidence patterns
    - detection_notes: forensic interpretation guidance

    Example URI: file:///attack_routing/technique/T1003.001
    """
    from sift_mcp.routing import get_technique_routing
    import json

    try:
        routing = get_technique_routing(technique_id)
        if routing is None:
            return json.dumps({"error": f"Technique {technique_id} not found in routing catalog"})

        # Add technique_id to the response for convenience
        result = {"technique_id": technique_id, **routing}
        return json.dumps(result, indent=2)
