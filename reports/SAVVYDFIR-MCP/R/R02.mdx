# R02 대량 결과 전달

### R02.01 문자·항목 상한

**구현.** 이 방식은 결과 목록을 응답에 싣는 도구 대부분에 적용되고 상한은 도구마다 코드에 따로 정해 둔다.
메모리 도구 `scan_network`·`detect_injection`·`list_dlls`는 기본 `summary` 형식에서 결과 목록을 빼고 앞 3개만 `preview`에 싣는다 [1].
`build_contract_response`를 거치는 도구는 `normalized_observations`를 앞 20개 레코드로 만들고 `preview`를 따로 주지 않으면 그 앞 5개를 싣는다 [2].
같은 응답의 `pivot_entities`는 값 종류마다 처음 나온 고유 값 10개까지 싣는다 [2][3].
사용자 활동 도구는 `preview`를 10행과 `max_entries` 가운데 작은 값까지 싣는다 [4].
`summarize_evtx`는 CSV 앞쪽에서 500행까지만 표본으로 남기고 `detailed` 형식의 `data`를 그 표본에서 `max_entries`까지 싣는다 [5].
`run_analysis`는 질의 결과가 500행을 넘으면 앞 500행만 남긴다 [6].
`get_findings`와 `query_sigma_results`는 한 번에 돌려주는 항목 수 `limit`를 200으로 제한한다 [7][8].
`generate_report`의 `summary` 형식은 확인된 발견사항과 활성 단서를 각각 5개까지 싣는다 [9].

상한이 없는 응답도 있다.
`export_trace`는 호출 기록 전체를 `entries`에 싣는다 [10].
`query_timeline`은 psort가 낸 사건을 모두 `events`에 싣는다 [11].
`sigma_hunt`는 기준 등급 이상의 hit을 개수 제한 없이 `actionable_hits`에 싣는다 [12].
`extract_pca`는 의심 경로 항목 전체를 `suspicious_records`에 싣는다 [13].

**한계.** 항목 수 인자 `max_entries`·`max_results`는 모델이 인자로 바꾼다 [5][14].
`sigma_hunt`의 `max_entries`는 발견사항으로 만드는 hit 수만 정하고 응답에 싣는 `actionable_hits`의 수는 정하지 않는다 [12].

### R02.02 전체·반환 건수 표시

**구현.** 이 방식은 EVTX·MFT·레지스트리 추출과 탐지 도구, 조회 도구, `extract_pca`, `list_deleted_files`에 적용된다 [15][8][7][16][13][17][18].
`summarize_evtx`는 CSV 전체 행 수 `total_records`, 채널이 맞는 행 수 `matched_records`, 이번에 싣는 행 수 `records_count`, 잘림 여부 `data_truncated`, 범위 `data_scope`(`head_sample`), 표본 상한 `sample_cap`을 싣는다 [15].
`note`도 "Returning a bounded sample of N inline rows"처럼 두 수를 문장으로 적는다 [15].
`query_sigma_results`는 파일의 hit 수 `total_hits`, 거른 뒤의 수 `filtered_hits_total`, 이번에 싣는 수 `returned_count`를 싣는다 [8].
`get_findings`는 거른 뒤의 발견사항 수 `total_findings`와 `returned_count`를 싣는다 [7].
`extract_registry_run_keys`와 `extract_pca`는 "Returning X of Y" 문장을 `note`에 싣는다 [16][13].
`list_deleted_files`는 전체 항목 수 `records_count`와 이번에 싣는 수 `records_returned`를 싣는다 [17].
`sigma_hunt`는 거른 hit 수 `hits_total`, 거르기 전 수 `raw_hits_total`, 발견사항을 만들려고 고른 hit 수 `hits_returned`를 싣는다 [18].

**한계.** `extract_shimcache`는 CSV를 `max_entries`행까지만 읽고 읽은 행 수를 `entries_total`로 싣는다 [19].
그래서 `entries_total`은 CSV 전체 행 수가 아니고 상한에서 멈췄는지 알리는 필드도 없다 [19].
사용자 활동 도구의 `truncated`는 전체 행 수가 `max_entries`(기본 500)를 넘을 때만 참이다 [4].
`preview`는 10행까지만 싣기 때문에 11행부터 500행까지인 결과는 `preview`가 일부만 담아도 `truncated`가 거짓이다 [4].
`run_analysis`의 `row_count`와 `insights`의 행 수는 500행에서 자른 뒤의 수이고 결과에 잘림 여부나 원래 행 수가 없다 [6].
`hayabusa_hunt`의 `hits_returned`는 응답에 실린 hit 수가 아니라 만든 발견사항 수에서 1을 뺀 값이고 응답에는 hit 항목이 없다 [20].
버전 기준 Hayabusa v4.1.0에는 서버가 넘기는 `csv-timeline` 명령이 없어 `hayabusa_hunt`는 이 필드가 있는 응답 대신 `status`가 `error`인 응답을 돌려준다 [21][22].
Hayabusa의 이 동작은 소스로 확인했고 Hayabusa를 실행하지 않았다.

### R02.03 페이지·커서 조회

**구현.** 이 방식은 `get_findings`, `query_sigma_results`, `list_deleted_files`에 적용된다 [7][8][23].
`get_findings`와 `query_sigma_results`는 `offset`과 `limit`로 거른 목록의 일부를 돌려주고 응답에 두 값을 되돌려 싣는다 [7][8].
`list_deleted_files`는 `detailed` 형식에서 `page_offset`과 `limit`로 정한 범위를 `data`에 싣고 `page_offset`·`page_limit`을 응답에 싣는다 [23].
세 도구 모두 남은 항목이 있는지 알리는 필드는 따로 없고 전체 수와 `offset`으로 남은 수를 계산해야 한다 [7][8][17].

**한계.** `list_deleted_files`의 `summary` 형식은 `page_offset`을 쓰지 않고 앞쪽 `preview`만 싣는다 [23].

### R02.04 파일·리소스로 전체 결과 조회

**구현.** 이 방식은 결과를 CSV·JSON으로 남기는 추출·탐지 도구와 `run_analysis`에 적용된다 [24][25].
추출 도구는 외부 도구가 임시 폴더에 쓴 CSV를 `$OUTPUT_BASE/<사건>/artifacts/<도구>/` 아래로 복사하고 그 경로를 `csv_path`와 `handle.path`에 싣는다 [24][26].
`summary` 형식 응답의 `note`는 `detailed` 형식도 표본이므로 `csv_path`와 `run_analysis()`로 전체를 보라고 적는다 [27].
`sigma_hunt`와 `hayabusa_hunt`는 hit 전체를 담은 JSON·CSV 경로를 `output_path`에 싣고 `sigma_hunt`의 `handle.query_tool`은 `query_sigma_results`를 가리킨다 [28][20].
`run_analysis`는 한 번에 500행까지 돌려주지만 `df.iloc[500:600]`처럼 범위를 바꿔 부르면 남긴 CSV를 끝까지 읽는다 [6][29].

**한계.** `sigma_hunt`의 `detection_gap_invariant`는 `query_sigma_results(case_id, severity=..., rule_name=...)`로 원래 기록을 보라고 적는다 [30].
`query_sigma_results`의 인자는 `output_path`·`severity`·`techniques`·`limit`·`offset`·`response_format`이고 `case_id`와 `rule_name`은 없다 [30].
같은 도구의 `detailed` 형식도 hit을 줄인 형태로만 돌려주므로 Chainsaw의 원래 사건 기록은 이 도구로 읽지 못한다 [31].
CSV를 남기지 못해 경로가 임시 폴더로 남으면 응답의 `csv_path`와 `handle`을 비운다 [32].
버전 기준 Hayabusa v4.1.0에서는 `hayabusa_hunt`가 CSV를 남기지 않고 `output_path`가 없는 오류 응답을 돌려준다 [21][22].
Hayabusa의 이 동작은 소스로 확인했고 Hayabusa를 실행하지 않았다.

**구현.** 이 방식은 증거 글을 감싸는 공통 함수, EVTX 표본, 탐지 결과, 발견사항 요약에 적용된다.

`summarize_evtx` 표본의 `message_summary`는 500자에서 표시 없이 자르고 `extra_fields`의 값은 1,024자에서 자른 뒤 `...[truncated]`를 붙인다 [36].

### R02.08 보관한 출력의 일부 재조회

**구현.** 이 방식은 `query_sigma_results`, `query_timeline`, `run_analysis`에 적용된다 [8][42][25].
`query_sigma_results`는 `sigma_hunt`가 남긴 JSON을 다시 읽어 등급과 ATT&CK 기법으로 거른 hit을 돌려준다 [8][31].

**한계.** `query_timeline`은 조건에 맞는 사건 수에 상한을 두지 않으므로 넓은 범위로 부르면 결과 전체가 한 응답에 실린다 [11].

```python
def _strip_data_for_summary(response: Any, response_format: str = "summary",
                            count_key: str = "count") -> Any:
    """Context-budget discipline: when caller asks for summary format,
    strip the heavy ``data`` array but keep counts + handles. Mirrors the
    pattern used by disk tools via _apply_response_format.

    This applies to memory tools (scan_network, detect_injection, list_dlls)
    which previously returned full record arrays on every call - a typical
    list_dlls response is 200+ DLLs ≈ 30 KB of context per PID.
    """
    if not isinstance(response, dict):
        return response
    fmt = (response_format or "summary").strip().lower()
    if fmt == "detailed":
        return response
    # Default = summary - drop heavy fields, keep counts + handles + status.
    out = dict(response)
    data = out.get("data")
    if isinstance(data, list):
        out[count_key] = len(data)
        # Keep first 3 records as a tiny preview so the LLM has something
        # to anchor on without context bloat.
        out["preview"] = data[:3]
        out.pop("data", None)
    out["response_format"] = "summary"
    return out
```

```python
def compact_unique(values: Iterable[Any], limit: int = 10) -> list[str]:
    """Return unique, truthy stringified values in first-seen order."""
    seen: set[str] = set()
    compacted: list[str] = []
    for value in values:
        if value is None:
            continue
        text = str(value).strip()
        if not text or text in seen:
            continue
        seen.add(text)
        compacted.append(text)
        if len(compacted) >= limit:
            break
    return compacted
```

```python
def _persist_csv(tmp_csv_path: str, tool_short_name: str) -> str:
    """Copy a tempdir CSV to a persistent artifact path and return the new path.

    Pattern: $OUTPUT_BASE/<case_id>/artifacts/<tool_short_name>/<filename>
    Allows run_analysis() to query the full dataset after the tool returns.
    Returns the persistent path on success, original path on failure.
    """
    import shutil as _shutil
    src_path = Path(tmp_csv_path)
    if not src_path.exists():
        return tmp_csv_path
    base = _artifact_output_dir(tool_short_name)
    try:
        base.mkdir(parents=True, exist_ok=True)
        dest = base / src_path.name
        _shutil.copy2(str(src_path), str(dest))
        return str(dest)
    except OSError:
        return tmp_csv_path
```

```python
def fence_evidence_content(
    text: Optional[str],
    max_chars: int = DEFAULT_EVIDENCE_EXCERPT_MAX_CHARS,
) -> Optional[str]:
    """Fence model-facing evidence content so it is treated as data, not instruction.

    The default 1600-character cap is intentional: it keeps excerpts small
    enough to avoid prompt flooding while still preserving enough raw context
    for a reviewer or follow-up pivot. Full raw artifacts stay recoverable via
    persisted CSV/storage handles and provenance paths.
    """
    if not text:
        return None
    cleaned = str(text).replace("\x00", "")
    cleaned = re.sub(r"[\x01-\x08\x0b\x0c\x0e-\x1f\x7f]", "", cleaned).strip()
    if not cleaned:
        return None
    if len(cleaned) > max_chars:
        cleaned = cleaned[: max_chars - 3].rstrip() + "..."
    return f"<EVIDENCE_CONTENT>{cleaned}</EVIDENCE_CONTENT>"
```
