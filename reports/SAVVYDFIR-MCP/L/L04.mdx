# L04 기록 위변조 방지

### L04.01 해시 체인

**구현.** 이 방식은 서버가 `AuditLogger`로 `audit.jsonl`에 쓰는 모든 항목에 적용된다 [1].
`_seal_entry`는 항목마다 `schema_version`과 바로 앞 항목의 해시 `prev_entry_hash`를 넣고 그 항목의 해시 `entry_hash`를 계산해 붙인다 [1].
`entry_hash`는 `entry_hash`를 뺀 모든 필드를 키 차례로 정렬한 JSON 글의 SHA-256이다 [1].
서버를 시작한 뒤 첫 항목이면 `prev_entry_hash`는 파일에서 JSON으로 읽을 수 있는 마지막 줄의 `entry_hash`이고 파일이 없으면 `null`이다 [2].
`_write_entry`는 파일을 덧붙이기 모드로 열어 한 줄을 쓰고 `fsync`한 뒤에 메모리의 마지막 해시를 바꾼다 [3].
도구 호출 여러 번으로 쌓인 항목을 같은 방법으로 다시 계산하자 모든 `entry_hash`와 `prev_entry_hash`가 맞았다 [4].

체인 밖에 남는 값은 상태 파일 `state.json`의 실행 행에 담는 그 실행의 `started`·`completed`·`linked` 항목 해시다 [5].
`context_bundle`·`correction` 항목의 해시와 체인의 끝 값, 항목 수는 기록 밖에 따로 남지 않는다 [5].
상태 파일은 같은 분석 폴더에 같은 서버가 쓰는 파일이다 [6].
항목에는 항목마다 늘어나는 번호가 없고 `execution_id`는 한 실행의 여러 항목이 함께 쓴다 [7].

체인을 다시 계산해 대조하는 코드는 서버, 사용자 CLI, 훅 어디에서도 찾지 못했다 [8].
`get_provenance`는 발견사항의 항목을 돌려주며 `entry_hash`가 없는 항목이 있는지만 `legacy_unsealed`로 알린다 [8].
보고서 단계의 성공 판정도 실행 행에 `audit_completed_entry_hash` 값이 있는지만 본다 [8].
README는 이 기록을 hash-chained audit log로 소개한다 [9].

**한계.** 키를 쓰지 않으므로 파일 전체를 처음부터 다시 계산해 쓴 기록은 체인 계산을 통과한다 [1].
마지막 항목들을 지운 기록도 체인이 끊기지 않는다 [2].
서버는 다시 시작할 때 파일의 줄을 차례로 읽어 마지막 줄의 해시만 이어 받고 앞 항목의 해시를 다시 계산하지 않는다 [2].
첫 항목의 `command_line`을 고치고 마지막 줄을 지운 뒤 서버를 다시 시작하자 새 항목은 남은 마지막 줄의 해시를 이어 받았다 [4].
`get_provenance`는 고친 `command_line`을 그대로 돌려주고 `legacy_unsealed`를 거짓으로 알렸다 [4].

같은 파일에 해시 필드 없는 줄이 섞인다 [10].
Claude Code의 Stop 훅 `stop.py`는 waiver를 쓸 때 `audit.jsonl`에 해시 필드 없는 줄을 덧붙인다 [10].
실행 중인 서버는 메모리에 둔 자기 마지막 해시를 이어 쓰므로 다음 항목이 훅의 줄을 건너뛰어 앞 서버 항목을 가리킨다 [3].
훅의 줄이 마지막 줄일 때 서버를 다시 시작하면 `_sync_counter_from_file`이 마지막 해시를 `None`으로 두어 다음 항목의 `prev_entry_hash`가 `null`이 된다 [2].
시험 입력으로 훅을 실행하자 두 경우가 모두 그대로 나타났다 [4].

`audit.py` 설명은 이 기록 객체를 여러 프로세스가 함께 쓰는 용도로 만들지 않았다고 적는다 [11].
같은 분석 폴더로 서버 프로세스 둘이 실행되면 각 프로세스가 자기 마지막 해시를 이어 체인이 갈라진다 [3][11].
이 경우는 실행해 확인하지 않았다.

모델이 부르는 도구가 기록 파일 자체를 바꿀 수 있다 [12].
`generate_graph`는 `output_path`를 검사하지 않고 그래프 스크립트의 출력 경로로 넘긴다 [12].
출력 경로로 기록 파일을 가리키자 호출이 성공했고 기록 파일의 내용이 그래프 HTML로 바뀌었다 [4].

```python
    def _seal_entry(self, entry: AuditEntry) -> AuditEntry:
        """Attach forward-only hash-chain metadata to a newly written entry."""
        sealed = dict(entry)
        sealed["schema_version"] = _SCHEMA_VERSION
        sealed["prev_entry_hash"] = self._last_entry_hash
        sealed["entry_hash"] = self._compute_entry_hash(sealed)
        return sealed

    def _compute_entry_hash(self, entry: AuditEntry) -> str:
        """Return the canonical SHA-256 hash for an audit entry."""
        payload = {key: value for key, value in entry.items() if key != "entry_hash"}
        canonical = json.dumps(
            payload,
            sort_keys=True,
            ensure_ascii=True,
            separators=(",", ":"),
        )
        return hashlib.sha256(canonical.encode("utf-8")).hexdigest()
```

```python
def _audit_append(record: dict, audit_path: Path) -> tuple[bool, str]:
    """Append a JSONL record to audit.jsonl, fsync, and return (ok, error_text).

    fsync is required because crash durability matters when a record is the
    only artifact of an audited waiver consumption.
    """
    try:
        with open(audit_path, "a", encoding="utf-8") as fh:
            fh.write(json.dumps(record) + "\n")
            fh.flush()
            try:
                os.fsync(fh.fileno())
            except OSError as exc:
                # fsync may legitimately fail on non-disk fs (procfs, tmpfs
                # variants). Treat as soft warning, not fatal — the data is
                # in the page cache and will be visible to the next reader.
                return (True, f"fsync_warning:{exc}")
        return (True, "")
    except OSError as exc:
        return (False, f"audit_append_failed:{exc}")

```
