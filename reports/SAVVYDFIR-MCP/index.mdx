# SAVVYDFIR-MCP 원고

이 파일은 서버 개요다. 셀마다 이 폴더 아래 축 폴더의 `<축>/<셀ID>.mdx`에 쓴다.
셀과 상세 항목의 정의는 `matrix/cells/<축>/<셀ID>.mdx`를 따른다.
상세 항목마다 **구현**을 쓰고 그 방식이 적용되지 않는 경로나 조건이 있으면 **한계**를 따로 쓴다.
본문의 [번호]는 그 파일 끝 **근거**의 같은 번호를 가리킨다.

**기준 커밋.** [`9ac8e47`](https://github.com/kismatkunwar89/SAVVYDFIR-MCP/tree/9ac8e47540d4826227ac8957a5c5f4caf4f6c80b)(2026-09-24).
줄 번호는 모두 이 커밋 기준이다.

**범위.** 저장소의 Python 패키지 `sift_mcp`가 MCP 서버 하나다.
`sift_mcp/server.py`가 FastMCP로 서버(이름 `savvydfir-mcp`)를 만들고 도구 65개, 리소스 1개(`file:///attack_routing/techniques`), 초기화 지침(`instructions`)을 등록하며 프롬프트는 두지 않는다.
진입점은 `python -m sift_mcp.server`이고 전송은 stdio다.
서버 도구 `generate_graph`, `merge_host_graphs`, `build_reports_index`가 실행하는 `scripts/investigation_graph.py`, `scripts/merge_graphs.py`, `scripts/build_index.py`와 서버 도구가 불러오는 `scripts/summarize_run.py`, `scripts/extract_heuristic_slice.py`, 보고서 생성이 불러오는 `scripts/`의 모듈은 서버 구현으로 본다.
`data/`(아티팩트 지식 YAML, `hunt-evil-baseline.json`), `rules/chainsaw-sigma-mapping.yml`, `templates/graph.html`은 서버가 읽는 자료다.
Sleuth Kit, libewf, Volatility 3, YARA, Zimmerman 도구, Plaso, RegRipper, Chainsaw, Hayabusa는 서버가 하위 프로세스로 실행하거나 불러 쓰는 분석 도구로 본다.

`.claude/`(하위 에이전트 정의, 훅, skill, `settings.json`), `CLAUDE.md`, `claude_config/`, `.cursorrules`, `.mcp.json`은 클라이언트 자료와 설정이다.
다만 `.claude/agents/`의 `*-analyst.md` 12개는 서버 도구가 `scripts/extract_heuristic_slice.py`로 읽어 응답에 실으므로 서버가 읽는 자료로도 본다.
`.claude/settings.json`은 Claude Code 훅으로 세션 시작, 특정 도구 호출 앞뒤, 응답 끝에 `.claude/hooks/`의 스크립트와 `scripts/agent_trigger.py`를 실행한다.
서버 도구가 실행하지 않는 `scripts/`의 나머지(평가 채점, 실행 도우미, 그래프 서빙 셸 스크립트 등)와 저장소 최상위의 `run-case.sh`류 스크립트, `diag_native.py`, `real_velo_probe.py`, `reuse_check.py`, `reuse_verify.py`, `vanko_e2e_orchestrator.sh`는 사용자 CLI와 개발 도구다.
`install.sh`와 `download_vanko.sh`는 설치·자료 내려받기 스크립트다.
이 클라이언트 자료, 설정, 사용자 CLI는 상세가 클라이언트 쪽 방식을 묻는 경우, 클라이언트가 MCP 도구 호출을 기록하는 경우, 클라이언트가 서버 기록이나 응답으로 보고 산출물을 만드는 경우에만 구현으로 세고 그 밖에는 원고에 사실로만 적는다.
`tests/`, `docs/`, `research/`, `case-templates/`, `manifest-rocba.json`은 서버 구현으로 세지 않는다.
README와 문서의 설명(도구 수, 보장 문구, 정확도 수치)은 코드로 확인한 것만 사실로 쓴다.

**확인 방법.** 코드는 기준 커밋을 `git show`로 읽었다.
분석 도구와 라이브러리의 동작은 아래 버전 기준의 소스로 확인했다.
근거의 "실행 확인"은 기준 커밋을 `git archive`로 풀어 둔 사본을 Docker 컨테이너에서 실행해 본 결과다.
컨테이너는 SIFT 기준 환경과 같은 `ubuntu:22.04`에 Ubuntu 패키지 Sleuth Kit 4.11.1, ewf-tools, YARA를 설치하고 Python 의존성을 기준 커밋 시각 이전 버전으로 설치한 것이다(CPython 3.10.12, FastMCP 4.0.9, MCP Python SDK 2.2.0, Volatility 3 2.28.2).
서버는 불러올 때 소스 폴더 아래에 `analysis/`를 만들므로 작업마다 사본을 복사해 실행했다.
Zimmerman 도구, Plaso, RegRipper, Chainsaw, Hayabusa는 설치하지 않고 받은 인자를 기록하는 시험용 실행 파일로 바꿔 서버 쪽 처리만 확인했다.
Chainsaw 결과 처리는 Chainsaw v2.16.5의 JSON 출력 구조대로 만든 시험용 hit으로 확인했다.
Hayabusa의 명령 이름과 `-C` 동작은 소스로만 확인했다.
입력은 컨테이너 안에서 직접 만든 시험용 디스크 이미지와 파일만 썼고 컨테이너는 네트워크를 끈 상태(`--network none`)로 실행했다.

**외부 도구 버전 기준.** 서버는 외부 도구 버전을 고정하지 않는다.
`install.sh`는 SANS SIFT Workstation에서 실행한다고 전제하고 Volatility 3, Chainsaw, Sigma 규칙이 없을 때만 최신 버전을 받으며 `requirements.txt`는 `>=` 범위로만 적는다.
그래서 기준 커밋 시각(2026-09-25 00:15Z) 전 마지막 정식 SIFT Workstation 설치 정의인 `teamdfir/sift-saltstack` v2026.04.21(Ubuntu 22.04)을 기준 환경으로 삼는다.
SIFT 설치 정의가 고정한 버전을 먼저 쓰고 그다음 Ubuntu 22.04 저장소의 패키지 버전을 쓴다.
pip나 릴리스 내려받기처럼 받는 때에 따라 버전이 달라지는 것은 공개 시각이 기준 커밋 시각보다 앞선 최신 릴리스를 쓴다.
SIFT가 버전 없이 최신 실행 파일이나 기본 브랜치를 받는 도구는 기준 커밋 시각 전 마지막 소스 커밋으로 확인한다.

- Sleuth Kit 4.11.1, Python 3.10.12: Ubuntu 22.04 패키지(SIFT 기준 환경)다.
- Volatility 3: `install.sh`가 없을 때 `pipx install volatility3`로 받는다. 기준 시각 전 최신 릴리스 2.28.2다.
- Chainsaw: `install.sh`가 없을 때 최신 릴리스를 받는다. 기준 시각 전 최신 릴리스 v2.16.5(`WithSecureLabs/chainsaw`, 2026-08-25 공개)다.
- Sigma 규칙: `install.sh`가 없을 때 기본 브랜치를 `--depth=1`로 받는다. 기준 시각 전 마지막 커밋 `b151257`(`SigmaHQ/sigma`)이다.
- FastMCP: `requirements.txt`는 `fastmcp>=2.0`만 적는다. 기준 시각 전 최신 릴리스 4.0.9이고 이 버전으로 서버가 시작해 도구 65개를 등록하는 것을 실행으로 확인했다. MCP Python SDK는 FastMCP 4.0.9 설치에서 함께 받은 2.2.0이다.
- 그 밖의 Python 의존성(`pydantic` 2.13.5, `pandas` 2.3.3, `mitreattack-python` 4.0.2 등)도 기준 시각 전 최신 릴리스다.
- 그 밖의 Python 의존성 가운데 원고가 인용한 것은 `asteval` 1.0.10이다. FastMCP 4.0.9의 소스는 태그 커밋 `b21a49a`로, Volatility 3 2.28.2는 태그 커밋 `881e970`으로 확인한다.
- Ubuntu 22.04 패키지로는 ewf-tools 20140807과 SQLite 3.37.2를 썼다.
- Zimmerman 도구는 GitHub 태그가 배포 빌드를 따르지 않아 기준 시각 전 기본 브랜치 커밋으로 확인한다. EvtxECmd(`EricZimmerman/evtx`) `03a7a1f`, MFTECmd `6aadd87`, RECmd `bcd0ac3`이다.
- Plaso는 SIFT 기준 환경(GIFT PPA)의 기준 시각 전 최신 릴리스 20260720이다.
- Chainsaw v2.16.5의 `Cargo.lock`이 고정한 `evtx` 0.12.2(`omerbenamram/evtx` `99a6def`)와 chrono 0.4.45(`chronotope/chrono` `1703382`)로 EVTX 해석과 시각 표기를 확인한다.
- Hayabusa: 서버는 없으면 최신 릴리스를 받으라고 안내한다. 기준 시각 전 최신 릴리스 v4.1.0(`Yamato-Security/hayabusa`, 2026-09-12 공개, 태그 커밋 `11a7f64`)이다. 명령 해석은 그 `Cargo.lock`의 clap 4.6.6(`clap-rs/clap` `4a622b4`)으로 확인한다.
- p7zip: SIFT 기준 환경의 `p7zip-full` 패키지(Ubuntu 22.04 16.02+dfsg-8)다. 소스는 Debian `debian/16.02+dfsg-8` 태그 커밋 `54cfce9`로 확인한다.
- RegRipper는 원고에서 인용할 때 이 단락에 더한다.

**바뀔 수 있는 것.** 범위와 외부 도구 버전 기준은 조사하며 맞지 않는 곳이 나오면 검토를 거쳐 바꾼다.
