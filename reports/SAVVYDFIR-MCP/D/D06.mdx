# D06 산출물 식별·재생성 처리

### D06.02 입력·작업별 고유 이름

**구현.** 이 방식은 `sigma_hunt`·`hayabusa_hunt`·`query_timeline`의 결과 파일과 `list_processes`·`scan_processes`의 CSV에 적용된다 [1][2][3].
`sigma_hunt`·`hayabusa_hunt`는 결과 파일 이름에 초 단위 UTC 시각을 넣는다 [1].
`sigma_hunt`가 대체 대상으로 다시 실행할 때는 같은 시각 뒤에 `_fallback`을 붙인 이름을 쓴다 [4].
`query_timeline`은 `psort_out_<초 단위 UTC 시각>.csv`에 쓴다 [2].
이 시각 규칙은 같은 입력을 다시 실행한 결과도 구별한다.
`sigma_hunt`와 `query_timeline`을 각각 두 번 부르자 시각이 다른 결과 파일이 두 개씩 남았다 [5].
메모리 CSV는 메모리 덤프 파일 이름으로 만든 폴더에 두므로 이 규칙은 입력마다 같은 값을 쓴다 [3].
그래서 다른 덤프의 결과는 구별하지만 같은 덤프를 다시 실행한 결과는 같은 CSV에 쓴다 [3].
메모리 CSV는 도구 폴더 바로 아래의 `pslist.csv`·`psscan.csv`에도 복사되어 그 파일은 마지막 덤프의 결과만 담는다 [3].

다른 파일 파생물은 사건 폴더 안에서 이름이 하나다.
디스크 아티팩트 CSV, `deleted_files.json`, `.plaso` 저장 파일, 보고서, 기본 경로의 그래프는 사건 ID와 고정 이름으로 정한다 [6][7][8].
`extract_shimcache`는 AppCompatCacheParser가 정한 이름의 CSV 가운데 이름순 마지막 파일을 읽으며 그 이름 규칙은 확인하지 못했다 [9].

**한계.** 시각 규칙은 초 단위라 같은 초에 두 번 실행하면 같은 이름이 된다 [1][2].
`hayabusa_hunt`는 이때 Hayabusa에 `-C`를 넘기고 코드 주석은 이 옵션을 앞 출력 파일을 덮어쓰는 옵션이라고 적는다 [10].
버전 기준 Hayabusa v4.1.0에서 `-C`는 이미 있는 출력 파일을 덮어쓰게 하는 옵션이다 [11].
다만 v4.1.0에는 서버가 넘기는 `csv-timeline` 명령이 없어 `hayabusa_hunt`의 Hayabusa 실행은 출력 파일을 쓰기 전에 종료 코드 2로 끝난다 [12].
Hayabusa의 이 동작은 소스로 확인했고 Hayabusa를 실행하지 않았다.
메모리 덤프 이름 규칙은 다른 폴더에 있는 같은 이름의 덤프를 같은 폴더로 보낸다 [3].

### D06.04 덮어쓰기 선택·충돌 감지

**구현.** 이 방식은 상태 캐시를 쓰는 도구, 재사용 부속 자료를 쓰는 도구, `extract_windows_artifacts`, `extract_srum`의 내보내기 폴더에 적용된다 [13][14][15][16].
상태 캐시를 쓰는 도구는 `extract_mft_timeline`, `summarize_evtx`, `extract_registry_run_keys`, `build_timeline`이다 [13].
이 도구들은 인자(`mft_path` 등) JSON의 SHA-256 앞 24자를 도구 이름 뒤에 붙인 값을 키로 상태의 `cached_artifacts`를 찾는다 [17][13].
항목이 있고 그 CSV나 저장 파일이 비어 있지 않으면 외부 도구를 실행하지 않고 앞 파일을 돌려준다 [18].
이때 응답에는 `cache_hit: true`가, 실행 기록의 명령에는 `CACHE_HIT <도구 이름>`이 들어간다 [19].
상태 캐시가 없으면 `extract_mft_timeline`·`extract_usn_journal`·`summarize_evtx`와 사용자 활동 추출 도구는 재사용 부속 자료를 대조한다 [14].
파서 문자열, 인자 해시, 입력 목록 해시가 모두 같으면 파싱을 건너뛰고 응답에 `reused_output`과 `reuse_confidence: fingerprint_verified`를 싣는다 [14].
하나라도 다르면 다시 파싱해 같은 이름의 CSV를 덮어쓴다 [14][20].
같은 상태에서 `extract_mft_timeline`을 다시 부르자 시험용 `dotnet`이 실행되지 않았다 [21].
새 상태에서는 부속 자료로 재사용했고 입력 `$MFT`의 수정 시각을 바꾼 뒤에는 다시 파싱했다 [21].
`extract_windows_artifacts`는 종류별로 정해 둔 파일이 이미 있으면 다시 꺼내지 않고 `force_reextract` 인자로 다시 꺼낼지를 고르게 한다 [15].
재사용한 응답에는 `reused_from_cache`와 `cache_validation: content_presence_only_no_evidence_fingerprint`가 실린다 [15].
`extract_srum`은 내보내기 폴더가 이미 있으면 `esedbexport`를 실행하지 않고 그 폴더를 읽는다 [16].

이 밖의 도구는 같은 이름의 파일이 있는지 보지 않고 덮어쓴다.
`extract_prefetch`, `get_amcache`, `list_deleted_files`, 메모리 CSV, 보고서, 그래프, `load_memory`가 푼 파일이 여기에 해당한다 [20][7][8][22].
`list_deleted_files`를 같은 사건에서 두 번 부르자 같은 경로의 `deleted_files.json`이 둘째 결과로 바뀌었다 [23].
`load_memory`는 `7z`에 모든 확인 질문에 예로 답하게 하는 `-y`를 넘긴다 [22].
p7zip 16.02에서 `-y`를 주면 같은 이름의 파일이 있어도 묻지 않고 덮어쓰므로 같은 `output_dir`에 다시 풀면 앞 파일이 보관 파일의 내용으로 바뀐다 [24].
`build_timeline`은 저장 파일이 있는지 보지 않고 같은 경로를 `log2timeline.py`에 넘긴다 [6].
Plaso 20260720의 `log2timeline.py`는 저장 파일이 이미 있으면 이어 쓴다는 경고만 남기고 그 파일을 쓰기로 열어 앞 내용 뒤에 이어 쓴다 [25].

**한계.** 재사용을 고르거나 바뀐 입력을 알아채지 못하는 경로가 있다.
다시 파싱을 고르는 `force_reparse`는 내부 함수 인자이고 MCP 도구에는 없어 모델은 디스크 추출 도구의 재사용을 끌 수 없다 [26].
내부 `force_reparse`도 상태 캐시 검사 뒤에 쓰여 상태 캐시 재사용은 끄지 못한다 [13][14].
상태 캐시 키에는 입력 내용이 들어가지 않아 같은 경로의 입력이 바뀌어도 앞 결과를 돌려준다 [17][18].
같은 상태에서 `$MFT`의 내용과 크기를 바꾼 뒤 다시 부르자 `CACHE_HIT`로 앞 CSV를 돌려받았다 [27].
`extract_srum`의 내보내기 폴더 이름은 `case_id` 앞 20자로 정해 다른 사건이라도 앞 20자가 같으면 앞 사건의 폴더를 읽는다 [16].
이 경로는 코드로만 따라갔다.
`build_timeline`은 이 커밋에서 캐시 항목을 쓰기 전에 오류로 끝나 상태 캐시가 생기지 않고 부를 때마다 `log2timeline.py`를 다시 실행한다 [28][29].

```python
def _dump_identifier(dump_path: str) -> str:
    """Derive a filename-safe identifier from a memory dump path.

    E.1: in multi-dump cases (enterprise scope with
    one .img per host), pslist/psscan artifacts must be partitioned per
```

```python
def _persist_csv(tmp_csv_path: str, tool_short_name: str) -> str:
    """Copy a tempdir CSV to a persistent artifact path and return the new path.

    Pattern: $OUTPUT_BASE/<case_id>/artifacts/<tool_short_name>/<filename>
    Allows run_analysis() to query the full dataset after the tool returns.
    Returns the persistent path on success, original path on failure.
    """
    import shutil as _shutil
    src_path = Path(tmp_csv_path)
    if not src_path.exists():
        return tmp_csv_path
    base = _artifact_output_dir(tool_short_name)
    try:
        base.mkdir(parents=True, exist_ok=True)
        dest = base / src_path.name
        _shutil.copy2(str(src_path), str(dest))
        return str(dest)
    except OSError:
        return tmp_csv_path
```

```python
    """Return a deterministic cache key for a tool + normalized parameters."""
    payload = json.dumps(params, sort_keys=True, separators=(",", ":"), default=str)
```

```python
    cache_key: str,

) -> Optional[dict[str, Any]]:
    """Return cached metadata only when the backing artifact still exists."""
    cached = state_manager.get_artifact_cache(cache_key)
    if not isinstance(cached, dict):
        return None

    for key in required_keys or ():
        if key not in cached or cached[key] is None or cached[key] == "":

    artifact_path = cached.get(path_key)
    if not isinstance(artifact_path, str) or not artifact_path:

    path = Path(artifact_path)
    if not path.exists() or not path.is_file() or path.stat().st_size == 0:
        return None

    return cached
```
