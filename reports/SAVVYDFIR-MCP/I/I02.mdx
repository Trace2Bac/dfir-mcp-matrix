# I02 분석 도구 통신 차단

### 미구현

**판단.** 서버는 분석 도구를 실행할 때 그 도구의 통신을 끊거나 끄는 옵션이나 장치를 두지 않는다 [1].
실행기 `SafeRunner.run`은 `subprocess.run`에 `env`를 넘기지 않아 분석 도구는 서버 프로세스의 환경변수와 네트워크 설정을 그대로 물려받는다 [1].
실행기의 금지 명령 목록에는 `wget`, `curl`, `ssh`, `scp`가 있지만 이 목록은 실행할 프로그램 이름만 검사하고 실행한 분석 도구의 통신은 막지 않는다 [2].
저장소에는 분석 도구를 네트워크 없는 컨테이너, network namespace, 방화벽 규칙 아래에서 실행하는 구성이 없다.

Volatility 3는 통신을 끄지 않은 채 실행된다 [3][4].

- `VolatilityRunner.run_plugin`은 `vol`에 메모리 파일(`-f`), 출력 형식(`-r`), 플러그인 이름, 플러그인 인자만 넘기고 `--offline`을 붙이지 않는다 [3].
- `list_processes`의 항목에 남은 명령도 `-f`, `-r json`, `windows.pslist`뿐이었다 [5].
- Volatility 3 2.28.2에서 `constants.OFFLINE`의 기본값은 거짓이고 명령 행의 `--offline`이 이 값을 켠다 [4].
- 이 값이 꺼져 있으면 Volatility 3는 Windows 커널의 PDB 심볼 표가 로컬 심볼 폴더와 캐시에 없을 때 Microsoft 심볼 서버(`http://msdl.microsoft.com/download/symbols`)에서 PDB를 받아 변환한다 [4].
- 원격 ISF 목록 주소 `REMOTE_ISF_URL`은 기본값이 `None`이라 `-u`를 주지 않으면 그 목록은 조회하지 않는다 [4].

`extract_registry_run_keys`의 `sync_batch` 인자가 참이면 서버는 RECmd에 `--sync`를 붙여 배치 파일을 내려받게 한다 [6][7].
`sync_batch`를 켜고 부르자 시험용 `dotnet`이 받은 RECmd 인자 끝에 `--sync`가 있었다 [5].
이 내려받기는 서버 코드가 인자로 켜는 연결이므로 분석 도구가 스스로 여는 통신으로 보지 않는다 [6].

Plaso, Chainsaw, Hayabusa, YARA, Sleuth Kit와 RECmd를 뺀 Zimmerman 도구가 스스로 통신하는지는 확인하지 않았다.
