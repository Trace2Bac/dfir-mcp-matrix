# P06 조사 상태 유지

### P06.02 프로세스 메모리에만 보관

**구현.** 이 방식은 열린 사건, 참조 지식을 붙인 횟수, 참조 지식 글자 예산, 메모리 감시 상태, 호출 기록의 반복 차수에 적용된다 [1][2][3].
`CaseStateManager`는 `load`로 읽은 사건 상태를 프로세스 메모리의 `_state`에 두고 `_loaded`로 사건이 열렸는지 표시한다 [1].
열린 사건이 무엇인지는 파일에 따로 적지 않으므로 프로세스가 끝나면 사라진다 [1].
`_tool_call_counters`는 도구마다 참조 지식을 붙인 횟수를 세어 처음 세 응답에만 `corroborate_with`를 붙이는 데 쓰고 `_fk_advisory_chars_spent`는 참조 지식 글자 예산 6000자를 센다 [2].
메모리 감시의 마지막 경고 도구 이름과 `AuditLogger`의 반복 차수 `_current_iteration`도 프로세스 메모리에만 있다 [3][4].
서버를 다시 시작한 프로세스에서는 `_loaded`가 `False`이고 사건 ID가 `unknown`이었다 [5].

### P06.03 조사 상태를 파일·DB에 저장

**구현.** 이 방식은 사건 상태 파일, 호출 기록 파일, 추출 결과 재사용 정보, 이미지에서 꺼낸 파일, 작업 대기열에 적용된다 [6][7][8][9][10].
`state.json`에는 발견사항, 실행 기록, 레인, 가설, 참조 지식 인용, 캐시 항목 `cached_artifacts`, ID 카운터가 들어 있다 [6][11].
상태를 바꿀 때마다 `state.json.tmp`에 쓴 뒤 `os.replace`로 바꿔 끼운다 [12].
`audit.jsonl`은 항목마다 이어 쓰고 `fsync`로 디스크에 내린다 [7].
`cached_artifacts`의 키는 도구 이름과 입력 경로, 도구마다 정한 인자로 만들고 값에는 출력 CSV 경로와 실행 ID가 들어 있다 [13][14][15].
캐시 항목은 그 CSV 파일이 있고 크기가 0보다 클 때만 다시 쓴다 [8].
상태 파일과 별도로 출력 CSV 옆의 `.savvyreuse.json`에 입력 파일들의 경로·크기·수정 시각을 묶은 해시, 인자 해시, 파서 표시를 적는다 [8].
이 파일이 있고 세 값이 지금 값과 모두 같으면 파싱을 건너뛰고 CSV를 다시 쓴다 [8].
`extract_windows_artifacts`는 사건의 `artifacts/raw`에 종류별 파일이 있으면 다시 꺼내지 않고 그 파일을 돌려준다 [9][16].
같은 이미지에서 레지스트리와 Prefetch를 다시 요청하자 `reused_from_cache`가 `true`, `cache_validation`이 `content_presence_only_no_evidence_fingerprint`인 응답이 돌아왔다 [17].

**한계.** `cached_artifacts`의 키에는 입력 파일의 크기, 수정 시각, 내용이 들어 있지 않다 [13].
그래서 같은 경로의 입력이 바뀌어도 앞서 만든 CSV가 남아 있으면 상태 캐시가 먼저 적용되어 그 CSV를 돌려준다 [13][15].
`extract_windows_artifacts`의 재사용은 파일이 있는지만 보고 원본 이미지와 대조하지 않는다 [9][16].
재사용 응답의 안내는 `force_reparse=True`로 다시 파싱하라고 적지만 MCP 도구는 이 인자를 받지 않는다 [8][18].
상태 파일 주석은 한 분석 폴더를 한 서버 프로세스만 써야 하고 여러 프로세스의 접근은 지원하지 않는다고 적는다 [19].

### P06.04 재시작 뒤 자동 복구

**구현.** 이 방식은 호출 기록의 실행 ID 카운터와 해시 체인에 적용된다 [20].
`AuditLogger`는 만들어질 때 `audit.jsonl`을 처음부터 읽어 가장 큰 `E-NNN` 번호와 마지막 항목의 해시를 메모리에 다시 채운다 [20].
그래서 서버를 다시 시작해도 새 실행 ID는 앞 프로세스의 번호에 이어서 매기고 새 항목의 `prev_entry_hash`는 앞 프로세스의 마지막 해시를 가리킨다 [20][21].
마지막 항목이 `E-008`인 분석 폴더로 서버를 다시 시작하자 첫 새 항목은 `E-009`였고 `prev_entry_hash`가 이전 마지막 항목의 해시와 같았다 [5].

**한계.** 사건 상태 `state.json`은 서버가 시작할 때 읽지 않는다 [1][22].
모델이 사건 ID를 받는 도구를 불러야 상태가 다시 읽힌다 [22].
그 전에는 발견사항을 저장하는 도구가 `CaseStateManager has not been initialised` 오류를 돌려준다 [1].
다시 시작한 직후 `verify_integrity`는 이 오류로 끝났고 `read_state("CASE-A")`를 부른 뒤에는 성공했다 [5].
그 사이에 부른 `extract_windows_artifacts`는 성공 응답에 실행 기록 연결 실패를 알리는 `phase7_link_warning`을 실었다 [5].
`read_state`의 도구 설명은 조사 반복을 시작할 때마다 이 도구를 불러 서버를 다시 시작한 뒤에도 이어서 진행하라고 적는다 [23].
JSON으로 읽히지 않는 줄은 카운터를 채울 때 알림 없이 건너뛴다 [20].
반복 차수 `_current_iteration`은 다시 시작하면 1로 돌아간다 [4].

### P06.05 만료

**구현.** 이 방식은 보고서 생성이 확인하는 전문 에이전트 작업 항목 `/tmp/savvydfir_delegate.json`에 적용된다 [24].
`_pending_delegate_is_fresh`는 항목의 `created_at`이나 파일의 수정 시각이 환경변수 `SAVVYDFIR_TRIGGER_MAX_AGE_SECONDS`(기본 21600초)보다 오래되었으면 오래된 항목으로 본다 [24].
오래된 항목은 처리되지 않았어도 보고서 생성을 막는 대기 작업으로 보지 않는다 [25].

**한계.** `SAVVYDFIR_TRIGGER_MAX_AGE_SECONDS`를 0 이하로 정하면 항목이 만료되지 않는다 [24].
만료는 보고서 생성의 판단에만 적용되고 파일과 레인별 대기열의 항목은 지우지 않는다 [24][25].

```python
def get_valid_cached_artifact(
    state_manager: CaseStateManager,
    cache_key: str,
    *,
    path_key: str,
    required_keys: Optional[Iterable[str]] = None,
) -> Optional[dict[str, Any]]:
    """Return cached metadata only when the backing artifact still exists."""
    cached = state_manager.get_artifact_cache(cache_key)
    if not isinstance(cached, dict):
        return None

    for key in required_keys or ():
        if key not in cached or cached[key] is None or cached[key] == "":
            return None

    artifact_path = cached.get(path_key)
    if not isinstance(artifact_path, str) or not artifact_path:
        return None

    path = Path(artifact_path)
    if not path.exists() or not path.is_file() or path.stat().st_size == 0:
        return None

    return cached
```

    def _save_locked(self) -> None:
        """Write state to disk atomically.  Caller must hold ``_lock``."""
        self._state["updated_at"] = _utcnow_iso()

        target = self._state_path
        tmp = target.with_suffix(".json.tmp")

        target.parent.mkdir(parents=True, exist_ok=True)
        serialised = json.dumps(
            self._state, ensure_ascii=False, indent=2, default=str) + "\n"

        try:
            tmp.write_text(serialised, encoding="utf-8")
            os.replace(str(tmp), str(target))
        except OSError as exc:
            raise CaseStateError(
                f"Failed to save state to {target}: {exc}"
            ) from exc
        finally:
            # Remove tmp file if rename failed.
            try:
                if tmp.exists():
                    tmp.unlink()
            except OSError:
                pass
```

def _pending_delegate_is_fresh(
    pending_delegate: dict[str, Any], *, delegate_file: Path
) -> bool:
    try:
        max_age_seconds = int(
            os.environ.get("SAVVYDFIR_TRIGGER_MAX_AGE_SECONDS", "21600") or "21600"
        )
    except ValueError:
        max_age_seconds = 21600
    if max_age_seconds <= 0:
        return True

    created_at = _parse_iso8601(pending_delegate.get("created_at"))
    if created_at is None:
        modified_at = datetime.fromtimestamp(
            delegate_file.stat().st_mtime, tz=timezone.utc
        )
    else:
        modified_at = created_at
    age_seconds = (datetime.now(timezone.utc) - modified_at).total_seconds()
    return age_seconds <= max_age_seconds
```
