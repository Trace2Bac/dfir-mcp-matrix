# P01 분석 방법 적합성 확인

### P01.01 이름·확장자 판별

**구현.** 이 방식은 `detect_triage_layout`, 디스크 도구가 입력 경로를 정하는 함수, `load_memory`, `analyze_vss`, `extract_recycle_bin`에 적용된다 [1][2][3][4][5].
`detect_triage_layout`은 받은 경로가 `.7z`·`.zip`·`.tar`·`.gz`·`.tgz`로 끝나는 파일이면 `archive_unextracted`로 정하고 먼저 풀라는 안내를 돌려준다 [1].
폴더이면 바로 아래에 `Windows` 폴더와 `Users`·`Documents and Settings`·`ProgramData` 가운데 하나가 있을 때 `raw_mount`로 정한다 [6].
한 글자 이름의 폴더 아래에 그런 구조가 있으면 드라이브 트리로 보고 하위 이름이나 경로에 `kape`·`cylr` 표시가 있으면 형식 이름을 `kape`·`cylr`로 정한다 [6][7].
`uploads` 폴더와 `collection_context.json`·`uploads.json` 같은 Velociraptor 수집 파일 이름이 함께 있으면 `velociraptor`로 정한다 [8].
응답의 `recommended_next`는 정한 형식에 따라 디스크 도구에 넘길 `image_path`를 적는다 [7].
도구 설명은 이 도구가 판별만 하고 판별 결과를 추출 도구에 잇는 단계는 아직 없다고 적는다 [9].
`Windows`·`Users`가 있는 폴더, 같은 구조의 드라이브 폴더 두 개를 둔 폴더, 확장자가 `.zip`인 파일을 넘기자 각각 `raw_mount`, `windows_drive_tree`, `archive_unextracted`가 돌아왔다 [10].

디스크 도구는 입력 인자가 없을 때 받은 `image_path`의 이름으로 입력을 정한다 [2].
`_resolve_evtx_dir_input`은 경로가 `.evtx`로 끝나는 파일이면 그 부모 폴더를 EVTX 폴더로 쓴다 [2].
`_resolve_registry_hive_dir_input`은 파일 이름이 `SYSTEM`·`SOFTWARE`·`SECURITY`·`SAM`·`NTUSER.DAT`이면 그 부모 폴더를 하이브 폴더로 쓴다 [2].
`_resolve_mft_path_input`은 파일 이름이 `$MFT`이면, `_resolve_amcache_hive_input`은 이름이 `amcache.hve`이면 그 파일을 입력으로 쓴다 [2].
이름이 맞지 않으면 받은 경로를 Windows 볼륨 루트로 보고 `Windows/System32/winevt/Logs` 같은 정해 둔 상대 경로를 붙인다 [2][11].
상대 경로의 각 부분은 대소문자를 구별하지 않고 찾는다 [11].

`load_memory`는 확장자가 `.zip`이면 보관 파일로 보고 푼 뒤 `.raw`·`.mem`·`.vmem`·`.lime`·`.dmp` 차례로 처음 찾은 파일을 메모리 덤프로 정한다 [3].
`analyze_vss`는 확장자가 `.E01`·`.E02`·`.EWF`이면 EWF 이미지로 보고 `ewfmount`로 드러낸 원시 장치를 `vshadowinfo`에 넘긴다 [4].
`extract_recycle_bin`은 볼륨 루트 아래 `$Recycle.Bin`과 `RECYCLER` 폴더를 이름으로 찾아 휴지통 형식을 정한다 [5].

**한계.** `_resolve_mft_path_input`의 이름 비교는 대소문자를 구별하므로 이름이 `$mft`인 파일은 `$MFT`로 보지 않는다 [2].
`analyze_vss`의 확장자 목록에는 `.Ex01`이 없어 이 형식의 이미지는 EWF로 보지 않고 경로를 그대로 `vshadowinfo`에 넘긴다 [4].

### P01.02 메타데이터 조회

**구현.** 이 방식은 디스크 도구의 입력 결정, `summarize_evtx`의 채널 목록, `load_memory`, `analyze_vss`, 디스크 도구의 부재 판정에 적용된다 [12][13][3][14][15].
`probe_durable_raw`는 사건의 `artifacts/raw/<종류>` 폴더에 그 종류의 파일이 실제로 있는지 본다 [12].
EVTX는 `*.evtx` 파일이 하나 이상, 레지스트리는 `SYSTEM`이나 `SOFTWARE` 파일, Prefetch는 `*.pf` 파일이 있어야 하고 Amcache·`$MFT`·SRUM은 파일 크기가 0보다 커야 한다 [12].
디스크 도구의 입력 결정 함수는 입력 인자가 없으면 이 확인을 먼저 하고 통과한 폴더를 받은 `image_path`보다 앞서 쓴다 [2].
받은 경로가 폴더이면 그 안에 `*.evtx`·`*.pf`가 있는지, `SYSTEM`·`SOFTWARE`·`NTUSER.DAT`가 있는지로 그 폴더를 바로 입력으로 쓸지 정한다 [2].
`_enumerate_evtx_channels`는 EVTX 파일마다 크기를 읽어 4096바이트를 넘으면 기록이 있는 채널로 본다 [13].
`load_memory`는 푼 폴더에서 확장자로 덤프를 찾지 못하면 크기가 100,000,000바이트를 넘는 첫 파일을 덤프로 정한다 [3].

`analyze_vss`는 `partition_offset_sectors`가 없으면 `mmls` 출력에서 시작 섹터가 0보다 크고 공백으로 나눈 넷째 칸이 100000을 넘는 줄을 모아 넷째 칸이 가장 큰 줄의 시작 섹터를 고른다 [14].
Sleuth Kit 4.11.1 `mmls`의 넷째 칸은 길이가 아니라 끝 섹터이고 미할당 영역도 같은 형식의 줄로 출력된다 [16].
고른 시작 위치는 `vshadowinfo`와 `vshadowmount`의 `-o` 인자로 전달된다 [17].
디스크 이미지를 드러내고 `mmls`·`parted`로 파티션 위치를 정하는 `mount_image` 함수도 있지만 MCP 도구로 등록되어 있지 않다 [18].
서버의 도구 목록 65개에 `mount_image`가 없는 것을 실행으로 확인했다 [19].

`extract_prefetch`·`get_amcache` 같은 디스크 도구는 입력을 찾지 못하면 `_windows_volume_resolves`로 받은 경로 아래에서 `Windows` 폴더가 찾아지는지 본다 [15].
찾아지면 그 아티팩트가 없는 것으로 기록하고 찾아지지 않으면 다시 시도할 경로 오류로 둔다 [15][20].

**한계.** `probe_durable_raw`는 사건 폴더의 파일이 어느 이미지에서 꺼낸 것인지 보지 않는다 [12].
그래서 한 사건에 디스크 이미지가 여럿이면 다른 이미지의 `image_path`로 디스크 도구를 불러도 앞서 꺼낸 자료를 입력으로 쓴다 [2].
`analyze_vss`가 고르는 줄은 가장 긴 파티션이 아니라 끝 섹터가 가장 뒤에 있는 줄이고 미할당 영역일 수도 있다 [14][16].
두 파티션 뒤에 미할당 영역을 둔 MBR 이미지에서 `analyze_vss`는 가장 긴 파티션의 시작 2048이 아니라 미할당 영역의 시작 422048을 골랐다 [21].
`analyze_vss`의 주석은 가장 큰 NTFS 파티션을 고른다고 적지만 코드는 파티션의 파일시스템 종류를 보지 않는다 [14].
`_windows_volume_resolves`는 확인 중 예외가 나면 `True`를 돌려줘 아티팩트가 없는 것으로 기록하게 한다 [15].

### P01.03 내용·헤더 검사

**구현.** 이 방식은 `load_memory`와 `detect_profile`에 적용된다 [3][22].
`load_memory`는 `/usr/bin/file`로 파일 종류를 읽고 그 출력에 `zip`이 있거나 확장자가 `.zip`이면 보관 파일로 보고 `7z`로 푼다 [3].
그 밖의 파일은 받은 경로를 그대로 덤프 경로로 돌려준다 [3].
4096바이트짜리 파일을 넘기자 `was_extracted`가 `false`인 응답이 돌아왔다 [10].
`detect_profile`은 Volatility 3 `windows.info`를 실행해 덤프를 연다 [22][23].
`NtMajorVersion`·`NtMinorVersion`·`NtBuildLab`로 Windows 버전과 빌드를, `Is64Bit`로 아키텍처를 정해 응답과 발견사항 하나로 남긴다 [23].
다른 메모리 도구가 이 결과를 읽는 코드는 없다 [24].
`mount_image` 함수에는 섹터 0의 서명으로 NTFS·exFAT·FAT을 정하는 단계가 있지만 이 함수는 도구로 등록되어 있지 않다 [18].

**한계.** `load_memory`는 `file` 출력을 소문자로 바꿔 `zip` 글자가 들어 있는지만 본다 [3].
그래서 `gzip compressed data`처럼 설명에 `zip`이 들어간 다른 형식도 `7z`로 푸는 경로로 간다 [3].
`file`의 출력은 파일 경로로 시작하므로 경로에 `zip`이 들어간 덤프도 `7z`로 푸는 경로로 간다 [3].
폴더 이름에 `unzipped`가 들어간 경로에 둔 원시 덤프를 넘기자 푸는 경로로 갔고 기본 `output_dir`를 만들지 못해 오류로 끝났다 [25].
`detect_profile`은 `os_name`을 늘 `Windows`로 적고 Windows가 아닌 덤프는 `windows.info` 실행 오류로 끝난다 [23].

### P01.04 방법과 형식·OS 대조

**구현.** 이 방식은 `extract_recycle_bin`에 적용된다 [5].
이 도구의 파서는 `$Recycle.Bin/<SID>/$I*` 파일만 읽는다 [5].
볼륨 루트 아래에서 `$I` 파일을 찾지 못하고 `RECYCLER` 폴더가 있으면 옛 INFO2 형식으로 보고 파싱하지 않는다 [26].
이때 응답 상태는 `tool_incompatible`, 사유는 `legacy_info2_unsupported`이고 호출 기록 요약에도 `status=tool_incompatible`가 남는다 [26][27].
`$I` 파일과 `RECYCLER`가 함께 있으면 `$I` 파일만 파싱하고 응답에 `legacy_info2_not_parsed`를 붙인다 [28].

다른 도구는 실행 전에 방법을 판별한 형식이나 OS와 대조하지 않는다.
`start_investigation`은 매니페스트의 `memory_dumps`가 비어 있으면 메모리 도구를 보고서 필수 도구 목록에서 빼고 다음 단계도 메모리 단계를 건너뛰라고 적는다 [29].
이 값은 사용자가 매니페스트에 적은 증거 목록이고 서버가 덤프를 판별한 결과가 아니다 [29].
파일 접근 도구 묶음을 필수로 정하는 `windows_in_scope`도 매니페스트의 `os_in_scope` 글에 `windows`가 있는지만 보고 마운트 경로에서 OS를 추정하지 않는다 [30].
Volatility 실행이 실패하면 `classify_error`가 표준 오류의 글로 `incompatible_profile`·`missing_symbols`를 정해 호출 기록 요약 앞에 `tool_incompatible`를 붙인다 [31].
이 분류는 오류 글만 보고 덤프를 다시 열어 보지 않는다 [31].

**한계.** `RECYCLER` 폴더 안에 `INFO2` 파일이 있는지는 보지 않으므로 빈 `RECYCLER` 폴더만 있어도 `tool_incompatible`로 정한다 [26].

def windows_in_scope(os_in_scope: Any) -> bool:
    """Normalized, type-guarded 'is Windows in scope' predicate.

    Accepts a list/str/None. Returns True iff any entry contains 'windows'
    (case-insensitive) -- handles 'Windows 10/11', 'Windows Server 2019/2022'.
    Missing/malformed -> False (fail-closed on the OS axis; do NOT infer Windows
    from mount paths here).
    """
    if isinstance(os_in_scope, str):
        return "windows" in os_in_scope.lower()
    if isinstance(os_in_scope, (list, tuple)):
        return any(isinstance(o, str) and "windows" in o.lower() for o in os_in_scope)
    return False
