# matrix/ — 셀 구조와 정의

매트릭스의 축·셀·상세 항목 정의를 둔다. **셀 하나 = 파일 하나**다.
여기를 고치고 `python tools/pilot.py validate`로 확인한다.

- **셀은 거의 바뀌지 않는다.** 지금 셀로 분류할 수 없는 새 기능이 나올 때만 셀을 더하거나 나눈다(결정 기록을 쓴다).
- **상세 항목은 서버를 조사하면서 자주 바뀐다.** 이름을 고치고, 더하고, 합치고, 지운다. 그래서 상세 번호는 고정하고 이름은 자유롭게 바꾸게 했다(아래 [상세 다루기](#상세-다루기)).
- **상세는 실제 구현체가 있어야 의미가 있다.** 원고가 연결되거나 `seen_in`에 구현을 확인한 서버가 있으면 "구현 사례 있음", 둘 다 없으면 화면에 **후보**로 흐리게 보이고 `validate`가 개수를 알린다.

```
matrix/
├─ axes.yaml          축 차례·이름
├─ config.yaml        화면에 보일 서버, 시범 셀
├─ cells/<ID>.yaml    셀 하나의 질문과 상세 항목
└─ schema/            위 파일들과 원고 머리말의 JSON Schema(validate가 쓴다)
```

## 용어

- **축**: 셀을 묶는 큰 갈래. 글자 하나(P·E·T·R·L·D·I)로 쓴다.
- **셀**: 관찰 질문 하나. 번호는 `축 글자 + 두 자리`(예: `E03`).
- **상세 항목**: 그 질문에 답하는 구현 방식 하나. 번호는 `셀 번호.두 자리`(예: `E03.02`).
- **미구현**: 셀이 묻는 일을 하는데 어느 방식도 없다. **비적용**: 그 일의 전제를 서버가 아예 하지 않는다. **미확인**: 아직 조사하지 않았다(화면에만 쓴다).
- **†(exception)**: 원고의 구현에 적은 적용 범위 안에서 그 방식이 걸리지 않는 경우가 있다.

## axes.yaml

```yaml
axes:
- id: E                         # 축 글자. 축 이름 영어의 첫 글자
  name: 원본 증거 관리
  english: Evidence management
  description: 파생물이 아닌 원본 증거 데이터의 확보·등록·해시·보존·입력 준비
```

목록 차례가 화면의 축 차례다. 셀 파일 이름의 첫 글자가 그 셀의 축이다.

## cells/<ID>.yaml

```yaml
id: E03                          # 파일 이름과 같아야 한다
name: 원본 변경 방지              # 묻는 일을 명사로. 끝에 "방식"을 붙이지 않는다
question: 원본에 닿는 경로에서 누가 어떤 장치로 변경을 막는가?
conditional: false               # 지원 기능이 있는 서버에만 보는 셀이면 true
# applies_to: …                  # conditional: true일 때 적용 범위
boundary: …                      # (선택) 다른 셀과의 경계 설명. 화면에 셀 설명으로 보인다

# ── 아래는 정의를 쓴 셀만 둔다. 시범 셀(config.yaml의 pilot_cells)은 반드시 쓴다 ──
scope: …                         # 적용 범위. †를 판단하는 범위
not_implemented: …               # 이 셀에서 미구현의 뜻
not_applicable: …                # 이 셀에서 비적용의 뜻

details:                         # 상세 항목. 목록 차례가 화면 차례다
- id: E03.01                     # 한 번 정하면 바꾸지 않는다. 새 상세는 쓰지 않은 다음 번호
  name: 실행 환경의 읽기 전용 강제  # 언제든 바꿔도 된다(원고는 번호로 연결된다)
  include: …                     # 정의를 쓴 셀만. 포함 기준(아직 못 썼으면 validate가 경고만 한다)
  exclude: …                     # 정의를 쓴 셀만. 제외·범위 주의
  seen_in: [mulder, ChainsawMCP] # (선택) 원고는 아직 없지만 구현을 확인한 서버

retired:                         # (선택) 지운 상세. 번호를 다시 쓰지 않으려고 남긴다
- id: E03.04
  name: 출력 대상 검사
  merged_into: E03.02            # 다른 상세로 합쳤으면 그 번호
  reason: 서버 코드가 막는 방식으로 묶었다
```

- 정의를 아직 쓰지 않은 셀은 `details`에 `id`와 `name`만 둔다.
- 긴 글도 한 줄에 쓴다. YAML이 따옴표를 요구하면(값이 `:`·`#`·`"`로 시작하는 등) 큰따옴표로 감싼다.
- 다른 셀을 가리킬 때는 번호로 쓴다(예: "사본 생성은 E04").

## config.yaml

```yaml
servers: [ChainsawMCP, mcp_dfir, …]   # 화면에 보일 서버. reports/<서버>/가 없으면 모든 셀이 미확인
pilot_cells: [E03, T03, R02, L02]     # 원고가 담아야 하는 셀. 원고 폴더마다 이 셀 파일이 모두 있어야 한다
labels:
  미확인: 이 셀의 새 정의로 아직 조사하지 않았다.
```

## 상세 다루기

서버를 조사하다 보면 상세가 자주 바뀐다. 결정 기록 없이 이 파일만 고치고 커밋 메시지에 이유를 쓴다.

| 하려는 일 | 하는 법 | 원고 |
|---|---|---|
| 이름 바꾸기 | `name`만 고친다 | 고치지 않아도 된다(소제목 이름이 다르면 `check`가 경고만 한다) |
| 새 상세 더하기 | 이 셀에서 쓴 적 없는 다음 번호(`retired` 포함)로 `details`에 더한다. 차례는 목록 위치로 정한다 | 그 서버 원고에 연결한다. 원고를 아직 못 쓰면 `seen_in`에 서버를 적는다 |
| 구현을 봤지만 원고는 나중에 | `seen_in`에 서버 이름을 더한다 | 원고를 쓰면 `seen_in`에서 그 서버를 지운다 |
| 둘을 하나로 합치기 | 남길 상세에 기준을 합치고, 없앨 상세를 `retired`로 옮겨 `merged_into`를 적는다 | 옛 번호를 쓰는 원고가 있으면 `validate`가 "합쳤다"고 알린다. 머리말과 소제목을 새 번호로 고친다 |
| 없애기 | `retired`로 옮기고 `reason`을 적는다 | 그 번호를 쓰는 원고를 다른 상세나 미구현으로 고친다 |
| 차례 바꾸기 | 목록에서 위치만 옮긴다. 번호는 그대로 | 고치지 않는다 |

**번호를 다시 매기지 않는다.** 빈 번호가 생겨도 그대로 둔다. 지운 번호를 다시 쓰면 `validate`가 오류를 낸다.

## 셀 다루기 (드물다)

| 하려는 일 | 고칠 곳 |
|---|---|
| 셀 질문·이름 고치기 | `cells/<ID>.yaml`의 `question`·`name`. 원고 제목(`# ID 이름`)이 달라지면 `check`가 경고한다 |
| 셀 새로 만들기 | 지금 셀로 분류할 수 없는 새 기능이 나왔을 때. `cells/`에 축 안 마지막 번호 다음으로 `<ID>.yaml`을 만든다 |
| 셀 나누기·합치기·번호 바꾸기 | 파일을 만들고 지운 뒤 원고·문서의 옛 번호를 고친다. 절차는 [CONTRIBUTING.md](../CONTRIBUTING.md#셀을-나누거나-합치거나-번호를-바꾼다) |
| 셀의 범위(`scope`·미구현·비적용) 바꾸기 | `cells/<ID>.yaml` |
| 축 차례·이름 바꾸기 | `axes.yaml` |
| 시범 셀 바꾸기 | `config.yaml`의 `pilot_cells`. 그 셀에 정의(`scope` 등)가 있어야 한다 |

셀을 바꾸면 [docs/decisions/](../docs/decisions/)에 결정을 하나 더한다.
