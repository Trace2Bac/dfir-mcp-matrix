question: 서버가 처리 중 부르는 모델에게 넘길 자료를 구성하고 증거와 지시를 구분하며 역할과 반환 형식을 알리는 방식을 분류합니다.
conditional: true
applies_to: 서버가 처리 중에 모델을 부르는 경우입니다. 모델 요약, 서버 안 모델의 추론·서술, 모델 검토, 모델 계획 생성 가운데 하나라도 하는 서버가 그 예입니다.
boundary: 클라이언트 모델에게 돌려주는 응답의 지시 구분은 R07에서, 클라이언트 모델에게 주는 판단 안내는 F01에서 봅니다. 내부 모델의 출력을 서버가 실제로 받아들이거나 거부하거나 다시 계산하는 정책은 F05와 F02에서 봅니다. 모델 호출의 기록은 L02에서, 모델 버전 표시는 T06에서, 모델 API와의 연결은 I01에서 봅니다.
scope: 서버가 모델 API에 보내는 입력(시스템 지시, 사용자 메시지, 첨부한 증거와 도구 출력)이 적용 범위입니다. 입력 구성은 판단 결과가 아니라 요약, 결론, 검토, 계획에 함께 쓰이는 지원 기능입니다.
not_implemented: 서버가 모델에 넘기는 입력에 증거와 지시를 구분하는 표시도, 역할이나 반환 형식을 정하는 지시도 없는 경우입니다.
not_applicable: 서버가 처리 중에 모델을 부르지 않는 경우입니다.
details:

  name: 증거와 지시 구분 표시

  exclude: 표시가 있다는 사실만으로 주입을 막는다고 보지 않습니다. 실제 효과는 원고의 한계 단락에 확인한 범위만 씁니다.
  seen_in: [trudi]

  name: 역할·반환 형식 지시

  exclude: 지시만으로 판단 권한을 제한했다고 보지 않습니다.
  seen_in: [trudi]
