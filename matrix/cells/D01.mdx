id: D01
name: 파생물 보관
question: 서버는 도구 출력, 파생물, 중간 자료를 어디에 어떤 형태로 보관하고 얼마나 남기나요?
conditional: false
boundary: 저장 실패 처리는 D09에서 봅니다. 보관한 자료를 누가 지우는지(모델 도구, 운영자 명령, 자동 정리)와 삭제 흔적은 P05에서
  봅니다.
scope: 서버가 도구를 실행해 얻거나 만든 출력, 파생물, 중간 자료가 대상입니다. 상세마다, 원고의 구현 단락에 그 방식으로 보관한다고 적은
  도구와 자료가 적용 범위입니다. 그 범위 안에서 다음 경로가 있으면 †를 붙입니다. 일부만 남기는 경로, 호출 뒤에 지우는 경로, 다시 실행할
  때 앞 자료를 남기지 않는 경로, 설정이나 인자로 보관을 끄는 경로, 어디에 얼마나 남는지 확인하지 못한 경로입니다. 보관하지 않는 다른 도구와
  자료에는 †를 붙이지 않고 원고의 구현 단락에 씁니다.
not_implemented: 도구 출력과 파생물을 응답으로 돌려주기만 하고, 서버가 파일이나 DB, 저장소에 남기지 않는 경우입니다. 실행 중에
  임시 폴더에만 두었다가 호출이 끝나면 지우는 경우도 미구현으로 봅니다.
not_applicable: 없습니다. 모든 서버에 적용합니다.
details:
- id: D01.01
  name: 도구 출력 파일 저장
  include: 서버가 도구의 표준 출력이나 텍스트 출력을 호출마다 파일로 써서, 호출이 끝난 뒤에도 남기는 경우입니다.
  exclude: 도구가 스스로 만든 파일을 남기는 경우는 D01.02에서, DB나 객체 저장소에 넣는 경우는 D01.03에서 봅니다.
- id: D01.02
  name: 도구가 만든 파생물 유지
  include: 도구가 실행 중에 만든 파일을 호출이 끝난 뒤에도 남기는 경우입니다. 그런 파일은 풀어낸 파일, 꺼낸 파일, 복구한 파일, 도구의
    저장 파일, 보고 산출물입니다. 남기는 위치는 서버가 정했거나 호출 인자로 받은 위치입니다.
  exclude: 도구의 표준 출력이나 텍스트 출력을 서버가 따로 파일로 쓰는 경우는 D01.01에서, DB에 넣는 경우는 D01.03에서 봅니다.
    무엇을 담아 검토자에게 내는지는 D08에서 봅니다. 위치를 누가 정하고 어떻게 제한하는지는 D04에서 봅니다.
- id: D01.03
  name: 객체 저장소·DB 보관
  include: 도구 출력이나 서버가 가공한 결과를 DB(SQLite 등)의 행이나 객체 저장소의 객체로 넣어, 호출이 끝난 뒤에도 남기는 경우입니다.
  exclude: 프로세스 메모리에만 두는 상태는 P04에서 봅니다. 보관한 자료를 응답으로 다시 읽는 방식은 R02에서 봅니다.
- id: D01.04
  name: 도구 출력·가공본 별도 보관
  include: 한 도구 호출이나 서버가 한 처리로 묶은 실행이, 도구가 낸 원래 출력(저장 파일, 표준 출력)과 그 출력을 가공한 결과를 둘 다
    따로 남기는 경우입니다.
  exclude: 한쪽만 남기는 경우는 이 상세에 연결하지 않습니다. 가공 사실을 응답에 표시하는지는 R01에서 봅니다.
- id: D01.05
  name: 보존 기간·대상 정책
  include: 보관 기간, 보관하는 자료 전체의 크기나 개수 상한, 보관 대상을 정하는 설정이나 코드가 있고, 서버가 그에 따라 무엇을 얼마나 남길지 정하는 경우입니다.
  exclude: 정책에 따라 실제로 지우는 주체와 삭제 흔적은 P05에서 봅니다. 정책 없이 도구마다 일부만 남기는 경우는 해당 상세의 예외로
    씁니다.
