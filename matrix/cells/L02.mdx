---
id: L02
name: 기록 구성
question: 기록 항목에 요청·실제 실행·결과 상태·모델 호출·외부 요청 가운데 어떤 사건과 내용을 어떤 형태로 남기는가?
conditional: false
scope: 서버 기록에 항목이 남는 호출과 외부 요청이다. 기록을 만드는 장치와 그 장치를 거치지 않는 호출은 L01에서 본다. 그 항목에서 이
  방식의 내용이 빠지거나 다르게 남는 도구·경로가 있거나 기록이 인자 경계를 잃으면 †를 붙인다.
not_implemented: 기록은 남지만 요청 내용(도구·인자·명령)도 결과 상태도 남기지 않는다.
not_applicable: 서버가 기록을 남기지 않는다.
details:
- id: L02.01
  name: 요청 원문 기록
  include: 모델이 보낸 도구 이름과 인자를 받은 그대로 기록한다.
  exclude: 서버가 바꾼 뒤의 값만 남으면 L02.02다.
- id: L02.02
  name: 서버가 바꾼 인자 기록
  include: 서버가 dispatch·기본값·경로 변환을 적용한 뒤의 도구 이름과 인자를 기록한다.
  exclude: 외부 도구·프로세스에 넘긴 명령이면 L02.03이다. 요청 원문도 함께 남기면 L02.04에도 연결한다.
- id: L02.03
  name: 실제 실행 명령 기록
  include: 외부 도구·프로세스에 실제로 넘긴 실행 파일과 인자를 기록한다.
  exclude: 인자를 공백으로 이어 인자 경계가 사라지면 †를 붙이고 예외에 적는다. 서버 안 함수만 부르는 도구는 이 항목의 적용 범위가 아니다.
- id: L02.04
  name: 요청과 실행의 연결
  include: 요청 원문과 서버가 바꾼 값 또는 실제 실행 명령을 함께 기록하고 둘의 관계를 남긴다.
  exclude: 어느 한쪽만 남긴 기록은 제외한다.
- id: L02.05
  name: 모델 호출의 입력·응답 기록
  include: 서버가 부른 모델의 입력·응답·모델 식별을 기록에 남긴다. 판단을 다시 검토할 수 있도록 프롬프트·판정 정책의 식별값, 추론 설정(온도
    등), 모델 호출이 실패했을 때 그 사실과 그 뒤의 판정(통과·거부)도 함께 남기는지 본다.
  exclude: 모델 이름·버전만 남기면 T06 "모델·버전 표시"다. 실패 때 통과시키는지 막는지 자체는 T03의 게이트 동작이다.
- id: L02.06
  name: 실행 시작·종료·결과 상태 기록
  include: 한 실행의 시작과 종료, 성공·거부·실패·시간 초과를 기록에 남긴다.
  exclude: 실패를 알아차리는 방식은 T08, 응답에 알리는 방식은 R03이다. 기록 쓰기 자체가 실패할 때는 L03이다.
- id: L02.07
  name: 비동기 작업 최종 상태 기록
  include: 호출이 끝난 뒤에 끝나는 작업(수집·헌트·백그라운드 실행)의 최종 상태를 처음 호출의 기록에 이어 남긴다.
  exclude: 최종 상태를 조회하는 방식만 있으면 T08다.
- id: L02.08
  name: 호출 ID·시각으로 항목 연결
  include: 한 호출에서 나온 여러 항목(요청·실행·결과·외부 요청)을 같은 호출 ID나 시각으로 묶는다.
  exclude: 입력·파생물과 실행의 연결은 D02이다.
- id: L02.09
  name: 외부 요청 내용 기록
  include: 서버가 외부 서비스에 보낸 요청의 목적지·보낸 자료 요약·응답을 그 요청을 일으킨 호출과 함께 기록한다.
  exclude: 무엇을 보내는지 자체는 I03, 자격증명이 기록에 섞이는지는 I04이다.
