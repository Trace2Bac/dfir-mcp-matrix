---
id: R05
name: 결과 출처 표시
question: 각 결과 항목이 어느 증거·파일·레코드에서 나왔는지 응답에 어떻게 표시하는가?
conditional: false
boundary: 결과의 식별자로 다시 읽고 대조하는 일은 뒤의 다른 호출이라 이 셀에서 보지 않음. 저장한 출력을 다시 읽는 방식은 R02, 파생물
  대조는 D03
scope: 그 출처 표시가 걸린다고 구현에 적은 도구의 결과다. 그 도구 안에서 출처 표시가 빠지거나 실제와 다른 출처를 적는 경로(다른 반환 형식,
  값 잘림, 상수로 적은 출처, 여러 증거를 한 이름으로 묶음)가 있으면 †를 붙인다. 출처 표시가 없는 다른 도구는 †가 아니라 구현에 적는다.
not_implemented: 결과에 출처를 가리키는 값(증거·파일 ID, 증거 안 경로, 레코드 키, 오프셋)이 없다.
not_applicable: 서버가 증거에서 나온 결과를 돌려주지 않는다.
details:
- id: R05.01
  name: 증거·파일 ID
  include: 결과나 결과 항목에 그 결과가 나온 증거 파일의 ID·경로가 있다. 서버가 붙인 저장 자료 ID·이름으로 증거 경로를 찾는 조회가
    있어도 든다.
  exclude: 증거 안의 파일 경로는 R05.02, 증거 안 레코드는 R05.03에서 본다. 출처 이름이 증거 경로로 이어지지 않으면 제외한다.
- id: R05.02
  name: 증거 내부 경로
  include: 디스크 이미지·압축 파일처럼 파일을 담은 증거 안에서 결과가 나온 파일의 경로를 결과 항목에 싣는다. 외부 도구 출력에 든 경로를
    그대로 전달해도 든다.
  exclude: 서버가 증거에서 꺼낸 파일을 둔 작업 폴더 경로는 증거 안 경로가 아니므로 제외한다.
- id: R05.03
  name: 레코드 키·번호
  include: 결과 항목에 증거 안에서 그 레코드를 다시 찾을 수 있는 키·번호(inode, 이벤트 레코드 번호, 레지스트리 키 경로, DB
    행 키)가 있다. 외부 도구 출력에 든 값을 그대로 전달해도 든다.
  exclude: 서버가 결과를 저장하며 매긴 ID는 증거 안 레코드가 아니므로 제외한다.
- id: R05.04
  name: 바이트·섹터·행 오프셋
  include: 결과 항목이 증거 안 어디에 있는지 바이트·섹터 오프셋이나 텍스트 증거의 줄 번호로 싣는다. 외부 도구 출력에 든 값을 그대로
    전달해도 든다.
  exclude: 서버가 저장한 출력 안의 줄 번호·위치는 증거 안 위치가 아니므로 제외한다.
retired:
- id: R05.05
  name: 원본 범위 재읽기
  reason: 결과의 식별자로 다시 읽는 일은 뒤의 다른 호출이라 결과 전달 셀에서 보지 않는다(docs/decisions/0008)
- id: R05.06
  name: 작업 사본·저장 출력 조회
  reason: 저장한 출력을 다시 읽는 방식은 R02에서 본다(docs/decisions/0008)
- id: R05.07
  name: 재조회 시 해시·내용 대조
  reason: 결과 전달 셀에서 보지 않는다(docs/decisions/0008)
- id: R05.08
  name: 별도 검증 도구 연계
  reason: 파생물 대조는 D03, 원본 증거 대조는 E02에서 본다(docs/decisions/0008)
