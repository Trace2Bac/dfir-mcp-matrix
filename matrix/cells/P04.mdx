id: P04
name: 조사 문맥 관리
question: 조사를 어떤 단위(사건·세션·프로세스)로 묶어 실행·기록·파생물에 연결하고, 단위 사이를 어떻게 분리하며, 조사 상태(능력·단계·적재한
  입력·세션 문맥)를 요청·세션·재시작 사이에서 얼마나 유지·복구하는가?
conditional: false
boundary: 그 상태로 호출을 막는지는 T03, 도구로 지우거나 초기화하는 것은 P05, 발견사항 저장은 D05
scope: 서버가 조사 단위를 정하고 조사 상태를 두는 경로다. 단위 ID가 적용되지 않는 도구·저장 경로가 있거나, 단위 사이에 파일·캐시·기록이
  섞이거나, 검사가 일부 동시 작업에서 빠지거나, 저장·복구한다고 구현에 적은 상태를 다시 시작한 뒤 쓸 수 없으면 †를 붙인다. 상태를 두지 않는
  다른 도구는 †가 아니라 구현에 적는다.
not_implemented: 조사 단위를 식별·분리하는 장치가 없고 조사 상태를 두는 곳도 상세 어디에도 들지 않는다. 요청마다 상태를 새로 만드는
  서버는 P04.07에 든다.
not_applicable: 없음. 모든 서버에 적용한다.
details:
- id: P04.01
  name: 사건 시작 시 ID 확정
  include: 사건을 만들거나 열 때 서버가 사건 ID를 정하거나 검사하고 이후 호출을 그 사건에 묶는다.
  exclude: 호출마다 ID를 받아 대조하면 P04.02다. 사건을 바꾸는 경로는 원고에 적는다.
- id: P04.02
  name: 호출마다 사건 ID 전달·검사
  include: 사건 ID를 호출 인자나 세션 값으로 받아 서버가 열린 사건과 대조하고 다르면 거부한다.
  exclude: ID를 받기만 하고 대조하지 않으면 연결하지 않고 원고에 적는다.
- id: P04.03
  name: 폴더·DB·manifest에 사건 ID 연결
  include: 사건 ID를 저장 폴더·DB·호출 기록·보고서의 이름이나 필드에 넣어 저장물을 사건에 잇는다.
  exclude: 저장물이 사건마다 따로 있는지는 P04.04에서 본다.
- id: P04.04
  name: 사건별 폴더·DB 분리
  include: 사건마다 DB·폴더를 따로 두어 한 사건의 자료가 다른 사건의 자료와 섞이지 않게 한다.
  exclude: 사건 ID를 이름에 넣기만 하면 P04.03이다. 프로세스 메모리의 캐시가 사건을 구별하는지도 여기에 적는다. 사건 개념 없이
    운영자가 실행마다 저장 위치를 지정해 나누게 하면 연결하지 않고 조사 단위가 무엇인지와 함께 구현에 적는다.
- id: P04.05
  name: 세션·프로세스 상태 분리
  include: 세션·연결·프로세스마다 조사 상태를 따로 두어 한 세션의 상태가 다른 세션에 쓰이지 않게 한다.
  exclude: 서버 프로세스 하나에 연결이 하나뿐인 stdio 구성만으로는 연결하지 않는다.
- id: P04.06
  name: 동시 작업의 사건 문맥 검사
  include: 진행 중인 작업이 있으면 사건 전환을 거부하거나, 작업이 시작한 사건과 기록 직전의 사건이 같은지 다시 확인한다.
  exclude: 사건 ID를 호출마다 대조하는 것은 P04.02다.
- id: P04.07
  name: 요청마다 새로 생성
  include: 요청마다 서버나 조사 상태를 새로 만들어 요청 사이에 상태를 남기지 않는다.
  exclude: 요청 사이의 상태를 파일·DB로 넘기면 P04.09에 함께 연결한다.
- id: P04.08
  name: 프로세스 메모리에만 보관
  include: 조사 상태(열린 사건, 작업 목록, 캐시 등)를 프로세스 메모리에 두어 프로세스가 끝나면 사라진다.
  exclude: 같은 상태를 파일·DB에도 쓰면 P04.09에 함께 연결한다.
- id: P04.09
  name: 조사 상태를 파일·DB에 저장
  include: 조사 상태(적재한 자료, 호출 기록, 진행 기록, 중간값 등)를 파일·DB에 써서 프로세스가 끝나도 남긴다.
  exclude: 발견사항 저장 방식은 D05, 파생물 보관은 D01에서 본다.
- id: P04.10
  name: 재시작 뒤 자동 복구
  include: 서버를 다시 띄울 때 저장한 조사 상태를 다시 읽어 모델이 따로 복구하지 않아도 이어 쓴다. 어떤 상태를 되살리고 어떤 상태를
    버리는지 구현에 적는다.
  exclude: 모델이 사건 열기 도구를 불러야 다시 읽히면 그렇다고 원고에 적는다.
- id: P04.11
  name: 만료
  include: 조사 상태·캐시·세션에 유효 시간이나 개수 한도를 두고 넘으면 버린다.
  exclude: 프로세스가 끝나 사라지는 것은 P04.08이다.
