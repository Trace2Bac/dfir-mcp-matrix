name: 기록 방식
question: 서버 기록을 어떤 장치와 경로로 만드나요? 그 장치를 거치지 않는 호출은 무엇인가요?
conditional: false
boundary: 장치를 거치지 않아 기록되지 않는 호출이 있으면 예외 표시를 붙입니다. 기록 항목에 어떤 사건과 내용이 담기는지는 L02에서 봅니다. 이
  셀은 조사 과정을 다시 짜 맞추는 데 쓰는 기록을 봅니다. 디버그 출력은 호출 내용을 담을 때만 기록으로 인정합니다.
scope: 서버가 받는 모든 도구 호출이 적용 범위입니다. 같은 저장소가 함께 제공하는 클라이언트 코드, 훅, 설정이 서버 기록이나 사건 폴더에
  남기는 보조 기록은 L01.10에서 봅니다. 다음 경우에는 예외 표시를 붙입니다. 원고의 구현 단락에 적은 장치를 거치지 않아 항목이 남지 않는
  도구, 기록하기 전에 돌아가는 반환 지점, 기록하기 전에 난 예외, 기록할 곳이 없는 호출 상태(사건을 열기 전 등)가 있는 경우입니다. 항목에
  무엇이 담기는지는 L02에서, 기록 쓰기가 실패할 때의 처리는 L03에서 봅니다.
not_implemented: 서버가 도구 호출을 기록하지 않는 경우입니다. 도구 이름도 인자도 담지 않는 진단 로그만 있는 경우도 미구현으로 봅니다.
not_applicable: 없습니다. 모든 서버에 적용합니다.
details:
- id: L01.06
  name: 클라이언트·백엔드 기록에 위임
  include: 서버는 도구 호출을 기록하지 않고, 저장소가 안내하거나 구성해 둔 클라이언트 훅이나 백엔드 서비스의 기록에 맡기는 경우입니다.
  exclude: 저장소에 그런 구성이나 안내가 없으면 미구현입니다. 서버가 자기 기록도 남기면 그 장치의 상세에 연결하고, 맡기는 기록은 원고의
    구현 단락에 씁니다.
- id: L01.07
  name: 공통 요청 처리 단계에서 기록
  include: 모든 도구 호출이 지나는 공통 단계가 도구 실행 앞이나 뒤에 항목을 쓰는 경우입니다. 공통 단계는 dispatch, 미들웨어,
    등록 래퍼 같은 것입니다.
  exclude: 도구마다 골라 붙이는 데코레이터나 응답 함수는 여기가 아니라 L01.08에서 봅니다. 공통 단계가 기본 항목을 쓰고 일부 도구 본문이
    스스로 쓴 항목을 반영해 기본 항목을 생략하는 구조도 L01.07로 보며, 본문 기록은 원고의 구현 단락에 씁니다.
  seen_in:
  - ChainsawMCP
- id: L01.08
  name: 도구별 기록 호출
  include: 모든 호출이 지나는 공통 단계 없이, 도구 본문이 기록 함수, 기록하는 응답 함수, 데코레이터 가운데 필요한 것을 골라 써서 항목을
    만드는 경우입니다.
  exclude: 모든 요청이 지나는 dispatch나 미들웨어가 기록하는 경우는 L01.07에서 봅니다. 외부 명령을 실행하는 함수가 실행마다
    기록하는 경우는 L01.09에서 봅니다. 도구마다 따로 붙이는 데코레이터는 공통 단계로 인정하지 않습니다.
  seen_in:
  - agentic-velociraptor-mcp
- id: L01.09
  name: 실행기 안 기록
  include: 외부 명령이나 백엔드 질의를 실행하는 공통 실행 함수가 실행마다 항목을 쓰는 경우입니다.
  exclude: 실행 함수를 거치지 않는 도구는 그 도구가 쓰는 장치의 상세에서 봅니다. 실행 함수가 기록하지 않고 결과만 돌려주는 경우는 해당하지
    않습니다.
  seen_in:
  - mcp_dfir
- id: L01.10
  name: 클라이언트의 보조 기록
  include: 같은 저장소가 함께 제공하는 클라이언트 코드, 훅, 설정이, 서버를 거치지 않는 클라이언트 쪽 기록을 서버 기록이나 사건 폴더에 남기는
    경우입니다. 클라이언트 쪽 기록은 클라이언트 자체 도구 호출, 클라이언트가 부른 모델 호출, 사용자 입력, 대화 기록을 말합니다. 어느 클라이언트로
    붙을 때만 남는지 원고의 구현 단락에 씁니다.
  exclude: 서버가 자기 도구 호출을 기록하지 않고 클라이언트 기록에 맡기는 경우는 L01.06에서 봅니다.
