id: D09
name: 파생물 저장 실패 처리
question: 도구 출력·파생물·보고 산출물의 저장이 실패할 때 호출·작업 상태에 어떻게 반영하고 알리는가?
conditional: false
boundary: 호출 기록 쓰기 실패는 L03. 무엇을 어디에 보관하는지는 D01
scope: 서버가 도구 출력·파생물·보고 산출물을 파일·DB에 쓰거나 적재·복사하는 경로다. 쓸 내용을 만들다 실패해 그 파생물을 남기지 못하는
  경우도 든다. 그 경로에서 실패를 알리지만 실패 뒤 남은 자료가 완료된 것처럼 쓰이거나, 처리가 설정·인자로 바뀌거나, 실패 때의 동작을 확인하지
  못하면 †를 붙인다. 실패를 알리지 않고 계속하는 경로는 D09.04로 따로 들고 †로 세지 않는다.
not_implemented: 없음. 파생물을 저장하는 서버는 저장이 실패할 때 아래 상세 가운데 하나로 동작한다.
not_applicable: 서버가 도구 출력·파생물·보고 산출물을 저장하지 않고 응답으로만 돌려준다.
details:
- id: D09.01
  name: 오류·부분 완료 표시
  include: 저장이 실패하면 호출·작업을 오류로 끝내거나 응답에 저장하지 못한 부분을 싣는다. 저장 예외를 따로 잡지 않아 호출이 오류로 끝나는
    경우도 든다.
  exclude: 실패 전에 저장한 일부가 남는지는 구현에 적는다. 다시 시도하거나 다른 곳에 남기면 D09.02도 함께 본다.
- id: D09.02
  name: 재시도·대체 저장
  include: 저장이 실패하면 다시 쓰거나 다른 위치·형식으로 남기고 그 사실을 응답이나 기록에 남긴다.
  exclude: 실패한 부분을 빼고 나머지만 쓰면 D09.01이다.
- id: D09.03
  name: 저장 확인·검증
  include: 저장을 마친 뒤 완료 표시를 남기거나 저장한 파생물을 다시 읽어 확인하고, 확인되지 않은 파생물은 다음 호출에서 완료로 쓰지 않는다.
  exclude: 해시 기준값과 대조하는 무결성 검증은 D03이다. 파일이 있는지만 보고 이번 저장인지 가리지 않으면 제외한다.
- id: D09.04
  name: 알림 없이 계속
  include: 저장 실패를 잡아 로그에만 남기거나 버리고 성공 응답을 돌려준다.
  exclude: 응답에 실패나 경고를 실으면 D09.01이다.
