name: 조사 상태 유지
question: 열린 사건, 작업 목록, 진행 기록, 캐시 같은 조사 상태를 요청, 세션, 재시작 사이에 유지하고 버리는 방식을 분류합니다.
conditional: false
boundary: 조사 단위를 정하고 나누는 것은 P04에서, 상태를 지우거나 초기화하는 것(호출 기록 파일을 크기로 회전하며 앞선 파일을 지우는 것 포함)은 P05에서, 발견사항 저장은 F04에서, 파생물 보관은 D01에서 봅니다.
scope: 서버가 조사 상태를 두는 경로가 적용 범위입니다. 조사 상태는 열린 사건, 작업 목록, 불러온 자료, 진행 기록, 캐시, 중간값을 말합니다.
not_implemented: 없습니다. 모든 서버는 조사 상태를 두는 곳을 가리키는 상세(요청마다 새로 생성, 프로세스 메모리에만 보관, 조사 상태를 파일·DB에 저장) 가운데 하나 이상에 해당합니다.
not_applicable: 없습니다. 모든 서버에 적용합니다.
details:
- id: P06.01
  name: 요청마다 새로 생성
  include: 요청마다 서버나 조사 상태를 새로 만들어 요청 사이에 상태를 남기지 않으면 해당합니다.
- id: P06.02
  name: 프로세스 메모리에만 보관
  include: 열린 사건, 작업 목록, 캐시 같은 조사 상태를 프로세스 메모리에 두어 프로세스가 끝나면 상태도 사라지는 경우입니다.
- id: P06.03
  name: 조사 상태를 파일·DB에 저장
  include: 불러온 자료, 호출 기록, 진행 기록, 중간값 같은 조사 상태를 파일이나 DB에 써서 프로세스가 끝나도 남게 하면 해당합니다.
- id: P06.04
  name: 재시작 뒤 자동 복구
  include: 서버를 다시 시작한 뒤 저장한 조사 상태를 서버가 스스로 다시 읽어 모델이 따로 복구하지 않아도 이어서 쓸 수 있으면 해당합니다.
  exclude: 모델이 사건 열기 도구를 불러야 상태가 다시 읽히는 경우는 해당하지 않습니다. 서버를 담은 프로그램이 쥔 상태(열린 사건)에 서버가 다시 붙는 것은 서버가 저장한 상태가 아니므로 해당하지 않습니다.
- id: P06.05
  name: 만료
  include: 조사 상태, 캐시, 세션에 유효 시간이나 개수 한도를 두고 한도를 넘으면 버리는 경우입니다.
  exclude: 프로세스가 끝나서 상태가 사라지는 것은 해당하지 않습니다.
