name: 산출물 식별·재생성 처리
question: 파생물을 실행이나 입력마다 구별해 두는 방식과 같은 산출물을 다시 만들 때 앞 결과를 보존하거나 다시 쓰거나 덮어쓰는 방식을 분류합니다.
conditional: false
boundary: 목적지 경로를 정하고 제한하는 것과 목적지 이름을 문자열로 검사하는 것은 D04에서, 보관 위치·형태·기간은 D01에서, 지우는 주체와 흔적은 P05에서 봅니다.
scope: 서버가 파생물을 만드는 이름·위치 규칙과, 같은 작업을 다시 할 때 앞 산출물을 처리하는 방식이 대상입니다. 서버 코드가 정하는 규칙과, 서버가 부르는 외부 도구가 정하는 규칙을 모두 포함합니다.
not_implemented: 같은 이름으로 다시 만들 때 앞 산출물을 알리지 않고 덮어쓰고, 실행이나 입력마다 구별하지도 않는 경우입니다.
not_applicable: 서버가 파생물을 담은 파일이나 DB를 만들지 않는 경우입니다.
details:
- id: D06.01
  name: 실행 ID별 위치
  include: 실행마다 받은 ID(호출 ID, 작업 ID)로 폴더나 이름을 나눠 파생물을 두는 경우입니다.
- id: D06.02
  name: 입력·작업별 고유 이름
  include: 파생물 이름에 시각, 번호, 난수, 또는 입력마다 다른 값(경로 해시 등)을 넣어 다른 작업의 파생물과 겹치지 않게 하는 경우입니다. 입력마다 같은 값을 쓰는 규칙은 다른 입력의 산출물과는 구별하지만 같은 입력을 다시 실행한 결과는 구별하지 않으므로, 원고에 어느 쪽인지 적습니다.
  exclude: 호출이 끝나면 지우는 임시 폴더의 이름만 유일한 경우는 해당하지 않습니다.
- id: D06.03
  name: 버전·이력 보존
  include: 같은 이름의 파생물을 다시 만들 때 앞 결과를 지우지 않고 버전이나 시각과 함께 남겨, 둘을 구분할 수 있는 경우입니다.
  exclude: 덮어쓸지를 호출 인자로 고르거나 이미 있는 결과를 다시 쓰는 경우는 해당하지 않습니다.
- id: D06.04
  name: 덮어쓰기 선택·충돌 감지
  include: 같은 결과가 이미 있으면 알아채고 다시 만들지 않거나 덮어쓸지를 호출 인자로 고르게 하는 경우입니다.
  exclude: 알리지 않고 덮어쓰는 경우는 해당하지 않습니다.
