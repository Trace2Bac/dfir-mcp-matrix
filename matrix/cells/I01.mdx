---
id: I01
name: 외부 연동 대상 관리
question: 서버의 외부 연동은 어떤 조건에서 켜지고 접속 대상을 어떻게 정하고 제한하는가?
conditional: false
boundary: 운영자가 정한 원격 분석 호스트 접속도 서버 코드가 여는 연결이면 I01·I03·I04에서 보고, 그 호스트에서 실행하는 방식은
  T04에서 봄
scope: 서버 코드가 스스로 여는 외부 연결(외부 API 질의, 원격 저장소·자료 갱신, 원격 백엔드 접속)이다. 서버가 실행한 분석 도구가 스스로
  여는 통신은 I02에서 보고, 서버 밖 설치 명령의 내려받기는 보지 않는다. 그런 연결이 구현에 적은 활성화 조건·목적지 결정·제한을 거치지 않는
  도구·인자·설정이 있거나, 설명과 다른 목적지로 나가거나, 확인하지 못한 경로가 있으면 †를 붙인다.
not_implemented: 서버가 외부에 연결하는데 그 연결을 켜는 조건도 목적지를 정하는 규칙도 코드·설정에서 알아낼 수 없다.
not_applicable: 서버 코드가 스스로 외부에 연결하지 않는다. 분석 도구가 스스로 여는 통신만 있으면 I02에서 본다.
details:
- id: I01.01
  name: 명시적 설정으로 활성화
  include: 운영자가 설정 파일·환경변수·시작 인자로 외부 연동을 켜야 연결이 생긴다.
  exclude: 자격증명 값이 있는 것만으로 켜지면 I01.02다.
- id: I01.02
  name: 자격증명 존재로 활성화
  include: 외부 서비스의 자격증명(API 키 등)이 설정돼 있으면 그 서비스로 요청하고 없으면 요청하지 않는다.
  exclude: 자격증명을 어디에 두고 응답·기록에서 어떻게 빼는지는 I04에서 본다.
- id: I01.03
  name: 기본 활성화
  include: 켜는 설정이나 자격증명 없이 기본으로 외부에 연결한다.
  exclude: 끄는 설정이 있는지와 설치 상태(자산 유무·쓰기 권한)에 따라 건너뛰는 조건은 원고 구현에 적는다.
- id: I01.04
  name: 호출별 선택
  include: 연동을 쓸지, 어느 외부 서비스를 쓸지를 호출 인자로 호출마다 고른다.
  exclude: 접속할 호스트·URL 자체를 인자로 받으면 I01.07이다.
- id: I01.05
  name: 고정 목적지
  include: 목적지 주소를 코드에 고정해 설정이나 호출 인자로 바꾸지 못한다.
  exclude: 인자 값이 고정 주소의 경로·질의 값에만 들어가는 것은 목적지 지정으로 세지 않는다.
- id: I01.06
  name: 설정으로 목적지 지정
  include: 목적지를 운영자 설정(설정 파일·환경변수·설치된 자산의 원격 주소 등)이 정하고 호출 인자로는 바꾸지 못한다.
  exclude: 코드에 기본값이 있어도 설정으로 바꿀 수 있으면 여기에 둔다. 설정한 목록 밖을 거부하면 I01.09에도 연결한다.
- id: I01.07
  name: 호출자가 목적지 지정
  include: 모델이 호출 인자로 접속할 호스트·URL을 정한다.
  exclude: 허용 목록으로 좁히면 I01.09에도 연결한다.
- id: I01.08
  name: 동적 탐색
  include: 서버가 실행 중에 접속 대상을 찾아낸다(서비스 탐색, 응답에 든 다음 주소, 클러스터 노드 목록 등).
  exclude: 설정에 적은 목록을 차례로 쓰는 것은 I01.06이다.
- id: I01.09
  name: 목적지 허용 목록
  include: 서버가 허용한 호스트·주소 목록을 두고 그 밖의 목적지로 가는 연결을 거부한다.
  exclude: 코드에 주소를 고정했을 뿐 목록 대조가 없으면 I01.05다.
