---
id: T08
name: 실행 종료 판별
question: 실행의 성공, 실패, 시간 초과, 부분 완료, 비동기 완료를 구별하는 방식을 분류합니다.
conditional: false
boundary: 알아차린 상태를 응답으로 알리는 것은 R03에서, 기록에 남기는 것은 L02에서, 수집 대상과 시각, 누락 기록은 E01에서 봅니다.
scope: 서버가 실행하는 외부 프로그램, 라이브러리 분석 호출, 비동기 작업이 적용 범위입니다. 이 셀은 서버가 실행 결과를 알아차리는지를 봅니다.
not_implemented: 분석 실행(외부 프로그램, 라이브러리 호출, 비동기 작업)이 있는데 종료 코드, 시간 제한, 출력, 예외 중 어느 것으로도
  성공과 실패를 구분하지 않는 경우입니다.
not_applicable: 서버가 분석을 실행하지 않고 이미 저장된 자료를 조회만 하는 경우입니다. 서버 프로세스 안에서 라이브러리 호출만 하는
  서버는 비적용이 아니며 이 셀을 적용합니다.
details:
- id: T08.01
  name: 종료 코드 확인
  include: 서버가 외부 프로그램의 종료 코드를 보고 0이 아니면 실패로 다루는 경우입니다. 종료 코드가 0이 아니고 출력도 없을 때만 실패로
    보는 경우도 해당합니다.
  exclude: 언마운트나 임시 파일 삭제 같은 정리용 실행은 해당하지 않습니다.
- id: T08.02
  name: 시간 제한·종료 신호 처리
  include: 서버가 실행에 시간 제한을 두고 제한을 넘으면 실행을 끊어 시간 초과로 구별하는 경우입니다. 끊기 전에 나온 출력을 부분 결과로 따로
    다루거나 시간 초과된 작업을 다시 실행하는 것도 해당합니다.
  exclude: 시간 초과 뒤에 하위 작업이나 원격 작업의 최종 상태를 다시 조회하는 경우는 T08.05에서 봅니다.
- id: T08.03
  name: 오류·출력 내용 판독
  include: 서버가 출력을 읽어 실패, 빈 결과, 부분 결과를 구분하는 경우입니다. 출력이 비었는지, 형식(JSON, CSV, 헤더만 있음)이
    맞는지, 오류 문구가 있는지를 봅니다.
- id: T08.04
  name: 입력별 부분 완료 집계
  include: 입력, 플러그인, 하위 작업이 여럿인 호출에서 서버가 항목마다 성공, 실패, 생략을 구분하고 그 개수를 세는 경우입니다.
  exclude: 항목을 구분하지 않고 전체의 성공과 실패만 정하는 경우는 해당하지 않습니다.
- id: T08.05
  name: 비동기 최종 상태 조회
  include: 서버가 배경 작업의 상태(대기, 실행, 완료, 실패)를 두고 최종 상태를 조회해 정하는 경우입니다.
  exclude: 시작 응답만 돌려주고 최종 상태를 볼 수 없는 경우는 해당하지 않습니다. 러너가 사라진 작업을 조회 없이 완료나 실패로 정하는 경우는 해당하지 않습니다.
- id: T08.08
  name: 라이브러리 예외를 실패로 구별
  include: 서버 프로세스 안에서 부른 분석 라이브러리가 낸 예외를 서버가 처리해 그 호출이나 항목을 실패로 정하는 경우입니다.
  exclude: 예외를 처리하지 않고 호출 밖으로 내보내는 경우는 해당하지 않습니다.
  seen_in:
  - regipy
- id: T08.07
  name: 수집 작업의 시작·종료·취소 상태 추적
  include: 단말에서 증거를 모으는 수집 작업마다 시작, 진행, 종료, 실패, 취소 상태를 조회할 수 있는 경우입니다. 상태를 서버가 직접 두든
    수집 백엔드의 상태를 조회하든 해당합니다. 취소 같은 일부 상태를 다루지 않아도 해당합니다.
  exclude: 수집 기능이 없는 서버는 이 상세를 보지 않습니다.
