---
id: T10
name: 도구 명세 구성
question: 서버는 모델이 보는 도구 이름, 설명, 입력 schema, annotation, 사용법 문서를 무엇으로 만들고 실행 설정이나 클라이언트에
  따라 어떻게 바꾸나요? 그 명세가 실제 처리와 맞나요?
conditional: false
boundary: 도구를 목록에서 빼거나 호출을 막는 것은 이 셀이 아니라 T02에서 봅니다. 명세에 적힌 절차, 해석 주의, 지시 무시 안내의 내용은
  P02.01, R04, R07에서 봅니다. 처리기가 모르는 인자를 거부하는지는 T01에서 봅니다.
scope: 서버가 모델에게 노출하는 MCP 명세가 적용 범위입니다. 도구 목록의 이름, 설명, 입력 schema, annotation, 목록 변경
  알림과 도구 사용법을 알리는 리소스와 프롬프트가 여기에 포함됩니다.
not_implemented: 없습니다. 도구를 노출하는 MCP 서버는 도구 목록에 이름과 입력 schema를 반드시 내보냅니다.
not_applicable: 없습니다. 모든 서버에 적용합니다.
details:
- id: T10.01
  name: 처리 함수에서 명세 생성
  include: SDK가 처리 함수의 서명과 주석에서 입력 schema와 설명을 만들어 명세와 처리기가 같은 정의에서 나오는 경우입니다.
  exclude: 서명에 없는 인자를 받는 묶음 도구는 T10.03에서 봅니다.
- id: T10.02
  name: 처리기와 따로 둔 명세
  include: 입력 schema나 설명을 처리 코드와 다른 곳(코드 안의 표, 손으로 쓴 schema)에 두는 경우입니다.
  exclude: SDK가 처리 함수의 서명과 주석에서 명세를 만드는 경우는 T10.01에서 봅니다.
- id: T10.03
  name: 묶음 도구의 연산별 인자를 schema가 구분하지 않음
  include: 연산 이름이나 코드를 받는 도구 하나가 여러 연산을 실행하고 입력 schema가 연산별 인자를 구분하지 않는 경우입니다.
  exclude: 문서에 적힌 절차의 내용은 P02.01에서, 서버가 연산별 인자를 대조하는지는 T01에서 봅니다.
- id: T10.04
  name: 실행 설정·클라이언트별 명세 변경
  include: 사용자 설정이나 클라이언트 등록 설정에 따라 서버가 도구 설명이나 schema를 줄이거나 바꾸는 경우입니다.
  exclude: 그 때문에 빠지는 주의나 지시 무시 안내는 R04와 R07에서 봅니다.
- id: T10.05
  name: 등록 이름 변환
  include: 서버가 namespace 접두어를 붙이거나 중복 접두어를 떼는 등 도구의 등록 이름을 바꾸는 경우입니다.
  exclude: 클라이언트가 붙이는 이름 규칙은 해당하지 않습니다.
- id: T10.06
  name: 도구 annotation 표시
  include: 도구 목록에 `readOnlyHint`, `destructiveHint` 같은 annotation을 싣는 경우입니다.
  exclude: annotation은 클라이언트에 주는 힌트이므로 호출 제한(T02), 승인(T03), 원본 보호(E03)로 인정하지 않습니다.
- id: T10.07
  name: 실행 중 목록 변경 알림
  include: 서버가 `tools/list_changed`를 선언하고 실행 중에 알림을 보내는 경우입니다.
  exclude: 목록을 실제로 바꿔 도구를 숨기는 것은 T02.05에서 봅니다.
