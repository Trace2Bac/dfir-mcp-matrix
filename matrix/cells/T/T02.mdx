id: T02
name: 실행 허용 범위 제한
question: 모델이 부를 수 있는 작업과 고를 수 있는 명령, 플러그인, 질의를 서버가 어떻게 제한하나요?
conditional: false
boundary: 모델이 넘긴 인자가 옵션으로 읽히지 않게 막는 검사도 이 셀에서 봅니다. 조사 상태에 따라 호출을 거부하는 경우는 T03에서 봅니다.
  도구의 이름, 설명, schema, annotation을 만들거나 바꾸기만 하고 목록이나 호출을 바꾸지 않는 경우는 T10에서 봅니다.
scope: 모델이 고르는 도구와 작업, 그리고 서버가 외부 도구나 백엔드에 넘기는 명령, 플러그인, 질의가 적용 범위입니다.
not_implemented: 모델이 부를 수 있는 작업과 고를 수 있는 명령, 플러그인, 질의를 서버가 좁히지 않는 경우입니다. 모델이 명령 문자열
  전체를 정하고 서버가 그대로 실행하는 경우, 도구 설명으로 안내만 하는 경우도 미구현으로 봅니다.
not_applicable: 없습니다. 모든 서버에 적용합니다.
details:
- id: T02.01
  name: 시작 설정으로 등록 제외
  include: 사용자가 서버 시작 설정으로 도구나 작업을 등록하지 않아, 모델에게 보이지 않게 하는 경우입니다. 시작 설정은 실행 인자, 환경변수,
    설정 파일을 말합니다.
  exclude: 코드 상수로 정한 연산·플러그인 목록과 대조하는 경우는 T02.07에서 봅니다. 클라이언트 쪽에서 정하는 경우는 T02.03에서 봅니다.
- id: T02.02
  name: 호출 시 활성 설정 검사
  include: 도구는 등록해 두지만, 호출될 때 사용자 설정으로 켜져 있는지 확인하고 꺼져 있으면 거부하는 경우입니다.
  exclude: 설정이 아니라 앞선 호출의 상태를 보고 거부하는 경우는 여기가 아니라 T03에서 봅니다.
- id: T02.03
  name: 클라이언트 도구 선택
  include: 서버는 호출을 막지 않고, 저장소가 함께 제공하는 클라이언트나 설정이 허용·거부 목록으로 모델이 사용할 수 있는 도구를 정하는
    경우입니다. 확인 없이 쓰게 하는 도구와 쓰지 못하게 막는 도구를 원고의 구현 단락에 씁니다.
  exclude: 서버 자체에는 검사가 없어서, 다른 클라이언트로 붙으면 제한이 적용되지 않는다는 점을 원고의 구현 단락에 씁니다. 저장소에 그런
    클라이언트 구성이 없으면 이 상세에 연결하지 않습니다. 같은 설정이 서버가 감싼 분석 도구나 서버 출력에 클라이언트 자체 도구로
    직접 닿는 경로를 막는지는 T02.10에서 봅니다.
- id: T02.10
  name: 클라이언트 자체 도구 우회 차단
  include: 저장소가 함께 제공하는 클라이언트 설정이나 훅이, 서버가 감싼 분석 도구를 클라이언트 자체 도구(셸 등)로 직접 실행하거나 서버가 관리하는 출력과 기록을 직접 읽고 쓰는 것을 막는 경우입니다. 무엇을 막고 무엇을 열어 두는지 원고의 구현 단락에 씁니다.
  exclude: 서버 자체에는 검사가 없어 다른 클라이언트로 붙으면 적용되지 않는다는 점을 원고의 구현 단락에 씁니다. 클라이언트 자체 도구의 사용을 기록만 하고 막지 않는 동작은 구현으로 세지 않고 원고에 사실로 씁니다. 클라이언트가 MCP 도구 호출을 별도로 기록하는 방식은 L01.10에서 봅니다. 모델이 사용할 수 있는 도구 목록은 T02.03에서 봅니다. 클라이언트 자체 도구는 클라이언트 프로그램에 들어 있는 도구(셸, 파일 읽기·쓰기, 웹 요청 등)를 말합니다. 사용자가 세션에 더 붙인 다른 MCP 서버는 여기에 속하지 않으며, 그 서버가 세션에 남는지와 이 설정이 그 도구를 막는지를 원고의 구현 단락에 씁니다.
- id: T02.04
  name: 외부 플랫폼 권한에 위임
  include: 서버는 작업을 좁히지 않고, 백엔드 플랫폼의 계정이나 역할 권한이 허용한 작업만 실행되도록 맡기는 경우입니다.
  exclude: 플랫폼 권한이 실제로 작업을 막는지 확인하지 못했으면 원고의 한계 단락에 "실제 보호 미확인"이라고 씁니다.
- id: T02.05
  name: 조사 상태로 도구 노출 조정
  include: 조사 상태나 단계에 따라 서버가 모델에게 보이는 도구 목록을 바꾸는 경우입니다.
  exclude: 보이는 도구는 그대로 두고 호출만 거부하는 경우는 여기가 아니라 T03.01이나 T03.02에서 봅니다.
- id: T02.06
  name: 고정 명령·템플릿
  include: 서버 코드가 외부 도구나 백엔드의 명령과 인자 배열(또는 질의 틀)을 미리 정해 두고, 모델은 그 안의 값만 채우는 경우입니다.
  exclude: 셸을 거치는지는 T04에서 봅니다.
- id: T02.07
  name: 연산·플러그인 허용 목록
  include: 모델이 고르는 연산, 플러그인, 모드를 서버 코드의 목록과 대조하고, 목록에 없으면 거부하는 경우입니다. 목록에 없는 값을 거부하지
    않고 목록 안의 기본 연산으로 바꾸는 경우도 해당하며, 그 사실을 원고에 씁니다.
  exclude: 설치된 도구가 지원하는 값과 대조하는 경우는 T01.01에서 봅니다. 목록 안에 자유 질의를 받는 항목이 있으면, 그 질의는 T02.08에서
    봅니다.
- id: T02.08
  name: 질의 구조·연산 검사
  include: 모델이 쓴 질의, 명령, 룰의 구조와 연산을 서버 코드가 검사하면 해당합니다. 서버가 실행 엔진의 제한 기능을 걸어 허용한 연산만
    통과시키는 경우도 해당합니다. 제한 기능은 SQLite authorizer, 외부 도구의 sandbox 설정 같은 것입니다.
  exclude: 문법 오류만 거르는 검사는 해당하지 않습니다.
- id: T02.09
  name: 사전 등록된 백엔드 작업만 호출
  include: 서버가 미리 등록한 백엔드 작업만 호출하고, 모델은 그중에서 고르기만 하는 경우입니다. 등록한 작업은 아티팩트, 저장된 질의,
    작업 이름 같은 것입니다.
  exclude: 모델이 백엔드 작업의 정의 자체를 보내는 경우는 해당하지 않습니다. 목록이 서버 코드 안의 연산 목록이면 T02.07에서 봅니다.
