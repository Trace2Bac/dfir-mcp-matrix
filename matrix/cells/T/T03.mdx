name: 실행 조건 확인
question: 서버는 도구 인자 밖의 조건으로 호출을 허용할지와 언제 실행할지를 어떻게 정하나요? 그런 조건은 앞선 작업이나 판정 상태, 모델
  밖 승인자의 승인, 원격 호출자의 신원, 서버의 실행 자원 상태입니다.
conditional: false
scope: 도구 인자 밖의 조건을 걸어 둔 호출이 적용 범위입니다. 그런 조건은 앞선 호출이 만든 상태, 모델 밖 승인자의 승인, 원격 호출자의
  신원, 서버의 실행 자원 상태입니다. 도구 명세나 설명에 선행 조건이나 승인을 적어 둔 호출도 포함합니다. 다음 경우에는 예외 표시를 붙입니다. 이런
  호출인데도 검사를 건너뛰는 도구, 인자, 모드, 설정이 있는 경우, 검사 중에 오류가 났을 때 별도 처리 없이 통과시키는 경우, 조건이 실제 사실과 다르게
  채워지는 경우입니다.
not_implemented: 도구 인자 밖의 조건으로 호출을 막거나 미루는 코드가 없는 경우입니다. 서버 지침이나 도구 설명으로 순서나 승인을 안내만
  하는 경우, 도구 annotation만 있는 경우도 미구현으로 봅니다.
not_applicable: 없습니다. 모든 서버에 적용합니다.
details:
- id: T03.01
  name: 선행 결과 존재 대조
  include: 서버가 앞선 호출이 만든 결과가 있는지 확인하고, 없으면 호출을 거부하는 경우입니다. 그런 결과는 보유 능력, 적재한 입력, 인용한
    호출 기록, 기준선 파일 같은 것입니다.
  exclude: 결과를 어디에 두고 얼마나 남기는지는 P04에서 봅니다. 결과가 통과 판정인지까지 확인하는 경우는 T03.03에서 봅니다.
- id: T03.02
  name: 조사 단계 검사
  include: 서버가 조사 단계를 두고, 지금 단계에서 허용하지 않는 호출이나 조건을 채우지 않은 단계 이동을 거부하는 경우입니다.
  exclude: 단계를 안내하거나 보여 주기만 하는 경우는 P02와 P03에서 봅니다.
- id: T03.03
  name: 앞선 점검·판정 결과 대조
  include: 앞선 점검이나 검토 호출이 낸 판정이 통과인지 확인하고, 통과가 아니면 호출을 거부하는 경우입니다. 판정은 보고 준비 완료, 검토
    통과 같은 것입니다.
  exclude: 판정을 내리고 심사하는 방식은 D07에서 봅니다.
- id: T03.04
  name: 반복 호출 제한
  include: 같은 호출이 같은 결과를 정해 둔 횟수만큼 되풀이하면, 서버가 다음 호출을 거부하는 경우입니다.
  exclude: 알리기만 하고 막지 않는 경우는 해당하지 않습니다.
- id: T03.05
  name: 모델이 채우는 확인 값 검사
  include: 서버가 호출 인자로 받은 완료 표시나 확인 값(`confirm` 등)을 조건으로 삼아 호출을 막는 경우입니다.
  exclude: 서버가 그 값을 앞선 호출의 상태와 대조하는 경우는 T03.01~T03.03에서 봅니다. 이 값은 같은 요청 안에서 모델이 직접 채울
    수 있습니다. 그래서 선행 작업을 확인한 것이나 별도 승인자가 동의한 것으로 인정하지 않습니다. 모델이 채운 값을 모델 밖의 승인자가 남긴 기록과
    대조하는 경우는 T03.06에서 봅니다.
- id: T03.06
  name: 승인 토큰·서명 대조
  include: 모델 밖의 승인자가 낸 토큰, 서명, 기록이 있는지 서버가 대조하고, 없으면 호출을 거부하는 경우입니다. 모델 밖의 승인자는 운영자나
    외부 승인 경로를 말합니다. 승인자 기록은 저장소가 함께 제공하는 클라이언트 훅이나 플러그인이 운영자 입력을 서버가 읽는 기록에 남긴
    것도 인정합니다. 그 기록을 대조하는 일은 서버가 해야 합니다. 그런 구성이 없는 클라이언트로 붙었을 때 서버가 어떻게 동작하는지는 원고의
    구현 단락에 씁니다.
  exclude: 모델이 같은 대화 안에서 만들 수 있는 값이면 여기가 아니라 T03.05에서 봅니다. 승인한 내용이 요청과 맞는지는 T03.07에서
    봅니다. 서버가 서버 쪽 자료로 조치를 분류해 일부 분류에만 승인을 요구하면, 승인을 요구하지 않는 분류와 그 분류의 면제를 켜고 끄는 설정은
    적용 범위로 보고 원고의 구현 단락에 씁니다. 모델이 고른 인자나 모델이 바꿀 수 있는 파일로 분류가 바뀌는 경우, 분류 자료나 설정을 읽지
    못할 때 승인을 면제하는 경우에는 예외 표시를 붙입니다.
- id: T03.07
  name: 승인 내용과 요청 대조
  include: 승인에 묶인 작업, 대상, 인자가 실제 요청과 같은지 대조하고, 다르면 호출을 거부하는 경우입니다. 승인 기록을 요청의 식별자로
    정한 위치에 저장하고 실행할 때 같은 식별자로 찾는 것도 대조로 봅니다. 승인에 묶은 요소와 묶지 않은 요소(대상 호스트 등)를 원고의 구현
    단락에 씁니다.
  exclude: 승인이 있는지만 확인하는 경우는 T03.06에서 봅니다.
- id: T03.08
  name: 승인 만료·소모·재승인
  include: 승인에 유효 시간이나 사용 횟수를 두거나, 요청이 바뀌면 승인을 다시 받게 하는 경우입니다.
  exclude: T03.06이나 T03.07이 있을 때만 이 상세에 연결합니다.
- id: T03.09
  name: 원격 호출자 인증
  include: 원격 MCP 연결에서 서버가 프로토콜 인증, API key, 서명, 세션으로 호출자를 확인하는 경우입니다.
  exclude: stdio 서버를 실행하는 프로세스 권한은 이 셀에서 보지 않습니다. stdio 서버에 이 항목이 없는 것을 결함으로 보지 않습니다.
    서버가 백엔드에 접속할 때 쓰는 자격증명은 I04에서 봅니다.
- id: T03.10
  name: 앞단 게이트웨이 인증에 위임
  include: 서버는 호출자를 확인하지 않고, 저장소가 지원하는 배포 구성의 앞단 프록시나 게이트웨이 인증에 맡기는 경우입니다.
  exclude: 그런 배포 구성이 저장소에 없으면 이 상세에 연결하지 않습니다.
- id: T03.11
  name: 실행 자원 사용률 확인
  include: 서버가 실행 전에 메모리나 CPU 같은 자원 사용률을 확인하고, 기준을 넘으면 실행을 미루거나 거부하는 경우입니다.
  exclude: 정해 둔 시간을 기다린 뒤 실행하는 것은 설계된 동작이므로 원고의 구현 단락에 씁니다. 다음 경우에는 예외 표시를 붙입니다. 자원 상태를
    읽지 못했을 때 확인 없이 통과시키는 경우, 설정으로 이 검사를 끌 수 있는 경우입니다. 동시에 진행 중인 실행 수를 세어 제한하는 경우는
    T03.12에서 봅니다. 분석 도구 자체의 시간 제한은 T08.02에서 봅니다.
- id: T03.12
  name: 동시 실행 수 제한
  include: 서버가 세마포어, 용량 제한기, 큐, 스레드 풀로 동시에 진행 중인 분석 실행 수를 정해 둔 개수로 제한하고, 자리가 없으면 기다리게 하는
    경우입니다. 모든 실행을 하나씩 차례로 실행하는 큐도 여기에 해당합니다. 제한이 적용되는 단위(서버 프로세스, 세션, 요청마다 만든 서버
    객체), 한도를 정하는 주체(운영자 설정, 코드 고정값, 호출 인자), 같은 한도를 나눠 쓰지 않는 별도 풀을 원고의 구현 단락에 씁니다.
  exclude: 자원 사용률을 읽는 경우는 T03.11에서, 특정 도구만 따로 차례로 실행하는 순서 제약은 T03.13에서 봅니다. 다음 경우에는 예외 표시를
    붙입니다. 제한이 적용되는 프로그램을 제한 밖에서 실행하는 경로나 별도 풀이 있는 경우, 기본 구성이나 설정으로 제한이 꺼지는 경우, 모델이
    넘긴 인자로 한도를 정하거나 높일 수 있는 경우, 제한을 준비하다 오류가 나면 제한 없이 실행하는 경우입니다.
- id: T03.13
  name: 특정 도구 차례 실행
  include: 서버가 자원을 많이 쓰는 특정 도구를 다른 작업과 겹치지 않게, 같은 묶음의 병렬 작업이 끝난 뒤 하나씩 실행하는 경우입니다. 어느
    도구가 대상이고 어느 호출 안에서 적용되는지 원고의 구현 단락에 씁니다.
  exclude: 모든 실행을 한 큐로 차례로 실행하는 경우는 T03.12에서 봅니다. 결과를 입력 순서로 돌려주는 것은 해당하지 않습니다. 같은 도구를
    이 순서 제약 없이 실행하는 다른 경로가 있으면 예외 표시를 붙입니다.
