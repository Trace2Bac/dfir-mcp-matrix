---
id: T08
name: 실행 종료 판별
question: 성공·실패·시간 초과·부분 출력·비동기 완료를 어떻게 구별하는가?
conditional: false
scope: 서버가 실행하는 외부 프로그램·라이브러리 분석 호출·비동기 작업 가운데 구현에 적은 판별 방식이 걸리는 실행이다. 서버가 실행 결과를
  알아차리는지 보고, 알아차린 상태를 응답에 알리는 것은 R03, 기록에 남기는 것은 L02에서 본다. 그 실행에서 실패·시간 초과·부분 출력을
  아무 표시 없이 성공으로 넘기는 경로, 시간 제한이 걸리지 않거나 끊은 뒤에도 실행이 계속되는 경로, 집계·최종 상태가 실제 결과와 다르게 정해지는
  경우는 †를 붙인다. 판별 방식을 쓰지 않는 다른 실행은 †가 아니라 구현에 적는다.
not_implemented: 분석 실행(외부 프로그램·라이브러리 호출·비동기 작업)이 있는데 종료 코드·시간 제한·출력·예외 어느 것으로도 성공과
  실패를 가르지 않는다.
not_applicable: 서버가 분석을 실행하지 않고 이미 저장된 자료를 조회만 한다. 서버 프로세스 안 라이브러리 호출만 하는 서버도 이 셀에
  적용한다.
details:
- id: T08.01
  name: 종료 코드 확인
  include: 외부 프로그램의 종료 코드를 보고 0이 아니면 실패로 다룬다. 출력이 없을 때만 실패로 보는 조건도 여기에 두고 구현에 적는다.
  exclude: 정리용 실행(언마운트·임시 파일 삭제)은 세지 않는다. 종료 코드가 0이 아닌데 출력이 있어 성공으로 넘기면서 실패·부분 표시를
    붙이지 않으면 †다.
- id: T08.02
  name: 시간 제한·종료 신호 처리
  include: 실행에 시간 제한을 두고 넘으면 끊어 시간 초과로 구별한다. 끊기 전에 나온 출력을 부분 결과로 따로 다루거나 시간 초과 작업을
    다시 실행하는 것도 여기에 둔다.
  exclude: 시간 초과 뒤 하위·원격 작업의 최종 상태를 다시 조회하면 T08.06이다.
- id: T08.03
  name: 오류·출력 내용 판독
  include: 출력이 비었는지, 형식(JSON·CSV·헤더만 있음)이 맞는지, 오류 문구가 있는지 읽어 실패·빈 결과·부분 결과를 가린다.
  exclude: 종료 코드만 보면 T08.01이다. 판독한 상태를 응답에 알리는 방식은 R03이다.
- id: T08.04
  name: 입력별 부분 완료 집계
  include: 입력·플러그인·하위 작업이 여럿인 호출에서 항목마다 성공·실패·생략을 가르고 개수를 센다.
  exclude: 그 목록을 응답에 싣는 방식은 R03.03에서 본다. 항목을 가르지 않고 전체 성공·실패만 정하면 제외한다.
- id: T08.05
  name: 비동기 최종 상태 조회
  include: 배경 작업을 시작한 뒤 작업마다 대기·실행·완료·실패 상태를 두고 그 최종 상태를 조회하는 도구·경로를 둔다.
  exclude: 시작 응답만 돌려주고 최종 상태를 볼 수 없으면 제외한다. 작업을 맡은 러너가 사라진 뒤 상태를 다시 확인하면 T08.06이다.
- id: T08.06
  name: 러너 소실·시간 초과 뒤 최종 상태 재확인
  include: 작업을 맡은 러너·연결이 사라지거나 시간 초과로 기다림을 멈춘 뒤 하위·원격 작업의 실제 최종 상태를 다시 조회해 정한다.
  exclude: 같은 작업을 다시 실행하는 재시도는 T08.02다. 러너가 사라진 작업을 조회 없이 완료나 실패로 정하면 세지 않는다.
- id: T08.08
  name: 라이브러리 예외를 실패로 구별
  include: 서버 프로세스 안에서 부른 분석 라이브러리가 낸 예외를 잡아 그 호출이나 항목을 실패로 정한다.
  exclude: 예외를 잡지 않고 호출 밖으로 내보내면 제외한다. 예외를 잡고 아무 표시 없이 빈 결과나 성공으로 넘기면 †다. 외부 프로그램의
    종료 코드는 T08.01이다.
  seen_in:
  - regipy
- id: T08.07
  name: 수집 작업의 시작·종료·취소 상태 추적
  include: 단말에서 증거를 모으는 수집 작업마다 시작·진행·종료·취소·실패 상태를 두고 조회한다.
  exclude: 수집 기능이 없는 서버는 이 상세를 보지 않는다. 수집 대상·시각과 누락 기록은 E01이다.
