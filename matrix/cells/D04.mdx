---
id: D04
name: 출력 경로 제한
question: 생성·수정·삭제 대상의 경로를 어떻게 정하고 제한하며, 같은 작업을 다시 할 때 앞선 파생물을 덮어쓰지 않게 어떻게 구분하는가?
conditional: false
boundary: 원본 증거와의 충돌 검사는 E03
scope: 서버가 파생물을 만들거나 고치거나 지우는 대상 경로와, 같은 작업을 다시 할 때 앞 파생물과의 구분이다. 서버 코드가 정하는 목적지와
  서버가 부르는 외부 도구가 정하는 목적지가 모두 든다. 상세마다 그 방식이 걸린다고 구현에 적은 도구·인자가 적용 범위다. 그 범위 안에서 검사가
  걸리지 않는 이름·형식·링크, 외부 도구가 목적지를 정해 확인하지 못한 경로, 인자로 앞 파생물과 겹치게 할 수 있는 경로, 남긴 앞 결과를 읽는
  쪽에서 가리지 못하는 경우가 있으면 †를 붙인다. 방식이 없는 다른 도구는 †가 아니라 구현에 적는다.
not_implemented: 생성·수정·삭제 대상 경로를 호출 인자로 받아 그대로 쓰고, 다시 실행할 때 앞 파생물과 구분하지도 않는다.
not_applicable: 서버가 파일·DB에 아무것도 만들거나 고치거나 지우지 않는다.
details:
- id: D04.01
  name: 서버가 출력 위치 결정
  include: 생성 위치를 호출 인자가 아니라 서버가 정한 폴더와 이름 규칙으로 정한다. 호출 인자는 경로 구분자가 없는 이름 한 조각으로만
    들어간다.
  exclude: 호출 인자로 받은 목적지를 허용 폴더와 대조하면 D04.02다. 원본 증거와 겹치는지 검사하는 것은 E03이다.
- id: D04.02
  name: 실제 경로와 허용 폴더 대조
  include: 호출 인자로 받은 목적지를 링크와 `..`를 푼 실제 경로로 바꿔 허용 폴더 안인지 대조하고 대조한 그 경로를 쓴다.
  exclude: 실제 경로를 풀지 않고 문자열만 보는 이름 검사는 D04.04다.
- id: D04.03
  name: 파생물 ID로만 수정·삭제
  include: 저장된 파생물을 고치거나 지우는 도구가 경로가 아니라 서버가 매긴 ID로 대상을 고른다.
  exclude: 누가 지우고 흔적이 남는지는 P05다.
- id: D04.04
  name: 이름·확장자·충돌 검사
  include: 목적지 이름(호출 인자, 압축 항목·이미지 안의 이름)에서 경로 구분자·`..`·절대 경로·제어 문자·확장자를 문자열로 검사하거나
    이미 있는 이름과 겹치는지 보고 거부하거나 건너뛴다.
  exclude: 실제 경로로 풀어 허용 폴더와 대조하면 D04.02다. 겹칠 때 앞 결과를 돌려주거나 덮어쓸지 고르게 하면 D04.08이다.
- id: D04.05
  name: 실행 ID별 위치
  include: 실행마다 받은 ID(호출 ID·작업 ID)로 폴더나 이름을 나눠 파생물을 둔다.
  exclude: 입력마다 다른 이름이거나 시각·번호를 붙이면 D04.06이다.
- id: D04.06
  name: 유일 파일명·시각·번호
  include: 파생물 이름에 시각·번호·난수나 입력마다 다른 값(경로 해시 등)을 넣어 다른 작업의 파생물과 겹치지 않게 한다.
  exclude: 실행 ID로 나누면 D04.05다. 호출이 끝나면 지우는 임시 폴더 이름만 유일하면 연결하지 않는다.
- id: D04.07
  name: 버전·이력 보존
  include: 같은 이름의 파생물을 다시 만들 때 앞 결과를 지우지 않고 버전·시각과 함께 남겨 둘을 가릴 수 있다.
  exclude: 남기기만 하고 읽는 도구가 두 결과를 섞어 돌려주면 †를 붙인다.
- id: D04.08
  name: 덮어쓰기 선택·충돌 감지
  include: 같은 결과가 이미 있으면 알아채 다시 만들지 않거나 덮어쓸지를 호출 인자로 고르게 한다.
  exclude: 알리지 않고 덮어쓰는 도구는 구현에 적는다.
