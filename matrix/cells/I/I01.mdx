id: I01
name: 외부 연동 대상 관리
question: 서버의 외부 연동은 어떤 조건에서 켜지고, 접속 대상은 어떻게 정하고 제한하나요?
conditional: false
boundary: 운영자가 정한 원격 분석 호스트에 접속하는 것도, 서버 코드가 여는 연결이라면 I01, I03, I04에서 봅니다. 그 호스트에서
  분석을 실행하는 방식은 T04에서 봅니다. 서버 코드가 외부 연결을 하려고 실행하는 클라이언트 프로그램(ssh, 평판 조회 프로그램)의
  그 연결도 I01에서 봅니다. 그 프로그램이 의도한 연결 밖에서 스스로 하는 통신(업데이트 확인 등)은 I02에서 봅니다(결정 0019).
scope: 서버 코드가 스스로 여는 외부 연결이 적용 범위입니다. 외부 API 질의, 원격 저장소나 자료의 갱신, 원격 백엔드 접속이 그 예입니다.
  서버가 실행한 분석 도구가 스스로 여는 통신은 I02에서 봅니다. 서버 밖에서 실행하는 설치 명령의 내려받기는 보지 않습니다. 이런 연결에서 다음
  경우에는 예외 표시를 붙입니다. 원고의 구현 단락에 적은 활성화 조건, 목적지 결정, 제한을 거치지 않는 도구나 인자, 설정이 있는 경우, 설명과 다른
  목적지로 나가는 경우, 확인하지 못한 경로가 있는 경우입니다.
not_implemented: 서버가 외부에 연결하는데, 그 연결을 켜는 조건도 목적지를 정하는 규칙도 코드나 설정에서 알아낼 수 없는 경우입니다.
not_applicable: 서버 코드가 스스로 외부에 연결하지 않는 경우입니다. 분석 도구가 스스로 여는 통신만 있으면 I02에서 봅니다.
details:
- id: I01.01
  name: 명시적 설정으로 활성화
  include: 운영자가 설정 파일, 환경변수, 시작 인자로 외부 연동을 켜야만 연결이 생기는 경우입니다.
  exclude: 자격증명 값이 있는 것만으로 켜지는 경우는 I01.02에서 봅니다.
- id: I01.02
  name: 자격증명 존재로 활성화
  include: 외부 서비스의 자격증명(API 키 등)이 설정되어 있으면 그 서비스로 요청하고, 없으면 요청하지 않는 경우입니다.
  exclude: 자격증명을 어디에 두는지, 응답과 기록에서 어떻게 빼는지는 I04에서 봅니다.
- id: I01.03
  name: 기본 활성화
  include: 켜는 설정이나 자격증명이 없어도 기본으로 외부에 연결하는 경우입니다.
  exclude: 끄는 설정이 있는지, 그리고 설치 상태(자산이 있는지, 쓰기 권한이 있는지)에 따라 연결을 건너뛰는 조건은 원고의 구현 단락에
    씁니다.
- id: I01.04
  name: 호출별 선택
  include: 연동을 쓸지, 어느 외부 서비스를 쓸지를 호출할 때마다 호출 인자로 고르는 경우입니다. 운영자 설정에 등록한 대상 가운데
    하나를 이름으로 고르는 경우도 포함합니다.
  exclude: 접속할 호스트나 URL 자체를 인자로 받는 경우는 I01.07에서 봅니다.
- id: I01.05
  name: 고정 목적지
  include: 목적지 주소를 코드에 고정해 두어, 설정이나 호출 인자로 바꿀 수 없는 경우입니다.
  exclude: 인자 값이 고정 주소의 경로나 질의 값에만 들어가는 것은 목적지를 지정한 것으로 인정하지 않습니다.
- id: I01.06
  name: 설정으로 목적지 지정
  include: 목적지를 운영자 설정이 정하고, 호출 인자로는 바꿀 수 없는 경우입니다. 운영자 설정은 설정 파일, 환경변수, 설치된 자산의 원격
    주소 등입니다.
  exclude: 코드에 기본값이 있어도 설정으로 바꿀 수 있으면 여기에 해당합니다. 설정한 목록 밖의 목적지를 거부하면 I01.09에도 연결합니다.
- id: I01.07
  name: 호출자가 목적지 지정
  include: 모델이 호출 인자로 접속할 호스트나 URL을 정하는 경우입니다.
  exclude: 허용 목록으로 범위를 좁히면 I01.09에도 연결합니다. 등록한 이름으로만 고르면 I01.04에서 봅니다.
- id: I01.08
  name: 동적 탐색
  include: 서버가 실행 중에 접속 대상을 찾아내는 경우입니다. 서비스 탐색, 응답에 든 다음 주소, 클러스터 노드 목록 등을 쓰는 방식이
    그 예입니다.
  exclude: 설정에 적은 목록을 차례로 쓰는 경우는 I01.06에서 봅니다.
- id: I01.09
  name: 목적지 허용 목록
  include: 서버가 허용한 호스트나 주소 목록을 두고, 그 밖의 목적지로 가는 연결을 거부하는 경우입니다.
  exclude: 코드에 주소를 고정했을 뿐 목록과 대조하지 않는 경우는 I01.05에서 봅니다.
