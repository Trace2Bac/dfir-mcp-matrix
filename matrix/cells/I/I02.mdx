---
id: I02
name: 분석 도구 통신 차단
question: 서버가 부르는 분석 도구와 의존성이 스스로 여는 통신을 서버가 어떻게 제한하나요?
conditional: false
boundary: 로컬 참조 자료를 쓴다는 것만으로는 통신을 제한한 것으로 인정하지 않습니다.
scope: 서버가 실행하거나 부르는 분석 도구와 라이브러리가 스스로 여는 통신이 적용 범위입니다. 룰이나 심볼, 업데이트 내려받기, 분석 중에 도구가
  스스로 하는 평판 조회, 원격 전송이 그 예입니다. 서버 코드가 일부러 여는 연결은 I01에서 봅니다. 원고의 구현 단락에 적은 실행 경로 안에서 다음 경우에는 예외 표시를 붙입니다.
  그 제한이 빠지는 도구나 인자, 설정이 있는 경우, 제한을 걸지 못해도 그대로 실행하는 경우입니다.
not_implemented: 분석 도구나 라이브러리를 부르는데, 그 통신을 끊거나 끄는 장치가 없는 경우입니다. 갱신이나 조회 인자를 붙이지 않는
  것만으로는 제한으로 인정하지 않고 미구현으로 봅니다.
not_applicable: 서버가 외부 분석 도구나 라이브러리를 부르지 않고, 서버 코드만으로 분석하는 경우입니다.
details:
- id: I02.01
  name: 네트워크 차단
  include: 서버 코드나 저장소가 지원하는 실행 구성이 분석 도구 프로세스의 네트워크를 끊는 경우입니다. 컨테이너 `--network none`,
    network namespace, 방화벽 규칙이 그 예입니다.
  exclude: 문서가 권하기만 하고 서버 코드나 배포 구성에 없는 경우는 해당하지 않습니다.
- id: I02.02
  name: 오프라인 옵션
  include: 분석 도구를 실행할 때 그 도구의 오프라인 옵션이나 갱신 끄기 옵션(`--offline` 등)을 붙이거나, 라이브러리의 오프라인
    설정을 켜는 경우입니다.
  exclude: 갱신이나 조회 인자를 붙이지 않는 것만으로는 해당하지 않습니다.
- id: I02.03
  name: DNS 조회 끄기
  include: 분석 도구가 결과를 만들면서 하는 이름 풀이(역방향 DNS 등)를 끄는 옵션을 붙이는 경우입니다.
  exclude: 도구가 처음부터 이름 풀이를 하지 않는 것은 해당하지 않습니다.
- id: I02.04
  name: 프록시·목적지 제한
  include: 환경변수나 설정으로, 분석 도구 프로세스의 통신이 프록시나 허용한 목적지로만 나가도록 묶는 경우입니다.
  exclude: 서버 코드 자신의 연결 목적지를 제한하는 것은 I01.09에서 봅니다.
