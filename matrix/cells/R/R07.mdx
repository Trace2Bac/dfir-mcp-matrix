name: 증거 내용과 지시 구분
question: 서버가 증거에서 온 글을 모델에게 줄 때, 그 글이 따라야 할 지시가 아니라 데이터라는 것을 어떻게 드러내나요?
conditional: false
scope: 원고의 구현 단락에 연결한 상세의 표시나 안내가 붙는다고 적은 응답이 적용 범위입니다. 그 응답 안에서 표시가 빠지는 경로(예외 처리,
  다른 반환 형식)가 있으면 예외 표시를 붙입니다. 실행 설정이나 클라이언트에 따라 도구 설명이나 서버 지침의 안내가 빠지는 경우에도 예외 표시를
  붙입니다.
not_implemented: 증거 내용과 서버 문구를 아무 표시 없이 평문으로 섞어 돌려주는 경우입니다.
not_applicable: 서버가 증거에서 온 글을 모델에게 돌려주지 않는 경우입니다.
details:
- id: R07.01
  name: JSON 필드 분리
  include: 증거 내용이 구조화된 응답의 필드 값으로, 서버 문구와 따로 들어 있는 경우입니다.
  exclude: 이것을 신뢰할 수 없는 데이터라는 표시로 인정하지는 않습니다. 문자열 값 안에 든 지시도 모델은 글로 읽기 때문입니다.
- id: R07.02
  name: 출처 필드 부여
  include: 결과에 데이터의 출처나 신뢰 수준을 적는 필드를 붙이는 경우입니다.
  exclude: 일부 도구에만 붙는다면 적용 범위를 원고에 씁니다.
- id: R07.03
  name: 경계 태그 표시
  include: 증거에서 온 값을 표시 문자열로 감싸 서버 문구와 구분하는 경우입니다.
  exclude: 서버 문구까지 모두 감싸서 구분이 없는 경우는 해당하지 않습니다. 여는 머리말만 있고 닫는 표시가 없는 경우도 해당하지 않습니다.
- id: R07.04
  name: 경계 태그 위조 무력화
  include: 값 안에 든 표시 문자열을 바꿔, 증거 내용이 경계를 미리 닫지 못하게 하는 경우입니다.
  exclude: R07.03이 있을 때만 이 상세에 연결합니다.
- id: R07.05
  name: 증거 내 지시 무시 안내
  include: 도구 설명, 서버 지침, 응답에서 증거에서 온 글 속의 지시를 따르지 말라고 명시하는 경우입니다. 경계 태그가 있는지와는 관계없습니다.
  exclude: 클라이언트 쪽 프롬프트에 있는 경고는 해당하지 않습니다. 모델이 그 안내를 지키는지는 서버가 확인하지 않습니다. 일부 호출에만
    붙는다면 적용 범위를 적습니다.
- id: R07.06
  name: 지시 문구 필터링·차단
  include: 서버가 지시로 보이는 문구를 지우거나, 그런 결과를 막는 경우입니다.
  exclude: 표시하거나 안내하기만 하는 경우는 해당하지 않습니다.
