# 매트릭스 셀 검토 자료 (2026-09-30)

통합 개편안 10절의 새 셀마다 현행 판정·매트릭스 밖 관찰·경계 규칙을 모았다. 셀을 함께 검토할 때 쓰는 자료이고 결정이 아니다. 개편안·판정 YAML·`규칙적용표.yaml`에서 기계로 뽑았고 현행 판정 문구는 줄였다.

셀마다 보는 순서는 이렇다.
1. **관찰 목적**과 경계가 맞는가.
2. **현행 판정**의 방식 이름에서 구현 방식(상세) 후보를 뽑는다. 어느 방식에도 들지 않으면 `장치 없음` 항목에 둔다.
3. **관찰**과 **흡수 후보**가 상세로 들어올 수 있는가.
4. **현행 규칙**이 새 상세의 포함·제외 기준으로 맞는가.

- **관찰 목적.** 증거를 어떤 식별자·위치·등록 정보로 관리하는가?
- **개편안의 상세 후보.** 증거 ID·등록 목록 / 원래 위치와 저장 위치 기록 / 크기·등록 시각·등록자 기록
- **현행 H3 증거 목록** → C01. 증거 등록·원래 위치·저장 위치를 증거 접근과 연결
  - ChainsawMCP: 경로 일부만, 해시 미구현, 크기 미구현, 시각 일부만, 등록자 미구현 (증거 등록부는 없고 job.json에 증거 경로와 job 시작 시각이 함께 남으며 벌크 입력이면 evidence_paths 목록도 남는다)
  - MyIRTeam: 비적용 (사건 개념이 없어 증거를 등록하는 절차가 없다. 사람이 증거 루트에 파일을 두어도 서버는 기록하지 않는다)
  - agentic-velociraptor-mcp: 경로 미구현, 해시 미구현, 크기 있음, 시각 있음, 등록자 미구현 (증거 등록 절차가 따로 없고 다운로드가 그 역할을 한다)
  - mcp_dfir: 경로 미구현, 해시 미구현, 크기 미구현, 시각 미구현, 등록자 미구현 (증거 등록 절차도 기록도 없다)
  - mulder: 경로 일부만, 해시 일부만, 크기 일부만, 시각 일부만, 등록자 미구현 (evidence_registry에 파일 경로·SHA-256·바이트 크기·등록 시각이 들어간다)
  - regipy: 비적용 (사건 개념이 없어 증거를 등록하는 절차가 없다)
  - sift-kernel: 경로 일부만, 해시 미구현, 크기 미구현, 시각 일부만, 등록자 미구현 (증거 등록부는 없고 mount_evidence가 남기는 호출 기록 항목의 image_path·형식·timestamp가 증거 목록을 대신한다)
  - trudi: 경로 일부만, 해시 일부만, 크기 일부만, 시각 일부만, 등록자 미구현 (증거 등록 절차와 등록부는 없다)
- **매트릭스 밖 관찰.**
  - (함께) MY3 MyIRTeam 「ZIP 안 하이브를 파싱할 때 같은 폴더의 .LOG1·.LOG2만 부속 파일로 받아 하이브 사본 옆에 두고 로그 요청 여부를 응답에 싣는다」

### C02 증거 해시 계산 방식

- **관찰 목적.** 어떤 바이트·범위를 언제 해시하는가?
- **개편안의 상세 후보.** 등록·첫 접근 시 자동 해시 / 요청한 검증 도구에서 해시 / 전체 파일 해시 / 분할·논리 범위 해시
- **현행 C1 증거 해시 계산** → C02. 현행 질문의 목적과 구분을 유지
  - ChainsawMCP: 없음 (증거 파일의 해시를 계산하지 않는다)
  - MyIRTeam: 경우마다 다름 (artifact-forensic 파일 입력, ir-collect 압축 파일, local-forensic 파일 도구는 자동으로 해시한다)
  - agentic-velociraptor-mcp: 자동 (증거 파일을 내려받으면 받은 바이트의 SHA-256을 자동으로 계산해 응답에 담고 원격 값과 대조하지 않는다)
  - mcp_dfir: 요청할 때만 (해시는 모델이 get_hash를 부를 때만 계산된다)
  - mulder: 경우마다 다름 (사건을 만들 때 분류기가 알아본 파일마다 SHA-256을 등록한다)
  - regipy: 없음 (증거 파일의 해시를 계산하지 않는다)
  - sift-kernel: 요청할 때만 (해시는 모델이 verify_integrity를 부를 때만 ewfverify가 계산해 E01 안의 획득 해시와 비교하고 성공하면 integrity_verified 능력이 생긴다)
  - trudi: 요청할 때만 (해시는 모델이 hash.file·hash.verify_evidence_hash 같은 해시 도구를 부를 때만 계산된다)
- **현행 규칙 1개.**
  - `33-C1-대상` (규격 33절) C1은 파일·바이트로 받는 증거만 센다. 살아 있는 호스트를 조회하는 도구는 넣지 않는다.

### C03 증거 변경 검증과 처리 방식

- **관찰 목적.** 기준과 현재 증거를 어떻게 대조하고 차이를 처리하는가?
- **개편안의 상세 후보.** 전체 해시 재계산·대조 / 크기·수정 시각 대조 / 분석 전후 대조 / 불일치 시 중단·경고
- **현행 C2 증거 해시 재검증** → C03. 현행 질문의 목적과 구분을 유지
  - ChainsawMCP: 안 함 (증거 해시를 계산하지 않아 다시 비교할 기준값이 없다)
  - MyIRTeam: 경우마다 다름 (artifact-forensic 파일 입력과 ir-collect 압축 파일 분석은 실행 뒤 원본을 다시 해시해 실행 전 값과 비교하고 호출 사이 기준값은 두지 않는다)
  - agentic-velociraptor-mcp: 안 함 (계산한 증거 해시를 기준값으로 보관하지 않아 다시 비교할 기준값이 없다)
  - mcp_dfir: 안 함 (계산한 증거 해시를 기준값으로 보관하지 않아 다시 비교할 기준값이 없다)
  - mulder: 안 함 (evidence_registry에 넣은 증거 파일의 해시를 나중에 다시 계산해 비교하는 코드가 없다)
  - regipy: 안 함 (증거 해시를 계산하지 않아 다시 비교할 기준값이 없다)
  - sift-kernel: 안 함 (계산한 증거 해시는 ewfverify 출력 문자열에만 남고 서버가 기준값으로 보관하지 않는다)
  - trudi: 경우마다 다름 (finding 심사가 해시 호출을 인용하면 그 파일의 크기·mtime·ctime·inode가 해시 때와 다를 때 기록을 거부한다)
- **현행 규칙 2개.**
  - `25-C2-전후비교` (규격 25절) 같은 호출 안에서 외부 도구 실행 전후의 해시 비교도 C2 `해시 재계산`으로 센다.
  - `32-C2-불일치처리` (규격 32절) C2 보조 `불일치처리`는 `멈춤`·`경고만`·`알리지 않음`이고 C2가 `안 함`이면 `해당없음`이다.

### C04 원본 변경 방지 방식

- **관찰 목적.** 원본에 닿는 경로에서 어떤 장치가 변경을 막는가?
- **개편안의 상세 후보.** 컨테이너 증거 볼륨 읽기 전용 / 증거 파일시스템 읽기 전용 마운트 / 읽기 전용 접근 API / 출력 대상 검사 / 원본과 작업 입력 분리 / 외부 도구에 의존 / 외부 플랫폼 권한에 맡김
- **현행 C4 원본 쓰기 막기** → C04. 컨테이너·서버·외부 도구 등 실제 접근 주체별 쓰기 범위를 표시
  - ChainsawMCP: 일부만 (Windows는 AIM /readonly 마운트 / Linux는 pytsk3·TSK가 읽기만 함 / EVTX 폴더는 원본을 그대로 넘김 / extra_args --output으로 원본도 비움)
  - MyIRTeam: 일부만 (폴더 도구와 압축 파일 멤버는 사본을 분석 / work_on_copy 거짓이면 원본 폴더를 넘김 / artifact-forensic은 원본을 도구에 넘김 / 살아 있는 호스트에 읽기 전용 장치 없이 닿음)
  - agentic-velociraptor-mcp: 일부만 (원본 보호를 Velociraptor 계정 권한에 맡김 / 원본을 고치는 RPC를 부르지 않음 / 계정 권한과 아티팩트 동작은 확인 안 함)
  - mcp_dfir: 일부만 (증거 ro 마운트 / 호스트 노트·심볼 도구는 evidence에 씀 / 같은 이름의 기존 컨테이너는 마운트 확인 없이 재사용)
  - mulder: 일부만 (원본 SQLite는 mode=ro URI로 엶 / WAL 모드 DB는 옆에 -shm·-wal이 생김 / TSK 실패 시 xmount·ro 드라이버로 마운트 / SQLCipher 경로는 쓰기 가능 모드로 엶 / TSK·외부 파서·dislocker는 쓰기를 안 막음)
  - regipy: 있음 (읽기 모드로 열어 메모리 사본만 씀)
  - sift-kernel: 일부만 (쓰기 위치를 출력 폴더로 정함 / 원시 이미지는 ro 옵션으로 마운트 시도 / 분석 도구는 이미지 파일을 직접 읽음 / pcap 내보내기 폴더를 증거 경로 뒤에 붙임)
  - trudi: 일부만 (출력 경로를 증거 위치 거부 목록과 비교 / NTFS를 ro·norecover로 마운트 / 채팅 DB를 immutable 읽기 전용으로 엶 / 마운트 지점 인자는 검사 없음 / batch_run 임의 명령은 검사 없음 / 살아 있는 호스트 쓰기에 읽기 전용 장치 없음)
- **매트릭스 밖 관찰.**
  - (함께) M7 mulder 「SQLite 증거를 여는 경로마다 -wal 반영이 갈리고 응답은 어느 쪽인지 싣지 않는다」
- **현행 규칙 2개.**
  - `32-재사용환경` (규격 32절) 격리 설정을 새로 만드는 실행 환경에만 걸고 이름이 같은 기존 환경은 확인 없이 재사용하면 그 설정에 기대는 문항은 `일부만`이다.
  - `33-C4-라이브러리` (규격 33절) 서버 프로세스 안의 라이브러리가 읽기만 하는 것은 C4의 막는 곳이 아니다. 운영체제나 컨테이너가 쓰기를 거부할 때만 `실행 환경`이다.

### C05 분석 입력 접근 범위 제한 방식

- **관찰 목적.** 읽는 파일·증거·참조 자료의 접근 범위를 어떻게 제한하는가?
- **개편안의 상세 후보.** 실제 경로로 풀어 허용 폴더 대조 / 문자열 경로 검사 / 등록된 증거 ID로만 조회 / 고정 입력 경로 사용
- **현행 C3 읽기 경로 제한** → C05. 현행 질문의 목적과 구분을 유지
  - ChainsawMCP: 미구현 (증거·룰·Sigma·매핑 경로는 검사 없음 / extra_args·설치 경로도 검사 없음)
  - MyIRTeam: 일부만 (오프라인 서버 둘은 실제 경로로 루트와 비교 / 폴더 안 링크·junction은 거르지 않음 / local-forensic은 허용 루트를 두지 않음)
  - agentic-velociraptor-mcp: 일부만 (upload_name을 원격 목록 이름과 그대로 대조 / 아티팩트 파라미터가 정하는 단말 읽기 경로는 검사 없음)
  - mcp_dfir: 일부만 (컨테이너에 붙인 폴더와 이미지 안만 읽힘 / 압축 해제 원본 경로의 .. 문자열 거부 / 나머지 컨테이너 도구의 경로 인자는 검사 없음 / 같은 이름의 기존 컨테이너는 마운트 확인 없이 재사용 / 호스트 노트·심볼 도구의 경로는 검사 없음)
  - mulder: 일부만 (증거 파일 읽기와 목록은 실제 경로로 허용 루트와 비교 / 외부 파서·압축 원본·룰 경로는 검사 없음)
  - regipy: 미구현 (받은 경로를 그대로 증거 폴더로 씀)
  - sift-kernel: 미구현 (경로 인자를 검사 없이 외부 도구에 넘김 / 경로 검사 함수는 부르는 곳이 없음)
  - trudi: 미구현 (증거·룰·설정 경로는 검사 없음 / 원격 읽기 경로도 검사 없음 / batch_run 명령도 검사 없음)
- **현행 규칙 5개.**
  - `17-C3H4-경로방향` (규격 17절) 증거와 분석 입력(룰·설정 포함)을 읽는 경로는 C3, 서버가 파일을 만들거나 고치는 경로는 H4에서 본다. 경로를 만드는 데 쓰이는 인자는 이름·제목·ID처럼 경로로 보이지 않아도 모두 본다.
  - `24-우회경로` (규격 24절) 검사의 대조 논리 자체를 무너뜨리는 값(빈 문자열, 모든 경로에 맞는 와일드카드)은 우회 경로로 세 판정형은 `일부만`, B5 보조 `우회경로`는 `있음`이다. 그럴듯하지만 관련 없는 실제 값은 설명에만 적는다.
  - `28-C3-UNC` (규격 28절) 경로 인자에 UNC 경로를 주어 운영체제가 원격 공유에 접속하는 것은 서버가 여는 통신이 아니다. 외부통신으로 세지 않고 C3에 적는다.
  - `29-C3H4-호출자값` (규격 29절) `호출자 값 안 씀`은 호출자 값이 경로에 전혀 들어가지 않을 때만 쓴다. 형식 검사나 파일 이름 떼어 내기를 거쳐 경로 조각이 되면 `문자열 비교`다.
  - `33-C3-범위` (규격 33절) C3은 증거와 분석 입력을 읽는 경로만 본다. 서버가 만든 파생물을 다시 읽는 경로는 세지 않는다. 모델이 넘긴 값이 원격 단말에서 읽을 경로를 정하면 C3 범위다.

### E08 증거 내용과 지시의 구분 (2026-09-30)

**E08이 묻는 것.** 서버가 증거에서 온 글을 모델에게 줄 때 그것이 따를 지시가 아니라 데이터라는 것을 어떻게 드러내는가. JSON으로 감싸는 것 자체를 묻는 셀이 아니다. 문자열 값 안의 지시문도 모델이 글로 읽기 때문이다. 현행 E7에서 trudi를 뺀 7개 표본이 모두 `신뢰 불가 표시` 미구현이었다. JSON으로 응답하는 표본도 JSON 포장을 표시로 세지 않았다. 개편안 4절도 JSON 포장만으로 프롬프트 인젝션 방지를 인정하지 않는다.

**판정 전 표본의 코드 확인.** 아래 두 표본은 아직 판정하지 않았고 기준 커밋 코드만 읽었다.
- TheHiveMCP는 TheHive·Cortex에서 온 문자열 값을 `[UNTRUSTED_DATA]…[/UNTRUSTED_DATA]`로 감싼다([parsers.go:238](https://github.com/StrangeBeeCorp/TheHiveMCP/blob/fcbf62115556c1cb41832ddd76b1c2cc61309896/internal/utils/parsers.go#L238)).
  - 값 안에 이미 태그가 있으면 경고 문구로 바꿔 경계를 미리 닫지 못하게 한다([parsers.go:231](https://github.com/StrangeBeeCorp/TheHiveMCP/blob/fcbf62115556c1cb41832ddd76b1c2cc61309896/internal/utils/parsers.go#L231)).
  - 서버가 쓴 문구는 `TrustedString`으로 표시해 감싸지 않는다([parsers.go:208](https://github.com/StrangeBeeCorp/TheHiveMCP/blob/fcbf62115556c1cb41832ddd76b1c2cc61309896/internal/utils/parsers.go#L208)). Cortex 보고서처럼 통째로 외부 자료인 것은 키 이름과 관계없이 모두 감싼다([parsers.go:225](https://github.com/StrangeBeeCorp/TheHiveMCP/blob/fcbf62115556c1cb41832ddd76b1c2cc61309896/internal/utils/parsers.go#L225)).
  - 도구 설명은 태그 안의 지시를 따르지 말라고 적는다([execute_automation/models.go:51](https://github.com/StrangeBeeCorp/TheHiveMCP/blob/fcbf62115556c1cb41832ddd76b1c2cc61309896/internal/tools/execute_automation/models.go#L51)).
  - 감싸기는 도구가 `HasUntrustedData`를 선언할 때만 켜진다([middlewares.go:15-17](https://github.com/StrangeBeeCorp/TheHiveMCP/blob/fcbf62115556c1cb41832ddd76b1c2cc61309896/internal/tools/middlewares.go#L15-L17)). 선언을 빠뜨린 도구는 감싸지 않는다.
  - 표시일 뿐 차단은 아니다. 모델은 태그 안의 내용을 그대로 읽는다.
- Camel의 `Execute`는 모델이 쓴 스크립트가 출력한 글을 text 블록 하나로 돌려준다([MCPServer.cs:322-324](https://github.com/allisterb/Camel/blob/63f4cb2e26a2469a35f847bee607516cf6184e91/src/Camel.Server/MCPServer.cs#L322-L324)). 서버가 증거 내용을 가리는 표시가 없다. 그래서 E08에서는 `미구현`이다. JSON으로 감쌌더라도 아래 상세의 가장 약한 항목에 들 뿐이다.

**상세 항목 후보.**
1. `미구현` — 증거 내용과 서버 문구를 평문으로 섞어 돌려준다(Camel).
2. JSON 필드에 담음 — 증거 내용이 필드 값으로 따로 있지만 신뢰할 수 없다는 표시는 없다(현행 표본 여럿).
3. 출처 필드를 붙임 — 결과에 데이터의 출처를 적는 필드를 둔다(trudi `_metadata.data_provenance`, 현행 E7 `일부만`).
4. 경계 태그로 감쌈 — 증거에서 온 값을 표시 문자열로 감싼다(TheHiveMCP).
5. 경계 태그 위조 무력화 — 값 안의 태그를 바꿔 경계를 미리 닫지 못하게 한다(TheHiveMCP).
6. 태그 안 지시를 무시하라는 안내 — 도구 설명·서버 지침에 적는다(TheHiveMCP).
7. 내용 거르기·차단 — 지시로 보이는 문구를 지우거나 막는다(아직 본 표본 없음).

셀 이름은 "증거 내용과 지시 구분 방식"으로, 상세 항목은 위 7개로 정했다(개편안 6.2절).
