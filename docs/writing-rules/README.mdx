# 작성 규칙

작성 규칙은 이 저장소의 글을 어떤 낱말과 문장으로 쓰는지 정한 문서입니다. 규칙 하나마다 파일을 하나씩 만듭니다.
원고, 셀 정의, 안내 문서, 결정 기록에 모두 적용합니다. 규칙마다 적용 대상이 다르면 그 규칙 파일의 `적용 대상`에 적습니다.

파일 형식(머리말, 소제목, 근거 표지)은 작성 규칙이 아니라 [matrix/README.md](https://github.com/Trace2Bac/dfir-mcp-architecture-matrix-v2/blob/main/matrix/README.md)와 [reports/README.mdx](https://github.com/Trace2Bac/dfir-mcp-architecture-matrix-v2/blob/main/reports/README.mdx)에서 정합니다.

## 언제 쓰나요?

다음 경우에 규칙 파일을 더하거나 고칩니다.

- 새로 지킬 낱말이나 문장 규칙이 생겼을 때
- 지금 규칙의 범위나 예외를 바꿀 때
- `check`가 잡는 문장 규칙을 더하거나 뺄 때

규칙을 바꿀 때는 결정 기록을 따로 쓰지 않습니다. 규칙 파일의 `바뀐 내용`에 날짜와 무엇을 바꿨는지 적습니다.

## 쓰는 법

1. [`template.mdx`](https://github.com/Trace2Bac/dfir-mcp-architecture-matrix-v2/blob/main/docs/writing-rules/template.mdx)를 복사해 `NNNN-short-english-title.mdx`로 만듭니다.
   - `NNNN`은 0001부터 이어지는 네 자리 번호입니다. 한 번 쓴 번호는 지우거나 다시 매기지 않습니다.
   - 파일 이름의 제목 부분은 영어 소문자와 하이픈으로 씁니다.
2. 템플릿의 항목을 채웁니다. 규칙마다 고치기 전과 고친 뒤의 예를 하나 이상 넣습니다.
3. 규칙을 없애거나 다른 규칙으로 바꾸면 파일을 지우지 않고 `상태`를 `폐지` 또는 `대체됨(NNNN)`으로 고칩니다.
4. 아래 [목록](#목록)에 한 줄을 더하거나 상태를 고칩니다.

## 검사

`python tools/pilot.py check`가 규칙 일부를 기계로 잡습니다. 검사하는 규칙은 규칙 파일의 `검사`에 적습니다.

- **pilot.py 낱말 검사**: 원고와 셀 정의에서 0001·0002의 낱말을 찾아 경고합니다. 원고는 `check`, 셀 정의는 `validate`가 봅니다.
- **style_lint.py 문장 검사**: 원고에서 0004의 표현을 찾아 오류로 냅니다. 검사 규칙은 이 저장소의 `tools/style_lint.py`에 있습니다.

기계 검사는 일부만 잡습니다. 경고가 없어도 규칙을 읽고 씁니다.
경고가 났지만 그 낱말이 맞는 경우도 있습니다(예: 걸린 시간). 그때는 고치지 않고 둡니다.
