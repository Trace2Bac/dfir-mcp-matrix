# 0004. 번역투와 상투적인 표현을 쓰지 않습니다

- 날짜: 2026-10-04
- 상태: 시행
- 적용 대상: 원고. 다른 글도 이 규칙을 따릅니다
- 검사: `check`가 `tools/style_lint.py`로 원고를 검사해 오류로 냅니다

## 규칙

**번역투**

| 쓰지 않는 표현 | 바꿀 말 |
|---|---|
| ~에 있어(서) | ~에서 |
| ~와 관련하여, ~와 관련된 | ~에, ~의 |
| ~에 의해(피동) | 행위자를 주어로 쓰기 |
| ~되어진다, ~지게 된다(이중 피동) | ~된다, 또는 능동 |
| ~에서의, ~으로의, ~으로부터의(이중 조사) | 절로 풀어 쓰기 |

"~에 대해", "~를 통해", "~라는 점에서"는 한 문단에 세 번 넘게 쓰지 않습니다.

**상투적인 표현**

- "결론적으로", "따라서", "요약하면", "이를 통해"로 문장을 시작하지 않습니다. 필요하면 문서에 한두 번만 씁니다.
- "시사하는 바가 크다", "주목할 만하다", "매우 중요하다"를 쓰지 않습니다. 무엇이 어떻게 되는지 사실로 씁니다.
- "다음과 같다", "크게 세 가지로 나눌 수 있다" 같은 도입 문장 없이 바로 본론을 씁니다.
- "핵심은 ~이다", "문제는 ~라는 점이다"를 "~가 ~한다"로 바로 씁니다.
- "~하는 이유다", "~로 이어진다"로 끝맺지 않고 "그래서 ~한다"로 씁니다.
- "~다는 것이다", "~다는 뜻이다"와 "즉"은 문서에 두 번 이하로 씁니다.

**문장 모양**

- 연결어미(-고, -며, -지만, -면서, -어서) 바로 뒤에 쉼표를 찍지 않습니다.
- 줄표(—)로 부가 설명을 잇지 않고 문장을 나눕니다.
- "~할 수 있다"를 한 문단에 네 번 넘게 쓰지 않습니다.

## 예

| 고치기 전 | 고친 뒤 |
|---|---|
| 호출 기록은 서버에 의해 남겨진다. | 서버가 호출 기록을 남긴다. |
| 등록에 있어서 경로만 확인한다. | 등록할 때 경로만 확인한다. |
| 핵심은 원본을 쓰지 않는다는 점이다. | 서버는 원본을 쓰지 않는다. |
| 서버는 소비한 입력과 실행을 결과와 연결한다. | 서버는 파생물을 만들 때 사용한 입력과 실행을 그 파생물과 연결한다. |
| 처리기가 예외를 삼킨다. | 처리기가 예외를 호출한 쪽으로 넘기지 않는다. |

## 이유

번역투와 상투적인 표현은 문장을 길게 만들고 사실을 흐립니다. 특히 LLM이 쓴 글에 자주 나오므로 기계 검사로 먼저 거릅니다.
