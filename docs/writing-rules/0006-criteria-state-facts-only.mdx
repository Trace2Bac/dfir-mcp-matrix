# 0006. 포함·제외 기준에는 다른 셀이나 상세를 가리키지 않고 사실만 씁니다

- 날짜: 2026-10-09
- 상태: 시행
- 적용 대상: 셀 정의
- 검사: `validate`가 `include`·`exclude`의 셀·상세 번호를 경고합니다

## 규칙

상세의 `include`와 `exclude`에는 그 상세에 해당하는 것과 해당하지 않는 것을 사실로만 씁니다.
`matrix/candidates.yaml`의 후보에도 같은 규칙을 적용합니다.

- 셀·상세 번호를 쓰지 않습니다. 같은 셀의 다른 상세도 번호로 가리키지 않습니다.
- "~에서 봅니다", "이 셀에서 보지 않습니다", "~축에서 봅니다"처럼 그 경우를 어디서 다루는지 적지 않습니다. "~는 해당하지 않습니다"로 씁니다.
- 어느 상세나 셀이 그 경우를 다루는지는 쓰지 않습니다. 같은 셀의 상세는 셀 화면에 함께 보이고, 다른 셀과 차이점은 셀의 `boundary`에 씁니다.
- 다른 상세의 이름을 빌려 조건을 적지 않습니다. 그 상세가 무엇을 하는지를 풀어 씁니다.

다른 셀을 번호로 가리키는 곳은 `boundary`(다른 셀과 차이점)뿐입니다.

## 예

| 고치기 전 | 고친 뒤 |
|---|---|
| 출력 해시만 있고 입력은 경로나 이름으로만 가리키는 경우는 D02.01에서 봅니다. | 출력 해시만 있고 입력은 경로나 이름으로만 가리키는 경우는 해당하지 않습니다. |
| T03.05나 T03.06에 해당하지 않으면 이 상세도 해당하지 않습니다. | 서버가 승인 토큰이나 서명, 또는 승인 내용을 요청과 대조하지 않으면 해당하지 않습니다. |
| 클라이언트의 MCP 호출 기록(L01.04)으로 파일을 내보내는 경우도 해당합니다. | 클라이언트의 MCP 호출 기록으로 파일을 내보내는 경우도 해당합니다. |
| 위협 정보 조회처럼 결과에 정보를 보태는 외부 질의는 I축에서 봅니다. | 위협 정보 조회처럼 결과에 정보를 보태는 외부 질의는 해당하지 않습니다. |

## 이유

포함·제외 기준은 서버 하나를 이 상세에 연결할지 판단하는 데만 씁니다. 그 판단에 필요한 것은 해당하는지 아닌지라는 사실이고, 다른 상세의 번호는 필요하지 않습니다.
번호를 적으면 읽는 사람이 그 상세를 찾아 읽어야 뜻을 알 수 있고, 상세를 지우거나 합치거나 셀 번호를 바꿀 때 고칠 곳이 늘어납니다.
2026-10-09에 셀 정의와 후보의 `include`·`exclude` 52곳이 번호나 "~에서 봅니다"로 다른 상세나 셀을 가리키고 있어 모두 사실로 고쳤습니다.
