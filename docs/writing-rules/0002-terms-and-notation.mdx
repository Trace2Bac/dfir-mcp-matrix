# 0002. 용어는 필요한 곳에만 쓰고, 한 개념에는 한 표기를 씁니다

- 날짜: 2026-10-04
- 상태: 시행
- 적용 대상: 모든 글
- 검사: 원고는 `check`, 셀 정의는 `validate`가 코드 개념 직역어 일부를 경고합니다. 표기 통일 일부는 `check`의 style_lint가 오류로 잡습니다(0004 참고)

## 규칙

**전문용어는 쉬운 말로 같은 뜻을 전할 수 없을 때만 씁니다.**

- 업계에서 굳어진 용어는 그대로 씁니다(예: 해시, 파서, SSH의 "호스트 키 지문").
- 쉬운 우리말이 없으면 영어 원어를 씁니다(예: API 키, annotation, allowlist).
- 읽는 사람이 모를 수 있는 용어나 약어는 처음 나오는 곳에서 짧게 풀어 씁니다. 그 뒤로는 용어만 씁니다.

**코드 이름은 원문 그대로 씁니다.**

- 함수, 필드, 도구, 상태 값, 환경변수 이름은 영어 원문 그대로 백틱으로 감쌉니다.
- 파이썬 자료형 이름도 코드 이름입니다. `dict`, `list`, `tuple`, `bool`, `str`을 백틱으로 쓰고 딕트, 딕셔너리, 리스트, 튜플, 불리언으로 옮기지 않습니다. 일반적인 뜻의 목록은 "목록"으로 씁니다.
- 조사는 원어를 읽는 소리에 맞춥니다(`file`을, `dict`를).

**코드가 지은 개념 이름을 우리말로 직역하지 않습니다.**

- `review_receipt`를 "영수증"으로, `readiness_fingerprint`를 "지문"으로 옮기는 것처럼 영어 낱말을 그대로 번역한 비유어를 쓰지 않습니다.
- 코드 이름을 백틱으로 그대로 쓰고, 처음 나오는 곳에서만 "검토를 통과했다는 기록 `review_receipt`"처럼 뜻을 쉬운 우리말로 풀어 씁니다.

**한 개념에는 한 표기를 씁니다.**

| 쓰는 표기 | 쓰지 않는 표기 |
|---|---|
| 호출 기록 | 감사 로그, 감사 기록 |
| 폴더 | 디렉터리 |
| 실행 파일 | 바이너리 |
| 파생물 | 파생 파일, 결과물 |
| 시간 제한 | 타임아웃 |
| 검사(유효성 확인) / 검증(해시·기대값 대조) | 두 말을 섞어 쓰기 |

개수는 아라비아 숫자로 씁니다("28개", "3건").

## 예

| 고치기 전 | 고친 뒤 |
|---|---|
| 서버는 영수증이 있어야 보고서를 쓴다 | 서버는 검토를 통과했다는 기록 `review_receipt`가 있어야 보고서를 쓴다 |
| 결과를 딕셔너리로 돌려준다 | 결과를 `dict`로 돌려준다 |
| 타임아웃이 지나면 감사 로그에 남긴다 | 시간 제한이 지나면 호출 기록에 남긴다 |

## 이유

직역한 비유어는 코드에서 그 이름을 찾을 수 없게 만들고, 원래 낱말에 없는 뜻을 덧붙입니다.
같은 개념을 여러 표기로 쓰면 읽는 사람이 서로 다른 개념으로 오해하고, 검색으로도 찾기 어렵습니다.
