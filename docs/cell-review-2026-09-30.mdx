# 매트릭스 셀 검토 자료 (2026-09-30)

이 문서는 셀을 함께 검토할 때 보는 자료입니다. 여기 적힌 내용은 결정이 아닙니다.
통합 개편안 10절에서 정한 새 셀마다 현행 판정(2026-09-30 당시), 매트릭스 밖 관찰, 경계 규칙을 한곳에 모았습니다.
내용은 개편안, 판정 YAML, `규칙적용표.yaml`에서 기계로 뽑았습니다. 현행 판정 문구는 줄여서 실었습니다.

**주의: 이 문서의 셀 번호는 모두 지금 매트릭스(P·E·T·R·L·D·I 축)의 번호가 아닙니다.** 이 문서에서 "현행"은 이 문서를 쓴 2026-09-30 당시의 매트릭스를 뜻합니다. 번호는 세 가지가 섞여 있습니다.

- 소제목의 A01~H15는 당시 개편안 10절의 번호입니다.
- "현행 B2"처럼 "현행"이 붙은 번호는 당시 49셀 매트릭스의 번호입니다.
- 끝의 "셀 검토 메모"는 그보다 앞서, 번호를 다시 매기기 전에 쓴 것이라 번호가 또 다릅니다.

**용어.** 셀은 관찰 질문 하나이고, 상세는 그 질문에 답하는 구현 방식 하나입니다. 축은 셀을 묶는 큰 갈래입니다. 아래 A~H 절은 당시 개편안 10절의 축입니다.

**각 셀에 붙은 항목.** 셀마다 아래 항목 가운데 해당하는 것만 붙어 있습니다.

- **관찰 목적.** 이 셀이 답하려는 질문입니다.
- **적용 범위.** 소제목에 "(조건부)"가 붙은 셀에만 있습니다. 이 셀을 관찰하는 기능이나 배포를 적습니다.
- **개편안의 상세 후보.** 개편안이 제시한 구현 방식(상세) 후보입니다. 후보끼리는 `/`로 구분합니다. 뒤에 경계에 관한 메모가 붙기도 합니다.
- **현행 셀.** 당시 매트릭스에서 이 셀에 대응하는 셀입니다. "없음(새로 조사할 셀)"이면 대응하는 셀이 없어 새로 조사해야 합니다. 대응하는 셀이 있으면 이 자리에 "**현행 B2 조치 전 승인** → B02"처럼 당시 셀 번호·이름과 옮겨 갈 새 셀(또는 프로필)을 적습니다. 그 아래에는 서버별 현행 판정을 `서버: 판정 (설명)` 형식으로 줄여 실었습니다.
- **매트릭스 밖 관찰.** 당시 매트릭스의 셀 밖에서 따로 기록해 둔 구현 관찰입니다. 관찰 번호(R1, S7 등), 서버 이름, 「」로 인용한 관찰 내용 순서로 적습니다. 앞의 (주)와 (함께)는 개편안 10.6절 표의 두 열에서 왔습니다. (주)는 이 셀이 그 관찰의 "주된 관찰 목적"이라는 뜻이고, (함께)는 "함께 확인할 목적"이라는 뜻입니다.
- **흡수 후보(10.3절).** 개편안 10.3절에서 별도 셀로 둘지 검토하는 후보 가운데, 이 셀의 상세로 담을 수 있는지 볼 후보입니다.
- **현행 규칙.** `규칙적용표.yaml`에서 이 셀에 걸린 당시의 경계 규칙입니다. 규칙 ID, 근거가 된 규격 절, 규칙 내용 순서로 적습니다. 규칙 안의 셀 번호(A5, B2 등)는 당시 매트릭스의 셀 번호입니다.

**검토 순서.** 셀마다 다음 순서로 검토합니다.

1. **관찰 목적**과 경계가 맞는지 확인합니다.
2. **현행 판정**에 나온 방식 이름에서 구현 방식(상세) 후보를 뽑습니다. 어느 방식에도 해당하지 않으면 `장치 없음` 항목에 둡니다.
3. **관찰**과 **흡수 후보**를 상세로 담을 수 있는지 봅니다.
4. **현행 규칙**이 새 상세에 무엇을 넣고 뺄지 정하는 기준으로 맞는지 봅니다.

### E02 대량 결과 전달 방식

- **관찰 목적.** 응답 제한, 잘림, 나머지 결과에 대한 접근을 어떻게 처리하나요?

  - ChainsawMCP: 있음 (전체 건수와 반환 건수를 함께 실음)
  - MyIRTeam: 일부만 (주요 결과는 전체·반환 건수와 truncated를 실음 / 일부 목록은 표시 없이 자름)
  - agentic-velociraptor-mcp: 일부만 (결과 조회 2개는 반환 건수·전체 건수를 실음 / 검색과 목록 도구는 잘림을 알리지 않음)
  - mcp_dfir: 비적용 (서버가 응답을 스스로 자르는 경로가 없다. get_command_result는 출력 상한을 넘으면 자르지 않고 오류로 거부하고 head·tail·regex는 모델이 고른 범위다)
  - mulder: 일부만 (window·search 응답은 반환·전체 건수를 실음 / 일부 도구는 전체 건수 없이 자름)
  - regipy: 비적용 (응답 크기와 건수에 상한이 없어 결과 목록이 잘리지 않는다. 문자열 값이 256자에서 잘리는 것은 값 단위라 건수와 관계없다)
  - sift-kernel: 미구현 (잘림 문구만 붙임 / 줄 상한으로 끊긴 결과는 표시 없음)
  - trudi: 일부만 (줄 상한 꼬리말에 생략 줄 수를 적음 / 일부 도구는 전체·반환 건수를 실음 / 문자 상한과 여러 도구는 건수 없이 자름)

  - mcp_dfir: 출력 상한 일부만, 신뢰 불가 표시 미구현 (출력 상한은 get_command_result에만 있고 len으로 세어 문자 25,600개다)

  - (함께) CS1 ChainsawMCP 「build_incident_report가 탐지에서 ATT&CK 표·타임라인·IOC 후보·호스트와 계정 목록을 규칙으로 계산해 보고서에 싣는다」

### E08 증거 내용과 지시의 구분 (2026-09-30)

**E08이 묻는 것.** E08은 서버가 증거에서 온 글을 모델에게 줄 때, 그 글이 따라야 할 지시가 아니라 데이터라는 것을 어떻게 드러내는지 묻습니다. JSON으로 감싸는지를 묻는 셀은 아닙니다. 문자열 값 안에 들어 있는 지시문도 모델은 그냥 글로 읽기 때문입니다. 현행 E7에서는 trudi를 뺀 7개 표본이 모두 `신뢰 불가 표시` 미구현이었습니다. JSON으로 응답하는 표본도 JSON으로 감쌌다는 것만으로는 표시가 있다고 보지 않았습니다. 개편안 4절도 JSON 포장만으로는 프롬프트 인젝션 방지를 인정하지 않습니다.

**판정 전 표본의 코드 확인.** 아래 두 표본은 아직 판정하지 않았고, 기준 커밋의 코드만 읽었습니다.
- TheHiveMCP는 TheHive·Cortex에서 온 문자열 값을 `[UNTRUSTED_DATA]…[/UNTRUSTED_DATA]`로 감쌉니다([parsers.go:238](https://github.com/StrangeBeeCorp/TheHiveMCP/blob/fcbf62115556c1cb41832ddd76b1c2cc61309896/internal/utils/parsers.go#L238)).
  - 값 안에 이미 태그가 있으면 경고 문구로 바꿔, 값이 경계를 미리 닫지 못하게 합니다([parsers.go:231](https://github.com/StrangeBeeCorp/TheHiveMCP/blob/fcbf62115556c1cb41832ddd76b1c2cc61309896/internal/utils/parsers.go#L231)).
  - 서버가 쓴 문구는 `TrustedString`으로 표시해 감싸지 않습니다([parsers.go:208](https://github.com/StrangeBeeCorp/TheHiveMCP/blob/fcbf62115556c1cb41832ddd76b1c2cc61309896/internal/utils/parsers.go#L208)). Cortex 보고서처럼 통째로 외부 자료인 것은 키 이름과 관계없이 모두 감쌉니다([parsers.go:225](https://github.com/StrangeBeeCorp/TheHiveMCP/blob/fcbf62115556c1cb41832ddd76b1c2cc61309896/internal/utils/parsers.go#L225)).
  - 도구 설명에는 태그 안의 지시를 따르지 말라고 적혀 있습니다([execute_automation/models.go:51](https://github.com/StrangeBeeCorp/TheHiveMCP/blob/fcbf62115556c1cb41832ddd76b1c2cc61309896/internal/tools/execute_automation/models.go#L51)).
  - 감싸기는 도구가 `HasUntrustedData`를 선언할 때만 켜집니다([middlewares.go:15-17](https://github.com/StrangeBeeCorp/TheHiveMCP/blob/fcbf62115556c1cb41832ddd76b1c2cc61309896/internal/tools/middlewares.go#L15-L17)). 선언을 빠뜨린 도구의 출력은 감싸지 않습니다.
  - 이 방식은 표시일 뿐 차단은 아닙니다. 모델은 태그 안의 내용을 그대로 읽습니다.
- Camel의 `Execute`는 모델이 쓴 스크립트가 출력한 글을 text 블록 하나로 돌려줍니다([MCPServer.cs:322-324](https://github.com/allisterb/Camel/blob/63f4cb2e26a2469a35f847bee607516cf6184e91/src/Camel.Server/MCPServer.cs#L322-L324)). 서버가 증거 내용을 가리는 표시가 없습니다. 그래서 E08에서는 `미구현`입니다. JSON으로 감쌌더라도 아래 상세 항목 가운데 가장 약한 항목에 해당할 뿐입니다.

**상세 항목 후보.**
1. `미구현` — 증거 내용과 서버 문구를 평문으로 섞어 돌려줍니다(Camel).
2. JSON 필드에 담음 — 증거 내용이 필드 값으로 따로 있지만 신뢰할 수 없다는 표시는 없습니다(현행 표본 여럿).
3. 출처 필드를 붙임 — 결과에 데이터의 출처를 적는 필드를 둡니다(trudi `_metadata.data_provenance`, 현행 E7 `일부만`).
4. 경계 태그로 감쌈 — 증거에서 온 값을 표시 문자열로 감쌉니다(TheHiveMCP).
5. 경계 태그 위조 무력화 — 값 안의 태그를 바꿔 경계를 미리 닫지 못하게 합니다(TheHiveMCP).
6. 태그 안 지시를 무시하라는 안내 — 도구 설명이나 서버 지침에 적습니다(TheHiveMCP).
7. 내용 거르기·차단 — 지시로 보이는 문구를 지우거나 막습니다(아직 본 표본 없음).

셀 이름은 "증거 내용과 지시 구분 방식"으로, 상세 항목은 위 7개로 정했습니다(개편안 6.2절).
