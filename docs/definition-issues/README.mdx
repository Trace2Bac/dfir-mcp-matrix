# 정의 문제 목록

서버를 분석하다 셀 정의로 판정이 갈리거나 정의가 맞지 않는 곳을 찾으면 여기에 적습니다.
분석 중에는 셀 정의를 고치지 않고 지금 정의대로 판정한 뒤, 검토 주기에 이 목록을 모아 한 번에 고칩니다(결정 0041).
언제 무엇을 고치고 버전을 어떻게 올리는지는 [CONTRIBUTING.md의 정의를 바꾸는 때와 버전](https://github.com/Trace2Bac/dfir-mcp-architecture-matrix-v2/blob/main/CONTRIBUTING.md#정의를-바꾸는-때와-버전)에 있습니다.

## 쓰는 법

- 문제 하나에 한 줄을 씁니다. 번호는 1부터 이어 매기고 다시 매기지 않습니다.
- **지금 판정**에는 지금 정의대로 원고에 어떻게 판정해 두었는지 씁니다. 정의가 바뀌기 전까지 원고는 이 판정을 따릅니다.
- **제안**에는 정의를 어떻게 바꾸면 좋을지 씁니다. 비워 두어도 됩니다.
- 검토에서 처리하면 **처리**에 반영한 버전(날짜)과 결정 기록 번호를 씁니다(예: `2026-10-20, 결정 0042`). 고치지 않기로 했으면 그 이유를 짧게 씁니다.
- 상세를 새로 더하거나 상세 이름을 바꾸는 일은 여기에 적지 않고 바로 합니다. 정의 범위를 바꾸지 않기 때문입니다.
