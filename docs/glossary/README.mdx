# 용어 사전

이 문서는 이 저장소의 원고, 셀 정의, 안내 문서, 결정 기록에서 쓰는 용어의 뜻을 한곳에 모은 것입니다.
용어를 어떤 표기로 쓰는지(예: "감사 로그"가 아니라 "호출 기록")는 [작성 규칙 0002](../writing-rules/0002-terms-and-notation.mdx)에서 정하고, 여기서는 그 용어가 무엇을 가리키는지를 정합니다.
파일 형식(머리말, 소제목, 근거 표지를 쓰는 법)은 [matrix/README.md](https://github.com/Trace2Bac/dfir-mcp-architecture-matrix-v2/blob/main/matrix/README.md)와 [reports/README.mdx](https://github.com/Trace2Bac/dfir-mcp-architecture-matrix-v2/blob/main/reports/README.mdx)에 있습니다.

## 언제 고치나요?

다음 경우에 이 문서를 고칩니다.

- 셀 정의나 원고에 새 용어를 쓰기 시작했을 때
- 결정 기록으로 용어의 뜻이나 범위가 바뀌었을 때
- 같은 개념을 가리키는 용어가 둘 이상 쓰이고 있어 하나로 정할 때. 이때는 작성 규칙 0002의 표기 표도 함께 고칩니다

용어의 뜻만 고칠 때는 결정 기록을 쓰지 않습니다.
뜻이 바뀌어 셀의 범위나 판단 기준이 달라지면 그 변경은 결정 기록으로 남깁니다.

## 쓰는 법

- 용어는 갈래별 표에 가나다순이 아니라 읽는 차례대로 둡니다. 먼저 알아야 하는 용어를 위에 둡니다.
- 뜻은 "~입니다"로 끝나는 한두 문장으로 씁니다. 예외나 경계는 뜻 뒤에 이어 씁니다.
- 뜻을 정한 결정 기록이 있으면 뜻 끝에 "(결정 NNNN)"을 붙입니다.
- 코드 이름이나 머리말 키는 백틱으로 씁니다.

## 매트릭스 구조

| 용어 | 뜻 |
|---|---|
| 매트릭스 | DFIR MCP 서버들이 증거 무결성, 실행 통제, 결과 전달, 기록 같은 문제를 어떻게 구현하는지 비교하는 표입니다. 축 → 셀 → 상세 항목의 세 단계로 짜여 있습니다. |
| 축 | 셀을 묶는 큰 갈래입니다. P·E·T·R·L·D·I 일곱 개가 있고, 글자는 축 이름 영어의 첫 글자입니다. 축마다 다루는 범위는 축 페이지(`matrix/cells/<축>/index.mdx`)에 있습니다. |
| 셀 | 서버를 관찰할 때 던지는 질문 하나입니다. 번호는 축 글자와 두 자리 숫자입니다(예: `E03`). 서버가 구현했는지 미구현인지는 셀의 질문을 기준으로 판단합니다. |
| 상세 항목(상세) | 셀의 질문에 답하는 구현 방식 하나입니다. 번호는 셀 번호와 두 자리 숫자입니다(예: `E03.02`). 번호는 한 번 정하면 바꾸거나 다시 매기지 않고, 이름은 바꿀 수 있습니다. |
| 셀 정의 | 셀 파일(`matrix/cells/<축>/<ID>.mdx`) 머리말의 값입니다. 질문(`question`), 적용 범위(`scope`), 미구현·비적용의 뜻, 다른 셀과의 경계(`boundary`), 상세 목록(`details`)이 들어갑니다. |
| 적용 범위(`scope`) | 셀에서 상세를 연결하는 범위입니다. 그 범위 안에서 방식이 적용되지 않거나 미비한 점은 원고의 한계 단락에 씁니다. |
| 다른 셀과의 경계(`boundary`) | 비슷한 일을 다른 셀에서 볼 때 어디까지가 이 셀인지 적은 설명입니다. 화면에는 셀 설명으로 보입니다. |
| 포함 기준(`include`)·제외 기준(`exclude`) | 상세마다 어떤 구현이 그 상세에 해당하는지와 해당하지 않는지 적은 기준입니다. 제외 기준에는 그 구현을 보는 다른 셀이나 상세를 적습니다. |
| 조건부 셀(`conditional`) | 그 기능을 지원하는 서버에만 보는 셀입니다. 적용 대상은 `applies_to`에 적습니다. |
| 시범 셀 | 원고 폴더마다 반드시 원고가 있어야 하는 셀입니다. `matrix/config.yaml`의 `pilot_cells`에 적고, 정의(`scope` 등)를 반드시 씁니다. |
| 후보 | 구현 사례가 아직 없는 상세입니다. 연결된 원고도 없고 `seen_in`도 비어 있으면 화면에 흐리게 보이고, `validate`가 개수를 알려 줍니다. |
| `seen_in` | 원고는 아직 없지만 구현을 확인한 서버 목록입니다. 원고를 쓰면 그 서버를 목록에서 지웁니다. |

## 판정

미구현·비적용·미확인은 원고 머리말과 화면 데이터에는 괄호 안의 코드로 쓰고, 원고 소제목과 화면에는 한글 이름으로 씁니다.

| 용어 | 뜻 |
|---|---|
| 해당 | 서버가 셀의 어느 상세 방식을 구현한 경우입니다. 한 서버가 같은 셀의 여러 상세에 해당할 수 있습니다. |
| 미구현(`not_implemented`) | 서버가 셀이 묻는 일을 하는데 어느 상세 방식도 없는 경우입니다. 셀마다의 뜻은 셀 정의의 `not_implemented`에 있습니다. |
| 비적용(`not_applicable`) | 셀이 묻는 일의 전제를 서버가 아예 하지 않는 경우입니다. 예를 들어 파생물을 남기지 않는 서버는 파생물 추적 셀(D02)에서 비적용입니다. |
| 미확인(`unknown`) | 아직 조사하지 않은 경우입니다. 원고에는 쓰지 않고, 셀 화면에는 "조사한 서버 4/9"처럼 수로만 보입니다. |
| 우회 경로 | 장치가 지키는 바로 그 프로그램이나 동작을 장치 없이 할 수 있는 다른 도구나 경로입니다. 우회 경로는 원고의 한계 단락에 씁니다. 장치가 없는 다른 일을 하는 도구는 우회 경로가 아니라 구현 단락에 씁니다(결정 0010). |

## 원고

| 용어 | 뜻 |
|---|---|
| 원고 | 서버 하나가 셀 하나에서 어느 상세에 해당하는지를 구현, 한계, 근거와 함께 적은 문서입니다(`reports/<서버>/<축>/<셀ID>.mdx`). |
| 서버 머리 | 서버 원고 폴더의 `index.mdx`입니다. 저장소, 기준 커밋, 확인 방법처럼 그 서버의 모든 원고에 공통인 정보를 씁니다. |
| 기준 커밋 | 원고가 인용하는 코드의 커밋입니다. 줄 번호와 링크는 모두 이 커밋 기준이고, 서버 머리의 `commit`에 40자로 적습니다. |
| 확인 방법 | 서버 머리에 적는, 코드를 어떻게 읽고 무엇을 실행해 확인했는지에 대한 설명입니다. |
| 구현 | 원고에서 그 방식이 서버의 어느 도구나 경로에 있고 어떻게 동작하는지 쓰는 단락입니다. 첫머리에 그 방식의 적용 범위를 적습니다. |
| 한계 | 원고에서 구현 단락에 적은 적용 범위 안인데도 그 방식이 적용되지 않거나 미비한 점을 쓰는 단락입니다. 미비한 점이 없으면 쓰지 않습니다(결정 0033). |
| 판단 | 미구현이나 비적용 원고에서 왜 그렇게 판정했는지 쓰는 단락입니다. |
| 근거 | 원고의 설명을 뒷받침하는 자료입니다. 주로 기준 커밋의 코드 위치와 발췌이고, 원고 끝 `### 근거`에 번호를 매겨 둡니다. |
| 근거 표지 | 원고 본문 문장 끝의 `[번호]`입니다. 같은 번호의 근거를 가리키고, 코드 이름이 든 문장에는 반드시 답니다. |
| 발췌 | 근거에 붙이는 기준 커밋의 코드 원문입니다. 손으로 쓰지 않고 `@발췌 경로:시작-끝` 한 줄을 둔 뒤 `fill`로 채웁니다. `check`가 원문과 글자 하나까지 대조합니다. |
| 실행 확인 | 코드를 읽는 대신 실제로 실행해 확인한 근거입니다. 근거 첫 줄에 `(실행 확인)`을 붙이고, 무엇을 실행했는지는 서버 머리의 확인 방법에 씁니다. |
| 기능→셀 대응표(`coverage.mdx`) | 서버의 도구와 SDK 메서드를 모두 늘어놓고 어느 셀 원고에서 다뤘는지 보이는 표입니다. 두는 것은 선택이고, `tools/coverage.py`가 본문 표를 만듭니다. |

## 조사 대상

| 용어 | 뜻 |
|---|---|
| DFIR MCP 서버(서버) | 디지털 포렌식·사고 대응(DFIR) 기능을 MCP 도구로 모델에게 내놓는 서버입니다. 매트릭스가 관찰하는 대상입니다. |
| 모델 | MCP 클라이언트 안에서 도구를 고르고 부르는 언어 모델입니다. 서버의 응답을 근거로 다음 판단을 합니다. |
| 클라이언트 | 모델과 서버를 잇는 MCP 클라이언트 프로그램입니다. 같은 저장소가 함께 내놓는 클라이언트 구성의 동작은 상세가 클라이언트 쪽 방식을 묻는 경우에만 구현으로 셉니다(결정 0008, 0021). |
| 사용자 | 서버를 설치·설정·실행하고 클라이언트에서 모델과 함께 조사하는 사람입니다. 설정 파일, 환경변수, 시작 인자, 같은 저장소가 내놓는 CLI(사용자 CLI)로 서버를 다루고, 클라이언트에서 입력하거나 승인합니다. 증거 안의 계정을 가리키는 "사용자 이름"과는 다릅니다. |
| 도구(MCP 도구) | 서버가 모델에게 내놓아 부를 수 있게 한 기능 하나입니다. |
| 도구 호출 | 모델이 도구 하나를 인자와 함께 부르는 요청 하나입니다. |
| 도구 명세 | 모델이 도구를 고르기 전에 보는 도구 이름, 설명, 입력 schema, annotation, 사용법 문서입니다(T10). |
| 분석 도구 | 서버가 실제 분석에 쓰는 외부 프로그램, 라이브러리, 룰, 심볼, 이미지입니다. MCP 도구와 구별합니다. |
| 백엔드 | 서버가 분석을 작업으로 맡기거나 접속하는 원격 플랫폼이나 서비스입니다. |
| 실행 환경 | 분석 도구가 실제로 실행되는 곳입니다. 서버와 같은 프로세스, 별도 프로세스, 컨테이너·VM, 원격 호스트가 있습니다(T04). |
| 실행기 | 서버가 외부 프로그램을 실행하거나 백엔드에 질의할 때 여러 도구가 공통으로 거치는 함수입니다. 원고에서는 처음 나올 때 그 함수 이름을 함께 적습니다(예: trudi `run`, protocol-siftpp `VolatilityRunner.run`). 이 함수 안에서 실행마다 서버 기록을 남기는 방식은 L01.09에서 봅니다. |
| code-mode 서버 | 모델이 보낸 코드가 서버 SDK를 호출하고, 그 코드가 응답 글을 만드는 서버입니다. SDK 메서드가 그 코드에 돌려주는 객체를 R01~R06의 결과로 보고, R07은 MCP 응답 글을 봅니다(결정 0014). |
| 사건 | 조사를 묶는 단위 하나입니다. 서버에 따라 사건 대신 세션이나 프로세스를 단위로 씁니다(P04). |
| 원본 증거 | 조사 대상에서 확보한 증거 데이터입니다. 서버가 분석 중에 만든 자료는 원본 증거가 아니라 파생물입니다(E축). |
| 분석 입력 | 이미지, 보관 파일, 수집물에서 분석에 쓰도록 준비한 범위입니다. 작업 사본, 추출한 파일, 마운트한 파일 시스템이 그 예입니다(E04). |
| 작업 사본 | 원본을 바꾸지 않고 분석하려고 만든 원본 증거의 사본입니다. |
| 파생물 | 원본 증거가 아니면서 조사 과정에서 생긴 자료입니다. 도구 출력, 중간 자료, 발견사항과 결론, 보고 산출물이 여기에 포함됩니다(D축). |
| 발견사항 | 조사에서 얻은 사실이나 가설을 판정, 근거, 시각과 함께 남긴 기록입니다(D05). |
| 결론 | 서버가 도구 결과를 규칙이나 모델로 해석해 만든 판단입니다. 규칙 판정, 결과 사이의 관계, 점수, 공격 흐름 서술이 여기에 포함됩니다(D06). 모델이 기록으로 제출한 주장은 결론이 아니라 발견사항입니다. |
| 부재 주장 | 어떤 흔적이 증거에 없다는 주장입니다. 단서, 출처, 장치, 상대방, 가설 같은 대상을 증거에서 배제하는 처분도 포함합니다(D07). |
| 보고 산출물 | 검토자가 증거, 범위, 방법, 결과, 한계를 확인하도록 서버가 만드는 보고서, 묶음, 내보내기 파일입니다(D08). 같은 저장소의 사용자 CLI나 클라이언트 코드·훅이 서버 기록이나 서버 응답을 정해진 코드로 가공해 만드는 것도 포함합니다(결정 0013, 0028). |
| 서버 기록 | MCP 도구 호출과 그 실행의 이력을 다시 짜 맞추도록 서버가 남기는 기록입니다(L축). 처리 중 부른 모델이나 보낸 외부 요청도 포함합니다. 클라이언트 기록은 서버 기록과 구별하며, 같은 저장소의 클라이언트가 MCP 호출을 별도로 남기는 방식만 L01.10에서 봅니다. 출력이 기록에 함께 담겨 있어도 분석 내용의 보관·관리·검증은 D축에서 봅니다. |
| 호출 기록 | 서버 기록 가운데 도구 호출 하나하나를 남긴 항목들입니다. |
| 참조 자료 | 서버가 판단에 쓰거나 조회 결과로 모델에게 돌려주는, 사건 증거가 아닌 자료입니다. 룰, 심볼, 공격 기법 목록, 아티팩트 지식, 외부 위협 정보 조회 결과가 그 예입니다. 결과에 실린 이런 내용을 참조 지식이라고 합니다(결정 0025). |
| 대상 시스템 | 서버가 조사하는 살아 있는 단말이나 서버입니다. 증거 사본이나 이미지는 대상 시스템이 아닙니다(T09). |
| 대응 조치 | 격리, 차단, 프로세스 종료, 계정 잠금, 파일 삭제, 설정 변경처럼 대상 시스템을 바꾸는 조치입니다. 단말의 감시·수집 설정을 바꾸는 것도 여기에 포함됩니다(T09). |
| 외부 연동 | 서버나 서버가 실행한 프로그램이 서버 밖의 API, 서비스, 원격 호스트와 주고받는 통신입니다(I축). |
| 자격증명 | 서버가 외부에 접속할 때 쓰는 API 키, 토큰, 인증서, 비밀번호입니다(I04). |
