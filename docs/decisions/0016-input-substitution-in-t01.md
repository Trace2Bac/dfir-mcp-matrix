# 0016. 입력을 얻지 못해 다른 입력으로 실행하는 동작을 T01에서 본다

- 날짜: 2026-10-02
- 상태: 채택
- 결정한 사람: 결정권자(팀)

## 배경

sift-kernel 전체 적용에서 입력을 얻지 못했을 때 다른 입력으로 실행하는 동작이 세 셀에 나뉘어 적혔다.
T07.04 include는 도구·경로와 함께 입력의 대체도 담았고 E04 scope는 엉뚱한 파일을 입력으로 쓰거나 실패를 알리지 않는 경로를 †로 정했다.
그래서 sift-kernel이 추출에 실패한 이미지 안 경로를 호스트 경로로 넘기는 동작과 mulder가 EVTX를 꺼내지 못하면 다른 폴더의 EVTX 파일을 모으는 동작이 T07과 E04 원고에 겹쳐 적혔다.
T07은 도구·참조 자료가 없을 때의 처리를 묻고 E축은 원본 증거를 다룬다.
입력이 없는지 보는 일은 이미 T01.02 "입력 존재·읽기 가능 검사"가 다룬다.

## 결정

- 상세 T01.08 "입력 부재 시 다른 입력으로 대체"를 더한다. 입력 파일·경로를 찾지 못하거나 이미지에서 꺼내지 못하면 거부하지 않고 다른 파일·경로·범위를 입력으로 바꿔 실행하는 동작이다.
- T07.04 include에서 입력을 빼고 exclude에 "입력을 얻지 못해 다른 입력으로 실행하면 T01.08이다"를 더한다. 같은 입력을 다른 도구·경로로 얻는 대체는 T07에 남는다.
- E04 scope의 † 사유에서 "엉뚱한 파일을 입력으로 씀"과 "실패를 알리지 않고 지나감"을 빼고 "일부만 준비함"과 "누락을 알리지 않음"으로 고친다. 입력을 얻지 못해 다른 입력으로 실행하는 경로는 T01.08에서 본다고 적는다.

## 영향

sift-kernel과 mulder의 T01 원고에 T01.08을 더하고 T07.04·E04.02 원고의 같은 단락을 T01.08을 가리키는 문장으로 바꿨다.
Camel은 입력을 바꿔 실행하는 경로가 없어 바꾸지 않았다.
