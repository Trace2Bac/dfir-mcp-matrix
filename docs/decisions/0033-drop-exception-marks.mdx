# 0033. 예외 표시를 없애고 구현의 미비점은 원고의 한계 단락에 씁니다

- 날짜: 2026-10-06
- 상태: 채택(앞 결정에서 예외 표시를 붙이는 조건을 정한 부분을 대체)
- 결정한 사람: 결정권자(팀)

## 배경

원고는 상세마다 예외 표시(`exception: true`)를 붙일지 정하고 붙이면 예외 단락을 썼습니다. 셀마다 scope와 상세 exclude에 예외 표시를 붙이는 조건을 따로 적었습니다.

2026-10-06 전체 검토 결과는 다음과 같았습니다.

- 검토 발견 174건 가운데 54건이 예외 표시에 관한 것이었습니다. 붙일지 말지, 근거 문장을 어느 단락에 둘지, 셀마다 다른 조건을 어떻게 읽을지가 그 내용입니다.
- 셀 정의 43개의 scope와 exclude에 예외 조건이 97군데 따로 적혀 있었습니다. 셀 정의를 고칠 때마다 원고의 예외 표시가 함께 흔들렸습니다.
- 원고 연결 643개 가운데 407개(63%)에 예외 표시가 붙어 있었습니다. 대부분의 연결에 붙는 표시라 화면에서 서버 사이의 차이를 보여 주지 못했습니다.

## 결정

- 예외 표시를 없앱니다. 원고 머리말에 `exception`을 쓰지 않고 화면의 예외 배지도 없앱니다.
- 상세 연결, 미구현, 비적용 판정은 그대로 둡니다.
- 구현의 미비점은 상세마다 `**한계.**` 단락에 씁니다. 원고의 구현 단락에 적은 적용 범위 안에서 그 방식이 적용되지 않거나 미비한 점이 있을 때만 쓰고 없으면 쓰지 않습니다.
- 무엇을 한계로 쓸지는 CONTRIBUTING의 공통 원칙 하나로 정합니다. 셀마다 따로 정한 예외 조건은 셀 정의에서 지웁니다.
- 예외 조건 문장 안에 어디에 쓸지나 무엇과 연결할지 같은 다른 지시가 함께 있으면 그 지시만 남깁니다. 예를 들어 E03.03과 T02.04에서 확인하지 못한 보호를 "실제 보호 미확인"으로 쓰는 지시는 한계 단락에 쓰는 지시로 바꿔 남깁니다.
- 앞 결정에서 예외 표시를 붙이는 조건을 정한 부분은 모두 이 결정으로 대체합니다. 결정 본문은 고치지 않습니다.

## 영향

- 셀 정의 43개에서 예외 조건 70개 필드를 고쳤습니다. 내용이 예외 조건뿐이던 T10.02와 D04.07의 exclude는 경계 문장으로 새로 썼습니다.
- 원고 191개 파일에서 머리말의 `exception` 643줄을 지우고 `**예외.**` 단락 407개를 `**한계.**`로 바꿨습니다. 단락 내용은 그대로입니다.
- `tools/pilot.py`는 머리말에 `exception`이 있으면 오류로 알립니다. 단락 머리는 `**구현.**` 하나이거나 `**구현.**`과 `**한계.**`이어야 합니다. 화면 데이터에서 예외 값을 뺐습니다.
- `matrix/schema/report.schema.json`에서 `exception`을 뺐습니다.
- 화면에서 셀 화면의 예외 배지와 범례를 없애고 원고 단락 이름표를 "한계"로 바꿨습니다.
- CONTRIBUTING, `reports/README.mdx`, `matrix/README.md`, 용어 사전을 고쳤습니다. 용어 사전의 「예외 표시」를 지우고 「예외」 항목을 「한계」로 바꿨습니다.
- 0010, 0015, 0022의 예외 표시 부분을 대체합니다.
