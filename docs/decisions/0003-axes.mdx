# 0003. 축 여덟 개를 두고 R·F·D축은 같은 자료를 다른 행위로 봅니다

- 날짜: 2026-10-08(2026-10-07의 결정을 정리)
- 상태: 채택
- 결정한 사람: 결정권자(팀)

## 배경

조사에서 나온 판단(발견사항, 결론, 보고)에 관한 셀이 실행 결과 전달(R)과 파생물 관리(D)에 나뉘어 있었습니다.
같은 기능이 두 축 사이를 오갔고, D축은 저장된 자료를 보는 셀과 판단을 보는 셀이 섞여 묻는 것이 둘이었습니다.
"결론"과 "발견사항"도 누가 만들었는지로 나눠, 도구가 낸 판정이나 서버 안 모델이 만든 판단을 어디에 둘지 판정이 갈렸습니다.

## 결정

**축**

| 축 | 이름 | 보는 것 |
|---|---|---|
| P | 절차 관리 | 분석 방법 선택, 다음 작업, 진척, 조사 단위와 상태, 사건 자료 정리 |
| E | 원본 증거 관리 | 증거 등록, 무결성, 원본 변경 방지, 분석 입력 준비 |
| T | 도구 실행 통제 | 도구 명세, 실행 전 검사, 실행 방식, 도구 확인, 종료 판별, 대응 조치 |
| R | 실행 결과 전달 | 관측과 분석 결과를 어떻게 표현하고 전달하는가 |
| F | 발견사항과 결론 | 무엇을 판단하고, 안내하고, 기록하고, 검증하고, 보고하는가 |
| L | 서버 기록 | MCP 도구 호출과 그 실행의 이력 |
| D | 파생물 관리 | 저장된 표현을 어떻게 보관하고, 잇고, 지키고, 다시 만드는가 |
| I | 외부 연동 통제 | 외부 연결의 조건과 목적지, 분석 도구의 통신, 보내는 자료, 자격증명 |

- R·F·D축은 대상을 나눠 갖지 않고 같은 자료를 서로 다른 행위로 봅니다. 판단의 속성(확신 수준, 근거, 확정 상태)은 F, 그것을 실어 나르는 형태(잘림, 출처, 상태)는 R, 그것을 담은 파일의 보관·경로·기준값은 D입니다.

**발견사항과 결론**
- 발견사항은 조사에서 확인했거나 의심하는 개별 사실이고, 결론은 발견사항이나 다른 정보를 엮어 내린 해석입니다.
- 둘 다 도구, 서버의 규칙, 서버 안의 모델, 클라이언트 모델 어디서든 나올 수 있습니다. F축은 누가 만들었는지가 아니라 서버가 그것을 어떻게 다루는지를 분류합니다.
- 도구가 낸 판정이나 결론을 서버가 다시 엮거나 판정을 더하지 않고 그대로 옮기면 R축에서 봅니다.

## 영향

- 새 서버를 볼 때 같은 기능이 어느 축에 속하는지 행위(전달, 판단, 보관)로 정합니다.
- 축 설명은 `matrix/cells/<축>/index.mdx`에, 용어의 뜻은 용어 사전에 있습니다.
