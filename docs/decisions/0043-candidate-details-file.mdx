# 0043. 구현 사례가 없는 상세를 셀 정의에서 후보 파일로 옮깁니다

- 날짜: 2026-10-06
- 상태: 채택
- 결정한 사람: 결정권자(팀)

## 배경

상세는 기준에 맞는 구현 사례(원고 연결이나 `seen_in`)가 있을 때만 두기로 했습니다.
그런데 셀 정의에는 사례가 하나도 없는 상세가 38개(전체 276개의 14%) 있었습니다.
화면은 이 상세를 흐린 행으로 보여 줘서 실제 방식처럼 읽힐 수 있었고, 셀마다 상세 목록을 길게 만들었습니다.
반면 이 상세들은 서버를 조사할 때 찾아볼 방식의 목록으로는 쓸모가 있어 그냥 지우기는 아까웠습니다.

## 결정

- 사례가 없는 상세는 셀 정의(`matrix/cells/`)에 두지 않고 `matrix/candidates.yaml`에 셀별로 적습니다. 형식은 셀 정의의 상세와 같습니다(`id`·`name`·`include`·`exclude`).
- 후보는 화면에 보이지 않고 원고를 연결할 수 없습니다. 원고가 후보에 연결하면 `validate`가 오류로 알립니다.
- 사례를 찾으면 그 항목을 셀 정의로 옮기고 번호를 그대로 씁니다.
- 새 상세나 새 후보의 번호는 셀 정의와 후보 파일에서 아직 쓰지 않은 다음 번호로 정합니다. 후보 번호는 다른 상세에 쓰지 않습니다.
- 셀 정의에서 후보를 다른 상세처럼 가리키던 "~는 X에서 봅니다"는 "~는 해당하지 않습니다(후보 X)"로 바꿉니다. 그 상세에 들지 않는다는 기준은 그대로이고 후보 번호로 추적할 수 있습니다.
- 사례가 없는 상세가 셀 정의에 다시 생기면 `validate`가 알림으로 알려 줍니다.

셀 정의에서 사례가 없는 상세 38개를 옮긴 뒤, 기존 상세와 겹치거나 서로 겹치는 후보와 기존 상세와 조건만 다른 후보를 정리해 29개를 남깁니다.

- 기존 상세와 겹쳐 지운 후보 3개
  - P01.06 지원 카탈로그·검증 목록 대조: P01.04 방법과 형식·OS 대조가 담습니다. 목록으로 대조하는 것은 대조 수단입니다.
  - E04.04 메모리 사본 파싱: E04.01 작업 사본 생성이 담습니다. 메모리 덤프의 사본이나 형식을 바꾼 사본도 작업 사본입니다.
  - T05.07 컨테이너 digest 대조: digest 지정은 T05.01 저장소·의존성 고정, 실행 전 대조는 T05.05가 담습니다.
- 후보끼리 합친 3쌍(앞 번호를 남깁니다)
  - T02.01 + T02.02 → T02.01 설정으로 도구 끄기: 설정으로 도구를 끄는 같은 방식이고 적용 시점만 다릅니다.
  - T05.05 + T05.08 → T05.05 사용 전 기대값 대조: 쓰기 직전에 기대값과 대조하는 같은 방식이고 대조하는 값만 다릅니다.
  - R07.03 + R07.04 → R07.03 경계 태그 표시: 태그 위조를 막는 처리는 태그 표시에 딸린 속성입니다.
- 기존 상세와 수단이나 조건만 달라 기존 상세의 포함 기준에 넣은 후보 3개
  - T02.05 조사 상태로 도구 노출 조정 → T03.01·T03.02: 조사 단계나 앞선 결과로 호출을 막는 기준은 같고, 거부하느냐 목록에서 숨기느냐는 수단만 다릅니다. 두 상세의 포함 기준을 "호출을 거부하는"에서 "호출을 막는"으로 바꿉니다.
  - T08.06 러너 소실·시간 초과 뒤 최종 상태 재확인 → T08.05: 최종 상태를 조회해 정하는 방식은 같고 조건만 다릅니다. T08.05 포함 기준을 "최종 상태를 조회해 정하는 경우"로 씁니다.
  - T09.01 조치 전후 상태 기록 → T09.02: 대응 조치의 기록에 무엇을 담느냐의 차이입니다. T09.02 포함 기준에 전후 상태를 함께 남기는 경우를 더합니다.
- 지우거나 합친 번호(P01.06, E04.04, T05.07, T02.02, T05.08, R07.04, T02.05, T08.06, T09.01)는 다시 쓰지 않습니다.

남은 후보는 다음 29개입니다.

P03.02, T02.01, T03.10, T04.06, T04.07, T05.05, T05.06, T06.03, T07.03, R07.03, R07.06, R08.04, L03.01, L04.02, L04.05, D01.05, D02.04, D03.02, D07.06, D09.02, I01.07, I01.08, I02.01, I02.04, I03.05, I04.02, I04.03, I04.05, I04.06

## 영향

- 원고의 판정은 바뀌지 않습니다. 연결된 원고가 없는 상세만 옮겼습니다. 원고가 "D02.04에는 연결하지 않는다"처럼 후보 번호를 적은 문장은 후보 파일에 번호가 남아 있어 그대로 둡니다. 지운 후보를 적은 원고 문장 두 개(Camel P01의 P01.06, trudi T09의 T09.01)는 번호 없이 사실만 남깁니다.
- 셀 정의의 상세는 276개에서 238개가 됩니다.
- 셀 정의 문장 16개를 고쳤습니다. 후보를 가리키던 제외 기준 14개와 범위를 적은 미구현 정의 2개(I01, R08)입니다. T04.09의 "격리 장치(T04.04, T04.06, T04.07)"는 "격리 장치(T04.04)"로 줄였습니다. T05.01 제외 기준의 "(후보 T05.05~T05.08)"은 "(후보 T05.05·T05.06)"으로 고쳤습니다. 기존 상세 T03.01, T03.02, T08.05, T09.02의 포함 기준을 넓히고 T08.02, T08.05, T10.07의 제외 기준을 그에 맞췄습니다. 넓힌 기준으로도 지금 연결된 서버는 그대로 해당해 판정은 바뀌지 않습니다.
- 셀 정의가 바뀌므로 매트릭스 버전을 새 날짜로 바꿉니다. 같은 검토에서 하는 셀 정의 정리(경계 모으기, 형식뿐인 미구현·비적용 문장 정리)와 함께 한 날짜로 묶습니다.
- 고친 파일: `matrix/candidates.yaml`(새 파일), 셀 정의 24개, `tools/pilot.py`(후보 읽기와 검사), `matrix/README.md`, `CONTRIBUTING.md`, 용어 사전, 원고 작성 가이드.
