# 0041. 셀 정의를 버전 단위로 모아서 바꾸고 분석 중 찾은 문제는 정의 문제 목록에 적습니다

- 날짜: 2026-10-06
- 상태: 채택
- 결정한 사람: 결정권자(팀)

## 배경

셀 정의는 서버를 분석하는 도중에 그때그때 고쳐 왔습니다.
2026-10-01부터 10-06까지 결정 기록이 40건 쌓였고, 그 가운데 약 15건은 새 서버를 분석하다 기존 정의로 판단이 갈려 바로 고친 것이었습니다.

정의를 바꾸면 이미 분석한 모든 서버의 원고를 다시 봐야 합니다.
예를 들어 0040에서 P04·R01을 나눌 때 원고 26개를 고치고 19개를 새로 만들었습니다.
서버가 늘수록 같은 변경의 비용도 커지고, 분석 도중에 정의가 바뀌면 같은 서버 안에서도 원고마다 기준이 달라집니다.

MITRE ATT&CK 같은 매트릭스는 정의를 버전 단위로 내고 버전마다 변경 내역을 남깁니다.

## 결정

- 매트릭스 정의에 버전을 둡니다. 버전은 셀 정의를 바꾼 날짜(`YYYY-MM-DD`)이고 `matrix/config.yaml`의 `version`에 적습니다. 지금 정의(0040까지 반영)는 `2026-10-06`입니다.
- 셀 정의는 셀의 확인 사항, 적용 범위, 경계, 미구현·비적용의 뜻, 기존 상세의 포함·제외 기준, 셀 구성(더하기·지우기·나누기·합치기·번호)을 말합니다.
- 주·부 같은 단계를 두지 않고 날짜만 씁니다. 무엇이 바뀌었는지는 그 버전의 결정 기록이 알려 줍니다.
- 서버를 분석하는 중에는 셀 정의를 고치지 않습니다. 판정이 갈리면 지금 정의대로 판정하고 [정의 문제 목록](../definition-issues/README.mdx)에 적습니다.
- 상세를 더하거나 상세 이름을 바꾸거나 `seen_in`을 고치는 일은 정의 범위를 바꾸지 않으므로 버전과 관계없이 언제든 합니다.
- 검토 주기(새 서버 분석을 하나 마칠 때마다, 또는 팀이 정한 때)에 정의 문제 목록을 모아 한 번에 고치고 버전을 그 날짜로 바꿉니다. 결정 기록은 버전마다 하나를 씁니다.
- 서버 머리(`reports/<서버>/index.mdx`)에 그 원고가 기준으로 삼은 버전 `matrix_version`을 적습니다. `validate`는 이 값이 지금 버전보다 이른 서버를 "다시 볼 서버"로 알립니다.

## 영향

- 다시 조사할 셀과 서버는 없습니다. 원고가 있는 서버 7개의 `matrix_version`을 `2026-10-06`으로 적습니다.
- 고친 파일: `matrix/config.yaml`과 `matrix/schema/config.schema.json`(`version`), `tools/pilot.py`(`matrix_version` 검사와 알림), 서버 머리 7개, `docs/definition-issues/README.mdx`(새 문서), `docs/index.mdx`, `CONTRIBUTING.md`(「정의를 바꾸는 때와 버전」), `AGENTS.md`, `matrix/README.md`, `reports/README.mdx`, `docs/glossary/README.mdx`.
