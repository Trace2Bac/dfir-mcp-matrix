# 0002. 파생물 저장 실패 처리를 D01에서 떼어 새 셀 D09로 옮깁니다

- 날짜: 2026-10-01
- 상태: 채택
- 결정한 사람: 결정권자(팀)

## 배경

D01 파생물 보관 셀 하나가 두 가지 질문을 함께 묻고 있었습니다.

- 무엇을 어디에 보관하는가
- 저장이 실패하면 어떻게 하는가

서버 기록을 다루는 쪽은 사정이 달랐습니다.
41번 결정에서 기록 쓰기 실패를 L03 기록 실패 처리라는 별도 셀로 두었습니다.
그래서 두 축이 저장 실패를 다루는 기준이 서로 달랐습니다.

또 D01.05 "보존·정리 정책"이 P05 사건 자료 정리의 "자동 정리"와 겹쳤습니다.

## 결정

- D01은 보관만 묻습니다. 새 질문은 "도구 출력·파생물·중간 자료를 어디에 어떤 형태로 보관하고 얼마나 남기는가?"입니다.
- 저장 실패 처리는 새 셀 D09 파생물 저장 실패 처리로 옮깁니다. D09는 L03과 같은 구성으로 둡니다.
- 보관한 자료를 지우는 일은 P05에서 봅니다. 누가 지우는지와 삭제 흔적이 여기에 해당합니다. 지우는 주체는 모델 도구, 사용자 명령, 자동 정리입니다.
- D01.05는 이름을 "보존 기간·대상 정책"으로 바꾸고, 보관 정책만 봅니다.
- 용어를 고칩니다. D01.04 "원본·가공본 별도 보관"을 "도구 출력·가공본 별도 보관"으로 바꿉니다. "원본"이라는 말은 원본 증거를 가리킬 때만 씁니다.
- R06.03 "적용 위치별(응답·기록·보고서) 처리"를 지웁니다. 이것은 구현 방식 하나를 가리키는 상세가 아니라 보는 관점이기 때문입니다. 어디에 적용하는지는 원고의 **구현** 단락에 씁니다.

옮기거나 지운 상세는 다음과 같습니다.

| 옛 번호 | 새 번호 | 상세 |
|---|---|---|
| D01.06 | D09.01 | 오류·부분 완료 표시 |
| D01.07 | D09.02 | 재시도·대체 저장 |
| D01.08 | D09.03 | 저장 확인·검증 |
| D01.09 | D09.04 | 알림 없이 계속 |
| R06.03 | 없음 | 적용 위치별(응답·기록·보고서) 처리 |

새 셀은 D축의 마지막 번호 다음인 D09를 받았습니다. 다른 셀의 번호는 바뀌지 않습니다.

## 영향

- 공통 셀은 41개, 조건부 셀은 1개(T09)가 됩니다.
- D01, D09, R06은 시범 셀이 아니어서 고칠 원고가 없습니다.
- `validate`가 다른 셀의 상세를 가리키는 `merged_into`도 받아들이도록 고쳤습니다. 셀을 나누면서 상세를 다른 셀로 옮길 때 이 값을 씁니다.
