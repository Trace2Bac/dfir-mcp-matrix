# 0028. 같은 저장소의 클라이언트 코드가 남기는 보조 기록과 만드는 보고 산출물도 L01·D08에서 봅니다

- 날짜: 2026-10-05
- 상태: 채택(0013 범위 보완)
- 결정한 사람: 결정권자(팀)

## 배경

protocol-siftpp를 조사하면서, 같은 저장소의 클라이언트 `siftpp-investigate`가 훅이 아니라 자기 코드로 기록을 남기고 보고서를 만든다는 것이 드러났습니다.

- **L01**: 결정 0027로 만든 L01.10은 "클라이언트 훅이나 설정"이 남기는 보조 기록만 담았습니다. protocol-siftpp 클라이언트는 `orchestrator.py`가 모델 호출, 발견사항 제출, 검토, 실행 시작과 끝을 서버 기록과 다른 파일에 직접 씁니다. 기록하는 방법만 다르고 하는 일은 trudi·Camel의 훅과 같은데 연결 근거가 없었습니다. L01 scope의 "클라이언트 훅이 서버 기록에 더하는 항목"은 사건 폴더에 남기는 Camel과도 맞지 않았습니다.
- **D08**: 결정 0013은 같은 저장소의 사용자 CLI나 클라이언트 훅이 "서버 기록"을 정해진 코드로 가공해 만드는 산출물을 인정했습니다. protocol-siftpp의 `report.json`·`report.md`는 클라이언트 코드가 조사 중 받은 서버 응답으로 만들고, `report.html`은 사용자 CLI가 클라이언트 기록을 읽어 만듭니다. 판정은 구현으로 두었지만 scope 문구가 그 판정을 뒷받침하지 못했습니다.

## 결정

- **L01.10**의 이름을 「클라이언트의 보조 기록」으로 바꾸고, include의 주체를 "같은 저장소가 함께 제공하는 클라이언트 코드, 훅, 설정"으로 넓힙니다. 클라이언트 쪽 기록의 예에 "클라이언트가 부른 모델 호출"을 더합니다.
- **L01 scope** 문장을 "같은 저장소가 함께 제공하는 클라이언트 코드, 훅, 설정이 서버 기록이나 사건 폴더에 남기는 보조 기록은 L01.10에서 봅니다."로 고치고, T02.10 exclude도 "서버 기록이나 사건 폴더"로 맞춥니다.
- **D08 scope**의 인정 범위를 "같은 저장소가 함께 제공하는 사용자 CLI나 클라이언트 코드·훅이 서버 기록이나 서버 응답을 정해진 코드로 가공해 그 산출물을 만드는 경로"로 넓힙니다. D08.05 exclude도 같이 맞춥니다. 사용자가 실행해야 산출물이 생긴다는 점을 구현 단락 첫머리에 쓰는 조건과 클라이언트 모델이 직접 쓰는 파일을 빼는 조건은 그대로 둡니다.
- 용어 사전의 「보고 산출물」 뜻에 같은 범위를 더합니다.

이 결정은 클라이언트의 발견사항 제출이나 검토를 D05·D07의 서버 기능으로 인정하지 않습니다. 클라이언트 동작은 상세가 클라이언트 쪽 방식을 묻는 경우와 D08에서만 구현으로 셉니다(결정 0008, 0021).

## 영향

- 결정 0013의 D08 인정 범위를 넓힙니다.
- trudi·Camel·protocol-siftpp의 L01.10 소제목 이름이 바뀝니다. 연결과 예외 표시는 그대로입니다.
- mulder의 `mulder investigate`가 사건 폴더에 남기는 기록이 L01.10에 해당하는지 다시 확인합니다.
- D08 연결이 바뀌는 원고는 없습니다. protocol-siftpp D08은 이 결정으로 scope 문구의 근거를 얻습니다.
