# 0034. 2026-10-06 전체 검토에 따라 셀 다섯 개의 범위 문구를 고칩니다

- 날짜: 2026-10-06
- 상태: 채택(0032의 "결론" 정의 보완, 0028의 D08 재료 범위 보완)
- 결정한 사람: 결정권자(팀)

## 배경

2026-10-06 전체 검토(`docs/reviews/2026-10-06-full-matrix/`)에서 셀 범위 문구가 원고 판정을 서버마다 갈라 놓는 곳을 찾았습니다.

- D06은 "집계"를 서버의 판단에 넣었지만 집계만 보는 상세가 없었습니다. 건수를 세어 응답하는 것은 R01.03이 이미 봅니다.
- D08 scope는 클라이언트 코드가 "서버 기록이나 서버 응답"을 가공한 산출물을 포함한다고 적었습니다. 0029에서 "서버 기록"이 MCP 서버의 기록으로 좁혀져, 클라이언트의 MCP 호출 기록을 가공한 산출물이 문구에서 빠졌습니다.
- E03.03 include가 "서버에는 쓰기를 막는 장치가 없고"라고 서버 단위로 적어, 다른 장치가 있는 서버(trudi)에서 외부 도구에 원본 보호를 맡기는 경로가 빠졌습니다.
- D04 not_applicable이 "파일이나 DB에 아무것도 만들지 않는 경우"였습니다. 서버 기록 파일만 쓰는 서버(protocol-siftpp)가 D04에서만 구현으로 나왔습니다.
- E04.01의 "그 사본을 분석 입력으로 쓰면"을 서버가 다음 연산에 넘길 때로 좁게 읽어, 같은 전체 복원 기능이 서버마다 다르게 분류됐습니다.

## 결정

- D06 question·scope·not_implemented와 용어 사전 「결론」에서 "집계"를 뺍니다. 건수가 판정이나 점수에 쓰이면 D06.01·D06.03에서 봅니다. not_implemented 끝 문장은 "판단은 클라이언트 모델이 하고, 모델이 기록으로 낸 주장은 발견사항(D05)으로 봅니다"로 고칩니다.
- D08 scope와 D08.05 exclude의 재료를 "서버 기록, 서버 응답, 또는 클라이언트의 MCP 호출 기록(L01.10)"으로 고칩니다.
- E03.03 include를 경로 단위로 고칩니다. exclude에는 외부 도구가 원본을 읽기 모드로 여는지 서버 머리의 버전 기준으로 소스를 확인하고 확인하지 못하면 한계 단락에 "실제 보호 미확인"이라고 쓴다는 기준을 둡니다(0015와 같음).
- D04 not_applicable을 파생물 기준으로 고칩니다. 서버 기록만 담은 파일은 L01·L04에서 봅니다. 서버 기록 파일이 발견사항 같은 파생물도 담으면 그 파일 경로는 D04에서 봅니다(0029의 역할 기준).
- E04.01 include에 "서버가 꺼낸 사본을 같은 호출에서 다음 분석에 넘기는지와 관계없이, 분석에 쓰도록 꺼내 두면 해당합니다."를 더합니다.

상세 단위로 고친 문구는 다음과 같습니다. 상세 단위 변경이므로 기록만 남깁니다.

- T01.06 exclude: 인용이 비어 대조할 값이 없는 경우는 D07.01에서 봅니다.
- D06.02 include: 위치에 "MFT 레코드 번호처럼 차례가 위치를 뜻하는 번호"를 넣습니다.
- P04.02 include: 사건 안의 조사 ID 대조도 넣습니다.
- P05.04 exclude: 대상을 제한하는 장치가 있으나 일부 조건에서 원본까지 지우는 경우는 P05.05의 한계로 씁니다.
- L01.07 `seen_in`에서 ChainsawMCP를 뺍니다. 도구마다 붙인 데코레이터로 기록하므로 L01.08에 해당합니다.

## 영향

- protocol-siftpp D04는 비적용이 됩니다. trudi는 E03.03에 새로 연결하고 sift-kernel은 `recover_deleted`로 E04.01에 새로 연결합니다.
- 원고 반영 내용은 같은 날 검토 묶음 1·2의 결정에 따릅니다.
