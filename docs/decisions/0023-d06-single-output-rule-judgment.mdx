# 0023. D06에 도구 출력 하나에 규칙을 대어 판정하는 경우도 넣습니다

- 날짜: 2026-10-04
- 상태: 채택
- 결정한 사람: 결정권자(팀)

## 배경

D06 scope는 "여러 도구 결과나 발견사항을 분류해 잇거나"로 시작했고, D06.01 include는 "여러 결과 항목을 분류하고 잇는 경우"였습니다.

그런데 원고에는 도구 출력 하나의 레코드에 임계값, 값 조건, 서명 같은 규칙을 대어 이상 여부만 판정하는 도구가 D06.01에 여럿 들어가 있었습니다. trudi `af.timestomp_drift`, mulder `detect_timestomping`, sift-kernel `detect_wiping_tools`, Camel `ValidateProcessTreeAsync`가 그런 예입니다. 이 도구들은 결과를 잇지 않으므로 문구에 맞지 않았습니다.

mulder `analyze_office_document`의 위험 등급은 D06.03에 있었지만, 가중치나 건수를 계산하지 않고 VBA, 자동 실행, 실행 낱말이 있는지의 조합으로 등급을 정합니다. D06.03 include의 "가중치, 평균, 유사도, 건수"에 맞지 않았습니다.

## 결정

- D06 scope의 "분류해 잇거나"를 "분류하거나 잇거나"로 바꿉니다.
- D06.01 include의 "여러 결과 항목을 분류하고 잇는"을 "결과 항목을 분류하거나 잇는"으로 바꿉니다.
- 규칙으로 판정하는 경우는 D06.01, 가중치·평균·유사도·건수로 점수나 등급을 계산하는 경우는 D06.03으로 봅니다. 값을 옮기거나 형식만 바꾸는 경우는 지금처럼 R01에서 봅니다.

## 영향

- mulder `analyze_office_document`의 등급을 D06.03에서 D06.01로 옮겼습니다.
- mulder `analyze_pdf`의 존재 규칙은 D06.01에, 위험 낱말 개수 규칙은 D06.03에 나눠 적었습니다.
- mulder `detect_steganography`를 D06.01에 더했습니다.
- mulder 보고서 렌더러의 IOC 정규식 표는 새로 판정하지 않고 값을 뽑는 일이라 D06.01에서 빼고 D08에 두었습니다.
- trudi·sift-kernel·Camel의 단일 출력 탐지기는 연결이 바뀌지 않았습니다.
