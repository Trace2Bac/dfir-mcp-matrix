# 0015. R03에 실행 중 알림을 넣고 외부 라이브러리 동작의 근거 기준을 정한다

- 날짜: 2026-10-02
- 상태: 채택
- 결정한 사람: 결정권자(팀)

## 배경

Camel 원고를 쓰고 검토하면서 지금 셀 정의로 담지 못하는 일이 나왔다.

- Camel `Execute`는 스크립트가 도는 동안 20초마다 진행 알림을 보내지만 R03은 완료·오류만 물었다.
- 기록 쓰기 실패 처리처럼 외부 라이브러리가 정하는 동작은 늘 "확인하지 못함" †가 되었다.
- L04가 미구현인 서버는 모델 도구로 기록을 지울 수 있다는 사실을 † 사유로 둘 곳이 없었다.
- T04 scope가 †를 붙이지 않는 호출 방식 목록에 새 상세 T04.09를 넣지 않았다.

## 결정

- R03 질문을 "호출자에게 분석 완료·오류·부재·누락과 실행 중 상태를 어떻게 알리는가?"로 넓히고 상세 R03.05 "실행 중 경과·생존 알림"을 더한다. 경과·생존만 알리고 진행률이 아니면 그 사실을 구현에 적는다.
- 외부 라이브러리가 정하는 동작은 저장소의 의존성 관리 파일에서 실제로 쓰는 버전을 찾고 그 버전의 소스나 공식 문서를 근거로 확인한다. 버전을 정할 수 없거나 근거를 찾지 못한 경우에만 "확인하지 못함"으로 †를 붙인다. CONTRIBUTING의 판단 기준에 적는다.
- 모델이 부를 수 있는 도구로 기록을 지우거나 덮어쓸 수 있는지는 P05.01에서 본다. L04에 위변조 방지 장치가 있는데 그 경로가 장치를 우회하면 †다. L04 `boundary`를 고친다.
- T04 scope의 호출 방식 목록에 T04.09를 넣는다.
- 셀 정의와 원고에서 직역 느낌의 용어를 고친다. 도구·자료의 "판"은 "버전"으로, 예외를 "삼킨다"는 "호출한 쪽으로 넘기지 않는다"로 쓴다.

## 영향

Camel R03에 R03.05를 더했다.
Camel L03.04는 Serilog 4.2.0 소스로 기록 쓰기 실패 처리를 확인해 †를 뗐다.
E04.04에 포함·제외 기준을 썼다.
