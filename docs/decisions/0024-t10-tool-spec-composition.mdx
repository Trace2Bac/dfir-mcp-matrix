# 0024. 도구 명세를 만드는 방식을 보는 새 셀 T10을 더합니다

- 날짜: 2026-10-04
- 상태: 채택(0000의 8번 가운데 annotation 위치를 대체)
- 결정한 사람: 결정권자(팀)

## 배경

모델은 서버가 노출하는 도구 이름, 설명, 입력 schema, annotation, 사용법 문서를 보고 도구를 고릅니다. 서버마다 이 명세를 만드는 방식이 다르고 그 차이에서 실제 결함이 나왔습니다.

- trudi는 실행 설정에 따라 도구 설명을 300자로 줄이고, 중복된 namespace 접두어를 뗍니다.
- sift-kernel은 커널 도구의 schema를 처리기와 따로 손으로 적고, 분류 도구의 설명과 연산 목록을 표에서 만듭니다. 그 결과 timeline schema가 알리는 인자와 처리기가 읽는 인자가 다르고, 쓰기 연산이 있는 도구를 `readOnlyHint`로 표시하며, 목록 변경 알림을 보내도 목록은 바뀌지 않습니다.
- Camel `Execute`의 schema는 `script` 하나이고 SDK 사용법은 손으로 쓴 리소스 문서에 있습니다.

T02는 호출을 어떻게 제한하는지, T01은 실행 전에 인자를 어떻게 검사하는지, R04·R07·P02.01은 명세에 적힌 안내의 내용을 묻습니다. 명세를 무엇으로 만들고 설정에 따라 어떻게 바꾸며 실제 처리와 맞는지를 묻는 셀은 없었습니다. 첫 버전 전 결정(0000의 8번)은 annotation을 프로필에만 두기로 했지만 그 자리는 만들어지지 않았습니다.

## 결정

- T축에 새 셀 T10 「도구 명세 구성」을 더합니다. 상세는 실제 구현이 있는 7개입니다.
  - T10.01 처리 함수에서 명세 생성
  - T10.02 처리기와 따로 둔 명세
  - T10.03 묶음 도구의 연산 명세를 schema 밖에 둠
  - T10.04 실행 설정·클라이언트별 명세 변경
  - T10.05 등록 이름 변환
  - T10.06 도구 annotation 표시
  - T10.07 실행 중 목록 변경 알림
- 명세가 알리는 인자, 동작, 목록이 실제 처리와 다르거나 설정에 따라 주의 문구가 빠지면 †를 붙입니다.
- annotation은 이 셀에서 보되, 호출 제한·승인·원본 보호로 인정하지 않는다는 0000 8번의 취지는 T10.06 exclude로 유지합니다.
- T01·T02 boundary와 T축 설명에 T10을 가리키는 문장을 더합니다.

## 영향

- trudi·mulder·Camel·sift-kernel의 T10 원고를 새로 썼습니다.
- 원고가 없는 다른 서버는 T10이 미확인으로 보입니다.
