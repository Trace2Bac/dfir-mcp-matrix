# 0010. E03의 † 범위를 공통 규칙에 맞추고 T08 비적용을 좁히고 P01.05를 P01.04에 합친다

- 날짜: 2026-10-02
- 상태: 채택
- 결정한 사람: 결정권자(팀)

## 배경

2026-10-02 검토(`docs/reviews/2026-10-02/review.md` 4~6번)가 셀 정의 사이의 충돌 세 가지를 짚었다.

- E03의 scope는 원본에 닿는 경로 가운데 하나라도 장치가 걸리지 않으면 †를 붙이게 했다. 공통 규칙은 구현에 적은 적용 범위 안의 예외에만 †를 붙인다.
- T08의 scope는 라이브러리 분석 호출을 포함하지만 비적용은 라이브러리 호출만 하는 서버였다. regipy처럼 외부 프로그램 없이 라이브러리 예외를 잡아 실패로 돌려주는 서버를 볼 곳이 없었다.
- P01.05 필수 입력 확인과 T07.01 가용성 검사가 부속 자료 파일이 있는지 보는 검사를 함께 셌다.

## 결정

- E03의 scope를 공통 규칙에 맞춘다. 구현에 적은 장치가 걸리는 경로 안의 우회·꺼짐·변경·미확인에만 †를 붙인다. 장치가 없는 다른 실행 방식·도구·경로는 구현에 적는다. 원본을 지키는 것이 외부 도구의 동작뿐이면 E03.03에서 본다.
- T08의 비적용을 "분석을 실행하지 않고 저장된 자료를 조회만 하는 서버"로 좁힌다. 라이브러리 호출만 하는 서버도 T08을 본다. 미구현에 예외를 더하고 상세 T08.08 "라이브러리 예외를 실패로 구별"을 더한다(`seen_in: regipy`).
- P01.05를 지우고 P01.04 방법과 형식·OS 대조에 합친다. 부속 입력이 맞는지는 P01.04, 있는지만 보는 검사는 T07.01에서 본다.

## 영향

mulder E03.01의 †를 뗐다. 호스트 설치 실행과 `run_dislocker` 마운트는 장치가 없는 경로로 구현에 적었다. trudi·mcp_dfir의 E03.01 †는 장치가 걸리는 경로 안의 예외라 그대로다.
T08·P01·T07 원고는 바뀌지 않는다.
