# 0010. E03의 † 범위를 공통 규칙에 맞추고, T08 비적용을 좁히고, P01.05를 P01.04에 합칩니다

- 날짜: 2026-10-02
- 상태: 채택(예외 표시 부분은 0033으로 대체)
- 결정한 사람: 결정권자(팀)

## 배경

2026-10-02 검토(`docs/reviews/2026-10-02/review.md` 4~6번)에서 셀 정의끼리 충돌하는 곳 세 가지가 지적되었습니다.

1. **E03의 † 기준이 공통 규칙과 달랐습니다.** †(예외 표시)는 원고의 구현 단락에 적은 적용 범위 안에서 그 방식이 적용되지 않는 경우가 있다는 표시입니다.
   - E03의 scope는 원본에 닿는 경로 가운데 하나라도 장치가 걸리지 않으면 †를 붙이도록 했습니다.
   - 하지만 공통 규칙은 원고의 **구현** 단락에 적은 적용 범위 안에서 생긴 예외에만 †를 붙입니다.
2. **T08의 scope와 비적용이 맞지 않았습니다.**
   - T08의 scope는 라이브러리 분석 호출을 포함했습니다. 하지만 비적용은 라이브러리 호출만 하는 서버였습니다.
   - 그래서 regipy처럼 외부 프로그램 없이 라이브러리 예외를 잡아 실패로 돌려주는 서버를 볼 곳이 없었습니다.
3. **같은 검사가 두 상세에 해당했습니다.** 부속 자료 파일이 있는지 보는 검사가 P01.05 필수 입력 확인과 T07.01 가용성 검사 양쪽에 해당했습니다.

## 결정

- E03의 scope를 공통 규칙에 맞춥니다.
  - **구현** 단락에 적은 장치가 걸리는 경로 안에서 일어나는 우회, 꺼짐, 변경, 미확인에만 †를 붙입니다.
  - 장치가 없는 다른 실행 방식, 도구, 경로는 **구현** 단락에 씁니다.
  - 원본을 지키는 것이 외부 도구의 동작뿐이면 E03.03에서 봅니다.
- T08의 비적용을 "분석을 실행하지 않고 저장된 자료를 조회만 하는 서버"로 좁힙니다.
  - 라이브러리 호출만 하는 서버도 T08을 봅니다.
  - 미구현에 예외를 더합니다.
  - 상세 T08.08 "라이브러리 예외를 실패로 구별"을 더합니다(`seen_in: regipy`).
- P01.05를 지우고 P01.04 방법과 형식·OS 대조에 합칩니다.
  - 부속 입력이 맞는지는 P01.04에서 봅니다.
  - 부속 입력이 있는지만 보는 검사는 T07.01에서 봅니다.

## 영향

- mulder E03.01의 †를 뗐습니다. 호스트 설치 실행과 `run_dislocker` 마운트는 장치가 없는 경로로 보고 **구현** 단락에 썼습니다.
- trudi와 mcp_dfir의 E03.01 †는 그대로 둡니다. 장치가 걸리는 경로 안에서 생긴 예외이기 때문입니다.
- T08, P01, T07 원고는 바뀌지 않습니다.
