# 0038. 매트릭스를 분류표로 정하고 셀 정의에서 평가하는 말을 뺍니다

- 날짜: 2026-10-06
- 상태: 채택
- 결정한 사람: 결정권자(팀)

## 배경

이 매트릭스가 서버의 방식을 분류하는 표인지, 확인 사항을 지키는지 판정하는 표인지 정해 두지 않았습니다.
그래서 셀 정의와 안내 문서에 두 성격의 말이 섞여 있었습니다.

- 축 설명 7개가 "믿을 수 있게 관리하는지", "안전하고 정확하게 실행하는지"처럼 평가하는 문장이었습니다.
- 셀 정의의 포함·제외 기준에 "~로 인정하지 않습니다"·"~로 인정합니다"가 20번, "결함으로 보지 않습니다" 같은 평가 문장이 있었습니다.
- T07 질문은 "확인하나요? … 처리하나요? … 알리나요?"처럼 예와 아니오로 답하는 질문 셋이었고, T01 질문에는 "올바르고"가 있었습니다.
- 용어 사전과 CONTRIBUTING은 한계 단락을 "미비한 점"을 쓰는 곳으로 설명했습니다.

## 결정

- 이 매트릭스는 서버가 셀이 다루는 일을 어떤 방식으로 하는지 분류하는 표입니다. 방식에 좋고 나쁨을 매기지 않습니다.
- 상세는 분류값입니다. 장치가 없는 동작(예: "알림 없이 계속")도 관찰한 방식이면 상세로 둡니다.
- 미구현은 셀이 다루는 장치나 처리가 서버에 없어 어느 상세에도 해당하지 않는다는 분류 결과입니다.
- 셀 정의와 원고에는 평가하는 말 대신 "~에 해당한다", "~에 해당하지 않는다" 같은 분류의 말을 씁니다.
- 셀 질문은 "어떻게 ~하나요?"로 묻습니다.
- 한계 단락에는 구현 단락에 적은 적용 범위 안에서 그 방식이 적용되지 않는 경로나 조건을 사실로 씁니다.

이에 따라 다음을 고칩니다.

- 축 설명 7개를 "~하는 방식을 분류합니다"와 그 축에 속하는 일의 목록으로 다시 씁니다.
- T01 question: "서버는 실행 전에 이번 호출의 인자와 입력을 어떻게 검사하고 허용한 접근 범위 안에 있는지 어떻게 확인하나요?"
- T07 question: "서버는 필요한 외부 도구와 참조 자료가 있는지 어떻게 확인하고 없거나 실패할 때 어떻게 처리하고 알리나요?"
- 셀 정의 21개 파일의 "~로 인정하지 않습니다"·"~로 인정합니다"·"~로 보지 않습니다"(평가로 쓴 곳)를 "~에 해당하지 않습니다"·"~에 해당합니다"로 바꿉니다. T03.09 exclude의 "stdio 서버에 이 항목이 없는 것을 결함으로 보지 않습니다."는 지웁니다.

판정 범위는 바꾸지 않습니다. 문장의 말만 분류의 말로 바꿉니다.

## 영향

- 원고 연결과 판정은 바뀌지 않습니다. 다시 조사할 셀은 없습니다.
- 고친 파일: `matrix/cells/*/index.mdx` 7개, 셀 정의 21개, `CONTRIBUTING.md`(「매트릭스는 분류표입니다」 절과 한계 단락 설명), `docs/glossary/README.mdx`(매트릭스·미구현·적용 범위·한계), `reports/README.mdx`(한계 단락 설명), `tools/pilot.py`(안내 문구).
- 0033의 한계 단락 설명 가운데 "미비한 점"이라는 표현을 대체합니다.
