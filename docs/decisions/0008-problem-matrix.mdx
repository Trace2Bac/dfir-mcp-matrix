# 0008. 구현 방식 분류표를 가이드라인 목차에 따른 문제 매트릭스로 바꿉니다

- 날짜: 2026-11-24
- 상태: 제안
- 결정한 사람:

## 배경

이전 매트릭스는 축 여덟 개, 셀, 상세로 서버마다 구현 방식을 분류하고, 서버 원고에 구현·한계·근거를 적었다.
원고의 한계 단락이 기여와 가이드라인 원고의 출처가 됐지만, 분류표와 가이드라인의 목차가 서로 달라 같은 문제를 두 구조에서 따로 찾아야 했다.
분류표는 서버가 무엇을 하는지는 보여 주었지만, 어떤 문제가 몇 개 서버에서 관찰됐는지는 한눈에 보여 주지 못했다.

## 결정

매트릭스를 가이드라인의 목차(장 → 원고 → 구현방안 소제목)에 맞춘 문제 매트릭스로 바꾼다.

- 단위는 소제목 아래의 문제다. 문제마다 해당 기능이 있는 서버, 문제가 관찰된 서버, 서버별 사례를 둔다.
- 소제목은 `<원고>.<순서>`(1.3.2)로, 문제는 소제목과 따로 `P0001`로 식별한다. 문제를 다른 소제목으로 옮겨도 문제ID는 바뀌지 않는다.
- 원본은 `problems/_data/*.csv`이고, 페이지는 `tools/problems_build.py`가 만든다.
- 이전의 축·셀 정의(`matrix/`), 서버 원고(`reports/`), 검사 도구(`tools/pilot.py` 등)와 화면은 지운다. 이전 상태는 브랜치 `backup/main-2026-11-24`와 태그 `backup-main-2026-11-24`에 남긴다.

## 영향

- 결정 0001~0007은 이전 매트릭스의 분류 원칙이라 대체됨으로 둔다.
- 작성 규칙과 용어 사전에는 이전 매트릭스의 셀과 원고를 예로 든 문장이 남아 있다. 문제 매트릭스에 맞춰 다시 정리해야 한다.
