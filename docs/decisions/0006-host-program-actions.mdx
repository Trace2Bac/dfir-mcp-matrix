# 0006. 다른 프로그램에 붙은 서버에서는 그 프로그램이 한 일을 서버 구현으로 세지 않습니다

- 날짜: 2026-10-09
- 상태: 채택
- 결정한 사람: 결정권자(팀)

## 배경

autopsy는 Autopsy 데스크톱 프로그램 안에서 도는 MCP 서버입니다.
증거 등록, 케이스 열기, ingest 모듈 실행, 해시 계산, 점수 매기기, 보고서 생성은 모두 Autopsy 본체가 하고 MCP 도구는 그 결과를 케이스 DB에서 조회합니다.
셀 정의는 서버가 혼자 증거를 받아 분석하는 경우를 전제로 쓰여 있어, 본체가 한 일을 서버 구현으로 볼지 셀마다 판정이 갈렸습니다.
증거 등록(E01), 분석 입력 준비(E04), 등록된 ID 대조(T01), 사건 단위(P04), 상태 복구(P06), 외부 연결(I01), 참조 지식 출처(R05)에서 같은 문제가 나왔습니다.

## 결정

- 서버를 담은 프로그램(호스트)이 하는 일은 서버 구현으로 세지 않고 원고에 사실로만 씁니다.
- 서버가 호스트의 결과를 조회해 돌려주는 동작은 결과를 다루는 셀에서 봅니다.
- 이 원칙을 셀 정의에 다음과 같이 반영합니다.
  - E01·E04 비적용에 호스트가 등록한 증거를 조회하거나 읽기만 하는 경우를 넣습니다.
  - T01.05는 서버가 등록하거나 만든 목록과 대조하는 경우로 밝히고, 백엔드에 객체가 있는지만 보는 확인은 T01.02로 보냅니다.
  - P04에 호스트가 연 사건에 호출을 묶는 상세를 둡니다.
  - P06.04에서 호스트가 쥔 상태에 다시 붙는 것을 뺍니다.
  - I01 범위에서 호스트가 만든 백엔드 연결을 서버가 여는 연결로 보지 않습니다.
  - R05에서 호스트가 참조 자료와 대조해 만든 분석 결과를 참조 지식 결과로 보지 않습니다.

## 영향

- 같은 방식으로 다른 프로그램에 붙은 서버를 분석할 때 호스트의 기능을 서버 판정에 섞지 않습니다.
- 매트릭스 버전 2026-10-09에서 정의를 바꿨고, 분석한 서버 가운데 판정이 바뀐 것은 autopsy뿐입니다.
- 규칙은 CONTRIBUTING의 「특수한 경우」에 있습니다.
