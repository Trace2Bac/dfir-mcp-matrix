# 0031. T01은 인자 값을, T03은 인자 밖의 조건을 보도록 경계를 다시 나눕니다

- 날짜: 2026-10-06
- 상태: 채택(0011의 T03.11 범위 보완)
- 결정한 사람: 결정권자(팀)

## 배경

T01~T03의 상세별 구현을 서버마다 대조하자 다음 문제가 드러났습니다.

- T01.03 「백엔드 지원·설정 검사」는 인자 값을 설치된 도구의 지원 목록이나 사용자 설정과 대조하는 경우와 디스크 여유 공간 검사를 함께 담았습니다. 디스크 여유 공간은 인자와 관계없는 실행 자원 상태이고 T03 question이 이미 묻는 것입니다. T01 question의 "실행 조건"도 T03 이름 「실행 조건 확인」과 겹쳤습니다.
- T01.01 exclude는 플러그인을 고르는 값의 검사를 T02로 보내고 T02.07 exclude는 설치된 도구가 지원하는 값과 대조하면 T01.03으로 보냈습니다. 같은 검사를 가리키는 곳이 엇갈렸습니다.
- 발견사항이 인용한 호출 ID가 호출 기록에 있는지 보는 검사가 T01.06, T03.01, D07.01 세 곳에 연결되어 있었습니다. 인용한 ID는 인자이므로 "도구 인자 밖의 조건"을 묻는 T03과 맞지 않았습니다.
- T03.01 include는 앞선 결과가 없으면 거부하는 경우만 적었습니다. 그런데 Camel `SetEvidence`의 재등록 거부와 mulder `load_case`의 사건 전환 거부처럼 앞선 상태가 있어서 거부하는 사례도 연결되어 있었습니다.
- T03.05 「모델이 채우는 확인 값 검사」는 인자로 받은 값을 보는 상세라 T03 question과 맞지 않았고 연결 사례도 없었습니다.

## 결정

- T01 question에서 "실행 조건"을 뺍니다. T01은 이번 호출의 인자와 입력을 보고 T03은 인자 밖의 조건을 봅니다.
- T01.03을 지우고 T01.01에 합칩니다. T01.01은 기준이 서버 코드에 있는 경우와 서버가 실행할 때 읽는 경우(설치된 도구나 백엔드가 지원한다고 알린 값, 사용자 설정)를 함께 봅니다. 실행할 때 읽는 기준을 읽지 못했을 때의 처리는 원고에 씁니다.
- 연산이나 플러그인을 고르는 값을 서버 코드의 목록이나 틀로 좁히는 검사는 T02에서, 설치된 도구가 지원하는 값과 대조하는 검사는 T01.01에서 봅니다.
- 디스크 여유 공간 검사는 T03.11에서 봅니다. T03.11의 이름을 「실행 자원 확인」으로 바꾸고 include에 디스크 여유 공간을 더합니다.
- 인자로 받은 ID를 등록 목록과 대조하는 검사는 T01.06에서 봅니다. T01.06의 이름을 「등록된 ID와 대조」로 바꿉니다. 등록 목록에는 증거 목록, 사건 자료, 호출 기록이 포함됩니다. 그 ID로 읽을 입력을 고르는 경우와 그 ID를 결과의 근거로 남기는 경우를 모두 넣습니다.
- 같은 대조를 D07.01에서도 봅니다. 두 상세는 같은 코드를 각자의 역할로 평가합니다.
  - T01.06은 호출을 허용하는지를 봅니다. 어느 인자를 어느 목록과 대조하는지와 대조를 거치지 않는 경로가 있는지를 씁니다.
  - D07.01은 결론을 받아들이는지를 봅니다. 그 대조가 발견사항을 받는 조건인지와 어떤 기록을 근거로 인정하는지를 씁니다.
  - 인용이 비어 대조할 값이 없는 경우는 D07.01에서만 예외로 봅니다. 인자가 꼭 있어야 하는지는 T01.01의 필수 항목 검사에서 봅니다.
- T03.01의 이름을 「선행 결과 대조」로 바꿉니다. 필요한 결과가 없는 경우뿐 아니라 앞선 작업이 끝나지 않은 경우와 한 번만 허용하는 작업이 이미 이루어진 경우도 포함합니다. 인자로 받은 ID의 대조는 T01.06으로 보냅니다.
- T03.05를 지웁니다. 모델이 같은 대화 안에서 만들 수 있는 값은 T03.06에서 승인자의 기록으로 보지 않습니다. T03 not_implemented가 이미 "도구 인자 밖의 조건"으로 정의하므로 문장을 따로 더하지 않습니다.

## 영향

- mulder: T01.03의 설치 도구 지원 목록·`MULDER_CASE_ID` 대조와 그 예외를 T01.01로 합쳤습니다. 카빙 도구의 디스크 공간 검사와 `OSError` 예외는 T03.11로 옮겼습니다. `submit_finding`·`update_finding`의 인용 대조는 T03.01에서 T01.06으로 옮겼습니다. T03.01의 예외 표시는 다른 예외가 남아 그대로 둡니다.
- trudi: `live_hosts.json` 대조는 T01.01로 옮겼습니다. `misc.evtx_filter`의 헤더 검사는 P01.03·P01.04에 같은 내용이 있어 T01에서 뺐습니다. `misc.record_finding` 등의 인용 대조는 T03.01에서 T01.06으로 옮겼고 남은 예외가 없어 T03.01의 예외 표시를 뗐습니다.
- sift-kernel: `register_finding`·`reassess_finding`의 인용 대조로 T01.06에 새로 연결했습니다. 가설 ID를 대조하지 않는다는 사실은 D07.01에서 T01.06으로 옮겼습니다.
- mulder, trudi, sift-kernel의 D07.01 원고는 대조 방식을 T01.06으로 넘기고 근거로 인정하는 기록의 범위를 남겼습니다.
- Camel·regipy·sift-kernel T03 원고는 소제목만 바꿨습니다. trudi T03 원고에서 T03.05를 가리키던 문장을 고쳤습니다.
- 기존 원고의 사실을 옮긴 것이라 다시 조사할 셀은 없습니다.
- 0011이 더한 T03.11의 범위를 넓힙니다.
