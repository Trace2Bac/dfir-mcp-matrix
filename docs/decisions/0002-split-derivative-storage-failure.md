# 0002. 파생물 저장 실패 처리를 D01에서 D09로 나눈다

- 날짜: 2026-10-01
- 상태: 채택
- 결정한 사람: 결정권자(팀)

## 배경

D01 파생물 보관은 무엇을 어디에 보관하는가와 저장이 실패하면 어떻게 하는가를 함께 물었다.
서버 기록 쪽은 41번 결정에서 기록 쓰기 실패를 L03 기록 실패 처리로 따로 두었으므로 두 축의 기준이 달랐다.
D01.05 "보존·정리 정책"은 P05 사건 자료 정리의 "자동 정리"와 겹쳤다.

## 결정

- D01은 보관만 묻는다. 질문은 "도구 출력·파생물·중간 자료를 어디에 어떤 형태로 보관하고 얼마나 남기는가?"다.
- 저장 실패 처리는 새 셀 D09 파생물 저장 실패 처리로 옮긴다. L03과 같은 짜임이다.
- 보관한 자료를 지우는 주체(모델 도구·운영자 명령·자동 정리)와 삭제 흔적은 P05에서 본다. D01.05는 "보존 기간·대상 정책"으로 이름을 바꿔 보관 정책만 본다.
- 용어를 고친다. D01.04 "원본·가공본 별도 보관"은 "도구 출력·가공본 별도 보관"이다("원본"은 원본 증거에만 쓴다).
- R06.03 "적용 위치별(응답·기록·보고서) 처리"는 상세가 아니라 관점이라 지운다. 어디에 적용하는지는 원고 구현에 적는다.

| 옛 번호 | 새 번호 | 상세 |
|---|---|---|
| D01.06 | D09.01 | 오류·부분 완료 표시 |
| D01.07 | D09.02 | 재시도·대체 저장 |
| D01.08 | D09.03 | 저장 확인·검증 |
| D01.09 | D09.04 | 알림 없이 계속 |
| R06.03 | 없음 | 적용 위치별(응답·기록·보고서) 처리 |

셀 번호는 축 안 마지막 번호 다음(D09)을 받았다. 다른 셀 번호는 바뀌지 않는다.

## 영향

공통 셀은 41개, 조건부 셀은 1개(T09)다.
D01·D09·R06은 시범 셀이 아니라 고칠 원고가 없다.
`validate`가 다른 셀의 상세를 가리키는 `merged_into`를 받도록 고쳤다(셀을 나눠 상세를 옮길 때 쓴다).
