# 0007. mulder 원고를 쓰며 셀 정의 37개를 처음 쓴다

- 날짜: 2026-10-01
- 상태: 채택
- 결정한 사람: 결정권자(팀)

## 배경

시범 셀(E03·T03·R02·L02)과 R07을 뺀 셀은 상세 이름만 있고 적용 범위·미구현·비적용과 상세의 포함·제외 기준이 없었다.
셀 정의를 미리 모두 정하지 않고 서버를 분석하면서 정하기로 했고, 첫 서버로 mulder(기준 커밋 `3164843`)의 전체 셀 원고를 썼다.

## 결정

- 아래 37개 셀에 `scope`·`not_implemented`·`not_applicable`을 처음 썼다.
  - P01~P05, E01·E02·E04, T01·T02·T04~T09, R01·R03~R06, L01·L03·L04, D01~D09, I01~I04
- 상세의 `include`·`exclude`는 mulder가 드는 상세는 mulder 코드로, mulder가 들지 않는 상세는 상세 이름과 셀 질문으로 썼다. 뒤의 것은 구현 사례로 확인하지 않은 기준이다.
- 새 서버를 조사하며 맞지 않는 기준이 나오면 그때 고친다. 상세의 이름·포함·제외는 셀 파일만 고치고, 셀의 `scope`·미구현·비적용을 바꾸면 결정을 더한다.
- 새 정의로 판단하면 첫 버전 전 판정에서 비적용이던 서버가 미구현이 되거나 셀이 적용될 수 있다(예: I02·T05·T07·E01의 비적용 기준). 새 정의를 따른다.
- 상세를 더하고 고쳤다.
  - 더함: D06.06 규칙 기반 공격 단계 분류·흐름 서술, P03.05 모델이 적은 진행 기록 보관, P05.08 자료가 남은 사건의 초기화 거부
  - 이름 변경: D06.04 "모델 추론·공격 흐름 서술" → "모델 추론·서술"

## 영향

`reports/mulder/`에 42개 셀 원고가 생겼다(공통 41개, T09 비적용).
첫 서버가 mulder라 기준이 mulder 구조에 맞춰졌을 수 있다. 두 번째 서버부터 기준을 다시 확인한다.
