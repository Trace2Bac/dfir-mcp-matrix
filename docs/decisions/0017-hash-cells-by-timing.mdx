# 0017. D03·E02 상세를 기준값 계산과 검증 시점으로 나눈다

- 날짜: 2026-10-02
- 상태: 채택
- 결정한 사람: 결정권자(팀)

## 배경

sift-kernel 전체 적용에서 D03.07 "서명·MAC 검증"이 MAC을 붙이는 일과 검증하는 일을 한 상세에 묶어 HMAC만 붙이는 서버를 담지 못했다.
D03·E02 상세는 해시 범위(파일 전체·일부), 기준값을 남기는 곳(응답·기록), 대조 방법(해시 재계산·MAC·크기), 대조 시점이 섞여 있었다.
그래서 한 서버의 같은 동작이 여러 상세에 나뉘어 적혔고 E02.06·E02.07에는 정의가 없었다.

## 결정

- 두 셀을 같은 뼈대로 둔다. 기준값을 자동으로 계산하는 상세, 도구를 요청해 기준값을 계산하는 상세, 도구 호출 중 자동 검증, 도구를 요청해 검증, 불일치 시 중단·경고다.
- D03은 D03.01 "생성 시 기준값 자동 계산", D03.02 "도구를 요청해 기준값 계산", D03.09 "도구 호출 중 자동 검증", D03.11 "도구를 요청해 검증", D03.10 "불일치 시 중단·경고"를 둔다.
- E02는 E02.01 "등록 시 기준값 자동 계산", E02.02 "도구를 요청해 기준값 계산", E02.07 "도구 호출 중 자동 검증", E02.09 "도구를 요청해 검증", E02.08 "불일치 시 중단·경고"를 둔다.
- 해시 범위, MAC·서명, 기준값을 남기는 곳은 기준값 상세의 구현에 적는다. 대조 방법과 기준값을 가져오는 곳은 검증 상세의 구현에 적는다.
- D03.03·D03.04·D03.05·D03.07은 D03.01로, D03.06·D03.08은 D03.11로 합친다. E02.03·E02.04는 E02.02로, E02.05·E02.06은 E02.09로 합친다.

## 영향

mulder D03은 D03.01·D03.11†, sift-kernel D03은 D03.01†가 되었다.
mulder E02는 E02.01†·E02.02, sift-kernel과 Camel E02는 E02.02·E02.09†·E02.08†가 되었다.
sift-kernel D03.01에 `format`이 `json`이면 HMAC이 없다는 †를 더했다.
