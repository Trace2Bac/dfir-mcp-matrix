# 0042. 링크·문장 검사 도구를 이 저장소로 옮기고 새 서버 원고의 틀을 만드는 명령을 둡니다

- 날짜: 2026-10-06
- 상태: 채택
- 결정한 사람: 결정권자(팀)

## 배경

`pilot.py`의 `fill`과 `check`는 옛 매트릭스 저장소(`Claude outputs`)의 `tools/linkify.py`와 `tools/style_lint.py`를 읽어 썼습니다.
새 기여자는 이 저장소 말고도 옛 저장소를 받아 옆 폴더에 두거나 환경변수 `DFIR_V1`을 지정해야 했습니다.
`linkify.py`는 불러올 때 옛 저장소의 판정 YAML을 읽어 서버 목록과 클론 위치를 정했지만, `pilot.py`가 그 값을 이 저장소의 서버 머리(`reports/<서버>/index.mdx`)로 덮어썼습니다.
지금 원고가 있는 서버는 판정 YAML의 클론 위치나 추가 저장소를 쓰지 않습니다.

새 서버를 분석할 때는 서버 머리와 셀 원고 파일을 손으로 만들었습니다.

## 결정

- `linkify.py`와 `style_lint.py`를 이 저장소의 `tools/`로 옮깁니다. 검사 규칙과 변환 동작은 그대로 둡니다.
  - `linkify.py`에서 옛 판정 YAML을 읽는 부분과 옛 초안 폴더를 직접 돌리던 실행부를 뺍니다. 서버 목록은 `pilot.py`가 서버 머리로 채웁니다.
  - 클론은 환경변수 `DFIR_CLONES`가 가리키는 폴더, 없으면 이 저장소의 부모 폴더 아래 서버 이름의 폴더에서 찾습니다.
  - 환경변수 `DFIR_V1`은 더 쓰지 않습니다.
- `pilot.py new <서버> --repo <소유자/이름> --commit <40자 커밋> [셀ID … | all]`을 둡니다.
  - 서버 머리가 없으면 만들고 `matrix/config.yaml`의 `servers`에 서버를 더합니다. 서버 머리의 `matrix_version`은 지금 매트릭스 버전입니다.
  - 셀을 주지 않으면 시범 셀, `all`이면 모든 셀의 원고 틀을 만듭니다. 이미 있는 파일은 건드리지 않습니다.
  - 틀은 머리말 `details`가 비어 있어 화면에서 미확인으로 보이고, `validate`가 "작성 중인 틀"로 알립니다.

## 영향

- 다시 조사할 셀과 서버는 없습니다. Camel·mulder의 `check` 결과(오류 0, 경고 0)는 옮기기 전과 같습니다.
- 고친 파일: `tools/linkify.py`·`tools/style_lint.py`(새 파일), `tools/pilot.py`(도구 읽기, `new` 명령, 틀 파일 안내), `CONTRIBUTING.md`(준비하기), `reports/README.mdx`(새 서버 원고 시작하기), `README.md`, 작성 규칙 README와 0004, 서버 머리 7개의 안내 문구("미비한 점" → "그 방식이 적용되지 않는 경로나 조건").
