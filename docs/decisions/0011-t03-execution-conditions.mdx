# 0011. T03 이름을 "실행 조건 확인"으로 넓히고 실행 자원 상태 확인을 더합니다

- 날짜: 2026-10-02
- 상태: 채택
- 결정한 사람: 결정권자(팀)

## 배경

2026-10-02 검토(`docs/reviews/2026-10-02/review.md` 7번)에서 지적이 하나 나왔습니다.
mulder의 공통 자원 대기를 원고 본문이 설명하지 않는다는 것입니다.

mulder는 동기 도구를 실행하기 전에 다음을 합니다.

- 메모리와 CPU 사용률을 확인하고, 기준을 넘으면 기다립니다.
- 동시에 도는 실행 수를 제한합니다.

이 확인은 도구 인자가 아닌 다른 조건을 보고 실행을 정하는 일입니다.
하지만 T03은 호출을 허용할지만 물었습니다. 그래서 실행을 뒤로 미루는 동작은 담을 수 없었습니다.

## 결정

- T03 이름을 "실행 허가 조건 확인"에서 "실행 조건 확인"으로 바꿉니다.
- 질문을 넓혀, 호출을 허용할지뿐 아니라 언제 실행할지도 묻습니다. 새 질문은 다음과 같습니다.
  - "인자 밖의 조건(앞선 작업·판정 상태, 모델 밖 승인자의 승인, 원격 호출자의 신원, 서버의 실행 자원 상태)으로 호출을 허용할지와 언제 실행할지를 어떻게 정하는가?"
- scope와 미구현도 같은 뜻으로 고칩니다.
- 상세 T03.11 "실행 자원 상태 확인"을 더합니다.
  - 정해 둔 시간을 기다린 뒤 실행하는 것은 설계된 동작입니다. 그래서 원고의 **구현** 단락에 씁니다.
  - 다음 경우에는 †(예외 표시)를 붙입니다. †(예외 표시)는 원고의 구현 단락에 적은 적용 범위 안에서 그 방식이 적용되지 않는 경우가 있다는 표시입니다. 자원 상태를 읽지 못할 때 그냥 통과시키는 경우, 이 확인을 설정으로 끌 수 있는 경우입니다.

## 영향

- 서버 5곳의 T03 원고 제목을 고쳤습니다. 상세 번호와 다른 연결은 그대로입니다.
- mulder T03 원고에 T03.11(†)을 더했습니다.
