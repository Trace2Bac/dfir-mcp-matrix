# 0007. 서버 프로세스 안 분석은 라이브러리 호출과 서버 자체 분석 코드를 함께 뜻합니다

- 날짜: 2026-10-09
- 상태: 채택
- 결정한 사람: 결정권자(팀)

## 배경

T04와 T08이 「라이브러리」를 서로 다르게 읽히게 적고 있었습니다.
T04.01은 "라이브러리 함수로 수행하는 경우"라고 적었지만 원고는 서버 자체 코드로 하는 파싱·계산도 여기에 넣었습니다.
T08의 적용 범위와 미구현·비적용 문장, 그리고 예외를 실패로 구별하는 상세는 "분석 라이브러리"만 적었습니다.
그래서 같은 동작의 판정이 서버마다 갈렸습니다.
findevil은 서버 자체 Python 코드가 파일 읽기 예외를 받아 판정을 보류하는 경로를 예외 처리 상세에 연결했습니다.
sift-kernel은 처리기가 분석 라이브러리를 부르지 않는 서버 코드라는 이유로 그 상세를 보지 않았습니다.
외부 라이브러리 없이 서버 코드로만 분석하는 서버는 T08을 적용할지도 문구로 정할 수 없었습니다.
동기 원격 분석 요청도 T08 적용 범위의 열거에 없었습니다.

## 결정

- 「서버 프로세스 안 분석」은 서버가 자기 프로세스 안에서 라이브러리 함수나 서버 자체 코드로 하는 분석을 뜻합니다. 분석 코드를 외부 라이브러리가 쓰는지 서버가 쓰는지로 판정을 나누지 않습니다.
- T04.01 이름을 「서버 프로세스 안 분석」으로 바꾸고 include·exclude에 서버 자체 코드를 넣습니다.
- T08 적용 범위를 "외부 프로그램, 서버 프로세스 안 분석(라이브러리 호출과 서버 자체 분석 코드), 원격 분석 요청, 비동기 작업"으로 바꾸고 미구현 문장의 열거도 같게 맞춥니다.
- T08 비적용 문장의 "라이브러리"를 "라이브러리나 서버 자체 코드"로 바꿉니다.
- T08의 예외 처리 상세 이름을 「프로세스 안 분석 예외를 실패로 구별」로 바꾸고 include에 서버 자체 분석 코드가 낸 예외를 넣습니다.
- T08의 출력 판독 상세 include에 원격 응답과 오류 상태 값을 넣습니다.

## 영향

- 매트릭스 버전은 이미 2026-10-09였으므로 날짜가 바뀌지 않습니다. 그래서 `validate`는 다시 볼 서버를 알려 주지 않습니다. 이번 변경으로 다시 본 셀과 서버는 아래와 같습니다.
- 다시 본 셀: T04, T08.
- 다시 본 서버: T04 또는 T08 원고가 있는 Camel, mulder, trudi, sift-kernel, findevil, autopsy, protocol-siftpp. mcp_dfir와 regipy는 T04·T08 원고가 없습니다.
- 판정이 바뀐 서버는 없습니다.
  - sift-kernel은 서버 안 처리기를 감싸는 예외 처리가 없어 넓힌 정의로도 예외 처리 상세에 해당하지 않습니다. 이유 문장을 그 사실로 바꿨습니다.
  - protocol-siftpp는 서버 자체 코드의 예외를 처리하지 않고 호출 밖으로 내보내므로 바꿀 것이 없습니다.
  - Camel, mulder, trudi, findevil, autopsy는 예외 처리 상세의 구현 단락에 서버 자체 분석 코드 경로를 더했습니다. 또 예외를 받아 빈 값이나 기본값으로 넘기는 경로를 사실로 적었습니다. mulder T04.01에는 서버 자체 광학 디스크 파서, SQLite 카빙, 접속 간격 계산을 더했습니다.
- T04.06의 원격 API 작업 요청에 연결한 서버는 trudi뿐입니다. trudi는 원격 요청을 실행 파일로 보내므로 기존 상세로 판정이 그대로입니다.
