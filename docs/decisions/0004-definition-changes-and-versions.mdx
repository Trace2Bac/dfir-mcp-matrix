# 0004. 셀 정의는 검토 주기에 모아 바꾸고 날짜로 버전을 붙입니다

- 날짜: 2026-10-08(2026-10-06~10-08의 결정을 정리)
- 상태: 채택
- 결정한 사람: 결정권자(팀)

## 배경

서버를 분석하면서 셀 정의를 바로바로 고치자 이미 분석한 서버의 원고가 정의와 어긋났습니다.
서버가 늘수록 정의를 바꿀 때 다시 볼 원고도 늘어납니다.
정의를 바꿀 때마다 결정 기록을 쓰다 보니 셀 문구 수정 기록이 쌓여 꼭 필요한 결정을 찾기 어려웠습니다.

## 결정

- 매트릭스 정의에 버전을 둡니다. 버전은 셀 정의를 바꾼 날짜(`YYYY-MM-DD`)이고 `matrix/config.yaml`의 `version`에 적습니다.
- 서버를 분석하는 중에는 셀 정의를 고치지 않습니다. 판정이 갈리면 지금 정의대로 판정하고 GitHub 이슈나 토론에 올립니다.
- 검토 주기(새 서버 분석을 하나 마칠 때마다, 또는 팀이 정한 때)에 올라온 문제를 모아 정의를 고치고 버전을 그 날짜로 바꿉니다. 상세를 더하거나 이름을 바꾸는 일은 정의 범위를 바꾸지 않으므로 언제든 합니다.
- 서버 머리의 `matrix_version`에 그 원고가 기준으로 삼은 버전을 적습니다. `validate`는 이 값이 지금 버전보다 이른 서버를 알려 주고, 바뀐 셀은 `matrix/cells/`의 git 이력에서 찾아 다시 봅니다.
- 결정 기록은 축이나 셀을 더하거나 나누거나 합칠 때, 여러 셀에 걸친 판정 원칙을 바꿀 때만 씁니다. 셀 하나의 문구 수정은 커밋 메시지에 무엇을 왜 바꿨는지 남깁니다.
- 다른 문서에 결정 번호를 참조로 달지 않습니다. 규칙은 CONTRIBUTING과 원고 안내에 적고, 결정 기록에는 그렇게 정한 이유를 남깁니다.
- 사이트는 버전 태그 `v<버전>`(같은 날 다시 내면 `v<버전>.<번호>`)을 올릴 때만 빌드하고 배포합니다.

## 영향

- 분석 중에는 정의가 바뀌지 않아 한 서버의 원고가 한 버전 기준으로 쓰입니다.
- 결정 기록이 바탕 결정만 담아, 결정 기록을 합치거나 번호를 다시 매겨도 다른 문서를 고치지 않습니다.
- 절차는 CONTRIBUTING의 「정의를 바꾸는 때와 버전」에 있습니다.
