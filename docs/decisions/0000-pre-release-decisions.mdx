# 0000. 첫 버전 전의 결정 1~41번

- 날짜: 2026-09-30 ~ 2026-10-01
- 상태: 채택(이후 결정이 일부를 대체함. 각 항목 본문 참고)
- 결정한 사람: 결정권자(팀)

## 배경

첫 공개 버전을 내기 전에는 결정을 개편안(`보고서_매트릭스_통합개편안_2026-09-30.md`) 12절에 번호를 매겨 적었습니다.
커밋 `fc7b826`에서 개편안을 `docs/redesign-plan-2026-09-30.md`로 옮겼습니다. 이때 12절을 비우고, 결정은 ADR 파일로 남기기로 했습니다.
이 파일은 그 12절을 옮긴 것입니다.

- 1~40번은 커밋 `3582336`의 개편안 12절에서 옮겼습니다(`git show 3582336:보고서_매트릭스_통합개편안_2026-09-30.md`). 처음에는 글자 그대로 옮겼고, 그 버전은 커밋 `1883405`의 이 파일에서 볼 수 있습니다. 2026-10-03에 내용은 바꾸지 않고 문체, 문장, 항목 안의 목록 구성을 읽기 쉽게 다듬었습니다(41번과 배경도 같습니다).
- 41번은 원문이 어느 커밋에도 없습니다. 그래서 `3582336`과 `fc7b826`의 셀 구성을 비교하고, `docs/redesign-plan-2026-09-30.md` 6절과 11절의 설명을 더해 다시 적었습니다.

**용어.** 이 문서에서 자주 쓰는 말의 뜻은 다음과 같습니다.

- 셀: 매트릭스가 서버에 던지는 관찰 질문 하나입니다.
- 상세(상세 항목): 셀의 질문에 답하는 구현 방식 하나입니다.
- 축: 셀을 묶는 큰 갈래입니다.
- 예외 표시(†): 원고의 구현 단락에 적은 적용 범위 안에서 그 방식이 적용되지 않는 경우가 있다는 표시입니다. 이 뜻은 28번에서 정했습니다.
- `미구현`·`비적용`·`미확인`: 구현 방식이 아닌 행입니다. `미구현`과 `비적용`의 차이는 12번에 있습니다.

**번호 주의.** 각 결정 본문의 셀 번호는 그 결정을 내린 때의 번호입니다.

- 1~21번은 첫 번호 재부여(22번) 전의 번호를 씁니다.
- 22~32번은 축 재편(33번) 전의 번호를 씁니다.
- 33~38번은 A~H 글자를 씁니다.
- 39번부터는 P·E·T·R·L·D·I 글자를 씁니다.

옛 글자와 지금 글자가 겹치므로 주의하세요. 예를 들어 옛 E02는 지금의 R02이고, 지금의 E02는 옛 C02입니다.
지금 번호는 각 결정의 대응표와 41번 표에서 찾으세요.

## 결정

1~21번은 셀 번호를 다시 매기기 전에 쓴 기록이라 옛 번호를 씁니다. 새 번호는 22번의 대응표에서 찾습니다.
22~32번은 33번에서 축과 번호를 바꾸기 전의 번호를 씁니다. 지금 번호는 33번의 대응표에서 찾습니다.
33번 뒤의 G축은 34번 대응표를 함께 보고, H축은 35번 대응표도 봅니다.

**2026-09-30.**
1. 코드 근거는 셀 절 끝의 근거 소절에 모읍니다. 본문 문장에는 번호 표지를 붙여 그 근거와 연결합니다(3.1절).
2. 매트릭스의 상세 항목은 구현 방식을 기준으로 만듭니다. 구현이 없는 프로젝트는 `미구현` 항목에 넣습니다. `비적용`과 `미확인`도 항목으로 둡니다. 상태, 적용 주체, 요약 필드는 두지 않습니다(6절).
3. 현행 경계 규칙은 필요할 때 씁니다. 다만 그 규칙이 새 셀 구조에 맞는지는 셀 검토 때 확인합니다(8절).
4. 새 셀 후보가 나오면 먼저 기존 셀의 구현 방식으로 흡수할 수 있는지 봅니다(10.3절). 다음 단계는 개편될 셀 전체를 결정권자와 함께 검토하는 것입니다.
5. 여러 셀을 묶어 보는 화면은 두지 않습니다. 해시 계산(C02)과 재검증(C03)처럼 이어지는 동작도 셀마다 따로 비교합니다. 비교 기준은 각 셀의 상세 항목과, 그 방식을 쓰는 프로젝트입니다.
6. 용어를 통일합니다(6.4절). 이름을 바꾼 것은 C01·C02·A02·B03·B08·C08·D03·D05·E06·E08·F05·H05·H08과 F·G 축 이름입니다. C07의 "부속 자료와 입력 일관성"은 그대로 둡니다.
7. E08의 상세 항목을 정했습니다(6.2절). 그 가운데 JSON 필드에 담는 방식이 가장 약한 항목입니다. 이 방식은 신뢰할 수 없다는 표시로 인정하지 않습니다.
8. **A축 검토.** A01~A04를 모두 둡니다.
    - 확인 대상에 따라 셀을 구분합니다. 방법과 입력이 서로 맞는지 확인하는 것은 A02에서 봅니다. 앞선 호출이 만든 상태를 확인하는 것은 B05에서 봅니다. 예를 들어 regipy에서 하이브를 적재했는지는 B05이고, 플러그인이 쓸 유형의 하이브가 있는지는 A02입니다(10.4절).
    - A1 annotation은 프로필에만 둡니다.
    - B03에는 서버나 백엔드가 실제로 확인하는 승인만 해당합니다.
    - A2 불일치 건수는 매트릭스에 보이지 않게 합니다. 보고서의 선언 대조 부록에만 둡니다.
9. **B축 검토.** B01(작업·대상 권한 확인)을 뺍니다. 외부 플랫폼을 감싸는 서버에서는 권한을 플랫폼이 정하기 때문입니다.
    - 지금까지 본 권한 구현은 모두 B02와 B06에 해당합니다. 예를 들어 mulder의 역할별 허용 목록은 B02 "클라이언트 도구 선택"이고, agentic-velociraptor-mcp의 계정 권한 위임은 B02 "외부 플랫폼 권한에 맡김"입니다. 계정의 실제 권한을 확인하지 못했으면 예외 표시(†)를 붙입니다(12절 13번에서 바꿈).
    - 호출자마다 권한을 구분하는 구현이 나오면 B02의 상세로 더합니다.
    - B04와 B05는 보는 범위가 달라서 둘 다 둡니다. B04는 이번 호출의 인자와 환경을 보고, B05는 앞선 호출이 만든 상태를 봅니다.
    - B07의 이름은 "대상 시스템 변경의 기록·되돌림 방식"으로 바꿉니다.
    - 인자 형식 검사는 B04입니다. 인자가 옵션으로 읽히지 않게 막는 검사는 B06입니다(10.4절).
    - B02·B03·B06·B08은 그대로 둡니다.
    - 13.1절의 "B01~B06 유지"는 이 결정으로 대체합니다.
10. **13.2절 보완 채택(A·B축).**
    - 서버가 호출자가 준 유형을 대조하지 않고 그대로 받으면, A01의 판별 방식이 아니라 미구현입니다.
    - 서버나 클라이언트가 단계를 실행하는 것은 A03의 결정 방식이 아닙니다. 그래서 진행 판단은 A04에서, 호출 거부는 B05에서 봅니다.
    - 모델이 같은 요청 안에서 참으로 채울 수 있는 확인 인자가 있습니다. 이것은 B03에서 별도 승인자의 동의와는 다른 항목("모델이 채우는 확인 인자 검사")으로 봅니다.
    - 셀 ID는 셀 검토가 모두 끝난 뒤 한 번에 다시 매깁니다. B01을 뺀 자리도 그때 채웁니다.
11. **C축 검토(진행 중).** C04에 "외부 도구에 의존"(C04.06) 항목을 둡니다.
    - 서버에는 보호 장치가 없고, 읽기만 하는 외부 도구에 원본 보호를 맡기는 표본을 위한 항목입니다. ChainsawMCP의 Linux 경로와 sift-kernel이 그런 표본입니다.
    - 원본에 쓸 수 있는 인자를 외부 도구에 넘길 수 있으면 예외 표시를 붙입니다(ChainsawMCP `extra_args`, sift-kernel pcap 내보내기).
    - 서버 코드가 읽기 모드를 지정하는 경우는 C04.03입니다.
    - 표본이 없는 후보 항목은 정의만 둡니다. 매트릭스에는 표본이 생길 때 보입니다(6절).
12. **셀의 행 구성과 C01 비적용.** 셀마다 구현 방식 행을 두고, 그 아래에 `미구현`·`비적용`·`미확인` 행을 둡니다. 한 프로젝트가 구현 방식 행 여러 개에 들어갈 수 있습니다.
    - 앞서 쓴 "장치 없음"은 팀 용어인 `미구현`으로 바꿉니다.
    - 비적용은 셀이 묻는 일의 전제를 서버가 아예 하지 않을 때입니다. 미구현은 서버가 그 일을 하는데도 장치가 없을 때입니다(규격 3절).
    - C01은 사건 개념이 없는 표본(MyIRTeam·regipy)에는 비적용입니다. 이런 서버가 증거를 읽고도 어떤 파일을 읽었는지 남기지 않는 빈틈은 E04(결과 출처 표시)와 F05에서 봅니다.
    - 13.2절의 C01 권고는 이 결정으로 대체합니다.
13. **C축 마무리.** C01~C08을 모두 둡니다.
    - 원본 보호나 권한을 외부 플랫폼에 맡기는 경우는 B02와 C04에 같은 이름 "외부 플랫폼 권한에 맡김"으로 둡니다. 계정의 실제 권한을 확인하지 못했으면 예외 표시(†)를 붙입니다(agentic-velociraptor-mcp).
    - 사본을 만드는 것은 C06에서 봅니다. C04.05에는 원본을 바꿀 수 있는 경로가 사본으로 제한될 때만 해당합니다.
    - 그래서 regipy의 메모리 사본은 C06에만 들어갑니다. MyIRTeam은 C04.05에 예외 표시와 함께 들어갑니다.
14. **D축 검토.** D01~D06을 두고 13.2절의 보완을 받아들입니다.
    - regipy는 D01 "라이브러리 내부 호출"입니다.
    - D02에서는 같은 권한으로 도는 별도 프로세스를 격리로 인정하지 않습니다.
    - D03은 선언된 버전과 실행 때 확인한 버전을 구분합니다.
    - D05에는 사용 직전의 실제 대상과 대조할 때만 해당합니다.
    - D06에 "러너 소실·시간 초과 뒤 최종 상태 재확인"을 더합니다.
    - D07은 뺍니다. 그 후보들은 이미 다른 셀이 묻고 있기 때문입니다. F03(실행 명령·설정), D03·D04(manifest), H04(중간 파생물), A05 후보(분석 상태)가 그렇습니다.
    - 서버 안에서 모델이 내린 판단을 재현할 자료는 D04 "모델·버전 표시"와 F03 "모델 호출의 입력·응답 기록"에서 봅니다. trudi `run_profile`처럼 서버 자신의 버전을 알리는 것은 D04에서 봅니다.
    - 현행 D4는 프로필로 옮깁니다.
    - 대체 실행 경로는 새 셀 D08로 둡니다. 표본은 sift-kernel `img_stat` 대체, trudi `tool_unavailable`, MyIRTeam의 등록된 대체만, ChainsawMCP의 추출 경로 3개, mulder의 파서 경로입니다.
    - 13.2절의 D07 권고와 13.3절 4번의 D07 흡수는 이 결정으로 대체합니다.
15. **E축 검토.** E01~E09를 모두 둡니다.
    - 잘림(건수·값)은 E02에서, 내용 변환은 E01에서 봅니다. 그래서 regipy의 256자 값 잘림은 E02 "값 단위 잘림"이고, velociraptor의 float64 반올림은 E01입니다.
    - E02에 "상한 초과 시 거부"(mcp_dfir), "값 단위 잘림"(regipy), "건수 없이 잘림만 알림"을 더합니다. mcp_dfir와 regipy의 옛 비적용 판정은 이어받지 않습니다.
    - 모델이 호출 인자로 상한을 올리거나 끌 수 있으면 상한 항목에 예외 표시(†)를 붙입니다.
    - E05의 "별도 검증 도구 연계"에는 같은 출처와 범위를 찾아 대조할 때만 해당합니다.
    - E08과 E09는 막는 위험이 달라서 따로 둡니다(10.4절).
16. **F축 셀 이름과 F05 위치.** F02의 이름은 "실행 결과 상태 기록 방식"으로, F03의 이름은 "실행 요청 내용 기록 방식"으로 바꿉니다.
    - F01은 기록이 생기는지를 봅니다.
    - F02는 실행 결과가 기록에 적히는지를 봅니다. 실행 결과는 시작, 끝, 거부, 실패, 시간 초과, 비동기 완료입니다.
    - F03은 실행 요청이 기록에 적히는지를 봅니다. 실행 요청은 도구, 인자, 실제 명령입니다.
    - F05(증거·호출·파생물 연결)는 H축의 H04~H06 옆으로 옮깁니다. 이 셀은 호출 기록 자체가 아니라 파생물을 중심으로 한 연결을 묻기 때문입니다. 호출 기록이 파생물의 경로나 해시를 남기는 것은 옮긴 F05의 한 항목입니다.
    - F축 이름은 "호출 기록"으로 줄입니다(12절 6번의 이름을 바꿈).
    - 셀 번호는 검토가 끝난 뒤 다시 매깁니다.
17. **F04 항목.** 서버가 기록 쓰기에 실패했는데도 알리지 않고 결과를 돌려주면, `미구현`이 아니라 "알리지 않고 계속" 항목입니다(ChainsawMCP, sift-kernel). 이 항목은 "경고 후 계속"과 짝을 이룹니다. D08의 "알림 없이 대체 실행"과 같은 기준이며, H06에도 같은 이름을 씁니다.
18. **F축 마무리.** F01~F04와 F06을 둡니다.
    - 호출 기록이 없는 서버(MyIRTeam·regipy)는 F01이 `미구현`이고, F02·F03·F04·F06은 `비적용`입니다. 이렇게 해서 이 빈틈은 F01에서 한 번만 집계합니다.
    - F01에서 기록되지 않는 호출이 있으면 그 항목에 예외 표시(†)를 붙입니다(mcp_dfir, mulder, sift-kernel).
    - F06의 항목은 해시 체인, 서명·MAC, 일련번호, 외부 기준점, 쓰기 권한 분리·추가 전용 저장, 검증 도구입니다.
    - 모델이 도구로 기록을 지울 수 있으면 예외 표시를 붙입니다(sift-kernel `reset_investigation`, trudi `clear_case_run`). 삭제와 초기화를 새 셀로 둘지는 H축에서 정합니다.
19. **G축 검토.** G01~G05를 둡니다.
    - 외부와 통신하지 않는 서버(MyIRTeam·regipy·sift-kernel)는 G01·G02·G03·G05가 `비적용`입니다.
    - G04는 서버가 실행하는 외부 도구의 통신을 봅니다. 그래서 서버가 외부 도구를 실행하면 이 셀을 적용합니다(sift-kernel은 `미구현`).
    - G04 항목에서 "로컬 참조 자료 사용"을 빼고 "DNS 조회 끄기"를 더합니다(MyIRTeam `tcpvcon -n`, trudi `tcpdump -nn`).
