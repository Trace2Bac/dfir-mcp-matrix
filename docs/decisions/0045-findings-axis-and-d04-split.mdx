# 0045. 판단을 F축으로 모으고 R축을 표현·전달로, D축을 저장된 표현으로 좁히며 D04를 나눕니다

- 날짜: 2026-10-07
- 상태: 제안
- 결정한 사람: (팀 검토 전)

## 배경

R축과 D축에 판단에 관한 일이 나뉘어 있어 같은 기능이 두 축 사이를 오갔습니다.

- 2026-10-06 전체 검토의 R축 항목 넷이 같은 원인에서 나왔습니다.
  - R-04: 발견사항을 제출할 때 붙는 단서 문구를 담을 상세가 없었습니다.
  - R-06: 서버 안 모델에게 넘기는 입력을 볼 셀이 없었습니다.
  - R-11: R01.03의 "점수, 상관"이 D06과 겹쳤습니다.
  - R-19: 조사 상태로 고르는 편향 경고의 자리가 정해지지 않았습니다.
- R04.04 「불확실성·추정 범위 표시」는 서버가 만든 결론의 속성인데 R축에 있었습니다.
- R04.05 「서버 공통 해석 지침」은 결론을 만드는 원칙이고 도구 결과에 붙는 주의가 아니었습니다.
- D축 원고의 약 66%(근거 포함 줄 수)가 D05~D08이었고, 두 묶음은 묻는 것이 달랐습니다. D01~D04·D09는 저장된 자료를 보고, D05~D08은 판단을 봅니다.
- D04는 경로 제한과 재실행 구분이라는 두 질문을 함께 물었습니다(전체 검토 D-16).
- D06 boundary 첫 문장은 2026-10-06 문장 개선에서 "발견사항으로 기록될 때"를 잃어 D07 범위와 맞지 않았습니다.

## 결정

**축을 하나 더하고 세 축이 보는 행위를 나눕니다.** 대상을 배타적으로 나누지 않고, 같은 자료를 세 축이 서로 다른 행위로 봅니다.

- **R 실행 결과 전달:** 도구에서 얻은 관측과 서버가 만든 분석 결과를 어떻게 표현하고 전달하는가
- **F 발견사항·결론 관리(새 축, 차례 5):** 무엇을 판단하고, 안내하고, 기록하고, 검증하고, 보고하는가
- **D 파생물 관리:** 저장된 표현을 어떻게 보관하고, 잇고, 지키고, 다시 만드는가

L·D·I의 차례를 하나씩 미룹니다(L 6, D 7, I 8).

**셀**

- 옛 D05~D08을 F04·F02·F05·F06으로 옮기고 F01 「판단 지침」을 새로 둡니다.
- F03 「서버 안 모델 입력 구성」은 조건부 셀로 둡니다.
- D04는 「출력 경로 제한」으로 좁히고, 재실행 구분 상세 넷을 D10 「산출물 식별·재생성 처리」로 나눕니다.
- R01은 「결과 가공」, R04는 「도구 결과 해석 주의」로 이름을 바꿉니다.

**경계 규칙**

1. R과 F는 판단이 생기는지로 나눕니다.
   - 값을 옮기고 형식을 바꾸고 건수를 세고, 이미 만든 결과에서 응답 목록만 고르면 R01입니다.
   - 판정, 관계, 점수·등급, 흐름 서술을 만들거나, 분석 대상·의심 후보를 정하는 제외 규칙이면 F02입니다. 차집합으로 후보를 고르는 규칙도 F02입니다.
   - 여기서 판단은 새 필드나 숫자가 아니라 결과 집합이 갖는 조사 의미입니다.
2. 모델 요약은 둘로 나눕니다. 관측을 줄이거나 다시 서술하면 R01.04이고, 관계·가설·판정을 새로 만들면 F02.04입니다.
3. 안내 문구는 무엇에 관한 안내인지로 나눕니다.
   - 특정 도구 결과의 주의는 R04, 조사 전체 원칙·결론 서술·기록 단서·편향 경고는 F01, 다음 작업과 문맥 손실 뒤 재조회 절차는 P02, 증거 속 지시 무시는 R07입니다.
   - 안내는 그 안내를 따르게 하는 장치의 구현으로 세지 않습니다.
4. 판단의 속성은 F, 판단을 실어 나르는 형태(잘림, 출처, 상태)는 R, 판단을 담은 파일의 보관·경로·해시는 D입니다.
5. 옛 셀·상세 번호는 다른 뜻으로 다시 쓰지 않습니다. D05~D08, R04.04, R04.05, D04.05~D04.08은 결번입니다.
