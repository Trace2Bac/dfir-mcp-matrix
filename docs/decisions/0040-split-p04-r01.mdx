# 0040. 한 셀에 분류 기준 하나를 두고, 기준이 섞인 P04·R01을 나눠 P06·R08을 만듭니다

- 날짜: 2026-10-06
- 상태: 채택
- 결정한 사람: 결정권자(팀)

## 배경

0038로 이 매트릭스를 분류표로 정했습니다.
분류표에서는 한 셀의 상세가 같은 기준으로 나뉘어야 합니다.
그런데 두 셀은 서로 다른 기준의 상세를 한 셀에 담고 있었습니다.

- P04 조사 문맥 관리: 조사를 단위로 묶고 나누는 방식과, 조사 상태를 요청·세션·재시작 사이에 유지하는 방식
- R01 도구 출력 가공: 출력을 가공하는 방식과, 시각 값을 변환하고 표시하는 방식

섞인 기준은 원고에서도 판정을 가렸습니다.
sift-kernel과 protocol-siftpp의 P04 원고는 "사건 ID가 없다"는 조사 단위 판단을 상태 보관 상세 단락에 적었습니다.
두 서버는 상태 보관 상세에 연결되어 있어서 조사 단위가 없다는 사실이 화면에 드러나지 않았습니다.

T03(실행 조건 확인)도 나누는 안을 검토했습니다.
그러나 선행 결과·판정, 승인, 호출자 인증, 실행 자원 확인은 모두 "실행 전에 인자 밖의 조건으로 실행을 통제(허용·거부·대기)하는 방식"이라는 한 기준 위에 있어 나누지 않습니다.

## 결정

- 한 셀에는 분류 기준 하나만 둡니다. 상세들이 같은 기준으로 나뉘면 한 셀에 두고 기준이 다르면 셀을 나눕니다.
- 같은 기준의 방식을 다른 셀로 떼어 내지 않습니다. 셀이 늘면 관리할 파일과 경계도 늘어납니다.
- 구현 사례의 수는 셀을 나누거나 합치는 기준이 아닙니다. 기준에 맞는 구현이 하나라도 있으면 상세로 둡니다.
- P04는 이름을 「조사 단위 관리」로 바꾸고 조사를 단위로 묶고 나누는 방식만 봅니다. 사건 개념 없이 사용자가 실행마다 저장 위치를 지정해 나누게 하는 경우는 미구현입니다.
- 새 셀 P06 조사 상태 유지는 조사 상태를 요청, 세션, 재시작 사이에 유지하고 버리는 방식을 봅니다.
- R01은 출력 가공과 가공 사실 표시만 봅니다.
- 새 셀 R08 시간값 처리는 응답에 싣는 시각 값의 변환과 원래 값, 시간대, 변환 사실의 표시를 봅니다.
- 옮긴 상세의 포함·제외 기준은 번호만 새 번호로 바꾸고 내용은 그대로 둡니다. P06.03 include와 T03.01 include의 "적재한"은 "불러온"으로 바꿉니다.

## 영향

- 셀은 43개에서 45개가 되고 상세 수는 그대로입니다.
- 원고는 옮긴 상세의 단락과 근거를 새 셀 파일로 옮기고 근거 번호를 다시 매겼습니다(`renumber`). 코드 발췌는 원래 원고와 글자 하나까지 같습니다.
