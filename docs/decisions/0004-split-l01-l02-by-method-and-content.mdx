# 0004. L01은 "기록 경로", L02는 "기록 구성"을 묻도록 나눕니다

- 날짜: 2026-10-01
- 상태: 채택(L01 이름은 0005로 대체됨)
- 결정한 사람: 결정권자(팀)

## 배경

L01 기록 범위와 L02 기록 내용 구성은 둘 다 "무엇이 기록되는가"를 물었습니다.
다만 L01은 사건 종류를 기준으로, L02는 필드를 기준으로 물었습니다.
그래서 거부된 호출, 외부 요청, 서버 안에서 하는 모델 호출이 두 셀에 모두 나왔습니다.

## 결정

- L01 이름을 "기록 경로"로 바꿉니다.
  - 새 질문은 "서버 기록을 어떤 장치·경로로 만들고, 그 장치를 거치지 않는 호출은 무엇인가?"입니다.
  - 장치를 거치지 않아 기록되지 않는 호출이 있으면 †를 붙입니다. †(예외 표시)는 원고의 구현 단락에 적은 적용 범위 안에서 그 방식이 적용되지 않는 경우가 있다는 표시입니다.
  - 논의에서 나온 이름은 "기록 방식"이었습니다. 하지만 셀 이름 끝에 "방식"을 붙이지 않는다는 규칙(첫 버전 전 결정 40번)이 있었습니다. 그래서 첫 버전 전 F1 판정에서 쓰던 이름 "호출 기록 경로"를 따랐습니다.
- L02 이름을 "기록 구성"으로 바꿉니다. L02는 기록 항목에 어떤 사건과 내용을 어떤 형태로 남기는지를 묻습니다.
- L01에서 사건 종류별 상세를 지웁니다.
  - 거부 호출은 L02.06에서, 외부 요청은 L02.09에서, 서버 안 모델 호출은 L02.05에서 봅니다.
  - 도구 호출 기록은 옮기지 않고 지웁니다. 기록을 남기는 서버라면 모두 해당하므로, 서버끼리 구별해 주지 못하기 때문입니다.
- L01에 기록 장치별 상세 세 가지를 더합니다. 공통 요청 처리 단계에서 기록, 도구별 기록 호출, 실행기 안 기록입니다.
- 상태 변경(승인, 삭제, 초기화) 기록은 구현 사례가 확인되면 L02에 상세로 더합니다. 상세는 실제 구현체가 있을 때만 두기 때문입니다.

번호는 다음과 같이 바뀝니다.

| 옛 번호 | 새 번호 | 상세 |
|---|---|---|
| L01.01 | 없음 | 도구 호출 기록 |
| L01.02 | L02.06 | 거부·검사 실패 호출 기록 |
| L01.03 | L02.09 | 외부 요청 기록 |
| L01.04 | 없음(사례 확인 뒤 L02에 더함) | 상태 변경 기록 |
| L01.05 | L02.05 | 서버 안 모델 호출 기록 |
| 없음 | L01.07 | 공통 요청 처리 단계에서 기록 |
| 없음 | L01.08 | 도구별 기록 호출 |
| 없음 | L01.09 | 실행기 안 기록 |

## 영향

- 셀 번호와 L02 상세 번호는 바뀌지 않습니다. 그래서 시범 원고(L02)는 제목만 고쳤습니다.
- L01.07~09의 `seen_in`은 첫 버전 전 분석(옛 F1 판정)에서 옮겨 왔습니다. 원고를 쓸 때 기준 커밋의 코드로 다시 확인해야 합니다.
- L02의 상세 가운데 시범 서버 4개의 원고가 연결된 상세는 3개뿐입니다. 그래서 나머지 서버를 조사하면서 상세의 이름과 구성이 바뀔 수 있습니다.
